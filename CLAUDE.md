# openframe-oss-frontend — repository layout

| Path | What | Guide |
|------|------|-------|
| `apps/web/` | Next.js web app — the only UI code. Docker image (`apps/web/Dockerfile`) and the static export the shells bundle | `apps/web/CLAUDE.md` (imported below) |
| `apps/desktop/` | Tauri 2 desktop shell (`src-tauri/`) — no UI code | `apps/desktop/README.md`, `apps/desktop/docs/` |
| `apps/mobile/` | Capacitor iOS/Android shell (`ios/`, `android/`) — no UI code | `apps/mobile/CLAUDE.md` |
| `docs/` | Web app documentation, generated by the hub's code-documentation workflow | — |

Each app is self-contained: its own `package.json`, lockfile, `node_modules` and lint/format
config. There are no npm workspaces and no root `package.json` — run every command inside the app
(`cd apps/web && npm run type-check`). Git hooks live in the root `.husky/` (installed by
`apps/web`'s `prepare` script) and gate only `apps/web`. Desktop and mobile were imported with
full history from `openframe-saas-desktop` / `openframe-saas-mobile`.

Node is declared once, in the root `.nvmrc`: every `setup-node` step reads it, and the major in
`apps/web/Dockerfile` (a literal, so Renovate can pin its digest) is bumped with it.
npm is held at ≥ 11.11 by `devEngines` in each app's `package.json`: older npm rewrites the
lockfile without its `libc` fields.

## Shells and the web bundle

- `scripts/build-web.sh` in each shell builds `apps/web`'s static export
  (`OPENFRAME_BUILD_TARGET=export`) and stages it into the shell's `www/`, so a shell and its
  **built-in** bundle are always one commit.
- **A phone also runs bundles its shell was not built with.** The mobile shells take the release
  their environment runs over the air (`NativeUpdate`, `apps/mobile/docs/ota.md`): a signed
  bundle runs on any installed shell whose `BRIDGE_LEVEL` meets the bundle's
  `REQUIRED_BRIDGE_LEVEL` (`apps/web/src/lib/native-shell.ts`). So a web change reaches shells
  already in the field, and what may ship that way is limited (`apps/web/CLAUDE.md`, "Over-the-air
  bundles").
- **Release** is one `.github/workflows/release.yml` (version from `version.yml`): a dispatch
  publishes one `x.y.z` release, the web image plus the desktop installers and `updater.json`, and
  the mobile over-the-air bundle (`openframe-mobile-<x.y.z>.tar.xz` + signed `mobile.json`,
  `apps/mobile/docs/ota.md`); a push to `main` builds the `latest` image when the web side
  changed, and the desktop bundles as workflow artifacts (no release) when `apps/desktop` changed.
  Installed desktop apps update through the tenant gateway, which serves the release that
  environment runs; `openframe-saas-desktop`, where the shell was released before, is legacy. The
  release builds no store binaries: the signed `.ipa`/`.aab` come from the
  `apps/mobile/scripts/build-*-prod.sh` lanes, uploaded to the stores by hand. PR tests and
  checks run in the hub's code reviewer (`flamingo-code-review.yml`); `test.yml` builds, scans and
  pushes the PR image.
- A bridge name change (Tauri command/event, Capacitor plugin method) touches
  `apps/web/src/lib/native-shell.ts` and the shell implementation in the same PR.
  On mobile a bridge change is an **addition**, probed by the bundle (`plugin.foo?.()`): bundles
  older and newer than the shell both run on it. The same PR bumps the shells' `BRIDGE_LEVEL`;
  `REQUIRED_BRIDGE_LEVEL` rises only when a bundle stops working without the addition.
  A new Tauri command also goes in `src-tauri/build.rs` and, if the page calls it,
  `src-tauri/capabilities/main.json`; without both it is refused at runtime.
