Zustand store managing onboarding progress state for both tenant and user onboarding flows, mirroring backend progress data across all onboarding UI surfaces simultaneously.

## Key Components

### Interfaces

| Interface | Description |
|---|---|
| `TenantOnboardingProgress` | Completed steps, overall completion flag, and timestamp for tenant-level onboarding |
| `UserOnboardingProgress` | Extends tenant progress with `skipped`/`skippedAt` fields for user-level onboarding |
| `OnboardingState` | Full store shape combining both progress objects, load state, and action methods |

### Store Actions

| Action | Description |
|---|---|
| `setTenant(progress)` | Updates tenant progress and marks the store as loaded |
| `setUser(progress)` | Updates user progress and marks the store as loaded |
| `setLoaded()` | Marks the store as loaded without updating progress data |
| `reset()` | Clears all progress and resets `isLoaded` to `false` |

### `useOnboardingStore`

The exported Zustand store, composed with `devtools` (Redux DevTools support) and `immer` (mutable-style state updates). Named `"onboarding-store"` in DevTools.

## Usage Example

```typescript
// Hydrate the store (called once by OnboardingProgressHydrator)
const { setTenant, setUser } = useOnboardingStore.getState();
setTenant({ completedSteps: ['INVITE_USERS'], completed: false, completedAt: null });

// Read in a UI component — treats isLoaded === false as still loading
const { tenant, user, isLoaded } = useOnboardingStore();

if (!isLoaded) return <Spinner />;
if (tenant?.completed) return <SetupComplete />;
```

> **Note:** `isLoaded` intentionally starts as `false` and is non-suspending — onboarding chrome is decorative and must never block the app shell.
