Manages file downloads from a MeshCentral remote agent, handling the full download lifecycle including chunked binary transfer, progress reporting, and browser-side file saving.

## Key Components

### `DownloadTask` Interface
Represents an in-progress or completed download with fields for chunk accumulation, transfer size tracking, and lifecycle `status` (`pending` → `negotiating` → `downloading` → `completed` / `failed` / `cancelled`).

### `FileDownloader` Class
Core download manager. Supports one active download at a time via `activeDownloadId`.

| Method | Description |
|---|---|
| `downloadFile(remotePath, fileName?, fileSize?)` | Initiates a download, sends a `start` request over the WebSocket, returns a `downloadId` |
| `handleControlMessage(message)` | Dispatches JSON control messages: `start`, `cancel`, `error` |
| `handleBinaryChunk(data, isFinal)` | Processes raw binary chunks; reads the 4-byte big-endian MeshCentral header to detect final chunk, sends `ack` for each non-final chunk |
| `saveFile(downloadId)` | Triggers a browser download via a synthetic `<a>` click against an object URL |
| `cancelDownload(downloadId)` | Marks task cancelled, sends a `cancel` control message, cleans up state |
| `resetActiveDownload()` | Force-fails a stuck active download without sending a cancel message |
| `clearAll()` | Removes all tracked downloads and resets active state |

## Usage Example

```typescript
const downloader = new FileDownloader(
  (data) => socket.send(data),           // sendMessage
  (progress) => console.log(progress),  // onProgress
  (fileName, reason) => alert(`Server cancelled ${fileName}: ${reason}`) // onServerCancel
);

// Initiate download
const id = downloader.downloadFile('/home/user/report.pdf', 'report.pdf', 204800);

// Route incoming WebSocket messages
socket.onmessage = (event) => {
  if (typeof event.data === 'string') {
    downloader.handleControlMessage(JSON.parse(event.data));
  } else {
    const chunk = new Uint8Array(event.data);
    downloader.handleBinaryChunk(chunk, false);
  }
};
```

> **Protocol note:** Each binary chunk begins with a 4-byte big-endian header; bit 0 signals the final chunk. The downloader automatically sends `ack` messages after every non-final chunk and triggers `saveFile` on completion.
