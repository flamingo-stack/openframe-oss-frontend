The NATS chunk → reducer glue shared by both chat hosts: the mingo dialog subscription and the tickets per-side processor. Returns one identity-stable `processChunk`, plus the two effects that keep a reducer instance correct across LRU eviction.

## Key Components

| Export | Purpose |
|---|---|
| `useChatChunkProcessor(options)` | Returns `(chunk: unknown) => void` — decode, optionally intercept, apply |
| `UseChatChunkProcessorOptions` | `boundMirror`, `messages`, `approvalStatuses?`, `interceptEvent?` |
| `ChatModelMetadata` | Re-exported from `chat-stream-thread` for host convenience |

## Hot path

```
decodeNatsChunk(chunk) → interceptEvent?.(event) → boundMirror.apply(event)
```

`interceptEvent` returning `true` claims the event and skips the shared path. Tickets uses it for client-authored `DIRECT_MESSAGE` rows, which the lib reducer would otherwise render as admin-authored — its home surface only ever sees technician takeovers.

## Key Behaviors

- **Stable identity** — `processChunk` never changes identity. Both hosts stash it in a ref handed to a long-lived JetStream subscription, so a per-render identity would churn the subscription. Props are mirrored into refs **during render** (write-only, never read during render), so the first chunk after a prop change already sees the new value.
- **Approval-status merge** — persisted statuses are merged into the reducer, which applies state-monotonic precedence: a resolved status is never downgraded back to `pending` by a stale snapshot.
- **Post-eviction re-seed** — the only seeding this hook owns. Ordinary hydration goes through `mirror.hydrate`; eviction is the case `hydrate` cannot cover, because the store replaces a reducer behind an **unchanged** key and no host has a reason to refetch. Parking restores thread, statuses, seq cursor and echoes — but not the per-turn kernel, so an unfinished turn would resume into a fresh bubble. Re-seeds with `expectingReplay: false`: the replacement gets no catchup replay, and an adopt-once flag armed here would survive until the next genuine turn.
- **Eviction epoch** — both effects depend on `boundMirror.evictionEpoch`, which is what re-arms them against the replacement instance.

## Moved out of this hook

- **Own-echo suppression** → the reducer (`pushOptimisticSend` records the sent text; the `MESSAGE_REQUEST` handler consumes exactly one match). The old blanket `event.userId === currentUserId` drop also swallowed this user's messages sent from a second tab or device.
- **Model-badge metadata** → the reducer's `onMetadata` effect, wired once in `natsMirrorOptions`.
