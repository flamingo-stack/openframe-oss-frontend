Configures and manages the singleton Relay GraphQL environment for the OpenFrame frontend, handling authentication headers, token refresh, and custom record normalization.

## Key Components

- **`getAuthHeaders()`** — Builds HTTP authorization headers using bearer token auth when applicable, reading from the token store.
- **`getGraphqlUrl()`** — Resolves the GraphQL endpoint URL from runtime config or `window.location.origin`.
- **`fetchRelay`** — Core Relay `FetchFunction` that executes GraphQL requests, handles 401 responses with a single token refresh retry, forces logout on refresh failure, and detects trial-expiration errors in GraphQL responses.
- **`UNNORMALIZED_TYPES`** — A `Set` of type names (`SubscriptionOptionDetail`, `OrganizationFilterOption`) opted out of Relay's global id-based record normalization to prevent incorrect data merging from colliding backend IDs.
- **`resolveDataId()`** — Custom `getDataID` implementation that returns `undefined` for unnormalized types, falling back to the default `id`-based strategy for all others.
- **`getRelayEnvironment()`** — Returns the singleton `IEnvironment` for the browser (with GC buffer and query cache tuning), or a fresh server-side instance per call for SSR.
- **`resetRelayEnvironment()`** — Nullifies the singleton, forcing re-creation on next access (intended for logout or auth state changes).

## Usage Example

```typescript
import { getRelayEnvironment, resetRelayEnvironment } from './environment';

// In your app root or RelayEnvironmentProvider
const environment = getRelayEnvironment();

// On logout
resetRelayEnvironment();
```

## Notes

- The `fetchRelay` function captures the token epoch **before** sending the request so a stale-token 401 triggers a refresh+retry rather than a duplicate rotation.
- Requests to `/auth/*` paths short-circuit on 401 with a thrown error instead of triggering a refresh loop.
- The client-side store is configured with a 20-entry GC release buffer and a 5-minute query cache TTL.
