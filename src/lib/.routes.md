Centralized, typed registry of all internal app routes. Serves as the single source of truth for navigation, replacing scattered path strings with type-checked route builders that handle dynamic IDs and query parameters.

## Key Components

### `TAB_IDS`
A `const` object defining valid tab identifiers for every tabbed page in the app (customers, devices, monitoring, settings, etc.).

### Tab Type Exports
Derived union types from `TAB_IDS` tuples:
- `CustomerListTab`, `CustomerDetailTab`, `CustomerEditTab`
- `DeviceDetailTab`, `ScriptsTab`, `ScheduleDetailTab`
- `MonitoringTab`, `SettingsTab`, `AiSettingsTab`, `NotificationsTab`
- `HelpCenterLegalDoc` — `'privacy' | 'terms'`

### `withQuery(base, query?)` *(internal)*
Appends a typed query string to a base path, skipping `undefined`/`null` values and URL-encoding the rest.

### `routes`
The main export. A nested object of static strings and typed builder functions covering all app sections: `auth`, `customers`, `devices`, `scripts`, `scriptsV2`, `monitoring`, `tickets`, `knowledgeBase`, `settings`, `helpCenter`, `mingo`, `notifications`, and `checkout`.

## Usage Example

```typescript
import { routes } from '@/routes';

// Static route
router.push(routes.dashboard);

// Route with tab
router.push(routes.monitoring.root({ tab: 'policies' }));

// Route with dynamic ID and optional tab
router.push(routes.customers.details(customerId, { tab: 'tickets' }));

// Link component
<Link href={routes.devices.details(deviceId, { tab: 'overview' })} />;

// Settings with nested tab
router.push(routes.settings.aiSettings({ tab: 'mingo', edit: true }));

// Help Center legal doc (type-guarded)
router.push(routes.helpCenter.legal('privacy'));
```
