Defines and exports the `openframeConfig` object — the central `AppConfig` configuration for the OpenFrame platform, covering branding, SEO, layout, navigation, UI behavior, footer, and contact/social metadata.

## Key Components

- **`openframeConfig`** (`AppConfig`) — The primary export. A fully-typed platform configuration object containing:
  - **`seo`** — Title template, description, keywords, and dynamic OG/Twitter image URLs resolved via `getBaseUrl()`
  - **`layout`** — Header/footer/sidebar visibility and header type
  - **`navigation`** — Logo element, allowed/restricted routes, and nav visibility flags
  - **`ui.getHeaderActions`** — Dynamic header button factory; renders a `Profile` button for authenticated users, a `Sign Up` button for guests, and a static `Get Started` CTA linking to GitHub
  - **`footer.sections`** — Static links for Resources (`/docs`, `/examples`) and Company (`/about`, `/contact`)
  - **`brandColors`** — Metadata-only color tokens (cyan primary, dark background); actual UI theming is handled by ODS CSS
  - **`contact` / `social`** — Email, support URL, GitHub, and Twitter handles

## Usage Example

```typescript
import { openframeConfig } from './openframe.config';

// Access platform metadata
console.log(openframeConfig.name);          // "OpenFrame"
console.log(openframeConfig.seo.title);     // "OpenFrame - Open Source Framework"
console.log(openframeConfig.url);           // Resolved base URL at runtime

// Render header actions in a layout component
const { left, right } = openframeConfig.ui.getHeaderActions({
  user: currentUser,
  router,
  pathname,
  onSignUp: handleSignUp,
});
```

> **Note:** `url` and `logo` are getter properties — they call `getBaseUrl()` lazily at access time, ensuring correct resolution in SSR and client environments.
