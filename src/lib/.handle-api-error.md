Utility module providing error extraction and toast notification helpers for API and GraphQL (Relay) error handling.

## Key Components

### `getErrorMessage(error: unknown): string`
Extracts a plain string message from any error value — `Error` instances, raw strings, or unknown types (falls back to a generic message).

### `getRelayErrorMessage(error: unknown, fallback?: string): string`
Extracts a clean, user-facing message from Relay mutation/query errors. Unwraps Relay's verbose error wrapper, reads structured `error.source.errors`, and filters out graphql-java non-null field noise (e.g. `"The field at path … was null"`). Deduplicates messages and joins them with newlines.

### `handleApiError(...): void`
Convenience wrapper for React Query `onError` callbacks. Calls `getErrorMessage` and fires a destructive toast notification.

## Usage Example

```typescript
// Basic error extraction
import { getErrorMessage, getRelayErrorMessage, handleApiError } from './handle-api-error';

// In a React Query mutation
useMutation({
  mutationFn: updateDevice,
  onError: (error) => {
    handleApiError(error, toast, 'Failed to update device');
  },
});

// In a Relay mutation callback
commitMutation(environment, {
  mutation,
  variables,
  onError: (error) => {
    const message = getRelayErrorMessage(error, 'Could not save changes');
    setFormError(message);
  },
});

// Direct extraction
try {
  await fetchData();
} catch (err) {
  console.error(getErrorMessage(err)); // "Network request failed"
}
```

## Notes

- `getRelayErrorMessage` silently drops `isNonNullFieldNoise` messages (graphql-java internal non-null violations) to avoid surfacing framework-level noise to users.
- If `error.source.errors` contains only noise messages, they are used as-is rather than falling back to a generic string.
- `handleApiError` is designed specifically for [shadcn/ui](https://ui.shadcn.com/docs/components/toast)-style `toast()` APIs with `variant: 'destructive'`.
