Bridge between this app's chat `Message` shape and the core library's stream reducer, plus the multi-key reducer registry (`createReducerMirror`) both chat hosts — mingo and tickets — are built on. The reducer owns every accumulation rule; this module owns the conversion, the registry, and the history-hydration protocol.

## Key Components

### Shape conversion

- **`toUnifiedMessage(message)`** — app `Message` (`content: string | MessageSegment[]`) → reducer `UnifiedChatMessage` (`content: string` + `segments?`)
- **`fromUnifiedMessage(...)`** *(module-private)* — the inverse; only the mirror may call it, because it owns the per-key output-array reuse the reference-stability contract depends on

Both directions are cached in `WeakMap`s keyed by object identity, so an untouched reducer message always converts back to the **same** app instance. Per-message React memoization and the history merge's reference reuse both depend on this.

### Hydration

- **`HydrateOptions`** — `{ expectingReplay?: boolean }`
- **`ReducerMirror.hydrate(key, messages, options?)`** / **`BoundMirror.hydrate(...)`** — THE door for a thread fetched from history

`hydrate` is one call because restoring a turn takes three steps that only work together:

1. `initializeWithState(thread)` — derives `resumed`, which makes a chunk arriving with no preceding `turn-start` **append** to the hydrated bubble instead of replacing its segments. A reload mid-stream lands exactly there.
2. the accumulator seed, when the trailing assistant run is unfinished.
3. the adopt-once flag, so a **replayed** `turn-start` re-streams into the partial bubble instead of opening a duplicate beside it.

The flag is disarmed on the first applied event that is not a `turn-start` — this app's subscriptions have no catchup-finished signal, and an armed flag left behind would make the next genuine turn overwrite a completed bubble. Pass `expectingReplay: false` for hydration that is not a fresh subscribe.

### Registry — `createReducerMirror(config)`

| Area | What it does |
|---|---|
| Identity | `identityFor(key)` maps a host key to `(dialogId, side)` + assistant defaults. A key must always map to the same identity for the mirror's lifetime. |
| Snapshots | `onSnapshot(key, { messages, phase, streamingId, state })` publishes a converted read-mirror into the host store |
| Thread ops | `mutateThread`, `upsertMessage`, `patchMessage`, `removeMessage`, `prependWithBoundaryMerge`, `pushOptimisticSend`, `setTyping`, `mergeApprovalStatuses` |
| Retention | `setActiveKeys(keys)` pins displayed keys against LRU eviction; `drop(key)` removes one outright |
| Eviction | `onEvict` **parks** the thread, approval statuses, seq cursor and armed echoes; the next `getReducer` replays them into the replacement instance |
| Binding | `bind(key)` → `BoundMirror` (`apply`, `hydrate`, `mutate`, `mergeApprovalStatuses`, `evictionEpoch`), memoized per key |

`evictionEpoch` is the signal consumers need: eviction replaces a reducer behind an unchanged key, so any one-shot state written into the old instance must be re-applied against the new one.

### NATS wiring

- **`natsMirrorOptions(handlersFor, batchApprovalsEnabled, selfUserId)`** — reducer creation options for NATS hosts: approve/reject binding, batch-approval flag, own-echo author guard, and the model-badge metadata effect
- **`ChatModelMetadata`**, **`NatsMirrorHandlers`** — the late-bound handler bundle each host registers per dialog

### Small helpers

- **`computeIncompleteTailState(messages)`** — adapts app rows to the lib's `extractIncompleteTailState`, the single incompleteness rule set
- **`makeChatRowId(prefix)`** — one recipe for locally-authored row ids (the reducer's echo consumption keys off rows looking the way this send path makes them)
- **`adminDisplayName(user)`** — display name for an operator-authored row

## Consumers

`mingo-messages-store` (key = dialogId), `ticket-details-store` (key = side, two reducers per dialog), `use-chat-chunk-processor` (the shared NATS glue), and `use-send-admin-message` (id/name helpers).

## Tests

`chat-stream-thread.test.ts` pins the hydration seam: append-without-turn-start, referential stability, adopt-once arm/disarm, and eviction parking. Each assertion was verified to fail with its fix reverted.
