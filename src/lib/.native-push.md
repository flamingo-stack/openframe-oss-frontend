Manages native push notification lifecycle for iOS and Android via Firebase/FCM (`@capacitor-firebase/messaging`). Handles permission requests, FCM token registration/deregistration with the backend via Relay mutations, and deep-links notification taps to in-app routes. No-ops silently on web or in shells without the plugin.

## Key Components

| Export / Symbol | Description |
|---|---|
| `initNativePush(navigate)` | Initializes push after login: attaches FCM listeners, requests permission, and registers the device token with the backend |
| `unregisterNativePush()` | Deregisters the stored FCM token server-side; call before clearing local tokens at logout |
| `registerPushDevice(token)` | Internal — persists token to `localStorage` and upserts it via `registerPushDeviceMutation` |
| `unregisterPushDevice(token)` | Internal — removes the token via `unregisterPushDeviceMutation`; non-blocking on failure |
| `commitPushMutation<T>` | Internal — wraps `commitMutation` in a `Promise` for `async/await` usage |
| `pushPlatform()` | Maps Capacitor's platform string to the GraphQL `PushPlatform` enum; returns `null` on web |
| `PUSH_TOKEN_STORAGE_KEY` | `'native:push-token'` — `localStorage` key persisting the FCM token across sessions for logout-time deregistration |

## Usage Example

```typescript
// After successful login:
import { initNativePush, unregisterNativePush } from '@/lib/native-push';
import { useNavigate } from 'react-router-dom';

const navigate = useNavigate();

// Start push — requests permission if not yet granted, registers with backend.
await initNativePush((route) => navigate(route));

// On logout — must be called while still authenticated:
await unregisterNativePush();
```

## Notes

- **Init is idempotent** — the `initialized` guard prevents duplicate listener attachment across React re-renders or strict-mode double invocations.
- **Tap deep-linking** is restricted to routes beginning with `/`, preventing arbitrary URL redirects from push payloads.
- **Token rotation** is handled automatically — `tokenReceived` fires on every rotation and the backend mutation is an idempotent upsert.
- **All failures are non-fatal** — registration errors are logged as warnings; deregistration failures must not block logout.
