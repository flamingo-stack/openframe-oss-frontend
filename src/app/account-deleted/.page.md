Full-screen terminal page shown right after successful account self-deletion: OpenFrame logo, "Your account has been deleted" headline, organization-aware subtitle, "Powered by Flamingo" footer.

## Key Components

### `AccountDeletedPage`

- Lives **outside** the `(app)` and `(auth)` route groups: the visitor is signed out by the time it renders, so it must not sit behind the app layout's auth gate, and saas-tenant (web) blocks the entire `/auth` subtree.
- Performs the LOCAL sign-out on mount (forceLogout + seeding the session query with null), gated by `ACCOUNT_DELETED_PENDING_STORAGE_KEY` - doing it before navigation flashed "Sign in required"; the flag also keeps a direct visit from signing out a live session.
- Performs the LOCAL sign-out on mount (`forceLogout` + seeding the auth-session query with `null`), gated by `ACCOUNT_DELETED_PENDING_STORAGE_KEY` — doing it before the navigation landed flashed "Sign in required"; the flag also keeps a direct visit from signing out a live session. The server-side session revoke happens earlier, in the mutation.
- Reads the organization name from sessionStorage (`DELETED_ACCOUNT_ORG_STORAGE_KEY`, written by `useDeleteOwnAccount`) in a `useEffect` — not a state initializer — because the page is prerendered and a server/client mismatch would break hydration. Missing value degrades to "your organization".
- No navigation controls by design: the deletion flow `replace`s onto this URL, so Back lands on a guarded app route that redirects a signed-out visitor to sign-in.
