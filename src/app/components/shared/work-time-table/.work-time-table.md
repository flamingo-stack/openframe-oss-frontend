Paginated data table component for displaying and managing employee work time entries, including stat summary cards, date/search filtering, edit/delete actions, and Relay-based pagination.

## Key Components

### `WorkTimeTableData`
Internal Suspense-ready component that fetches data via `useLazyLoadQuery` + `usePaginationFragment` (Relay), maps GraphQL edges to `WorkTimeRow` objects, and renders the `DataTable` with stat cards.

### `buildColumns`
Factory function that composes column definitions (`ColumnDef<WorkTimeRow>[]`) based on visibility flags (`showEmployee`, `showCustomer`) and injects filter options and action callbacks (edit/delete) into the final column set.

### Column Definitions
Four static column definitions — `employeeColumn`, `timeColumn`, `customerColumn`, `ticketNotesColumn` — plus a dynamic `actionsColumn` built inside `buildColumns`.

### Key Interfaces
| Interface | Purpose |
|---|---|
| `WorkTimeRow` | Flattened row data including user, organization, ticket, and duration fields |
| `WorkTimeFilter` | GraphQL filter shape (employee IDs, org IDs, date range) |
| `QueryVars` | Full variable bag passed to the Relay query |

## Usage Example

```typescript
// Rendered inside a Suspense boundary; filter state lifted to parent
<Suspense fallback={<SkeletonRows />}>
  <WorkTimeTableData
    showEmployee={true}
    showCustomer={true}
    vars={{
      filter: {
        employeeIds: null,
        organizationIds: null,
        startedFrom: '2024-01-01',
        startedTo: '2024-01-31',
      },
      search: null,
      first: 20,
      after: null,
    }}
    fetchKey={0}
    onEdit={(row) => openEditModal(row)}
    onDelete={(row) => confirmDelete(row)}
    employeeFilterOptions={[]}
    customerFilterOptions={[]}
    columnFilters={[]}
    onColumnFiltersChange={setColumnFilters}
  />
</Suspense>
```

## Notes

- Date range params are persisted to URL search params via `useSearchParam` using `yyyy-MM-dd` format (`DAY_PARAM_FORMAT`).
- Stat cards (`TODAY TOTAL`, `PERIOD TOTAL`, `AVG. PER DAY`) are driven by `employeeTimeStats` on the query root.
- `makeDeleteTimeEntryUpdater` handles optimistic Relay store updates after deletion.
- Source: [`work-time-table.tsx`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/components/work-time-table.tsx)- The EMPLOYEE cell marks deleted users (via `useUserStatusMap`) with the shared `DeletedUserAvatar`.
