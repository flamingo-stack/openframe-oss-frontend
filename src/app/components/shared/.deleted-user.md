Shared building blocks for rendering deleted users (statuses `DELETED` / `SELF_DELETED`) across the app.

## Key Components

### `isDeletedUserStatus(status?)`

Case-insensitive check whether a user-status string means "deleted for display purposes" — true for `DELETED` (admin-deleted, revivable) and `SELF_DELETED` (anonymized). `REMOVED` (purged) users never appear in lists and are intentionally not handled.

### `DeletedUserAvatar`

Red round `UserXmarkIcon` placeholder shown instead of the avatar for deleted users (`bg-ods-error/20` circle + `text-ods-error` icon). Sizes mirror `SquareAvatar` buckets: `sm` 32 / `md` 40 / `lg` 48. A dedicated component because `SquareAvatar` has no icon slot — its only fallback is text initials.

### `DELETED_EMPLOYEE_LABEL`

`"Deleted Employee"` — display label for surfaces with no (or stale) user data of their own. Surfaces with fresh data keep showing it (real name for admin-DELETED, backend-anonymized for SELF_DELETED).

## Notes

- Consumers: settings employees list/details, tickets assignee cells, scripts initiator/author cells, worktime employee cell, KB article author.
- Status detection: GraphQL-fed surfaces read `User.status` straight from their payloads; only tickets still join through [`useUserStatusMap`](../../hooks/.use-user-status-map.md).
- Email rule: admin-`DELETED` users keep showing their real email; `SELF_DELETED` emails are synthetic and hidden everywhere (`isSelfDeletedUserStatus` / `isUserSelfDeleted`).
