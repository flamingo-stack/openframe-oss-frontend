A reusable confirmation dialog component built on `ModalV2` primitives, supporting destructive, warning, and default intent variants with async pending state management.

## Key Components

### `ConfirmDialog`
The single exported component. Wraps `ModalV2`, `ModalV2Header`, `ModalV2Footer`, and `Button` from the core UI library to produce a responsive modal (centered on desktop, bottom-anchored on mobile) with:

- **`variant`** — `'destructive'` (red), `'warning'` (yellow), or `'default'` (accent) controls confirm button color via `CONFIRM_VARIANT` map
- **`isPending`** — passes `loading` to the confirm `Button`, showing a spinner; the dialog stays open until the parent flips `open` to `false`
- **`extraContent`** — optional slot rendered between the description and footer (e.g. a command box or picker)
- **`pendingLabel`** *(deprecated)* — retained for backward compatibility; has no effect

### `CONFIRM_VARIANT`
Internal lookup table mapping dialog intent to a `Button` variant and optional `className` override. Typed against `ComponentProps<typeof Button>['variant']` to stay in sync with core library changes automatically.

## Usage Example

```typescript
import { ConfirmDialog } from './confirm-dialog';

function DeleteUserButton({ userId }: { userId: string }) {
  const [open, setOpen] = useState(false);
  const [isPending, setIsPending] = useState(false);

  const handleConfirm = async () => {
    setIsPending(true);
    await deleteUser(userId);
    setIsPending(false);
    setOpen(false);
  };

  return (
    <>
      <button onClick={() => setOpen(true)}>Delete User</button>
      <ConfirmDialog
        open={open}
        onOpenChange={setOpen}
        title="Delete user?"
        description="This action cannot be undone."
        confirmLabel="Delete"
        variant="destructive"
        isPending={isPending}
        onConfirm={handleConfirm}
      />
    </>
  );
}
```

> **Note:** The dialog never auto-closes on confirm — the parent is responsible for setting `open` to `false` after the async operation settles, keeping the pending spinner visible throughout.
