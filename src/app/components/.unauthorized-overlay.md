Full-screen overlay displayed when a user attempts to access a protected route without an active session, prompting them to sign in.

## Key Components

**`UnauthorizedOverlay`** — Default exported React component that renders a centered "Sign in required" screen with a single call-to-action button.

**`UnauthorizedOverlayProps`**

| Prop | Type | Description |
|------|------|-------------|
| `onRetry` | `() => void` (optional) | Fallback callback invoked when no `loginUrl` is configured and the app is not running in the native shell. |

**`handleLogin`** — Internal click handler with three routing strategies:

1. **Native shell** — uses `router.replace(routes.auth.root)` so the auth flow doesn't stack on the back-history.
2. **Auth host configured** — redirects `window.location.href` directly to the `/auth/login/` path of the configured auth host.
3. **Fallback** — calls `onRetry()` if provided.

## Usage Example

```typescript
// Render the overlay when an API call returns 401
function ProtectedPage() {
  const { data, error, refetch } = useSomeProtectedQuery();

  if (error?.status === 401) {
    return <UnauthorizedOverlay onRetry={refetch} />;
  }

  return <PageContent data={data} />;
}
```

## Notes

- Uses `isNativeShell()` to detect Electron/native wrapper environments and route accordingly.
- `router.replace` (not `push`) is intentional — prevents the login screen from appearing in the browser history after a successful sign-in.
- `loginUrl` is read from [`runtimeEnv`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/src/lib/runtime-config.ts) at render time, allowing dynamic auth host configuration without a rebuild.
