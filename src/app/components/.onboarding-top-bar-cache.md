Manages localStorage caching for the onboarding top bar banner, preventing layout shift when backend progress data loads after the initial shell render.

## Key Components

### Types

- **`OnboardingTopBarKind`** — Union type: `'initial-setup' | 'tour' | 'none'`. `'none'` is a valid cached state indicating onboarding is complete.
- **`CachedOnboardingTopBar`** — Cached state shape containing `kind` and `started` (controls CTA copy and width).

### Functions

- **`readCachedOnboardingTopBar()`** — Reads and validates the cached bar state from `localStorage`. Returns `null` on SSR, parse failure, or invalid `kind`.
- **`writeCachedOnboardingTopBar(next)`** — Persists bar state to `localStorage`. Skips write if value is unchanged; silently handles quota/private-mode errors.

### Component

- **`CachedOnboardingTopBar`** — Renders either `<InitialSetupBar>` or `<OnboardingTourBar>` based on cached state. Shared between the skeleton and live layout to prevent drift. Computes `showAction` from `pathname` using the same page rules as the loaded chrome.

## Usage Example

```typescript
// Writing cache after backend resolves
writeCachedOnboardingTopBar({ kind: 'initial-setup', started: false });

// Reading in the shell skeleton to reserve the top band
const cached = readCachedOnboardingTopBar();

// Rendering in both skeleton and live layout
<CachedOnboardingTopBar
  cached={cached}
  pathname={pathname}
  onStart={handleStartOnboarding}
/>
```

## Notes

- Storage key: `openframe:onboarding-top-bar-v1`
- Follows the same pattern as the tickets board-column cache and feature-flag snapshot — persisting a layout decision so the pre-data render matches the post-data render
- All reads are guarded against SSR (`typeof window === 'undefined'`)
