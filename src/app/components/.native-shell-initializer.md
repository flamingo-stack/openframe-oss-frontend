Initializes native shell integrations on the client side — token hydration, chrome setup, back-navigation, and OS notification routing — running once per page mount without blocking rendering.

## Key Components

| Export | Type | Description |
|---|---|---|
| `NativeShellInitializer` | React component | Headless component that bootstraps all native shell side effects; renders `null` |
| `clickListenerRegistered` | module-level flag | Guards `onNativeNotificationClick` registration to exactly once per page, surviving React re-mounts |

## Behavior

Runs only when `isNativeShell()` is truthy (no-op on web). On mount it:

1. Sets `data-native-shell="true"` on `<html>` to activate shell-specific CSS safe-area rules
2. Calls `initNativeChrome()` — configures status bar overlay and insets
3. Calls `initNativeBack()` — wires Android hardware/gesture back through overlay dismiss → SPA history → app exit
4. Calls `initTokenStore()` — hydrates Keychain tokens into memory early so the first API calls can attach a bearer token synchronously; hides the splash screen after hydration settles (also covers biometric unlock prompts on cold start)
5. Registers `onNativeNotificationClick` exactly once — maps the raw NATS envelope to an in-app route via `resolveNatsNotificationRoute`, falling back to `/notifications`

## Usage Example

```typescript
// app/layout.tsx — mount once at the root layout
import { NativeShellInitializer } from '@/components/native-shell-initializer';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <NativeShellInitializer />
        {children}
      </body>
    </html>
  );
}
```

> **Note:** The `clickListenerRegistered` module flag persists across React Strict Mode double-invocations and hot reloads, ensuring the native notification click handler is never registered more than once per page session.
