Resolves the current subscription status and publishes it to the tree via context and to the network layer via the subscription gate. One component, one hook — the status query, the lock state and the context all live in this file.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `SubscriptionGuard` | Component | Wraps the app shell: reads the `billings` flag, resolves the status, owns the context and the network gate |
| `useSubscriptionLock` | Hook | `{ status, isLocked, isResolved }`; resolved-and-unlocked when no guard sits above the caller |
| `useSubscriptionOpen` | Hook | `boolean` — may automatic (non-user-initiated) traffic go out? Fails closed and `console.error`s in dev when mounted above the guard |
| `SubscriptionStatusHydrator` | Component (internal) | Runs `subscriptionGuardQuery` inside a `Suspense fallback={null}` and reports the status up — a separate component only because `useLazyLoadQuery` suspends and cannot be called conditionally |

**Status resolution priority:**

1. `billings` flag `off` → `ACTIVE` (an answer, not an absence — nothing to lock)
2. `trialExpiredFromErrors` signal → `TRIAL_EXPIRED`
3. Query answer: `subscription == null` → `CANCELED`, otherwise `resolveSubscriptionStatus()`
4. Until one of the above lands, `null` — surfaced as `isResolved: false`, never as "unlocked"

## Usage Example

```typescript
// Wrap the app shell. Children render immediately and stay mounted — the guard
// never suspends them.
<SubscriptionGuard>
  <AppShell>{children}</AppShell>
</SubscriptionGuard>

// Consume the lock state downstream:
import { useSubscriptionLock } from './subscription-lock/subscription-guard';

const { isLocked, isResolved } = useSubscriptionLock();
```

**Background traffic:** mutations bypass the network gate by design, so a timer-driven mutation on a locked workspace fails on every interval — `PresenceHeartbeat` and `NativePushInitializer` therefore mount *below* the guard and ask `useSubscriptionOpen()` first. `useSubscriptionLock` is for UI that renders differently when locked; it must not be used to decide whether to send a request.

> **Design note:** no redirects, and no `Suspense` around `children`. The content swap happens in `AppLayout` off the context, which keeps rendering synchronous; suspending here used to mount the whole chrome twice per cold start. The tree shape below the guard is fixed for the same reason — only the (invisible) hydrator's presence varies.
