Resolves the current subscription status via a Relay GraphQL query and provides it to the component tree through `SubscriptionLockProvider`, enabling the app to react to locked/expired states without triggering redirects.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `SubscriptionGuard` | Component | Public wrapper that gates on the `subscription` feature flag and wraps the inner query component in `Suspense` |
| `SubscriptionGuardInner` | Component (internal) | Executes the `subscriptionGuardQuery` Relay query and feeds resolved status into context |
| `resolveGuardStatus` | Function (internal) | Merges server subscription status with client-side trial-expired error signal into a single `SubscriptionStatus` |

**Status resolution priority:**

1. `trialExpiredFromErrors` signal → `TRIAL_EXPIRED`
2. `subscription == null` → `CANCELED`
3. Server `subscription.status` → delegated to `resolveSubscriptionStatus()`

## Usage Example

```typescript
// Wrap your app shell or layout with SubscriptionGuard.
// Children receive subscription lock state via SubscriptionLockProvider context.

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <SubscriptionGuard fallback={<LoadingSpinner />}>
      <AppShell>{children}</AppShell>
    </SubscriptionGuard>
  );
}

// Consume lock state downstream via the context hook
import { useSubscriptionLock } from './subscription-lock-context';

function AppShell({ children }: { children: ReactNode }) {
  const { status } = useSubscriptionLock();

  if (status === SubscriptionStatus.TRIAL_EXPIRED) {
    return <TrialExpiredScreen />;
  }
  return <>{children}</>;
}
```

> **Design note:** `SubscriptionGuard` intentionally avoids redirects. Content swapping based on lock state is deferred to `AppShell` via context, preventing redirect races during SSR/hydration.
