A client-side React component that initializes deployment environment detection on app mount and exposes deployment metadata as HTML attributes for debugging and conditional styling.

## Key Components

### `DeploymentInitializer` (exported component)

A renderless component intended for root-level placement in the application tree. It consumes the `useDeployment` hook and performs two side effects once the deployment context is resolved:

1. **Console logging** — Logs the detected deployment details (`type`, `hostname`, `isCloud`, `isSelfHosted`, `isDevelopment`) to aid in runtime debugging.
2. **DOM attribute injection** — Sets `data-deployment` and `data-hostname` attributes on `<html>` for use in CSS selectors or external tooling.

Returns `null` — no UI is rendered.

## Usage Example

Place the component once at the application root (e.g., a layout file):

```typescript
// app/layout.tsx
import { DeploymentInitializer } from '@/components/deployment-initializer';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <DeploymentInitializer />
        {children}
      </body>
    </html>
  );
}
```

After initialization, the `<html>` element will reflect the deployment context:

```html
<html data-deployment="cloud" data-hostname="app.flamingo.run">
```

These attributes can then be targeted in CSS or end-to-end tests:

```css
[data-deployment="self-hosted"] .cloud-only-banner {
  display: none;
}
```

## Notes

- Requires the `useDeployment` hook (`@/app/hooks/use-deployment`) to supply `isInitialized` and `deployment`.
- The `document` guard (`typeof document !== 'undefined'`) ensures SSR safety, though the `'use client'` directive limits execution to the browser.
- Source: [`deployment-initializer.tsx`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/deployment-initializer.tsx)
