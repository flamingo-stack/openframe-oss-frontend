Renders the correct page-specific loading skeleton for the current route during the app shell's cold-start blocking phase, replacing a previously hardcoded dashboard skeleton with route-aware skeleton resolution.

## Key Components

### `RouteSkeletonProps`
Interface defining optional props passed to all route skeletons:
- `tab` — restores the deep-linked `?tab=` on detail pages
- `viewMode` — supports board/table view switch via `?viewMode=`

### `lazySkeleton(loader)`
Wraps `next/dynamic` to lazily load a skeleton component with `ssr: false` and a `null` interim fallback, preventing skeleton chunks from inflating the initial bundle.

### `ROUTE_SKELETONS`
A `Map<string, ComponentType<RouteSkeletonProps>>` of exact-path-to-skeleton entries covering all major routes (dashboard, devices, customers, tickets, scripts, settings, etc.). Exact matching is intentional — sibling routes like `/customers/new` and `/customers/details` are unrelated pages.

### `PREFIX_SKELETONS`
A fallback prefix-match array used only where a single skeleton covers an entire dynamic subtree (currently `/help-center/*`).

### `GenericPageSkeleton`
Fallback component rendering a `PageLayout` header in loading state plus three neutral content blocks — used for any route not listed in the registry.

### `resolveRouteSkeleton(pathname)`
Strips trailing slashes, attempts an exact `ROUTE_SKELETONS` lookup, then falls back to prefix matching, then `GenericPageSkeleton`.

### `RouteContentSkeleton`
The exported component. Reads `pathname` and `searchParams` via Next.js hooks and renders the resolved skeleton. Must be mounted inside a `Suspense` boundary.

## Usage Example

```typescript
// In a Suspense boundary within the app shell layout:
import { Suspense } from 'react';
import { RouteContentSkeleton } from './route-content-skeleton';

export function AppShellSkeleton() {
  return (
    <Suspense fallback={null}>
      <RouteContentSkeleton />
    </Suspense>
  );
}
```
