Supplies the `ChatRuntime` context required by `<EmbeddableChat>`, wiring up both Mingo (NATS) and Guide (SSE) transport modes with host-mode navigation, auth token management, and content URL routing for the OpenFrame frontend.

## Key Components

| Export / Symbol | Purpose |
|---|---|
| `OpenframeChatRuntimeProvider` | React provider component that builds and supplies `ChatRuntime` via `ChatRuntimeContext` |
| `CHAT_AUTH_ADAPTER` | Module-singleton `EmbedAuthAdapter` that attaches Bearer tokens (bearer mode) or cookies (`credentials: 'include'`) to every embedded chat request, with epoch-aware refresh |
| `CHAT_SOURCE` | Stable `'openframe'` namespace string for localStorage key scoping inside the lib |
| `lastChatSendEpoch` | Module-level variable tracking last token epoch at header-build time, used to avoid redundant token rotations on 401 |
| `navigate` callback | Host-mode navigation: in-page doc-tree swap → same-origin `router.push` (with hash smoothing) → cross-origin fallback (new tab) |
| `decideNewTab` callback | Origin-based tab decision; intentionally ignores `targetPlatform` to prevent hub-absolute URLs from resolving on the wrong origin |

## Usage Example

```typescript
// Wrap the chat-bearing subtree once, typically in a layout component:
import { OpenframeChatRuntimeProvider } from './openframe-chat-runtime-provider';

export default function HelpCenterLayout({ children }: { children: React.ReactNode }) {
  return (
    <OpenframeChatRuntimeProvider>
      {children}
    </OpenframeChatRuntimeProvider>
  );
}
```

> **Note:** The auth adapter (`CHAT_AUTH_ADAPTER`) and proxy-auth cleanup (`clearEmbedProxyAuth` / `setEmbedAuthAdapter`) are registered at **module load time** — before any child mount effects — so no additional setup is required. The provider handles both web (relative `/content/*` paths proxied by Next.js rewrites) and native shell (`CONTENT_ORIGIN`-absolutized) environments automatically.
