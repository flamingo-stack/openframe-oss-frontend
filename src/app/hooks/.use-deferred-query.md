Wraps React's `useDeferredValue` for table query variables (filters + search) to keep stale rows visible during a refetch instead of falling back to a Suspense boundary.

## Key Components

### `useDeferredQuery<F>(filters, search)`

Generic hook that defers both filter and search query variables. Returns a `UseDeferredQueryResult<F>` with:

| Field | Description |
|---|---|
| `deferredFilters` | Lagging copy of `filters` fed to the query |
| `deferredSearch` | Lagging copy of `search` fed to the query |
| `isPending` | `true` while either deferred value trails its live counterpart |

## Usage Example

```typescript
const { deferredFilters, deferredSearch, isPending } = useDeferredQuery(filters, search);

return (
  <div style={{ opacity: isPending ? 0.5 : 1 }}>
    {/* Pass deferred values to query — live values drive controls */}
    <DataTable filters={deferredFilters} search={deferredSearch} />
  </div>
);
```

## Notes

- **`filters` must be reference-stable per logical value** — build with `useMemo` (e.g. from `useApiParams`). `isPending` relies on identity (`!==`) comparison, so an unstable reference will never resolve to `false`.
- Live `filters` and `search` should still drive UI controls (checkboxes, inputs) directly so interactions remain instant.
- `isPending` guards against false empty-states: stale rows on screen are not "no data".
