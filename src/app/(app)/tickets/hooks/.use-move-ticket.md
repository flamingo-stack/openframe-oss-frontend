Provides a React Query mutation hook for moving and reordering tickets on a kanban-style board, with optimistic UI updates and rollback support.

## Key Components

### `MoveTicketParams`
Interface defining the parameters for a ticket move operation:
- `ticketId` — the ticket being moved
- `sourceStatusId` / `targetStatusId` — origin and destination columns
- `afterTicketId` / `beforeTicketId` — anchor tickets for ordering (`null` if none)

### `moveTicketRequest`
Internal async function that determines the correct API call:
- Cross-column move **without** an anchor → calls `transitionTicket`
- All other cases (reorder within column, or cross-column with anchor) → calls `reorderTicket`

Exactly **one** anchor is forwarded to `reorderTicket` — `afterTicketId` when the drop
has one, `beforeTicketId` otherwise. Sending both makes the backend rank strictly
between the two given ranks, which throws when they are equal; with one anchor it
resolves the opposite neighbour itself and cannot hit a tie.

### `useMoveTicket`
Primary mutation hook. Handles:
- **Optimistic update** via `applyOptimisticMove` before the request fires
- **Rollback** via `rollbackOptimisticMove` on error, with a destructive toast notification
- **Resync on settle** — `invalidateBoardColumns` re-reads the source and target lanes however the
  move ended. The optimistic state is a guess on failure (a failed `reorderTicket` may still have
  committed its status transition) and on success (another invalidation may have overwritten it
  mid-flight). Scoped to two lanes, not the whole board
- **Cache invalidation** on settle: always invalidates ticket detail; invalidates statistics only on cross-column moves

### `useMovingTicketIds`
Derives a `Set<string>` of ticket IDs currently in-flight for a move. Useful for disabling drag interactions or showing loading indicators on specific cards.

## Usage Example

```typescript
// Trigger a move
const { mutate: moveTicket } = useMoveTicket();

moveTicket({
  ticketId: 'ticket-123',
  sourceStatusId: 'status-todo',
  targetStatusId: 'status-in-progress',
  afterTicketId: 'ticket-456',
  beforeTicketId: null,
});

// Check if a ticket is currently being moved
const movingIds = useMovingTicketIds();
const isMoving = movingIds.has('ticket-123');
```

## Notes

- All moves share the mutation scope `'tickets-board-move'`, serialising concurrent drags to prevent race conditions.
- The mutation key `['tickets-board', 'move']` is shared between both hooks to correlate pending state without prop drilling.
