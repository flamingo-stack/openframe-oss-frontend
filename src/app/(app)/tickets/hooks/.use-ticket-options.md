A collection of React Query-based hooks and fetchers that provide autocomplete option data for ticket-related form fields, including organizations, devices, assignees, labels, and linked tickets.

## Key Components

### Interfaces
- **`AutocompleteOption`** — Base `{ label, value }` shape for dropdown options
- **`AvatarOption`** — Extends `AutocompleteOption` with an optional `imageUrl`
- **`TicketSearchOption`** — Extends `AutocompleteOption` with organization metadata derived from a linked ticket

### Hooks
| Hook | Source | Enabled condition |
|---|---|---|
| `useOrganizationOptions(search, enabled)` | `/api/graphql` (organizations) | Always (when `enabled`) |
| `useDeviceOptions(organizationId, search)` | `fetchDevicesPage` (shared device query layer) | Only when `organizationId` is set |
| `useAssigneeOptions(enabled)` | `/api/users` (REST) | Always (when `enabled`) |
| `useTicketLabelOptions()` | `/chat/graphql` (ticket labels) | Always |
| `useTicketSearchOptions(search, organizationId)` | `/chat/graphql` (tickets) | After statuses load |

### Utility
- **`customerOptionFromTicket(ticket)`** — Derives an `AvatarOption` for the customer/organization field directly from a `TicketSearchOption`, returning `null` if no organization is present

## Usage Example

```typescript
// Populate a ticket form with linked customer, device, and assignee dropdowns
function TicketForm() {
  const { options: orgOptions } = useOrganizationOptions('Acme');
  const [selectedOrg, setSelectedOrg] = useState<string>();

  const { options: deviceOptions } = useDeviceOptions(selectedOrg);
  const { options: assigneeOptions } = useAssigneeOptions();
  const { options: labelOptions } = useTicketLabelOptions();

  // Ticket search with auto-derived customer
  const { options: ticketOptions } = useTicketSearchOptions('login issue');
  const customerOption = customerOptionFromTicket(ticketOptions[0]);

  return <form>{/* render dropdowns */}</form>;
}
```

> **Note:** `useDeviceOptions` runs the same Relay document as the Devices page, but through the
> imperative `fetchDevicesPage` (`@/app/(app)/devices/queries/devices-api`) wrapped in react-query
> and keyed by `deviceQueryKeys.page(...)` — NOT the suspending `useDeviceList`. It re-queries on
> every keystroke, and a Suspense boundary would blank the open dropdown between characters;
> react-query keeps the previous options visible while the next search resolves. Scoped to
> `DEFAULT_DEVICES_LIST_STATUSES` (ONLINE/OFFLINE only), so the dropdown shows the same fleet the
> `/devices` table does.

> **Note:** `useTicketSearchOptions` automatically filters out `ARCHIVED` tickets by scoping the GraphQL query to non-archived status IDs fetched via `useTicketStatusesQuery`, with a client-side `kind !== 'ARCHIVED'` guard as a safety net.
- `fetchAssigneeOptions` filters out deleted users (`DELETED`/`SELF_DELETED`) — they are not assignable and are hidden from assignee pickers/filters.
