A React Query hook that fetches and caches a single ticket's full dialog detail by ID.

## Key Components

- **`useTicketDetail(ticketId)`** — Accepts an optional/nullable ticket ID string and returns the ticket detail state. The query is disabled when `ticketId` is falsy, using a stable placeholder query key to avoid cache collisions.

## Usage Example

```typescript
import { useTicketDetail } from '@/features/tickets/hooks/use-ticket-detail';

function TicketDetailPanel({ ticketId }: { ticketId: string | null }) {
  const { ticket, isLoading, isOffline, error, refetch } = useTicketDetail(ticketId);

  if (isLoading) return <Spinner />;
  if (error || isOffline) {
    return <LoadError {...loadErrorProps(isOffline, "Couldn't load this ticket.", () => refetch())} />;
  }
  if (!ticket) return null;

  return <DialogView dialog={ticket} />;
}
```

## Return Shape

| Field | Type | Description |
|---|---|---|
| `ticket` | `Dialog \| null` | Fetched ticket dialog data, or `null` if unavailable |
| `isLoading` | `boolean` | Initial fetch in flight. **Never true while paused** — see below |
| `isOffline` | `boolean` | No data and no link; render the offline copy, not a skeleton or a not-found |
| `error` | `string \| null` | Terminal failure with no data. Already normalized; render with a Retry |
| `hasData` | `boolean` | The record itself arrived — the only safe guard for a form prefill |
| `canClaimEmpty` | `boolean` | Data arrived and nothing is obscuring it; the precondition for "not found" |
| `refetch` | `function` | Manually re-triggers the query |

The last five come from `queryState` in `src/lib/query-state.ts`, which the hook spreads.

## Behavior Notes

- Query is **disabled** when `ticketId` is `null` or `undefined` — no network request is made
- Data is considered **fresh for 30 seconds** (`staleTime: 30_000`) before a background refetch is triggered
- Uses `ticketsQueryKeys.detail(ticketId)` for consistent cache key management across the tickets feature
- **Offline is a distinct phase, not "no ticket".** A paused query reports `isLoading: false`, `error: null` and no data, so a view that falls straight through to a not-found tells the user the ticket does not exist because their link is down. Gate on `isOffline` before that branch.
