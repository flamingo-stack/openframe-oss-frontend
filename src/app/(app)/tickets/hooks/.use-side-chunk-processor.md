Drives one side (client or admin) of a ticket's chat dialog by wiring NATS real-time chunk processing to the ticket details store, managing streaming state, tool executions, approvals, and message history for a single `ChatSide`.

## Key Components

### `useSideChunkProcessor(side, options)`

Primary export. Returns a `processChunk` function that consumers call with incoming NATS stream chunks.

**Parameters:**

| Parameter | Type | Description |
|---|---|---|
| `side` | `ChatSide` | `'client'` or `'admin'` — which dialog lane to drive |
| `assistantName` | `string` | Display name of the assistant |
| `assistantType` | `AssistantType` | Type classification for the assistant message |
| `userDisplayName` | `string?` | Display name for user-authored messages |
| `isDirectMode` | `boolean?` | Enables direct message routing |
| `onApprove` | `function?` | Called when an approval is granted |
| `onReject` | `function?` | Called when an approval is rejected |
| `onMetadata` | `function?` | Called with model/provider metadata on stream start |

### `isInProgress(segments)`

Internal helper. Returns `true` if any segment represents an in-flight tool execution, a pending approval request, or an incomplete approval batch — used to resume an existing assistant bubble rather than creating a new one.

## Usage Example

```typescript
const processChunk = useSideChunkProcessor('client', {
  assistantName: 'Mingo',
  assistantType: 'MINGO',
  userDisplayName: 'Jane Doe',
  onApprove: async (requestId) => {
    await approveAction(requestId);
  },
  onReject: async (requestId) => {
    await rejectAction(requestId);
  },
  onMetadata: ({ modelDisplayName, contextWindow }) => {
    console.log(`Using ${modelDisplayName} (${contextWindow} tokens)`);
  },
});

// Feed incoming NATS stream chunk
processChunk(incomingChunk);
```

## Notes

- Approval status updates are cross-synced to **both** sides (`client` and `admin`) since an approval resolved on one side must reflect in the other.
- Tool execution matching prefers `toolExecutionRequestId` for exact lookup across sides; falls back to side-scoped fuzzy matching to avoid collisions.
- `incompleteState` is recomputed when `messages` changes to allow the accumulator to correctly resume interrupted streams after async history loads.
