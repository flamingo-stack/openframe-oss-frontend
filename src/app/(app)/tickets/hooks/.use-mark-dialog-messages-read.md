Hook that resets the technicians' shared unread client-message counter of one dialog (`markDialogMessagesRead`, saas-ai-agent) and keeps the cached tickets board/table badge in step.

## Key Components

### `useMarkDialogMessagesRead(): (dialogId: string, ticketId: string) => Promise<void>`

- Zeroes `unreadMessageCount` for the ticket in every cached list/board-column page (`clearCachedUnreadMessages`) **before** the request and **again after** it (a column poll landing in between would have repainted the stale count).
- One request per dialog at a time; a call made while one is in flight runs once more after it, so a client message that landed between the server's reset and the response does not stay counted although it is on screen.
- On failure: `console.warn` + `invalidateQueries(dialogsQueryKeys.all)` so the optimistic zero does not outlive a rejected write. No toast - the user never triggered the write (same reasoning as `useMarkEntityNotificationsRead`), and the next client message or attention edge retries.

## Usage Example

```tsx
const markDialogMessagesRead = useMarkDialogMessagesRead();
useEffect(() => {
  if (clientChatOnScreen && dialogId) void markDialogMessagesRead(dialogId, ticketId);
}, [clientChatOnScreen, dialogId, ticketId, markDialogMessagesRead]);
```

## Notes

- Only caller today: `TicketNotificationsAutoReader`, which owns the on-screen / attention / once-per-message gating.
- The counter is shared by every technician (one admin side per dialog), so this clears the "New Message" badge for all of them; other technicians see it after their next poll (no live event).
