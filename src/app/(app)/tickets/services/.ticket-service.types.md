Defines the TypeScript contracts for the ticket service layer, including parameter shapes, paginated response types, and the `TicketService` interface that abstracts all ticket-related data operations.

## Key Components

### Interfaces

| Interface | Description |
|---|---|
| `TicketsPage` | Paginated response containing `Dialog[]`, cursor-based `pageInfo`, and a `filteredCount` |
| `MessagePage` | Paginated response containing `Message[]` with cursor-based `pageInfo` |
| `FetchTicketsParams` | Filter and pagination parameters for listing tickets (`statusIds` — lifecycle status ids resolved by callers, no enum fallback; search, org, assignee, tags, `unreadOnly`) |
| `FetchBoardColumnByStatusIdParams` | Scoped fetch params for a single kanban board column by `statusId` (same filters plus `activity?: TicketActivityFilter[]` — sent as `TicketFilterInput.activity`, OR within the list, AND with other params; empty list sends no filter) |
| `ReorderTicketParams` | Drag-and-drop reorder payload with before/after ticket anchors and an optional lifecycle `statusId` (always sent, even same-column — its presence selects lifecycle ranking over the legacy `status`-enum one) |
| `TicketStatusTransitionRule` | Maps a status id (`from`) to its allowed target status ids (`to`), plain strings from the API |
| `FetchMessagesParams` | Pagination and sort options for fetching messages within a dialog |
| `TicketService` | Main service contract — all ticket operations the UI layer depends on |

## Usage Example

```typescript
import type {
  TicketService,
  FetchTicketsParams,
  ReorderTicketParams,
} from './ticket-service.types';

// Inject or resolve your TicketService implementation
declare const ticketService: TicketService;

// Fetch open tickets with filters
const params: FetchTicketsParams = {
  statusIds: ['status-open'],
  assigneeIds: ['user-123'],
  limit: 25,
};
const { dialogs, pageInfo, filteredCount } = await ticketService.fetchDialogs(params);

// Reorder a ticket on the board
const reorderParams: ReorderTicketParams = {
  id: 'ticket-abc',
  afterTicketId: 'ticket-xyz',
  beforeTicketId: null,
  statusId: 'status-open',
};
const newStatus = await ticketService.reorderTicket(reorderParams);
```

## Notes

- `TicketService` is an interface, not a concrete class — implementations are injected, enabling easy mocking in tests.
- Status filtering is entirely id-based now: `statusIds`/`statusId` come from the lifecycle status snapshot; the old `BoardStatus`/`DialogStatus`-enum params are gone.
- `unreadOnly` is sent as `TicketFilterInput.hasUnreadNotifications: true` only — false/null mean "no filter".
- `activity` (board-column fetch) backs the board activity indicators feature (staleness filtering via `TicketActivityFilter` from `../types/dialog.types`).
- `transitionTicket`, `reorderTicket` (returns the new `DialogStatus`), and `fetchTicketStatusTransitionRules` cover board movement; `fetchChunks` integrates with `ChunkData` from `@flamingo-stack/openframe-frontend-core` for streaming/chunked message delivery.
