Orchestrates the tickets view by managing shared filter state and toggling between **board** and **table** display modes. URL search params are used as the single source of truth for all filter and view-mode values.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `TicketsView` | React component | Root view component that renders either `TicketsBoard` or `CurrentTickets` based on `viewMode` |

**Internal dependencies:**

- `useApiParams` — reads/writes filter state to URL search params
- `useSearchParam` — debounced (300 ms) local search state to avoid router re-renders on every keystroke
- `resolveTicketsViewMode` / `TicketsViewMode` — resolves the raw `viewMode` param (empty = board default) from `../utils/resolve-view-mode`
- `TicketActivityFilter` — activity-filter enum type from `../types/dialog.types`
- `TicketsBoard` — Kanban-style board view
- `CurrentTickets` — tabular tickets list view
- `TabSelector` — icon tab switcher rendered as a shared `selector` prop passed down to both views

## Usage Example

```typescript
// Drop into any page that needs the full tickets UI with URL-persisted filters
import { TicketsView } from './tickets-view';

export default function TicketsPage() {
  return <TicketsView />;
}
```

**Filter params managed in the URL:**

| Param | Type | Default |
|-------|------|---------|
| `status` | `string[]` | `[]` |
| `organizationIds` | `string[]` | `[]` |
| `assigneeIds` | `string[]` | `[]` |
| `tagIds` | `string[]` | `[]` |
| `unread` | `boolean` | `false` — written as `unread=true` or dropped (`setParam('unread', null)`), never `unread=false` |
| `activity` | `TicketActivityFilter[]` | `[]` — board activity filter; values mirror the server enum (`ACTIVE` / `STALE` / `AWAITING_EXTERNAL`), OR-ed together |
| `search` | `string` | `''` |
| `viewMode` | `string` | `''` — no default on purpose: an absent param stays distinguishable from an explicit `viewMode=table`; resolved to `'board' \| 'table'` via `resolveTicketsViewMode` |

> **Note:** Multi-param updates use `setParams` to write everything in a single URL snapshot, avoiding param clobbering from sequential `setParam` calls. Two atomic variants exist: `handleFiltersChange` (board — orgs/assignees/unread/activity) and `handleTableFiltersChange` (table — also carries the `status` filter). The child views speak `unreadOnly: boolean`; this component maps it to the `unread` URL param. The board additionally receives `activity`/`onActivityChange`; the activity filter is board-only.
