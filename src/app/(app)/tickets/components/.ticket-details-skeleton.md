Loading skeleton component for the ticket details page, matching both the classic two-chat layout and the new sidebar layout to enable seamless transitions while ticket data loads.

## Key Components

### `TicketDetailsSkeleton` (exported)
The main skeleton component rendered by Next.js route-level loading. Reads the `mingo-sidebar-context` feature flag via `skeletonFlagEnabled` to determine which layout to render before `FeatureFlagsGate` has the server's answer.

**Props:**
| Prop | Type | Description |
|------|------|-------------|
| `onBack` | `() => void` | Back button handler passed through to `PageLayout` |
| `showTechnicianChat` | `boolean?` | Selects classic vs. sidebar layout; defaults to flag value |

### `SidebarLayoutSkeleton` (internal)
Mirrors the new sidebar layout: a main chat pane with a right sidebar containing Ticket Details info, Attachments, and Tags sections. Desktop-only sidebar hidden on mobile via `lg:` breakpoint.

### `ClassicChatSkeleton` (internal)
Mirrors the legacy layout: a collapsed info bar row followed by two equal-width chat columns (client + technician). Uses `ChatMessageListSkeleton` in both columns.

### Constants
- `SIDEBAR_ACTIONS` — disabled "Edit Ticket" button for the sidebar layout header
- `CLASSIC_MENU_ACTIONS` — "Edit Ticket" behind the `…` menu for the classic layout
- `CLASSIC_ACTIONS` — empty array (Archive/Unarchive are status-dependent)

## Usage Example

```typescript
// app/tickets/[id]/loading.tsx
'use client';

import { useRouter } from 'next/navigation';
import { TicketDetailsSkeleton } from './ticket-details-skeleton';

export default function Loading() {
  const router = useRouter();
  return <TicketDetailsSkeleton onBack={() => router.back()} />;
}
```

> **Layout selection:** Pass `showTechnicianChat={false}` to force the sidebar layout in tests or Storybook, bypassing the feature flag read.
