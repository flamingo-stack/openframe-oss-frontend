Modal component (mobile-only on the board, every breakpoint on the table) that provides a buffered filter interface for ticket filtering by customer (organization), assignee and "New Messages Only" (plus status for the table view), preventing race conditions from sequential URL state writes.

## Key Components

### `TicketsFilterModal`
The primary exported component. Wraps `SimpleModal` with the filter controls and local state buffering — selections are held internally until the user explicitly applies or resets them.

**Props (`TicketsFilterModalProps`):**

| Prop | Type | Description |
|------|------|-------------|
| `isOpen` | `boolean` | Controls modal visibility |
| `onClose` | `() => void` | Callback to close the modal |
| `organizationIds` | `string[]` | Currently active organization filter values |
| `assigneeIds` | `string[]` | Currently active assignee filter values |
| `unreadOnly` | `boolean` | Currently active "New Messages Only" value (a `CheckboxBlock` after Assignee) |
| `status` | `{ value: string[]; options: StatusOption[] }?` | Table view only — adds the Status section |
| `onApply` | `(filters: { organizationIds; assigneeIds; unreadOnly; status? }) => void` | Flushes every filter atomically in a single call |

**Internal behavior:**
- Local state (`localOrganizationIds`, `localAssigneeIds`, `localUnreadOnly`, `localStatus`) is re-seeded from props on the open transition, during render (not in an effect)
- **Reset** calls `onApply` with empty arrays / `unreadOnly: false` and closes
- **Apply** calls `onApply` with current local selections and closes

## Usage Example

```typescript
<TicketsFilterModal
  isOpen={isFilterOpen}
  onClose={() => setFilterOpen(false)}
  organizationIds={activeOrgIds}
  assigneeIds={activeAssigneeIds}
  unreadOnly={activeUnreadOnly}
  onApply={({ organizationIds, assigneeIds, unreadOnly }) => {
    setSearchParams({ organizationIds, assigneeIds, unread: unreadOnly || null });
  }}
/>
```

## Notes

- The board renders its Customer/Assignee/New Messages controls inline on md+ and opens this only on mobile; the table has no inline surface for the "New Messages Only" checkbox, so its filter icon opens this on desktop too
- The `onApply` single-callback pattern avoids URL clobbering that would occur with two sequential writes (e.g., updating `organizationIds` then `assigneeIds` separately in a URL-based state manager)
