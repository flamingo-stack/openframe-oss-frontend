Headless React component that manages an infinite query for a single kanban board column, enabling a dynamic number of columns without violating React's rules of hooks.

## Key Components

### `BoardColumnSubscriber`
A renderless component (`return null`) that owns one column's `useInfiniteQuery` instance. Propagates query state upward via callbacks rather than rendering UI. Empty filter arrays and falsy flags are normalized to `undefined` before hitting `ticketService.fetchBoardColumnByStatusId`.

### `dedupeById`
Flattened pages are deduped by ticket id (first occurrence wins) — cursor pages can shift under live updates/reorders and return a ticket twice, which would give React duplicate keys and a second drag source for one card.

### `BoardColumnUpdate` (interface)
The update payload passed to `onUpdate`, containing:
- `state` — flattened `BoardColumnState` (tickets, total, cursor, pagination flags)
- `isLoading` — initial load indicator
- `error` — query error or `null`

### `BoardColumnSubscriberProps` (interface)
| Prop | Description |
|---|---|
| `statusId` | Identifies the board column / ticket status |
| `params` | Filter parameters (search, org, assignee, tags, `unreadOnly`, `activity` — `TicketActivityFilter[]` staleness/activity-state filter) |
| `onUpdate` | Callback fired whenever query state changes |
| `registerLoadMore` | Registers a `fetchNextPage` trigger with the parent board |

## Usage Example

```typescript
// Render one subscriber per column in the parent board component
columns.map(col => (
  <BoardColumnSubscriber
    key={col.statusId}
    statusId={col.statusId}
    params={{ search, organizationIds, assigneeIds, tagIds, unreadOnly, activity }}
    onUpdate={(statusId, update) => {
      setColumnStates(prev => ({ ...prev, [statusId]: update }));
    }}
    registerLoadMore={(statusId, loadMore) => {
      loadMoreRefs.current[statusId] = loadMore;
    }}
  />
));
```

## Query Behavior

| Setting | Value |
|---|---|
| `staleTime` | 60 seconds |
| `gcTime` | 5 minutes |
| `refetchInterval` | 15 seconds |
| `retry` | 2 attempts, 1 s delay |

The query key (`dialogsQueryKeys.boardColumn`) is the same key targeted by `applyOptimisticMove`, ensuring optimistic updates in the cache are reflected immediately in the column.
