Manages a `localStorage` cache of the last-seen ticket board column layout, enabling the loading skeleton to render the correct number of lanes before tenant status data resolves.

## Key Components

### `CachedBoardColumn` Interface
Serializable column descriptor stored in `localStorage`. Contains `id`, `label`, `color`, `system` flag, and an optional `statusKey` for canonical system statuses.

### `readCachedBoardColumns(): CachedBoardColumn[] | null`
Reads and validates the cached column set from `localStorage`. Performs field-by-field validation (not spread) to prevent stale/corrupt blobs from injecting unexpected props into `BoardColumnDef` — specifically guarding `color` and `statusKey`, both of which reach downstream `.replace()` calls that throw on non-strings.

### `buildPlaceholderBoardColumns(): BoardColumnDef[]`
Returns the placeholder lanes used by both the route skeleton and `TicketsBoard` during the statuses query. Falls back to three system-status columns (`AI_ASSISTANCE`, `TECH_REQUIRED`, `RESOLVED`) on a cold profile. Sharing this builder between the skeleton and the board makes the handoff a visual no-op.

### `writeCachedBoardColumns(columns: CachedBoardColumn[]): void`
Persists the current column set to `localStorage`. Skips the write if the serialized value is unchanged (no-op) or if running server-side. Swallows quota/private-mode errors silently.

## Usage Example

```typescript
import {
  buildPlaceholderBoardColumns,
  writeCachedBoardColumns,
  type CachedBoardColumn,
} from './board-columns-cache';

// In the route skeleton — render lanes before data arrives
const placeholderColumns = buildPlaceholderBoardColumns();

// In TicketsBoard — after statuses resolve, persist for next visit
const columnsToCache: CachedBoardColumn[] = resolvedStatuses.map(s => ({
  id: s.id,
  statusKey: s.key,
  label: s.label,
  color: s.color,
  system: s.system,
}));
writeCachedBoardColumns(columnsToCache);
```
