A null-rendering side-effect component that marks every notification about one ticket read once that ticket's client chat is the pane on screen.

## Key Components

### `TicketNotificationsAutoReader({ ticketId, clientChatOnScreen })`

Renders `null`. Commits `markNotificationsReadForEntity(TICKET, ticketId)` through `useMarkEntityNotificationsRead`, then invalidates `dialogsQueryKeys.all` so the board and table `unreadNotificationCount` badges clear.

| Prop | Type | Description |
|---|---|---|
| `ticketId` | `string` | Raw ai-agent ticket id — the same id `Ticket.unreadNotificationCount` is keyed on. Not a Relay global id. |
| `clientChatOnScreen` | `boolean` | Whether the client chat pane is actually being shown. Derived by `TicketDetailsContent`, the only place that knows which of the page's two layouts is mounted. |

## Key Behaviors

- **Fires only when the chat is on screen.** The mutation is entity-scoped with no type filter, so it clears the ticket's chat-message notifications too. Those route to `?tab=chat` precisely so `notificationTargetsLocation` will not auto-read them from the Details tab — firing on mount would mark a customer's message read sight-unseen. Full contract on `useMarkEntityNotificationsRead`.
- **Feature-flag gated** on `notifications`, like every other consumer of notification data (`EntityViewAutoReader`, `UnreadCountsHydrator`). With the flag off nothing renders these counts, and the write is irreversible and cross-device.
- **Session gated** on `isSessionActive({ idleAfterMs: ATTENTION_IDLE_MS })`, re-running on the `subscribeSessionActivity` edge, so a tab the browser restored into the chat with nobody watching does not retract the user's phone banner.
- **Once per ticket per mount** (`markedReadTicketRef`), so returning to the chat does not re-invalidate the lists. Later arrivals fall to `EntityViewAutoReader`, which covers them because this fires only while the URL carries `tab=chat` — the very param a chat notification's route matches on.
- **Owns its own state** rather than living in `TicketDetailsContent`: the activity subscription ticks on every focus/blur, and holding it in the page component would re-render both chat lists and every info section each time the user alt-tabs.

## Usage Example

```tsx
// Inside TicketDetailsContent's returned fragment
const clientChatOnScreen = hasClientChat && mainTab === 'chat';

<TicketNotificationsAutoReader ticketId={ticketId} clientChatOnScreen={clientChatOnScreen} />
```

## Notes

- Known under-fire: with `showDetailsTabs` false the sidebar layout's desktop column renders the chat bare (`mainTab` stays `'details'`) while its mobile column shows tabs on Details. Both columns are mounted and only CSS picks one, so no boolean is correct for both without `matchMedia`. Under-firing leaves a badge up, which is the safe direction here.
