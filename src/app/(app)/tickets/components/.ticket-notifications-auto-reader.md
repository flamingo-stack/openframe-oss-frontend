A null-rendering side-effect component that marks every notification about one ticket read once that ticket's client chat is the pane on screen.

## Key Components

### `TicketNotificationsAutoReader({ ticketId, clientChatOnScreen })`

Renders `null`. Commits `markNotificationsReadForEntity(TICKET, ticketId)` through `useMarkEntityNotificationsRead`, then clears the ticket's `unreadNotificationCount` in the cached board/table pages and invalidates `dialogsQueryKeys.all`.

| Prop | Type | Description |
|---|---|---|
| `ticketId` | `string` | Raw ai-agent ticket id — the same id `Ticket.unreadNotificationCount` is keyed on. Not a Relay global id. |
| `clientChatOnScreen` | `boolean` | Whether the client chat pane is actually being shown. Derived by `TicketDetailsView`, the only place that knows which layout column the viewport is showing. |

## Key Behaviors

- **Fires only when the chat is on screen.** The mutation is entity-scoped with no type filter, so it clears the ticket's chat-message notifications too. Those route to `?tab=chat` precisely so `notificationTargetsLocation` will not auto-read them from the Details tab — firing on mount would mark a customer's message read sight-unseen. Full contract on `useMarkEntityNotificationsRead`.
- **Feature-flag gated** on `notifications`, like every other consumer of notification data (`EntityViewAutoReader`, `UnreadCountsHydrator`). With the flag off nothing renders these counts, and the write is irreversible and cross-device.
- **Session gated** on `isSessionActive({ idleAfterMs: ATTENTION_IDLE_MS })`, re-running on the `subscribeSessionActivity` edge, so a tab the browser restored into the chat with nobody watching does not retract the user's phone banner.
- **Once per ticket per mount** (`markedReadTicketRef`), so returning to the chat does not re-invalidate the lists. Later arrivals fall to `EntityViewAutoReader`.
- **Writes the badge rather than invalidating** (`clearCachedUnreadCount`). Invalidation only marks the board/table stale while they are unmounted behind this page, so navigating back painted the cached pages and the card kept its badge until the column's 15s poll. The count is known to be zero, so it is written into every cached `InfiniteData<TicketsPage>` under `dialogsQueryKeys.all`. Nothing else about those rows changes here, so there is no refetch to trigger.
- **Owns its own state** rather than living in the page component: the activity subscription ticks on every focus/blur, and holding it there would re-render the chat list and every info section each time the user alt-tabs.

## Usage Example

```tsx
// Inside TicketDetailsView
const clientChatOnScreen = hasClientChat && (mainTab === 'chat' || (useLgUp() === true && !showDetailsTabs));

<TicketNotificationsAutoReader ticketId={ticketId} clientChatOnScreen={clientChatOnScreen} />
```

## Notes

- `clientChatOnScreen` cannot be read off `?tab=` alone. A ticket with no description and no assigned items has nothing to put in a Details tab, so the desktop column renders the chat bare with `mainTab` still `'details'` — that is every ticket the AI dialog opens. The mobile column keeps its tabs there (the desktop sidebar's info/attachments/tags fold into them), so the two always-mounted columns disagree and only the breakpoint separates them. `useLgUp()` uses the same 1280px the core Tailwind preset gives `lg:`, and its `undefined` (viewport not yet known) reads as "not on screen", deferring the mark-read by a tick.
