Lazy-loads the `SimpleMarkdownRenderer` and `MarkdownEditor` components from `@flamingo-stack/openframe-frontend-core` using Next.js dynamic imports, disabling SSR to prevent server-side rendering issues with rich client-side markdown components.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `SimpleMarkdownRenderer` | Dynamic Component | Client-only markdown renderer, loaded lazily with no SSR |
| `MarkdownEditor` | Dynamic Component | Client-only markdown editor UI, loaded lazily with no SSR |

## Usage Example

```typescript
import { SimpleMarkdownRenderer, MarkdownEditor } from '@/components/lazy-markdown';

// Render markdown content (no SSR hydration issues)
function ArticleBody({ content }: { content: string }) {
  return <SimpleMarkdownRenderer content={content} />;
}

// Full markdown editing experience
function NoteEditor({ value, onChange }: { value: string; onChange: (v: string) => void }) {
  return <MarkdownEditor value={value} onChange={onChange} />;
}
```

## Notes

- Both components render `null` during loading via `loading: () => null`, avoiding layout shifts
- The `'use client'` directive ensures this module is never accidentally included in server bundles
- Props are typed directly from the source components via `ComponentProps<typeof ...>`, keeping types in sync without duplication
