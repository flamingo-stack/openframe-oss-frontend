Kanban-style board view for support tickets, rendering status-based columns with drag-and-drop movement, real-time updates, filtering, and approval handling.

## Key Components

### `TicketsBoard` (default export)
Main board component accepting filter props and orchestrating column state, ticket movement, and approval workflows.

### `toLaneDefinition(status)`
Converts a `TicketStatusDefinition` into a `CachedBoardColumn`, determining whether to use canonical status styling or backend-supplied color.

### `dialogToBoardTicket(dialog, isUserDeleted?)`
Maps a `Dialog` entity to a `BoardTicket` shape consumed by the `Board` UI component, including assignee avatar URLs and tags.

### `initialsOf(name)`
Derives up to two uppercase initials from a display name string.

## Key Behaviors

- **Column skeleton**: Uses `buildPlaceholderBoardColumns` while statuses load to prevent layout flash during navigation.
- **Lane caching**: After statuses resolve, persists lane definitions (not ticket data) to localStorage via `writeCachedBoardColumns`.
- **Transition rules**: Builds an `allowedFromColumns` map per status to enforce valid drag-and-drop moves.
- **Approval actions**: Inline approve/reject flow that optimistically clears `pendingApproval` in the React Query cache.
- **Unread highlighting**: `BoardTicket.hasNewMessage` is set from `Dialog.unreadNotificationCount > 0` (from `Ticket.unreadNotificationCount`), drawing the column-coloured border and "New Message" tag. The card carries no numeric badge — the exact count is shown on the table row instead.
