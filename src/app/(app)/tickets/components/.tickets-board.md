Kanban-style board view for support tickets, rendering status-based columns with drag-and-drop movement, real-time updates, filtering, and approval handling.

## Key Components

### `TicketsBoard` (default export)
Main board component accepting filter props and orchestrating column state, ticket movement, and approval workflows.

### `toLaneDefinition(status)`
Converts a `TicketStatusDefinition` into a `CachedBoardColumn`, determining whether to use canonical status styling or backend-supplied color.

### `dialogToBoardTicket(dialog, isUserDeleted?)`
Maps a `Dialog` entity to a `BoardTicket` shape consumed by the `Board` UI component, including assignee avatar URLs and tags.

### `initialsOf(name)`
Derives up to two uppercase initials from a display name string.

## Key Behaviors

- **Column skeleton**: `usePlaceholderBoardColumns` stands in while statuses load to prevent layout flash; after statuses resolve, lane definitions (not ticket data) persist to localStorage via `writeCachedBoardColumns`.
- **Transition rules**: builds an `allowedFromColumns` map per status from `useTicketStatusTransitionRules` to enforce valid drags.
- **Approval actions**: inline approve/reject flow that optimistically clears `pendingApproval` in the React Query cache and invalidates the ticket detail.
- **Take Over interception**: dragging an AI-worked ticket (`hasActiveAiDialog`: AI Handling lane + dialog still in AI mode) cross-column opens `TakeOverTicketModal`; the drop is HELD via `applyHeldMove` until confirmed (then replayed as a re-rank, or re-held in the modal-chosen lane) or released on cancel, with a `boardResetNonce` to resync the Board and a 5s settle timeout backstop after close.
- **Reopen interception**: with flag `ai-resolution` on, dragging OUT of the Resolved lane opens `ReopenTicketModal` instead of committing the move. The drop is HELD exactly like Take Over - both modals share one `heldMove` and the `confirmHeldMove` / `closeHeldModal` pair (confirm keeps the card in the chosen lane and replays the drop as a re-rank, cancel releases it).
- **AI-owned cards**: tickets in AI_ASSISTANCE lanes, plus Resolved tickets with `resolvedBy` AI_AGENT/END_USER, render no assign control; others get the plain `BoardAssigneePicker` - outside AI Handling the AI is already stopped, so assignment is a one-click change. Handed down via render-stable refs to keep card memoization effective.
- **Unread highlighting**: `BoardTicket.hasNewMessage` from `unreadNotificationCount > 0` draws the column-coloured border and "New Message" tag; the exact count lives on the table row.
- **"New Messages Only" filter**: `unreadOnly` `CheckboxBlock` in the filter grid and mobile modal; rides every `BoardColumnSubscriber`'s params and the Archive Resolved filter, so the archive count matches the filtered Resolved lane.
- **Card timestamp**: `createdAt` uses `statusUpdatedAt ?? createdAt` so a reopened ticket's "N ago" tracks the last lifecycle change.

## Usage Example

<TicketsBoard
  search={searchQuery}
  onSearchChange={setSearchQuery}
  organizationIds={selectedOrgIds}
  onOrganizationIdsChange={setOrgIds}
  assigneeIds={selectedAssigneeIds}
  onAssigneeIdsChange={setAssigneeIds}
  tagIds={selectedTagIds}
  onTagIdsChange={setTagIds}
  unreadOnly={unreadOnly}
  onUnreadOnlyChange={setUnreadOnly}
  onFiltersChange={({ organizationIds, assigneeIds, unreadOnly }) => applyAll(...)}
  selector={<ViewSwitcher />}
