Kanban-style board view for support tickets, rendering status-based columns with drag-and-drop movement, real-time updates, filtering, approval handling, take-over/reopen interception, and per-card activity indicators.

## Key Components

### `TicketsBoard` (named export)
Main board component accepting filter props and orchestrating column state, ticket movement, approval workflows, and the Take Over / Reopen modals.

### `toLaneDefinition(status)`
Converts a `TicketStatusDefinition` into a `CachedBoardColumn`, determining whether to use canonical status styling or backend-supplied color; system lanes carry a `SYSTEM_KIND_META` tooltip.

### `toBoardTicket(dialog, isUserDeleted?, activity?)` / `dialogToBoardTicket`
Maps a `Dialog` entity to a `BoardTicket` shape consumed by the `Board` UI component (assignee avatar URLs, tags, `pendingApproval`, `escalatedByUser`, `activity`). Cached per-dialog in a `WeakMap` keyed also by `isUserDeleted` identity and an activity value key (`kind|label`), so column ticks don't re-render unchanged cards.

### `applyHeldMove(columns, move)`
Pure view transform re-seating a dropped ticket at its drop position while a Take Over modal is deciding (the drop persists nothing, so without this the card snaps back behind the modal).

### `initialsOf(name)`
Derives up to two uppercase initials from a display name string.

## Key Behaviors

- **Activity indicators**: `resolveBoardActivity(ticket, status, now)` (from `../utils/board-activity`) computes each card's `BoardTicketActivity` from `lastActivityAt`/`activityState`; a `useNow(60_000)` minute tick keeps staleness labels moving between the 15s column polls.
- **Activity filter**: `activity?: TicketActivityFilter[]` prop (active / stale / awaiting client, OR within the list) rendered by `ActivityFilter` in the md+ grid (now 4 columns: Customer / Assignee / Activity / New Messages Only) and carried in the mobile `TicketsFilterModal`; rides column-fetch params and the Archive Resolved filter, and suppresses the rich empty state when set.
- **Column skeleton**: `usePlaceholderBoardColumns` stands in while statuses load to prevent layout flash; after statuses resolve, lane definitions (not ticket data) persist to localStorage via `writeCachedBoardColumns`.
- **Transition rules**: builds an `allowedFromColumns` map per status from `useTicketStatusTransitionRules` to enforce valid drags.
- **Approval actions**: inline approve/reject flow that optimistically clears `pendingApproval` in the React Query cache and invalidates the ticket detail.
- **Take Over interception**: dragging an AI-worked ticket (`hasActiveAiDialog`) cross-column opens `TakeOverTicketModal`; the drop is HELD via `applyHeldMove` until confirmed (then replayed as a re-rank, or re-held in the modal-chosen lane) or released on cancel, with a `boardResetNonce` to resync the Board and a 5s settle timeout backstop after close.
- **Reopen interception**: with flag `ai-resolution` on, dragging OUT of the Resolved lane opens `ReopenTicketModal` instead of committing the move.
- **AI-owned cards**: tickets in AI_ASSISTANCE lanes, plus Resolved tickets with `resolvedBy` AI_AGENT/END_USER, render no assign control; others get `BoardAssigneePicker` (with take-over path when AI is active). Handed down via render-stable refs to keep card memoization effective.
- **Unread highlighting**: `BoardTicket.hasNewMessage` from `unreadNotificationCount > 0` draws the column-coloured border and "New Message" tag; the exact count lives on the table row.
- **"New Messages Only" filter**: `unreadOnly` `CheckboxBlock` in the filter grid and mobile modal; rides every `BoardColumnSubscriber`'s params and the Archive Resolved filter, so the archive count matches the filtered Resolved lane.
- **Card timestamp**: `createdAt` uses `statusUpdatedAt ?? createdAt` so a reopened ticket's "N ago" tracks the last lifecycle change.

## Usage Example

```typescript
<TicketsBoard
  search={searchQuery}
  onSearchChange={setSearchQuery}
  organizationIds={selectedOrgIds}
  onOrganizationIdsChange={setOrgIds}
  assigneeIds={selectedAssigneeIds}
  onAssigneeIdsChange={setAssigneeIds}
  tagIds={selectedTagIds}
  onTagIdsChange={setTagIds}
  unreadOnly={unreadOnly}
  onUnreadOnlyChange={setUnreadOnly}
  activity={activity}
  onActivityChange={setActivity}
  onFiltersChange={({ organizationIds, assigneeIds, unreadOnly, activity }) => applyAll(...)}
  selector={<ViewSwitcher />}
/>
```
