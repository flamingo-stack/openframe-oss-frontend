Helpers behind the technicians' shared "unread client messages" mark: which chat row re-arms it, and how the cached board/table badge is zeroed.

## Key Functions

| Function | Description |
|---|---|
| `lastClientMessageId(messages)` | Id of the newest row with `authorType === 'user'` (the END USER - both the persisted history and the live direct-message intercept stamp it), or `null`. Technician (`'admin'`) and assistant (`'fae'`) rows do not move it. A change in this id is the one signal that the read mark may be behind. |
| `clearCachedUnreadMessages(queryClient, ticketId)` | Sets `unreadMessageCount: 0` for the ticket in every `InfiniteData<TicketsPage>` cached under `dialogsQueryKeys.all` (lists and board columns). Written rather than invalidated so navigating back paints an already-cleared badge; caches that do not hold the ticket unread are returned as the same reference. |

## Usage Example

```ts
const newestClientMessageId = lastClientMessageId(clientMessages); // in TicketDetailsView
clearCachedUnreadMessages(queryClient, ticketId);                   // in useMarkDialogMessagesRead
```
