Scans paginated message history to find and return the AI model used by the most recent assistant message, providing per-chat model provenance for UI display.

## Key Components

### `latestAssistantModel(pages, modelsByProvider)`

The sole export. Iterates through `MessagePage[]` in newest-first order, returning the first `AiModel` it finds where the message owner is of type `ASSISTANT` with a valid `model` and `providerName`.

| Parameter | Type | Description |
|---|---|---|
| `pages` | `MessagePage[] \| undefined` | Paginated message history (newest-first) |
| `modelsByProvider` | `SupportedModelsByProvider \| undefined` | Provider/model map used to resolve a human-readable display name |

**Returns:** `AiModel | null` — `{ provider, displayName }` from the latest assistant message, or `null` if no assistant message with model data is found.

## Usage Example

```typescript
import { latestAssistantModel } from './latest-assistant-model';

const model = latestAssistantModel(messagePages, modelsByProvider);

if (model) {
  console.log(model.provider);     // e.g. "openai"
  console.log(model.displayName);  // e.g. "GPT-4o"
}
```

## Notes

- Designed for the **"current model" badge** rendered on chat reload — reflects the actual model used in that specific chat thread, not the tenant-wide AI configuration.
- Delegates display-name resolution to [`getModelLabelByName`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/(app)/settings/ai-settings/hooks/use-supported-models.ts) to keep label logic centralised.
- Returns `null` gracefully when `pages` is `undefined` (e.g. during initial data fetch).
