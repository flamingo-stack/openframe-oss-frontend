GraphQL query and mutation string constants for the ticket management domain, targeting the `openframe-saas-ai-agent` service via `/chat/graphql` (raw-POST domain — intentionally not Relay).

## Key Components

### Queries
| Export | Description |
|---|---|
| `GET_TICKET_QUERY` | Fetch a single ticket by ID with full detail (owner, notes, attachments, dialog + token usage, transitions, creationSource) |
| `GET_TICKETS_QUERY` | Paginated ticket list with cursor-based pagination, filtering, search, and `unreadNotificationCount` |
| `getBoardColumnTicketsQuery()` | Lifecycle board column tickets filtered by status, org, assignee, tags, `$hasUnreadNotifications`, and `$activity: [TicketActivityFilter!]` (board activity filter) — built per-call because the fragment is feature-flag-dependent |
| `GET_TICKET_STATUS_TRANSITION_RULES_QUERY` | Allowed status transition rules between ticket states |
| `GET_TICKET_TAGS_QUERY` | All available ticket tags |
| `GET_TICKET_ATTACHMENT_DOWNLOAD_URL` | Pre-signed download URL for a ticket attachment |
| `GET_TICKET_STATISTICS_QUERY` | Aggregate counts per status/kind, average resolution time and rating |

### Mutations
| Export | Description |
|---|---|
| `CREATE_TICKET_MUTATION` | Create a new ticket with owner, device, and org context |
| `UPDATE_TICKET_MUTATION` | Update ticket fields (title, description, tags, etc.) |
| `TRANSITION_TICKET_MUTATION` | Move a ticket to a new status via a defined transition |
| `REQUEST_TICKET_REOPEN_MUTATION` | Reopen a Resolved/Archived ticket with optional reason; returns `targetStatusKind`; idempotent |
| `TAKE_OVER_TICKET_MUTATION` | Atomic transition + assign + switch/create client dialog in DIRECT mode |
| `ASSIGN_TICKET_MUTATION` / `UNASSIGN_TICKET_MUTATION` | Manage ticket assignee |
| `REORDER_TICKET_MUTATION` | Update ticket sort order within a board column |
| `ADD_TICKET_NOTE_MUTATION` / `UPDATE_TICKET_NOTE_MUTATION` / `DELETE_TICKET_NOTE_MUTATION` | Manage internal ticket notes |
| `CREATE_TEMP_ATTACHMENT_UPLOAD_URL` / `DELETE_TEMP_ATTACHMENT` / `DELETE_TICKET_ATTACHMENT` | Attachment lifecycle management |
| `UNLINK_DEVICE_FROM_TICKET_MUTATION` / `UNLINK_ORGANIZATION_FROM_TICKET_MUTATION` | Detach linked device or organization |
| `ARCHIVE_RESOLVED_TICKETS_MUTATION` | Bulk-archive resolved tickets matching a filter |

### Internal Fragment
- `boardCardTicketFragment()` — builder for the `BoardCardTicket` fragment used by the board column query, including `pendingApproval` tool calls used by Mingo AI, `unreadNotificationCount`, and the board activity indicator fields `lastActivityAt` / `activityState`. Flag-conditional fields: `escalatedByUser` (`ai-escalation`) and `resolvedBy` (`ai-resolution`) are interpolated only when their flag is on, because an undeclared field fails validation for the whole document and empties every board column.

## Notable Behaviors
- `unreadNotificationCount` and `lastActivityAt`/`activityState` are selected unconditionally (no server flag exists), making them a deploy-ordering requirement: the saas-ai-agent exposing them must ship before this frontend, or board columns / tickets table / ticket picker come back empty (see the doc comment above the fragment).
- List/board queries sort by `order` ASC and return `filteredCount` plus cursor `pageInfo`.

## Usage Example

```typescript
import { GET_TICKET_QUERY, getBoardColumnTicketsQuery } from '@/app/(app)/tickets/queries/ticket-queries';
import { apiClient } from '@/lib/api-client';

const response = await apiClient.post('/chat/graphql', {
  query: getBoardColumnTicketsQuery(),
  variables: { statusId, limit: 20, activity: ['STALE'] },
});
```
