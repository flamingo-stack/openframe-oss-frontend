Provides React Query mutation hooks for creating, updating, reordering, and deleting custom ticket statuses via GraphQL, including a diff-based batch save algorithm.

## Key Components

### `useSaveTicketStatusesMutation`
Hook that diffs the current form state against a server snapshot and dispatches the minimal create → update → reorder sequence. Returns updated statuses with real server IDs replacing any temporary IDs.

### `useDeleteTicketStatusMutation`
Hook that deletes a single ticket status by ID, with optional reassignment of its tickets to a replacement status. Invalidates board/list queries on success.

### `saveTicketStatuses` (internal)
Core batch-save logic:
1. **Creates** — rows absent from the snapshot
2. **Updates** — persisted rows with changed `name` or `color`
3. **Reorders** — only when order changed or new rows were created

### `precedingSystemId` (internal)
Determines the system status anchor for reordering: the system row immediately before the first custom status, or the row before the first `RESOLVED`/`ARCHIVED` status when no customs exist yet.

### `SaveTicketStatusesInput` / `DeleteTicketStatusInput`
Exported TypeScript interfaces for the respective mutation inputs.

## Usage Example

```typescript
// Saving (create/update/reorder in batch)
const { mutate: saveStatuses } = useSaveTicketStatusesMutation();

saveStatuses({
  customStatuses: formStatuses,   // current form state (may include temp IDs)
  snapshot: serverStatuses,       // last known server state for diffing
});

// Deleting with ticket reassignment
const { mutate: deleteStatus } = useDeleteTicketStatusMutation();

deleteStatus({
  id: 'status-id-to-remove',
  replacementStatusId: 'status-id-for-existing-tickets',
});
```

> **Note:** Deletes must be dispatched before saves when both are needed — the replacement status referenced during deletion must already exist on the server.
