Fetches and normalizes ticket status definitions via GraphQL, separating results into system and custom statuses sorted by fractional-index position.

## Key Components

### `TicketStatusesData`
Interface describing the query's return shape:
- `systemStatuses` — built-in statuses mapped to `SystemTicketStatus`
- `customStatuses` — user-defined statuses mapped to `CustomTicketStatus`
- `snapshot` — raw ordered `TicketStatusDefinition[]` for reference

### `useTicketStatusesQuery(options?)`
React Query hook that posts the `GET_TICKET_STATUSES_QUERY` GraphQL query to the API, extracts the response, sorts definitions by fractional-index position (bytewise comparison), and partitions them into system vs. custom statuses.

| Option | Type | Default | Description |
|---|---|---|---|
| `enabled` | `boolean` | `true` | Conditionally enables the query |

## Usage Example

```typescript
import { useTicketStatusesQuery } from './use-ticket-statuses-query';

function TicketStatusPicker() {
  const { data, isLoading } = useTicketStatusesQuery();

  if (isLoading) return <Spinner />;

  return (
    <>
      {data?.systemStatuses.map(s => (
        <StatusBadge key={s.id} status={s} />
      ))}
      {data?.customStatuses.map(s => (
        <StatusBadge key={s.id} status={s} />
      ))}
    </>
  );
}

// Disable until a condition is met
const { data } = useTicketStatusesQuery({ enabled: isAuthenticated });
```

## Notes

- Query is cached under `ticketsQueryKeys.statuses()` — results are shared across consumers without duplicate network requests.
- Fractional-index positions use bytewise string comparison (`<`/`>`), not locale-aware collation, preserving insertion-order semantics.
