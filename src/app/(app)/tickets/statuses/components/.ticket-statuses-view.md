Renders the full Ticket Statuses configuration page, allowing users to view, add, reorder, edit, and delete both system and custom ticket statuses within a form-based layout.

## Key Components

- **`TicketStatusesView`** — Main page component; orchestrates the form, drag-and-drop reordering, and delete confirmation flow
- **`createCustomStatus()`** — Factory function that generates a new `CustomTicketStatus` with a unique UUID and default color
- **`renderSystemRow()`** — Helper that renders a read-only `TicketStatusConfigRow` for system-managed statuses
- **`DeleteStatusDialog`** — Modal triggered when deleting a persisted custom status; prompts user to select a replacement status before confirming deletion
- **`TOP_KINDS`** — Set controlling display order; `AI_ASSISTANCE` and `TECH_REQUIRED` statuses render above custom statuses, remaining system statuses render below

## Usage Example

```typescript
// Rendered as a route-level page component (no props required)
// Internally uses useTicketStatusesForm() for all state and mutations

import { TicketStatusesView } from './ticket-statuses-view';

// In your route file:
export default function TicketStatusesPage() {
  return <TicketStatusesView />;
}
```

## Behavior Notes

- **Add**: Appends a new custom status to the field array without focusing
- **Delete (unpersisted)**: Removes immediately from the field array
- **Delete (persisted)**: Opens `DeleteStatusDialog` requiring a replacement selection; calls `deleteMutation` on confirm, then removes from array on success
- **Save**: Disabled until form is dirty or a save is in progress; triggers `form.handleSubmit`
- **Minimum enforcement**: Delete is disabled when `canDelete` is `false`, showing `"At least one custom status is required"`
