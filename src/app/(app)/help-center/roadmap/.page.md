Thin Next.js route component that mounts the shared `<RoadmapPage>` from the OpenFrame frontend core library, wiring it to the local `/content`-proxied API endpoints for the Help Center roadmap feature.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `RoadmapRoute` | Default export (React component) | Next.js page component rendering the pre-built `<RoadmapPage>` |

### Props passed to `<RoadmapPage>`

| Prop | Value | Purpose |
|------|-------|---------|
| `shell` | `false` | Disables the lib's own layout chrome (host app provides it) |
| `roadmapEndpoint` | `EP.roadmap` | API route for fetching roadmap items |
| `buildRefreshUrl` | `EP.roadmapById` | Factory for per-item refresh URLs |
| `voteApiEndpoint` | `EP.roadmapVote` | API route for submitting votes |
| `backButton` | `{ label, href }` | Navigation link back to the Help Center root |

## Usage Example

```typescript
// This file is a Next.js App Router page — no manual import needed.
// Route: /help-center/roadmap (or wherever the file is placed)

// To customise endpoints, update EP in the local endpoints file:
// EP.roadmap       → '/content/roadmap'
// EP.roadmapById   → (id: string) => `/content/roadmap/${id}`
// EP.roadmapVote   → '/content/roadmap/vote'
```

## Notes

- `shell={false}` delegates layout responsibility to the host app, avoiding double-wrapping with `PageLayout` chrome.
- All API calls are proxied through the local `/content` routes, keeping third-party credentials server-side.
