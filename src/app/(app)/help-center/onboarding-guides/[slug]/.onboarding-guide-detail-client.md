Client component that renders the detail view for a single onboarding guide, extracting the route slug from URL params and passing endpoint/path config to the shared library view.

## Key Components

### `OnboardingGuideDetailClient`

A config-only client component that bridges Next.js routing with the `OnboardingGuideDetailView` from `@flamingo-stack/openframe-frontend-core`. It reads the dynamic `slug` param from the URL and delegates all data fetching to the library view itself.

| Prop passed to view | Value | Purpose |
|---|---|---|
| `shell` | `false` | Renders without outer shell wrapper |
| `slug` | from `useParams` | Identifies the guide to fetch |
| `guideEndpoint` | `EP.onboardingBySlug` | API endpoint for guide lookup |
| `basePath` | `${HELP_CENTER_BASE}/onboarding-guides` | Base path for internal navigation |

## Usage Example

```typescript
// app/help-center/onboarding-guides/[slug]/page.tsx
import { OnboardingGuideDetailClient } from './onboarding-guide-detail-client';

export default function OnboardingGuideDetailPage() {
  return <OnboardingGuideDetailClient />;
}
```

The component requires no props — all configuration is resolved internally from route params and the shared `EP` / `HELP_CENTER_BASE` constants.

## Notes

- The `'use client'` directive is required because `useParams` is a client-side hook.
- Data fetching is owned entirely by `OnboardingGuideDetailView`; this component is intentionally config-only with no local state or effects.
- `slug` defaults to `''` to avoid undefined passing on initial render before params resolve.
