Client-side entry point for the release detail page that wires host-supplied data fetching and injected UI sections into the `ReleaseDetailPage` component from `openframe-frontend-core`.

## Key Components

| Export / Function | Description |
|---|---|
| `ReleaseDetailClient` | Main exported component; renders `ReleaseDetailPage` with all injected sections and endpoints |
| `useRelease` | Host-supplied data hook fetching a single release by slug via `embedAuthedFetch` with TanStack Query |
| `RoadmapSection` | Injected section rendering `RoadmapGrid` wired to voting/refresh endpoints |
| `VideoDisplaySection` | Injected section replacing the lib's multi-player default with a single tabbed `EntityVideoSection` |
| `DeliverySection` | Injected section rendering `DeliveryTable` rows for completed and in-progress delivery items |

## Usage Example

```typescript
// app/(app)/help-center/releases/detail/page.tsx
import { ReleaseDetailClient } from './release-detail-client';

export default function ReleasePage() {
  const slug = useSearchParams().get('slug') ?? '';
  return <ReleaseDetailClient slug={slug} />;
}
```

## Behavior Notes

- **`useRelease`** takes the `slug` the route page read from `?slug=` and passes it into `ReleaseDetailPage` as the host-controlled data hook. Queries are disabled until `slug` is defined; a non-OK response throws so the lib surfaces its own error state rather than crashing.
- **`VideoDisplaySection`** prevents the lib from mounting multiple independent video players by substituting a single `EntityVideoSection` with Full Video / Highlights tabs.
- **`DeliverySection`** gates rendering on data presence — returns `null` when no data is available, causing `ReleaseDetailPage` to skip the section entirely.
- All authenticated requests flow through `embedAuthedFetch` (bearer token in dev-ticket mode, `credentials: include`, 401-refresh-retry), keeping auth behaviour consistent with other help-center surfaces.
