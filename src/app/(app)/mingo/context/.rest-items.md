Renders paginated context item lists for Tickets, Policies, and Queries using TanStack Query suspense hooks, supporting server-side search and progressive loading within the Mingo AI chat context picker.

## Key Components

### Exported Components

| Component | Data Source | Pagination Strategy |
|---|---|---|
| `TicketItems` | `ai-agent` GraphQL (`/chat/graphql`) | Cursor-based infinite scroll |
| `PolicyItems` | Fleet REST (`getPolicies`) | Full fetch → client-side paging via `useClientPaging` |
| `QueryItems` | Fleet REST (`getQueries`) | Page/per_page offset infinite scroll |

### Internal Fetch Functions

- **`fetchTicketsPage(query, cursor)`** — Posts a GraphQL query with cursor pagination; maps edges to `ChatContextItem[]`
- **`fetchPolicies(query)`** — Fetches full policy list with optional server-side search filter
- **`fetchQueriesPage(query, page)`** — Fetches a single page of queries with offset pagination

All three throw on HTTP errors or GraphQL errors, triggering the caller's error boundary.

## Usage Example

```typescript
import { TicketItems, PolicyItems, QueryItems } from './rest-items';

// Inside a Suspense boundary (skeleton shown during load)
<Suspense fallback={<ContextPickerSkeleton />}>
  <TicketItems
    query="network"
    selectedKeys={selectedKeys}
    onToggle={handleToggle}
    atLimit={false}
  />
</Suspense>

<Suspense fallback={<ContextPickerSkeleton />}>
  <PolicyItems
    query=""
    selectedKeys={selectedKeys}
    onToggle={handleToggle}
    atLimit={true}
  />
</Suspense>
```

> All three components **must** be wrapped in a `<Suspense>` boundary — they suspend on initial load and throw to the nearest error boundary on failure. Query results are cached for 30 seconds (`staleTime: 30_000`).
