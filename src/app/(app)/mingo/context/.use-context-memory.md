Provides the `contextMemory` data for `EmbeddableChat` by surfacing the user's navigation context — the current view and recently visited entities — as a structured list with per-item removal support.

## Key Components

### `MingoContextMemory` (interface)

| Field | Type | Description |
|---|---|---|
| `items` | `ChatContextItem[]` | Ordered list: current open view first, then recent views newest-first |
| `onRemove` | `(item: ChatContextItem) => void` | Removes a single item from context memory via the store |

### `useMingoContextMemory` (hook)

Reads from `useMingoContextStore` to compose the `items` array and `onRemove` handler. The same `openView` / `recentViews` values are sent on every Mingo message, so the strip reflects exactly what the agent receives — no additional fetch required. Store refs are structurally compatible with `ChatContextItem` and are passed through unmapped.

## Usage Example

```typescript
import { useMingoContextMemory } from './use-context-memory';
import { EmbeddableChat } from '@flamingo-stack/openframe-frontend-core/components/chat';

function MingoChat() {
  const contextMemory = useMingoContextMemory();

  return (
    <EmbeddableChat
      contextMemory={contextMemory}
      // items: [currentTicket, ...recentViews]
      // onRemove: forgets a single entity from context
    />
  );
}
```

## Notes

- `openView` is prepended to `recentViews` when present, giving it visual priority in the strip
- `onRemove` delegates directly to `removeView` in the Mingo context store, keyed on `type:id` — matching the identifier the chat row passes back on dismiss
- Both `items` and the returned object are memoized to prevent unnecessary re-renders
