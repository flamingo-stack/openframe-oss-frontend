Defines and exports the ordered list of entity-context types surfaced in the Mingo AI chat context picker, mapping each MSP entity kind to its display label, backend mention marker, and lead icon.

## Key Components

### `MINGO_CONTEXT_ENTITY_TYPES`

An ordered array of `ChatContextEntityType` objects representing the eight supported entity kinds available for `@mention` context selection in the Mingo chat UI. Each entry contains:

| Field | Description |
|---|---|
| `type` | Backend discriminator from `CONTEXT_ENTITY_KIND` |
| `label` | Human-readable display name shown in the picker |
| `marker` | Short-form token from `CONTEXT_ENTITY_MARKER` used to commit `@marker:id` mentions |
| `icon` | 24px lead glyph rendered at the first-level picker list |

**Registered entity kinds (in display order):**

1. `DEVICE` — Device
2. `SCRIPT` — Script
3. `TICKET` — Ticket
4. `ORGANIZATION` — Customer
5. `USER` — User
6. `KB_ARTICLE` — Knowledge Article
7. `POLICY` — Policy
8. `QUERY` — Query

## Usage Example

```typescript
import { MINGO_CONTEXT_ENTITY_TYPES } from './context-sources';

// Pass the full list to the context picker component
<ChatContextPicker entityTypes={MINGO_CONTEXT_ENTITY_TYPES} />

// Look up a specific entity type's marker for mention tokenization
const deviceType = MINGO_CONTEXT_ENTITY_TYPES.find(
  (e) => e.type === CONTEXT_ENTITY_KIND.DEVICE
);
// → { type: 'device', label: 'Device', marker: '@dev', icon: <MonitorIcon /> }
```

## Notes

- Display order in this array controls the picker's first-level list order (Figma `31:28708`).
- The `marker` values correspond to the backend `MentionParser`'s expected token format; all eight kinds resolve server-side.
- Actual entity data for each type is fetched by per-type components (`relay-items`, `rest-items`, `batch-items`) dispatched via `renderMingoContextItems` — this file only defines the type registry.
