Self-fetching Relay mention chips that resolve raw database IDs to display names for GraphQL-backed entity types (devices, organizations, KB articles, and scripts).

## Key Components

### `GraphqlMentionChip` (exported)
The primary component. Accepts a `kind`, raw `id`, optional `icon`, and optional `fallbackLabel`. Wraps inner fetchers with `MentionErrorBoundary` and `Suspense` (skeleton shown during first fetch; `store-or-network` prevents re-fetch flashes on streaming remounts).

### Inner Fetcher Components
Three private components handle the three distinct fetch paths:

| Component | Query | Entity Types |
|---|---|---|
| `NodeInner` | `node(id:)` via `relayMentionChipsNodeQuery` | Device (`Machine`), Organization |
| `KbInner` | `knowledgeBaseItem(id:)` via `relayMentionChipsKbQuery` | KB Article |
| `ScriptInner` | `script(id:)` via `relayMentionChipsScriptQuery` | Script |

### `hrefFor`
Maps `ContextEntityKind` to a detail-page URL. Device and Organization routes use the raw DB id; KB Article and Script routes use the Relay global id.

### ID Encoding
Raw DB ids are re-encoded to Relay global ids via `ensureGlobalIdForType` (`base64("<Typename>:<rawId>")`). Already-global ids pass through unchanged. This is a temporary shim until the backend emits global ids end-to-end.

## Usage Example

```typescript
import { GraphqlMentionChip } from './relay-mention-chips';
import { CONTEXT_ENTITY_KIND } from '../context-types';
import { MonitorIcon } from 'lucide-react';

// Resolves a device by raw machineId, shows hostname/displayName
<GraphqlMentionChip
  kind={CONTEXT_ENTITY_KIND.DEVICE}
  id="abc123"
  icon={<MonitorIcon />}
  fallbackLabel="Unknown Device"
/>

// Resolves a KB article by its id
<GraphqlMentionChip
  kind={CONTEXT_ENTITY_KIND.KB_ARTICLE}
  id="kb-456"
  fallbackLabel="Untitled Article"
/>
```

On fetch failure or unresolvable name, falls back to a plain `MentionTag` displaying `fallbackLabel ?? id`.
