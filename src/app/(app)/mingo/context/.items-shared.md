Shared utilities and types for per-type context-item picker components, providing a common interface, search filtering, and client-side pagination for the Mingo AI chat context picker.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `MINGO_CONTEXT_PAGE_SIZE` | `const` | Default page size (`10`) shared across all context item sources |
| `ContextItemsProps` | `interface` | Props contract for per-type items components rendered via `ChatContextPickerConfig.renderItems` |
| `matches()` | `function` | Case-insensitive substring filter for client-side batch sources (scripts, users, policies) |
| `useClientPaging()` | `hook` | Incremental client-side pagination with automatic reset on source list change |

## Usage Example

```typescript
import {
  ContextItemsProps,
  matches,
  useClientPaging,
  MINGO_CONTEXT_PAGE_SIZE,
} from './items-shared';

function ScriptItems({ query, selectedKeys, onToggle, atLimit }: ContextItemsProps) {
  const allScripts = useScripts(); // fetch via relay / TanStack

  const filtered = allScripts.filter(s => matches(s.name, query));

  const { items, hasMore, loadMore } = useClientPaging(filtered);

  return (
    <ContextItemsList
      items={items}
      selectedKeys={selectedKeys}
      onToggle={onToggle}
      atLimit={atLimit}
      hasMore={hasMore}
      onLoadMore={loadMore}
    />
  );
}
```

## Notes

- `useClientPaging` uses the [adjust-state-during-render](https://react.dev/learn/you-might-not-need-an-effect#adjusting-some-state-when-a-prop-changes) pattern to reset the page count when `all` changes, avoiding an extra render flash.
- Intended exclusively for **batch-loaded** sources; server-paginated sources should handle pagination in their own fetch hooks.
