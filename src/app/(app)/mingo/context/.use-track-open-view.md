Tracks the currently open entity detail view in the Mingo context store, registering it on mount and rolling it into `recentViews` on unmount.

## Key Components

- **`TrackOpenViewInput`** — interface describing the entity to track (`type`, `id`, `label`, `description?`)
- **`useTrackOpenView(ref)`** — hook that calls `setOpenView` when an entity resolves and `clearOpenView` when the component unmounts or the entity changes

## Usage Example

```typescript
// In a device detail page component
useTrackOpenView(
  device
    ? { type: 'DEVICE', id: device.id, label: device.hostname }
    : null // deferred until data resolves
);
```

## Behavior Notes

- Pass `null` or `undefined` while data is loading — tracking is skipped until a valid ref is provided
- Depends on primitive fields (`type`, `id`, `label`, `description`) rather than object identity to avoid spurious re-runs when the caller passes a new object reference each render
- On unmount, `clearOpenView` is called only for the specific `{ type, id }` pair, preventing a race condition where a newly mounted detail page has already claimed the open view slot during a route transition
- The cleared view is rolled into `recentViews` inside the store, feeding the context carried on every Mingo message
