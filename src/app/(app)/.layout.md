Root layout component for the app route group that wraps all child pages with the chat runtime context and main application shell.

## Key Components

- **`AppGroupLayout`** – Default export; a client-side layout component that composes the chat runtime provider and app shell around page children.
- **`OpenframeChatRuntimeProvider`** – Supplies the `ChatRuntime` context consumed by the embedded chat drawer. Supports both Guide (SSE via `/guide` proxy) and Mingo (NATS → OpenFrame backend) modes simultaneously, toggled via an in-panel control.
- **`AppLayout`** – Renders the full application shell (header, sidebar, main content area) with an integrated `AppLayoutDrawer` for the embeddable chat.
- **`getMainClassNameOverride`** – Computes a pathname-specific CSS class override for the `<main>` element, allowing per-route layout customization.
- **`APP_MAIN_CLASS_NAME`** – Default CSS class applied to the main content area when no route override is present.

## Usage Example

```typescript
// This layout is automatically applied to all routes within the (app) group.
// No manual instantiation is needed; Next.js picks it up via the file system.

// To add a new route under this layout, create a page at:
// app/(app)/my-route/page.tsx

export default function MyPage() {
  return <div>My page content, wrapped by AppGroupLayout automatically.</div>;
}
```

## Notes

- The embedded chat (`EmbeddableChat`) lives inside `AppLayout` as a drawer, keeping the header and sidebar interactive while chat is open — unlike a floating body-level button.
