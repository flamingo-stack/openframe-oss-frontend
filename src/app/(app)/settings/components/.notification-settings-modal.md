A modal dialog component for viewing and updating user push notification settings, using Relay for data fetching and mutation.

## Key Components

- **`NotificationSettingsModal`** — Main exported component that renders a `SimpleModal` containing a toggle switch for enabling/disabling push notifications
- **`NotificationSettingsModalProps`** — Interface defining `isOpen` (boolean) and `onClose` (callback) props
- **Push state management** — Uses `useState` with `null` as the initial/reset value to distinguish between "not yet loaded" and a real boolean preference
- **Relay integration** — Fetches current settings via `fetchQuery` with `store-or-network` policy on open; persists changes via `updateNotificationSettingsMutation` with a manual `updater` to re-link the root `notificationSettings` field (which lacks an `id` for automatic Relay cache merging)
- **Loading/saving states** — Shows a `Skeleton` placeholder while fetching; disables controls during save

## Usage Example

```typescript
import { NotificationSettingsModal } from '@/app/components/notifications/notification-settings-modal';

function SettingsPage() {
  const [isOpen, setIsOpen] = useState(false);

  return (
    <>
      <Button onClick={() => setIsOpen(true)}>Notification Settings</Button>
      <NotificationSettingsModal
        isOpen={isOpen}
        onClose={() => setIsOpen(false)}
      />
    </>
  );
}
```

## Notes

- Settings are reset to `null` on close, ensuring fresh data is fetched each time the modal opens
- The Relay store updater manually re-links `notificationSettings` on the root because the type has no `id` field, preventing automatic cache reconciliation
- Toast notifications surface both fetch and mutation errors via `getErrorMessage`
