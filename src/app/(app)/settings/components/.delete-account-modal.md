"Confirm Deletion" modal for deleting your own account, opened from the profile-card kebab menu on `/settings`. One dialog, two variants switched on `useOwnerGate`.

## Key Components

### `DeleteAccountModal`

**Props (`DeleteAccountModalProps`):**

| Prop | Type | Description |
|---|---|---|
| `open` | `boolean` | Controls dialog visibility |
| `onOpenChange` | `(open: boolean) => void` | Callback for open state changes |

**Variants:**

- **Regular user** — permanent-deletion warning copy + Cancel / destructive "Delete Account".
- **Owner** — same copy plus a red `AlertTriangleIcon` banner and a mandatory **New Owner** select; the confirm button becomes "Transfer & Delete Account" and stays disabled until a successor is chosen (the backend 403s a delete while the caller still holds `OWNER`).

### `NewOwnerSelect` (internal)

Select of transfer candidates: `ACTIVE` users excluding the caller (via `useUsers(0, 1000)`), each rendered with a round `SquareAvatar` + display name. It is a separate component mounted only in the owner variant, so the users request fires only when actually needed.

## Notes

- Built on `SimpleModal` (not `ConfirmDialog`) because the owner variant needs a confirm button that is *disabled* — not just pending — until a new owner is selected.
- The actual API flow (optional transfer-ownership → delete self → logout → redirect to `/account-deleted`) lives in [`useDeleteOwnAccount`](.use-account-deletion.md); on success the modal never closes itself — the page under it is replaced.
- Closing is blocked while the mutation is pending; closing resets the selected new owner.
- The org name in the copy falls back to "your organization" when `user.organizationName` is empty.
