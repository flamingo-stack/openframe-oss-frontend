Route-level loading skeleton for the `/settings` page, mirroring the layout of `SettingsHub` to prevent content shift during data fetching.

## Key Components

| Export | Type | Description |
|---|---|---|
| `SettingsPageSkeleton` | React component | Full-page skeleton matching the settings hub layout |
| `MENU_CARD_KEYS` | `const` tuple | Keys for the six navigation card skeletons (`billing`, `ai`, `architecture`, `employees`, `api-keys`, `sso`) |

## Layout Structure

The skeleton renders three sections in the same spatial arrangement as the loaded page:

1. **Account card** — `h-40` full-width placeholder for the user-dependent account/profile card
2. **Navigation card grid** — responsive `1→2` column grid of six `88px` tall cards
3. **Log Out button** — `h-12 w-32` pill pushed to the bottom via `mt-auto`

## Usage Example

Drop directly into a Next.js `loading.tsx` file alongside the settings route:

```typescript
// app/settings/loading.tsx
export { SettingsPageSkeleton as default } from '@/app/settings/_components/settings-page-skeleton';
```

Or compose it as a suspense fallback:

```typescript
import { Suspense } from 'react';
import { SettingsPageSkeleton } from './_components/settings-page-skeleton';
import { SettingsHub } from './_components/settings-hub';

export default function SettingsPage() {
  return (
    <Suspense fallback={<SettingsPageSkeleton />}>
      <SettingsHub />
    </Suspense>
  );
}
```

## Notes

- Marked `'use client'` because `PageLayout` and `Skeleton` are client components from `@flamingo-stack/openframe-frontend-core`
- Spacing tokens (`--spacing-system-l`, `--spacing-system-xl`, etc.) mirror the real hub exactly, preventing layout shift on hydration
- Adding a new settings nav card requires a corresponding key added to `MENU_CARD_KEYS`
