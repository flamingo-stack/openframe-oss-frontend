A full-page detail view for displaying and managing a single employee's profile, including avatar, contact info, role, and status, with support for editing and deleting the record.

## Key Components

- **`EmployeeDetailsView`** — Main exported component. Accepts a `userId` prop, fetches user data, and renders the profile card within a `PageLayout` shell. Handles loading/error/not-found states and wires up delete and edit actions via a context menu.
- **`EmployeeSummarySkeleton`** — Loading placeholder that mirrors the profile card layout using `Skeleton` elements, preventing layout shift during data fetch.
- **`ProfileFieldSkeleton`** — Reusable skeleton for individual label/value pairs within the summary skeleton.

## Hooks & Side Effects

| Hook | Purpose |
|---|---|
| `useUser(userId)` | Fetches the employee record |
| `useDeleteUser()` | Mutation for deleting the user |
| `useUpdateProfile()` | Mutation for updating the current user's profile |
| `useTrackOpenView()` | Registers this employee as the active Mingo context entity |
| `useAuthStore` | Reads the current authenticated user to gate self-edit and delete |

## Usage Example

```typescript
// Rendered via dynamic route, e.g. /settings/employees/[userId]
import { EmployeeDetailsView } from '@/app/features/employees/components/employee-details-view';

export default function EmployeePage({ params }: { params: { userId: string } }) {
  return <EmployeeDetailsView userId={params.userId} />;
}
```

## Delete Guard Logic

The delete action is disabled when any of the following apply:

- The user holds the `owner` role
- The viewed user is the currently authenticated user (`isSelf`)
- The user's status is already `Deleted`

## Feature Flags

The `EmployeeWorkTime` section is conditionally rendered based on `featureFlags.timeTracker.enabled()`, keeping time-tracking UI hidden when the feature is inactive.
- Deleted users render a dedicated variant per design: red `DeletedUserAvatar`, Name + grey status tag (`DELETED` or `SELF DELETED`) only - the role row is dropped, and the email is shown for admin-`DELETED` users but hidden for `SELF_DELETED` (synthetic address); the Delete menu action is disabled for them.
