React Query hooks for fetching and mutating the client assistant appearance configuration (ClientView), including tenant-wide defaults and per-organization overrides.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `clientViewQueryKeys` | Object | Query key factory for cache scoping by `organizationId` |
| `useClientView` | Hook | Fetches the current `ClientView`; returns `null` when no record exists |
| `useUpdateClientView` | Hook | Saves a `ClientViewInput`; exposes `mutateAsync` for caller-controlled toast feedback |
| `useResetClientView` | Hook | Deletes a per-org override, reverting to the tenant-wide default |

## Usage Example

```typescript
// Fetch the tenant-wide default
const { view, isLoading } = useClientView();

// Fetch a specific org's override
const { view, isLoading } = useClientView('org_123');

// Save changes — feedback is owned by the caller
const { update, isPending } = useUpdateClientView('org_123', { invalidateOnSuccess: false });
await update({ assistantName: 'Fae', accentColor: '#FF5A36' });
// attach avatar here, then manually invalidate once

// Reset a per-org override back to tenant default
const { reset, isPending } = useResetClientView('org_123');
await reset();
```

## Notes

- `useUpdateClientView` accepts `invalidateOnSuccess: false` to prevent a premature refetch mid-avatar-upload that would flicker the preview; the caller is responsible for invalidating after the full save sequence completes.
- `toClientView` normalizes nullable GQL fields (`null` / `undefined`) into the canonical `ClientView` shape before returning data to consumers.
- All three hooks throw on both network-level errors and GraphQL `userErrors`, so the caller's `try/catch` or `onError` handler receives a single, unified error.
