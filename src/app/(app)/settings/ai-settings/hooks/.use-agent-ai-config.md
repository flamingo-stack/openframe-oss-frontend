React Query hooks for fetching and updating AI configuration settings for the Fae (client) and Mingo (admin) agents, communicating with the backend via GraphQL over the `/chat/graphql` endpoint.

## Key Components

| Export | Description |
|---|---|
| `agentAiConfigQueryKeys` | Query key factory for cache invalidation, scoped by `AgentType` |
| `useClientAiConfig` | Fetches tenant-wide AI config for the Fae (CLIENT) agent |
| `useAdminAiConfig` | Fetches tenant-wide AI config for the Mingo (ADMIN) agent |
| `useUpdateClientAiConfig` | Mutation hook to persist updated Fae AI config |
| `useUpdateAdminAiConfig` | Mutation hook to persist updated Mingo AI config |

Internal helpers `fetchAiConfig`, `useAiConfigQuery`, and `toAgentAiConfig` handle GraphQL fetching, query wiring, and GQL-to-domain type mapping respectively.

## Usage Example

```typescript
// Reading config
const { config, isLoading, error } = useClientAiConfig({ enabled: isReady });

if (config) {
  console.log(config.llmProvider, config.answerStyle);
}

// Updating config (callers own toast feedback)
const { update, isPending } = useUpdateClientAiConfig();

await update({
  llmProvider: 'OPENAI',
  providerModel: 'gpt-4o',
  answerStyle: 'CONCISE',
  customPrompt: null,
  quickActions: [],
});
```

Both query hooks return `{ config, isLoading, error, refetch }`. Both mutation hooks return `{ update, isPending }` where `update` is `mutateAsync`, allowing callers to compose multiple saves and surface a single combined toast. Cache is automatically invalidated on successful mutation; a CLIENT save additionally drops all `organization-client-ai-config` entries, because orgs on `inheritDefault` resolve their effective config from the tenant default.
