View-models and type definitions for the AI settings two-collection model, covering tenant-wide agent AI logic (`AgentAiConfig`) and client assistant appearance (`ClientView`), synchronized with `ai-settings.graphqls`.

## Key Components

| Export | Kind | Description |
|---|---|---|
| `AgentType` | Type | `'CLIENT'` (Fae) or `'ADMIN'` (Mingo) — identifies which assistant owns a config |
| `AIProvider` | Type (re-export) | LLM provider enum from the generated GraphQL schema |
| `ApplicationTheme` | Type | `'DARK'` \| `'LIGHT'` \| `'SYSTEM'` |
| `AnswerStyle` | Type | `'SHORT'` \| `'STANDARD'` \| `'DETAILED'` \| `'CUSTOM'` |
| `AiImage` | Interface | Image record with optional `id`, `imageUrl`, and perceptual `hash` |
| `AiQuickAction` | Interface | Chat chip shortcut with name, instructions, and optional icon metadata |
| `AgentAiConfig` | Interface | Full AI logic config for one agent — LLM provider, model, prompt, quick actions |
| `AgentAiConfigInput` | Interface | Partial mutation input for updating `AgentAiConfig` |
| `ClientView` | Interface | Assistant appearance record — name, avatar, theme, accent color; `organizationId === null` is the tenant-wide default |
| `ClientViewInput` | Interface | Partial mutation input for updating `ClientView` |
| `getDefaultAgentAiConfig()` | Function | Returns an unpersisted `AgentAiConfig` fallback (`id: ''`) for a given `AgentType` |
| `getDefaultClientView()` | Function | Returns an unpersisted `ClientView` fallback with `DARK` theme and Flamingo pink accent |

## Usage Example

```typescript
import {
  getDefaultAgentAiConfig,
  getDefaultClientView,
  type AgentAiConfigInput,
  type ClientViewInput,
} from '@/types/ai-settings';

// Seed local state when the backend returns null (first-time tenant setup)
const agentConfig = getDefaultAgentAiConfig('CLIENT');
const clientView  = getDefaultClientView(null); // null = tenant-wide default

// Partial input objects for GraphQL mutations
const configUpdate: AgentAiConfigInput = {
  llmProvider: 'ANTHROPIC',
  answerStyle: 'DETAILED',
  quickActions: [{ name: 'Reset password', instructions: 'Guide the user…' }],
};

const viewUpdate: ClientViewInput = {
  assistantName: 'Fae',
  applicationTheme: 'LIGHT',
  accentColor: '#F357BB',
};

// Detect whether a record has been persisted yet
if (!agentConfig.id) {
  // call createAgentAiConfig mutation instead of update
}
```

> **Note:** `id: ''` on both default objects is the convention signalling "not yet persisted" — consumers should branch on this to call a *create* mutation rather than an *update*.
