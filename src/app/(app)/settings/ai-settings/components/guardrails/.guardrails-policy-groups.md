Renders a labeled section for each policy group in a guardrails configuration, displaying a `PolicyConfigurationPanel` beneath each group heading.

## Key Components

- **`GuardrailsPolicyGroups`** — Main exported component that iterates over a `Map` of policy group names to permission categories, rendering each group with an `h5`-style label and its corresponding `PolicyConfigurationPanel`.
- **`GuardrailsPolicyGroupsProps`** — Interface defining the component's props:
  - `groups` — `Map<string, PermissionCategory[]>` mapping group names to their permission categories
  - `editMode` — Toggles editable state (defaults to `false`)
  - `onPolicyPermissionChange` — Callback fired when an individual policy permission level changes
  - `onCategoryPermissionChange` — Callback fired when a category-level permission changes

## Usage Example

```typescript
import { GuardrailsPolicyGroups } from './guardrails-policy-groups';

const policyGroups = new Map([
  ['Network Access', [{ id: 'cat-1', label: 'Firewall', policies: [...] }]],
  ['Data Management', [{ id: 'cat-2', label: 'Backups', policies: [...] }]],
]);

<GuardrailsPolicyGroups
  groups={policyGroups}
  editMode={true}
  onPolicyPermissionChange={(categoryId, policyId, level) => {
    console.log('Policy changed:', { categoryId, policyId, level });
  }}
  onCategoryPermissionChange={(categoryId, level) => {
    console.log('Category changed:', { categoryId, level });
  }}
/>
```

## Notes

- Both callback props default to a `noop` function, making them safely optional in read-only display contexts.
- Spacing between groups uses the design token `--spacing-system-l`; spacing within each group uses `--spacing-system-xxs`.
