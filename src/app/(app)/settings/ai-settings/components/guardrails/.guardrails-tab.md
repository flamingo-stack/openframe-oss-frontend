Renders the Guardrails configuration tab within the AI Settings layout, wiring a shared form ID to the `useGuardrailsEditor` hook and delegating save coordination to the parent layout's action bar.

## Key Components

- **`GUARDRAILS_FORM_ID`** — Exported constant (`'ai-settings-guardrails-form'`) used by the shared `AiSettingsLayout` save button to remotely submit this form via `id` targeting.
- **`GuardrailsTab`** — Main component that composes `useGuardrailsEditor` and `GuardrailsPanel` inside a `<form>` element.
- **`GuardrailsTabProps`** — Interface accepting `isEditMode` (controlled by the parent layout) and `onSaved` (callback invoked after a successful save to signal the parent to exit edit mode).

## Usage Example

```typescript
import { GuardrailsTab, GUARDRAILS_FORM_ID } from './guardrails-tab';

// Inside AiSettingsLayout — the Save button submits by form ID:
<button form={GUARDRAILS_FORM_ID} type="submit">
  Save
</button>

// The tab itself receives edit state from the parent:
<GuardrailsTab
  isEditMode={isEditMode}
  onSaved={() => setIsEditMode(false)}
/>
```

## Notes

- Save logic is fully encapsulated in `useGuardrailsEditor`; this component only calls `editor.save()` and forwards the result to `onSaved`.
- The `void` operator on the save promise is intentional — unhandled rejection is expected to be managed within the hook itself.
- Edit mode is **read-only** from this component's perspective; it is owned and toggled by the parent `AiSettingsLayout`.
