Mutation hook for deleting the signed-in user's own account, with the optional owner-transfer step and the post-deletion sign-out/redirect.

## Key Components

### `useDeleteOwnAccount()`

React Query mutation. `mutate({ newOwnerId? })`:

1. If `newOwnerId` is set — `POST /api/users/{newOwnerId}/transfer-ownership` (owner hands over the `OWNER` role; required because the backend 403s deleting a user who still holds it).
2. `DELETE /api/users/{selfId}` (reuses `deleteUserApi` from `use-users`) — backend marks the account `SELF_DELETED` and anonymizes personal data.

On success: stashes `user.organizationName` in sessionStorage under `DELETED_ACCOUNT_ORG_STORAGE_KEY` (for the `/account-deleted` page copy), `forceLogout({ shouldRedirect: false })`, seeds the auth-session query with `null`, and `router.replace(routes.accountDeleted)`.

On error: toast via `handleApiError`.

### `DELETED_ACCOUNT_ORG_STORAGE_KEY`

sessionStorage key (`of-deleted-account-org`) handing the organization name over to the standalone page after the session is destroyed.

## Notes

- Transfer + delete are sequential, not atomic: if the delete fails after a successful transfer, the caller has already become `ADMIN` and stays signed in; the recovery is retrying the deletion (now without a transfer step).
- No server-side logout call — after deletion the session is already invalid, so only local state is cleared.
- `router.replace` keeps the app out of history: Back from `/account-deleted` lands on a guarded app route, which bounces a signed-out visitor to the mode's sign-in surface.
