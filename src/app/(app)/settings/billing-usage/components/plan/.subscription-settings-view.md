Renders the subscription settings page, orchestrating product cards, plan-change comparison, and submit controls for both the "update existing subscription" and "new checkout" flows.

## Key Components

| Export / Symbol | Description |
|---|---|
| `SubscriptionSettingsView` | Public entry point; wraps content in `<Suspense>` with a skeleton fallback |
| `SubscriptionSettingsContent` | Inner component that fetches data via `useLazyLoadQuery` and drives all layout logic |
| `PRODUCT_DISPLAY` | Static config map (`OpenframeProduct → ProductDisplay`) defining UI labels, descriptions, and behaviour flags per product |
| `subscriptionSettingsViewQuery` | Relay GraphQL query fetching `billingPlan.products` and `subscription.products` |
| `ProductDisplay` | Interface describing per-product display metadata (title, description factory, labels, custom-amount flag) |

## Usage Example

```typescript
// Drop into any Next.js route that requires auth + active Relay environment
import { SubscriptionSettingsView } from './subscription-settings-view';

export default function SubscriptionSettingsPage() {
  return <SubscriptionSettingsView />;
}
```

## Behaviour Notes

- **Checkout vs. update flow**: when subscription status is `TRIAL`, `TRIAL_EXPIRED`, or `CANCELED`, changes are routed through Stripe Checkout (`needsCheckout = true`) rather than a mutation diff.
- **Billing-period alignment**: if any product card exposes a monthly/yearly toggle, all cards reserve that vertical space to stay aligned.
- **Plan-change summary**: `PlanChangeSummary` is only rendered in the update flow when at least one product comparison differs from the current plan (`isPlanChanged`).
- **Responsive submit bar**: desktop uses an inline flex row; mobile uses a `fixed` bottom bar (the app's `<main>` reserves `pb-20` for it).
