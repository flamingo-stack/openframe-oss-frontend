Provides two React hooks for managing Stripe test-clock operations (advance and reset) in dev/staging environments, using Relay mutations with full error handling and Relay store invalidation on success.

## Key Components

### `useAdvanceTestClock()`
Hook that commits the `advanceTestClock(days: Int!)` GraphQL mutation. On success, invalidates the entire Relay store (since billing state changes server-side outside the mutation payload) and calls an optional `onSuccess` callback with the new `frozenTime`. Handles both partial-error payloads (nullable field + `errors` array) and hard network/GraphQL errors via toast notifications.

**Returns:** `{ mutate(days, onSuccess?), isPending }`

### `useResetTestClock()`
Hook that commits the `resetTestClock` mutation, which deletes the Stripe customer. On success, invalidates the Relay store and fires an optional `onSuccess` callback. Guards against partial-error payloads that would otherwise silently report success.

**Returns:** `{ mutate(onSuccess?), isPending }`

### `extractGraphqlErrorMessage(err, fallback)`
Internal utility that strips Relay's verbose wrapper (`"No data returned for operation X, got error(s): ..."`) from GraphQL errors, surfacing only the backend's actual message in toast notifications.

## Usage Example

```typescript
function BillingTestPanel() {
  const { mutate: advance, isPending: advancing } = useAdvanceTestClock();
  const { mutate: reset, isPending: resetting } = useResetTestClock();

  return (
    <>
      <button
        disabled={advancing}
        onClick={() => advance(30, (frozenTime) => console.log('New time:', frozenTime))}
      >
        Advance 30 days
      </button>
      <button
        disabled={resetting}
        onClick={() => reset(() => console.log('Clock reset'))}
      >
        Reset clock
      </button>
    </>
  );
}
```

> **Note:** Both hooks are gated by the `test-clock` feature flag and should only be rendered in dev/staging environments.
