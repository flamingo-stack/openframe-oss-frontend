Loading skeleton for the Billing & Usage page that mirrors the real page's layout with `Skeleton` placeholders while data is being fetched.

## Key Components

| Component | Description |
|---|---|
| `BillingUsageSkeleton` | Main exported skeleton for the full Billing & Usage page |
| `InfoCardSkeleton` | Mimics a `DashboardInfoCard` with a real title, skeleton value, and optional progress ring |
| `StatCardSkeleton` | Mimics a `UsageStatCard` with real title/caption and a skeleton value |
| `Value` | Inline helper rendering a sized `Skeleton` for `BillingRow` value slots |

## Usage Example

Drop in as a `loading.tsx` or a suspense fallback for the Billing & Usage route:

```typescript
import { BillingUsageSkeleton } from './billing-usage-skeleton';

// app/settings/billing/loading.tsx
export default function Loading() {
  return <BillingUsageSkeleton />;
}
```

`InfoCardSkeleton` conditionally renders the circular progress ring via `withProgress` (defaults to `true`). Device Usage shows the ring; AI Usage (pay-as-you-go) omits it:

```typescript
<InfoCardSkeleton title="Device Usage" />                   // with ring
<InfoCardSkeleton title="AI Usage" withProgress={false} />  // without ring
```

## Notes

- Reuses [`BillingRow`, `SectionBlock`, `TestModeBanner`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/billing-section.tsx) from `billing-section` to keep structural parity with the real page.
- The invoices table loads through the shared `TableSkeleton`, driven by the same `INVOICES_TABLE_COLUMNS` layout the live `InvoicesHistory` table reads — so its loading state is identical to every other table's, and its header/column widths cannot drift from the loaded table.
- Back navigation is handled by `useSafeBack`, falling back to `routes.settings.root()`.
