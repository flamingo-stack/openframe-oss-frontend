Skeleton loading UI for the Subscription Settings page, rendering static copy and structural chrome immediately while server-derived option rows and pricing remain as placeholder skeletons.

## Key Components

| Export/Symbol | Description |
|---|---|
| `SubscriptionSettingsSkeleton` | Top-level exported skeleton page; wraps two `ProductCardSkeleton` instances inside a `PageLayout` with a disabled "Update Subscription" button |
| `ProductCardSkeleton` | Internal card skeleton mirroring `ProductSubscriptionCard` — renders real title, description, and "Packages" label; skeletonizes tier rows and prices |
| `RadioRow` | Internal row skeleton representing a single radio option — accepts optional static `label`/`subtitle` props and skeletonizes whatever is server-derived |

## Usage Example

Drop in as the `loading.tsx` or Suspense fallback for the subscription settings route:

```typescript
// app/settings/subscription/loading.tsx
import { SubscriptionSettingsSkeleton } from './subscription-settings-skeleton';

export default function Loading() {
  return <SubscriptionSettingsSkeleton />;
}
```

Or as an explicit Suspense boundary:

```typescript
import { Suspense } from 'react';
import { SubscriptionSettingsSkeleton } from './subscription-settings-skeleton';
import { SubscriptionSettingsPage } from './subscription-settings-page';

export default function Page() {
  return (
    <Suspense fallback={<SubscriptionSettingsSkeleton />}>
      <SubscriptionSettingsPage />
    </Suspense>
  );
}
```

## Notes

- Static copy (e.g. helper text, "Pay as you go", "Packages") is rendered for real to avoid layout shift once data loads.
- The number of skeleton tier rows is controlled by the `tierRows` prop on `ProductCardSkeleton` (defaults to `0`).
- Back navigation uses `useSafeBack` with `routes.settings.billingUsage` as the fallback route.
