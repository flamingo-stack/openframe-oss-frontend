Custom React hook that wraps a Relay GraphQL mutation for updating a subscription plan, handling success/error toasts and post-mutation navigation.

## Key Components

- **`updateSubscriptionMutation`** — Relay GraphQL mutation that calls `updateSubscription`, returning updated subscription fields (`status`, `startDate`, `currentPeriodEnd`, `cancellationEffectiveAt`, `pendingInvoices`) and any errors.
- **`useUpdateSubscription()`** — The exported hook that exposes a `mutate` function and an `isPending` loading flag.
- **`mutate(input: UpdateSubscriptionInput)`** — Commits the mutation; on success, shows a neutral success toast and redirects to the Billing & Usage settings route; on GraphQL-level or network errors, shows a destructive toast with the error message.

### Re-exports

- `PackageUpdateInput` — Type re-exported for consumers.
- `UpdateSubscriptionInput` — Type re-exported for consumers.

## Usage Example

```typescript
import { useUpdateSubscription } from './use-update-subscription';
import type { UpdateSubscriptionInput } from './use-update-subscription';

function ChangePlanButton() {
  const { mutate, isPending } = useUpdateSubscription();

  const handleUpgrade = () => {
    const input: UpdateSubscriptionInput = {
      packages: [{ id: 'pkg_pro', quantity: 1 }],
    };
    mutate(input);
  };

  return (
    <button onClick={handleUpgrade} disabled={isPending}>
      {isPending ? 'Updating…' : 'Upgrade Plan'}
    </button>
  );
}
```

## Behavior Notes

- **Upgrade vs. downgrade**: Upgrades may generate a pending invoice; downgrades do not. The success toast intentionally uses a neutral message directing users to the invoices list rather than asserting an invoice was created.
- **Navigation**: On success, the router pushes to `routes.settings.billingUsage`.
- **Error handling**: Both GraphQL-level errors (in `result.errors`) and network/runtime errors (`onError`) surface via the `destructive` toast variant.
