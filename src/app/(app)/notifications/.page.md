Entry point for the Notifications page route that gates rendering behind a feature flag, returning a 404 if notifications are disabled.

## Key Components

- **`NotificationsPage`** — Default export; client-side page component that checks the `notifications` feature flag before rendering the page view.
- **`featureFlags.notifications.enabled()`** — Runtime feature flag check; triggers `notFound()` to return a 404 response if the flag is off.
- **`NotificationsPageView`** — The actual page UI, rendered only when the feature flag is enabled.

## Usage Example

This component is automatically used by Next.js as the page route handler. No manual instantiation is needed. To control visibility, toggle the feature flag:

```typescript
// lib/feature-flags.ts (example)
export const featureFlags = {
  notifications: {
    enabled: () => process.env.NEXT_PUBLIC_NOTIFICATIONS_ENABLED === 'true',
  },
};
```

When the flag returns `false`, navigating to the notifications route will produce a 404. When `true`, `NotificationsPageView` is rendered.

## Notes

- The `'use client'` directive makes this a client component, meaning the feature flag is evaluated in the browser.
- For server-side flag evaluation (e.g., environment-based flags), consider moving the check to a server component or middleware.
- See [`NotificationsPageView`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/notifications/components/notifications-page-view.tsx) for the full page UI implementation.
