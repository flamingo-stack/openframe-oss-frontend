Route-level loading skeleton for the `/notifications` page, combining a tab bar placeholder with the real `NotificationsSection` component in its unhydrated (null `queryRef`) state to avoid duplicating skeleton markup.

## Key Components

- **`NotificationsPageSkeleton`** — Default export component that renders the full page skeleton, accepting an optional `tab` prop to display the correct section title and row variant (`'read'` for history, `'unread'` for active notifications)
- **`TAB_WIDTHS`** — Tuple of Tailwind width classes passed to `TabBarSkeleton` to approximate the real tab dimensions
- **`noop`** — Stable no-op callback satisfying the required `onSearchChange` prop without triggering re-renders

## Design Pattern

Rather than duplicating skeleton markup, this component leverages the fact that `NotificationsSection` already renders a skeleton state (`SectionTableSkeleton`) when `queryRef` is `null`. The skeleton page and the real page share the same loading UI automatically.

## Usage Example

```typescript
// app/notifications/loading.tsx (Next.js route-level loading file)
import { NotificationsPageSkeleton } from './notifications-page-skeleton';

export default function Loading() {
  return <NotificationsPageSkeleton />;
}

// With tab context (e.g., history tab loading state)
<NotificationsPageSkeleton tab="history" />
```
