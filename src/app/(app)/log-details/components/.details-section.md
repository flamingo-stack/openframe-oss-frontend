Renders a formatted JSON details panel for a log entry, parsing the `details` field if present or falling back to structured log metadata.

## Key Components

- **`DetailsSection`** — Client component that accepts a `LogEntry` and displays its details as pretty-printed JSON
- **`DetailsSectionProps`** — Interface requiring a `logDetails: LogEntry` prop
- **JSON parsing logic** — Attempts to parse `logDetails.details`; on failure or absence, constructs a structured object from core log fields (`toolEventId`, `eventType`, `toolType`, `severity`, `userId`, `deviceId`, `timestamp`, `ingestDay`, `message`). If raw parsing fails, the original string is preserved under `rawDetails`

## Usage Example

```typescript
import { DetailsSection } from './details-section';
import type { LogEntry } from '../../logs-page/types/log.types';

const log: LogEntry = {
  toolEventId: 'evt-001',
  eventType: 'alert',
  toolType: 'monitoring',
  severity: 'high',
  userId: 'user-123',
  deviceId: 'device-456',
  timestamp: '2024-01-15T10:00:00Z',
  ingestDay: '2024-01-15',
  message: 'Disk usage exceeded threshold',
  details: '{"diskUsage": 95, "threshold": 90}',
};

<DetailsSection logDetails={log} />
```

## Notes

- Handles three cases: valid JSON in `details`, missing `details`, and invalid/non-JSON `details` strings
- Output is rendered in a scrollable `<pre>` block with `whitespace-pre-wrap` and `break-words` to handle long values on small screens
