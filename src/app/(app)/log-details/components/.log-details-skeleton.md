Loading state skeleton component for the Log Details page, rendering animated placeholder elements that mirror the layout of the actual log details view during data fetching.

## Key Components

### `LogDetailsSkeleton` (exported)
Main skeleton component accepting an `onBack` callback. Renders the full log details page structure within `PageLayout` with a back button and selector placeholder.

### Internal Skeleton Sections

| Component | Purpose |
|---|---|
| `StatusTimestampSkeleton` | Status badge + timestamp placeholders |
| `LogSummaryCardSkeleton` | Card with title, type badge, and metadata placeholders |
| `DeviceInfoSkeleton` | Section header + `DeviceInfoSectionSkeleton` |
| `FullInformationSkeleton` | 7-row key/value table with connecting dividers |
| `DetailsSkeleton` | Multi-line content block (17 lines with indentation) |

## Usage Example

```typescript
import { LogDetailsSkeleton } from '@/app/components/log-details-skeleton';

function LogDetailsPage() {
  const router = useRouter();

  if (isLoading) {
    return <LogDetailsSkeleton onBack={() => router.back()} />;
  }

  return <LogDetailsContent data={logData} onBack={() => router.back()} />;
}
```

## Notes

- Uses `'use client'` directive — rendered client-side only
- `FULL_INFO_ROWS` and `DETAILS_LINE_WIDTHS` are static arrays defining skeleton proportions to approximate real content widths
- Skeleton widths are intentionally varied to create a natural, content-like appearance
- Depends on `Skeleton` and `PageLayout` from `@flamingo-stack/openframe-frontend-core` and the shared `DeviceInfoSectionSkeleton`
