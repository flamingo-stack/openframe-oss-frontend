Renders the full detail view for a single Knowledge Base article, handling article metadata display, status management (publish/unpublish/archive), and attachment downloads within a suspense boundary.

## Key Components

### `ArticleDetailsPage` (exported)
Root component wrapping content in a `Suspense` boundary with an animated skeleton fallback. Accepts a single `articleId` (Relay global ID) prop.

### `ArticleDetailsContent`
Core rendering logic. Responsibilities include:
- Fetching article data via `useKnowledgeBaseItem`
- Decoding the Relay global ID to a raw DB ID for Mingo AI context tracking (`useTrackOpenView`)
- Building conditional `actions` and `menuActions` based on article status (`DRAFT` | `PUBLISHED` | `ARCHIVED`)
- Orchestrating three modals: **Archive**, **Move to Folder**, and **Unarchive**

### `ArticleDetailsFallback`
Pulse-animated skeleton shown during Suspense loading.

### `STATUS_VARIANT`
Maps `ArticleStatus` to Tag colour variants (`success`, `warning`, `grey`).

## Usage Example

```typescript
// In a Next.js page:
import { ArticleDetailsPage } from '@/features/knowledge-base/components/article-details-page';

export default function Page({ params }: { params: { id: string } }) {
  return <ArticleDetailsPage articleId={params.id} />;
}
```

## Status-Driven Action Buttons

| Status | Primary Action | Menu Actions |
|---|---|---|
| `DRAFT` | Edit + Publish | Archive, Move to Folder |
| `PUBLISHED` | Edit | Archive, Move to Folder, Move to Draft |
| `ARCHIVED` | Unarchive | *(none)* |

## Notes
- `articleId` must be a **Relay global ID**; the component internally decodes it to a raw DB ID for Mingo context
- Calls `notFound()` if the fetched item is missing or not of type `ARTICLE`
- Source connection ID for cache invalidation is derived from article status (archive vs. standard listing connection)- Deleted authors (via `useUserStatusMap`) render `DeletedUserAvatar` + red author name.
