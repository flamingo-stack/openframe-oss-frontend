React hook for deleting a knowledge base folder via a GraphQL mutation, with optimistic Relay store updates and toast error notifications.

## Key Components

- **`deleteFolderMutation`** — GraphQL mutation (`useDeleteFolderMutation`) accepting a `DeleteFolderInput` with folder ID and children disposition strategy.
- **`FolderChildrenAction`** — Union type (`'MOVE' | 'ARCHIVE'`) controlling what happens to child items when the folder is deleted.
- **`DeleteFolderArgs`** — Interface defining the hook's delete parameters: folder `id`, `childrenAction`, optional `moveTargetFolderId`, Relay `connections` to update, and an optional `onCompleted` callback.
- **`useDeleteFolder`** — Primary export. Returns `deleteFolder` (the trigger function) and `isPending` (mutation in-flight state).

The Relay `updater` performs two store operations: removes the deleted node from each provided connection via `ConnectionHandler.deleteNode`, and filters it out of the flat `KNOWLEDGE_BASE_FOLDER_TREE_FIELD` linked records on the root.

## Usage Example

```typescript
import { useDeleteFolder } from './use-delete-folder';

function FolderActions({ folderId, connectionId }) {
  const { deleteFolder, isPending } = useDeleteFolder();

  const handleDelete = () => {
    deleteFolder({
      id: folderId,
      childrenAction: 'MOVE',
      moveTargetFolderId: 'parent-folder-id',
      connections: [connectionId],
      onCompleted: () => console.log('Folder deleted'),
    });
  };

  return (
    <button onClick={handleDelete} disabled={isPending}>
      Delete Folder
    </button>
  );
}
```

> **Note:** When `childrenAction` is `'ARCHIVE'`, `moveTargetFolderId` is automatically set to `null` regardless of the value passed in.
