Manages form state and avatar lifecycle for the customer appearance settings panel, handling deferred avatar uploads/removals that are committed only when a saved `ClientView` ID is available.

## Key Components

- **`useCustomerAppearanceForm(options)`** — Primary hook accepting a `ClientView` and returning form controls plus avatar management utilities
- **`pendingFileRef` / `pendingRemovalRef`** — Refs that stage avatar mutations until `commitAvatar()` is explicitly called, preventing premature writes against the wrong `ClientView` ID
- **`commitAvatar(clientViewId)`** — Async function that flushes staged avatar changes (upload or delete) to `/api/client-agent-settings/{id}/image`
- **`syncKey`** — Derived from `view.id` + `view.updatedAt` to re-sync form state and avatar whenever the underlying record changes

## Usage Example

```typescript
import { useCustomerAppearanceForm } from './use-customer-appearance-form';

function CustomerAppearancePanel({ view }: { view: ClientView }) {
  const {
    form,
    avatarUrl,
    handleAvatarChange,
    handleAvatarRemove,
    commitAvatar,
  } = useCustomerAppearanceForm({ view });

  const onSubmit = async (values: CustomerAppearanceFormValues) => {
    // Save form fields first, get back the persisted clientViewId
    const savedId = await saveAppearanceSettings(values);
    // Then flush any staged avatar change
    await commitAvatar(savedId);
  };

  return (
    <Form {...form}>
      <AvatarUpload
        src={avatarUrl}
        onFileSelect={handleAvatarChange}
        onRemove={handleAvatarRemove}
      />
      {/* ...other fields */}
    </Form>
  );
}
```

## Notes

- Avatar object URLs are eagerly revoked via `clearPreview()` to prevent memory leaks
- Form state auto-resets when `view.id` or `view.updatedAt` changes, discarding staged-but-uncommitted previews
- `commitAvatar` only performs a backend call if there is an actual pending change
