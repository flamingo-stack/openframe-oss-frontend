Renders the "AI-Assistant Appearance" block on the customer edit page, allowing per-customer overrides of the tenant-wide AI assistant appearance (name, theme, accent color, avatar) or inheritance of the global default.

## Key Components

### `CustomerAiAssistantAppearance`

A `forwardRef` component exposing an imperative `CustomerAppearanceHandle` to the parent "Save Customer" page. It owns no Save button — persistence is orchestrated externally via the ref handle.

### `CustomerAppearanceHandle` (ref interface)

| Method | Description |
|--------|-------------|
| `validate()` | Triggers form validation; resolves `true` when in "use default" mode or all fields are valid |
| `commit()` | Persists the override (or deletes it when "use default" is active) and refetches the cache |

### Key Behaviors

- **Toggle mode** — `CheckboxBlock` switches between inheriting the tenant default and editing a per-customer override
- **Confirm on reset** — switching back to "use default" when an override exists opens a `ConfirmDialog` before deleting it
- **Avatar coordination** — avatar upload (`commitAvatar`) is sequenced after the view update inside `commit()`, followed by a single cache invalidation to prevent preview flicker
- **Seeded once** — `useEffect` + `seededRef` seeds the toggle state only after the org record loads

## Usage Example

```typescript
const appearanceRef = useRef<CustomerAppearanceHandle>(null);

// On form submit:
const isValid = await appearanceRef.current?.validate();
if (isValid) {
  await appearanceRef.current?.commit();
}

// In JSX:
<CustomerAiAssistantAppearance
  ref={appearanceRef}
  organizationId="org_abc123"
/>
```
