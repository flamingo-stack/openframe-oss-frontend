Defines the Zod validation schema and TypeScript types for per-customer appearance overrides, scoped to the `ClientView` fields (name, theme, accent color) that organizations can customize — excluding tenant-wide AI logic configuration.

## Key Components

| Export | Type | Description |
|---|---|---|
| `customerAppearanceSchema` | `z.ZodObject` | Zod schema validating assistant name, application theme, and accent color |
| `CustomerAppearanceFormValues` | `type` | Inferred TypeScript type from the Zod schema |
| `getCustomerAppearanceDefaults` | `function` | Maps a `ClientView` object to default form values |

## Schema Fields

| Field | Validation |
|---|---|
| `assistantName` | Non-empty trimmed string |
| `applicationTheme` | Enum: `DARK`, `LIGHT`, or `SYSTEM` |
| `accentColor` | Hex color string matching `#RGB` or `#RRGGBB` |

## Usage Example

```typescript
import {
  customerAppearanceSchema,
  getCustomerAppearanceDefaults,
  type CustomerAppearanceFormValues,
} from './customer-appearance.types';

// Populate form defaults from an existing ClientView
const defaults: CustomerAppearanceFormValues = getCustomerAppearanceDefaults(clientView);

// Validate user-submitted form data
const result = customerAppearanceSchema.safeParse({
  assistantName: 'Mingo',
  applicationTheme: 'DARK',
  accentColor: '#F357BB',
});

if (!result.success) {
  console.error(result.error.flatten());
}
```

> **Note:** This schema covers only the appearance subset of `ClientView`. AI logic settings (provider, model, quick actions) are tenant-wide and cannot be overridden per organization.
