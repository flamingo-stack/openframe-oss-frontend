Defines and manages the tab configuration for the customer detail view, including stable wrapper components, visibility-gated AI tabs, and utility functions for resolving tab items by ID.

## Key Components

### Exported Constants
- **`CUSTOM_AI_ASSISTANT_TAB_ID`** — Stable tab ID (`'custom-ai-assistant'`) type-checked against the `CustomerDetailTab` route union
- **`CUSTOMER_GUARDRAILS_TAB_ID`** — Stable tab ID (`'customer-ai-guardrails'`) type-checked against the `CustomerDetailTab` route union

### Exported Functions
- **`getCustomerTabs(visibility)`** — Returns the visible tab list; appends AI assistant and/or guardrails tabs based on the `CustomerTabsVisibility` flags
- **`getCustomerTab(tabId)`** — Looks up a `TabItem` by ID from the full superset (including hidden tabs)
- **`getCustomerTabComponent(tabId)`** — Returns the React component for a given tab ID, or `null` if not found

### Types
- **`CustomerTabProps`** — Shared prop interface (`{ organization: CustomerDetails }`) passed into all tab wrapper components

## Usage Example

```typescript
import {
  getCustomerTabs,
  getCustomerTabComponent,
  type CustomerTabProps,
} from './customer-tabs';

// Build the visible tab list based on feature flags / customer config
const tabs = getCustomerTabs({
  showCustomAiAssistant: customer.hasCustomAppearance,
  showGuardrails: isSaasTenant && guardrailsEnabled,
});

// Resolve and render the active tab's component dynamically
const TabComponent = getCustomerTabComponent(activeTabId);
if (TabComponent) {
  return <TabComponent organization={customerDetails} />;
}
```

> **Note:** Tab wrapper components (`DevicesTab`, `TicketsTab`, etc.) are declared at module level — not inline — to keep stable function references across parent re-renders. This prevents React from unmounting/remounting the active tab and avoids `TabNavigation`'s internal effect from resetting the active tab during navigation transitions.
