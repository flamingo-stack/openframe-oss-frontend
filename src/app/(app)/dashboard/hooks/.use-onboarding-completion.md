Tracks onboarding step completion by aggregating data from multiple API sources — SSO providers, organizations, devices, and users — into a single status map.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `useOnboardingCompletion` | Hook (public) | Returns a `completionStatus` map and combined `isLoading` flag for all onboarding steps |
| `useActiveSsoProviderCount` | Hook (internal) | Fetches available SSO providers and counts how many have `enabled: true` |
| `useUsersCount` | Hook (internal) | Queries total user count via GraphQL |

### Completion Status Keys

| Key | Condition |
|-----|-----------|
| `sso-configuration` | At least 1 active SSO provider |
| `organizations-setup` | More than 1 organization |
| `device-management` | At least 1 device |
| `company-and-team` | More than 1 user |

## Usage Example

```typescript
import { useOnboardingCompletion } from './use-onboarding-completion';

function OnboardingChecklist() {
  const { completionStatus, isLoading } = useOnboardingCompletion();

  if (isLoading) return <Spinner />;

  return (
    <ul>
      {Object.entries(completionStatus).map(([step, done]) => (
        <li key={step}>
          {step}: {done ? '✅' : '⬜'}
        </li>
      ))}
    </ul>
  );
}
```

## Notes

- All internal queries are gated on `isAuthenticated` from `useAuthStore`
- SSO check performs two sequential API calls: list available providers, then fetch each provider's config individually
- `completionStatus` is memoized — only recalculates when any underlying count changes
- Depends on [`useDevicesOverview`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/(dashboard)/hooks/use-dashboard-stats.ts) and [`useCustomersOverview`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/(dashboard)/hooks/use-customers-overview.ts) for device and organization data
