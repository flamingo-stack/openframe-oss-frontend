Skeleton components for the dashboard's three overview sections (Devices, Tickets, Customers), designed to be pixel-identical to their loaded counterparts to eliminate layout shift during data fetching.

## Key Components

| Export | Description |
|---|---|
| `DevicesOverviewSkeleton` | Renders the Devices Overview section with a real header and 4 info-card skeletons (Online, Offline, Pending, Archived) |
| `TicketsOverviewSkeleton` | Renders the Tickets Overview section with real `TicketStatusTag` elements and value skeletons |
| `CustomersOverviewSkeleton` | Renders the Customers Overview section with a real header and 3 customer row skeletons |
| `InlineSkeleton` *(internal)* | Phrasing-valid `<span>` skeleton bar safe to nest inside `<p>` and heading elements |
| `InfoCardSkeleton` *(internal)* | Single `DashboardInfoCard` skeleton — real title, skeletal value/percentage/progress ring |
| `OverviewHeaderSkeleton` *(internal)* | Section header with real static title and unit, skeletal count |

## Design Principle

Static labels (section titles, card titles, ticket status tags, unit strings) are rendered as **real elements** — only query-dependent values (counts, percentages, progress rings, customer data) are replaced with skeletons. This keeps card heights pixel-identical between loading and loaded states.

## Usage Example

```typescript
// In a route-level loading.tsx
import {
  DevicesOverviewSkeleton,
  TicketsOverviewSkeleton,
  CustomersOverviewSkeleton,
} from './dashboard-skeletons';

export default function DashboardLoading() {
  return (
    <>
      <DevicesOverviewSkeleton />
      <TicketsOverviewSkeleton />
      <CustomersOverviewSkeleton />
    </>
  );
}

// Also used inline when a section is fetching its own data
function DevicesSection() {
  if (isLoading) return <DevicesOverviewSkeleton />;
  return <DevicesOverview data={data} />;
}
```

Both `loading.tsx` and per-section loading branches use the same components, ensuring the skeleton shown before route resolution is identical to the one shown during section-level fetches — eliminating any shape-shift flash between the two phases.
