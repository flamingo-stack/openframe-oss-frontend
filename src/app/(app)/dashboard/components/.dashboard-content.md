Renders the main dashboard page content, orchestrating all dashboard sections (onboarding, devices, tickets, and customers) with conditional rendering based on feature flags and app mode.

## Key Components

- **`DashboardContent`** — Default export. Top-level dashboard layout component that composes all dashboard sections.
- **`ONBOARDING_WRAPPER_CLASS`** — Shared CSS class string for onboarding block wrappers; uses `empty:hidden` to collapse automatically when inner content renders `null`.

### Conditional Logic

| Condition | Behavior |
|---|---|
| `featureFlags.newOnboarding.enabled()` | Renders `InitialSetupCard` (with `Suspense`) instead of legacy `OnboardingSection` |
| `isSaasTenantMode()` | Renders `TicketsOverviewSection` |
| `useInitialSetupActive()` | Dims and disables dashboard interaction while tenant initial setup is pending |

## Usage Example

Intended for dynamic import at the route level (e.g., `page.tsx`):

```typescript
import dynamic from 'next/dynamic';
import DashboardSkeleton from './dashboard-skeleton';

const DashboardContent = dynamic(
  () => import('./dashboard-content'),
  { loading: () => <DashboardSkeleton /> }
);

export default function DashboardPage() {
  return <DashboardContent />;
}
```

## Notes

- The onboarding wrapper is intentionally rendered **outside** `PageLayout` so it appears above the standard page chrome.
- The local `Suspense` boundary around `InitialSetupCard` prevents suspending queries (e.g., `useSuspenseQuery` in device setup steps) from bubbling up to route-level `loading.tsx` and re-flashing the full dashboard skeleton.
- Dashboard dimming (`opacity-40`, `pointer-events-none`) is tied exclusively to `useInitialSetupActive()`, ensuring it never appears without the setup card being visible.
