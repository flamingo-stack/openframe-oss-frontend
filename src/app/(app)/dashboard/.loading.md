Route-level loading state for the `/dashboard` page, rendering skeleton placeholders that match the layout of the fully-loaded dashboard to prevent layout shifts during navigation.

## Key Components

- **`DashboardLoading`** — Default export. Next.js `loading.tsx` convention component that displays skeleton UIs while dashboard data fetches resolve.
- **`isSaasTenantMode`** — Controls conditional rendering of `TicketsOverviewSkeleton`; tickets section only appears in SaaS tenant mode.
- **Skeleton components** — `DevicesOverviewSkeleton`, `TicketsOverviewSkeleton`, `CustomersOverviewSkeleton` mirror the shape of their real counterparts to ensure a seamless skeleton → data transition.

## Behavior Notes

- The onboarding block (`InitialSetupCard`) is intentionally **not** skeletoned — it renders nothing until its progress data loads.
- Uses `PageLayout` with the same spacing tokens (`--spacing-system-l`) as `DashboardContent`, ensuring zero layout shift between loading and loaded states.
- Wrapped in a `div` with `role="status"` and `aria-label` for accessibility.

## Usage Example

```typescript
// Next.js automatically renders this component during dashboard route transitions.
// No manual invocation needed — place this file at:
// app/dashboard/loading.tsx

// To test skeleton visibility, simulate a slow data fetch:
export default function DashboardLoading() {
  const showTickets = isSaasTenantMode();

  return (
    <div role="status" aria-label="Loading dashboard">
      <PageLayout className="px-[var(--spacing-system-l)] pb-[var(--spacing-system-l)]">
        <DevicesOverviewSkeleton />
        {showTickets && <TicketsOverviewSkeleton />}
        <CustomersOverviewSkeleton />
      </PageLayout>
    </div>
  );
}
```
