GraphQL query definitions for fetching log data, including filter options, paginated log listings, and detailed log entry retrieval.

## Key Components

| Export | Description |
|--------|-------------|
| `GET_LOG_FILTERS_QUERY` | Fetches available filter options (tool types, event types, severities, organizations) for log filtering UI |
| `GET_LOGS_QUERY` | Paginated log listing with cursor-based pagination (`first`/`after`) and full-text `search` support |
| `GET_LOG_DETAILS_QUERY` | Retrieves a single log entry's full details including raw `message` and structured `details` fields |

## Usage Example

```typescript
import {
  GET_LOG_FILTERS_QUERY,
  GET_LOGS_QUERY,
  GET_LOG_DETAILS_QUERY,
} from './logs-queries';

// Fetch available filters
const filtersResult = await graphqlClient.query({
  query: GET_LOG_FILTERS_QUERY,
  variables: { filter: { organizationId: 'org-123' } },
});

// Fetch paginated logs
const logsResult = await graphqlClient.query({
  query: GET_LOGS_QUERY,
  variables: {
    filter: { severity: 'ERROR', toolType: 'PSA' },
    first: 25,
    after: null,
    search: 'disk failure',
  },
});

// Fetch full details for a specific log
const detailsResult = await graphqlClient.query({
  query: GET_LOG_DETAILS_QUERY,
  variables: {
    logId: 'evt-abc123',
    ingestDay: '2025-01-15',
    toolType: 'RMM',
    eventType: 'ALERT',
    timestamp: '2025-01-15T14:32:00Z',
  },
});
```

> **Note:** `GET_LOG_DETAILS_QUERY` requires five identifying fields (`toolEventId`, `ingestDay`, `toolType`, `eventType`, `timestamp`) to uniquely locate a log entry — typically sourced from a row returned by `GET_LOGS_QUERY`.
