Skeleton loading state component for the Logs page route, rendering placeholder chrome that mirrors the real `PageLayout` structure — including title, a disabled Refresh button, search toolbar, and table skeleton — to prevent layout shift during data fetches.

## Key Components

- **`LogsPageSkeleton`** — Default exported function component that wraps `PageLayout`, `SearchBarSkeleton`, and `LogsTableSkeleton` inside the page's standard spacing container
- **`SKELETON_ACTIONS`** — Static `PageActionButton[]` array defining a disabled, non-interactive Refresh button used as the action chrome placeholder

## Usage Example

```typescript
// app/logs/loading.tsx  (Next.js route-level loading UI)
export { LogsPageSkeleton as default } from './logs-page-skeleton';
```

```typescript
// Or used explicitly in a Suspense boundary
import { Suspense } from 'react';
import { LogsPageSkeleton } from './logs-page-skeleton';
import { LogsPage } from './logs-page';

export default function Page() {
  return (
    <Suspense fallback={<LogsPageSkeleton />}>
      <LogsPage />
    </Suspense>
  );
}
```

> **Layout fidelity:** `LogsPageSkeleton` intentionally replicates the exact padding (`px`/`pb` via `--spacing-system-l`) and `PageLayout` props (`title="Logs"`, `actions`) used by the real page, ensuring zero cumulative layout shift (CLS) when the live content loads.
