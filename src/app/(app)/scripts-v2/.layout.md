Route guard layout component for the `/scripts-v2/*` route group that redirects unauthenticated or flagged-out users to the stable `/scripts` page when the `scripts-v2` feature flag is disabled.

## Key Components

- **`ScriptsV2Layout`** — Default export; a client-side layout component that wraps all `/scripts-v2/*` routes and enforces the `scripts-v2` feature flag gate.
- **`useFeatureFlagsStore`** — Zustand store subscription that reads the resolved server-side flag value once the store is hydrated.
- **`featureFlags.scriptsV2.enabled()`** — Env-var fallback used when the server has not yet returned a flag value, preventing a flash of unguarded content.

## Usage Example

```typescript
// Automatically applied to all routes under /scripts-v2/* via Next.js layout nesting.
// No manual usage required — place this file at:
// app/scripts-v2/layout.tsx

// To enable the feature, set the flag via the feature flags service or
// configure the env-var fallback:
NEXT_PUBLIC_FEATURE_SCRIPTS_V2=true
```

## Behavior

| Flag State | Result |
|---|---|
| `true` (server or env) | Renders `{children}` normally |
| `false` | Redirects to `/scripts` via `router.replace`, returns `null` |
| Loading (store not hydrated) | Falls back to env-var default; no content flash |

## Notes

- The `useEffect` + `router.replace` pattern ensures navigation is a **replace** (not push), so the guarded URL does not appear in browser history.
- Relies on `FeatureFlagsGate` higher up the tree to guarantee flags are loaded before this layout evaluates, eliminating a redirect flicker on direct navigation.
