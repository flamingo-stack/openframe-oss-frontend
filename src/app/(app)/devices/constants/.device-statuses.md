Defines device status constants and typed status arrays used throughout the frontend to control which devices appear in different views and queries.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `DEVICE_STATUS` | `const` object | Exhaustive enum-like map of all possible device statuses |
| `DeviceStatus` | `type` | Union type derived from all `DEVICE_STATUS` values |
| `DEFAULT_VISIBLE_STATUSES` | `const` array | Statuses shown in standard device views (`ONLINE`, `OFFLINE`, `PENDING`) |
| `DEFAULT_DASHBOARD_STATUSES` | `const` array | Statuses shown on the dashboard (adds `ARCHIVED` to visible set) |
| `DEFAULT_DEVICES_LIST_STATUSES` | `const` array | Statuses for the default device list view (`ONLINE`, `OFFLINE` only — excludes `PENDING`) |
| `DEVICE_ENRICHMENT_STATUSES` | `const` array | Statuses used when enriching monitoring/policy tables with device metadata (includes `ARCHIVED`) |
| `HIDDEN_DEVICE_STATUSES` | `const` array | Statuses excluded from all default views (`ARCHIVED`, `DELETED`) |
| `HiddenDeviceStatus` | `type` | Union type of hidden statuses |
| `DefaultVisibleStatus` | `type` | Union type of default visible statuses |

## Usage Example

```typescript
import {
  DEVICE_STATUS,
  DEFAULT_DEVICES_LIST_STATUSES,
  DEVICE_ENRICHMENT_STATUSES,
  type DeviceStatus,
} from '@/constants/device-statuses';

// Type-safe status comparison
function isOnline(status: DeviceStatus): boolean {
  return status === DEVICE_STATUS.ONLINE;
}

// Use in a device list query
const devices = await fetchDevices({
  statuses: DEFAULT_DEVICES_LIST_STATUSES, // ['ONLINE', 'OFFLINE']
});

// Use in an enrichment/monitoring context (keeps archived hosts enriched)
const enrichedDevices = await fetchDevices({
  statuses: DEVICE_ENRICHMENT_STATUSES, // ['ONLINE', 'OFFLINE', 'ARCHIVED']
});
```

## Notes

- `ARCHIVED` devices are intentionally excluded from `DEFAULT_VISIBLE_STATUSES` and have a dedicated `/devices/archive` page
- `PENDING` (still-enrolling) devices are included in `DEFAULT_VISIBLE_STATUSES` for filter UI availability but excluded from `DEFAULT_DEVICES_LIST_STATUSES` — they only appear when explicitly filtered
- When new backend statuses are introduced, they must be added to the appropriate constant arrays to appear in any default view
