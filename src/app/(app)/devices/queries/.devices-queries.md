GraphQL query definitions for the Devices feature, covering organization presence checks, device listing with filtering/pagination, individual device lookup, and a lightweight overview query.

## Key Components

| Export | Purpose |
|---|---|
| `HAS_ORGANIZATIONS_QUERY` | Minimal probe — fetches the first organization to gate the "Add Device" action |
| `GET_DEVICE_FILTERS_QUERY` | Retrieves available filter facets (status, OS type, org, tags) with counts |
| `GET_DEVICES_QUERY` | Full paginated device list with rich fields, tool connections, and tags |
| `GET_DEVICE_QUERY` | Single device lookup by `machineId`, including installed agents |
| `GET_DEVICES_OVERVIEW_QUERY` | Lightweight query returning only `status` per device for dashboard/summary views |

## Usage Example

```typescript
import {
  HAS_ORGANIZATIONS_QUERY,
  GET_DEVICES_QUERY,
  GET_DEVICE_QUERY,
  GET_DEVICE_FILTERS_QUERY,
} from './devices-queries';

// Check if any organizations exist before showing "Add Device"
const { organizations } = await gqlClient.request(HAS_ORGANIZATIONS_QUERY);
const canAddDevice = organizations.edges.length > 0;

// Fetch a filtered, paginated device list
const { devices } = await gqlClient.request(GET_DEVICES_QUERY, {
  filter: { osType: 'WINDOWS', status: 'ONLINE' },
  first: 25,
  after: null,
  search: 'laptop',
  sort: { field: 'lastSeen', direction: 'DESC' },
});

// Fetch a single device by machineId
const { device } = await gqlClient.request(GET_DEVICE_QUERY, {
  machineId: 'abc-123-xyz',
});
```

## Notes

- `GET_DEVICES_QUERY` and `GET_DEVICE_QUERY` share the same core device fields; `GET_DEVICE_QUERY` additionally returns `installedAgents`.
- `GET_DEVICES_OVERVIEW_QUERY` intentionally omits heavy fields for performance — prefer it for status-only aggregations.
- All list queries support `DeviceFilterInput` for server-side filtering; `GET_DEVICES_QUERY` also accepts a `SortInput`.
