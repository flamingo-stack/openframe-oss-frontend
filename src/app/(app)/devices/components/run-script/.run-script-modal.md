Multi-step modal orchestrating the "Run Script on device" workflow across three states: script selection, run configuration, and post-run confirmation.

## Key Components

- **`RunScriptModal`** — Primary export; a stateful wrapper managing the two-modal sequence and step transitions
- **`step` state** — Controls which step is rendered: `'select'` or `'config'`
- **`ran` state** — Toggles between `SimpleModal` (pre-run) and `ScriptRunningModal` (post-run)
- **`Suspense` boundary** — Wraps `RunScriptConfigStep` with `RunScriptConfigStepSkeleton` as fallback while config data loads

## Workflow Steps

1. **Select Script** — `RunScriptSelectStep` renders a searchable, tag-filtered, infinite-scroll list of active scripts
2. **Run Script** — `RunScriptConfigStep` displays the selected script's details and overridable per-run variables (`timeout`, `privilege`, `args`, `env`), then invokes `batchRunScript`
3. **Scripts Running** — `ScriptRunningModal` confirms execution and provides a "Device Logs" CTA

## Usage Example

```typescript
<RunScriptModal
  isOpen={isModalOpen}
  onClose={() => setIsModalOpen(false)}
  machineId="device-abc-123"
  onViewDeviceLogs={() => navigateTo('/device/abc-123/logs')}
/>
```

## Notes

- The modal resets to `step: 'select'` and clears `scriptId`/`ran` state on every open via `useEffect`
- `handleViewDeviceLogs` closes the modal before calling the parent's navigation callback
- The two modals (`SimpleModal` and `ScriptRunningModal`) are mutually exclusive via `isOpen && !ran` / `isOpen && ran`
