Skeleton loading components for the run-script workflow, providing placeholder UI for both the script picker list and the script configuration step.

## Key Components

| Export | Description |
|--------|-------------|
| `RunScriptSelectListSkeleton` | Skeleton for the script picker/select list step — renders 6 rows with varying description widths, a name line, and an OS badge placeholder |
| `RunScriptConfigStepSkeleton` | Skeleton for the script configuration step — mirrors the full config layout including summary card, timeout/run-as-user inputs, script arguments, environment vars, and a pinned footer |
| `ArgumentsSkeleton` *(internal)* | Reusable skeleton for a single arguments column (title, key/value row, add button) |

## Usage Example

```typescript
import {
  RunScriptSelectListSkeleton,
  RunScriptConfigStepSkeleton,
} from './run-script-skeletons';

// In a step-based run-script flow:
function RunScriptStep({ step, isLoading }) {
  if (isLoading && step === 'select') {
    return <RunScriptSelectListSkeleton />;
  }

  if (isLoading && step === 'config') {
    return <RunScriptConfigStepSkeleton />;
  }

  // Render real content...
}
```

## Notes

- `PICKER_ROW_DESCRIPTIONS` cycles through six Tailwind width classes (`w-40`–`w-72`) to prevent visually uniform skeleton rows.
- `RunScriptConfigStepSkeleton` reuses `ScriptSummaryCardSkeleton` (with `RUN_SUMMARY_STATS`) from the shared scripts module to stay in sync with the real summary card's stat count.
- Both components use ODS design tokens (e.g., `--spacing-system-mf`) and `border-ods-border` to exactly mirror the live component spacing.
