Route-level loading skeleton for the devices list pages (`/devices` and `/devices/archive`). Renders the real `PageLayout` header with disabled action buttons and `DevicesTableBody` in loading mode to prevent layout shift and column drift during data fetches.

## Key Components

- **`DevicesPageSkeleton`** — Main exported component accepting an optional `archived` boolean prop to toggle between the active and archived device list skeleton states
- **`LIST_ACTIONS`** — Pre-defined disabled action buttons (`Archive`, `Add Device`) mirroring the real `DevicesPanel` actions
- **`EMPTY_DEVICES`** — Typed empty array (`never[]`) passed to `DevicesTableBody` during the loading state
- **`useSafeBack`** — Hook providing a functional back button even during the loading phase, preventing a dead/missing control in the archive page header

## Usage Example

```typescript
// app/devices/page.tsx
import { Suspense } from 'react';
import { DevicesPageSkeleton } from './devices-page-skeleton';

export default function DevicesPage() {
  return (
    <Suspense fallback={<DevicesPageSkeleton />}>
      <DevicesPanel />
    </Suspense>
  );
}

// app/devices/archive/page.tsx
export default function ArchivePage() {
  return (
    <Suspense fallback={<DevicesPageSkeleton archived />}>
      <ArchivedDevicesPanel />
    </Suspense>
  );
}
```

## Notes

- Columns are sourced from the real `DevicesTableBody` definition, ensuring skeleton columns stay in sync with the live table automatically
- The back button remains interactive during loading on the archive route — the header row is always rendered to avoid layout shift on hydration
