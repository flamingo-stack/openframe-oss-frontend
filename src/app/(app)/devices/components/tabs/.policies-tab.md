Renders the compliance policies tab within a device detail view, displaying a searchable, filterable table of policies applied to a specific device with pass/fail/pending status mapping.

## Key Components

| Export / Helper | Description |
|---|---|
| `PoliciesTab` | Main exported component; renders search input + `PoliciesTable` for a given device |
| `toStatus` | Maps `DevicePolicy['response']` (`pass`/`fail`/other) to `PolicyTableRow` status objects with label and variant |
| `parsePlatforms` | Splits a comma-separated platform string into a clean `string[]` |
| `PoliciesTabProps` | Interface accepting a nullable `Device` prop |

## Usage Example

```typescript
import { PoliciesTab } from './policies-tab';
import type { Device } from '../../types/device.types';

// Inside a device detail page or layout
export default function DevicePage({ device }: { device: Device | null }) {
  return <PoliciesTab device={device} />;
}
```

## Rendering Behavior

The component handles three distinct states:

```text
device === null         → TabEmptyState ("No policies applied")
policies.length === 0   → PoliciesEmptyState (rich onboarding UI from monitoring)
policies.length > 0     → Sticky search bar + PoliciesTable with filtered rows
```

- **Search** filters on `name` and `description` (case-insensitive).
- The search input is hidden when the table is empty and no search is active.
- Clicking a policy row or its **Policy Details** action navigates to `routes.monitoring.policy(id)`.
- Sticky toolbar offset is managed by the `useStickyToolbar` hook to coordinate with any parent sticky headers.
