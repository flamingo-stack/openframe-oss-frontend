The main page-level view component for the Devices section, orchestrating device listing in both table and grid modes with search, filtering, and infinite scroll capabilities.

## Key Components

**`DevicesView`** — Primary export; a full-page React component that composes:

- **`useDevicesUrlParams`** — Manages URL-driven filter/search state (statuses, OS types, org IDs, tags, view mode)
- **`useDevices`** — Fetches paginated device data with infinite scroll support
- **`useDeviceFilters`** — Loads available filter options for the filter modal
- **`useTagFilterModal`** — Controls the tag/filter modal open state and filter group configuration
- **`useGridInfiniteScroll`** — Wires an intersection observer sentinel for grid-mode auto-loading
- **`useStickyToolbar`** — Computes sticky toolbar offset for correct header positioning
- **`DevicesTableBody`** — Table view with column filters, row actions, and an infinite-scroll footer
- **`DevicesGrid`** — Card grid view with sentinel-based infinite scroll
- **`FilterModal`** — Slide-in modal for tag and faceted filters

## Usage Example

```typescript
// Render inside a Next.js app router page (requires 'use client' boundary)
import { DevicesView } from '@/features/devices/components/devices-view';

export default function DevicesPage() {
  return <DevicesView />;
}
```

The component is self-contained — it reads all state from URL params and manages its own data fetching. No props are required.

## Notes

- Switches between `table` and `grid` view modes via a `TabSelector`, persisted in the URL via `viewMode` param.
- The sticky toolbar hosts a `TagSearchInput` and a responsive filter button (icon-only on small screens, labeled on `md+`).
- Row actions (e.g. device-level operations) trigger a `refetch` on completion.
- Navigation to the new-device flow uses `routes.devices.new()` from the centralized routes config ([`lib/routes`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/lib/routes.ts)).
