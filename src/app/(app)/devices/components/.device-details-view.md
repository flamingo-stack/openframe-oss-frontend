Renders the full device details page for a given device, including tabbed navigation, header actions, status display, and a run-script modal.

## Key Components

- **`DeviceDetailsView`** — Primary page component accepting a `deviceId` prop; orchestrates data fetching, tab state, action menus, and modal visibility
- **Tab management** — URL-driven tab state via `?tab=` search param; validated against `DEVICE_TAB_IDS` derived from `DEVICE_TABS` to prevent blank panels from stale/invalid URLs
- **`useDeviceDetails`** — Fetches device data; surfaces `isLoading`, `error`, and `deviceDetails` states
- **`useDeviceActionsMenu`** — Builds the actions menu registry (run script, manage files, archive, delete, remote control, remote shell)
- **`useTrackOpenView`** — Registers the current device as the active Mingo AI context entity
- **`RunScriptModal`** — Native scripts-v2 modal triggered via UI button or `?action=runScript` URL param
- **`PageLayout`** — Core layout with title, subtitle, back button, inline status `Tag`, and grouped `menuActions`

## Usage Example

```typescript
// Rendered by the device details route (e.g., /devices/details?id=abc123)
import { DeviceDetailsView } from './device-details-view';

export default function DeviceDetailsPage({ params }: { params: { id: string } }) {
  return <DeviceDetailsView deviceId={params.id} />;
}
```

## Notes

- Tab changes use `router.replace` (no scroll) to keep the URL as the single source of truth, avoiding a flicker bug in `urlSync` mode
- A 1-second interval forces re-renders to keep the relative-time subtitle (`Updated X ago`) current
- The `?action=runScript` URL param allows external navigation (e.g., from a device table dropdown) to trigger the script modal on load, then cleans itself from the URL
