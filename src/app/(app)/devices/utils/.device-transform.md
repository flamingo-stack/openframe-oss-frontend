The device list-row transforms: a GraphQL `Machine` in, the flat `Device` the shared tables, cards and selectors render out — one function per step of the `@inline` fragment ladder in `src/graphql/devices/`.

## Key Components

| Export | Purpose |
|---|---|
| `machineRowToDevice(ref)` | Step 1 — reads `deviceRowFields_machine`: identity, status, last-seen, customer, tags |
| `machineSelectorToDevice(ref)` | Step 2 — reads `deviceSelectorFields_machine`: step 1 + hardware ids + customer contact email |
| `machineToDevice(ref)` | Step 3 — reads `deviceFields_machine`: step 2 + network, OS detail, tool connections |
| `rowFieldsToDevice(fields)` | Step 1 taking plain DATA rather than a fragment reference — the door for non-Relay callers |
| `DeviceRowFields` | `Omit<deviceRowFields_machine$data, ' $fragmentType'>` — the shape those callers must satisfy |
| `toDeviceTags(tags)` | Maps GraphQL `Tag` nodes to `DeviceTag`, renaming `id` -> `tagId` |

## Notes

- **A caller cannot read what it did not select.** Each step takes its own fragment key, so the fragment a query spreads decides which transform it may call and the compiler enforces the rest. This replaced a single `MachineLike` interface whose fields were all optional — there, a forgotten selection rendered an empty column instead of failing to compile.
- **Why three steps and not one fragment.** The lists afford different amounts of fan-out: `assignedDevices` resolves per machine and has timed out once on test-dev, so the schedule's Assigned Devices tab stops at step 1, the picker takes step 2, the Devices page takes step 3. Each step spreads the one below it, so the field sets cannot drift apart.
- **The non-Relay door.** `use-assigned-items.ts` reads its machines through a raw-POST union query and has no fragment reference; it builds `DeviceRowFields` by hand and calls `rowFieldsToDevice`. Because that type is generated, a missing field is a compile error rather than a blank cell.
- **Not the detail record.** `createDevice()` in `hooks/use-device-details.ts` is a different job — a Fleet-first merge of GraphQL + Fleet + MeshCentral where nearly every field carries a priority rule. Only the tag mapping is shared, via `toDeviceTags`, whose parameter is deliberately loose (`Partial<TagFields> & Pick<TagFields, 'id' | 'key'>`) so that raw-POST path fits too.
- **`tags` requires `id` in the selection.** Any document feeding this must select `tags { id ... }`; without it every `DeviceTag.tagId` is `undefined` and tag React keys collide.
