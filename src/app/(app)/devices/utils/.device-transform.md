The single device list-row transform: a GraphQL `Machine` node in, the flat `Device` the shared tables, cards and selectors render out.

## Key Components

| Export | Purpose |
|---|---|
| `MachineLike` | Structural `Machine` shape — everything past `id` optional, nullable, readonly-tolerant, so both Relay artifacts and plain objects fit |
| `machineToDevice(machine)` | The transform. Only fields present in the caller's selection are populated |
| `toDeviceTags(tags)` | Maps GraphQL `Tag` nodes to `DeviceTag`, renaming `id` -> `tagId` |

## Notes

- **One transform, two transports.** The Relay device queries and the react-query whole-fleet walk both land here, which is what stops a picker and the Devices page disagreeing about what a device is. It replaced a `createDeviceListItem` (raw-POST path) / `machineToDevice` (scripts-v2 path) pair that had already drifted on tag mapping.
- **`MachineLike` is structural on purpose.** The list, the pickers and the schedule tables select different subsets; a caller passes whatever it selected and gets the rest left `undefined`.
- **Not the detail record.** `createDevice()` in `hooks/use-device-details.ts` is a different job — a Fleet-first merge of GraphQL + Fleet + MeshCentral where nearly every field carries a priority rule. Only the tag mapping is shared, via `toDeviceTags`.
- **`tags` requires `id` in the selection.** Any document feeding this must select `tags { id ... }`; without it every `DeviceTag.tagId` is `undefined` and tag React keys collide.
