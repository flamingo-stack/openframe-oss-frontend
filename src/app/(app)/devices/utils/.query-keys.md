Defines the structured, hierarchical query key factory for **every** device-related React Query cache entry, plus the single invalidation entry point.

Every cached device read hangs off the `['devices']` root — lists, whole-fleet reads, details, filter facets and counters alike. That single prefix is what lets one invalidation refresh every device surface; a device query keyed outside it silently keeps serving stale data after an archive or delete. Adding a device query means adding its key here, never inventing a literal at the call site.

## Key Components

- **`deviceQueryKeys.all`** – Base key `['devices']` shared by all device queries
- **`deviceQueryKeys.lists()`** – Root for every list-shaped read: `['devices', 'list']`
- **`deviceQueryKeys.page(filter, search, first)`** – Single bounded page (the ticket-form device autocomplete)
- **`deviceQueryKeys.full(filter)`** – Whole fleet, paged to exhaustion (`useAllDevices`)
- **`deviceQueryKeys.detail(machineId)`** – Single device (`useDeviceDetails`)
- **`deviceQueryKeys.counts()` / `.countsBy(filter)`** – Per-organization counters
- **`deviceQueryKeys.stats()`** – Dashboard status breakdown
- **`invalidateDeviceQueries(queryClient)`** – Refreshes every device surface after a mutation

## Usage Example

```typescript
import { deviceQueryKeys, invalidateDeviceQueries } from './query-keys';

// After archiving / unarchiving / deleting a device
invalidateDeviceQueries(queryClient);

// Invalidate only list-shaped reads, leaving details and facets alone
queryClient.invalidateQueries({ queryKey: deviceQueryKeys.lists() });

// Read a specific device out of the cache
const data = queryClient.getQueryData(deviceQueryKeys.detail('machine-abc-123'));
```

The hierarchical structure allows React Query's cache invalidation to cascade — invalidating `deviceQueryKeys.all` also invalidates lists, details, facets and counters, while invalidating `deviceQueryKeys.lists()` leaves detail caches untouched.

`invalidateDeviceQueries` additionally invalidates the dashboard's customers-overview key, which is the one query joining organization rows to their device counts and therefore lives outside the `['devices']` root.
