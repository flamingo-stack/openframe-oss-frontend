The top-level client-side page component for the "New Device" route, wrapping the device creation form in a `Suspense` boundary to display a skeleton loader while content hydrates.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `NewDevicePage` | Default export | Page-level component that renders `NewDeviceContent` with a `NewDeviceSkeleton` fallback |

**Dependencies:**

- [`NewDeviceContent`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/(routes)/devices/new/new-device-content.tsx) — the primary form/content for adding a device
- [`NewDeviceSkeleton`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/(routes)/devices/new/new-device-skeleton.tsx) — loading placeholder displayed during suspension

## Usage Example

This is a Next.js App Router page component — it is rendered automatically when a user navigates to the `/devices/new` route. No manual instantiation is required.

```typescript
// Rendered automatically by Next.js at /devices/new
// Internal structure:
<Suspense fallback={<NewDeviceSkeleton />}>
  <NewDeviceContent />
</Suspense>
```

> **Note:** The `'use client'` directive marks this as a Client Component. The `Suspense` boundary ensures users see a skeleton UI immediately while `NewDeviceContent` resolves any async data dependencies, improving perceived performance.
