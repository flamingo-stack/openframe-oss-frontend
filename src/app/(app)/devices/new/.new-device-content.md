Renders the "New Device" onboarding page, allowing users to select a customer organization and OS platform, manage device tags, and generate or download a platform-specific agent installation command.

## Key Components

| Export / Hook | Purpose |
|---|---|
| `NewDeviceContent` | Main page component orchestrating the new-device flow |
| `newDeviceSchema` | Zod schema validating `organizationId` and `platform` fields |
| `useInstallCommand` | Generates the install command string and `initialKey` secret |
| `useDeviceOrganizations` | Fetches available customer organizations via GraphQL/TanStack Query |
| `validateBeforeAction` | Guards copy/run actions — checks form validity, secret availability, and tag integrity |
| `copyCommand` | Copies the generated install command to the clipboard |
| `runOnCurrentMachine` | Validates platform match, generates a `.ps1` or `.sh` script, and triggers a browser download |

## Usage Example

```typescript
// Rendered at the /devices/new route.
// Accepts an optional `organizationId` query param to pre-select a customer.
// e.g. /devices/new?organizationId=org_abc123

import { NewDeviceContent } from './new-device-content';

export default function NewDevicePage() {
  return <NewDeviceContent />;
}
```

```typescript
// Tag validation — only keys/values matching this pattern are included
// in the generated install command:
const validTags = tags.flatMap(t => {
  if (!t.key || !isValidTag(t.key)) return [];
  // duplicate keys and empty value lists are also filtered
  const validValues = t.values.filter(isValidTag);
  return validValues.length > 0 ? [{ ...t, values: validValues }] : [];
});
```

## Notes

- **Platform mismatch detection** compares the user's `navigator.userAgent` against the selected `platform` field and surfaces a destructive toast if they differ.
- **Script generation** produces a PowerShell (`.ps1`) script for Windows and a Bash (`.sh`) script for macOS/Linux, both embedding the generated `command`.
- **Pre-selection priority**: `?organizationId` query param → default org → first org in the list.
- Platform availability is driven by `AVAILABLE_PLATFORMS` / `DISABLED_PLATFORMS` from [`/lib/platforms`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/src/lib/platforms.ts).
