Complete TypeScript type definitions for Fleet MDM API responses, modeling host data including hardware specs, software inventory, policies, vulnerabilities, and MDM enrollment state.

## Key Components

| Interface | Purpose |
|---|---|
| `FleetHost` | Root host object with all device attributes grouped by category |
| `FleetHostResponse` | Top-level API response wrapper (`GET /hosts/:id`) |
| `FleetSoftware` | Installed software entry with CPE, vulnerability list, and source type |
| `FleetVulnerability` | CVE record with optional Fleet Premium severity fields (CVSS, EPSS, CISA) |
| `FleetHostPolicy` | Policy definition with per-host `pass`/`fail`/`''` response |
| `FleetMdmInfo` | MDM enrollment state, DEP profile, encryption key availability |
| `FleetGeolocation` | GeoIP data attached when Fleet has the GeoIP database loaded |
| `FleetEndUser` | IdP/email identity from Chrome-profile or directory sync |
| `FleetLabel` | Fleet label membership record |
| `FleetUser` | OS-level user account entry |
| `FleetBattery` | Battery cycle count and health string |
| `FleetIssues` | Aggregate policy failure and issue counts |
| `FleetSignatureInfo` | macOS code-signing path and team identifier |

## Usage Example

```typescript
import type {
  FleetHostResponse,
  FleetHost,
  FleetVulnerability,
} from './fleet.types';

// Deserialize API response
const response = await fetch('/api/fleet/hosts/42');
const { host }: FleetHostResponse = await response.json();

// Access core identity
console.log(host.hostname, host.hardware_serial, host.status);

// Enumerate vulnerable software
const vulnerabilities: FleetVulnerability[] = (host.software ?? [])
  .flatMap(sw => sw.vulnerabilities ?? []);

const critical = vulnerabilities.filter(
  v => v.cisa_known_exploit === true
);

// Check policy compliance
const failingPolicies = host.policies.filter(p => p.response === 'fail');

// MDM enrollment state
if (host.mdm.connected_to_fleet && !host.mdm.encryption_key_available) {
  console.warn(`${host.display_name}: encryption key not escrowed`);
}
```

## Notes

- **Fleet Premium fields** on `FleetVulnerability` (`cvss_score`, `epss_probability`, `cisa_known_exploit`, `cve_published`, `resolved_in_version`) are all optional/nullable — guard with `?? null` before use.
- `FleetHost.status` is a discriminated union (`'online' | 'offline' | 'mia'`); use exhaustive checks when branching on device reachability.
- `policies`, `labels`, `batteries`, and `users` are always arrays (never `null`); `software`, `pack_stats`, and `end_users` may be absent or `null`.
