Composes device action menu items with confirmation dialogs and routing logic for a device context menu.

## Key Components

### `useDeviceActionsMenu(device, options)`

Main hook that builds a complete set of `ActionsMenuItem` entries for a given device, wiring up dialogs, availability checks, and navigation.

**Parameters:**

| Name | Type | Description |
|------|------|-------------|
| `device` | `Device \| null \| undefined` | The target device |
| `options.onRunScript` | `() => void` | Override for run script click (defaults to router push) |
| `options.onActionComplete` | `() => void` | Callback fired after any successful action |
| `options.deviceId` | `string` | Fallback ID used when device is still loading |
| `options.iconSize` | `string` | Tailwind size classes for icons (default: `w-6 h-6`) |
| `options.navigateOnDestructive` | `boolean` | Navigate to `/devices` after archive/delete |

### `DeviceActionsMenuItems`

Typed map of all menu entries:
`deviceDetails`, `remoteShell`, `remoteControl`, `manageFiles`, `runScript`, `deviceLogs`, `archive`, `unarchive`, `delete`

Destructive items (`archive`, `unarchive`, `delete`) are `null` when the action is unavailable for the current device state.

### `UseDeviceActionsMenuResult`

| Field | Description |
|-------|-------------|
| `items` | Full `DeviceActionsMenuItems` map |
| `dialogs` | Confirmation dialog nodes to render in the component tree |
| `actionAvailability` | Raw `DeviceActionAvailability` for external gate checks |

## Usage Example

```typescript
export function DeviceContextMenu({ device }: { device: Device }) {
  const { items, dialogs } = useDeviceActionsMenu(device, {
    navigateOnDestructive: true,
    onActionComplete: () => refetch(),
  });

  return (
    <>
      <ActionsMenu items={Object.values(items).filter(Boolean)} />
      {dialogs}
    </>
  );
}
```

> **Note:** Always render `dialogs` alongside the menu — archive and delete actions require their confirmation nodes to be mounted in the tree.
