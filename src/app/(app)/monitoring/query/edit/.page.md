Wrapper page component for the edit query route that extracts and validates the required `id` URL parameter before rendering the edit form.

## Key Components

- **`EditQueryPageWrapper`** — Default export; a client-side page component that guards against missing route parameters and delegates rendering to `EditQueryPage`
- **`useRequiredIdParam`** — Hook that reads the `id` param from the URL, redirecting to the queries list or new query page if it is absent
- **`EditQueryPage`** — The actual edit form component, rendered only when a valid `queryId` is available

## Usage Example

This component is used as a Next.js page route (e.g., `app/monitoring/queries/[id]/edit/page.tsx`). No manual usage is required — Next.js mounts it automatically.

```typescript
// Rendered automatically by Next.js at /monitoring/queries/[id]/edit
// If `id` is missing from the URL, the user is redirected to:
//   - routes.monitoring.root({ tab: 'queries' })  (queries list)
//   - routes.monitoring.queryNew                  (new query page)
export default function EditQueryPageWrapper() {
  const id = useRequiredIdParam(
    routes.monitoring.root({ tab: 'queries' }),
    routes.monitoring.queryNew
  );
  if (!id) return null;
  return <EditQueryPage queryId={id} />;
}
```

## Notes

- The `'use client'` directive marks this as a Client Component, required because `useRequiredIdParam` relies on client-side navigation hooks.
- Returning `null` while the redirect is in-flight prevents a flash of the edit form with an undefined ID.
