Query details page component that renders a saved query's detail view, with a legacy redirect handling `?id=new` URLs to the current query creation route.

## Key Components

- **`QueryPage`** — Default export page component that reads the `id` search parameter and either redirects legacy `?id=new` links or renders the detail view for an existing query.
- **`QueryDetailsView`** — Imported child component responsible for rendering the full details UI for a given `queryId`.
- **`routes.monitoring.queryNew`** — Route constant used as the redirect target for legacy `?id=new` bookmarks.

## Usage Example

```typescript
// Navigating to this page with an existing query ID
router.push('/monitoring/query?id=abc-123');
// → renders <QueryDetailsView queryId="abc-123" />

// Legacy ?id=new usage (e.g. old bookmark)
router.push('/monitoring/query?id=new');
// → immediately redirects to routes.monitoring.queryNew (the create form)
```

## Notes

- The `if (paramId === 'new') return null` guard prevents a flash of the detail view before the redirect completes.
- If no `id` param is present, `queryId` falls back to an empty string `''`, which `QueryDetailsView` must handle gracefully.
- Uses `router.replace` (not `push`) so the legacy URL is not added to browser history.
