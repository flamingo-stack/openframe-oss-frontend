Renders the full detail view for a single monitoring query, including its metadata, SQL script preview, tabbed results/devices panels, and edit/delete actions.

## Key Components

- **`QueryDetailsView`** — Primary exported component; accepts a `queryId` string prop and orchestrates all data fetching, routing, and UI state for the query detail page
- **`formatInterval`** — Pure utility that converts a seconds value into a human-readable frequency string (e.g. `"Every 5m"`, `"Manual"`)
- **`QUERY_TABS`** — Static tab configuration for `"Query Results"` and `"Assigned Devices"` panels, driven by URL `?tab=` search param
- **`useQueryDetails`** / **`useQueryReport`** / **`useQueries`** — Data hooks providing query metadata, report rows, and delete mutation respectively
- **`useTrackOpenView`** — Registers the current query as Mingo's passive context entity so the AI agent has working context on the next interaction

## Usage Example

```typescript
// In a Next.js page component (e.g. app/monitoring/queries/[id]/page.tsx)
import { QueryDetailsView } from './query-details-view';

export default function QueryPage({ params }: { params: { id: string } }) {
  return <QueryDetailsView queryId={params.id} />;
}
```

## Behavior Notes

- **Tab state** is URL-controlled via `?tab=results|devices`; invalid tab values fall back to `"results"`
- **Loading/error states** render `CardLoader`, `LoadError`, or `NotFoundError` from the core library before the main layout
- **Delete flow** opens `ConfirmDeleteMonitoringModal` then navigates back to the queries list on success
- **Back navigation** uses `useSafeBack` to prefer browser history with a safe fallback to `routes.monitoring.root({ tab: 'queries' })`
