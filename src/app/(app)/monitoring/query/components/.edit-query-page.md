Renders the edit/create form for an osquery-style monitoring query, handling name, frequency, SQL body, device assignment, and live test execution.

## Key Components

| Export / Symbol | Description |
|---|---|
| `EditQueryPage` | Main page component accepting an optional `queryId` prop; switches between create and edit modes |
| `secondsToUnitValue` | Converts a raw seconds value to a `{ value, unit }` pair using the largest clean time unit |
| `unitValueToSeconds` | Inverse of `secondsToUnitValue`; multiplies a display value by the selected unit's multiplier |
| `queryFormSchema` | Zod schema enforcing a minimum name, optional description/SQL, and a ≥ 300 s interval |
| `TIME_UNITS` | Const tuple of `minutes / hours / days` with their second multipliers |

## Usage Example

```typescript
// app/monitoring/queries/[id]/edit/page.tsx
import { EditQueryPage } from './edit-query-page';

export default function Page({ params }: { params: { id?: string } }) {
  // Pass null to create a new query; pass the string ID to edit an existing one
  return <EditQueryPage queryId={params.id ?? null} />;
}
```

## Key Behaviors

- **Create vs. edit** — determined by parsing `queryId`; `null` or `NaN` enters create mode
- **Frequency picker** — a numeric `<Input>` paired with a `<Select>` for minutes/hours/days; values are normalised to seconds before form submission
- **Device assignment** — `usePolicyDevices` loads available devices; `useQueryHosts` seeds the initial selection for edits; `useReplaceQueryHosts` syncs the final list on save
- **Live test panel** — calls `useLiveCampaign.startCampaign` with the current SQL and selected host IDs; `<LiveTestPanel>` displays streaming results inline
- **Save flow** — `createQuery` or `updateQuery` runs first, then `replaceQueryHostsMutation` updates host assignments; failures in host sync are silently caught (mutation hook shows its own toast)
- **Loading / error guards** — renders `<CardLoader>`, `<LoadError>`, or `<NotFoundError>` before the form based on query-fetch state
