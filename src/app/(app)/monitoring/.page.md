A Next.js page component for the Monitoring section of the OpenFrame frontend, rendering tab-based navigation with URL-synchronized state management.

## Key Components

- **`Monitoring`** — Default exported page component that orchestrates tab navigation and renders the active tab's content
- **`useApiParams`** — Hook managing `tab` and `search` URL parameters; `search` resets to `''` on every tab switch to ensure each tab starts fresh
- **`getTabComponent`** — Resolves the correct component from `MONITORING_TABS` based on the active `tab` param
- **`MonitoringTabNavigation`** — Tab navigation UI; receives `activeTab` and triggers `onTabChange` which clears `search` on switch

## Usage Example

```typescript
// The page is route-driven; no manual instantiation needed.
// URL params control active state:
//   /monitoring?tab=policies         → renders PoliciesTab
//   /monitoring?tab=alerts&search=cpu → renders AlertsTab with search pre-filled

// Tab switching resets search automatically:
onTabChange={tab => setParams({ tab, search: '' })}

// Adding a new tab — register it in MONITORING_TABS:
export const MONITORING_TABS = [
  { key: 'policies', component: PoliciesTab },
  { key: 'alerts',   component: AlertsTab },
  { key: 'my-tab',   component: MyNewTab }, // ← add here
];
```

## Notes

- Default tab is `policies` — navigating to `/monitoring` without query params lands on the Policies tab
- `search` is declared at the page level (not inside each tab) so the page can clear it on tab change
- If `TabComponent` resolves to `null` (unknown `tab` param), nothing renders — add a fallback tab or redirect as needed
