A Next.js client component that renders the create/edit form for a monitoring policy, handling policy metadata, SQL query authoring, device assignment, and live query testing.

## Key Components

| Export / Symbol | Description |
|---|---|
| `EditPolicyPage` | Main page component; accepts an optional `policyId` to toggle between create and edit mode |
| `policyFormSchema` | Zod schema validating `name` (required), `description`, and `query` fields |
| `PolicyFormData` | Inferred TypeScript type from `policyFormSchema` |
| `getDeviceKey` | Helper that resolves a stable string key from a `Device` using its Fleet host ID |

## Key Behaviors

- **Create vs. edit mode** — determined by parsing `policyId`; drives which hooks fire, the page title, and post-save navigation.
- **Host assignment** — pre-populates selected device IDs from `usePolicyHosts` (edit mode) and syncs them via `useReplacePolicyHosts` on save.
- **Live test panel** — `useLiveCampaign` orchestrates a real-time osquery campaign; `LiveTestPanel` appears when "Test Policy" is clicked and requires at least one device and a non-empty query.
- **Form validation** — `react-hook-form` + `zodResolver`; field errors surface inline, with a toast for the first validation failure on submit.

## Usage Example

```typescript
// app/monitoring/policies/[id]/page.tsx
import { EditPolicyPage } from './edit-policy-page';

export default function Page({ params }: { params: { id: string } }) {
  // Pass null to create a new policy
  return <EditPolicyPage policyId={params.id} />;
}

// Create mode
<EditPolicyPage policyId={null} />

// Edit mode
<EditPolicyPage policyId="42" />
```
