Skeleton placeholder component for monitoring detail routes (`/monitoring/policy` and `/monitoring/query`), rendering a consistent loading state while REST queries are in flight.

## Key Components

- **`MonitoringDetailSkeleton`** – Client component that renders `<CardLoader items={4} />`, matching the exact layout of both policy and query detail views to prevent a visible skeleton swap on cold load.

## Usage Example

```typescript
// Typically used as a Next.js route-level `loading.tsx` export
export { MonitoringDetailSkeleton as default } from './monitoring-detail-skeleton';
```

```typescript
// Or composed directly inside a Suspense boundary
import { MonitoringDetailSkeleton } from './monitoring-detail-skeleton';

<Suspense fallback={<MonitoringDetailSkeleton />}>
  <MonitoringPolicyDetail id={policyId} />
</Suspense>
```

## Notes

- The `items={4}` count is intentionally fixed to mirror what both monitoring detail views render, so the app-shell placeholder is visually stable across the loading → loaded transition.
- Sourced from [`@flamingo-stack/openframe-frontend-core`](https://github.com/flamingo-stack/openframe-oss-frontend) via the shared `CardLoader` primitive.
