Renders the full "Get Started" onboarding page, managing step expansion state, URL hash sync, completion tracking, and auto-advance behaviour for all user onboarding steps.

## Key Components

- **`OnboardingContent`** — Mount gate component; shows `OnboardingSkeleton` until progress loads, redirects to dashboard if tenant setup is incomplete or the tour was already finished on arrival, then renders `LoadedOnboardingContent`.
- **`LoadedOnboardingContent`** — The active page body; owns all interactive state (expanded step, completing spinner, skip dialog) and orchestrates mutations.
- **`STEP_BODY`** — Static map from `UserOnboardingStep` enum values to their body `ComponentType`, used to render the correct form inside each accordion row.
- **`StepBodyProps`** — Shared prop contract for every step body: `completed`, `completing`, `onComplete`, and `onCompleteBackground`.

### Key Behaviours

| Behaviour | Mechanism |
|---|---|
| URL hash sync | `navigateSamePageHash` writes `#step-<name>`; `hashchange` listener parses it back |
| Auto-advance | `useOnboardingAutoAdvance` opens the next incomplete step and scrolls it into view |
| Background completion | `completeUserInBackground` fires once (ref-guarded) the moment `allDone` becomes true |
| Skip confirmation | `ConfirmDialog` gated by `skipConfirmOpen` state; calls `skipUser` on confirm |
| Redirect lock | `completedOnArrivalRef` captures completion at first load; prevents re-entry without blocking in-session completion |

## Usage Example

```typescript
// Rendered by the /onboarding route — no props required.
// Progress is read from the global onboarding store.
import { OnboardingContent } from './onboarding-content';

export default function OnboardingPage() {
  return <OnboardingContent />;
}
```
