Coordinates loading and disabled states for the two action buttons in an onboarding step — a primary action button and a "Mark as Complete" button — ensuring only the clicked button shows a spinner while the other is disabled.

## Key Components

### `StepActionKind`
Union type (`'primary' | 'complete'`) identifying which button initiated an in-flight action.

### `useStepActionState(options)`
Custom hook that accepts:
- `completing` — parent-level flag indicating the completion mutation is in flight
- `primaryBusy` — the primary button's own network request state (e.g. `isSubmitting`); omit for navigation-only primaries

Returns:
- `begin(kind)` — call at the start of a button's `onClick` to register which button was clicked
- `complete` — `{ loading, disabled }` state for the "Mark as Complete" button
- `primary` — `{ loading, disabled }` state for the primary action button

## Usage Example

```typescript
const { begin, complete, primary } = useStepActionState({
  completing: isCompleting,
  primaryBusy: form.isSubmitting,
});

return (
  <>
    <Button
      loading={primary.loading}
      disabled={primary.disabled}
      onClick={() => {
        begin('primary');
        form.submit();
      }}
    >
      Save
    </Button>

    <Button
      loading={complete.loading}
      disabled={complete.disabled}
      onClick={() => {
        begin('complete');
        onComplete();
      }}
    >
      Mark as Complete
    </Button>
  </>
);
```

## Notes

- `via` is never reset between renders — it persists for the duration of the in-flight operation and is overwritten on the next click, which is safe since `anyBusy` disables the idle button.
- A navigation-only primary (no network call) should omit `primaryBusy`; the `completing` flag alone drives its loading state once `onComplete` is called.
