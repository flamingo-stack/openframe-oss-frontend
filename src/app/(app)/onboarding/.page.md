Route entry point for the new onboarding experience, gated behind the `newOnboarding` feature flag. When the flag is disabled, the route returns a 404 and users fall back to the legacy dashboard onboarding flow.

## Key Components

| Export | Type | Description |
|---|---|---|
| `OnboardingPage` | `default` (page component) | Next.js App Router page component that guards and renders the onboarding flow |
| `featureFlags.newOnboarding` | Feature flag | Controls whether this route is accessible; returns `notFound()` when disabled |
| `OnboardingContent` | Component | The primary onboarding UI, loaded asynchronously |
| `OnboardingSkeleton` | Component | Suspense fallback shown while `OnboardingContent` is loading |

## Usage Example

This is a Next.js route module — it is not imported directly. It is resolved automatically at the `/onboarding` path. To enable the route, toggle the feature flag:

```typescript
// lib/feature-flags.ts
export const featureFlags = {
  newOnboarding: {
    enabled: () => process.env.NEXT_PUBLIC_NEW_ONBOARDING === 'true',
  },
};
```

When the flag is on, the page renders with a streaming Suspense boundary:

```typescript
// Rendered output (simplified)
<Suspense fallback={<OnboardingSkeleton />}>
  <OnboardingContent />
</Suspense>
```

When the flag is off, `notFound()` triggers Next.js's built-in 404 handling, keeping the route invisible to users on the legacy flow.

## Notes

- Marked `'use client'` — runs in the browser despite being a page-level component.
- Suspense boundary ensures the skeleton is shown immediately while `OnboardingContent` resolves any async data or lazy imports.
- See [`OnboardingContent`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/onboarding/components/onboarding-content.tsx) and [`OnboardingSkeleton`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/onboarding/components/onboarding-skeleton.tsx) for rendering details.
