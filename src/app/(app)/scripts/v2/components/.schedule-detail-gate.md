Relay data gate for the schedule detail pages. Suspends on the `scriptScheduleDetailRelayQuery`, seeds the loaded schedule into component state, and throws `NotFoundSignal` if the schedule is missing — ensuring consumers only ever receive a defined `ScheduleDetailData` payload.

## Key Components

| Export | Type | Description |
|---|---|---|
| `ScheduleDetailData` | Type alias | The non-null `scriptSchedule` payload from the detail query response |
| `ScheduleDetailGate` | Component | Public gate, keyed by `scheduleId` to force remount on schedule navigation |
| `ScheduleDetailGateInner` | Component (internal) | Holds `schedule` state; wraps seeder in `<Suspense fallback={null}>` and `<NotFoundBoundary>` |
| `ScheduleDetailGateProps` | Interface | Props: `scheduleId: string` + render-prop `children: (schedule) => ReactNode` |
| `ScheduleDataSeeder` | Component (internal) | Invisible data island — fires `useLazyLoadQuery`, seeds via `useLayoutEffect`, throws `NotFoundSignal` on missing schedule |

## Behavior Notes

- **`store-and-network` fetch policy** — always revalidates against the server; consumers must tolerate a second delivery (the edit form guards seeding on `!isDirty`)
- **`useLayoutEffect` seeding** — on a warm Relay store (e.g., navigating from the details page), the schedule is seeded before first paint, skipping the loading flash entirely
- **Keyed remount** — `ScheduleDetailGate` passes `key={scheduleId}` to the inner component, so navigating between schedules resets all state, boundaries, and forms cleanly

## Usage Example

```typescript
// Inside a schedule edit page component
<ScheduleDetailGate scheduleId={params.id}>
  {(schedule) => (
    <ScheduleEditForm
      // `schedule` is undefined while the query is in flight;
      // not-found never reaches here — NotFoundBoundary handles it
      schedule={schedule}
    />
  )}
</ScheduleDetailGate>
```
