Unified page component for creating and editing script schedules, handling form state, validation, GraphQL mutations, and navigation for both create and update workflows.

## Key Components

### `EditScheduleForm` (internal)
Core form component managing the full schedule editing lifecycle:
- **`scheduleId`** — `string | null`: determines create vs. update mode
- **`initialValues`** — `EditScheduleFormData | null`: pre-populated data for edit mode; seeded once without clobbering in-progress edits (`isDirty` guard)
- **`loading`** — `boolean`: disables all controls while schedule query is in flight (no skeleton swap pattern)

### `EditScheduleFormData` (exported type)
Zod-inferred form shape:
- `name` — required, 1–255 chars
- `description` — optional free text
- `supportedPlatforms` — min 1 platform ID string
- `scripts` — min 1 entry, each with `scriptId` + `name`

### `scheduleToFormValues` (internal helper)
Maps `ScheduleDetailData` (from Relay gate) into `EditScheduleFormData`, falling back to a single empty script row when no scripts exist.

## Usage Example

```typescript
// Rendered by the page shell via ScheduleDetailGate
// Create mode — no scheduleId
<EditScheduleForm
  scheduleId={null}
  initialValues={null}
/>

// Edit mode — data arrives asynchronously
<EditScheduleForm
  scheduleId="schedule-abc123"
  initialValues={scheduleToFormValues(scheduleData)}
  loading={false}
/>
```

## Behavior Notes

- **Error visibility**: validation errors are hidden until the first save attempt (`showErrors` flag), then track live — mirrors the script form contract
- **Platform toggles**: deselecting the last platform is allowed; the min-1 rule fires only on submit
- **Mutations**: uses Relay `useMutation` for both `createScriptScheduleMutation` and `updateScriptScheduleMutation`; on success, navigates to the schedule detail page via `router.replace`
