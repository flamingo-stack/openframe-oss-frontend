Route-level loading skeletons for the scripts-v2 detail surfaces, rendering through the real `ScriptPageChrome` shell so the initial page load shows the actual page structure rather than a generic placeholder.

## Key Components

| Export | Route | Description |
|--------|-------|-------------|
| `ScriptDetailsPageSkeleton` | `/scripts-v2/details` | Skeleton for the details page; supports both `details` and `executions` tab states via `tab` prop |
| `RunScriptPageSkeleton` | `/scripts-v2/details/run` | Skeleton for the run script page with disabled form fields, argument blocks, and device selector in loading mode |
| `EditScriptPageSkeleton` | `/scripts-v2/edit` and `/scripts-v2/new` | Skeleton for the edit/create form; accepts `mode` prop to set the chrome title |

## Usage Example

```typescript
// app/scripts-v2/details/loading.tsx
import { ScriptDetailsPageSkeleton } from './script-page-skeletons';

export default function Loading() {
  return <ScriptDetailsPageSkeleton tab="executions" />;
}

// app/scripts-v2/details/run/loading.tsx
import { RunScriptPageSkeleton } from './script-page-skeletons';

export default function Loading() {
  return <RunScriptPageSkeleton />;
}

// app/scripts-v2/new/loading.tsx
import { EditScriptPageSkeleton } from './script-page-skeletons';

export default function Loading() {
  return <EditScriptPageSkeleton mode="new" />;
}
```

## Notes

- The `inert` HTML attribute is used on `ScriptDetailsPageSkeleton`'s content div (rather than wrapping `TabNavigation`) to fully remove the placeholder subtree from the accessibility tree and tab order, while keeping the chrome's Back button focusable.
- Monaco editor is intentionally omitted from `EditScriptPageSkeleton` — a `Skeleton` block is used instead since mounting Monaco for a placeholder has a higher cost than the fidelity gain.
- All action buttons are rendered in a `disabled` state to match the real page chrome.
