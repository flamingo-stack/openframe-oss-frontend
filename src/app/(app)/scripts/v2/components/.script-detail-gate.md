Renders the edit/run script pages with a "pour data in after mount" pattern: children render immediately in an empty/disabled state while the Relay query is in-flight, then receive the script payload once loaded — avoiding skeleton swaps and preventing Monaco editor remounts.

## Key Components

### `ScriptDetailGate` (exported)
Top-level gate component that wraps `ScriptDetailGateInner` with `key={scriptId}`. The explicit key ensures a full remount (state, boundary, and form) on script ID changes, preventing stale data from a previous script leaking into a new route segment.

### `ScriptDetailGateInner`
Holds gate-owned `useState` for the script payload. Composes `NotFoundBoundary`, a silent `<Suspense fallback={null}>`, and the seeder. Passes `script | undefined` to children via render prop.

### `ScriptDataSeeder` (internal)
Executes the `scriptDetailRelayQuery` via `useLazyLoadQuery` with `store-and-network` fetch policy. Uses `useLayoutEffect` to seed data before first paint on warm Relay store navigations. Throws `NotFoundSignal` if the query returns no script, triggering the full-page not-found state.

### `ScriptDetailData` (exported type)
`NonNullable` unwrap of the `script` field from the query response — consumers never handle `null`.

## Usage Example

```typescript
// app/scripts/[id]/edit/page.tsx
import { ScriptDetailGate, type ScriptDetailData } from './script-detail-gate';

export default function EditScriptPage({ params }: { params: { id: string } }) {
  return (
    <ScriptDetailGate scriptId={params.id}>
      {(script) => (
        // Renders immediately; `script` is undefined while loading.
        // Guard seeding effects on `!isDirty` to handle late store-and-network
        // revalidation delivering a second value.
        <ScriptEditForm script={script} />
      )}
    </ScriptDetailGate>
  );
}
```

> **`store-and-network` note:** The seeder may deliver the script twice — once from the Relay store cache and again after the network response. Child forms should guard any seeding effects with `!isDirty` to avoid overwriting user edits on revalidation.
