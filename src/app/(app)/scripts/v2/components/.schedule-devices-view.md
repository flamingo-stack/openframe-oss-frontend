Relay-powered "Edit Devices" page for a script schedule, allowing users to view and update the set of devices assigned to a schedule via the `setScriptScheduleDevices` mutation.

## Key Components

| Export / Component | Description |
|---|---|
| `ScheduleDevicesView` | Root export. Wraps content in `ScheduleDetailGate` to gate rendering on schedule data availability. |
| `ScheduleDevicesContent` | Inner page logic: manages device selection state, seeds from current assignment, and commits the mutation on save. |
| `AssignedDevicesSeeder` | Invisible Suspense island that runs a separate lazy query for the schedule's current device assignment and hands results up via `onData`. Kept outside the detail gate to avoid blocking the page chrome and device list. |

## Usage Example

```typescript
// Render the Edit Devices page for a given schedule
<ScheduleDevicesView scheduleId="U2NoZWR1bGU6MTIz" />
```

## Key Behaviors

- **Two-query split**: Schedule metadata comes from `ScheduleDetailGate`; current device assignment comes from `AssignedDevicesSeeder` using a dedicated heavier query — so chrome, info bar, and the candidate list render without waiting on per-machine resolution.
- **One-time selection seed**: `seededRef` ensures the `selectedIds` state is seeded from `assigned` exactly once — subsequent re-deliveries of assignment data never clobber in-progress edits.
- **Key → Global ID resolution**: Before committing, `handleSave` builds a `Map` merging both the fetched candidate list and the current assignment, so devices beyond the fetch limit (assigned but not in candidates) are still included in the mutation payload.
- **Save guard**: The Save button stays disabled until both `schedule` and `assigned` are loaded, preventing a save from wiping an unseen assignment.
