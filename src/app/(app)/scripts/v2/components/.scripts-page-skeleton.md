Route-level loading skeleton for the `/scripts-v2` and `/scripts-v2/schedules` pages, rendering a placeholder tab bar, action buttons, and table columns while content loads.

## Key Components

### `ScriptsPageSkeleton`

The default export component that accepts a `view` prop (`'list'` | `'schedules'`, defaults to `'list'`) and renders the appropriate skeleton variant via `ListPageSkeleton`.

### Constants

| Constant | Description |
|---|---|
| `SCRIPT_COLUMNS` | Column layout mirroring `scripts-table.tsx` (name, shell type, OS, added by, actions) |
| `SCHEDULE_COLUMNS` | Column layout mirroring `script-schedules-table.tsx` (script, OS, date/time, repeat, devices, actions) |
| `SCRIPT_ACTIONS` | Disabled "Archive" and "Add Script" action buttons |
| `SCHEDULE_ACTIONS` | Disabled "Archive" and "Add Schedule" action buttons |
| `TAB_WIDTHS` | Tab bar widths rendered only when the `script-schedules` feature flag is enabled |

## Usage Example

```typescript
// Default scripts list skeleton
<ScriptsPageSkeleton />

// Schedules tab skeleton
<ScriptsPageSkeleton view="schedules" />
```

## Feature Flag Behavior

The tab bar is conditionally rendered based on the `script-schedules` feature flag via `skeletonFlagEnabled`. This consults the last cached server answer rather than a raw store read, preventing a flash of the wrong tab bar on cold starts for tenants with the flag enabled.

## Notes

- Column definitions mirror the real table components — keep them in sync when updating `scripts-table.tsx` or `script-schedules-table.tsx`
