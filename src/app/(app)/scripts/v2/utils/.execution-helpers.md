Presentation and formatting helpers for script execution records, providing consistent labels, tag variants, and display values shared across the Execution History table and single-execution details page.

## Key Components

### Types

- **`TagVariant`** — Union type for UI tag color variants: `'success' | 'error' | 'warning' | 'grey'`
- **`MachineLike`** — Structural interface for machine objects with optional `machineId`, `hostname`, `displayName`, and `organization`
- **`InitiatorLike`** — Structural interface for user objects with optional `firstName`, `lastName`, and `email`
- **`ExecutionResultLike`** — Structural interface for execution result objects with optional `stdout`, `stderr`, and `error`

### Functions

| Function | Description |
|---|---|
| `formatExecutionTimestamp` | Formats a date/time value as `"date, time"` in the user's locale (e.g. `"6/26/26, 2:31 PM"`), returns `"—"` for nullish input |
| `executionStatusLabel` | Maps `ScriptExecutionStatus` to a human-readable label (`SUCCESS` → `"Completed"`) |
| `executionStatusVariant` | Maps `ScriptExecutionStatus` to a `TagVariant` for UI coloring |
| `privilegeLevelLabel` | Maps `PrivilegeLevel` to a display label (`ADMIN` → `"System"`) |
| `machineLabel` | Resolves the best display name for a machine (`displayName → hostname → machineId`) |
| `organizationLabel` | Returns the organization name for a machine, or empty string |
| `initiatorName` | Resolves a full name from a user object, falling back to email then `"Unknown"` |
| `initiatorInitials` | Derives up-to-two-letter initials for avatar fallbacks |
| `executionResultText` | Returns the first non-empty output string from `stdout → stderr → error` |

## Usage Example

```typescript
import {
  formatExecutionTimestamp,
  executionStatusLabel,
  executionStatusVariant,
  machineLabel,
  initiatorName,
  initiatorInitials,
  executionResultText,
} from '@/features/executions/execution-helpers';

// Timestamp formatting
formatExecutionTimestamp('2026-06-26T14:31:00Z'); // "6/26/26, 2:31 PM"
formatExecutionTimestamp(null);                    // "—"

// Status label and tag variant
executionStatusLabel('SUCCESS');   // "Completed"
executionStatusVariant('FAILED');  // "error"
executionStatusVariant('RUNNING'); // "warning"

// Machine display
const machine = { displayName: 'Prod Server', hostname: 'srv-01', machineId: 'abc123' };
machineLabel(machine); // "Prod Server"
machineLabel(null);    // "—"

// Initiator display
const user = { firstName: 'Jane', lastName: 'Doe', email: 'jane@example.com' };
initiatorName(user);     // "Jane Doe"
initiatorInitials(user); // "JD"
initiatorInitials(null); // "UN"

// Result text
executionResultText({ stdout: 'OK', stderr: '', error: '' }); // "OK"
executionResultText({ stdout: '', stderr: 'timeout' });        // "timeout"
```

## Notes

- All functions handle `null` and `undefined` inputs gracefully, returning `"—"` or safe fallbacks.
- `executionStatusLabel` and `executionStatusVariant` accept raw strings in addition to the typed enum, allowing use with partially-typed GraphQL responses.
- Enum values are imported from `@/generated/schema-enums` — no hardcoded string literals.
