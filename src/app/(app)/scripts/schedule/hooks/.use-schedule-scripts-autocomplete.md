Provides server-side script autocomplete state management for the schedule form, using Relay's `fetchQuery` for lazy, non-suspending data fetching with debounced search and platform filtering.

## Key Components

### `PickerScript` (interface)
Shape of a script item returned by the autocomplete query, containing `id`, `name`, `supportedPlatforms`, and `defaultTimeoutSeconds`.

### `useScheduleScriptsAutocomplete(supportedPlatforms)`
Main hook that manages autocomplete lifecycle:
- **Lazy fetching** — query only fires while the dropdown is active (`isActive`)
- **Debounced input** — 300ms debounce via `useDebounce` to limit query frequency
- **Imperative fetch** — uses `fetchQuery` with `store-or-network` policy so results cache in the Relay store without suspending the parent form
- **Platform filtering** — converts raw platform strings to GraphQL enums via `platformsToEnums`; uses a stable `platformsKey` string to avoid effect re-runs from referentially new arrays
- **Auto-reset** — clears `inputValue` on close so the next open starts unfiltered

## Usage Example

```typescript
const {
  scripts,
  isLoading,
  inputValue,
  onInputChange,
  onOpen,
  onClose,
} = useScheduleScriptsAutocomplete(['windows', 'macos']);

// Wire into a combobox/dropdown:
<Combobox
  options={scripts}
  inputValue={inputValue}
  onInputChange={onInputChange}
  onOpen={onOpen}
  onClose={onClose}
  loading={isLoading}
/>
```

## Notes

- Fetches a maximum of 20 scripts per query (`first: 20`)
- Passing an empty `supportedPlatforms` array omits the platform filter, returning scripts for all platforms
- The Relay subscription is cleaned up on unmount or when dependencies change, preventing stale updates
