Unified page component for creating and editing script schedules, handling form state, validation, GraphQL mutations, and navigation for both create and update workflows.

## Key Components

### `ScheduleFormPage` (internal)
The page around the fields — title, Back, the action bar and the form instance. Reads nothing from the server, so it renders on the first pass and is never replaced by a placeholder. Holds the record state (`loading | missing | ready`), locks the fields through `ScheduleFormFields.disabled` until the schedule lands, and seeds the form via `useSeedForm` (which must run here, in the owner of `useForm` — see that hook for why).

### `ScheduleRecordLoader` (internal)
The page's data island, and it renders **nothing**. It reads `scriptScheduleDetailRelayQuery` and hands the mapped form values up through `onResolved`; its `Suspense` fallback is `null`, because what it is loading is already drawn below, locked. This is what removes the last guess from the page: the form BRANCHES on the trigger (a DATE_TIME schedule shows Date / Time / Repeat where an event-driven one collapses that row), which a skeleton had to pick blind — arriving from the details page the schedule is already in the Relay store, so the seed lands before the first paint and the right branch is simply what gets drawn.

### `EditScheduleFormData` (exported type)
Zod-inferred form shape:
- `name` — required, 1–255 chars
- `description` — optional free text
- `supportedPlatforms` — min 1 platform ID string
- `scripts` — min 1 entry, each with `scriptId` + `name`

### `scheduleToFormValues` (internal helper)
Maps `ScheduleDetailData` (from Relay gate) into `EditScheduleFormData`, falling back to a single empty script row when no scripts exist.

## Usage Example

```typescript
// Rendered by the page shell via ScheduleDetailGate
// Create mode — no scheduleId
<EditScheduleForm
  scheduleId={null}
  initialValues={null}
/>

// Edit mode — data arrives asynchronously
<EditScheduleForm
  scheduleId="schedule-abc123"
  initialValues={scheduleToFormValues(scheduleData)}
  loading={false}
/>
```

## Behavior Notes

- **Error visibility**: validation errors are hidden until the first save attempt (`showErrors` flag), then track live — mirrors the script form contract
- **Platform toggles**: deselecting the last platform is allowed; the min-1 rule fires only on submit
- **Mutations**: uses Relay `useMutation` for both `createScriptScheduleMutation` and `updateScriptScheduleMutation`; on success, navigates to the schedule detail page via `router.replace`
