Full-page view component for displaying script details, combining page chrome, header metadata, and tab-based content (script details + execution history) with Relay-powered data fetching and Suspense-based loading states.

## Key Components

| Export | Type | Description |
|---|---|---|
| `ScriptDetailsView` | Component | Root page component; renders chrome, header, and tabbed content |
| `ScriptHeaderSection` | Component | Suspense island — fetches and renders tag chips + summary card |
| `ScriptHeaderSkeleton` | Component | Loading placeholder for the header island |
| `ScriptDetailsTab` | Component | Details tab: a Suspense island for the param cards, plus the source editor beside it |
| `DETAIL_TABS` | Constant | Two-tab config: `details` (Script Details) and `executions` (Execution History) |

**Internal:** `ScriptParamCards` (the suspending island — fetches args/env vars and hands the source up), `InfoCardSkeleton` / `ScriptParamCardsSkeleton` (its fallback). The editor is deliberately OUTSIDE that boundary, mounted from the first render with `loading`, so the editor builds while the query is still out, shows one placeholder for the whole wait, and is never built twice.

## Architecture Notes

- **Relay deduplication:** `ScriptHeaderSection` uses `store-and-network` to revalidate on mount; `ScriptParamCards` — the island inside `ScriptDetailsTab` that actually issues the query — uses `store-or-network` to avoid redundant refetches on tab re-entry.
- **Not-found escalation:** `ScriptHeaderSection` throws `NotFoundSignal` when the script is missing; `NotFoundBoundary` (keyed by `scriptId`) catches it and renders a full-page error state — and resets on client-side navigation to a new script ID.
- **Mingo context tracking:** `useTrackOpenView` receives the raw DB ID (decoded from the Relay global ID) to register the script in the AI assistant's open-view context.

## Usage Example

```typescript
// Used as the page-level component in the [id] route segment
<ScriptDetailsView scriptId="U2NyaXB0OjEyMw==" />
```
