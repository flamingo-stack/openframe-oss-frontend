Thin wrapper around `ConfirmDialog` that presents a confirmation modal for restoring an archived script back to active status.

## Key Components

- **`RestoreScriptModal`** — Named export; renders a pre-configured `ConfirmDialog` with restore-specific copy and a `"default"` variant (non-destructive styling).
- **`RestoreScriptModalProps`** — Interface defining the four props passed through to `ConfirmDialog`.

| Prop | Type | Description |
|---|---|---|
| `open` | `boolean` | Controls modal visibility |
| `onOpenChange` | `(open: boolean) => void` | Callback for open/close state changes |
| `onConfirm` | `() => void` | Called when the user confirms the restore action |
| `isPending` | `boolean?` | Disables actions and shows `"Restoring..."` label during async operation |

## Usage Example

```typescript
import { RestoreScriptModal } from './restore-script-modal';

function ScriptActions({ scriptId }: { scriptId: string }) {
  const [open, setOpen] = useState(false);
  const { mutate, isPending } = useRestoreScript();

  return (
    <>
      <button onClick={() => setOpen(true)}>Restore</button>
      <RestoreScriptModal
        open={open}
        onOpenChange={setOpen}
        onConfirm={() => mutate(scriptId)}
        isPending={isPending}
      />
    </>
  );
}
```

## Notes

- Delegates all rendering to [`ConfirmDialog`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/components/shared/confirm-dialog.tsx) — this component only provides fixed string constants and the `"default"` variant.
- The `isPending` prop should reflect the in-flight state of the restore mutation to prevent double-submits.
