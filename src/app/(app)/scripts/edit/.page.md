Wrapper page component for the script editing route that extracts and validates the required `id` URL parameter before rendering the edit UI.

## Key Components

- **`EditScriptPageWrapper`** — Default export; a client-side page component that guards against missing route parameters and delegates rendering to `EditScriptPage`.
- **`useRequiredIdParam`** — Hook that reads the `id` param from the URL, redirecting to `/scripts` or the new-script route if absent.
- **`EditScriptPage`** — The actual edit UI component, rendered only when a valid `scriptId` is available.

## Usage Example

This component is used as a Next.js dynamic route page (e.g., `app/scripts/[id]/edit/page.tsx`). No direct instantiation is needed — Next.js mounts it automatically.

```typescript
// Rendered by Next.js for routes like /scripts/abc-123/edit
// If `id` is missing or invalid, the user is redirected to /scripts or routes.scripts.new
export default function EditScriptPageWrapper() {
  const id = useRequiredIdParam('/scripts', routes.scripts.new);
  if (!id) return null;
  return <EditScriptPage scriptId={id} />;
}
```

The `null` return acts as a render guard — preventing `EditScriptPage` from mounting with an undefined `scriptId` during any redirect transition.

## Notes

- Marked `'use client'` — runs entirely on the client side.
- Redirect fallback targets are `/scripts` (list view) and `routes.scripts.new` (create flow), ensuring graceful degradation for invalid URLs.
