Renders the Edit Schedule page for the Scripts feature, extracting and validating the required schedule ID from the route parameters before delegating to the `EditSchedulePage` component.

## Key Components

- **`EditScheduleV2Page`** — Default export; a client-side page component that retrieves the `id` param using `useRequiredIdParam`, guards against missing IDs, and renders `EditSchedulePage` with the resolved `scheduleId`.
- **`useRequiredIdParam`** — Hook that enforces a valid ID in the URL, redirecting to the new schedule route (`routes.scripts.schedules.new`) if absent.
- **`EditSchedulePage`** — The presentational/logic component from the Scripts feature that handles the full edit schedule UI.

## Usage Example

This page is automatically rendered by the Next.js router when navigating to a path such as `/scripts/schedules/[id]/edit`. No manual instantiation is needed, but the underlying component can be used directly:

```typescript
import { EditSchedulePage } from '@/app/(routes)/scripts/scripts/components/edit-schedule-page';

// Direct usage (e.g., in tests or Storybook)
<EditSchedulePage scheduleId="schedule-123" />
```

## Notes

- The `'use client'` directive marks this as a Client Component, enabling hooks and interactivity.
- If the `id` param is missing or invalid, `useRequiredIdParam` handles the redirect; the component returns `null` in the interim to avoid rendering with an undefined ID.
