A Next.js layout component that guards all `/scripts/schedules/*` routes behind the `script-schedules` feature flag, redirecting unauthorized users to the Scripts list.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `ScriptSchedulesLayout` | Default export | Route-level feature flag gate for script schedules routes |

**Dependencies:**

- `useFeatureFlagsStore` — subscribes to the resolved `script-schedules` flag from the Zustand store
- `featureFlags.scriptSchedules.enabled()` — env-var fallback when the server value is unavailable
- `routes.scripts.list` — redirect target when the flag is disabled

## Usage Example

```typescript
// app/scripts/schedules/layout.tsx (this file)
// Wraps all child routes under /scripts/schedules/*
export default function ScriptSchedulesLayout({ children }: { children: React.ReactNode }) {
  // Reads server-resolved flag; falls back to env-var default
  const serverValue = useFeatureFlagsStore(s => (s.isLoaded ? s.flags['script-schedules'] : undefined));
  const enabled = serverValue ?? featureFlags.scriptSchedules.enabled();

  // Redirect and render nothing when flag is off
  useEffect(() => {
    if (!enabled) router.replace(routes.scripts.list);
  }, [enabled, router]);

  if (!enabled) return null;
  return <>{children}</>;
}
```

## Behavior Notes

- **No flash:** the flag is read as a tri-state (`useFeatureFlagGate`), so an unanswered flag renders the loading branch instead of redirecting on a guess
- **Reactivity:** Subscribes to the store so the gate re-evaluates if flag values change at runtime
- **UI parity:** The "Scripts Schedules" tab is hidden via the same flag in `scripts-tabs.tsx`, keeping navigation consistent
