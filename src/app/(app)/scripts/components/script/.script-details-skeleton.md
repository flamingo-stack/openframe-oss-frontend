Loading state skeleton component for the script details page, rendering placeholder UI while script data is being fetched.

## Key Components

- **`InfoFieldSkeleton`** — Renders a two-line skeleton (value + label) for individual info fields. Accepts a `valueWidth` prop to vary the top line's width.
- **`ScriptInfoSectionSkeleton`** — Composes a card skeleton with a description row and a responsive 3-column grid mimicking Shell Type, Supported Platforms, and Category fields.
- **`CodeEditorSkeleton`** — Renders 12 skeleton lines with algorithmically varied widths to simulate code content inside a fixed-height editor area.
- **`ScriptDetailsSkeleton`** *(exported)* — Top-level skeleton for the full script details page, combining the page header, action buttons, info section, and code editor placeholders inside a `PageLayout`.

## Usage Example

```typescript
import { ScriptDetailsSkeleton } from './script-details-skeleton';

// Render while the script data is loading
export default function ScriptDetailsPage() {
  const { data, isLoading } = useScriptDetails(scriptId);

  if (isLoading) {
    return <ScriptDetailsSkeleton />;
  }

  return <ScriptDetailsContent script={data} />;
}
```

## Notes

- Uses `Skeleton` and `PageLayout` from `@flamingo-stack/openframe-frontend-core`.
- The `CodeEditorSkeleton` line widths are computed as `Math.max(20, 80 - i * 5 + ((i * 17) % 30))` to produce a natural-looking stagger without randomness, ensuring consistent SSR/CSR output.
- Marked `'use client'` as it renders inside the Next.js App Router client boundary.
