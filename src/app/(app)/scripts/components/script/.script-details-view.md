A read-only detail view component for displaying a single automation script's metadata, arguments, environment variables, and syntax with Edit/Run action buttons.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `ScriptDetailsView` | Component | Main detail view accepting a `scriptId` prop |
| `ScriptDetailsViewProps` | Interface | `{ scriptId: string }` |

**Internal composition:**

- `useScriptDetails` — fetches script data, loading state, and errors
- `useSafeBack` — navigates back to the scripts list safely
- `useTrackOpenView` — registers the script as the active Mingo context entity (cleared on unmount)
- `ScriptArgumentsCard` — renders args and environment variable tables
- `ScriptEditor` — read-only syntax-highlighted code editor
- `ScriptInfoSection` — displays shell type, platforms, category, and description

**Conditional rendering states:**

- `isLoading` → `ScriptDetailsSkeleton`
- `error` → `LoadError`
- `!scriptDetails` → `NotFoundError`

## Usage Example

```typescript
// Render the detail view for a specific script ID (e.g., from a route param)
import { ScriptDetailsView } from './script-details-view';

export default function ScriptDetailPage({ params }: { params: { id: string } }) {
  return <ScriptDetailsView scriptId={params.id} />;
}
```

**Action behavior:**

- **Edit Script** — always rendered; navigates to `routes.scripts.edit(scriptId)`
- **Run Script** — only rendered when `scriptDetails.id` resolves; navigates to `routes.scripts.run(id)`

## Notes

- Uses `useMemo` to stabilize the `actions` array, preventing unnecessary re-renders on parent updates.
- The Mingo tracking call passes `null` during loading, so the context entity is only registered once data is available.
