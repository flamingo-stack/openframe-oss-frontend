Detail view component for displaying and managing a script schedule, rendering schedule metadata, navigation tabs, and action buttons within a URL-driven tab layout.

## Key Components

### `ScheduleDetailView`
Main exported component that accepts a `scheduleId` prop and orchestrates the full schedule detail page, including:
- **Loading/error states** — renders `ScheduleDetailSkeleton`, `LoadError`, or `NotFoundError` as appropriate
- **URL-driven tab navigation** — reads/writes the active tab via the `tab` query parameter using `router.replace` to avoid flicker bugs from `urlSync` mode
- **Page actions** — memoized "Edit Devices" and "Edit Schedule" buttons linking to their respective routes

### Tab Configuration (`SCHEDULE_TABS`)
Three tabs rendered via `TabNavigation` + `TabContent`:

| Tab ID | Label | Component |
|---|---|---|
| `schedule-scripts` | Scheduled Scripts | `ScheduleScriptsTab` |
| `schedule-devices` | Assigned Devices | `ScheduleDevicesTab` |
| `schedule-history` | Execution History | `ScheduleHistoryTab` |

## Usage Example

```typescript
// Rendered by a parent page component that receives scheduleId from route params
import { ScheduleDetailView } from './schedule-details-view';

export default function ScheduleDetailPage({ params }: { params: { id: string } }) {
  return <ScheduleDetailView scheduleId={params.id} />;
}
```

Tab state is managed via URL query params — navigating to `/schedules/123?tab=schedule-history` activates the Execution History tab directly. Invalid or missing `tab` values fall back to `schedule-scripts`.
