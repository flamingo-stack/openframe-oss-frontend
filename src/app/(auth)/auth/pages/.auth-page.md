The main authentication page component that handles new organization registration, rendering the sign-up form with SSO provider options and managing redirects for already-authenticated users.

## Key Components

- **`AuthPage`** — Default export; Next.js page component mounted at the `/auth` route
- **`useAuth`** — Provides `isLoading` state and `registerOrganizationSso` mutation
- **`useRegistrationProviders`** — Fetches available SSO providers from the backend
- **`useAuthStore`** — Reads `isAuthenticated` to guard against re-entering the auth flow
- **`CreateOrganizationSection`** — Form UI for org name, domain, and email input
- **`TabSelector`** — Sign Up / Login tab switcher; navigates to `/auth/login` on tab change

## Behavior Notes

- Authenticated users are redirected to the dashboard via `router.replace` (not `push`), preventing `/auth` from remaining in the back stack
- The Login tab chunk is prefetched on mount so tab switching is instant with no loading skeleton flash
- On email/password sign-up, org details (`org_name`, `domain`, `email`) are persisted to `sessionStorage` before navigating to `/auth/signup/`
- SSO registration is filtered to `google` and `microsoft` providers only, cross-referenced against what the backend reports as available

## Usage Example

```typescript
// Rendered automatically by Next.js at /auth
// No props required — all state is sourced from hooks and stores

// sessionStorage keys written on org creation:
// 'auth:org_name', 'auth:domain', 'auth:email'

// SSO flow example (invoked internally):
registerOrganizationSso({
  tenantName: 'Acme Corp',
  tenantDomain: 'acme.com',
  email: 'admin@acme.com',
  provider: 'google',
  redirectTo: '/auth/login',
});
```
