Stateful wrapper component that connects the shared `CreateOrganizationForm` UI to the sign-up registration flow, handling field state, validation, email/domain availability checks, and SSO registration.

## Key Components

### `CreateOrganizationSection` (exported function component)

Owns all form state and validation logic before delegating submission upward via callbacks.

**Props (`CreateOrganizationSectionProps`):**

| Prop | Type | Description |
|---|---|---|
| `onRegister` | `({orgName, domain, email, firstName, lastName, password}) => void` | Primary submit callback |
| `onSsoLogin` | `(provider) => void` | Provider sign-up with nothing filled in |
| `ssoProviders` | `AuthSsoProvider[]` | Provider buttons, rendered above the email field on step one |
| `isLoading` | `boolean` | External loading state |

**Internal responsibilities:**
- **Two steps, one screen** — `step === 'email'` renders `LoginForm` (providers + email + Continue); the details step renders `CreateOrganizationForm` with the email read-only and a Back action
- **Email validation** — regex check + live availability via `useEmailAvailability`; Continue waits for that check to settle, since step two cannot correct the address
- **Credentials** — first/last name and password, with `MIN_PASSWORD_LENGTH` from `constants/registration-validation`

**Delegated:**
- The whole subdomain concern — sanitizing, live availability, the `409 TENANT_REGISTRATION_BLOCKED` capacity case, suggestion merging and the submit-time re-check — belongs to `useOrganizationDomain`, shared with the two SSO screens; the chips render via `DomainSuggestions`

## Usage Example

```typescript
<CreateOrganizationSection
  onRegister={payload => {
    // handle account creation
  }}
  ssoProviders={[{ id: 'google', label: 'Google' }]}
  isLoading={isPending}
/>
```
