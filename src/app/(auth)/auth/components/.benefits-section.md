A client-side React component that renders the authentication page's right-hand benefits panel, with two modes: a waitlist signup form (for `saas-shared` app mode) and a static benefits display (for all other modes).

## Key Components

- **`AuthBenefitsSection`** — Primary exported component with conditional rendering based on `appMode`
- **`handleRegister`** — Async callback that submits email/phone to the OpenFrame waitlist API (`https://content-api.openframe.ai/api/waitlist`), handles duplicate emails gracefully, and attaches Reddit click IDs for ad attribution
- **Waitlist mode** (`saas-shared`) — Renders `WaitlistForm` with OpenFrame branding and early-access messaging
- **Benefits mode** (default) — Renders three static `BenefitCard` components: "Cut Vendor Costs", "Automate Everything", "Reclaim Your Profits"

## Usage Example

```typescript
// Rendered automatically within the auth layout.
// App mode is resolved from runtime environment config.
import { AuthBenefitsSection } from '@/components/auth/benefits-section';

export default function AuthLayout({ children }: { children: React.ReactNode }) {
  return (
    <div className="flex min-h-screen">
      <main className="flex-1">{children}</main>
      <aside className="hidden lg:block w-1/2">
        <AuthBenefitsSection />
      </aside>
    </div>
  );
}
```

## Notes

- Reddit click ID (`rdt_cid`) is read from local storage via `getStoredRedditClickId()` and cleared on successful submission for one-time attribution tracking
- Duplicate email responses (`DUPLICATE_EMAIL`) are treated as soft successes — `isSuccess` is set to `true` and the user sees an informational toast rather than an error
- Styling relies on ODS (OpenFrame Design System) CSS custom properties such as `--color-accent-primary` and `--color-text-primary`
