Smart login section component that wires the shared `LoginForm` UI to tenant discovery logic — debouncing email input, running account lookup, and unlocking SSO provider buttons only when a valid tenant is found.

## Key Components

### `LoginDiscoveryResult`
Interface representing the outcome of a tenant discovery call:
- `found` — whether an account exists for the email
- `providers` — list of available SSO providers for that tenant

### `LoginSection`
The main exported component managing the full discovery lifecycle:

| Prop | Description |
|---|---|
| `onDiscover` | Async callback to resolve tenant by email; returns `null` on failure |
| `onSso` | Called when the user selects an SSO provider |
| `allProviders` | Full provider list (rendered disabled until discovery succeeds) |
| `isLoading` | Optional loading state passed through to the form |

**Internal state machine** (`DiscoveryStatus`): `idle` → `checking` → `found` / `not-found` / `error`

- Email is debounced 400ms before triggering discovery
- Stale results from previous emails are discarded via a `cancelled` flag
- `onDiscover` is stored in a `ref` to prevent the effect from re-running on parent re-renders

## Usage Example

```typescript
import { LoginSection } from './login-form-section';

async function discoverTenant(email: string) {
  const res = await fetch(`/api/tenant-discovery?email=${email}`);
  if (!res.ok) return null;
  return res.json(); // { found: boolean, providers: AuthSsoProvider[] }
}

<LoginSection
  onDiscover={discoverTenant}
  onSso={(provider) => signInWithSso(provider)}
  allProviders={['google', 'microsoft']}
  isLoading={isSubmitting}
/>
```
