Loading placeholder for authentication pages, rendering the real `AuthShell` with skeleton content matching each form variant to prevent layout shift during page load.

## Key Components

| Export | Type | Description |
|---|---|---|
| `AuthPageSkeleton` | Component | Main exported skeleton component wrapping `AuthShell` with variant-specific form placeholders |
| `AuthPageSkeletonVariant` | Type | Union type: `'create-organization'` \| `'login'` \| `'complete-account'` |
| `AuthPageSkeletonProps` | Interface | `variant` (defaults to `'create-organization'`) and `withTabs` (defaults to `true`) |

**Internal skeleton primitives:**

- `FieldSkeleton` — label + input placeholder (matches `text-h4` label + `Input`)
- `ButtonSkeleton` — default-size `Button` placeholder
- `HeaderSkeleton` — title + subtitle placeholder (matches `text-h2` + `text-h4`)
- `CreateOrganizationFormSkeleton` — header, 3 fields, terms checkbox, single action button
- `LoginFormSkeleton` — header, 1 field, forgot-password + continue buttons
- `CompleteAccountFormSkeleton` — header, 4 fields, back + submit buttons

## Usage Example

```typescript
// Default: create-organization form while the page loads
<AuthPageSkeleton />

// Login page — no tabs (e.g. invite flow)
<AuthPageSkeleton variant="login" withTabs={false} />

// Complete account form
<AuthPageSkeleton variant="complete-account" />
```

## Notes

- Uses `role="status"` and `aria-label` for accessibility during loading states
- The `withTabs` prop hides the tab selector skeleton on invite-style pages where tab switching is unavailable
- Variant-to-skeleton mapping is handled via the `FORM_SKELETONS` record, making it straightforward to add new variants
