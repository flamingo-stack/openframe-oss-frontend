Defines a Relay GraphQL query that fetches the three backend signals required by the client-side tenant onboarding auto-detect logic in a single network round-trip.

## Key Components

### `tenantOnboardingAutoDetectRelayQuery`

A `graphql` tagged template literal exported for use with `useTenantOnboardingAutoDetect`. Fetches:

| Field | Purpose |
|---|---|
| `tenantInfo` | MSP profile completeness — `name`, `website`, and `image.imageUrl` |
| `organizations(first: 1).filteredCount` | Total customer/organization count |
| `deviceFilters(filter: $deviceFilter).filteredCount` | Connected device count; caller passes `statuses:[ONLINE, OFFLINE]` to exclude archived/pending devices |

## Usage Example

```typescript
// Inside useTenantOnboardingAutoDetect (network-only to reflect current state)
const data = useLazyLoadQuery<tenantOnboardingAutoDetectRelayQuery>(
  tenantOnboardingAutoDetectRelayQuery,
  { deviceFilter: { statuses: ['ONLINE', 'OFFLINE'] } },
  { fetchPolicy: 'network-only' },
);

const hasProfile =
  !!data.tenantInfo?.name &&
  !!data.tenantInfo?.website &&
  !!data.tenantInfo?.image?.imageUrl;

const hasCustomer  = (data.organizations?.filteredCount ?? 0) > 0;
const hasDevice    = (data.deviceFilters?.filteredCount ?? 0) > 0;
```

> ⚠️ **Temporary stopgap** — this query exists because the backend does not yet compute step completion inside `tenantOnboardingProgress`. Once that lands, this file and `useTenantOnboardingAutoDetect` should be removed. User count is intentionally omitted here; it is sourced from the REST `api/users` endpoint (`totalElements`) because the GraphQL `users` count did not match the Settings → Employees figure.
