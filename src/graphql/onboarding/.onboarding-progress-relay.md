Fetches and synchronizes tenant/user onboarding progress from the GraphQL backend into the Zustand onboarding store using Relay.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `onboardingProgressRelayQuery` | GraphQL query | Relay query for tenant and user onboarding progress (completed steps, completion state, skip state) |
| `OnboardingProgress` | Interface | Store-ready shape pairing `TenantOnboardingProgress` and `UserOnboardingProgress` |
| `syncOnboardingStore()` | Function | Parses a query/mutation response and writes both progress objects into the Zustand store |
| `fetchOnboardingProgress()` | Async function | Network-only fetch of onboarding progress; syncs the store and returns `null` on empty payload or error |
| `refreshOnboardingProgress()` | Function | Fire-and-forget wrapper around `fetchOnboardingProgress` for app-shell mount hydration |

## Usage Example

```typescript
// App-shell mount — hydrate the onboarding store silently on load
import { refreshOnboardingProgress } from '@/relay/onboarding-progress-relay';
import { useRelayEnvironment } from 'react-relay';

function AppShell() {
  const environment = useRelayEnvironment();

  useEffect(() => {
    refreshOnboardingProgress(environment);
  }, [environment]);
}

// Explicit fetch — e.g. after a tenant switch or mutation
import { fetchOnboardingProgress } from '@/relay/onboarding-progress-relay';

async function handleTenantSwitch(environment: IEnvironment) {
  const progress = await fetchOnboardingProgress(environment);
  if (!progress) {
    console.warn('Onboarding progress unavailable');
    return;
  }
  console.log('Tenant completed:', progress.tenant.completed);
}

// Sync after a mutation that returns onboarding fields
import { syncOnboardingStore } from '@/relay/onboarding-progress-relay';

const progress = syncOnboardingStore({
  tenantOnboardingProgress: mutationResponse.tenantOnboardingProgress,
  userOnboardingProgress: mutationResponse.userOnboardingProgress,
});
```

## Notes

- Uses `fetchPolicy: 'network-only'` to guarantee the backend is the source of truth, preventing stale client snapshots after tenant switches.
- On null payload or network error, calls `setLoaded()` so the onboarding chrome degrades gracefully rather than spinning indefinitely.
- `syncOnboardingStore` is intentionally exported for reuse in mutations that return onboarding progress fields alongside their primary payload.
