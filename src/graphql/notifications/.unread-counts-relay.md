Fetches and refreshes unread notification counts by category via Relay, writing results directly into the Relay store for subscribed components to consume reactively.

## Key Components

- **`unreadCountsRelayQuery`** — GraphQL query that retrieves `unreadCountsByCategory`, returning an array of `{ category, count }` objects.
- **`refreshUnreadCounts(environment)`** — Triggers a `network-only` fetch of the unread counts query against the provided Relay environment. Errors are silently swallowed so stale counts persist rather than resetting on failure.

## Usage Example

```typescript
import { refreshUnreadCounts } from '@/relay/unread-counts-relay';
import { getCurrentEnvironment } from '@/relay/environment';

// Call after an action that may change unread state (e.g. marking a ticket read)
function onTicketResolved() {
  refreshUnreadCounts(getCurrentEnvironment());
}
```

## Notes

- Uses `fetchPolicy: 'network-only'` to bypass the Relay cache and always hit the network, ensuring counts stay accurate after mutations.
- Components that render unread counts (e.g. sidebar badges) should subscribe to `unreadCountsRelayQuery` via `useLazyLoadQuery` or a fragment — they will re-render automatically when `refreshUnreadCounts` writes updated data into the store.
- The `.subscribe()` pattern (rather than `.toPromise()`) is intentional: fire-and-forget with no await needed at the call site.
