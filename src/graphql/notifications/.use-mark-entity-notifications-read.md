A React hook that marks every notification about one entity read in a single call and refreshes the per-category unread counts the sidebar badges read.

## Key Components

### `useMarkEntityNotificationsRead()`

Returns one callback:

| Signature | Description |
|---|---|
| `(entityType: NotificationEntityType, entityId: string, onCompleted?: () => void) => void` | Commits `markNotificationsReadForEntity`, then calls `refreshUnreadCounts` and the optional `onCompleted` |

## Usage Example

Callers should own this in a null-rendering child (see `TicketNotificationsAutoReader` in
`tickets/components/ticket-details-view.tsx`), so the activity subscription's focus/blur ticks
do not re-render the host page:

```typescript
const markEntityNotificationsRead = useMarkEntityNotificationsRead();
const markedReadRef = useRef<string | null>(null);
const [activityEdge, setActivityEdge] = useState(0);
useEffect(() => subscribeSessionActivity(() => setActivityEdge(edge => edge + 1)), []);

// biome-ignore lint/correctness/useExhaustiveDependencies: activityEdge is the re-run trigger.
useEffect(() => {
  if (!onScreen || markedReadRef.current === entityId) return;       // content actually shown
  if (!isSessionActive({ idleAfterMs: ATTENTION_IDLE_MS })) return;  // somebody is watching
  markedReadRef.current = entityId;                                  // once per entity per mount
  markEntityNotificationsRead(NotificationEntityType.TICKET, entityId, () => {
    queryClient.invalidateQueries({ queryKey: dialogsQueryKeys.all });
  });
}, [entityId, onScreen, activityEdge, markEntityNotificationsRead, queryClient]);
```

## Notes

- **Call it only where the entity's content is actually on screen.** The mutation is entity-scoped with no type filter — for a ticket it clears the chat-message notifications along with everything else. Those deliberately route to `?tab=chat` so `notificationTargetsLocation` will not auto-read them from the Details tab; firing this on mount would defeat that and mark a customer's message read sight-unseen. Firing only where the URL already matches the notification's own route also keeps `EntityViewAutoReader` in step, so the drawer does not show a card as unread beside a count this call zeroed.
- **Gate it on `isSessionActive`** and re-run on the `subscribeSessionActivity` edge, as `EntityViewAutoReader` does. Read state is cross-device and irreversible — the backend retracts the push banner from the user's phone — so a tab the browser restored with nobody watching must not clear it.
- **Pass the RAW entity id**, not a Relay global id, despite the mutation running against openframe-api. `NotificationReadState.entityId` stores whatever id the notification's producer carried — for a ticket, the ai-agent `Ticket.id` that also keys `Ticket.unreadNotificationCount`. Encoding it (as `toTicketGlobalId` does for saas-api time-tracker mutations) matches zero rows and silently no-ops.
- Complements `EntityViewAutoReader` (in `notifications-data-provider.tsx`), which flips the notifications the drawer has actually loaded so its list and connections stay consistent. This hook is about the **counts**: it also clears notifications the drawer never paged in, which is what `Ticket.unreadNotificationCount` and the sidebar buckets are counting.
- Counts are **refetched**, not adjusted locally — the mutation's return value spans categories.
- Failures are silent by design: nothing is surfaced to the user, so a failed call leaves a stale badge that the next entity open retries. No toast (unlike `useNotificationMutations`, whose operations are user-initiated).
- Callers that render the entity's own count (the tickets board/table) must invalidate their list queries in `onCompleted` — the count lives on the entity, not in the Relay store.
