Defines a dedicated Relay GraphQL query for fetching devices assigned to a script schedule, intentionally isolated from the main schedule detail query to avoid performance issues caused by per-machine resolution latency.

## Key Components

- **`scriptScheduleDevicesRelayQuery`** — A `graphql` tagged template literal exporting a Relay query that fetches `deviceCount` and `assignedDevices` for a given schedule `$id`. Each node is a `...deviceRowFields_machine` spread — the narrowest step of the device field ladder (`src/graphql/devices/`), which is the point here: `assignedDevices` resolves per machine and has timed out once on test-dev, so this list stops at a table row and its mapper is `machineRowToDevice`.

## Design Rationale

This query is split from `scriptScheduleDetailRelayQuery` for two explicit performance reasons documented in the source:

1. **Slow field isolation** — Per-machine device resolution was causing 504 gateway timeouts observed on test-dev. Splitting it out means the main schedule detail loads fast, and device data is fetched only when needed.
2. **N+1 prevention** — The `organization` field is deliberately omitted from `assignedDevices` since it fans out one lookup per machine; no schedule view requires it.

## Usage Example

This query is only mounted by components that specifically need device data — the **Assigned Devices tab** and the **Edit Devices page**.

```typescript
import { useQueryLoader } from 'react-relay';
import { scriptScheduleDevicesRelayQuery } from './script-schedule-devices-relay';

const [queryRef, loadQuery] = useQueryLoader(scriptScheduleDevicesRelayQuery);

// Load only when the Assigned Devices tab is active
loadQuery({ id: scheduleId });
```
