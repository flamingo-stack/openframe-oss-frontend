The per-row field set every device list renders, as an `@inline` fragment on `Machine`.

## Why a fragment

The infinite list, the bounded pickers and the schedule tables all feed the same `Device` shape into the same shared tables, so they must select the same fields. Spreading one fragment makes that structural instead of a convention three documents are each trusted to follow.

`Machine implements Node`, so Relay normalizes these records by `id` across every query that spreads this — the list, a picker and a schedule tab read one record. That is what keeps device state consistent between screens; react-query could only ever hold a separate copy per cache key.

## Why `@inline`

The consumer is `machineToDevice`, a plain function that flattens a row into the flat `Device` the shared tables render — not a component. `readInlineData` is how a fragment's data is read outside React; without it the spread hands back an opaque fragment reference and every row needs its own `useFragment` component.

`readMachine` / `readMachineEdges` (`devices/utils/read-machine.ts`) are the only callers of `readInlineData` for this fragment.
