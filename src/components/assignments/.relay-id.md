Normalizes raw entity IDs to Relay-compliant global IDs for assignment mutations, working around a known backend issue where `Ticket.id` returns raw MongoDB ObjectIds instead of Relay global IDs.

## Key Components

- **`RELAY_TYPE_NAME`** — Maps `AssignmentItemType | AssignmentTargetType` enum values to their Relay GraphQL type names (e.g., `DEVICE → "Machine"`, `KNOWLEDGE_ARTICLE → "KnowledgeBaseItem"`)
- **`btoaUtf8` / `atobUtf8`** — Cross-environment base64 encode/decode helpers that work in both browser (`window.btoa/atob`) and Node.js (`Buffer`)
- **`decodeGlobalId`** — Decodes a base64 string and validates it matches the `TypeName:rawId` Relay format against known types; returns `null` if invalid
- **`toGlobalId`** — Encodes a type + raw ID into a Relay global ID string
- **`ensureGlobalId`** *(exported)* — Idempotent normalization: returns the value unchanged if it's already a valid Relay global ID, otherwise encodes it

## Usage Example

```typescript
import { ensureGlobalId } from './relay-id';

// Raw MongoDB ObjectId from ai-agent's Ticket resolver
const rawTicketId = '507f1f77bcf86cd799439011';
const globalId = ensureGlobalId('TICKET', rawTicketId);
// → btoa("Ticket:507f1f77bcf86cd799439011")

// Already a Relay global ID — returned unchanged (idempotent)
const alreadyEncoded = ensureGlobalId('TICKET', globalId);
// → same globalId string, no double-encoding

// Other entity types
ensureGlobalId('ORGANIZATION', 'org-123'); // → btoa("Organization:org-123")
ensureGlobalId('DEVICE', 'machine-456');   // → btoa("Machine:machine-456")
```

> **Note:** This module is temporary. Once `ai-agent`'s `TicketDataFetcher` is updated to return proper Relay global IDs (see the TODO comment in [relay-id.ts](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/relay-id.ts)), this normalization layer should be removed.
