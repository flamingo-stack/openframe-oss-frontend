A client-side gate component that prevents rendering authenticated app content until both the auth session and feature flags are fully loaded, avoiding skeleton flash on transient routes.

## Key Components

### `FeatureFlagsGate`
A wrapper component with the following gating logic:

| Condition | Behavior |
|---|---|
| SaaS shared mode | Passes through immediately; marks flags as loaded |
| `/auth/*` or `/` routes | Passes through (no chrome, no flags needed) |
| Session not ready, or authenticated but flags not loaded | Renders `AppShellSkeleton` |
| All checks pass | Renders `children` |

**Dependencies:**
- `useAuthSession` — provides `isReady` and `isAuthenticated` state
- `useFeatureFlagsQuery` — fetches flags when authenticated and not in SaaS shared mode
- `useFeatureFlagsStore` — reads `isLoaded` and `setLoaded` from the flags store
- `isSaasSharedMode` — determines if the app is running in the unauthenticated shared surface

## Usage Example

```typescript
// Wrap the app shell or layout to gate authenticated routes
import { FeatureFlagsGate } from '@/app/components/feature-flags-gate';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <FeatureFlagsGate>
      {children}
    </FeatureFlagsGate>
  );
}
```

## Notes

- **SaaS shared mode** marks flags as terminally loaded but never fetches them — this surface is auth-only and has no flag-gated UI
- **Signed-out sessions** are intentionally not marked as loaded to prevent stale empty-flags state surviving into post-login renders
- The skeleton is shown only for authenticated users awaiting flags — unauthenticated users on public routes are never blocked
