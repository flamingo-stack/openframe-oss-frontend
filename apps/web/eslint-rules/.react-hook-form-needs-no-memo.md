# react-hook-form-needs-no-memo.mjs

A custom ESLint rule that enforces a module-level `'use no memo'` directive in any file that uses react-hook-form at runtime, protecting against React Compiler memoization breaking form state.

React Compiler's memoization can't detect react-hook-form's in-place mutations to `control` or its proxied `formState`, causing stale `watch()` values and empty inputs after `register()` + `reset()`. This rule catches both runtime imports and type-only imports that carry a live form handle (e.g., `Control`, `UseFormReturn`), since even a type-only import signals the file drives form state.

## Key Components

- **`FORM_STATE_CARRIER_TYPES`** — Set of react-hook-form type names (`Control`, `FormState`, `UseFormReturn`, etc.) that, even when imported type-only, indicate the file handles live form state.
- **`reactHookFormNeedsNoMemo`** — The exported ESLint rule object (`import('eslint').Rule.RuleModule`) with:
  - `ImportDeclaration` visitor — detects imports from `react-hook-form` that are runtime-relevant (non-type-only specifiers, bare imports, or type imports naming a form-state carrier type).
  - `Program:exit` visitor — checks the directive prologue for `'use no memo'`; reports and auto-fixes if missing, inserting the directive after any existing `'use client'` directive (or at the top of the file otherwise).

## Usage Example

```javascript
// eslint.config.mjs
import { reactHookFormNeedsNoMemo } from './rules/react-hook-form-needs-no-memo.mjs';

export default [
  {
    plugins: { custom: { rules: { 'react-hook-form-needs-no-memo': reactHookFormNeedsNoMemo } } },
    rules: {
      'custom/react-hook-form-needs-no-memo': 'error',
    },
  },
];
```

Before the fix is applied:

```typescript
import { useForm } from 'react-hook-form';

export function useSeedForm() {
  const form = useForm();
  return form;
}
```

After `eslint --fix`:

```typescript
'use no memo';

import { useForm } from 'react-hook-form';

export function useSeedForm() {
  const form = useForm();
  return form;
}
```

This rule should be removed once the project upgrades to react-hook-form 7.75+ with React 19.2.5, per the [upstream discussion](https://github.com/orgs/react-hook-form/discussions/12524).
