Custom ESLint rule that enforces a consistent "large" (`text-h4`) label scale across all dashboard form fields, preventing new forms from silently defaulting to the library's smaller `text-h6` label size.

## Key Components

- **`LIB_FIELD_CONTROLS`** - Map of library form controls (from `@flamingo-stack/openframe-frontend-core`) to the prop name that carries their label text (e.g., `Input` → `label`, `ScriptArguments` → `titleLabel`, `ImageUploader`/`FileUpload` → `fieldLabel`).
- **`formLabelScale`** - The exported ESLint rule object implementing `meta` (messages, fixable, docs) and `create` (the visitor logic).
- **`literal(attr)`** - Helper that extracts a JSX attribute's static string value, handling plain literals, expression containers, and simple template literals; returns `undefined` for computed values.
- **`attribute(node, name)`** - Helper to find a named JSX attribute on an element.

## Usage Example

This file is an ESLint rule module, wired into an ESLint flat config as part of a custom plugin:

```javascript
import { formLabelScale } from './form-label-scale.mjs';

export default [
  {
    plugins: { dashboard: { rules: { 'form-label-scale': formLabelScale } } },
    rules: { 'dashboard/form-label-scale': 'error' },
  },
];
```

The rule tracks local import bindings for lib field controls and `Label`, then on each JSX element:
- For field controls with a label prop but no `labelVariant="large"`, it reports and auto-fixes by inserting `labelVariant="large"`.
- For `<Label>` elements (excluding `variant="surface"`), it requires `variant="large"` unless `className` already states `text-h4`.
- If `className` specifies a conflicting `text-h*` scale, it reports the conflict without auto-fixing, since a human decision is needed.
