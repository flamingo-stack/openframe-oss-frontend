ESLint flat-config entry point dedicated to detecting circular imports (`import/no-cycle`) across the project, run as a separate lint stage from the main fast-pass configuration.

## Key Components

- **Default export** — an ESLint flat config array built with `defineConfig`, combining the project's base configuration (`./eslint.config.mjs`) with the shared `cycles` rule-set from `@flamingo-stack/openframe-frontend-core/eslint-config/cycles`.
- **Ordering requirement** — `...base` **must** be spread before `...cycles`. The cycle-detection plugin needs the base config's parser/resolver settings to build a complete module export graph; without them it silently reports zero cycles instead of failing or warning.

## Usage Example

```bash
# Run only the import-cycle detection pass
npx eslint --config eslint.cycles.mjs .
```

```javascript
// eslint.cycles.mjs
import cycles from '@flamingo-stack/openframe-frontend-core/eslint-config/cycles';
import { defineConfig } from 'eslint/config';

import base from './eslint.config.mjs';

export default defineConfig([...base, ...cycles]);
```

This config is intentionally kept separate from the primary `eslint.config.mjs` because `import/no-cycle` traverses the entire import graph, making it too slow for routine/fast lint runs but essential for CI to catch real circular-dependency regressions (e.g., cycles introduced through barrel files).
