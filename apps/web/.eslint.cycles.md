# eslint.cycles.mjs

A dedicated ESLint configuration focused exclusively on detecting circular import dependencies (`import/no-cycle`) across the entire project's import graph.

This configuration is separated from the main fast-pass lint config because cycle detection requires traversing the full module dependency graph, making it too slow for routine linting but essential for CI validation.

## Key Components

- **`cycles`** — Shared cycle-detection rule config imported from `@flamingo-stack/openframe-frontend-core/eslint-config/cycles`.
- **`base`** — The project's base ESLint configuration (from `./eslint.config.mjs`), spread in *first* to ensure the plugin can properly resolve the export graph.
- **Default export** — A combined `defineConfig` array merging `base` and `cycles`, used as a standalone lint target (typically invoked separately in CI, not during normal dev linting).

## Usage Example

Run this config explicitly via the ESLint CLI as a separate CI step:

```bash
eslint --config eslint.cycles.mjs .
```

Or as a dedicated script in `package.json`:

```json
{
  "scripts": {
    "lint:cycles": "eslint --config eslint.cycles.mjs ."
  }
}
```

**Important:** Always spread `...base` before `...cycles` when composing this config. If `cycles` is used standalone (without the base config), the `import/no-cycle` plugin cannot construct a proper export graph and will silently report zero cycles — producing a false-positive "clean" result even when real circular dependencies exist (e.g., a 3-hop cycle through a barrel file).

For full configuration composition details, see [`eslint.config.mjs`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/eslint.config.mjs).
