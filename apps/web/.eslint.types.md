## Purpose

ESLint configuration for the type-aware linting pass, used to catch issues like floating promises, unsafe `any` usage, and misused `await` expressions. This is kept as a separate config from the primary lint pass because it requires building a full TypeScript program — a much slower operation requiring an increased Node memory limit.

## Key Components

- **Default export** — An ESLint flat config array (via `defineConfig`) composed of:
  - `globalIgnores([...])` — excludes config files, scripts, and `.mjs` files that fall outside the TypeScript project (`tsconfig.json` scope), since `projectService` cannot build a type program for them.
  - `base` — the fast/base ESLint config (imported from `./eslint.config.mjs`), extended rather than duplicated.
  - `typeChecked` — the type-aware rule set from `@flamingo-stack/openframe-frontend-core/eslint-config/type-checked`.
  - `prettierCompat` — re-applied after `typeChecked` to ensure Prettier-compatibility rules take precedence, since `typeChecked` is layered on top of the base config's own copy.

## Usage Example

This file is consumed directly by ESLint's CLI via a dedicated `package.json` script, since it requires extra memory for TypeScript program construction:

```json
{
  "scripts": {
    "lint:types": "NODE_OPTIONS=--max-old-space-size=8192 eslint -c eslint.types.mjs ."
  }
}
```

Run it from the command line:

```bash
npm run lint:types
```

This runs independently of the standard `npm run lint` task, which uses `eslint.config.mjs` and does not perform type-aware checks.
