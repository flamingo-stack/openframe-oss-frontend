This file defines the **type-aware ESLint configuration** used for the slower, deeper lint pass that requires a full TypeScript program (e.g., detecting floating promises, unsafe `any` usage, and misused `await`). It extends the fast base config (`eslint.config.mjs`) rather than duplicating its rules, and is run as a separate stage (`lint:types`) due to its higher memory and performance cost.

## Key Components

- **Default export** — An ESLint flat config array built with `defineConfig`, combining:
  - `globalIgnores(...)` — excludes config files, scripts, and `.mjs` files that fall outside the TypeScript project (`tsconfig.json`'s `src/**` scope), since `projectService` cannot type-check files outside that program.
  - `base` — the fast, non-type-aware ESLint config imported from `./eslint.config.mjs`.
  - `typeChecked` — type-aware rules from `@flamingo-stack/openframe-frontend-core/eslint-config/type-checked`.
  - `prettierCompat` — re-applied Prettier compatibility rules, since `typeChecked` is layered on after the fast config's own copy and would otherwise override it.

## Usage Example

This config is not imported directly in application code—it's invoked via ESLint's CLI as a dedicated lint stage, typically defined in `package.json`:

```javascript
// package.json (excerpt)
{
  "scripts": {
    "lint": "eslint .",
    "lint:types": "NODE_OPTIONS=--max-old-space-size=8192 eslint --config eslint.types.mjs ."
  }
}
```

Run it directly from the CLI:

```bash
NODE_OPTIONS=--max-old-space-size=8192 eslint --config eslint.types.mjs .
```

Because building a TypeScript program is expensive, this pass is kept separate from the default `npm run lint` fast pass, and should typically be run in CI or before merging, rather than on every save.
