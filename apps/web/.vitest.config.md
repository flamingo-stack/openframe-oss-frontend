## vitest.config.mts

Vitest configuration for unit testing the chat stream bridge modules (`src/lib/chat-stream-thread`, `src/lib/use-chat-chunk-processor`) and other TypeScript/TSX logic in the project.

## Key Components

- **`projectRoot`** — resolves the project root using `import.meta.dirname` for path aliasing.
- **`resolve.alias['@']`** — maps the `@` import alias to the `src` directory, mirroring the app's TypeScript path config.
- **`test.environment: 'jsdom'`** — required because the core library barrel touches browser globals at module scope, even in non-component modules.
- **`test.include`** — restricts test discovery to `src/**/*.test.ts` and `src/**/*.test.tsx`. Legacy `src/lib/*.test.mjs` files are intentionally excluded since they rely on `node:test` and run separately via `npm run test:node`.
- **`test.setupFiles`** — loads `./vitest.setup.ts` before running tests.
- **`test.server.deps.inline`** — forces `@flamingo-stack/openframe-frontend-core` to be processed through Vite's resolver rather than Node's raw ESM loader, since the library imports extensionless Next.js entry points (for example `next/link`, `next/navigation`) that Node's ESM loader cannot resolve directly.

## Usage Example

```bash
# Run Vitest-based TS/TSX unit tests
npx vitest run

# Run in watch mode
npx vitest

# Run the separate node:test suite (legacy .mjs tests)
npm run test:node
```
