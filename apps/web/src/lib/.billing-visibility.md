## billing-visibility.ts

Centralizes billing-surface visibility rules across OpenFrame's three shells (web, desktop/Tauri, mobile/Capacitor). Billing tier is derived purely from shell detection (no env var), ensuring the correct experience is always shown regardless of build configuration: full billing on web, read-only visibility on desktop, and fully hidden on mobile (to satisfy App Store/Google Play in-app purchase policies).

## Key Components

- **`isBillingHidden()`** — Returns `true` on mobile shells. Hides all payment-related UI (plans, checkout, invoices, upgrade/cancel CTAs) to comply with App Store Review Guideline 3.1.1 and Google Play Billing requirements. Usage counters remain visible since they're account state, not a purchase mechanism.
- **`isBillingReadOnly()`** — Returns `true` on desktop (Tauri) shells. Billing data (plan, rate, usage, invoices) is visible but not actionable; all mutating actions redirect to the web app.
- **`isPaymentUiEnabled()`** — Returns `true` only when the server-side `billings` feature flag is enabled AND the build isn't hidden or read-only. Gates purchase-related surfaces (checkout, plan changes, cancellation).
- **`openBillingInBrowser()`** — Opens the web app's billing/usage page in the system browser via `window.open`, used as the desktop build's escape hatch for any billing action it can't perform natively.

## Usage Example

```typescript
import { isBillingHidden, isBillingReadOnly, isPaymentUiEnabled, openBillingInBrowser } from './billing-visibility';

if (isBillingHidden()) {
  // Mobile: render nothing for billing, show usage counters only
} else if (isBillingReadOnly()) {
  // Desktop: render read-only billing summary
  renderBillingSummary({ onManage: openBillingInBrowser });
} else if (isPaymentUiEnabled()) {
  // Web with billing flag enabled: show full plan picker / checkout flow
  renderCheckoutFlow();
}
```

This module should be the single source of truth for any component deciding whether to render billing/payment UI—avoid re-implementing shell checks (`isDesktopShell`, `isMobileShell`) directly in feature code.
