# app-config.tsx

Defines the application configuration system for OpenFrame's frontend, providing typed schemas for navigation, layout, SEO, and UI behavior, along with helper functions to resolve app-specific config, generate structured data, and enforce route/component visibility rules.

## Key Components

- **`AppType`** — Union type distinguishing `'openframe-auth'` and `'openframe-dashboard'` app variants (both currently map to the same config).
- **`AppConfig`** — Central interface describing an app's identity, branding, SEO metadata, layout flags, navigation structure, UI options, footer, contact, and social links.
- **`NavigationMenuItem` / `NavigationSection`** — Interfaces modeling header, mobile, and sidebar navigation structures, including dropdowns and badges.
- **`FooterConfig` / `FooterSection` / `FooterCta` / `FooterLink`** — Interfaces for configuring footer content and call-to-action blocks.
- **`getAppConfig(appType?)`** — Returns the `AppConfig` for the given or current app type.
- **`getCurrentAppType()`** — Resolves the active app type from runtime environment variables.
- **`getAllAppConfigs()`** — Returns all registered app configurations.
- **`isCurrentApp(appType)`** — Checks if a given app type matches the current one.
- **`getPlatformAssetPaths(appType?)`** — Builds absolute URLs for favicon, manifest, and social preview images.
- **`generateStructuredData(config)`** — Produces JSON-LD `WebSite` and `Organization` schema objects for SEO.
- **`shouldShowAdminMenu(userRole?)`**, **`shouldShowComponent(component)`**, **`isRouteAllowed(pathname)`**, **`getHeaderStyle()`** — UI decision helpers driven by the resolved config.

## Usage Example

```typescript
import { getAppConfig, isRouteAllowed, shouldShowComponent } from './app-config';

const config = getAppConfig();

if (isRouteAllowed('/dashboard/devices')) {
  console.log(`Navigating within ${config.name}`);
}

if (shouldShowComponent('searchBar')) {
  // render search bar in header
}
```

Since this repository only ships the OpenFrame platform, both app types resolve to `openframeConfig`, making `getAppConfig()` a stable entry point for consuming navigation, SEO, and layout settings throughout the UI.
