# file-operations.ts

Provides a `FileOperations` helper class that builds MeshCentral file-manager protocol requests (list, mkdir, rename, delete, copy, move, zip/unzip, search, get/set file) and handles cross-platform path manipulation (Windows `\` vs. POSIX `/` separators). It also includes error types for cases where the agent's response is ambiguous (e.g., silent delete failures).

## Key Components

- **`FileDeleteError`** — Error class signaling a delete request reached the agent but some requested items survived (distinct from a transport failure).
- **`FileOperationTimeoutError`** — Error class for requests that never received an agent response within the expected time.
- **`FileOperations`** — Main class with methods to:
  - Generate unique request IDs (`generateRequestId`)
  - Build protocol request objects: `createListDirectoryRequest`, `createMakeDirRequest`, `createRenameRequest`, `createDeleteRequest`, `createCopyRequest`, `createMoveRequest`, `createZipRequest`, `createUnzipRequest`, `createSearchRequest`, `createCancelSearchRequest`, `createGetFileRequest`, `createSetFileRequest`
  - Manipulate paths: `joinPath`, `parsePath`, `buildPath`, `getParentPath`, `sanitizeName`, `validatePath`
  - Diagnose delete outcomes: `describeDeleteFailure` — compares requested names against a post-delete directory listing to infer partial/failed deletions, since the `rm` action never returns a direct success/failure response.

## Usage Example

```typescript
import { FileOperations } from './file-operations';

const fileOps = new FileOperations();

// Build a request to list a directory
const listReq = fileOps.createListDirectoryRequest('C:\\Users\\Public');

// Join a base path with a new segment (separator-aware)
const newPath = fileOps.joinPath('C:\\Users\\Public', 'Documents');
```
