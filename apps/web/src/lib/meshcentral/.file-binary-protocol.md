Handles MeshCentral's binary file-transfer protocol by accumulating incoming `ArrayBuffer` chunks, parsing length-prefixed frames, and dispatching complete payloads to a callback.

## Key Components

- **`FileBinaryProtocol`** — class that buffers and decodes a custom binary streaming protocol.
  - **`push(data, onChunk)`** — appends new binary data to the internal buffer and synchronously processes any complete frames, invoking `onChunk(payload, isFinal)` for each.
  - **`reset()`** — clears the internal buffer, useful when starting a new transfer session or recovering from an error.
  - **`isBinaryData(data)`** — type guard that checks whether a value is `ArrayBuffer`/`Uint8Array`-like, including cross-realm buffers (e.g. from iframes or workers) where `instanceof` checks fail.
  - **`consume` / `readHeader`** (private) — internal frame-parsing logic. Each frame has a 4-byte little-endian header where bit 0 marks the final chunk and bits 1-31 encode the payload length.

## Usage Example

```typescript
import { FileBinaryProtocol } from './file-binary-protocol';

const protocol = new FileBinaryProtocol();

socket.addEventListener('message', (event: MessageEvent) => {
  if (!protocol.isBinaryData(event.data)) return;

  const buffer = event.data instanceof ArrayBuffer
    ? event.data
    : (event.data as Uint8Array).buffer;

  protocol.push(buffer, (payload, isFinal) => {
    // payload: Uint8Array chunk of file data
    appendToFile(payload);

    if (isFinal) {
      finalizeFileTransfer();
      protocol.reset();
    }
  });
});
```

This pattern is typically used alongside a WebSocket connection to MeshCentral's remote file manager, where binary frames must be reassembled across multiple `message` events before the full file chunk can be processed.
