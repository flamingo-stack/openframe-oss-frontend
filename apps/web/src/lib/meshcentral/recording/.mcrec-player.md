## McrecPlayer

Offline playback engine for MeshCentral `.mcrec` session recordings. It decouples timeline control (play/pause/seek/speed) from rendering by driving a protocol-agnostic `RecordingRenderer` adapter (canvas/KVM or terminal) through a virtual-time clock that paces record feeding for real-time playback.

## Key Components

- **`McrecPlayer`** — Main player class managing playback state, timeline cursor, and renderer feeding.
  - `load(buffer)` / `loadParsed(recording, opts)` — parse/load a recording, optionally marked incomplete for streaming sessions via `extend`.
  - `extend(recording, complete)` — appends more data to an in-progress recording without disturbing playback.
  - `play()` / `pause()` / `setSpeed(speed)` — standard transport controls.
  - `seek(targetMs)` / `seekToTime(atMs)` — seek by playback offset or wall-clock time; seeks past loaded data wait (`'waiting'` state) until the data arrives.
  - `stepBack()` / `stepForward()` — jump by a fixed 10-second step (`STEP_MS`).
  - `cancelWait()` — cancels a pending out-of-range seek.
  - `attachRenderer(renderer)` — binds a `RecordingRenderer` for painting frames.
  - `dispose()` — tears down timers and renderer resources.
  - Getters: `state`, `currentMs`, `durationMs`, `currentSpeed`.
- **`McrecPlayerCallbacks`** — Optional hooks: `onTime`, `onDuration`, `onState`.
- Internally uses `parseMcrec`, `seekFrame`, `lastFrameAtMs`, `toPlaybackMs` from sibling modules to parse recordings, perform fast single-pass seeks (via tile repaint), and resolve timeline boundaries.

## Usage Example

```typescript
import { McrecPlayer } from './mcrec-player';
import type { RecordingRenderer } from './mcrec-types';

const player = new McrecPlayer({
  onTime: (ms) => updateScrubber(ms),
  onDuration: (ms) => setTotalDuration(ms),
  onState: (state) => console.log('playback state:', state),
});

player.attachRenderer(renderer as RecordingRenderer);

const response = await fetch('/recordings/session.mcrec');
const buffer = await response.arrayBuffer();
player.load(buffer);

player.play();
player.setSpeed(2);

// Seek 30s forward
await player.seek(player.currentMs + 30_000);

// Clean up when done
player.dispose();
```

Seeking prefers a one-pass repaint from visible tiles (`renderer.paint`) when the protocol supports it; otherwise it replays from the nearest restart point, draining the renderer in batches (`SEEK_DRAIN_BATCH`) to avoid overwhelming the decode pipeline. A generation counter ensures only the latest seek wins when seeks are issued in rapid succession.
