# meshcentral-tunnel.ts

Implements a resilient WebSocket-based relay tunnel to MeshCentral's `meshrelay.ashx` endpoint, handling the agent handshake protocol, control-channel messaging (RTT pings, console status, pairing requests), and automatic reconnection with fresh relay IDs.

## Key Components

- **`TunnelState`** — Numeric union type representing lifecycle states: `0` stopped, `1` connecting, `2` open, `3` connected (handshake complete).
- **`TunnelOptions`** — Configuration for terminal size (`cols`, `rows`) and login requirement, sent during handshake.
- **`createRelayNonce()`** — Generates a cryptographically random 12-character alphanumeric nonce used to build unique relay IDs per dial attempt.
- **`MeshTunnel`** — Main class wrapping a `WebSocketManager` to manage a single tunnel:
  - `start()` — Builds the relay URL (with auth cookie/bearer token), opens the connection, and wires state/message callbacks.
  - `stop()` — Sends a graceful close control message and tears down the socket.
  - `reconnect()` — Forces a reconnect if not currently connected.
  - `sendText(text)` / `sendBinary(data)` — Send raw text or binary frames through the tunnel.
  - `sendCtrl(obj)` — Sends a JSON control-channel message (channel `102938`) used for RTT, options, pairing, and ping/pong.
  - `getState()` / `isConnected()` — Query current tunnel state.
  - `updateAuthCookie(cookie)` — Updates the auth cookie used on future reconnects.
  - `getRelayId()` — Returns the current relay ID (changes on each redial).

Internally, each connection performs a handshake (`'c'`/`'cr'` sentinel messages) before accepting data, tracks round-trip latency via a periodic ping, and distinguishes control-channel JSON messages from raw tunneled data (prefixed with `~` for text).

## Usage Example

```typescript
import { MeshTunnel } from './meshcentral-tunnel';

const tunnel = new MeshTunnel({
  authCookie: 'session-cookie-value',
  nodeId: 'node//abc123',
  protocol: 1, // e.g., terminal protocol
  options: { cols: 80, rows: 24 },
  onData: data => console.log('Received data:', data),
  onStateChange: (state, key) => console.log(`Tunnel ${key} state:`, state),
  onConsoleMessage: msg => console.log('Agent status:', msg),
  onFailed: () => console.error('Tunnel permanently failed'),
  getAuthCookie: () => localStorage.getItem('authCookie'),
});

tunnel.start();

// Later, send input
tunnel.sendText('ls -la\n');

// Clean up
tunnel.stop();
```

This class is typically used by terminal, desktop, or file-transfer UI components that need a persistent, auto-reconnecting channel to a managed device via MeshCentral's relay.
