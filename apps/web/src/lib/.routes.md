## routes.ts

Centralized, typed registry of all internal application routes, providing a single source of truth for URL construction, dynamic path parameters, query strings, and tab identifiers—eliminating hand-written path strings scattered across the codebase.

## Key Components

- **`TAB_IDS`** — Const object enumerating valid tab ids for each tabbed page (e.g., `customerDetails`, `deviceDetails`, `monitoring`), shared with in-page tab-component arrays.
- **Tab type exports** (e.g., `CustomerDetailTab`, `DeviceDetailTab`, `MonitoringTab`, `SettingsTab`) — Derived literal union types from `TAB_IDS` entries for compile-time tab validation.
- **`MANAGE_AI_BALANCE_ACTION`** — Constant used to deep-link `/settings/billing-usage` to the Manage AI Balance modal.
- **`TICKET_PREFILL_KEYS`** / **`TicketPrefill`** — Shared keys for prefilling the new-ticket form via query params from other pages (e.g., incidents).
- **`withQuery(base, query)`** — Helper that serializes a typed query object into a URL, skipping `undefined`/`null`, encoding arrays as repeated keys.
- **`MINGO_DIALOG_PARAM`** / **`withMingoDialog(url, dialogId)`** — Legacy query param and helper for adding/removing the Mingo chat dialog param from a URL while preserving path, query, and hash.
- **`isMingoWhatToAsk(query)`** — Checks whether a chat page's query represents the "What to ask Mingo?" view.
- **`routes`** — The main exported registry object. Static routes are plain strings; parametrized routes are typed functions (e.g., `routes.mingo.chat(id)`, `routes.helpCenter.onboardingGuide(slug)`).

## Usage Example

```typescript
import { routes, TAB_IDS } from '@/routes';

// Navigate to a static route
router.push(routes.dashboard);

// Navigate with a tab query param
router.push(routes.monitoring.root({ tab: 'policies' }));

// Navigate to a detail page with a dynamic id
router.push(routes.customers.details(customerId, { tab: 'tickets' }));

// Build a link in a component
<Link href={routes.devices.details(deviceId)} />

// Deep-link to a CMS-backed content page via query param (static export friendly)
router.push(routes.helpCenter.onboardingGuide('getting-started'));

// Check a tab id against the shared source of truth
const isValidTab = TAB_IDS.deviceDetails.includes(tab);
```

Routes that depend on dynamic segments or filters use `withQuery` internally to produce consistent, type-safe query strings (including array params serialized as repeated keys), ensuring bookmarks and deep links remain stable across the app.
