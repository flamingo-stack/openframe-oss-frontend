# exhaustive-map.ts

Type-safe helpers for working with enum-keyed lookup tables where enum values arrive from Relay/GraphQL as plain strings that may include `"%future added value"` (a server running ahead of the checked-in schema). These functions preserve exhaustiveness checking at the table-definition site while safely handling unknown values at the call site.

## Key Components

- **`presentationFor<K, V>(map, key)`** — Safely reads a value from a `Record<K, V>` map (typically declared with `satisfies Record<SomeEnum, T>` for compile-time exhaustiveness) using a loosely-typed string key. Returns `undefined` if the key isn't an own property of the map, which signals the server knows an enum value this build doesn't. Uses `Object.hasOwn` to avoid false positives from inherited `Object.prototype` properties (e.g. `toString`, `__proto__`).

- **`knownValue<T>(values, value)`** — Narrows a raw string to a known enum member `T` (from `@/generated/schema-enums`) by checking membership in the enum's value set. Returns `null` for unrecognized values instead of throwing or passing through unsafe data.

- **`knownValues<T>(values, selected)`** — Applies `knownValue` across a list (e.g., URL query params), filtering out anything unrecognized while preserving order. Useful for defending against stale or hand-edited URLs that reference enum values the current build doesn't support.

## Usage Example

```typescript
import { presentationFor, knownValue, knownValues } from "./exhaustive-map";
import { SomeStatus } from "@/generated/schema-enums";

const statusLabels = {
  ACTIVE: "Active",
  PAUSED: "Paused",
  ARCHIVED: "Archived",
} satisfies Record<SomeStatus, string>;

// Reading from a raw string (e.g. a GraphQL field)
const label = presentationFor(statusLabels, rawStatusFromServer) ?? rawStatusFromServer;

// Narrowing a single value from the URL
const status = knownValue(SomeStatus, searchParams.get("status"));

// Narrowing a list of values from the URL
const ticks = knownValues(FunnelStage, searchParams.getAll("stage"));
```

## Notes

- Table definitions should use `satisfies Record<EnumType, T>` rather than a `switch` statement, so widening the enum (via `npm run fetch-schema` + `npm run generate-enums`) causes a compile error until the new case is handled.
- Callers are responsible for deciding how to render an `undefined`/`null` result — typically the raw string value or a neutral fallback tag.
