Utility for comparing application version strings using the `MAJOR.MINOR.PATCH` prefix convention, used to drive mobile force-update logic consistently with the tenant gateway's `X-OpenFrame-Client` version check.

## Key Components

- **`Triple`** — internal type alias for a parsed `[major, minor, patch]` numeric tuple.
- **`parseVersion(value)`** — extracts the leading `MAJOR.MINOR.PATCH` numeric prefix from a version string (e.g. `1.0.125-4-geae0416-dirty` → `[1, 0, 125]`). Returns `null` if the string doesn't start with a valid numeric prefix (including `null`, `undefined`, or non-conforming strings like `-` or a raw commit hash).
- **`isVersionBelow(current, target)`** — returns `true` only if `current` is strictly numerically less than `target`. Returns `false` if either version fails to parse, ensuring that unparseable versions never trigger a force-update prompt.

## Usage Example

```typescript
import { parseVersion, isVersionBelow } from './app-version';

parseVersion('1.0.125-4-geae0416-dirty'); // [1, 0, 125]
parseVersion('bad-version');              // null

isVersionBelow('1.0.125', '1.1.0');       // true
isVersionBelow('1.2.0', '1.1.9');         // false
isVersionBelow('garbage', '1.0.0');       // false — unparseable, never prompts
```

## Notes

- Comparison is purely numeric on the `MAJOR.MINOR.PATCH` prefix; build metadata, pre-release tags, or commit suffixes are ignored.
- This matches the gateway's `X-OpenFrame-Client` version rule so that both client and server agree on which versions are considered outdated.
- An unparseable version on either side is treated as "unknown" and never causes a force-update prompt, avoiding false positives for unusual build strings.
