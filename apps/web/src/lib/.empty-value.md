Defines a shared convention for representing "missing" values in the UI—using a single em-dash constant so that empty dates, counts, or versions render consistently across all screens, rather than each component inventing its own placeholder.

## Key Components

- **`EMPTY_VALUE`** — The constant string (`'—'`) used everywhere a value is absent. Components like `EmptyValue`, `InfoCell`, and `ValueText` render this muted.
- **`isEmptyValue(value)`** — Type guard that checks whether a value counts as "missing" (`null`, `undefined`, empty string, or already equal to `EMPTY_VALUE`). Narrows the type to `null | undefined | ''`.
- **`displayValue(value)`** — Converts a string/number (or missing value) into display text, falling back to `EMPTY_VALUE` when the value is empty. Intended for plain-text contexts (toasts, copy-to-clipboard) rather than styled UI components.

## Usage Example

```typescript
import { EMPTY_VALUE, isEmptyValue, displayValue } from './empty-value';

// Checking if a field is missing
const version: string | null = null;
if (isEmptyValue(version)) {
  console.log('No version available');
}

// Rendering text safely in a toast or copy action
const label = displayValue(version); // '—'
const count = displayValue(0);        // '0' (zero is not empty)
const name = displayValue('');        // '—'

// Consistent display across components
console.log(`Last seen: ${displayValue(device.lastSeenAt)}`);
```

Use `isEmptyValue` when you need conditional logic (e.g., hiding a tooltip or disabling an action), and `displayValue` when you need a renderable string fallback without a dedicated UI component.
