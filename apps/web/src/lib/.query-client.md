# query-client.ts

Configures and exposes the application's shared React Query `QueryClient`, wiring it to a real connectivity signal and making it reachable outside the React component tree (notably for forced sign-out logic).

## Key Components

- **`onlineManager.setEventListener(...)`** — Replaces React Query's default `window` `online`/`offline` listeners with `subscribeConnectivity`, fixing stale connectivity state in WKWebView (mobile shell) where native browser events lag badly.
- **`makeQueryClient()`** — Internal factory that builds a `QueryClient` with `staleTime: 60_000` and `refetchOnWindowFocus: false`.
- **`getQueryClient()`** — Returns the shared `QueryClient` instance:
  - On the server, returns a fresh client per call (avoids leaking cached data across concurrent requests).
  - In the browser, lazily creates and caches a single module-level singleton, shared between the `QueryClientProvider` and any non-React caller (e.g. `force-logout.ts`).

## Usage Example

```typescript
import { QueryClientProvider } from '@tanstack/react-query';
import { getQueryClient } from './query-client';

function Providers({ children }: { children: React.ReactNode }) {
  const [client] = useState(() => getQueryClient());

  return (
    <QueryClientProvider client={client}>
      {children}
    </QueryClientProvider>
  );
}

// Outside the component tree, e.g. in a forced logout flow:
import { getQueryClient } from './query-client';

export async function forceLogout() {
  const queryClient = getQueryClient();
  queryClient.setQueryData(['auth', 'session'], null);
  // ...reset auth stores in the same breath
}
```

**Note:** Keeping the client accessible via `getQueryClient()` (rather than only inside a `useState`) ensures the `['auth', 'session']` query and app-level auth stores stay in sync during forced sign-outs, preventing the UI from getting stuck in a skeleton state.
