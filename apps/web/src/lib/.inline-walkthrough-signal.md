# inline-walkthrough-signal.ts

Shared Zustand-backed signal that lets a component rendering an inline walkthrough video suppress the app-shell's floating walkthrough card, preventing the same clip from playing twice simultaneously.

## Key Components

- **`useInlineWalkthroughSignal`** — Internal Zustand store holding a `claims` counter (not a boolean) along with `claim()`/`release()` actions. A counter is used because route transitions mount the incoming tree before unmounting the outgoing one, so overlapping components can hold claims simultaneously; a boolean would be incorrectly cleared by the first of two unmounts.
- **`useInlineWalkthroughClaim(active: boolean)`** — Hook called by the component that renders the inline walkthrough video. When `active` is `true`, it claims the signal on mount and releases it on unmount/cleanup. Pass `active: false` when there's no video to show, since suppressing the floating card in that case would leave no walkthrough visible at all.
- **`useHasInlineWalkthrough(): boolean`** — Hook for the app-shell's floating card, returning `true` whenever at least one inline walkthrough video is currently claimed (`claims > 0`), signaling that the floating card should stay hidden.

## Usage Example

```typescript
// In the component rendering the inline walkthrough video:
import { useInlineWalkthroughClaim } from './inline-walkthrough-signal';

function InitialSetupCard({ hasVideo }: { hasVideo: boolean }) {
  useInlineWalkthroughClaim(hasVideo);
  return hasVideo ? <video src="/walkthrough.mp4" /> : null;
}
```

```typescript
// In the app-shell's floating walkthrough card:
import { useHasInlineWalkthrough } from './inline-walkthrough-signal';

function FloatingWalkthroughCard() {
  const suppressed = useHasInlineWalkthrough();
  if (suppressed) return null;
  return <video src="/walkthrough.mp4" className="floating-corner-card" />;
}
```

## Notes

- Claims are scoped to the **component**, not the route (`pathname`), because some pages (e.g. Initial Setup) stop rendering their inline video once a task completes, even though the route itself hasn't changed.
- `release()` uses `Math.max(0, ...)` to guard against React StrictMode's double-invoked effect cleanup in development, preventing the counter from going negative.
