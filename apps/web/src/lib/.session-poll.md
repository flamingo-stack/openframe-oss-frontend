# session-poll.ts

Provides a centralized gating mechanism for background polling queries that depends on tenant session health, ensuring polling queries stop retrying/refetching once a session becomes unhealthy (e.g., after a failed auth refresh) and automatically resume when the session recovers.

## Key Components

- **`sessionPollMeta`** — A constant metadata object (`{ sessionPoll: true }`) attached to a React Query's `meta` field so polling queries can be identified and targeted later for resumption.
- **`sessionPollsAllowed()`** — Returns `true` only when the current session health is `'healthy'`. Used as a guard at the top of custom interval callbacks.
- **`sessionRetry(base)`** — Wraps a retry count or retry predicate function. Returns a React Query `retry` function that short-circuits to `false` whenever the session is unhealthy, preventing wasted retries on a doomed request.
- **`sessionInterval(intervalMs)`** — Returns a React Query `refetchInterval` function that yields `intervalMs` while the session is healthy, or `false` (disabling polling) otherwise.
- **`resumeSessionPolls(queryClient)`** — Subscribes to session health state changes. When health transitions back to `'healthy'`, it refetches all active queries tagged with `sessionPollMeta`, which restarts their intervals. Returns an unsubscribe function for cleanup.

## Usage Example

```typescript
import { useQuery, useQueryClient } from '@tanstack/react-query';
import { sessionRetry, sessionInterval, sessionPollMeta, resumeSessionPolls } from './session-poll';
import { useEffect } from 'react';

function useDeviceStatusPoll() {
  return useQuery({
    queryKey: ['device-status'],
    queryFn: fetchDeviceStatus,
    retry: sessionRetry(3),
    refetchInterval: sessionInterval(5000),
    meta: sessionPollMeta,
  });
}

// At app root: restart polls when session health recovers
function useSessionPollResumer() {
  const queryClient = useQueryClient();
  useEffect(() => resumeSessionPolls(queryClient), [queryClient]);
}
```

## Why This Matters

Polling queries normally keep retrying and refetching regardless of auth state. Without this gate, a session that goes unhealthy (e.g., refresh token rejected) would cause repeated failed requests. Because React Query doesn't re-evaluate `refetchInterval` on external state changes, `resumeSessionPolls` explicitly triggers a refetch when health recovers, which is what restarts the interval loop.
