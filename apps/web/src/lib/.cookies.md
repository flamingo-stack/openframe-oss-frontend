# cookies.ts

Browser-only utility for reading and writing `document.cookie` entries, providing a single source of truth for cookie parsing and serialization. All functions are safe no-ops when executed outside a browser environment (e.g., during SSR).

Note: this module cannot write cookies that need to survive Safari's 7-day cap on JS-set cookies—those require a `Set-Cookie` header from a server, which this app doesn't provide here (see `referral-cookie.ts` for that use case).

## Key Components

- **`CookieAttributes`** — Interface describing a cookie to write: `name`, `value` (raw, auto-encoded), optional `domain` (leading-dot form for subdomain sharing), `maxAgeSeconds`, optional `path`, `sameSite`, and `secure`.
- **`readCookie(name: string): string | undefined`** — Reads and URL-decodes a single cookie value by name. Returns `undefined` if not found or if `document` is unavailable.
- **`writeCookie(attributes: CookieAttributes): void`** — Serializes and writes a cookie to `document.cookie`. URL-encodes the value, applies sensible defaults (`path: '/'`, `sameSite: 'lax'`), and silently swallows write failures (sandboxed documents, full cookie jar) since cookies are treated as best-effort state.

## Usage Example

```typescript
import { readCookie, writeCookie } from './cookies';

// Write a session preference cookie, shared across subdomains
writeCookie({
  name: 'theme',
  value: 'dark',
  domain: '.openframe.ai',
  maxAgeSeconds: 60 * 60 * 24 * 30, // 30 days
  sameSite: 'lax',
  secure: true,
});

// Read it back later
const theme = readCookie('theme');
if (theme) {
  console.log(`Current theme: ${theme}`);
}
```

## Notes

- Cookie writes are best-effort; never rely on `writeCookie` succeeding as critical application state.
- For cookies that must persist beyond Safari's JS-cookie lifetime cap, use a server-side `Set-Cookie` header instead (see `referral-cookie.ts`).
