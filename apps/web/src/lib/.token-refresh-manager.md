## Token Refresh Manager

Centralized, single-flight token refresh manager that serializes refresh attempts across browser tabs and distinguishes transient failures (network, 5xx, WAF, timeout) from terminal failures (401) to avoid spuriously logging out users during temporary outages.

## Key Components

- **`RefreshOutcome`** — Type describing the result of a refresh attempt: `'refreshed'`, `'transient'`, or `'terminal'`.
- **`RefreshOptions`** — Options for a refresh call, notably `ignoreBackoff` to force a cycle even during the inter-cycle backoff window.
- **`getRefreshBackoffRemainingMs()`** — Returns milliseconds remaining before the next refresh cycle may start (0 if none pending); used by UI to schedule automatic retries.
- **Cross-tab coordination** — Uses a Web Lock (`openframe-token-refresh`) plus `localStorage` markers (`of_token_rotated_at`, `of_token_refresh_backoff`) to serialize rotations and share backoff state across tabs.
- **Backoff logic** (`armCycleBackoff`, `clearCycleBackoff`, `firstFailureDeadline`) — Implements escalating delays (`CYCLE_BACKOFF_DELAYS_MS`) between failed refresh cycles, with a "first failure is not an outage" grace period.
- **Retry/timeout constants** — `REFRESH_TIMEOUT_MS`, `RETRY_DELAYS_MS`, `CYCLE_BUDGET_MS` govern per-request timeout, server-error retries, and overall cycle time budget.
- **`buildRefreshUrl()`** — Constructs the `/oauth/refresh` endpoint URL without a `tenantId` query param to avoid WAF false positives.
- **`initCrossTabSync()`** — Listens for `storage` events to adopt token rotations performed by other tabs.
- **`readJwtExpiryMs()` / `snapshotCredential()` / `credentialReplacedSince()`** — Helpers for proactive refresh scheduling and detecting concurrent credential replacement.

## Usage Example

```typescript
import { getRefreshBackoffRemainingMs } from './token-refresh-manager';

// Check if an automatic retry should wait before attempting another refresh
const remainingMs = getRefreshBackoffRemainingMs();
if (remainingMs > 0) {
  console.log(`Next refresh cycle allowed in ${remainingMs}ms`);
} else {
  // Safe to attempt a refresh cycle now
}
```

This module is consumed internally by `ApiClient`, `AuthApiClient`, and the Relay environment — application code typically does not call its internal refresh function directly, but may use `getRefreshBackoffRemainingMs()` to drive retry UI (e.g., the "can't verify your session" screen).
