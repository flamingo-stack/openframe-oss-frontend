# query-client-provider.tsx

Client component that wraps the application with TanStack Query's `QueryClientProvider`, providing a stable, SSR-safe query client instance and handling cache invalidation when pages are restored from the browser's back-forward cache (bfcache).

## Key Components

- **`QueryClientProvider`** — React component that:
  - Lazily initializes the query client via `useState(getQueryClient)`, ensuring each server render gets its own client while the browser reuses a single shared instance (see `query-client.ts`).
  - Listens for the `pageshow` event and invalidates all queries when `event.persisted` is `true`, forcing on-screen queries to refetch after a bfcache restore. This compensates for window focus refetching being disabled and avoids stale data when navigating back from an edit page (e.g., via `router.back()`).
  - Wraps `children` in TanStack Query's native `QueryClientProvider`.

## Usage Example

```typescript
// app/layout.tsx
import { QueryClientProvider } from './query-client-provider';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <QueryClientProvider>{children}</QueryClientProvider>
      </body>
    </html>
  );
}
```

```typescript
// Any descendant component can now use TanStack Query hooks
import { useQuery } from '@tanstack/react-query';

function DeviceList() {
  const { data } = useQuery({
    queryKey: ['devices'],
    queryFn: fetchDevices,
  });

  return <ul>{data?.map((d) => <li key={d.id}>{d.name}</li>)}</ul>;
}
```

**Note:** This component must be used in a Client Component context (`'use client'`) and should wrap the portion of the tree that needs access to the query cache, typically near the root layout.
