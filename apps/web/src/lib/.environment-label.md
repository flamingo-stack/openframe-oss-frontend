# environment-label.ts

Derives a human-readable environment label (e.g., "Production environment", "QA environment") from a tenant host's hostname, used to populate the super user strip's environment chip.

Because a single web bundle serves all environments and native shells learn their host only at login, the environment cannot be baked in at build time — it must be inferred from the hostname itself at runtime.

## Key Components

- **`PRODUCTION_HOST`** — Regex matching production hosts of the form `<tenant>.openframe.ai`.
- **`ENVIRONMENT_HOST`** — Regex matching SaaS non-production hosts of the form `<tenant>.<env>.openframe.build`, capturing the environment segment (e.g., `dev`, `dev10`, `qa`, `stage`).
- **`LOCAL_HOST`** — Regex matching local development hosts (`localhost`, `127.0.0.1`, `[::1]`, or any `*.localhost`).
- **`environmentLabel(hostname: string): string | undefined`** — Resolves a hostname to a label:
  - Production host → `"Production environment"`
  - SaaS host with env segment → `"<ENV> environment"` (uppercased, e.g. `"QA environment"`)
  - Local host → `"Local environment"`
  - Anything else (self-hosted, custom domain) → `undefined` (no chip shown)

## Usage Example

```typescript
import { environmentLabel } from './environment-label';

environmentLabel('acme.openframe.ai');           // "Production environment"
environmentLabel('acme.qa.openframe.build');      // "QA environment"
environmentLabel('acme.dev10.openframe.build');   // "DEV10 environment"
environmentLabel('localhost:3000');               // "Local environment"
environmentLabel('msp.example.com');              // undefined

// Typical usage in a UI component
const label = environmentLabel(window.location.hostname);
if (label) {
  renderEnvironmentChip(label);
}
```

Since `undefined` is returned for hosts that don't match a known shape (self-hosted or custom domains), callers should treat the absence of a label as "don't render a chip" rather than falling back to a guessed value.
