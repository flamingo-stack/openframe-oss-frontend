The multi-key reducer registry (`createReducerMirror`) both chat hosts, mingo and tickets, are built on. The core library's stream reducer owns every accumulation rule, and a thread is `ChatMessage[]` on both sides, the reducer's own objects by reference; this module owns the registry, one decoder per key and the history-hydration protocol.

## Key Components

### Hydration

- **`HydrateOptions`** — `{ expectingReplay?: boolean }`
- **`ReducerMirror.hydrate(key, messages, options?)`** / **`BoundMirror.hydrate(...)`** — THE door for a thread fetched from history

`hydrate` is one call because restoring a turn takes three steps that only work together:

1. `initializeWithState(thread)` — a chunk arriving with no preceding `start` **appends** to the hydrated bubble. A reload mid-stream lands exactly there.
2. the extras, when the trailing assistant run is unfinished (`extractIncompleteTailState`), which restore the activity indicator.
3. the adopt-once flag, so a **replayed** `start` re-streams into the partial bubble instead of opening a duplicate beside it.

While the reducer has a turn open (`streaming`), only step 1 runs and adopt-once is disarmed.

The flag is disarmed on the first applied entry that is not a `start` — this app's subscriptions have no catchup-finished signal, and an armed flag left behind would make the next genuine turn overwrite a completed bubble. Pass `expectingReplay: false` for hydration that is not a fresh subscribe.

### Registry — `createReducerMirror(config)`

| Area | What it does |
|---|---|
| Identity | `identityFor(key)` maps a host key to `(dialogId, side)`. A key must always map to the same identity for the mirror's lifetime. |
| Snapshots | `onSnapshot(key, { messages, phase, streamingId, state })` publishes a read-mirror into the host store |
| Thread ops | `mutateThread`, `upsertMessage`, `patchMessage`, `removeMessage`, `prependWithBoundaryMerge`, `pushOptimisticSend`, `setTyping`, `mergeApprovalStatuses` |
| Retention | `setActiveKeys(keys)` pins displayed keys against LRU eviction; `drop(key)` removes one outright |
| Eviction | `onEvict` **parks** the thread, approval statuses, seq cursor and armed echoes; the next `getReducer` replays them into the replacement instance |
| Binding | `bind(key)` → `BoundMirror` (`decode`, `apply`, `hydrate`, `mutate`, `mergeApprovalStatuses`, `evictionEpoch`), memoized per key |
| Decoder | One stateful `createMingoDecoder` per key, which lives as long as the key's sequence: `drop(key)` retires it. A send (`pushOptimisticSend`) lands what it still holds of a turn that ended with no `MESSAGE_END`, and a hydration that took the message it was writing discards it |

`evictionEpoch` is the signal consumers need: eviction replaces a reducer behind an unchanged key, so any one-shot state written into the old instance must be re-applied against the new one.

### NATS wiring

- **`natsMirrorOptions(handlersFor, selfUserId)`** — reducer creation options for NATS hosts: own-echo author guard and the model-badge metadata effect. A card's approve and reject are `ChatMessageActions` at render, not reducer options
- **`ChatModelMetadata`**, **`NatsMirrorHandlers`** (`{ onMetadata }`) — the late-bound handler bundle each host registers per dialog

### Small helpers

- **`makeChatRowId(prefix)`** — one recipe for locally-authored row ids (the reducer's echo consumption keys off rows looking the way this send path makes them)
- **`adminDisplayName(user)`** — display name for an operator-authored row

## Consumers

`mingo-messages-store` (key = dialogId), `ticket-details-store` (key = side, two reducers per dialog), and `use-chat-chunk-processor` (the shared NATS glue).

## Tests

`chat-stream-thread.test.ts` pins the hydration seam: append-without-start, referential stability, adopt-once arm/disarm and eviction parking; a key's decoder, what it holds across a merge and a send; and a multi-round answer's part order through the mirror.
