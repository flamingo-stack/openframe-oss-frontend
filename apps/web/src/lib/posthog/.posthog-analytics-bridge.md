# posthog-analytics-bridge.tsx

A headless React component that bridges authentication state to the GTM `dataLayer` for PostHog analytics, driving the signup funnel tracking without rendering any UI.

Since PostHog runs via Google Tag Manager (no bundled SDK), this component subscribes to the auth store and synchronously pushes `identify` and `signup_completed` events to the data layer the moment an authenticated session first resolves. It centralizes tracking for all authentication paths — post-signup login, SSO, and session restore — in a single place, avoiding duplicated logic scattered across auth flows.

The sync happens on the auth-store subscription callback (not inside a `useEffect` reacting to derived state), ensuring the event fires before any dashboard-redirect effect runs. This guarantees the event survives soft client-side navigations.

## Key Components

- **`PostHogAnalyticsBridge`** — Default-exported function component. Subscribes to `useAuthStore` on mount, tracks the last-seen user ID to avoid duplicate `identify` calls, and fires `signup_completed` exactly once per fresh signup (guarded by `consumePendingSignup()`). Renders `null`.

## Usage Example

Mount the bridge once near the root of the authenticated app shell (e.g., in a root layout or providers component):

```typescript
import { PostHogAnalyticsBridge } from '@/components/analytics/posthog-analytics-bridge';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <PostHogAnalyticsBridge />
      {children}
    </>
  );
}
```

No props are required. The component relies on `useAuthStore` for user state and on `pushIdentify` / `pushSignupCompleted` / `consumePendingSignup` from `@/lib/posthog/posthog-events` to interact with the GTM `dataLayer`.
