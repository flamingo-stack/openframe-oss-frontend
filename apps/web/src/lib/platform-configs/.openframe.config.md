This file defines the application configuration for the **OpenFrame** platform, implementing the shared `AppConfig` interface to customize branding, navigation, header/footer UI, and SEO metadata.

## Key Components

- **`openframeConfig`** — the exported `AppConfig` object containing:
  - **Identity**: `name`, `legalName`, `description`, `slogan`, `platform`
  - **Dynamic getters**: `url` and `logo` resolved via `getAppUrl()`
  - **`brandColors`**: metadata-only color tokens (actual UI styling uses ODS CSS)
  - **`seo`**: page title template, description, keywords, and social preview images
  - **`layout`**: toggles for header, footer, announcement banner, and sidebar visibility
  - **`navigation`**: logo render function, allowed/restricted routes, and nav visibility flags
  - **`ui`**: header behavior (`headerAutoHide`, `headerStyle`) and `getHeaderActions()` for rendering contextual profile/sign-up/CTA buttons
  - **`footer`**: logo, name, and link sections (Resources, Company)
  - **`contact`** and **`social`**: support/contact info and social links

## Usage Example

```typescript
import { openframeConfig } from './openframe.config';

// Consumed by a shared app shell/provider
function App() {
  return <AppShell config={openframeConfig} />;
}

// Example of dynamic header actions usage
const { left, right } = openframeConfig.ui.getHeaderActions({
  user: currentUser,
  router,
  onSignUp: () => router.push('/signup'),
});
```

This config is typically imported by a platform-selection layer that switches between multiple `AppConfig` objects (e.g., `openframeConfig`, other product configs) based on the active deployment target, enabling a single codebase to power multiple branded frontends.
