# test-module-resolve.mjs

A Node.js ESM loader hook that patches module resolution so native `node --test` runs can import TypeScript sources using the project's `@/` path alias and extensionless relative imports, mirroring behavior normally provided by the bundler.

## Key Components

- **Module-level side effect** — calling `registerHooks()` from `node:module` at import time, installing a custom `resolve` hook into Node's ESM resolution pipeline.
- **`SRC` constant** — resolves to the absolute `file://` URL of the project's source root (one directory up from this file), used to expand `@/` aliases.
- **`resolve(specifier, context, nextResolve)` hook**:
  - Rewrites `@/`-prefixed specifiers to absolute file URLs under `SRC`.
  - Appends a `.ts` extension to relative (`./`, `../`) or `file:` specifiers that lack a file extension, so extensionless imports resolve correctly.
  - Passes package specifiers (e.g. `node_modules` imports) through unmodified to `nextResolve`.

## Usage Example

Import this module for its side effect **before** dynamically importing the module under test:

```javascript
// my-module.test.mjs
import './test-module-resolve.mjs';

const { encodeCookie } = await import('./cookies.ts');
const { formatDate } = await import('@/utils/date.ts');

// ... test assertions using encodeCookie, formatDate
```

Run the test with Node's built-in test runner:

```bash
node --test src/lib/my-module.test.mjs
```

This avoids `ERR_MODULE_NOT_FOUND` errors that would otherwise occur because Node's resolver has no built-in knowledge of the `@/` alias or extensionless TypeScript imports used throughout the codebase.
