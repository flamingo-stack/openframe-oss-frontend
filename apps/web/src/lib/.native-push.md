# native-push.ts

Manages mobile push notifications for the Capacitor-based mobile shell: handles permission requests, Firebase Cloud Messaging (FCM) token registration with the backend, and forwards notification taps to the host app. This module is mobile-only — it no-ops on the web, desktop shell, and any shell without the Firebase messaging plugin. Notably, routing of tapped notifications is intentionally left to the caller, which uses the same resolution table as the in-app notification drawer, keeping the backend decoupled from frontend routes.

## Key Components

- **`initNativePush(onNotificationTap)`** — Entry point called post-login. Attaches plugin listeners (once per document load), requests notification permissions, fetches the FCM token, and registers the device. Re-runs token registration on every call to support re-login without a WebView reload.
- **`unregisterNativePush()`** — Deregisters the device server-side using the locally persisted token. Must be called while still authenticated, before logout clears local storage.
- **`registerPushDevice(token)`** (internal) — Persists the token locally and commits the `registerPushDevice` GraphQL mutation with platform and app version (used by the backend to select push payload format).
- **`unregisterPushDevice(token)`** (internal) — Best-effort GraphQL mutation to remove the device registration; failures are non-fatal.
- **`attachPushListeners(plugin)`** (internal) — Wires up `notificationActionPerformed` (tap), `tokenReceived` (rotation), and `notificationReceived` (retraction cleanup) listeners, each isolated so one failure doesn't block the others.

## Usage Example

```typescript
import { initNativePush, unregisterNativePush } from '@/native/native-push';
import { resolvePushNotificationAction } from '@/native/push-navigation';

// After successful login
await initNativePush((data) => {
  const route = resolvePushNotificationAction(data);
  if (route) router.push(route);
});

// Before logout, while still authenticated
await unregisterNativePush();
```

Notification tap data is passed verbatim as the raw FCM `data` map (a flat string map), which the caller resolves into an app route — this module never performs navigation itself.
