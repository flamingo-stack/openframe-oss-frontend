# scroll-to-first-invalid-field.ts

Utility that scrolls the first invalid field in a form into view and focuses it after a failed validation submit, ensuring users aren't left hunting for off-screen errors.

## Key Components

- **`scrollToFirstInvalidField()`** — Main exported function. Locates the first rendered field marked `[data-invalid]` (in DOM/reading order), scrolls its nearest real scroll container into view, and focuses an appropriate target element.
- **`INVALID_SELECTOR`** — `[data-invalid]`, the attribute core form inputs (and manually-marked custom blocks) set when invalid.
- **`INVALID_FIELD_TOP_OFFSET_PX`** — `96`px offset applied above the scrolled-to field so its error message isn't flush against the viewport edge.
- **`FOCUSABLE_SELECTOR`** — Matches standard focusable elements inside a field marker.
- **`FOCUS_TARGET_SELECTOR`** — `[data-invalid-focus]`, an opt-in override letting a wrapper (editor, button grid, radio group) specify which inner element should actually receive focus.

## Implementation Notes

- Runs inside `requestAnimationFrame` to wait for React to commit invalid-state attributes.
- Filters out invalid markers that aren't actually rendered (e.g., hidden responsive duplicates) by checking `offsetParent !== null` or `position: fixed`.
- Uses `scrollElementIntoView` from `@flamingo-stack/openframe-frontend-core/utils` instead of native `scrollIntoView`, avoiding the native API's side effect of scrolling every scrollable ancestor (including `overflow: hidden` containers), which can leave the app's nested scroll containers permanently misaligned.
- Calls `.focus({ preventScroll: true })` so screen readers/keyboard focus follow the scroll without triggering a conflicting jump.

## Usage Example

```typescript
import { scrollToFirstInvalidField } from './scroll-to-first-invalid-field';

function onInvalidSubmit() {
  toast.error('Please fix the highlighted fields');
  scrollToFirstInvalidField();
}

// In a react-hook-form handleSubmit call:
const submit = handleSubmit(onValid, onInvalidSubmit);
```

To let a wrapper component (e.g., a code editor or radio group) specify a custom focus target:

```vue
<template>
  <div data-invalid="true">
    <input type="radio" />
    <input data-invalid-focus type="text" />
  </div>
</template>
```
