# analytics.ts

Fire-and-forget analytics utility for tracking dashboard activation and engagement events. Designed to never block, delay, or throw errors into the calling UX flow.

## Key Components

- **`EVENT_TYPE`** — Constant string `'DASHBOARD_ACTIVITY'` used for every tracked event.
- **`REPEAT_MODE`** — Object defining counting semantics: `SINGULAR` (one-time milestone) vs `MULTI` (every occurrence counts).
- **`RepeatMode`** — Type derived from `REPEAT_MODE` values.
- **`EVENT_SUBTYPE`** — Single source of truth for all trackable event subtypes, organized by surface (`main_dashboard`, `mingo`, `ticket_detail`). Call sites must always use these constants rather than hand-written strings.
- **`EventSubtype`** — Type derived from `EVENT_SUBTYPE` values.
- **`repeatModeFor(subtype)`** — Internal helper that derives the repeat mode from the subtype using an internal `SINGULAR_SUBTYPES` set, so callers never need to specify it manually.
- **`trackDashboardActivity(subtype)`** — Main exported function. Posts the event to `/api/events` via `apiClient`, swallows all synchronous and asynchronous errors, and does not return a promise to the caller.

## Usage Example

```typescript
import { trackDashboardActivity, EVENT_SUBTYPE } from '@/lib/analytics';

// Fire on button click — no await needed, safe inside any handler
function handleAddDeviceClick() {
  trackDashboardActivity(EVENT_SUBTYPE.ADD_DEVICE);
  // ... continue with UI logic
}

// Fire inside a mutation success callback
function onTicketResolved() {
  trackDashboardActivity(EVENT_SUBTYPE.RESOLVE_TICKET);
}

// Onboarding skip is automatically treated as SINGULAR (counted once per user)
function handleSkipOnboarding() {
  trackDashboardActivity(EVENT_SUBTYPE.SKIP_ONBOARDING);
}
```

Since `trackDashboardActivity` is synchronous and error-safe, it can be called directly inside event handlers, `onClick` props, or mutation `onSuccess` callbacks without `try/catch` or `await`.
