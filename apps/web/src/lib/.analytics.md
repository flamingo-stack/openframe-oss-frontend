Thin analytics utility for fire-and-forget dashboard activity tracking. Provides typed event constants and a non-blocking `trackDashboardActivity` function that POSTs events to `/api/events` without ever blocking or surfacing errors to the caller.

## Key Components

| Export | Type | Description |
|---|---|---|
| `EVENT_TYPE` | `const` | Fixed string `'DASHBOARD_ACTIVITY'` sent with every event |
| `REPEAT_MODE` | `const object` | `SINGULAR` (one-time milestone) or `MULTI` (every occurrence) |
| `EVENT_SUBTYPE` | `const object` | Single source of truth for all valid event subtype strings |
| `RepeatMode` | `type` | Union of `REPEAT_MODE` values |
| `EventSubtype` | `type` | Union of `EVENT_SUBTYPE` values |
| `trackDashboardActivity` | `function` | Fire-and-forget POST; swallows all errors |

### Event Subtypes by Surface

| Surface | Subtypes |
|---|---|
| `/dashboard` | `ADD_DEVICE`, `ADD_SSO_IDP`, `SKIP_ONBOARDING` |
| Mingo chat drawer | `SEND_MINGO_MESSAGE`, `APPROVE_MINGO_COMMAND`, `REJECT_MINGO_COMMAND` |
| `/tickets/dialog` | `OPEN_REMOTE_SHELL`, `OPEN_REMOTE_CONTROL`, `RESOLVE_TICKET`, `START_DIRECT_CHAT` |

`SKIP_ONBOARDING` and `ADD_SSO_IDP` are automatically sent with `repeatMode: SINGULAR` — all others use `MULTI`. Call sites never need to specify the repeat mode.

## Usage Example

```typescript
import { trackDashboardActivity, EVENT_SUBTYPE } from '@/lib/analytics';

// Inside an event handler or mutation success callback — safe, non-blocking
function handleTicketResolved() {
  doSomethingImportant();
  trackDashboardActivity(EVENT_SUBTYPE.RESOLVE_TICKET); // fire-and-forget
}
```
