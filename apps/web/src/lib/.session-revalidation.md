# session-revalidation.ts

Implements re-validation of a `paused` session by periodically probing `/api/me`, triggered by app/tab becoming visible, native shell resume, network connectivity recovery, and a slow backoff timer. This is the mechanism that determines whether a paused session should resume polling, stay paused, or be signed out.

## Key Components

- **`REVALIDATE_INTERVAL_MS`** — Default interval (5 minutes) between timer-driven probes.
- **`REVALIDATE_MAX_INTERVAL_MS`** — Maximum backoff ceiling (1 hour) reached when probes keep getting rejected.
- **`REVALIDATE_MIN_GAP_MS`** — Minimum gap (30 seconds) enforced between event-driven probes to prevent flapping focus events from becoming a poller.
- **`RELAPSE_WINDOW_MS`** — Window (1 minute) used to detect a relapse into the same `rejected` pause shortly after resuming, doubling the backoff interval instead of resetting it.
- **`startSessionRevalidation()`** — Main entry point. Wires up:
  - `visibilitychange` listener (browser tab/app foreground)
  - `onAppResume` (native shell resume)
  - `subscribeConnectivity` (network link recovery, only on an off→on edge)
  - A self-rearming timer that fires while the session is `paused`
  
  Each trigger calls an internal `probe()` function that calls `apiClient.me()`:
  - On success (`2xx`), marks the session healthy and resumes normal polling.
  - On failure, re-arms the timer, doubling the interval if the pause reason is `'rejected'` (refresh-token rotation already spent).
  
  Returns a cleanup function that stops the timer and removes all listeners/subscriptions.

## Usage Example

```typescript
import { startSessionRevalidation } from './session-revalidation';

// Call once during app initialization, after session health store is set up.
const stopRevalidation = startSessionRevalidation();

// On app teardown (e.g., logout flow or test cleanup):
stopRevalidation();
```

This function is typically invoked once at app bootstrap alongside other session-health wiring (see `session-health.ts`), and the returned disposer should be called on full app shutdown or when tearing down in tests.
