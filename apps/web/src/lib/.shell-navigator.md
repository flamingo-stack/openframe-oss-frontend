Provides a router-agnostic navigation bridge that lets code outside React's render tree (notification handlers, desktop OS toasts, chip click callbacks) perform client-side, in-app navigation without reloading the whole application or depending on `window.location`.

## Key Components

- **`registerShellNavigator(navigate)`** — Registers a `Navigate` function (typically bound to Next's router) as the active app navigator. Returns an unregister callback that only clears the slot if it still points to the same navigator, preventing a stale remount's cleanup from clobbering a newer registration.
- **`navigateInApp(href)`** — Invokes the currently registered navigator to perform a client-side navigation to an in-app `href`. Returns `false` (and logs an error in non-production builds) if no navigator is registered, signaling the caller that there's no mounted app shell to navigate within.

## Usage Example

```typescript
// Inside the (app) layout — register once on mount
import { useRouter } from 'next/navigation';
import { useEffect } from 'react';
import { registerShellNavigator } from './shell-navigator';

function ShellNavigatorRegistrar() {
  const router = useRouter();

  useEffect(() => {
    const unregister = registerShellNavigator((href) => router.push(href));
    return unregister;
  }, [router]);

  return null;
}
```

```typescript
// Anywhere outside React — e.g. a notification click handler
import { navigateInApp } from './shell-navigator';
import { routes } from './routes';

function onNotificationClick(deviceId: string) {
  const didNavigate = navigateInApp(routes.device(deviceId));
  if (!didNavigate) {
    // Fallback: no app shell mounted, e.g. show a toast or queue navigation
  }
}
```

**Note:** Only one navigator is active at a time; registering a second replaces the first.
