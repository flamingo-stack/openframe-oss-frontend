Utility for determining whether a link click will navigate the current browser window, as opposed to opening the link in a new tab/window via modifier-key or middle-click interactions.

## Key Components

- **`navigatesCurrentWindow(event)`** — Pure function that inspects a click event's `button` and modifier key state (`metaKey`, `ctrlKey`, `shiftKey`, `altKey`) and returns `true` only when the click is a plain left-click with no modifiers held. It accepts any object structurally matching the relevant subset of `MouseEvent` properties, so it works with both native DOM events and React's `SyntheticEvent`.

## Usage Example

```typescript
import { navigatesCurrentWindow } from './link-click';

function handleLinkClick(event: React.MouseEvent<HTMLAnchorElement>) {
  if (navigatesCurrentWindow(event)) {
    // The click will navigate this window — safe to dismiss
    // a drawer, modal, or overlay before navigation occurs.
    closeDrawer();
  }
  // Otherwise (cmd/ctrl-click, shift/alt-click, or middle-click),
  // the link opens in a new tab/window — leave the current UI untouched.
}
```

## Notes

Use this check anywhere a dismissible UI surface (drawers, popovers, menus) contains links. Without it, a user who cmd-clicks a link to open it in a background tab would unexpectedly lose the surface they intentionally kept open, since the click handler would otherwise treat every click as a navigation.
