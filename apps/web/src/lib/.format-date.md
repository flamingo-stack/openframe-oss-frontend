Locale-aware date and time formatting utilities using `Intl.DateTimeFormat`. Accepts strings, numbers, or `Date` objects and returns a locale-appropriate string, falling back to `'—'` for missing or unparseable inputs.

## Key Components

| Export | Description |
|---|---|
| `formatDate` | Formats a date-only string (e.g. `12/31/24`) |
| `formatTime` | Formats a time-only string without seconds (e.g. `2:30 PM`) |
| `formatTimeWithSeconds` | Formats a time string including seconds (e.g. `2:30:45 PM`) |
| `formatDateTime` | Combines date and time into a single string (e.g. `12/31/24 2:30 PM`) |
| `DateInput` | Accepted input type: `string \| number \| Date` |

All formatters use `Intl.DateTimeFormat` with `undefined` locale (inherits the user's browser/system locale) and guard against invalid dates rather than throwing.

## Usage Example

```typescript
import { formatDate, formatTime, formatTimeWithSeconds, formatDateTime } from './format-date';

// ISO string from an API response
formatDate('2024-12-31T14:30:45Z');      // '12/31/24'
formatTime('2024-12-31T14:30:45Z');      // '2:30 PM'
formatTimeWithSeconds('2024-12-31T14:30:45Z'); // '2:30:45 PM'
formatDateTime('2024-12-31T14:30:45Z'); // '12/31/24 2:30 PM'

// Unix timestamp (milliseconds)
formatDateTime(1735652400000);           // '12/31/24 2:30 PM'

// Invalid / missing value — no try/catch needed at call site
formatDate(null as any);                 // '—'
formatDate('not-a-date');               // '—'
```

> Output format varies by locale. A user with `en-GB` locale will see `31/12/2024` instead of `12/31/24`.
