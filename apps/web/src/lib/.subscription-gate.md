# subscription-gate.ts

A client-side gate that holds all non-essential APP Relay requests until the workspace's subscription status is known, preventing a flash of error boundaries when a locked (e.g., trial-expired) workspace renders queries whose non-null fields the API cannot fulfill.

## Key Components

- **`GateState`** — Internal type: `'pending'` (unresolved, time-boxed), `'open'` (resolved, not locking), `'locked'` (resolved, locking — requests held indefinitely until paid).
- **`FAIL_OPEN_AFTER_MS`** — 10-second timeout after which `pending` requests are released even without an answer, to avoid stranding the app.
- **`markSubscriptionOpen()`** — Call when the subscription query resolves as non-locking (or billing doesn't apply); releases all parked requests.
- **`markSubscriptionLocked()`** — Call when the subscription query resolves as a locking status; keeps requests parked and re-arms the gate even if it had previously failed open.
- **`resetSubscriptionGate()`** — Resets to `pending` (e.g., on sign-out), waking parked requests so their resulting 401s drive the sign-in redirect.
- **`waitForSubscriptionGate()`** — Returns a `Promise<void>` to await before issuing a request, or `undefined` if the gate is open, already failed open, or running on the server.

## Usage Example

```typescript
import {
  waitForSubscriptionGate,
  markSubscriptionOpen,
  markSubscriptionLocked,
  resetSubscriptionGate,
} from './subscription-gate';

// In a Relay fetch wrapper, before issuing an app query:
async function fetchRelay(request: Request) {
  const skip = request.cacheConfig?.metadata?.skipSubscriptionGate;
  if (!skip) {
    await waitForSubscriptionGate();
  }
  return performFetch(request);
}

// After the subscription query itself resolves:
function handleSubscriptionResponse(data: SubscriptionPayload) {
  if (isLockingStatus(data.status)) {
    markSubscriptionLocked();
  } else {
    markSubscriptionOpen();
  }
}

// On sign-out or session invalidation:
resetSubscriptionGate();
```

Queries that render the lock screen itself (plan picker, billing portal) and all mutations must opt out via `networkCacheConfig: { metadata: { skipSubscriptionGate: true } }` to avoid deadlocking the app.
