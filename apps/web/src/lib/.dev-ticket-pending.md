# dev-ticket-pending.ts

Tracks whether a dev authentication ticket present in the URL is still awaiting its token exchange, preventing premature session checks from firing a doomed `/me` request (and resulting 401/refresh loop) before the ticket has been redeemed for a bearer credential.

## Key Components

- **`markDevTicketSettled(ticket: string): void`** — Records that the given dev ticket's exchange has completed, whether it succeeded or failed. Call this once the exchange request resolves.
- **`isDevTicketExchangePending(): boolean`** — Returns `true` if the current URL contains a `devTicket` query parameter that hasn't yet been marked as settled. Returns `false` on the server (no `window`) or when there's no unsettled ticket.

## Usage Example

```typescript
import { isDevTicketExchangePending, markDevTicketSettled } from './dev-ticket-pending';

// Session check: skip the /me call while a ticket exchange is still pending
async function checkSession() {
  if (isDevTicketExchangePending()) {
    return; // avoid firing /me before the exchange delivers a bearer token
  }
  await fetchCurrentUser();
}

// Token exchange: mark the ticket settled once it resolves, success or failure
async function exchangeDevTicket(ticket: string) {
  try {
    await performExchange(ticket);
  } finally {
    markDevTicketSettled(ticket);
  }
}
```

## Notes

- State is held in a module-level variable (`settledTicket`), so it resets on full page reloads—each ticket is only ever "spent" by its single exchange attempt during that page's lifetime.
- Designed to be read by both the session-check logic and the exchange logic, coordinating them without a shared store or event bus.
