Generates Next.js `Metadata` title objects that remain correct at any route nesting depth, avoiding the suffix-dropping problem of Next.js's segment-relative title templates.

## Key Components

- **`APP_NAME`** — Constant holding the application name (`'OpenFrame'`), appended as a suffix to every generated title.
- **`routeTitle(name: string): Metadata['title']`** — Builds an *absolute* title object (`{ absolute: "<name> | OpenFrame" }`) for use in a route segment's `metadata` export. Using `absolute` bypasses the root layout's `'%s | OpenFrame'` template, ensuring the suffix is applied consistently regardless of nesting depth and is never dropped or duplicated.

## Usage Example

```typescript
import type { Metadata } from 'next';
import { routeTitle } from './route-title';

export const metadata: Metadata = {
  title: routeTitle('Devices'),
};

// Deeper nested route, e.g. /devices/details
export const metadata: Metadata = {
  title: routeTitle('Device'),
};
```

Both routes produce the correct, non-stacked title (`"Devices | OpenFrame"` and `"Device | OpenFrame"` respectively), unlike a plain string title which would only correctly apply the template suffix one level below the layout that declares it. For client-rendered sections that need to set this dynamically, see `app/(app)/route-title-layout.tsx`.
