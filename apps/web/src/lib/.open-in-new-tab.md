Utility functions for programmatic navigation inside `<Link>`-wrapped DataTable rows, where nesting `<a>` inside `<a>` is invalid HTML.

## Key Components

- **`openInNewTab(href)`** — Returns a click handler that opens `href` in a new tab using `window.open` with `noopener,noreferrer` security flags and calls `preventDefault` to suppress parent link navigation.
- **`navigateTo(router, href)`** — Returns a click handler that navigates to `href` in the same tab via the Next.js router (`useRouter`), also calling `preventDefault` to stop the parent row `<Link>` from firing.
- **`Router`** — Minimal interface requiring only a `push` method, keeping the utility decoupled from a specific router implementation.

## Usage Example

```typescript
import { openInNewTab, navigateTo } from '@/utils/open-in-new-tab';
import { useRouter } from 'next/navigation';

function TicketRowActions({ ticketId }: { ticketId: string }) {
  const router = useRouter();

  return (
    <>
      {/* Opens ticket detail in a new tab */}
      <button
        data-no-row-click
        onClick={openInNewTab(`/tickets/${ticketId}`)}
      >
        Open in new tab
      </button>

      {/* Navigates in the same tab without triggering the row <Link> */}
      <button
        data-no-row-click
        onClick={navigateTo(router, `/tickets/${ticketId}/edit`)}
      >
        Edit
      </button>
    </>
  );
}
```

> Both handlers are designed to be used alongside `data-no-row-click` to prevent the parent DataTable row's `<Link>` from also navigating. See the source at [`src/utils/open-in-new-tab.ts`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/src/utils/open-in-new-tab.ts).
