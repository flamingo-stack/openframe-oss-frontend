# visit-attribution.ts

Tracks where a visitor came from (UTM tags, ad-platform click ids, referrer) and persists it in `localStorage` so a signup or download can later read the attribution. The logic is shared byte-for-byte between `multi-platform-hub` and `openframe-oss-frontend` — any change must be mirrored in both repositories.

## Key Components

- **`VISIT_SOURCE_PARAMS` / `VISIT_FIELDS`** — Canonical lists of the URL parameters (UTM tags, click ids) and visit fields (adds `referrer`, `landing_url`) recognized by the module.
- **`CLICK_PLATFORMS`** — Maps each supported ad platform (`meta`, `google`, `reddit`, `linkedin`) to its click-id query parameter.
- **`Visit` / `VisitFields` / `Click`** — Core data shapes: a `Visit` bundles source fields with a `landedAt` timestamp; a `Click` pairs a platform's click id with `clickedAt`.
- **`VisitAttribution`** — The overall stored state: `firstVisit`, `lastVisit`, and `latestClicks` per platform.
- **`parseFbc(value)`** — Parses Meta's `_fbc` cookie format (`fb.<subdomain>.<time>.<fbclid>`) into a `Click`.
- **`pickFbc(values, attribution)`** — Given candidate `_fbc` values, determines which one names the latest known Meta click.
- **Internal storage helpers** (`readEntry`, `writeEntry`, `removeEntry`, `readStoredVisit`, `writeVisit`, `readStoredClick`, `keepClick`) — Manage `localStorage` reads/writes with a 90-day TTL (`ATTRIBUTION_TTL_MS`), since entries never expire on their own.
- **Arrival/visit classification helpers** (`isDirect`, `isInsideReferrer`, `isOwnHost`, `outranks`, `sameFields`) — Decide whether a page load counts as an "arrival" (has a source) vs. a "direct" visit, and whether a new visit should replace a stored one.
- **`toVisitUrl`** — Sanitizes and truncates a URL to `origin + pathname`, dropping it if it exceeds `VISIT_URL_MAX_LENGTH`.

## Usage Example

```typescript
import { parseFbc, pickFbc, VisitAttribution } from './visit-attribution';

// Parse a raw _fbc cookie value into a structured click
const click = parseFbc('fb.1.1700000000000.abc123');
// => { id: 'abc123', clickedAt: 1700000000000 }

// Decide which _fbc value to send to the backend given stored attribution
const attribution: VisitAttribution = {
  firstVisit: { fields: { fbclid: 'abc123' }, landedAt: 1700000000000 },
  lastVisit: undefined,
  latestClicks: {},
};

const fbc = pickFbc([document.cookie.match(/_fbc=([^;]+)/)?.[1]], attribution);
```

Visit and click data are read/written automatically through internal `localStorage` helpers using the `of_attr_` key prefix; consumers typically interact with higher-level functions (e.g., attribution recording on page load and retrieval at signup) built on top of these primitives.
