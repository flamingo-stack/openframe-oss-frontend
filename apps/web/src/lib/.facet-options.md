## facet-options.ts

Client-side utilities for managing server-driven facet (filter) options in search/funnel UIs, ensuring previously selected values remain selectable even when the server's current result set no longer includes them.

## Key Components

- **`FacetRow`** — Interface describing one facet option as returned by the server: `value`, `label`, and `count`.
- **`withSelected<T>(options, selected, atZero)`** — Merges server-provided facet options with any currently selected values that are missing from the result set (because a search or another filter zeroed them out). Missing selected values are synthesized via `atZero(value)` and appended so the UI can still display/untick them.
- **`useSeenLabels<K>(answer)`** — React hook that remembers the label each facet value was last seen under, across successive query answers. Useful when a later answer drops a previously ticked value (count now zero) but the UI still needs to show its original label instead of falling back to the raw id. Uses the "adjust state while rendering" pattern, keyed on reference equality of `answer`, so pass the query's own record (not a render-time copy).

## Usage Example

```typescript
import { withSelected, useSeenLabels, type FacetRow } from './facet-options';

// Merging selected ticks back into server facet options
const serverOptions: FacetRow[] = [
  { value: 'acme', label: 'Acme Corp', count: 12 },
];
const selectedValues = ['acme', 'globex']; // 'globex' no longer in results

const options = withSelected(
  serverOptions,
  selectedValues,
  (value) => ({ value, label: value, count: 0 }),
);
// => [{ value: 'acme', ... }, { value: 'globex', label: 'globex', count: 0 }]

// Remembering labels across query updates
function CustomerFacet({ answer }: { answer: Record<'customer', FacetRow[]> }) {
  const getLabel = useSeenLabels(answer);
  const label = getLabel('customer', 'globex'); // returns last known label, if seen
}
```

**Note:** `useSeenLabels` relies on the identity of `answer` (e.g., from Relay) to detect new data — avoid passing a freshly created object on every render.
