# session-activity.ts

Tracks whether a human is actively present in the current browser tab or mobile app shell, exposing two distinct signals — **attention** (is someone at the keyboard *right now*) and **presence** (is someone around at all) — used to gate irreversible actions like auto-read and push-notification cancellation.

This module deliberately avoids conflating "session is active" with "notification was seen": the former is a property of the tab, the latter a property of the item (and is cross-device). It also implements two independent detection strategies — input-recency tracking on the web, and `appStateChange` foreground signal on the mobile shell — because touch interfaces have no pointer-movement equivalent to infer idleness from.

## Key Components

- **`ATTENTION_IDLE_MS`** — 10s threshold for irreversible actions (auto-read, push cancel). Tight window; under-firing is the safe failure mode.
- **`PRESENCE_IDLE_MS`** — 5 minute threshold for presence heartbeat / outbox grace decisions. Generous window; costs only a skipped grace period.
- **`isSessionActive({ idleAfterMs })`** — Returns whether the session counts as active given the caller's chosen threshold. Lazily starts the detection source (web listeners or shell `appStateChange`) on first call.
- **`subscribeSessionActivity`** *(referenced, truncated in source)* — Notifies on hard edges only (focus/blur, foreground/background).
- **`subscribeAttention`** *(referenced, truncated in source)* — Notifies on hard edges plus the "human resumed input after an idle window" edge.

## Usage Example

```typescript
import { isSessionActive, ATTENTION_IDLE_MS, PRESENCE_IDLE_MS } from './session-activity';

// Gate an irreversible auto-read / push-cancel decision
if (isSessionActive({ idleAfterMs: ATTENTION_IDLE_MS })) {
  cancelPendingPushNotification();
  markItemAsRead();
}

// Feed a presence heartbeat to the server
function reportPresence() {
  const present = isSessionActive({ idleAfterMs: PRESENCE_IDLE_MS });
  sendHeartbeat(present);
}
```

Callers should always pick the threshold matching the cost of being wrong: use `ATTENTION_IDLE_MS` for anything that can't be undone (push cancellation, marking read across devices), and `PRESENCE_IDLE_MS` for lower-stakes signals like heartbeats or grace-period decisions.
