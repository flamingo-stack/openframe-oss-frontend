Zustand store that holds tenant- and user-level onboarding progress, mirrored from the backend and shared across all onboarding surfaces (app-layout top bar, sidebar badge, dashboard Initial Setup card, and the `/onboarding` Get Started page). It is hydrated once by `OnboardingProgressHydrator` and kept in sync via mutation hooks that return the full progress object, so a single update (e.g. "Mark as Complete") reflects everywhere instantly.

The store is intentionally non-suspending — onboarding UI is decorative chrome and must never block app rendering. Consumers should check `isLoaded === false` to show a loading/placeholder state rather than suspending.

## Key Components

- **`TenantOnboardingProgress`** — Shape of tenant-level onboarding state: `completedSteps`, `completed`, `completedAt`.
- **`UserOnboardingProgress`** — Shape of user-level onboarding state: `completedSteps`, `completed`, `completedAt`, `skipped`/`skippedAt`, `tourDialogId` (Mingo tour conversation), and `setupSeen` (persistent flag that the setup wizard's final screen was shown).
- **`OnboardingState`** — Store interface combining `tenant`, `user`, `isLoaded`, and actions `setTenant`, `setUser`, `setLoaded`, `reset`.
- **`useOnboardingStore`** — The Zustand hook, built with `immer` (for ergonomic mutable updates) and `devtools` (for debugging), named `onboarding-store` in devtools.

## Usage Example

```typescript
import { useOnboardingStore } from '@/stores/onboarding-store';

// Read progress in a component
function OnboardingBadge() {
  const { tenant, isLoaded } = useOnboardingStore();

  if (!isLoaded) return null; // non-blocking: just hide until hydrated
  if (tenant?.completed) return null;

  return <span>{tenant?.completedSteps.length} steps completed</span>;
}

// Update progress after a mutation response
function handleMarkComplete(progress: TenantOnboardingProgress) {
  useOnboardingStore.getState().setTenant(progress);
}

// Reset on logout
useOnboardingStore.getState().reset();
```
