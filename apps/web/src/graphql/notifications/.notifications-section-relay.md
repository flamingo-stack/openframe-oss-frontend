# notifications-section-relay.ts

Defines the GraphQL query and paginated, refetchable fragment used by the notifications section to fetch and infinitely scroll through notifications, sharing the same underlying data shape as the notifications drawer.

## Key Components

- **`notificationsSectionRelayQuery`** – Root GraphQL query that accepts pagination (`first`, `after`), `filter`, and `search` arguments and spreads the `notificationsSectionRelay_query` fragment.
- **`notificationsSectionRelayFragment`** – A `@refetchable` fragment on `Query` (generates `notificationsSectionRelayPaginationQuery`) that resolves a `notifications` connection with `@connection` support for pagination via `useConnectionQuery`/`usePaginationFragment`. Each edge spreads the shared `notificationFields_notification` fragment to ensure consistent row data across the section and drawer views.

## Usage Example

```typescript
import { usePaginationFragment } from 'react-relay';
import { notificationsSectionRelayFragment } from './notifications-section-relay';

function NotificationsSection({ queryRef }) {
  const { data, loadNext, hasNext, refetch } = usePaginationFragment(
    notificationsSectionRelayFragment,
    queryRef
  );

  return (
    <div>
      {data.notifications.edges.map(({ node, cursor }) => (
        <NotificationRow key={cursor} notification={node} />
      ))}
      {hasNext && <button onClick={() => loadNext(50)}>Load more</button>}
    </div>
  );
}
```

Fetch the root query with `notificationsSectionRelayQuery` via `useLazyLoadQuery`, passing `first`, `after`, `filter`, and `search` variables, then pass the resulting query reference into `usePaginationFragment` as shown above to enable infinite scrolling and refetching when filters or search terms change.
