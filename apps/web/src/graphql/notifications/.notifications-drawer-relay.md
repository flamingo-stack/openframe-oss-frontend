## notifications-drawer-relay.ts

Defines the Relay GraphQL query and refetchable fragment powering the notifications drawer's paginated feed, plus a throttled refetch helper used to reconcile the Relay store after live-push gaps (e.g., dropped NATS connections).

## Key Components

- **`DRAWER_PAGE_SIZE`** — Constant (`30`) defining the first-page size; kept in sync with the fragment's `first` default.
- **`notificationsDrawerRelayQuery`** — GraphQL query that spreads the paginated fragment, accepting `first` and `after` arguments.
- **`notificationsDrawerRelayFragment`** — `@refetchable` fragment on `Query` exposing a `@connection`-annotated `notifications` field (filtered to unread, no search), reusing the shared `notificationFields_notification` row selection so the drawer and section list read identical store data.
- **`refetchNotificationsDrawer(environment)`** — Issues a cursor-less, `network-only` fetch of the drawer's first page to replace the connection's edges in the Relay store. Throttled per-`IEnvironment` via a `WeakMap` (minimum 3s between refetches) so bursts of calls cost a single network request. On failure, previous rows are preserved and a warning is logged.

## Usage Example

```typescript
import { useEnvironment } from 'react-relay';
import { refetchNotificationsDrawer } from './notifications-drawer-relay';

function useNotificationGapRecovery() {
  const environment = useEnvironment();

  // Call whenever the live-push channel reconnects or a gap is detected
  function handleReconnect() {
    refetchNotificationsDrawer(environment);
  }

  return { handleReconnect };
}
```

The exported query/fragment are typically consumed via `usePaginationFragment` or `useLazyLoadQuery` in the drawer component to render and paginate the unread notifications list, while `refetchNotificationsDrawer` is invoked out-of-band (e.g., on reconnect events) to ensure the store stays consistent with the server.
