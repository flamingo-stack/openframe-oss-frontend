# store-fixtures.ts

Test helper utilities for creating and inspecting a real Relay runtime store populated with notification connection data, intended for tests that need to validate actual store state rather than relying on mocked Relay environments.

## Key Components

- **`makeOfflineEnvironment()`** — Creates a Relay `Environment` with a network layer that always rejects (since no network calls should occur in tests), backed by a fresh in-memory `Store`/`RecordSource`.
- **`createConnection(store, filters)`** — Materializes an empty `NotificationConnection` record under the store root, mimicking the shape a GraphQL query response would produce (including an empty `edges` list and a `PageInfo` record with `hasNextPage: false`). Keys the connection using the same handle-key/filters scheme Relay's `ConnectionHandler` expects.
- **`nodeIds(environment, filters)`** — Reads back the node IDs currently linked in the notifications connection for the given filters, using `ConnectionHandler.getConnection` inside a local update transaction.

## Usage Example

```typescript
import { makeOfflineEnvironment, createConnection, nodeIds } from './store-fixtures';
import { commitLocalUpdate } from 'relay-runtime';

const environment = makeOfflineEnvironment();
const filters = { status: 'UNREAD' };

// Set up an empty connection in the store
commitLocalUpdate(environment, store => {
  createConnection(store, filters);
});

// Inspect which node IDs are currently in the connection
const ids = nodeIds(environment, filters);
expect(ids).toEqual([]);
```

This pattern is useful for testing Relay updaters, subscriptions, or mutations that manipulate the `NotificationConnection` directly in the store, since it exercises the real `ConnectionHandler` APIs rather than asserting against mocked calls.
