# mark-notification-read-mutation.ts

Defines a Relay GraphQL mutation for marking a single notification as read, applying optimistic updates to all live notification lists and refreshing unread counts.

## Key Components

- **`markNotificationReadMutation`** — GraphQL mutation definition (`markNotificationAsRead`) that accepts a notification `ID!` and marks it as read on the server.
- **`commitMarkNotificationRead(environment, id, { pairs, onError })`** — Core mutation committer. Applies an optimistic and server-confirmed store update via `makeMarkReadUpdater` across all connection pairs supplied by `pairs()`, then refreshes global and entity-scoped unread counts on completion.
- **`markNotificationReadById(rawId)`** — Convenience wrapper for use outside React (e.g., from a notification shell/tap handler). Resolves the raw id to a global id, uses `getLiveConnectionPairs` to target all mounted notification lists, and logs (rather than throws) on failure.

## Usage Example

```typescript
import { commitMarkNotificationRead, markNotificationReadById } from './mark-notification-read-mutation';
import { getRelayEnvironment } from '@/lib/relay/environment';
import { getLiveConnectionPairs } from './live-connection-pairs';

// From within a React component with access to Relay environment
commitMarkNotificationRead(getRelayEnvironment(), notificationId, {
  pairs: getLiveConnectionPairs,
  onError: (error) => console.error('Failed to mark notification read:', error),
});

// From outside React, e.g. a push notification tap handler
markNotificationReadById(rawNotificationId);
```

**Note:** For notifications marked read via a live bridge arrival, commit the bare `markNotificationReadMutation` directly instead of calling `commitMarkNotificationRead`, since the arrival's own store update already reflects the read state (see `notifications-data-provider.tsx`).
