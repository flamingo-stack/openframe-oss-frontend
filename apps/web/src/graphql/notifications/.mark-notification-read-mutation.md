Defines the Relay GraphQL mutation that marks a single notification read, and the commit every read the user causes goes through.

## Key Components

- **`markNotificationReadMutation`** — A compiled Relay `graphql` mutation that calls `markNotificationAsRead` on the server, accepting a notification `ID` and returning a boolean result.
- **`commitMarkNotificationRead(environment, id, { pairs, onError })`** — How a read the user causes (a click, a shell's tap, arriving at its entity) is committed: optimistically into the connections `pairs()` names (read when the store update runs), then the unread counts and the notification's entity counts re-read. `useNotificationMutations`' `markRead` / `autoMarkRead` go through it. The live bridge's reads on arrival (`notifications-data-provider.tsx`) commit the bare mutation instead: the arrival's own store update already holds the read.
- **`markNotificationReadById(rawId)`** — The same read from outside React, on the Relay singleton and every live list (`getLiveConnectionPairs`), failures logged only: what a shell's tap calls for an announcement it opened (the id comes from `tappedNotificationId`).

## Usage Example

```typescript
import { useRelayEnvironment } from 'react-relay';
import { commitMarkNotificationRead, markNotificationReadById } from './mark-notification-read-mutation';

// In React: read the row into the lists this view shows, and say when it failed.
const environment = useRelayEnvironment();
commitMarkNotificationRead(environment, notificationGlobalId, {
  pairs: () => filterPairs,
  onError: error => toast({ title: 'Failed to mark as read', description: error.message, variant: 'destructive' }),
});

// Outside React (a shell's tap), by the stored id the payload names:
const notificationId = tappedNotificationId(payload);
if (notificationId) markNotificationReadById(notificationId);
```

## Notes

- The mutation accepts a single `$id: ID!` variable mapped to the `notificationId` argument.
