# use-mark-entity-notifications-read.ts

A React hook that marks all notifications for a specific entity (e.g., a ticket or Mingo dialog) as read in a single mutation call, and refreshes the related unread-count caches used by sidebar badges.

This hook complements `EntityViewAutoReader` (which updates individually loaded notification cards) by handling notifications the drawer never paged in — which is what sidebar bucket counts actually reflect. Since no Relay updater is committed, callers must ensure their invocation context overlaps with wherever auto-reading occurs (e.g., the ticket caller only fires when the URL has `tab=chat`), or accept temporary UI skew between the drawer and refreshed counts.

**Important:** `entityId` must be the raw entity id (e.g., the ai-agent's raw `Ticket.ticketId`), not a Relay global id — encoding it would silently no-op the mutation.

Failures are logged (not toasted), since the action isn't user-triggered and the next entity open will naturally retry.

## Key Components

- **`useMarkEntityNotificationsRead()`** — Hook returning a memoized callback to mark notifications read for a given entity.
- **Returned callback signature:** `(entityType: NotificationEntityType, entityId: string, onCompleted?: () => void) => void`
  - Commits `markNotificationsReadForEntityMutation`.
  - On success: calls `refreshUnreadCounts` and `refreshEntityUnreadCounts`, then invokes `onCompleted`.
  - On error: logs a warning via `console.warn`.

## Usage Example

```typescript
import { useMarkEntityNotificationsRead } from './use-mark-entity-notifications-read';

function TicketChatPanel({ ticketId }: { ticketId: string }) {
  const markEntityRead = useMarkEntityNotificationsRead();
  const searchParams = useSearchParams();

  useEffect(() => {
    if (searchParams.get('tab') === 'chat') {
      markEntityRead('TICKET', ticketId, () => {
        console.log('Ticket notifications marked as read');
      });
    }
  }, [ticketId, searchParams, markEntityRead]);

  return <div>{/* chat UI */}</div>;
}
```

**Note:** Only invoke this when your view's active state matches the condition the entity's notifications route on (e.g., chat tab open), to avoid showing stale `read: false` cards in other parts of the UI until they refetch.
