Fetches paginated, unread approval-request notifications (ticket and Mingo approval types) from the Relay GraphQL endpoint, serving as the data source for the "Needs approval" notifications page.

## Key Components

- **`approvalNotificationsRelayQuery`** — GraphQL query (via `graphql` tagged template) that fetches a page of notifications filtered by type, reusing the shared `notificationFields_notification` fragment also used by the notifications drawer.
- **`APPROVAL_NOTIFICATIONS_PAGE_SIZE`** — Constant defining the default page size (`20`) for pagination.
- **`APPROVAL_NOTIFICATIONS_FILTER`** — Server-side filter object restricting results to unread notifications of type `TICKET_APPROVAL_REQUEST_TYPE` or `MINGO_APPROVAL_REQUEST_TYPE`.
- **`ApprovalNotificationsPage`** — Interface describing the shape of a fetched page: an array of `Notification` objects plus Relay `pageInfo` (cursor-based pagination state).
- **`fetchApprovalNotifications(after)`** — Async function that executes the Relay query with a `network-only` fetch policy, maps each returned node through `readNotificationNode` → `mapNotificationNode` → `withNotificationIcon`, and returns an `ApprovalNotificationsPage`.

## Usage Example

```typescript
import { fetchApprovalNotifications } from './approval-notifications-relay';

async function loadApprovals() {
  let after: string | undefined;
  let allNotifications = [];

  do {
    const page = await fetchApprovalNotifications(after);
    allNotifications = allNotifications.concat(page.notifications);
    after = page.pageInfo.hasNextPage ? page.pageInfo.endCursor ?? undefined : undefined;
  } while (after);

  return allNotifications;
}
```

This is typically consumed by the "Needs approval" page component to incrementally load unread approval notifications as the user scrolls or paginates, ensuring notifications beyond the first page are still surfaced via server-side filtering.
