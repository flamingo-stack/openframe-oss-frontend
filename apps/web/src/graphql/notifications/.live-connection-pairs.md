# live-connection-pairs.ts

Maintains a registry of active notification connection pairs and a pub/sub channel for triggering read-status refreshes, enabling live read-state events to propagate across all mounted notification lists (not just the drawer).

## Key Components

- **`registerLiveConnectionPairs(pairs)`** — Registers a list's set of `NotificationConnectionPair`s so live read-state updates can be applied to it. Returns an unregister function for cleanup (e.g., on unmount).
- **`getLiveConnectionPairs()`** — Returns all currently registered connection pairs, always including `UNFILTERED_NOTIFICATION_PAIR` first (used by the drawer). Duplicates are allowed since consumers dedupe by connection.
- **`subscribeReadStatusRefresh(listener)`** — Subscribes a callback to be invoked when a read-status refresh is needed (used by history lists that can't self-resolve an ambiguous event). Returns an unsubscribe function.
- **`requestReadStatusRefresh()`** — Notifies all subscribed listeners to refetch read status from the server.

## Usage Example

```typescript
import {
  registerLiveConnectionPairs,
  getLiveConnectionPairs,
  subscribeReadStatusRefresh,
  requestReadStatusRefresh,
} from './live-connection-pairs';

// In a mounted notifications list component
useEffect(() => {
  const unregister = registerLiveConnectionPairs(myConnectionPairs);
  return unregister;
}, [myConnectionPairs]);

// In the live bridge, when a read-state event arrives
const allPairs = getLiveConnectionPairs();
applyReadStateToConnections(allPairs);

// In a history list needing a refresh on ambiguous ARCHIVED/READ events
useEffect(() => {
  return subscribeReadStatusRefresh(() => refetchNotifications());
}, []);

// When the live bridge can't resolve the event locally
requestReadStatusRefresh();
```

## Notes

This module relies on `NotificationConnectionPair` and `UNFILTERED_NOTIFICATION_PAIR` from `./notifications-helpers`. Unregistered stale pairs (e.g., from a prior search string) are safely ignored since their Relay queries are disposed and subsequent loads use `network-only` fetch policy.
