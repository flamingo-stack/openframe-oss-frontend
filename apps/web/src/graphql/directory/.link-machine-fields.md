# link-machine-fields.ts

Defines a Relay inline GraphQL fragment for `Machine` data and a transformation function that normalizes raw machine fields into a `LinkMachine` shape used by the Devices tab and device-linking UI (e.g., Link modal).

## Key Components

- **`linkMachineFieldsFragment`** — Relay `@inline` GraphQL fragment on `Machine`, selecting fields needed for machine linking: `id`, `machineId`, `hostname`, `displayName`, `nickname`, `type`, `status`, `lastSeen`, `osVersion`, `serialNumber`, and `directorySources`.
- **`LinkMachine`** — Interface representing the normalized machine data consumed by UI components. Notably distinguishes the Relay `id` (for cache/identity) from `machineId` (the agent id used by `linkDirectoryDevice` and device pages).
- **`toLinkMachine(ref)`** — Reads the inline fragment data from a given Relay fragment key and maps it into a `LinkMachine` object, deriving `name` via `getDeviceName`, `summary` via `machineSummary`, and `facts` via `machineLinkFacts`.

## Usage Example

```typescript
import { toLinkMachine, linkMachineFieldsFragment } from './link-machine-fields';
import type { linkMachineFields_machine$key } from '@/__generated__/linkMachineFields_machine.graphql';

function MachineRow({ machineRef }: { machineRef: linkMachineFields_machine$key }) {
  const machine = toLinkMachine(machineRef);

  return (
    <div>
      <h3>{machine.name}</h3>
      <p>{machine.summary}</p>
      <p>{machine.facts}</p>
      <span>Status: {machine.status ?? 'Unknown'}</span>
    </div>
  );
}
```

This pattern is typically used wherever a parent query spreads the `linkMachineFields_machine` fragment on a `Machine` type, allowing child components to call `toLinkMachine` to get a flattened, display-ready object without re-fetching data.
