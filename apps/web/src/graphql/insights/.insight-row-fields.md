## insight-row-fields.ts

Defines a Relay `@inline` GraphQL fragment that selects the minimal set of fields needed to render a row in the Incidents table, intentionally excluding heavier detail-page fields.

## Key Components

- **`insightRowFieldsFragment`** — An `@inline` GraphQL fragment (`insightRowFields_insight` on `Insight`) selecting:
  - Core fields: `id`, `title`, `type`, `severity`, `status`, `snoozedUntil`, `detectedAt`
  - Machine data: `machineId` (raw id) plus `machine { nickname, hostname, displayName, type }`
  - Organization data: `organizationId` (raw id) plus `organization { id, name }` (opaque node handle)
  - Assignee data: `assigneeId` (raw `User.id`) plus `assignee` spreading `userSummaryFields_user`

This fragment is deliberately narrow — it omits `description` and `queryResult` (osquery evidence), which belong to the detail view and can be large payloads.

Note the dual id pattern: raw ids (`machineId`, `organizationId`, `assigneeId`) are used by filters, routes, and mutations like `assignInsight`, while the nested `.id` fields are opaque Relay node handles used for object identity/refetching.

## Usage Example

```typescript
import { readInlineData, graphql } from 'react-relay';
import { insightRowFieldsFragment } from './insight-row-fields';

function toIncidentRow(insightRef: any) {
  const insight = readInlineData(insightRowFieldsFragment, insightRef);

  return {
    id: insight.id,
    title: insight.title,
    severity: insight.severity,
    status: insight.status,
    machineLabel: insight.machine?.displayName ?? insight.machine?.hostname,
    organizationId: insight.organizationId,
    organizationName: insight.organization?.name,
    assigneeId: insight.assigneeId,
  };
}
```

Typically consumed by a parent query that spreads `...insightRowFields_insight` on each `Insight` node in a list, then maps results through `toIncidentRow` to produce table-ready row objects.
