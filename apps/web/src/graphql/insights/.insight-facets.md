## Overview

Defines a GraphQL Relay fragment that exposes filter facet data for the Incidents table's column funnels (dropdown filters), along with the total filtered result count displayed in the "N results" label. This fragment is designed to be spread by the list query so that every refetch (pagination, filter change, "Archive Resolved" action, etc.) keeps the facet counts in sync with the current result set.

## Key Components

- **`insightFacetsFragment`** — A GraphQL fragment (`insightFacets_filters` on `InsightFilters`) marked `@inline`, exposing:
  - `types` — facet options for incident type, each with `value`, `label`, `count`
  - `severities` — facet options for severity level
  - `statuses` — facet options for incident status
  - `organizationIds` — facet options for organization filtering
  - `assigneeIds` — facet options for assignee filtering
  - `filteredCount` — total number of results matching current filters

The `@inline` directive is used because consuming components read the fragment data directly (e.g., mapping facets to dropdown options) rather than passing it through Relay's container/reader boundary.

## Usage Example

```typescript
import { readInlineData, graphql } from 'react-relay';
import { insightFacetsFragment } from './insight-facets';

const query = graphql`
  query IncidentsListQuery {
    insightFilters {
          # Spread result used with readInlineData
    }
  }
`;

// Inside a component or resolver that has the parent data:
function getFacets(parentFilters: any) {
  const facets = readInlineData(insightFacetsFragment, parentFilters);

  const statusOptions = facets.statuses.map((s) => ({
    label: `${s.label} (${s.count})`,
    value: s.value,
  }));

  return { statusOptions, resultsLabel: `${facets.filteredCount} results` };
}
```

Each time the Incidents list query refetches (e.g., after applying a filter or archiving resolved items), the spread fragment data updates automatically, keeping facet dropdowns and the results count label accurate.
