Provides all onboarding GraphQL mutations for tenant and user flows, committing them via Relay's `commitMutation` (lifecycle-decoupled), syncing results to the onboarding Zustand store, and surfacing toast feedback on errors or key milestones.

## Key Components

### `useOnboardingMutations()`

The single exported hook returning eight mutation functions and a loading flag:

| Return Value | Description |
|---|---|
| `completeTenantStep(step, onSettled?)` | Marks a tenant onboarding step complete; tracks pending state; silent on success |
| `completeTenantStepInBackground(step)` | Fire-and-forget tenant step — no spinner, no success toast; used for navigate/open actions |
| `completeTenantInBackground()` | Fire-and-forget full tenant onboarding completion; "Setup Complete" banner is the feedback |
| `completeUserStep(step, onSettled?)` | Marks a user onboarding step complete; tracks pending state; silent on success |
| `completeUserStepInBackground(step)` | Fire-and-forget user step — same rationale as the tenant variant |
| `completeUserInBackground()` | Fire-and-forget full user onboarding completion |
| `skipUser(onDone?)` | Skips the user's Get Started tour entirely |
| `resetUser(onDone?)` | Resets the user's tour; toasts a success confirmation |
| `isMutating` | `true` while any tracked mutation is in-flight |

### Internal helpers

- **`toTenant(payload)`** / **`toUser(payload)`** — Normalise raw GraphQL response payloads into `TenantOnboardingProgress` / `UserOnboardingProgress` store shapes.
- **`begin()` / `finish()`** — Increment/decrement a `pending` counter that drives `isMutating`.
- **`onError(fallback)`** — Returns an error handler that calls `finish()` and shows a destructive toast.

## Usage Example

```typescript
const {
  completeTenantStep,
  completeTenantStepInBackground,
  skipUser,
  isMutating,
} = useOnboardingMutations();

// Tracked step completion — show a spinner while in-flight
<Button disabled={isMutating} onClick={() => completeTenantStep('ADD_CUSTOMER', handleNext)}>
  Save Customer
</Button>

// Navigate action — mark step complete in background, no spinner
<Button onClick={() => { completeTenantStepInBackground('VIEW_DEVICES'); router.push('/devices'); }}>
  Go to Devices
</Button>

// Skip the Get Started tour
<Button variant="ghost" onClick={() => skipUser(handleClose)}>
  Skip tour
</Button>
```

> **Why `commitMutation` instead of `useMutation`?** Components that fire a completion and immediately navigate away would unmount before the request completes, causing `useMutation` to cancel it. `commitMutation` is decoupled from the React lifecycle, so completions always land even after the page changes.
