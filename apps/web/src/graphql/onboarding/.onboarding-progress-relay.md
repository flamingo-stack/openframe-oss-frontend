# onboarding-progress-relay.ts

Relay query module that fetches tenant and user onboarding progress from the backend and synchronizes it into the Zustand onboarding store, ensuring the current session's state is always the source of truth.

## Key Components

- **`onboardingProgressRelayQuery`** — GraphQL query fetching `tenantOnboardingProgress` (completed steps, completion status/date) and `userOnboardingProgress` (completed steps, completion, skip, tour, and setup state).
- **`OnboardingProgress`** — Interface pairing parsed `tenant` and `user` onboarding progress in store-ready shape.
- **`syncOnboardingStore(data)`** — Parses a query/mutation response and writes the resulting progress into the onboarding Zustand store (`useOnboardingStore`). Returns the parsed `OnboardingProgress`.
- **`fetchOnboardingProgress(environment)`** — Async function that performs a network-only Relay fetch of onboarding progress, syncs it into the store, and returns it. Resolves `null` on empty payload or network failure, marking the store as loaded in either case so UI doesn't spin indefinitely.
- **`refreshOnboardingProgress(environment)`** — Fire-and-forget wrapper around `fetchOnboardingProgress`, intended for use on app-shell mount (e.g., by `OnboardingProgressHydrator`).

## Usage Example

```typescript
import { useRelayEnvironment } from 'react-relay';
import { refreshOnboardingProgress, fetchOnboardingProgress } from '@/relay/onboarding-progress-relay';

// Fire-and-forget hydration on app shell mount
function OnboardingProgressHydrator() {
  const environment = useRelayEnvironment();

  useEffect(() => {
    refreshOnboardingProgress(environment);
  }, [environment]);

  return null;
}

// Awaited fetch when explicit progress data is needed (e.g., after tenant switch)
async function handleTenantSwitch(environment: IEnvironment) {
  const progress = await fetchOnboardingProgress(environment);
  if (progress) {
    console.log('Tenant completed:', progress.tenant.completed);
    console.log('User completed steps:', progress.user.completedSteps);
  }
}
```

**Note:** This module always fetches with `network-only` policy, since onboarding state must reflect the currently active session's tenant/user and must never be served from a stale cache after a tenant switch.
