Defines a GraphQL mutation that marks the user's onboarding setup as "seen," used to update onboarding tour state via Relay.

## Key Components

- **`markUserOnboardingSetupSeenMutation`** — A `graphql` tagged template literal exported for use with `react-relay`'s `useMutation` (or `commitMutation`) hooks. It invokes the `markUserOnboardingSetupSeen` server mutation and requests the following fields in response:
  - `completedSteps` — list/count of onboarding steps completed
  - `completed` — boolean flag indicating full onboarding completion
  - `completedAt` — timestamp of completion
  - `skipped` — boolean flag indicating onboarding was skipped
  - `skippedAt` — timestamp of skip action
  - `tourDialogId` — identifier for the associated tour dialog
  - `setupSeen` — boolean flag indicating the setup screen has been seen

## Usage Example

```typescript
import { useMutation } from 'react-relay';
import { markUserOnboardingSetupSeenMutation } from './mark-user-onboarding-setup-seen-mutation';

function OnboardingSetup() {
  const [commit, isInFlight] = useMutation(markUserOnboardingSetupSeenMutation);

  const handleSetupSeen = () => {
    commit({
      variables: {},
      onCompleted: (response) => {
        console.log('Setup seen:', response.markUserOnboardingSetupSeen.setupSeen);
      },
      onError: (error) => {
        console.error('Failed to mark setup as seen:', error);
      },
    });
  };

  return (
    <button onClick={handleSetupSeen} disabled={isInFlight}>
      Dismiss Setup
    </button>
  );
}
```

This mutation is typically triggered once a user dismisses or completes the initial onboarding setup flow, ensuring the UI doesn't re-prompt the tour on subsequent sessions.
