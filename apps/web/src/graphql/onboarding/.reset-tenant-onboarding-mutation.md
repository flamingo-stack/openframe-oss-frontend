Defines a GraphQL mutation for resetting a tenant's onboarding state, intended for development and QA environments only.

## Key Components

- **`resetTenantOnboardingMutation`** — A Relay GraphQL mutation document generated via the `graphql` tagged template literal. It calls the `resetTenantOnboarding` server field and requests the updated `completedSteps`, `completed`, and `completedAt` fields in response.

## Usage Example

```typescript
import { useMutation } from 'react-relay';
import { resetTenantOnboardingMutation } from './reset-tenant-onboarding-mutation';
import type { resetTenantOnboardingMutation as ResetTenantOnboardingMutationType } from './__generated__/resetTenantOnboardingMutation.graphql';

function ResetOnboardingButton() {
  const [commit, isInFlight] = useMutation<ResetTenantOnboardingMutationType>(
    resetTenantOnboardingMutation
  );

  const handleReset = () => {
    commit({
      variables: {},
      onCompleted: (response) => {
        console.log('Onboarding reset:', response.resetTenantOnboarding);
      },
      onError: (error) => {
        console.error('Failed to reset onboarding:', error);
      },
    });
  };

  return (
    <button onClick={handleReset} disabled={isInFlight}>
      Reset Onboarding (Dev/QA only)
    </button>
  );
}
```

## Notes

- The `resetTenantOnboarding` field is only available in the GraphQL schema when the `onboarding-skip` feature flag is enabled on the backend.
- This mutation should **not** be exposed in production UI flows; gate any UI that triggers it behind the same feature flag or an environment check.
- Requires Relay's code generation step to produce the corresponding `__generated__` types before use.
