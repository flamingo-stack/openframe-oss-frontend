Defines a GraphQL query (via `react-relay`'s `graphql` tagged template) used to fetch the signals needed for client-side auto-detection of tenant onboarding step completion. This is a **temporary stopgap** that should be removed once step completion logic is moved to the backend's `tenantOnboardingProgress` field.

## Key Components

- **`tenantOnboardingAutoDetectRelayQuery`** — Relay GraphQL query exporting three onboarding signals in a single round-trip:
  - `tenantInfo` — MSP profile data (`name`, `website`, `image.imageUrl`) used to check profile completeness.
  - `organizations` — First 2 organization edges (`id`, `isDefault`) used to detect whether a non-default (real customer) organization exists, without relying on a count or a schema-level `isDefault` filter.
  - `deviceFilters` — `filteredCount` of devices matching a passed-in `$deviceFilter`, typically scoped to `statuses:[ONLINE,OFFLINE]` to exclude archived/pending devices.

## Usage Example

```typescript
import { useLazyLoadQuery } from 'react-relay';
import { tenantOnboardingAutoDetectRelayQuery } from './tenant-onboarding-auto-detect-relay';

function useOnboardingSignals() {
  const data = useLazyLoadQuery(tenantOnboardingAutoDetectRelayQuery, {
    deviceFilter: { statuses: ['ONLINE', 'OFFLINE'] },
  });

  const hasProfile = Boolean(
    data.tenantInfo?.name && data.tenantInfo?.website && data.tenantInfo?.image?.imageUrl
  );
  const hasCustomer = data.organizations?.edges?.some(
    (edge) => !edge?.node?.isDefault
  );
  const hasDevices = (data.deviceFilters?.filteredCount ?? 0) > 0;

  return { hasProfile, hasCustomer, hasDevices };
}
```

**Note:** This query is consumed primarily by `useTenantOnboardingAutoDetect`. Once backend support for `tenantOnboardingProgress` is complete, this query and its consuming hook should be deprecated and removed.
