Converts the app's loosely-typed, string-based `DeviceFilterInput` (sourced from URL query parameters) into the strict enum-typed `RelayDeviceFilter` shape expected by Relay's generated GraphQL operations.

## Key Components

- **`RelayDeviceFilter`** — Interface describing the enum-typed device filter shape Relay generates from the GraphQL schema, covering statuses, device types, OS types, organization IDs, tags, directory sources, and user links.
- **`knownOrNull`** — Internal helper that returns `null` for an unset (`undefined`) filter field, or filters a provided array down to only recognized enum values (via `knownValues`), preserving an empty array if nothing matches.
- **`toRelayDeviceFilter`** — Main export. Converts a `DeviceFilterInput` (or `undefined`/`null`) into a `RelayDeviceFilter`, or `null` if no filter is given.

## Usage Example

```typescript
import { toRelayDeviceFilter } from './to-relay-device-filter';
import type { DeviceFilterInput } from '@flamingo-stack/openframe-frontend-core/components/features';

const urlFilter: DeviceFilterInput = {
  statuses: ['ONLINE', 'NOT_A_REAL_STATUS'],
  deviceTypes: ['SERVER'],
  organizationIds: ['org-123'],
};

const relayFilter = toRelayDeviceFilter(urlFilter);
// relayFilter.statuses -> ['ONLINE'] (invalid value dropped)
// relayFilter.deviceTypes -> ['SERVER']
// relayFilter.organizationIds -> ['org-123']

const query = useLazyLoadQuery(DeviceListQuery, { filter: relayFilter });
```

## Notes

- This is a real validation boundary, not a type cast: unrecognized enum values from user-controlled query params are silently dropped instead of being sent to the server, where a GraphQL enum coercion error would fail the entire query and blank the device list.
- `directorySources` and `userLinks` are conditionally spread into the result only when present in the input, since the backend's `DeviceFilterInput` rejects unknown keys when the `tenant-management-v2` feature flag is off.
