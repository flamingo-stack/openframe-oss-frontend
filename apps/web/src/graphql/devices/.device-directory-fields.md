# device-directory-fields.ts

Defines a GraphQL Relay fragment supplying the USER and SOURCES columns for the Devices list, sourced from directory-matching data populated by the SaaS matcher (fields remain empty/inert in OSS deployments).

## Key Components

- **`deviceDirectoryFieldsFragment`** — A `@inline` Relay fragment (`deviceDirectoryFields_machine`) defined on the `Machine` type, exposing:
  - `directorySources` — identifies which directory source(s) matched the device
  - `directoryUserLink` — link/reference to the matched directory user
  - `directoryUserIds` — matched directory user identifier(s)
  - `directoryUserName` — display name of the matched directory user

This fragment is intentionally separate from the progressive fragment ladder in `device-fields.ts`. It exists only because these fields belong to the Tenant Management Phase 2 schema (`tenant-management-v2`). Since the pickers already spread `deviceFields_machine` unconditionally through `devicesPageRelayQuery`, only the component rendering these specific columns needs to spread `deviceDirectoryFields_machine`.

## Usage Example

```typescript
import { useFragment } from 'react-relay';
import { deviceDirectoryFieldsFragment } from './device-directory-fields';

function DeviceUserColumn({ machineRef }: { machineRef: any }) {
  const data = useFragment(deviceDirectoryFieldsFragment, machineRef);

  return (
    <div>
      <span>{data.directoryUserName ?? '—'}</span>
      <span>{data.directorySources?.join(', ') ?? 'None'}</span>
    </div>
  );
}
```

Consumers should spread `...deviceDirectoryFields_machine` on the parent `Machine` selection only within components that render the USER/SOURCES columns, since other device list consumers do not require this data.
