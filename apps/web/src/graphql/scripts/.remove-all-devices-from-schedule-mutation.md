## Purpose

Defines a GraphQL mutation (via `react-relay`) that bulk-unassigns devices from a schedule, server-side, based on the current filter/search criteria applied to the device list. When no filter or search is provided, it clears the entire device assignment for the schedule.

## Key Components

- **`removeAllDevicesFromScheduleMutation`** — a `graphql` tagged template exporting the Relay mutation definition.
  - **Variables:**
    - `scheduleId: ID!` — the target schedule.
    - `filter: DeviceFilterInput` — optional filter criteria matching the currently selected device list view.
    - `search: String` — optional search string matching the currently selected device list view.
  - **Response fields:**
    - `id`, `deviceCount` — updated schedule identity and device count.
    - `selectionMode` — always requested, since it's the only server-visible signal indicating whether the schedule's assignment mode changed as a side effect of this mutation.
    - `deviceCriteria { organizationIds, deviceTypes, osTypes }` — current criteria state, kept in sync with the store.

This mutation is resolved entirely server-side because the client only holds pages of devices it has fetched — "remove all" must be computed against the full dataset, not just what's loaded locally.

## Usage Example

```typescript
import { commitMutation, useRelayEnvironment } from 'react-relay';
import { removeAllDevicesFromScheduleMutation } from './remove-all-devices-from-schedule-mutation';

function useRemoveAllDevices() {
  const environment = useRelayEnvironment();

  return (scheduleId: string, filter?: object, search?: string) => {
    commitMutation(environment, {
      mutation: removeAllDevicesFromScheduleMutation,
      variables: { scheduleId, filter, search },
      onCompleted: (response) => {
        console.log('Updated device count:', response.removeAllDevicesFromSchedule?.deviceCount);
      },
      onError: (err) => console.error('Failed to remove devices:', err),
    });
  };
}
```
