# unarchive-script-schedule-mutation.ts

Defines a GraphQL Relay mutation that restores an archived script schedule back to `ACTIVE` status, removing it from the Archived list's connection while keeping the record intact for any mounted details view.

## Key Components

- **`unarchiveScriptScheduleMutation`** — A `graphql` tagged template (via `react-relay`) representing the `unarchiveScriptSchedule` mutation. It accepts:
  - `$id: ID!` — the schedule to restore.
  - `$connections: [ID!]!` — the Relay connection ID(s) to detach the schedule's edge from (typically the Archived list connection).

  The mutation response includes:
  - `id` annotated with `@deleteEdge(connections: $connections)` — removes the edge from the specified connection(s) in the Relay store without deleting the underlying record, so the active Schedules page (refetched via `store-and-network`) can pick it up.
  - `status` — written directly into the record so a details page that stays mounted on the archived schedule can immediately reflect the new status (flipping its action button between Archive/Restore) without needing a refetch.

## Usage Example

```typescript
import { useMutation } from 'react-relay';
import { unarchiveScriptScheduleMutation } from './unarchive-script-schedule-mutation';

function useUnarchiveSchedule() {
  const [commit, isInFlight] = useMutation(unarchiveScriptScheduleMutation);

  const unarchive = (scheduleId: string, archivedListConnectionId: string) => {
    commit({
      variables: {
        id: scheduleId,
        connections: [archivedListConnectionId],
      },
    });
  };

  return { unarchive, isInFlight };
}
```

**Note:** Pair this with `archive-script-mutation.ts` for the inverse operation, and ensure the Archived list's connection ID is captured via `ConnectionHandler.getConnectionID` so `@deleteEdge` targets the correct connection.
