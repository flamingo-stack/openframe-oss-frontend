# remove-devices-from-schedule-mutation.ts

Defines a GraphQL Relay mutation for unassigning one or more devices from a schedule. Removing an id that isn't currently assigned is a safe no-op.

## Key Components

- **`removeDevicesFromScheduleMutation`** — A `graphql` tagged template exporting the `removeDevicesFromSchedule` mutation. It accepts:
  - `scheduleId: ID!` — the target schedule.
  - `machineIds: [ID!]!` — the device ids to unassign.
  
  The response selects `id`, `selectionMode`, and `deviceCriteria` (`organizationIds`, `deviceTypes`, `osTypes`) so the Relay store is updated with the server's authoritative selection mode after the mutation, preventing the UI from retaining a stale `CRITERIA` mode after a device-level edit.

## Usage Example

```typescript
import { useMutation } from 'react-relay';
import { removeDevicesFromScheduleMutation } from './remove-devices-from-schedule-mutation';

function useRemoveDevicesFromSchedule() {
  const [commit, isInFlight] = useMutation(removeDevicesFromScheduleMutation);

  const removeDevices = (scheduleId: string, machineIds: string[]) => {
    commit({
      variables: { scheduleId, machineIds },
      onCompleted: (response) => {
        console.log('Updated selection mode:', response.removeDevicesFromSchedule?.selectionMode);
      },
      onError: (error) => {
        console.error('Failed to remove devices:', error);
      },
    });
  };

  return { removeDevices, isInFlight };
}
```

## Notes

This mutation's companion, `add-devices-to-schedule-mutation.ts`, documents the reasoning behind fetching `selectionMode` and `deviceCriteria` on every assignment write — refer to it for details on why the delta between device and criteria-based scheduling matters.
