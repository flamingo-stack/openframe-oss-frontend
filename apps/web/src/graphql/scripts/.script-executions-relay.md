# script-executions-relay.ts

Defines Relay GraphQL query and fragment definitions for fetching a single script's execution history, using cursor-based pagination via OpenFrame's native GraphQL API. This is the v2 implementation that replaces legacy REST-based execution history fetching with a Relay connection pattern.

## Key Components

- **`scriptExecutionsRelayQuery`** — The root query operation. Accepts `scriptId`, `filter` (`ScriptExecutionFilterInput`), `search`, `sort`, and pagination args (`first`/`after`). Fetches both the paginated execution list (via the spread fragment) and `scriptExecutionFilters` (filter facet options) in a single round-trip, so filter dropdowns and row data stay in sync.
- **`scriptExecutionsRelayFragment`** — A `@refetchable` fragment (`scriptExecutionsRelayPaginationQuery`) that wraps the `scriptExecutions` connection. Annotated with `@connection(key: "scriptExecutionsRelay_scriptExecutions")` to enable Relay's `usePaginationFragment`/`loadNext` for infinite scroll. Each edge spreads `executionFields_execution` (shared row fields defined elsewhere) — no script name field, since this view is scoped to one script.

## Usage Example

```typescript
import { useLazyLoadQuery, usePaginationFragment } from 'react-relay';
import { scriptExecutionsRelayQuery, scriptExecutionsRelayFragment } from './script-executions-relay';

function ScriptExecutionHistory({ scriptId }: { scriptId: string }) {
  const data = useLazyLoadQuery(scriptExecutionsRelayQuery, {
    scriptId,
    filter: { statuses: ['SUCCESS', 'FAILED'] },
    search: '',
    sort: { field: 'dispatchedAt', direction: 'DESC' },
    first: 20,
    after: null,
  });

  const { data: paginated, loadNext, hasNext } = usePaginationFragment(
    scriptExecutionsRelayFragment,
    data
  );

  return (
    <>
      {paginated.scriptExecutions.edges.map(({ node }) => (
        <ExecutionRow key={node.id} execution={node} />
      ))}
      {hasNext && <button onClick={() => loadNext(20)}>Load more</button>}
    </>
  );
}
```

**Notes:**
- Filter facets (`scriptExecutionFilters`) live on the outer query, not the paginated fragment, so `loadNext` won't re-trigger facet refetching.
- Date-range filters (`dispatchedAtFrom`/`dispatchedAtTo`) share the same `filter` object as other facets but are independent of `sort`, which only affects ordering, not row matching.
