Defines Relay GraphQL query and fragment for the "Run Script on device" modal's script picker, supporting paginated, filterable script selection.

## Key Components

- **`scriptsRunPickerRelayQuery`** — Root query that spreads the picker fragment, accepting `search`, `tagIds`, and `first` as variables for server-side filtering and initial page size.
- **`scriptsRunPickerRelayFragment`** — Refetchable fragment on `Query` with `@connection` for infinite scroll pagination. Filters to `ACTIVE` scripts only; changing `search` or `tagIds` starts a fresh connection while `loadNext` continues paging within the current filter.

### Fragment Fields Per Script Node

| Field | Description |
|---|---|
| `id` | Unique script identifier |
| `name` | Display name |
| `description` | Short description shown in picker |
| `supportedPlatforms` | Platforms the script can run on |

## Usage Example

```typescript
import { usePreloadedQuery, useFragment } from 'react-relay';
import {
  scriptsRunPickerRelayQuery,
  scriptsRunPickerRelayFragment,
} from './scripts-run-picker-relay';

// Preload at the modal open boundary
const queryRef = loadQuery(RelayEnvironment, scriptsRunPickerRelayQuery, {
  search: '',
  tagIds: [],
  first: 20,
});

// Inside the picker component
const queryData = usePreloadedQuery(scriptsRunPickerRelayQuery, queryRef);
const { data, loadNext, hasNext } = usePaginationFragment(
  scriptsRunPickerRelayFragment,
  queryData,
);

const scripts = data.scripts.edges.map((e) => e.node);
```

Refetch with new filters (e.g., tag change) by calling `refetch({ search, tagIds, first: 20 })`, which resets the connection to page 1.

## Notes

- The `@connection(key: "scriptsRunPickerRelay_scripts")` key is used by the Relay store for cache normalisation and optimistic updates.
- `after` cursor is managed internally by Relay's pagination runtime; do not pass it manually.
