# add-all-devices-to-schedule-mutation.ts

GraphQL Relay mutation that assigns **all devices matching a filter/search** to a schedule, with the filtering logic resolved server-side rather than client-side.

## Key Components

- **`addAllDevicesToScheduleMutation`** — Relay `graphql` tagged mutation that:
  - Takes `scheduleId`, an optional `filter` (`DeviceFilterInput`), and an optional `search` string
  - Delegates matching logic to the server via `addAllDevicesToSchedule`, since the client may only have a partial (paged) view of the candidate device list
  - Returns the updated schedule's `id`, `deviceCount`, `selectionMode`, and `deviceCriteria` (`organizationIds`, `deviceTypes`, `osTypes`)

The `selectionMode` field is always requested because assigning devices is the only documented way the mode can change server-side (for `CRITERIA`-based schedules), so the response must be read back into the store to avoid the UI holding a stale mode.

## Usage Example

```typescript
import { useMutation } from 'react-relay';
import { addAllDevicesToScheduleMutation } from './add-all-devices-to-schedule-mutation';

function useAddAllDevices() {
  const [commit, isInFlight] = useMutation(addAllDevicesToScheduleMutation);

  const addAll = (scheduleId: string, filter?: object, search?: string) => {
    commit({
      variables: { scheduleId, filter, search },
      onCompleted: (response) => {
        console.log('Updated device count:', response.addAllDevicesToSchedule.deviceCount);
      },
      onError: (error) => {
        console.error('Failed to add all devices:', error);
      },
    });
  };

  return { addAll, isInFlight };
}
```

**Important:** Always pass the exact same `filter` and `search` values currently displayed in the Available Devices list. Assembling a device ID set client-side defeats the purpose of this mutation, since it would silently exclude devices not yet paged into view.
