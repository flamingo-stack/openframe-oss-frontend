# schedule-trigger-relay.ts

Defines a minimal, cache-friendly GraphQL query that fetches only a script schedule's `trigger` field, used to determine which tabs render on the schedule details page before the full schedule data loads.

## Key Components

- **`scheduleTriggerRelayQuery`** — A Relay `graphql` query tagged template that fetches a `scriptSchedule` by `id`, returning only `id` and `trigger`. It is intentionally separate from the fuller `scriptScheduleDetailRelayQuery` (which also resolves every script's `scriptBody`) so that the tab strip can render immediately without waiting on the heavier query.

## Design Notes

- Because `trigger` is already selected by the schedules table (the list view), Relay can typically resolve this query from its local store on first render when navigating from that list — avoiding a Suspense fallback.
- The query uses a `store-and-network` fetch policy (applied at the call site) so the cached value paints instantly while a background request revalidates it.
- The `trigger` value determines tab visibility — e.g., `DEVICE_ONLINE` triggers have no "Schedule Runs" tab (see `schedule-detail-tabs.ts` for the tab-resolution logic).

## Usage Example

```typescript
import { useLazyLoadQuery } from 'react-relay';
import { scheduleTriggerRelayQuery } from './schedule-trigger-relay';
import type { scheduleTriggerRelayQuery as ScheduleTriggerRelayQueryType } from './__generated__/scheduleTriggerRelayQuery.graphql';

function ScheduleTabsStrip({ scheduleId }: { scheduleId: string }) {
  const data = useLazyLoadQuery<ScheduleTriggerRelayQueryType>(
    scheduleTriggerRelayQuery,
    { id: scheduleId },
    { fetchPolicy: 'store-and-network' }
  );

  const trigger = data.scriptSchedule?.trigger;

  // Use `trigger` to decide which tabs to render
  // e.g., skip "Schedule Runs" tab when trigger === 'DEVICE_ONLINE'
  return (
    <TabsStrip trigger={trigger} />
  );
}
```
