## add-devices-to-schedule-mutation.ts

A Relay GraphQL mutation that adds one or more devices to a script schedule's assignment via an idempotent, delta-based operation rather than overwriting the full device set.

This mutation is part of a set of four schedule-assignment mutations that replace the older `setScriptScheduleDevices` approach, which required transmitting the entire machine set on every update. By sending only the devices being added, the client avoids needing to hold (or risk dropping) the full assignment in memory — a requirement that doesn't scale once an assignment grows beyond a single page.

Notably, this mutation's response intentionally omits `deviceCount`. Because each response represents an absolute snapshot, concurrent in-flight mutations could race and leave a stale count in the store. Instead, `deviceCount` is tracked client-side as a composable delta (see `assignmentUpdaters` in the shared device selector), while `selectionMode` — a server-owned state rather than a running total — is safely read directly from the mutation response.

## Key Components

- **`addDevicesToScheduleMutation`** — Relay `graphql` tagged mutation accepting `scheduleId: ID!` and `machineIds: [ID!]!`, returning the schedule's `id`, `selectionMode`, and `deviceCriteria` (`organizationIds`, `deviceTypes`, `osTypes`).

## Usage Example

```typescript
import { useMutation } from 'react-relay';
import { addDevicesToScheduleMutation } from './add-devices-to-schedule-mutation';

function useAddDevicesToSchedule() {
  const [commit, isInFlight] = useMutation(addDevicesToScheduleMutation);

  const addDevices = (scheduleId: string, machineIds: string[]) => {
    commit({
      variables: { scheduleId, machineIds },
      onCompleted: (response) => {
        console.log('Updated selection mode:', response.addDevicesToSchedule.selectionMode);
      },
      onError: (error) => {
        console.error('Failed to add devices:', error);
      },
    });
  };

  return { addDevices, isInFlight };
}
```

**Note:** Pair this mutation with the optimistic updater logic in `assignmentUpdaters` (shared device selector) to keep the picker's `deviceCount` accurate across concurrent operations, since the mutation response itself does not return a count.
