## script-schedule-detail-relay.ts

Defines a GraphQL Relay query that fetches a single script schedule's full configuration, including its ordered list of scripts and per-script overrides, for the schedule detail and edit pages. It deliberately excludes assigned device resolution, which is handled by a separate, lighter-weight query to avoid timeouts on large fleets.

## Key Components

- **`scriptScheduleDetailRelayQuery`** — Relay `graphql` tagged query that takes a schedule `id` and returns:
  - Core schedule metadata: `name`, `description`, `supportedPlatforms`, `status`, `author`, `deviceCount`
  - Targeting configuration: `selectionMode` (`SPECIFIC` vs `CRITERIA`) and `deviceCriteria`
  - Scheduling behavior: `trigger`, `offlineBehavior`, `reconnectWindowSeconds`, `timeReference`, `startAt`, `repeat`, `nextRunAt`, `lastRunAt`
  - Ordered `scripts[]` array with full script bodies and env vars
  - `scriptCustomParams[]` — sparse per-script overrides keyed by `scriptId`

## Usage Example

```typescript
import { useLazyLoadQuery } from 'react-relay';
import { scriptScheduleDetailRelayQuery } from './script-schedule-detail-relay';
import type { scriptScheduleDetailRelayQuery as ScheduleDetailQueryType } from './__generated__/scriptScheduleDetailRelayQuery.graphql';

function ScheduleDetailPage({ scheduleId }: { scheduleId: string }) {
  const data = useLazyLoadQuery<ScheduleDetailQueryType>(
    scriptScheduleDetailRelayQuery,
    { id: scheduleId }
  );

  const { scriptSchedule } = data;

  return (
    <div>
      <h1>{scriptSchedule.name}</h1>
      <p>Status: {scriptSchedule.status}</p>
      <ul>
        {scriptSchedule.scripts.map((script) => (
          <li key={script.id}>{script.name}</li>
        ))}
      </ul>
    </div>
  );
}
```

**Note:** For views that render assigned devices, pair this query with `script-schedule-devices-relay.ts`. For the "Edit Devices" page specifically, use `script-schedule-devices-settings-relay.ts` instead, since it avoids loading script bodies entirely.
