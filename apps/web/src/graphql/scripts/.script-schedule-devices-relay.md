## script-schedule-devices-relay.ts

Defines the Relay GraphQL query and paginated fragment used to lazily load the machines assigned to a script schedule, split out from the main schedule query to avoid timeouts caused by the per-machine `organization` field resolution.

## Key Components

- **`scriptScheduleDevicesRelayQuery`** — Root query that fetches a `ScriptSchedule` by `id` along with its `deviceCount`, spreading the paginated devices fragment. Mounted only by consumers that actually need the device list (e.g., Assigned Devices tab, Edit Devices page).
- **`scriptScheduleDevicesRelayFragment`** — `@refetchable` fragment (`scriptScheduleDevicesRelay_schedule`) exposing the `assignedDevices` connection with `filter`, `search`, and pagination (`first`/`after`) arguments. Declares a `@connection` keyed as `scriptScheduleDevicesRelay_assignedDevices`, with `filter`/`search` as connection-identity filters so each filtered view is stored separately rather than merged into the unfiltered page.
- Each device node spreads `deviceRowFields_machine` — the narrowest fragment in the device field ladder, providing only table-row data (including the costly per-machine `organization`/CUSTOMER column).

## Usage Example

```typescript
import { useLazyLoadQuery, usePaginationFragment } from 'react-relay';
import {
  scriptScheduleDevicesRelayQuery,
  scriptScheduleDevicesRelayFragment,
} from './script-schedule-devices-relay';

function AssignedDevicesTab({ scheduleId }: { scheduleId: string }) {
  const data = useLazyLoadQuery(scriptScheduleDevicesRelayQuery, {
    id: scheduleId,
    first: 20,
    after: null,
    filter: null,
    search: null,
  });

  const { data: paginated, loadNext, hasNext } = usePaginationFragment(
    scriptScheduleDevicesRelayFragment,
    data.scriptSchedule
  );

  return (
    <DevicesTableBody
      edges={paginated.assignedDevices.edges}
      deviceCount={data.scriptSchedule?.deviceCount}
      onLoadMore={() => hasNext && loadNext(20)}
    />
  );
}
```

**Note:** Only mount this query where the device list is actually rendered — including it elsewhere reintroduces the per-machine `organization` fan-out cost this split was designed to avoid.
