Relay GraphQL query and pagination fragment for the Script Schedules list view, implementing cursor-based pagination with server-side search and platform filtering.

## Key Components

### `scriptSchedulesTableRelayQuery`
Root query that composes the paginated fragment with `scriptScheduleFilters`. Accepts:
- `$filter` — `ScriptScheduleFilterInput` for platform-based filtering
- `$search` — server-side text search string
- `$first` / `$after` — cursor pagination arguments

Fetches `scriptScheduleFilters.platforms` (value, label, count) at the root level so filter facets are **not** refetched during `loadNext` pagination calls.

### `scriptSchedulesTableRelayFragment`
`@refetchable` fragment on `Query` driving infinite scroll via the `@connection` directive. Returns per-node fields:
- `id`, `name`, `description`, `supportedPlatforms`, `deviceCount`

Also exposes `filteredCount`, `pageInfo.hasNextPage`, and `pageInfo.endCursor` for pagination state. The connection key `scriptSchedulesTableRelay_scriptSchedules` is used by Relay's store for cache management.

## Usage Example

```typescript
import { useLazyLoadQuery, usePaginationFragment } from 'react-relay';
import {
  scriptSchedulesTableRelayQuery,
  scriptSchedulesTableRelayFragment,
} from './script-schedules-table-relay';

// Load root query
const queryData = useLazyLoadQuery(scriptSchedulesTableRelayQuery, {
  first: 20,
  filter: { platforms: ['windows'] },
  search: 'backup',
});

// Drive pagination from the refetchable fragment
const { data, loadNext, hasNext } = usePaginationFragment(
  scriptSchedulesTableRelayFragment,
  queryData,
);

const schedules = data.scriptSchedules.edges.map(({ node }) => node);
const platforms = queryData.scriptScheduleFilters.platforms;
```

## Notes

- Filter facets (`scriptScheduleFilters`) are intentionally placed on the outer query — not inside the `@refetchable` fragment — ensuring they update atomically on filter changes but remain stable during pagination.
- `authors` facet is defined in the schema but intentionally omitted; the schedules table has no author column.
