# archive-script-mutation.ts

Defines a GraphQL Relay mutation that archives a script by updating its status while surgically removing it from active-list UI connections without deleting the underlying record from the Relay store.

## Key Components

- **`archiveScriptMutation`** — A `graphql` tagged mutation that:
  - Accepts an `id` (`ID!`) identifying the script to archive and `connections` (`[ID!]!`) identifying the Relay connection(s) to update.
  - Uses `@deleteEdge(connections: $connections)` on the returned `id` field to remove the script's edge from the active list's connection(s) **without** deleting the `Script` record itself.
  - Returns `status` so that any mounted detail/sidebar view referencing the same record gets its status updated in place (no refetch needed).

This mutation intentionally avoids `@deleteRecord` because fully deleting the record causes two issues: a dangling null-node edge remains, and any subsequent `script(id:)` query would re-create the record in the store — causing the archived item to reappear in the active list.

## Usage Example

```typescript
import { useMutation } from 'react-relay';
import { archiveScriptMutation } from './archive-script-mutation';
import type { ArchiveScriptMutation } from './__generated__/archiveScriptMutation.graphql';

function useArchiveScript(connectionId: string) {
  const [commit, isInFlight] = useMutation<ArchiveScriptMutation>(archiveScriptMutation);

  const archiveScript = (scriptId: string) => {
    commit({
      variables: {
        id: scriptId,
        connections: [connectionId],
      },
    });
  };

  return { archiveScript, isInFlight };
}
```

**Notes:**
- Pass the connection ID(s) from the active scripts list query (typically obtained via `ConnectionHandler.getConnectionID`).
- The Archived page should use a `store-and-network` fetch policy on navigation to display newly archived scripts, since they are not optimistically added to that list's connection by this mutation.
