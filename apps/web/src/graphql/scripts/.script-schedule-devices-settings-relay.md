## script-schedule-devices-settings-relay.ts

Defines the GraphQL query powering the "Edit Devices" page for a script schedule, fetching only the fields needed to render the device-targeting UI and to safely resubmit a full update via `updateScriptSchedule`.

## Key Components

- **`scriptScheduleDevicesSettingsRelayQuery`** — a Relay `graphql` tagged query that fetches a `scriptSchedule` by `id`, including:
  - Core display fields: `name`, `description`, `supportedPlatforms`, `trigger`, `startAt`, `repeat`, `timeReference`
  - Offline handling: `offlineBehavior`, `reconnectWindowSeconds` (required to avoid silently downgrading retry behavior on save)
  - Targeting data: `selectionMode` (the field that determines whether the SPECIFIC or CRITERIA picker renders) and `deviceCriteria`
  - PUT-payload-only fields (not rendered, but required to prevent data loss on update): `scripts { id }`, `scriptCustomParams`

This query is deliberately split from `scriptScheduleDetailRelayQuery` to avoid blocking on the heavier `scripts { scriptBody envVars }` resolution, since `selectionMode` is the one value this page needs before it can draw anything.

## Usage Example

```typescript
import { useLazyLoadQuery } from 'react-relay';
import { scriptScheduleDevicesSettingsRelayQuery } from './script-schedule-devices-settings-relay';

function EditDevicesPage({ scheduleId }: { scheduleId: string }) {
  const data = useLazyLoadQuery(
    scriptScheduleDevicesSettingsRelayQuery,
    { id: scheduleId },
    { fetchPolicy: 'store-and-network' }
  );

  const schedule = data.scriptSchedule;

  return schedule.selectionMode === 'SPECIFIC'
    ? <SpecificDevicesPicker scheduleId={schedule.id} />
    : <CriteriaPicker criteria={schedule.deviceCriteria} />;
}
```

**Note:** Because Relay normalizes by node ID, navigating from the schedule details page means this data is typically already in the store, allowing the page to render on first paint while `store-and-network` triggers a background revalidation.
