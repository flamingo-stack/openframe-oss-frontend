# schedule-device-picker-relay.ts

Defines the Relay GraphQL queries and fragments powering the device picker for script schedules, providing paginated, server-filtered "Available Devices" and "Selected Devices" lists scoped to a specific schedule.

## Key Components

- **`SCHEDULE_PICKER_CONNECTION_KEYS`** — `AssignmentOwner['keys']` object mapping the `available` and `assigned` connection keys used by the shared assignment-updaters to target the picker's two lists in the Relay store.
- **`scheduleDevicePickerRelayQuery`** — Root query fetching a `scriptSchedule` by `$scheduleId` and spreading the available-devices fragment, filtered by platform compatibility, search, and pagination args.
- **`scheduleDevicePickerRelayFragment`** — Refetchable fragment (`scheduleDevicePickerRelay_available`) exposing `availableDevices` as a `@connection`. Each edge carries an `assigned` boolean (pre-check state) plus `id`/`machineId` and spreads `deviceSelectorFields_machine` for row rendering.
- **`scheduleDevicePickerRelayAssignedQuery`** — Root query fetching the schedule's `deviceCount` (total assignment size) alongside the assigned-devices fragment.
- **`scheduleDevicePickerRelayAssignedFragment`** — Refetchable fragment (`scheduleDevicePickerRelay_schedule`) exposing `assignedDevices` as a separate `@connection`, independently searchable/filterable from the read-only devices tab.

## Usage Example

```typescript
import {
  scheduleDevicePickerRelayQuery,
  scheduleDevicePickerRelayAssignedQuery,
  SCHEDULE_PICKER_CONNECTION_KEYS,
} from '@/app/components/.../schedule-device-picker-relay';
import { useLazyLoadQuery } from 'react-relay';

function ScheduleDevicePicker({ scheduleId, filter, search }: Props) {
  const availableData = useLazyLoadQuery(scheduleDevicePickerRelayQuery, {
    scheduleId,
    filter,
    search,
    first: 20,
  });

  const assignedData = useLazyLoadQuery(scheduleDevicePickerRelayAssignedQuery, {
    scheduleId,
    filter,
    search,
    first: 20,
  });

  // Pass SCHEDULE_PICKER_CONNECTION_KEYS to assignmentUpdaters so
  // add/remove mutations patch the correct connection in the store.
}
```

Both fragments spread `deviceSelectorFields_machine` for consistent row data, and `filteredCount` on each connection reflects the current search/filter narrowing, while `deviceCount` on the schedule itself represents the unfiltered total assignment size.
