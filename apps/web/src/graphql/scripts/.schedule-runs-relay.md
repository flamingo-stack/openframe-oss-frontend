Defines the GraphQL query and paginated fragment for fetching **schedule run** data — one row per schedule *fire* (a dispatch to its assigned devices), serving as the aggregate view above the per-device execution history.

## Key Components

- **`scheduleRunsRelayQuery`** — Root GraphQL query that fetches `scheduleRunFilters` (status facet counts for the status funnel) alongside the paginated `scheduleRunsRelay_query` fragment, both scoped by the same `filter`/`search` arguments in a single round-trip.
- **`scheduleRunsRelayFragment`** — Refetchable, paginated fragment (`@refetchable` → `scheduleRunsRelayPaginationQuery`) exposing the `scheduleRuns` connection. Each node includes `id`, `executionId` (links to the Execution History tab's search), `status`, `totalMachineCount`/`respondedMachineCount` (drives progress ratio), `dispatchedAt`, and `initiator` details.

## Usage Example

```typescript
import { useLazyLoadQuery, usePaginationFragment } from 'react-relay';
import { scheduleRunsRelayQuery, scheduleRunsRelayFragment } from './schedule-runs-relay';

function ScheduleRunsList({ scheduleId }: { scheduleId: string }) {
  const data = useLazyLoadQuery(scheduleRunsRelayQuery, {
    scheduleId,
    filter: { statuses: ['COMPLETED'] },
    search: '',
    sort: { field: 'dispatchedAt', direction: 'DESC' },
    first: 20,
    after: null,
  });

  const { data: paginationData, loadNext, hasNext } = usePaginationFragment(
    scheduleRunsRelayFragment,
    data
  );

  const runs = paginationData.scheduleRuns.edges.map((edge) => edge.node);

  return (
    <div>
      {runs.map((run) => (
        <div key={run.id}>
          <span>{run.status}</span>
          <span>{run.respondedMachineCount}/{run.totalMachineCount}</span>
          <span>{run.dispatchedAt}</span>
        </div>
      ))}
      {hasNext && <button onClick={() => loadNext(20)}>Load more</button>}
    </div>
  );
}
```

## Notes

- Only `statuses` is wired to a filter funnel — `initiators` is returned but unused since `ScheduleRunFilterInput` has no corresponding field.
- `sort` and `dispatchedAtFrom`/`dispatchedAtTo` filter on `dispatchedAt`, mirroring the Execution History column's date-range behavior.
