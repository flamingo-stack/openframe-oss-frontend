# scripts-table-relay.ts

Defines Relay GraphQL query and fragment definitions for the Scripts list view, implementing cursor-based pagination against the native OpenFrame GraphQL API (v2).

This module powers the scripts table's data-fetching layer, combining paginated script rows with filter facet metadata in a single query operation to keep the UI's filter dropdowns and results in sync.

## Key Components

- **`scriptsTableRelayQuery`** — The root GraphQL query. Accepts `filter` (`ScriptFilterInput`), `search`, `first`, and `after` variables. Spreads the paginated fragment and also fetches `scriptFilters` (shells, platforms, authors facets with `value`/`label`/`count`) on the same round-trip, so filter options update atomically with search results.
- **`scriptsTableRelayFragment`** — A `@refetchable` fragment (`scriptsTableRelayPaginationQuery`) on `Query`, declaring the `scripts(...)` connection with `@connection(key: "scriptsTableRelay_scripts")`. Drives infinite scroll via `pageInfo.hasNextPage`/`endCursor` and exposes `filteredCount`, plus per-script fields (`name`, `description`, `shell`, `supportedPlatforms`, `defaultTimeoutSeconds`, `author`).

## Usage Example

```typescript
import { usePaginationFragment, useLazyLoadQuery } from 'react-relay';
import { scriptsTableRelayQuery, scriptsTableRelayFragment } from './scripts-table-relay';

function ScriptsTable({ filter, search }: { filter?: ScriptFilterInput; search?: string }) {
  const queryData = useLazyLoadQuery(scriptsTableRelayQuery, {
    filter,
    search,
    first: 20,
  });

  const { data, loadNext, hasNext } = usePaginationFragment(
    scriptsTableRelayFragment,
    queryData,
  );

  return (
    <div>
      {data.scripts.edges.map(({ node }) => (
        <div key={node.id}>{node.name}</div>
      ))}
      {hasNext && <button onClick={() => loadNext(20)}>Load more</button>}
    </div>
  );
}
```

## Notes

- `scriptFilters` lives on the outer query (not the `@refetchable` fragment), so pagination via `loadNext` never triggers a redundant refetch of filter facets.
- The backend excludes each facet's own group when computing counts, so selecting options within a facet (e.g., multiple shells) won't cause its own sibling options to disappear.
- Filter option `value` fields must match `ScriptFilterInput` enum/id types (`shells`/`platforms` are enums, `authors` is a user id).
