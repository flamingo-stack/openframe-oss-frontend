## Purpose

Defines a shared Relay `@inline` GraphQL fragment (`executionFields_execution`) that selects the common set of fields required to render a row in any Execution History list (per-script tab, per-schedule tab, and Schedule Run Details page).

## Key Components

- **`executionFieldsFragment`** — the exported GraphQL fragment literal, tagged with `@inline` so its data can be read outside of a React component via Relay's `readInlineData`.
- **Selected fields** — `id`, `executionId`, `status`, `dispatchedAt`, `source` (trigger origin: manual/scheduled/AI-assisted), `stdout`, `stderr`, `error`, nested `machine` (with `organization`), and nested `initiator` (with `image`).
- **Deliberate omission** — `scriptName` is intentionally excluded since only schedule-related views need it; those consumers select it alongside the fragment spread.

This fragment exists to guarantee structural consistency: every consumer feeding the shared `toUiExecution` mapper and execution table selects identical fields, rather than relying on convention across three separate GraphQL documents.

## Usage Example

```typescript
import { graphql, readInlineData } from 'react-relay';
import { executionFieldsFragment } from './execution-fields';

// Parent query/fragment spreads it alongside anything view-specific
const scheduleExecutionsQuery = graphql`
  query ScheduleExecutionsQuery($scheduleId: ID!) {
    schedule(id: $scheduleId) {
      executions {
        scriptName
        ...executionFields_execution
      }
    }
  }
`;

// A plain mapper function (not a component) reads the inline data
function toUiExecution(executionRef: any) {
  const data = readInlineData(executionFieldsFragment, executionRef);

  return {
    id: data.id,
    status: data.status,
    dispatchedAt: data.dispatchedAt,
    source: data.source,
    machineName: data.machine?.displayName,
    initiatorEmail: data.initiator?.email,
  };
}
```
