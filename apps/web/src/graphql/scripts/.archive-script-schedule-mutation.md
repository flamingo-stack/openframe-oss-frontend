# archive-script-schedule-mutation.ts

Defines a Relay GraphQL mutation that archives a script schedule by updating its status to `ARCHIVED`, while surgically managing cache consistency between list and detail views.

## Key Components

- **`archiveScriptScheduleMutation`** — A `graphql` tagged template exporting the `archiveScriptSchedule` mutation. It:
  - Accepts an `id` (the schedule to archive) and `connections` (the Relay connection IDs representing active-schedule lists).
  - Uses `@deleteEdge(connections: $connections)` on the returned `id` field to remove the schedule's edge from the specified list connections immediately, without deleting the underlying `ScriptSchedule` record from the Relay store.
  - Also requests `status` in the response so that if the schedule's details page is currently mounted, the new status is written directly into the record — letting the UI toggle its action button (Archive ↔ Restore) without needing a refetch.

## Usage Example

```typescript
import { useMutation } from 'react-relay';
import { archiveScriptScheduleMutation } from './archive-script-schedule-mutation';

function useArchiveSchedule() {
  const [commit, isInFlight] = useMutation(archiveScriptScheduleMutation);

  const archiveSchedule = (scheduleId: string, connectionIds: string[]) => {
    commit({
      variables: { id: scheduleId, connections: connectionIds },
      onCompleted: () => {
        console.log('Schedule archived');
      },
      onError: (err) => {
        console.error('Failed to archive schedule', err);
      },
    });
  };

  return { archiveSchedule, isInFlight };
}
```

**Note:** Because the record is preserved (not deleted) via `@deleteEdge` rather than `@deleteRecord`, a subsequent fetch of `scriptSchedule(id:)` on the details page will correctly return the archived record instead of resurrecting a stale entry in the active list. See `archive-script-mutation.ts` for the detailed rationale behind this pattern.
