# create-script-schedule-mutation.ts

Defines a GraphQL mutation that creates a new script schedule via Relay, selecting a response shape rich enough to immediately populate the schedule detail page's cache without an extra network round-trip.

## Key Components

- **`createScriptScheduleMutation`** — A `graphql` tagged mutation document accepting a `CreateScriptScheduleInput!` and returning the full `ScriptSchedule` object, including:
  - Core metadata: `id`, `name`, `description`, `supportedPlatforms`, `status`, `deviceCount`
  - Scheduling fields: `trigger`, `startAt`, `repeat`, `nextRunAt`, `lastRunAt`
  - Offline handling: `offlineBehavior` (defaults to `SKIP` for legacy records) and `reconnectWindowSeconds` (the deadline before a queued run is abandoned; `null` when `offlineBehavior` is `SKIP`)
  - Time semantics: `timeReference` (`SERVER` vs `DEVICE_LOCAL`, defaults to `SERVER` for legacy records) used to determine whether `startAt` needs timezone conversion for display
  - Associated `scripts` (with shell, platforms, timeout, default args, and env vars)
  - `scriptCustomParams` (per-script argument/env var overrides)

## Usage Example

```typescript
import { useMutation } from 'react-relay';
import { createScriptScheduleMutation } from './create-script-schedule-mutation';

function useCreateSchedule() {
  const [commit, isInFlight] = useMutation(createScriptScheduleMutation);

  const createSchedule = (input: CreateScriptScheduleInput) => {
    commit({
      variables: { input },
      onCompleted: (response) => {
        const schedule = response.createScriptSchedule;
        // Navigate to the detail page; the store is already warm
        navigate(`/schedules/${schedule.id}`);
      },
    });
  };

  return { createSchedule, isInFlight };
}
```

This mutation is designed so the create flow can redirect to the new schedule's detail route and have its `store-and-network` query render instantly from the mutation's cached payload.
