## user-summary-fields.ts

Provides a shared Relay inline fragment and reader for rendering a `User` consistently across the UI — tables, pickers, chips, and assignee displays — ensuring every surface agrees on name fallback logic and deleted-account handling.

## Key Components

- **`userSummaryFieldsFragment`** — A GraphQL `@inline` fragment on `User` selecting `id`, `firstName`, `lastName`, `email`, `status`, and `image` fields. Using `@inline` allows the fragment to be read synchronously from any parent query that spreads it.
- **`UserSummary`** — Interface describing the normalized shape consumed by UI components:
  - `rawId`: unwrapped global ID for use with ticket/worktime/auth APIs.
  - `name`: full name, falling back to email if both name parts are empty.
  - `email`: `null` when the account is self-deleted (since the stored email is a placeholder).
  - `avatarUrl`: resolved full image URL, if available.
  - `deleted` / `selfDeleted`: flags derived from the user's `status`.
- **`toUserSummary(ref)`** — Reads the inline fragment data from a `userSummaryFields_user$key` and transforms it into a `UserSummary`, centralizing the name-fallback and deleted-status logic so no caller needs to reimplement it.

## Usage Example

```typescript
import { graphql, useFragment } from 'react-relay';
import { userSummaryFieldsFragment, toUserSummary } from './user-summary-fields';

function AssigneeChip({ userRef }: { userRef: any }) {
  const summary = toUserSummary(userRef);

  if (summary.deleted) {
    return <span className="chip chip--deleted">{summary.name} (deleted)</span>;
  }

  return (
    <span className="chip">
      {summary.avatarUrl && <img src={summary.avatarUrl} alt={summary.name} />}
      {summary.name}
      {summary.email && <small>{summary.email}</small>}
    </span>
  );
}
```

Spread `userSummaryFieldsFragment` into any parent fragment/query that fetches a `User`, then pass the resulting data key to `toUserSummary` wherever that user needs to be rendered.
