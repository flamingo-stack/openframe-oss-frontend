# proxy.ts

Edge middleware that gates access to routes based on the application's deployment mode (`oss-tenant`, `saas-tenant`, or `saas-shared`), redirecting disallowed requests while preserving query strings for attribution tracking.

## Key Components

- **`getMode()`** — Reads `NEXT_PUBLIC_APP_MODE` from the environment and falls back to `'oss-tenant'` if unset.
- **`isAllowed(pathname)`** — Determines whether a given pathname is reachable in the current app mode. Always allows static/internal assets (`/_next`, `/static`, `/favicon`, `/assets`, `/icons`, `/robots.txt`) and `/account-deletion` (required by app store policies, reachable signed-out in every mode). Mode-specific rules: `saas-shared` only allows `/auth` and `/`; `saas-tenant` blocks `/auth`; `oss-tenant` allows everything.
- **`defaultRedirect()`** — Returns the fallback path for disallowed requests: `/auth` for `saas-shared` and `oss-tenant`, `/mingo` for `saas-tenant`.
- **`proxy(request)`** — The middleware entry point. Checks `isAllowed`, and if blocked, redirects to the mode's default path while cloning the URL (preserving query parameters like `fbclid`/`utm_source` for attribution). Otherwise passes the request through.
- **`config.matcher`** — Excludes `_next/`, `static/`, `favicon`, `assets/`, `icons/`, and `robots.txt` from middleware invocation entirely.

## Usage Example

This file is consumed automatically by Next.js as middleware (typically re-exported from `middleware.ts` at the project root):

```typescript
// middleware.ts
export { proxy as middleware, config } from './proxy';
```

Given `NEXT_PUBLIC_APP_MODE=saas-tenant`, a request to `/auth/login` is redirected to `/mingo?<original-query>`, while a request to `/account-deletion` or `/dashboard` passes through untouched.

**Note:** This logic deliberately mirrors `isRouteAllowedInCurrentMode` in `lib/app-mode.ts` but is kept separate since this file runs in the Edge runtime and cannot depend on browser globals.
