Client-side route guard component that blocks access to routes not permitted in the current application mode (e.g., static export builds), rendering a styled "Access restricted" message instead of the protected content.

## Key Components

- **`RouteGuard`** — Wrapper component that checks the current pathname against allowed routes using `isRouteAllowedInCurrentMode`. Renders children if allowed, or an access-restricted screen if not.
- **`RouteGuardProps`** — Interface accepting `children: React.ReactNode`.

## Usage Example

```typescript
// layout.tsx
import { RouteGuard } from './components/route-guard';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <RouteGuard>
          {children}
        </RouteGuard>
      </body>
    </html>
  );
}
```

## Notes

- Uses `'use client'` directive — runs only in the browser.
- Route permission logic is delegated to [`isRouteAllowedInCurrentMode`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/lib/app-mode.ts), which determines allowed routes based on the current app mode (e.g., OSS vs. hosted, static vs. server-rendered).
- The restricted-access UI uses ODS (OpenFrame Design System) tokens (`ods-bg`, `ods-text-primary`, `ods-text-secondary`) for consistent styling.
