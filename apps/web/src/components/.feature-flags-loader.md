## FeatureFlagsLoader

A non-blocking React component that triggers the server feature-flags fetch and synchronizes session/subscription state, rendering its `children` unconditionally without gating the app on flag resolution.

This component replaces an earlier blocking implementation. Since feature flags are now read reactively (not via a one-shot store snapshot), consumers that need to avoid a flash of an incorrect value should use `useFeatureFlagGate` and render their own loading branch locally, rather than relying on this loader to delay the entire app shell.

## Key Components

- **`FeatureFlagsLoader`** — Wrapper component that:
  - Invokes `useFeatureFlagsQuery`, enabled only when not in SaaS-shared mode, the session is ready, and the user is authenticated.
  - Calls `markSessionReady()` once the session resolves to an authenticated user, unlocking app-wide data requests gated on `session-ready.ts`.
  - Calls `resetSessionReady()` and `resetSubscriptionGate()` on sign-out, so stale credentials/subscription answers don't leak into the next session.
  - In SaaS-shared mode, marks flags as terminally "loaded" (since that surface never fetches flags), preventing `isLoaded` consumers from waiting indefinitely.
  - Always renders `children` immediately — it never blocks or shows a placeholder.

## Usage Example

```typescript
// app/layout.tsx
import { FeatureFlagsLoader } from '@/components/feature-flags-loader';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <FeatureFlagsLoader>
      {children}
    </FeatureFlagsLoader>
  );
}
```

```typescript
// Consuming a flag that may still be resolving — use the gate, not this loader
import { useFeatureFlagGate } from '@/hooks/use-feature-flag-gate';

function BillingBanner() {
  const { isLoading, value } = useFeatureFlagGate('new-billing-ui');

  if (isLoading) return <BannerSkeleton />;
  return value ? <NewBillingBanner /> : <LegacyBillingBanner />;
}
```

**Note:** `FeatureFlagsLoader` should be mounted once near the app root, above any component relying on `useFeatureFlagsStore` or `useFeatureFlagGate`, so the query lifecycle and session sync effects run globally.
