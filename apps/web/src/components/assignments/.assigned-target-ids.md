Converts a form's in-memory `AssignmentsValue` (keyed by target type) into the `assigned…Ids` global-ID list shape expected by GraphQL `CreateArticleInput`/`UpdateArticleInput` mutations, only including lists that changed relative to the stored (persisted) assignments.

## Key Components

- **`AssignedTargetIds`** — Interface describing the optional `assigned…Ids` fields (`assignedOrganizationIds`, `assignedDeviceIds`, `assignedTicketIds`, `assignedKnowledgeArticleIds`) sent to the server. A field omitted means "leave this assignment type untouched."
- **`INPUT_FIELD`** — Internal map from `ServerAssignmentTargetType` to the corresponding `AssignedTargetIds` key, enforced to cover all target types via `satisfies Record<...>`.
- **`targetIds(assignments, targetType)`** — Internal helper that extracts the refs for a given target type from an `AssignmentsValue` and converts each `ref.id` to a global id via `ensureGlobalId`.
- **`assignedTargetIds(assignments, stored?)`** — Main export. Compares the current form `assignments` against the `stored` (persisted) assignments per target type, and returns only the lists that differ (by size or content), using global ids throughout.

## Usage Example

```typescript
import { assignedTargetIds } from './assigned-target-ids';

const formAssignments = {
  ORGANIZATION: [{ id: 'org-1' }, { id: 'org-2' }],
  DEVICE: [{ id: 'device-1' }],
};

const storedAssignments = {
  ORGANIZATION: [{ id: 'org-1' }, { id: 'org-2' }],
  DEVICE: [],
};

const input = assignedTargetIds(formAssignments, storedAssignments);
// => { assignedDeviceIds: ['<global-id-for-device-1>'] }
// ORGANIZATION omitted: unchanged from stored

const mutationInput = {
  title: 'My Article',
  ...input,
};
```

Use this when building mutation variables for article create/update forms, ensuring unchanged assignment categories are omitted so the server doesn't unintentionally clear them.
