## knowledge-base-assigned-table.tsx

Renders a searchable, read-only data table of knowledge base articles assigned to an entity (e.g., a device or policy). It filters the already-fetched article list client-side as the user types, reusing the knowledge base listing's column set minus the row action menu.

## Key Components

- **`AssignedArticle`** — Type for a row, combining `KnowledgeBaseItemNameProps` with the `id` and `createdAt` fields picked from the `knowledgeBaseItemCreatedCell_item` GraphQL fragment. Since assignments are fetched via raw POST (no fragment reference), typing rows this way ensures a missing field becomes a compile error instead of a silently empty column.
- **`COLUMNS`** — `ColumnDef<AssignedArticle>[]` defining three columns: article name (with status/summary), created timestamp, and an "open in new tab" action.
- **`KnowledgeBaseAssignedTable`** — Main exported component. Props:
  - `articles: AssignedArticle[]` — full list of assigned articles.
  - `isLoading?: boolean` — shows skeleton rows while true.

Internally it manages local search state, debounces input (300ms), filters by name/summary, and wires the result into `useDataTable` for rendering via `DataTable`.

## Usage Example

```typescript
import { KnowledgeBaseAssignedTable } from '@/app/(app)/knowledge-base/components/.../knowledge-base-assigned-table';

function AssignedArticlesSection({ articles, loading }: { articles: AssignedArticle[]; loading: boolean }) {
  return (
    <KnowledgeBaseAssignedTable articles={articles} isLoading={loading} />
  );
}
```

Each row links to the article's detail page via `routes.knowledgeBase.details(row.id)`, and rows can be opened directly or via the dedicated "open in new tab" cell. When no articles match the search term or none are assigned, an empty state message ("No articles assigned.") is shown.
