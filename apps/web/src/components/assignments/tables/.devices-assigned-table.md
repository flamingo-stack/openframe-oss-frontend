# devices-assigned-table.tsx

A React client component that renders a searchable table of devices assigned to a given entity (e.g., a policy or group), with debounced client-side filtering by device name or organization.

## Key Components

- **`DevicesAssignedTable`** — Main exported component that renders a search input and a filtered device table.
- **`DevicesAssignedTableProps`** — Props interface accepting `devices: Device[]` and optional `isLoading?: boolean`.
- Uses `DevicesTableBody` and `matchesDeviceName` from `@flamingo-stack/openframe-frontend-core` for rendering and matching logic.
- Uses `useDebounce` (300ms) to avoid excessive re-filtering while typing.
- Displays a one-line empty state (`"No devices assigned."`) when no devices match or exist.

## Usage Example

```typescript
import { DevicesAssignedTable } from '@/app/(app)/.../devices-assigned-table';
import type { Device } from '@/app/(app)/devices/types/device.types';

function AssignedDevicesSection({ devices, isLoading }: { devices: Device[]; isLoading: boolean }) {
  return (
    <section>
      <h2>Assigned Devices</h2>
      <DevicesAssignedTable devices={devices} isLoading={isLoading} />
    </section>
  );
}
```

The component internally manages search state and filters the `devices` array in-memory using `useMemo`, matching against the device name (via `matchesDeviceName`) and the device's `organization` field (case-insensitive substring match). While `isLoading` is `true`, the table renders skeleton rows (count defined by `ASSIGNED_ITEMS_SKELETON_ROWS`) instead of data.
