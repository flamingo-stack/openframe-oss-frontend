Thin wrapper around the shared `apiClient` for executing GraphQL queries and mutations, normalizing HTTP errors and GraphQL-level errors into a single thrown `Error`.

## Key Components

- **`GraphQlEnvelope<T>`** – Internal interface modeling the standard GraphQL response shape (`data` and `errors` fields).
- **`postGraphQl<T>(query, variables)`** – Generic async function that POSTs a GraphQL document to `/api/graphql`, unwraps the envelope, and returns the typed `data` payload. Throws on HTTP failure, GraphQL errors, or missing data.

## Usage Example

```typescript
import { postGraphQl } from '@/lib/graphql';

const GET_USER = `
  query GetUser($id: ID!) {
    user(id: $id) {
      id
      name
      email
    }
  }
`;

interface GetUserResult {
  user: { id: string; name: string; email: string };
}

const result = await postGraphQl<GetUserResult>(GET_USER, { id: '123' });
console.log(result.user.name);
```

## Error Handling

The function surfaces errors at three layers in priority order:

1. **HTTP failure** – non-OK status from `apiClient`
2. **GraphQL errors** – first message from the `errors` array
3. **Empty response** – `data` field is absent despite a 200 OK

All three conditions throw a plain `Error`, so callers can use a single `try/catch` regardless of where the failure originated.
