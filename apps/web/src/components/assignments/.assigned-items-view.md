Renders a tabbed view of items (customers, devices, knowledge base articles, tickets) assigned to a given entity, dynamically showing only tabs for non-empty assignment categories.

## Key Components

### `AssignedItemsViewProps`
| Prop | Type | Description |
|------|------|-------------|
| `itemId` | `string` | ID of the entity whose assignments are displayed |
| `itemType` | `AssignmentItemType` | Type of the source entity (e.g. ticket, device) |
| `className` | `string?` | Optional CSS class for the wrapping `<section>` |
| `showTitle` | `boolean` | Whether to render the built-in "Assigned Items" heading (default: `true`) |

### `AssignedItemsView`
Main exported component. Fetches assignment data via `useAssignedItems`, filters out empty categories, and renders either a single table (no tabs) or a `TabNavigation` with one tab per populated category.

**Rendering states:**
- **Loading + no data** — Shows a skeleton placeholder
- **No assignments** — Returns `null` (renders nothing)
- **Single category** — Renders the table directly without tab chrome
- **Multiple categories** — Renders a `TabNavigation` with pinned tab state

## Usage Example

```typescript
// On a ticket details page (host supplies its own heading)
<AssignedItemsView
  itemId="ticket-123"
  itemType="TICKET"
  showTitle={false}
  className="mt-4"
/>

// Standalone section with built-in heading
<AssignedItemsView
  itemId="device-456"
  itemType="DEVICE"
/>
```

## Notes

- Tab state is **pinned** — the selected tab persists until the user switches; if the pinned tab's category becomes empty, it falls back to the first active tab.
- Per-category tables (`CustomersAssignedTable`, `DevicesAssignedTable`, etc.) are rendered lazily via `renderTabBody` only when their tab is active.
