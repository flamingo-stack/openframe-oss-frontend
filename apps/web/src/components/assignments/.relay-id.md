## relay-id.ts

Provides a workaround utility for normalizing entity IDs into Relay-compliant global IDs (base64-encoded `Type:rawId` strings). This exists specifically to patch a backend inconsistency: ai-agent's `Ticket` type returns raw MongoDB ObjectIds instead of proper Relay global IDs, unlike other `AssignableTarget` types. The module should be removed once the backend fix lands (see TODO comment in the source).

## Key Components

- **`RELAY_TYPE_NAME`** — Maps `AssignmentItemType`/`AssignmentTargetType` enum values (e.g. `ORGANIZATION`, `DEVICE`, `TICKET`) to their corresponding GraphQL Relay type names (e.g. `Organization`, `Machine`, `Ticket`).
- **`KNOWN_RELAY_TYPES`** — Set of valid Relay type names used to validate decoded IDs.
- **`btoaUtf8(value)`** / **`atobUtf8(value)`** — Cross-environment base64 encode/decode helpers (browser `window.btoa`/`atob` or Node `Buffer` fallback).
- **`decodeGlobalId(value)`** — Attempts to base64-decode a string and parse it as `type:id`; returns `null` if decoding fails or the type isn't recognized.
- **`toGlobalId(type, rawId)`** — Encodes a raw ID into a Relay global ID string for the given type.
- **`ensureGlobalId(type, value)`** (exported) — Idempotently normalizes an ID: returns it unchanged if already a valid Relay global ID, otherwise encodes it as one.

## Usage Example

```typescript
import { ensureGlobalId } from './relay-id';

// Raw MongoDB ObjectId from ai-agent's Ticket.id gets encoded
const ticketGlobalId = ensureGlobalId('TICKET', '64f1a2b3c4d5e6f7a8b9c0d1');

// Already-valid Relay global IDs (e.g. from Organization) pass through unchanged
const orgGlobalId = ensureGlobalId('ORGANIZATION', existingRelayId);

// Use in assignment mutations that require proper Relay global IDs
await assignTicket({ variables: { id: ticketGlobalId, targetId: orgGlobalId } });
```

**Note:** This is a temporary shim — remove once ai-agent's `TicketDataFetcher` implements a proper `@DgsData` resolver for `Ticket.id` that returns `RELAY.toGlobalId("Ticket", ...)`.
