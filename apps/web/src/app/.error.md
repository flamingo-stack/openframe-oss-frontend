This file defines the root-level error boundary for the Next.js App Router, handling uncaught exceptions that occur above the authenticated app layout.

## Key Components

- **`Error` (default export)** — A client component that serves as the root route-segment error boundary. It receives Next.js's standard error boundary props (`error` with an optional `digest`, and `reset` callback) and delegates rendering to the shared `RouteError` component.

## Behavior Notes

This boundary sits **above** `(app)/layout.tsx`, meaning:
- It does **not** preserve the signed-in app chrome (header, navigation, etc.) — triggering this boundary replaces the entire screen.
- Errors thrown within the authenticated app pages are instead caught by the nested `(app)/error.tsx` boundary, which keeps the app shell mounted.
- This root boundary only activates for throws originating from `(app)/layout.tsx` itself, or from the auth/marketing route segments that live outside the app layout.

## Usage Example

This file is automatically wired up by Next.js's file-based routing convention — no manual import is needed. Simply placing `error.tsx` at the root of the `app` directory enables it:

```typescript
// app/error.tsx
'use client';

import { RouteError } from './components/route-error';

export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  return <RouteError error={error} reset={reset} label="Error Boundary" />;
}
```

When a throw occurs in a root-level segment (e.g., `(app)/layout.tsx`, or the auth/marketing routes), Next.js automatically renders this component, passing the caught `error` and a `reset` function to retry rendering the segment.

See also: [`(app)/error.tsx`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/(app)/error.tsx) for the nested boundary that preserves app chrome.
