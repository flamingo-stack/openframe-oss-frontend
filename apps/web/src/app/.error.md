Route-segment error boundary component that catches render and data errors thrown within a page segment, keeping the app shell (header, sidebar) mounted while replacing only the failed page content with a recovery UI.

## Key Components

- **`Error`** (default export) — Next.js `error.tsx` boundary component accepting `error` (with optional `digest`) and `reset` props
- **`retryRef`** — `useRef` pointing to the "Try Again" button; auto-focused on mount for accessible keyboard/AT recovery
- **`role="alert"`** wrapper — ensures screen readers announce the error state immediately
- **`ContentPageContainer`** — app-shell UI wrapper rendering a consistent page title and subtitle
- **`Button` (accent)** — calls `reset()` to re-render the failed segment in place
- **`Button` (outline)** — falls back to a full `window.location.reload()` when the error is unrecoverable

## Usage Example

This file is automatically invoked by Next.js when an error is thrown in any child route segment. No manual import is required.

```typescript
// app/some-route/error.tsx — Next.js picks this up automatically
// Throwing inside a page or server component triggers this boundary:

export default function Page() {
  throw new Error('Something broke');
}
```

To test the `reset()` flow manually during development:

```typescript
// Simulate a recoverable error in a child component
'use client';
import { useState } from 'react';

export function Faulty() {
  const [fail, setFail] = useState(false);
  if (fail) throw new Error('Recoverable failure');
  return <button onClick={() => setFail(true)}>Break it</button>;
}
```

> **Accessibility note:** Focus is programmatically moved to the "Try Again" button on mount so keyboard and assistive technology users immediately reach the recovery control without having to navigate through the error UI.
