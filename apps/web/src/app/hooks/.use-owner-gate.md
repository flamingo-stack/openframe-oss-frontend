# use-owner-gate.ts

A client-side React hook that determines whether the currently signed-in user holds the `OWNER` role in the active workspace, returning a tri-state result to avoid premature access denials during auth resolution.

## Key Components

- **`OwnerGate`** — Union type `'loading' | 'owner' | 'not-owner'` representing the three possible ownership states. The `'loading'` state exists so consumers don't prematurely deny access (e.g., via `notFound()`) before the real answer is known.
- **`useOwnerGate()`** — Hook that reads `isReady`, `isAuthenticated`, and `user` from `useAuthSession()` and returns an `OwnerGate` value:
  - Returns `'loading'` if the session isn't ready, the user isn't authenticated, or user data is unavailable (including the signed-out case, since the app is already redirecting/replacing the view).
  - Returns `'owner'` if any of `user.roles` case-insensitively matches `'owner'`.
  - Returns `'not-owner'` otherwise.

## Usage Example

```typescript
'use client';

import { useOwnerGate } from '@/hooks/use-owner-gate';
import { notFound } from 'next/navigation';

export function WorkspaceDeletionPanel() {
  const ownerGate = useOwnerGate();

  if (ownerGate === 'loading') {
    return <PlaceholderSpinner />;
  }

  if (ownerGate === 'not-owner') {
    notFound();
  }

  return <DeleteWorkspaceForm />;
}
```

## Notes

- Reads ownership from the `/me` payload (via `useAuthSession`) rather than the auth store, avoiding a race between query settlement and store commit that could incorrectly 404 an eligible owner.
- Role comparison is case-insensitive, matching the convention used in `employee-details-view.tsx`.
- Scoped strictly to ownership-gated actions (e.g., self-deletion of a workspace). Billing access is a separate concern handled by `use-billing-access-gate.ts`, since billing is also open to admins.
