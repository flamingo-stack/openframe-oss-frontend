## use-seed-form.ts

A React hook that fills an uncontrolled form with data that arrives after the form has already mounted, without ever swapping the real form for a loading skeleton. It is the core mechanism behind "render the real form immediately, hydrate it when the record shows up" edit pages.

## Key Components

- **`useSeedForm(form, values)`** — First overload: seeds the form directly from a values object (or `null` while loading).
- **`useSeedForm(form, record, valuesOf)`** — Second overload: seeds the form from a richer `record`, using `valuesOf` to extract just the form's field values from it.
- **`Seed<R, T>`** — Internal type pairing the source `record` with the derived form `values`.
- Returns the `record` the form was actually seeded from (`null` until a seed has been applied), which the caller can use to know when real data is showing instead of a placeholder.

## Usage Example

```typescript
import { useForm } from 'react-hook-form';
import { useSeedForm } from './use-seed-form';

interface UserRecord {
  id: string;
  name: string;
  email: string;
  updatedAt: string;
}

interface UserFormValues {
  name: string;
  email: string;
}

function EditUserForm({ record }: { record: UserRecord | null }) {
  const form = useForm<UserFormValues>({
    defaultValues: { name: '', email: '' },
  });

  // Extracts just the editable fields from the fetched record.
  const seededRecord = useSeedForm(form, record, (r) => ({
    name: r.name,
    email: r.email,
  }));

  return (
    <form>
      <input {...form.register('name')} disabled={!seededRecord} />
      <input {...form.register('email')} disabled={!seededRecord} />
    </form>
  );
}
```

**Important:** Call `useSeedForm` from the component that owns `useForm`, not from a child/island that performs the data fetch. Because React Hook Form subscribes fields in a layout effect (children before parents), a `reset` triggered from a fetching sibling rendered above the fields can fire before those fields have subscribed, silently dropping the seeded values — especially with cached/instant query responses.

The hook only seeds while the form is pristine (`!isDirty`), so background refetches never clobber in-progress edits, and each seed is applied exactly once per record change.
