# use-admin-gate.ts

A client-side React hook that determines whether the currently signed-in user holds an `OWNER` or `ADMIN` role for the active workspace, returning a tri-state result suitable for gating UI rendering while session data loads.

## Key Components

- **`AdminGate`** — Type alias representing the three possible states: `'loading'`, `'admin'`, `'not-admin'`. The explicit `'loading'` state avoids conflating "unknown yet" with "not authorized."
- **`ADMIN_ROLES`** — Internal constant listing the lowercase role strings (`owner`, `admin`) considered admin-level, matching the backend's `hasAnyAuthority('ADMIN','OWNER')` check.
- **`useAdminGate()`** — Hook that reads session state via `useAuthSession` and returns an `AdminGate` value based on the user's roles from the `/me` payload (not the auth store), case-insensitively compared.

## Usage Example

```typescript
'use client';

import { useAdminGate } from '@/app/(auth)/auth/hooks/use-admin-gate';

export function AdminOnlyPanel() {
  const adminGate = useAdminGate();

  if (adminGate === 'loading') {
    return <Spinner />;
  }

  if (adminGate === 'not-admin') {
    return <AccessDenied />;
  }

  return <AdminSettingsForm />;
}
```

## Notes

- Relies on `useAuthSession` to determine `isReady` and `isAuthenticated` status before evaluating roles, ensuring the gate doesn't prematurely resolve to `'not-admin'` during session hydration.
- Role matching is case-insensitive and tolerant of `null`/`undefined` entries in `user.roles`.
- Mirrors the pattern used in `use-owner-gate.ts` for consistency across role-based gating hooks.
