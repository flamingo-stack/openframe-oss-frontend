# use-is-mobile-viewport.ts

A React hook that detects whether the current viewport is narrower than the `md` breakpoint (800px), using `useSyncExternalStore` for safe SSR/hydration behavior. Unlike a simple boolean, it distinguishes between "not known yet" (server/pre-hydration) and the actual client-side state, preventing hydration mismatches when the answer determines which component subtree gets mounted.

## Key Components

- **`isMobileViewportNow()`** — Synchronous, non-reactive check of the current viewport against the `md` breakpoint. Returns `false` if no viewport is available (e.g., non-browser environment). Intended for use in event handlers rather than render.
- **`useIsMobileViewport()`** — React hook returning `boolean | undefined`:
  - `undefined` on the server and during initial hydration (viewport unknown).
  - `true`/`false` once the client has mounted and the real viewport is known.
  - Subscribes to `matchMedia` changes for live updates as the viewport resizes across the breakpoint.
- **`subscribe`** (internal) — Wires up a `matchMedia` change listener, with safe no-op fallback when `window`/`matchMedia` is unavailable.
- **`getServerSnapshot`** (internal) — Always returns `undefined`, signaling "unknown" during SSR and hydration replay.

## Usage Example

```typescript
import { useIsMobileViewport, isMobileViewportNow } from './use-is-mobile-viewport';

function ResponsiveLayout() {
  const isMobile = useIsMobileViewport();

  // Hold a neutral state until the real answer arrives
  if (isMobile === undefined) {
    return <LayoutSkeleton />;
  }

  return isMobile ? <MobileNav /> : <DesktopNav />;
}

function handleSendClick() {
  // Non-reactive check inside an event handler
  if (isMobileViewportNow()) {
    trackEvent('send_clicked_mobile');
  }
}
```

**Important:** Use this hook only when the boolean decides *which component* to mount (e.g., switching between distinct subtrees). For purely visual/layout differences within the same component, prefer core's `useMdUp()` instead, which doesn't need to handle the "unknown" SSR state.
