## `use-same-window-links.ts`

A React hook that determines whether outbound links should navigate in the current window instead of opening a new tab, accounting for both the Capacitor app shell and narrow viewports.

## Key Components

- **`useSameWindowLinks()`** — Primary hook export. Returns `true` when links must stay in the current window (no new tab), `false` when opening a new tab is acceptable.
- **`subscribe()`** — Internal no-op subscription function for `useSyncExternalStore`, since the app shell cannot change mid-session.
- **`getServerSnapshot()`** — Internal SSR snapshot function; defaults to `false` (assumes web) until hydration corrects it via `isAppShell`.

## Usage Example

```typescript
import { useSameWindowLinks } from '@/hooks/use-same-window-links';

function ExternalLinkChip({ href, label }: { href: string; label: string }) {
  const sameWindow = useSameWindowLinks();

  return (
    <a
      href={href}
      target={sameWindow ? undefined : '_blank'}
      rel={sameWindow ? undefined : 'noopener noreferrer'}
    >
      {label}
    </a>
  );
}
```

## Behavior Notes

The hook returns `true` (stay in same window) under two independent conditions:

1. **Running inside the app shell** (Capacitor WKWebView) — `target="_blank"` and `window.open()` are silently dropped there, so new-tab links would be dead clicks. This is shell-based, not viewport-based, since tablets running the mobile app still hit this issue despite a wide viewport.
2. **Narrow viewport** (below the `md`/`mobileBreakpoint = 800` breakpoint) — At this width the drawer goes `inset-0` and covers the page, making a background tab harder to return to than an in-place navigation.

This hook relies on `isAppShell` (from `@/lib/platform`) and `useIsMobileViewport` for its two conditions, and uses `useSyncExternalStore` to safely read the shell state across SSR/hydration boundaries.
