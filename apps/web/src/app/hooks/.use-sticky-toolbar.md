Measures and publishes the sticky toolbar's height as a CSS custom property so a sticky table header always pins flush below it without a hard-coded offset.

## Key Components

### `useStickyToolbar(): StickyToolbar`

The single exported hook. Returns a `StickyToolbar` object with three members:

| Member | Type | Purpose |
|---|---|---|
| `toolbarRef` | `RefObject<HTMLDivElement \| null>` | Attach to the sticky toolbar element to measure |
| `containerStyle` | `CSSProperties` | Apply to the wrapper element; publishes `--sticky-toolbar-h` |
| `stickyHeaderOffset` | `string` | Pass to `DataTable.Header`'s `stickyHeaderOffset` prop |

Internally, a `ResizeObserver` watches the toolbar element for height changes (e.g. when a tag filter row appears or collapses) and keeps the CSS variable in sync.

## Usage Example

```typescript
import { useStickyToolbar } from '@/hooks/use-sticky-toolbar';

export function DevicesTable() {
  const { toolbarRef, containerStyle, stickyHeaderOffset } = useStickyToolbar();

  return (
    <div style={containerStyle}>
      {/* Toolbar height is observed here */}
      <div ref={toolbarRef}>
        <FilterToolbar />
      </div>

      {/* Table header pins flush below the toolbar */}
      <DataTable.Header stickyHeaderOffset={stickyHeaderOffset} />
    </div>
  );
}
```

## Notes

- `ResizeObserver` is torn down on unmount via the `useEffect` cleanup return.
- The Tailwind class `top-[var(--sticky-toolbar-h)]` on `stickyHeaderOffset` requires the CSS variable to be in scope on an ancestor element, which `containerStyle` provides.
- The hook is marked `'use client'` and must only be used in client components.
