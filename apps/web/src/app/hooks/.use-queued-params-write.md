Custom React hook that batches multiple same-tick calls to a `setParams` updater (from `useApiParams`) into a single merged URL update, preventing race conditions where sequential writes silently overwrite each other.

## Key Components

- **`useQueuedParamsWrite<Params>`** — Hook that wraps a `setParams` function and returns a new updater function with the same signature. Internally:
  - Uses a `useRef` to hold pending updates across synchronous calls within the same tick.
  - On the first call in a tick, clones the updates into the ref and schedules a `queueMicrotask` to flush the merged result via the original `setParams`.
  - On subsequent calls in the same tick, merges new updates into the pending object via `Object.assign` instead of scheduling another write.
  - Eagerly scrolls the page's `main` element to the top (instant, idempotent) on every call, ensuring a single scroll even when multiple calls are merged.

## Usage Example

```typescript
import { useApiParams } from './use-api-params';
import { useQueuedParamsWrite } from './use-queued-params-write';

function FilterModal() {
  const { params, setParams } = useApiParams<FilterState>();
  const queuedSetParams = useQueuedParamsWrite(setParams);

  function onApply() {
    // Both calls happen in the same tick (e.g. inside one handler)
    onFilterChange(selectedFunnels, queuedSetParams);
    dateFilter.onChange(selectedRange, queuedSetParams);
    // Result: ONE merged URL update instead of two conflicting ones
  }

  return <button onClick={onApply}>Apply</button>;
}
```

This is particularly useful for modals or forms where multiple independent sub-components each call an update callback synchronously, but all updates must land in a single consistent URL state change.
