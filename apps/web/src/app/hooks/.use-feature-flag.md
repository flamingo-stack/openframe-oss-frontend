## Purpose

This file provides React hooks for reading feature flag state from the Zustand-backed `feature-flags-store`. It deliberately distinguishes "not yet answered" from "off" via the `FeatureFlagGate` type, preventing UI from rendering incorrect state (wrong redirects, incomplete navigation, flickering layouts) during the loading window before the server responds.

## Key Components

- **`useFeatureFlagsReady()`** — Returns `boolean` indicating whether the feature flags store has finished loading (succeeded or terminally failed). Used by app shells to hold a stub/skeleton until flag-dependent chrome (e.g., sidebar nav) can render completely.
- **`useFeatureFlagGate(flagName, envFallback?)`** — Returns `'loading' | 'on' | 'off'`. Use this for anything where an incorrect value during loading is unacceptable: redirects, route gates, nav items, tabs, layout switches. Callers must handle `'loading'` explicitly rather than treating it as `'off'`.
- **`useFeatureFlag(flagName, envFallback = false)`** — Returns a plain `boolean`, treating "not answered yet" as the fallback value. Only safe for UI whose late appearance is harmless (e.g., an optional card/section) and where no other page behavior depends on it.

## Usage Example

```typescript
import { useFeatureFlagGate, useFeatureFlag, useFeatureFlagsReady } from '@/hooks/use-feature-flag';

function SettingsTabs() {
  const gate = useFeatureFlagGate('insights');

  if (gate === 'off') {
    redirect('/settings');
    return null;
  }

  return (
    <LoadingWhen loading={gate === 'loading'}>
      <Tabs items={['Overview', 'Insights']} />
    </LoadingWhen>
  );
}

function OptionalPromoCard() {
  // Safe: appearing late is fine, absence changes nothing else.
  const showPromo = useFeatureFlag('promoBanner', false);
  return showPromo ? <PromoCard /> : null;
}

function AppShell({ children }: { children: React.ReactNode }) {
  const ready = useFeatureFlagsReady();
  if (!ready) return <AppShellSkeleton />;
  return <>{children}</>;
}
```

## Notes

- Do not collapse `'loading'` into `'off'` when using `useFeatureFlagGate`—this defeats the hook's purpose.
- For imperative (non-React) reads, use `featureFlags.*.enabled()`, which shares the same fallback-before-ready caveat as `useFeatureFlag`.
