# use-walkthrough-video-data.ts

A shared React hook that fetches walkthrough video content for the current platform via a single, cached React Query key, used by both the app-shell floating card and the onboarding promo block.

## Key Components

- **`WALKTHROUGH_DISMISS_STORAGE_KEY`** — Platform-specific cookie key used to persist the dismissal state, ensuring dismissing the video in one surface (e.g., the promo) suppresses it everywhere (e.g., the floating card).
- **`WalkthroughVideoResult`** — Return type interface with:
  - `video: WalkthroughVideoData | null` — the video data, or `null` while loading or when none is configured
  - `isLoading: boolean` — loading state flag
- **`useWalkthroughVideoData()`** — Main hook that fetches `/content/api/walkthrough-video` using `embedAuthedFetch` (not a bare `fetch`, to support role-gated gateway access in dev-ticket mode and the native shell), caches the result via React Query, and normalizes relative `captionsUrl` paths against `CONTENT_BASE`.

## Usage Example

```typescript
import { useWalkthroughVideoData } from '@/hooks/use-walkthrough-video-data';

function WalkthroughCard() {
  const { video, isLoading } = useWalkthroughVideoData();

  if (isLoading) {
    return <Spinner />;
  }

  if (!video) {
    return null; // no walkthrough configured for this platform
  }

  return (
    <VideoPlayer
      src={video.videoUrl}
      captionsUrl={video.captionsUrl}
    />
  );
}
```

**Notes:**
- The hook treats HTTP `404`/`410` responses as "no video configured" (returns `null`), while any other non-OK response throws so React Query retries rather than caching a false negative.
- Requests use `cache: 'no-store'` since a `410` response would otherwise be cached by the browser, breaking future mounts.
- `captionsUrl` rewriting happens inside `queryFn` (not `select`) to preserve object identity across re-renders and avoid restarting the video widget's appear-delay timer.
