# use-is-mobile-shell.ts

A React hook that provides a hydration-safe way to detect whether the app is running inside a mobile shell (e.g., a wrapped WebView), avoiding server/client rendering mismatches.

## Key Components

- **`useIsMobileShell()`** — Exported hook that returns a `boolean` indicating whether the app is running inside a mobile shell. Built on `useSyncExternalStore` to safely bridge server-rendered and client-rendered values.
- **`subscribe()`** — Internal no-op subscription function. Since shell type cannot change mid-session, there's no external store to listen to.
- **`getServerSnapshot()`** — Internal function that always returns `false` (assumes "web") during server-side rendering, since `window`/shell context isn't available at build/prerender time.

## Usage Example

```typescript
import { useIsMobileShell } from '@/hooks/use-is-mobile-shell';

function MyComponent() {
  const isMobileShell = useIsMobileShell();

  if (isMobileShell) {
    return <MobileOptimizedView />;
  }

  return <WebView />;
}
```

## Notes

- This hook trades a single-frame flash of the web variant on mobile devices for correctness during hydration — the same pattern used by `useMediaQuery` in the core library.
- Since the server always prerenders assuming "web", the hook re-renders once the client determines the actual shell context via `isMobileShell()` from `@/lib/platform`.
- **Important:** If your UI must render correctly in the *first* painted frame (no flash), do not rely on this hook. Instead, use CSS that the shell can apply before hydration occurs.
- The underlying shell type is assumed immutable for the lifetime of a document/session, which is why `subscribe()` is a no-op.
