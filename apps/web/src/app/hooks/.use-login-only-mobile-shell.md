# use-login-only-mobile-shell.ts

A React hook that safely detects whether the app is running inside a login-only mobile shell, avoiding hydration mismatches during static export/prerendering.

## Key Components

- **`useLoginOnlyMobileShell()`** — Hook that returns a `boolean` indicating whether the current environment is a login-only mobile shell. Built on `useSyncExternalStore` to synchronize client/server rendering.
- **`noSubscription`** — Internal no-op subscription function, used because the shell mode is static for the lifetime of a document (it never changes, so no store subscription is needed).
- Relies on `isLoginOnlyMobileShell` from `@/lib/app-mode` as the client snapshot getter.

## Usage Example

```typescript
'use client';

import { useLoginOnlyMobileShell } from '@/hooks/use-login-only-mobile-shell';

function AuthLayout({ children }: { children: React.ReactNode }) {
  const isLoginOnlyShell = useLoginOnlyMobileShell();

  if (isLoginOnlyShell) {
    return <CompactLoginScreen />;
  }

  return <TabbedAuthLayout>{children}</TabbedAuthLayout>;
}
```

## Why It Matters

Static export prerenders auth layouts without an actual shell context. A direct call to `isLoginOnlyMobileShell()` during render would produce a client/server mismatch: the server has no shell, but the client might detect one post-hydration, causing React hydration errors (e.g., rendering a compact login screen over prerendered tabbed markup).

By using `useSyncExternalStore` with a server snapshot that always returns `false`, the initial hydration pass matches the prerendered markup exactly. React then re-renders with the real client-detected value once hydration completes safely.
