# use-customers-overview.ts

React Query hook that powers the dashboard's "Customers" overview section, combining organization data with per-status device counts into a ranked, limited list of customer summary rows.

## Key Components

- **`OrganizationOverviewRow`** — Shape of each row: organization identity, image, and computed device totals/percentages (active/inactive).
- **`CUSTOMERS_OVERVIEW_LIMIT`** — Default row limit (`10`), also used to size the loading skeleton.
- **`useCustomersOverview(limit?)`** — Primary hook; returns `rows`, `loading`, `isOffline`, `canClaimEmpty`, `error`, `totalOrganizations`, and `refresh`.
- **`fetchCustomersOverview(limit)`** — Fetches organizations and device counts in parallel (one round-trip, not sequential), merges them, sorts by total devices descending, and slices to `limit`.
- **`fetchOrganizations()`** — Throws on failure so the hook surfaces an `error` state instead of silently resolving to an empty result (which would incorrectly render the "no customers" empty state).
- **`organizationCountsForStatuses(statuses)`** — Fetches device counts per organization for given statuses; degrades to an empty map on failure rather than failing the whole query, since device counts are a secondary detail of the customer list.

## Usage Example

```typescript
import { useCustomersOverview, CUSTOMERS_OVERVIEW_LIMIT } from './use-customers-overview';

function CustomersOverviewSection() {
  const {
    rows,
    loading,
    isOffline,
    canClaimEmpty,
    error,
    totalOrganizations,
    refresh,
  } = useCustomersOverview(CUSTOMERS_OVERVIEW_LIMIT);

  if (loading) return <CustomersSkeleton count={CUSTOMERS_OVERVIEW_LIMIT} />;
  if (error) return <ErrorState onRetry={refresh} />;
  if (canClaimEmpty) return <EmptyState message="No Customers added yet" />;

  return (
    <div>
      <p>Total organizations: {totalOrganizations}</p>
      {rows.map(row => (
        <CustomerRow key={row.id} row={row} />
      ))}
    </div>
  );
}
```

**Design notes:** Device counts (active/inactive) are derived from two independent status queries rather than three, since `total === active + inactive` by construction of the backend's status partitioning. The hook uses `refetchOnMount: 'always'` to keep data fresh on each dashboard visit without showing a skeleton over existing data.
