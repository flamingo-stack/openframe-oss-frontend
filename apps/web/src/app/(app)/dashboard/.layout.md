Defines page metadata for the Dashboard route segment and re-exports a shared layout component to handle rendering, ensuring the browser tab title reflects the current page.

## Key Components

- **`metadata`** — A Next.js `Metadata` object that sets the document title to `"Dashboard"` using the `routeTitle` helper, which likely formats it consistently (e.g., appending an app name suffix).
- **Default export** — Re-exported from `@/app/(app)/route-title-layout`, delegating the actual layout rendering logic (such as wrapping children or injecting a dynamic title into the UI) to a shared component instead of duplicating it per route.

## Usage Example

This file follows the Next.js App Router convention where a `layout.tsx` file applies to all routes within its directory segment (in this case, the Dashboard section).

```typescript
// Next.js automatically picks up this layout for routes under this segment
// No manual import is required elsewhere in the app

// Example of the helper it depends on:
// lib/route-title.ts
export function routeTitle(page: string): string {
  return `${page} | OpenFrame`;
}
```

Because the component logic is re-exported rather than redefined, adding a new page's layout typically only requires creating a similar `layout.tsx` file that sets `metadata.title` via `routeTitle('PageName')` and re-exports the shared layout, keeping title management consistent across the app while avoiding duplicated layout markup.
