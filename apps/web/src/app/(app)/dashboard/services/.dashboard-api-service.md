# dashboard-api-service.ts

Client-side service that aggregates device and ticket statistics for the dashboard view, combining device status counts with GraphQL-sourced ticket metrics into UI-ready summary objects.

## Key Components

- **`DashboardDeviceStats`** — Interface describing device counts (total, active, inactive, pending, archived) and their corresponding percentages.
- **`DashboardTicketStats`** — Interface describing ticket totals, resolution metrics, average rating, and lifecycle status breakdowns (AI assistance, tech required, other).
- **`DashboardApiService`** — Singleton class exposing:
  - `fetchDeviceStats()` — Retrieves device status counts via `fetchDeviceStatusCounts` and computes percentages per status (online, offline, pending, deleted/archived).
  - `fetchTicketStats()` — Queries the `ticketStatistics` GraphQL endpoint and derives resolved counts, average resolution time, average rating, and status-kind breakdowns.
  - Private `handleApiError()` — Normalizes thrown errors with contextual operation names.
- **`dashboardApiService`** — Exported singleton instance ready for use in components.

## Usage Example

```typescript
import { dashboardApiService } from './dashboard-api-service';

async function loadDashboard() {
  try {
    const [deviceStats, ticketStats] = await Promise.all([
      dashboardApiService.fetchDeviceStats(),
      dashboardApiService.fetchTicketStats(),
    ]);

    console.log(`Active devices: ${deviceStats.active} (${deviceStats.activePercentage}%)`);
    console.log(`Resolved tickets: ${ticketStats.resolved}/${ticketStats.total}`);
  } catch (error) {
    console.error('Failed to load dashboard data:', error);
  }
}
```

## Notes

- Uses the singleton pattern via `getInstance()` — do not instantiate `DashboardApiService` directly (constructor is private).
- Device stats rely on the shared query layer (`fetchDeviceStatusCounts`) from the devices feature module.
- Ticket stats use the `ticketStatistics` GraphQL query, which replaced a legacy `dialogStatistics` query after tickets were split from dialogs on the backend.
- Archived device count combines both `DELETED` and legacy `ARCHIVED` statuses to match the `/devices/archive` listing behavior.
