# devices-overview.tsx

Renders the dashboard's "Devices Overview" section, showing four status cards (Online, Offline, Pending, Archived) with device counts and percentages. Handles loading states, error states, and links each card to its filtered device list.

## Key Components

- **`DeviceStatusInfoCard`** - Reusable card component for a single device status, mapping a status key to its title and progress-bar color via `DEVICE_STATUS_CARD`. Shared by both the devices overview and per-customer cards elsewhere in the app.
- **`DEVICE_STATUS_CARD`** - Constant mapping each `DEVICE_STATUS` value to its card title and `ProgressVariant` (success/error/warning/info).
- **`DevicesOverviewSection`** - Data-fetching wrapper that calls `useDevicesOverview()`, signals reveal-readiness via `useRevealPart`, and renders `DevicesOverview` inside a `LoadingWhen` region.
- **`DevicesOverview`** - Presentational component that builds the four `DeviceStatusCard` entries, displays load errors via `SectionLoadError`, and renders the grid of `DeviceStatusInfoCard`s with links to filtered device routes.

## Usage Example

```typescript
import { DevicesOverviewSection, DevicesOverview, DeviceStatusInfoCard } from './devices-overview';
import { DEVICE_STATUS } from '@flamingo-stack/openframe-frontend-core/components/features';

// Self-fetching usage (typical dashboard placement)
function Dashboard() {
  return <DevicesOverviewSection />;
}

// Passing pre-fetched data (e.g. from a parent reveal-together context)
function CustomDashboard({ devices }: { devices: ReturnType<typeof useDevicesOverview> }) {
  return <DevicesOverview devices={devices} />;
}

// Reusing a single status card elsewhere (e.g. per-customer summary)
function CustomerCard() {
  return (
    <DeviceStatusInfoCard
      status={DEVICE_STATUS.ONLINE}
      value={42}
      percentage={87.5}
    />
  );
}
```

Notes:
- A `null` count value indicates a failed stats request and renders as `EMPTY_VALUE` (not zero), avoiding misleading data.
- Archived devices link to a dedicated archive route; other statuses link to the filtered devices list.
- Loading state is driven by `useLoadingScope()` combined with the hook's own `isLoading`/absence of data.
