# mingo-intro-banner.tsx

A dismissible onboarding banner component displayed on the OpenFrame dashboard that introduces Mingo's AI-driven workflow via a walkthrough video and a call-to-action to book an onboarding call. The banner persists its dismissed state per-user in `localStorage` and coordinates its reveal timing with the page's `RevealTogether` loading sequence.

## Key Components

- **`MingoIntroBanner`** — Main exported component rendering the intro banner. Renders `null` when loading, already dismissed, or when neither a walkthrough video nor a bookable call link is available.
- **`useDismissed(key)`** — Internal hook built on `useSyncExternalStore` that reads/writes the dismissed flag from `localStorage`, ensuring SSR and first client render stay in sync (always `false` until hydration resolves).
- **`subscribeDismissed` / `dismissListeners`** — Module-level pub/sub mechanism notifying all subscribed banner instances when the dismissal state changes.
- **`readDismissed(key)`** — Safely reads the dismissed flag from storage, defaulting to `false` if storage access fails.
- **`DISMISSED_KEY_PREFIX`** — Storage key prefix, scoped per authenticated user ID (or `'anonymous'`).

## Usage Example

```typescript
import { MingoIntroBanner } from '@/app/(app)/dashboard/components/mingo-intro-banner';

function DashboardOverview() {
  return (
    <div className="flex flex-col gap-4">
      <MingoIntroBanner />
      {/* rest of dashboard sections */}
    </div>
  );
}
```

The component requires no props — it self-manages visibility based on:
- Authentication state (`useAuthStore`) for per-user dismissal scoping
- Onboarding meeting link availability (`useOnboardingMeetingLink`)
- Walkthrough video data (`useWalkthroughVideoData`)
- Page-level reveal coordination (`useRevealPart`, `useRevealHeld`, `useLoadingScope`)

Clicking the dismiss (`X`) button hides the banner permanently for that user on that device. Clicking **Book a Call** opens the `BookCallModal`.
