# dashboard-content.tsx

Renders the main dashboard page content, composing the onboarding banner/setup card with overview sections (Devices, Tickets, Customers) behind a coordinated reveal. Also exports shared building blocks reused by Mingo's home page.

## Key Components

- **`IntroBanner`** — Onboarding v2's dismissable welcome banner (`MingoIntroBanner`). Renders nothing until the `onboarding-v2` feature flag resolves to `on`.
- **`InitialSetupSection`** (internal) — Renders the legacy `InitialSetupCard` when onboarding v2 is off, with its own loading boundary for suspending queries.
- **`OverviewSections`** — Shared layout for Devices/Tickets/Customers overview cards. Supports `live` (fetch real data vs. loading skeletons), `filterTicketLinks`, an `incidents` slot, and `dimDuringInitialSetup` to visually disable sections while tenant setup is active.
- **`DashboardOverviews`** — Combines the intro banner, initial setup card, and `OverviewSections` for the classic app shell.
- **`DashboardContent`** (default export) — The dashboard page entry point; wraps `DashboardOverviews` in `RevealTogether` so all sections appear simultaneously once ready.

## Usage Example

```typescript
// app/(app)/dashboard/page.tsx
import DashboardContent from './dashboard-content';

export default function DashboardPage() {
  return <DashboardContent />;
}
```

```typescript
// Reusing overview sections elsewhere (e.g. Mingo's home page)
import { OverviewSections } from './dashboard-content';

function MingoHome() {
  return (
    <OverviewSections
      live
      filterTicketLinks
      incidents={<IncidentsSection />}
      dimDuringInitialSetup={false}
    />
  );
}
```

Components rely on `useFeatureFlagGate('onboarding-v2')` to switch between the legacy dashboard (Initial Setup card, dimmed sections during setup) and onboarding v2 (welcome banner, no dimming, setup moved to `/setup`). The `RevealTogether`/`useRevealPart` pair ensures async sections appear together rather than popping in individually.
