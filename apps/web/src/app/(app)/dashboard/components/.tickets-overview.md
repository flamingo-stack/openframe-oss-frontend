Dashboard section component that renders the "Tickets Overview" panel: four summary cards (AI Assistance, Tech Required, Resolved, Other Statuses) showing ticket counts, each optionally linking to a pre-filtered Tickets list view.

## Key Components

- **`TicketsOverviewSection`** — Self-fetching wrapper that calls `useTicketsOverview()`, registers loading state with the page's `RevealTogether` coordination (`useRevealPart`), and wraps `TicketsOverview` in a `LoadingWhen` boundary tied to `useRevealHeld`.
- **`TicketsOverview`** — Presentational component accepting pre-fetched `tickets` data. Renders a `TitleBlock`, an error state via `SectionLoadError` when data fails or the client is offline, and a responsive grid of `DashboardInfoCard` components.
- **`TICKET_CARDS`** — Static ordered config array defining each card's title renderer (using `TicketStatusTag`), the `TICKET_STATUS_KIND` it represents, and how to read its count from the tickets data.
- **`TicketsOverviewLinks`** (type) — Props controlling whether cards link to status-filtered ticket lists (`filterLinks`) or the plain list.

## Usage Example

```typescript
import { TicketsOverviewSection } from './tickets-overview';

// Basic usage inside a dashboard page, cards link to the unfiltered tickets list
export function DashboardPage() {
  return <TicketsOverviewSection />;
}

// With status-filtered card links (uses ticket statuses query to resolve status ids)
export function DashboardPageFiltered() {
  return <TicketsOverviewSection filterLinks />;
}

// Rendering with already-fetched data (e.g. from a parent that batches dashboard queries)
import { useTicketsOverview } from '../hooks/use-dashboard-stats';
import { TicketsOverview } from './tickets-overview';

function CustomDashboardSection() {
  const tickets = useTicketsOverview();
  return <TicketsOverview tickets={tickets} filterLinks />;
}
```

**Notes:** Each card shows a loading skeleton (bar) when `tickets` is undefined, loading, or an ancestor `LoadingScope` is active. When `filterLinks` is enabled, card hrefs are resolved via `useTicketStatusesQuery`, mapping each `TICKET_STATUS_KIND` to concrete status ids shared with the Tickets page cache.
