# page.tsx

This file defines the root `Dashboard` page component, which conditionally renders the appropriate dashboard experience depending on the current app mode (OSS tenant, SaaS tenant, or Manhattan v2 shell).

## Key Components

- **`Dashboard`** (default export) — The main page component that determines which dashboard UI to render:
  - In **Manhattan v2 shell** mode: renders nothing (`null`) and redirects to the Mingo home route via `useAppModeRedirect`, since Manhattan has no dashboard (its "Needs you" view lives on Start Work).
  - In **SaaS tenant** mode: renders `MingoDashboard`, since SaaS logins land on Mingo's home.
  - In **OSS tenant** mode (default): renders `DashboardContent`, the standard OSS dashboard.

## Dependencies

- `useManhattanDock` — Detects whether the Manhattan shell context is active.
- `useAppModeRedirect` — Performs conditional client-side redirection based on app mode.
- `isSaasTenantMode` — Determines whether the app is running in SaaS tenant mode.
- `routes.mingo.home` — Centralized route definition for Mingo's home page.
- `DashboardContent` — Local component rendering the OSS dashboard UI.
- `MingoDashboard` — Mingo-specific dashboard UI for SaaS tenants.

## Usage Example

```typescript
// This component is automatically rendered by Next.js routing
// when navigating to the dashboard page path.

// Example of the routing behavior it encapsulates:
import Dashboard from './page';

// Manhattan shell active -> redirects to routes.mingo.home, renders null
// SaaS tenant mode -> renders <MingoDashboard />
// OSS tenant mode (default) -> renders <DashboardContent />
```

This page acts as the landing destination after login for OSS tenants, while SaaS and Manhattan modes are redirected or routed to their respective dashboard equivalents, ensuring a consistent entry point across different deployment modes.
