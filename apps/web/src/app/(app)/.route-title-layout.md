Renders child routes unchanged; its sole purpose is to serve as a server component "anchor" that route segments can re-export in order to attach a `metadata` title, since `metadata` exports are only valid in server components and every page under `(app)` is a client component.

## Key Components

- **`RouteTitleLayout`** — Default export; a no-op server component layout that simply returns `children`. Used by route-specific `layout.tsx` files that need to export `metadata` but otherwise have no layout logic of their own.

## Usage Example

Each route segment needing a title re-exports this component alongside its own `metadata`:

```typescript
// app/(app)/devices/layout.tsx
export { default } from '@/app/(app)/route-title-layout';
export const metadata: Metadata = { title: routeTitle('Devices') };
```

Every nested route under `devices/` then inherits the "Devices" title until a deeper layout overrides it.

## Why This Pattern Exists

- `metadata` exports can only live in server components; client pages (everything under `(app)`) can't declare their own.
- Next.js commits resolved metadata into `<head>` *after* client-side effects run, so a `document.title` assignment from a client component gets silently overwritten within ~20ms of navigation.
- Rendering a `<title>` element directly from a client component doesn't help either — it just creates a second `<title>` tag, and the metadata-driven one still wins.
- This title also propagates to the desktop shell (openframe-desktop's `set_window_title`), so any route missing this layout ends up with its native window labeled using the root layout's generic marketing title instead of something meaningful.
