# action-detail-logs.tsx

Renders per-device execution logs for a software action run (install/uninstall/update), bridging a GraphQL fragment to the `SoftwareLogsTable` component. Handles loading states and gracefully no-ops when the run's action or package manager enum is unrecognized by the current build.

## Key Components

- **`ActionDetailLogs`** — Main exported component. Resolves a `SoftwareActionRun` fragment via `useFragment`, validates the `action` and `engine` fields against known enums (`SoftwareAction`, `PackageManagerType`), and renders either:
  - A loading placeholder (`SoftwareLogsRows` with empty data) while the loading scope is active
  - `null` if the fragment data is missing or contains unrecognized enum values
  - The full `SoftwareLogsTable` with resolved package manager, software name, action, and execution ID

- **`actionDetailLogsFragment`** — GraphQL fragment (`actionDetailLogs_action`) selecting `executionId`, `software`, `engine`, and `action` from `SoftwareActionRun`.

- **`ActionDetailLogsProps`** — Props interface requiring a fragment reference (`actionDetailLogs_action$key`, nullable) and `ExecutionsTabState`.

## Usage Example

```typescript
import { ActionDetailLogs } from './action-detail-logs';

function ExecutionDetailPanel({ actionRef, tabState }) {
  return (
    <ActionDetailLogs
      action={actionRef}
      state={tabState}
    />
  );
}
```

The component expects to be rendered within a `useLoadingScope`-aware context (e.g., wrapped in a Relay suspense/loading boundary) so it can display the table's native loading rows before data resolves. It relies on `knownValue` to safely map raw GraphQL enum strings to typed enums, silently rendering nothing if the action or engine value is outside the set this build recognizes.
