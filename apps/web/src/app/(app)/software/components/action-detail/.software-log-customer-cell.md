# software-log-customer-cell.tsx

Renders the "Customer" column cell for a software log table row, displaying the owning organization's logo, name, and a resolved contact email address. It uses Relay fragments to colocate its data requirements with the `Machine` type and supports a loading-skeleton state via `useLoadingScope`.

## Key Components

- **`SoftwareLogCustomerCell`** — Client component that renders the customer cell. Accepts a `machine` prop (a Relay fragment reference or `null`/`undefined`) and resolves the organization's image, name, and contact email.
- **`softwareLogCustomerCellFragment`** — GraphQL fragment (`softwareLogCustomerCell_machine`) defined on `Machine`, fetching the related `organization`'s `name`, `image` (URL + hash), and `contactInformation.contacts[].email`.

## Usage Example

```typescript
import { SoftwareLogCustomerCell } from '@/app/(app)/software-logs/components/software-log-customer-cell';
import type { softwareLogCustomerCell_machine$key } from '@/__generated__/softwareLogCustomerCell_machine.graphql';

function SoftwareLogRow({ machine }: { machine: softwareLogCustomerCell_machine$key | null }) {
  return (
    <td>
      <SoftwareLogCustomerCell machine={machine} />
    </td>
  );
}
```

**Behavior notes:**
- When rendered inside a loading scope (`useLoadingScope()` returns `true`), the fragment is not read and the component renders skeleton placeholders (via `EntityImage` and `TruncateText`'s loading states) instead of real data.
- If not loading and the organization has no `name`, the cell falls back to `ValueText` with a `null` value (typically rendering an empty/placeholder state).
- The contact email is derived using `customerContactEmail`, which picks an appropriate address from the organization's list of contacts.
- Images are resolved via `getFullImageUrl`, combining the organization's `imageUrl` and `hash` for cache-busting/CDN resolution.
