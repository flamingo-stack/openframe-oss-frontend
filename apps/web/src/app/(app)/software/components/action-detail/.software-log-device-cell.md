# software-log-device-cell.tsx

Renders the DEVICE column cell for a software log table row, displaying a device type icon, the device's name with its online status tag, and a "last online" timestamp. Supports skeleton loading states when the underlying GraphQL data is still being fetched.

## Key Components

- **`SoftwareLogDeviceCell`** — React component that accepts a Relay fragment reference (`machine`) and renders:
  - `DeviceTypeTile` — icon tile representing the device type
  - `ValueText` — the resolved device name (prioritizing nickname, display name, then hostname)
  - `Tag` — a status chip (e.g., online/offline) derived via `getDeviceStatusConfig`
  - `TruncateText` — the formatted "last seen" timestamp, with built-in loading skeleton support
- **`softwareLogDeviceCellFragment`** — GraphQL fragment (`softwareLogDeviceCell_machine`) declaring the `Machine` fields required: `nickname`, `displayName`, `hostname`, `status`, `type`, `lastSeen`.

## Usage Example

```typescript
import { SoftwareLogDeviceCell } from '@/app/components/software-log-device-cell';
import type { softwareLogDeviceCell_machine$key } from '@/__generated__/softwareLogDeviceCell_machine.graphql';

function SoftwareLogRow({ machine }: { machine: softwareLogDeviceCell_machine$key | null }) {
  return (
    <tr>
      <td>
        <SoftwareLogDeviceCell machine={machine} />
      </td>
      {/* other columns */}
    </tr>
  );
}
```

The component integrates with `useLoadingScope` to detect when it's rendered within a loading row context (e.g., during pagination or initial fetch). When loading, it skips reading the Relay fragment and renders skeleton placeholders via `TruncateText`'s `loading` prop instead of real data, ensuring consistent layout during data fetches.
