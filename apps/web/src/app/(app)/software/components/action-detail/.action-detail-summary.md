# action-detail-summary.tsx

Client component that renders the summary header for a software action run's detail page, displaying package metadata and processing progress alongside a logs section heading. It also surfaces a single, page-level not-found error when the underlying GraphQL fragment resolves to no data.

## Key Components

- **`ActionDetailSummary`** — Main exported component. Accepts an `action` prop (a `actionDetailSummary_action$key` fragment reference, nullable) and renders:
  - A `SummaryCard` with 4 columns: software name, package manager label, package version (via `ActionPackageVersion`), and processed device count (via `ProcessedDevicesCount`).
  - An `ActionDetailLogsHeading` showing the action-specific logs heading copy.
  - A `NotFoundError` when loading has finished but no data was resolved.
- **`actionDetailSummaryFragment`** — GraphQL fragment (`actionDetailSummary_action`) on `SoftwareActionRun`, fetching `software`, `engine`, `action`, `respondedMachineCount`, and `totalMachineCount`.

## Usage Example

```typescript
import { ActionDetailSummary } from './action-detail-summary';
import { graphql, useLazyLoadQuery } from 'react-relay';

function ActionDetailPage({ actionId }: { actionId: string }) {
  const data = useLazyLoadQuery(
    graphql`
      query actionDetailPageQuery($id: ID!) {
        softwareActionRun(id: $id) {
          ...actionDetailSummary_action
        }
      }
    `,
    { id: actionId }
  );

  return <ActionDetailSummary action={data.softwareActionRun} />;
}
```

This component relies on `useLoadingScope` to coordinate loading state across the page, rendering skeleton/loading bars via `LoadingWhen` while the fragment is unresolved, and gracefully falls back to `null` field values when data is unavailable (e.g., an unrecognized package manager won't render `ActionPackageVersion`).
