# software-log-search.ts

Provides client-side search/filter logic for software script execution logs, matching user-typed text against device, customer, output, and status fields of an already-loaded log row.

## Key Components

- **`softwareLogSearchFragment`** — An `@inline` GraphQL fragment (`softwareLogSearch_execution`) on `ScriptExecution` that pulls the fields needed for matching: `status`, `stdout`, `stderr`, `error`, and the related `machine` (with nickname, display name, hostname, and organization/contact info). Marked `@inline` because it's consumed by a plain predicate function rather than a React component.
- **`matchesSoftwareLog(ref, needle)`** — Reads the inline fragment data via `readInlineData` and checks whether any of the following fields contain `needle` (case-insensitive): the resolved device name, organization name, customer contact email, combined execution output, and the human-readable run status label. Returns `true` on any match.

## Usage Example

```typescript
import { matchesSoftwareLog } from './software-log-search';
import type { softwareLogSearch_execution$key } from '@/__generated__/softwareLogSearch_execution.graphql';

function filterLogs(rows: softwareLogSearch_execution$key[], searchTerm: string) {
  const needle = searchTerm.toLowerCase();
  if (!needle) return rows;
  return rows.filter(row => matchesSoftwareLog(row, needle));
}
```

This function is typically used in a table component (e.g. `SoftwareLogsTable`) to filter already-fetched rows client-side. Since the underlying GraphQL query's `search` parameter targets only the `executionId`, this predicate extends filtering to user-visible fields like device name, organization, contact email, output text, and status. Note that an empty match result still keeps the infinite-scroll sentinel mounted, allowing the search to effectively converge on the full run's data as more pages load.
