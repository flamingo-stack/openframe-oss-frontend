Maps a device software run's execution status to a human-readable label used specifically in software/script design views, where terminology differs slightly from the generic script execution status labels (e.g., "Success" instead of "Completed").

## Key Components

- **`SOFTWARE_RUN_STATUS_LABEL`** — An internal, exhaustive lookup map (`Record<ScriptExecutionStatus, string>`) pairing each `ScriptExecutionStatus` enum value with its display label for software run contexts:
  - `QUEUED` → `"Queued"`
  - `RUNNING` → `"Running"`
  - `SUCCESS` → `"Success"`
  - `FAILED` → `"Failed"`
- **`softwareRunStatusLabel(status: string): string`** — Public function that resolves a raw status string to its corresponding label via `presentationFor`. Falls back to returning the original `status` string if no match is found in the map.

## Usage Example

```typescript
import { softwareRunStatusLabel } from '@/lib/software-run-status';
import { ScriptExecutionStatus } from '@/generated/schema-enums';

// Typical usage with a known enum value
softwareRunStatusLabel(ScriptExecutionStatus.SUCCESS); // "Success"
softwareRunStatusLabel(ScriptExecutionStatus.QUEUED);  // "Queued"

// Unrecognized status falls back to the raw string
softwareRunStatusLabel('UNKNOWN_STATUS'); // "UNKNOWN_STATUS"

// Example: rendering a run status badge in a UI component
const label = softwareRunStatusLabel(run.status);
```

This helper relies on `presentationFor` from `@/lib/exhaustive-map`, which performs a type-safe, exhaustive lookup against the enum-backed map, ensuring all `ScriptExecutionStatus` values are explicitly handled at compile time.
