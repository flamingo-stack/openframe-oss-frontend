Top-level layout component for the software detail page, composing the record's header/content area and its tab navigation without wrapping them in a single suspense boundary.

## Key Components

- **`SoftwareDetailView`** — Memoized functional component that renders the software detail page layout. Accepts `softwareId` (string) and an optional `loading` flag, and composes `SoftwareDetailContent` (the record's title/card area) and `SoftwareDetailTabs` (tab navigation and tab bodies) as independent siblings rather than nesting them.

## Design Notes

Unlike typical pages that use `PageLayout` directly, this component intentionally avoids it. Since the page title *is* the fetched record, using `PageLayout` directly would cause the entire page to suspend until the record loads. Instead:

- `SoftwareDetailContent` owns its own loading/error boundary for the record data.
- `SoftwareDetailTabs` fetches its list data independently by `softwareId`, so the tab strip, search bar, and list skeleton render immediately on first paint — not blocked behind the record fetch.
- Page padding is applied by the parent (`details/page.tsx`) around a `ContentErrorBoundary`, keeping chrome layout stable even if a query throws.

## Usage Example

```typescript
import { SoftwareDetailView } from './software-detail-view';

export default function SoftwareDetailPage({ params }: { params: { id: string } }) {
  return <SoftwareDetailView softwareId={params.id} />;
}
```

Passing `loading` explicitly defers all fetching until the flag resolves:

```typescript
<SoftwareDetailView softwareId="sw-123" loading={isFlagResolving} />
```
