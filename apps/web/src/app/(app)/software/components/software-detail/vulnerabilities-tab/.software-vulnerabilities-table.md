# software-vulnerabilities-table.tsx

Renders the "Vulnerabilities" tab on a software title's detail page, listing CVEs matched to that software. Each row represents one CVE × affected version pair (a CVE hitting multiple installed versions appears once per version), with search support and sorting on discovery date only. Clicking a row opens the CVE's own detail page.

## Key Components

- **`SoftwareVulnerabilitiesTable`** — Public entry point. Wraps the reader in a `LoadingSuspense` boundary so the query suspends independently of the parent page.
- **`SoftwareVulnerabilitiesTableReader`** — Chooses between rendering placeholder rows (inside a loading scope) or firing the live GraphQL query.
- **`SoftwareVulnerabilitiesTableQuery`** — Executes `softwareVulnerabilitiesTableQuery` via `useLazyLoadQuery`, then paginates results with `usePaginationFragment` over `softwareVulnerabilitiesTable_query`.
- **`SoftwareVulnerabilitiesTableRows`** — Presentational component building the `useDataTable` instance, deciding between the section-level `EmptyState` (no CVEs at all) and the table's own "no match" row (search with no results), and rendering via `LiveTable`.
- **`COLUMNS`** — Column definitions: CVE ID (truncated text), affected version (`SoftwareVulnerabilityVersionCell`), discovered date (`SoftwareVulnerabilityDiscoveredCell`), and an `OpenRowButton` to open the CVE page in a new tab.
- **`getRowId`** — Builds a unique row key from `cveId\0affectedVersion` to avoid collisions between rows sharing a CVE.
- **`rowHref`** — Resolves a row's link target via `routes.software.vulnerability(cveId)`.

## Usage Example

```typescript
import { SoftwareVulnerabilitiesTable } from './software-vulnerabilities-table';

function SoftwareVulnerabilitiesTab({ softwareId, search, sort }: TabProps) {
  const [sortState, setSortState] = useState<DataTableSortState | null>(null);
  const [isEmpty, setIsEmpty] = useState(false);

  return (
    <SoftwareVulnerabilitiesTable
      softwareId={softwareId}
      debouncedSearch={search}
      sort={sort}
      sortState={sortState}
      onSortChange={(columnId) => setSortState(/* toggle logic */)}
      isPending={false}
      onEmptyChange={setIsEmpty}
      stickyHeaderOffset="64px"
    />
  );
}
```

Consumers should use `onEmptyChange` to hide the tab's search/sort toolbar when the title has no vulnerabilities at all, as distinct from a search yielding zero matches (handled internally by the table).
