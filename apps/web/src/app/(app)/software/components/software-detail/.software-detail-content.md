## software-detail-content.tsx

Renders the header and summary card for a single software title's detail page, handling data fetching, loading states, and "not found" reporting. The two detail tabs (which fetch their own paginated lists by software id) are mounted separately by the parent view and are intentionally not part of this component.

## Key Components

- **`softwareDetailContentQuery`** — GraphQL query fetching a software record by `id`, spreading fragments for `SoftwareDetailHeader` and `SoftwareDetailSummary`. The `software(id:)` field is nullable, so a missing/stale id resolves to `null` instead of throwing.
- **`SoftwareDetailContent`** — Public entry point. Wraps the reader in a `LoadingSuspense` boundary; accepts a `loading` flag that gates rendering before the module's own flag has resolved.
- **`SoftwareDetailContentReader`** — Checks `useLoadingScope()` to detect if rendering is inside a suspense fallback or loading window, and if so renders header/summary with `null` data (no fetch triggered).
- **`SoftwareDetailContentQuery`** — Performs the actual `useLazyLoadQuery` fetch, registers the viewed software with Mingo's "open view" tracking via `useTrackOpenView`, and renders either the summary card or a `NotFoundError`.

## Usage Example

```typescript
import { SoftwareDetailContent } from './software-detail-content';

export default function SoftwarePage({ params }: { params: { id: string } }) {
  return <SoftwareDetailContent softwareId={params.id} />;
}
```

Passing `loading` defers fetching until an upstream feature flag or module state resolves:

```typescript
<SoftwareDetailContent softwareId={softwareId} loading={isFlagLoading} />
```
