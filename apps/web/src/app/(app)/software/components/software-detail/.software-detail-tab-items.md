# software-detail-tab-items.ts

Defines the tab configuration for the Software detail page, pairing each tab's label and icon with its content component. This mirrors the pattern used by the script and customer detail pages, where the body component travels alongside the tab metadata instead of being resolved separately by the page.

## Key Components

- **`SoftwareTabBody`** — Type alias for a component accepting `softwareId` and optional `loading` props; each tab body fetches its own data by id.
- **`SOFTWARE_DETAIL_TABS`** — Array of `TabItem` entries defining the Software detail tabs: `devices` (`SoftwareDevicesTab`) and `vulnerabilities` (`SoftwareVulnerabilitiesTab`), each with an `id`, `label`, `icon`, and `component`.
- **`SOFTWARE_DEFAULT_TAB`** — The default tab id (first entry in `SOFTWARE_DETAIL_TABS`), used when `?tab=` is missing or unrecognized.
- **`softwareTabBody(tabId)`** — Resolves the body component registered for a given `tabId`, falling back to the default tab's component if no match is found.

## Usage Example

```typescript
import { SOFTWARE_DETAIL_TABS, SOFTWARE_DEFAULT_TAB, softwareTabBody } from './software-detail-tab-items';

// Render a tab strip
<TabNavigation tabs={SOFTWARE_DETAIL_TABS} defaultTab={SOFTWARE_DEFAULT_TAB} />

// Resolve a body component for a given query-param tab id
const activeTabId = searchParams.get('tab') ?? SOFTWARE_DEFAULT_TAB;
const TabBody = softwareTabBody(activeTabId);

<TabBody softwareId="software-123" loading={false} />
```

Each tab's `component` is `memo`'d at its own export (e.g., `SoftwareDevicesTab`) since `TabNavigation` defers rendering the body, invoking the render prop multiple times—on initial switch and on every query-param change.
