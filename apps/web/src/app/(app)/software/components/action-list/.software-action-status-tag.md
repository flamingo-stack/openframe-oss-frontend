Renders a status chip for Software Action rows, mapping each `SoftwareActionStatus` enum value to a visual presentation (label, color variant, and optional in-flight loader icon). It also handles a temporary backend naming mismatch where `COMPLETED` may arrive as `SUCCESS`.

## Key Components

- **`ActionStatusPresentation`** — interface describing how a status renders: `label`, `variant` (`warning` | `success` | `error` | `outline`), and optional `inFlight` flag for the loader glyph.
- **`SOFTWARE_ACTION_STATUS`** — exhaustive map (via `presentationFor`) from `SoftwareActionStatus` enum values to their `ActionStatusPresentation`.
- **`RENAMED_ACTION_STATUS`** — compatibility shim mapping the legacy/renamed `SUCCESS` string to the same presentation as `COMPLETED`, to be removed once `fetch-schema` picks up the backend rename.
- **`statusPresentation(status)`** — internal helper resolving a raw status string to its presentation, checking both the current and renamed maps.
- **`softwareActionStatusLabel(status)`** — exported function returning just the display label for a given status string, or `undefined` if unrecognized.
- **`SoftwareActionStatusTag`** — exported component rendering the `Tag` chip for a Software Actions row; falls back to a grey `Tag` with the raw status string if unknown.

## Usage Example

```typescript
import { SoftwareActionStatusTag, softwareActionStatusLabel } from '@/components/software-action-status-tag';

function ActionRow({ status }: { status: string }) {
  return (
    <div className="flex items-center gap-2">
      <SoftwareActionStatusTag status={status} />
      <span className="sr-only">{softwareActionStatusLabel(status)}</span>
    </div>
  );
}

// Example statuses:
// "SCHEDULED"   -> warning chip, "Scheduled"
// "IN_PROGRESS" -> outline chip with loader icon, "In Progress"
// "COMPLETED" or "SUCCESS" -> success chip, "Success"
// "FAILED"      -> error chip, "Failed"
// "UNKNOWN_X"   -> grey chip with raw label "UNKNOWN_X"
```
