## software-actions-table.tsx

Renders the **Software → Software Actions** table — one row per package install/update run per device, combining already-dispatched runs with runs still awaiting their schedule (the backend lists scheduled runs first). Search and the three column filters (action, engine, status) are server-driven, while the row order follows the backend's own newest-first ordering.

## Key Components

- **`SoftwareActionsTable`** — Public entry point. Wraps the reader in a `LoadingSuspense` boundary with a "Loading software actions" label.
- **`SoftwareActionsTableReader`** — Chooses between rendering placeholder rows (inside a loading scope) or firing the real Relay query.
- **`SoftwareActionsTableQuery`** — Executes `softwareActionsTableQuery` via `useLazyLoadQuery`, then paginates through `softwareActionsTable_query` fragment with `usePaginationFragment`. Derives `rows`, `totalCount`, and infinite-scroll handlers.
- **`SoftwareActionsRows`** — Builds the actual `DataTable` via `useDataTable`, applies column filters, manages placeholder rows during loading, and signals an empty-tenant state via `onEmptyChange`.
- **`buildColumns(options)`** — Constructs `ColumnDef[]` for software name, action type, engine, status, processed devices, and an "open in new tab" action column, wiring filter dropdowns to server-supplied option lists.
- **`detailsHref(row)`** — Returns a details route unless the row's status is `SCHEDULED` (no run exists yet to open).
- **`SoftwareActionSelections`** — Type describing the live (uncommitted) funnel selections, keyed by column id.
- **`SoftwareActionsTableProps`** — Props contract: deferred `backendFilters`, `debouncedSearch`, live `selections`/`onSelectionsChange`, `isPending`, `onEmptyChange`, and `stickyHeaderOffset`.

## Usage Example

```typescript
import { SoftwareActionsTable, type SoftwareActionSelections } from './software-actions-table';
import { useState } from 'react';

function SoftwareActionsPanel() {
  const [selections, setSelections] = useState<SoftwareActionSelections>({
    action: [],
    engine: [],
    status: [],
  });

  return (
    <SoftwareActionsTable
      backendFilters={null}
      debouncedSearch=""
      selections={selections}
      onSelectionsChange={setSelections}
      isPending={false}
      onEmptyChange={(isEmpty) => console.log('Table empty:', isEmpty)}
      stickyHeaderOffset="64px"
    />
  );
}
```

This component is typically rendered by a parent page that owns the search input, funnel state, and debouncing logic, passing the resolved values down as props.
