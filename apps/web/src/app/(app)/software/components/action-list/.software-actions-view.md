# software-actions-view.tsx

Client-side view component for the `/software/actions` page, rendering a filterable, searchable list of install and update actions executed across the fleet (one row per package per run). It owns URL-backed state for search and the three facet filters (action, engine, status) and coordinates deferred querying with a sticky search toolbar.

## Key Components

- **`toFilter(selections)`** — Converts `SoftwareActionSelections` into a `SoftwareActionFilterInput | null`. Returns `null` when no filters are selected, allowing both the GraphQL query and empty-state logic to treat "no selections" as "unfiltered" uniformly.
- **`SoftwareActionsView({ loading })`** — Main exported component. Responsibilities:
  - Reads/writes `search`, `action`, `engine`, `status` as URL params via `useApiParams`.
  - Debounces search input (300ms) via `useSearchParam`.
  - Memoizes filter selections for stable identity (required by `useDeferredQuery` to detect in-flight refetches).
  - Uses `useDeferredQuery` to defer both search and filter changes together, exposing a single `isPending` flag.
  - Manages sticky toolbar positioning via `useStickyToolbar`.
  - Tracks empty-result state (`isEmpty`) to conditionally hide the search toolbar.
  - Renders `PageLayout` with page actions (Update, Install buttons linking to `routes.software.update` / `routes.software.install`) and delegates row rendering to `SoftwareActionsTable`.

## Usage Example

```typescript
import { SoftwareActionsView } from './software-actions-view';

// Typically rendered inside a page shell with its own error boundary/padding
export default function SoftwareActionsPage() {
  return <SoftwareActionsView />;
}

// With an external loading flag (e.g. during route transition)
function SoftwareActionsPageWithLoading({ isNavigating }: { isNavigating: boolean }) {
  return <SoftwareActionsView loading={isNavigating} />;
}
```

Note: when `loading` is `true`, the component wraps the table in `LoadingWhen`, which suppresses fetching and renders the table's own loading state instead.
