# software-vulnerabilities-cell.tsx

A React table-cell component that renders the "VULNS" column in the Software module, showing the number of matched CVEs (Common Vulnerabilities and Exposures) for a software title, or a "no CPE match" note when the scanner found no corresponding CPE entry.

## Key Components

- **`SoftwareVulnerabilitiesCell`** — Default-exported functional component that accepts a `software` Relay fragment reference and renders either:
  - A pluralized CVE count (e.g., "3 CVEs") when `cveCount > 0`
  - An empty `ValueText` placeholder when `cveCount` is `0`
  - A secondary "no CPE match" note when `cveCount` is `0` **and** `cpeMatched` is explicitly `false`
- **`softwareVulnerabilitiesCellFragment`** — GraphQL fragment (`softwareVulnerabilitiesCell_software`) fetching `cpeMatched` and `vulnerabilitySummary.cveCount` from the `Software` type.

The component integrates with `useLoadingScope()` to detect skeleton/loading rows, passing `null` to `useFragment` in that case so `ValueText` can render its loading bar instead of attempting to read fragment data.

## Usage Example

```typescript
import { SoftwareVulnerabilitiesCell } from '@/app/components/software/software-vulnerabilities-cell';
import { graphql, useFragment } from 'react-relay';

function SoftwareRow({ softwareRef }: { softwareRef: any }) {
  return (
    <tr>
      <td>
        <SoftwareVulnerabilitiesCell software={softwareRef} />
      </td>
    </tr>
  );
}
```

**Important notes:**
- `cpeMatched === false` is the only signal that renders "no CPE match" — a `null`/`undefined` value means "unknown" and must not trigger the note.
- No severity indicator is shown since the underlying scanner does not rate CVE severity; any severity band would always render empty.
- Relies on `@flamingo-stack/openframe-frontend-core` for `TruncateText` and `useLoadingScope`, and on the shared `ValueText` component for consistent empty-state rendering.
