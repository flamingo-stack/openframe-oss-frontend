# software-table.tsx

Renders a shared software list table (one row per `Software` title) used across both the fleet-wide software inventory and per-device software lists. It handles its own loading, empty, and search-empty states via a Relay fragment and the shared `LiveTable` component.

## Key Components

- **`softwareTableFragment`** — Relay GraphQL fragment (`@relay(plural: true)`) that reads `Software` nodes plus child fragments for name, version, and vulnerabilities cells.
- **`SoftwareRow`** — Type alias for a single row's fragment data.
- **`COLUMNS`** — Column definitions (name, current version, vulnerabilities, open-in-new-tab) built from `SOFTWARE_LIST_COLUMNS`, each rendering a dedicated cell component.
- **`LoadedSoftwareTable`** — Internal component that resolves the fragment, builds the table via `useDataTable`, decides between the real empty state vs. a "no search match" row, and notifies the parent via `onEmptyChange`.
- **`SoftwareTableLoading`** — Internal component rendering `LiveTable` with placeholder/skeleton rows when data hasn't loaded yet.
- **`SoftwareTable`** (exported) — Entry point component that switches between `SoftwareTableLoading` and `LoadedSoftwareTable` based on whether `rows` is present in props.
- **`SoftwareTableProps`** — Props interface: `rows` (Relay fragment key), `totalCount`, `debouncedSearch`, `isPending`, `emptyState`, `onEmptyChange`, `stickyHeaderOffset`, `infiniteScroll`.

## Usage Example

```typescript
import { SoftwareTable } from '@/app/components/software/software-table';

function FleetSoftwareList() {
  const [isEmpty, setIsEmpty] = useState(false);

  if (!queryData) {
    return <SoftwareTable stickyHeaderOffset="64px" />;
  }

  return (
    <SoftwareTable
      rows={queryData.softwares}
      totalCount={queryData.filteredCount}
      debouncedSearch={search}
      isPending={isRefetching}
      emptyState={<EmptySoftwareState />}
      onEmptyChange={setIsEmpty}
      stickyHeaderOffset="64px"
      infiniteScroll={<LoadMoreTrigger onLoadMore={loadNext} />}
    />
  );
}
```

Each caller (fleet inventory, device software list) owns its own query, pagination, and narrowing, and simply spreads its connection nodes into this component's `rows` prop.
