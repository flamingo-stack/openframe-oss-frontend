Defines the static, data-only column layout configuration for the Software table, shared across both the fleet-wide Software page and a device's Software tab. Kept free of imports and JSX so it can be reused as a lightweight schema for rendering, loading skeletons, and pagination.

## Key Components

- **`SOFTWARE_LIST_COLUMNS`** — A `const` object satisfying `Record<string, TableSkeletonColumn>` that describes each table column:
  - `name` — Software name column, flexible width.
  - `currentVersion` — Current version column, flexible width, hidden below the `md` breakpoint.
  - `vulnerabilities` — CVE count column (`cveCount` id), fixed narrow width.
  - `open` — Trailing action/expand column, fixed width, right-aligned.
- **`SOFTWARE_LIST_PAGE_SIZE`** — Re-exported page size constant, aliased from `FLEET_LIST_PAGE_SIZE` to keep Software list pagination consistent with the rest of the fleet list views.

## Usage Example

```typescript
import { SOFTWARE_LIST_COLUMNS, SOFTWARE_LIST_PAGE_SIZE } from './software-list-columns';
import { TableColumnLayout } from '@/app/components/shared/table-column-layout';

// Render the table header/skeleton using the shared column definitions
<TableColumnLayout columns={Object.values(SOFTWARE_LIST_COLUMNS)} />

// Use the shared page size for fetching paginated software data
const { data } = useSoftwareList({ pageSize: SOFTWARE_LIST_PAGE_SIZE });
```

This module should remain pure data (no components or side effects) since it is consumed by multiple rendering contexts, including skeleton loaders that need the column shape without any UI logic. See [`table-column-layout.ts`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/components/shared/table-column-layout.ts) for the rationale behind this pattern.
