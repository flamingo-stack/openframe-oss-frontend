# fleet-list-paging.ts

Defines shared constants that govern paging size and search debounce timing for Fleet-backed lists (software titles, CVEs, and associated devices). These values exist to mitigate backend performance characteristics: Fleet rebuilds the entire list in memory on every request rather than paging at the source, so the number of requests—not the page size—drives server load.

## Key Components

- **`FLEET_LIST_PAGE_SIZE`** — Number of items fetched per page (`100`). Larger pages reduce the number of full-list rebuilds needed to scroll through results.
- **`FLEET_SEARCH_DEBOUNCE_MS`** — Debounce delay in milliseconds (`500`) applied to search input before triggering a backend request. Prevents a rebuild on every keystroke.

## Usage Example

```typescript
import { FLEET_LIST_PAGE_SIZE, FLEET_SEARCH_DEBOUNCE_MS } from './fleet-list-paging';
import { debounce } from 'lodash-es';

async function fetchSoftwareTitles(page: number, query: string) {
  return api.getSoftwareTitles({
    page,
    pageSize: FLEET_LIST_PAGE_SIZE,
    query,
  });
}

const debouncedSearch = debounce((query: string) => {
  fetchSoftwareTitles(0, query);
}, FLEET_SEARCH_DEBOUNCE_MS);
```

## Notes

These constants are intentionally conservative client-side mitigations. Because Fleet does not support true server-side paging, both values should be tuned together: increasing `FLEET_LIST_PAGE_SIZE` reduces rebuild frequency during scrolling, while `FLEET_SEARCH_DEBOUNCE_MS` reduces rebuild frequency during typing. Any component consuming Fleet-backed lists (software, CVEs, devices) should import these shared values rather than hardcoding paging or debounce behavior.
