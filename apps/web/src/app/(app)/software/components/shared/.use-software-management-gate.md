# use-software-management-gate.ts

A client-side gating hook that guards access to all `/software` routes based on the `software-management` feature flag, triggering a 404 only on a definitive "off" response.

## Key Components

- **`useSoftwareManagementGate()`** — Hook returning `'loading' | 'on'` for the current feature flag state. Internally wraps `useFeatureFlagGate('software-management')` from `use-feature-flag.ts`.
  - If the flag resolves to `'off'`, it calls Next.js `notFound()`, which throws and renders the 404 page.
  - If the flag is `'loading'` or `'on'`, the value is returned as-is so the calling page can render its own loading skeleton or the actual content.

This design intentionally avoids throwing `notFound()` while the flag state is still unresolved (`loading`), since that would be unrecoverable and could incorrectly 404 a tenant who actually has access — the throw only happens once the answer is a confirmed `'off'`.

## Usage Example

```typescript
'use client';

import { useSoftwareManagementGate } from '@/app/hooks/use-software-management-gate';
import { SoftwarePageSkeleton } from '@/app/components/software-page-skeleton';
import { SoftwareDashboard } from '@/app/components/software-dashboard';

export default function SoftwarePage() {
  const gate = useSoftwareManagementGate();

  if (gate === 'loading') {
    return <SoftwarePageSkeleton />;
  }

  // gate === 'on' — flag confirmed enabled
  return <SoftwareDashboard />;
}
```

Every route under `/software` should call this hook at the top of the page component. Other surfaces referencing the software feature (e.g., sidebar navigation links or the Mingo command picker) should instead use the plain `useFeatureFlagGate` hook directly, since those UI elements can safely render late without needing the 404 guard.
