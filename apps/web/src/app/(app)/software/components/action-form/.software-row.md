# software-row.ts

Defines the shape of software package input data used in mutations and provides a helper to convert UI-level software rows into mutation-ready package inputs, validating that all rows are fully populated.

## Key Components

- **`PackageInput`** — Interface representing a single package entry as expected by GraphQL mutations, containing `packageManager`, `packageName`, and `brewPackageType`.
- **`toPackageInputs(rows: SoftwareRow[]): PackageInput[] | null`** — Converts an array of `SoftwareRow` objects (UI state) into an array of `PackageInput` objects. Returns `null` if any row is missing a selected package (`pkg`), signaling that the form/mutation is not yet ready to submit.

## Usage Example

```typescript
import { toPackageInputs, type PackageInput } from './software-row';
import type { SoftwareRow } from '@flamingo-stack/openframe-frontend-core/components/features';

function handleSubmit(rows: SoftwareRow[]) {
  const inputs: PackageInput[] | null = toPackageInputs(rows);

  if (!inputs) {
    console.warn('Some software rows are incomplete — cannot submit yet.');
    return;
  }

  // Safe to pass to mutation now that every row has a resolved package
  submitInstallMutation({ packages: inputs });
}
```

**Notes:**
- The `packageName` is derived from the selected package's catalog `id`, since that id matches the identifier the underlying package manager uses to install it.
- `brewPackageType` is only populated when `packageManager` is `PackageManagerType.BREW`; otherwise it's `null`.
- Use the `null` return value as a guard to disable submission in the UI until all rows have a selected package.
