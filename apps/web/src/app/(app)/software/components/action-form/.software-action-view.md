# software-action-view.tsx

Container component that renders the "Install Software" and "Update Software" forms by wrapping the shared `SoftwareActionForm` from `@flamingo-stack/openframe-frontend-core`. It bridges the generic form library to app-specific concerns: device filtering, draft bundle management, feature flag gating, and submission handling.

## Key Components

- **`SoftwareActionView`** — Main exported component. Accepts an `action` (`SoftwareAction` enum) and a `loading` flag, and renders the full software action form, wiring up back navigation, feature-flag-gated update settings/notifications, and submit logic.
- **`renderPackageSearch`** — Slot renderer for the package catalog search field, wrapped in an `ErrorBoundary` (keyed by package manager) so a failed search doesn't crash the whole form.
- **`ScopedBundleDevicePicker`** — Internal component that scopes the device picker to online/offline devices matching the selected OS types, memoizing the filter by `osTypesKey`.
- **`SCHEDULE_TIMING`** — Static config object implementing date/time/timezone logic for scheduling, reusing script-schedule semantics (`earliestScheduleDay`, `getTimeSlotOptions`, past-start validation).
- **`agentMissing`** — Helper that disables device selection when a device has no connected agent (`machineId`).

## Usage Example

```typescript
import { SoftwareActionView } from './software-action-view';
import { SoftwareAction } from '@/generated/schema-enums';

export default function InstallSoftwarePage() {
  return <SoftwareActionView action={SoftwareAction.INSTALL} />;
}
```

```typescript
// With a loading state while feature flags resolve
<SoftwareActionView action={SoftwareAction.UPDATE} loading={isFlagsLoading} />
```

**Notes on architecture:**
- Device selection is **not** local component state — it lives on a server-side "draft bundle" (`useDraftBundle`), and each device assignment edits that bundle directly, so submission only passes `bundleId` and `deviceCount`.
- The device picker remounts (via `key={osTypesKey}`) whenever the OS scope changes, intentionally resetting search/filter state rather than refetching in place.
- `updateSettingsGate` and `updateNotificationsGate` are feature flags (`useFeatureFlagGate`) controlling whether update-specific UI and submission fields are shown.
