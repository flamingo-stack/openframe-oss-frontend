# use-bundle-device-assignment.ts

React hook that manages device assignment writes for a software bundle's device picker, handling both single-row toggles (optimistic, incremental) and bulk "add all / remove all" actions (server-resolved, network-refreshed).

## Key Components

- **`useBundleDeviceAssignment(options)`** — Main hook accepting `bundleId`, the live `filter`/`search` (what the user currently sees), and the `deferredFilter`/`deferredSearch` (the narrowing the mounted picker queries were actually read with). Returns `{ busy, addDevice, removeDevice, addAllDevices, removeAllDevices }`.
- **`addDevice(device)` / `removeDevice(device)`** — Single-row mutations (`useBundleDeviceAssignmentAddMutation`, `...RemoveMutation`) that apply an optimistic connection update via `assignmentUpdaters`. Guarded by an in-flight `Set` ref so a row can't double-fire before its write lands, and blocked entirely while a bulk action is `busy`.
- **`addAllDevices()` / `removeAllDevices()`** — Bulk mutations (`useBundleDeviceAssignmentAddAllMutation`, `...RemoveAllMutation`) resolved server-side against the current filter/search, then followed by `refreshLists` to re-fetch both the available and assigned connections.
- **`busy`** — `true` while either bulk mutation is in flight; used to lock the picker UI.
- **`refreshLists(bundleId)`** — Internal helper that re-fetches `bundlePickerListsAvailableQuery` and `bundlePickerListsAssignedQuery` with `network-only` policy, keyed by the deferred narrowing.

## Usage Example

```typescript
const {
  busy,
  addDevice,
  removeDevice,
  addAllDevices,
  removeAllDevices,
} = useBundleDeviceAssignment({
  bundleId: draftBundle.id,
  filter: liveFilter,
  search: liveSearch,
  deferredFilter,
  deferredSearch,
});

// Single-row toggle, optimistic and instant
<DeviceRow device={device} onToggle={() => addDevice(device)} />

// Bulk action, disabled while busy, refreshes lists on completion
<Button disabled={busy} onClick={addAllDevices}>
  Add All Matching Devices
</Button>
```

Note: filter/search narrowing is read via refs at click time (`narrowingRef`, `queryVarsRef`) rather than closed over directly, keeping handler identities stable while still reflecting the latest committed values.
