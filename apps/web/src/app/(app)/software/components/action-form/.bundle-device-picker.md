## Overview

`bundle-device-picker.tsx` implements the "Device Selection" UI for the Install/Update Software bundle form. It manages device search, tab selection, and filter narrowing within a given scope, delegating actual assignment mutations to `useBundleDeviceAssignment`, and isolates failures in its own error boundary so a failed query doesn't discard the user's in-progress package selection.

## Key Components

- **`BundleDevicePicker`** — Top-level exported component. Wraps everything in a `ContentErrorBoundary`, surfaces draft-creation errors via `ThrowError`, and shows a loading state (`LoadingWhen`) until `bundleId` is available.
- **`BundleDevicePickerBody`** — Wraps the lists in a `LoadingSuspense` boundary so device queries draw their own loading UI.
- **`BundleDevicePickerLists`** — Owns local UI state (`activeTab`, `search`, `narrowing`), debounces search input, computes the effective filter via `narrowWithinScope`, and wires add/remove handlers from `useBundleDeviceAssignment` into `BundlePickerLists`.
- **`narrowWithinScope(scope, narrowing)`** — Merges user-chosen facets with the form's base scope; untouched dimensions fall back to the scope's values, keeping selections a subset of the allowed scope.
- **`ThrowError`** — Helper that re-throws a draft-creation error so the surrounding `ContentErrorBoundary` renders the same error card/Retry UX as a failed query.

## Usage Example

```typescript
import { BundleDevicePicker } from './bundle-device-picker';

function InstallSoftwareForm() {
  const { bundleId, createError, retryCreate } = useDraftBundle();

  return (
    <BundleDevicePicker
      bundleId={bundleId}
      createError={createError}
      onRetryCreate={retryCreate}
      scope={{ osTypes: ['windows'], statuses: ['online'] }}
      isDeviceDisabled={(device) => (device.locked ? 'Device is locked' : undefined)}
    />
  );
}
```

The component requires a `bundleId` (or `null` while the draft is being created), a `scope` defining which devices are eligible (e.g., matching OS and live status), and optional `isDeviceDisabled` logic to disable specific rows in the device lists.
