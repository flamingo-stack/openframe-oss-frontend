# bundle-picker-lists.tsx

Implements the dual-list device picker (Available/Selected tabs) for assigning devices to a software bundle. Both lists are server-driven Relay connections scoped to the bundle, with search, filters, and pagination resolved on the backend rather than the client.

## Key Components

- **`BUNDLE_PICKER_CONNECTION_KEYS`** — Exported `@connection` keys (`bundlePickerLists_availableDevices`, `bundlePickerLists_assignedDevices`) used by mutation store-updaters to target the picker's lists directly after a single add/remove.
- **`bundlePickerListsAvailableQuery` / `bundlePickerListsAssignedQuery`** — GraphQL queries fetching the bundle's available and assigned device connections respectively, each paginated and filterable.
- **`availableFragment` / `assignedFragment`** — Refetchable fragments backing `usePaginationFragment`, exposing `filteredCount`, edges (with `assigned` flag on the available side), and `pageInfo`.
- **`BundlePickerLists`** — Public component. Checks `useLoadingScope()` and renders a disabled/empty `ServerDevicePickerLists` during loading, otherwise delegates to `BundlePickerListsQuery`.
- **`BundlePickerListsQuery`** — Core logic: issues both queries with `store-and-network` fetch policy (keyed by `useRetryKey` for boundary-driven retries), wires pagination fragments, and renders the two lists wrapped in a `ContentErrorBoundary` plus `BundleDeviceFacets` for filter options.
- **`BundleDeviceFacets`** — Isolates the facet/filter-options read (`useBundleDeviceFilters`) behind its own render-prop boundary so a facet failure only costs the filter funnels, not the whole picker.

## Usage Example

```typescript
import { BundlePickerLists, BUNDLE_PICKER_CONNECTION_KEYS } from './bundle-picker-lists';

function BundleDeviceAssignment({ bundleId, osScope }: { bundleId: string; osScope: DeviceFilterInput }) {
  const [activeTab, setActiveTab] = useState<SubTab>('available');
  const [search, setSearch] = useState('');
  const [narrowing, setNarrowing] = useState<DeviceSelectorNarrowing>({});

  return (
    <BundlePickerLists
      bundleId={bundleId}
      scope={osScope}
      activeTab={activeTab}
      onTabChange={setActiveTab}
      search={search}
      onSearchChange={setSearch}
      narrowing={narrowing}
      onNarrowingChange={setNarrowing}
      deferredFilter={osScope}
      deferredSearch={search}
      busy={false}
      onAdd={(device) => console.log('add', device)}
      onRemove={(device) => console.log('remove', device)}
      onAddAll={() => console.log('add all')}
      onRemoveAll={() => console.log('remove all')}
    />
  );
}
```

Mutations affecting a single device should target `BUNDLE_PICKER_CONNECTION_KEYS` in their Relay store updaters so the lists update without a network refetch.
