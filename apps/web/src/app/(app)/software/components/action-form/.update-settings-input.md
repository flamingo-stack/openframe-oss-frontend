Converts the "Update Settings" form model (`SoftwareUpdateSettingsValues`) used in the UI into the GraphQL submit payload shapes (`PackageUpdateSettingsInput` and `SoftwareAutoUpdateInput`) expected by the backend mutation.

## Key Components

- **`PackageUpdateSettingsInput`** — Submit-ready shape describing an update policy: `mode` (`WAIT`/`FORCE`), `deadlineSeconds` (nullable), and `countdownSeconds`.
- **`SoftwareAutoUpdateInput`** — Submit-ready shape describing auto-update behavior: `enabled` flag plus optional nested `settings` (null means "use the same settings as the main update policy").
- **`toPolicyInput(policy)`** — Internal helper that maps a UI `SoftwareUpdatePolicy` (`mode`, `deadlineEnabled`, `deadlineSeconds`, `countdownSeconds`) into a `PackageUpdateSettingsInput`, nulling out the deadline for `FORCE` mode or when the deadline toggle is off.
- **`toUpdateSettingsInputs(settings)`** — Main exported function that converts a full `SoftwareUpdateSettingsValues` form value into `{ updateSettings, autoUpdate }` ready for the mutation submit.

## Usage Example

```typescript
import { toUpdateSettingsInputs } from './update-settings-input';
import type { SoftwareUpdateSettingsValues } from '@flamingo-stack/openframe-frontend-core/components/features';

function buildMutationVariables(formValues: SoftwareUpdateSettingsValues) {
  const { updateSettings, autoUpdate } = toUpdateSettingsInputs(formValues);

  return {
    input: {
      updateSettings,
      autoUpdate,
    },
  };
}
```

When `settings.autoUpdate` is `true` and `sameForAutoUpdate` is `false`, the auto-update policy is independently converted via `toPolicyInput`; otherwise `autoUpdate.settings` is `null`, signaling the server to reuse the main update policy.
