Next.js client page component that renders the Software Vulnerabilities section, displaying a list of detected software vulnerabilities within the shared software management page layout.

## Key Components

- **`SoftwareVulnerabilitiesPage`** — Default-exported page component that composes the vulnerabilities view.
- **`useSoftwareManagementGate`** — Hook that returns a gate state (e.g., `'loading'`) used to control loading behavior before data/access checks resolve.
- **`SoftwarePageShell`** — Shared layout wrapper providing consistent title, section context, and error handling (`errorMessage`) across software management pages.
- **`SOFTWARE_SECTIONS.vulnerabilities.label`** — Centralized label metadata used for the page title, ensuring consistency with navigation/menu entries.
- **`VulnerabilityListView`** — Core content component rendering the actual list of vulnerabilities, driven by the `loading` prop derived from the gate.

## Usage Example

```typescript
// This file is a Next.js route entry (e.g., app/software/vulnerabilities/page.tsx)
// It is rendered automatically by the Next.js App Router when navigating to
// the "Software > Vulnerabilities" section.

// Example of the pattern used internally:
import { SoftwarePageShell } from '../components/shared/software-page-shell';
import { VulnerabilityListView } from '../components/vulnerability-list/vulnerability-list-view';

function ExamplePage() {
  const gate = useSoftwareManagementGate();

  return (
    <SoftwarePageShell section="vulnerabilities" title="Vulnerabilities">
      <VulnerabilityListView loading={gate === 'loading'} />
    </SoftwarePageShell>
  );
}
```

This component requires no props since it's a route-level page; it relies entirely on shared hooks and shell components for state and layout. The `useSoftwareManagementGate` hook likely checks feature entitlement or data readiness before allowing the vulnerability list to render fully.
