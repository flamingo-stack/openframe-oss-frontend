# use-initial-setup-active.ts

A React hook that acts as the single source of truth for determining whether the tenant's "Initial Setup" onboarding flow is currently active, ensuring the dashboard dimming overlay and the Initial Setup card stay in sync.

## Key Components

- **`useInitialSetupActive()`** — Hook returning a `boolean` indicating whether Initial Setup onboarding is active. Returns `true` only when:
  - Onboarding progress has finished loading (`isLoaded`)
  - A real tenant progress record exists (`!!tenant`)
  - That tenant record is not yet marked `completed`

## Usage Example

```typescript
import { useInitialSetupActive } from '@/hooks/use-initial-setup-active';

function DashboardOverlay() {
  const isSetupActive = useInitialSetupActive();

  if (!isSetupActive) return null;

  return <div className="dimming-overlay" />;
}
```

```typescript
import { useInitialSetupActive } from '@/hooks/use-initial-setup-active';
import { InitialSetupCard } from '@/components/initial-setup-card';

function Dashboard() {
  const isSetupActive = useInitialSetupActive();

  return (
    <>
      {isSetupActive && <InitialSetupCard />}
      {/* other dashboard content */}
    </>
  );
}
```

## Important Notes

- The `!!tenant` guard prevents a critical bug: `refreshOnboardingProgress` can mark the store as loaded even when the fetch fails or returns empty (leaving `tenant` as `null`). Without this guard, a null tenant could be misinterpreted as "not completed," causing the overlay to show while the card correctly stayed hidden.
- This hook guarantees one-directional consistency: whenever it returns `true`, the Initial Setup card is guaranteed to be visible (either its content or Suspense skeleton). However, the card may remain visible in a "completed" victory state for the session even after this hook returns `false` — that asymmetry is intentional.
