## useTenantOnboardingAutoDetect

A React hook that derives tenant "Initial Setup" onboarding step completion directly from live workspace data (MSP profile, customers, devices), and silently persists any newly-detected completions to the backend via background mutations.

This is a **temporary** client-side workaround until the backend's `tenantOnboardingProgress` query computes completion itself. Once that lands, this hook should be deleted and `completedSteps` read straight from the store.

## Key Components

- **`DataDetectableStep`** — Type alias enumerating the only `TenantOnboardingStep` values whose completion can be derived from data (`MSP_SETUP`, `CUSTOMERS_SETUP`, `DEVICE_MANAGEMENT`). `MEET_MINGO` is intentionally excluded since no query can confirm it.
- **`useTenantOnboardingAutoDetect()`** — Main hook. Returns a `Set<TenantOnboardingStep>` representing steps whose completion is currently inferable from data:
  - `MSP_SETUP`: tenant has name, website, and logo image all set
  - `CUSTOMERS_SETUP`: at least one non-default organization exists
  - `DEVICE_MANAGEMENT`: at least one device with `ONLINE`/`OFFLINE` status (excludes `ARCHIVED`/`PENDING`)
- **`AUTO_DETECT_VARIABLES`** / **`AUTO_DETECT_OPTIONS`** — Module-level constants providing stable references for the Relay query variables (device status filter) and fetch policy (`store-and-network`, to refresh on mount without re-suspending on re-render).

## Usage Example

```typescript
import { Suspense } from 'react';
import { useTenantOnboardingAutoDetect } from './use-tenant-onboarding-auto-detect';

function InitialSetupStepsInner() {
  const completedByData = useTenantOnboardingAutoDetect();

  const isDeviceManagementDone = completedByData.has(TenantOnboardingStep.DEVICE_MANAGEMENT);

  return (
    <div>
      {isDeviceManagementDone ? 'Devices connected' : 'Waiting for a device...'}
    </div>
  );
}

// MUST be rendered only while onboarding is active, and wrapped in Suspense —
// the hook's query read suspends and has no mount gate of its own.
export function InitialSetupCard() {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <InitialSetupStepsInner />
    </Suspense>
  );
}
```

**Important usage notes:**
- Must be mounted only while onboarding is active, inside a `Suspense` boundary.
- The returned set is a statement about workspace *data*, not about what the user has manually checked off — callers should union it with persisted `completedSteps` for display purposes.
- Completion mutations fire one step at a time per mount to avoid race conditions, since each mutation overwrites the full `completedSteps` list.
