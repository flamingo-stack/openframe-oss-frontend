# onboarding-content.tsx

Renders the user-facing "Get Started" onboarding page: a header with progress and a skip action, a book-a-call offer, and accordion groups of interactive steps (tickets, scripting, monitoring, logging, knowledge base, Mingo). Handles loading states, onboarding v2 feature-flag redirection, hash-based deep linking to a specific step, lockout for already-completed users, and auto-commits completion when every step is done.

## Key Components

- **`OnboardingContent`** — Top-level mount gate. Reads tenant/user onboarding state from `useOnboardingStore`, redirects to the dashboard when onboarding v2 is on, initial tenant setup isn't complete, or the user already finished the tour (captured via a one-shot `completedOnArrival` snapshot). Wraps the reader in `LoadingSuspense` so rows render their own skeletons while data loads.
- **`OnboardingContentReader`** — Switches between `OnboardingView` (loading scope, no data) and `LoadedOnboardingContent` (interactive, real progress) based on `useLoadingScope()`.
- **`useHashStep`** — Syncs the step opened by the URL hash (e.g. `#step-tickets`) using `useSyncExternalStore`, so the loading and loaded views open the same row.
- **`OnboardingView`** — Presentational component rendering the page header (title, progress subtitle, Skip action), the `OnboardingCompleteBanner` when all steps are done, `BookCallSection`, and `OnboardingAccordionGroup`/`OnboardingAccordionItem` rows for each step in `USER_ONBOARDING_GROUPS`.
- **`STEP_BODY`** — Maps each `UserOnboardingStepId` to its interactive body component (`TicketsStep`, `ScriptingStep`, `MonitoringStep`, `LoggingStep`, `KnowledgeBaseStep`, `MingoStep`).
- **`StepBodyProps`** — Shared prop contract (`completed`, `completing`, `onComplete`, `onCompleteBackground`, `expanded`) implemented by every step body.

## Usage Example

```typescript
// Rendered by the /onboarding route (see app/lib/routes.ts)
import { OnboardingContent } from '@/app/onboarding/components/onboarding-content';

export default function OnboardingPage() {
  return <OnboardingContent />;
}
```

Deep linking to a specific step uses a URL hash that matches `onboardingStepAnchorId`:

```text
https://app.example.com/onboarding#step-tickets
```

For the full implementation (including `LoadedOnboardingContent`, mutation wiring, and the auto-advance accordion logic), see the source file at [`onboarding-content.tsx`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/onboarding/components/onboarding-content.tsx).
