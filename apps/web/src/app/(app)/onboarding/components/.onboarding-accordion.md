Accordion UI primitives for the onboarding flow, providing a collapsible step-by-step interface with `active`, `completed`, and `disabled` states.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `OnboardingAccordionItem` | Component | Single accordion row with icon, title, description, and animated expand/collapse body |
| `OnboardingAccordionGroup` | Component | Wrapper that groups multiple items in a bordered, rounded container with an optional section label |
| `OnboardingStepStatus` | Type | Union type: `'active' \| 'completed' \| 'disabled'` |
| `OnboardingAccordionItemProps` | Interface | Props for `OnboardingAccordionItem` |
| `OnboardingAccordionGroupProps` | Interface | Props for `OnboardingAccordionGroup` |

**Internal:** `InlineTextSkeleton` — inline `<span>` skeleton bar that preserves row height during loading without layout shift.

## Usage Example

```typescript
import {
  OnboardingAccordionGroup,
  OnboardingAccordionItem,
} from './onboarding-accordion';
import { IdCardIcon } from '@flamingo-stack/openframe-frontend-core/components/icons-v2';

// Basic controlled usage (e.g. driven by useOnboardingAutoAdvance)
<OnboardingAccordionGroup label="GETTING STARTED">
  <OnboardingAccordionItem
    id="step-add-customer"
    icon={<IdCardIcon size={24} />}
    title="Add a Customer"
    description="Set up your first customer record."
    status="completed"
  />
  <OnboardingAccordionItem
    id="step-configure-alerts"
    icon={<IdCardIcon size={24} />}
    title="Configure Alerts"
    description="Set up notification rules."
    status="active"
    expanded={isExpanded}
    onExpandedChange={setIsExpanded}
  >
    {/* Step body form goes here */}
  </OnboardingAccordionItem>
  <OnboardingAccordionItem
    icon={<IdCardIcon size={24} />}
    title="Invite Team"
    description="Add your technicians."
    status="disabled"
    requirementHint="Add Customer required"
  />
</OnboardingAccordionGroup>
```

## Notes

- Expand/collapse animates via `grid-rows: 0fr → 1fr` transition, supporting dynamic content heights.
- `disabled` and `loading` steps never mount child content, preventing premature data-fetching hooks from running.
- Supports both **uncontrolled** (`defaultExpanded`) and **controlled** (`expanded` + `onExpandedChange`) modes — the controlled path integrates with `useOnboardingAutoAdvance`.
- The `data-onboarding-step-body` attribute on the body wrapper is a hook consumed by `useOnboardingAutoAdvance` for scroll offset calculations.
