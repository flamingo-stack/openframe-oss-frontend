# company-team-step.tsx

A React client component implementing the "Company & Team" onboarding step, allowing users to invite teammates to OpenFrame via email. **Currently unreferenced** in the active onboarding flow—it was replaced by a "Meet Mingo" step—but is kept intact for potential future use. Team invitations remain reachable via Settings → Company & Users.

## Key Components

- **`CompanyTeamStep`** — Main exported component rendering a dynamic list of email/role invite rows with add/remove controls, a "Manage Roles" link to the employees settings page, and footer actions to mark the step complete and/or send invites.
- **`InviteRow`** — Local type representing a single invite entry (`email`, `role`).
- **`companyTeamStepInviteMutationNode`** — GraphQL mutation (`inviteUsers`) used to submit invite emails via `react-relay`.
- **`EMAIL_REGEX`** — Simple email validation pattern used to enable/disable submission and show inline validation errors.
- **`ROLE_OPTIONS`** — Static list of selectable roles (currently only `ADMIN`).

The component relies on shared helpers: `useStepActionState` (manages busy/loading state for "complete" and "primary" actions), `invalidateInvitationsListings` / `invitationsListingId` (cache invalidation for the employees invitations list), and `describeInviteRefusals` (formats per-email mutation errors).

## Usage Example

```typescript
import { CompanyTeamStep } from './company-team-step';

function OnboardingFlow() {
  const [stepCompleted, setStepCompleted] = useState(false);

  return (
    <CompanyTeamStep
      completed={stepCompleted}
      completing={false}
      onComplete={() => setStepCompleted(true)}
    />
  );
}
```

**Behavior notes:**
- Users can add/remove rows (minimum one row always remains) and enter emails with a role per row.
- The "Send Invites" button is enabled only when at least one row has a valid email.
- On successful invite submission, the step auto-completes via `onComplete`—but only the first time, preventing re-triggering on subsequent invites after completion.
- Invite failures (including per-email backend rejections) surface via toast notifications using `getRelayErrorMessage` and `describeInviteRefusals`.
