## Overview

Client component that renders the "Initial Setup" onboarding card on the tenant dashboard. It gates on the onboarding store's loading state, suspends on live-data detection, and coordinates a 4-step onboarding checklist (MSP Setup, Customers Setup, Device Management, Meet Mingo) with per-step completion tracking, accordion-style expand/collapse behavior, and data-driven lock gates for steps that require prerequisite data to exist.

## Key Components

- **`InitialSetupCard`** — Top-level mount gate. Renders nothing until the onboarding store reports `isLoaded`; hides permanently once setup is complete, using a `shown` latch to avoid hiding mid-render when completion flips in the background.
- **`InitialSetupCardReader`** — Chooses between the static `InitialSetupCardView` (while in a loading scope) and the data-driven `InitialSetupCardContent`.
- **`InitialSetupCardView`** — Pure presentational component rendering the section header, progress line, `BookCallSection`, the four `OnboardingAccordionItem` rows, and the `OnboardingCompleteBanner` when all steps are done. Accepts optional props so it can render a skeleton/loading state with no data.
- **`InitialSetupCardContent`** — Data-wired version: reads tenant state and `useTenantOnboardingAutoDetect` for data-based completion, manages per-step "Mark as Complete" mutations via `useOnboardingMutations`, auto-commits tenant completion once all steps are done, and dispatches to the correct step body (`MspSetupStep`, `CustomerSetupStep`, `DeviceSetupStep`, `MingoStep`).
- **`STEP_META`** — Static metadata (icon, title, description, optional `requiresData` gate) for the four onboarding steps.
- **`StepMeta`** — Type describing a step's static presentation and optional data precondition.

## Usage Example

```typescript
import { InitialSetupCard } from '@/app/(dashboard)/onboarding/initial-setup-card';

export default function DashboardPage() {
  return (
    <div className="flex flex-col gap-6">
      {/* Renders nothing if onboarding is already complete or store not loaded */}
      <InitialSetupCard />
    </div>
  );
}
```

The component requires no props — it reads tenant and onboarding progress directly from `useOnboardingStore` and `useOnboardingMutations`. It is intended to be mounted once, typically on the main dashboard, and manages its own visibility lifecycle internally.
