Renders the tenant onboarding "Initial Setup" card on the Dashboard, managing a four-step guided flow (MSP Setup, Customers, Device Management, Company & Team) with background completion; it draws nothing until the onboarding store says setup is active, then its own loading state.

## Key Components

### `InitialSetupCard` (exported)
Mount gate component. Renders nothing until onboarding progress has loaded and a tenant record exists. Permanently hides after `tenant.completed` is set, with a ref-latch to keep the "Setup Complete" victory view visible during the current mount.

### `InitialSetupCardContent` (internal)
The card body. Suspends via `useTenantOnboardingAutoDetect` until all step counts resolve. Merges backend-persisted `completedSteps` with live-data-derived completions. Auto-commits `completeTenantInBackground` exactly once when all steps are done. Delegates accordion expand/collapse and scroll-into-view to `useOnboardingAccordion`.

### `InitialSetupCardView` (internal)
The card from props. While progress is read it is rendered in a loading scope (through `GatedSuspense` with `bare`), where its rows draw their own loading state, so the loading → loaded transition has no layout shift.

### `STEP_META` (internal constant)
Single source of truth for the four steps' icons, titles, and descriptions — shared by the loaded and the loading card.

## Usage Example

```typescript
// Dashboard layout — the card owns its loading state and its Suspense boundary
import { InitialSetupCard } from './initial-setup-card';

export function DashboardContent() {
  return <InitialSetupCard />;
}
```

The card self-hides when `tenant.completed === true`, so no conditional rendering is needed at the call site.
