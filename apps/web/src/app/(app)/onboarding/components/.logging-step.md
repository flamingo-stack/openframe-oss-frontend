# logging-step.tsx

Renders the "Logging" step of the onboarding flow, showing a live preview of the activity/logs table populated with real data, plus actions to mark the step complete or navigate to the full logs page.

## Key Components

- **`LoggingStep`** — Main exported component. Fetches up to `LOG_PREVIEW_LIMIT` (3) recent logs via `useLogs()`, renders them in a read-only `DataTable` mirroring the production logs table, and provides "Mark as Complete" / "View Logs" footer actions.
- **`LogRow`** — Internal row shape mapping a raw `LogEntry` to display fields (status variant, device/organization labels, tool type, summary).
- **`severityVariant(severity)`** — Maps log severity strings (`ERROR`, `WARNING`, `INFO`, `CRITICAL`) to `Tag` color variants.
- **`logDetailsUrl(log)`** — Builds the deep link to a log's detail page via `routes.logs.details`.
- **`LogSourceCell`** — Table cell showing device name and organization, with skeleton loading state driven by `useLoadingScope`.
- **`OpenLogButton`** — Icon button that opens a log's detail page in a new tab; disabled while loading.

## Usage Example

```typescript
import { LoggingStep } from './logging-step';

function OnboardingLoggingPage() {
  const [completed, setCompleted] = useState(false);
  const [completing, setCompleting] = useState(false);

  return (
    <LoggingStep
      completed={completed}
      completing={completing}
      onComplete={async () => {
        setCompleting(true);
        await markStepComplete('logging');
        setCompleted(true);
        setCompleting(false);
      }}
      onCompleteBackground={() => markStepComplete('logging')}
    />
  );
}
```

The component is self-contained: it fetches its own data, builds table columns, and shows skeleton placeholder rows (via `loadingPlaceholderRows`) while `useLogs()` is loading, so every cell draws its own loading form rather than a generic spinner overlay.
