# tickets-step.tsx

Renders the body content for the "Tickets" step in the onboarding flow — an informational walkthrough explaining how AI Assistant conversations become tickets, paired with a demo video and a dynamic footer action.

## Key Components

- **`TicketsStep`** — Main exported component rendering the onboarding step body. Accepts callbacks and state flags (`onComplete`, `onCompleteBackground`, `completed`, `completing`, `expanded`) to control footer behavior and completion state.
- **`LabeledBlock`** — Internal helper component rendering an uppercase section label above arbitrary children content.
- **`INSIDE_TICKET_POINTS`** — Static array of bullet points describing ticket capabilities (title/description, assignment, attachments, internal notes, chat takeover).
- **`DEMO_VIDEO_ID`** — Placeholder YouTube video ID used until real onboarding videos are produced.

## Usage Example

```typescript
import { TicketsStep } from './tickets-step';

function OnboardingStepRenderer() {
  const [completing, setCompleting] = useState(false);
  const [completed, setCompleted] = useState(false);

  const handleComplete = async () => {
    setCompleting(true);
    await markStepComplete('tickets');
    setCompleted(true);
    setCompleting(false);
  };

  return (
    <TicketsStep
      expanded
      completed={completed}
      completing={completing}
      onComplete={handleComplete}
      onCompleteBackground={() => markStepComplete('tickets')}
    />
  );
}
```

**Behavior notes:**
- The footer's "Go to Tickets" button only appears once `useTicketStatistics` reports at least one ticket exists (gated by `isSaasTenantMode()`); otherwise a passive "Waiting for first ticket" indicator is shown.
- Navigating to Tickets from this step silently completes the onboarding step in the background if not already marked complete, using `onboardingHintUrl` to deep-link with contextual hints.
- The demo `Video` component only auto-activates playback when `expanded` is true, and suspends otherwise to avoid background playback.
