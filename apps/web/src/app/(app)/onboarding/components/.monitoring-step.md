# monitoring-step.tsx

A simplified monitoring policy creation form used within the onboarding flow, allowing users to quickly define a policy (name + query), assign it to devices, and complete the corresponding onboarding step.

This component is a trimmed-down version of the full create-policy form, reusing the same data hooks (`usePolicies`, `usePolicyDevices`, `useReplacePolicyHosts`) and the shared `DeviceSelector` UI, but presented as a compact onboarding step with "Mark as Complete" and "Add Policy" actions.

## Key Components

- **`MonitoringPolicyForm`** (type) — Zod-inferred form shape with `name` and `query` fields.
- **`monitoringPolicySchema`** — Zod schema requiring a non-empty policy name.
- **`getDeviceKey`** — Derives a stable string key for a `Device` from its Fleet host ID, used for selection tracking.
- **`MonitoringStep`** — Main exported component rendering:
  - A `name` input field (validated).
  - A `query` field rendered via `ScriptEditor` (SQL syntax).
  - A `DeviceSelector` for choosing target devices (disabled for devices without a Fleet agent).
  - A footer with a `FullFormLink` to the full policy creation page, a conditional "Mark as Complete" button, and an "Add Policy" button that creates the policy, assigns hosts, and redirects.

## Usage Example

```typescript
import { MonitoringStep } from './monitoring-step';

function OnboardingWizard() {
  const [completed, setCompleted] = useState(false);

  return (
    <MonitoringStep
      completed={completed}
      completing={false}
      onComplete={() => setCompleted(true)}
    />
  );
}
```

On successful submission, `MonitoringStep`:
1. Calls `createPolicy` with the form's `name` and `query`.
2. Assigns any selected devices via `useReplacePolicyHosts`.
3. Marks the onboarding step complete (if not already) by invoking `onComplete`.
4. Redirects to the policy details page using `routes.monitoring.policy(policy.id)` with an onboarding coach-mark hint.

If validation fails, a destructive toast displays the first field error message.
