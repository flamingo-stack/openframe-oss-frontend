## BookCallWalkthroughVideo

Renders the walkthrough video that forms the right half of the "Book a call" promo section, coordinating with the app-shell's floating video card so the same clip isn't offered to the user twice simultaneously.

This component wraps the shared library's `InlineWalkthroughVideo` with two page-specific concerns: claiming the video source from the floating card (via `useInlineWalkthroughClaim`), and surfacing a loading state while the video data request is in flight.

## Key Components

- **`BookCallWalkthroughVideo`** — Client component (`'use client'`) accepting an optional `className` prop.
- **`useWalkthroughVideoData`** — App hook supplying `{ video, isLoading }`.
- **`useInlineWalkthroughClaim`** — Claims the video so the floating app-shell card defers to this instance; called with a boolean indicating whether a playable source (`mainVideoUrl` or `youtubeUrl`) actually exists.
- **`LoadingWhen`** — Wraps rendering so the library's own 16:9 loading slot is shown while `isLoading` is true.
- **`InlineWalkthroughVideo`** — Library component that actually renders the video, started autoplaying and muted (`autoPlayCard`).

Renders nothing once loading settles and no video is configured, allowing sibling copy to expand and fill the card.

## Usage Example

```typescript
import { BookCallWalkthroughVideo } from '@/components/book-call-walkthrough-video';

export function BookCallSection() {
  return (
    <section className="grid grid-cols-2 gap-8">
      <div>
        <h2>Book a call</h2>
        <p>See how OpenFrame unifies your MSP stack.</p>
      </div>
      <BookCallWalkthroughVideo className="rounded-xl overflow-hidden" />
    </section>
  );
}
```

**Note:** The claim boolean must mirror the library's own render guard (`Boolean(video?.mainVideoUrl || video?.youtubeUrl)`) — claiming the video slot when there's no playable source would leave the user without any video at all.
