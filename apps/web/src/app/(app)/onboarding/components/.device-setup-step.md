# device-setup-step.tsx

Client component rendering the "Device Management" onboarding step. It lets the user pick a customer organization and target OS platform, surfaces a copy-to-clipboard install command for the OpenFrame agent, and tracks whether a device has connected — switching from a "waiting" state to completion actions once one does.

## Key Components

- **`DeviceSetupStep`** — Main exported component. Accepts optional callbacks/flags:
  - `onComplete?: () => void` — invoked when the user clicks "Mark as Complete".
  - `onCompleteBackground?: () => void` — invoked silently when navigating to the Devices page before the step is explicitly completed.
  - `completed?: boolean` — hides the "Mark as Complete" button once true.
  - `completing?: boolean` — shows a loading state on the completion button.

**Internal behavior:**
- Uses `useDeviceOrganizations` to fetch orgs and auto-selects the tenant's default org (or the first available) during render, guarded so it only runs once.
- Uses `useInstallCommand` to build the install script and registration key for the selected org/platform.
- Uses `useDevicesOverview` to detect if any device has connected (`total > 0`); `null`/unknown counts keep the install UI visible rather than falsely signaling completion.
- Uses `useCopyToClipboard` for the "click to copy" install command box, with toast validation errors for missing org/secret.
- Tracks the `ADD_DEVICE` analytics event via `trackDashboardActivity` on copy.
- Renders `Autocomplete` (customer picker with `OrgAvatar`), `OsPlatformSelector` (platform picker), and conditional "connected" vs "waiting" UI blocks.

## Usage Example

```typescript
import { DeviceSetupStep } from './device-setup-step';

function OnboardingWizard() {
  const [completed, setCompleted] = useState(false);
  const [completing, setCompleting] = useState(false);

  return (
    <DeviceSetupStep
      completed={completed}
      completing={completing}
      onComplete={async () => {
        setCompleting(true);
        await persistStepCompletion('device-setup');
        setCompleted(true);
        setCompleting(false);
      }}
      onCompleteBackground={() => {
        // Fire-and-forget completion when navigating away early
        persistStepCompletion('device-setup');
      }}
    />
  );
}
```

This component is intended to be embedded within a larger onboarding flow (e.g., a stepper) that supplies persistence logic via `onComplete`/`onCompleteBackground` and tracks `completed`/`completing` state externally.
