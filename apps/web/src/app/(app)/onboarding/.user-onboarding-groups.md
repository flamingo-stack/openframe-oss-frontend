Defines static presentation metadata for the user-facing "Get Started" onboarding steps, grouping each step with its icon, title, and description independent of backend state.

## Key Components

- **`UserStepMeta`** — Interface describing a single onboarding step's static metadata: `step` (narrowed `UserOnboardingStepId`), `icon`, `title`, and `description`.
- **`UserGroupMeta`** — Interface describing a labeled group of `UserStepMeta` items.
- **`USER_ONBOARDING_GROUPS`** — Exported array of `UserGroupMeta` defining the two onboarding sections:
  - **"Work smarter with AI"** — Meet Mingo (shared metadata from `MEET_MINGO_META`) and Tickets.
  - **"Run your operations"** — Scripting, Monitoring, Logging, and Knowledge Management.

This module acts as the single source of truth for onboarding step presentation, consumed by the onboarding content component in both loaded and loading states. Only completion status is fetched from the backend; everything else (icon, copy, grouping) lives here.

## Usage Example

```typescript
import { USER_ONBOARDING_GROUPS } from './user-onboarding-groups';

function OnboardingList({ completedSteps }: { completedSteps: Set<string> }) {
  return (
    <>
      {USER_ONBOARDING_GROUPS.map((group) => (
        <section key={group.label}>
          <h2>{group.label}</h2>
          {group.items.map((item) => (
            <div key={item.step}>
              {item.icon}
              <h3>{item.title}</h3>
              <p>{item.description}</p>
              {completedSteps.has(item.step) && <span>✓ Done</span>}
            </div>
          ))}
        </section>
      ))}
    </>
  );
}
```

Each step's `step` field maps to `UserOnboardingStep` from `@/generated/schema-enums`, letting consumers cross-reference backend completion data against this static metadata.
