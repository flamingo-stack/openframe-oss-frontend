## edit-query-page.tsx

A Next.js client page component for creating or editing a scheduled osquery-based query, including configuring its name, description, SQL body, run frequency, and target device assignment.

## Key Components

- **`EditQueryPage`** — Main exported component. Accepts a `queryId` prop (`string | null`); when `null`, renders a "New Query" creation form, otherwise fetches and edits the existing query identified by the numeric ID.
- **`TIME_UNITS`** — Static list of supported frequency units (`minutes`, `hours`, `days`) with their second multipliers, used to translate between raw seconds (stored interval) and a user-friendly value/unit pair.
- **`secondsToUnitValue` / `unitValueToSeconds`** — Helper functions converting between the query's `interval` (seconds) and the displayed numeric value + unit dropdown selection.
- **`queryFormSchema`** — Zod schema validating `name`, `description`, `query`, and `interval` (minimum 300 seconds / 5 minutes).
- **Form handling** — Uses `react-hook-form` with `zodResolver` for validation, `Controller` for the custom frequency input/select pairing, and renders validation errors via toast notifications (`onFormError`).
- **Data hooks** — `useQueryDetails`, `useQueries` (create/update), `useQueryHosts`/`useReplaceQueryHosts` (device targeting), and `usePolicyDevices` (available device list) drive data fetching and mutations.
- **Device targeting** — Manages `selectedFleetHostIds` state and syncs it with the form submission via `replaceQueryHostsMutation`.
- **UI composition** — Uses `PageLayout`, `DeviceSelector`, `ScriptEditor` (for SQL editing), and `TestQuerySection` (ad-hoc query testing against selected devices).

## Usage Example

```typescript
import { EditQueryPage } from './edit-query-page';

// Create a new query
export default function NewQueryRoute() {
  return <EditQueryPage queryId={null} />;
}

// Edit an existing query (e.g., from a dynamic route param)
export default function EditQueryRoute({ params }: { params: { id: string } }) {
  return <EditQueryPage queryId={params.id} />;
}
```

On submit, the component validates the form, persists the query via `createQuery`/`updateQuery`, then replaces the associated device assignments before navigating back to the query detail or query list view using routes from `@/lib/routes`.
