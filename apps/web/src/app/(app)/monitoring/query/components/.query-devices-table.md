## query-devices-table.tsx

Renders the devices table for a single osquery Query detail page, showing every device the query targets along with status, OS, customer/organization, and a per-row "Quick Query" toggle that lets a user run the query's SQL against an individual device inline.

## Key Components

- **`QueryDevicesTable`** – Entry component; if rendered inside a `useLoadingScope`, it shows skeleton rows immediately via `QueryDevicesTableView`, otherwise delegates to `QueryDevicesTableContent`.
- **`QueryDevicesTableContent`** – Fetches rows via `useQueryDevicesTable(queryId)` and passes data/loading state to the view.
- **`QueryDevicesTableView`** – Core presentational component: owns search text, tag-filter selection, filter modal visibility, and the set of rows with an open "Quick Query" sub-panel. Builds table columns (device, organization, OS, status, open link, quick query toggle), computes filter options (status/OS/customer) from the full row set, applies client-side search/tag filtering, and renders `DataTable` with a search `Input`, a `FilterModal` trigger `Button`, and expandable `QuickQueryPanel` sub-rows.
- **`QueryDevicesTableProps`** – `{ queryId: number; query?: string }` — `query` is the osquery SQL copied into each device's Quick Query draft when its panel opens.

## Usage Example

```typescript
import { QueryDevicesTable } from './query-devices-table';

function QueryDetailPage({ queryId, sql }: { queryId: number; sql: string }) {
  return (
    <section>
      <h2>Assigned Devices</h2>
      <QueryDevicesTable queryId={queryId} query={sql} />
    </section>
  );
}
```

The component handles its own loading skeleton, search, tag filtering, and per-device Quick Query expansion internally — consumers only need to supply the `queryId` and optionally the query's SQL text.
