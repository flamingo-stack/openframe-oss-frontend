This file implements the Monitoring page, a client-rendered route component that manages tab-based navigation and renders the active tab's content.

## Key Components

- **`Monitoring` (default export)** — The main page component for the Monitoring route. It manages URL-synced state (`tab` and `search`) via `useApiParams`, resolves the active tab component with `getTabComponent`, and renders the tab navigation along with the selected tab's content.
- **`useApiParams`** — Hook (from `@flamingo-stack/openframe-frontend-core/hooks`) used to read/write query-string-backed state, here configured with a `tab` param (default `'policies'`) and a `search` param (default `''`).
- **`MONITORING_TABS` / `MonitoringTabNavigation`** — Imported from `./components/tabs/monitoring-tabs`; define the available monitoring tabs and render the tab navigation UI.
- **`getTabComponent`** — Utility that maps the current `tab` param to its corresponding React component from `MONITORING_TABS`.

## Usage Example

```typescript
// Routed automatically by Next.js as the page for its directory.
// Example of switching tabs and resetting search state:

const { params, setParams } = useApiParams({
  tab: { type: 'string', default: 'policies' },
  search: { type: 'string', default: '' },
});

// Switching tabs clears the search query so each tab starts fresh
setParams({ tab: 'alerts', search: '' });
```

Because `search` is declared in this component (even though it's primarily owned/consumed by individual tabs), switching tabs via `onTabChange` resets the search value, ensuring no stale search filters persist across tab changes.
