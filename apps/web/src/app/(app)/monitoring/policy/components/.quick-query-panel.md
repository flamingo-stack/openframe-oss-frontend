Renders a per-device "Quick Query" panel that expands under a row in the policy Devices table, letting users edit and test-run a copy of the policy's osquery SQL against a single device without persisting changes back to the policy.

## Key Components

- **`QuickQueryPanel`** — Main component that renders an editable SQL editor, a Start/Duration/status row, a contextual action button (Run / Stop / Test Again), and the live result table.
- **`QuickQueryPanelProps`** — Props interface:
  - `fleetHostId: number` — target device's Fleet host ID.
  - `deviceName?: string` — SSOT-resolved display name, falling back to Fleet's own host name.
  - `initialQuery: string` — policy SQL copied into the editable draft when the panel opens.
- Uses `useQueryTestRun` to own a self-contained live campaign scoped to this panel instance, so test state is created and destroyed with the row.
- Uses `ScriptEditor` (SQL mode) for the editable query draft.
- Uses `TimingStat`, `TestRunStatusStat`, and `TestRunResults` from `@flamingo-stack/openframe-frontend-core` to display run timing, status, and results.

## Usage Example

```typescript
import { QuickQueryPanel } from './quick-query-panel';

function DeviceRowExpansion({ host, policyQuerySql }: { host: { id: number; name: string }; policyQuerySql: string }) {
  return (
    <QuickQueryPanel
      fleetHostId={host.id}
      deviceName={host.name}
      initialQuery={policyQuerySql}
    />
  );
}
```

The panel is intended to be mounted inside an expandable row of a devices table. Each instance manages its own query draft and test-run lifecycle independently — opening a new row creates a fresh editable copy of `initialQuery` and a fresh test campaign, while the original policy query remains unmodified since results are never saved back.
