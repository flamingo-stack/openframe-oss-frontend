Renders the full detail view for a single monitoring policy, including metadata, SQL query display, assigned devices, and live test execution controls.

## Key Components

### `PolicyStatusTag`
Internal helper component that renders a styled `Tag` for a policy's computed status (e.g., passing, failing) using `POLICY_STATUS_CONFIG`.

### `PolicyDetailsView`
Primary export. Accepts a `policyId` string prop and orchestrates the full policy detail page, including:

- **Data fetching** — `usePolicyDetails` for policy data; `usePolicies` for the delete mutation
- **Live test execution** — `useLiveCampaign` drives the "Run Now" flow; results surface in `LiveTestPanel`
- **Mingo context tracking** — `useTrackOpenView` registers the open policy as passive AI agent context
- **Responsive metadata layout** — separate `PanelRow` entries per breakpoint (desktop vs. tablet/mobile) using Tailwind visibility classes
- **Page actions** — Edit (outline) and Run Now (accent) as `PageActionButton[]`; Delete in the overflow `ActionsMenuGroup`
- **Guarded run state** — `runNowDisabledReason` provides a human-readable tooltip for every disabled condition (no query, campaign in progress, no devices assigned)

## Usage Example

```typescript
// app/monitoring/policies/[policyId]/page.tsx
import { PolicyDetailsView } from './policy-details-view';

export default function PolicyPage({ params }: { params: { policyId: string } }) {
  return <PolicyDetailsView policyId={params.policyId} />;
}
```

## State & Loading Behavior

| State | Rendered Output |
|---|---|
| Loading | `<CardLoader items={4} />` |
| Fetch error | `<LoadError message="..." />` |
| Not found / invalid ID | `<NotFoundError message="Policy not found" />` |
| Success | Full `PageLayout` with panels, query editor, devices table |
