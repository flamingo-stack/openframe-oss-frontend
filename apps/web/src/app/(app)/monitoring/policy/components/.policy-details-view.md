# policy-details-view.tsx

Client-side React component that renders the full policy detail page: metadata, read-only SQL query with an inline test runner, assigned devices table, and edit/delete actions. It handles its own loading, error, and not-found states with skeleton placeholders rather than a blocking spinner.

## Key Components

- **`PolicyDetailsView`** — Main exported component. Accepts a `policyId` prop (string, parsed to a numeric ID) and orchestrates data fetching, layout, and actions for the policy detail page.
- **`PolicyStatusTag`** — Internal helper component that renders the policy's status tag, falling back to a self-skeletoning `Tag` while `policy` is `null`.

### Behavior highlights
- Uses `usePolicyDetails`, `usePolicies`, and `usePolicyDevices` hooks for data and mutations.
- Registers the open policy with Mingo's passive context via `useTrackOpenView` so the AI agent is aware of the user's current view.
- Renders `LoadError` / `NotFoundError` for error and missing-policy states.
- Builds responsive `PanelRow` configurations for `StackedRowsPanel`, splitting metadata into one row (desktop) or two rows (tablet/mobile).
- Displays the policy query in a read-only `ScriptEditor` (SQL) paired with `TestQuerySection` for inline query testing against assigned devices.
- Lists assigned devices via `PolicyDevicesTable`.
- Provides page actions (`Edit Policy`) and a menu action (`Delete Policy`) that opens `ConfirmDeleteMonitoringModal`.
- Navigation uses `useSafeBack` and `routes.monitoring` helpers for back/edit/delete redirects.

## Usage Example

```typescript
import { PolicyDetailsView } from './policy-details-view';

// Typically rendered from a Next.js dynamic route page, e.g. app/monitoring/policies/[policyId]/page.tsx
export default function PolicyPage({ params }: { params: { policyId: string } }) {
  return <PolicyDetailsView policyId={params.policyId} />;
}
```

The component internally handles:
- Invalid/non-numeric `policyId` (treated as `null` for the details hook, triggering not-found behavior).
- Loading skeletons for every field via `InfoCell` and `Tag` while data resolves.
- Deletion flow: clicking "Delete Policy" opens a confirmation modal; confirming calls `deletePolicy` and redirects to the policies tab on success.
