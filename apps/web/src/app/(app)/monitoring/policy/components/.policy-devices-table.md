Renders the devices table within a policy detail page, showing each device's identity, organization, OS, compliance status with the policy, and per-row actions to open the device or launch a Quick Query panel pre-filled with the policy's osquery SQL.

## Key Components

- **`PolicyDevicesTable`** — Entry component; delegates to a skeleton view when inside a loading scope, otherwise fetches and renders real data via `PolicyDevicesTableContent`.
- **`PolicyDevicesTableContent`** — Fetches policy device rows using `usePolicyDevicesTable(policyId, assignedHostIds)` and passes them to the view.
- **`PolicyDevicesTableView`** — Builds the `DataTable` column definitions (device, organization, OS, compliance, open-in-new-tab, Quick Query toggle), manages per-row Quick Query open/close state, and renders an expandable sub-row (`QuickQueryPanel`) when toggled.
- **`DeviceCustomerCell`** — Displays organization logo and name with its own loading skeleton.
- **`DeviceOpenCell`** — Button that opens the device detail page in a new tab (disabled/hidden when no `machineId`).
- **`QuickQueryToggle`** — Button toggling the inline Quick Query sub-row; disabled when no policy query exists and the panel is closed.
- **`ComplianceCell`** — Renders a `Tag` reflecting `pending` / `non-compliant` / passing compliance status.

## Usage Example

```typescript
import { PolicyDevicesTable } from './policy-devices-table';

function PolicyDetailSection({ policyId, policyQuery, assignedHostIds }: {
  policyId: number;
  policyQuery?: string;
  assignedHostIds?: Array<{ id: number; hostname: string }>;
}) {
  return (
    <PolicyDevicesTable
      policyId={policyId}
      assignedHostIds={assignedHostIds}
      policyQuery={policyQuery}
    />
  );
}
```

Within a loading context (e.g., while the parent policy is still being fetched), wrapping this component in the app's loading scope provider automatically renders skeleton rows instead of requiring conditional logic from the caller.
