Fetches and merges device data with Fleet policy compliance status to produce a sorted, deduplicated table of `PolicyDeviceRow` entries for a given policy.

## Key Components

- **`fetchDevicesPage(cursor)`** — Fetches a single paginated page of devices via GraphQL, returning devices, pagination info, and the next cursor.
- **`usePolicyDevicesTable(policyId, assignedHostIds)`** — Primary hook. Combines assigned host IDs, Fleet failing/passing host lists, and the full device inventory to produce `PolicyDeviceRow[]` sorted by compliance status (`non-compliant` → `pending` → `passing`), then alphabetically by display name.

## Usage Example

```typescript
import { usePolicyDevicesTable } from './use-policy-devices-table';

function PolicyDevicesTable({ policyId, assignedHosts }) {
  const { rows, isLoading, error } = usePolicyDevicesTable(policyId, assignedHosts);

  if (isLoading) return <Spinner />;
  if (error) return <ErrorMessage message={error} />;

  return (
    <Table
      rows={rows}
      columns={['displayName', 'osType', 'complianceStatus', 'organization']}
    />
  );
}
```

## Notes

- **Compliance resolution:** Assigned host IDs are the source of truth for which devices appear. Fleet's failing/passing lists only supply status — hosts not in `assignedHostIds` are excluded to prevent stale rows from lingering after a host is unassigned.
- **Device deduplication:** When multiple device records share the same Fleet host ID, the most recently seen record wins.
- **Status precedence:** A host already marked `non-compliant` from the failing list will not be overwritten if it also appears in the passing list.
- **Device registry:** supplied by `useAllDevices({ filter: DEVICE_ENRICHMENT_FILTER })`, which owns the cursor walk and its cache.
