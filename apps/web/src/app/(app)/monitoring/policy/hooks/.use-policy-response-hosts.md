Fetches and caches the list of hosts that are either passing or failing a specific Fleet policy, using TanStack Query for data management.

## Key Components

- **`policyResponseHostsQueryKeys`** — Structured query key factory for cache scoping; keys are namespaced by `policyId` and `response` type (`'passing'` | `'failing'`).
- **`fetchPolicyResponseHosts`** *(internal)* — Async function that calls `fleetApiClient.getHosts` with `policy_id`, `policy_response`, and a cap of 100 hosts per page. Throws on non-OK responses.
- **`usePolicyResponseHosts`** — Primary hook. Accepts a nullable `policyId` and a `policyResponse` filter; the query is disabled when `policyId` is `null`. Returns a stable empty array (`EMPTY_HOSTS`) instead of `undefined` while loading.

## Usage Example

```typescript
import { usePolicyResponseHosts } from '@/hooks/use-policy-response-hosts';

function FailingHostsList({ policyId }: { policyId: number | null }) {
  const { hosts, isLoading, error } = usePolicyResponseHosts(policyId, 'failing');

  if (isLoading) return <p>Loading...</p>;
  if (error) return <p>Error: {error}</p>;

  return (
    <ul>
      {hosts.map(host => (
        <li key={host.id}>{host.hostname}</li>
      ))}
    </ul>
  );
}
```

## Notes

- Pass `policyId: null` to safely suspend fetching (e.g., before a policy is selected) — the query will not fire until a valid ID is provided.
- Results are paginated at **100 hosts** per request; consider extending the fetch logic if policies are expected to match more than 100 hosts.
- `disable_failing_policies: true` is passed to avoid recursive policy evaluation on returned hosts.
