Defines the `PolicyDeviceRow` interface and `ComplianceStatus` type used to represent a device's compliance state within a policy view.

## Key Components

- **`ComplianceStatus`** — Union type representing the three possible compliance states: `'non-compliant'`, `'passing'`, or `'pending'`
- **`PolicyDeviceRow`** — Interface describing a single device row in a policy compliance table, including identity, organizational, and OS metadata

## Usage Example

```typescript
import type { PolicyDeviceRow, ComplianceStatus } from './policy-device-row';

const device: PolicyDeviceRow = {
  id: 'abc-123',
  hostname: 'workstation-01',
  displayName: 'Workstation 01',
  deviceType: 'desktop',
  organization: 'Acme Corp',
  organizationImageUrl: 'https://cdn.example.com/acme-logo.png',
  organizationImageHash: 'sha256-abc',
  osType: 'windows',
  complianceStatus: 'passing',
  machineId: 'machine-xyz',
  fleetHostId: 42,
};

function filterByStatus(devices: PolicyDeviceRow[], status: ComplianceStatus) {
  return devices.filter(d => d.complianceStatus === status);
}
```

## Notes

- `organizationImageUrl` and `organizationImageHash` accept `null | undefined` to accommodate devices not associated with an org logo
- `machineId`, `deviceType`, `organization`, and `osType` are all optional (`undefined`) to handle incomplete device records
- `fleetHostId` is a required numeric identifier used to reference the device in the Fleet integration
