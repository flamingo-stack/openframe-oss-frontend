Route-level loading skeleton for the `/monitoring` page, rendering placeholder UI for both the Policies and Queries tabs while data is being fetched.

## Key Components

- **`MonitoringPageSkeleton`** — Main exported component. Accepts an optional `tab` prop (`"queries"` or unset for policies) and renders the appropriate skeleton layout.
- **`TAB_WIDTHS`** — Constant defining tab bar pill widths passed to `TabBarSkeleton`.
- **`SUMMARY_CARD_KEYS`** — Keys for the four policy summary cards (`total`, `compliance`, `failed`, `updated`), rendered as `Skeleton` blocks only on the Policies tab.
- **`addAction`** — Helper that produces a disabled `PageActionButton` array with a `PlusCircleIcon`, used for both `POLICY_ACTIONS` and `QUERY_ACTIONS`.

## Usage Example

```typescript
// app/monitoring/loading.tsx
import { MonitoringPageSkeleton } from './monitoring-page-skeleton';

export default function Loading() {
  return <MonitoringPageSkeleton />;
}

// With tab context (e.g., queries tab loading state)
<MonitoringPageSkeleton tab="queries" />
```

## Notes

- Both tabs reuse the real `PoliciesTable` / `QueriesTable` components with `isLoading` mode rather than duplicating column structure in a separate skeleton — keeping column layout in sync automatically.
- The four summary cards (Policies tab only) match the height of `DashboardInfoCard` (`h-16` / `md:h-[104px]`).
