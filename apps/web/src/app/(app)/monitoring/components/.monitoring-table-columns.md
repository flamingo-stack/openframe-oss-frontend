Defines shared, data-only column layouts for the two monitoring detail device tables: the policy detail page's "Devices" section and the query detail page's "Assigned Devices" tab. Each column spec (header, width, responsive breakpoint) is consumed by both the real `DataTable` and its loading-skeleton counterpart, ensuring layout stays in sync whether a table is loaded or loading.

## Key Components

- **`MONITORING_DEVICES_SKELETON_ROWS`** — constant (`5`) for the number of placeholder rows drawn while either device list loads (both lists are fetched whole, with no pagination).
- **`POLICY_DEVICE_COLUMNS`** — column layout for the policy detail page's Devices table. Includes a `compliance` column (header `STATUS`) representing the device's compliance with *that specific policy*. No column funnels.
- **`QUERY_DEVICE_COLUMNS`** — column layout for the query detail page's Assigned Devices table. Includes a `status` column (header `STATUS`) representing the device's own online/offline state. Its live (non-skeleton) columns additionally support funnels (`meta.filter`) on three headers, though the skeleton layout itself is identical to the policy table.

Shared internal column definitions (`DEVICE`, `ORGANIZATION`, `OS`, `OPEN`, `QUICK_QUERY`) are not exported, since the two tables are identical except for the `STATUS` column's id/meaning and the presence of funnels.

## Usage Example

```typescript
import {
  POLICY_DEVICE_COLUMNS,
  QUERY_DEVICE_COLUMNS,
  MONITORING_DEVICES_SKELETON_ROWS,
} from './monitoring-table-columns';
import { TableSkeleton } from '@/app/components/shared/table-column-layout';

// Policy detail page devices table
<TableSkeleton
  columns={Object.values(POLICY_DEVICE_COLUMNS)}
  rows={MONITORING_DEVICES_SKELETON_ROWS}
/>

// Query detail page assigned devices table
<TableSkeleton
  columns={Object.values(QUERY_DEVICE_COLUMNS)}
  rows={MONITORING_DEVICES_SKELETON_ROWS}
/>
```

Live `DataTable` configurations should reference these same constants for `id`, `header`, and `width`/`hideAt` to guarantee the loaded table and its loading skeleton remain pixel-aligned.
