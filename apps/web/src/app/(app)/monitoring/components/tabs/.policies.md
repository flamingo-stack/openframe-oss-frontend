# policies.tsx

Client-side page component that renders the monitoring Policies list view, including search, summary stats, a paginated table, and policy deletion flow.

## Key Components

- **`Policies`** — Main exported component rendering the full policies page: page layout with title/actions, summary cards, search toolbar, data table, empty/error states, and a delete confirmation modal.
- **`rows` / `PolicyTableRow` mapping** — Transforms the raw `Policy` domain model into the normalized view-model consumed by `PoliciesTable`, including computed status, severity label, and row actions.
- **`rowActions`** — Builds per-row action menu entries ("Policy Details", "Delete Policy") that navigate via `routes.monitoring.policy(id)` or open the delete modal.
- **`actions`** — Page-level header action ("Add Policy") with an AI-generation shortcut (`useGenerateWithAiAction`) and variant styling based on empty-state.
- **Local state** — `visibleCount` for client-side pagination, `policyToDelete` for the delete confirmation flow, plus `search`/`debouncedSearch` from `useSearchParam` for responsive, URL-synced filtering.

## Usage Example

```typescript
// Rendered as a Next.js app route page (client component)
import { Policies } from './policies';

export default function PoliciesPage() {
  return <Policies />;
}
```

Key behaviors to note when modifying this file:
- `canClaimEmpty` (from `usePolicies`) gates whether empty states render, preventing "no policies" messaging from showing during offline/error states.
- Search input updates a local state immediately for responsiveness, while the debounced value drives filtering and URL param sync (`useApiParams`).
- The Platform column/platform parsing logic is intentionally commented out but preserved for easy restoration — re-enable by uncommenting `parsePlatforms`, `ALL_PLATFORMS`, the `platforms` row field, and removing `showPlatform` suppression on `PoliciesTable`.
- Deletion is handled via `deletePolicy` from `usePolicies`, invoked through `ConfirmDeleteMonitoringModal` with an `onSuccess` callback clearing local state.
