# use-queries.ts

A React hook providing data fetching and mutation operations for Fleet osquery "queries" (saved osquery scripts), built on TanStack React Query with toast notifications and automatic cache invalidation.

## Key Components

- **`queriesQueryKeys`** — Centralized query key factory for cache management, with `all`, `list(params)`, and `detail(id)` key builders.
- **`fetchQueries` / `createQueryApi` / `updateQueryApi` / `deleteQueryApi`** — Internal API functions wrapping `fleetApiClient` calls, normalizing Fleet's response shapes and throwing on failure.
- **`useQueries(params?)`** — Main hook exposing:
  - `queries` — list of `Query` objects (defaults to empty array).
  - `isLoading`, `isError`, `error` (via `queryState` spread), and `refetch`.
  - `createQuery(data, options?)` — creates a query, invalidates cache, shows success/error toast.
  - `updateQuery(id, data, options?)` — updates a query by id.
  - `deleteQuery(id, options?)` — deletes a query by id.
  - `isCreating`, `isUpdating`, `isDeleting` — mutation pending flags.
  - `queriesQuery` — raw underlying `useQuery` result for advanced consumers.

## Usage Example

```typescript
import { useQueries } from './use-queries';

function QueriesPanel({ teamId }: { teamId?: number }) {
  const {
    queries,
    isLoading,
    createQuery,
    isCreating,
    deleteQuery,
  } = useQueries({ team_id: teamId });

  if (isLoading) return <p>Loading queries...</p>;

  const handleCreate = () => {
    createQuery(
      { name: 'List USB devices', query: 'SELECT * FROM usb_devices;' },
      { onSuccess: () => console.log('Created!') },
    );
  };

  return (
    <div>
      <button onClick={handleCreate} disabled={isCreating}>
        New Query
      </button>
      <ul>
        {queries.map(q => (
          <li key={q.id}>
            {q.name}
            <button onClick={() => deleteQuery(q.id)}>Delete</button>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

**Notes:**
- Requires `'use client'` — intended for Next.js client components.
- All mutations automatically invalidate `queriesQueryKeys.all`, refreshing any active query lists/details.
- Error handling is centralized via `handleApiError`, which surfaces failures as toasts while still allowing custom `onError` callbacks.
