Client-rendered Next.js page component that renders the user edit screen, gated behind the tenant management v2 feature flag and requiring a valid user `id` query parameter.

## Key Components

- **`EditUserPage`** — Default export; the page component rendered at the user edit route.
- **`useTenantManagementV2Gate`** — Hook determining whether the tenant management v2 feature is `'on'`, `'off'`, or `'loading'`.
- **`useRequiredIdParam`** — Hook that extracts the `id` query parameter, redirecting to `routes.users.list` if missing.
- **`TenantPageShell`** — Shared layout wrapper providing title, error boundary (`errorMessage`), and reset behavior keyed by `resetKey`.
- **`LoadingWhen`** — Conditional wrapper that renders a locked/loading UI state while `loading` is true.
- **`EditUserView`** — The actual user editing form/view, keyed by `id` to force remount on user change.

## Behavior

1. Checks the feature gate; if `'off'`, triggers Next.js `notFound()`.
2. Resolves the required `id` param; returns `null` while redirecting if absent.
3. Wraps content in `TenantPageShell` for consistent error handling and title display.
4. Uses `LoadingWhen` to lock the UI until the gate state is confirmed (`'loading'`), preventing premature "flag is off" assumptions.
5. Keys `EditUserView` by `id` so navigating between users resets component state instead of preserving stale edits.

## Usage Example

```typescript
// This is a Next.js App Router page component.
// It is automatically rendered when navigating to its route, e.g.:
// /tenant-management/users/edit?id=123

// No manual invocation needed — Next.js handles routing.
// Example of the underlying route definition it depends on:

const editUserUrl = `${routes.users.list}?id=123`;
```
