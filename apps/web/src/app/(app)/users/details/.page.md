# User Detail Page

Next.js client page component that renders the detail view for a single user, gated behind a feature flag and requiring a valid `id` query parameter.

## Key Components

- **`UserDetailsPage`** (default export) — Page component that:
  - Checks the `useTenantManagementV2Gate()` feature flag; returns a 404 (`notFound()`) when the gate is `'off'`
  - Resolves the required `id` query parameter via `useRequiredIdParam`, redirecting to the users list route when missing (renders `null` during redirect)
  - Wraps the content in `TenantPageShell` for consistent title, error handling, and reset-on-id-change behavior
  - Renders `UserDetailView`, keyed by `id` so React remounts the view when the user changes, passing a `loading` flag while the gate status resolves

## Usage Example

This page is automatically routed by Next.js based on its file location (e.g., `app/.../users/detail/page.tsx`) and expects an `id` query parameter:

```typescript
// Navigating to the user detail page
import { routes } from '@/lib/routes';
import { useRouter } from 'next/navigation';

function UserRow({ accountId }: { accountId: string }) {
  const router = useRouter();

  const openDetails = () => {
    router.push(`${routes.users.detail}?id=${accountId}`);
  };

  return <button onClick={openDetails}>View User</button>;
}
```

The page itself requires no props since it reads state from the URL and shared hooks:

```typescript
// app/.../users/detail/page.tsx
export default function UserDetailsPage() {
  // Automatically invoked by Next.js router for this route segment
}
```

## Notes

- Relies on `TenantPageShell` and `UserDetailView` from sibling feature modules for rendering and error boundaries.
- The `resetKey={id}` prop ensures the shell's error boundary resets when navigating between different user IDs.
