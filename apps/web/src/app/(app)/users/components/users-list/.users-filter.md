# users-filter.ts

Converts the user directory table's funnel-style filter selections (customer, status, license) into the GraphQL `DirectoryUserFilterInput` shape consumed by the `directoryUsers` query, while also tracking URL-serializable selection state.

## Key Components

- **`UserSelections`** — Interface defining the ticked options per filter column (`customer`, `status`, `license`), matching the shape persisted in the URL.
- **`NO_LICENSE`** — Internal sentinel constant representing the "users with no license" option within the license funnel.
- **`unnamedLicenseLabel(value)`** — Maps a license filter value to its display label, rendering `NO_LICENSE` as `"No licence"` and passing through any SKU id unchanged.
- **`toFilter(selections)`** — Transforms `UserSelections` into a `DirectoryUserFilterInput | null`. Returns `null` when no filters are selected (signaling "unfiltered" to both the query and empty-state UI). Otherwise builds an object including only the fields with active selections, converting raw status strings to validated `OrgUserStatus` enum values via `knownValues`, and splitting the license selection into `skuIds` (excluding the `NO_LICENSE` sentinel) plus a `noLicense` boolean flag.

## Usage Example

```typescript
import { toFilter, unnamedLicenseLabel, type UserSelections } from './users-filter';

const selections: UserSelections = {
  customer: ['org_123'],
  status: ['ACTIVE'],
  license: ['sku_abc', 'NO_LICENSE'],
};

const filter = toFilter(selections);
// {
//   organizationIds: ['org_123'],
//   statuses: ['ACTIVE'],
//   skuIds: ['sku_abc'],
//   noLicense: true,
// }

// No selections at all yields null, signaling an unfiltered query
const empty = toFilter({ customer: [], status: [], license: [] });
// null

// Display label for a license option
unnamedLicenseLabel('NO_LICENSE'); // "No licence"
unnamedLicenseLabel('sku_abc');    // "sku_abc"
```

This utility is typically used alongside a Relay/GraphQL query component for the directory users table, where `UserSelections` mirrors the filter state stored in the URL query params and `toFilter` bridges that state to the server-side filter input.
