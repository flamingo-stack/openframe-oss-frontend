# user-detail-view.tsx

Renders a directory user's detail page with a record-driven header and a tabbed body (Details, Devices, Groups, Licences), each tab loading and failing independently of the others.

## Key Components

- **`userDetailViewQuery`** — GraphQL query fetching a `directoryUser` by `id`, spreading fragments consumed by both the header and the Details tab so the record is fetched once per page.
- **`useUserRecord(id)`** — Hook wrapping `useLazyLoadQuery` with `store-and-network` fetch policy and a retry key, returning the `directoryUser` record or `null`.
- **`UserDetailHeaderIsland`** — Suspense-gated island rendering the page title (`UserDetailHeader`), showing a loading state via `UserTitle` while `useLoadingScope()` is active.
- **`DetailsTabBody`** — `memo`'d island for the "Details" tab body, guarded by `LoadingSuspense` since `TabNavigation` may invoke the render prop twice.
- **`USER_DETAIL_TABS`** — Array of `TabItem` configs (Details, Devices, Groups, Licences) each mapping to its own component, consumed by `TabNavigation`.
- **`userTabBody(tabId)`** — Resolves the active tab id to its component, defaulting to the first tab.
- **`USER_TAB_ERRORS` / `userTabError(tabId)`** — Per-tab error messages shown by `ContentErrorBoundary` on fetch failure.
- **`UserDetailView`** — Main exported component; composes the header island and `TabNavigation`, wrapping each tab body in its own `ContentErrorBoundary` so a failed tab doesn't break the title or sibling tabs.

## Usage Example

```typescript
import { UserDetailView } from './user-detail-view';

// Typically rendered from a route handler with the user's id from search params
export default function Page({ searchParams }: { searchParams: { id: string } }) {
  return <UserDetailView id={searchParams.id} />;
}

// During a parent transition, pass loading to gate both the header and active tab
<UserDetailView id={userId} loading={isPending} />
```

Each tab (`Details`, `Devices`, `Groups`, `Licences`) independently fetches its own data keyed by `id`, so switching tabs doesn't refetch the header, and a failure in one tab is isolated via `ContentErrorBoundary` without affecting the page title or other tabs.
