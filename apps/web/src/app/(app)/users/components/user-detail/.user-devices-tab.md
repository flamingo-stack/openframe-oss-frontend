## Overview

Renders the Devices tab on a user/directory-account detail page, showing an account's managed and unmanaged devices alongside a "Suggested Devices" table for records with possible agent-machine matches. Fetches data via a Relay query and supports linking an unmanaged directory record to a machine through `LinkDeviceModal`.

## Key Components

- **`userDevicesTabRecordFragment`** — Inline GraphQL fragment reading a single `OrgDevice` record (identity, source, OS, customers, link suggestions).
- **`userDevicesTabQuery`** — Root query fetching `directoryAccount.devices` split into `managed` and `unmanaged` lists.
- **`DeviceRow` / `SuggestedRow`** — Row shapes for the main devices table and the suggested-match table, with optional fields for loading-skeleton states.
- **`readRecord`**, **`toDeviceRows`**, **`toSuggestedRows`** — Transform Relay fragment data into row data for the two tables.
- **`DeviceCell`, `StatusCell`, `OsCell`, `ActionsCell`, `SuggestedDeviceCell`** — Cell renderers (device identity, managed/not-supported status, OS badge, link/open actions).
- **`LinkButton`** — Icon button opening the link-device flow for an eligible record.
- **`deviceColumns`** — Builds `ColumnDef[]` for the main devices `DataTable`, wiring the `onLink` callback.
- **`DEVICE_COLUMNS`, `SUGGESTED_COLUMNS`** — Column layout/skeleton metadata for `LiveTable` loading states.

## Usage Example

```typescript
import { UserDevicesTab } from '@/app/components/user-detail/user-devices-tab';

function UserDetailPage({ accountId }: { accountId: string }) {
  return (
    <UserTabHeading title="Devices" />
    // Renders managed/unmanaged devices and suggested matches for the account
  );
}
```

This component is typically rendered as a tab panel within a user/directory-account detail view, driven by the `directoryAccount(id)` Relay query, and requires no props beyond the account `id` resolved via its parent route context.
