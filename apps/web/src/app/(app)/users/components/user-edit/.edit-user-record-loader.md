# edit-user-record-loader.tsx

A headless data-loading component that fetches a directory user's record via Relay and hands the resolved state up to a parent form through a callback, without rendering any UI of its own.

## Key Components

- **`editUserRecordLoaderQuery`** — GraphQL query fetching a `directoryUser` by `id`, spreading the `editUserForm_person` fragment used to build the editable record.
- **`EditUserRecordState`** — Discriminated union representing the load outcome: `{ status: 'loading' }`, `{ status: 'missing' }`, or `{ status: 'ready'; record: EditUserRecord }`.
- **`EditUserRecordLoader`** — Public entry component. Wraps the query logic in a `LoadingSuspense` boundary labeled "Loading user".
- **`EditUserRecordReader`** — Internal component that short-circuits rendering while inside a loading scope (Suspense fallback or module-level loading flag), preventing premature state propagation.
- **`EditUserRecordQuery`** — Internal component performing the actual `useLazyLoadQuery` fetch with `store-and-network` policy and a retry key, computing the resolved state via `useMemo`, and reporting it to the parent via `onResolved` inside a `useLayoutEffect` (so seeding happens before paint).

## Usage Example

```typescript
import { useState, useCallback } from 'react';
import { EditUserRecordLoader, type EditUserRecordState } from './edit-user-record-loader';

function EditUserPage({ userId }: { userId: string }) {
  const [state, setState] = useState<EditUserRecordState>({ status: 'loading' });

  const handleResolved = useCallback((next: EditUserRecordState) => {
    setState(next);
    // Parent form owner seeds the form here (e.g. useSeedForm(next.record))
  }, []);

  return (
    <>
      <EditUserRecordLoader id={userId} onResolved={handleResolved} />
      {state.status === 'missing' && <p>User not found.</p>}
      {state.status === 'ready' && <EditUserForm record={state.record} />}
    </>
  );
}
```

**Notes:**
- This component renders nothing itself (`EditUserRecordReader`/`EditUserRecordQuery` return `null`); it exists purely to drive data fetching and lift state.
- Record identity is preserved via `useMemo` so downstream seeding hooks (`useSeedForm`) only re-seed when a genuinely new record arrives.
- Use `useRetryKey` from `@/app/components/shared` to force query refetches (e.g., after a retry action).
