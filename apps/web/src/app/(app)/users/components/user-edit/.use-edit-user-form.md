# useEditUserFormMutation.graphql / use-edit-user-form.ts

React hook that drives the Edit User form: it seeds `react-hook-form` state from a loaded directory user record, validates with a dynamic Zod schema, and commits changes via a Relay mutation, handling partial success, sync-pending states, and server-side field errors.

## Key Components

- **`useEditUserForm(loaded)`** — Main hook, returns `{ form, record, isSubmitting, handleSave }`.
  - `form` — the `react-hook-form` instance, resolver recomputed per-render against the currently seeded record's `usageLocation`.
  - `record` — the `EditUserRecord` the form was last seeded from, used as Save's diff baseline.
  - `isSubmitting` — mutation in-flight flag (`useMutation`'s `isSaving`).
  - `handleSave` — guarded submit handler that validates, diffs, and commits the update.
- **`editUserMutation`** — GraphQL mutation (`updateDirectoryUser`) requesting updated person fragments and `userErrors`.
- **`SAVE_FAILED`** / **`SYNC_PENDING`** — constants for toast messaging and detecting provider write/read lag.

## Usage Example

```typescript
import { useEditUserForm } from './use-edit-user-form';

function EditUserPage({ loaded }: { loaded: EditUserRecord | null }) {
  const { form, record, isSubmitting, handleSave } = useEditUserForm(loaded);

  return (
    <form onSubmit={e => { e.preventDefault(); handleSave(); }}>
      <input
        {...form.register('displayName')}
        disabled={!record}
      />
      {form.formState.errors.displayName && (
        <span>{form.formState.errors.displayName.message}</span>
      )}
      <button type="submit" disabled={isSubmitting}>
        Save
      </button>
    </form>
  );
}
```

**Behavior notes:**
- The form seeds once from `loaded` via `useSeedForm`; a dirty form is never reseeded by a background refetch, preserving unsaved edits and the correct Save baseline.
- On successful commit, toasts a success message and navigates back via `safeBackOrReplace`.
- Partial success (e.g., manager update failed but person data returned) surfaces a `warning` toast; pure `SYNC_PENDING` errors are shown as success since the write succeeded but the read hasn't caught up.
- Full failure maps `userErrors` back to form fields via `formFieldOfInput` and scrolls to the first invalid field.
