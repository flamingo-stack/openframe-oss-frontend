# edit-user-view.tsx

Client-side page component that renders the "Edit User" form at `/users/edit`, orchestrating record loading, form state, and save/cancel actions within the shared `PageLayout` shell.

## Key Components

- **`EditUserView`** — Main exported component. Accepts an `id` prop (user ID) and composes:
  - `EditUserRecordLoader` — fetches the user record and reports status (`loading` / `ready` / `missing`) via `onResolved`.
  - `useEditUserForm` — seeds and manages form state once the record is `ready`; exposes `form`, `record`, `isSubmitting`, and `handleSave`.
  - `EditUserFields` — renders the actual form fields, disabled while submitting.
  - `NotFoundError` — shown if the record status is `missing`.
  - `LoadingWhen` — wraps fields to show a loading state until the record resolves.
  - `PageLayout` — provides title, back button, and action buttons (Cancel / Save User).

- **`RECORD_LOADING`** — Constant initial state (`{ status: 'loading' }`) used to seed the local `state`.

## Behavior Notes

- The form is locked (via the `disabled` logic in `actions` and `EditUserFields`) until the record reaches `ready` status.
- `record` reflects the value the form was originally seeded with, not necessarily the latest fetch — Save diffs against this snapshot.
- Save is disabled if the record isn't ready, is missing, has no associated customers, or a submission is already in progress.
- Navigation back uses `useSafeBack`, falling back to `routes.users.details(id)`.
- On "not found", the user is redirected to `routes.users.list` via `router.replace`.

## Usage Example

```typescript
import { EditUserView } from './edit-user-view';

export default function EditUserPage({ params }: { params: { id: string } }) {
  return <EditUserView id={params.id} />;
}
```
