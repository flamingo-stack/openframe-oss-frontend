# edit-user-fixtures.ts

Test fixture factory for Edit User tests, producing mock account data that mimics the shape of GraphQL fragment data without requiring Relay's `readInlineData` to be mocked individually in every test. It bridges the gap between generated fragment types (`customerOption_organization`, `userPhone_account`) and the flat structure expected by `toEditUserRecord`.

## Key Components

- **`FixtureAccount`** - Type combining `PersonAccount` fields with flattened fragment data from `userPhone_account$data` and `customerOption_organization$data`, stripping Relay fragment-spread markers so fixtures can be built as plain objects.
- **`LIVE_DETAILS`** - A constant representing a fully-populated "live" details response (job title, department, manager, etc.) used as the default for account details across fixtures.
- **`fixtureAccount(overrides?)`** - Builds a single mock account ("Olivia Grant") sourced from Microsoft 365, with all editable fields open and sensible defaults. Accepts partial overrides to customize individual tests.
- **`userRecord(overrides?)`** - Wraps `fixtureAccount` into a full `EditUserRecord` by calling `toEditUserRecord`, performing the one necessary type cast to bridge generated fragment types with flat fixture data. Throws if the record can't be constructed.

## Usage Example

```typescript
import { userRecord, LIVE_DETAILS } from './edit-user-fixtures';

// Default fixture: Olivia Grant at Northbridge, Microsoft 365 source
const record = userRecord();

// Override specific fields for a test case
const terminatedUser = userRecord({
  leavingDate: '2024-01-15',
  readOnlyReasons: ['TERMINATED'],
});

// Override nested details while keeping defaults
const noManagerUser = userRecord({
  details: { ...LIVE_DETAILS, manager: null },
});
```

Use these fixtures in component or integration tests for the Edit User form where account data needs to be shaped consistently without manually mocking each Relay fragment read.
