# group-detail-view.tsx

Renders a directory group's detail page composed of independently-loading "islands" (title, cards, members), each fetching data via a shared Relay GraphQL query rather than a single blocking page-level query.

## Key Components

- **`groupDetailViewQuery`** — GraphQL query fetching a `directoryGroup` by `id` (and optional `organizationId`), spreading fragments consumed by the title and cards islands.
- **`useGroupRecord(props)`** — Hook wrapping `useLazyLoadQuery`, using `store-and-network` fetch policy and a retry key to re-fetch on demand; returns the group record or `null`.
- **`TitleIsland` / `CardsIsland`** — Suspense-wrapped sections (`LoadingSuspense`) that gate rendering while `loading` is `true`, showing skeleton/placeholder content via `useLoadingScope`.
- **`TitleReader` / `TitleQuery`** — Resolve and render `GroupDetailTitle`, falling back to a `NotFoundError` with a redirect to `groupPageBackRoute` if the group doesn't exist.
- **`CardsReader` / `CardsQuery`** — Resolve and render `GroupCards`, passing `null` while in loading scope.
- **`GroupDetailView`** — The exported page component; composes `TitleIsland`, `CardsIsland`, and `GroupMembersSection` in a vertical flex layout.

## Usage Example

```typescript
import { GroupDetailView } from './group-detail-view';

export default function GroupPage({ params }: { params: { id: string } }) {
  return (
    <GroupDetailView
      id={params.id}
      customerId="org-123"
    />
  );
}
```

Each island (title, cards, members) independently suspends and fetches data, so a slow members query won't block the title or cards from rendering. Passing `loading={true}` keeps all islands in a gated/skeleton state, useful for optimistic navigation transitions before `id` is resolved.
