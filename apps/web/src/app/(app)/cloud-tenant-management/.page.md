Entry point (Next.js App Router page) for the Tenant Management feature. It gates access based on feature-flag state and renders either the v2 or legacy (v1) tenant list view inside a shared page shell.

## Key Components

- **`TenantManagementPage`** — Default-exported page component that:
  - Resolves feature gate state via `useTenantManagementGate` (overall feature on/off/loading) and `useTenantManagementV2Gate` (v2 UI on/off/loading).
  - Calls `notFound()` only when the gate is definitively `'off'`, ensuring a `'loading'` state never triggers a 404.
  - Wraps content in `TenantPageShell` with a fixed title and error message.
  - Conditionally renders `TenantListView` (v2) or `TenantListViewV1` (legacy), passing a combined `loading` flag while either gate is still resolving.

## Usage Example

```typescript
// This file is a Next.js route page and is rendered automatically
// by the App Router for its corresponding path (e.g. /tenants).
// No manual import/usage is required.

// Example of the gating logic pattern used internally:
const gate = useTenantManagementGate();   // 'on' | 'off' | 'loading'
const v2 = useTenantManagementV2Gate();   // 'on' | 'off' | 'loading'

if (gate === 'off') {
  notFound();
}

const loading = gate === 'loading' || v2 === 'loading';
```

**Notes:**
- Marked `'use client'` since it relies on client-side hooks for gate resolution.
- Designed to avoid flashing a 404 during async feature-flag resolution by distinguishing `'loading'` from `'off'`.
- Delegates actual tenant list rendering and data fetching to child components (`TenantListView` / `TenantListViewV1`).
