This Next.js client page component renders the Cloud Tenant Management section, feature-gating access and version between V1 and V2 list views based on tenant entitlement checks.

## Key Components

- **`TenantManagementPage`** — Default export; the route's page component.
- **`useTenantManagementGate()`** — Hook that determines whether the tenant management feature is enabled (`'on'`, `'off'`, or `'loading'`) for the current tenant.
- **`useTenantManagementV2Gate()`** — Hook that determines whether the V2 UI variant is enabled (`'on'`, `'off'`, or `'loading'`).
- **`TenantPageShell`** — Shared layout wrapper providing title and error-handling chrome for the page.
- **`TenantListView`** — The V2 implementation of the tenant list.
- **`TenantListViewV1`** — The legacy V1 implementation of the tenant list.

## Usage Example

This file is a Next.js App Router page and is rendered automatically for its route; it isn't imported directly elsewhere. The gating logic it demonstrates can be reused as a pattern:

```typescript
const gate = useTenantManagementGate();
const v2 = useTenantManagementV2Gate();

// Only 'off' is a definitive negative result — never 404 while still loading.
if (gate === 'off') {
  notFound();
}

const loading = gate === 'loading' || v2 === 'loading';

return (
  <TenantPageShell title="Cloud Tenant Management" errorMessage="Couldn't load the tenants.">
    {v2 === 'on' ? <TenantListView loading={loading} /> : <TenantListViewV1 loading={loading} />}
  </TenantPageShell>
);
```

**Notes:**
- The gate check intentionally distinguishes between `'off'` (hard denial → `notFound()`) and `'loading'` (indeterminate → render in a loading state) to avoid flashing a 404 while entitlement data is still resolving.
- View selection (`v2 === 'on'`) allows gradual rollout of the new tenant list UI without breaking existing users still on V1.
