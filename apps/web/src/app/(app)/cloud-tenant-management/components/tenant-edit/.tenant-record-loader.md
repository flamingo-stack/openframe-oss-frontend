# tenant-record-loader.tsx

A Relay-backed data loader component for the Tenant Edit page, responsible for fetching a tenant's directory connection record, rendering its identity card, and surfacing the resolved record to a parent-owned form via a callback.

## Key Components

- **`TenantRecordState`** — Discriminated union type representing the loader's lifecycle: `'loading'`, `'missing'`, or `'ready'` (merged with `TenantFormRecord`).
- **`TenantRecordLoader`** — Public entry component. Wraps the query logic in a `LoadingSuspense` boundary labeled "Loading tenant".
- **`TenantRecordLoaderReader`** — Internal component that checks `useLoadingScope()` to render a bare identity card placeholder while inside a loading boundary/flag window, avoiding premature reads.
- **`TenantRecordQuery`** — Executes `tenantRecordLoaderQuery` via `useLazyLoadQuery`, derives a memoized `TenantRecordState` from the result, and calls `onResolved` inside a `useLayoutEffect` so the parent can seed its form before paint.
- **`tenantRecordLoaderQuery`** — GraphQL query fetching `directoryConnection` by `id`, spreading fragments `tenantFormHelpers_connection` and `tenantSummaryCard_identity`.

## Usage Example

```typescript
import { TenantRecordLoader, type TenantRecordState } from './tenant-record-loader';
import { useState, useCallback } from 'react';

function TenantEditPage({ tenantId }: { tenantId: string }) {
  const [record, setRecord] = useState<TenantRecordState>({ status: 'loading' });

  const handleResolved = useCallback((state: TenantRecordState) => {
    setRecord(state);
    // Parent owns useForm/useSeedForm and seeds the form here when state.status === 'ready'.
  }, []);

  return (
    <div>
      <TenantRecordLoader id={tenantId} onResolved={handleResolved} />
      {record.status === 'missing' && <p>Tenant not found.</p>}
    </div>
  );
}
```

**Design notes:** The loader intentionally separates data-fetching (`TenantRecordQuery`) from form-seeding ownership—the parent page retains control of `useForm`/`useSeedForm` to avoid duplicate writes. The `useMemo` on `connection` identity ensures the form is only reseeded when a genuinely new record arrives, not on every re-render.
