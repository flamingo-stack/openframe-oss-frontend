## useEditTenantForm

A React hook that powers the Edit Tenant form, managing two independently-seeded forms (tenant name and customer attribution) and submitting only the fields that actually changed.

## Key Components

- **`useEditTenantForm(id, stored)`** — Main hook accepting a tenant `id` and the `stored` record to seed from; returns `{ form, attributionForm, isSubmitting, handleSave }`.
- **`form`** — `react-hook-form` instance for the tenant name field, validated via `editTenantFormSchema` with `zodResolver`, seeded from `stored.values` via `useSeedForm`.
- **`attribution`** — Separate attribution form state from `useAttributionForm`, seeded independently from `stored.attribution.values`.
- **`handleSave`** — Submit handler that:
  - Guards on both forms being seeded before allowing a save.
  - Diffs the attribution form against its seed via `attributionChanged`; only includes it in the payload if changed.
  - Uses `changedFields` to send only the `name` field diff (provider/domain ride along unvalidated and hidden).
  - Calls `submit` (from `useSubmitWithAttribution`) to coordinate validation across both forms, then `save` to persist via `useSaveIntegration`.
  - On success, shows a success toast and navigates back (or replaces) to the tenant details route.

## Usage Example

```typescript
import { useEditTenantForm } from './use-edit-tenant-form';

function EditTenantPage({ id, stored }: { id: string; stored: TenantFormRecord | null }) {
  const { form, attributionForm, isSubmitting, handleSave } = useEditTenantForm(id, stored);

  return (
    <form onSubmit={form.handleSubmit(handleSave)}>
      <input {...form.register('name')} placeholder="Tenant name" />

      {/* Attribution fields rendered from attributionForm */}
      <AttributionFields form={attributionForm} />

      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Saving...' : 'Save'}
      </button>
    </form>
  );
}
```

Each form independently tracks whether it has been seeded from the fetched record, so a background refetch won't clobber unsaved edits in a dirty form, and unchanged customer attribution is never sent alongside a simple name rename.
