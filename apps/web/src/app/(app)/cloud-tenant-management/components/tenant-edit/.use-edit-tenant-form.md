## useEditTenantForm

A React hook that powers the Edit Tenant form (Figma 3126-14295), managing both the tenant's core fields (name) and its attribution/customer associations as two independently-seeded, independently-dirty forms.

The hook seeds form state from a fetched `stored` record without clobbering in-progress edits on refetch, computes a minimal diff of changed fields, and submits only what actually changed — the provider and domain fields ride along hidden and unvalidated, while the name and customer attribution are validated and conditionally sent.

## Key Components

- **`useEditTenantForm(id, stored)`** — main hook, returns `{ form, attributionForm, isSubmitting, handleSave }`
- **`form`** — `react-hook-form` instance for the tenant name, validated with `editTenantFormSchema` via `zodResolver`
- **`attribution`** — separate attribution form (customers), managed by `useAttributionForm`
- **`seeded`** — tracks the record a form was last seeded from (via `useSeedForm`), enabling dirty-state-aware diffing
- **`handleSave`** — builds the save payload using `changedFields` and `attributionChanged`, calls `useSaveIntegration().save`, and navigates back on success via `safeBackOrReplace`

## Usage Example

```typescript
import { useEditTenantForm } from './use-edit-tenant-form';

function EditTenantPage({ tenantId, record }: { tenantId: string; record: TenantFormRecord | null }) {
  const { form, attributionForm, isSubmitting, handleSave } = useEditTenantForm(tenantId, record);

  return (
    <form onSubmit={(e) => { e.preventDefault(); handleSave(); }}>
      <input {...form.register('name')} placeholder="Tenant name" />
      {/* attributionForm fields render customer selection */}
      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Saving...' : 'Save'}
      </button>
    </form>
  );
}
```

**Notes:**
- Only fields that changed relative to the seeded record are submitted (name is always diffed; attribution only when its values differ from the seeded attribution).
- A dirty form is not reseeded by a background refetch — the two forms independently decide whether to accept new `stored` data.
- On successful save, a success toast is shown and the user is routed back to `routes.cloudTenantManagement.details(id)`.
