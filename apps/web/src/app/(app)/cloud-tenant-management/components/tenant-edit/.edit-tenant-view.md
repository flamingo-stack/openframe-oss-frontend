# edit-tenant-view.tsx

Client component that renders the Edit Tenant Integration page at `/cloud-tenant-management/edit`. It loads a tenant record asynchronously, then displays and locks form fields until the record is ready, handling both the "not found" and "loading" states.

## Key Components

- **`EditTenantView`** — Main exported component, accepts an `id` prop (tenant ID) and orchestrates the edit flow:
  - Uses `TenantRecordLoader` to fetch the tenant record by `id` and reports resolution via `onResolved`
  - Tracks record state (`loading`, `missing`, `ready`) with local `useState`
  - Delegates form state and submission logic to `useEditTenantForm`
  - Renders `NotFoundError` when the record is missing, redirecting to the tenant list on "home"
  - Wraps form fields in `LoadingWhen` to show a loading state until the record seeds the forms
  - Renders `TenantFormFields` (core identity fields, domain hidden) and `AttributionFields` (connection/provider attribution, locked/read-only based on record readiness and connection status)
  - Supplies a single `PageActionButton` (Save) via `TenantFormFrame`, disabled/loading based on submission and readiness state

## Usage Example

```typescript
import { EditTenantView } from './edit-tenant-view';

export default function EditTenantPage({ params }: { params: { id: string } }) {
  return <EditTenantView id={params.id} />;
}
```

This component is intended to be used as the content of a Next.js route page, receiving the tenant `id` from route params. It is "compiled" in the sense that it never reads live form state during render—state is passed down to child field components (`TenantFormFields`, `AttributionFields`), keeping `EditTenantView` itself a thin orchestration layer.
