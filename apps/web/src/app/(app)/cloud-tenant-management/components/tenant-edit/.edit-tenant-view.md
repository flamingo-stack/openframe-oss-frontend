# edit-tenant-view.tsx

Client-side React component that renders the **Edit Tenant Integration** page for `/cloud-tenant-management/edit`, managing the loading, not-found, and ready states of a tenant record while delegating form logic and data fetching to dedicated hooks and child components.

## Key Components

- **`EditTenantView`** — The main exported component. Accepts an `id` prop identifying the tenant to edit, and:
  - Tracks the tenant record's load state (`loading`, `missing`, `ready`) via `TenantRecordLoader`.
  - Wires the loaded record into `useEditTenantForm` to obtain form controls, attribution form, submission state, and save handler.
  - Renders a `NotFoundError` view with navigation back to the tenant list when the record is missing.
  - Wraps form fields in `LoadingWhen` to lock inputs until the record resolves.
  - Composes `TenantFormFrame`, `TenantFormFields`, and `AttributionFields` to build the full page layout and actions.

- **`RECORD_LOADING`** — Default initial state constant (`{ status: 'loading' }`) used to seed the `record` state before the loader resolves.

## Usage Example

```typescript
import { EditTenantView } from './edit-tenant-view';

export default function EditTenantPage({ params }: { params: { id: string } }) {
  return <EditTenantView id={params.id} />;
}
```

The component is purely declarative in its render path: all tenant data fetching happens in `TenantRecordLoader` (via the `onResolved` callback), and form state/submission logic lives in `useEditTenantForm`. This keeps `EditTenantView` focused solely on composing UI based on the current `TenantRecordState` (`loading`, `missing`, or `ready`).
