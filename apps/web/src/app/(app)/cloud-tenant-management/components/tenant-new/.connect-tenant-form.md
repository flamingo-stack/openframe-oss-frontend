## connect-tenant-form.tsx

Renders the "connect" step of the tenant integration wizard (Figma 3562-27595 → 27507). This step reuses the tenant creation form layout but locks the provider and domain fields, replaces the "Generate Link" button with a consent verification card once a link exists, and gates attribution/customer fields until the directory connection is confirmed readable.

## Key Components

- **`ConnectTenantForm`** — Entry point component. Takes a `record: TenantFormRecord | null` and renders a pending (loading) state if the record isn't loaded yet or a loading scope is active, otherwise renders the fully loaded form.
- **`LoadedConnectTenantForm`** — Internal component driving the loaded state via `useConnectTenantForm(record)`. Manages save/generate actions, domain-edit toggling, consent minting/retry, and connection-check status.
- **`ConnectTenantFormView`** — Shared presentational frame used by both loaded and pending states, rendering `TenantFormFrame`, `TenantFormFields` (with locked domain/provider), and slots for consent/attribution content.
- **`PendingConnectTenantForm`** — Skeleton/loading variant shown before the record is available; uses a throwaway `react-hook-form` instance with default values and a disabled Save action.

## Usage Example

```typescript
import { ConnectTenantForm } from './connect-tenant-form';
import type { TenantFormRecord } from '../tenant-form/tenant-form-helpers';

function TenantConnectPage({ record }: { record: TenantFormRecord | null }) {
  return (
    <div className="page-container">
      <ConnectTenantForm record={record} />
    </div>
  );
}
```

The component internally decides whether to show a pending or loaded state—callers simply pass the current `record` (or `null` while fetching). All save/generate/consent logic is delegated to the `useConnectTenantForm` hook.
