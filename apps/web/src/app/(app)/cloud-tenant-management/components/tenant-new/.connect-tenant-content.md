## connect-tenant-content.tsx

Renders the "Connect Tenant" step of the tenant integration flow, fetching the directory connection record via Relay and handing it off to the tenant form. Manages loading boundaries and not-found states for a tenant lookup by `id`.

## Key Components

- **`connectTenantContentQuery`** — GraphQL query fetching a `directoryConnection` by `id`, spreading the `tenantFormHelpers_connection` fragment. Intentionally has no background refetch to avoid overwriting a freshly-minted `consentUrl` created on mount.
- **`ConnectTenantContent({ id })`** — Public entry point. Wraps the reader in a `LoadingSuspense` boundary labeled "Loading tenant form".
- **`ConnectTenantContentReader({ id })`** — Checks `useLoadingScope()`; if within a loading scope (e.g. a parent fallback), renders `ConnectTenantForm` with a `null` record to show its own loading state instead of suspending again.
- **`ConnectTenantContentQuery({ id })`** — Executes the Relay query with `useLazyLoadQuery`, using `store-or-network` fetch policy and a `retryKey` (via `useRetryKey`) to support retries. Renders:
  - A `PageLayout` with `NotFoundError` if no connection is found (with a back button and home redirect to `routes.cloudTenantManagement.list`).
  - `ConnectTenantForm` populated via `readTenantFormRecord(connection)` on success.

## Usage Example

```typescript
import { ConnectTenantContent } from './connect-tenant-content';

export default function ConnectTenantPage({ params }: { params: { id: string } }) {
  return <ConnectTenantContent id={params.id} />;
}
```

This component is typically rendered by a route-level page component that supplies the tenant connection `id` from the URL params, delegating all data fetching, loading states, and error handling to `ConnectTenantContent`.
