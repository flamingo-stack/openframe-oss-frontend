# connect-tenant-content.tsx

Client-side React component that loads and displays the "Connect Tenant" step of the cloud tenant integration flow, fetching an existing `directoryConnection` record via Relay and rendering the connect form with appropriate loading and not-found states.

## Key Components

- **`ConnectTenantContent`** — Top-level exported component. Wraps the query-driven reader in a `LoadingSuspense` boundary with a live loading label, isolating its own loading UI from parent suspense boundaries.
- **`ConnectTenantContentReader`** — Internal component that checks `useLoadingScope()`. If within a loading scope (e.g., fallback rendering), it renders `ConnectTenantForm` with a `null` record to avoid suspending further; otherwise it delegates to the data-fetching query component.
- **`ConnectTenantContentQuery`** — Internal component that executes `connectTenantContentQuery` via `useLazyLoadQuery` using a `store-or-network` fetch policy and a `retryKey` for manual refetch support. Renders a `NotFoundError` inside `PageLayout` if the connection doesn't exist, or the populated `ConnectTenantForm` otherwise.
- **`connectTenantContentQuery`** — GraphQL query fragment fetching `directoryConnection` by `id`, spreading the `tenantFormHelpers_connection` fragment used by `readTenantFormRecord`.

## Usage Example

```typescript
import { ConnectTenantContent } from './connect-tenant-content';

export default function ConnectTenantPage({ params }: { params: { id: string } }) {
  return <ConnectTenantContent id={params.id} />;
}
```

**Note:** This component intentionally avoids background refetching after initial mount. A record created without a link mints a `consentUrl` on mount, and the design relies on `store-or-network` fetch policy plus the Relay store cache to avoid overwriting that freshly minted value with a stale refetch.
