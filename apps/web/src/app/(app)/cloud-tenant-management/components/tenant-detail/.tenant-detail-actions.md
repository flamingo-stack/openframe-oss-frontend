Defines the action buttons and dropdown menu configuration for the tenant detail page, covering both readable (connected) and unreadable (partially consented) tenant states, with actions for reconnecting, editing, pausing/resuming sync, disconnecting, and deleting.

## Key Components

- **`reconnectAction(id)`** — Returns a `PageActionButton` config for the "Reconnect" button, linking to the tenant's reconnect route.
- **`editAction(id)`** — Returns a `PageActionButton` config for the "Edit Integration" button, linking to the tenant's edit route.
- **`tenantMenuGroups(options)`** — Builds the `ActionsMenuGroup[]` for the page's "…" overflow menu. Accepts a `TenantMenuOptions` object (`id`, `readable`, `paused`, `onPause`, `onResume`, `busy`) and returns different menu structures depending on whether the tenant connection is currently readable:
  - **Unreadable tenant**: only `Reconnect` and `Delete connection` are shown.
  - **Readable tenant**: shows `Pause Sync`/`Resume Sync` (toggled by `paused`, disabled while `busy`), `Reconnect`, `Disconnect`, and `Delete connection` (in a separate danger group).
- **`deleteGroup(id)`** (internal) — Builds the danger "Delete connection" menu group.
- **`reconnectItem(id)`** (internal) — Builds the shared "Reconnect" menu item used in both menu states.
- **`MENU_ICON_CLASS`** — Shared Tailwind class applied to dropdown menu icons.

## Usage Example

```typescript
import { reconnectAction, editAction, tenantMenuGroups } from './tenant-detail-actions';

const pageActions = [editAction(tenantId), reconnectAction(tenantId)];

const menuGroups = tenantMenuGroups({
  id: tenantId,
  readable: tenant.readable,
  paused: tenant.syncPaused,
  busy: isMutating,
  onPause: () => pauseSyncMutation.mutate(tenantId),
  onResume: () => resumeSyncMutation.mutate(tenantId),
});

// Pass `pageActions` to the page header and `menuGroups` to the "…" ActionsMenu component.
```

Icons and `ActionsMenuGroup`/`PageActionButton` types come from `@flamingo-stack/openframe-frontend-core`, and routes are resolved via `routes.cloudTenantManagement` from `@/lib/routes`.
