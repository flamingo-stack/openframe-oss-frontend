# tenant-consent-alert.tsx

A client-side React component that renders a status alert summarizing the outcome of a tenant's last directory consent attempt, surfacing issues like denied tiers or unfinished OAuth consent flows.

## Key Components

- **`tenantConsentAlertFragment`** — GraphQL fragment (`tenantConsentAlert_connection`) that fetches `domain`, `access.state`, and `lastConsentInfo` (outcome, denied tiers, and issues) from a `DirectoryConnection`.
- **`TenantConsentAlert`** — Component that accepts a Relay fragment key (`connection`), derives an alert payload via the `consentAlert` utility, and renders an `Alert` with a warning icon and message. Returns `null` when there's nothing to report (e.g., clean consent state).

## Usage Example

```typescript
import { graphql, useFragment } from 'react-relay';
import { TenantConsentAlert } from './tenant-consent-alert';
import type { tenantConsentAlertParent_connection$key } from '@/__generated__/tenantConsentAlertParent_connection.graphql';

function TenantSummaryCard({ connection }: { connection: tenantConsentAlertParent_connection$key }) {
  const data = useFragment(
    graphql`
      fragment tenantConsentAlertParent_connection on DirectoryConnection {
        ...tenantConsentAlert_connection
      }
    `,
    connection,
  );

  return (
    <div className="flex flex-col gap-[var(--spacing-system-m)]">
      {/* ...summary content... */}
      <TenantConsentAlert connection={data} />
    </div>
  );
}
```

## Notes

- Relies on `consentAlert` and `isReadable` helpers from `../../utils/tenant-presentation` to compute whether an alert should display and which variant/message to use.
- Checks `DirectoryConsentIssueKind.NOT_FINISHED` issues to collect unfinished consent tiers.
- Marked with `data-loading-optional` since the alert is conditionally rendered and omitted during loading states.
- Designed to match Figma specs (settings frames 2885-2333 / 2885-3620) for consent alert styling.
