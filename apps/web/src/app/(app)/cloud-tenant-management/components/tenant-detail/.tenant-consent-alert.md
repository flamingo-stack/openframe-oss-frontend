## tenant-consent-alert.tsx

Renders a status alert summarizing the outcome of the most recent directory consent attempt for a tenant connection (e.g., denied tiers, unfinished steps). Returns `null` when there's nothing noteworthy to report, so it gracefully disappears for clean consent states.

## Key Components

- **`tenantConsentAlertFragment`** — GraphQL fragment on `DirectoryConnection` fetching `domain`, `access.state`, and `lastConsentInfo` (outcome, denied tiers, and issues with kind/tier).
- **`TenantConsentAlert`** — React component that:
  - Resolves fragment data via `useFragment` from a `tenantConsentAlert_connection$key` reference.
  - Derives unfinished tiers by filtering `issues` for `DirectoryConsentIssueKind.NOT_FINISHED`.
  - Computes alert presentation (variant + message) using the `consentAlert` utility, factoring in whether the connection's access state is readable.
  - Renders an `Alert` with an `AlertTriangleIcon` and message text, or nothing if `consentAlert` returns a falsy value.

## Usage Example

```typescript
import { graphql, useFragment } from 'react-relay';
import { TenantConsentAlert } from './tenant-consent-alert';
import type { tenantConsentAlert_connection$key } from '@/__generated__/tenantConsentAlert_connection.graphql';

function TenantSummaryCard({ connectionRef }: { connectionRef: tenantConsentAlert_connection$key }) {
  return (
    <div className="flex flex-col gap-4">
      {/* Summary card content */}
      <TenantConsentAlert connection={connectionRef} />
    </div>
  );
}
```

This component is intended to be placed directly beneath a tenant summary card. It relies on a parent query spreading the `tenantConsentAlert_connection` fragment on a `DirectoryConnection` type, and is also refreshed automatically when a "Check Connection" action re-runs the consent probe, since the fragment data updates reactively via Relay.
