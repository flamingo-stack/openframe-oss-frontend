# tenant-attribution-rules.tsx

Renders the "Attribution Rules" table on a directory integration's detail page, showing each bound customer's attribution rules (match criteria, matched values, and user counts) with client-side sorting and filtering. Supports a Suspense-based loading skeleton and integrates with a nested loading-scope boundary for graceful fallback rendering.

## Key Components

- **`TenantAttributionRules({ id })`** — Public entry point. Wraps the query/reader tree in `LoadingSuspense` with a labeled fallback.
- **`TenantAttributionRulesReader({ id })`** — Detects an active loading scope (e.g., parent Suspense boundary still resolving) and renders skeleton placeholder rows instead of firing the query.
- **`TenantAttributionRulesQuery({ id })`** — Executes `tenantAttributionRulesQuery` via `useLazyLoadQuery` with `store-and-network` fetch policy and a retry key for manual refetch.
- **`TenantAttributionRulesRecord({ connection })`** — Resolves the `tenantAttributionRules_connection` GraphQL fragment to get `customers`.
- **`AttributionRulesTable({ customers })`** — Core table UI: builds rows via `toRows`, derives sort/filter state, renders `DataTable` plus a mobile `FilterModal`.
- **`toRows(customers)`** — Flattens each customer's `rules` array into one `AttributionRuleRow` per rule, including deleted-value badges and customer badges (e.g., "Archived").
- **`AttributionRuleRow`** — Row shape: `customer`, `badge`, `matchBy`, `values`, `valuesBadge`, `users`.
- **`attributionRuleColumns(customerOptions, matchByOptions)`** — Builds `ColumnDef[]` with filterable `customer`/`matchBy` columns and a sortable `users` column (undefined sorts last).
- **`optionsOf(rows, key)`** — Derives deduplicated, sorted filter options from the current row set.

## Usage Example

```typescript
import { TenantAttributionRules } from './tenant-attribution-rules';

function DirectoryIntegrationDetail({ directoryId }: { directoryId: string }) {
  return (
    <div className="flex flex-col gap-8">
      {/* other integration sections */}
      <TenantAttributionRules id={directoryId} />
    </div>
  );
}
```

The component handles its own GraphQL fetching, loading skeleton, and empty states (no customers bound vs. no rows matching active filters), so callers only need to pass the directory connection `id`.
