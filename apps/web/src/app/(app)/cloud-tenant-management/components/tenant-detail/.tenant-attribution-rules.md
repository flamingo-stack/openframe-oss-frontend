This file implements the **Attribution Rules** section of a tenant/directory detail page, displaying a filterable, sortable table of customer attribution rules (how users are matched to customers within a directory connection) with live GraphQL data via Relay.

## Key Components

- **`TenantAttributionRules`** – Public entry component; wraps the reader in a `LoadingSuspense` boundary, accepts a directory `id`.
- **`TenantAttributionRulesReader`** – Detects whether it's inside a loading scope (skeleton placeholder) or should fetch real data.
- **`TenantAttributionRulesQuery`** – Executes `tenantAttributionRulesQuery` via `useLazyLoadQuery` and renders the record component.
- **`AttributionRulesTable`** – Core table UI: builds rows, columns, sorting/filtering state, renders `DataTable`, `FilterModal`, and a mobile filter button.
- **`tenantAttributionRulesFragment`** – Relay fragment on `DirectoryConnection` selecting `customers`, their `rules` (kind, values, userCount).
- **`tenantAttributionRulesQuery`** – Relay query fetching a `directoryConnection` by `id` and spreading the fragment.
- **`toRows`** – Transforms `Customers` fragment data into flat `AttributionRuleRow[]`, excluding `DirectoryRuleKind.ALL` rules (handled elsewhere as a summary, not a rule row).
- **`attributionRuleColumns`** – Builds `ColumnDef[]` for customer, match-by, values, and users columns with filter/sort configuration.
- **`optionsOf`** – Derives unique, sorted filter options from current row data.
- **`AttributionRuleRow`** – Row shape: customer name, badge (e.g., archived/deleted), match type, values string, deleted-values badge, and user count.

## Usage Example

```typescript
import { TenantAttributionRules } from './tenant-attribution-rules';

function DirectoryDetailPage({ directoryId }: { directoryId: string }) {
  return (
    <div className="flex flex-col gap-8">
      {/* Other directory sections */}
      <TenantAttributionRules id={directoryId} />
    </div>
  );
}
```

The component handles its own loading state (via `LoadingSuspense`/skeleton rows), empty states (no customers vs. no matching rules), and client-side sorting/filtering by customer and match type, with a dedicated mobile `FilterModal` for smaller viewports.
