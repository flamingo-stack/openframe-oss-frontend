# tenant-summary-card.tsx

Renders the summary card displaying a directory tenant's provider, bound customers, attribution, user count, sync status, and last-read time. Provides two exports: a full two-row card for the tenant details page and a condensed one-row variant for Edit/Reconnect flows. Both components support skeleton loading states via `LoadingWhen` and `useLoadingScope`, ensuring the layout doesn't shift when data arrives.

## Key Components

- **`TenantSummaryCard`** — Full two-row card (Figma 3065-17490 / 3051-7340) showing provider, customers, attribution, users, sync status, and last-read time. Consumes `tenantSummaryCard_connection$key` via Relay fragment.
- **`TenantIdentityCard`** — Single-row cut (Figma 2097-123264) showing only provider and domain name, used on Edit/Reconnect screens. Consumes `tenantSummaryCard_identity$key`.
- **`ProviderCell`** — Internal cell rendering the provider's logo and label.
- **`CustomersCell`** — Internal cell rendering the lead bound customer (avatar, name, badge) plus an "+N" overflow menu (`AllCustomersMenu`) for additional customers.
- **`AttributionCell`** — Internal cell showing attributed/unattributed user counts, highlighting warnings in the warning color.
- **`AllCustomersMenu`** — Dropdown listing all bound customers when more than one exists.

## Usage Example

```typescript
import { TenantSummaryCard, TenantIdentityCard } from './tenant-summary-card';

// Full details page card
function TenantDetailsPage({ connectionRef }: { connectionRef: tenantSummaryCard_connection$key | null }) {
  return <TenantSummaryCard connection={connectionRef} />;
}

// Condensed card for Edit/Reconnect flows
function EditTenantPage({ connectionRef }: { connectionRef: tenantSummaryCard_identity$key | null }) {
  return <TenantIdentityCard connection={connectionRef} />;
}
```

Both components can be rendered with a `null` connection inside a `LoadingScope` to display their skeleton loading state automatically, keeping layout stable while the Relay fragment resolves.
