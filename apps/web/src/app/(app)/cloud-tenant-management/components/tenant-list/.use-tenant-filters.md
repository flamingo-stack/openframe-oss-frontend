# use-tenant-filters.ts

A React hook that fetches and shapes GraphQL facet data into filter options for the tenants data table, supporting tenant/provider, customer, license, and access-state filtering with graceful handling of unknown enum values and zero-count selections.

## Key Components

- **`tenantFiltersQuery`** — GraphQL query that fetches `directoryConnectionFilters` (providers, customers, accessStates, licenses) scoped by search text and active filters, conditionally included via the `list` variable.
- **`toOptions(facet, selected, labelOf)`** — Converts raw facet rows into `DataTableFilterOption[]`, ensuring any currently selected value that returned a zero count is still included (via `withSelected`) so users don't lose visibility of their active selections.
- **`enumLabel(members, name)`** — Builds a label resolver for enum-backed funnels (provider, license, access state). Falls back to the server-provided label for unrecognized enum values, and to the raw value if neither is available.
- **`useTenantFilters(search, filter, selections, enabled)`** — Main hook. Runs a non-suspending query against `tenantFiltersQuery` and returns:
  - `options` — the shaped `TenantsTableFilters['options']` object with `tenant`, `customer`, `licenses`, and `access` option lists.
  - `pending` — `true` while the hook is disabled or awaiting its first successful data load.

## Usage Example

```typescript
import { useTenantFilters } from './use-tenant-filters';

function TenantsFilterPanel({ search, filter, selections }: {
  search: string;
  filter: DirectoryConnectionFilterInput | null;
  selections: TenantSelections;
}) {
  const { options, pending } = useTenantFilters(search, filter, selections, true);

  if (pending) {
    return <FilterSkeleton />;
  }

  return (
    <TenantsTableFilters
      options={options}
      selections={selections}
    />
  );
}
```

The hook is designed to be called unconditionally with an `enabled` flag—when `enabled` is `false`, the query is skipped and `pending` remains `true`, allowing consumers to defer fetching until prerequisites (e.g., initial search state) are ready, while previously loaded options remain visible between refetches.
