# tenant-list-view.tsx

Client component rendering the Cloud Tenant Management page: a searchable, filterable, sortable table of tenants with a sticky toolbar and a "Connect Tenant" split-button action. Orchestrates URL-synced query params, debounced search, deferred filtering, and a filter/sort modal.

## Key Components

- **`CONNECT_TENANT_ACTION`** — `PageActionButton` config for the page header's "Connect Tenant" split button; the label navigates in place while the arrow icon opens the connect page in a new tab.
- **`TenantListViewProps`** — Props interface; accepts an optional `loading` flag that renders the page frame without fetching rows (used while a feature flag is resolving).
- **`TenantListView`** — Default exported component. Responsibilities:
  - Syncs search, filter selections (`tenant`, `customer`, `licenses`, `access`), and sort state (`sortBy`, `sortDirection`) with URL params via `useApiParams`.
  - Debounces local search input into the URL param via `useSearchParam`.
  - Builds a memoized `query` (filter + orderBy) from current selections, deferred via `useDeferredQuery` to avoid UI jank during refetches.
  - Loads filter option lists via `useTenantFilters`.
  - Renders `ConsentAnnouncementBanner`, a sticky search/filter toolbar (`useStickyToolbar`), `TenantsTable`, and a `FilterModal` for advanced filtering/sorting.

## Usage Example

```typescript
import { TenantListView } from './tenant-list-view';

export default function CloudTenantManagementPage() {
  const featureReady = useFeatureFlag('cloud-tenant-management');

  return <TenantListView loading={!featureReady} />;
}
```

The component expects to be rendered inside a page shell providing padding and an error boundary (e.g. `TenantPageShell`), since it intentionally omits outer page padding to let its sticky toolbar span full width.
