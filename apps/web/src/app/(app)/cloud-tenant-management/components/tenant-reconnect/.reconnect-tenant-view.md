## reconnect-tenant-view.tsx

Client-side React view for the `/cloud-tenant-management/reconnect` page, allowing an admin to re-establish and verify a customer's directory connection consent after it has lapsed or been revoked. It orchestrates loading states, consent-link minting, connection verification, and attribution field editing for a tenant's directory integration.

## Key Components

- **`ReconnectTenantView`** — Public entry component; wraps content in a `LoadingSuspense` boundary with a live loading label.
- **`ReconnectTenantContent`** — Internal component that renders placeholder/loading chrome when inside a loading scope, otherwise delegates to the data-fetching component.
- **`ReconnectTenantContentQuery`** — Core logic component: runs the `reconnectTenantViewQuery` GraphQL query, auto-mints a consent link when none is outstanding, checks connection verdict/readability, manages the attribution form, and renders `TenantIdentityCard`, `ConsentBlock`, and `AttributionFields`.
- **`reconnectTenantViewQuery`** — GraphQL query fetching the `directoryConnection` by `id`, including fragments for the identity summary card and tenant form helpers.

## Usage Example

```typescript
import { ReconnectTenantView } from './reconnect-tenant-view';

// Typically rendered by a Next.js route/page component
export default function Page({ params }: { params: { id: string } }) {
  return <ReconnectTenantView id={params.id} />;
}
```

Key behaviors to note when integrating or extending this file:
- Uses `fetchPolicy: 'store-or-network'` deliberately to avoid overwriting a freshly minted `consentUrl` with a stale background refetch (see in-code comment for rationale).
- Consent minting (`useStartConsent`) only auto-fires when a connection exists and no `consentUrl` is already outstanding, preventing accidental invalidation of a link the customer's admin may hold.
- `readable` (field visibility) depends on `useCheckConnection`'s verdict, reflecting that a revoked grant should hide/lock attribution values.
- Falls back to `NotFoundError` with a redirect to `routes.cloudTenantManagement.list` when the connection record is missing.
