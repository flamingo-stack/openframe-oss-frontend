# reconnect-tenant-view.tsx

This file implements the page view for reconnecting a tenant's directory integration consent flow, located at `/cloud-tenant-management/reconnect`. It handles minting a new consent URL, verifying grant readability, and allowing admins to edit attribution fields while the consent is being re-established.

## Key Components

- **`ReconnectTenantView`** — Public entry component; wraps the content in a `LoadingSuspense` boundary for the async data fetch.
- **`ReconnectTenantContent`** — Internal wrapper that renders a static loading-state skeleton (identity card, consent block, pending attribution fields) when inside a loading scope, otherwise delegates to the query-driven component.
- **`ReconnectTenantContentQuery`** — Core logic component that:
  - Fetches the `directoryConnection` via `reconnectTenantViewQuery` GraphQL query (using `store-or-network` fetch policy to avoid clobbering a freshly-minted consent URL).
  - Auto-mints a new consent URL via `useStartConsent` when no outstanding link exists.
  - Checks connection/grant readability via `useCheckConnection`.
  - Renders `TenantIdentityCard`, `ConsentBlock`, and `AttributionFields`, or a `NotFoundError` if the tenant doesn't exist.
  - Wires a "Save" page action button tied to `useReconnectTenantForm`.

## Usage Example

```typescript
import { ReconnectTenantView } from './reconnect-tenant-view';

export default function Page({ params }: { params: { id: string } }) {
  return <ReconnectTenantView id={params.id} />;
}
```

The component expects to be rendered within a route that supplies a valid `directoryConnection` `id`. On mount, if no consent URL already exists for the connection, it automatically triggers consent minting; the admin can then verify the connection and edit attribution fields once the grant is readable. If the tenant record cannot be found, it redirects users back to `routes.cloudTenantManagement.list`.
