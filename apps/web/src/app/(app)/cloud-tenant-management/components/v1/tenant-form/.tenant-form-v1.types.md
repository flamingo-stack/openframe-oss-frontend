Zod validation schemas and TypeScript types for the legacy (v1) New/Edit Tenant Integration form, rendered under `cloud-tenant-management` while the `tenant-management-v2` feature flag is off. Validates provider selection, domain format, connection name, and customer binding, with the customer field isolated for easy removal when phase 2 decouples customers from connections.

## Key Components

- **`domainSchema`** - Validates a registrable domain string (lowercase, trimmed, dot-joined labels, no protocol/path/spaces) used as the tenant segment in Microsoft 365 admin consent URLs.
- **`tenantCustomerFieldSchemaV1`** - Isolated schema fragment requiring `organizationId` (customer selection). Marked as the phase-2 removal point.
- **`tenantFormSchemaV1`** - Combined schema for the "New Tenant" form: `provider` (enum), `domain`, `name`, extended with the customer field schema.
- **`TenantFormDataV1`** - Inferred TypeScript type from `tenantFormSchemaV1`.
- **`editTenantFormSchemaV1`** - Variant for editing, where `domain` is relaxed to any string (edit never resends domain; stored value may be a GUID or empty).
- **`TENANT_FORM_DEFAULT_VALUES_V1`** - Default form values, pre-selecting `DirectoryProvider.MICROSOFT_365`.

## Usage Example

```typescript
import {
  tenantFormSchemaV1,
  editTenantFormSchemaV1,
  TENANT_FORM_DEFAULT_VALUES_V1,
  type TenantFormDataV1,
} from './tenant-form.types';

// New tenant form (e.g. with react-hook-form + zodResolver)
const form = useForm<TenantFormDataV1>({
  resolver: zodResolver(tenantFormSchemaV1),
  defaultValues: TENANT_FORM_DEFAULT_VALUES_V1,
});

// Edit tenant form - domain validation relaxed
const editForm = useForm<TenantFormDataV1>({
  resolver: zodResolver(editTenantFormSchemaV1),
  defaultValues: { ...existingTenant },
});
```
