# tenant-detail-view-v1.tsx

Legacy (v1) tenant detail view component rendered when the `tenant-management-v2` feature flag is off. This is the pre-flag implementation of the cloud tenant detail page and is slated for deletion once the flag is removed, with `tenant-detail-view.tsx` serving as the canonical successor.

Unlike pages using `PageLayout`, this view intentionally skips the shared layout wrapper because the page title itself is derived from the fetched tenant record — only the inner content island (`TenantDetailContentV1`) needs to handle the loading state while data resolves.

## Key Components

- **`manageActions(id: string)`** — Builds the page action button configuration (`PageActionButton[]`) for tenant management: a "Reconnect" button linking to the reconnect route, and an "Edit Integration" button linking to the edit route, both using outline-variant buttons with icons.
- **`TenantDetailViewProps`** — Props interface accepting:
  - `id: string` — the tenant identifier
  - `loading?: boolean` — indicates the feature flag hasn't resolved yet, so the frame renders but no data fetch occurs
- **`TenantDetailViewV1`** — Default export component that renders a flex column wrapper around `TenantDetailContentV1`, passing through `id`, computed `actions`, and `loading`.

## Usage Example

```typescript
import { TenantDetailViewV1 } from './tenant-detail-view-v1';

function TenantPage({ params }: { params: { id: string } }) {
  const { flagResolved } = useFeatureFlag('tenant-management-v2');

  return (
    <TenantDetailViewV1
      id={params.id}
      loading={!flagResolved}
    />
  );
}
```

This component is typically rendered conditionally based on the `tenant-management-v2` flag state within the parent route file at `apps/web/src/app/(app)/cloud-tenant-management/components/tenant-detail/tenant-detail-view.tsx`.
