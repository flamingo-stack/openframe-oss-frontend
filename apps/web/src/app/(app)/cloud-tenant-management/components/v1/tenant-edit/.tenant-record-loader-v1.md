Legacy (v1) data-loading component for the Cloud Tenant Management "Edit Tenant" page. It fetches a tenant/directory connection via Relay, renders the tenant's identity card, and reports the resolved record state up to the parent so it can seed the edit form. This file is rendered only while the `tenant-management-v2` feature flag is off and is slated for deletion once the flag is removed.

## Key Components

- **`tenantRecordLoaderV1Query`** — GraphQL query fetching a `directoryConnection` by `id`, including fragments for the tenant form helpers and summary card.
- **`TenantRecordStateV1`** — Discriminated union describing the record's load state: `loading`, `missing`, or `ready` (with form values and organization).
- **`TenantRecordLoaderV1`** — Public entry component; wraps the reader in a `LoadingSuspense` boundary with a "Loading tenant" label.
- **`TenantRecordLoaderReader`** — Detects whether it's inside a loading scope (suspense fallback or flag transition window) and short-circuits to a loading identity card if so.
- **`TenantRecordQuery`** — Performs the actual Relay query, derives the `TenantRecordStateV1` via `readTenantFormRecordV1`, and reports it to the parent via `onResolved` inside a `useLayoutEffect` (to seed/unlock the form before paint).

## Usage Example

```typescript
import { TenantRecordLoaderV1, type TenantRecordStateV1 } from './tenant-record-loader-v1';
import { useState } from 'react';

function TenantEditPage({ tenantId }: { tenantId: string }) {
  const [record, setRecord] = useState<TenantRecordStateV1>({ status: 'loading' });

  return (
    <>
      <TenantRecordLoaderV1 id={tenantId} onResolved={setRecord} />
      {record.status === 'ready' && (
        <TenantEditForm values={record.values} organization={record.organization} />
      )}
      {record.status === 'missing' && <NotFoundMessage />}
    </>
  );
}
```

**Notes:**
- `onResolved` must be stable (e.g., memoized) to avoid redundant state updates, since it's a `useLayoutEffect` dependency.
- The form-seeding logic (`useSeedForm`) lives in the parent component, not here — this loader only reads and reports data.
- Identity stability of the `values` object matters: it only changes when the underlying `connection` changes, thanks to `useMemo`.
