## new-tenant-view-v1.tsx

Legacy (v1) React component rendering the "New Tenant" form at `/cloud-tenant-management/new`, shown before a tenant record exists. It lets the user pick a directory provider, fill in required fields, and generate a connection link; on success the flow transitions to `ConnectTenantViewV1` via the `?id=` query param. This file is the pre-`tenant-management-v2` implementation and is slated for deletion once that feature flag is removed.

## Key Components

- **`NewTenantViewV1()`** — Main exported component. Composes:
  - `useNewTenantFormV1()` — supplies the form instance, `isCreating` state, and `generateLink` handler.
  - `useFormState` (react-hook-form) — tracks live form validity (`mode: 'onChange'`).
  - `useLoadingScope()` — detects an active loading scope to lock fields and defer fetching.
  - `ProviderFieldV1` — provider picker; reports which `DirectoryProvider`s the deployment offers via `onOffered`.
  - `TenantFormFieldsV1` — renders the remaining form fields alongside the provider field.
  - `TenantFormFrame` — shared layout wrapper with title and consistent chrome.
  - An effect that auto-selects the first offered provider if the current selection isn't available in the deployment's offered set.

## Usage Example

```typescript
import { NewTenantViewV1 } from './new-tenant-view-v1';

// Rendered by the parent route when tenant-management-v2 flag is disabled
export default function CloudTenantManagementNewPage() {
  return <NewTenantViewV1 />;
}
```

Behavior notes:
- The **Generate Connection Link** button stays disabled until the form is valid and at least one provider is confirmed as offered (`!isValid || !offered || offered.length === 0`).
- While `isCreating` or an ancestor `loading` scope is active, all fields are disabled and the button shows a loading spinner.
- Since a deployment may support only a single provider, the component automatically corrects the preselected provider to match what's actually available.
