# reconnect-tenant-view-v1.tsx

Legacy (v1) implementation of the tenant reconnect page, rendered while the `tenant-management-v2` feature flag is off. This component lets an operator re-establish OAuth consent for a cloud directory connection whose link has expired or failed, pairing the tenant identity card with a consent block that auto-mints a new consent URL when none is outstanding. It is slated for deletion once the v2 flag is fully rolled out.

## Key Components

- **`ReconnectTenantViewV1({ id })`** — Public entry point. Wraps content in a `LoadingSuspense` boundary (`live` mode) with a "Loading tenant" label.
- **`ReconnectTenantContent({ id })`** — Detects whether it's inside a loading scope (via `useLoadingScope()`) and renders static skeleton chrome (identity card + consent block in loading states) versus the live, data-fetching version.
- **`ReconnectTenantContentQuery({ id })`** — Core logic:
  - Fetches the `directoryConnection` via `reconnectTenantViewV1Query` (Relay), using `store-or-network` fetch policy to avoid clobbering a freshly-minted consent URL with a stale background refetch.
  - Uses `useStartConsent` to auto-mint a new consent URL only when no outstanding URL exists.
  - Uses `useCheckConnection` to poll/verify consent approval status.
  - Renders `TenantIdentityCardV1` and `ConsentBlock` (mode `"reconnect"`) inside `TenantFormFrame`, with a single "Save" action that simply navigates back to the tenant details page.
  - Shows `NotFoundError` if the connection doesn't exist.
- **`reconnectTenantViewV1Query`** — GraphQL query fetching `id`, `provider`, `consentUrl`, and identity fragment data for the connection.

## Usage Example

```typescript
import { ReconnectTenantViewV1 } from './reconnect-tenant-view-v1';

// Rendered by a route/page component when tenant-management-v2 flag is disabled
export default function ReconnectPage({ params }: { params: { id: string } }) {
  return <ReconnectTenantViewV1 id={params.id} />;
}
```

**Note:** This file is tied directly to the `tenant-management-v2` feature flag. When the flag is permanently enabled, this file—along with its v1 sibling components—should be removed in favor of the v2 implementation at `apps/web/src/app/(app)/cloud-tenant-management/components/tenant-reconnect/reconnect-tenant-view.tsx`.
