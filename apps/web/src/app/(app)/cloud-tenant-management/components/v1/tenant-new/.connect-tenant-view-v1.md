This file defines a thin wrapper component that renders the tenant connection view when the `tenant-management-v2` feature flag is disabled. It serves as the legacy (V1) entry point for the tenant consent hand-off flow on the `/cloud-tenant-management/new?id=` route, and is slated for removal once the flag is fully rolled out.

## Key Components

- **`ConnectTenantViewV1`** - A client component that accepts a tenant `id` prop and delegates rendering to `ConnectTenantContentV1`, which handles the actual consent/connection UI for a tenant record previously created by the "Generate" flow.

## Usage Example

```typescript
import { ConnectTenantViewV1 } from './connect-tenant-view-v1';

// Rendered on the /cloud-tenant-management/new route when
// the tenant-management-v2 flag is off
export default function NewTenantPage({ searchParams }: { searchParams: { id: string } }) {
  return <ConnectTenantViewV1 id={searchParams.id} />;
}
```

## Notes

- This component is tied to the `tenant-management-v2` feature flag and exists purely as a V1 fallback alongside the V2 implementation.
- When the feature flag is fully enabled and removed from the codebase, this file (along with `connect-tenant-content-v1`) should be deleted as part of cleanup.
- All actual rendering logic lives in `ConnectTenantContentV1`; this file only forwards the `id` parameter.
