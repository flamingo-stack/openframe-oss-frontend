# connect-tenant-content-v1.tsx

Renders the "connect tenant" step of the tenant onboarding flow for the legacy (v1) UI, shown when the `tenant-management-v2` feature flag is off. Fetches the directory connection record by ID via GraphQL and hands it to the connect form, handling loading and not-found states.

## Key Components

- **`connectTenantContentV1Query`** — GraphQL query fetching a `directoryConnection` by `id`, spreading the `tenantFormHelpersV1_connection` fragment used to populate the form.
- **`ConnectTenantContentV1({ id })`** — Public entry component. Wraps the reader in a `LoadingSuspense` boundary with a "Loading tenant form" label.
- **`ConnectTenantContentReader({ id })`** — Internal dispatcher. If rendering inside a loading scope (e.g. a Suspense fallback), renders `ConnectTenantFormV1` with a `null` record instead of issuing the query, avoiding a stale/empty `consentUrl` overwrite.
- **`ConnectTenantContentQuery({ id })`** — Performs the actual `useLazyLoadQuery` fetch (policy `store-or-network`, keyed by `useRetryKey` for retries). Renders a `NotFoundError` inside a `PageLayout` if no connection is found, otherwise passes the parsed record (via `readTenantFormRecordV1`) to `ConnectTenantFormV1`.

## Usage Example

```typescript
import { ConnectTenantContentV1 } from './connect-tenant-content-v1';

export default function ConnectTenantPage({ params }: { params: { id: string } }) {
  return <ConnectTenantContentV1 id={params.id} />;
}
```

**Notes:**
- This component is tied to the legacy tenant management flow and is slated for deletion once `tenant-management-v2` fully replaces it.
- The loading-scope check prevents a background refetch from clobbering a `consentUrl` that was just minted on mount for a newly created, unlinked record.
- Navigation back uses `useSafeBack` targeting `routes.cloudTenantManagement.list`.
