# connect-tenant-content-v1.tsx

Legacy (v1) implementation of the "connect tenant" step in the Cloud Tenant Management flow, rendered only while the `tenant-management-v2` feature flag is off. It fetches a previously created directory connection record via Relay and hands it off to the connect form. This file is slated for deletion once the flag is removed.

## Key Components

- **`ConnectTenantContentV1`** — Public entry component. Wraps `ConnectTenantContentReader` in a `LoadingSuspense` boundary with a "Loading tenant form" label, giving the subtree its own suspense scope.
- **`ConnectTenantContentReader`** — Internal reader that checks `useLoadingScope()`. If currently inside a loading scope (e.g. a fallback render), it renders `ConnectTenantFormV1` with a `null` record to show the form's native loading state instead of triggering a Relay fetch.
- **`ConnectTenantContentQuery`** — Runs the `connectTenantContentV1Query` GraphQL query via `useLazyLoadQuery`, using `fetchPolicy: 'store-or-network'` so a freshly created record (already in the Relay store) resolves without a network round-trip. Renders a `NotFoundError` inside `PageLayout` if the connection is missing, otherwise renders `ConnectTenantFormV1` with the parsed record from `readTenantFormRecordV1`.
- **`connectTenantContentV1Query`** — GraphQL query fetching `directoryConnection(connectionId: $id)` and spreading the `tenantFormHelpersV1_connection` fragment.

## Usage Example

```typescript
import { ConnectTenantContentV1 } from './connect-tenant-content-v1';

export default function ConnectTenantPage({ params }: { params: { id: string } }) {
  return <ConnectTenantContentV1 id={params.id} />;
}
```

**Note:** Uses `useRetryKey()` to allow manual refetching and `useSafeBack` to navigate back to `routes.cloudTenantManagement.list` on error. The deliberate avoidance of background refresh prevents an empty `consentUrl` from overwriting a just-minted record on mount.
