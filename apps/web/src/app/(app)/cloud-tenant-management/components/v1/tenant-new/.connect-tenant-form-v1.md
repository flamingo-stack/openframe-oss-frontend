# connect-tenant-form-v1.tsx

Renders the "connect tenant" step of the cloud tenant management flow (legacy v1, used while the `tenant-management-v2` feature flag is off). This step reuses the create-tenant form layout but locks the provider and domain fields, replaces the Generate button with a consent card, and moves the Save action into the page title bar. It handles three UI states: pending (no record yet), loaded with domain locked (showing consent/mint status), and loaded with domain unlocked for editing (showing the Generate Link button again).

## Key Components

- **`ConnectTenantFormV1({ record })`** - Entry point component. Shows `PendingConnectTenantForm` while loading or when `record` is `null`, otherwise renders `LoadedConnectTenantForm`.
- **`LoadedConnectTenantForm({ record })`** - Main form logic via `useConnectTenantFormV1` hook. Wires up save/generate actions, mint retry, and domain-edit toggling. Conditionally shows either the "Generate Link" button (domain editing mode) or the `ConsentBlock` with mint-failure error handling.
- **`ConnectTenantFormView(...)`** - Shared presentational frame wrapping `TenantFormFrame` and `TenantFormFieldsV1`, used identically by both loaded and pending states to avoid layout flicker.
- **`PendingConnectTenantForm()`** - Renders the same frame with a throwaway `useForm` instance and a disabled Save action, delegating its own loading indication to `ConsentBlock`.

## Usage Example

```typescript
import { ConnectTenantFormV1 } from './connect-tenant-form-v1';
import type { TenantFormRecordV1 } from '../tenant-form/tenant-form-helpers-v1';

function TenantConnectPage({ record }: { record: TenantFormRecordV1 | null }) {
  return (
    <div className="page-container">
      <ConnectTenantFormV1 record={record} />
    </div>
  );
}
```

**Note:** This component is rendered only when `tenant-management-v2` is disabled and is slated for deletion once the flag is fully removed. Prefer the v2 equivalent for new work.
