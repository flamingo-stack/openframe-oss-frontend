# connect-tenant-form-v1.tsx

Legacy (v1) implementation of the tenant "connect" step form, rendered when the `tenant-management-v2` feature flag is off. Mirrors the create-tenant form but locks provider/domain fields and swaps the Generate button for a consent card, unless the domain is being edited. This file is slated for deletion once the v2 flag is fully rolled out.

## Key Components

- **`ConnectTenantFormV1({ record })`** — Top-level entry point. Shows a pending/loading state via `PendingConnectTenantForm` when inside a loading scope or `record` is `null`; otherwise renders `LoadedConnectTenantForm`.
- **`LoadedConnectTenantForm({ record })`** — Main form logic using `useConnectTenantFormV1` hook. Handles save/generate actions, domain editing toggle, OAuth consent minting state, and error retry via `SectionLoadError`.
- **`ConnectTenantFormView`** — Shared presentational frame combining `TenantFormFrame`, `TenantFormFieldsV1`, and a locked `ProviderFieldV1`, used by both loaded and pending states to keep markup consistent.
- **`PendingConnectTenantForm`** — Renders a disabled/busy form with a throwaway `useForm` instance while the real record is still loading, delegating its own loading UI to `ConsentBlock`.

## Usage Example

```typescript
import { ConnectTenantFormV1 } from './connect-tenant-form-v1';
import type { TenantFormRecordV1 } from '../tenant-form/tenant-form-helpers-v1';

function TenantConnectPage({ record }: { record: TenantFormRecordV1 | null }) {
  return <ConnectTenantFormV1 record={record} />;
}
```

The component internally decides whether to show a loading placeholder or the fully interactive form based on the presence of `record` and ambient loading scope state—no additional wiring is required by the caller.
