## tenant-detail-content-v1.tsx

Renders the tenant detail page body for the legacy (v1) tenant-management flow — the version of `tenant-detail-content.tsx` used while the `tenant-management-v2` feature flag is off. It fetches a single directory connection by ID and composes the title, summary card, consent handling, and integration section around its connection/loading/not-found states. This file is deleted once the v2 flag is fully rolled out.

## Key Components

- **`TenantDetailContentV1`** — Public entry component. Wraps the reader in `LoadingSuspense`, gating rendering while the owning module's flag is still resolving.
- **`TenantDetailContentReader`** — Internal component that checks `useLoadingScope()` to decide between rendering skeleton/loading UI (title, summary card, integration section as placeholders) or delegating to the data-fetching query component.
- **`TenantDetailContentQuery`** — Fetches `tenantDetailContentV1Query` via `useLazyLoadQuery`, handles the "tenant not found" case, and renders the real page: title, summary card, consent alert/issues, and either the integration section (if the connection is readable) or a `ConsentBlock` prompting consent/reconnection.
- **`tenantDetailContentV1Query`** — GraphQL query fetching `directoryConnection` by `id`, including fragments for the summary card and consent components. Integration rows are fetched separately inside `TenantIntegrationSectionV1`.

## Usage Example

```typescript
import { TenantDetailContentV1 } from './tenant-detail-content-v1';

function TenantDetailPage({ tenantId, pageActions, flagLoading }: {
  tenantId: string;
  pageActions: PageActionButton[];
  flagLoading: boolean;
}) {
  return (
    <TenantDetailContentV1
      id={tenantId}
      actions={pageActions}
      loading={flagLoading}
    />
  );
}
```

This component is typically rendered by a page-level route component in `cloud-tenant-management`, conditionally selected based on the `tenant-management-v2` flag state, alongside its v2 counterpart.
