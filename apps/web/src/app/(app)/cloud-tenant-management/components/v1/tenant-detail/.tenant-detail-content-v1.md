# tenant-detail-content-v1.tsx

Renders the legacy (v1) body of the Cloud Tenant Management detail page, shown while the `tenant-management-v2` feature flag is off. It fetches a single `directoryConnection` by id via Relay, handles its own loading and not-found states, and conditionally shows either the live integration section (for connected tenants) or a consent hand-off block (for tenants pending connection). This file is slated for deletion once the v2 flag is fully rolled out.

## Key Components

- **`tenantDetailContentV1Query`** — GraphQL query fetching the tenant connection (`id`, `name`, `provider`, `consentUrl`, `access.state`) plus fragment spreads for the summary card and consent components. Integration rows are fetched separately by `TenantIntegrationSectionV1`.
- **`TenantDetailContentV1`** — Public entry component. Wraps the reader in `LoadingSuspense`, gated by the `loading` prop (true while the owning flag hasn't resolved yet), so nothing fetches during that window.
- **`TenantDetailContentReader`** — Internal switch that renders skeleton/loading UI (via `useLoadingScope`) or delegates to the data-fetching query component.
- **`TenantDetailContentQuery`** — Executes `useLazyLoadQuery`, handles the "not found" case (unknown id), and renders the title, summary card, consent alerts/issues, and either the integration section (wrapped in `ContentErrorBoundary`) or `ConsentBlock` depending on `access.state` readability.

## Usage Example

```typescript
import { TenantDetailContentV1 } from './tenant-detail-content-v1';

function TenantDetailPage({ tenantId, isFlagLoading }: { tenantId: string; isFlagLoading: boolean }) {
  const actions = [
    { label: 'Reconnect', href: `/tenants/${tenantId}/reconnect` },
    { label: 'Edit', href: `/tenants/${tenantId}/edit` },
  ];

  return (
    <TenantDetailContentV1
      id={tenantId}
      actions={actions}
      loading={isFlagLoading}
    />
  );
}
```

Rendering is driven entirely by `connection.access.state`: readable states show `TenantIntegrationSectionV1` inside an error boundary, while unreadable states (pending consent) show `ConsentBlock` with live connection-check status via `useCheckConnection`.
