## Overview

Legacy (v1) view component for editing a cloud tenant integration at `/cloud-tenant-management/edit`. It renders the tenant form frame immediately, loads the tenant record asynchronously, and keeps the form fields locked until the record resolves. This file is rendered only while the `tenant-management-v2` feature flag is off and will be deleted along with the flag.

## Key Components

- **`EditTenantViewV1`** — Main component accepting a tenant `id`. Manages record-loading state (`loading` / `ready` / `missing`) and wires it into the form, action buttons, and conditional rendering (not-found error vs. locked/loading fields).
- Uses **`TenantRecordLoaderV1`** to fetch the tenant record and resolve state via `onResolved`.
- Uses **`useEditTenantFormV1`** hook to manage form control, submission state, and save handler, seeded once the record is ready.
- Renders **`TenantFormFrame`** as the page shell with title and save action, **`TenantFormFieldsV1`** for the editable fields, **`LoadingWhen`** to gate field interactivity, and **`NotFoundError`** for missing tenants.

## Usage Example

```typescript
import { EditTenantViewV1 } from './edit-tenant-view-v1';

export default function EditTenantPage({ params }: { params: { id: string } }) {
  return <EditTenantViewV1 id={params.id} />;
}
```

Internally, the component composes state and behavior like this:

```typescript
const [record, setRecord] = useState<TenantRecordStateV1>({ status: 'loading' });
const ready = record.status === 'ready';
const { form, isSubmitting, handleSave } = useEditTenantFormV1(id, ready ? record.values : null);
```

The fields remain disabled (`disabled={!ready || isSubmitting}`) and wrapped in `LoadingWhen` until the record resolves, preventing edits against stale or empty data. If the tenant cannot be found, a `NotFoundError` is shown with a link back to the tenant list via `routes.cloudTenantManagement.list`.
