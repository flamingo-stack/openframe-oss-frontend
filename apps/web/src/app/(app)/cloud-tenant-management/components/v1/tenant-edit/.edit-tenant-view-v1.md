# edit-tenant-view-v1.tsx

Legacy (v1) client component that renders the Edit Tenant page at `/cloud-tenant-management/edit`, active only while the `tenant-management-v2` feature flag is off. It coordinates record loading, form state, and save actions for editing a cloud tenant integration, and is slated for deletion once the flag is removed.

## Key Components

- **`EditTenantViewV1`** — Main exported component. Accepts a tenant `id` prop and:
  - Tracks tenant record loading state (`loading` / `ready` / `missing`) via `TenantRecordLoaderV1`.
  - Wires up form state and submission through `useEditTenantFormV1`.
  - Renders a `NotFoundError` view if the tenant record is missing, redirecting to the tenant list on "Home".
  - Wraps `TenantFormFieldsV1` in `LoadingWhen` to lock fields until the record resolves.
  - Builds a `PageActionButton` array (save action) passed to `TenantFormFrame`, disabling/loading it based on readiness and submission state.

- **`RECORD_LOADING`** — Initial `TenantRecordStateV1` constant representing the loading state before the record resolves.

## Usage Example

```typescript
import { EditTenantViewV1 } from './edit-tenant-view-v1';

export default function EditTenantPage({ params }: { params: { id: string } }) {
  return <EditTenantViewV1 id={params.id} />;
}
```

**Notes:**
- This component is purely presentational/orchestration — form logic lives in `useEditTenantFormV1`, and record fetching lives in `TenantRecordLoaderV1`.
- `TenantFormFieldsV1` is rendered with `hideDomain` (domain not editable here) and receives `includeOrganization`/`customersEnabled` only once the record is `ready`.
- This file is part of the v1 fallback path; new development should target the `tenant-management-v2` equivalent at `apps/web/src/app/(app)/cloud-tenant-management/components/tenant-edit/edit-tenant-view.tsx`.
