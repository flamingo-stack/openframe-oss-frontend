Renders the legacy (pre-`tenant-management-v2`) summary card for a tenant's directory connection on the Cloud Tenant Management detail page, showing provider, domain, customer, user count, status, and sync timestamps with built-in loading-skeleton support.

## Key Components

- **`TenantIdentityCardV1`** — Single-row card variant used on Edit / Reconnect flows; shows only provider and domain name. Consumes `tenantSummaryCardV1_identity$key`.
- **`TenantSummaryCardV1`** — Two-row full card used on the tenant details page; shows provider, domain, customer (with avatar), user count, access status tag, connected date, and last-read timestamp. Consumes `tenantSummaryCardV1_connection$key`.
- **`ProviderCell`** — Internal cell rendering the provider logo and label, with skeleton fallback when provider is `null`.
- **`ConnectedCell`** — Internal cell formatting the `connectedAt` timestamp into date/time parts.
- **GraphQL fragments** — `tenantSummaryCardIdentityFragment` and `tenantSummaryCardFragment` define the `DirectoryConnection` fields each card variant needs.
- **`LABELS`, `CARD_CLASSES`, `ROW_CLASSES`, `DIVIDED_ROW_CLASSES`** — Shared static label text and Tailwind class constants for layout consistency.

Both components rely on `useLoadingScope` and `LoadingWhen` to render a skeleton state automatically when the record hasn't loaded yet, ensuring no layout shift once data arrives.

## Usage Example

```typescript
import { TenantSummaryCardV1, TenantIdentityCardV1 } from './tenant-summary-card-v1';

// Full details-page card
function TenantDetailPage({ connectionRef }: { connectionRef: tenantSummaryCardV1_connection$key | null }) {
  return <TenantSummaryCardV1 connection={connectionRef} />;
}

// Compact card for Edit / Reconnect flows
function ReconnectPanel({ connectionRef }: { connectionRef: tenantSummaryCardV1_identity$key | null }) {
  return <TenantIdentityCardV1 connection={connectionRef} />;
}
```
