## Key Components

- **`SERVER_ERROR`** — Constant marking field errors set by server-side refusals (as opposed to client-side validation), used to distinguish which errors should be left untouched during re-validation.
- **`shownErrorPaths(form)`** — Scans all customer entries and returns the field paths currently displaying a non-server validation error, used to selectively re-trigger validation.
- **`useAttributionForm(initial, seed?)`** — Main hook that manages the "Customers and attribution" form shared by Connect, Edit, and Reconnect flows. Returns `{ form, seeded, placeUserErrors }`.

## Usage Example

```typescript
import { useAttributionForm } from './use-attribution-form';

function AttributionFormPanel({ initialData, fetchedRecord }: Props) {
  const { form, seeded, placeUserErrors } = useAttributionForm(initialData, fetchedRecord);

  const onSubmit = form.handleSubmit(async (data) => {
    const result = await saveAttribution(data);
    if (result.errors) {
      // Map server-side field errors (e.g. duplicate organization) onto the form
      placeUserErrors(result.errors);
    }
  });

  return (
    <form onSubmit={onSubmit}>
      {/* customers[] fields bound via form.control */}
    </form>
  );
}
```

### Behavior Notes

- `initial` populates the form on mount (used by Connect/Reconnect, which have data upfront).
- `seed` populates the form once an async record resolves (used by Edit, which renders before data arrives); `seeded` reports which seed was actually applied, ignoring late seeds if the form is already dirty.
- The hook automatically re-validates currently-errored customer fields (excluding server-set errors) whenever any customer field changes, since certain validation rules (e.g. "All accounts" conflicts, duplicate values across rules) can be resolved by editing a *different* field than the one showing the error.
- `placeUserErrors` maps backend validation failures (`TenantUserError[]`) onto the correct form field paths based on the current `mode`.
