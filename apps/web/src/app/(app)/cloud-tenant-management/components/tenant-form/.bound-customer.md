# bound-customer.ts

Provides a reusable Relay fragment and helper functions for reading and formatting a customer bound to a directory connection, ensuring consistent naming and badge display across all screens that reference it.

## Key Components

- **`boundCustomerFragment`** — Inline GraphQL fragment on `DirectoryConnectionCustomer` that selects `organizationId` and the organization's `status`, spreading in `customerOption_organization` for shared customer-option formatting.
- **`readBoundCustomer(ref)`** — Reads the inline fragment data from a `boundCustomer_customer$key` and returns a plain `BoundCustomer` object (no fragment reference retained), suitable for form state or other non-Relay-aware code.
- **`boundCustomerOption(ref)`** — Converts a fragment reference into a `PickerCustomer`, applying the shared `storedOption` naming/badge convention.
- **`boundCustomerOptions(refs)`** — Maps a list of fragment references to `PickerCustomer` options and sorts them so active (badged) customers appear first.

## Usage Example

```typescript
import { boundCustomerOptions, readBoundCustomer } from './bound-customer';

// In a component rendering a list of directory connections
function DirectoryCustomerList({ customers }: { customers: boundCustomer_customer$key[] }) {
  const options = boundCustomerOptions(customers);

  return (
    <ul>
      {options.map((option) => (
        <li key={option.organizationId}>
          {option.label} {option.badge && <span>{option.badge}</span>}
        </li>
      ))}
    </ul>
  );
}

// In form logic that needs plain data without holding a fragment ref
function initializeFormState(ref: boundCustomer_customer$key) {
  const boundCustomer = readBoundCustomer(ref);
  return { organizationId: boundCustomer.organizationId };
}
```
