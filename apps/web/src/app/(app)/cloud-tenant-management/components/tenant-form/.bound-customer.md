# bound-customer.ts

Provides a shared Relay inline fragment and helper functions for reading and formatting customer data bound to a directory connection, ensuring consistent naming and display across all screens that show a bound customer.

## Key Components

- **`boundCustomerFragment`** — GraphQL inline fragment (`boundCustomer_customer`) declared on `DirectoryConnectionCustomer`, fetching `organizationId` and the organization's `status` plus the `customerOption_organization` fragment spread.
- **`readBoundCustomer(ref)`** — Reads the inline fragment data from a `boundCustomer_customer$key` and returns a plain `BoundCustomer` object (organization ID plus an optional organization option enriched with `status`). Intended for code (e.g., forms) that doesn't retain a fragment reference.
- **`boundCustomerOption(ref)`** — Converts a bound customer reference into a `PickerCustomer` using `storedOption`, producing the standardized name/badge representation used across the UI.
- **`boundCustomerOptions(refs)`** — Maps a list of fragment references into `PickerCustomer` options and sorts them so badged (active) entries appear first.

## Usage Example

```typescript
import { readBoundCustomer, boundCustomerOption, boundCustomerOptions } from './bound-customer';
import type { boundCustomer_customer$key } from '@/__generated__/boundCustomer_customer.graphql';

function CustomerCell({ customerRef }: { customerRef: boundCustomer_customer$key }) {
  const option = boundCustomerOption(customerRef);
  return <PickerBadge label={option.label} badge={option.badge} />;
}

function CustomerForm({ customerRef }: { customerRef: boundCustomer_customer$key }) {
  const { organizationId, organization } = readBoundCustomer(customerRef);
  // use organizationId / organization directly without holding a fragment ref
}

function CustomerListCell({ refs }: { refs: readonly boundCustomer_customer$key[] }) {
  const options = boundCustomerOptions(refs);
  return <PickerList options={options} />;
}
```

This module centralizes the logic for displaying bound customers so that every screen (cells, forms, pickers) presents the same label, badge, and ordering behavior.
