Defines the Zod validation schema and TypeScript types for the New/Edit Tenant Integration form, covering provider selection, domain validation, and connection naming.

## Key Components

- **`tenantFormSchema`** — Zod object schema validating `provider` (enum of `DirectoryProvider`), `domain` (registrable domain format), and `name` (1–100 chars) for creating a new tenant connection.
- **`TenantFormData`** — TypeScript type inferred from `tenantFormSchema`, used for form state typing.
- **`editTenantFormSchema`** — Variant of `tenantFormSchema` that relaxes `domain` validation (accepts any string, including a stored GUID or empty value), since edit flows never resend the domain.
- **`TENANT_FORM_DEFAULT_VALUES`** — Default form values with `DirectoryProvider.MICROSOFT_365` pre-selected as the default provider.
- **`domainSchema`** / **`nameSchema`** — Internal reusable field validators with trimming, case normalization, and friendly error messages.
- **`DOMAIN_PATTERN`** / **`DOMAIN_ERROR`** — Regex and error message enforcing a valid registrable domain format (e.g., `contoso.com`), matching the tenant segment used in the Microsoft 365 admin consent URL.

## Usage Example

```typescript
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import {
  tenantFormSchema,
  editTenantFormSchema,
  TenantFormData,
  TENANT_FORM_DEFAULT_VALUES,
} from './tenant-form.types';

// New tenant form
const form = useForm<TenantFormData>({
  resolver: zodResolver(tenantFormSchema),
  defaultValues: TENANT_FORM_DEFAULT_VALUES,
});

// Edit tenant form (domain validation relaxed)
const editForm = useForm<TenantFormData>({
  resolver: zodResolver(editTenantFormSchema),
  defaultValues: {
    ...TENANT_FORM_DEFAULT_VALUES,
    domain: existingTenant.domainId, // may be a GUID or empty
    name: existingTenant.name,
  },
});
```

## Notes

- Domain validation requires at least two dot-separated labels (e.g., `contoso.com`), rejecting protocols, paths, or spaces.
- Customer-level attribution fields are defined separately in `attribution.types.ts` and are not part of this schema.
