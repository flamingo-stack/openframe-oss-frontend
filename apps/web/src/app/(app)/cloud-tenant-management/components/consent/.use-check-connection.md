# use-check-connection.ts

A React hook that drives the "Check Connection" action for directory integrations, triggering a GraphQL mutation that probes a tenant's connection and surfaces the resulting access state or failure as a toast and local verdict.

## Key Components

- **`CheckedAccess`** — Type alias for the `access` payload (state + capabilities) returned by the `checkDirectoryConnection` mutation.
- **`CheckVerdict`** — Discriminated union representing either an `'answered'` result (with access data) or a `'failed'` result (with an error message).
- **`useCheckConnection(connectionId)`** — Hook that exposes:
  - `check()` — Fires the mutation for the current `connectionId`, ignoring the call if one is already in flight or no ID is set.
  - `isChecking` — Boolean mutation-in-flight flag from `useMutation`.
  - `verdict` — The latest `CheckVerdict`, or `null` if no check has completed yet.
  - `reset()` — Clears the verdict and invalidates any in-flight attempt (used when the underlying connection link changes, e.g. Edit Domain → Generate).

Internally, an `attemptRef` counter guards against stale responses landing after the connection ID has changed — only the response matching the latest attempt updates state.

## Usage Example

```typescript
import { useCheckConnection } from './use-check-connection';

function ConnectionCard({ connectionId }: { connectionId: string | null }) {
  const { check, isChecking, verdict, reset } = useCheckConnection(connectionId);

  return (
    <div>
      <button onClick={check} disabled={isChecking}>
        {isChecking ? 'Checking…' : 'Check Connection'}
      </button>

      {verdict?.kind === 'answered' && (
        <p>State: {verdict.access.state}</p>
      )}
      {verdict?.kind === 'failed' && (
        <p role="alert">{verdict.message}</p>
      )}

      {/* Call reset() when connectionId changes, e.g. after editing a domain */}
      <button onClick={reset}>Reset check</button>
    </div>
  );
}
```

Note: failures and non-readable access states automatically trigger a destructive toast via `useToast`, so consuming components only need to render the `verdict` for inline feedback.
