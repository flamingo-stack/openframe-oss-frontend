# use-start-consent.ts

A React hook that mints a directory consent link via a GraphQL mutation, optionally auto-triggering the mint on mount when gated by subscription state. Used by consent flow UI to request a fresh `consentUrl` for a given connection.

## Key Components

- **`startConsentMutation`** — GraphQL mutation definition (`startDirectoryConsent`) that returns the updated connection (`id`, `consentUrl`) or `userErrors`.
- **`MINT_FAILED`** — Exported constant string used as the toast title on mint failure.
- **`StartConsentOptions`** — Options interface with `autoMintWhen` to control automatic minting on mount.
- **`useStartConsent(connectionId, options)`** — Main hook returning:
  - `mint(onMinted?)` — Callback to trigger the mutation; shows a destructive toast and sets failure state on error or user-level refusal.
  - `isMinting` — Boolean indicating in-flight mutation state.
  - `mintFailed` — Boolean flag reflecting the last mint attempt's outcome.

The hook guards against double-minting on mount (e.g., React StrictMode double effects) using a `startedRef`, and only auto-mints when both `autoMintWhen` is true and `useSubscriptionOpen()` reports the subscription gate is open.

## Usage Example

```typescript
import { useStartConsent } from '@/hooks/use-start-consent';

function ConsentCard({ connectionId }: { connectionId: string }) {
  const { mint, isMinting, mintFailed } = useStartConsent(connectionId, {
    autoMintWhen: true, // mint automatically once subscription gate opens
  });

  return (
    <div>
      {mintFailed && <p>Failed to create consent link.</p>}
      <button onClick={() => mint()} disabled={isMinting}>
        {isMinting ? 'Minting…' : 'Regenerate Link'}
      </button>
    </div>
  );
}
```

Because `consentUrl` is read directly off the `connection` object by id, components displaying the link via Relay will automatically re-render once the mutation completes—no manual refetch needed.
