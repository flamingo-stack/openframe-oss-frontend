# consent-block.tsx

A provider-dispatching React component that renders the appropriate consent UI for directory integrations (Microsoft 365 vs. generic providers), acting as a stable seam so consuming pages don't need provider-specific logic.

## Key Components

- **`ConsentBlock`** — Main exported component. Accepts either a fully-resolved `ConsentPanelProps` (provider known) or a `PendingConsentBlockProps` (provider not yet loaded). Dispatches rendering:
  - If `provider === null`: renders `ConsentLinkPanel` wrapped in `LoadingWhen` to show a loading state while the directory record is being fetched.
  - If `provider === DirectoryProvider.MICROSOFT_365`: renders `MicrosoftConsentPanel`, which implements Microsoft-specific consent flow divergences.
  - Otherwise: renders the generic `ConsentLinkPanel`.
- **`PendingConsentBlockProps`** — Interface for the pre-load state, where only `mode` is known and `provider` is `null`.
- Re-exports **`ConsentMode`** and **`ConsentPanelProps`** (aliased as `ConsentBlockProps`) from `./consent-link-panel` for consumer convenience.

## Usage Example

```typescript
import { ConsentBlock } from './consent-block';
import { DirectoryProvider } from '@/generated/schema-enums';

// While the directory record is loading
<ConsentBlock mode="new" provider={null} />

// Once the record resolves to a known provider
<ConsentBlock
  mode="reconnect"
  provider={DirectoryProvider.MICROSOFT_365}
  consentUrl="https://login.microsoftonline.com/..."
  checking={false}
  verdict={null}
  onCheck={() => refreshConsentStatus()}
/>
```

This allows pages (New, Reconnect, Details) to render a single `<ConsentBlock>` without branching on provider type themselves — the branching logic is centralized here.
