A client-side React component that renders the consent step UI for directory provider integrations, dispatching to a provider-specific panel implementation while presenting a unified interface to consumer pages.

## Key Components

- **`ConsentBlock`** — The main exported component. Accepts either a `ConsentPanelProps` (when the provider record is known) or `PendingConsentBlockProps` (when only the `mode` is known and `provider` is `null`). It dispatches rendering based on `provider`:
  - `provider === null` → renders `ConsentLinkPanel` wrapped in `LoadingWhen` to show a loading state.
  - `provider === DirectoryProvider.MICROSOFT_365` → renders `MicrosoftConsentPanel`.
  - any other provider → renders the generic `ConsentLinkPanel`.
- **`PendingConsentBlockProps`** — Internal interface describing the pre-record state (`mode` known, `provider: null`).
- **Re-exported types** — `ConsentMode` and `ConsentPanelProps` (aliased as `ConsentBlockProps`) are re-exported from `./consent-link-panel` for consumers.

## Usage Example

```typescript
import { ConsentBlock } from './consent-block';
import { DirectoryProvider } from '@/generated/schema-enums';

// Before the directory record is loaded
<ConsentBlock mode="new" provider={null} />

// Once the record is known, with Microsoft 365 provider
<ConsentBlock
  mode="reconnect"
  provider={DirectoryProvider.MICROSOFT_365}
  consentUrl="https://login.microsoftonline.com/..."
  checking={false}
  verdict={null}
  onCheck={() => {/* trigger consent check */}}
/>

// Generic provider falls back to the shared panel
<ConsentBlock
  mode="new"
  provider={DirectoryProvider.GOOGLE_WORKSPACE}
  consentUrl="https://accounts.google.com/..."
  checking={false}
  verdict="granted"
  onCheck={() => {/* trigger consent check */}}
/>
```

This component allows pages like "New", "Reconnect", and directory details to render consent flows without needing provider-specific logic—`ConsentBlock` and its sibling panels encapsulate that complexity.
