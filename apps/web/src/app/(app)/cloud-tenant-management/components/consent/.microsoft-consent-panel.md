This file defines the Microsoft 365 integration's consent panel by re-exporting the shared `ConsentLinkPanel` component under a Microsoft-specific name, since Microsoft's admin-consent flow uses a generated link identical in shape to Google's.

## Key Components

- **`MicrosoftConsentPanel`** — Re-exported alias of `ConsentLinkPanel` from `./consent-link-panel`, used wherever the Microsoft 365 consent UI is needed.

## Usage Example

```typescript
import { MicrosoftConsentPanel } from './microsoft-consent-panel';

function IntegrationSettings() {
  return (
    <MicrosoftConsentPanel
      integrationName="Microsoft 365"
      // props mirror those of ConsentLinkPanel, since
      // Microsoft's admin-consent URL follows the same pattern as Google's
    />
  );
}
```

## Notes

- This is intentionally a thin re-export, not a distinct implementation. The code comment documents that Microsoft's admin-consent flow (`login.microsoftonline.com/<domain>/v2.0/adminconsent?…`) was confirmed to behave like Google's link-based consent flow on the feature environment.
- If Microsoft's consent flow ever diverges from the shared link-based pattern (e.g., requiring a different UI or flow logic), only this file's body needs to change — swap the re-export for a dedicated `MicrosoftConsentPanel` implementation without affecting consumers importing from this module.
- Marked `'use client'` since it is part of the client-side component tree (likely Next.js App Router).
