This file defines the Microsoft 365 admin-consent UI panel by re-exporting the shared `ConsentLinkPanel` component under a Microsoft-specific name, since Microsoft's OAuth admin-consent flow uses a link-based pattern identical to Google's.

## Key Components

- **`MicrosoftConsentPanel`** — Re-exported alias of `ConsentLinkPanel` from `./consent-link-panel`, used wherever the Microsoft 365 integration needs to render its admin-consent link UI.

## Usage Example

```typescript
import { MicrosoftConsentPanel } from './microsoft-consent-panel';

export function IntegrationSettings() {
  return (
    <div>
      <h2>Microsoft 365 Integration</h2>
      <MicrosoftConsentPanel
        // props accepted by ConsentLinkPanel, e.g. consentUrl, onConnect, status, etc.
      />
    </div>
  );
}
```

## Notes

This is a thin wrapper/alias module, not a standalone implementation. It exists to give the Microsoft integration its own named component for clarity in imports and routing, while delegating all rendering logic to the shared `ConsentLinkPanel`. If Microsoft's admin-consent flow ever diverges from the generic link-based pattern (e.g., requiring a different UI or multi-step flow), the implementation should be moved into this file directly rather than modifying the shared component.
