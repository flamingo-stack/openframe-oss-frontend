# use-tenant-management-gate.ts

Provides feature-flag gates that control access to the Cloud Tenant Management module, including a phased rollout mechanism for v2 functionality. Built on top of the generic `useFeatureFlagGate` hook, returning a tri-state result (`'on'` | `'off'` | `'loading'`) so pages can render skeletons during loading instead of prematurely showing 404s.

## Key Components

- **`useTenantManagementGate()`** — Gates every page under `/cloud-tenant-management` based on the `tenant-management` flag. The sidebar's "Integrations" nav item relies on the same flag via `NavigationFlags`.
- **`useTenantManagementV2Gate()`** — Gates Phase 2 features. Resolves to `'on'` only when **both** `tenant-management` and `tenant-management-v2` flags are `'on'`. If either flag is still loading, the combined result is `'loading'`; otherwise it falls back to `'off'`, which routes to the legacy v1 screens/operations.

## Usage Example

```typescript
'use client';

import { useTenantManagementGate, useTenantManagementV2Gate } from '@/app/hooks/use-tenant-management-gate';

export function CloudTenantManagementPage() {
  const gate = useTenantManagementGate();

  if (gate === 'loading') return <PageSkeleton />;
  if (gate === 'off') return null; // handled by router/404 logic

  return <TenantManagementContent />;
}

export function TenantDetailScreen() {
  const v2Gate = useTenantManagementV2Gate();

  if (v2Gate === 'loading') return <SectionSkeleton />;

  return v2Gate === 'on' ? <TenantDetailV2 /> : <TenantDetailV1 />;
}
```

**Notes:**
- Both flags for Phase 2 originate from a single backend answer, so `tenant-management` and `tenant-management-v2` always resolve together—never independently inconsistent.
- The backend serves the phase-2 schema under the same API key regardless of flag state; the `'off'` branch simply determines which frontend screens/operations (`v1/`) are used.
