# tenant-page-error.tsx

Defines a reusable error-fallback factory for Cloud Tenant Management pages, rendering a page-level error state while preserving the page title and layout when a data load fails.

## Key Components

- **`tenantPageErrorFallback(title, message, className?)`** — Factory function that returns a `TenantPageError` render function. It wraps the error display in a `PageLayout` so the page title is redrawn even though the component tree that normally carries it failed to load.
- **`TenantPageError(retry, state)`** — The returned render function, called by the error boundary/fallback mechanism with a `retry` callback and a `state.isOffline` flag. Renders `LoadError` inside a negative-margin wrapper to cancel out the core `ErrorState` component's default padding, keeping alignment consistent with the surrounding `PageLayout`.

## Usage Example

```typescript
import { tenantPageErrorFallback } from '@/components/tenant-page-error';

// Basic usage for a standalone tenant page
const errorFallback = tenantPageErrorFallback(
  'Tenant Settings',
  'Failed to load tenant settings.'
);

// Usage inside an embedded tab view, applying layout offset
const embeddedErrorFallback = tenantPageErrorFallback(
  'Billing',
  'Failed to load billing data.',
  'EMBEDDED_PAGE_OFFSET'
);

// Typically passed to a query/error-boundary wrapper
<QueryBoundary errorFallback={errorFallback}>
  <TenantBillingContent />
</QueryBoundary>
```

## Notes

- Relies on `loadErrorProps` from `@/lib/query-state` to map `isOffline`/`message`/`retry` into the props expected by `LoadError`.
- The `-m-[var(--spacing-system-lf)]` negative margin offsets `ErrorState`'s built-in 24px padding so the error card aligns flush within `PageLayout`.
- Use the optional `className` parameter (e.g. `EMBEDDED_PAGE_OFFSET`) when the page is rendered inside another page's tab, to match the embedding layout's spacing.
