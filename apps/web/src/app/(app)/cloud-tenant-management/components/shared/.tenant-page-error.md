# tenant-page-error.tsx

A factory function that creates a standardized error-fallback renderer for Cloud Tenant Management pages, used when data loading fails within a page's layout.

## Key Components

- **`tenantPageErrorFallback(title, message, className?)`** — Factory function that returns a `TenantPageError` render function. Takes the page title, error message, and an optional `className` for layout customization.
- **`TenantPageError(retry, state)`** — The returned render function. Accepts a `retry` callback and a `state` object (with `isOffline`) and renders the `PageLayout` wrapping a `LoadError` component. Designed to be used as a fallback renderer in query/error-boundary state handling.

## Usage Example

```typescript
import { tenantPageErrorFallback } from '@/components/tenant-page-error';

// Create a reusable error fallback for a specific tenant page
const errorFallback = tenantPageErrorFallback(
  'Tenant Settings',
  'Failed to load tenant settings.',
  EMBEDDED_PAGE_OFFSET
);

// Used wherever a query/error state render-prop is expected
<QueryBoundary errorFallback={errorFallback}>
  <TenantSettingsContent />
</QueryBoundary>
```

## Notes

- The title is redrawn inside the error state because the page's own `PageLayout` (which normally carries the title) is part of what failed to load.
- The wrapping `<div>` applies a negative margin (`-m-[var(--spacing-system-lf)]`) to offset the core `ErrorState` component's internal 24px padding, keeping the error card flush with the page edges.
- Pass `className` (e.g., `EMBEDDED_PAGE_OFFSET`) when this error state renders inside another page's tab, to match the embedding layout's spacing.
- Relies on shared UI primitives `LoadError` and `PageLayout` from `@flamingo-stack/openframe-frontend-core`, and the `loadErrorProps` helper from `@/lib/query-state` to map offline/error state into component props.
