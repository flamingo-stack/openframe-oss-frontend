A client-side layout wrapper that applies consistent page padding and wraps tenant detail pages in an error boundary, ensuring a thrown query error still renders within the correctly indented page shell.

## Key Components

- **`TenantPageShellProps`** - Props interface: `title` (used for the error fallback heading), `errorMessage` (fallback body text), optional `resetKey` (changing this value resets a tripped error boundary, e.g. when navigating to a different record via `?id=`), and `children` (the page content to render).
- **`TenantPageShell`** - Component that renders a padded `div` containing a `ContentErrorBoundary`. If `children` throws during render, `tenantPageErrorFallback(title, errorMessage)` is displayed inside the same padded container instead of the page content.

## Usage Example

```typescript
import { TenantPageShell } from './tenant-page-shell';

function TenantDetailsPage({ tenantId }: { tenantId: string }) {
  return (
    <TenantPageShell
      title="Tenant Details"
      errorMessage="Unable to load tenant details."
      resetKey={tenantId}
    >
      <TenantDetailsContent tenantId={tenantId} />
    </TenantPageShell>
  );
}
```

Passing `tenantId` as `resetKey` ensures that if the error boundary trips while viewing one tenant, navigating to a different tenant (changing the `?id=` query) automatically resets the boundary instead of continuing to show the stale error state.
