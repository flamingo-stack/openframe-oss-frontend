# page.tsx

Client-rendered Next.js page component for deleting a tenant connection within the cloud tenant management feature, gated behind a feature flag check.

## Key Components

- **`DeleteConnectionPage`** — Default export; the page component rendered at the delete-connection route.
- **`useTenantManagementV2Gate`** — Hook determining whether the tenant management v2 feature is enabled (`'on'`, `'off'`, or `'loading'`).
- **`useRequiredIdParam`** — Hook extracting the required tenant `id` route param, redirecting to `routes.cloudTenantManagement.list` if missing.
- **`TenantPageShell`** — Shared layout wrapper providing title, error boundary, and reset behavior keyed by tenant `id`.
- **`LoadingWhen`** — Conditional wrapper from `@flamingo-stack/openframe-frontend-core` that shows a loading state while the gate resolves.
- **`EndConnectionView`** — Shared view component (used for both delete and disconnect flows) configured here with `mode="delete"`.

## Usage Example

This file is a Next.js App Router page and is not imported directly; it's resolved automatically based on its file path. Navigation to it is typically triggered via the configured route helper:

```typescript
import { routes } from '@/lib/routes';
import { useRouter } from 'next/navigation';

function NavigateToDelete({ tenantId }: { tenantId: string }) {
  const router = useRouter();

  const handleDelete = () => {
    router.push(routes.cloudTenantManagement.delete(tenantId));
  };

  return <button onClick={handleDelete}>Delete Connection</button>;
}
```

**Behavior notes:**
- If the `useTenantManagementV2Gate` feature flag resolves to `'off'`, the page triggers Next.js's `notFound()` behavior.
- If the required `id` param is absent, the user is redirected to the tenant list and the component renders `null`.
- While the feature gate is `'loading'`, a loading indicator is shown instead of the `EndConnectionView`.
