# page.tsx — Reconnect Tenant Page

Next.js page component for reconnecting a cloud tenant integration. It gates access via feature flags, resolves the tenant ID from the route, and renders either the v2 or v1 reconnect view depending on the active feature gate.

## Key Components

- **`ReconnectTenantPage`** (default export) — The page component. Responsible for:
  - Checking the `useTenantManagementGate` flag; calls `notFound()` if the feature is disabled.
  - Checking `useTenantManagementV2Gate` to determine which view variant to render.
  - Resolving the required tenant `id` from the URL via `useRequiredIdParam`, redirecting to the tenant list or new-tenant route if missing.
  - Wrapping content in `TenantPageShell` for consistent title, error handling, and reset-on-id-change behavior.
  - Using `LoadingWhen` to defer rendering until both gates resolve, ensuring the mint guard and probe verdict apply to a single, known tenant.

## Usage Example

This file is a Next.js route page and is rendered automatically by the framework for its corresponding path; it isn't typically imported directly. Example of the pattern it follows:

```typescript
// Route: app/.../reconnect/page.tsx
'use client';

export default function ReconnectTenantPage() {
  const gate = useTenantManagementGate();
  const v2 = useTenantManagementV2Gate();
  const id = useRequiredIdParam(routes.cloudTenantManagement.list, routes.cloudTenantManagement.new());

  if (gate === 'off') return notFound();
  if (!id) return null;

  return (
    <TenantPageShell title="Reconnect Tenant Integration" errorMessage="Couldn't load this tenant." resetKey={id}>
      <LoadingWhen loading={gate === 'loading' || v2 === 'loading'}>
        {v2 === 'on' ? <ReconnectTenantView key={id} id={id} /> : <ReconnectTenantViewV1 key={id} id={id} />}
      </LoadingWhen>
    </TenantPageShell>
  );
}
```
