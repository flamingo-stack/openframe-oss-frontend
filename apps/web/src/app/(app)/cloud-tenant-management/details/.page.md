Client-rendered Next.js page component that displays the tenant detail view, gated behind feature flags and requiring a tenant `id` query parameter.

## Key Components

- **`TenantDetailsPage`** — Default-exported page component that:
  - Resolves the tenant management feature gate via `useTenantManagementGate` and renders `notFound()` if the feature is disabled.
  - Extracts the required `id` query parameter via `useRequiredIdParam`, redirecting to the tenant list (when missing) or the "new tenant" route (when `id=new`).
  - Checks `useTenantManagementV2Gate` to decide whether to render the v2 (`TenantDetailView`) or legacy (`TenantDetailViewV1`) detail view.
  - Wraps the view in `TenantPageShell` for consistent title, error handling, and reset-on-id-change behavior.

## Usage Example

This file is a Next.js App Router page and is not imported directly; it's rendered automatically for its route (e.g. `/cloud/tenant-management?id=<tenantId>`).

```typescript
// Navigating to the tenant detail page programmatically
import { useRouter } from 'next/navigation';
import { routes } from '@/lib/routes';

function ViewTenantButton({ tenantId }: { tenantId: string }) {
  const router = useRouter();
  return (
    <button onClick={() => router.push(`${routes.cloudTenantManagement.list}?id=${tenantId}`)}>
      View Tenant
    </button>
  );
}
```

**Behavior notes:**
- If the `tenantManagement` feature gate is `'off'`, the page renders Next.js's `notFound()` (404 page).
- If `id` is absent, `useRequiredIdParam` triggers a redirect and the component returns `null` while that happens.
- The `key={id}` prop ensures the detail view remounts cleanly when the `id` query param changes without a full route change.
- While either gate is resolving (`'loading'`), a `loading` flag is passed down to the detail view to render loading state.
