Next.js client page component that renders the tenant detail screen, handling feature-gated routing between v1 and v2 tenant detail views based on the tenant management rollout flags.

## Key Components

- **`TenantDetailsPage`** (default export) — Page component for viewing a single tenant's details, resolved from the `?id=` query parameter.
- **`useTenantManagementGate`** — Determines whether the tenant management feature is enabled (`'on'`, `'off'`, or `'loading'`).
- **`useTenantManagementV2Gate`** — Determines whether the v2 tenant detail UI should be used instead of v1.
- **`useRequiredIdParam`** — Extracts the required `id` query parameter, redirecting to the tenant list if missing or to the "new tenant" page if `id=new`; returns `null` while redirecting.
- **`TenantPageShell`** — Wraps the view with consistent layout, title, and error boundary handling, reset via `resetKey`.
- **`TenantDetailView` / `TenantDetailViewV1`** — The actual detail rendering components for v2 and v1 respectively.

## Usage Example

This page is automatically routed by Next.js based on its file location (e.g., `app/.../tenant-details/page.tsx`) and is not invoked directly. It is reached via a URL such as:

```text
/cloud/tenant-management/tenant-details?id=abc123
```

Behavior summary:

```typescript
// If gate === 'off' -> renders Next.js notFound()
// If id is missing -> redirects to tenant list (routes.cloudTenantManagement.list)
// If id === 'new'  -> redirects to create page (routes.cloudTenantManagement.new())
// Otherwise renders TenantDetailView (v2) or TenantDetailViewV1 (v1) keyed by id
```

The `key={id}` prop ensures React remounts the detail view whenever the `id` query parameter changes, even though Next.js reuses the same route segment.
