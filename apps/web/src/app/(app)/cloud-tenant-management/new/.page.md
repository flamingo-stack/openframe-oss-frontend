# New Tenant Page

Next.js page component that renders the "New Tenant Integration" flow, handling both the initial tenant creation step and the subsequent connection step, with feature-flag-gated support for two versions of the tenant management UI (v1 and v2).

## Key Components

- **`NewTenantPage`** (default export) — Page component that:
  - Gates access via `useTenantManagementGate()`, returning a 404 (`notFound()`) when the feature is disabled.
  - Resolves UI version via `useTenantManagementV2Gate()`, selecting between v1 and v2 component sets.
  - Reads a `connectionId` from the URL search params (`?id=`) to determine whether to show the "create" view or resume the "connect" step for an already-generated tenant record.
  - Wraps content in `TenantPageShell` for consistent title/error handling and a `resetKey` tied to `connectionId` so switching records remounts the form cleanly.
  - Uses `LoadingWhen` to lock controls and avoid premature rendering while feature gates are still resolving (`'loading'` state).

## Usage Example

This page is routed automatically by Next.js (e.g., at `/tenants/new`) and is not typically imported directly. Navigation examples:

```typescript
// Start a new tenant creation flow
router.push('/tenants/new');

// Resume the connect step for an in-progress tenant
router.push('/tenants/new?id=abc123');
```

Component resolution logic based on gate state:

```typescript
// gate: 'off' | 'on' | 'loading'
// v2:   'off' | 'on' | 'loading'

if (gate === 'off') {
  // renders 404
}

// connectionId present + v2 on  -> ConnectTenantView
// connectionId present + v2 off -> ConnectTenantViewV1
// connectionId absent  + v2 on  -> NewTenantView
// connectionId absent  + v2 off -> NewTenantViewV1
```
