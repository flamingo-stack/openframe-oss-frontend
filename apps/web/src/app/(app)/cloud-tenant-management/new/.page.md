# page.tsx

Next.js client page component for creating or resuming a new tenant integration, supporting both legacy (v1) and current (v2) tenant management views behind feature flag gates.

## Key Components

- **`NewTenantPage`** (default export) — Page component that:
  - Resolves feature gates via `useTenantManagementGate` (on/off/loading) and `useTenantManagementV2Gate` (v1/v2 variant toggle).
  - Calls `notFound()` if tenant management is gated `off`.
  - Reads an optional `id` query parameter to determine whether the page is in "new" mode (no id) or "connect" mode (resuming an existing connection record created by a "Generate" step).
  - Wraps content in `TenantPageShell` for consistent layout and error handling, keyed by `connectionId` so the shell resets appropriately per connection.
  - Uses `LoadingWhen` to lock the UI while gate flags are still resolving, preventing premature rendering of the wrong variant.
  - Conditionally renders one of four views: `ConnectTenantView`, `ConnectTenantViewV1`, `NewTenantView`, or `NewTenantViewV1`, based on the presence of `connectionId` and the v2 gate state.

## Usage Example

```typescript
// This page is rendered automatically by Next.js App Router
// for a route such as: /tenants/new

// Navigating with no query param renders the "new tenant" form:
// /tenants/new -> <NewTenantView /> or <NewTenantViewV1 />

// Navigating with an id (e.g., after a "Generate" step) resumes
// the connect flow for that specific tenant record:
// /tenants/new?id=abc123 -> <ConnectTenantView id="abc123" />
```

The component relies on `useSearchParams` from `next/navigation`, so it must run in a client component context (`'use client'`), and the `connectionId`-based `key` props ensure each distinct connection record mounts a fresh instance of its respective view.
