# approvals-view.tsx

Implements the "Needs approval" page (`/approvals`) of the Mingo-first shell. It renders the approval requests a user can act on, split into two sections — standalone requests raised in chat and tickets handed to a technician waiting for approval — with infinite scroll to load additional pages as the user scrolls.

## Key Components

- **`ApprovalsView`** — Top-level page component. Wires together `useApprovalSources` (data fetching/pagination state), `useApprovalDecider` (approve/reject decision handling and local "kept" state), and `composeApprovalInbox` (merges sources and dedupes cards) inside a `PageLayout`.
- **`ApprovalList`** (internal) — Renders the two `ApprovalSection`s, loading skeletons (`NotificationTile loading`), error states (`SectionLoadError`), an empty state (`NoData`), and an infinite-scroll sentinel element driven by `useGridInfiniteScroll`.
- **`ApprovalSection`** (internal) — Renders a labeled, counted list of `ApprovalRequestCard` items for one category (plain requests vs. tickets). Returns `null` when there are no cards to show. The displayed count favors the server-reported total but never drops below the number of pending cards currently rendered.

## Usage Example

```typescript
// app/(app)/approvals/page.tsx
import { ApprovalsView } from '@/app/components/approvals/approvals-view';

export default function ApprovalsPage() {
  return <ApprovalsView />;
}
```

The component requires no props — all state is sourced internally via the `useApprovalSources` and `useApprovalDecider` hooks. Related logic lives in:
- `approval-inbox.ts` — composes and dedupes cards from multiple sources.
- `use-approval-decider.ts` — handles approve/reject decisions and propagates them to the drawer, chat, and board.
- `use-approval-sources.ts` — fetches paginated approval/ticket sources and exposes loading/error/total state.
