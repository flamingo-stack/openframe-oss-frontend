# Incident Details Page

Next.js page component that renders the detail view for a single incident, guarded by a feature flag gate and a required `id` query parameter.

## Key Components

- **`IncidentDetailsPage`** (default export) — Page component for the incident details route. Combines three concerns:
  - **Feature gate** via `useIncidentsGate()` — triggers `notFound()` when the feature is definitively disabled, or shows a loading skeleton while the flag is resolving.
  - **Required ID validation** via `useRequiredIdParam(routes.incidents.list)` — redirects back to the incidents list if the `?id=` query param is missing, avoiding an API call with an empty id.
  - **Error boundary** via `ContentErrorBoundary` — wraps the content so failures render a friendly "Incident" error message instead of crashing the page.

## Usage Example

This file is a Next.js App Router page and is not imported directly; it's resolved automatically for its route (e.g. `/incidents/[id]` or similar, based on `?id=` query param).

```typescript
// Navigating to the incident details page from elsewhere in the app:
import { useRouter } from 'next/navigation';
import { routes } from '@/lib/routes';

function IncidentRow({ incidentId }: { incidentId: string }) {
  const router = useRouter();

  const openDetails = () => {
    router.push(`${routes.incidents.details}?id=${incidentId}`);
  };

  return <button onClick={openDetails}>View Incident</button>;
}
```

## Notes

- If the feature flag gate is `'loading'`, the page renders immediately with `LoadingWhen` wrapping `IncidentDetailsView`, allowing each sub-section to show its own skeleton state.
- If `id` resolves to `null` (redirect in progress), the component renders nothing (`return null`) to avoid a flash of invalid content.
