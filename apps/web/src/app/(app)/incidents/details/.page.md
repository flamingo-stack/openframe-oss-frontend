# Incident Details Page

Next.js App Router page component that renders detailed view for a single incident, guarded by a feature flag gate and requiring a valid `id` query parameter.

## Key Components

- **`IncidentDetailsPage`** (default export) — Page component that:
  - Resolves the incidents feature flag via `useIncidentsGate()`
  - Extracts and validates the required `id` param via `useRequiredIdParam`, redirecting to the incidents list route if missing
  - Calls `notFound()` when the feature gate is definitively `'off'`
  - Renders a skeleton loading state while the gate status is `'loading'`
  - Wraps content in `ContentErrorBoundary` for graceful error handling
  - Delegates rendering to `IncidentDetailsView` once `id` and gate are resolved

## Behavior Notes

- If `id` is `null` (missing or invalid), the component returns `null` while `useRequiredIdParam` handles navigation back to `routes.incidents.list`.
- Only an explicit `'off'` gate state triggers a 404 — this avoids false negatives while the flag is still loading.
- Loading state is scoped per-section using `LoadingWhen`, allowing `IncidentDetailsView` to manage its own skeleton UI.

## Usage Example

This page is automatically routed by Next.js based on its file location (e.g., `app/incidents/details/page.tsx`) and expects an `id` query parameter:

```typescript
// Navigating to the incident details page
import { useRouter } from 'next/navigation';

function IncidentRow({ incidentId }: { incidentId: string }) {
  const router = useRouter();

  const openDetails = () => {
    router.push(`/incidents/details?id=${incidentId}`);
  };

  return <button onClick={openDetails}>View Incident</button>;
}
```
