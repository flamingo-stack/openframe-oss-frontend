Client-side React hook that determines whether the Incidents module should be enabled, combining a feature flag check with an application mode restriction.

## Key Components

- **`useIncidentsGate()`** — Hook returning a `FeatureFlagGate` value (`'on'`, `'off'`, or similar gate states) that controls visibility/access to the Incidents module.
  - Reads the `insights` feature flag via `useFeatureFlagGate`.
  - Hard-forces the gate to `'off'` unless the app is running in SaaS tenant mode (checked via `isSaasTenantMode()`), since the underlying insights API is only available in that mode.

## Usage Example

```typescript
'use client';

import { useIncidentsGate } from '@/app/hooks/use-incidents-gate';

export function IncidentsNavLink() {
  const gate = useIncidentsGate();

  if (gate === 'off') {
    return null;
  }

  return <a href="/incidents">Incidents</a>;
}
```

## Notes

- This hook must be used in a client component context (`'use client'` directive).
- The gate logic is deliberately conservative: even if the `insights` feature flag is enabled, the module remains disabled outside SaaS tenant mode, since non-SaaS deployments lack the backing insights API.
- Consumers should treat the returned `FeatureFlagGate` value as the single source of truth for whether to render Incidents-related UI, rather than checking the feature flag or app mode independently.
