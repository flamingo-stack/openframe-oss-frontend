## use-incident-dialogs.ts

React Query hooks that resolve the latest active Mingo chat dialog associated with an incident (insight), used to drive the "Fix with Mingo" button state in both the incident detail header and the incidents table.

## Key Components

- **`latestIncidentDialogQuery(insightId)`** — Internal `queryOptions` factory. Posts a GraphQL query to `/chat/graphql` filtering dialogs by `insightId`, `agentTypes: ['ADMIN']`, and `ACTIVE_DIALOG_STATUSES`. Returns the first matching `DialogNode`, or `null` on any transport/GraphQL error (fails silently, no toast). Cached under the `mingo-dialogs` query key family with a 30-second stale time.
- **`useLatestIncidentDialog(insightId)`** — Suspense-based hook for a single incident. Returns `DialogNode | null`. Used by the detail header so it renders once with the correct button label, without a loading spinner.
- **`IncidentDialogLookup`** — Type alias: `Readonly<Record<string, DialogNode | null | undefined>>`, mapping insight id → dialog (`undefined` means still pending).
- **`useLatestIncidentDialogs(insightIds)`** — Non-suspense hook for a table of incidents. Issues one query per id via `queryClient.fetchQuery`, fanned out from a single query keyed on the sorted id list, so results land in the same cache entries the detail header reads. Uses `keepPreviousData` to avoid blanking already-known rows when the id set grows (e.g., infinite scroll).

## Usage Example

```typescript
import { useLatestIncidentDialog, useLatestIncidentDialogs } from './use-incident-dialogs';

// Detail header — suspends until resolved
function IncidentHeader({ insightId }: { insightId: string }) {
  const dialog = useLatestIncidentDialog(insightId);
  return dialog ? <ReopenMingoButton dialogId={dialog.id} /> : <StartMingoButton />;
}

// Incidents table — one shared lookup for all visible rows
function IncidentsTable({ insights }: { insights: { id: string }[] }) {
  const lookup = useLatestIncidentDialogs(insights.map(i => i.id));

  return (
    <>
      {insights.map(incident => {
        const dialog = lookup[incident.id]; // DialogNode | null | undefined
        return <IncidentRow key={incident.id} incident={incident} dialog={dialog} />;
      })}
    </>
  );
}
```

Both hooks share the same cache keys (`['mingo-dialogs', ...]`), so creating a new dialog elsewhere and invalidating that key keeps the header and table in sync.
