## use-incident.ts

A client-side React hook module that fetches incident detail data via Relay, providing both a lightweight incident-only accessor and a full detail accessor that also includes the status-transition table.

This file centralizes the GraphQL query variables and fetch policy for the incident detail page, ensuring that multiple UI "islands" (e.g., header and body) requesting the same incident deduplicate into a single network request through Relay. It also wires in `useRetryKey` so that retry actions correctly invalidate any previously retained rejected query results, rather than replaying a stale failure.

## Key Components

- **`useIncident(incidentId: string): Incident`** — Convenience hook that returns just the transformed `Incident` record for a given incident ID.
- **`useIncidentDetail(incidentId: string): { incident: Incident; transitions: IncidentTransitionTable }`** — Fetches the incident detail Relay query (`incidentDetailRelayQuery`) with a `store-and-network` fetch policy, keyed by a shared `fetchKey` from `useRetryKey`, and returns both the incident record and its transition table, transformed via `toIncident` and `toTransitionTable`.

## Usage Example

```typescript
import { useIncident, useIncidentDetail } from './use-incident';

// When only the incident record is needed (e.g., page body)
function IncidentBody({ incidentId }: { incidentId: string }) {
  const incident = useIncident(incidentId);
  return <div>{incident.title}</div>;
}

// When both incident and transition history are needed (e.g., page header)
function IncidentHeader({ incidentId }: { incidentId: string }) {
  const { incident, transitions } = useIncidentDetail(incidentId);
  return (
    <header>
      <h1>{incident.title}</h1>
      <StatusTimeline transitions={transitions} />
    </header>
  );
}
```

**Note:** Because both components call the same underlying query with identical variables and a shared `fetchKey` (via `useRetryKey`), Relay automatically dedupes the requests into a single network call, as long as both are rendered under the same retry context.
