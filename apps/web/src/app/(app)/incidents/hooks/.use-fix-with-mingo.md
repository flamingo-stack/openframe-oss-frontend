# use-fix-with-mingo.ts

React hook and helper that implement the "Fix with Mingo" action for incidents: fetching a server-generated chat prompt for an incident and handing it off to Mingo's launcher as a prefilled draft, without auto-sending it. Also provides a shared decision function that determines what a Mingo-related button should display and do, based on whether an existing chat session for the incident is known.

## Key Components

- **`useFixWithMingo()`** — Hook that exposes:
  - `fixWithMingo(incident)`: fetches the insight chat prompt via a Relay network-only query and pushes a draft into `useMingoLauncherStore`. Guards against duplicate in-flight requests using a `ref` (to avoid stale-state races from double clicks) alongside `pendingId` state (used for per-row loading UI).
  - `pendingId`: ID of the incident whose prompt fetch is currently in flight, or `null`.
  - `canOpenMingo`: whether the Mingo dock is mounted and ready.

- **`MingoAction`** — Interface describing a button's rendered state: `label`, `onClick`, `disabled`, `loading`.

- **`mingoActionFor(incident, session, controls)`** — Pure function shared by the header and table row UI. Given:
  - an existing `session` (`DialogNode | null | undefined`) — `undefined` means lookup pending, `null` means no session exists,
  - the controls returned by `useFixWithMingo()`,
  
  it returns a `MingoAction` describing whether to open the existing session or launch a new "Fix with Mingo" flow, disabling the button while another incident's prompt is loading or the Mingo dock is unavailable.

## Usage Example

```typescript
import { useFixWithMingo, mingoActionFor } from './use-fix-with-mingo';

function IncidentRowActions({ incident, session }: { incident: IncidentRow; session: DialogNode | null | undefined }) {
  const mingoControls = useFixWithMingo();
  const action = mingoActionFor(incident, session, mingoControls);

  return (
    <button onClick={action.onClick} disabled={action.disabled}>
      {action.loading ? 'Loading…' : action.label}
    </button>
  );
}
```

The hook is intended to be called once per table/section and its return value passed into `mingoActionFor` for each row, ensuring only one incident's prompt fetch is in flight at a time.
