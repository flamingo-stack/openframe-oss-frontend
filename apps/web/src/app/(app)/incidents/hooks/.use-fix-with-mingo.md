This file provides the "Fix with Mingo" feature logic: a React hook that fetches an AI-generated prompt for an incident and prefills a new Mingo chat draft, plus a helper that decides whether a UI control should trigger that flow or open an existing Mingo chat session.

## Key Components

- **`useFixWithMingo()`** — Hook that exposes:
  - `fixWithMingo(incident)`: fetches the incident's chat prompt via GraphQL (`insightChatPromptRelayQuery`) and pushes a draft into the Mingo launcher store (`draftToMingo`). Guards against duplicate in-flight requests using a ref (to avoid stale-state races) alongside state (to drive UI).
  - `pendingId`: the incident ID currently awaiting its prompt, used to show loading state on the originating button.
  - `canOpenMingo`: whether the Mingo dock is mounted and able to accept a new draft/session.
- **`MingoAction`** interface — Shape of the action a button should perform: `label`, `onClick`, `disabled`, `loading`.
- **`mingoActionFor(incident, session, controls)`** — Pure function shared by the incident table row and header to decide between two states:
  - If a `session` (existing `DialogNode`) exists, returns an action to reopen that Mingo dialog.
  - Otherwise, returns an action to trigger `fixWithMingo`, disabled while Mingo is unavailable, the session lookup is pending (`undefined`), or another prompt is in flight.

## Usage Example

```typescript
import { useFixWithMingo, mingoActionFor } from './use-fix-with-mingo';

function IncidentRowButton({ incident, session }: { incident: IncidentRow; session: DialogNode | null | undefined }) {
  const mingoControls = useFixWithMingo();
  const action = mingoActionFor(incident, session, mingoControls);

  return (
    <button onClick={action.onClick} disabled={action.disabled}>
      {action.loading ? 'Preparing…' : action.label}
    </button>
  );
}
```

Both the incident table and its header should call `useFixWithMingo()` once and pass the returned controls into `mingoActionFor` per row, ensuring consistent disabled/loading behavior across the UI while only one prompt fetch is in flight at a time.
