# incident-assigned-tickets.tsx

Renders the "Assigned Ticket" section on an incident detail page, displaying tickets that were created from (and linked to) a given incident.

Conceptually, an incident is stored server-side as an `INSIGHT` item type, and when a ticket is created with an `insightId`, the backend records an assignment linking the insight (item) to the ticket (target). This component surfaces that relationship by reusing the generic assignments system, scoped to the incident's tickets.

The component follows a "no reserved slot" rendering pattern: it renders nothing while loading or when there are no assigned tickets and no fetch failure, but renders the section (with an error state) if the tickets query failed to resolve.

## Key Components

- **`IncidentAssignedTickets`** — Client component (`'use client'`) that accepts an `incidentId` prop and renders the assigned tickets section for that incident.
  - Uses `useAssignedItems({ itemId: incidentId, itemType: 'INSIGHT' })` to fetch tickets assigned to the incident.
  - Returns `null` if there are no tickets and no `TICKET` fetch failure (avoids rendering an empty section).
  - Delegates actual list rendering to `AssignedItemsContent` from `@/components/assignments`.

## Usage Example

```typescript
import { IncidentAssignedTickets } from '@/components/incidents/incident-assigned-tickets';

export function IncidentDetailPage({ incidentId }: { incidentId: string }) {
  return (
    <div className="flex flex-col gap-[var(--spacing-system-l)]">
      {/* other incident detail sections */}
      <IncidentAssignedTickets incidentId={incidentId} />
    </div>
  );
}
```

**Notes:**
- The `data-loading-optional` attribute marks this section as non-blocking for page-level loading states, since it may render nothing.
- `showTitle={false}` is passed to `AssignedItemsContent` because the heading ("Assigned Ticket") is rendered locally by this component instead.
