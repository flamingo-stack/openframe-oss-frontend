# incident-assigned-tickets.tsx

A React client component that renders the "Assigned Ticket" section on an incident detail page, displaying tickets that were created from (and linked to) a given incident.

This component leverages the shared assignments system to fetch and display tickets whose server-side link records the incident (treated as an `INSIGHT` item type) as the owning assignment. The server establishes this link automatically when a ticket is created with an `insightId` referencing the incident. The component follows a "no empty slot" rendering pattern: it renders nothing while data is unresolved or empty, and only appears once there are rows to show or an explicit fetch failure to report.

## Key Components

- **`IncidentAssignedTickets`** — Default export component accepting an `incidentId` prop (`string`). Renders a `<section>` containing an "Assigned Ticket" heading and the shared `AssignedItemsContent` list.
- **`useAssignedItems`** (imported) — Hook from `@/components/assignments` that fetches assigned items for a given `itemId`/`itemType` pair, returning `tickets`, `failedTypes`, and related state.
- **`AssignedItemsContent`** (imported) — Shared presentational component that renders the list of assigned items for a given `itemType`.

## Usage Example

```typescript
import { IncidentAssignedTickets } from '@/components/incidents/incident-assigned-tickets';

export function IncidentDetailPage({ incidentId }: { incidentId: string }) {
  return (
    <div className="flex flex-col gap-4">
      {/* Other incident detail sections */}
      <IncidentAssignedTickets incidentId={incidentId} />
    </div>
  );
}
```

**Rendering behavior:**
- Returns `null` if there are no tickets **and** no fetch failure for the `TICKET` type — avoiding a reserved empty slot on the page.
- Renders the section (with `data-loading-optional` attribute) once tickets exist or the ticket fetch explicitly failed, so the UI can surface the failure reason instead of silently hiding it.
