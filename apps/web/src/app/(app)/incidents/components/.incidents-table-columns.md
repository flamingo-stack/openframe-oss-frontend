Defines the shared column layout configuration for the Incidents table, used by both the live data table and its Suspense loading skeleton to ensure consistent column widths and responsive behavior between loading and loaded states.

## Key Components

- **`INCIDENT_COLUMNS`** — A `const` object (typed via `satisfies Record<string, TableSkeletonColumn>`) defining each table column's layout metadata:
  - `incident` — Incident type column (`type` filter key), flexible width.
  - `device` — Device/customer column (`organizationId` filter key), flexible width, hidden below `md` breakpoint.
  - `severity` — Severity column with fixed, breakpoint-responsive widths.
  - `status` — Status column, fixed width, hidden below `lg` breakpoint.
  - `assignee` — Assigned-to column (`assigneeId` filter key), fixed width, hidden below `lg` breakpoint.
  - `actions`, `mingo`, `open` — Compact icon/action columns, right-aligned, some hidden below `md`.

Each entry's `id` corresponds directly to the TanStack Table column id used for server-side filtering (e.g., `type`, `organizationId`, `assigneeId`), so keeping this file data-only ensures the skeleton and live table stay in sync without duplicating layout logic.

## Usage Example

```typescript
import { INCIDENT_COLUMNS } from './incidents-table-columns';

// Used by the live table to define TanStack column configs
const columns = Object.values(INCIDENT_COLUMNS).map((col) => ({
  id: col.id,
  header: col.header,
}));

// Used by the Suspense fallback skeleton to render matching placeholder headers
function IncidentsTableSkeleton() {
  return (
    <thead>
      <tr>
        {Object.values(INCIDENT_COLUMNS).map((col) => (
          <th key={col.id} className={col.width}>
            {col.header}
          </th>
        ))}
      </tr>
    </thead>
  );
}
```

See [`table-column-layout.ts`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/components/shared/table-column-layout.ts) for the `TableSkeletonColumn` type definition.
