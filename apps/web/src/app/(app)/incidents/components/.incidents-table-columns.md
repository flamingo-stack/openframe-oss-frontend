Defines the shared column layout configuration for the Incidents table, providing a single source of truth for column widths, headers, and responsive visibility used by both the live data table and its loading skeleton.

## Key Components

- **`INCIDENT_COLUMNS`** — A `const` object (typed via `satisfies Record<string, TableSkeletonColumn>`) mapping logical column keys to their layout metadata:
  - `incident` — Incident type column (filters by `type`)
  - `device` — Device/customer column (filters by `organizationId`, hidden below `md`)
  - `severity` — Fixed-width severity badge column
  - `status` — Status column (hidden below `lg`)
  - `assignee` — Assigned user column (filters by `assigneeId`, hidden below `lg`)
  - `actions` — Right-aligned row actions column
  - `mingo` — Right-aligned AI assistant indicator column (hidden below `md`)
  - `open` — Right-aligned "open" action column (hidden below `md`)

Each entry's `id` corresponds to a TanStack Table column id used for server-side filtering, while `width`, `hideAt`, and `align` drive responsive rendering.

## Usage Example

```typescript
import { INCIDENT_COLUMNS } from './incidents-table-columns';

// In the live table, define a TanStack column using the shared id/header
const columns = [
  {
    id: INCIDENT_COLUMNS.incident.id,
    header: INCIDENT_COLUMNS.incident.header,
  },
  // ...other columns
];

// In the Suspense fallback skeleton, reuse the same config to match widths
function IncidentsTableSkeleton() {
  return (
    <TableSkeletonHeader columns={Object.values(INCIDENT_COLUMNS)} />
  );
}
```

This ensures the loading skeleton and the populated table always stay visually aligned, since both consume the same `INCIDENT_COLUMNS` definition.
