# incident-summary-card.tsx

Renders the summary card displayed at the top of an incident detail page, showing the finding's title/description followed by two strips of key-value cells (device/customer/detected/assignee, and severity/category/interval/status). Supports a fully-skeletonized loading state when the incident data is not yet available.

## Key Components

- **`IncidentSummaryCard`** — Main exported component. Accepts an optional `incident` (undefined while loading) and an `assigneeSlot` (a `ReactNode` that owns its own assignment mutation/loading logic).
- **`Row`** — Internal layout helper rendering a horizontally-wrapping strip of cells with consistent spacing and a bottom border (last row omits it).
- **`Cell`** — Internal wrapper for a single detail cell; supports an `optional` flag (used for the "Until" cell, shown only for snoozed incidents) that marks it via `data-loading-optional` for skeleton handling.
- **`DESCRIPTION_SKELETON_LINES`** / **`DEVICE_ICON_CLASS`** — Constants controlling the skeleton line count for the description and the icon's sizing class, shared between real and placeholder renders.

## Usage Example

```typescript
import { IncidentSummaryCard } from './incident-summary-card';
import { IncidentAssignee } from './incident-assignee';

function IncidentPage({ incident }: { incident?: Incident }) {
  return (
    <IncidentSummaryCard
      incident={incident}
      assigneeSlot={<IncidentAssignee incident={incident} />}
    />
  );
}
```

The component automatically detects a loading state via `useLoadingScope()` or the absence of `incident`, rendering skeleton placeholders for the title, description, icons, and all value cells while preserving the four-column layout. The "Until" cell only appears when `incident.status === InsightStatus.SNOOZED`, and `incident.hasDevice` determines whether the device name links to `routes.devices.details(...)`.
