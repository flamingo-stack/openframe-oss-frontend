# incident-summary-card.tsx

A React client component that renders the summary card shown at the top of an incident detail page, displaying the incident's title/description followed by two strips of key-value cells (device/customer/detected/assignee, and severity/category/interval/status). It fully supports a loading state, rendering skeleton placeholders in place of every value while the incident record is being fetched.

## Key Components

- **`IncidentSummaryCard`** — Main exported component. Accepts an optional `incident` (undefined while loading) and an `assigneeSlot` render prop for the assignee cell, which manages its own mutation/loading state independently.
- **`Row`** — Internal layout helper rendering a horizontal, wrapping strip of cells with a bottom border (omitted on the last row).
- **`Cell`** — Internal wrapper for a single data point within a `Row`; supports an `optional` flag (used for the "Until" cell, which only appears for snoozed incidents) via `data-loading-optional`.
- Uses `InfoCell` and `CustomerInfoCell` (shared components) to render labeled values with built-in skeleton/loading support.
- Uses `IncidentSeverityTag` and `IncidentStatusTag` for styled severity/status badges.
- Links to device details via `routes.devices.details(machineId)` only when `incident.hasDevice` is true.

## Usage Example

```typescript
import { IncidentSummaryCard } from './incident-summary-card';
import { IncidentAssignee } from './incident-assignee';

function IncidentDetailPage({ incident }: { incident?: Incident }) {
  return (
    <IncidentSummaryCard
      incident={incident}
      assigneeSlot={<IncidentAssignee incidentId={incident?.id} />}
    />
  );
}
```

The component automatically detects loading state via `useLoadingScope()` or by the absence of `incident`, rendering skeleton bars for every value while preserving the card's layout (four columns across two strips, with the optional "Until" cell shown only when `incident.status === InsightStatus.SNOOZED`).
