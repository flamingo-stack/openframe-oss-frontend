# incident-notes.tsx

Client component that renders and manages the notes section for an incident, backed by a paginated Relay fragment. Notes are fetched as the incident's own root query (not nested per-incident in a list), isolated behind their own error boundary and loading suspense so a notes failure or slow load doesn't affect the rest of the incident page.

## Key Components

- **`IncidentNotes`** – Public entry point. Wraps the section in a `ContentErrorBoundary` so notes failures degrade gracefully without replacing the already-loaded incident page.
- **`IncidentNotesSection`** – Wraps the reader in `LoadingSuspense` to show a loading state while the query resolves.
- **`IncidentNotesReader`** – Detects an active loading scope (via `useLoadingScope`) and renders a skeleton `NotesSection` with no items, or falls through to `IncidentNotesContent` once data is ready.
- **`IncidentNotesContent`** – Core logic: runs the paginated Relay query/fragment, maps edges to `NoteItem[]`, and wires up add/edit/delete mutations with toast notifications and optimistic updates. Also renders a "Load older notes" button when more pages exist.

## Usage Example

```typescript
import { IncidentNotes } from '@/app/incidents/components/incident-notes';

function IncidentDetailPage({ incidentId }: { incidentId: string }) {
  return (
    <div className="incident-detail">
      {/* ...other incident sections... */}
      <IncidentNotes incidentId={incidentId} />
    </div>
  );
}
```

Internally, `handleAdd`, `handleEdit`, and `handleDelete` use Relay's `connections` declarative directive so added/removed note edges automatically update the paginated connection without a manual store updater. Errors from any mutation are surfaced via `getRelayErrorMessage` and displayed through the shared `useToast` hook.
