# incident-notes.tsx

Renders the notes section for an incident/insight, fetching paginated notes via a Relay fragment and providing add/edit/delete mutations with optimistic UI and toast feedback. Notes are isolated in their own query, error boundary, and loading boundary so they don't block or break the rest of the incident page.

## Key Components

- **`IncidentNotes`** — Public entry point. Wraps the section in a `ContentErrorBoundary` so note-loading failures degrade gracefully without affecting the already-loaded incident.
- **`IncidentNotesSection`** — Wraps the reader in `LoadingSuspense`, providing a dedicated loading UI scoped to notes only.
- **`IncidentNotesReader`** — Detects loading scope via `useLoadingScope()` and renders a skeleton `NotesSection` (with no-op handlers) while loading, otherwise renders `IncidentNotesContent`.
- **`IncidentNotesContent`** — Core logic: runs `useLazyLoadQuery` + `usePaginationFragment` to fetch notes, maps Relay edges to `NoteItem[]`, and wires up `addInsightNoteMutation`, `updateInsightNoteMutation`, and `deleteInsightNoteMutation` with Relay's declarative `connections` directive for automatic cache updates.
- **`NOTES_PAGE_SIZE`** — Pagination page size constant (50).

## Usage Example

```typescript
import { IncidentNotes } from '@/app/incidents/[id]/incident-notes';

function IncidentDetailPage({ incidentId }: { incidentId: string }) {
  return (
    <div className="incident-detail">
      {/* other incident sections */}
      <IncidentNotes incidentId={incidentId} />
    </div>
  );
}
```

The component requires a Relay environment provider and an authenticated user in `useAuthStore` (used to flag `isOwn` notes for edit/delete permissions). Mutations automatically update the paginated connection via the `connections` array derived from the fragment's `__id`, so no manual Relay store updater is needed for add/delete.
