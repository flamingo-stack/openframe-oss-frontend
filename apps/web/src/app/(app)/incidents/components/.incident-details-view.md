# incident-details-view.tsx

Composes the Incident Details page by manually assembling independent, suspense-boundaried "islands" (header, summary, notes, assigned tickets, evidence) so each part can load and suspend on its own rather than blocking the whole page on a single data fetch.

## Key Components

- **`IncidentDetailsView`** — Main exported component (memoized). Accepts `incidentId` and renders the page frame, falling back to skeleton placeholders when inside a loading scope (e.g., an unresolved feature flag).
- **`IncidentHeader` / `IncidentHeaderLive` / `IncidentHeaderLoaded`** — Header island with its own `LoadingSuspense` boundary. Fetches the incident and its legal status transitions, builds the action bar (Fix with Mingo, Create Ticket, status transition menu), and renders the `SnoozeIncidentModal`.
- **`IncidentTitleBlock`** — Wraps `TitleBlock` with a static title, back button (via `useSafeBack`), and the given actions.
- **`IncidentSummary` / `IncidentSummaryLive`** — Summary card island, rendering `IncidentSummaryCard` with an `IncidentAssignee` slot.
- **`IncidentEvidence` / `IncidentEvidenceLive`** — Query/evidence results island, rendering `IncidentQueryResults`.
- **`IncidentDetailsFrame`** — Layout helper combining header and body sections with consistent spacing.
- **`TICKET_PREFILL_DESCRIPTION_MAX`** — Caps the incident description length (1000 chars) carried into the "Create Ticket" URL prefill.
- **`LOADING_ACTIONS`** — Static placeholder action buttons shown while the incident record is loading.

## Usage Example

```typescript
import { IncidentDetailsView } from './incident-details-view';

export default function IncidentPage({ params }: { params: { id: string } }) {
  return <IncidentDetailsView incidentId={params.id} />;
}
```

Each sub-section (header, summary, notes, assigned tickets, evidence) independently checks `useLoadingScope()` to render a skeleton/placeholder state without performing data reads, and otherwise wraps its "live" variant in `LoadingSuspense` so slow queries don't block sibling sections from rendering.
