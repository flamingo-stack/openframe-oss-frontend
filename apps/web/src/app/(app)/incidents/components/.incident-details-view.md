# incident-details-view.tsx

Top-level page component for the incident details view. It composes independently-suspending sections (header, summary, notes, assigned tickets, and query evidence) so each "island" can load and render on its own schedule rather than blocking the entire page on a single data fetch.

## Key Components

- **`IncidentDetailsView`** — The exported, memoized page component. Accepts `incidentId` and renders an `IncidentDetailsFrame` containing the header and body sections. Handles the global loading-scope case (e.g., feature flag pending) by rendering skeleton-only versions of all sections.
- **`IncidentHeader` / `IncidentHeaderLive` / `IncidentHeaderLoaded`** — Suspense-wrapped header island. Fetches the incident and its legal status transitions via `useIncidentDetail`, then builds the action bar (Fix with Mingo, Create Ticket, status transition menu).
- **`IncidentSummary` / `IncidentSummaryLive`** — Suspense-wrapped summary card island using `useIncident`, paired with the `IncidentAssignee` slot.
- **`IncidentEvidence` / `IncidentEvidenceLive`** — Suspense-wrapped query-results (evidence) island.
- **`IncidentDetailsFrame`** — Layout helper replicating `PageLayout`'s structure (header + scrollable body) without requiring synchronized suspense across sections.
- **`IncidentTitleBlock`** — Renders the shared `TitleBlock` with back navigation and action buttons, used in both loading and loaded header states.
- **`TICKET_PREFILL_DESCRIPTION_MAX`** — Constant (1000) capping the incident description length passed via URL to the new-ticket form.

## Usage Example

```typescript
import { IncidentDetailsView } from './incident-details-view';

export default function IncidentPage({ params }: { params: { incidentId: string } }) {
  return <IncidentDetailsView incidentId={params.incidentId} />;
}
```

Each section (`IncidentHeader`, `IncidentSummary`, `IncidentEvidence`) independently fetches data and falls back to a skeleton via `LoadingSuspense` and `useLoadingScope`, ensuring the "Create Ticket" and "Resolve/Archive/Reopen" actions always reflect the incident's current status without delaying the rest of the page.
