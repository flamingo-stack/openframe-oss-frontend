# incident-query-results.tsx

Renders the "Query Details" section of an incident view, displaying the raw osquery rows that produced the detection finding, using the shared `QueryReportTable` component. Handles loading, empty, and populated states for a single incident's query evidence.

## Key Components

- **`IncidentQueryResults`** — Main exported component. Accepts an optional `incident` prop and renders its `queryResult` rows in a report table. Shows loading skeleton rows while the incident is unresolved (via `useLoadingScope` or a missing `incident`), and displays a context-aware empty state message depending on whether evidence data exists but is empty, or was never kept.
- **`QueryResultsFrame`** — Internal layout wrapper providing the section heading ("Query Details") and consistent vertical spacing around the table content.
- **`INCIDENT_EVIDENCE_SKELETON_ROWS`** / **`INCIDENT_EVIDENCE_SKELETON_COLUMNS`** — Constants defining the shape of the loading skeleton (1 row, 3 columns), since the detecting query's actual column count is unknown until data arrives.

## Usage Example

```typescript
import { IncidentQueryResults } from './incident-query-results';
import type { Incident } from '../utils/incident-transform';

function IncidentDetailPage({ incident }: { incident?: Incident }) {
  return (
    <div className="flex flex-col gap-6">
      {/* Other incident summary sections */}
      <IncidentQueryResults incident={incident} />
    </div>
  );
}
```

When `incident` is `undefined` or the component is within a loading scope, the table renders skeleton rows automatically. Once data resolves, it displays either the query result rows, or one of two empty-state messages depending on whether `queryResult` is an empty array (no rows returned) versus `undefined` (evidence not retained).
