# incident-query-results.tsx

Renders the "Query Details" section of an incident view, displaying the raw osquery result rows that triggered the detection. It reuses the shared `QueryReportTable` component (the same one used on the Monitoring query page) and handles loading/empty states gracefully.

## Key Components

- **`IncidentQueryResults`** — Main exported component. Accepts an optional `incident` prop and renders the evidence table:
  - Shows skeleton loading rows when `incident` is undefined or an ancestor loading scope is active (via `useLoadingScope`).
  - Displays query result rows (`incident.queryResult`) when available, with dynamic columns determined by the detecting query (no device column, since an incident is scoped to a single machine).
  - Shows a contextual empty-state message distinguishing between "query returned no rows" vs. "no evidence was kept".

- **`QueryResultsFrame`** — Internal layout wrapper providing the section heading ("Query Details") and consistent spacing around the table content.

- **`INCIDENT_EVIDENCE_SKELETON_ROWS`** / **`INCIDENT_EVIDENCE_SKELETON_COLUMNS`** — Constants defining the skeleton placeholder shape (1 row, 3 columns) shown while loading.

## Usage Example

```typescript
import { IncidentQueryResults } from './incident-query-results';
import type { Incident } from '../utils/incident-transform';

function IncidentDetailPage({ incident }: { incident?: Incident }) {
  return (
    <div className="flex flex-col gap-[var(--spacing-system-l)]">
      {/* Other incident summary sections */}
      <IncidentQueryResults incident={incident} />
    </div>
  );
}
```

When `incident` is `undefined` (e.g., still fetching), the component automatically renders loading skeleton rows. Once data resolves, it either displays the query result table or an appropriate empty-state message based on whether `queryResult` is present and non-empty.
