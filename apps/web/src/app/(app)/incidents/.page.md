# page.tsx

The Incidents page component, responsible for rendering a tabbed incidents view (e.g., "Current" vs. "Snoozed") gated behind a feature flag, with URL-synced tab state and isolated error/loading boundaries per tab.

## Key Components

- **`IncidentsPage`** (default export) — Client component that:
  - Uses `useIncidentsGate()` to determine whether the feature is `'off'`, `'loading'`, or enabled, calling Next.js `notFound()` only on a definitive `'off'` state.
  - Manages the active tab and incident filter params via `useApiParams`, defaulting to the `current` tab.
  - Clears filter params (`NO_INCIDENT_FILTERS`) whenever the tab changes, since filters are tab-scoped.
  - Wraps content in `LoadingWhen` to show skeleton loading while the feature flag is unresolved.
  - Renders `TabNavigation` for switching between `INCIDENTS_TABS`.
  - Wraps the table in `ContentErrorBoundary`, keyed by `tab`, so switching tabs resets any prior error state.
  - Renders `IncidentsTable`, keyed by `tab` to force remount (resetting search, dialogs, and refetch counters) on tab switch.

## Usage Example

This is a Next.js App Router page component and is rendered automatically by the framework when its route is visited — it isn't imported directly elsewhere.

```typescript
// app/incidents/page.tsx
// Next.js automatically renders this as the route's page component.
// No manual invocation needed; navigating to the incidents route triggers it.

export default function IncidentsPage() {
  // ...implementation as shown above
}
```

Related conventions used by this file:

```typescript
// Tab-aware filter params, owned by the table but declared at the page level
const { params, setParams } = useApiParams({
  tab: { type: 'string', default: 'current' },
  ...INCIDENT_FILTER_PARAMS,
});

// Switching tabs resets filters for a clean per-tab experience
setParams({ tab: 'snoozed', ...NO_INCIDENT_FILTERS });
```
