Zustand store for the Mingo AI chat: dialog identity, cache/persistence concerns, and a converted **read mirror** of the core library's stream reducer. Message accumulation itself lives in the lib reducer (one per dialogId, side `'main'`), reached through `createReducerMirror` in `@/lib/chat-stream-thread`.

## State

| Category | Fields |
|---|---|
| Read mirror | `messagesByDialog`, `phaseByDialog`, `streamingIdByDialog`, `tokenUsageByDialog` |
| Dialogs | `activeDialogId`, `dialogs` |
| Realtime bookkeeping | `unreadCounts`, `highestStreamSeqByDialog` |
| Loading / errors | `isLoadingDialog`, `isLoadingMessages`, `isCreatingDialog`, `dialogError`, `messagesError` |
| Pagination | `hasMoreMessages`, `messagesCursor`, `newestMessageCursor` |

Mirror fields are written **only** by the mirror's `onSnapshot`, so the reducer stays the single writer of thread state.

## Module-level exports

- **`mingoChatDialogStore`** — the `ChatDialogStore` backing this host's reducers (built by the mirror so its `onEvict` is wired in)
- **`bindMingoDialog(dialogId)`** — pre-curried `{ apply, hydrate, mutate, mergeApprovalStatuses, evictionEpoch }`, identity-stable per dialog
- **`mutateMingoDialog(dialogId, fn)`** — run reducer commands, then mirror
- **`setMingoChatHandlers(dialogId, handlers)`** — late-bind approve/reject + model-badge handlers (merged, not replaced: separate effects register them)

## Thread commands

All delegate to the reducer — the store performs no message mutation of its own.

- **`setMessages`** — history hydration, routed through `mirror.hydrate`. Deliberately not a raw thread write: restoring a turn needs `resumed`, the accumulator seed and the adopt-once flag **together** (see `HydrateOptions`). A reload mid-stream otherwise loses the persisted head of the turn to the first replayed delta.
- **`prependMessages` / `prependWithBoundaryMerge`** — older history pages
- **`addMessage` / `updateMessage` / `removeMessage` / `removeWelcomeMessages`** — row-level edits
- **`pushOptimisticSend`** — local send; the reducer records the text and consumes the backend's `MESSAGE_REQUEST` echo itself (a blanket "drop echoes carrying my user id" would also hide this user's sends from a second tab)
- **`updateApprovalStatusInMessages`** — cross-message approval flip through the reducer's projection
- **`setTyping` / `getTyping` / `getStreamingId`** — the reducer's phase machine; `phaseByDialog !== 'idle'` is the typing signal

## Other actions

`setTokenUsage` also routes through the reducer, keeping one writer for `tokenUsageByDialog`. `recordHighestStreamSeq` / `getHighestStreamSeq` carry the JetStream cursor across `DialogSubscription` remounts. `clearDialog` drops the reducer caches together with the store slice.

## Usage

```typescript
// History hydration (merged first page)
useMingoMessagesStore.getState().setMessages(dialogId, mergedMessages);

// Realtime chunks — through the shared processor, never by hand
const processChunk = useChatChunkProcessor({
  boundMirror: bindMingoDialog(dialogId),
  messages,
  approvalStatuses,
});

// Reading
const messages = useMingoMessagesStore(s => s.messagesByDialog.get(dialogId));
const isStreaming = useMingoMessagesStore(s => (s.phaseByDialog.get(dialogId) ?? 'idle') !== 'idle');
```
