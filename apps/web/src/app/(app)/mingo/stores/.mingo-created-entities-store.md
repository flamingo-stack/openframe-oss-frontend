# mingo-created-entities-store.ts

Zustand-backed store that bridges Mingo AI's server-side entity creation with the UI, ensuring lists (scripts, policies, tickets, knowledge base) refresh automatically when the AI agent creates a new row, even though those creations bypass the page's own mutation flows.

## Key Components

- **`MingoCreatedEntity`** — Union type of entity kinds a Mingo create tool can add: `'script' | 'scriptSchedule' | 'policy' | 'ticket' | 'knowledgeBase'`.
- **`createdEntityOf(chunk)`** — Inspects a streamed tool-execution chunk and returns the `MingoCreatedEntity` it created, or `null` if the chunk isn't a successful create call.
- **`useMingoCreatedEntitiesStore`** — Zustand store holding an `epoch` counter per Relay-backed entity (`script`, `scriptSchedule`, `knowledgeBase`) and a `bump` action to increment one.
- **`noteMingoToolExecuted(chunk)`** — Call this with each stream chunk; it detects successful creates and refreshes the matching list (via react-query invalidation or epoch bump).
- **`useMingoCreatedEpoch(entity)`** — Hook for Relay-based lists to read their deferred epoch counter, used as a `fetchKey` to trigger a refetch without unmounting the list.

## Usage Example

```typescript
import { noteMingoToolExecuted, useMingoCreatedEpoch } from './mingo-created-entities-store';

// In the chat stream handler, after each tool-execution chunk arrives:
function handleStreamChunk(chunk: ToolChunk) {
  noteMingoToolExecuted(chunk);
}

// In a Relay-powered scripts list component:
function ScriptsList() {
  const fetchKey = useMingoCreatedEpoch('script');
  const data = useLazyLoadQuery(ScriptsQuery, {}, { fetchKey });
  // ...render list
}
```

For react-query-backed lists (policies, tickets), no hook is needed—`noteMingoToolExecuted` invalidates the relevant query keys directly, and the existing `useQuery`/`useSuspenseQuery` hooks refetch automatically.
