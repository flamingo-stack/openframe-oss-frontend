# mingo-home-incidents.tsx

Renders the "Incidents" section of Mingo's home dashboard, showing a current unresolved incident count alongside four severity cards (Critical, High, Medium, Low), each linking to the Incidents list pre-filtered by severity and unresolved status.

## Key Components

- **`MingoHomeIncidents`** — Top-level export. Gates visibility via `useIncidentsGate()` (hidden when the feature is `off`), coordinates with the page's shared loading/reveal system, and wraps the data-dependent content in a `ContentErrorBoundary` with retry support.
- **`IncidentsSection` / `IncidentsReader`** — Suspense and loading-scope wrappers that defer rendering of the live query until the section is ready to reveal.
- **`IncidentsCards`** — Fetches `mingoHomeIncidentsQuery` (GraphQL) via `useLazyLoadQuery`, derives per-severity counts from the `insightFilters` facet response, and renders the title with a total count plus a grid of `DashboardInfoCard`s linking to filtered incident views.
- **`IncidentsSkeleton`** — Loading placeholder preserving the real header/severity tags while count values are shown as loading bars.
- **`IncidentsFailed`** — Error fallback UI; displays an em-dash (`EMPTY_VALUE`) instead of fabricating counts, with a `SectionLoadError` retry affordance.
- **`mingoHomeIncidentsQuery`** — GraphQL query fetching unresolved (`NEW`, `ACKNOWLEDGED`) incident counts grouped by severity.
- **`severityHref`** — Builds a route to the Incidents list filtered by a given severity and unresolved statuses.

## Usage Example

```typescript
import { MingoHomeIncidents } from './mingo-home-incidents';

// Rendered as a section within the Mingo home dashboard page
export function MingoHomePage() {
  return (
    <div>
      <MingoHomeIncidents />
      {/* other dashboard sections */}
    </div>
  );
}
```

The component requires no props—it independently manages its data fetching, loading states, error boundaries, and visibility gating (SaaS-only, dependent on `insights` entitlement). It coordinates with sibling sections via `useRevealWait`/`useRevealPart` to synchronize a unified page reveal.
