# mingo-home-incidents.tsx

Renders the "Incidents" section on Mingo's home dashboard, showing a count of currently unresolved incidents and a grid of severity-based cards (Critical, High, Medium, Low) that each link to a filtered Incidents list. Handles loading, error, and gated (SaaS-only) states via coordinated reveal/loading hooks.

## Key Components

- **`MingoHomeIncidents`** — Top-level export. Checks the `insights` feature gate via `useIncidentsGate`, shows a skeleton while loading, and wraps the data-driven section in a `ContentErrorBoundary`.
- **`mingoHomeIncidentsQuery`** (GraphQL) — Fetches `insightFilters` for `NEW`/`ACKNOWLEDGED` statuses, returning per-severity counts and a total `filteredCount`.
- **`IncidentsSection` / `IncidentsReader`** — Suspense and loading-scope wrappers that defer the actual Relay read until ready.
- **`IncidentsCards`** — Executes the lazy-loaded query, renders the title with the current total count, and a grid of `DashboardInfoCard`s per severity, each linking via `severityHref`.
- **`IncidentsSkeleton`** — Loading placeholder with real header/tags but skeleton bars for counts.
- **`IncidentsFailed`** — Error fallback showing `EMPTY_VALUE` (`—`) instead of fabricated counts, with a retry affordance via `SectionLoadError`.
- **`severityHref`** — Builds a route to the Incidents list filtered by severity and unresolved statuses (`NEW`, `ACKNOWLEDGED`).
- **`SEVERITIES`** — Ordered list of the four severities displayed (most severe first).

## Usage Example

```typescript
import { MingoHomeIncidents } from '@/app/(app)/mingo/home/components/mingo-home-incidents';

export function MingoHomePage() {
  return (
    <div className="dashboard-sections">
      <MingoHomeIncidents />
      {/* other home sections */}
    </div>
  );
}
```

The component is self-contained: it internally handles its own gating (via `useIncidentsGate`), data fetching (Relay), loading states, and error boundaries. Consumers simply render `<MingoHomeIncidents />` within a page that participates in the shared `reveal-together` coordination (`useRevealWait`/`useRevealPart`) used across dashboard sections for synchronized reveal timing.
