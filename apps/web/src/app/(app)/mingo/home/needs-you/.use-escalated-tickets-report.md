# use-escalated-tickets-report.ts

A React hook that powers the "Needs you" dashboard source for escalated tickets—tickets in a Tech Required status that the end user has explicitly escalated (flagged by the ai-agent via `escalatedByUser`).

## Key Components

- **`useEscalatedTicketsReport(gate: FeatureFlagGate): SourceReport`** — Main hook that:
  - Resolves Tech Required status IDs via `useTicketStatusesQuery`
  - Fetches a bounded set of escalated tickets (`ESCALATED_CANDIDATES = 5`) scoped to those status IDs
  - Merges loading/error/offline states from both the statuses and tickets queries into a single `SourceReport`
  - Maps raw ticket data to display rows using `escalatedTicketRow`

- **`ESCALATED_CANDIDATES`** — Constant (5) controlling how many escalated tickets are requested, sized to allow for duplicate-row filtering downstream in the card.

- **`NO_IDS`** — Empty-array sentinel used when no Tech Required statuses exist, avoiding an unscoped fetch.

## Usage Example

```typescript
import { useEscalatedTicketsReport } from './use-escalated-tickets-report';
import type { FeatureFlagGate } from '@/lib/feature-flags';

function NeedsYouEscalatedCard({ gate }: { gate: FeatureFlagGate }) {
  const report = useEscalatedTicketsReport(gate);

  if (report.status === 'loading') return <CardSkeleton />;
  if (report.status === 'error') {
    return <CardError isOffline={report.isOffline} onRetry={report.retry} />;
  }

  return (
    <ul>
      {report.rows.map(row => (
        <TicketRow key={row.id} row={row} />
      ))}
    </ul>
  );
}
```

## Notes

- Query results are cached under the shared `dialogsQueryKeys.all` namespace so any ticket mutation that invalidates the dialogs cache automatically refreshes this source—distinct from the board's own infinite-query cache key.
- `refetchOnMount: 'always'` ensures fresh data is drawn over stale data on every dashboard visit without showing a loading skeleton.
- When the feature flag `gate` is not `'on'`, queries are disabled and state reports as `'closed'` rather than `'loading'` or `'error'`.
