# needs-you-approvals-source.tsx

A headless React component that sources pending approval-request rows for a "Needs You" aggregation view by reusing the notifications drawer's existing Relay query and connection, avoiding duplicate network requests.

## Key Components

- **`NeedsYouApprovalsSource`** — Default-exported function component accepting an `onReport: ReportSource` callback prop. Renders nothing (`null`); it's a pure data-sourcing component that reports its results via callback.
- Uses `useLazyLoadQuery` with `notificationsDrawerRelayQuery` and `fetchPolicy: 'store-or-network'` to piggyback on the notifications drawer's already-loaded first page (kept live via its NATS bridge).
- Uses `useFragment` with `notificationsDrawerRelayFragment` to read the connection data.
- Cross-references `useMingoChat()` session dialogs to resolve chat titles for approval rows whose backend title is generic ("Approval required").
- Builds rows via `approvalRow(mapNotificationNode(readNotificationNode(...)), chatTitles)`, filtering out non-approval notifications.
- Reports results synchronously via `useLayoutEffect` (not `useEffect`) so that store-cached data renders in the same paint cycle, avoiding a loading-state flash on page return.

## Usage Example

```typescript
import { NeedsYouApprovalsSource } from './needs-you-approvals-source';
import type { ReportSource } from './needs-you-rows';

function NeedsYouPage() {
  const handleReport: ReportSource = (sourceKey, result) => {
    // sourceKey === 'approvals'
    // result === { status: 'ready', rows: NeedsYouRow[] }
    updateAggregatedRows(sourceKey, result);
  };

  return (
    <>
      <NeedsYouApprovalsSource onReport={handleReport} />
      {/* other sources (tasks, mentions, etc.) report similarly */}
    </>
  );
}
```

## Notes & Limitations

- Only sees approvals within the drawer's first page (`DRAWER_PAGE_SIZE`); approvals beyond that page aren't surfaced since there's no dedicated `notifications(filter: { types })` query yet.
- Relies on `useRetryKey` from `content-error-boundary` to support retry-driven refetches.
- Any decision made in the drawer, chat, or the Needs Approval page updates the shared store, which automatically propagates here.
