## Overview

A headless Relay data source component that surfaces pending approval requests ("Needs approval") by reusing the notifications drawer's existing query and connection. It renders nothing visually—it reads data and reports computed rows to a parent via a callback, avoiding a duplicate network request.

## Key Components

- **`NeedsYouApprovalsSource`** — React component (headless, returns `null`) that:
  - Loads notifications via `useLazyLoadQuery` with the shared `notificationsDrawerRelayQuery`, using `fetchPolicy: 'store-or-network'` so it reuses the drawer's cached store data when available.
  - Reads the fragment `notificationsDrawerRelayFragment` to get the notifications connection.
  - Cross-references chat dialog titles from `useMingoChat()` to enrich approval rows with session chat names.
  - Maps each notification edge through `mapNotificationNode`, `readNotificationNode`, and `approvalRow` to build `NeedsYouRow` entries, filtering out non-approval rows.
  - Calls `onReport('approvals', { status: 'ready', rows })` inside a `useLayoutEffect` (not `useEffect`) so the rows are available before the browser paints, avoiding a flash of a loading state.
  - Uses `useRetryKey()` as the Relay `fetchKey` to support manual retry/refetch via the app's error boundary mechanism.

## Usage Example

```typescript
import { NeedsYouApprovalsSource } from './needs-you-approvals-source';
import type { ReportSource } from './needs-you-rows';

function NeedsYouPanel() {
  const handleReport: ReportSource = (sourceName, result) => {
    console.log(`${sourceName} reported:`, result.status, result.rows);
  };

  return (
    <>
      <NeedsYouApprovalsSource onReport={handleReport} />
      {/* other sources (e.g. tasks, mentions) composed the same way */}
    </>
  );
}
```

**Notes:**
- This component only sees notifications within the drawer's first loaded page (`DRAWER_PAGE_SIZE`); approvals beyond that page aren't reflected yet.
- Must be rendered inside a Relay environment provider and a `MingoChatProvider` ancestor, since it depends on `useMingoChat()`.
- Designed to be composed alongside sibling "source" components that each report into a shared aggregator via `onReport`.
