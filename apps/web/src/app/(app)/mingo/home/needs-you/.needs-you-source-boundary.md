Isolates one or more Relay-backed "Needs you" data sources inside their own error boundary, so that a failed backend only affects its own rows while sibling sources continue rendering independently within the same card.

## Key Components

- **`NeedsYouSourceBoundary`** — Wraps `children` (a Relay-suspending source) in a `ContentErrorBoundary`. On retry, it resets each source's status to `loading` before the remount happens, so the UI doesn't show a stale failure line while the request is already re-running. The `Suspense` fallback is intentionally `null` because the parent card is responsible for drawing the loading state, not this boundary.
- **`ReportFailure`** — Internal helper component rendered as the error boundary's fallback. It calls `onReport` for every source in `sources` with an `error` status (including `isOffline` and a `retry` callback), then renders nothing. Uses `useEffect` so reporting happens as a side effect rather than during render.
- **`NeedsYouSourceBoundaryProps`** — Props: `sources` (the list of `NeedsYouSource` affected by this boundary), `onReport` (callback of type `ReportSource` to communicate status), and `children` (the Relay-backed content to render).

## Usage Example

```typescript
import { NeedsYouSourceBoundary } from './needs-you-source-boundary';
import type { NeedsYouSource, ReportSource } from './needs-you-rows';

function TicketsSource({ onReport }: { onReport: ReportSource }) {
  const source: NeedsYouSource = 'tickets';

  return (
    <NeedsYouSourceBoundary sources={[source]} onReport={onReport}>
      <TicketsRelayFragment onReport={onReport} />
    </NeedsYouSourceBoundary>
  );
}
```

Each source is wrapped independently inside the "Needs you" card, so that if the tickets backend fails, the alerts or approvals sources keep loading and rendering normally. The card listens to `onReport` calls to decide what to render for each source: loading, error (with retry), or the actual rows once Relay resolves.
