## MingoDashboard

The primary dashboard view for the Mingo-first shell, rendered at `/dashboard` for SaaS tenants. It composes the onboarding banner, a "Needs you" action panel, and overview sections (Devices, Incidents, Tickets, Customers) into a single coordinated view.

## Key Components

- **`MingoDashboard({ live })`** — Main exported component. Assembles the dashboard layout:
  - `IntroBanner` — onboarding call-to-action
  - `NeedsYouCard` / `NeedsYouPanel` — surfaces items awaiting human action (loading state used when `live` is off)
  - `OverviewSections` — Devices / Tickets / Customers cards with `MingoHomeIncidents` rendered between Tickets and Customers
  - `RevealTogether` — wraps the page in live mode so all data-fetching blocks resolve together before revealing content, avoiding staggered pop-in

## Usage Example

```typescript
import { MingoDashboard } from './mingo-dashboard';

// Default: live mode, fetches and reveals data together
export default function DashboardPage() {
  return <MingoDashboard />;
}

// Non-live mode: used while the shell waits on an onboarding
// decision (holdsDashboard), rendering skeleton-equivalent content
// without triggering data reads.
export function PendingDashboardSlot() {
  return <MingoDashboard live={false} />;
}
```

**Notes:**
- No "Initial Setup" card is rendered here — setup is handled by the separate `/setup` wizard (onboarding v2).
- The component holds no composer/quick-actions UI; those live in the shared shell dock and the dedicated `/mingo` chat.
- The `empty:hidden` utility ensures the intro/needs-you wrapper collapses (including its padding) when both children render nothing.
