## MingoDashboard

The main dashboard view for the Mingo-first shell, rendered at `/dashboard` for SaaS tenants. It composes an onboarding intro banner, a "Needs you" panel for items requiring human attention, and overview sections for Devices, Tickets, Incidents, and Customers.

Unlike the legacy dashboard, this component has no Initial Setup card (onboarding is handled by the separate `/setup` wizard) and no action composer (quick actions live in the dedicated `/mingo` chat instead).

## Key Components

- **`MingoDashboard`** — Default export; accepts a `live` prop (default `true`) controlling whether the component fetches live data or renders a loading/skeleton state.
- **`IntroBanner`** / **`OverviewSections`** — Imported from dashboard-content to render the onboarding banner and the filtered Devices/Tickets/Incidents/Customers sections.
- **`NeedsYouCard`** / **`NeedsYouPanel`** — Live or loading variants of the panel surfacing items that need human action.
- **`MingoHomeIncidents`** — Incidents block injected between Tickets and Customers in the overview.
- **`RevealTogether`** — Wrapper that defers rendering until all child data sources resolve, then reveals content in a single step (avoids staggered pop-in).

## Usage Example

```typescript
import { MingoDashboard } from './mingo-dashboard';

// Standard live dashboard (fetches real data)
export function DashboardPage() {
  return <MingoDashboard />;
}

// Non-live mode: used while the shell waits on an async
// onboarding check (e.g. `holdsDashboard`), renders skeleton only
export function DashboardPageLoading() {
  return <MingoDashboard live={false} />;
}
```

**Behavior notes:**
- When `live` is `true`, all data-dependent blocks are wrapped in `RevealTogether`, so the UI shows a unified skeleton until every section has loaded, then reveals all content at once.
- When `live` is `false`, no network requests are made; a static skeleton is shown so the eventual hand-over to live data causes no layout shift.
- The intro banner and "Needs you" panel container uses `empty:hidden` so padding collapses when both have nothing to show.
