## Overview

Shared utilities supporting the per-type context-item components used by the chat context picker's `renderItems` configuration. Provides a common props contract and a client-side pagination hook for REST-backed (fully-loaded) data sources, complementing GraphQL/Relay sources that paginate server-side.

## Key Components

- **`MINGO_CONTEXT_PAGE_SIZE`** — Constant (`10`) defining the default page size, kept in sync with the picker's loading-skeleton count.
- **`ContextItemsProps`** — Interface describing the props every per-type items component receives from `renderItems`: `query` (debounced search text), `selectedKeys` (currently selected item keys), `onToggle` (selection callback), and `atLimit` (whether the selection limit has been reached).
- **`useClientPaging<T>(all, pageSize?)`** — Hook that incrementally reveals items from a fully-loaded array. Resets the visible count automatically when the source array reference changes (e.g., a new search result), using the adjust-state-during-render pattern to avoid a flash of stale data. Returns `items`, `hasMore`, and `loadMore`.

## Usage Example

```typescript
import { useClientPaging, ContextItemsProps, MINGO_CONTEXT_PAGE_SIZE } from './items-shared';

function DocumentContextItems({ query, selectedKeys, onToggle, atLimit }: ContextItemsProps) {
  const allDocuments = useFetchDocuments(query); // REST hook returning full list

  const { items, hasMore, loadMore } = useClientPaging(allDocuments, MINGO_CONTEXT_PAGE_SIZE);

  return (
    <ContextItemsList
      items={items}
      selectedKeys={selectedKeys}
      onToggle={onToggle}
      atLimit={atLimit}
      hasMore={hasMore}
      onLoadMore={loadMore}
    />
  );
}
```

Use this pattern for any REST-backed source feeding the chat context picker; for GraphQL/Relay sources, rely on the native pagination hook instead of `useClientPaging`.
