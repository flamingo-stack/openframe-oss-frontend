## items-shared.ts

Shared utilities and type definitions supporting per-type context-item components used by the chat context picker's `renderItems` configuration. It provides a common props contract and a client-side pagination hook for REST-backed data sources.

## Key Components

- **`MINGO_CONTEXT_PAGE_SIZE`** — Constant (`10`) defining the default page size, matching the picker's skeleton loading count.
- **`ContextItemsProps`** — Interface describing the props passed to every per-type items component by `renderItems`: `query` (debounced search text), `selectedKeys` (currently selected item keys), `onToggle` (selection handler), and `atLimit` (whether the selection limit is reached).
- **`useClientPaging<T>`** — Hook implementing incremental client-side paging over a fully-loaded array. Reveals more items on each `loadMore()` call and automatically resets the visible count when the underlying list reference changes (e.g., a new search), using the adjust-state-during-render pattern to avoid UI flashing.

## Usage Example

```typescript
import { useClientPaging, type ContextItemsProps, MINGO_CONTEXT_PAGE_SIZE } from './items-shared';

function MyRestContextItems({ query, selectedKeys, onToggle, atLimit }: ContextItemsProps) {
  const allResults = useFetchResultsSomehow(query); // e.g., REST hook

  const { items, hasMore, loadMore } = useClientPaging(allResults, MINGO_CONTEXT_PAGE_SIZE);

  return (
    <ContextItemsList
      items={items}
      selectedKeys={selectedKeys}
      onToggle={onToggle}
      atLimit={atLimit}
      hasMore={hasMore}
      onLoadMore={loadMore}
    />
  );
}
```

This pattern is used across REST-backed context sources (as opposed to GraphQL/react-relay sources, which rely on cursor-based pagination instead).
