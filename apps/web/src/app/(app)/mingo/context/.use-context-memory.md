# use-context-memory.ts

A React hook that supplies data for `EmbeddableChat`'s `contextMemory` strip — the UI above Mingo's chat composer that shows which entities the agent currently "remembers" (the open view plus recently visited ones), with removable rows.

This hook adapts the shared navigation-context store (`useMingoContextStore`) into the shape expected by the chat UI library, ensuring the memory strip reflects exactly the context data sent along with every Mingo message, without any additional data fetching.

## Key Components

- **`MingoContextMemory`** — Return type interface exposing:
  - `items`: ordered list of `ChatContextItem`s (currently-open entity first, then recent views, most-recent-first)
  - `onRemove`: callback to forget/remove a context entity
  - `pending`: `true` while a detail page is still loading the entity to add, so the UI can render a loading state
- **`useMingoContextMemory()`** — The hook itself. Reads `openView`, `recentViews`, `removeView`, and `openViewPending` from `useMingoContextStore`, merges `openView` and `recentViews` into a single ordered `items` array, and wraps `removeView` as a memoized `onRemove` callback.

## Usage Example

```typescript
import { useMingoContextMemory } from './use-context-memory';

function ChatContextStrip() {
  const { items, onRemove, pending } = useMingoContextMemory();

  if (pending && items.length === 0) {
    return <ContextStripSkeleton />;
  }

  return (
    <EmbeddableChat
      contextMemory={{
        items,
        onRemoveItem: onRemove,
      }}
      // ...other chat props
    />
  );
}
```

Since `ContextRefWithLabel` in the store is structurally identical to `ChatContextItem` (`type`, `id`, `label`, `description`), store entries pass through to the UI without transformation. Removal is keyed by `type:id`, matching what the row component returns on user interaction.
