# use-context-memory.ts

A React hook that powers the `contextMemory` slot of `EmbeddableChat` — the strip above the Mingo chat composer that shows which entities (pages/records) Mingo currently "remembers" from the user's navigation history.

This hook adapts the navigation-context store (`useMingoContextStore`) into the shape expected by the chat UI, ensuring the displayed context exactly matches what's sent to the Mingo agent on every message — no separate fetch or divergent state.

## Key Components

- **`MingoContextMemory`** — interface describing the hook's return value:
  - `items: ChatContextItem[]` — the currently-open entity (if any) followed by previously-viewed entities, most-recent-first.
  - `onRemove: (item: ChatContextItem) => void` — removes an entity from context (wired to each row's `×` control).
  - `pending: boolean` — `true` while a detail page is still loading the entity to be added, used to render a loading placeholder in the strip.
- **`useMingoContextMemory()`** — the hook itself; reads `openView`, `recentViews`, `removeView`, and `openViewPending` from `useMingoContextStore` and derives a memoized `items` list and stable `onRemove` callback.

## Usage Example

```typescript
import { useMingoContextMemory } from './hooks/use-context-memory';
import { EmbeddableChat } from '@flamingo-stack/openframe-frontend-core/components/chat';

function MingoChatPanel() {
  const contextMemory = useMingoContextMemory();

  return (
    <EmbeddableChat
      contextMemory={contextMemory}
      // ...other EmbeddableChat props
    />
  );
}
```

Internally, `items` is derived by prepending `openView` (the entity currently open, if any) to `recentViews`:

```typescript
const items = openView ? [openView, ...recentViews] : recentViews;
```

Since `ContextRefWithLabel` from the store is structurally compatible with `ChatContextItem` (`type`, `id`, `label`, `description`), no mapping is needed before passing items to the chat component.
