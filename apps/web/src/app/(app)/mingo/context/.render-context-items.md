## render-context-items.tsx

Dispatcher function that maps a context entity type to its corresponding items-rendering component. It serves as the `renderItems` implementation wired into `ChatContextPickerConfig`, routing the active entity type (device, ticket, policy, etc.) to the appropriate per-type component that owns its own data-fetching hooks.

## Key Components

- **`COMPONENTS`** — A lookup record mapping each `CONTEXT_ENTITY_KIND` value to its corresponding items component (e.g., `DeviceItems`, `TicketItems`, `PolicyItems`). Combines components backed by relay data sources (`relay-items`) and REST data sources (`rest-items`).
- **`renderMingoContextItems(args)`** — The exported dispatcher function. Looks up the component for the given `type`, and if found, returns it as a JSX element (not invoked directly as a function) so its internal hooks execute properly. Returns `null` if no matching component exists for the type.

## Usage Example

```typescript
import type { ChatContextPickerConfig } from '@flamingo-stack/openframe-frontend-core/components/chat';
import { renderMingoContextItems } from './render-context-items';

const contextPickerConfig: ChatContextPickerConfig = {
  // ...other config
  renderItems: renderMingoContextItems,
};
```

**Important implementation notes:**

- The function is called inside the library's `<Suspense>` boundary and error boundary, so the returned component may suspend during its initial data load.
- The component must be returned as a JSX element (`<Component ... />`), never invoked as a plain function call, to ensure React hooks inside it run correctly.
- The `key={type}` prop forces a remount whenever the active entity type changes, isolating each type's internal hook state from the previous type's.
