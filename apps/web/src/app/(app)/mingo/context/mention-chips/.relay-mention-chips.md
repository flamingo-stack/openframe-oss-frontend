## relay-mention-chips.tsx

Renders self-fetching mention chips (`@marker:id` references) for GraphQL-resolvable entity types—device, organization, user, KB article/folder, script, scheduled script, insight, and software. Each chip suspends on first load (showing a skeleton), reads from the Relay store on remounts via `store-or-network` fetch policy, and gracefully falls back to a plain id/label chip on error or unresolved name.

## Key Components

- **`GraphqlMentionChip`** — Public entry component. Accepts `kind`, raw `id`, optional `icon`, and `fallbackLabel`; computes the Relay global id (re-encoding raw ids per entity type) and renders the chip inside an error boundary.
- **`hrefFor(kind, rawId, globalId)`** — Resolves the correct detail-page route per entity kind, using either the raw db id (device, org, software, user) or the Relay global id (KB article/folder, script, schedule, insight).
- **Inner fetch components** — `NodeInner` (device/org/user via `node(id:)`), `KbInner` (`knowledgeBaseItem(id:)`), `ScriptInner` (`script(id:)`), `ScheduleInner` (`scriptSchedule(id:)`), `InsightInner` (`insight(id:)`), `SoftwareInner` (`software(id:)`).
- **`innerFor(kind)`** — Dispatches to the correct inner component based on entity kind.
- **`GraphqlMentionLoader`** / **`GraphqlMentionReader`** — Wraps the inner fetcher in a `LoadingSuspense` scope so the chip itself renders a skeleton while loading, without surfacing a page-level loading state.

## Usage Example

```typescript
import { GraphqlMentionChip } from './relay-mention-chips';
import { CONTEXT_ENTITY_KIND } from '../context-types';

function MessageBody() {
  return (
    <p>
      Device{' '}
      <GraphqlMentionChip
        kind={CONTEXT_ENTITY_KIND.DEVICE}
        id="machine-123"
        fallbackLabel="Unknown device"
      />{' '}
      was flagged in incident{' '}
      <GraphqlMentionChip kind={CONTEXT_ENTITY_KIND.INSIGHT} id="insight-456" />.
    </p>
  );
}
```

Each `GraphqlMentionChip` is self-contained: it handles its own GraphQL fetch, loading skeleton, and error fallback, making it safe to embed multiple chips inline within rendered message text.
