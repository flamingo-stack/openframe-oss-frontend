# mention-tag.tsx

Presentational components for rendering mention chips in chat messages — inline badges that link to entity detail pages (e.g., a device, ticket, or user referenced in a conversation). Provides the shared visual shell, navigation behavior, and resilience wrapper used by every per-type mention chip in the app.

## Key Components

- **`MentionTag`** — Renders a chip (via the shared `InlineChip` component) that optionally links to an entity's detail page. If no `href` is provided, it renders as a plain, non-clickable chip. If an `href` is provided:
  - When the app can't open new tabs, the chip becomes a single chat-navigation link (`NavLinkAnchorViaRuntime`), preserving the chat sidebar/composer so "Back" returns to the conversation.
  - When new tabs are supported, the chip splits into two segments: the main chip (same-window chat navigation) and a trailing external-link icon segment that opens the same page in a new tab.
- **`MentionErrorBoundary`** — A class-based error boundary that catches fetch/render errors from an individual mention chip and renders a fallback (typically a plain ID chip) instead of crashing the entire chat message.
- **`CHIP_CLASS`** — Shared max-width constraint (`min(16rem,100%)`) ensuring chips truncate gracefully inside narrow containers (tooltips reveal the full label).
- **`SEGMENT_HOVER_CLASS` / `MAIN_SEGMENT_CLASS` / `NEW_TAB_SEGMENT_CLASS`** — Styling for the split-segment two-target hover behavior when a new-tab option is available.

## Usage Example

```typescript
import { MentionTag, MentionErrorBoundary } from '@/components/mention-tag';
import { MentionSuspense } from '@/components/mention-suspense';

function DeviceMention({ deviceId }: { deviceId: string }) {
  return (
    <MentionErrorBoundary fallback={<MentionTag label={`Device #${deviceId}`} />}>
      <MentionSuspense>
        <ResolvedDeviceChip deviceId={deviceId} />
      </MentionSuspense>
    </MentionErrorBoundary>
  );
}

function ResolvedDeviceChip({ deviceId }: { deviceId: string }) {
  const device = useDevice(deviceId); // throws while loading, resolved by Suspense
  return (
    <MentionTag
      icon={<DeviceIcon />}
      label={device.name}
      href={routes.devices.detail(device.id)}
    />
  );
}
```

Each per-type mention chip composes `MentionTag` inside `MentionSuspense` (loading skeleton) and `MentionErrorBoundary` (fetch-error fallback), ensuring a consistent lifecycle: skeleton → resolved chip → plain ID chip on failure.
