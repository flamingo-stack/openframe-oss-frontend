Draws the record chips of the Mingo chat: each record link `[name](record://<type>/<id>)` in an answer, and each context item a message carries, as a self-fetching entity chip (GraphQL or REST) by its record type.

## Key Components

### `renderMingoRecordChip({ type, id, label? })`
The chat's `renderRecordChip`: reads a record link's type as a kind with the lib's `openFrameRecordKindOf` and draws its chip. `policy`, `query` and `ticket` go to `RestMentionChip`, every other kind (`device`, `organization`, `kb`, `kbFolder`, `script`, `scheduledScript`, `insight`, `software`, `user`) to `GraphqlMentionChip`. A `vulnerability` draws a linked `RecordChip` with no fetch, an earlier conversation a `ChatReferenceChip`. Returns `null` for an unknown type, so the lib draws its own chip with the link's name.

### `renderMingoContextItem(item: ChatContextItem)`
The chat's `renderContextItem`: maps an attached context item `{ type, id, label }` to its record type and draws it through `renderMingoRecordChip`, with the picked label as the fallback so a chip never shows a bare id on reload.

## Usage Example

```typescript
<EmbeddableChat renderRecordChip={renderMingoRecordChip} renderContextItem={renderMingoContextItem} />

// record://device/abc123   -> <GraphqlMentionChip kind="DEVICE" .../>
// record://ticket/42       -> <RestMentionChip marker="ticket" .../>
// record://script/507f...  -> <GraphqlMentionChip kind="SCRIPT" .../>
```

Both functions are module-level (not hooks), so their identity is stable across streaming re-renders: the lib's per-message memo depends on it.
