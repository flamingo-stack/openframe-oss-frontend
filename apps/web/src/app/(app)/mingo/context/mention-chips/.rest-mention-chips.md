Self-fetching mention chip component for REST-backed entity types (policy, query, script, ticket), resolving an id into a display label and link via per-marker async resolvers backed by TanStack Query's `useSuspenseQuery`.

## Key Components

- **`RestMentionChip`** — Public component. Wraps rendering in a `MentionErrorBoundary` (falls back to `fallbackLabel || id`) and delegates to `RestLoader`.
- **`RestLoader`** / **`RestReader`** / **`RestInner`** — Internal rendering pipeline: `RestLoader` establishes a non-blocking loading scope (inline `span`, no visible loading status), `RestReader` renders a bare skeleton chip while inside that scope (no fetch triggered), and `RestInner` performs the actual `useSuspenseQuery` fetch and renders the resolved `MentionTag`.
- **`RESOLVERS`** — Map of marker type (`policy`, `query`, `script`, `ticket`) to async resolver functions, each returning a `Resolved` (`{ label, href? }`) object. Resolvers never throw; they degrade gracefully to `{ label: id }` on failure.
- **`resolvePolicy` / `resolveQuery`** — Fetch from `fleetApiClient`, linking to `/monitoring/policy/{id}` and `/monitoring/query/{id}`.
- **`resolveScript`** — Legacy Tactical RMM resolver; Tactical's single-script endpoint has been removed, so this always degrades to showing the raw id, linking to `/scripts/details/{id}`. New scripts resolve via a separate Relay `GraphqlMentionChip`.
- **`resolveTicket`** — Queries the ai-agent GraphQL `/chat/graphql` endpoint for ticket title/number, formats via `formatTicketRef`, links to the ticket dialog route.

## Usage Example

```typescript
import { RestMentionChip } from './rest-mention-chips';

function MessageBody() {
  return (
    <p>
      See <RestMentionChip marker="ticket" id="64f1..." fallbackLabel="Login issue" /> and{' '}
      <RestMentionChip marker="policy" id="123" />.
    </p>
  );
}
```

Dispatch by marker/id shape typically happens in `render-mention.tsx`, which decides between this REST resolver path and the Relay-based equivalents (e.g., for new scripts) based on id format (24-char ObjectId vs. numeric).
