# chat-reference-chip.tsx

Renders the inline `@chat:<dialogId>` mention Mingo emits when citing an **earlier conversation** of the same technician from chat memory. Unlike regular `ContextItemType` markers, `chat` is reference-only — it's never attachable as context, never offered by the mention picker, and has no entry in `CONTEXT_ENTITY_MARKER`. The chip resolves the dialog's title via the ai-agent GraphQL endpoint and links to that chat's page.

## Key Components

- **`CHAT_REFERENCE_MARKER`** — the `'chat'` marker string written by `ConversationMemoryReferenceService.CHAT_TAG_PREFIX`.
- **`resolveChatReference(id)`** — async function that POSTs a raw GraphQL query to `/chat/graphql` and returns a `ChatReference | null`. Returns `null` when the backend explicitly refuses to name the chat (not owned by the caller, or deleted); throws on any other failure (network, GraphQL errors).
- **`ChatReference`** — `{ id, title }` shape returned on success.
- **`ChatReferenceChip({ id, icon })`** — the public component. Wraps resolution in a `MentionErrorBoundary` so failed lookups fall back to a generic linked label (`UNRESOLVED_CHAT`) rather than breaking the chip.
- Internal helpers: `LinkedChatTag` (renders the linked `MentionTag`), `ChatReferenceLoader`/`ChatReferenceReader`/`ChatReferenceInner` (suspense + loading-scope plumbing that renders a label-less skeleton while the title loads, inline within the message text).

## Usage Example

```typescript
import { ChatReferenceChip, CHAT_REFERENCE_MARKER } from './chat-reference-chip';

// Rendering a parsed @chat:<dialogId> mention within message content
function MentionRenderer({ marker, id }: { marker: string; id: string }) {
  if (marker === CHAT_REFERENCE_MARKER) {
    return <ChatReferenceChip id={id} />;
  }
  return null;
}
```

**Resolution outcomes:**
- Backend returns a title → chip links to `mingoDialogLink(id)` with that title (or "Untitled conversation" if blank).
- Backend returns `null` → chip shows "Chat unavailable" with **no link** (the one case where nothing can be opened).
- Query throws (network/error) → error boundary falls back to a generic "Chat" label that **still links** to the dialog, since the chat page resolves the dialog independently.
