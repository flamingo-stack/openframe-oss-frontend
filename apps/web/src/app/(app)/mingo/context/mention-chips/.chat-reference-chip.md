# chat-reference-chip.tsx

Renders the inline `@chat:<dialogId>` marker Mingo inserts when citing an **earlier conversation** of the same technician from chat memory. Unlike `ContextItemType` markers, `chat` is mention-only — it is never offered by the context picker and has no `CONTEXT_ENTITY_MARKER` entry. The chip resolves the dialog's title via GraphQL and links to the chat's page.

## Key Components

- **`CHAT_REFERENCE_MARKER`** — the `'chat'` marker string the ai-agent writes before a recalled dialog id.
- **`resolveChatReference(id)`** — async function that POSTs to `/chat/graphql` and resolves a `ChatReference` (`{ id, title }`), returns `null` when the backend refuses to name the chat for the caller, or throws when the lookup itself fails.
- **`ChatReference`** — interface describing the resolved `{ id, title }` pair.
- **`ChatReferenceChip`** — the public component. Wraps resolution in a `MentionErrorBoundary`; on failure, falls back to a linked chip labeled `"Chat"` (since the chat page can resolve the dialog itself even if this lookup couldn't).
- Internal helpers: `LinkedChatTag` (renders the clickable `MentionTag` pointing at `mingoDialogLink(id)`), `ChatReferenceLoader`/`ChatReferenceReader`/`ChatReferenceInner` (handle the suspense/loading-scope lifecycle and distinguish `null` — "`Chat unavailable`" — from a resolved title).

## Usage Example

```typescript
import { ChatReferenceChip, resolveChatReference } from './chat-reference-chip';

// Rendered inline wherever Mingo's response text contains a `@chat:<id>` marker
<p>
  As discussed earlier, <ChatReferenceChip id="dialog-123" />, the fix was...
</p>

// Direct resolution (e.g. for prefetching)
const reference = await resolveChatReference('dialog-123');
if (reference) {
  console.log(reference.title); // e.g. "Untitled conversation" or actual title
}
```

The chip automatically shows a skeleton while loading, falls back to `"Chat unavailable"` when the backend explicitly declines to name the chat, and falls back to a generically-labeled link (`"Chat"`) if the lookup request itself fails.
