Defines the shared entity-context type system for Mingo's context layer, establishing the canonical mapping between context entity kinds, backend wire formats, and display metadata used across the picker, recent-views store, and chat message payloads.

## Key Components

- **`CONTEXT_ENTITY_KIND`** — Const enum of all eight supported context entity kinds (`DEVICE`, `SCRIPT`, `TICKET`, `ORGANIZATION`, `USER`, `KB_ARTICLE`, `POLICY`, `QUERY`), mirroring the backend `ContextItemType` enum
- **`ContextEntityKind`** — Union type derived from `CONTEXT_ENTITY_KIND` values
- **`CONTEXT_ENTITY_KINDS`** — Runtime array of all kinds in declaration order
- **`CONTEXT_ENTITY_MARKER`** — Maps each kind to its backend `@mention` short token (e.g. `KB_ARTICLE → 'kb'`); single source of truth for inline mention formatting
- **`CONTEXT_RELAY_TYPENAME`** — Partial map of GraphQL-resolvable kinds to their Relay `__typename` strings, used to re-encode raw DB ids to Relay global ids for client-side `node()` fetches in chips
- **`ContextRef`** — Minimal wire shape `{ type, id }` for `contextItems` and view refs
- **`ContextRefWithLabel`** — `ContextRef` extended with `label` and optional `description` for picker/store display
- **`CONTEXT_ITEMS_MAX`** / **`RECENT_VIEWS_MAX`** — Spec-defined limits (10 and 5 respectively)

## Usage Example

```typescript
import {
  CONTEXT_ENTITY_KIND,
  CONTEXT_ENTITY_MARKER,
  ContextRef,
  ContextRefWithLabel,
} from './context-types';

// Build a wire payload ref
const ref: ContextRef = {
  type: CONTEXT_ENTITY_KIND.KB_ARTICLE,
  id: '42',
};

// Build the inline @-mention token (e.g. "@kb:42")
const token = `@${CONTEXT_ENTITY_MARKER[ref.type]}:${ref.id}`;
// → "@kb:42"

// Enrich with display metadata for the picker store
const enriched: ContextRefWithLabel = {
  ...ref,
  label: 'How to reset a device',
  description: 'Knowledge base article',
};

// Strip label before sending on the wire
const { label, description, ...wireRef } = enriched;
```

## Extending with a New Kind

Adding a kind requires three changes — the `Record<ContextEntityKind, …>` constraints on `CONTEXT_ENTITY_MARKER` and `FETCHERS` (in `context-sources.tsx`) make omissions compile errors:

1. Add the kind to `CONTEXT_ENTITY_KIND` and its marker to `CONTEXT_ENTITY_MARKER`
2. Wire its label/icon in `MINGO_CONTEXT_ENTITY_TYPES` (`context-sources.tsx`)
3. Add its fetcher to `FETCHERS` (`context-sources.tsx`)
