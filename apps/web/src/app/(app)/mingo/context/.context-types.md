Defines the shared entity-context types of Mingo's context layer (the picker, the recent-views store and the send payload). The kinds and each kind's record type are the lib's one table of OpenFrame record types (`OPENFRAME_RECORD_KIND`, `OPENFRAME_RECORD_TYPE` in `chat-protocol`), imported from there wherever they are used.

## Key Components

- **`CONTEXT_RELAY_TYPENAME`**: partial map of the GraphQL-resolvable kinds to their Relay `__typename`, used to re-encode a raw database id as a Relay global id right before a chip's `node()` fetch
- **`ContextRef`**: the wire shape `{ type, id }` of `contextItems`, `currentView` and `recentViews`
- **`ContextRefWithLabel`**: a `ContextRef` with `label` and an optional `description`, for the picker and the store
- **`CONTEXT_ITEMS_MAX`** / **`RECENT_VIEWS_MAX`**: the limits of the spec (10 and 5)

## Usage Example

```typescript
import { OPENFRAME_RECORD_KIND, recordHref } from '@flamingo-stack/openframe-frontend-core/chat-protocol';
import type { ContextRef, ContextRefWithLabel } from './context-types';

const ref: ContextRef = { type: OPENFRAME_RECORD_KIND.KB_ARTICLE, id: '42' };

const enriched: ContextRefWithLabel = { ...ref, label: 'How to reset a device', description: 'Knowledge base article' };

// The label is display data: it is stripped before the ref goes on the wire.
const { label, description, ...wireRef } = enriched;
```

## Extending with a New Kind

1. Add the kind and its record type to the lib's `OPENFRAME_RECORD_KIND` / `OPENFRAME_RECORD_TYPE`
2. Wire its label and icon in `MINGO_CONTEXT_ENTITY_TYPES` (`context-sources.tsx`)
3. Add its fetcher to `FETCHERS` (`context-sources.tsx`); its `Record<OpenFrameRecordKind, …>` type makes a missing entry a compile error
