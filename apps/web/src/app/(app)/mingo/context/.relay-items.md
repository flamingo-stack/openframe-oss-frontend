# relay-items.tsx

Relay-backed context item provider components used by Mingo's context picker to query and paginate GraphQL data sources (Devices, Organizations, Users, Knowledge Articles/Folders, Scripts, Script Schedules, Incidents, Software, Vulnerabilities) from the app's own `/api/graphql` endpoint.

Each entity follows an idiomatic Relay cursor-pagination pattern: a `@refetchable` fragment with `@connection`, fetched via `useLazyLoadQuery` (suspends on initial load, driving the picker's Suspense skeleton) and incrementally loaded via `usePaginationFragment` (`loadNext` triggered on scroll). There's no manual cursor/`hasMore` bookkeeping — Relay's store manages the connection state automatically.

## Key Components

- **`DeviceItems`** — Lists devices filtered to `ONLINE`/`OFFLINE` statuses only (via `DEFAULT_DEVICES_LIST_STATUSES`), excluding pending/archived/deleted devices so Mingo never surfaces irrelevant machines. Uses `getDeviceName` for consistent labeling across the app.
- **`OrganizationItems`** — Lists organizations with name/category metadata.
- **`UserItems`** — Lists users via the shared `userSummaryFields_user` fragment and `toUserSummary` helper for consistent name/email display.
- Each component:
  - Decodes Relay global IDs to raw database IDs (via `decodeGlobalId`/`rawIdOf`) since backend context resolvers and `@mention` markers expect raw IDs, not Relay's base64-encoded global IDs.
  - Renders via the shared `ContextItemsList` component, wired with `selectedKeys`, `onToggle`, `atLimit`, pagination (`hasMore`, `onLoadMore`, `loadingMore`), and an `emptyLabel`.
- Additional entity item components (Knowledge Articles/Folders, Scripts, Schedules, Incidents, Software, Vulnerabilities) follow the identical fragment/query/pagination pattern (truncated in this excerpt).

## Usage Example

```typescript
import { DeviceItems, OrganizationItems, UserItems } from './relay-items';

function ContextPickerPanel({ activeEntity, query, selectedKeys, onToggle, atLimit }) {
  switch (activeEntity) {
    case 'DEVICE':
      return (
        <DeviceItems
          query={query}
          selectedKeys={selectedKeys}
          onToggle={onToggle}
          atLimit={atLimit}
        />
      );
    case 'ORGANIZATION':
      return (
        <OrganizationItems
          query={query}
          selectedKeys={selectedKeys}
          onToggle={onToggle}
          atLimit={atLimit}
        />
      );
    case 'USER':
      return (
        <UserItems
          query={query}
          selectedKeys={selectedKeys}
          onToggle={onToggle}
          atLimit={atLimit}
        />
      );
    default:
      return null;
  }
}
```

Each component must be rendered inside a `Suspense` boundary, since `useLazyLoadQuery` suspends while the initial page loads.
