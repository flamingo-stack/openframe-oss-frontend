React hook that registers an entity detail page as Mingo's "open view," keeping the AI chat context strip in sync with whatever record the user is currently viewing.

## Key Components

- **`TrackOpenViewInput`** — interface describing the tracked entity: `type` (a `ContextEntityKind`), `id`, `label`, and optional `description`.
- **`useTrackOpenView(ref, options?)`** — hook that:
  - Sets the open view in `useMingoContextStore` on mount and whenever `type`/`id`/`label`/`description` change.
  - Clears the open view on unmount (only if this entity is still the current open view, avoiding races during route transitions).
  - Accepts `null`/`undefined` to skip tracking (e.g., while data is still loading).
  - Supports a `{ loading: true }` option to mark the open view as *pending* via `setOpenViewPending`, so Mingo's UI can render a loading placeholder instead of shifting layout once data arrives.
  - Depends on primitive fields rather than object identity, so passing a new object literal each render doesn't cause unnecessary re-registration.

## Usage Example

```typescript
import { useTrackOpenView } from './use-track-open-view';

function DeviceDetailPage({ deviceId }: { deviceId: string }) {
  const { data: device, isLoading } = useDeviceQuery(deviceId);

  useTrackOpenView(
    device
      ? {
          type: 'DEVICE',
          id: device.id,
          label: getDeviceName(device) || device.id,
        }
      : null,
    { loading: isLoading },
  );

  if (isLoading) return <DeviceSkeleton />;
  return <DeviceView device={device} />;
}
```

While `isLoading` is true and no device is available, Mingo shows a loading indicator for the open view. Once `device` resolves, the hook registers it as the active open view; on navigation away, it clears (rolling into `recentViews`) unless another page has already claimed the open view slot.
