# use-track-open-view.ts

A React hook that registers the current entity detail page as the "open view" in Mingo's context store, enabling Mingo AI to track which entity the user is currently viewing and surface it in chat context.

## Key Components

- **`TrackOpenViewInput`** — interface describing the tracked entity: `type` (`ContextEntityKind`), `id`, `label`, and optional `description`.
- **`useTrackOpenView(ref, options?)`** — hook that:
  - Sets the open view in `useMingoContextStore` on mount and whenever the entity's primitive fields (`type`, `id`, `label`, `description`) change.
  - Clears the open view on unmount, rolling it into `recentViews`.
  - Marks the view as "pending" (via `setOpenViewPending`) when `{ loading: true }` is passed and no entity ref is yet available — this lets Mingo's context strip show a loading state instead of jumping when data resolves.
  - Skips tracking entirely when `ref` is `null`/`undefined` and not loading.

## Usage Example

```typescript
import { useTrackOpenView } from './use-track-open-view';
import { getDeviceName } from './device-utils';

function DeviceDetailPage({ device, isLoading }: { device?: Device; isLoading: boolean }) {
  useTrackOpenView(
    device
      ? { type: 'DEVICE', id: device.id, label: getDeviceName(device) || device.id }
      : null,
    { loading: isLoading },
  );

  if (isLoading) return <Spinner />;
  return <DeviceDetails device={device} />;
}
```

**Notes:**
- Always pass a fresh object literal for `ref`; the hook depends on primitive fields internally, so object identity changes won't cause unnecessary re-registration.
- Use the `loading` option during data fetches to prevent Mingo's context UI from appearing/moving abruptly once the entity loads.
- On unmount, the hook only clears the open view if the current entity still matches — this avoids clobbering a newer page's open view during fast route transitions.
