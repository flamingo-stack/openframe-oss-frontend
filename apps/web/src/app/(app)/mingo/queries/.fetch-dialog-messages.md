# fetch-dialog-messages.ts

Fetches paginated chat messages for a Mingo dialog via a GraphQL POST request, with automatic backward-compatibility fallback for older backends that don't recognize the `AttachmentsData` fragment.

## Key Components

- **`MessagesVariables`** - Interface defining GraphQL query variables: `dialogId`, pagination `cursor`, `limit`, `sortField`, and `sortDirection`.
- **`legacyGuide`** (module-level flag) - Tracks whether the current backend requires the legacy `GuideData` fragment instead of `AttachmentsData`. Persists across calls once set, avoiding repeated failed requests.
- **`fetchMingoDialogMessages(variables)`** - Async function that posts the dialog messages query to `/chat/graphql`. If the backend rejects the query due to an unrecognized `AttachmentsData` type, it flips `legacyGuide` to `true` and retries once using the legacy fragment via `getMingoDialogMessagesQuery`.

## Usage Example

```typescript
import { fetchMingoDialogMessages } from './fetch-dialog-messages';

const response = await fetchMingoDialogMessages({
  dialogId: 'dialog-123',
  cursor: undefined,
  limit: 20,
  sortField: 'createdAt',
  sortDirection: 'DESC',
});

if (response.data?.errors) {
  console.error('GraphQL errors:', response.data.errors);
} else {
  const messages = response.data?.data;
  console.log(messages);
}
```

**Note:** This is a temporary compatibility shim (tracked as `saas-tenant#3633`). Once all backends support `AttachmentsData`, the `legacyGuide` fallback logic and `LEGACY_GUIDE_FRAGMENT` should be removed.
