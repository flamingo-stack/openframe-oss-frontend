# fetch-dialog-messages.ts

Fetches paginated chat messages for a Mingo dialog via GraphQL, with automatic fallback handling for backend version incompatibilities around attachment/guide data schemas.

## Key Components

- **`MessagesVariables`** — Interface defining the GraphQL query variables: `dialogId`, optional pagination `cursor`, `limit`, and sort options (`sortField`, `sortDirection`).
- **`legacyGuide`** — Module-level flag tracking whether the backend requires the legacy `GuideData` GraphQL fragment instead of the newer `AttachmentsData` fragment. Persists across calls to avoid repeated failed requests.
- **`fetchMingoDialogMessages(variables)`** — Async function that posts a GraphQL query to `/chat/graphql` to retrieve dialog messages. If the backend rejects the query due to an unrecognized `AttachmentsData` type, it automatically retries once using the legacy query fragment and remembers this for future calls.

## Usage Example

```typescript
import { fetchMingoDialogMessages } from './fetch-dialog-messages';

async function loadMessages(dialogId: string) {
  const response = await fetchMingoDialogMessages({
    dialogId,
    limit: 50,
    sortField: 'createdAt',
    sortDirection: 'DESC',
  });

  if (response.data?.errors) {
    console.error('Failed to fetch messages:', response.data.errors);
    return;
  }

  return response.data?.data;
}

// Paginated fetch using a cursor
async function loadNextPage(dialogId: string, cursor: string) {
  return fetchMingoDialogMessages({
    dialogId,
    cursor,
    limit: 50,
    sortField: 'createdAt',
    sortDirection: 'DESC',
  });
}
```

## Notes

This is a temporary compatibility shim (tracked as `saas-tenant#3633`). Once all backend deployments support the `AttachmentsData` fragment, this fallback logic and the associated `LEGACY_GUIDE_FRAGMENT` in `dialogs-queries` should be removed.
