# MingoArchivePage

Next.js client page component that renders the archived chats view for the Mingo AI assistant, but only in SaaS tenant mode. In OSS tenant mode, where Mingo is unavailable, it redirects users to the dashboard instead.

## Key Components

- **`MingoArchivePage`** (default export) — Page component that conditionally renders `MingoArchiveView` or triggers a redirect based on the current app mode.
- **`isSaasTenantMode()`** — Utility (from `@/lib/app-mode`) used to detect whether the app is running in SaaS tenant mode.
- **`useAppModeRedirect`** — Hook (from `@/app/hooks/use-app-mode-redirect`) that performs the redirect to `routes.dashboard` when Mingo is not available (OSS mode).
- **`MingoArchiveView`** — The actual archive UI, rendered only when SaaS tenant mode is active.

## Usage Example

This file is a Next.js route page and is rendered automatically by the framework's file-based routing—no manual import is typically needed. It corresponds to a route such as:

```text
app/mingo/archive/page.tsx
```

Behavior by mode:

```typescript
// SaaS tenant mode:
// - isSaasTenantMode() returns true
// - useAppModeRedirect(null) performs no redirect
// - MingoArchiveView is rendered

// OSS tenant mode:
// - isSaasTenantMode() returns false
// - useAppModeRedirect(routes.dashboard) redirects to the dashboard
// - component renders null while redirecting
```

## Notes

- The `'use client'` directive marks this as a Client Component, required for using hooks like `useAppModeRedirect`.
- This pattern (feature-flagged rendering + redirect) is used across the app to gate SaaS-only features from OSS tenants. See the related repository file at [`app/hooks/use-app-mode-redirect`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/hooks/use-app-mode-redirect.ts) for redirect logic details.
