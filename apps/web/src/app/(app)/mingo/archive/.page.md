Client-side Next.js page component that renders the Mingo archived chats view, exclusively for SaaS tenant mode deployments. In OSS tenant mode, where Mingo (the AI assistant) is unavailable, it redirects users to the dashboard instead.

## Key Components

- **`MingoArchivePage`** — Default export; the page component for the Mingo chat archive route. Checks the current tenant mode and either renders the archive view or triggers a redirect.
- **`isSaasTenantMode()`** — Utility (from `@/lib/app-mode`) that determines whether the app is running in SaaS or OSS tenant mode.
- **`useAppModeRedirect()`** — Hook (from `@/app/hooks/use-app-mode-redirect`) that conditionally redirects to a given route based on app mode.
- **`MingoArchiveView`** — The actual archive UI component rendered only when in SaaS mode.

## Usage Example

```typescript
// This file is a Next.js route page and is rendered automatically
// when navigating to the Mingo archive route in SaaS tenant mode.

// Behavior summary:
// - SaaS tenant mode: renders <MingoArchiveView />
// - OSS tenant mode: redirects to routes.dashboard, renders nothing

import { isSaasTenantMode } from '@/lib/app-mode';
import { routes } from '@/lib/routes';
import { useAppModeRedirect } from '@/app/hooks/use-app-mode-redirect';

function ExampleGuardedPage() {
  const isSaas = isSaasTenantMode();
  useAppModeRedirect(isSaas ? null : routes.dashboard);

  if (!isSaas) return null;
  return <div>SaaS-only content</div>;
}
```

## Notes

This pattern—checking `isSaasTenantMode()` and calling `useAppModeRedirect` with a fallback route—is used to gate SaaS-exclusive features (like Mingo, the AI assistant) so that OSS tenants are seamlessly redirected to the dashboard instead of encountering a broken or irrelevant page.
