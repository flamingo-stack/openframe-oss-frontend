Manages real-time NATS JetStream subscriptions for Mingo AI chat dialogs, handling streaming message chunks, tool execution state, and approval workflows in the OpenFrame frontend.

## Key Components

### `useMingoRealtimeSubscription(activeDialogId, options)`
Primary hook for managing multi-dialog subscription state. Tracks which dialogs are subscribed, their connection status, and catch-up state. Automatically subscribes the active dialog on mount.

**Returns:** `subscribeToDialog`, `unsubscribeFromDialog`, `getSubscriptionState`, `subscribedDialogs`, `connectionState`, `onConnectionChange`

### `useDialogChunkProcessor(dialogId, options)`
Internal hook that wires real-time chunk callbacks to the `useMingoMessagesStore`. Handles the full message lifecycle:

- **`ensureAssistantMessage`** — Creates or rehydrates an assistant message bubble before streaming begins
- **`addErrorMessage`** — Inserts or replaces an empty assistant bubble with an error message
- **`realtimeCallbacks`** — Event handlers passed to the chunk processor: `onStreamStart`, `onStreamEnd`, `onSegmentsUpdate`, `onError`, `onAgentBusy`, `onTokenUsage`, `onApprovalResolved`, `onToolExecuted`

### `isInProgress(segments)`
Utility that determines whether an assistant message is still actively executing — checks for running tool calls, pending approval requests, or incomplete approval batches.

## Usage Example

```typescript
import { useMingoRealtimeSubscription } from './use-mingo-realtime-subscription';

function MingoChat({ dialogId }: { dialogId: string }) {
  const { subscribeToDialog, connectionState, getSubscriptionState } =
    useMingoRealtimeSubscription(dialogId, {
      onChunkReceived: (id, chunk, messageType) => {
        console.log('Chunk received for dialog', id, chunk);
      },
    });

  const state = getSubscriptionState(dialogId);
  // state.isSubscribed, state.isConnected, state.hasCaughtUp

  return <div>Connection: {connectionState}</div>;
}
```

## Notes

- Uses `CHAT_CHUNKS` JetStream stream and `admin-message` topic
- Compaction events (segment updates with `isCompacting: true`) deliberately skip typing state changes to prevent composer unlock between stream windows
- Approved tool commands execute outside the `message_start/message_end` window; `onAgentBusy` keeps the composer locked during execution
