React hook managing Mingo AI admin chat dialog lifecycle — creating dialogs, sending messages, and tracking state via TanStack Query mutations.

## Key Components

| Export | Type | Description |
|---|---|---|
| `useMingoDialog` | Hook | Primary hook for managing Mingo admin chat dialogs |
| `createDialog` | Method | Creates a new ADMIN-type dialog via `/chat/api/v1/dialogs` |
| `sendMessage` | Method | Sends a message to an active dialog, auto-creating one if needed |
| `resetDialog` | Method | Clears dialog state and resets both mutations |
| `getActiveDialogId` | Internal | Resolves the active dialog ID from state, ref, or override |

## Usage Example

```typescript
import { useMingoDialog } from './use-mingo-dialog';

function MingoChat() {
  const {
    currentDialogId,
    isCreatingDialog,
    isSendingMessage,
    hasDialog,
    sendMessage,
    resetDialog,
  } = useMingoDialog();

  const handleSend = async (text: string) => {
    // Automatically creates a dialog if none exists
    const success = await sendMessage(text);
    if (!success) console.warn('Message failed to send');
  };

  const handleNewChat = () => resetDialog();

  return (
    <div>
      <button onClick={() => handleSend('Hello, Mingo!')} disabled={isSendingMessage}>
        {isSendingMessage ? 'Sending...' : 'Send'}
      </button>
      {hasDialog && (
        <button onClick={handleNewChat}>New Chat</button>
      )}
    </div>
  );
}
```

## Notes

- Dialog ID is tracked in both React state (`useState`) and a `useRef` to handle async race conditions where state may not yet be updated.
- `sendMessage` validates non-empty content before proceeding and shows a destructive toast on empty input, API errors, or creation failure.
- Dialog creation is **idempotent during pending state** — calling `createDialog` while a request is in-flight returns the current dialog ID.
- Successful dialog creation invalidates the `mingo-dialogs` query cache.
