## use-mingo-dialog-selection.ts

React hook that manages the full lifecycle of a selected Mingo chat dialog — fetching dialog metadata, paginated message history, merging realtime stream updates, and handling approval/rejection of agent-proposed commands.

## Key Components

- **`MINGO_DIALOG_NOT_FOUND`** — Sentinel error message string thrown when a dialog id can't be resolved (deleted, inaccessible, or invalid). Consumers match on this string rather than displaying it directly.
- **`isAwaitingGeneratedTitle(dialog)`** — Utility predicate determining whether a dialog's title is still being asynchronously generated by the backend, bounded by a max age window (`TITLE_POLL_MAX_DIALOG_AGE_MS`).
- **`useMingoDialogSelection()`** — Primary hook exposing:
  - `dialogQuery`: a `useQuery` fetching dialog metadata via GraphQL, with conditional polling for `STREAMING` state, a "suspicious busy" composer-lock watchdog, and title-generation polling.
  - `messagesQuery`: a `useInfiniteQuery` fetching paginated historical messages, normalizing ask-intro aliases and folding pending-approval envelopes.
  - `handleApprove(requestId)` / `handleReject(requestId)`: optimistic mutation handlers that flip local approval state immediately (before network resolution) to avoid race conditions with incoming stream chunks, lock the composer during execution, and release the lock on failure (respecting prior lock ownership).
  - Internal state synced with `useMingoMessagesStore` (zustand) for messages, typing/streaming state, pagination, and approval status, plus toast-based error reporting via `useToast`.

## Usage Example

```typescript
import { useMingoDialogSelection } from './use-mingo-dialog-selection';

function MingoDialogPanel() {
  const {
    dialogQuery,
    messagesQuery,
    handleApprove,
    handleReject,
  } = useMingoDialogSelection();

  if (dialogQuery.isLoading) return <LoadingSpinner />;
  if (dialogQuery.error?.message === MINGO_DIALOG_NOT_FOUND) {
    return <EmptyState message="This chat no longer exists." />;
  }

  return (
    <div>
      <DialogHeader title={dialogQuery.data?.title ?? 'New Chat'} />
      <MessageList
        pages={messagesQuery.data?.pages}
        onApprove={handleApprove}
        onReject={handleReject}
      />
    </div>
  );
}
```

Consumers should rely on the returned react-query objects (`dialogQuery`, `messagesQuery`) for loading/error states, and call `handleApprove`/`handleReject` with the request id extracted from an approval-type message to resolve pending agent commands.
