Manages the selection and state of a Mingo AI dialog session, coordinating message history loading, real-time streaming reconciliation, and approval/rejection workflows for AI-generated commands.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `useMingoDialogSelection` | Hook | Primary hook orchestrating dialog selection, message pagination, streaming state, and command approvals |

### Internal Logic

- **`handleApprove`** — Optimistically updates approval status, locks the composer, and fires the approval mutation with rollback on failure
- **`handleReject`** — Mirrors `handleApprove` for rejections; locks composer awaiting agent acknowledgment
- **`dialogQuery`** — Polls the active dialog's `streamState` every 15s during streaming or suspicious-busy states
- **`messagesQuery`** — Infinite query fetching paginated `ADMIN`-type chat messages in descending order
- **Self-heal watchdog** — Detects stuck `typing` locks (approved/rejected commands with no guaranteed `MESSAGE_END`) and releases them on a server-side `IDLE` signal fetched after the busy assertion
- **`streamingExemptId`** — Gates the history merge exemption so stale streaming entries cannot block their own replacement

## Usage Example

```typescript
import { useMingoDialogSelection } from './use-mingo-dialog-selection';

function MingoDialogPanel() {
  const {
    handleApprove,
    handleReject,
    dialogQuery,
    messagesQuery,
    chronologicalMessages,
  } = useMingoDialogSelection();

  return (
    <div>
      {chronologicalMessages.map(msg => (
        <MessageBubble
          key={msg.id}
          message={msg}
          onApprove={handleApprove}
          onReject={handleReject}
        />
      ))}
    </div>
  );
}
```

## Notes

- Optimistic approval flips happen **before** the network round-trip to prevent streaming continuation chunks from re-adopting a pending approval card
- The `suspiciousBusyRef` flag (typing + no open stream) keeps the dialog polling alive so stuck composer locks self-heal via a fresh server `IDLE` fetch
- Message pages are filtered to `CHAT_TYPE.ADMIN` only before being stored
