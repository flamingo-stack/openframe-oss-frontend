Mingo on the core lib's chat engine (`useChatEngine`): the engine's configuration for OpenFrame's operator chat. The engine owns the dialog list, the selection, the history, the live tail, sends, approvals, the thread, Display, the faces of history rows and its own refresh (the list's first page, the open dialog's record and a locked composer, read again on a timer); this file names the transport (the JetStream tail of `admin-message` and the ai-agent's commands), the history (the lib's GraphQL readers over `postMingoGraphql`), the module-level thread store, the slash-command catalog, the link a dialog is copied as, and Compact.

## Key Components

### `useMingoUnifiedChatState(): MingoUnifiedChat`
Called once per session by `MingoChatRunner`. Returns:
- `state: UnifiedChatState`, the engine's state as `useChatEngine` returned it (the dock hands it to the panel through `ChatEngineProvider`)
- `dialogStatusOf(dialog)`, the working / approval glyph at the end of a list row
- `dialogNotFound`, the open dialog's record answered that it does not exist for this viewer
- `dialogCreatedAt`, when the open dialog was created

### `postMingoGraphql`, `mingoDialogs`
How the lib's GraphQL readers post to `/chat/graphql`, and Mingo's dialog list and dialogs over it. Every dialog node an answer carries is noted for the list's rows (`mingo-dialog-rows-store`).

### `snapshotSendContext(options)`
The page context folded into every send: the page, the open view, recent views, and the picker's selection.

## What stays the app's
The page context and analytics of a send, the row status, the link a dialog is copied as (on the tenant host), Compact (reported by the compaction watchers), and the toasts of the dialog commands.
