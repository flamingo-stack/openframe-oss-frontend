# dialog-row-status.ts

Computes and synchronizes the "status" badge shown on a chat dialog row in the Mingo dialog list (e.g., working/streaming or awaiting approval), reconciling the server-fetched list state with the live state of the currently open chat so the UI doesn't flicker or wait for the next poll.

## Key Components

- **`DialogRowState`** — Interface describing a row's derived status: whether it's streaming, awaiting approval, and the pending approval request ID.
- **`MingoDialogsPage`** — Shape of one paginated page from the dialog list query.
- **`serverRowState(node)`** — Derives `DialogRowState` from a dialog node as last seen by the list query (`streamState`, `pendingApproval`).
- **`liveRowState(phase, messages)`** — Derives `DialogRowState` from the currently open chat's live stream phase and message segments, scanning for unresolved `approval_request`/`approval_batch` segments.
- **`dialogRowStatus(state)`** — Reduces a `DialogRowState` to the final badge value (`'working'`, `'approval'`, or `undefined`). Streaming takes priority over approval.
- **`withLiveRowState(data, dialogId, live)`** — Patches the open chat's row within cached `InfiniteData` pages with its live state, preserving referential equality for unchanged pages (important for React Query cache updates and render optimization).

## Usage Example

```typescript
import {
  serverRowState,
  liveRowState,
  dialogRowStatus,
  withLiveRowState,
} from './dialog-row-status';

// Status for a row as returned by the list query
const status = dialogRowStatus(serverRowState(dialogNode));

// Status for the currently open chat, derived from its live stream
const liveStatus = dialogRowStatus(liveRowState(chatPhase, chatMessages));

// Patch the dialog list cache so the open chat's row reflects live state
queryClient.setQueryData(mingoDialogQueryKeys.list(), (data) =>
  withLiveRowState(data, activeDialogId, liveRowState(chatPhase, chatMessages)),
);
```

## Notes

- `pendingApprovalIn` treats a batch/request as pending only if no other copy of it has already been resolved, preventing stale "awaiting approval" states when duplicate segments exist in the thread.
- `withLiveRowState` returns the original `data` reference untouched when nothing changed, avoiding unnecessary re-renders downstream.
