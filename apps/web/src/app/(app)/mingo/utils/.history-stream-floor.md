## Purpose

Computes the JetStream resume point for a dialog's live message consumer, based on previously-loaded history pages. It determines whether the consumer should resume after a known sequence number, replay everything from the start, or just tail new messages live.

## Key Components

- **`historyStreamFloor(pages)`** — Main exported function. Takes an array of `MessagePage` objects (or `undefined`) and returns:
  - A positive `number`: the highest `lastChunkStreamSeq` stamp found across assistant messages, meaning the consumer should resume *after* that sequence.
  - `0`: no stamped assistant rows exist and no assistant row is present at all — replay everything the stream retains (covers the case where only a user message exists and the first answer is still streaming).
  - `null`: assistant rows exist but none carry a stamp (e.g., persisted by an ai-agent that didn't stamp them) — history already covers those turns, so start the consumer live to avoid duplicating rendered content.

This logic relies on `maxPersistedStreamSeq` (from `@flamingo-stack/openframe-frontend-core`) to extract the highest stamped sequence, and checks message ownership via `OWNER_TYPE.ASSISTANT`.

## Usage Example

```typescript
import { historyStreamFloor } from './history-stream-floor';
import type { MessagePage } from '../types';

const pages: MessagePage[] = await loadDialogHistory(dialogId);

const floor = historyStreamFloor(pages);

if (floor === null) {
  // Start consumer as a live tail (no replay)
  subscribeToStream({ dialogId, startSeq: 'live' });
} else {
  // Resume after `floor` (0 means replay from the very start)
  subscribeToStream({ dialogId, startSeq: floor });
}
```

**Note:** This function is pure and synchronous — it only inspects already-fetched history pages and performs no I/O itself.
