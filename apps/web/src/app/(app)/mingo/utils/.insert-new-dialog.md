Manages optimistic cache updates for newly created Mingo dialogs, ensuring they appear instantly in chat lists before the server's list query catches up, and keeps actively-used dialogs sorted to the top.

## Key Components

- **`NewDialogOwner`** — Interface describing the admin user who owns a newly created dialog.
- **`insertNewDialog(queryClient, dialogId, owner, options)`** — Injects a freshly created dialog node at the top of every cached, unsearched chat list via `QueryClient`, and registers it in an internal `createdDialogs` map so it survives until the server's own list includes it.
- **`raiseDialog(queryClient, dialogId, now)`** — Moves an existing dialog to the top of any cached list that contains it, updating `lastActivityAt`, used when the user sends a message in that chat.
- **`keepCreatedDialogs(page, now)`** — Called when processing a fetched list page; re-inserts any recently created dialogs the server hasn't returned yet (within the `HOLD_MS` 60-second window), and prunes entries that are stale or already returned.
- **`forgetCreatedDialogs()`** — Clears the internal held-dialogs map, intended for test cleanup or sign-out.

## Usage Example

```typescript
import { useQueryClient } from '@tanstack/react-query';
import { insertNewDialog, raiseDialog, keepCreatedDialogs } from './insert-new-dialog';

const queryClient = useQueryClient();

// After successfully creating a dialog on the server
const dialogId = await createDialog();
insertNewDialog(queryClient, dialogId, currentAdminUser, { title: 'New Chat' });

// After the user sends a message in an existing dialog
raiseDialog(queryClient, dialogId);

// When normalizing a fetched list page before caching it
const normalizedPage = keepCreatedDialogs(fetchedPage);

// In test teardown
forgetCreatedDialogs();
```

Note: `insertNewDialog` and `raiseDialog` skip search-filtered lists and lists that already contain (or don't contain, respectively) the target dialog, avoiding redundant cache writes.
