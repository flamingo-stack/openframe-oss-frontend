# page.tsx

Next.js client page component that renders a single Mingo AI chat conversation, handling dialog ID normalization, SaaS-only access control, and redirect logic for canonical chat URLs.

## Key Components

- **`MingoChatPage`** (default export) — Page component that:
  - Checks if the app is running in SaaS tenant mode via `isSaasTenantMode()` (Mingo is unavailable in OSS mode)
  - Reads the `id` query parameter to determine which conversation to load
  - Detects the special "What to ask Mingo?" entry route via `isMingoWhatToAsk()`
  - Normalizes legacy Relay global IDs to raw IDs using `normalizeMingoDialogId()`
  - Computes a redirect `target` route when the URL isn't canonical, delegating the actual redirect to `useAppModeRedirect`
  - Renders `MingoChatView` with the resolved `dialogId` once no redirect is needed

## Redirect Logic

| Condition | Redirect Target |
|---|---|
| Not in SaaS tenant mode | `routes.dashboard` |
| No dialog ID and not "what to ask" | `routes.mingo.home` |
| Dialog ID present but needs normalization | `routes.mingo.chat(dialogId)` |
| Otherwise | No redirect — render chat view |

## Usage Example

This page is wired into the Next.js App Router and is not invoked directly. It responds to URL patterns such as:

```typescript
// Canonical chat conversation
// /mingo?id=<normalized-dialog-id>

// New chat entry point
// /mingo?whatToAsk=true

// Mingo home (no id)
// /mingo
```

Consumers only need to navigate to these routes, e.g.:

```typescript
import { routes } from '@/lib/routes';
import { useRouter } from 'next/navigation';

function OpenMingoChatButton({ dialogId }: { dialogId: string }) {
  const router = useRouter();
  return (
    <button onClick={() => router.push(routes.mingo.chat(dialogId))}>
      Open Chat
    </button>
  );
}
```
