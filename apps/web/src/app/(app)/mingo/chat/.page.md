# page.tsx

Next.js page component rendering a single Mingo chat conversation, handling route normalization and SaaS-only access control.

## Key Components

- **`MingoChatPage`** (default export) — Client component that resolves the current chat dialog from URL query parameters, performs redirects for invalid or legacy states, and renders the `MingoChatView` for a valid conversation.

### Behavior

- Reads `id` and "what to ask" state from the URL query string via `useSearchParams`.
- Normalizes legacy Relay global IDs to raw dialog IDs using `normalizeMingoDialogId`.
- Determines a redirect `target` based on app mode and URL state:
  - OSS tenant (non-SaaS mode) → redirects to `routes.dashboard` (Mingo is unavailable).
  - SaaS mode with no dialog id and not "what to ask" → redirects to `routes.mingo.home`.
  - SaaS mode with a legacy global id → redirects to the canonical `routes.mingo.chat(dialogId)` URL.
  - Otherwise renders the chat view directly.
- Applies the redirect via `useAppModeRedirect(target)` and renders `null` while redirecting.

## Usage Example

This page is rendered automatically by Next.js App Router for its route segment; it is not typically imported directly. Example of the expected URL patterns it handles:

```typescript
// New chat / "What to ask Mingo?" flow
// /mingo/chat?whatToAsk=true

// Existing conversation by raw dialog id
// /mingo/chat?id=abc123

// Legacy Relay global id (will be normalized and redirected)
// /mingo/chat?id=TWluZ29EaWFsb2c6YWJjMTIz
```

Internally, it composes two project utilities to decide what to render:

```typescript
import { useAppModeRedirect } from '@/app/hooks/use-app-mode-redirect';
import { isSaasTenantMode } from '@/lib/app-mode';

const mingo = isSaasTenantMode();
const target = mingo ? null : routes.dashboard;
useAppModeRedirect(target);
```

## Notes

- Depends on `MingoChatView` for actual chat rendering ([`mingo-chat-view.tsx`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/mingo/chat/mingo-chat-view.tsx)).
- Relies on `routes` config from `@/lib/routes` for all navigation targets, keeping route definitions centralized.
