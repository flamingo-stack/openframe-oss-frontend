# mingo-chat-view.tsx

Renders a single Mingo conversation page within the Mingo-first shell. This component itself draws no chat UI directly — instead, it publishes a DOM node that the composer dock's shared `EmbeddableChat` portals its header and thread into, allowing the composer and its draft to persist across navigation. It owns loading, error, not-found, and crash states that the embedded chat cannot represent on its own.

## Key Components

- **`MingoChatView({ dialogId })`** — Top-level page component. Resolves the chat session via `useMingoChatSurface`, tracks selection status via `useChatPageSelection`, and renders one of several states:
  - Session error → retry UI (`ChatExclamationIcon`)
  - `not-found` → "Conversation not available" with a link back to Mingo home
  - `failed` → retry (refetches dialog/messages queries) or return home
  - Otherwise → `ChatThreadSlot` once loading completes
- **`ChatThreadSlot({ loaded })`** — Publishes the portal target node via `useChatPageNodeStore`, marks the thread as "on screen" (for popups/auto-read), and gates when the dock's chat is allowed to portal in (`threadReady`) based on `chatMounted` and `loaded`. Shows `ChatThreadSkeleton` until ready.
- **`ChatThreadSkeleton()`** — Skeleton matching the real chat's geometry: a 56px header row plus a loading `ChatMessageList`, so nothing shifts layout once the real chat mounts.
- **`ChatPageState({ icon, title, description, action })`** — Generic centered empty/error state wrapper using `NoData`.

## Usage Example

```typescript
import { MingoChatView } from './mingo-chat-view';

// Rendered by the Mingo page route, driven by the `?id` query param
export default function MingoPage({ searchParams }: { searchParams: { id?: string } }) {
  return <MingoChatView dialogId={searchParams.id ?? null} />;
}
```

`dialogId` of `null` represents a not-yet-created chat (e.g., "What to ask Mingo?"), while a string ID resolves an existing conversation, including archived (read-only) dialogs.
