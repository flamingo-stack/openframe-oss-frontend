# mingo-chat-view.tsx

Renders a single Mingo conversation as a page within the Mingo-first shell. Rather than drawing its own chat UI, this page publishes a DOM node that the session's shared `EmbeddableChat` (living in the composer dock) portals its header and thread into — preserving the composer and draft text across navigation. It owns UI states the chat component itself can't express: not-found, load failure, and crashed sessions.

## Key Components

- **`MingoChatView`** — Top-level component taking a `dialogId` (or `null` for a not-yet-created chat). Uses `useMingoChatSurface` to keep the chat session alive and `useChatPageSelection` to resolve the dialog's load status (`'not-found' | 'failed' | 'ready'`). Renders error/empty states via `ChatPageState`, or delegates to `ChatThreadSlot` once ready.
- **`ChatThreadSlot`** — Publishes the portal target node via `useChatPageNodeStore().setNode` and coordinates readiness: shows `ChatThreadSkeleton` until both the dock's chat has mounted and the conversation data has `loaded`, then flips `threadReady` (via a `useLayoutEffect` for single-paint handoff) to let the real thread portal in. Once shown, it stays shown.
- **`ChatThreadSkeleton`** — Placeholder matching the real chat's geometry (56px header row + message list skeleton) so nothing shifts layout when the actual content mounts.
- **`ChatPageState`** — Generic centered empty/error state wrapper using `NoData`, for unavailable, not-found, or failed-to-load scenarios.

## Usage Example

```tsx
import { MingoChatView } from '@/app/components/mingo-shell/mingo-chat-view';

// Rendered per conversation route, e.g. /mingo?id=<dialogId>
export default function MingoChatPage({ searchParams }: { searchParams: { id?: string } }) {
  return <MingoChatView dialogId={searchParams.id ?? null} />;
}
```

Passing `dialogId={null}` represents a conversation not yet created — the page that will host the next chat Mingo creates. The component itself requires no additional props or configuration; it reads chat state from shared providers (`useMingoChatSurface`, `useChatPageNodeStore`) and React Query caches (`mingoDialogQueryKeys`).
