## Purpose

A React hook that synchronizes the Mingo chat page's `?id` URL parameter with the active chat session's selected dialog, handling bidirectional sync (URL → selection, selection → URL) and surfacing a status to drive page rendering.

## Key Components

- **`ChatPageStatus`** — Union type (`'starting' | 'ready' | 'not-found' | 'failed'`) representing the page's rendering state for the current `?id`.
- **`useChatPageSelection(dialogId, chat)`** — Main hook that:
  - Writes `dialogId` into the session's selection once per id (via `selectDialog`), without re-applying on later selection changes.
  - Watches the session's `activeDialogId` after this dialog has "landed" (became selected), and redirects the page (`router.replace`) when the selection moves to another dialog or is cleared (back to Mingo home).
  - Latches a `not-found` state when `dialogError` indicates `MINGO_DIALOG_NOT_FOUND` for the currently active dialog, so the error renders for exactly one frame before the session drops the selection.
  - Returns the current `ChatPageStatus` for the page to render accordingly.

## Usage Example

```typescript
import { useChatPageSelection } from './use-chat-page-selection';
import { useSearchParams } from 'next/navigation';

function MingoChatPage() {
  const searchParams = useSearchParams();
  const dialogId = searchParams.get('id');
  const chat = useMingoChatState(); // MingoChatState | null

  const status = useChatPageSelection(dialogId, chat);

  switch (status) {
    case 'starting':
      return <ChatSkeleton />;
    case 'ready':
      return <DockedChat dialogId={dialogId} />;
    case 'not-found':
      return <ChatNotFoundToast />;
    case 'failed':
      return <ChatLoadError dialogId={dialogId} />;
  }
}
```

**Notes:**
- Pass `dialogId={null}` for the "new chat" composer state — no selection is written, and landing occurs once `activeDialogId` becomes `null`.
- The hook performs navigation side effects (`router.replace`) internally; the consuming page should not duplicate redirect logic.
