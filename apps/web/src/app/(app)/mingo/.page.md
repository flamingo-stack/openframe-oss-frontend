Root page component that renders Mingo's home experience for SaaS tenants, acting as the entry point for a new chat session or the Manhattan v2 "Start Work" view, while redirecting OSS tenants to the dashboard since Mingo is a SaaS-only feature.

## Key Components

- **`MingoHomePage`** — Default-exported page component that:
  - Checks tenant mode via `isSaasTenantMode()` to determine if Mingo is available.
  - Uses `useManhattanDock()` to detect whether the Manhattan v2 shell is active.
  - Calls `useAppModeRedirect()` to redirect OSS tenants to `routes.dashboard` (passes `null` for SaaS tenants, meaning no redirect).
  - Renders `null` while redirecting (non-SaaS mode).
  - Renders `ManhattanStartWork` when inside the Manhattan shell, otherwise renders `MingoNewChat`.

## Usage Example

This is a Next.js route page (`page.tsx`), rendered automatically by the framework for its route segment—it isn't imported directly elsewhere:

```typescript
// app/(some-route)/page.tsx
// Next.js automatically renders this as the page for its route.
// No manual import or invocation is required.

export default function MingoHomePage() {
  // ...component logic
}
```

Conditional UI logic it encapsulates:

```typescript
const mingo = isSaasTenantMode();      // true only for SaaS tenants
const manhattan = useManhattanDock();  // true when Manhattan v2 shell is active

// OSS tenants are redirected to the dashboard via useAppModeRedirect
// SaaS tenants see either:
//   - ManhattanStartWork (inside Manhattan shell)
//   - MingoNewChat (default new chat experience)
```

Related modules referenced: `ManhattanStartWork` and `MingoNewChat` (in `./home/`), `useManhattanDock` context, `useAppModeRedirect` hook, and app mode/routing utilities from `@/lib/app-mode` and `@/lib/routes`.
