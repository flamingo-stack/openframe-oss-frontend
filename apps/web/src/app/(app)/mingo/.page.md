Next.js page component that renders Mingo's home experience for SaaS tenants, with conditional UI based on whether the Manhattan v2 shell is active, and redirects OSS tenants to the dashboard.

## Key Components

- **`MingoHomePage`** (default export): Page component that:
  - Checks tenant mode via `isSaasTenantMode()` to determine if Mingo (AI chat assistant) is available.
  - Uses `useManhattanDock()` to detect if the app is running inside the Manhattan v2 shell.
  - Calls `useAppModeRedirect()` to redirect non-SaaS (OSS) tenants to `routes.dashboard`, since OSS tenants have no Mingo feature.
  - Conditionally renders either `ManhattanStartWork` (when inside the Manhattan shell) or `MingoNewChat` (standard new-chat experience) for SaaS tenants.
  - Returns `null` while/if redirecting non-SaaS tenants, avoiding a flash of Mingo-specific content.

## Usage Example

This is a Next.js App Router page, so it's automatically wired to its route and requires no manual invocation:

```typescript
// Rendered automatically by the Next.js router for the corresponding route segment.
// No direct import/usage needed elsewhere in the codebase.

// Internal behavior summary:
// - SaaS tenant + Manhattan shell -> <ManhattanStartWork />
// - SaaS tenant + legacy shell    -> <MingoNewChat />
// - OSS tenant                   -> redirected to routes.dashboard
```

**Dependencies:**
- `useManhattanDock` from the Manhattan shell dock context for shell-mode detection.
- `useAppModeRedirect` hook for conditional client-side redirects.
- `isSaasTenantMode` from `@/lib/app-mode` to distinguish SaaS vs. OSS deployments.
- `routes` from `@/lib/routes` for centralized route definitions.
