Streaming skeleton component for the `/worktime` route, rendering a placeholder layout that matches the real `WorktimeView` while its data is loading — including disabled header actions, search/date-range input skeletons, and the full `WorkTimeTableSkeleton`.

## Key Components

- **`WorktimePageSkeleton`** — Primary export; a client-side page-level skeleton component that mirrors the `WorktimeView` structure.
- **`ACTIONS`** — Static array of disabled `PageActionButton` configs used to hold space for the "Add Work Time" button during loading.
- **`WorkTimeTableSkeleton`** — Reused shared skeleton from `@/app/components/shared/work-time-table`, rendered with `showEmployee` and `showCustomer` props to match the full worktime table layout.

## Usage Example

Typically registered as the `loading.tsx` or a `Suspense` fallback for the `/worktime` route:

```typescript
// app/worktime/loading.tsx
export { WorktimePageSkeleton as default } from '@/app/components/shared/worktime-page-skeleton';
```

Or used directly in a `Suspense` boundary:

```typescript
import { Suspense } from 'react';
import { WorktimePageSkeleton } from '@/app/components/worktime/worktime-page-skeleton';
import { WorktimeView } from './worktime-view';

export default function WorktimePage() {
  return (
    <Suspense fallback={<WorktimePageSkeleton />}>
      <WorktimeView />
    </Suspense>
  );
}
```

## Notes

- The search input skeleton (`md:flex-1`) and date-range picker skeleton (`md:w-[276px]`) are sized to exactly match the real filter controls, preventing layout shift on hydration.
- The `WorkTimeTableSkeleton` is rendered with both `showEmployee` and `showCustomer` enabled, so the skeleton column count matches the full worktime view.
