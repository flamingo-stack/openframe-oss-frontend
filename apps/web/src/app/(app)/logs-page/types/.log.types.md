Defines TypeScript interfaces for the log management domain, covering log entry structure, graph-edge wrapping, filter options, and filter input for querying logs.

## Key Components

| Interface | Description |
|---|---|
| `LogEntry` | Core log record with severity levels, device/org context, and optional metadata |
| `LogEdge` | GraphQL-style edge wrapper around a `LogEntry` node |
| `LogFilters` | Available filter options (tool types, event types, severities, organizations) |
| `LogFilterInput` | Input shape for querying/filtering logs with optional timestamp range bounds |

### `LogEntry` Severity Levels

```typescript
'DEBUG' | 'INFO' | 'WARNING' | 'ERROR' | 'CRITICAL'
```

## Usage Example

```typescript
import type { LogEntry, LogFilterInput } from './log.types';

// Constructing a log entry
const entry: LogEntry = {
  toolEventId: 'evt_abc123',
  eventType: 'agent.task.completed',
  ingestDay: '2024-01-15',
  toolType: 'mingo-ai',
  severity: 'INFO',
  summary: 'Task completed successfully',
  timestamp: '2024-01-15T10:30:00Z',
  hostname: 'workstation-01',
  organizationName: 'Acme Corp',
};

// Building a filter input with timestamp range
const filters: LogFilterInput = {
  severities: ['ERROR', 'CRITICAL'],
  toolTypes: ['mingo-ai'],
  organizationIds: ['org_xyz'],
  timestampFrom: '2024-01-01T00:00:00Z',
  timestampTo: '2024-01-31T23:59:59Z',
};
```

## Notes

- `device` is typed as `Partial<Device>` to accommodate backend responses that may return incomplete device objects
- `timestampFrom` / `timestampTo` are inclusive UTC ISO-8601 bounds, as noted in JSDoc
- `LogEdge` follows the GraphQL connection pattern — useful when consuming paginated log queries
