# log.types.ts

TypeScript type definitions for log entries and related filtering structures used across the logs feature, bridging legacy raw-POST data fetching paths with the generated GraphQL/Relay shapes.

## Key Components

- **`LogEntry`** — Core log record interface extending `CopyableLogDetails` (generated copy payload shape). Includes ingestion metadata (`ingestDay`, `userId`, `deviceId`, `summary`, `metadata`), denormalized device/organization fields from the backend (`hostname`, `nickname`, `organizationName`, `organizationId`), and a transformed `device` object following the `PartialNamedDevice` pattern.
- **`LogEdge`** — Minimal edge wrapper (`{ node: LogEntry }`) used for list/pagination rendering of log entries.
- **`LogFilters`** — Describes available filter options surfaced in the UI: `toolTypes`, `eventTypes`, `severities`, and `organizations` (id/name pairs).
- **`LogFilterInput`** — Input shape for querying/filtering logs, supporting `severities`, `toolTypes`, `organizationIds`, `deviceId`, `userId`, and an inclusive timestamp range (`timestampFrom` / `timestampTo` as `Instant`).

## Usage Example

```typescript
import type { LogEntry, LogFilterInput, LogFilters } from './log.types';

function buildFilterInput(filters: LogFilters): LogFilterInput {
  return {
    severities: filters.severities,
    toolTypes: filters.toolTypes,
    organizationIds: filters.organizations.map((org) => org.id),
  };
}

function renderLogSummary(log: LogEntry): string {
  const deviceLabel = log.nickname ?? log.hostname ?? 'Unknown device';
  return `[${log.ingestDay}] ${deviceLabel}: ${log.summary}`;
}
```

**Notes:**
- `LogEntry` intentionally duplicates some fields by hand because `use-logs.ts` and `use-log-details.ts` still use raw-POST data fetching rather than Relay-generated queries; once migrated, these restated fields can be removed in favor of the generated shape.
- `nickname` is explicitly nullable (`string | null`) to distinguish "no nickname set at ingest time" from "field not present."
