# log-drawer-details.tsx

Renders the full log details block inside the "Log Details" drawer, lazily fetching the complete log payload (via GraphQL/Relay) when the drawer opens, with loading skeletons and error-boundary fallback to the row summary.

## Key Components

- **`LogDrawerDetails`** — Public component. Takes a `log` fragment reference and a `fallback` string (row summary). Extracts the composite key (`toolEventId`, `ingestDay`, `toolType`, `eventType`, `timestamp`) via `useFragment` and renders the details content inside an error boundary keyed by log identity.
- **`LogDrawerDetailsContent`** — Wraps the data-reading component in a `LoadingSuspense` boundary with its own loading label.
- **`LogDrawerDetailsContentReader`** — Checks `useLoadingScope()`; if inside a loading scope (parent fallback or outer loading state), renders a skeleton instead of issuing a network read.
- **`LogDrawerDetailsContentLive`** — Executes `useLazyLoadQuery` against `logDrawerDetailsQuery` and renders formatted log text, or the `fallback` if no log is returned.
- **`LogDrawerDetailsText`** — Renders either a `TextLineSkeleton` (while loading/undefined) or the final formatted, copy-ready text.
- **`LogDrawerDetailsErrorBoundary`** — Class-based error boundary that catches render errors, shows the `fallback`, and reports errors via a `toast` notification (through `onError`).
- **`logDrawerDetailsFragment`** / **`logDrawerDetailsQuery`** — GraphQL definitions for the composite log key and the full log details fetch.

## Usage Example

```typescript
import { LogDrawerDetails } from './log-drawer-details';
import type { logDrawerDetails_log$key } from '@/__generated__/logDrawerDetails_log.graphql';

function LogDrawer({ logRef, rowSummary }: { logRef: logDrawerDetails_log$key; rowSummary: string }) {
  return (
    <div className="log-drawer-content">
      <h3>Log Details</h3>
      <LogDrawerDetails log={logRef} fallback={rowSummary} />
    </div>
  );
}
```

The component is designed to be mounted when a drawer opens; it remounts its error boundary per unique log (via the `key` prop) so switching logs while the drawer stays open resets any prior error state.
