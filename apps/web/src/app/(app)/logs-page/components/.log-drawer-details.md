# log-drawer-details.tsx

Renders the full, formatted log details inside the "Log Details" drawer, lazily fetching the complete log record (beyond the summary already shown in the row) via a GraphQL query keyed on the log's composite identity. Includes loading skeletons and an error boundary that falls back to the row summary if the fetch fails.

## Key Components

- **`LogDrawerDetails`** — Public component. Accepts a Relay fragment reference (`log`) and a `fallback` string (the row summary), unwraps the composite key fields via `useFragment`, and wraps the content in a keyed error boundary that resets when a different log is selected.
- **`LogDrawerDetailsContent`** — Wraps the data-fetching reader in a `LoadingSuspense` boundary with its own scope.
- **`LogDrawerDetailsContentReader`** — Checks `useLoadingScope()` to decide whether to render a skeleton or perform the live query, avoiding redundant fetches while an ancestor boundary is still loading.
- **`LogDrawerDetailsContentLive`** — Executes `logDrawerDetailsQuery` via `useLazyLoadQuery`, formats the result with `formatLogDetailsRefForCopy`, and renders the text (or falls back to the summary if no log is returned).
- **`LogDrawerDetailsText`** — Renders either a `TextLineSkeleton` (while loading) or the final pre-wrapped, word-broken details text.
- **`LogDrawerDetailsErrorBoundary`** — Class-based error boundary; on catch, calls `onError` (used to surface a destructive toast) and renders the fallback summary instead of crashing the drawer.

## Usage Example

```typescript
import { LogDrawerDetails } from './log-drawer-details';

function LogDrawer({ logRef, summary }: { logRef: logDrawerDetails_log$key; summary: string }) {
  return (
    <div className="p-4">
      <h3>Log Details</h3>
      <LogDrawerDetails log={logRef} fallback={summary} />
    </div>
  );
}
```

The component expects `logRef` to satisfy the `logDrawerDetails_log` GraphQL fragment (containing `toolEventId`, `ingestDay`, `toolType`, `eventType`, `timestamp`). The `fallback` text is shown both before the detailed fetch resolves (if an error occurs) and when the server returns no matching log record.
