Client-side Next.js page component that renders the Logs view, displaying a table of log entries wrapped in a shared error boundary for consistent failure handling.

## Key Components

- **`Logs`** (default export): The page component rendered at the logs route. It composes `ContentErrorBoundary` and `LogsTable` to display log data with built-in error handling and consistent page padding using CSS custom properties.
- **`ContentErrorBoundary`**: Shared component (imported from `@/app/components/shared`) that catches rendering errors within its children and displays a fallback title/message.
- **`LogsTable`**: Local component (from `./components/logs-table`) responsible for fetching and rendering the actual log entries in a table.

## Usage Example

This file is a Next.js App Router page and is automatically routed based on its file location (e.g., `app/logs/page.tsx`). It requires no manual invocation—navigating to the corresponding route renders it.

```typescript
// Example: how the page composes its children
export default function Logs() {
  return (
    <div className="px-[var(--spacing-system-l)] pb-[var(--spacing-system-l)]">
      <ContentErrorBoundary title="Logs" message="Couldn't load logs.">
        <LogsTable />
      </ContentErrorBoundary>
    </div>
  );
}
```

If `LogsTable` throws during render or data fetching, `ContentErrorBoundary` intercepts the error and displays "Logs" as the title with the message "Couldn't load logs." instead of crashing the page.

## Notes

- Marked `'use client'`, so this component renders on the client side, enabling interactive features in `LogsTable`.
- Styling relies on CSS custom properties (`--spacing-system-l`) for consistent spacing across the app.
