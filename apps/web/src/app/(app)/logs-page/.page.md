Client-rendered page component that serves as the entry point for the Logs view, rendering a logs table wrapped in an error boundary for graceful failure handling.

## Key Components

- **`Logs`** (default export) - A client-side React component (`'use client'`) that renders the Logs page layout.
- **`ContentErrorBoundary`** - Shared wrapper component that catches rendering errors within its children and displays a fallback UI with a custom title and message.
- **`LogsTable`** - Local component (imported from `./components/logs-table`) responsible for fetching and displaying the actual logs data.

## Usage Example

This file is a Next.js App Router page component, automatically routed based on its file path (e.g., `/logs`). It requires no props and is rendered directly by the Next.js routing system:

```typescript
// Automatically invoked by Next.js when navigating to the logs route
// No manual import/usage needed - file-based routing handles this

// Example of the rendered structure:
export default function Logs() {
  return (
    <div className="px-[var(--spacing-system-l)] pb-[var(--spacing-system-l)]">
      <ContentErrorBoundary title="Logs" message="Couldn't load logs.">
        <LogsTable />
      </ContentErrorBoundary>
    </div>
  );
}
```

The component applies consistent spacing via CSS custom properties (`--spacing-system-l`) and ensures that any errors thrown by `LogsTable` (e.g., failed data fetches) are caught by `ContentErrorBoundary`, displaying a user-friendly "Couldn't load logs." message instead of crashing the page.
