## setup-wizard.tsx

Implements the tenant onboarding setup wizard: a multi-step flow that guides new admins through workspace configuration (organization, customer, device enrollment) before handing off to Mingo AI. Handles step progression, server-side persistence, auto-detection of completed steps, and the transition to the dashboard/Mingo chat.

## Key Components

- **`SetupWizard`** - Top-level export wrapping the wizard in a `LoadingSuspense` boundary with its own flex column layout, ensuring the loading placeholder and live wizard share identical framing.
- **`SetupLoadingFrame`** - Renders a static placeholder screen (welcome or all-set) while onboarding data loads, based on tenant completion state already in the store.
- **`SetupWizardReader`** - Internal switch that renders the loading frame or the live wizard depending on `useLoadingScope()`.
- **`SetupWizardLive`** - Core state machine: tracks current `SetupStep`, persists step completion via GraphQL mutations, auto-advances through steps using `isDone`/`nextSetupScreen`, and handles the final "Start with Mingo" transition with a fail-open timeout (`START_FAIL_OPEN_MS`).
- **`START_FAIL_OPEN_MS`** - Constant (8000ms) bounding how long the wizard waits for server confirmation before navigating away regardless.

## Usage Example

```typescript
import { SetupWizard } from '@/app/(app)/onboarding/components/setup-wizard';

export default function OnboardingPage() {
  return <SetupWizard />;
}
```

The wizard reads tenant/user state from `useOnboardingStore` and `useAuthStore`, renders the appropriate step component (`WelcomeStep`, `OrganizationStep`, `CustomerStep`, `DeployDeviceStep`, `ReadyStep`, `AllSetStep`) inside `SetupFrame`, and persists progress through `useOnboardingMutations`. On completion, it marks the tour started and redirects to either Mingo's home or the dashboard depending on `isSaasTenantMode()`.
