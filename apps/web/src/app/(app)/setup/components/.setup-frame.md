Renders the shared page frame for the tenant setup wizard, providing a progress indicator, centered content area, and a consistent footer across all onboarding screens.

## Key Components

- **`SetupProgress`** — Internal component rendering a segmented progress bar (one segment per tenant setup step). Each segment is styled as `done`, `current`, or `pending` based on the current `step`, using `setupProgressOf` to compute progress state. Includes ARIA attributes for accessibility.
- **`SetupFrame`** — The exported page frame component. Lays out:
  - Top: `SetupProgress` bar
  - Middle: centered `children` content, capped at `max-w-[990px]`, with responsive top/center alignment (top on phone, centered from tablet up)
  - Bottom: footer row with `NeedHelpMenu` (left), `PoweredByFlamingo` (center), and `DevSkipOnboardingButton` (right, dev/QA only)

## Usage Example

```typescript
import { SetupFrame } from './setup-frame';
import type { SetupStep } from '../setup-steps';

export default function WelcomeStep() {
  const step: SetupStep = 'welcome';

  return (
    <SetupFrame step={step}>
      <h1>Welcome to OpenFrame</h1>
      <p>Let's get your tenant set up.</p>
    </SetupFrame>
  );
}
```

**Notes:**
- `step` must be one of the values defined in `SETUP_TENANT_SCREENS` to correctly compute progress state.
- The component assumes it is rendered within the top-level app shell (which owns viewport sizing and safe-area insets), so it intentionally uses window-chrome breakpoints (`sm:`, `md:`) rather than content-panel breakpoints.
- `children` should be constrained to the wizard's standard content width; the frame itself handles outer layout and spacing.
