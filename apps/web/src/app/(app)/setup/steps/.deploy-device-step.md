## Deploy Device Step

This file implements the "Deploy First Device" onboarding step, presenting an install command for a selected OS platform and tracking device enrollment progress through a live checklist. It handles both the web/copy-command flow and the desktop shell's local agent installation flow.

## Key Components

- **`DeployDeviceStep`** — Top-level exported component rendering the step heading plus `DeployDeviceSection`.
- **`DeployDeviceSection`** — Wraps the body in a `LoadingSuspense` boundary so reads (organizations, install command, enrollment) suspend locally instead of bubbling to the page.
- **`DeployDeviceBody`** — Switches between `DeployDeviceLoading` (while in loading scope) and `DeployDeviceForm`.
- **`DeployDeviceForm`** — Main interactive form: resolves the effective organization, builds the install command via `useInstallCommand`, polls enrollment via `useFirstDeviceEnrollment`, and manages local install via `useLocalAgentInstall`.
- **`DeployDeviceLoading`** — Inert skeleton version of the form shown during suspense.
- **`DeployActions`** — Renders "Copy Command" plus a contextual primary action (`deploy` or `continue`) based on `PrimaryAction` type.
- **`CommandBox`** — Styled container for the install command/skeleton.
- **`detectPlatform()`** — Infers the admin's OS (`darwin`/`windows`) from `navigator.platform`.
- **`checklistLines()`** — Builds the enrollment checklist strings (`workspace resolved`, `device enrolled`, `inventory received`, `mingo unlocked`).
- **`installFailureCopy()`** — Maps `AgentInstallError` kinds to toast title/description.
- **`DeployDeviceStepProps`** — Props interface: `organizationId`, `onContinue`, `persisting`.

## Usage Example

```typescript
import { DeployDeviceStep } from './deploy-device-step';

function OnboardingWizard() {
  const [device, setDevice] = useState<FirstDevice | null>(null);

  return (
    <DeployDeviceStep
      organizationId="org_123"
      persisting={false}
      onContinue={(enrolledDevice) => {
        setDevice(enrolledDevice);
        // advance to next onboarding step
      }}
    />
  );
}
```

The component is self-contained: pass the organization selected earlier in onboarding (or `null` to use the default), and handle `onContinue` once the first device finishes enrolling and the AI assistant comes online.
