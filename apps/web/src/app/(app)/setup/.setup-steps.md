# setup-steps.ts

Defines the ordered screens of the tenant setup wizard and provides helpers for tracking/advancing progress through the tenant onboarding steps.

This module models the wizard flow as two layers: the full screen sequence (`welcome` → `organization` → `customer` → `device` → `ready` → `all-set`), and the subset of screens (`organization`, `customer`, `device`) that each correspond to a persisted `TenantOnboardingStep`. Progress and navigation logic use this mapping to skip already-completed steps and render an accurate progress bar.

## Key Components

- **`SETUP_STEPS`** / **`SetupStep`** — The full ordered list of wizard screens and its derived type.
- **`SETUP_TENANT_SCREENS`** / **`SetupTenantScreen`** — The subset of screens that persist a tenant onboarding step; defines the progress bar's segments.
- **`TENANT_STEP_OF`** — Maps each tenant screen to its corresponding `TenantOnboardingStep` enum value.
- **`isTenantScreen(step)`** — Type guard narrowing a `SetupStep` to a `SetupTenantScreen`.
- **`setupProgressOf(step)`** — Returns `{ done, current }` describing how many progress segments are complete and which is active, for rendering the progress bar.
- **`nextSetupScreen(from, isDone)`** — Determines the next screen to show, skipping tenant screens whose step is already marked done.

## Usage Example

```typescript
import { setupProgressOf, nextSetupScreen, TENANT_STEP_OF } from './setup-steps';
import { TenantOnboardingStep } from '@/generated/schema-enums';

// Render progress bar for the current screen
const { done, current } = setupProgressOf('customer');
// done: 1, current: 2

// Determine the next screen, skipping completed steps
const completedSteps = new Set([TenantOnboardingStep.MSP_SETUP]);
const next = nextSetupScreen('organization', step => completedSteps.has(step));
// next: 'customer' (organization already done, so skipped if applicable)
```
