# page.tsx

Next.js route component that renders the Trust Center page within the Help Center section of the application, delegating all rendering logic to a shared library component.

## Key Components

- **`TrustCenterRoute`** — Default-exported client component that mounts `TrustCenterPage` from `@flamingo-stack/openframe-frontend-core`, configured for this app's routing and endpoint context.

This component is a thin wrapper:
- Passes `shell={false}` since the parent `AppLayout` already supplies the page `<main>` chrome.
- Supplies `endpoint={EP.trustCenter}` so the library component self-fetches the hub's public Vanta Trust Center data through the `/content` proxy.
- Configures a `backButton` linking to `HELP_CENTER_BASE` for navigation back to the Help Center index.
- Relies on the library's internal `ContactForm`, which reads `HELP_CENTER_ENDPOINTS.contactUrl` from the Help Center subtree's `EndpointsRuntime` for gated-document requests (documents, subprocessors, AI statements).

## Usage Example

This file is a Next.js page route and is not imported directly; it is resolved automatically by the file-based routing system when a user navigates to the Trust Center path under the Help Center section.

```typescript
// Example of how the route is structured within the app directory,
// e.g. app/help-center/trust-center/page.tsx

import { EP, HELP_CENTER_BASE } from '../endpoints';

export default function TrustCenterRoute() {
  return (
    <TrustCenterPage
      shell={false}
      endpoint={EP.trustCenter}
      backButton={{ label: 'Back to Help Center', href: HELP_CENTER_BASE }}
    />
  );
}
```

Consumers only need to ensure `EP.trustCenter` and `HELP_CENTER_BASE` are correctly defined in the sibling `endpoints` module for this route to resolve content and navigation properly.
