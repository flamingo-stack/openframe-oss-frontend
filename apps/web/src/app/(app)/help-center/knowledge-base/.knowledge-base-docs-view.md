Renders the OpenFrame in-app knowledge base docs hub by wiring `<DocsHubPage>` from the core library to the app's proxied doc endpoints and markdown renderer.

## Key Components

### `KnowledgeBaseDocsView`
The primary exported component. Accepts a `docPath` prop and delegates all chrome, sidebar tree, scroll-spy, and search UI to `<DocsHubPage>`. It connects four `/content`-proxied endpoints (tree, content, resolve-link, search) and provides the `baseRoute` so sidebar navigation soft-routes to `/help-center/knowledge-base/<path>`.

### `markdownRenderer`
A `DocumentTypeRenderers['markdown']` implementation passed to `<DocsHubPage>`. Handles two cases:
- **`.mmd` files** — wraps raw Mermaid content in a fenced ` ```mermaid ` block so diagrams render correctly.
- **All other files** — passes content directly to `<RichMarkdownRenderer>`, threading internal-link handlers plus `resolveLinkEndpointUrl={EP.docsResolveLink}` so relative links resolve through the `/content` proxy rather than the lib's hub-relative `/api/docs/resolve-link` default (which hits this app's own origin and 500s).

### `KB_SOURCE_ID`
Constant (`'openframe-docs'`) that identifies the doc source; must match the hub's `DOC_SOURCES` id.

## Usage Example

```typescript
// app/help-center/knowledge-base/[[...path]]/page.tsx
import { KnowledgeBaseDocsView } from './knowledge-base-docs-view';

export default function Page({ params }: { params: { path?: string[] } }) {
  const docPath = params.path?.join('/') ?? '';
  return <KnowledgeBaseDocsView docPath={docPath} />;
}
```

## Notes

- `shell={false}` suppresses the library's outer page shell since the host app provides its own layout.
- `chatSource="openframe"` is a trusted platform identifier injected into resolve-link and search requests — it is never derived from user input.
- The back button links to `HELP_CENTER_BASE`, keeping navigation within the in-app help center.
