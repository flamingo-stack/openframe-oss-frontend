# page.tsx

Next.js App Router page component that renders a deep-link route for an individual knowledge base document, supporting direct navigation to `/help-center/knowledge-base/<path>` URLs.

This file solves a specific static export challenge: since documentation paths are runtime/CMS-driven content rather than build-time enumerable routes, it can't statically generate every possible doc path. Instead, it prerenders a single placeholder shell and relies on the app's SPA fallback routing to handle real doc paths dynamically at runtime.

## Key Components

- **`generateStaticParams()`** — Required by Next.js `output: 'export'` static export mode. Returns a single placeholder param (`{ path: ['index'] }`) since doc paths aren't known at build time. Actual path resolution happens client-side via SPA fallback.
- **`KnowledgeBaseDocPage`** — Default async Server Component that receives route `params` (a catch-all `path` segment array), normalizes it, and delegates rendering to `KnowledgeBaseDocsView`.
- Relies on **`normalizeDocPath`** (from `@flamingo-stack/openframe-frontend-core/utils`) to lowercase and join the catch-all URL segments into a canonical path string — the same single source of truth (SSOT) used by the knowledge base hub for tree resolution.

## Usage Example

This page is automatically matched by Next.js routing for paths like:

```text
/help-center/knowledge-base/getting-started/installation
```

The framework invokes it as follows:

```typescript
// Next.js resolves the dynamic catch-all segment into `path`
const params = Promise.resolve({ path: ['getting-started', 'installation'] });

// Internally, the page does:
const { path } = await params;
const docPath = normalizeDocPath(path); // "getting-started/installation"

<KnowledgeBaseDocsView docPath={docPath} />
```

No manual invocation is required — this file is a route handler discovered by the Next.js App Router based on its file path (typically `app/help-center/knowledge-base/[...path]/page.tsx`).
