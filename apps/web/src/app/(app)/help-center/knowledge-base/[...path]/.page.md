# page.tsx

Next.js App Router catch-all page component that renders an individual knowledge base document at the route `/help-center/knowledge-base/<path>`. It supports deep-linking into specific docs while working within the constraints of static export (`output: 'export'`).

## Key Components

- **`generateStaticParams()`** — Required for static export builds. Since doc paths are runtime/CMS-driven content and not enumerable at build time, this returns a single placeholder param (`{ path: ['index'] }`) to satisfy Next.js's static export requirements. Actual doc paths are resolved client-side via the native shell's SPA fallback routing (or dynamically in the web/standalone build).
- **`KnowledgeBaseDocPage`** — Default async page component that awaits the route's `params`, normalizes the catch-all `path` segments via `normalizeDocPath`, and passes the result to `KnowledgeBaseDocsView` as `docPath`.

## Usage Example

This file is a Next.js route handler and is not imported directly. It automatically handles requests matching its file-based route, e.g.:

```typescript
// Route: app/help-center/knowledge-base/[...path]/page.tsx
// Matches URLs like:
//   /help-center/knowledge-base/getting-started/installation
//   /help-center/knowledge-base/faq

// Next.js invokes the page with the matched segments:
// params = Promise.resolve({ path: ['getting-started', 'installation'] })

// normalizeDocPath(['getting-started', 'installation'])
// -> 'getting-started/installation'
```

The `normalizeDocPath` utility (from `@flamingo-stack/openframe-frontend-core/utils`) ensures the path matches the same single source of truth (SSOT) used by the knowledge base hub/tree, so both direct navigation and hard page loads/shared links resolve to the correct document rather than falling back to the root index.

## Notes

- Relies on `KnowledgeBaseDocsView` (sibling component) to perform the actual tree lookup and document rendering.
- The static export limitation means this page acts as a shell; real content resolution happens at runtime against the CMS-backed doc tree.
