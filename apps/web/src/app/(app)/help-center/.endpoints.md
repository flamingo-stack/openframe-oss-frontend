# endpoints.ts

Single source of truth for all Help Center content endpoints, consolidating every URL under the `EP` object and `CONTENT_ENDPOINTS` runtime config. Centralizing endpoints here means repointing the content data source requires only a one-line change to `CONTENT_BASE`.

## Key Components

- **`CONTENT_ORIGIN`** — Empty string on web (relative, same-origin via Next.js `rewrites()`); resolves to the tenant gateway origin in the native app shell (where there's no Next server to proxy requests).
- **`CONTENT_BASE`** — The `/content` proxy root, exported for callers that build their own paths on top (e.g., `FaqSection`, relative hub URLs arriving in payloads).
- **`IMAGE_PROXY_SKIP_DOMAINS`** — Domains (own Supabase storage host) that should load images directly instead of through the proxy, avoiding WAF 502 errors.
- **`HELP_CENTER_BASE`** — Fixed route prefix used as the back-button target across Help Center pages.
- **`KNOWLEDGE_BASE_ROUTE`** — Route for the knowledge-base docs hub, shared between the docs page and chat doc-chip composer.
- **`EP`** — Object containing all content endpoint URLs/builders: onboarding guides, roadmap, delivery items, product releases, legal documents, trust center, downloads, FAQs, knowledge base docs (structure/content/search/resolve-link), walkthrough video, meetings, and YouTube poster resolver.
- **`CONTENT_ENDPOINTS`** — `EndpointsRuntime` config satisfying the shared library's required-context contract for contact forms, access codes, and announcements.

## Usage Example

```typescript
import { EP, CONTENT_ENDPOINTS, HELP_CENTER_BASE } from '@/lib/endpoints';

// Fetch FAQs list
const faqs = await contentFetch(EP.faqs);

// Build a dynamic onboarding guide URL
const guideUrl = EP.onboardingBySlug('getting-started');

// Fetch docs hub structure for a given source
const structure = await contentFetch(EP.docsStructure('openframe-docs'));

// Wire up a Help Center page's back button
const backButton = { label: 'Back to Help Center', href: HELP_CENTER_BASE };

// Provide runtime endpoints to the lib's contact form context
<EndpointsRuntimeContext.Provider value={CONTENT_ENDPOINTS}>
  <ContactForm />
</EndpointsRuntimeContext.Provider>
```

**Note:** On web, all `EP` URLs resolve same-origin and are forwarded server-side via Next.js rewrites (carrying session cookies). In the native app shell, they resolve directly against the tenant gateway using bearer-token auth via `embedAuthedFetch`.
