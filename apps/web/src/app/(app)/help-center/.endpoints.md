# endpoints.ts

Single source of truth for all Help Center content API endpoints. Centralizes endpoint construction around a `CONTENT_BASE` that resolves differently depending on runtime: relative (`/content`, same-origin) on the web — proxied server-side via Next's `rewrites()` to the tenant host, preserving session cookies — versus absolute (tenant gateway origin) in the native Capacitor shell, where there's no Next server to perform the rewrite.

## Key Components

- **`CONTENT_ORIGIN`** — `''` on web, tenant host URL in the native app shell (`isAppShell()`). Exported for the chat's `allowedOrigins` cross-origin guard.
- **`CONTENT_BASE`** — The `/content` proxy root (no `/api` suffix). Used by `<FaqSection>` and for re-routing relative URLs embedded in payloads (e.g., caption URLs).
- **`IMAGE_PROXY_SKIP_DOMAINS`** — Domains (own Supabase storage host) that should bypass the image proxy and load directly.
- **`HELP_CENTER_BASE`** — Fixed route prefix/back-button target for Help Center pages.
- **`KNOWLEDGE_BASE_ROUTE`** — Route for the docs hub, shared between the hub page and chat doc-chip composer.
- **`EP`** — Object mapping every content feature (onboarding, roadmap, delivery, releases, legal, trust center, downloads, FAQs, docs, walkthrough video, meetings, YouTube poster) to its endpoint URL or URL-builder function.
- **`CONTENT_ENDPOINTS`** — `EndpointsRuntime` config for the lib's contact/access-code/announcement surfaces, required by `<ContactForm>`'s `useContactSubmission` hook.

## Usage Example

```typescript
import { EP, CONTENT_ENDPOINTS, HELP_CENTER_BASE } from '@/lib/endpoints';

// Fetch onboarding guide by slug
const res = await contentFetch(EP.onboardingBySlug('getting-started'));

// Build a roadmap vote request
await contentFetch(EP.roadmapVote, { method: 'POST', body: JSON.stringify(vote) });

// Use as back-button destination
<HelpCenterList backButton={{ label: 'Back to Help Center', href: HELP_CENTER_BASE }} />

// Provide required runtime context for lib components
<EndpointsRuntimeContext.Provider value={CONTENT_ENDPOINTS}>
  <ContactForm />
</EndpointsRuntimeContext.Provider>
```

Every endpoint flows through `contentFetch`, which routes via `embedAuthedFetch` for consistent auth handling (bearer tokens, credentials, 401-refresh) across both web and native shell deployments.
