Where a content record opens in OpenFrame: the core lib's one embedder composer (`makeEmbedderComposeContentUrl`)
with the pages this app has for the hub's content. Both host-mode runtimes (the Help Center subtree and the app-wide
chat) register it.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `composeOpenframeInAppContentUrl` | `ComposeContentUrl` | Relative in-app hrefs for the records OpenFrame has a page for; the server's absolute address, on the content hub, for every other |

**Pages named:** onboarding guide and release detail routes (`?slug=`), the Knowledge Base (product docs at their
tree path), the roadmap and bug-fixes lists (`?search=<id>`), the tickets list (a ticket open), the FAQ page (a
question's anchor) and the trust center.

`hubspot_ticket_anon` is not hosted: it is another customer's known issue, which the viewer's tickets list cannot find.

## Usage Example

```typescript
composeOpenframeInAppContentUrl({ type: 'product_release', identifier: 'v2-launch' });
// → { href: '/help-center/releases/detail?slug=v2-launch', targetPlatform: null }

composeOpenframeInAppContentUrl({
  type: 'blog_post',
  identifier: '456',
  externalUrl: 'https://www.flamingo.run/blog/my-post',
});
// → { href: 'https://www.flamingo.run/blog/my-post', targetPlatform: null }
```
