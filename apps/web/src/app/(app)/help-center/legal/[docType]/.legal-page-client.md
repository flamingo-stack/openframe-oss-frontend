# legal-page-client.tsx

Client component that renders a single legal document page (e.g., Privacy Policy, Terms of Service) within the Help Center, guarding against document types that are hidden for the current build configuration (such as billing-related docs when billing is disabled).

## Key Components

- **`LegalPageClient`** — Default-exported-style named component (no default export) that:
  - Reads the `docType` route param via `useParams`.
  - Validates the type is a recognized legal document type and is currently "shown" given billing visibility (`isBillingHidden()`), calling `notFound()` otherwise.
  - Delegates actual rendering (title, version, effective date, FAQ topic) to the shared `LegalDocumentPage` component from `@flamingo-stack/openframe-frontend-core`, passing only the `docType`, API endpoints, and a back-button config.

## Usage Example

```typescript
// app/legal/[docType]/page.tsx
import { LegalPageClient } from './legal-page-client';

export default function Page() {
  return <LegalPageClient />;
}
```

This component is intended to be used as the client boundary for a statically generated legal document route (e.g., `/legal/privacy-policy`). Since the page is prerendered for every known legal document type, the visibility check ensures that a document type excluded in the current build (e.g., due to `isBillingHidden()`) still resolves to a valid route but immediately triggers Next.js's `notFound()` behavior instead of rendering stale or inapplicable content. Note the deliberate use of the bare `isBillingHidden()` predicate rather than a `useIsMobileShell()`-style hook, since a hook would allow the document to render once before being suppressed during hydration.
