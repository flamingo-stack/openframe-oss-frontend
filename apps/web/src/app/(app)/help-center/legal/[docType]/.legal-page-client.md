# legal-page-client.tsx

Client component that renders a single legal document page (e.g., Terms of Service, Privacy Policy) by delegating to the shared `LegalDocumentPage` component, while gating visibility of document types that are hidden in the current build (such as billing-related documents).

## Key Components

- **`LegalPageClient`** — Default-exported client component (marked `'use client'`) that:
  - Reads the `docType` route parameter via `useParams`.
  - Validates the type against `isLegalDocumentType` and checks it's in the currently shown set from `shownLegalDocumentTypes(isBillingHidden())`.
  - Calls `notFound()` synchronously (not via a hook) when the document type is valid but hidden for this build, since statically-exported paths exist for every legal document type regardless of build configuration.
  - Renders `LegalDocumentPage` with `shell={false}`, passing the document type, API endpoints, and a back button pointing to the Help Center.

## Usage Example

```typescript
// app/legal/[docType]/page.tsx
import { LegalPageClient } from './legal-page-client';

export default function Page() {
  return <LegalPageClient />;
}
```

This component relies on being rendered within a route that provides a `docType` URL parameter (e.g., `/legal/[docType]`). It assumes the surrounding static export generates a page for every possible legal document type, and uses a plain conditional (rather than a hook like `useIsMobileShell()`) to call `notFound()` before any subtree renders, avoiding a flash of content for document types hidden in the current build (for example, when `isBillingHidden()` suppresses billing-related legal documents).
