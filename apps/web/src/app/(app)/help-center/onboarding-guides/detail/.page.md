This Next.js client page renders the detail view for a single onboarding guide, reading the guide's slug from the URL query string rather than a path segment.

## Key Components

- **`OnboardingGuideDetailRoute`** (default export) — Client component that extracts the `slug` query parameter via `useSearchParams` and renders `OnboardingGuideDetailView` from `@flamingo-stack/openframe-frontend-core`, passing the slug, guide endpoint, and base path as configuration.

## Design Notes

- **Config-only pattern**: This page does not fetch data itself. `OnboardingGuideDetailView` self-fetches the guide content using `EP.onboardingBySlug`; the page only supplies routing configuration (`slug`, `guideEndpoint`, `basePath`).
- **Query param, not path segment**: Since guide slugs come from CMS content, they can't be statically prerendered under `output: 'export'`. Using a query param (`?slug=...`) avoids the need for static path generation that a dynamic route segment would require. See `routes.helpCenter.onboardingGuide` for the related route definition.
- **`shell={false}`**: Disables the view's internal layout shell, implying this page is composed within an outer layout elsewhere in the app.

## Usage Example

```typescript
// Navigating to this route with a slug query param:
// /help-center/onboarding-guides/detail?slug=getting-started-with-rmm

import { useRouter } from 'next/navigation';

function GuideLink({ slug }: { slug: string }) {
  const router = useRouter();
  return (
    <button onClick={() => router.push(`/help-center/onboarding-guides/detail?slug=${slug}`)}>
      View Guide
    </button>
  );
}
```
