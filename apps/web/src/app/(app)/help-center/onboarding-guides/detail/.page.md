Next.js client page component that renders the detail view for a single onboarding guide, resolving the guide's slug from a query parameter rather than a dynamic path segment.

## Key Components

- **`OnboardingGuideDetailRoute`** (default export) — Client component (`'use client'`) that reads the `slug` query parameter via `useSearchParams` and renders `OnboardingGuideDetailView` from `@flamingo-stack/openframe-frontend-core`, passing:
  - `shell={false}` — renders without the outer app shell/layout
  - `slug` — guide identifier extracted from the URL query string
  - `guideEndpoint={EP.onboardingBySlug}` — API endpoint used by the library view to self-fetch guide data
  - `basePath` — computed as `${HELP_CENTER_BASE}/onboarding-guides`, used for internal navigation links within the view

## Design Notes

Since guide slugs are CMS-managed content, they can't be statically prerendered under `output: 'export'`. Using a query param (`?slug=...`) instead of a dynamic path segment (`/onboarding-guides/[slug]`) avoids requiring build-time knowledge of all possible slugs, while the `OnboardingGuideDetailView` component handles data fetching client-side at runtime.

## Usage Example

```typescript
// Navigating to this route from elsewhere in the app:
import { useRouter } from 'next/navigation';
import { HELP_CENTER_BASE } from '../../endpoints';

function GuideLink({ slug }: { slug: string }) {
  const router = useRouter();

  const goToGuide = () => {
    router.push(`${HELP_CENTER_BASE}/onboarding-guides/detail?slug=${slug}`);
  };

  return <button onClick={goToGuide}>View Guide</button>;
}
```

See related configuration: [`endpoints.ts`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/endpoints.ts) for `EP` and `HELP_CENTER_BASE` definitions, and `routes.helpCenter.onboardingGuide` for route structure.
