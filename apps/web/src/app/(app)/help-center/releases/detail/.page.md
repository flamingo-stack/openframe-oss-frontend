# page.tsx

Next.js route component for displaying a single product release detail page. Since release slugs come from CMS content and the app uses `output: 'export'` for static builds, the slug is passed as a query parameter rather than a dynamic path segment, avoiding the need for build-time prerendering of CMS-driven routes.

## Key Components

- **`ReleaseDetailRoute`** - Default export client component that reads the `slug` query parameter via `useSearchParams` and renders `ReleaseDetailClient` with it.

## Usage Example

This route is resolved automatically by Next.js based on file location, and is typically linked to via the `routes.helpCenter.release` helper:

```typescript
import { routes } from '@/lib/routes';
import Link from 'next/link';

function ReleaseLink({ slug }: { slug: string }) {
  return (
    <Link href={`${routes.helpCenter.release}?slug=${encodeURIComponent(slug)}`}>
      View Release
    </Link>
  );
}
```

Navigating to a URL like `/help-center/release?slug=v1-2-0` renders this route, which extracts `v1-2-0` from the query string and delegates rendering to `ReleaseDetailClient`.

**Note:** Because this is a `'use client'` component, `useSearchParams` runs on the client, making it compatible with static export builds that cannot resolve dynamic CMS slugs at build time.
