Client-side route component that renders the product release detail page, reading the release identifier from a URL query parameter rather than a dynamic path segment.

## Key Components

- **`ReleaseDetailRoute`** - Default-exported Next.js page component (client component via `'use client'`). It extracts the `slug` query parameter using `useSearchParams` and passes it to `ReleaseDetailClient` for rendering.

## Usage Notes

This page intentionally uses a query parameter (`?slug=...`) instead of a dynamic path segment (e.g., `/release/[slug]`). Since release slugs are managed as CMS content and the app is built with `output: 'export'` (static export), Next.js cannot prerender dynamic path segments whose values come from external/CMS data at build time. Using a query param sidesteps this limitation, letting the route resolve the slug client-side at runtime. See the `routes.helpCenter.release` route definition for how links to this page are constructed.

## Usage Example

```typescript
// Linking to a release detail page elsewhere in the app
import Link from 'next/link';
import { routes } from '@/lib/routes'; // conceptual reference

function ReleaseLink({ slug }: { slug: string }) {
  return (
    <Link href={`${routes.helpCenter.release}?slug=${encodeURIComponent(slug)}`}>
      View release notes
    </Link>
  );
}
```

```typescript
// The page component itself (simplified)
export default function ReleaseDetailRoute() {
  const slug = useSearchParams().get('slug') ?? '';
  return <ReleaseDetailClient slug={slug} />;
}
```

**Note:** If `slug` is missing from the URL, it defaults to an empty string, and `ReleaseDetailClient` is responsible for handling that case (e.g., showing a not-found state).
