# help-center-runtime-provider.tsx

A React context provider that overrides the app-wide `ChatRuntime` for the `/help-center` route subtree, enabling in-app navigation for Help Center content surfaces while preserving chat configuration from the parent runtime.

This provider exists because Help Center hosts two in-app content surfaces (onboarding guides and product release details). It customizes how content links resolve (`composeContentUrl`) so that chat cards, RAG search results, and knowledge base links soft-navigate within the app instead of opening the external Flamingo content hub, while inheriting all chat-side config (endpoints, auth, image proxy) from the parent context via spread.

## Key Components

- **`HelpCenterRuntimeProvider`** — The main provider component. Wraps `children` with two context providers:
  - `EndpointsRuntimeContext.Provider` — supplies `CONTENT_ENDPOINTS` (required by the ticket-create `<ContactForm>`).
  - `ChatRuntimeContext.Provider` — supplies a memoized `runtime` object derived from the parent `ChatRuntime`, with `navigation.mode` forced to `'host'` and `composeContentUrl` set to `composeOpenframeInAppContentUrl`.

Key behavior:
- Reads the parent runtime via `useContext(ChatRuntimeContext)` and **spreads** it rather than replacing it, preserving `navigate`, `decideNewTab`, `openExternal`, and other chat config.
- Uses a shared `composeContentUrl` function (from `help-center-content-href.ts`) so content routing stays consistent between chat-rendered cards and standalone Help Center pages.
- Memoizes the runtime object on `[parent]` to avoid unnecessary re-renders.

## Usage Example

```typescript
// layout.tsx for the /help-center route segment
import { HelpCenterRuntimeProvider } from './help-center-runtime-provider';

export default function HelpCenterLayout({ children }: { children: React.ReactNode }) {
  return (
    <section className="help-center-shell">
      <HelpCenterRuntimeProvider>
        {children}
      </HelpCenterRuntimeProvider>
    </section>
  );
}
```

Once mounted, any descendant component calling `useContext(ChatRuntimeContext)` (e.g., chat cards or `useDocSearch`) will resolve content hrefs relative to `/help-center/...`, and forms using `useRequiredEndpointsRuntime()` will resolve against `CONTENT_ENDPOINTS`.
