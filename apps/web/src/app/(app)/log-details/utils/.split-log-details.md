# split-log-details.ts

Splits a log entry's `details` JSON payload into separate Input and Output sections for the Log Details page, extracting script run inputs (`result.input`) from the surrounding output data when present.

## Key Components

- **`LogOutputTitle`** — Type alias for the output section's heading: `'Output'` (when an input exists to pair with it) or `'Details'` (generic single-block case).
- **`LogPayloadSections`** — Return shape containing optional `input`, the `output` payload, and the `outputTitle` to display.
- **`fallbackDetails(log, rawDetails?)`** — Builds a structured stand-in object from a log's identifying fields (toolEventId, eventType, severity, etc.) when `details` is missing or unparseable, ensuring the panel is never empty.
- **`splitLogDetails(log)`** — Main export. Parses `log.details` as JSON and:
  - Returns fallback details with `'Details'` title if `details` is absent or invalid JSON.
  - Returns the parsed object as-is with `'Details'` title if there's no `result.input` to extract.
  - Otherwise lifts `input` out of `result`, keeps the rest of the payload (`result` minus `input`, plus `error`, `additional_info`, etc.) untouched, and returns `'Output'` as the title.

## Usage Example

```typescript
import { splitLogDetails } from './split-log-details';
import type { LogEntry } from '../../logs-page/types/log.types';

function renderLogDetails(log: LogEntry) {
  const { input, output, outputTitle } = splitLogDetails(log);

  return {
    showInputPanel: input !== undefined,
    inputContent: input,
    outputHeading: outputTitle, // 'Output' or 'Details'
    outputContent: output,
  };
}
```

This is typically consumed by the Log Details page component to render a two-column layout (Input | Output) for script run logs, falling back to a single "Details" panel for other event types like Fleet audit logs or MeshCentral events.
