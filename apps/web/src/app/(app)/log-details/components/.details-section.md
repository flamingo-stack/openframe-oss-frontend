# details-section.tsx

Renders the payload portion of the Log Details page, adapting its layout based on log type: script-run logs display separate "Input" and "Output" cards, while other logs show a single "Details" card.

## Key Components

- **`DetailsSectionProps`** — Interface accepting an optional `logDetails` (a `LogEntry`, `null`, or `undefined`). When absent, the component renders its own loading skeleton.
- **`DetailsSection`** — The main component function. It:
  - Returns a loading `JsonPanel` while data is unavailable (via `useLoadingScope()` or a missing `logDetails`).
  - Calls `splitLogDetails` to derive `input`, `output`, and `outputTitle` from the raw log's `details` JSON.
  - Conditionally renders an "Input" `JsonPanel` only when `input` is defined (i.e., for script-run logs).
  - Always renders a final `JsonPanel` for the output/details, using the dynamic `outputTitle`.

## Usage Example

```typescript
import { DetailsSection } from './details-section';
import type { LogEntry } from '../../logs-page/types/log.types';

function LogDetailsPage({ log }: { log: LogEntry | null }) {
  return (
    <div className="log-details-layout">
      <DetailsSection logDetails={log} />
    </div>
  );
}
```

The component handles its own loading and empty states internally, so consumers can pass `undefined`/`null` directly while data is being fetched:

```typescript
// While fetching
<DetailsSection logDetails={undefined} />

// After fetch resolves
<DetailsSection logDetails={fetchedLogEntry} />
```

See [`split-log-details.ts`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/utils/split-log-details.ts) for the exact mapping logic between a log's `details` payload and the rendered Input/Output structure.
