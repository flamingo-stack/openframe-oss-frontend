# log-details-view.tsx

Client-side React component that renders a detailed view of a single log entry, including status, timestamp, message, associated device, and structured metadata sections. Handles loading, error, and loaded states via a loading-scope pattern.

## Key Components

- **`LogDetailsView`** — Main exported component. Fetches log details by ID on mount, manages loading/error/not-found states, and renders the log's severity tag, timestamp, message, tool badge, event type, device info, and detail sections. Provides a "Copy Log Details" action and a back navigation button.
- **`EventTypeText`** — Internal helper component that renders the event type text or a skeleton placeholder when within a loading scope.
- **`getSeverityVariant`** — Maps a log severity string (`ERROR`, `WARNING`, `INFO`, `CRITICAL`, `DEBUG`) to a `Tag` visual variant (`error`, `warning`, `grey`, `critical`).
- **`LOG_MESSAGE_SKELETON_LINES`** — Constant controlling the number of skeleton lines shown for the log message while loading.

## Usage Example

```typescript
import { LogDetailsView } from './log-details-view';

export default function LogDetailsPage({
  searchParams,
}: {
  searchParams: {
    logId: string;
    ingestDay: string;
    toolType: string;
    eventType: string;
    timestamp: string;
  };
}) {
  return (
    <LogDetailsView
      logId={searchParams.logId}
      ingestDay={searchParams.ingestDay}
      toolType={searchParams.toolType}
      eventType={searchParams.eventType}
      timestamp={searchParams.timestamp}
    />
  );
}
```

The component requires all five identifying props to perform the fetch; if any are missing, it redirects back to the logs listing page (`routes.logs.page`). It relies on `useLogDetails` for data fetching and `useCopyToClipboard` for the copy-to-clipboard action.
