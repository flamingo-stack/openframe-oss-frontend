Renders the full detail view for a single log entry, handling loading, error, and success states while providing copy-to-clipboard functionality for log details.

## Key Components

### `LogDetailsViewProps`
| Prop | Type | Description |
|------|------|-------------|
| `logId` | `string` | Unique identifier for the log entry |
| `ingestDay` | `string` | Day the log was ingested (used for fetching) |
| `toolType` | `string` | Source tool type of the log |
| `eventType` | `string` | Category/type of the log event |
| `timestamp` | `string` | Timestamp of the log entry |

### `getSeverityVariant(severity)`
Maps a severity string (`ERROR`, `WARNING`, `INFO`, `CRITICAL`, `DEBUG`) to a `Tag` variant for visual styling.

### `LogDetailsView` (default export)
The primary component. Fetches log details via `useLogDetails`, renders three states:
- **Loading** — `LogDetailsSkeleton`
- **Error / not found** — inline fallback UI with a back button
- **Success** — `PageLayout` with severity tag, timestamp, log summary card, `DeviceInfoSection`, `FullInformationSection`, and `DetailsSection`

## Usage Example

```typescript
// Typically rendered from a dynamic route, e.g. /logs/[logId]
<LogDetailsView
  logId="abc-123"
  ingestDay="2024-01-15"
  toolType="endpoint"
  eventType="system.alert"
  timestamp="2024-01-15T10:30:00Z"
/>
```

## Notes

- If any required prop is missing on mount, the component redirects to `routes.logs.page` via `router.replace`.
- The copy action uses `formatLogDetailsForCopy` to serialize log data, with visual feedback toggling between `Copy02Icon` and `CheckIcon`.
- Back navigation is handled by `useSafeBack`, falling back to `routes.logs.page` if no browser history is available.
