# full-information-section.tsx

Renders a "Full Information" card displaying the complete set of metadata fields for a log entry, including tool type, event type, severity, user/device IDs, and timestamp. Supports a loading skeleton state and a graceful empty state when no log details are available.

## Key Components

- **`FullInformationSection`** — Client component that accepts optional `logDetails` and renders either a loading skeleton, an empty-state message, or a fully populated `InfoCard`.
- **`ROW`** — Constant object defining the canonical set of row labels (`toolEventId`, `ingestDay`, `toolType`, `eventType`, `severity`, `userId`, `deviceId`, `timestamp`) shared between the loaded card data and its loading skeleton.
- **`LOADING_SKELETON`** — Predefined skeleton shape (row labels, no title) used by `InfoCard` while data is loading, based on typical log entry composition.
- **`FullInformationSectionProps`** — Props interface accepting an optional `LogEntry` (`logDetails`).

## Usage Example

```typescript
import { FullInformationSection } from '@/app/components/.../full-information-section';
import type { LogEntry } from '../../logs-page/types/log.types';

function LogDetailsPage({ log }: { log: LogEntry | null }) {
  return (
    <div className="flex flex-col gap-6">
      <FullInformationSection logDetails={log} />
    </div>
  );
}
```

When rendered inside a loading scope (via `useLoadingScope`), the component automatically displays the `InfoCard` skeleton instead of requiring an explicit loading prop. If `logDetails` is `null`/`undefined` and not in a loading scope, it renders a "No log details available" placeholder. Optional fields (`userId`, `deviceId`) are conditionally included only when present on the log entry.
