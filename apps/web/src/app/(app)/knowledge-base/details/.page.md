This is a Next.js client page component that renders a single knowledge base article's detail view, resolving the article ID from the URL query string.

## Key Components

- **ArticleDetailsPage** (default export): Page component that reads the `id` query parameter from the URL, triggers a 404 (`notFound()`) if no `id` is present, and renders the article detail view wrapped in a shared error-boundary shell.
- **useSearchParams**: Next.js hook used to extract the `id` parameter from the current URL's query string.
- **KnowledgeBasePageShell**: Shared wrapper component providing consistent error handling/display across knowledge base pages, configured here with a custom `errorMessage` and a `resetKey` to reset its error state when the article changes.
- **ArticleDetailView**: Renders the actual article content, keyed by `articleId` to force React to remount the component when navigating between different articles via `?id=` changes.

## Usage Example

```typescript
// Navigating to this page via query string
// URL: /knowledge-base/article?id=abc123
import { useRouter } from 'next/navigation';

function ArticleLink({ articleId }: { articleId: string }) {
  const router = useRouter();
  return (
    <button onClick={() => router.push(`/knowledge-base/article?id=${articleId}`)}>
      View Article
    </button>
  );
}
```

**Notes:**
- The `key={id}` prop on `ArticleDetailView` ensures the component fully remounts (resetting internal state, re-fetching data) whenever the `id` query parameter changes, even though Next.js would otherwise reuse the route segment.
- If the `id` parameter is missing, Next.js renders its default 404 page via `notFound()`.
- This file must include `'use client'` since it relies on the `useSearchParams` hook, which requires client-side rendering.
