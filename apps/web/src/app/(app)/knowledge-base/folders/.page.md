# FolderPage (`page.tsx`)

Client-rendered Next.js page component that displays a specific knowledge base folder, identified via a `id` query string parameter.

## Key Components

- **`FolderPage`** — Default export; a client component (`'use client'`) that reads the `id` search parameter and renders the folder's contents.
- Uses **`useSearchParams`** from `next/navigation` to extract the `id` query parameter.
- Calls **`notFound()`** to render the 404 page when no `id` is provided.
- Wraps content in **`KnowledgeBasePageShell`** to provide consistent error handling/layout, with a custom `errorMessage` and a `resetKey` tied to `id` (so the error boundary resets when navigating between folders).
- Renders **`KnowledgeBaseView`** with `folderId={id}`, keyed by `id` so React remounts the view when the folder changes (since Next.js router otherwise reuses the segment when only the query string changes).

## Usage Example

This page is automatically invoked by Next.js routing when navigating to its route with an `id` query parameter, e.g.:

```typescript
// Navigating to this route from another component
import { useRouter } from 'next/navigation';

function FolderLink({ folderId }: { folderId: string }) {
  const router = useRouter();

  return (
    <button onClick={() => router.push(`/knowledge-base/folder?id=${folderId}`)}>
      Open Folder
    </button>
  );
}
```

No direct manual instantiation is needed — Next.js handles rendering `FolderPage` based on file-based routing. If `id` is missing from the query string, the user is redirected to the standard 404 page via `notFound()`.
