## Overview

A React client component that renders the "Assigned Articles" tab shown on a customer or device detail page. It displays a searchable, tag-filterable table of knowledge base articles assigned to the given target, alongside controls to assign new articles and filter by tags.

## Key Components

- **`AssignedArticlesTab`** — Main exported component. Accepts a `target` prop (customer/device reference, or `null` while loading) and renders:
  - A header with an "Assign Article" action button
  - A sticky toolbar with `TagSearchInput` (debounced search + tag chips) and an "Article Tags" filter button
  - `AssignedArticlesTable` for the row data
  - `AssignArticleModal` and `KnowledgeBaseTagsFilterModal` dialogs, mounted only once `target` is resolved

- **`AssignedArticlesTabProps`** — Props interface; `target: AssignedArticlesTarget | null`.

### Internal behavior
- Search (`search`/`debouncedSearch`) and tag filters (`tagIds`) are kept as **tab-local state**, not URL query params, to avoid leaking filters into sibling tabs sharing the same page URL.
- `useDeferredQuery` smooths filter transitions (`deferredFilters`, `deferredSearch`, `isPending`) to avoid flicker while results reload.
- `refreshKey` is bumped after assign/unassign actions to force the table and tags modal to refetch; it also invalidates the `ASSIGNED_ITEMS_QUERY_KEY` react-query cache so the article's own assignee list stays in sync.
- `useStickyToolbar` manages the sticky positioning of the search/filter bar relative to the page header.
- When no articles are assigned (`isEmpty`), the toolbar is hidden entirely since there's nothing to search.

## Usage Example

```typescript
import { AssignedArticlesTab } from './assigned-articles-tab';

function CustomerDetailPage({ customerId }: { customerId: string | null }) {
  const target = customerId ? { type: 'customer', id: customerId } : null;

  return (
    <div>
      <AssignedArticlesTab target={target} />
    </div>
  );
}
```

While `target` is `null`, the tab renders in a loading state (via `LoadingWhen`) and the "Assign Article" button is disabled; once resolved, the table, filters, and modals become fully interactive.
