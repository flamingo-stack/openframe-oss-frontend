A client-side layout wrapper used across Knowledge Base routes to apply consistent page padding and contain rendering errors within an error boundary scoped to that content area.

## Key Components

- **`KnowledgeBasePageShellProps`** — Props interface:
  - `errorMessage` (`string`): Message displayed if a child throws during render.
  - `resetKey` (`string`, optional): Changing this value (typically a record ID) resets the error boundary, allowing recovery when navigating between records.
  - `children` (`ReactNode`): The page content to render inside the shell.
- **`KnowledgeBasePageShell`** — Functional component that wraps `children` in a padded `div` and a `ContentErrorBoundary`, keeping the error boundary and page padding coupled so a thrown error doesn't collapse the layout's spacing.

## Usage Example

```typescript
import { KnowledgeBasePageShell } from '@/app/(knowledge-base)/knowledge-base-page-shell';

export default function ArticlePage({ searchParams }: { searchParams: { id?: string } }) {
  return (
    <KnowledgeBasePageShell
      errorMessage="Failed to load the knowledge base article."
      resetKey={searchParams.id}
    >
      <ArticleContent id={searchParams.id} />
    </KnowledgeBasePageShell>
  );
}
```

Use this shell in any route under the Knowledge Base section to ensure consistent padding and isolated error handling. Pass `resetKey` whenever the page renders data tied to an identifier (e.g., article or category ID), so switching records clears any previously triggered error state instead of leaving the boundary tripped.
