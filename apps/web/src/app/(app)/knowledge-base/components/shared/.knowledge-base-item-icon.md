# knowledge-base-item-icon.ts

Defines a centralized mapping between Knowledge Base item types and their corresponding icon components, ensuring consistent visual representation across the application.

## Key Components

- **`KB_ITEM_ICON`** — A constant record mapping each `KnowledgeBaseItemType` enum value to its icon component:
  - `KnowledgeBaseItemType.ARTICLE` → `BookTextIcon`
  - `KnowledgeBaseItemType.FOLDER` → `FolderIcon`

The `satisfies Record<KnowledgeBaseItemType, typeof BookTextIcon>` constraint guarantees type safety, ensuring every enum member has a corresponding icon and that all icons share a compatible component type.

## Usage Example

```typescript
import { KB_ITEM_ICON } from './knowledge-base-item-icon';
import { KnowledgeBaseItemType } from '@/generated/schema-enums';

// Render the correct icon for a KB item
function KnowledgeBaseRow({ type }: { type: KnowledgeBaseItemType }) {
  const Icon = KB_ITEM_ICON[type];
  return <Icon className="w-4 h-4" />;
}

// Usage in a table row
<KnowledgeBaseRow type={KnowledgeBaseItemType.ARTICLE} />
<KnowledgeBaseRow type={KnowledgeBaseItemType.FOLDER} />
```

This mapping is shared between the Knowledge Base listing page and Mingo's `@kb` / `@kbFolder` mention chips in chat, so items render with identical icons regardless of where they appear in the UI. Adding a new `KnowledgeBaseItemType` requires updating this map, and TypeScript will enforce completeness via the `satisfies` check.
