Lazily loads Markdown components using Next.js dynamic imports to prevent server-side rendering, optimizing bundle splitting for the `SimpleMarkdownRenderer` and `MarkdownEditor` components from `@flamingo-stack/openframe-frontend-core`.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `SimpleMarkdownRenderer` | Dynamic Component | Client-only markdown renderer, loaded lazily with no SSR |
| `MarkdownEditor` | Dynamic Component | Client-only markdown editor UI, loaded lazily with no SSR |

## Usage Example

```typescript
import { SimpleMarkdownRenderer, MarkdownEditor } from '@/components/lazy-markdown';

// Render markdown content
function ArticleView({ content }: { content: string }) {
  return <SimpleMarkdownRenderer content={content} />;
}

// Edit markdown content
function ArticleEditor({ value, onChange }: { value: string; onChange: (v: string) => void }) {
  return <MarkdownEditor value={value} onChange={onChange} />;
}
```

## Notes

- Both components are wrapped with `{ ssr: false }` — safe to use in client components but will not render during Next.js server-side rendering passes.
- `loading: () => null` suppresses any loading placeholder; add a skeleton if flash-of-empty-content is a concern.
- Props are fully typed via `ComponentProps<typeof ...>`, so consumers get the same TypeScript signatures as the original components.
