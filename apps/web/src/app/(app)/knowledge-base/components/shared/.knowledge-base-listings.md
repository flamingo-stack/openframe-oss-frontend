# knowledge-base-listings.ts

Relay store helper utilities for managing knowledge base item listings (folder contents, search results, tag filters) and the folder tree used by folder pickers. Centralizes the logic for keeping Relay connection records consistent after mutations like moves, deletes, archives, and folder creation.

## Key Components

- **`KnowledgeBaseListing`** — Interface describing one listing: `parentId` (folder, or `null` for root), `search`, and `tagIds`.
- **`isSubtreeListing(listing)`** — Returns `true` if a search term or tag filter is applied, meaning the listing spans multiple folders at any depth rather than a single level.
- **`knowledgeBaseListingArgs(listing)`** — Builds the GraphQL `filter`/`search` arguments for the `knowledgeBaseItems` query, matching how the table's connection is keyed in the Relay store.
- **`removeFromListings(store, listingIds, itemId)`** — Deletes an item's row from one or more connections; safely skips listings not present in the store.
- **`removeFromFolderListing(store, parentId, itemId)`** — Removes an item from a specific folder's plain (unfiltered) listing.
- **`invalidateFolderListing(store, parentId)`** — Marks a folder's listing stale so it refetches, used when an item is added rather than attempting to splice in an edge.
- **`moveBetweenFolders(store, move)`** — Handles a folder move: removes the row from the source folder, invalidates the destination folder and any on-screen subtree listings (search/tag views).
- **`invalidateArchiveListing(store)`** — Marks the archived articles connection stale.
- **`addToFolderTree(store, folder)`** / **`removeFromFolderTree(store, folderId)`** — Add/remove a folder record from the root's folder tree field used by folder-picker UIs.

## Usage Example

```typescript
import {
  knowledgeBaseListingArgs,
  moveBetweenFolders,
  invalidateFolderListing,
  addToFolderTree,
} from '@/relay/knowledge-base-listings';

// Build query args for a table fetching a folder's contents
const args = knowledgeBaseListingArgs({ parentId: 'folder-1', search: '', tagIds: [] });

// Inside a mutation updater, after moving an item between folders
moveBetweenFolders(store, {
  itemId: 'item-123',
  from: 'folder-1',
  to: 'folder-2',
  onScreen: [currentSearchListingId],
});

// After creating a new item under root
invalidateFolderListing(store, null);

// After creating a folder, keep folder pickers in sync
const folderRecord = store.get('new-folder-id');
if (folderRecord) addToFolderTree(store, folderRecord);
```
