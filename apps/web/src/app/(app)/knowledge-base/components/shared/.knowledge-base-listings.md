Relay store helpers for keeping knowledge base listings (folder/article tables, archive, and folder tree) consistent after local mutations, without relying on server-returned connection edges.

## Key Components

- **`KnowledgeBaseListing`** — interface describing a single listing: `parentId`, `search`, and `tagIds`.
- **`isSubtreeListing(listing)`** — determines whether a listing (due to search/tag filters) spans a subtree rather than a single folder level.
- **`knowledgeBaseListingArgs(listing)`** — builds the `filter`/`search` arguments used to construct a listing's connection key, matching what the table query sends.
- **`removeFromListings(store, listingIds, itemId)`** — removes an item's node from one or more connections in the Relay store.
- **`removeFromFolderListing(store, parentId, itemId)`** — removes an item from its unfiltered parent folder listing.
- **`invalidateFolderListing(store, parentId)`** — marks a folder's listing stale so it refetches, instead of guessing insertion order/position.
- **`moveBetweenFolders(store, move)`** — handles an item moving folders: removes it from the old folder listing and invalidates the new folder plus any other on-screen subtree listings.
- **`invalidateArchiveListing(store)`** — marks the archived-articles connection stale.
- **`addToFolderTree(store, folder)`** / **`removeFromFolderTree(store, folderId)`** — adds/removes a folder record from the root's folder tree field used by folder pickers.

## Usage Example

```typescript
import { moveBetweenFolders, invalidateArchiveListing, addToFolderTree } from './knowledge-base-listings';

// Inside a Relay mutation's updater function:
function updater(store: RecordSourceProxy) {
  const movedItem = store.get(itemId)!;

  moveBetweenFolders(store, {
    itemId: movedItem.getDataID(),
    from: previousParentId,
    to: newParentId,
    onScreen: currentListingIds, // other listings visible on screen, e.g. search results
  });

  // When archiving an article elsewhere in the same mutation:
  invalidateArchiveListing(store);

  // When a new folder is created:
  const newFolder = store.get(newFolderId);
  if (newFolder) addToFolderTree(store, newFolder);
}
```

These helpers are typically invoked from Relay mutation `updater`/`optimisticUpdater` functions to keep connection-backed tables (knowledge base items, archived articles) and the folder-picker tree synchronized after create/move/delete operations, favoring invalidation over manual edge insertion when ordering is server-determined.
