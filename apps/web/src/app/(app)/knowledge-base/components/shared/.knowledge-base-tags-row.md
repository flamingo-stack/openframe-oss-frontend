This client component renders a row of filterable knowledge base tags as selectable chips, with built-in support for Suspense-based loading states and nested loading scopes.

## Key Components

- **`KnowledgeBaseTagsRow`** — Public component that wraps the tag row in a `LoadingSuspense` boundary (labeled "Loading tags"), so the tag data fetch suspends independently of the rest of the toolbar.
- **`KnowledgeBaseTagsRowReader`** — Internal component that checks `useLoadingScope()`. If rendering inside a loading scope (e.g., a Suspense fallback), it renders `SelectableTagsRow` with an empty tag list (`NO_ITEMS`) and performs no data read, avoiding redundant fetches during fallback rendering.
- **`KnowledgeBaseTagsRowQuery`** — Internal component that calls `useKnowledgeBaseTags(parentId, archived)` to fetch the actual tags and renders them via `SelectableTagsRow`.

## Usage Example

```typescript
import { KnowledgeBaseTagsRow } from './knowledge-base-tags-row';
import type { SelectableTag } from '@/app/components/shared';

function KnowledgeBaseToolbar({ parentId }: { parentId: string | null }) {
  const [selectedIds, setSelectedIds] = useState<string[]>([]);

  const handleAdd = (tag: SelectableTag) => {
    setSelectedIds((prev) => [...prev, tag.id]);
  };

  return (
    <KnowledgeBaseTagsRow
      parentId={parentId}
      archived={false}
      selectedIds={selectedIds}
      onAdd={handleAdd}
    />
  );
}
```

The component is designed to be used within a toolbar or filter bar where tag-based filtering is needed. The `parentId` and `archived` props scope which tags are fetched, while `selectedIds` and `onAdd` manage the selection state externally. The internal loading-scope detection ensures the component gracefully degrades to an empty state when rendered as part of a parent Suspense fallback, preventing duplicate or unnecessary data fetching.
