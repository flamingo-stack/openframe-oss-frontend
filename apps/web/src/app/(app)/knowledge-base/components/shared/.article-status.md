Defines shared presentation and normalization logic for knowledge base article statuses, ensuring consistent status badge colors and fallback behavior across article list and detail views.

## Key Components

- **`ARTICLE_STATUS_VARIANT`** — A constant mapping each `KnowledgeBaseArticleStatus` value to a tag/badge color variant (`'success'`, `'warning'`, or `'grey'`). Typed with `satisfies Record<KnowledgeBaseArticleStatus, string>` to guarantee all enum values are covered at compile time.
- **`toArticleStatus(status)`** — A normalization function that converts a raw, possibly null/undefined status string into a valid `KnowledgeBaseArticleStatus`. Any value other than `PUBLISHED` or `ARCHIVED` is treated as `DRAFT`, reflecting the business rule that an article without an explicit status is a draft.

## Usage Example

```typescript
import { ARTICLE_STATUS_VARIANT, toArticleStatus } from '@/utils/article-status';
import { KnowledgeBaseArticleStatus } from '@/generated/schema-enums';

// Normalizing a raw status value from an API response
const rawStatus = article.status; // could be null, undefined, or any string
const status = toArticleStatus(rawStatus);

// Using the normalized status to pick a tag color
const variant = ARTICLE_STATUS_VARIANT[status];

// Example in a component template binding
// <Tag :variant="variant">{{ status }}</Tag>
```

This pattern ensures the article list and article detail page render identical status badges, since both derive their variant from the same `ARTICLE_STATUS_VARIANT` map and normalize raw data through `toArticleStatus`.
