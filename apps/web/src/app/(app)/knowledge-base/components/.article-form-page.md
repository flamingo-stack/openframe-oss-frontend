Orchestrates the create/edit page for knowledge base articles, rendering form fields within a `PageLayout` and handling both new-article and edit-article modes with Suspense-based loading states.

## Key Components

| Export / Component | Description |
|---|---|
| `ArticleFormPage` | Primary exported component; decides between edit and create mode, wraps in `Suspense` |
| `FormShell` | Inner form wrapper that wires up `useEditArticleForm`, navigation actions, and `ArticleFormFields` |
| `EditFormBody` | Fetches the existing article via `useKnowledgeBaseItem`; calls `notFound()` if the item is missing or not an `ARTICLE` type |
| `ArticleFormFallback` | Skeleton loading UI displayed while `Suspense` resolves |
| `ArticleFormPageProps` | Props interface: `articleId` (null for create) and optional `initialFolderId` |

## Usage Example

```typescript
// Create mode — no articleId
<ArticleFormPage articleId={null} initialFolderId="folder-123" />

// Edit mode — articleId provided
<ArticleFormPage articleId="article-abc" initialFolderId={null} />
```

## Behaviour Notes

- **Edit vs. Create** is determined by whether `articleId` is `null`; the `backButton` destination changes accordingly (`knowledgeBase.details` in edit mode, `knowledgeBase.list` in create mode).
- **Save actions** expose two variants — *Save as Draft* (`DRAFT`) and *Save and Publish* (`PUBLISHED`) — both disabled while `isSubmitting` is `true`.
- **Tags** are normalised via `useMemo` to `{ id, key }` pairs before being passed to `ArticleFormFields`.
- **`notFound()`** is called in `EditFormBody` when the fetched item is absent or not of type `ARTICLE`, delegating to Next.js's 404 handling.
