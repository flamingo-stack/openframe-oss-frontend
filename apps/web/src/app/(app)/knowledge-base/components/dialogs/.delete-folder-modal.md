# delete-folder-modal.tsx

A confirmation modal component for deleting a knowledge base folder, allowing the user to choose whether the folder's contents are archived or moved to another folder before deletion.

## Key Components

- **`DeleteFolderModal`** — The main exported component. Renders a `ConfirmDialog` with a folder picker that lets the user select a destination folder for the deleted folder's children (or archive them instead).
- **`deleteFolderModalFragment`** — GraphQL fragment fetching `id`, `name`, and `parentId` from a `KnowledgeBaseItem`.
- **`deleteFolderModalMutation`** — GraphQL mutation (`deleteFolder`) that performs the deletion, accepting a `childrenAction` (`MOVE` or `ARCHIVE`) and optional `moveTargetFolderId`.
- **`DeleteFolderModalProps`** — Props interface: `folder` (fragment key), `isOpen`, `onClose`, optional `listingIds` (listings on screen referencing the folder), and optional `onDeleted` callback.
- **`ARCHIVE_LABEL`** — Constant label `"Don't Move and Archive"` used as the default/leading option in the folder picker.

## Usage Example

```typescript
import { DeleteFolderModal } from '@/app/components/folders/delete-folder-modal';

function FolderActions({ folder, listingIds }: { folder: deleteFolderModal_folder$key; listingIds: string[] }) {
  const [isModalOpen, setModalOpen] = useState(false);

  return (
    <>
      <button onClick={() => setModalOpen(true)}>Delete Folder</button>
      <DeleteFolderModal
        folder={folder}
        isOpen={isModalOpen}
        onClose={() => setModalOpen(false)}
        listingIds={listingIds}
        onDeleted={() => router.push('/knowledge-base')}
      />
    </>
  );
}
```

**Behavior notes:**
- The mutation's `updater` removes the folder from all relevant Relay store listings (search results, folder listing, folder tree) and invalidates either the destination folder's listing or the archive listing, depending on the chosen action.
- The `destination` state resets when the modal transitions from open to closed, handled synchronously during render to avoid a stale value flashing during the close animation.
- Errors are surfaced via `getRelayErrorMessage` and displayed through the `useToast` hook.
