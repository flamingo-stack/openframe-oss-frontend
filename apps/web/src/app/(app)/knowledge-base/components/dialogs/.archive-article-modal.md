# archive-article-modal.tsx

A React client component that renders a confirmation dialog for archiving a knowledge base article, handling the GraphQL mutation and local Relay store updates to keep the UI in sync.

## Key Components

- **`ArchiveArticleModal`** — The main exported component. Displays a `ConfirmDialog` asking the user to confirm archiving an article, and executes the archive mutation on confirmation.
- **`archiveArticleModalFragment`** — GraphQL fragment fetching `id`, `name`, and `parentId` from a `KnowledgeBaseItem`.
- **`archiveArticleModalMutation`** — GraphQL mutation that calls `archiveArticle`, returning the updated `id`, `status`, and `updatedAt`.
- **`ArchiveArticleModalProps`** — Props interface:
  - `article` — Relay fragment reference (`archiveArticleModal_article$key`).
  - `isOpen` / `onClose` — Dialog visibility controls.
  - `listingIds` — Optional list of listing IDs currently displaying the article, used to prune the Relay store on archive.

## Usage Example

```typescript
import { useState } from 'react';
import { ArchiveArticleModal } from '@/app/components/.../archive-article-modal';
import type { archiveArticleModal_article$key } from '@/__generated__/archiveArticleModal_article.graphql';

function ArticleRow({ article }: { article: archiveArticleModal_article$key }) {
  const [isArchiveOpen, setArchiveOpen] = useState(false);

  return (
    <>
      <button onClick={() => setArchiveOpen(true)}>Archive</button>
      <ArchiveArticleModal
        article={article}
        isOpen={isArchiveOpen}
        onClose={() => setArchiveOpen(false)}
        listingIds={['search-results', 'folder-view']}
      />
    </>
  );
}
```

On confirmation, the component commits the mutation and applies an `updater` that removes the article from any provided listings, removes it from its parent folder listing, and invalidates cached archive listings so the archive view refreshes. Success and error states are surfaced via `useToast`.
