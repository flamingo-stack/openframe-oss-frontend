# use-article-form.ts

React hook powering the knowledge base article form, handling both create and edit flows by combining form state, attachment management, and save orchestration into a single cohesive API.

## Key Components

- **`useArticleForm(options)`** — Main hook that wires together `react-hook-form`, Zod validation, attachment handling, and save logic for the article form.
- **`UseArticleFormOptions`** — Input props: `articleId` (null for create mode), `initialFolderId` (folder context for new articles), and `stored` (the loaded article data, or null while loading/creating).
- **Return value** — `{ form, attachments, isSubmitting, handleSave }`:
  - `form`: the `react-hook-form` instance (typed with `ArticleFormData`)
  - `attachments`: attachment state/actions from `useArticleAttachments`
  - `isSubmitting`: boolean save-in-progress flag
  - `handleSave(status)`: submit handler accepting a `SaveStatus` (e.g., draft vs. published)

The hook also guards against double-submission via an `inFlightRef`, since `handleSubmit`'s async resolver leaves a window before `isSaving` disables the UI.

## Usage Example

```typescript
import { useArticleForm } from './use-article-form';

function ArticleEditor({ articleId, initialFolderId, stored }: {
  articleId: string | null;
  initialFolderId: string | null;
  stored: StoredArticle | null;
}) {
  const { form, attachments, isSubmitting, handleSave } = useArticleForm({
    articleId,
    initialFolderId,
    stored,
  });

  return (
    <form onSubmit={e => e.preventDefault()}>
      {/* form fields bound via `form.register` / `form.control` */}
      <button type="button" disabled={isSubmitting} onClick={() => handleSave('draft')}>
        Save Draft
      </button>
      <button type="button" disabled={isSubmitting} onClick={() => handleSave('published')}>
        Publish
      </button>
    </form>
  );
}
```

On successful save, the hook shows a success toast and navigates: new articles replace the route with the article's detail page; edited articles navigate back safely (or replace if no history) to the detail page via `safeBackOrReplace`.
