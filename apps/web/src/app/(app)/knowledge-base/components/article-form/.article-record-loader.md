## article-record-loader.tsx

A headless data-fetching component that loads a knowledge base article by ID via GraphQL and hands the parsed record to a parent callback, without rendering any visible UI itself.

## Key Components

- **`ArticleRecordLoader`** — Public entry point. Wraps the loading logic in a `LoadingSuspense` boundary (labeled "Loading article") so the page shows a single loading announcement while data resolves. Uses `className="contents"` so the boundary doesn't affect page layout.
- **`ArticleRecordReader`** — Internal guard that returns `null` while still inside the loading scope (i.e., while the Suspense fallback is active), preventing premature queries.
- **`ArticleRecordQuery`** — Performs the actual Relay query (`articleRecordLoaderQuery`) using `useLazyLoadQuery`, verifies the item is of type `ARTICLE`, converts it via `readArticleFormRecord`, and invokes `onResolved` inside a `useLayoutEffect` so the parent form is seeded before paint. Calls `notFound()` if the ID doesn't resolve to an article (e.g., unknown ID or a folder).

## Usage Example

```typescript
import { ArticleRecordLoader } from './article-record-loader';
import type { ArticleFormRecord } from './article-form-record';

function EditArticlePage({ articleId }: { articleId: string }) {
  const handleResolved = (record: ArticleFormRecord) => {
    // Seed the form state here, e.g. via useSeedForm(record)
    seedForm(record);
  };

  return (
    <>
      <ArticleRecordLoader articleId={articleId} onResolved={handleResolved} />
      {/* Rest of the edit form UI */}
    </>
  );
}
```

**Notes:**
- This component renders no visible output; it exists purely to fetch data and trigger a callback.
- The `record` passed to `onResolved` is memoized by article identity, ensuring `useSeedForm`-style consumers only re-seed when the underlying data actually changes.
- Relies on `useRetryKey` for refetch support and `fetchPolicy: 'store-and-network'` to prefer cached data while revalidating.
