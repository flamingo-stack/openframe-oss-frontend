# use-article-image-upload.ts

React hook that provides an inline image upload handler for the markdown article editor, uploading images to a durable, GET-able URL that can be safely embedded in persisted markdown content (unlike presigned attachment URLs, which expire).

The upload flow works in two steps: the client first requests upload metadata from the backend (`POST /api/knowledge-base/images`), receiving a presigned `uploadUrl` plus a stable `url`; it then `PUT`s the raw file bytes to `uploadUrl`. The returned stable `url` (e.g. `/knowledge-base/images/<id>`) redirects to a freshly signed URL on every `GET`, so it remains valid indefinitely inside saved markdown.

Validation guards against unsupported file types (only JPG, PNG, WebP are allowed, mirroring the backend's `openframe.kb.images.allowed-types` whitelist) and oversized files (10 MB limit), surfacing user-friendly toast notifications before any network call is made.

## Key Components

- **`ARTICLE_IMAGE_UPLOAD_ENDPOINT`** — API endpoint for creating image upload metadata.
- **`MAX_IMAGE_SIZE_BYTES`** — 10 MB upload size limit.
- **`ALLOWED_IMAGE_TYPES`** / **`ALLOWED_IMAGE_TYPES_LABEL`** — Whitelisted MIME types and their human-readable label.
- **`uploadArticleImage(file)`** — Internal async function handling the metadata request + presigned `PUT` upload, returning the durable image URL.
- **`useArticleImageUpload()`** — Hook returning a memoized `(file: File) => Promise<string>` callback intended for the `onUploadFile` prop of `MarkdownEditor`. Validates type/size, performs the upload, and shows `toast` notifications on failure.

## Usage Example

```typescript
import { useArticleImageUpload } from '@/hooks/use-article-image-upload';

function ArticleEditor() {
  const handleUploadFile = useArticleImageUpload();

  return (
    <MarkdownEditor
      onUploadFile={handleUploadFile}
      // ...other editor props
    />
  );
}
```

When a user pastes or uploads an image via the toolbar, the editor calls `handleUploadFile(file)`, which validates the file, uploads it, and inserts `![name](url)` using the resolved durable URL. Invalid files or failed uploads throw an error after displaying a destructive toast.
