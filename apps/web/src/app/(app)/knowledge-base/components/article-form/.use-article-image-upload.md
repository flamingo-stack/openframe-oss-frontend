# use-article-image-upload.ts

React hook that provides an image upload handler for inline images embedded in knowledge-base article markdown content via the MarkdownEditor component.

Unlike temporary attachment uploads (which use expiring presigned URLs), inline article images require a durable, directly GET-able URL since the editor persists the URL inside the markdown content itself. This hook implements a two-step flow: it first requests upload metadata from the backend, then PUTs the file bytes to a presigned upload URL, and finally returns a stable `/knowledge-base/images/<id>` path that redirects to a fresh signed URL whenever it's accessed.

The hook also enforces client-side validation (file type and 10 MB size limit) matching the backend whitelist, surfacing user-friendly toast notifications on failure so unsupported uploads fail fast with clear messaging.

## Key Components

- **`useArticleImageUpload()`** — Hook returning a memoized async callback compatible with MarkdownEditor's `onUploadFile` prop. Validates file type/size, uploads the image, and returns the durable URL to embed as `![name](url)`.
- **`uploadArticleImage(file: File)`** — Internal async function handling the two-step upload: requests `{ url, uploadUrl, uploadHeaders }` metadata via POST, then PUTs the raw file to `uploadUrl`.
- **`ALLOWED_IMAGE_TYPES`** — Whitelist of accepted MIME types (`image/jpeg`, `image/png`, `image/webp`), mirroring the backend's `openframe.kb.images.allowed-types` config.
- **`MAX_IMAGE_SIZE_BYTES`** — 10 MB upload size cap.
- **`CreateArticleImageResponse`** — Interface describing the backend's upload-metadata response shape.

## Usage Example

```typescript
import { useArticleImageUpload } from '@/hooks/use-article-image-upload';

function ArticleEditor() {
  const handleUploadFile = useArticleImageUpload();

  return (
    <MarkdownEditor
      onUploadFile={handleUploadFile}
      // handleUploadFile validates, uploads, and returns
      // a durable URL to insert as `![name](url)` in markdown
    />
  );
}
```

On invalid file type or oversized file, the hook shows a destructive toast and throws, preventing the editor from inserting the image. On successful upload, it returns the stable image URL resolved via `getFullImageUrl`.
