A modal component for filtering Knowledge Base entries by tags, wrapping a `FilterModal` with tag data fetching and Suspense-based loading.

## Key Components

- **`KnowledgeBaseTagsFilterModal`** — Public export; gates content behind `Suspense` (fallback `null`) until tags resolve
- **`KnowledgeBaseTagsFilterModalContent`** — Inner component that fetches tags via `useKnowledgeBaseTags` and maps them to `FilterModal` checkbox options
- **`TAGS_GROUP_ID`** — Constant `'tags'`; single filter group ID since Knowledge Base tags are flat (no key:value hierarchy)
- **`KnowledgeBaseTagsFilterModalProps`** — Props interface defining open state, tag selection, folder scope (`parentId`), archive filtering, and an `onApply` callback with replace semantics

## Usage Example

```typescript
import { KnowledgeBaseTagsFilterModal } from './knowledge-base-tags-filter-modal';
import type { SelectedKnowledgeBaseTag } from './knowledge-base-tags-row';

function MyComponent() {
  const [isOpen, setIsOpen] = useState(false);
  const [selectedTags, setSelectedTags] = useState<SelectedKnowledgeBaseTag[]>([]);

  return (
    <KnowledgeBaseTagsFilterModal
      isOpen={isOpen}
      onClose={() => setIsOpen(false)}
      parentId="folder-123"
      selectedIds={selectedTags.map(t => t.id)}
      archived={false}
      onApply={(tags) => {
        setSelectedTags(tags); // replace semantics
        setIsOpen(false);
      }}
    />
  );
}
```

## Behavior Notes

- `currentFilters` is re-seeded from `selectedIds` each time the modal opens, ensuring pre-checked state reflects the current applied filters
- `onApply` receives the full new selection (replace, not merge); the resolved tags are surfaced as chips in the parent search field
- Tag loading is suspended — the modal renders nothing until `useKnowledgeBaseTags` resolves, preventing flash of empty state
