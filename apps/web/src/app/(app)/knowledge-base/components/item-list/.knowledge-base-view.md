# knowledge-base-view.tsx

Renders a single level (root or folder) of the knowledge base, managing URL-driven search/tag filters, a sticky toolbar, header actions, and the New Folder dialog. The folder's title component owns its own loading boundary, so the page header can render immediately while folder data streams in separately from the article rows.

## Key Components

- **`KnowledgeBaseView`** — Main component accepting a `folderId` (string or `null` for root). Renders either `KnowledgeBaseListTitle` (root) or `KnowledgeBaseFolderTitle` (nested folder), a conditional search toolbar, and `KnowledgeBaseItemsTable` for the article rows.
- **`pageActions(folderId, onNewFolder, emphasizeAddArticle, generateWithAi)`** — Builds the header action buttons (`New Folder`, `Add Article`, and `Archive` for root only). Accents "Add Article" when the current level is empty.
- **`KnowledgeBaseViewProps`** — Props interface: `{ folderId: string | null }`.

## Usage Example

```typescript
import { KnowledgeBaseView } from './knowledge-base-view';

// Root level of the knowledge base
export default function KnowledgeBasePage() {
  return <KnowledgeBaseView folderId={null} />;
}

// Nested folder view
export default function KnowledgeBaseFolderPage({
  params,
}: {
  params: { folderId: string };
}) {
  return <KnowledgeBaseView folderId={params.folderId} />;
}
```

### Behavior notes
- Uses `useTagSearchState` and `useDeferredQuery` to debounce and defer search/tag filtering so stale data doesn't flash during transitions.
- Uses `useStickyToolbar` to pin the search toolbar and pass a `stickyHeaderOffset` down to the table for correct sticky positioning.
- The search toolbar is hidden entirely when the level has no items (`isEmpty`), since there's nothing to search.
- Only the root (`folderId === null`) exposes the "Archive" action, since archived items span the whole knowledge base rather than a single folder.
