# knowledge-base-item-actions-cell.tsx

Renders the row-level "⋯" actions menu for a Knowledge Base table row, adapting its menu options based on whether the row represents a folder or an article.

## Key Components

- **`knowledgeBaseItemActionsCellFragment`** — GraphQL fragment pulling `id` and `type` from a `KnowledgeBaseItem`.
- **`ItemDialogKind`** — Type union of dialog kinds a row's menu can open: a folder's dialog kinds (`FolderDialogKind`) or `'archive'`.
- **`articleMenuGroups(articleId, onOpen)`** — Builds the `ActionsMenuGroup[]` for an article row: Edit (navigates via `routes.knowledgeBase.edit`), Move to folder, and Archive (both trigger dialogs via `onOpen`).
- **`KnowledgeBaseItemActionsCell`** — The exported component. Reads the fragment (skipping it while in a loading scope), picks `folderMenuGroups` or `articleMenuGroups` based on `KnowledgeBaseItemType`, and renders `ActionsMenuDropdown`.

## Usage Example

```typescript
import { KnowledgeBaseItemActionsCell } from './knowledge-base-item-actions-cell';

function KnowledgeBaseRow({ itemRef }: { itemRef: knowledgeBaseItemActionsCell_item$key }) {
  const { openDialog } = useRowDialog();

  return (
    <tr>
      {/* ...other cells... */}
      <td>
        <KnowledgeBaseItemActionsCell
          item={itemRef}
          onOpen={(dialogKind) => openDialog(dialogKind)}
        />
      </td>
    </tr>
  );
}
```

**Notes:**
- The `onOpen` callback is owned by the table (via `useRowDialog`), not the row itself, so dialog state persists independently of row re-renders.
- The `data-no-row-click` attribute prevents the row's own click/link handler from firing when the menu is interacted with.
- During a loading scope, the fragment is intentionally not read, producing an inert trigger with empty menu groups until real data resolves.
