## article-detail-content.tsx

Client component that loads a knowledge base article by its Relay global ID and renders it, handling loading states and Mingo context tracking independently from its parent page.

## Key Components

- **`articleDetailContentQuery`** — GraphQL query fetching a `knowledgeBaseItem` by `id`, including its `type`, `name`, and the `articleDetail_article` fragment. The query resolves to `null` for unknown IDs rather than throwing.
- **`ArticleDetailContent(props: { articleId: string })`** — Top-level export. Wraps the reader in a `LoadingSuspense` boundary (with a "Loading article" label) so this subtree can load independently of the rest of the page.
- **`ArticleDetailContentReader`** — Checks `useLoadingScope()`; if in a loading scope (e.g., optimistic/skeleton render), renders `ArticleDetail` with a `null` article and skips fetching entirely.
- **`ArticleDetailContentQuery`** — Executes the Relay query via `useLazyLoadQuery` with `store-and-network` fetch policy and a retry key. Validates the item is of type `ARTICLE`, registers it as the active Mingo "open view" (re-encoding the Relay global ID to the raw DB ID expected by Mingo), and calls `notFound()` if no valid article exists (unknown ID or a folder instead of an article).

## Usage Example

```typescript
import { ArticleDetailContent } from './article-detail-content';

export default function ArticlePage({ params }: { params: { id: string } }) {
  return <ArticleDetailContent articleId={params.id} />;
}
```

The component self-contains its loading UI and data fetching—callers simply pass the Relay global `articleId` and don't need to manage suspense boundaries or Mingo view tracking separately.
