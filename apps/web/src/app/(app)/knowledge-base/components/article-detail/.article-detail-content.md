## article-detail-content.tsx

Client component that fetches and renders a knowledge base article by its Relay global ID, handling loading states, Mingo view tracking, and not-found scenarios.

## Key Components

- **`ArticleDetailContent`** — Top-level export that wraps the data-fetching component in a `LoadingSuspense` boundary, giving the article section its own independent loading indicator.
- **`ArticleDetailContentReader`** — Checks `useLoadingScope()` to render a skeleton (`ArticleDetail` with `null` article) during scope-wide loading transitions instead of triggering a new fetch.
- **`ArticleDetailContentQuery`** — Executes the `articleDetailContentQuery` GraphQL query via `useLazyLoadQuery`, validates the item is an `ARTICLE` type, registers the article as the active Mingo "open view", and calls `notFound()` when the article doesn't exist or isn't an article (e.g., it's a folder).
- **`articleDetailContentQuery`** — GraphQL query fetching `knowledgeBaseItem` by ID, including `type`, `name`, and the `articleDetail_article` fragment. The field is nullable, so unknown IDs resolve to `null` rather than throwing.

## Usage Example

```typescript
import { ArticleDetailContent } from './article-detail-content';

export default function ArticlePage({ params }: { params: { articleId: string } }) {
  return <ArticleDetailContent articleId={params.articleId} />;
}
```

### Notes

- Uses `decodeGlobalId` to convert the Relay global ID back into the raw database ID required by Mingo's context tracking (`useTrackOpenView`).
- `useRetryKey` supplies a `fetchKey` so the query can be manually re-triggered (e.g., after an error retry) without remounting the component tree.
- The `fetchPolicy: 'store-and-network'` ensures cached data renders immediately while a background refresh keeps it current.
