Next.js page component that renders the edit view for an existing Knowledge Base article, resolving and validating the article `id` from the URL query string before rendering the form.

## Key Components

- **`EditArticlePage`** — Default-exported page component (Client Component) responsible for:
  - Extracting and validating the `id` query parameter via `useRequiredIdParam`.
  - Redirecting to the knowledge base list if `id` is missing, or to the "new article" route if `id=new`.
  - Rendering `null` while a redirect is in progress.
  - Wrapping `ArticleFormView` in `KnowledgeBasePageShell` for consistent layout and error handling.
  - Keying `ArticleFormView` by `id` so the component remounts cleanly when navigating between different article IDs within the same route segment.

## Usage Example

This page is automatically rendered by Next.js routing (e.g., at a route like `/knowledge-base/edit?id=123`) and isn't typically imported directly. The pattern it follows can be reused for similar "edit by id" pages:

```typescript
'use client';

import { useRequiredIdParam } from '@/app/hooks/use-required-id-param';
import { routes } from '@/lib/routes';

export default function EditEntityPage() {
  const id = useRequiredIdParam(routes.entity.list, routes.entity.new());
  if (!id) {
    return null; // Redirect in progress
  }

  return <EntityFormView key={id} entityId={id} />;
}
```

**Notes:**
- Visiting the route without `?id=` redirects to `routes.knowledgeBase.list`.
- Visiting with `?id=new` redirects to `routes.knowledgeBase.new()`.
- The `key={id}` prop ensures React treats each article id as a distinct component instance, forcing a clean remount of form state when switching between articles.
