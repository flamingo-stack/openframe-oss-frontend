Next.js page component that renders the Knowledge Base article edit screen, resolving the article ID from the URL query string and handling redirect edge cases.

## Key Components

- **`EditArticlePage`** – Default-exported page component. Reads the `?id=` query parameter via `useRequiredIdParam`, redirecting to the knowledge base list if the param is missing, or to the "new article" page if `id=new`. Renders `null` while a redirect is in progress.
- **`useRequiredIdParam`** – Hook (imported) that enforces presence of a required `id` query param, performing navigation side effects when it's absent or set to the `new` sentinel value.
- **`KnowledgeBasePageShell`** – Shared layout/error-boundary wrapper that provides a consistent shell (including error message display) for knowledge base pages.
- **`ArticleFormView`** – The actual article editing form, re-mounted via the `key={id}` prop whenever the article `id` changes, ensuring fresh form state per article.

## Usage Example

```typescript
// Accessed via a route such as /knowledge-base/edit?id=123
// Next.js automatically renders this as the page component.

// Internally, navigation to this page is typically triggered like:
import { routes } from '@/lib/routes';
import { useRouter } from 'next/navigation';

function NavigateToEdit({ articleId }: { articleId: string }) {
  const router = useRouter();
  return (
    <button onClick={() => router.push(`${routes.knowledgeBase.edit}?id=${articleId}`)}>
      Edit Article
    </button>
  );
}
```

**Notes:**
- If `?id=` is omitted, the user is redirected to `routes.knowledgeBase.list`.
- If `?id=new`, the user is redirected to `routes.knowledgeBase.new()`.
- The `key={id}` on `ArticleFormView` forces React to unmount/remount the form when switching between articles within the same route segment, preventing stale form state.
