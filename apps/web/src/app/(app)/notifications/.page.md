Next.js page component that renders the Notifications section of the application, wrapping the main view in a shared error boundary for resilient error handling.

## Key Components

- **`NotificationsPage`** — Default export; a client-side page component (`'use client'`) that serves as the route entry point for the notifications page.
- **`ContentErrorBoundary`** — Shared wrapper component providing a fallback UI (title and message) if rendering the notifications content fails.
- **`NotificationsPageView`** — The actual notifications content/logic, imported from a local `components` directory.

## Usage Example

This file is a Next.js page and is automatically routed based on its file path (e.g., `app/notifications/page.tsx`). It requires no manual invocation:

```typescript
// Automatically rendered by Next.js when navigating to the
// corresponding route (e.g., /notifications)

export default function NotificationsPage() {
  return (
    <ContentErrorBoundary title="Notifications" message="Couldn't load notifications.">
      <NotificationsPageView />
    </ContentErrorBoundary>
  );
}
```

The `ContentErrorBoundary` ensures that if `NotificationsPageView` throws an error during rendering (e.g., due to a failed API call), users see a friendly fallback message ("Notifications" / "Couldn't load notifications.") instead of a broken page.
