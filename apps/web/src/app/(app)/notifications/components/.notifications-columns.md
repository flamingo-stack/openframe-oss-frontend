# notifications-columns.tsx

Defines the column configuration and cell renderers for the notifications data table, rendering notification title, details, action button, and row controls (mark-as-read / delete) with loading-skeleton support.

## Key Components

- **`NotificationRow`** — Interface representing a table row: notification metadata (`id`, `title`, `description`, `createdAt`, `read`, `archived`) plus the underlying `Notification` object.
- **`buildNotificationColumns({ rowVariant, onMarkRead, onDelete })`** — Builds the `ColumnDef<NotificationRow>[]` array consumed by the table component. Produces four columns: `notification` (icon/title/time), `details` (kind label + description, hidden on small screens), `action` (context-aware action button/split-button/external link), and `rowIcon` (mark-as-read or delete control based on `rowVariant`).
- **`NotificationTitle`** — Renders the truncated title plus an "Archived" tag when applicable.
- **`NotificationCell`** — Renders the leading icon, title, and relative timestamp; collapses title+description into one cell on mobile when the details column is hidden.
- **`NotificationDetailsCell`** — Renders the notification's kind label and truncated (2-line) description.
- **`RowIconCell`** — Renders either a "Mark as done" button (unread rows) or a "Delete" button (read rows).
- **`titleColorBySeverity`** — Maps `NotificationSeverity` (`DANGER`, `WARNING`, `SUCCESS`) to Tailwind text color classes for the title.
- **`DESCRIPTION_LINES`** — Constant (2) controlling how many lines of description show before truncation, chosen to keep consistent row height for skeleton loading.

## Usage Example

```typescript
import { buildNotificationColumns, type NotificationRow } from './notifications-columns';
import { DataTable } from '@flamingo-stack/openframe-frontend-core/components/ui';

function UnreadNotificationsTable({ rows }: { rows: NotificationRow[] }) {
  const columns = buildNotificationColumns({
    rowVariant: 'unread',
    onMarkRead: (id) => markNotificationRead(id),
    onDelete: (id) => deleteNotification(id),
  });

  return <DataTable columns={columns} data={rows} />;
}
```

The action column automatically resolves the correct interaction (external link, in-app route via `SplitButton`, or a Mingo dialog opened in-page) based on `resolveNotificationAction`, and clears the unread/archived flag via `onMarkRead` when appropriate.
