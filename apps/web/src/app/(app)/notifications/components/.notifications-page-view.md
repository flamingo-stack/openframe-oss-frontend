Top-level page component that renders the Notifications page with two tabs (New/History), managing Relay-powered data loading, search, entity-scoped filtering, and live read-status updates.

## Key Components

- **`NotificationsPageView`** — the main exported React component. Renders a `TabNavigation` with "New Notifications" and "Notifications History" tabs, each backed by a `NotificationsSection` fed from independently loaded Relay queries.
- **`NOTIFICATIONS_TABS`** — static tab configuration (id, label, icon) for the two views.
- **Entity scope handling** — parses `entityType`/`entityId`/`entityName` URL params via `parseNotificationEntityScope` to scope the page to a single entity (e.g., opened from a row's unread count), with a `clearEntity` action to reset scope.
- **Search** — shared debounced search state (`useSearchParam`) synced to the URL, reset on tab change.
- **Relay query loaders** — `useQueryLoader` instances for the "new" (unread) and "history" (read) tabs, refetched whenever filters (`search`, `entity`) change via `filterPairs` built with `notificationsConnectionFilters`.
- **Live updates** — registers connection pairs (`registerLiveConnectionPairs`) so live read-state events update the correct filtered Relay connections, and subscribes to `subscribeReadStatusRefresh` to debounce-refetch the history tab (e.g., after ticket archival) while preserving already-loaded row count.
- **Mutations** — uses `useNotificationMutations` for `markRead`, `markAllRead`, `markEntityRead`, `removeNotification`, and `removeAllRead`, each wired to success toasts.
- **Actions & dialogs** — builds `PageActionButton[]` arrays (`newActions`, `historyActions`) per tab, and a `ConfirmDialog` guarding the destructive "Delete All" history action.

## Usage Example

```typescript
// Typically rendered directly by a Next.js route/page file
import { NotificationsPageView } from '@/app/notifications/notifications-page-view';

export default function NotificationsPage() {
  return <NotificationsPageView />;
}
```

The component relies on URL query params (`tab`, `search`, `entityType`, `entityId`, `entityName`) for state, so navigating to a URL like `/notifications?entity Type=ticket&entityId=123&entityName=Printer+Issue` opens the page pre-scoped to that entity's notifications.
