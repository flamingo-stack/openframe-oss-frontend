## facet-options.ts

Utility module for converting server-driven facet data into filter dropdown options for table columns. It handles label-sorting, server-enum-to-UI-id mapping, and pending/loading state representation for filter funnels.

## Key Components

- **`FacetOption`** — Interface representing a single filter dropdown option (`id`, `label`, `value`, `count`).
- **`FacetEntry`** — Interface representing a raw server facet entry (`value`, `label`, `count`).
- **`facetToSortedOptions(facet)`** — Maps server facet entries directly to `FacetOption[]`, preserving `value` verbatim (so it round-trips through URL params), sorted alphabetically by label.
- **`facetToMappedOptions(facet, toId)`** — Maps server facet entries to `FacetOption[]` via a `toId` resolver function, used when the server's enum values don't match UI ids (e.g., platform/shell filters). Entries resolving to the same id have their counts merged; entries with no matching id are dropped. Preserves server order.
- **`facetFilter(options)`** — Wraps resolved options (or `null`/`undefined` while loading) into a column's `meta.filter` shape, returning a `pending: true` marker when data hasn't arrived yet so loading-state tables still render filter funnels.

## Usage Example

```typescript
import { facetToSortedOptions, facetToMappedOptions, facetFilter } from './facet-options';

// Direct mapping (value matches server filter input, e.g. machineIds)
const machineOptions = facetToSortedOptions(data?.machineFacet);

// Enum-to-UI-id mapping (e.g. platform facet: MAC_OS / MACOS -> darwin)
const platformToId = (value: string): string | null => {
  if (value === 'MAC_OS' || value === 'MACOS') return 'darwin';
  if (value === 'WINDOWS') return 'windows';
  return null;
};
const platformOptions = facetToMappedOptions(data?.platformFacet, platformToId);

// Column definition using pending-aware filter meta
const column = {
  accessorKey: 'machineId',
  meta: {
    filter: facetFilter(isLoading ? undefined : machineOptions),
  },
};
```
