Utility functions for building device filters and mapping script platform identifiers for script execution and testing flows (e.g., run-script and test-run device pickers).

## Key Components

- **`testDeviceFilter(supportedPlatforms)`** — Builds a `DeviceFilterInput` restricted to `ONLINE` devices only, used by test-run pickers that require the device to be reachable immediately.
- **`runDeviceFilter(supportedPlatforms)`** — Builds a `DeviceFilterInput` allowing both `ONLINE` and `OFFLINE` devices, used by run-script pickers that can dispatch to devices asynchronously.
- **`mapPlatformsToOsTypes(platforms)`** — Converts script-level platform strings (`windows`, `darwin`, `linux`) into device filter `osTypes` values (`WINDOWS`, `MAC_OS`). Note: `linux` has no mapping and is dropped.
- **`mapPlatformsForDisplay(platforms)`** — Converts script-level platform strings into human-readable display labels (`Windows`, `macOS`, `Linux`).
- **Re-exports:** `AVAILABLE_PLATFORMS`, `DISABLED_PLATFORMS` from `@/lib/platforms`.

## Usage Example

```typescript
import { testDeviceFilter, runDeviceFilter, mapPlatformsForDisplay } from './script-utils';

const supportedPlatforms = ['windows', 'darwin'];

// Test-run modal: only online devices matching OS
const testFilter = testDeviceFilter(supportedPlatforms);
// => { statuses: ['ONLINE'], osTypes: ['WINDOWS', 'MAC_OS'] }

// Run-script page: online or offline devices matching OS
const runFilter = runDeviceFilter(supportedPlatforms);
// => { statuses: ['ONLINE', 'OFFLINE'], osTypes: ['WINDOWS', 'MAC_OS'] }

// Display-friendly labels for UI badges
const labels = mapPlatformsForDisplay(supportedPlatforms);
// => ['Windows', 'macOS']
```

These helpers ensure the v2 and legacy UI surfaces share consistent device-filtering and platform-mapping logic, preventing drift between implementations.
