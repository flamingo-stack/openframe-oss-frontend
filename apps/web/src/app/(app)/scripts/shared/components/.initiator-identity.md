# initiator-identity.tsx

Renders the "Executed by" identity cell shared by execution and run pages/tables, combining a user avatar and a linked name with built-in loading and deleted-user states.

## Key Components

- **`Initiator`** — Interface describing the dispatcher of an execution/run: `id`, `name`, `initials`, optional `image`, and a `deleted` flag.
- **`toInitiator(node)`** — Maps a GraphQL `InitiatorNode` (as selected by execution/run queries) into a normalized `Initiator` object, resolving image URLs and deleted-status.
- **`InitiatorAvatar`** — Renders the initiator's avatar; shows `DeletedUserAvatar` if the account is deleted, otherwise a `SquareAvatar` with image/initials fallback.
- **`InitiatorName`** — Renders the initiator's name, linked to their employee detail page when resolvable. Behaves as a button (new-tab, opts out of row click) when `inRow` is true, or a plain `<a>` link otherwise. Supports a loading skeleton state.
- **`InitiatorIdentity`** — The combined avatar + name cell; toggles into skeleton/loading mode automatically via `useLoadingScope()` or an explicit `loading` prop.

## Usage Example

```typescript
import { toInitiator, InitiatorIdentity } from './initiator-identity';

function ExecutionRow({ executionNode }: { executionNode: InitiatorNode }) {
  const initiator = toInitiator(executionNode);

  return (
    <InitiatorIdentity
      initiator={initiator}
      size="sm"
      inRow
      loading={false}
    />
  );
}
```

In a standalone page (not inside a clickable row), omit `inRow` so the name renders as a regular link:

```typescript
<InitiatorIdentity initiator={toInitiator(execution.initiator)} size="md" />
```

Loading state is typically driven automatically by wrapping content in a loading scope provider, but can also be forced via the `loading` prop for skeleton placeholders while data is in flight.
