Renders the script details page, resolving the script ID from the URL query string and delegating rendering to the `ScriptDetailsView` component, wrapped in an error boundary for graceful failure handling.

## Key Components

- **`ScriptDetailsPage`** (default export): Next.js page component that reads the `id` query parameter via `useSearchParams` and passes it to `ScriptDetailsView`.
- **`ContentErrorBoundary`**: Shared error boundary component that displays a fallback title/message if rendering the script details fails.
- **`ScriptDetailsView`**: Feature component responsible for fetching and displaying the actual script details based on `scriptId`.

## Usage Example

```typescript
// Navigated to via a URL like: /scripts/details?id=abc123
// Next.js automatically renders this page component for that route.

export default function ScriptDetailsPage() {
  const id = useSearchParams().get('id') ?? '';
  return (
    <ContentErrorBoundary title="Script" message="Couldn't load this script.">
      <ScriptDetailsView scriptId={id} />
    </ContentErrorBoundary>
  );
}
```

**Notes:**
- Marked as a client component (`'use client'`) since it relies on the `useSearchParams` hook.
- Defaults `id` to an empty string if the query parameter is missing, preventing undefined-related errors downstream.
- Error handling is isolated to this page's content via `ContentErrorBoundary`, ensuring failures don't crash the broader app shell.
