This client-rendered Next.js page component that reads a script `id` from the URL query parameters and renders the `RunScriptView` for executing that script.

## Key Components

- **`RunScriptPage`** — Default exported page component. Reads the `id` query parameter via `useSearchParams` and passes it as `scriptId` to `RunScriptView`.

## Usage Example

This page is automatically routed by Next.js based on its file location (e.g., `app/.../run-script/page.tsx`). It's accessed via a URL containing an `id` query parameter:

```typescript
// Navigating to this page, e.g.:
// /scripts/run-script?id=abc123

// The page extracts the id and renders the script execution view:
export default function RunScriptPage() {
  const id = useSearchParams().get('id') ?? '';

  return <RunScriptView scriptId={id} />;
}
```

To link to this page from elsewhere in the app:

```typescript
import { useRouter } from 'next/navigation';

const router = useRouter();
router.push(`/scripts/run-script?id=${scriptId}`);
```

## Notes

- Marked with `'use client'` since it relies on the `useSearchParams` hook, which requires client-side rendering.
- If `id` is missing from the URL, an empty string is passed as `scriptId`; `RunScriptView` is expected to handle this case (e.g., showing a loading or error state).
- The component does not wrap `RunScriptView` in a `Suspense` boundary itself, since `RunScriptView` manages its own loading state internally.
