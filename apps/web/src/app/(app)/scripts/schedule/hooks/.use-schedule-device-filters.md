# use-schedule-device-filters.ts

A React hook that provides scoped device filter facets for one half (assigned or available) of a schedule's device sets, used to populate filter dropdowns without narrowing the result set the user is building.

## Key Components

- **`ScheduleDeviceHalf`** — Type alias for `'assigned' | 'available'`, identifying which device set a schedule's facets describe.
- **`ScheduleDeviceFiltersOptions`** — Options interface with `prefetchOtherHalf`, which fetches both halves' facets in one query so tab switches read from the Relay store instead of suspending.
- **`useScheduleDeviceFilters(scheduleId, half, options?)`** — Main hook returning `DeviceFilters` for the specified half of a given schedule.

The hook queries `scheduleDeviceFiltersRelayQuery` with an **unfiltered** (`UNFILTERED`) variable set deliberately — this keeps every filter dropdown showing all possible values for its half rather than collapsing options as the user narrows their selection, since the GraphQL schema can't express "exclude this dimension from its own facet" in a single round trip. Narrowed counts are instead reported by the device list's own `filteredCount`.

Tags are sourced from the fleet-wide `useDeviceFilters(UNFILTERED)` call rather than the scoped facets, since scoped tag data isn't yet available server-side.

## Usage Example

```typescript
import { useScheduleDeviceFilters } from './use-schedule-device-filters';

function AvailableDevicesFilterBar({ scheduleId }: { scheduleId: string }) {
  // Scoped to only this schedule's available-device facets
  const filters = useScheduleDeviceFilters(scheduleId, 'available');

  return <DeviceFilterPanel filters={filters} />;
}

// Picker surface that toggles between both halves without re-suspending:
function DevicePickerFilters({ scheduleId, activeTab }: { scheduleId: string; activeTab: ScheduleDeviceHalf }) {
  const filters = useScheduleDeviceFilters(scheduleId, activeTab, {
    prefetchOtherHalf: true,
  });

  return <DeviceFilterPanel filters={filters} />;
}
```

**Note:** This hook suspends on first read — wrap it in the same `Suspense` boundary as the device list it filters, with its own error boundary so a failed facet fetch doesn't take down the list (see `ScheduleDeviceFacets`).
