# use-schedule-scripts-autocomplete.ts

A React hook that powers server-side script autocomplete for the schedule creation form, fetching script suggestions from the GraphQL API via Relay with debounced search and platform filtering.

## Key Components

- **`PickerScript`** — Interface describing a script option surfaced in the picker, including its ID, name, supported platforms, and default run parameters (timeout, args, env vars) used to seed the schedule form on selection.
- **`useScheduleScriptsAutocomplete(supportedPlatforms)`** — Hook that manages the autocomplete lifecycle: lazy-loads results only while the dropdown is active, debounces the search input (300ms), maps platform strings to GraphQL enums, and returns picker state/handlers.

### Returned API
- `scripts: PickerScript[]` — current search results
- `isLoading: boolean` — fetch-in-progress flag
- `inputValue: string` — current search text
- `onInputChange(value)` — update search text
- `onOpen()` — activate the query (dropdown focused)
- `onClose()` — deactivate and clear input (next open starts unfiltered)

## Usage Example

```typescript
import { useScheduleScriptsAutocomplete } from './use-schedule-scripts-autocomplete';

function ScriptPicker({ platforms }: { platforms: string[] }) {
  const {
    scripts,
    isLoading,
    inputValue,
    onInputChange,
    onOpen,
    onClose,
  } = useScheduleScriptsAutocomplete(platforms);

  return (
    <Combobox
      value={inputValue}
      onChange={onInputChange}
      onFocus={onOpen}
      onBlur={onClose}
      loading={isLoading}
      options={scripts.map(script => ({
        label: script.name,
        value: script.id,
      }))}
    />
  );
}
```

The hook uses an imperative `fetchQuery` call with `store-or-network` fetch policy instead of a suspense-based query, so the dropdown never blocks the surrounding form while refreshing results per keystroke. Results populate the Relay store, making re-opens with the same search term render instantly.
