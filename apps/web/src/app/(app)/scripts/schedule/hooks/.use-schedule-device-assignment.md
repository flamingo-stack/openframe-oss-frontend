## Overview

A React hook that encapsulates all Relay mutations for managing device assignment within a schedule — single-row add/remove, bulk "add all"/"remove all" (filtered by device criteria/search), and saving rule-based device criteria. It coordinates optimistic updates for single-row edits against network-backed refreshes for wholesale changes.

## Key Components

- **`useScheduleDeviceAssignment(options)`** — Main hook, returns handlers and state for managing a schedule's assigned devices.
  - `addDevice(device)` / `removeDevice(device)` — Optimistic single-row mutations using `assignmentUpdaters` to patch the Relay store directly; no refetch.
  - `addAllDevices()` / `removeAllDevices()` — Bulk mutations scoped to the current filter/search (captured via `narrowingRef`), followed by `refreshLists()` to re-read both the full and assigned device connections from the network.
  - `saveCriteria(criteria, onSaved)` — Persists rule-based criteria and invalidates stale `assignedDevices` connections, since the response doesn't include member device IDs.
  - `busy` — `true` while any wholesale mutation (`addAll`, `removeAll`, `setCriteria`) is in flight; used to disable the UI. Single-row add/remove are intentionally excluded since they render optimistically per-row.
  - `refreshLists()` — Internal helper that re-fetches both the device picker query and the assigned-devices query using `fetchPolicy: 'network-only'`, keyed off the **deferred** filter/search (matching what mounted queries were actually read with).

## Usage Example

```typescript
'use client';

import { useScheduleDeviceAssignment } from '@/app/(app)/schedules/hooks/use-schedule-device-assignment';

function ScheduleDevicePicker({ scheduleId, filter, search, deferredFilter, deferredSearch }) {
  const {
    addDevice,
    removeDevice,
    addAllDevices,
    removeAllDevices,
    saveCriteria,
    busy,
  } = useScheduleDeviceAssignment({
    scheduleId,
    filter,
    search,
    deferredFilter,
    deferredSearch,
  });

  return (
    <>
      <button disabled={busy} onClick={addAllDevices}>
        Add All Matching Devices
      </button>
      <button disabled={busy} onClick={removeAllDevices}>
        Remove All Matching Devices
      </button>
      {/* per-row buttons call addDevice(device) / removeDevice(device) */}
    </>
  );
}
```

**Design note:** The hook distinguishes between two write models — single-row changes are applied optimistically and never refetched (Relay's store diffing handles rendering), while bulk/criteria changes lock the UI (`busy`) and trigger a network refresh because the client cannot locally derive the new device set.
