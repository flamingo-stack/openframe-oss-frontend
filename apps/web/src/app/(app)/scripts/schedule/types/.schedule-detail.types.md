# schedule-detail.types.ts

Centralized TypeScript type definitions for script schedule detail data, derived directly from GraphQL query artifacts to ensure type safety stays in sync with the schema.

## Key Components

- **`ScheduleDetailData`** — The non-nullable `scriptSchedule` response shape from `ScheduleDetailQueryType`. Represents the full payload used across schedule pages (details, edit, devices) once the detail query resolves.
- **`ScheduleScript`** — A single element of `ScheduleDetailData['scripts']`, representing one script entry with its execution args and environment.
- **`ScheduleDevicesSettingsData`** — The non-nullable `scriptSchedule` response shape from `ScheduleDevicesSettingsQueryType`. A lighter payload used by the "Edit Devices" page, containing targeting mode, rules, info bar fields, and data needed to round-trip through `updateScriptSchedule`.

These types are derived (not hand-written) from generated Relay query types, so any GraphQL schema change immediately surfaces as a type error at consuming call sites rather than causing silent drift.

## Usage Example

```typescript
import type {
  ScheduleDetailData,
  ScheduleScript,
  ScheduleDevicesSettingsData,
} from '@/types/schedule-detail.types';

function renderScriptList(schedule: ScheduleDetailData) {
  schedule.scripts.forEach((script: ScheduleScript) => {
    console.log(script.name, script.args, script.env);
  });
}

function toggleTargetingMode(settings: ScheduleDevicesSettingsData) {
  if (settings.targetingMode === 'MANUAL') {
    // apply manual rule logic
  }
}
```

## Notes

- Types are intentionally derived via `NonNullable<...['response']['scriptSchedule']>` rather than duplicated interfaces, keeping a single source of truth tied to the generated Relay artifacts (`scriptScheduleDetailRelayQuery.graphql` and `scriptScheduleDevicesSettingsRelayQuery.graphql`).
- Use these types wherever schedule detail or devices-settings data is consumed to guarantee consistency with the live GraphQL schema.
