## edit-schedule.types.ts

Defines the Zod validation schema and supporting types for the schedule editing form, encoding the business rules that govern how a script schedule's timing, platform targeting, offline behavior, and per-script parameters are validated before submission.

## Key Components

- **`DEFAULT_TIMEOUT_SECONDS`** — Fallback timeout (90s) applied when a script has no timeout of its own.
- **`platformLabel(id: string): string`** — Resolves a platform id to its display name using the full `OS_PLATFORMS` list (including platforms hidden from the selector, like Linux).
- **`editScheduleFormSchema`** — The core Zod object schema for the schedule edit form, covering:
  - Trigger type (`DATE_TIME` vs `DEVICE_ONLINE`) and conditionally-required timing fields (`scheduledDate`, `scheduledTime`, `timeReference`, `repeatEnabled`, `repeatInterval`, `repeatUnit`).
  - "Stored" passthrough fields (`repeatSecondsStored`, `startAtStored`, `reconnectWindowSecondsStored`) that preserve values the UI controls cannot fully express, so unrelated edits don't silently rewrite them.
  - Offline behavior (`offlineBehavior`, `reconnectInterval`, `reconnectUnit`) for `RETRY_ON_RECONNECT` handling.
  - `supportedPlatforms` and a `scripts` array, each entry validated for a non-empty `scriptId`, per-script `timeoutSeconds` (≥1 once a script is chosen), `args`/`envVars`, and their script-provided defaults.
  - A `superRefine` cross-field pass that flags scripts unsupported on a selected platform, and detects duplicate `scriptId` entries carrying conflicting argument overrides.

## Usage Example

```typescript
import { editScheduleFormSchema, platformLabel } from './edit-schedule.types';

const result = editScheduleFormSchema.safeParse(formValues);

if (!result.success) {
  // Each issue includes a `path` pointing at the offending field/row
  result.error.issues.forEach(issue => {
    console.error(issue.path.join('.'), issue.message);
  });
}

// Display-friendly platform name, falling back to the raw id
const label = platformLabel('darwin'); // "MacOS"
```

This schema is consumed by the schedule edit form component to validate user input before constructing the API payload, working alongside helpers from `schedule-timing` and `schedule-script-params` to convert between form state and the backend's `ScheduleDetailData` representation.
