# schedule-script-card.tsx

Renders a single script entry within a schedule's detail view, showing its name, timeout, and parameter overrides. The card adapts responsively: on desktop the chevron toggles a read-only source code viewer while parameter panels stay permanently visible; on mobile the chevron instead toggles the parameter panels, and the source editor is never shown.

## Key Components

- **`ScheduleScriptCard`** — Main exported component. Displays a script's name, timeout, and an expandable region containing either the source editor (desktop) or argument/environment-variable panels (mobile). Handles loading states via `useLoadingScope`, lazy-loads the `ScriptEditor` chunk ahead of time with `prewarmScriptEditor`, and computes effective (possibly overridden) script parameters via `effectiveScriptParams`.
- **`ScriptParamsPanel`** — Internal helper component rendering a titled list of key/value rows (`ScriptParamRows`) with an optional footer, used for both the "Script Arguments" and "Environment Vars" panels.
- **`ScheduleScriptCardProps`** — Props interface: optional `script` (absent during loading) and optional `customParams` (the schedule's stored override of the script's own defaults).
- **`DEFAULT_TIMEOUT_SECONDS`**, **`SOURCE_HEIGHT`** — Layout/behavior constants.

## Usage Example

```typescript
import { ScheduleScriptCard } from './schedule-script-card';

function ScheduleScriptList({ scripts, overrides }) {
  return (
    <div className="flex flex-col gap-4">
      {scripts.map(script => (
        <ScheduleScriptCard
          key={script.id}
          script={script}
          customParams={overrides[script.id]}
        />
      ))}
    </div>
  );
}

// While data is loading, render without `script` to show skeleton state:
function LoadingScheduleScriptCard() {
  return <ScheduleScriptCard />;
}
```

Key behaviors to note when integrating:
- Pass `customParams` only when the schedule overrides the script's own default arguments or environment variables; the component merges them via `effectiveScriptParams`.
- The component relies on `useContentMdUp()` to determine breakpoint-specific behavior (source editor vs. parameter panels), so it must be rendered within the app's responsive context providers.
- Navigation to the full script page uses `routes.scripts.details(scriptId)` via Next.js `useRouter`.
