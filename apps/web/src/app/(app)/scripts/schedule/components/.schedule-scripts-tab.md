# schedule-scripts-tab.tsx

Renders the "Scheduled Scripts" tab of a schedule detail view, displaying the ordered list of scripts a schedule runs, along with their per-script parameter overrides. Manages its own Suspense boundary so loading/refetching this tab doesn't affect sibling UI (header, timing bar, tab strip).

## Key Components

- **`ScheduleScriptsTab`** — Exported, memoized entry component. Wraps content in a `LoadingSuspense` boundary keyed by `scheduleId`.
- **`ScheduleScriptsTabReader`** — Internal dispatcher that checks `useLoadingScope()` to decide whether to render the loading skeleton or fetch real data, avoiding unnecessary network reads while inside a loading scope.
- **`ScheduleScriptsTabContent`** — Fetches schedule data via `useLazyLoadQuery` with `store-or-network` fetch policy (relies on sibling components having already revalidated the query). Renders a `ScheduleScriptCard` per script, using **run position** (not `script.id`) as the uniqueness key since a schedule may repeat the same script.
- **`ScheduleScriptsTabLoading`** — Renders a single `ScheduleScriptCard` skeleton (count fixed at `SCHEDULE_SCRIPTS_SKELETON_COUNT = 1`), since any valid schedule has at least one script.
- **`customParamsByScriptId`** (imported util) — Maps schedule-level custom parameters to scripts by `script.id`, since overrides are keyed by script, not run position.

## Usage Example

```typescript
import { ScheduleScriptsTab } from './schedule-scripts-tab';

function ScheduleDetailTabs({ scheduleId }: { scheduleId: string }) {
  return (
    <div>
      {/* other tabs */}
      <ScheduleScriptsTab scheduleId={scheduleId} />
    </div>
  );
}
```

The component requires no props beyond `scheduleId`; it handles its own data fetching, loading skeletons, empty states, and not-found cases (delegated silently, since the timing bar reports not-found once at a higher level).
