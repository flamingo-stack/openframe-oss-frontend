## schedule-runs-columns.tsx

Defines the column configuration for the Schedule Runs table, which lists individual executions ("fires") of a scheduled script across devices. It provides both the live, data-driven columns (via a hook) and a static loading-state variant that share the same column layout to prevent layout drift between loaded and skeleton states.

## Key Components

- **`RUNS_PAGE_SIZE`** — Constant defining the number of runs loaded per page (20).
- **`RunStatusOption`** — Interface for a Status funnel filter option, scoped to the server facet of current data.
- **`UiRun`** — Interface representing a single schedule run as rendered by the table (execution id, status, timestamp, device counts, initiator, scheduled flag).
- **`runDetailsHref(run)`** — Returns the route to a run's detail page.
- **`useScheduleRunColumns(statusOptions, dateFilter)`** — Hook that builds the memoized `ColumnDef<UiRun>[]` for the live table, wiring up toast-based "Copy Execution ID" row actions.
- **`SCHEDULE_RUN_LOADING_COLUMNS`** — Pre-built columns for the skeleton/loading state (no status options or date filter, no row actions).
- Internal cell components: `InitiatorCell`, `RunStatusCell`, `RunDevicesCell`, `OpenRunButton` — each respects `useLoadingScope()` to render skeleton placeholders while data loads.

## Usage Example

```typescript
import { useScheduleRunColumns, SCHEDULE_RUN_LOADING_COLUMNS, type UiRun } from './schedule-runs-columns';

function ScheduleRunsTable({ runs, statusOptions, dateFilter, isLoading }: {
  runs: UiRun[];
  statusOptions: RunStatusOption[];
  dateFilter: TableDateFilter;
  isLoading: boolean;
}) {
  const columns = useScheduleRunColumns(statusOptions, dateFilter);

  return (
    <DataTable
      columns={isLoading ? SCHEDULE_RUN_LOADING_COLUMNS : columns}
      data={runs}
    />
  );
}
```

The `Execution` column header hosts the date filter/sort control shared with Execution History views, the `Status` column renders a filterable tag backed by a server facet, and the `Devices` column shows a `responded/total` ratio. Row actions expose a "Copy Execution ID" menu item, and the trailing `open` column links to the run's detail page in a new tab.
