# schedule-runs-tab.tsx

Renders the **Schedule Runs** tab for a schedule detail page — one row per fire of a schedule (an aggregate over its fan-out of per-device/per-script executions). Handles search, status filtering, date-range filtering/sorting, pagination, and responsive (desktop column funnel vs. mobile `FilterModal`) filter UX, backed by a Relay paginated query.

## Key Components

- **`ScheduleRunsTab`** — Exported, memoized top-level component. Owns URL-synced params (`runSearch`, `runStatus`, `runDateFrom`, `runDateTo`, `runSortDir`), sticky toolbar state, and mobile filter modal visibility. Renders `ScheduleRunsTable` inside its own Suspense/loading boundary below the toolbar so filter changes don't remount the search box.
- **`ScheduleRunsTable`** — Wraps `ScheduleRunsTableReader` in a `LoadingSuspense` boundary with a "Loading schedule runs" label.
- **`ScheduleRunsTableReader`** — Checks `useLoadingScope()`; renders a skeleton `LiveTable` (using `SCHEDULE_RUN_LOADING_COLUMNS`) while loading, otherwise delegates to `ScheduleRunsContent`.
- **`ScheduleRunsContent`** — Core data/UI logic: runs `useLazyLoadQuery` + `usePaginationFragment` against `scheduleRunsRelayQuery`/`scheduleRunsRelayFragment`, derives status filter options from the server-provided `scheduleRunFilters` facet (falling back to `FALLBACK_STATUS_OPTIONS`), maps edges to `UiRun[]`, builds a `useDataTable` instance, and renders `LiveTable` plus the mobile `FilterModal`.
- **`FALLBACK_STATUS_OPTIONS`** — Status filter options derived from the `ScriptExecutionStatus` enum, used until the server facet responds.
- **`DISPATCHED_AT_SORT_FIELD`** — Constant identifying the sort field (`dispatchedAt`) used by the Execution column header.
- **`ContentProps`** — Interface describing props passed down into `ScheduleRunsContent`/`ScheduleRunsTableReader`.

## Usage Example

```typescript
import { ScheduleRunsTab } from './schedule-runs-tab';

function ScheduleDetailPage({ scheduleId }: { scheduleId: string }) {
  return (
    <div>
      {/* Other schedule detail tabs/sections */}
      <ScheduleRunsTab scheduleId={scheduleId} />
    </div>
  );
}
```

This component is intended to be used as one tab within a schedule detail view, alongside a separate "Execution History" tab. It manages its own URL query params (prefixed with `run`) to avoid collisions with sibling tabs on the same page.
