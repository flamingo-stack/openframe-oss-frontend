## Overview

Client component rendering the "Edit Devices" screen for a schedule (v2, Relay-based), supporting two device-targeting modes: an explicit, incrementally-committed device set ("specific") and a server-resolved rule ("criteria"). It wraps data loading in a `LoadingSuspense` boundary and composes several shared picker/frame components to produce a consistent page layout regardless of loading state.

## Key Components

- **`ScheduleDevicesView`** — public entry point; wraps `ScheduleDevicesReader` in a `LoadingSuspense` boundary with a "Loading schedule" label.
- **`ScheduleDevicesReader`** — chooses between the loading shell (`ScheduleDevicesShell`) and the data-bound content (`ScheduleDevicesContent`) based on `useLoadingScope()`.
- **`ScheduleDevicesFrame`** — shared page chrome (title, back button, info bar, mode radio) used by both the loading shell and the loaded content, so the radio/info bar never remount across mode switches.
- **`ScheduleDevicesShell`** — pre-data loading state of the frame, showing a locked radio and a loading `DeviceSelector`.
- **`SchedulePickerLoading`** — renders `DeviceSelector` in its loading state for a given `DeviceSelectionMode`.
- **`ScheduleDevicesContent`** — the fully data-bound view: runs the settings Relay query, derives `selectionMode`/`criteria` from stored schedule data (overridable by local state), debounces search/filter inputs, and wires up `useScheduleDeviceAssignment` and `useScheduleSelectionMode` for mutations.
- **`LOADING_ACTIONS`** — placeholder page action shown while settings are loading.

## Usage Example

```typescript
import { ScheduleDevicesView } from './schedule-devices-view';

export default function Page({ params }: { params: { scheduleId: string } }) {
  return <ScheduleDevicesView scheduleId={params.scheduleId} />;
}
```

The component is designed to be rendered directly on a schedule's "edit devices" route; it internally handles its own Relay query suspense via `LoadingSuspense`, branching between "specific" (incremental add/remove) and "criteria" (rule-based, saved) device selection modes based on the schedule's stored `selectionMode`.
