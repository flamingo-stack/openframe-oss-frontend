# schedule-criteria-fields.tsx

Renders the editor and read-only summary for "Select Devices by Criteria" schedule rules, letting users constrain a device schedule by customer and OS type while previewing the resulting match.

## Key Components

- **`ScheduleCriteriaFields`** — Top-level component that detects a loading scope (via `useLoadingScope`) and renders a skeleton-aware view, falling back to `ScheduleCriteriaFieldsContent` once data is ready.
- **`ScheduleCriteriaFieldsContent`** — Fetches the organization list via `useDeviceOrganizations(100)` and passes it to the view.
- **`ScheduleCriteriaFieldsView`** — Renders the actual form: a multi-select `Autocomplete` for customers and a single-select `Select` for OS type, both `AND`ed to form the criteria. Uses sentinel values (`ALL_CUSTOMERS`, `ALL_OS_TYPES`) internally to represent "no constraint," always mapping back to an empty array (`[]`) when emitted via `onChange`.
- **`CustomCriteriaField`** — A disabled, "Coming Soon"-tagged input placeholder; no backing field exists yet in `ScheduleDeviceCriteriaInput`.
- **`ScheduleCriteriaSummary`** — Read-only `InfoCard` summarizing a stored `ScheduleCriteria` (customer names, device types, OS types) for display on the schedule's Assigned Devices tab.
- **`humanizeDeviceType`** — Helper converting enum-style strings (e.g. `MOBILE_DEVICE`) to human-readable labels (`Mobile Device`).

## Usage Example

```typescript
import { ScheduleCriteriaFields, ScheduleCriteriaSummary } from './schedule-criteria-fields';
import type { ScheduleCriteria } from '../utils/schedule-criteria';

function ScheduleRuleEditor({ deviceFilters }: { deviceFilters: DeviceFilters | null }) {
  const [criteria, setCriteria] = useState<ScheduleCriteria>({
    organizationIds: [],
    deviceTypes: [],
    osTypes: [],
  });

  return (
    <>
      <ScheduleCriteriaFields
        criteria={criteria}
        onChange={setCriteria}
        deviceFilters={deviceFilters}
      />
      <ScheduleCriteriaSummary criteria={criteria} />
    </>
  );
}
```

Notes:
- `deviceFilters` must come from an **unfiltered** fleet-wide query, since OS options are not re-derived from the current match.
- The customer `Autocomplete` always offers the full customer list (not just those with devices), supporting forward-looking rules.
- Unconstrained dimensions are stored as empty arrays (`organizationIds: []`, `osTypes: []`) and rendered as "All Customers" / "All Platforms" in both the editor and the summary.
