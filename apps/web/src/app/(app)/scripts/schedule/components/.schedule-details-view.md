## schedule-details-view.tsx

Client component rendering the schedule detail page: a header with archive/edit actions, a timing info bar, and a tabbed body (overview, device targets, schedule runs). Composed of independently-suspending "islands" so a slow or failed query in one section doesn't block the others.

## Key Components

- **`ScheduleDetailsViewProps`** — shared props interface `{ scheduleId: string }`.
- **`ScheduleHeader` / `ScheduleHeaderReader` / `ScheduleHeaderLive`** — header island with its own `LoadingSuspense` boundary. Renders the title, "Archived" tag, and action buttons (Archive/Unarchive, Edit Devices, Edit Schedule) based on `scriptScheduleDetailRelayQuery`.
- **`ScheduleHeaderView`** — presentational header using `TitleBlock`; handles loading state, back navigation via `useSafeBack`, archive confirmation modal, and Mingo context tracking via `useTrackOpenView`.
- **`LOADING_ACTIONS`** — placeholder `PageActionButton[]` shown while the schedule loads.
- **`ScheduleInfoBar` / `ScheduleInfoBarReader` / `ScheduleInfoBarLive`** — timing bar island reading the same query/variables as the header (Relay dedupes the request); acts as the page's single not-found reporter via `NotFoundError`.
- **`ScheduleTabs`** — tab strip and body container, rendering `TabNavigation` with schedule-dependent tabs (event-driven schedules omit the "Schedule Runs" tab).

## Usage Example

```typescript
import { ScheduleDetailsView } from './schedule-details-view';

export default function SchedulePage({ params }: { params: { id: string } }) {
  return <ScheduleDetailsView scheduleId={params.id} />;
}
```

Internally, each section (`ScheduleHeader`, `ScheduleInfoBar`, `ScheduleTabs`) is wrapped in its own `LoadingSuspense`/`Suspense` boundary and checks `useLoadingScope()` before issuing Relay queries, ensuring skeleton states render without triggering redundant network fetches during an ancestor's loading phase.
