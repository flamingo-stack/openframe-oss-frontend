# schedule-picker-lists.tsx

Client component rendering the "Select Specific Devices" half of a schedule editor — two paginated, server-narrowed device lists (available vs. assigned) backed by Relay connections, with facet-driven filtering scoped to each half.

## Key Components

- **`SchedulePickerLists`** — the main exported component. Runs two `useLazyLoadQuery` calls (available/assigned devices for a schedule) with `store-and-network` fetch policy, wraps each result in `usePaginationFragment` for incremental loading, and renders `ServerDevicePickerLists` inside a `ScheduleDeviceFacets` provider (itself wrapped in a `ContentErrorBoundary`).
- **`SchedulePickerListsProps`** — prop contract covering schedule identity, active tab/search/narrowing state (both live and deferred), bulk-busy flag, and add/remove/add-all/remove-all callbacks.

## Usage Example

```typescript
<SchedulePickerLists
  scheduleId={schedule.id}
  activeTab={activeTab}
  onTabChange={setActiveTab}
  search={search}
  onSearchChange={setSearch}
  narrowing={narrowing}
  onNarrowingChange={setNarrowing}
  deferredFilter={deferredFilter}
  deferredSearch={deferredSearch}
  busy={isBulkActionPending}
  onAdd={(device) => addDeviceToSchedule(device)}
  onRemove={(device) => removeDeviceFromSchedule(device)}
  onAddAll={() => addAllMatchingDevices()}
  onRemoveAll={() => removeAllAssignedDevices()}
/>
```

## Notes

- No `fetchKey` is used on the queries: single-device add/remove actions are written directly into the Relay store by mutation updaters, so these queries only refetch from the network for bulk actions that replace the assignment wholesale.
- Facet options (`DeviceFilters`) are resolved server-side per active half (`assigned` vs `available`) rather than derived from in-memory rows, ensuring filter options reflect the full dataset, not just the current page.
- Facets are deferred like the lists themselves to avoid dropping the whole picker (search box, tab state) into a loading state on every filter click.
- A dedicated `ContentErrorBoundary` falls back to rendering both lists with `EMPTY_DEVICE_FILTERS` if the facets query fails, keeping the picker usable without funnels.
- `selectedCount` reflects the entire schedule assignment (not search-filtered), since the tab label describes schedule membership, not search results.
