# schedule-device-facets.tsx

A thin render-prop wrapper component that fetches device filter facets for a schedule (include/exclude half) and exposes them to its children, designed to be isolated inside its own error boundary so a failed facet fetch doesn't break the rest of the schedule UI.

## Key Components

- **`ScheduleDeviceFacets`** — Client component (`'use client'`) that:
  - Accepts a `scheduleId`, a `half` (`ScheduleDeviceHalf`, e.g. include/exclude side of a schedule), an optional `prefetchOtherHalf` flag, and a `children` render-prop function.
  - Calls `useScheduleDeviceFilters(scheduleId, half, { prefetchOtherHalf })` to resolve `DeviceFilters` for that half.
  - Invokes `children(deviceFilters)` to render the result, following a render-props pattern rather than rendering markup itself.

This component is intentionally minimal — it exists purely as an isolation boundary. Wrapping it in an error boundary (as noted in its docblock, alongside a sibling `DeviceFacets` component) allows a fallback UI to render the same shape of filters using empty defaults (`EMPTY_DEVICE_FILTERS`) if the facet fetch fails, degrading gracefully from functional filters to inert display rows.

## Usage Example

```typescript
import { ScheduleDeviceFacets } from './schedule-device-facets';
import { ErrorBoundary } from 'some-error-boundary-lib';

function ScheduleIncludeFilters({ scheduleId }: { scheduleId: string }) {
  return (
    <ErrorBoundary fallback={<EmptyFiltersFallback />}>
      <ScheduleDeviceFacets scheduleId={scheduleId} half="include" prefetchOtherHalf>
        {(deviceFilters) => (
          <DeviceFilterList filters={deviceFilters} />
        )}
      </ScheduleDeviceFacets>
    </ErrorBoundary>
  );
}
```

Each half (`include`/`exclude`) of a schedule's device targeting is typically wrapped independently so a failure in one half's facet data doesn't affect the other.
