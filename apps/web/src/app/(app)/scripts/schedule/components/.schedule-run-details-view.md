## Overview

Client component rendering the details page for a single schedule run (`ScheduleRun`), showing run metadata (status, timing, device response count, initiator) and a paginated, searchable table of the executions it produced. Composes three independently-suspending "islands" (header, summary, executions table) that each read from Relay via a shared `node(id)` query, letting Relay dedupe the identical in-flight requests into one round trip.

## Key Components

- **`ScheduleRunDetailsViewProps`** — props contract requiring `runId` (global id of the `ScheduleRun`).
- **`useScheduleRun(runId, fetchPolicy)`** — shared hook that fetches the run node and narrows its type via `in` checks, exposing `run`, `executionId`, and `scheduleId`.
- **`RunInfoBar`** — presentational info bar showing devices responded, initiator, status tag, start/finish times; self-renders skeletons when loading or run is absent.
- **`RunHeader` / RunHeaderReader / RunHeaderLive / RunHeaderView`** — title block with back navigation to the parent schedule's "runs" tab, subtitle set to the execution id.
- **`RunSummary` / RunSummaryReader / RunSummaryLive`** — wraps `RunInfoBar` in a `LoadingSuspense` boundary; renders `NotFoundError` if the run doesn't resolve.
- **`RunExecutions` / RunExecutionRows`** — fetches and paginates the schedule's executions filtered to this run's `executionId` (used as the `search` scope), applies client-side `narrowSearch`, and renders `ExecutionsTable` inside `ExecutionsTabShell`.
- **`EXECUTIONS_EMPTY_STATE`** — empty-state config (icon, title, description) shown when a run produced no executions.

## Usage Example

```typescript
import { ScheduleRunDetailsView } from './schedule-run-details-view';

export default function Page({ params }: { params: { runId: string } }) {
  return <ScheduleRunDetailsView runId={params.runId} />;
}
```

Each island (`RunHeader`, `RunSummary`, `RunExecutions`) manages its own `LoadingSuspense` boundary and loading-scope fallback, so the page progressively reveals the title, then the info bar, then the executions table as data resolves.
