# schedule-executions-tab.tsx

Renders the "Execution History" tab for a schedule, displaying a flat, paginated list of all device executions across every script run by that schedule.

## Key Components

- **`ScheduleExecutionsTab`** — Memoized public component that accepts a `scheduleId` prop. Wraps the content in `ExecutionsTabShell`, which owns the toolbar (search, filters, sort) and exposes that state via render props, keeping the GraphQL boundary below the toolbar so filter changes don't reset the search box.
- **`ScheduleExecutionsContent`** — Internal component that performs the actual data fetching:
  - Uses `useLazyLoadQuery` to fetch `scheduleExecutionsRelayQuery`, passing `scheduleId`, backend filters, search term, sort, and pagination params in a single round-trip (facet options ride along via `scheduleExecutionFilters`).
  - Uses `usePaginationFragment` on `scheduleExecutionsRelayFragment` to support incremental loading (`loadNext`, `hasNext`, `isLoadingNext`).
  - Converts raw GraphQL edges into `UiExecution[]` via `toUiExecution`, including `scriptName` per row since a schedule can run multiple scripts.
  - Renders the shared `ExecutionsTable` component with facet options, empty state, and pagination callbacks.
- **`EMPTY_STATE`** — Placeholder config (icon, title, description) shown when a schedule has no execution history.

## Usage Example

```typescript
import { ScheduleExecutionsTab } from './schedule-executions-tab';

function ScheduleDetailPage({ scheduleId }: { scheduleId: string }) {
  return (
    <div>
      {/* ...other tabs... */}
      <ScheduleExecutionsTab scheduleId={scheduleId} />
    </div>
  );
}
```

This component is typically rendered as one tab within a schedule detail view (e.g., `schedule-detail-tabs.ts`), alongside an aggregate "Runs" tab that summarizes execution data at a higher level.
