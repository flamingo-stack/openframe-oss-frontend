# schedule-device-filters.ts

Provides helpers for bridging the device criteria editor's filter model with the GraphQL input types used when creating or updating schedule rules.

## Key Components

- **`UNFILTERED`** — A module-level constant (`DeviceFilterInput = {}`) representing an empty filter. Used to query the entire fleet's filterable dimensions (e.g., customers, device types) so criteria dropdowns always show the full set of options, rather than only values matching the rule currently being edited. Keeping this as a stable module-level reference avoids unnecessary query re-execution tied to object identity.
- **`toRelayCriteria(criteria)`** — Converts a `ScheduleCriteria` object (editor-facing model, where `deviceTypes` is plain strings) into a `ScheduleDeviceCriteriaInput` (the relay-generated GraphQL input type). Internally delegates to `criteriaToInput` and casts the result, relying on the fact that the editor's string values are guaranteed members of the generated `DeviceType` enum.

## Usage Example

```typescript
import { UNFILTERED, toRelayCriteria } from './schedule-device-filters';
import type { ScheduleCriteria } from './schedule-criteria';

// Fetch all available filter dimensions for the dropdowns (unfiltered)
const { data } = useDeviceFilterOptionsQuery({ variables: { filter: UNFILTERED } });

// Convert editor state into the mutation input shape
const criteria: ScheduleCriteria = {
  customerIds: ['cust-1'],
  deviceTypes: ['LAPTOP', 'DESKTOP'],
};

const input = toRelayCriteria(criteria);

await commitSetScheduleDeviceCriteriaMutation({
  variables: { scheduleId, criteria: input },
});
```

## Notes

- Always use `UNFILTERED` (not a fresh `{}`) when requesting the full set of filter options to preserve query key stability and avoid cache misses.
- `toRelayCriteria` assumes the editor's `deviceTypes` strings are valid `DeviceType` enum members defined in `@/generated/schema-enums`; mismatches will only surface as type errors if the underlying schema changes.
