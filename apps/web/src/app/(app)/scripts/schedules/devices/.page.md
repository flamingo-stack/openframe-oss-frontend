Next.js client page component that renders the devices view for a specific patch management schedule, identified via a URL query parameter.

## Key Components

- **`ScheduleDevicesPage`** — Default-exported page component. Reads the `id` query parameter from the URL using `useSearchParams` and passes it as `scheduleId` to `ScheduleDevicesView`.
- **`ScheduleDevicesView`** — Imported view component (from `../../schedule/components/schedule-devices-view`) responsible for rendering the list of devices associated with the given schedule. It internally manages its own loading/Suspense behavior.

## Usage Example

This page is automatically routed by Next.js based on its file location (e.g., `app/.../schedule-devices/page.tsx`) and is accessed via a URL with an `id` query parameter:

```text
/schedule-devices?id=abc123
```

```typescript
// Example of how the component resolves the schedule ID
'use client';

import { useSearchParams } from 'next/navigation';
import { ScheduleDevicesView } from '../../schedule/components/schedule-devices-view';

export default function ScheduleDevicesPage() {
  const id = useSearchParams().get('id') ?? '';
  return <ScheduleDevicesView scheduleId={id} />;
}
```

**Notes:**
- Uses the `'use client'` directive since it relies on the client-side `useSearchParams` hook.
- Defaults to an empty string if the `id` parameter is missing, so `ScheduleDevicesView` should gracefully handle an empty `scheduleId`.
- Does not wrap `ScheduleDevicesView` in a `Suspense` boundary, as the view component manages its own loading state internally.
