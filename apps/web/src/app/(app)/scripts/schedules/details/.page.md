Renders the schedule details page, reading the schedule ID from the URL query parameters and delegating rendering to the `ScheduleDetailsView` component, wrapped in an error boundary for resilient failure handling.

## Key Components

- **`ScheduleDetailsPage`** — Default-exported Next.js page component (client component) that:
  - Extracts the `id` query parameter via `useSearchParams` from `next/navigation`
  - Falls back to an empty string if `id` is not present
  - Wraps the content in `ContentErrorBoundary` to gracefully handle rendering errors
  - Renders `ScheduleDetailsView`, passing the resolved `scheduleId`

## Usage Example

This file is a Next.js route page and is rendered automatically based on the file-system routing convention. It is accessed via a URL containing a `id` query parameter, for example:

```text
/schedule-details?id=abc123
```

Internally, the page composes existing shared components:

```typescript
import { ContentErrorBoundary } from '@/app/components/shared';
import { ScheduleDetailsView } from '../../schedule/components/schedule-details-view';

// ContentErrorBoundary catches rendering errors and displays
// a fallback title/message instead of crashing the app.
<ContentErrorBoundary title="Schedule" message="Couldn't load this schedule.">
  <ScheduleDetailsView scheduleId={id} />
</ContentErrorBoundary>
```

**Notes:**
- Since it uses `useSearchParams`, this component must remain a client component (`'use client'` directive).
- If the `id` parameter is missing, `ScheduleDetailsView` receives an empty string and should handle that case appropriately (e.g., showing a not-found or loading state).
