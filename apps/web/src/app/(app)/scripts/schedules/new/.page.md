Client-side Next.js page component that renders the schedule creation UI by reusing the shared `EditSchedulePage` component in "create" mode.

## Key Components

- **`NewSchedulePage`** — Default-exported React functional component serving as the route entry point for creating a new schedule. It delegates rendering to `EditSchedulePage`, passing `scheduleId={null}` to signal that the form should operate in creation mode rather than editing an existing schedule.

## Usage Example

This file is a Next.js page component and is rendered automatically based on its file path within the `app` directory (e.g., `app/.../schedule/new/page.tsx`). It requires no manual invocation.

```typescript
// Navigating to the corresponding route in the app
// automatically renders this page:
import { useRouter } from 'next/navigation';

function NavigateToNewSchedule() {
  const router = useRouter();

  const handleClick = () => {
    router.push('/schedule/new');
  };

  return <button onClick={handleClick}>Create New Schedule</button>;
}
```

Internally, the page simply composes the shared editor component:

```typescript
import { EditSchedulePage } from '../../schedule/components/edit-schedule-page';

export default function NewSchedulePage() {
  return <EditSchedulePage scheduleId={null} />;
}
```

By passing `scheduleId={null}`, the `EditSchedulePage` component can detect that no existing schedule is being edited and should instead initialize an empty form for creating a new one, keeping create/edit logic unified in a single component.
