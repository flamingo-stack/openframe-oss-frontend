Next.js page component that renders the edit view for a script schedule, resolving the schedule ID from the route and delegating rendering to a shared `EditSchedulePage` component.

## Key Components

- **`EditSchedulePageWrapper`** (default export) — Client component that extracts a required `id` route/query parameter and renders `EditSchedulePage` with it. Returns `null` while the ID is not yet available (e.g., during redirect/navigation handling).
- **`useRequiredIdParam`** — Hook used to read and validate the required `id` param, falling back to a redirect path (`/scripts/schedules`) and a "new" route (`routes.scripts.schedules.new`) if the ID is missing.

## Usage Example

This file is a Next.js route page and is rendered automatically by the framework for its corresponding route (e.g., `/scripts/schedules/[id]/edit`). It isn't typically imported directly, but conceptually behaves as:

```typescript
// app/scripts/schedules/[id]/edit/page.tsx
export default function EditSchedulePageWrapper() {
  const id = useRequiredIdParam('/scripts/schedules', routes.scripts.schedules.new);
  if (!id) return null;

  return <EditSchedulePage scheduleId={id} />;
}
```

**Note:** No `Suspense` boundary is added here intentionally — `EditSchedulePage` handles its own layout/chrome on first render and only suspends internally around the data loader that fetches the schedule record, avoiding a full-page loading flash.
