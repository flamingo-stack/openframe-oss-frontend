Next.js client page component that renders the detailed view of a single script execution, identified by an `id` query parameter.

## Key Components

- **`ScriptExecutionDetailsPage`** — Default export; a client-side page component that:
  - Reads the `id` query parameter from the URL via `useSearchParams`
  - Wraps content in `ContentErrorBoundary` to gracefully handle load failures
  - Renders `ScriptExecutionDetailsView`, passing the extracted `id` as `executionId`

## Dependencies

- `next/navigation` — `useSearchParams` for reading URL query parameters
- `@/app/components/shared` — `ContentErrorBoundary` for error handling UI
- `../script/components/script-execution-details-view` — `ScriptExecutionDetailsView`, the main content renderer

## Usage Example

This page is automatically routed by Next.js based on its file location (e.g., `app/.../script-execution-details/page.tsx`). It's accessed via a URL with an `id` query parameter:

```typescript
// Navigating to this page from elsewhere in the app:
import { useRouter } from 'next/navigation';

function ExecutionLink({ executionId }: { executionId: string }) {
  const router = useRouter();

  const goToDetails = () => {
    router.push(`/script-execution-details?id=${executionId}`);
  };

  return <button onClick={goToDetails}>View Execution</button>;
}
```

If the `id` parameter is missing, the component defaults to an empty string, allowing `ScriptExecutionDetailsView` to handle the empty/invalid state (e.g., showing a "not found" message). Any rendering errors are caught by `ContentErrorBoundary`, displaying a user-friendly "Execution" error message instead of crashing the page.
