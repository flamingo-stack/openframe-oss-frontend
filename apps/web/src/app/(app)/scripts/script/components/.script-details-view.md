# script-details-view.tsx

Client-side React component rendering the Script Details page: a composable, Relay-backed view that shows a script's header (with context-aware actions), summary/tags, and tabbed detail content, designed so only data-dependent sections suspend independently rather than blocking the whole page.

## Key Components

- **`ScriptDetailsView`** — Top-level memoized export. Composes `PageLayout`'s structure manually (rather than using `PageLayout` directly) so the header, summary, and tabs each suspend independently instead of as one unit.
- **`ScriptHeader` / `ScriptHeaderReader` / `ScriptHeaderLive` / `ScriptHeaderView`** — Header island. Fetches the script via `scriptDetailRelayQuery`, renders `TitleBlock` with a Back button, an "Archived" tag when applicable, and status-dependent actions (Run + Edit for active scripts, Unarchive for archived ones). Tracks the open view in Mingo context.
- **`ScriptSummary` / `ScriptSummaryReader` / `ScriptSummaryLive` / `ScriptSummaryView`** — Summary island. Reads the same query/variables as the header (Relay dedupes the request) and renders tag chips plus `ScriptSummaryCard`. Owns the page's single "not found" report via `NotFoundError`.
- **`ScriptTags`** — Renders tag chips with a loading skeleton (`LoadingItems`) or empty-state fallback (`ValueText`).
- **`ScriptRecord`** — Type alias for the script object returned by `ScriptDetailQueryType`.

## Usage Example

```typescript
import { ScriptDetailsView } from './script-details-view';

// Typically rendered from a Next.js dynamic route page
export default function ScriptDetailPage({ params }: { params: { id: string } }) {
  return <ScriptDetailsView scriptId={params.id} />;
}
```

The component relies on Relay's `useLazyLoadQuery` with a shared `fetchKey` (via `useRetryKey`) across the header and summary islands to ensure both share a single network request while still being individually retriable after an error. Each island wraps itself in `LoadingSuspense` so skeleton states render independently during data fetch, and `useLoadingScope()` lets child views detect when they're rendering inside a fallback boundary.
