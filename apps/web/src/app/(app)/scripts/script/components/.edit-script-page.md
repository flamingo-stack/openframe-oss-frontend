## edit-script-page.tsx

Page component for creating and editing scripts, handling record loading, form state, tag association, and dispatching test executions against remote devices via Relay mutations.

## Key Components

- **`ScriptFields`** – Renders the shared `ScriptFormFields` tree (shell type, body, tags) used identically by both the create flow and the edit flow's loading/loaded states, avoiding component remounts.
- **`ScriptRecordFields` / `ScriptRecordFieldsReader`** – Wraps the fields in a `LoadingSuspense` boundary; while suspended (or in any outer loading scope) renders a disabled, data-less version of the form so the layout never shifts.
- **`ScriptRecordLoader`** – A render-nothing data island that calls `useLazyLoadQuery` for the script detail, then reports the resolved state up via `onResolved` inside a `useLayoutEffect` (pre-paint seeding).
- **`ScriptRecordState`** – Discriminated union (`loading` | `missing` | `ready`) describing what the page currently knows about the edited record.
- **`EditScriptForm`** – The top-level page: owns the `react-hook-form` instance (via `useEditScriptForm`), the Back navigation, save/test handlers, and renders `ExecutionStartedModal` / `TestScriptModal` for running scripts against a device.

## Usage Example

```typescript
import EditScriptPage from './edit-script-page';

// Create mode
<EditScriptPage scriptId={null} />

// Edit mode
<EditScriptPage scriptId="script-123" />
```

Internally, the page composes record loading and form editing so that:

```typescript
function EditScriptForm({ scriptId }: { scriptId: string | null }) {
  const { form, isSubmitting, handleSave } = useEditScriptForm({ scriptId, isEditMode: Boolean(scriptId) });
  const [record, setRecord] = useState<ScriptRecordState>(
    scriptId ? RECORD_LOADING : RECORD_NOT_NEEDED,
  );

  useSeedForm(form, record.status === 'ready' ? record.values : null);

  return (
    <PageLayout>
      <ScriptRecordFields
        scriptId={scriptId}
        record={record}
        onResolved={setRecord}
        form={form}
        showErrors={false}
      />
    </PageLayout>
  );
}
```

Test execution requires a shell, script body, and at least one supported platform before opening the device picker; failures surface via toast rather than inline form errors, keeping "Test" distinct from "Save" validation semantics.
