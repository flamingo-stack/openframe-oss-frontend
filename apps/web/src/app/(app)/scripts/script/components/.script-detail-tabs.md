# script-detail-tabs.ts

Defines the tab configuration for the script details page, mapping tab IDs to their labels, icons, and body components. This registry drives both the tab navigation strip and the content resolution for a given `?tab=` query parameter.

## Key Components

- **`ScriptTabProps`** — Interface shared by all tab body components, requiring a `scriptId`.
- **`DETAIL_TABS`** — Array of `TabItem` entries defining the two available tabs: "Script Details" (`ScriptDetailsTab`) and "Execution History" (`ScriptExecutionsTab`). Note that a Schedules tab is intentionally excluded.
- **`SCRIPT_DEFAULT_TAB`** — The tab ID used when `?tab=` is missing or unrecognized (defaults to the first tab, `'details'`).
- **`scriptTabBody(tabId)`** — Resolves a tab ID to its corresponding body component, falling back to the default tab's component if no match is found.

Each tab body is individually `memo`'d (in its own module) to avoid unnecessary re-renders, since `TabNavigation` defers rendering and re-invokes render props on tab switches and query-param changes. Each body also manages its own `Suspense` boundary, positioned according to UX needs (e.g., Execution History places its boundary below the toolbar to preserve filter/search state during reloads).

## Usage Example

```typescript
import { DETAIL_TABS, SCRIPT_DEFAULT_TAB, scriptTabBody } from './script-detail-tabs';

// Render tab navigation
<TabNavigation tabs={DETAIL_TABS} defaultTab={SCRIPT_DEFAULT_TAB} />

// Resolve the body component for the active tab
const activeTabId = searchParams.get('tab') ?? SCRIPT_DEFAULT_TAB;
const TabBody = scriptTabBody(activeTabId);

<TabBody scriptId={scriptId} />
```

Adding a new tab only requires appending an entry to `DETAIL_TABS`; the page itself never needs to know individual tab IDs.
