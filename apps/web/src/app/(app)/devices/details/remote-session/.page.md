# page.tsx — Remote Session Page

Next.js page component that displays a single remote session recording, gated behind a feature flag and guarded by a required route parameter.

## Key Components

- **`RemoteSessionPage`** — Default export; the page component rendered for the remote session recording route.
- **`useSessionRecordingsGate`** — Hook that determines whether the session recordings feature is enabled (`'on'` or `'off'`).
- **`useRequiredIdParam`** — Hook that extracts the recording ID from the route params, redirecting to `routes.devices.list` if missing.
- **`RemoteSessionView`** — Component responsible for rendering the actual remote session recording content.
- **`LoadingWhen`** — Shared UI wrapper from `@flamingo-stack/openframe-frontend-core` that displays a loading state based on a boolean condition.

## Behavior

1. On mount, if the feature gate (`gate`) is `'off'`, the user is redirected to the devices list via `router.replace`.
2. The page is only considered `ready` once the gate is `'on'` **and** a valid `recordingId` has been resolved.
3. While not ready, `LoadingWhen` renders a loading state and `RemoteSessionView` receives `null` for `recordingId`, effectively rendering nothing of substance until the gate and ID checks pass.

## Usage Example

This page is automatically routed by Next.js based on its file location (e.g., `app/(app)/devices/remote-sessions/[id]/page.tsx`) and requires no manual invocation. It expects a dynamic route segment resolvable by `useRequiredIdParam`:

```typescript
// Example route: /devices/remote-sessions/abc123
// Next.js resolves params and this page handles gating/loading automatically.

export default function RemoteSessionPage() {
  // ...gate and id resolution logic
}
```

If the session recordings feature is disabled, navigating to this route will redirect users to the devices list defined by `routes.devices.list`.
