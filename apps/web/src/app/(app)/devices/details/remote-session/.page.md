# RemoteSessionPage

Next.js client page component that displays a recorded remote session view, guarded by a feature gate and a required route parameter.

## Key Components

- **`RemoteSessionPage`** (default export) — Page component that:
  - Reads the `useSessionRecordingsGate` feature flag to determine if session recordings are enabled.
  - Extracts and validates the `recordingId` via `useRequiredIdParam`, redirecting to the devices list if missing.
  - Redirects to `routes.devices.list` if the feature gate is `'off'`.
  - Renders `RemoteSessionView` only when the gate is `'on'` and a valid `recordingId` is present; otherwise shows a loading state via `LoadingWhen`.

## Usage Example

This component is a route-level page and is rendered automatically by Next.js for its corresponding route segment (e.g., `/devices/remote-sessions/[id]`). It is not typically imported directly, but conceptually behaves as:

```typescript
// Rendered by Next.js routing for a dynamic segment, e.g.:
// app/(app)/devices/remote-sessions/[id]/page.tsx

export default function RemoteSessionPage() {
  // Gate check: redirects to devices list if recordings feature is disabled
  // ID check: redirects to devices list if no valid id param is found
  // Otherwise: renders RemoteSessionView with the validated recordingId
}
```

Consumers navigate to this page via a link or router call, e.g.:

```typescript
router.push(`/devices/remote-sessions/${sessionId}`);
```

## Notes

- Uses `'use client'` directive since it relies on client-side hooks (`useRouter`, `useEffect`, feature gate state).
- The `LoadingWhen` wrapper ensures no premature data fetching or rendering occurs before the gate and ID are resolved, avoiding flash-of-unauthorized-content issues.
