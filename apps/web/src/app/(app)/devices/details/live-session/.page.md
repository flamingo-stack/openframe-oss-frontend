# Live Session Page

Next.js client page component that renders a live remote device session view, guarded by a feature gate and a required session ID route parameter.

## Key Components

- **`LiveSessionPage`** (default export) — Page component for viewing an active remote session. It:
  - Resolves the `useRemoteSessionWatchGate()` feature flag to determine if the feature is enabled.
  - Extracts the required `sessionId` from the route via `useRequiredIdParam`, redirecting to the devices list route if missing.
  - Redirects to `routes.devices.list` if the gate is `'off'`.
  - Renders a loading state (`LoadingWhen`) until both the gate is `'on'` and the session ID is available.
  - Delegates actual session rendering to `LiveSessionView`.

## Usage Example

This page is automatically routed by Next.js based on its file location under `app/(app)/devices/...`. It is not typically imported directly, but conceptually behaves as:

```typescript
// Rendered automatically for a route like /devices/[id]/live-session

export default function LiveSessionPage() {
  const router = useRouter();
  const gate = useRemoteSessionWatchGate();
  const sessionId = useRequiredIdParam(routes.devices.list);

  useEffect(() => {
    if (gate === 'off') router.replace(routes.devices.list);
  }, [gate, router]);

  const ready = gate === 'on' && Boolean(sessionId);

  return (
    <LoadingWhen loading={!ready}>
      <LiveSessionView sessionId={ready ? sessionId : null} />
    </LoadingWhen>
  );
}
```

**Behavior notes:**
- If the watch gate is disabled, the user is immediately redirected away without rendering the session view.
- The `LiveSessionView` component is responsible for its own internal loading/error states when `sessionId` is `null` or not yet ready.
