# Live Session Page

Next.js page component that renders the live remote device session viewer, gating access behind a feature flag and a valid session ID extracted from the URL.

## Key Components

- **`LiveSessionPage`** (default export) - Page component for viewing a live remote device session. Combines a feature gate check (`useRemoteSessionWatchGate`) with a required route parameter (`useRequiredIdParam`) to determine readiness before rendering the `LiveSessionView`.
- **Gate redirect logic** - If the remote session watch feature is disabled (`gate === 'off'`), the user is redirected to the devices list via `router.replace(routes.devices.list)`.
- **`LoadingWhen`** - Wraps the view so a loading state is shown until both the gate and session ID are resolved as "ready".

## Usage Example

This file is a Next.js App Router page and is rendered automatically based on its file path (e.g., `/devices/remote-sessions/live/[id]`). It isn't imported directly elsewhere, but its behavior depends on these hooks:

```typescript
// Simplified behavior this page relies on
const gate = useRemoteSessionWatchGate(); // 'on' | 'off' | 'loading'
const sessionId = useRequiredIdParam(routes.devices.list); // string | null

// Redirect away if the feature is disabled
useEffect(() => {
  if (gate === 'off') router.replace(routes.devices.list);
}, [gate, router]);

// Only pass a real sessionId to the view once both conditions are satisfied
const ready = gate === 'on' && Boolean(sessionId);
```

## Notes

- The `ready` flag ensures `LiveSessionView` never receives a partial or invalid `sessionId` while the gate or route param resolution is still in progress.
- Redirect uses `router.replace` (not `push`) to avoid adding a back-navigation entry for the blocked session page.
