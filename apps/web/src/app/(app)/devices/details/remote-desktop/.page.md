## page.tsx

Next.js client page component for the remote desktop (VNC-style KVM) control surface in the OpenFrame devices module. It wraps the session-establishing logic behind mobile/approval gates and hosts the MeshCentral-backed remote desktop viewer with chat, settings, shortcuts, and toolbar UI.

## Key Components

- **`RemoteDesktopPage`** (default export) — Entry route component. Reads the `id` query param, redirects on the mobile shell, renders a `NoData` dead-end on narrow viewports when the remote-access approval gate is enabled, and otherwise mounts `RemoteDesktopSession` inside `RemoteAccessGate` so the MeshCentral tunnel is never opened before approval.
- **`RemoteDesktopSession`** — Core session component. Resolves device info from either a legacy `deviceData` query param or `useDeviceDetails`, tracks the device as the active Mingo "open view", and manages MeshCentral desktop/tunnel/control refs (`MeshDesktop`, `MeshTunnel`, `MeshControlClient`), display selection, stream/frame state, clipboard, settings, and session reporting.
- **`LegacyDeviceData`** — Interface for the backward-compatible `deviceData` query param shape (`id`, `meshcentralAgentId`, `hostname`, `organization`).
- **Constants** — `DESKTOP_PROTOCOL` (MeshCentral KVM relay protocol id), `FIRST_FRAME_TIMEOUT_MS`, `MAX_STREAM_RETRIES`, `SESSION_ENDED_COPY` (end-reason messaging map).
- **`displayLabel(displayId)`** — Formats a monitor display id into a human-readable label.

## Usage Example

This is a Next.js App Router page; it is not imported directly but resolved via the file-based route. It expects a `deviceId` in the URL:

```typescript
// Navigating to the remote desktop page for a device
import { useRouter } from 'next/navigation';
import { routes } from '@/lib/routes';

function openRemoteDesktop(router: ReturnType<typeof useRouter>, deviceId: string) {
  router.push(`${routes.devices.remoteDesktop}?id=${deviceId}`);
}
```

The page automatically:
1. Redirects away on mobile shells.
2. Shows a "not supported" message on narrow viewports (when the approval gate flag is on).
3. Gates the `RemoteDesktopSession` behind `RemoteAccessGate` to avoid opening a MeshCentral tunnel pre-approval.
