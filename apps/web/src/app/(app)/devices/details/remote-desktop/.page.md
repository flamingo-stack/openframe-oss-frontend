## page.tsx

Next.js client page component implementing the remote desktop (KVM) viewing experience for a device, orchestrating a MeshCentral tunnel/session, approval gating, mobile-device redirection, and UI chrome (toolbar, chat, settings, shortcuts).

## Key Components

- **`RemoteDesktopPage`** (default export) — Entry route component. Handles mobile-shell redirect, mobile-viewport dead-end screen (behind the remote-access approval gate flag), and wraps the actual session in `RemoteAccessGate` so the MeshCentral tunnel is never mounted before approval.
- **`RemoteDesktopSession`** — Core session component that:
  - Resolves device info from either a legacy `deviceData` query param or `useDeviceDetails`.
  - Tracks MeshCentral tool-connection state (`live`/offline) and agent id.
  - Manages the `MeshDesktop`/`MeshTunnel`/`MeshControlClient` lifecycle via refs.
  - Implements first-frame-timeout and retry logic (`FIRST_FRAME_TIMEOUT_MS`, `MAX_STREAM_RETRIES`) for flaky relay pairings.
  - Integrates chat (`useRemoteSessionChat`), action reporting (`useRemoteSessionActionReporter`), remote settings, keyboard shortcuts, viewer list, and session-end handling.
  - Registers the device as the active "Mingo open view" via `useTrackOpenView`.
- **Constants**: `DESKTOP_PROTOCOL`, `FIRST_FRAME_TIMEOUT_MS`, `MAX_STREAM_RETRIES`, `SESSION_ENDED_COPY` (per-`RemoteSessionEndReason` messaging).
- **`displayLabel(displayId)`** — Formats a display identifier into a human-readable label (agent exposes no monitor names).
- **`LegacyDeviceData`** — Interface for the deprecated `deviceData` query-param payload, kept for backward compatibility.

## Usage Example

This is a Next.js App Router page and is rendered automatically for its route — it is not imported directly. It expects a `?id=<deviceId>` search param identifying the target device:

```typescript
// Navigated to via:
router.push(`/devices/remote-desktop?id=${deviceId}`);
```

Related route helper used elsewhere in the app:

```typescript
import { routes } from '@/lib/routes';

// Links back to a device's detail page from remote desktop
router.push(routes.devices.details(deviceId));
```

The page relies on `RemoteAccessGate` to keep the MeshCentral tunnel unmounted until approval, and on `useRemoteAccessSession` to supply the approved session context consumed by `RemoteDesktopSession`.
