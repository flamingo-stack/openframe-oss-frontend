Defines the Next.js route metadata and layout wrapper for the Remote Shell page, setting the browser tab title and delegating layout rendering to a shared layout component.

## Key Components

- **`metadata`** — A `Metadata` object (Next.js App Router convention) that sets the page title to `"Remote Shell"` using the `routeTitle` helper for consistent title formatting across the app.
- **Default export** — Re-exports the shared `route-title-layout` component from `@/app/(app)/route-title-layout`, avoiding duplication of layout logic across routes.

## Usage Example

This file follows the Next.js App Router convention where a `layout.tsx` co-located with a page automatically applies to that route segment:

```typescript
// app/(app)/remote-shell/layout.tsx
import type { Metadata } from 'next';
import { routeTitle } from '@/lib/route-title';

export { default } from '@/app/(app)/route-title-layout';

export const metadata: Metadata = { title: routeTitle('Remote Shell') };
```

Next.js automatically picks up this `metadata` export to render the `<title>` tag for the "Remote Shell" route, while the re-exported default layout component handles consistent page chrome (e.g., headers displaying the route title) across all routes using this pattern.

## Notes

- This is a thin configuration file—no custom logic is defined here beyond metadata declaration and layout delegation.
- The `routeTitle` utility (from `@/lib/route-title`) ensures consistent title formatting (e.g., appending a suffix like `"| OpenFrame"`) across all route layouts.
- To see the shared layout implementation, refer to [`app/(app)/route-title-layout.tsx`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/(app)/route-title-layout.tsx).
