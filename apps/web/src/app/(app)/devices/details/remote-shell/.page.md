Remote shell page component that establishes and manages an interactive terminal session with a remote device via MeshCentral WebSocket tunneling, rendered using xterm.js.

## Key Components

| Export / Symbol | Description |
|---|---|
| `RemoteShellPage` | Default export — Next.js page component for the remote shell surface |
| `WINDOWS_POWERSHELL_CMD` | Fallback command chain that locates and launches PowerShell on Windows |
| `MeshTunnel` | WebSocket tunnel abstraction used to stream terminal data to/from the agent |
| `MeshControlClient` | Control-plane client that obtains auth cookies and brokers relay pairing |
| `shellType` | Derived from `?shellType=powershell` query param; drives auto-send of PowerShell launcher |
| `state` (`TunnelState`) | Numeric tunnel state (0 Idle → 1 Connecting → 2 Open → 3 Connected) displayed in the status badge |

## Usage Example

Navigate to the page with required query parameters:

```typescript
// Programmatic navigation
import { routes } from '@/lib/routes';
import { useRouter } from 'next/navigation';

const router = useRouter();

// Open CMD shell
router.push(`/remote-shell?id=${deviceId}`);

// Open PowerShell shell
router.push(`/remote-shell?id=${deviceId}&shellType=powershell`);
```

The component handles its own lifecycle:

1. Fetches device details (including MeshCentral `agentToolId`) via `useDeviceDetails`
2. Lazily imports `@xterm/xterm` and `@xterm/addon-fit` after the agent ID is confirmed
3. Opens a `MeshTunnel` session; on first data receipt with `shellType=powershell`, sends `WINDOWS_POWERSHELL_CMD`
4. Cleans up the tunnel, control client, and xterm instance on unmount

## States Rendered

| Condition | Output |
|---|---|
| `isDeviceLoading` | Animated skeleton layout |
| `deviceError` | Error message + Back button |
| `!meshcentralAgentId` | "Agent not available" message + Back button |
| Ready | Full `PageLayout` with xterm terminal, status badge, and Disconnect button |
