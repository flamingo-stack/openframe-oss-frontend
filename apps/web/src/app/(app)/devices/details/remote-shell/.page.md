# Remote Shell Page (`page.tsx`)

Next.js client page that establishes an interactive remote shell (CMD or PowerShell) session with a managed device via MeshCentral, rendering the terminal UI with `xterm.js` over a tunneled connection.

## Key Components

- **`RemoteShellPage`** — Top-level route component; delegates immediately to `RemoteShellSession` (no approval gate, unlike remote screen sessions).
- **`RemoteShellSession`** — Core component that:
  - Reads `id` (device ID) and `shellType` (`cmd` | `powershell`) from URL search params.
  - Fetches device details via `useDeviceDetails` and resolves the MeshCentral tool connection/agent ID.
  - Lazily loads `@xterm/xterm` and `@xterm/addon-fit`, initializes the terminal, and wires a `ResizeObserver` to keep the terminal sized to its container.
  - Opens a `MeshControlClient` session and a `MeshTunnel` to stream terminal I/O (binary data in/out) and control messages (terminal resize, console messages).
  - Auto-injects a PowerShell bootstrap command (`WINDOWS_POWERSHELL_CMD`) once the tunnel is connected and shell type is `powershell`.
  - Tracks the device as the active Mingo "open view" context via `useTrackOpenView`.
  - Handles connection states (`Idle`, `Connecting`, `Open`, `Connected`), error states, and "MeshCentral unavailable" fallback UI.
- **`WINDOWS_POWERSHELL_CMD`** — Shell command string that tries multiple PowerShell executable locations (pwsh 7, WindowsPowerShell, Sysnative) with fallbacks via `||`.

## Usage Example

This page is route-driven and not typically imported directly. It's reached via a URL like:

```text
/devices/remote-shell?id=<deviceId>&shellType=powershell
```

Internally, the tunnel lifecycle is managed through refs to survive React's async effect timing:

```typescript
const tunnelRef = useRef<MeshTunnel | null>(null);

useEffect(() => {
  const tunnel = new MeshTunnel({
    authCookie,
    nodeId: meshcentralAgentId,
    protocol: 1,
    onData: data => term.write(data),
    onStateChange: setState,
  });
  tunnelRef.current = tunnel;
  tunnel.start();

  return () => tunnelRef.current?.stop();
}, [isPageReady, meshcentralAgentId]);
```

## Notes

- Relies on refs (`cleanupRef`, `controlRef`, `tunnelRef`) to bridge async IIFE setup with synchronous effect cleanup.
- Resize is observed on the terminal **container**, not the window, to handle docked panel layouts.
- Reconnection logic (`onBeforeReconnect`, `onRequestPairing`) re-opens the control session and relays tunnel keys to recover from dropped connections without throwing from tunnel callbacks.
