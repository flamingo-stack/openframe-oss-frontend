Defines route-level metadata and layout wiring for the File Manager page within the Next.js App Router structure.

## Key Components

- **`metadata`** — A `Metadata` object exported for Next.js to apply page-specific `<title>` tags, generated via the `routeTitle` helper with `'File Manager'` as input.
- **Default export** — Re-exports the shared `route-title-layout` component from `@/app/(app)/route-title-layout`, allowing this route segment to reuse a common layout implementation without duplicating layout logic.

## Usage Example

This file is automatically picked up by Next.js as the `layout.tsx` for its route segment—no manual import is required. The pattern can be replicated for other routes needing a titled layout:

```typescript
import type { Metadata } from 'next';
import { routeTitle } from '@/lib/route-title';

export { default } from '@/app/(app)/route-title-layout';

export const metadata: Metadata = { title: routeTitle('Your Page Name') };
```

Here, `routeTitle('File Manager')` likely formats the title consistently (e.g., appending a brand suffix like "File Manager | OpenFrame"), ensuring uniform title formatting across the application. The actual layout rendering (navigation, wrappers, providers) is delegated to the shared `route-title-layout` component, keeping route-specific files minimal—limited to metadata declaration and layout delegation.

This approach centralizes layout logic while allowing each route to independently define its page title, reducing duplication across the `app/(app)/` route group in the [openframe-oss-frontend repository](https://github.com/flamingo-stack/openframe-oss-frontend).
