# remote-session-chat-api-service.ts

Implements the chat API for remote sessions, bridging the ticket chat system's DIRECT-mode client-chat dialog to the remote session chat UI. It converts persisted ticket messages and live JetStream chunks into normalized chat rows, distinguishing between end-user (CLIENT) and technician (ADMIN) authored lines while filtering out system notices and non-text content.

## Key Components

- **`decodeRemoteSessionChatChunk(payload, technician?)`** — Decodes a live NATS/JetStream chunk into a `RemoteSessionChatMessage`, or returns `null` for non-participant events (assistant deltas, system notices, malformed chunks). Assigns a stable `seq`-based id when available, otherwise a local incrementing id.
- **`RemoteSessionChatApiService`** — Implements `IRemoteSessionChatService`:
  - `history(dialogId)` — Fetches a page of persisted messages via `ticketService.fetchMessages`, reverses them to chronological order, flattens into chat rows, and computes the highest sequence number seen (`lastSeq`).
  - `send(dialogId, body)` — Sends a technician message through `ticketService.sendMessage` using `CHAT_TYPE.CLIENT`.
- **`remoteSessionChatApiService`** — Singleton instance exported for consumption by hooks/components.
- **`rowsOf(message)`** (internal) — Extracts `TEXT`-type rows from a persisted `Message`, mapping owner type to `'user'` or `'technician'` authorship.
- **`technicianName(owner)`** (internal) — Derives a display name from an `AdminOwner`, falling back to `"Technician"`.

## Usage Example

```typescript
import { remoteSessionChatApiService, decodeRemoteSessionChatChunk } from './remote-session-chat-api-service';

// Load chat history for a remote session's dialog
const { messages, lastSeq } = await remoteSessionChatApiService.history(dialogId);

// Send a technician message
await remoteSessionChatApiService.send(dialogId, 'How can I help?');

// Decode a live chunk received over the JetStream subscription
```
