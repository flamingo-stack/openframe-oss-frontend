# remote-session-api-service.ts

GraphQL service layer for the technician side of the remote session lifecycle. It fetches and ends remote sessions via `openframe-saas-api`, and provides pure helpers to translate GraphQL wire data and NATS lifecycle events into the app's `RemoteSession` read model.

## Key Components

- **`fromWireRemoteSession(data)`** — Converts a GraphQL fragment payload (`WireSession`) into a `RemoteSession`, normalizing status, mode, timestamps, end reason, and recording-suppressed flags. Throws if required fields (`sessionId`, `status`) are missing.
- **`parseRemoteSessionEvent(payload)`** — Parses a notification-subject payload into a `RemoteSessionEvent` (`REMOTE_SESSION_STARTED` / `REMOTE_SESSION_ENDED`), returning `null` for unrelated payloads.
- **`applyRemoteSessionEvent(session, event)`** — Folds a lifecycle event into an existing (or `null`) session, building a new record on STARTED or marking it `ENDED` with reason/timestamp.
- **`RemoteSessionApiService`** — Class exposing:
  - `active(deviceId)` — Fetches the caller's own `ACTIVE` session on a device, or `null`.
  - `get(sessionId)` — Fetches a session by ID (poll fallback); throws if not found.
  - `end(sessionId)` — Mutates to end the session; tolerates an "already ended" error code as success.
  - `endOnUnload(sessionId)` — Fires the end mutation as a keepalive beacon on page unload (fire-and-forget).
- **`remoteSessionApiService`** — Singleton instance of the service for app-wide use.

## Usage Example

```typescript
import { remoteSessionApiService, parseRemoteSessionEvent, applyRemoteSessionEvent } from './remote-session-api-service';

// Check for an active session on a device
const active = await remoteSessionApiService.active(deviceId);

// Poll a known session
const session = active ?? (await remoteSessionApiService.get(sessionId));

// Handle a lifecycle push from the notification subject
const event = parseRemoteSessionEvent(notificationPayload);
if (event) {
  const updated = applyRemoteSessionEvent(session, event);
}

// End the session (e.g. technician clicks "Stop")
await remoteSessionApiService.end(sessionId);

// On page unload, best-effort end without waiting for a response
window.addEventListener('beforeunload', () => {
  remoteSessionApiService.endOnUnload(sessionId);
});
```

Note: `REMOTE_SESSION_STARTED`/`ENDED` push events are consumed separately by `useRemoteSession`, which subscribes to the technician's notification subject and uses `parseRemoteSessionEvent` from this module.
