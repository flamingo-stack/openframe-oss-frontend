## Remote Access Policy Service

Defines the contract for reading and mutating remote access policies at the tenant, organization, and device scopes. This interface abstracts the policy resolution hierarchy (device → organization → tenant) used by settings screens and the connect flow, with a concrete implementation provided by `RemoteAccessPolicyApiService` against `openframe-saas-api`.

## Key Components

- **`IRemoteAccessPolicyService`** — Interface defining the remote access policy API surface:
  - `getTenantPolicy()` — fetches the tenant-wide default policy.
  - `updateTenantPolicy(policy)` — updates the tenant default.
  - `getOrganizationPolicy(organizationId)` — fetches an organization's policy, including its effective mode.
  - `setOrganizationMode(organizationId, mode)` — sets or clears (`null`) an organization-level override.
  - `getDevicePolicy(deviceId)` — fetches a single device's override and resolved effective mode.
  - `getDevicePolicies(deviceIds)` — batch fetch for table views; returns a `Map` keyed by device id, omitting unknown devices.
  - `setDeviceMode(deviceId, mode)` — sets or clears (`null`) a device-level override, returning the updated policy.

## Usage Example

```typescript
import type { IRemoteAccessPolicyService } from './remote-access-policy-service';

async function syncOrganizationOverride(
  service: IRemoteAccessPolicyService,
  organizationId: string
) {
  // Read current effective policy
  const policy = await service.getOrganizationPolicy(organizationId);
  console.log(policy.effectiveMode);

  // Apply an override
  await service.setOrganizationMode(organizationId, 'RESTRICTED');

  // Clear the override to inherit the tenant default
  await service.setOrganizationMode(organizationId, null);
}

async function loadDeviceTableRows(
  service: IRemoteAccessPolicyService,
  deviceIds: string[]
) {
  const policies = await service.getDevicePolicies(deviceIds);
  return deviceIds.map((id) => policies.get(id));
}
```

## Notes

Consumers should depend on this interface rather than the concrete `RemoteAccessPolicyApiService` to keep settings UI and connect-flow logic decoupled from the API transport layer. See [`remote-access-policy-api-service.ts`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/src/services/remote-access-policy-api-service.ts) for the implementation and [`remote-access.ts`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/src/types/remote-access.ts) for the related type definitions.
