# remote-session-events-api-service.ts

Provides GraphQL-backed access to a remote session's timeline events, used by the session recording playback page to list event markers and report playback activity to the server.

## Key Components

- **`SessionEventsPage`** — Interface describing a paginated result: `events` (array of `SessionTimelineEvent`) and `nextCursor` (string or null for the last page).
- **`fetchSessionEventsPage(recordingId, after)`** — Fetches one page (up to 500 items) of timeline events for a recording, filtered to a fixed set of relevant `RemoteSessionEventType` values (session lifecycle, input toggles, clipboard actions, shortcuts, monitor switches, and recording retention events). Returns events oldest-first along with a cursor for further pagination.
- **`recordRecordingPlayed(sessionId)`** — Commits a mutation notifying the server that a recording was played; resolves to a boolean indicating whether the server accepted the report.
- **`LISTED_TYPES`** — Internal constant restricting which event types appear in the timeline list (excludes request/chat/raw playback events by design).
- **`PAGE_SIZE`** — Internal constant (500) matching the server's page size ceiling.
- **`eventsQuery` / `playedMutation`** — Internal GraphQL documents backing the above functions.

## Usage Example

```typescript
import { fetchSessionEventsPage, recordRecordingPlayed } from './remote-session-events-api-service';

// Load the first page of timeline events for a recording
const { events, nextCursor } = await fetchSessionEventsPage('recording-123', null);

// Load subsequent pages until exhausted
if (nextCursor) {
  const nextPage = await fetchSessionEventsPage('recording-123', nextCursor);
}

// Report that a recording was played
const accepted = await recordRecordingPlayed('session-456');
if (!accepted) {
  console.warn('Server did not accept the playback report');
}
```
