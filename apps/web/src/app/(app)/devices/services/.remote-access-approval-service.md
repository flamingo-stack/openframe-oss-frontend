# remote-access-approval-service.ts

Defines the service contract for managing remote-access approval requests, along with a helper to determine whether a request status represents a final (settled) state. This file is a type/interface definition only; the actual implementation lives in `remote-access-approval-api-service.ts`.

## Key Components

- **`IRemoteAccessApprovalService`** — Interface describing the backend surface for remote-access approval workflows:
  - `create(input)` — Creates an approval request for a device. The server enforces at most one open request per device; calling `create` again while one is open returns the existing request instead of creating a new one.
  - `get(requestId)` — Fetches the current state of a request, used as a polling fallback in case the real-time push notification is missed.
  - `revoke(requestId)` — Allows the technician to cancel an open request, transitioning it to `REVOKED` and closing the client-side prompt.
- **`SETTLED`** — A `ReadonlySet` of `RemoteAccessRequestStatus` values (`APPROVED`, `DENIED`, `TIMED_OUT`, `REVOKED`, `CANCELLED`, `EXPIRED`) representing terminal states.
- **`isSettledRequestStatus(status)`** — Utility function returning `true` if the given status is a final/settled state, `false` if the request is still pending/open.

## Usage Example

```typescript
import { isSettledRequestStatus } from './remote-access-approval-service';
import type { IRemoteAccessApprovalService } from './remote-access-approval-service';

async function pollUntilSettled(
  service: IRemoteAccessApprovalService,
  requestId: string
) {
  let request = await service.get(requestId);

  while (!isSettledRequestStatus(request.status)) {
    await new Promise((resolve) => setTimeout(resolve, 2000));
    request = await service.get(requestId);
  }

  return request;
}
```

The actual decision (approve/deny) typically arrives via NATS push notifications consumed by `useRemoteAccessApproval`, with `get` serving only as a fallback when a push notification is missed.
