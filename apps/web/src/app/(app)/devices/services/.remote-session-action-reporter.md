# remote-session-action-reporter.ts

Implements a fire-and-forget reporter that records remote session console actions to the backend API, queuing them in order and retrying transient failures without blocking the console UI.

## Key Components

- **`RemoteSessionActionReporterDeps`** — Injectable dependencies interface (`send`, `newEventId`, `now`, `sleep`) enabling deterministic testing.
- **`RemoteSessionActionReporter`** — Main class that queues and sequentially drains session action reports for a given `sessionId`.
  - `report(action)` — Enqueues an action (synchronous, non-throwing) and triggers background draining.
  - `drain()` (private) — Sends queued reports one at a time, retrying only on retryable (no-answer) errors with increasing delays, and dropping actions after a final refusal or exhausted retries.
- **`uuid()`** — Generates a v4 UUID, falling back to manual generation when `crypto.randomUUID` is unavailable (e.g., non-secure contexts).
- **`RETRY_DELAYS_MS`** — Backoff schedule (`1s, 3s, 10s`) for resending unanswered requests before giving up.
- **`MAX_QUEUED`** — Caps the queue at 100 entries; oldest reports are dropped first during prolonged outages.

## Usage Example

```typescript
import { RemoteSessionActionReporter } from './remote-session-action-reporter';

const reporter = new RemoteSessionActionReporter(sessionId);

// Called whenever the user performs a console action
reporter.report({
  type: 'KEY_PRESS',
  key: 'Enter',
  // ...other action fields
});

// report() returns immediately; sending/retrying happens in the background
```

Each call to `report` assigns a unique `clientEventId`, ensuring the server deduplicates actions even if a request is resent after a timeout. Only requests that receive no response are retried; explicit API errors cause the action to be dropped immediately.
