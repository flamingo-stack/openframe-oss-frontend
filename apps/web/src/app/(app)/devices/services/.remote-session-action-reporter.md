Reports a remote session's console actions to the backend API in order, one at a time, with automatic retry on transient failures and bounded in-memory queuing—all without blocking the caller.

## Key Components

- **`RemoteSessionActionReporter`** — Class that queues and sequentially sends `RecordRemoteSessionActionInput` payloads for a given session. `report()` enqueues an action and returns immediately; an internal `drain()` loop processes the queue one request at a time, retrying retryable failures with increasing delays before giving up.
- **`RemoteSessionActionReporterDeps`** — Injectable dependency interface (`send`, `newEventId`, `now`, `sleep`) enabling deterministic unit testing by substituting the network call, ID generation, clock, and delay mechanism.
- **`DEFAULT_DEPS`** — Production dependency set using `recordRemoteSessionAction`, `crypto.randomUUID`-based IDs, real timestamps, and `setTimeout`-based sleeping.
- **`RETRY_DELAYS_MS`** — Backoff schedule (`1s`, `3s`, `10s`) for resending an action that received no response before it is dropped.
- **`MAX_QUEUED`** — Caps the queue at 100 entries; oldest reports are dropped first during prolonged API outages.
- **`uuid()`** — Fallback v4 UUID generator used when `crypto.randomUUID` is unavailable (e.g., non-secure contexts).

## Usage Example

```typescript
import { RemoteSessionActionReporter } from './remote-session-action-reporter';
import type { RemoteSessionAction } from './remote-session-actions-api-service';

const reporter = new RemoteSessionActionReporter(sessionId);

function onConsoleAction(action: RemoteSessionAction) {
  // Fire-and-forget: never blocks or throws
  reporter.report(action);
}
```

Each call to `report()` assigns a unique `clientEventId`, ensuring that resent actions are deduplicated server-side. Only network/connectivity failures (per `isRetryableReportError`) trigger a resend; explicit server rejections are dropped immediately.
