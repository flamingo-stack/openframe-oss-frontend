## Overview

A service layer that bridges GraphQL/Relay data with the Remote Sessions UI, handling recording listing, playback detail, live session status, storage quotas, and lifecycle mutations (delete, keep/hold, release) for the Flamingo OpenFrame remote session recordings feature.

## Key Components

- **`customerLogoUrl(organization, device)`** — Resolves the correct customer logo URL, preferring the device's current customer image over the session's stored organization logo.
- **`fromWireSession(session)`** — Maps a `WireSession` (GraphQL fragment data) into a `RecordingSummary` row used by the Remote Sessions tab, computing aggregate size, protocol, recording state, and keep/hold status.
- **`readSession(ref)`** — Reads an inline `sessionRecordingsApiService_session` fragment from a Relay fragment reference.
- **GraphQL definitions** — `sessionFragment`, `deviceCustomerFragment`, `listQuery`, `detailQuery`, `liveQuery`, `storageQuery`, `deviceQuery`, and mutations (`deleteMutation`, `keepMutation`, `releaseMutation`) for fetching and mutating session/recording data.
- **Lookup tables** — `RECORDING_STATES` maps server `RemoteSessionRecordingState` to UI `RecordingState`; `KEEP_REASONS_FROM_WIRE` / `KEEP_REASONS_TO_WIRE` translate between server `RecordingHoldReason` and the UI's `RemoteSessionKeepReason`.
- **`NOT_FOUND_CODES`** — Error codes used to distinguish "not found" responses (mapped to `RecordingNotFoundError`/`SessionNotFoundError`) from other failures.
- **`PAGE_SIZE` / `MAX_PAGES`** — Pagination constants controlling how much session history is fetched per device.
- Internal helpers `fromWireOrganization`, `readTranscript`, `readDevice` support assembling the full `RecordingDetail` view, including chat transcript (via `remoteSessionChatApiService`) and device/customer metadata.

## Usage Example

```typescript
import { fromWireSession, readSession, customerLogoUrl } from './session-recordings-api-service';

// Convert a Relay fragment reference into a row for the sessions table
const session = readSession(sessionFragmentRef);
const row = fromWireSession(session);

console.log(row.recordingState); // 'ready' | 'processing' | 'kept' ...
console.log(row.kept, row.keep?.reason);

// Resolve the correct logo to display for a session's organization
const logo = customerLogoUrl(session.organization, deviceFragmentRef);
```

This service is consumed by the implementation of `ISessionRecordingsService` (see `session-recordings-service.ts`) to provide list, detail, live, storage, delete, keep, and release operations backed by Relay queries/mutations against the `openframe-saas-api` GraphQL schema.
