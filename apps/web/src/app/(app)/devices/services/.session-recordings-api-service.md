## session-recordings-api-service.ts

Relay-based API service implementing `ISessionRecordingsService` for the Remote Sessions tab and recording detail page. It fetches and transforms `RemoteSession` GraphQL data into app-level types (`RecordingSummary`, `RecordingDetail`, `LiveSessionDetail`, etc.), handles keep/release/delete mutations for recordings, and enriches session data with device/customer logo info and chat transcripts.

## Key Components

- **GraphQL fragments/queries**: `sessionFragment`, `deviceCustomerFragment`, `listQuery`, `detailQuery`, `liveQuery`, `storageQuery`, `deviceQuery` — define the data shape fetched from `openframe-saas-api`.
- **Mutations**: `deleteMutation`, `keepMutation`, `releaseMutation` — delete a session, place a recording on hold ("keep"), or release a hold.
- **`customerLogoUrl(organization, device)`**: Resolves the correct customer logo, preferring the device's current organization image over the session's stored logo.
- **`fromWireSession(session)`**: Maps a wire `RemoteSession` fragment into a `RecordingSummary` row (duration, size, state, live flag, keep info, technician).
- **`readSession(ref)`**: Reads an inline Relay fragment reference into `WireSession` data.
- **`RECORDING_STATES`**, **`KEEP_REASONS_FROM_WIRE`**, **`KEEP_REASONS_TO_WIRE`**: Enum mapping tables between server (`RemoteSessionRecordingState`, `RecordingHoldReason`) and client-facing types (`RecordingState`, `RemoteSessionKeepReason`).
- **`readTranscript(dialogId)`**: Best-effort fetch of chat history via `remoteSessionChatApiService`; fails gracefully to an empty array.
- **`readDevice(machineId)`**: Fetches hostname and customer image data for the meta card, handling `NOT_FOUND_CODES` errors.
- **Constants**: `PAGE_SIZE` (100), `MAX_PAGES` (10), `NOT_FOUND_CODES` — control pagination and not-found detection.

## Usage Example

```typescript
import { fromWireSession, readSession, customerLogoUrl } from './session-recordings-api-service';

// Transform a Relay fragment reference into a UI-ready row
const session = readSession(sessionFragmentRef);
const row = fromWireSession(session);

console.log(row.recordingState); // 'ready' | 'processing' | 'expired' | ...
console.log(row.kept); // true if the recording is on hold

// Resolve customer logo with device-aware fallback
const logo = customerLogoUrl(session.organization, deviceFragmentRef);
```

This service is consumed by the Remote Sessions tab and recording detail/live pages to list, play, and manage recorded remote support sessions, including retention ("keep") workflows tied to compliance and dispute scenarios.
