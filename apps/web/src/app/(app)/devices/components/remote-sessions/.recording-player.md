# recording-player.tsx

Renders the playback surface for a session recording, hosting either a KVM canvas (protocol 2) or an xterm terminal (protocol 1) inside a black letterbox container, along with overlay states for seeking, pre-play, and unavailable recordings.

## Key Components

- **`RecordingPlayer`** — The main component. Mounts both the `<canvas>` (KVM) and terminal host `<div>` simultaneously, toggling visibility based on `protocol` rather than conditionally rendering them, to avoid detaching the decoder mid-session.
- **`RecordingPlayerProps`** — Props interface:
  - `player: UseRecordingPlayerResult` — refs, protocol, playback state, and `togglePlay` handler from the `useRecordingPlayer` hook.
  - `unavailableNote: string | null` — explanation shown when there's nothing to play (e.g., still processing); `null` means content may be available.
  - `className?: string` — optional styling override for the root container.

### Visual States
- **Seeking/Waiting**: dims the surface with a pulsing loading icon overlay.
- **Ready**: shows a centered Play button overlay (shown only before first playback starts).
- **Empty**: displays a "Session recording unavailable" message with the given reason, when `unavailableNote` is set and state is `'empty'`.

## Usage Example

```typescript
import { RecordingPlayer } from './recording-player';
import { useRecordingPlayer } from './use-recording-player';

function SessionRecordingView({ sessionId }: { sessionId: string }) {
  const player = useRecordingPlayer(sessionId);

  const unavailableNote =
    player.state === 'empty' ? 'Recording is still being processed.' : null;

  return (
    <RecordingPlayer
      player={player}
      unavailableNote={unavailableNote}
      className="h-[480px] rounded-lg"
    />
  );
}
```

## Notes

- Depends on `useRecordingPlayer` (see `use-recording-player.ts`) for state management, refs, and playback control logic.
- Uses design tokens (`--spacing-system-xsf`, `ods-*` color classes) and icon components from `@flamingo-stack/openframe-frontend-core` for consistent styling per Figma specs (758-46350, 775-50606).
