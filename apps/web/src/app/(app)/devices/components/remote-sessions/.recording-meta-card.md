Renders the metadata summary card for session recordings and live sessions, displaying details like date, resolution, duration, file size, hostname, customer, and employee info in a responsive grid layout.

## Key Components

- **`MetaFrame`** - Internal layout wrapper applying consistent row/border/padding styles to each grid cell; collapses to content-height on mobile and fixed 80px rows on desktop.
- **`CARD_CLASS`** - Shared grid container class (2 columns on mobile/tablet, 4 columns on desktop) with rounded border styling.
- **`RecordingMetaCard`** - Displays full metadata for a completed `RecordingDetail`: Date, Resolution, Duration, File size, Hostname, Customer, Employee, and either "Expires on" or "Kept by" (with lock icon and keep reason) depending on whether the recording was retained.
- **`LiveSessionMetaCard`** - Displays partial metadata for an in-progress `LiveSessionDetail`: Date, Resolution (passed separately since it's not part of the session object), Hostname, Customer, and Employee, with empty placeholder cells to preserve grid alignment on desktop.

Both components integrate with `useLoadingScope`/`LoadingWhen` to render skeleton/loading states automatically while data resolves.

## Usage Example

```typescript
import { RecordingMetaCard, LiveSessionMetaCard } from './recording-meta-card';

// Completed recording detail view
function RecordingDetailPage({ recording }: { recording: RecordingDetail | null }) {
  return (
    <div>
      <RecordingMetaCard recording={recording} />
    </div>
  );
}

// Live session view (resolution supplied externally, e.g. from a video stream)
function LiveSessionPage({ session }: { session: LiveSessionDetail | null }) {
  return (
    <div>
      <LiveSessionMetaCard session={session} resolution="1920x1080" />
    </div>
  );
}
```

Both components automatically handle `null`/loading states internally, so callers can pass data as soon as it's available (or `null` while fetching).
