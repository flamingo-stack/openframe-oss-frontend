This file renders user-facing warning banners related to session recording storage limits, using a shared alert component styled per the Figma design spec.

## Key Components

- **`RecordingWarningAlert`** – A reusable warning-styled `Alert` wrapper that displays a triangle icon alongside bold text. Accepts standard `HTMLAttributes<HTMLDivElement>` and forwards `children` as the alert message.
- **`RecordingStorageBanner`** – A self-contained banner that checks the tenant's recording storage status via the `useRecordingStorage` hook. It renders nothing if storage isn't full, is still loading, or can't be read (marked `data-loading-optional`). When full, it displays a message stating that new sessions won't be recorded, including the server-reported storage limit formatted via `formatBytes`.

## Usage Example

```typescript
import { RecordingStorageBanner, RecordingWarningAlert } from './recording-storage-banner';

// Automatically shows/hides based on live storage state
function DevicePageHeader() {
  return (
    <div>
      <RecordingStorageBanner className="mb-4" />
      {/* ...rest of page */}
    </div>
  );
}

// Generic warning alert, reusable for other contexts
function CustomWarning() {
  return (
    <RecordingWarningAlert>
      Custom warning message goes here.
    </RecordingWarningAlert>
  );
}
```

## Notes

- `RecordingStorageBanner` relies on the backend-provided `limitBytes` value rather than a hardcoded threshold, ensuring the UI always reflects the actual server-configured limit.
- The component fails safe: any loading or error state in `useRecordingStorage` results in no banner being shown, avoiding false warnings.
