## live-session-view.tsx

This file implements the **Live Session View** page component, which displays a real-time streaming view of an active remote control session (or its ended/processing state), including a canvas-rendered screen stream, viewer list, session timer, fullscreen support, and optional live chat.

## Key Components

- **`LiveSessionView`** — Main exported page component. Loads session data by `sessionId`, polls for updates, manages the live-to-recording handoff (redirects to the recording page once a recording file is ready), and renders the appropriate state: loading, not found, error, or active session content.
- **`LiveStreamFrame`** — Renders the host's screen stream onto a `<canvas>` via `attachCanvas`, with an overlay bar (host name, display label, viewers), a duration counter, and a fullscreen toggle.
- **`SessionEndedScreen`** — Placeholder shown when a session has ended but no recording is available yet, optionally indicating the recording is processing.
- **`ConnectingOverlay`** / **`UnavailableOverlay`** — Transient overlays shown while the watch socket connects or when the stream fails to connect (with retry).
- **`titleTag`** — Derives the status tag (`live`, `processing`, `failed`, or `null`) for the page title based on session state.
- **`useIsFullscreen`** — Internal hook tracking whether a given element is the current fullscreen target.
- **`displayLabel`**, **`SectionLabel`** — Small presentational helpers for display naming and section headers.

## Usage Example

```typescript
import { LiveSessionView } from './live-session-view';

export default function Page({ params }: { params: { sessionId: string } }) {
  return <LiveSessionView sessionId={params.sessionId} />;
}
```

The component relies on `useLiveSession` for polling session data and `useRemoteSessionWatch` for establishing the live streaming socket connection. When `sessionId` is `null`, the component renders in a loading state until the id becomes available. Once a session ends and its recording becomes `ready`, the view automatically redirects to `routes.devices.remoteSessionRecording(recordingId)`.
