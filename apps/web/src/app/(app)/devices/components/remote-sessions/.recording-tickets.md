Converts GraphQL-sourced ticket data into a normalized `RecordingTicket` shape for the Assigned Tickets table on the recording page, and provides a search-matching helper for filtering tickets by title or ticket number.

## Key Components

- **`recordingTicketFragment`** — Inline Relay GraphQL fragment (`recordingTickets_ticket`) on `RemoteSessionTicketLink`, defining the fields read for each linked ticket (id, number, title, status, assignee info, creation date).
- **`RecordingTicket`** — Interface describing a single row in the Assigned Tickets table, with nullable fields for status, assignee, and creation timestamp.
- **`toRecordingTicket(ref)`** — Reads the inline fragment data from a Relay fragment reference and maps it into a `RecordingTicket`, applying defaults (e.g., `'Untitled Ticket'` fallback) and resolving the assignee avatar URL via `getFullImageUrl`.
- **`matchesTicketSearch(ticket, search)`** — Case-insensitive search predicate matching a ticket's title or ticket number against a search string, stripping a leading `#` from the query for number matches.

## Usage Example

```typescript
import { toRecordingTicket, matchesTicketSearch } from './recording-tickets';

// Inside a component rendering the Assigned Tickets table:
const tickets = ticketRefs.map(toRecordingTicket);

// Filtering by the "Search for Tickets" input:
const [search, setSearch] = useState('');
const visibleTickets = tickets.filter((ticket) => matchesTicketSearch(ticket, search));

visibleTickets.forEach((ticket) => {
  console.log(ticket.ticketNumber, ticket.title, ticket.assignedName ?? 'Unassigned');
});
```

This pattern is typically used alongside Relay's `useFragment` or `readInlineData` calls when hydrating table rows from a parent query that includes `recordingTickets_ticket` fragment spreads.
