# remote-session-view.tsx

Client-side component that renders the **Remote Session Recording** page, composing the recording player, session metadata, chat transcript, event timeline, and linked support tickets into a single cohesive view.

## Key Components

- **`RemoteSessionView`** — Main exported component. Accepts `recordingId` (nullable while the page is still resolving the id) and orchestrates:
  - **Recording & session data**: `useSessionRecording`, `useSessionEvents`, `useRecordingTickets`, `useRecordingStorage`
  - **Playback**: `useRecordingPlayer` for loading/seeking segments, synced with `RemoteSessionTimelineMarkers` and `RemoteSessionEventList`
  - **Fullscreen handling**: Uses `FullscreenSwitchController` on the player's native DOM element (not a page overlay) so the browser's top-layer fullscreen bypasses app chrome (dock/sidebar masking issues)
  - **Ticket management**: Assign/unassign tickets via `useAssignRecordingTickets`, `useUnassignRecordingTicket`, backed by `AssignTicketModal` / `UnassignTicketModal`
  - **Keep/Release/Delete actions**: `useKeepSessionRecording`, `useReleaseSessionRecording`, `useDeleteRemoteSession`, gated by `canKeepSession` / `canDeleteSession`
  - **Error states**: Distinguishes `RecordingNotFoundError` (404) from transient load/offline errors
  - **Dev tooling**: `DevLocalFileLoader` enabled only via feature flag + `?dev=1` query param for testing playback without a storage backend

## Usage Example

```typescript
import { RemoteSessionView } from './remote-session-view';

// Typically rendered from a Next.js route page component
export default function Page({ params }: { params: { recordingId: string } }) {
  return <RemoteSessionView recordingId={params.recordingId} />;
}

// While resolving the id (e.g., during route param hydration):
<RemoteSessionView recordingId={null} />
```

The component handles its own loading, not-found, and error states internally based on `recordingId` and the underlying query results—callers only need to supply the id once known.
