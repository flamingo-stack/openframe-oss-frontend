# dev-local-file-loader.tsx

A development/QA-only component that lets testers load local `.mcrec` recording files directly into the player, bypassing the storage backend. It's gated behind a feature flag so it can safely ship in production builds while remaining hidden by default.

## Key Components

- **`DevLocalFileLoaderProps`** — Interface defining the `onLoad` callback, which receives an array of `ArrayBuffer`s (the session's recording segments, ordered oldest-first).
- **`DevLocalFileLoader`** — The main component:
  - Renders `null` if `useRemoteAccessMockTools()` returns `false` (defense-in-depth visibility gate, independent of caller checks).
  - Renders a hidden `<input type="file">` plus a visible "Open local .mcrec files (mock)" button that triggers the file picker.
  - Sorts picked files by filename (numeric-aware) since Mesh names recording segments after their start time, preserving session order.
  - Reads all files as `ArrayBuffer`s and passes them to `onLoad`.
  - Shows a success or error toast depending on the outcome.

## Usage Example

```typescript
import { DevLocalFileLoader } from './dev-local-file-loader';

function RemoteAccessPlayer() {
  const handleLoad = async (buffers: ArrayBuffer[]) => {
    // Feed buffers into the playback engine, e.g.:
    await player.loadSegments(buffers);
  };

  return (
    <div>
      {/* Only visible when the remote-access-mock-tools flag is enabled */}
      <DevLocalFileLoader onLoad={handleLoad} />
    </div>
  );
}
```

**Notes:**
- Visibility is controlled via the `useRemoteAccessMockTools` hook (typically combined with a `?dev=1` query param check by the caller).
- Multiple `.mcrec` files can be selected at once; they're treated as segments of a single session and joined in filename order.
- Errors during file reading or `onLoad` are surfaced via `getErrorMessage` and displayed as a destructive toast.
