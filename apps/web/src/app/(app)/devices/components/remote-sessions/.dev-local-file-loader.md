Developer/QA-only component that lets a user pick local `.mcrec` recording files from disk and load them directly into the player, bypassing the storage backend. It exists so the playback engine can be exercised end-to-end before real storage is wired up, and is gated behind a mock-tools feature flag so it never appears in normal production usage.

## Key Components

- **`DevLocalFileLoaderProps`** — Props interface: `onLoad` callback receiving an array of `ArrayBuffer`s (one per session segment, ordered oldest first).
- **`DevLocalFileLoader`** — React component rendering a hidden `<input type="file">` plus a visible "Open local .mcrec files (mock)" button that triggers it.
  - Guards rendering with `useRemoteAccessMockTools()` — returns `null` if the flag is disabled, acting as a defense-in-depth check independent of the caller's own gating.
  - `handleFiles` sorts selected files by filename (numeric-aware) since Mesh names each segment file after its start time, converts each to an `ArrayBuffer`, and invokes `onLoad`.
  - Shows a success toast (`"Recording Loaded"`) on completion or a destructive error toast via `getErrorMessage` on failure.

## Usage Example

```typescript
import { DevLocalFileLoader } from './dev-local-file-loader';

function PlayerToolbar() {
  const handleLoad = async (buffers: ArrayBuffer[]) => {
    await player.loadSegments(buffers);
  };

  return (
    <div className="toolbar">
      {/* Only visible when the remote-access-mock-tools flag is on */}
      <DevLocalFileLoader onLoad={handleLoad} />
    </div>
  );
}
```

**Notes:**
- Visibility is controlled entirely by the `useRemoteAccessMockTools` flag (typically combined with `?dev=1` in the URL by the caller), not by build environment, allowing QA to enable it on production builds.
- Multiple files can be selected at once; they are treated as consecutive segments of a single recording session.
