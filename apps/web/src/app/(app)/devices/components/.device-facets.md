# device-facets.tsx

This component isolates the fleet facet-fetching logic so it can be wrapped independently by an error boundary, ensuring that a failed facet query degrades gracefully (losing only the filter UI) without taking down the entire device list rendering.

## Key Components

- **`DeviceFacets`** — A render-prop component that fetches device facets (filter options) via `useDeviceFilters` and passes the resolved `DeviceFilters` to its `children` function.
  - **Props:**
    - `filters?: DeviceFilterInput` — Optional input used to scope/influence the facet query.
    - `children: (deviceFilters: DeviceFilters) => ReactNode` — Render prop invoked with the resolved facets.

## Usage Example

```typescript
import { DeviceFacets } from './device-facets';
import { ContentErrorBoundary } from '../components/content-error-boundary';

function DevicesPanel({ filters }: { filters?: DeviceFilterInput }) {
  const renderList = (deviceFilters: DeviceFilters) => (
    <DeviceList filters={deviceFilters} />
  );

  return (
    <ContentErrorBoundary fallback={() => renderList({} as DeviceFilters)}>
      <DeviceFacets filters={filters}>
        {renderList}
      </DeviceFacets>
    </ContentErrorBoundary>
  );
}
```

## Notes

- Designed to be rendered **inside** a `ContentErrorBoundary`, whose fallback should render the same `children` function with empty/default facets, so a facet-fetch failure only disables filtering rather than breaking the device list.
- Keeps facet-fetching (`useDeviceFilters`) decoupled from the list-rendering logic via the render-prop pattern, enabling independent failure isolation between "what narrows the list" and "the list itself."
