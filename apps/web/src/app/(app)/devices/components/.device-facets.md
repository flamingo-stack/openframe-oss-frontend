# device-facets.tsx

Renders device fleet filtering facets as an isolated component, decoupled from the device list itself so that filter-loading failures can be isolated via an error boundary without affecting the rendered device rows.

## Key Components

- **`DeviceFacets`** — A client component that fetches device filter facets (via `useDeviceFilters`) and passes the resulting `DeviceFilters` object to a render-prop `children` function. It accepts an optional `filters` input (`DeviceFilterInput`) to scope which facets are computed.

## Usage Example

```typescript
import { DeviceFacets } from './device-facets';
import { ContentErrorBoundary } from '@flamingo-stack/openframe-frontend-core/components/features';

function DevicesPanel() {
  return (
    <ContentErrorBoundary
      fallback={<DeviceList deviceFilters={{}} />}
    >
      <DeviceFacets filters={{ status: 'active' }}>
        {(deviceFilters) => <DeviceList deviceFilters={deviceFilters} />}
      </DeviceFacets>
    </ContentErrorBoundary>
  );
}
```

## Design Notes

This component is intentionally thin: it exists solely to let `useDeviceFilters` run inside its own subtree, separate from the list-rendering subtree. Wrapping `DeviceFacets` in a `ContentErrorBoundary` (as done in `DevicesPanel`) ensures that if the facet query fails, only the filter UI degrades (falling back to rendering `children` with empty facets), while the device rows themselves remain unaffected. This pattern keeps facet failures cheap and localized rather than taking down the entire devices view.
