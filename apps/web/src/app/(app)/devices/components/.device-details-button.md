# device-details-button.tsx

A reusable button component that navigates to a device's detail page, built on top of the shared `Button` component. It gracefully handles missing device IDs by hiding itself and supports loading states, new-tab navigation, and a callback for dismissing overlays when navigation occurs in the current window.

## Key Components

- **`DeviceDetailsButtonProps`** — Props interface accepting `deviceId` or `machineId` (either can supply the identifier), `label`, `variant`, `className`, `openInNewTab`, and an `onNavigate` callback.
- **`DeviceDetailsButton`** — The exported component. Resolves the device ID (preferring `machineId` over `deviceId`), consults `useLoadingScope()` to avoid flashing an empty state while data loads, and renders `null` only once loading has settled and no ID is available.
- **`onNavigate` callback** — Invoked only when the click triggers an actual same-window navigation (not a modifier/middle click, not opened in a new tab), determined via `navigatesCurrentWindow`. Useful for dismissing overlays (e.g., `LogDrawer`) when the user navigates to a detail page they're already viewing.

## Usage Example

```typescript
import { DeviceDetailsButton } from '@/components/device-details-button';

function DeviceRow({ device }: { device: { id: string } }) {
  return (
    <DeviceDetailsButton
      deviceId={device.id}
      variant="accent"
      label="View Device"
    />
  );
}

// Used inside an overlay that should close itself on same-window navigation
function LogDrawerFooter({ machineId, onClose }: { machineId: string; onClose: () => void }) {
  return (
    <DeviceDetailsButton
      machineId={machineId}
      openInNewTab={false}
      onNavigate={onClose}
    />
  );
}
```

## Notes

- Navigates to `routes.devices.details(id)`; disabled and non-clickable when no ID is resolved.
- Designed to stay invisible during loading to prevent layout flicker when the ID resolves asynchronously.
