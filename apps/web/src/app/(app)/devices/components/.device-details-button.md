# device-details-button.tsx

A client-side button component that navigates to a device's detail page, built on top of the shared `Button` component from the OpenFrame frontend core library. It gracefully handles missing device identifiers and loading states, and notifies callers when an in-window navigation actually occurs.

## Key Components

- **`DeviceDetailsButton`** — The main exported component. Resolves a target device ID from either `machineId` or `deviceId` props, builds a link to the device details route, and renders a `Button` that is disabled or hidden depending on ID availability.
- **`DeviceDetailsButtonProps`** — Props interface controlling label, visual variant, tab behavior, and an `onNavigate` callback for same-window navigation events.

### Behavior Notes
- If no `id` is available and the value isn't still loading (via `useLoadingScope`), the component renders nothing (`null`), since there's no valid destination.
- While the ID is loading, the button renders in a disabled state rather than disappearing, to avoid layout shift.
- The `onNavigate` callback fires only when the click causes **current-window navigation** (not a modifier/middle click, and not when `openInNewTab` is true), via `navigatesCurrentWindow`. This is useful for dismissing overlays (e.g. a `LogDrawer`) that would otherwise obscure the newly navigated page.

## Usage Example

```typescript
import { DeviceDetailsButton } from '@/components/device-details-button';

function DeviceRow({ device, closeOverlay }: { device: Device; closeOverlay: () => void }) {
  return (
    <DeviceDetailsButton
      deviceId={device.id}
      label="View Details"
      variant="accent"
      onNavigate={closeOverlay}
    />
  );
}

// Opening in a new tab, without needing an onNavigate handler
function DeviceLink({ machineId }: { machineId: string }) {
  return (
    <DeviceDetailsButton
      machineId={machineId}
      openInNewTab
      label="Open in New Tab"
    />
  );
}
```
