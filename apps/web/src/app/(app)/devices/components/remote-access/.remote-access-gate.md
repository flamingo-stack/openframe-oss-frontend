Approval gate component that controls when a remote desktop (MeshCentral) session surface is allowed to mount for a given device, rendering request/approval UI states (awaiting, denied, timed out, busy, unreachable, error) before passing control to its `children`.

## Key Components

- **`RemoteAccessGate`** - Main component. Fires a remote access request automatically on mount (when the `remote-access-approval` feature gate is `on`), renders the appropriate state screen (loading, policy-denied, awaiting approval with countdown, denied, timed out, busy, unreachable, or error), and only mounts `children` (the actual session UI) once `approval.state === 'approved'`. When the gate is `off`, renders `children` directly for legacy behavior.
- **`formatRemaining(expiresAt, nowMs)`** - Formats remaining time until expiry as `mm:ss`, floored at zero.
- **`BusyMark`** - Small animated/skeleton icon indicating an in-flight or pending request; switches between a skeleton (loading scope) and a live pulsing icon.
- **`ApprovedSessionScope`** - Internal wrapper mounted only after approval; resolves the backend session via `useRemoteSession` and provides session context (`requestId`, `session`, `ended`, `endSession`, `requestAgain`) to `children` via `RemoteAccessSessionProvider`.

## Usage Example

```typescript
import { RemoteAccessGate } from './remote-access-gate';

function RemoteDesktopPage({ deviceId, deviceName }: { deviceId: string; deviceName?: string }) {
  const router = useRouter();

  return (
    <RemoteAccessGate
      deviceId={deviceId}
      deviceName={deviceName}
      reason="Troubleshooting from ticket #4821"
      onBack={() => router.push(`/devices/${deviceId}`)}
    >
      {/* Mounted only once the end user approves the request */}
      <RemoteDesktopSessionSurface deviceId={deviceId} />
    </RemoteAccessGate>
  );
}
```

The component relies on `useRemoteAccessApprovalGate` (feature flag resolution), `useRemoteAccessApproval` (request lifecycle), and `useBusyDeviceLiveSession` (detecting another technician's active session) to drive its state machine. No manual state management is required by consumers - only `deviceId`, `onBack`, and the gated `children` need to be supplied.
