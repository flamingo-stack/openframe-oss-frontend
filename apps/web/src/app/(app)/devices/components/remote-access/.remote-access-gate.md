# remote-access-gate.tsx

Client component that gates access to a remote desktop (MeshCentral) session behind an approval workflow, rendering the appropriate UI for each stage (loading, awaiting approval, denied, timed out, busy, error) before mounting the actual session surface passed as `children`. When the approval feature flag is off, it renders `children` directly, preserving legacy auto-start behavior.

## Key Components

- **`RemoteAccessGate`** — Main exported component. Orchestrates the approval lifecycle using `useRemoteAccessApprovalGate`, `useRemoteAccessApproval`, and `useBusyDeviceLiveSession`. Auto-fires the access request on mount, tracks a countdown while awaiting end-user approval, and renders state-specific screens (loading, policy-denied, awaiting, denied, timed-out, busy, unreachable, error). Only mounts `children` once the request reaches the `approved` state.
- **`formatRemaining(expiresAt, nowMs)`** — Formats a countdown as `mm:ss` until an ISO expiry timestamp, floored at zero.
- **`BusyMark`** — Internal helper rendering a pulsing "live" busy icon, or a skeleton placeholder when inside a loading scope (gate flag unresolved).
- **`ApprovedSessionScope`** — Internal component mounted only once approved; resolves the backend remote session via `useRemoteSession` and provides it (plus `endSession`/`requestAgain`) through `RemoteAccessSessionProvider` context to `children`.

## Usage Example

```typescript
import { RemoteAccessGate } from './remote-access-gate';
import { RemoteDesktopSurface } from './remote-desktop-surface';

function RemoteScreenPage({ deviceId, deviceName }: { deviceId: string; deviceName?: string }) {
  const router = useRouter();

  return (
    <RemoteAccessGate
      deviceId={deviceId}
      deviceName={deviceName}
      reason="Prefilled from support ticket #1234"
      onBack={() => router.push(`/devices/${deviceId}`)}
    >
      <RemoteDesktopSurface deviceId={deviceId} />
    </RemoteAccessGate>
  );
}
```

The `children` prop (e.g. `RemoteDesktopSurface`) is only rendered once the approval reaches the `approved` state, preventing any tunnel/connection side effects from firing before the end user grants access. Inside the approved scope, `children` can consume `useRemoteAccessSession()` (from `remote-access-session-context`) to access the resolved session, dialog id, and `endSession`/`requestAgain` actions.
