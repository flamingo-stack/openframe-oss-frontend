Pixel-perfect skeleton loading state for the device details page, rendering placeholder UI that exactly mirrors the real page layout (header, tabs, tables, info cards) to prevent layout shifts during data fetching.

## Key Components

### Helper Skeletons
- **`TextSkeleton`** — Typography-aware text placeholder; uses an invisible character to match the exact line-box height of a given typography token, preventing header height jumps
- **`TagSkeleton`** — Matches the real `Tag` pill component (`h-8 rounded-md`)
- **`SectionHeadingSkeleton`** — Mirrors `h3.text-h5` section headings
- **`InfoCardSkeleton`** — Replicates the core `InfoCard` layout with configurable row count, title, subtitle, and progress bar slots
- **`InfoCellSkeleton`** — Mirrors the `InfoCell` header cell (optional icon + value + static label)
- **`CustomerCellSkeleton`** — Mirrors the customer header cell with a 40px avatar skeleton

### Composite Skeletons
- **`TableTabSkeleton`** — Standard table-tab loading pattern: real `Input` search bar + empty `DataTable` with `loading` prop; reused across Users, Software, Vulnerabilities, Policies, Queries, and Tickets tabs
- **`DeviceInfoSectionSkeleton`** — Full responsive info section matching mobile/tablet/desktop breakpoints
- **`SearchInputSkeleton`** — Renders the real `Input` component (not a grey bar) so chrome is pixel-identical during load

### Constants
- **`SKELETON_ACTIONS`** / **`SKELETON_MENU_ACTIONS`** — Disabled `PageActionButton` and `ActionsMenuGroup` arrays mirroring the live Remote Control, Remote Shell (CMD/PowerShell), and Run Script actions
- **Column sets** (`USERS_SKELETON_COLUMNS`, `SOFTWARE_SKELETON_COLUMNS`, etc.) — 1:1 column definitions matching each real tab's `useDataTable` column defs

## Usage Example

```typescript
// Rendered automatically by Next.js via loading.tsx or Suspense fallback
import { DeviceDetailsSkeleton } from './device-details-skeleton';

export default function Loading() {
  return <DeviceDetailsSkeleton />;
}
```
