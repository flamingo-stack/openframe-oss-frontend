Implements step 2 of the run-script modal flow, allowing a user to review a single script's details and override per-run settings (timeout, privilege level, arguments, environment variables) before dispatching a `batchRunScript` mutation to a single target machine.

## Key Components

- **`RunScriptConfigStep`** — Public entry component; wraps the reader in a `LoadingSuspense` boundary with a "Loading script settings" label.
- **`RunScriptConfigStepReader`** — Detects whether it's rendering inside a loading scope (Suspense fallback) and branches to either a "no script" view or the live data-fetching component.
- **`RunScriptConfigStepLive`** — Suspends via `useLazyLoadQuery` to fetch script details (`scriptDetailRelayQuery`).
- **`RunScriptConfigStepView`** — Core presentational component with the form UI: script summary card, timeout input, "Run as User" checkbox, script argument/env var editors (`ScriptArguments`), and Back/Run action buttons.
- **`runFormSchema`** — Zod schema validating timeout bounds (1–86400 seconds), `runAsUser` flag, and argument/env var arrays.
- **`RunScriptConfigStepProps`** — Props interface: `scriptId`, `machineId`, `onBack`, `onRan`.

## Usage Example

```typescript
import { RunScriptConfigStep } from './run-script-config-step';

function RunScriptModal({ scriptId, machineId }: { scriptId: string; machineId: string }) {
  const [step, setStep] = useState<'config' | 'running'>('config');

  if (step === 'config') {
    return (
      <RunScriptConfigStep
        scriptId={scriptId}
        machineId={machineId}
        onBack={() => setStep('select')}
        onRan={() => setStep('running')}
      />
    );
  }

  return <ScriptsRunningConfirmation />;
}
```

The component seeds form defaults from the script's saved configuration (timeout, privilege level, args, env vars) once loaded via `useEffect`, falling back to a single empty row for arguments/env vars when none are saved. On submit, it serializes form data and commits the `batchRunScriptMutation`, calling `onRan` on success or showing a destructive toast on error/validation failure.
