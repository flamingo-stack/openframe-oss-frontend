# run-script-config-step.tsx

Second step of the run-script modal: displays a single script's details and lets the user override its run-time parameters (timeout, privilege level, arguments, environment variables) before dispatching a `batchRunScript` mutation against a single target machine.

## Key Components

- **`RunScriptConfigStep`** — Public entry component. Wraps the step in a `LoadingSuspense` boundary with a "Loading script settings" label.
- **`RunScriptConfigStepReader`** — Detects whether it's rendering inside the loading fallback scope (`useLoadingScope`) and either renders the empty/loading view or triggers the live data fetch.
- **`RunScriptConfigStepLive`** — Suspends on `scriptDetailRelayQuery` to fetch script details via Relay, then hands data to the view.
- **`RunScriptConfigStepView`** — Core UI and form logic:
  - Uses `react-hook-form` + `zodResolver` with `runFormSchema` (timeout, `runAsUser`, `scriptArgs`, `envVars`).
  - Seeds form defaults from the loaded script (`defaultTimeoutSeconds`, `privilegeLevel`, `defaultArgs`, `envVars`) via `useEffect`/`reset`.
  - Renders `ScriptSummaryCard` plus editable fields for timeout, run-as-user checkbox, and two `ScriptArguments` lists (script args and env vars).
  - On submit, calls `commitBatchRun` (from `batchRunScriptMutation`) with the single `machineId`, showing a destructive toast on error and invoking `onRan()` on success.
- **`runFormSchema`** / **`RunFormData`** — Zod schema and inferred type validating timeout bounds (1–86400 seconds) and argument/env-var row shapes.
- **`EMPTY_ARG_ROW`** / **`EMPTY_ENV_ROW`** — Placeholder rows shown when the script has no saved arguments/env vars; dropped on submit if left empty.

## Usage Example

```typescript
import { RunScriptConfigStep } from '@/app/(app)/scripts/script/components/run-script-config-step';

function RunScriptModal({ scriptId, machineId }: { scriptId: string; machineId: string }) {
  const [step, setStep] = useState<'select' | 'config' | 'done'>('config');

  if (step === 'config') {
    return (
      <RunScriptConfigStep
        scriptId={scriptId}
        machineId={machineId}
        onBack={() => setStep('select')}
        onRan={() => setStep('done')}
      />
    );
  }

  return null;
}
```

The component is designed to be used as one step within a multi-step modal flow, where `onBack` navigates to a prior step (e.g., script selection) and `onRan` advances to a confirmation screen once the script has been dispatched.
