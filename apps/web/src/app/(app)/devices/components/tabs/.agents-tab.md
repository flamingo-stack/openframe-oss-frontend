# agents-tab.tsx

Renders the "Agent Versions" section of a device detail view, merging installed agents and tool connections into a unified, deduplicated list of agent status cards (with loading skeletons and an empty state).

## Key Components

- **`AgentsTab`** — Main exported component. Accepts a `device` prop, shows loading skeletons via `useLoadingScope`, an empty state when no agents exist, or a grid of `InfoCard`s otherwise.
- **`combineAgents(device)`** — Merges three data sources into one list of `CombinedAgent` objects: installed agents, tool connections (for agents without an installed-agent record), and expected-but-not-yet-reporting agents (shown as `pending` placeholders). Sorted alphabetically for stable ordering.
- **`agentCardData(agent)`** — Builds the `InfoCardData` (rows + footer) for a single agent, conditionally including Status/Last Seen only for agents with live status (`FLEET_MDM`, `MESHCENTRAL`).
- **`AGENT_CARD_SKELETONS`** — Precomputed loading skeleton shapes, one per known agent type, matching the real card's row/footer structure.
- **`getAgentDisplayStatus`** / **`formatTimestamp`** / **`formatRelative`** — Helpers for resolving status and formatting date/time values.
- **`AgentCards`** — Internal layout wrapper providing the section heading and responsive grid, shared between loading and loaded states.
- **`agentTypeToToolType`** — Static mapping from backend `agentType` strings to internal `toolType` identifiers.

## Usage Example

```typescript
import { AgentsTab } from './agents-tab';
import type { Device } from '../../types/device.types';

function DeviceDetailPanel({ device }: { device: Device }) {
  return (
    <div className="flex flex-col gap-6">
      {/* Other device detail tabs/sections */}
      <AgentsTab device={device} />
    </div>
  );
}
```

The component is self-contained: it reads `device.installedAgents` and `device.toolConnections`, derives expected agents via `getExpectedAgentTypes`, and automatically handles the loading state through the ambient `useLoadingScope` hook—no additional props or data fetching are required from the consumer.
