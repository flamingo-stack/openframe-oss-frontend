# users-tab.tsx

Renders the "Users" tab on a device detail page, displaying a searchable, sortable table of OS-level user accounts (username, UID, type, group, shell, and login status) for a given device. Handles loading skeletons, empty states, and deploy-pending states consistently with other device detail tabs.

## Key Components

- **`UsersTab`** — Main exported component. Accepts a `device` prop and renders a `DataTable` of users with a sticky search toolbar, end-user email tags, and contextual empty states.
- **`UserNameCell`** — Renders username plus a derived role label (e.g., "Active session", "User account"), with skeleton support via `useLoadingScope`.
- **`UserTypeCell`** — Renders the capitalized account type, falling back to `EmptyValue` or a skeleton bar while loading.
- **`roleLabel(user)`** — Helper that derives a human-readable role string from `isLoggedIn`/`type` fields.
- **`USER_COLUMNS`** — Column layout config (header, width, responsive `hideAt` breakpoints) shared between the live table and skeleton rendering.
- **`USERS_TAB_SKELETON_ROWS`** — Constant (10) defining placeholder row count during loading, kept in sync with the shared `DataTable.Body` default.

## Usage Example

```typescript
import { UsersTab } from '@/app/(authenticated)/devices/[id]/tabs/users-tab';
import type { Device } from '@/app/(authenticated)/devices/types/device.types';

function DeviceDetailTabs({ device }: { device: Device | null }) {
  return (
    <div className="tab-panel">
      <UsersTab device={device} />
    </div>
  );
}
```

The component internally manages search state (debounced 300ms), filters users client-side by username/group/type, and switches between three states: loading (skeleton rows), empty (no device, no users, or Fleet data pending deployment), and populated (searchable `DataTable`). Loading behavior is driven by the ambient `useLoadingScope()` context rather than a prop, allowing parent components to control the loading state declaratively.
