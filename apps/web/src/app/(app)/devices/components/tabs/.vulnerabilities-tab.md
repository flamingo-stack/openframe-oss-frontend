# vulnerabilities-tab.tsx

Renders the Vulnerabilities tab for a device's detail view, displaying CVEs detected on that machine. It switches between two implementations based on the `software-management` feature flag: a legacy Fleet-payload-based table or the Software module's own table backed by `deviceVulnerabilities`.

## Key Components

- **`VulnerabilitiesTab`** — Public entry point. Resolves the `software-management` feature flag gate and delegates to `FleetVulnerabilitiesTab` (flag off) or `ModuleVulnerabilitiesTab` (flag on/loading).
- **`ModuleVulnerabilitiesTab`** — Internal component rendering the module's search/filter frame (`SoftwareListFrame`) wrapping `DeviceVulnerabilitiesTable`, wrapped in a `ContentErrorBoundary` so a failed list doesn't crash the page. Shows a `DataSyncBanner` when the last vulnerability scan predates the current inventory.
- **`vulnerabilitiesEmptyState(device)`** — Maps the device's pipeline stage (via `getVulnerabilitiesEmptyReason`) to the appropriate empty-state UI: disconnected agent, collecting inventory, deploying agent, scan pending, or genuinely no vulnerabilities.
- **`NO_VULNERABILITIES`** — Shared static empty-state element for the "no vulnerabilities found" case.
- **`SEARCH_PLACEHOLDER`** — Search box placeholder text constant.

## Usage Example

```typescript
import { VulnerabilitiesTab } from './vulnerabilities-tab';
import type { Device } from '../../types/device.types';

function DeviceDetailTabs({ device }: { device: Device | null }) {
  return (
    <div>
      {/* Renders either the Fleet-based or module-based vulnerabilities view
          depending on the software-management feature flag */}
      <VulnerabilitiesTab device={device} />
    </div>
  );
}
```

The component requires no additional props configuration — it internally resolves the feature flag state and inventory-pipeline stage to decide what to render, including loading and error states.
