Renders a single device log line (time, level, message, optional hostname/count chips) that opens the Log Details drawer, plus a day-grouping wrapper and heading used by the device log list. Supports a GraphQL-fragment-driven loading state so rows render skeleton placeholders while data streams in.

## Key Components

- **`DeviceLogEntry`** — Plain interface representing a log entry's data (decoupled from the GraphQL fragment) used to pass a stable copy into the drawer.
- **`DeviceLogRow`** — Main component rendering one log line as a clickable `Button`/`li`. Resolves data via `useFragment(deviceLogRow_entry$key)`, shows loading skeletons via `useLoadingScope()` when data is unavailable, displays time/level/message, and conditionally shows a hostname chip (always on multi-device lists, only on mismatch for single-device lists) and a count chip when `count > 1`.
- **`DeviceLogDayGroup`** — Wraps a day's rows in a `<section>`/`<ul>`, optionally rendering the `DeviceLogDayHeader` when a `date` is provided.
- **`DeviceLogDayHeader`** — Renders the uppercase formatted date heading with a divider line; shows a skeleton bar while loading.
- **`deviceLogRowFragment`** — GraphQL fragment (`deviceLogRow_entry`) defining the fields fetched for each row: `timestamp`, `agentTimestamp`, `level`, `message`, `machineId`, `hostname`, `count`.

## Usage Example

```typescript
import { DeviceLogRow, DeviceLogDayGroup, type DeviceLogEntry } from './device-log-row';

function DeviceLogList({ entries, deviceHostname, selectedEntry, onSelectEntry }) {
  return (
    <DeviceLogDayGroup date={new Date()}>
      {entries.map((entry) => (
        <DeviceLogRow
          key={entry.id}
          entry={entry.fragmentRef}
          deviceHostname={deviceHostname}
          selected={selectedEntry?.timestamp === entry.timestamp}
          onSelect={(log: DeviceLogEntry) => onSelectEntry(log)}
        />
      ))}
    </DeviceLogDayGroup>
  );
}
```

When `entry` is `null` (e.g., during pagination fetch), `DeviceLogRow` automatically renders its skeleton state via `useLoadingScope`, keeping layout stable while data loads.
