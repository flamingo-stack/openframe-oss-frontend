# device-log-layout.ts

Defines shared Tailwind CSS class constants for the device log viewer UI, ensuring consistent row geometry between live log rows and their loading skeletons (preventing layout shift) and optimizing rendering performance for large, continuously-updating log lists.

## Key Components

- **`DEVICE_LOG_LINE`** — Flex layout classes for a single log line, shared by both live rows and skeleton placeholders to keep dimensions identical during content swap.
- **`DEVICE_LOG_TIME_COLUMN`** — Fixed-width column (`12ch`) sized to fit a timestamp like `13:23:05.486`.
- **`DEVICE_LOG_LEVEL_COLUMN`** — Fixed-width slot (`w-16`) for the log level chip (e.g. `INFO`, `ERROR`), ensuring the message column never shifts regardless of level label length.
- **`DEVICE_LOG_DAY_HEADER`** — Layout classes for the date heading grouping each day's log lines; mirrored by the skeleton state.
- **`DEVICE_LOG_LIST_CLASS`** — Single-column CSS grid (not flex) for stacking days/lines, chosen deliberately to avoid WebKit's expensive re-measurement of flex children on every layout pass during pagination/live-tail updates.
- **`DEVICE_LOG_SENTINEL_CLASS`** — Minimal-height (`h-px`) marker elements used as scroll-position probes for infinite scroll and live-tail detection.

## Usage Example

```typescript
import {
  DEVICE_LOG_LINE,
  DEVICE_LOG_TIME_COLUMN,
  DEVICE_LOG_LEVEL_COLUMN,
  DEVICE_LOG_LIST_CLASS,
  DEVICE_LOG_SENTINEL_CLASS,
} from './device-log-layout';

function DeviceLogList({ lines }: { lines: LogLine[] }) {
  return (
    <div className={DEVICE_LOG_LIST_CLASS}>
      <div className={DEVICE_LOG_SENTINEL_CLASS} data-role="top-sentinel" />
      {lines.map((line) => (
        <div key={line.id} className={DEVICE_LOG_LINE}>
          <span className={DEVICE_LOG_TIME_COLUMN}>{line.timestamp}</span>
          <span className={DEVICE_LOG_LEVEL_COLUMN}>{line.level}</span>
          <span>{line.message}</span>
        </div>
      ))}
      <div className={DEVICE_LOG_SENTINEL_CLASS} data-role="bottom-sentinel" />
    </div>
  );
}
```

These constants should always be imported from this shared module rather than redefined inline, so skeleton and live states remain pixel-identical.
