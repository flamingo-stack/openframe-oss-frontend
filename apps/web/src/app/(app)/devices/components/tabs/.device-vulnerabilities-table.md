# device-vulnerabilities-table.tsx

Renders the "Vulnerabilities" tab on the device detail page, listing the CVEs found on a specific machine. It reuses the same `VulnerabilityTable` component and `Vulnerability` fragment used by the fleet-wide vulnerability list, scoped to a single `machineId`, with search-only filtering and infinite scroll pagination via Relay.

## Key Components

- **`DeviceVulnerabilitiesTable`** — Public entry component. Wraps the reader in a `LoadingSuspense` boundary so the tab has its own loading fallback independent of the rest of the device page.
- **`DeviceVulnerabilitiesTableReader`** — Checks `useLoadingScope()`; if still inside a loading scope (e.g., device or feature flag not yet resolved), renders an empty `VulnerabilityTable` skeleton instead of issuing a query.
- **`DeviceVulnerabilitiesTableQuery`** — Executes the Relay query via `useLazyLoadQuery`, then paginates the result through `usePaginationFragment`, mapping edges to rows and wiring up infinite scroll (`loadNext`/`hasNext`/`isLoadingNext`).
- **`deviceVulnerabilitiesTableQuery`** / **`deviceVulnerabilitiesTableFragment`** — GraphQL query and `@refetchable` fragment definitions, keyed by `machineId`, `search`, `first`, and `after` cursor arguments.
- **`DeviceVulnerabilitiesTableProps`** — Props contract: `machineId`, `debouncedSearch`, `isPending` (guards stale-data flashes), `emptyState` (ReactNode for no-CVE state), `onEmptyChange` callback, and `stickyHeaderOffset`.

## Usage Example

```typescript
import { DeviceVulnerabilitiesTable } from '@/app/(app)/devices/[id]/components/device-vulnerabilities-table';

function DeviceVulnerabilitiesTab({ machineId, search }: { machineId: string; search: string }) {
  const [isEmpty, setIsEmpty] = useState(false);

  return (
    <DeviceVulnerabilitiesTable
      machineId={machineId}
      debouncedSearch={search}
      isPending={false}
      emptyState={<p>No vulnerabilities detected on this device.</p>}
      onEmptyChange={setIsEmpty}
      stickyHeaderOffset="64px"
    />
  );
}
```

Consumers typically place this inside a device detail tab, passing a debounced search term and an `emptyState` node tailored to the device's scan pipeline stage.
