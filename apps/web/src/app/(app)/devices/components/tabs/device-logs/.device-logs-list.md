A client-side React/Relay component that renders a paginated, auto-refreshing device logs list grouped by local day, with infinite scroll, loading states, and error handling for live tail and pagination failures.

## Key Components

- **`DeviceLogsFilter`** — Type alias for the GraphQL filter input used to query device logs.
- **`DeviceLogsList`** — Public entry component; wraps the reader in a `LoadingSuspense` boundary and remounts via `listKey` when the filter identity changes.
- **`DeviceLogsListReader`** — Detects an active loading scope and renders a skeleton first page instead of firing a query, otherwise delegates to `DeviceLogsListQuery`.
- **`DeviceLogsListQuery`** — Core implementation: runs the paginated Relay query (`deviceLogsListQueryNode` / `deviceLogsList_query` fragment), manages infinite scroll (`useGridInfiniteScroll`), top-sentinel detection (`useIsAtTop`), and live tail polling (`useDeviceLogsLiveTail`).
- **`DeviceLogsLoadingPage`** — Internal skeleton renderer showing `PAGE_SIZE` placeholder rows, optionally with a day header.
- **`PAGE_SIZE`** — Constant (100) controlling page size for both initial load and pagination.

## Usage Example

```typescript
import { DeviceLogsList, type DeviceLogsFilter } from './device-logs-list';

function DeviceLogsPanel() {
  const filter: DeviceLogsFilter = { severity: 'ERROR' };
  const [selectedKey, setSelectedKey] = useState<string | null>(null);

  return (
    <DeviceLogsList
      listKey={JSON.stringify(filter)}
      machineIds={['device-123']}
      filter={filter}
      deviceHostname="workstation-01"
      isPending={false}
      autoUpdate
      hasFilters={false}
      onResetFilters={() => {}}
      selectedKey={selectedKey}
      onSelect={(key, entry) => setSelectedKey(key)}
    />
  );
}
```

Notes:
- `machineIds`/`organizationIds` must be `undefined` (not `[]`) to mean "all"—an empty array is rejected by the API.
- Pass a stable `listKey` derived from the filter so the list remounts cleanly when filters change during a React transition, keeping prior rows visible until the new query resolves.
- The component is a client component (`'use client'`) and depends on Relay environment context and Flamingo's shared UI/loading primitives.
