# network-tab.tsx

Renders the "Network" tab of the device details view, displaying a device's interface identity, geolocation, and categorized IPv4/IPv6 addresses with loading, deploying, and empty states handled.

## Key Components

- **`NetworkTab`** — Main component accepting a `device: Device | null` prop. Uses `useLoadingScope()` to coordinate skeleton rendering while device data is being fetched, and conditionally renders:
  - A **Network** card (Public IP, Primary IPv4, MAC Address)
  - A **Location** card (City, Country from Fleet GeoIP)
  - **IPv4 Addresses** / **IPv6 Addresses** cards in a responsive two-column grid
- **`sortIpv4(addresses)`** — Numeric-aware sort helper for dotted IPv4/CIDR strings, comparing each octet as a number rather than lexicographically.
- **`Labeled`** — Small layout wrapper that renders an uppercase section title (`h3`) above its children.
- **`TYPICAL_IP_ROWS`** — Constant (2) used to size the skeleton placeholder for IP address lists while loading.

## Usage Example

```typescript
import { NetworkTab } from './network-tab';
import type { Device } from '../../types/device.types';

function DeviceDetailsPanel({ device }: { device: Device | null }) {
  return (
    <div>
      <NetworkTab device={device} />
    </div>
  );
}
```

The component automatically handles three states:
- **Loading** — all sections render with skeletons via `useLoadingScope()`.
- **Deploying** — if `device.sources.fleet === 'skipped-pending'`, shows `TabDeployingEmptyState`.
- **Empty** — if no interface, location, or IP data exists, shows `TabEmptyState` with a `Hierarchy02Icon`.

The Fleet-reported `primary_ip` is always pinned to the top of the sorted IPv4 list when present, and addresses are split into IPv4/IPv6 buckets based on the presence of a colon (`:`) in the string.
