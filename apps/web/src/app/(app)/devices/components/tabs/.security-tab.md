# security-tab.tsx

Renders the "Security" tab of a device detail view, showing disk encryption status, installed security agent versions, and Fleet policy/posture compliance. Handles loading, empty, and "deploying" states, and derives all displayed sections dynamically from whatever security data the device actually reports.

## Key Components

- **`SecurityTab`** — Main exported component. Accepts a `device: Device | null` prop, resolves loading/empty states via `useLoadingScope`, and renders one `SecuritySectionBlock` per available security section (Encryption, Security Agents, Posture).
- **`buildSections(device)`** — Builds the list of `SecuritySection`s from real device data only; sections with no backing data are omitted (no "Unknown/N/A" filler).
- **`LOADING_SECTIONS`** — Static skeleton version of a typical device's sections, used while data is loading, sourced from the same copy tables (`SECTION`, `ROW`, `AGENT_CARD`) as `buildSections` to keep loading and loaded UI in sync.
- **`SecuritySectionBlock`** — Renders a section heading plus a responsive grid of `SecurityStatusCard`s.
- **`SecurityStatusCard`** — Card for a group of related rows (e.g., one agent or one posture summary), with loading-aware title skeleton.
- **`StatusRow`** — Single label/value row using the shared `LeaderRow` component, with tone and icon driven by `SecurityStatus` (`success` | `error` | `warning` | `neutral`).
- **`normalizeVersion(version)`** — Normalizes agent version strings, treating `"unknown"`/empty values as absent.
- **Types** — `SecurityTabProps`, `SecurityStatus`, `SecurityRow`, `SecurityCard`, `SecuritySection`.

## Usage Example

```typescript
import { SecurityTab } from './security-tab';
import type { Device } from '../../types/device.types';

function DeviceDetailPanel({ device }: { device: Device | null }) {
  return (
    <div className="device-tabs">
      <SecurityTab device={device} />
    </div>
  );
}
```

When `device` is `null` and not loading, the component renders a `TabEmptyState`. While loading (via `useLoadingScope`), it renders skeleton rows/cards derived from `LOADING_SECTIONS`. If the device's Fleet source is `skipped-pending`, it renders `TabDeployingEmptyState` instead of the generic empty state.
