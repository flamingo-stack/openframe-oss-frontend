# software-tab.tsx

Renders the Software tab on a device detail page, switching between two implementations based on the `software-management` feature flag: a Fleet-native read-only view when the flag is off, and the Software module's full-featured table (with search, filters, and clickable software rows) when it's on.

## Key Components

- **`SoftwareTab`** — Top-level exported component. Reads the `software-management` feature flag via `useFeatureFlagGate` and delegates to `FleetSoftwareTab` (flag off) or `ModuleSoftwareTab` (flag on/loading), avoiding a flicker between implementations while the flag resolves.
- **`ModuleSoftwareTab`** — Internal component used when the feature flag is on. Wraps `SoftwareListFrame` + `DeviceSoftwareTable` in a `ContentErrorBoundary`, scoping loading state to the device/flag resolution and showing `NO_SOFTWARE` when there's no `machineId` to query.
- **`softwareEmptyState(device)`** — Derives the appropriate empty state (disconnected, deploying, collecting, or no-software) by reusing `getVulnerabilitiesEmptyReason` from the Vulnerabilities tab's shared pipeline-stage logic, minus the CVE-specific stages.
- **`NO_SOFTWARE`** — Static fallback empty state shown when no software data applies.
- **`SEARCH_PLACEHOLDER`** — Placeholder text for the software search input.

## Usage Example

```typescript
import { SoftwareTab } from './software-tab';
import type { Device } from '../../types/device.types';

function DeviceDetailPanel({ device }: { device: Device | null }) {
  return (
    <section>
      <h2>Software</h2>
      <SoftwareTab device={device} />
    </section>
  );
}
```

The component requires no additional configuration — it automatically resolves the active implementation via the `software-management` feature flag and handles loading, empty, and error states internally.
