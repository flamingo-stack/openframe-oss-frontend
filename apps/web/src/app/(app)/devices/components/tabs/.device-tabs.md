## device-tabs.tsx

Defines the full set of tabs rendered on the device detail page, including feature-flag-gated tabs (Incidents, Remote Sessions, Directory, Users) that must stay mounted while their gates resolve so panels never remount mid-load.

## Key Components

- **`ALL_DEVICE_TABS`** — Array of `TabItem` entries describing every possible device detail tab (Overview, Vulnerabilities, Incidents, Policies, Security, Agents, Tickets, Hardware, OS, Network, Users, Directory, Software, Device Logs, Remote Sessions, Assigned Articles), each with an `id`, `label`, `icon`, and `component`.
- **`useDeviceTabs(directoryGate)`** — Hook that filters `ALL_DEVICE_TABS` down to the visible set for the current session, based on the session-recordings gate, incidents gate, and Tenant Management V2 phase-2/directory gate. Only a gate value of `'off'` hides a tab; while loading, the tab stays visible and renders its own loading state.
- **`DeviceDirectoryGateContext`** — React context holding the single page-level read of the directory gate, ensuring the tab bar and tab panel never disagree on gate state.
- **`GatedIncidentsTab` / `GatedRemoteSessionsTab` / `GatedUsersTab` / `GatedDirectoryTab`** — Module-level wrapper components that keep gated tabs always mounted, showing a `LoadingWhen` placeholder until their respective feature flag resolves.
- **`ArticlesTab`** — Wrapper around `AssignedArticlesTab` that waits for `device.machineId` before resolving its target.
- **`REMOTE_SESSIONS_TAB_ID`** — Exported constant (`'remote-sessions'`) typed against the `DeviceDetailTab` route union via `satisfies`, used elsewhere to reference this tab safely.

## Usage Example

```typescript
import { useDeviceTabs, DeviceDirectoryGateContext } from './device-tabs';

function DeviceDetailPage({ device, directoryGate }: { device: Device; directoryGate: FeatureFlagGate }) {
  const tabs = useDeviceTabs(directoryGate);

  return (
    <DeviceDirectoryGateContext.Provider value={directoryGate}>
      <TabsComponent tabs={tabs} device={device} />
    </DeviceDirectoryGateContext.Provider>
  );
}
```

Consumers should always provide `DeviceDirectoryGateContext` at the page level (not per-tab) so the tab bar's visibility decision and the rendered tab's loading state read the same gate value.
