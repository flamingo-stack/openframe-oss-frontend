# tickets-tab.tsx

Renders the Tickets tab on a device's detail page, showing tickets scoped to the current device via a server-side `deviceIds` filter. Handles loading, error, empty, and search states, and reuses the shared ticket table columns with device-specific layout adjustments.

## Key Components

- **`TicketsTab`** — Main component accepting a `device` prop. Fetches tickets filtered by `device.machineId` using `useTicketsQuery`, builds a device-scoped column set, and renders a searchable, infinite-scrolling `LiveTable`.
- **Column customization** — Derives columns from `getTicketTableColumns`, drops the redundant `source` column, applies fixed widths from `DEVICE_TICKET_COLUMNS`, and appends `getTicketOpenColumn()` for the open-in-new-tab action. Anchors the `status` filter dropdown to `bottom-end` since it's the last data column.
- **Loading & empty states** — Uses `useLoadingScope` to detect page-level loading, shows placeholder rows via `loadingPlaceholderRows` while loading, and distinguishes a true empty state (`TabEmptyState`) from a zero-match search result (table's built-in `emptyState`).
- **Sticky toolbar** — Uses `useStickyToolbar` to keep the `SearchInput` pinned while scrolling, hidden entirely when the tab is genuinely empty and not searching.

## Usage Example

```typescript
import { TicketsTab } from './tickets-tab';
import type { Device } from '../../types/device.types';

function DeviceDetailTickets({ device }: { device: Device | null }) {
  return (
    <section>
      <TicketsTab device={device} />
    </section>
  );
}
```

**Notes:**
- Tickets are matched strictly by `deviceId` server-side; a ticket is excluded once its device is unlinked (no client-side owner fallback).
- Requires `device.machineId` to be present; the query is disabled (`enabled: Boolean(machineId)`) until it's available.
- Search input is debounced by 300ms via `useDebounce` before triggering a refetch.
- Pagination uses `TICKETS_PAGE_SIZE` with infinite-scroll via `fetchNextPage`/`hasNextPage`.
