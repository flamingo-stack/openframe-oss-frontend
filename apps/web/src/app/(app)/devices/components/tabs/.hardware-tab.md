# hardware-tab.tsx

Renders the **Hardware tab** of the device detail view, presenting hardware identity, boot/uptime, CPU, memory, storage, and battery information in a responsive grid of `InfoCard` blocks. Handles loading skeletons, partial data, and empty/deploying states gracefully.

## Key Components

- **`HardwareTab({ device })`** — Main exported component. Derives and displays grouped hardware data sections (System, Boot, CPU, Memory, Storage, Batteries) from a `Device` object, with per-section conditional rendering based on data availability.
- **`Row({ optional, children })`** — Internal layout helper rendering a responsive 3-column grid row of hardware blocks. `optional` rows (e.g., batteries) are hidden during loading.
- **`Block({ heading, item, children })`** — Internal wrapper pairing a heading with an `InfoCard`, ensuring consistent height alignment across grid cells.
- **`HardwareEmptyState()`** — Empty-state UI shown when no device or hardware data exists.
- **`formatUptime(seconds)`** — Utility converting uptime seconds into a human-readable string (e.g., `"3d 4h"`).

## Usage Example

```typescript
import { HardwareTab } from './hardware-tab';
import type { Device } from '../../types/device.types';

function DeviceDetailPanel({ device }: { device: Device | null }) {
  return (
    <div className="device-tab-content">
      <HardwareTab device={device} />
    </div>
  );
}
```

The component relies on a `useLoadingScope()` context to determine whether to render skeleton placeholders. When `device` is `null` and not loading, it renders `HardwareEmptyState`. If the device's Fleet data source is `'skipped-pending'` and no hardware data exists, it renders `TabDeployingEmptyState` instead, indicating the agent hasn't reported yet.

Data sections (System, Boot, CPU, Memory, Storage) are computed independently and conditionally shown based on presence of relevant fields (via `hasDeviceInfo`), allowing partial hardware data to render without blocking the whole tab.
