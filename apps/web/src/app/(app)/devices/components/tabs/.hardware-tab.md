# hardware-tab.tsx

Renders the "Hardware" tab of the device details view, displaying system, boot, CPU, memory, storage, and battery information for a device in a responsive grid layout with loading-skeleton and empty-state support.

## Key Components

- **`HardwareTab`** — Main exported component. Accepts a `device` prop and renders grouped hardware info cards (System, Boot, CPU sharing one row; Memory and Storage each in their own row; Batteries as an optional trailing row for laptops).
- **`Row`** — Internal layout helper rendering a 3-column responsive grid (`grid-cols-1` on small screens, `grid-cols-3` on larger ones) for grouping hardware blocks. Supports an `optional` flag for rows not present on all devices (e.g., batteries).
- **`Block`** — Internal helper wrapping a single `InfoCard` with an optional heading, ensuring consistent top-alignment and equal height across grid cells.
- **`formatUptime(seconds)`** — Converts a seconds count into a human-readable uptime string (e.g., `"3d 4h"`).
- **`HardwareEmptyState`** — Empty-state UI shown when no hardware data is available.
- **`STORAGE_TITLE` / `STORAGE_SUBTITLE`** — Constants for storage card labeling.

## Usage Example

```typescript
import { HardwareTab } from './hardware-tab';
import type { Device } from '../../types/device.types';

function DeviceDetailsPanel({ device }: { device: Device | null }) {
  return (
    <div>
      {/* Renders hardware details, loading skeletons, or an empty state automatically */}
      <HardwareTab device={device} />
    </div>
  );
}
```

The component relies on `useLoadingScope()` from `@flamingo-stack/openframe-frontend-core/components/ui` to detect whether the parent view is in a loading state, automatically rendering skeleton placeholders (`EMPTY_CARD`) until `device` data resolves. It also distinguishes a "deploying" empty state (`TabDeployingEmptyState`) when the Fleet data source is pending (`device.sources.fleet === 'skipped-pending'`).

Data mapping utilities (`deviceInfoItems`, `hasDeviceInfo`, `labelsOf`) and date formatting (`formatDateTimeOnDevice`) are imported from shared modules to keep row construction and empty-value detection consistent across tabs.
