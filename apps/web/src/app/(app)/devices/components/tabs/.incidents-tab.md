# incidents-tab.tsx

Renders the **Incidents** tab within a device's detail view, displaying a server-filtered list of incidents scoped to that specific device's machine.

This component acts as a thin adapter between the device detail page and the shared `DeviceIncidentsTable`, narrowing the global incidents list to a single machine via `InsightFilter.machineIds`. Visibility of this tab is controlled elsewhere (`useDeviceTabs`), so this file focuses purely on data wiring, loading coordination, and empty/error states.

## Key Components

- **`IncidentsTab`** — Main exported component. Accepts a `device` prop and renders either an empty state, a loading-aware table, or an error boundary depending on device/loading status.
- **`IncidentsTabProps`** — Props interface requiring a `device: Device | null`.
- **`NO_INCIDENTS`** — Shared `TabEmptyState` element shown both when no `machineId` exists and when the table itself returns zero results.

## Behavior Notes

- Uses `useLoadingScope()` to detect whether the parent device query is still in flight. While loading, the component defers to `DeviceIncidentsTable`'s own loading UI rather than short-circuiting to the empty state.
- If loading has finished and `device.machineId` is still missing, renders `NO_INCIDENTS` immediately since there's no valid key to filter incidents by.
- The table is **keyed by `machineId`** so it remounts once the real id is available, preventing a wasted initial fetch against an empty id.
- Wrapped in `ContentErrorBoundary` to isolate failures to this tab without crashing the rest of the device detail page.

## Usage Example

```typescript
import { IncidentsTab } from '@/app/(app)/devices/components/tabs/incidents-tab';

function DeviceDetailTabs({ device }: { device: Device | null }) {
  return (
    <TabPanel value="incidents">
      <IncidentsTab device={device} />
    </TabPanel>
  );
}
```
