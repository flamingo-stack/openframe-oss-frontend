# os-tab.tsx

Renders the "OS" tab of a device detail view, displaying operating system identity, boot/uptime/locale information, and Fleet management metadata (team and labels) in grouped `InfoCard` sections, with loading skeletons and empty-state handling.

## Key Components

- **`OsTab`** — Main exported component. Accepts a `device` prop and renders three sections: Operating System, Boot & Time, and Management. Uses `useLoadingScope()` to detect loading state and shows skeleton placeholders accordingly. Falls back to empty/deploying states when no device data or OS data is present.
- **`formatUptime(seconds)`** — Converts a seconds value into a human-readable uptime string (e.g. `"3d 4h"`, `"< 1m"`).
- **`Section`** — Small layout wrapper rendering an uppercase section title above its children.
- **`OsEmptyState`** — Empty-state UI shown when no device or OS data exists, using `TerminalMonitorIcon`.

## Usage Example

```typescript
import { OsTab } from './os-tab';
import type { Device } from '../../types/device.types';

function DeviceDetailPanel({ device }: { device: Device | null }) {
  return (
    <div>
      {/* Renders OS identity, boot/time, and Fleet management info */}
      <OsTab device={device} />
    </div>
  );
}
```

**Behavior notes:**
- Boot/uptime calculations use a `nowSeconds` value sampled once via `useState` on mount (not `Date.now()` in render) to keep the component pure across re-renders.
- If the device has no OS, boot, or management data and Fleet enrollment is `skipped-pending`, a `TabDeployingEmptyState` is shown instead of the generic empty state.
- Dates (`Last Boot`, `Enrolled`) are formatted using `formatDateTimeOnDevice`, respecting the device's reported timezone when available.
- Each `InfoCard` independently shows a skeleton (`EMPTY_CARD` + `labelsOf(rows)`) while `loading` is true, allowing partial sections to render progressively.
