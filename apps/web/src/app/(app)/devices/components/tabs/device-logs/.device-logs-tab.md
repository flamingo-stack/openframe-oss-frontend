## device-logs-tab.tsx

Renders the "Device Logs" tab within the device details view. It wires URL-synced filters, a debounced/deferred log list, and a log entry detail drawer together, while gracefully handling the loading state before the parent `device` is resolved.

## Key Components

- **`DeviceLogsTab`** — Main component accepting a `device: Device | null` prop. Composes:
  - `DeviceLogsToolbar` — search, level filters, time range, auto-update toggle, and refresh controls.
  - `DeviceLogsList` — the actual log rows, driven by a deferred/debounced version of the filter state to avoid resending requests on every keystroke.
  - `DeviceLogDrawer` — detail panel for a selected log entry, kept open across list remounts.
  - `ContentErrorBoundary` — wraps the list so load failures don't break the whole tab.
- **`DeviceLogsTabProps`** — props interface; `device` is `null` while the page's loading scope is active.

## Usage Example

```typescript
import { DeviceLogsTab } from './device-logs-tab';
import type { Device } from '../../../types/device.types';

function DeviceDetailsPage({ device }: { device: Device | null }) {
  return (
    <div>
      {/* Other tabs... */}
      <DeviceLogsTab device={device} />
    </div>
  );
}
```

## Implementation Notes

- Uses `useLoadingScope()` to detect whether the parent device data is still loading, locking the toolbar and showing a list skeleton accordingly.
- Builds a `list` key from `machineId`, `anchor`, and the serialized `filter` object via `useMemo`, ensuring `useDeferredLogList` produces a fresh, deduplicated request per meaningful filter change (including manual refresh).
- `selected` (the chosen log entry for the drawer) is deliberately lifted above `DeviceLogsList` so the drawer persists even when the list remounts due to filter changes.
- `LoadingWhen` guards against querying with a stale/empty `machineId` right after `device` resolves, since the deferred list trails the live state by the debounce interval.
- The error boundary uses `deferredList.key` (not the live key) as its `resetKey`, preventing a failed request from being immediately resent on every re-render.
