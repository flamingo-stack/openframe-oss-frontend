## FleetSoftwareTab

Renders the Software tab for a device's detail view, sourced directly from the Fleet host payload (`device.software`) rather than a dedicated API call. This is the fallback implementation used when the `software-management` feature module is disabled; the module-backed equivalent lives in `software-tab.tsx`.

## Key Components

- **`FleetSoftwareTab({ device })`** — Main exported component. Renders a searchable, client-side sortable `DataTable` of installed software, with loading skeletons and contextual empty states based on Fleet agent status.
- **`SoftwareNameCell`** — Displays software name and version, with skeleton fallback via `useLoadingScope`.
- **`SourceCell`** — Maps a software `source` string (e.g. `apps`, `chrome_extensions`) to an icon + label via `getSourceIcon`/`SOURCE_ICON`.
- **`VulnerabilityCountCell`** — Renders a `Tag` showing "NO ISSUES" or an issue count badge.
- **`LastUsedCell`** — Formats `last_opened_at` as relative time, treating epoch/invalid dates as empty.
- **`formatLastUsed(dateString)`** — Utility converting a date string to relative time or `EMPTY_VALUE`.
- **`FLEET_SOFTWARE_COLUMNS`** — Column layout config (header labels, widths, responsive `hideAt` breakpoints).
- **`FLEET_SOFTWARE_SKELETON_ROWS`** — Number of placeholder rows (10) shown while loading.

## Usage Example

```typescript
import { FleetSoftwareTab } from './fleet-software-tab';
import type { Device } from '../../types/device.types';

function DeviceDetailPanel({ device }: { device: Device | null }) {
  return (
    <section>
      <FleetSoftwareTab device={device} />
    </section>
  );
}
```

The component handles its own data derivation (search, sort, filter) and loading/empty states internally — callers only need to pass the `device` object (or `null` while the parent query resolves). Empty states automatically distinguish between Fleet errors, disconnected agents, pending deployment, and devices still collecting their initial software inventory.
