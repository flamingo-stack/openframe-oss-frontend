## Device Added By Cell

Renders a table/detail cell showing which user enrolled a device, resolving the user's name and avatar from a GraphQL `node` query while gracefully handling missing IDs, deleted users, and failed fetches.

## Key Components

- **`DeviceAddedByCell`** — Public component. Wraps rendering in a `ContentErrorBoundary` so a failed user lookup silently falls back to an empty state instead of surfacing an error toast (the device page itself has already loaded successfully).
- **`DeviceAddedByContent`** — Wraps the reader in `LoadingSuspense` with an accessible loading label.
- **`DeviceAddedByReader`** — Checks `useLoadingScope()` to short-circuit rendering while an ancestor scope (e.g. the device page) is still loading, and skips the query entirely when `userId` is absent.
- **`DeviceAddedByQuery`** — Executes `deviceAddedByCellQuery` via `useLazyLoadQuery`, resolving the `User` node. Shows the deleted-employee placeholder if the node type doesn't match `User`, or a deleted-user avatar/name if `toUserSummary` reports the user as deleted.
- **`AddedBy`** — Presentational cell: optional avatar + `InfoCell` labeled "Added by", with a skeleton placeholder for the name while loading.

## Usage Example

```typescript
import { DeviceAddedByCell } from '@/app/components/devices/device-added-by-cell';

function DeviceRow({ device }: { device: { addedByUserId?: string | null } }) {
  return (
    <tr>
      <td>
        <DeviceAddedByCell userId={device.addedByUserId} />
      </td>
    </tr>
  );
}
```

Passing `userId={null}` (e.g. for devices enrolled before the install command tracked a user) renders the cell with no avatar and an empty name mark, without issuing any query.
