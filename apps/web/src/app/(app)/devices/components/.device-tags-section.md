Renders the "Device Tags" section of the device Overview tab, displaying a device's key/value tags as badge-styled chips, with skeleton loading placeholders while device data is being fetched.

## Key Components

- **`DEVICE_TAGS_SKELETON_COUNT`** — Constant (`3`) controlling how many skeleton chips render during loading.
- **`TAGS_ROW_CLASS`** — Shared Tailwind class string for the flex-wrap chip row, ensuring consistent row height between loading and loaded states.
- **`DeviceTagsSectionProps`** — Props interface accepting a `device: Device | null`.
- **`DeviceTagsSection(props)`** — Main component export. Flattens the device's `tags` array (each tag has a `key` and multiple `values`) into individual chip entries, uses `useLoadingScope()` to detect loading state, and conditionally renders:
  - Skeleton `Tag` chips (via `LoadingItems`) while loading.
  - Actual `Tag` badges in `key:value` format once loaded.
  - `null` if loading is finished and the device has no tags (section disappears entirely).

## Usage Example

```typescript
import { DeviceTagsSection } from './device-tags-section';
import type { Device } from '../types/device.types';

function DeviceOverviewTab({ device }: { device: Device | null }) {
  return (
    <div className="flex flex-col gap-6">
      {/* Other overview sections */}
      <DeviceTagsSection device={device} />
    </div>
  );
}
```

The component expects `device.tags` to be an array of objects shaped like `{ tagId: string; key: string; values: string[] }`. Each tag's values are expanded into separate chips labeled `key:value`. Wrap the parent tree with the appropriate loading-scope provider (from `@flamingo-stack/openframe-frontend-core`) so `useLoadingScope()` correctly reflects the fetch state while `device` is still `null`.
