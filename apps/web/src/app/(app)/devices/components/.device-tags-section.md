# device-tags-section.tsx

Renders the "Device Tags" section within the device Overview tab, displaying a device's key:value tag pairs as badge chips. Shows skeleton loading placeholders while the device data is being fetched, and hides itself entirely if the loaded device has no tags.

## Key Components

- **`DeviceTagsSection`** — Main component that accepts a `device` prop and renders the tags section
- **`DeviceTagsSectionProps`** — Props interface requiring a `device: Device | null`
- **`DEVICE_TAGS_SKELETON_COUNT`** — Constant (3) controlling how many skeleton chips render during loading
- **`TAGS_ROW_CLASS`** — Shared Tailwind class string ensuring consistent row height between loading and loaded states

## Behavior

- Uses `useLoadingScope()` to detect an ancestor loading context
- Flattens `device.tags` (each tag has a `key` and multiple `values`) into individual chip entries keyed by `${tagId}-${value}`
- While loading, renders `DEVICE_TAGS_SKELETON_COUNT` skeleton `Tag` badges via `LoadingItems`
- Once loaded, if there are no tag values, the component returns `null` (section is omitted rather than shown empty)
- Each rendered tag uses the `badge` variant with a `key:value` label, which also provides a native hover tooltip via the `title` attribute

## Usage Example

```typescript
import { DeviceTagsSection } from './device-tags-section';
import type { Device } from '../types/device.types';

function DeviceOverviewTab({ device }: { device: Device | null }) {
  return (
    <div className="flex flex-col gap-4">
      {/* Other overview sections */}
      <DeviceTagsSection device={device} />
    </div>
  );
}
```

To show loading state, wrap the parent in the loading scope provider so `useLoadingScope()` resolves to `true` while `device` is being fetched:

```typescript
<LoadingScopeProvider loading={isFetchingDevice}>
  <DeviceTagsSection device={device} />
</LoadingScopeProvider>
```
