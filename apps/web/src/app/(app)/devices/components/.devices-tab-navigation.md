# devices-tab-navigation.tsx

A client-side React component that renders the tab navigation bar for the Devices page, switching between the "Devices List" and "Remote Sessions" views. Visibility is gated by the tenant's session recordings feature flag, keeping the strip rendered (in a loading state) while the gate resolves to avoid layout shift.

## Key Components

- **`DevicesPageTab`** - Type alias restricting the active tab to `'list' | 'remote-sessions'`.
- **`REMOTE_SESSIONS_PAGE_TITLE`** - Exported constant for the "Remote Sessions" tab label, matching the design spec (Figma 2539-21701).
- **`DEVICES_PAGE_TABS`** - Static array defining the two tabs with their icons (`MonitorIcon`, `ComputerMouseIcon`) and labels.
- **`DevicesTabNavigation`** - The main exported component. Accepts an `activeTab` prop, resolves the session-recordings feature gate via `useSessionRecordingsGate`, and renders a `TabNavigation` component that routes to `routes.devices.list` or `routes.devices.remoteSessions` on tab change.

## Usage Example

```typescript
import { DevicesTabNavigation } from './devices-tab-navigation';

export function DevicesListPage() {
  return (
    <>
      <DevicesTabNavigation activeTab="list" />
      {/* page content */}
    </>
  );
}

export function RemoteSessionsPage() {
  return (
    <>
      <DevicesTabNavigation activeTab="remote-sessions" />
      {/* page content */}
    </>
  );
}
```

## Behavior Notes

- Returns `null` entirely when the session recordings gate is `'off'`, so the Devices page falls back to its plain header with no second tab.
- While the gate is `'loading'`, the component still renders, passing `loading={true}` to `TabNavigation` so the UI holds its place instead of shifting once the gate resolves.
- Navigation uses Next.js `useRouter().push`, not `urlSync`, since tabs map to distinct routes rather than query parameters.
