# devices-tab-navigation.tsx

A client-side navigation component that renders tabs for the Devices page, letting users switch between the Devices List and Remote Sessions views. The tab strip is conditionally shown based on a feature gate controlling session recordings availability.

## Key Components

- **`DevicesPageTab`** - Type alias representing the two valid tab IDs: `'list'` and `'remote-sessions'`.
- **`REMOTE_SESSIONS_PAGE_TITLE`** - Exported constant for the Remote Sessions tab label, kept in sync with the design spec (Figma 2539-21701).
- **`DEVICES_PAGE_TABS`** - Static array of `TabItem` definitions (icon + label) for the two tabs.
- **`DevicesTabNavigation`** - Main component. Accepts an `activeTab` prop, resolves the session recordings feature gate via `useSessionRecordingsGate`, and renders a `TabNavigation` strip that navigates between `routes.devices.list` and `routes.devices.remoteSessions`.

## Usage Example

```typescript
import { DevicesTabNavigation } from './devices-tab-navigation';

export function DevicesListPage() {
  return (
    <div>
      <DevicesTabNavigation activeTab="list" />
      {/* page content */}
    </div>
  );
}
```

## Behavior Notes

- When `gate === 'off'`, the component renders `null`, so pages without session recordings enabled show no tab strip at all.
- While the gate status is `'loading'`, the component still renders (in an inert/loading state) to reserve layout space and avoid content shifting once the gate resolves.
- Tab changes are handled via `next/navigation`'s `useRouter`, pushing to the appropriate route rather than relying on the `TabNavigation` component's built-in URL sync (`urlSync={false}`).
- Clicking the already-active tab is a no-op, preventing redundant navigation.
