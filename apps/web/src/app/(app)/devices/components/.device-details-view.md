# device-details-view.tsx

Client-side React component that renders the full device details page, including header actions, status tag, tabbed content, and modal dialogs for a single managed device identified by `deviceId`.

## Key Components

- **`DeviceDetailsView`** — Main exported component. Fetches device data via `useDeviceDetails`, manages tab navigation synced to URL query params, renders the page header (title, status tag, back button, action buttons/menu), tab content, and the Run Script modal.
- **`DeviceStatusTag`** — Internal component rendering the device's connectivity status as a `Tag`, with built-in loading skeleton support via `useLoadingScope`.
- **`DETAIL_ICON_SIZE`** — CSS class constant controlling icon sizing specifically for dropdown menu items (header button icons are sized independently by their own variant styles).
- **`DEFAULT_DEVICE_TAB`** — Default tab id (`'overview'`) used when no valid `tab` query param is present.

## Behavior Notes

- **Tab state** is derived from and written to the URL (`?tab=...`) using `history.replaceState` rather than `router.replace`, avoiding a page-title flicker since tab switches are treated as view changes, not navigations.
- **Valid tabs** are computed from `useDeviceTabs(directoryGate)` so disabled or flag-gated tabs are automatically excluded; an invalid `tab` param falls back to `DEFAULT_DEVICE_TAB`.
- **Run Script modal** can be auto-opened via `?action=runScript` in the URL (e.g., from a table row action), with the param cleared afterward.
- **Loading state** is handled declaratively via `LoadingWhen`, allowing the header, tabs, and content to each render their own skeleton placeholders.
- **Mingo context tracking** registers the currently viewed device via `useTrackOpenView` for AI agent context awareness.
- Errors and missing devices render `LoadError` / `NotFoundError` respectively.

## Usage Example

```typescript
import { DeviceDetailsView } from './device-details-view';

export default function DevicePage({ params }: { params: { deviceId: string } }) {
  return <DeviceDetailsView deviceId={params.deviceId} />;
}
```

This component is intended to be used as the content of a Next.js dynamic route page (e.g., `/devices/[deviceId]`), where `deviceId` comes from the route params.
