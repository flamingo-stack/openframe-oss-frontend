# use-device-list.ts

A React hook providing a single bounded page of devices for "picker" UI surfaces (device selection pickers and schedule assignment views) that select from the fleet rather than browse it. Unlike autocomplete-style queries, this hook suspends via Relay and relies on conditional mounting rather than an `enabled` flag.

## Key Components

- **`DEVICE_LIST_LIMIT`** — Exported constant (`100`) capping the number of devices returned; pickers render what fits without pagination.
- **`UseDeviceListOptions`** — Input options interface: `filter` (device filter criteria), `search` (text query), `first` (page size, defaults to `DEVICE_LIST_LIMIT`), and `retryKey` (cache-breaker for forcing refetch after a thrown error).
- **`DeviceListResult`** — Return shape containing `devices` (array of `Device`) and `filteredCount` (total matching count).
- **`useDeviceList(options)`** — The main hook. Builds a composite `fetchKey` from `useDeviceEpoch()` and `retryKey`, executes `devicesPageRelayQuery` via `useLazyLoadQuery` with `store-and-network` fetch policy, and maps the result through `readMachineEdges`.

## Usage Example

```typescript
import { Suspense } from 'react';
import { useDeviceList } from './use-device-list';

function DevicePickerContent({ search }: { search: string }) {
  const { devices, filteredCount } = useDeviceList({
    search,
    filter: { status: 'ONLINE' },
  });

  return (
    <ul>
      {devices.map((d) => (
        <li key={d.id}>{d.hostname}</li>
      ))}
      <li>Total matches: {filteredCount}</li>
    </ul>
  );
}

function DevicePickerModal({ isOpen }: { isOpen: boolean }) {
  // Hook suspends — only mount when the modal is actually open.
  return isOpen ? (
    <Suspense fallback={<div>Loading devices…</div>}>
      <DevicePickerContent search="" />
    </Suspense>
  ) : null;
}
```

**Important notes:**
- Because this hook suspends (no `enabled` flag), gate rendering by conditionally mounting the component inside a `Suspense` boundary rather than toggling a hook option.
- To retry after an error, increment `retryKey`—remounting alone won't force a refetch, since Relay caches thrown errors by a key unaffected by remounts.
- This hook is **not** suited for per-keystroke autocomplete (e.g., ticket-form device search); use the imperative `fetchDevicesPage` for that case instead.
