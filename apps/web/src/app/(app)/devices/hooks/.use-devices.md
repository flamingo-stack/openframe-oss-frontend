# use-devices.ts

A React hook that powers the paginated, filterable device list used on the Devices page, customer devices tab, and archive view. It wraps Relay's `useLazyLoadQuery` and `usePaginationFragment` to provide normalized device data with cursor-based infinite scrolling, replacing the older manual `useInfiniteQuery` approach.

## Key Components

- **`useDevices(filters?, search?)`** — Main hook that fetches and paginates the device list based on optional filters and a search string.
- **`UseDevicesResult`** — Return type containing:
  - `devices: Device[]` — normalized machine records
  - `filteredCount: number` — total count matching current filters
  - `hasNextPage: boolean` — whether more pages are available
  - `isFetchingNextPage: boolean` — loading state for pagination
  - `fetchNextPage: () => void` — loads the next page of results

## Usage Example

```typescript
import { Suspense } from 'react';
import { useDevices } from './use-devices';

function DevicesList({ filters, search }: { filters?: DeviceFilterInput; search?: string }) {
  const { devices, filteredCount, hasNextPage, isFetchingNextPage, fetchNextPage } =
    useDevices(filters, search);

  return (
    <div>
      <p>{filteredCount} devices found</p>
      {devices.map((device) => (
        <DeviceRow key={device.id} device={device} />
      ))}
      {hasNextPage && (
        <button onClick={fetchNextPage} disabled={isFetchingNextPage}>
          Load more
        </button>
      )}
    </div>
  );
}

export function DevicesPage(props: { filters?: DeviceFilterInput; search?: string }) {
  return (
    <Suspense fallback={<LoadingSpinner />}>
      <DevicesList {...props} />
    </Suspense>
  );
}
```

**Important notes:**
- This hook **suspends** on initial load and on any filter/search change — callers must wrap it in `<Suspense>`.
- To avoid flashing the fallback on filter changes, defer the `filters`/`search` values before passing them in (see `DevicesPanel`), making the update a React transition.
- Pagination resets to the first page after any device mutation (a known limitation tied to `ConnectionHandler`'s head-fetch replace behavior); see inline comments for the planned fix once delete operations move from REST to a Relay mutation.
- Only active when the `tenant-management-v2` feature flag is enabled; otherwise, use `useDevicesV1`.
