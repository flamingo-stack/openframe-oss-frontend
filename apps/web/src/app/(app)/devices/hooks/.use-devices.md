# use-devices.ts

React hook that provides a paginated, filterable, searchable list of devices backed by Relay, replacing the legacy `useInfiniteQuery`-based approach. Powers the Devices page, customer devices tab, and archive page when the `tenant-management-v2` feature flag is enabled.

## Key Components

- **`UseDevicesResult`** — Return type interface exposing `devices`, `filteredCount`, `hasNextPage`, `isFetchingNextPage`, and `fetchNextPage`.
- **`useDevices(filters?, search?)`** — Main hook that:
  - Loads device data via `useLazyLoadQuery` with `store-and-network` fetch policy.
  - Paginates results via `usePaginationFragment`, connected to `devicesListRelayFragment`.
  - Converts app-level filters to Relay filters using `toRelayDeviceFilter`.
  - Normalizes GraphQL edges into `Device` records via `readDirectoryListedMachineEdges`.
  - Refetches automatically when `useDeviceEpoch` signals a device mutation occurred elsewhere in the app.

## Usage Example

```typescript
import { Suspense } from 'react';
import { useDevices } from './use-devices';

function DevicesPanel() {
  const { devices, filteredCount, hasNextPage, isFetchingNextPage, fetchNextPage } = useDevices(
    { status: 'ONLINE' },
    'macbook',
  );

  return (
    <div>
      <p>{filteredCount} devices found</p>
      <ul>
        {devices.map((device) => (
          <li key={device.id}>{device.hostname}</li>
        ))}
      </ul>
      {hasNextPage && (
        <button onClick={fetchNextPage} disabled={isFetchingNextPage}>
          Load more
        </button>
      )}
    </div>
  );
}

export function DevicesPage() {
  return (
    <Suspense fallback={<p>Loading devices…</p>}>
      <DevicesPanel />
    </Suspense>
  );
}
```

**Important notes:**
- This hook **suspends** on initial load and on any filter/search change — always wrap callers in `<Suspense>`.
- To avoid flashing the fallback on filter changes, defer the `filters`/`search` values (e.g., via `useDeferredValue`) before passing them in, enabling a smooth transition instead of a suspense drop.
- Known limitation: pagination resets to the first page after a device mutation triggers a refetch, since the Relay connection head-fetch replaces rather than merges records. A proper fix requires moving device deletion from REST to a Relay mutation with a `ConnectionHandler` updater.
