The scrolled device list — the Devices page, the customer devices tab and the archive page.

Part of the device **read-hook layer**, the only entry point components use to get device data. No component queries devices directly; if a screen needs devices, it needs one of these shapes:

| Hook | Module | Transport | For |
|---|---|---|---|
| `useDevices(filters?, search?)` | `use-devices.ts` | Relay `usePaginationFragment` | the scrolled list |
| `useDeviceList({ filter, search, first })` | `use-device-list.ts` | Relay `useLazyLoadQuery` | bounded pickers |
| `useAllDevices({ filter, enabled })` | `use-all-devices.ts` | react-query over a Relay cursor walk | whole-fleet lookups |
| `useDeviceFilters(filters?)` | `use-device-filters.ts` | Relay `useLazyLoadQuery` | filter facets |
| `useDeviceDetails(machineId)` | `use-device-details.ts` | react-query (GraphQL + Fleet + MeshCentral) | the detail page |

## `useDevices(filters?, search?)`

**Suspends** on first load and on any filter/search change. Relay owns the cursors and page merging the previous `useInfiniteQuery` did by hand, and rows are normalized `Machine` records shared with every device picker and schedule table in the app.

**Returns:** `devices`, `filteredCount`, `hasNextPage`, `isFetchingNextPage`, `fetchNextPage`.

There is no `isLoading` and no `error`: the Suspense boundary owns the first, an error boundary owns the second. `DevicesPanel` provides both, so its three call sites stay unaware of them.

## Keeping the list on screen while a filter changes

A Relay query re-suspends whenever its variables change, which would drop the whole panel to its skeleton mid-interaction. `DevicesPanel` passes **deferred** filter and search values (`useDeferredValue`), making a change a transition: React holds the current rows while the next set loads. The filter controls read the live params, so a checkbox still ticks immediately, and the list dims rather than being replaced by skeletons.

Pass deferred values yourself if you call this hook outside `DevicesPanel`.

## Usage Example

```typescript
import { Suspense } from 'react';
import { useDevices } from './use-devices';

function DeviceList({ filters, search }) {
  const { devices, hasNextPage, fetchNextPage, filteredCount } = useDevices(filters, search);
  return (
    <>
      <p>{filteredCount} devices found</p>
      {devices.map(device => <DeviceRow key={device.id} device={device} />)}
      {hasNextPage && <button onClick={fetchNextPage}>Load more</button>}
    </>
  );
}

// The caller owns the boundary.
<Suspense fallback={<Skeleton />}>
  <DeviceList filters={deferredFilters} search={deferredSearch} />
</Suspense>
```

> **Page size** is `20` (`DEVICES_PAGE_SIZE`). Ordering is `status DESC` (online first), fixed inside the Relay document rather than passed by callers, so two screens showing the same fleet cannot disagree about its order.
