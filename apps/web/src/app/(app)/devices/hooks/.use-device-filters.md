# use-device-filters.ts

A React hook that fetches device filter facets (statuses, device types, OS types, customer IDs, tags) with counts via a Relay query, used to populate filter UI alongside a device list.

## Key Components

- **`useDeviceFilters(filters?)`** — Client hook that executes `deviceFiltersRelayQuery` through `useLazyLoadQuery`, converts an optional `DeviceFilterInput` into the Relay filter shape via `toRelayDeviceFilter`, and returns a memoized `DeviceFilters` object (`statuses`, `deviceTypes`, `osTypes`, `organizationIds`, `tagKeys`, `filteredCount`).
- Uses `useDeviceEpoch()` and `useRetryKey()` to build a composite `fetchKey`, forcing a refetch whenever a device mutation occurs or an error boundary retries.
- Copies Relay's readonly arrays into new mutable arrays (memoized on `data.deviceFilters`) so downstream consumers (table column defs, filter modal) don't receive a new object reference on every render.

## Usage Example

```typescript
'use client';

import { Suspense } from 'react';
import { useDeviceFilters } from './use-device-filters';

function DeviceFilterToolbar({ filters }: { filters?: DeviceFilterInput }) {
  const deviceFilters = useDeviceFilters(filters);

  return (
    <div>
      <span>Matching devices: {deviceFilters.filteredCount}</span>
      <ul>
        {deviceFilters.statuses.map((status) => (
          <li key={status.value}>
            {status.value} ({status.count})
          </li>
        ))}
      </ul>
    </div>
  );
}

// Must share a Suspense boundary with the device table it filters,
// but should have its own error boundary so a failed facet query
// doesn't take down the row data.
function DevicesPanel() {
  return (
    <ErrorBoundary fallback={<FilterError />}>
      <Suspense fallback={<ToolbarSkeleton />}>
        <DeviceFilterToolbar />
        {/* Device table rendered in the same suspense tree */}
      </Suspense>
    </ErrorBoundary>
  );
}
```

**Important:** This hook suspends during data fetching — always wrap it in a `Suspense` boundary shared with the device list, and give it its own error boundary so filter-query failures don't affect the table rows.
