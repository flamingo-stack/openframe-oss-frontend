# use-remote-session-chat.ts

React hooks that power the remote-access session chat panel: resolving the active dialog id, deriving the signed-in technician's display identity, and combining a persisted history page with a live JetStream feed into a single deduplicated, ordered message list with unread tracking.

## Key Components

- **`useRemoteSessionDialogId()`** - Returns the chat `dialogId` for the current remote access session, or `null` when none is provisioned.
- **`useRemoteSessionChatTechnician()`** - Builds the signed-in technician's display info (`name`, `avatarUrl`) from the auth store.
- **`useRemoteSessionChat(dialogId, panelOpen?, host?)`** - Main hook combining history fetch, JetStream live tailing, gap-recovery polling, and send/markRead actions into a `RemoteSessionChatState`.
- **`RemoteSessionChatState`** - Return shape with `messages`, `isLoading`, `sending`, `technician`, `send()`, `hasUnread`, and `markRead()`.
- **`HISTORY_FALLBACK_MS`** - Polling interval (10s) used when the live feed is disconnected.

## Usage Example

```typescript
import { useRemoteSessionDialogId, useRemoteSessionChat } from './use-remote-session-chat';

function ChatPanel({ panelOpen }: { panelOpen: boolean }) {
  const dialogId = useRemoteSessionDialogId();
  const { messages, isLoading, sending, technician, send, hasUnread, markRead } =
    useRemoteSessionChat(dialogId, panelOpen);

  useEffect(() => {
    if (panelOpen) markRead();
  }, [panelOpen, markRead]);

  const handleSend = async (text: string) => {
    const ok = await send(text);
    if (!ok) {
      // show send-failure feedback
    }
  };

  if (isLoading) return <div>Loading chat…</div>;

  return (
    <div>
      {hasUnread && <span>New message</span>}
      {messages.map(m => (
        <div key={m.id}>{m.author === 'user' ? 'Client' : technician.name}: {m.body}</div>
      ))}
      <ChatInput onSubmit={handleSend} disabled={sending} />
    </div>
  );
}
```

**Notes:**
- Messages are deduplicated by `id` and ordered via a sequence-aware merge of history (`store.history`) and live (`store.live`) arrays.
- When the WebSocket feed is down, history is re-polled every `HISTORY_FALLBACK_MS` to keep chat moving.
- Pass `host` when rendering a session watched by a colleague, so unattributed live rows attribute correctly to the session owner rather than the viewer.
