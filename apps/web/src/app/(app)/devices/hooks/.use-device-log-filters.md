# use-device-log-filters.ts

Client-side React hook that manages URL-synced filter state (search, log levels, time range) for device log lists, translating UI controls into a `DeviceLogFilterInput` ready for GraphQL queries. Shared between a device's Device Logs tab and the tenant-wide Troubleshooting page.

## Key Components

- **`deviceLogParamSchema(defaultRange?)`** — Builds the `useApiParams` schema for `logSearch`, `logLevels`, `logRange`, `logFrom`, `logTo`, namespaced under `log*` keys to avoid colliding with other tables on the same page.
- **`DEVICE_LOG_PARAM_SCHEMA`** — Schema instance using the default preset.
- **`deviceLogParamReset(defaultRange?)`** / **`DEVICE_LOG_PARAM_RESET`** — Payload that resets all log params to defaults in a single `setParams` write.
- **`DEVICE_LOG_SEARCH_DEBOUNCE_MS`** — 500ms debounce for search input, matching other server-side search surfaces (Devices, Customers).
- **`DeviceLogParamsApi`** — The subset of `UseApiParamsReturn` (`pendingParams`, `setParam`, `setParams`) the hook consumes.
- **`DeviceLogFiltersOptions`** — Optional `defaultRange` override.
- **`DeviceLogFilters`** — Return shape: search state, level toggles, range/custom-range controls, picker bounds, the derived `filter`, `anchor` timestamp, `rangeClosed`, `hasFilters`, `resetFilters`, and `refresh`.
- **`useDeviceLogFilters(api, options?)`** — Main hook. Reads/writes from `pendingParams` (not the committed URL) so filter controls stay responsive during React transitions, and derives a memoized `DeviceLogsFilter` for query hooks like `useDeferredQuery`.

## Usage Example

```typescript
import { useApiParams } from '@flamingo-stack/openframe-frontend-core/hooks';
import { deviceLogParamSchema, useDeviceLogFilters } from './use-device-log-filters';

function DeviceLogsTab() {
  const schema = deviceLogParamSchema('day');
  const api = useApiParams(schema);
  const {
    search,
    setSearch,
    selectedLevels,
    toggleLevel,
    range,
    changeRange,
    filter,
    hasFilters,
    resetFilters,
    refresh,
  } = useDeviceLogFilters(api, { defaultRange: 'day' });

  // `filter` is ready to pass into the deviceLogs query
  return (
    <>
      <input value={search} onChange={e => setSearch(e.target.value)} />
      {hasFilters && <button onClick={resetFilters}>Reset</button>}
      <button onClick={refresh}>Refresh</button>
    </>
  );
}
```

Surfaces with their own params (e.g. a device-specific page) should spread `deviceLogParamSchema()` into their own schema and pass the single `useApiParams` result here, avoiding two hooks racing on the same URL.
