# use-device-log-filters.ts

A React hook that manages device log filter state (search, severity levels, time range) synced to URL params, and derives the corresponding `DeviceLogFilterInput` for GraphQL queries. Shared between a device's "Device Logs" tab and the tenant-wide Troubleshooting page, so it only owns *which lines* are shown—callers decide *which devices* to query.

## Key Components

- **`deviceLogParamSchema(defaultRange?)`** — Builds the `useApiParams` schema for log-related URL params (`logSearch`, `logLevels`, `logRange`, `logFrom`, `logTo`), namespaced under `log*` to avoid colliding with other tables on the same page.
- **`DEVICE_LOG_PARAM_SCHEMA`** — Schema instance built with the default range.
- **`deviceLogParamReset(defaultRange?)`** / **`DEVICE_LOG_PARAM_RESET`** — Produces the default-value payload for a single-write "Reset" action.
- **`DEVICE_LOG_SEARCH_DEBOUNCE_MS`** — Debounce (500ms) before search text is written to the URL, since each search re-scans the full log window.
- **`DeviceLogParamsApi`** — The subset of `UseApiParamsReturn` the hook needs (`pendingParams`, `setParam`, `setParams`).
- **`DeviceLogFiltersOptions`** — Optional `defaultRange` override.
- **`DeviceLogFilters`** — Return shape: search state, level toggles, range/custom-range controls, picker bounds, the derived `filter`, a fixed `anchor` timestamp, `rangeClosed`/`hasFilters` flags, `resetFilters`, and `refresh`.
- **`useDeviceLogFilters(api, options?)`** — The main hook: reads `pendingParams` (not the committed URL) so controls stay responsive during React transitions, and derives a memoized `filter` object for query hooks like `useDeferredQuery`.

## Usage Example

```typescript
import { useApiParams } from '@flamingo-stack/openframe-frontend-core/hooks';
import {
  DEVICE_LOG_PARAM_SCHEMA,
  useDeviceLogFilters,
} from './use-device-log-filters';

function DeviceLogsTab() {
  const api = useApiParams(DEVICE_LOG_PARAM_SCHEMA);
  const {
    search,
    setSearch,
    searchError,
    selectedLevels,
    toggleLevel,
    range,
    changeRange,
    filter,
    hasFilters,
    resetFilters,
    refresh,
  } = useDeviceLogFilters(api, { defaultRange: 'day' });

  return (
    <div>
      <input value={search} onChange={e => setSearch(e.target.value)} />
      {searchError && <span>{searchError}</span>}
      {hasFilters && <button onClick={resetFilters}>Reset</button>}
      {/* pass `filter` into your device-logs GraphQL query */}
    </div>
  );
}
```

Pair exactly one `useApiParams` instance with one `useDeviceLogFilters` call per page—two hooks writing the same URL would race against each other's pending writes.
