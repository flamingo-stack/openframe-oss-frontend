## Overview

A React hook that supplies filter options for the **DEVICE** and **CUSTOMER** funnels on the tenant-wide Remote Sessions page. Since the sessions API itself has no facets, this hook derives filter options from the tenant's device fleet (same source as the Devices list) and its customer/organization list.

## Key Components

- **`useTenantSessionFilterOptions(options?)`** - Main hook that returns `{ deviceOptions, customerOptions, pending }`.
  - `enabled` (optional, default `true`): when `false`, skips fetching entirely (useful while a parent view is in a loading state).
- **`FilterOption`** - Interface describing a filter option: `{ id, value, label }`.
- **`DEVICE_OPTIONS_LIMIT`** - Caps the device list at 100 entries; large fleets show only the first page of devices.

### Internal data sources
- `fetchDevicesPage` - fetches devices filtered by `DEFAULT_DEVICES_LIST_STATUSES`, used to build device options (`machineId` as both id and value, display name via `getDeviceName`).
- `useOrganizationOptions` - supplies customer/organization options, reused from the tickets feature.

## Usage Example

```typescript
import { useTenantSessionFilterOptions } from './use-tenant-session-filter-options';

function SessionsFilterBar({ isTableLoading }: { isTableLoading: boolean }) {
  const { deviceOptions, customerOptions, pending } = useTenantSessionFilterOptions({
    enabled: !isTableLoading,
  });

  if (pending) {
    return <FilterSkeleton />;
  }

  return (
    <>
      <DeviceFilterDropdown options={deviceOptions} />
      <CustomerFilterDropdown options={customerOptions} />
    </>
  );
}
```

Device options are sorted alphabetically by label, and both option lists use the session filter's expected values (`machineId` for devices, organization id for customers).
