# use-tenant-session-filter-options.ts

A React hook that builds the filter options (devices and customers) for the DEVICE and CUSTOMER funnels on the tenant-wide Remote Sessions page, since the sessions API itself provides no faceted filter data.

## Key Components

- **`DEVICE_OPTIONS_LIMIT`** — Caps the device list at 100 entries; large fleets only show their first devices in the funnel.
- **`FilterOption`** — Interface describing a selectable filter entry (`id`, `value`, `label`).
- **`useTenantSessionFilterOptions(options)`** — Main hook, returns:
  - `deviceOptions`: alphabetically sorted list of devices (using `machineId` as both `id` and `value`, and a friendly name as `label`), built from the same tenant device fleet shown on the Devices list.
  - `customerOptions`: list of organizations, sourced from `useOrganizationOptions`.
  - `pending`: `true` while either the devices query or the customers query is loading.

The hook accepts an `enabled` flag (default `true`) to suppress both underlying queries—useful when the parent table is in a loading/disabled state and no data should be fetched.

## Usage Example

```typescript
import { useTenantSessionFilterOptions } from '../hooks/use-tenant-session-filter-options';

function RemoteSessionsFilters({ isTableReady }: { isTableReady: boolean }) {
  const { deviceOptions, customerOptions, pending } = useTenantSessionFilterOptions({
    enabled: isTableReady,
  });

  if (pending) {
    return <FilterSkeleton />;
  }

  return (
    <>
      <FunnelSelect name="device" options={deviceOptions} />
      <FunnelSelect name="customer" options={customerOptions} />
    </>
  );
}
```

Internally, it combines `useQuery` (for fetching devices via `fetchDevicesPage`, keyed with `deviceQueryKeys.page`) and `useOrganizationOptions` (for customer data), memoizing the derived option lists to avoid unnecessary recomputation on re-render.
