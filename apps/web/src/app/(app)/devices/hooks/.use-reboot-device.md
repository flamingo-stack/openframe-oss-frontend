# use-reboot-device.ts

A React hook that triggers a remote device reboot via MeshCentral's control socket, providing user feedback through toast notifications and loading state tracking.

## Key Components

- **`useRebootDevice()`** — Hook returning `{ rebootDevice, isRebooting }` for managing device reboot operations.
- **`rebootDevice(meshcentralAgentId, deviceName?)`** — Async callback that sends a `poweraction` (`reset` action type) command through `MeshControlClient`. Returns `true` on success, `false` on failure.
- **`isRebooting`** — Boolean state flag indicating an in-flight reboot request, useful for disabling UI controls during the operation.

This hook relies on `MeshControlClient` (from `@/lib/meshcentral/meshcentral-control`) rather than any GraphQL/REST API, since reboot is only exposed via MeshCentral's control socket protocol. The target device's MeshCentral agent must be online for the action to succeed.

## Usage Example

```typescript
import { useRebootDevice } from '@/hooks/use-reboot-device';

function DeviceActionsMenu({ agentId, deviceName }: { agentId: string; deviceName: string }) {
  const { rebootDevice, isRebooting } = useRebootDevice();

  const handleReboot = async () => {
    const success = await rebootDevice(agentId, deviceName);
    if (success) {
      console.log('Reboot command sent successfully');
    }
  };

  return (
    <button onClick={handleReboot} disabled={isRebooting}>
      {isRebooting ? 'Rebooting...' : 'Reboot Device'}
    </button>
  );
}
```

**Notes:**
- Requires a valid `meshcentralAgentId`; the hook does not resolve it from a device ID — callers must supply the MeshCentral agent identifier directly.
- Toast notifications are shown automatically on both success and failure, so callers typically don't need additional error handling UI.
- The `MeshControlClient` socket connection is always closed in the `finally` block, regardless of outcome.
