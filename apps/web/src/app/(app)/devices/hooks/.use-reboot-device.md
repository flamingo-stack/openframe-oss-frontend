# use-reboot-device.ts

A React hook that reboots a managed device by sending a `poweraction` command through MeshCentral's control socket, providing toast feedback and loading state for the operation.

## Key Components

- **`useRebootDevice()`** — Hook that returns device reboot functionality.
  - **`rebootDevice(meshcentralAgentId, deviceName?)`** — Async function that opens a `MeshControlClient` connection, issues a `reset` power action against the given agent, and shows a success/error toast. Returns a `Promise<boolean>` indicating success.
  - **`isRebooting`** — Boolean state flag, `true` while the reboot request is in flight.

The hook relies on `MeshControlClient` (from `@/lib/meshcentral/meshcentral-control`) rather than a GraphQL/REST API, since MeshCentral exposes reboot only via its control socket (`poweraction` / `actiontype: reset`). The target agent must be online for the action to succeed.

## Usage Example

```typescript
import { useRebootDevice } from '@/hooks/use-reboot-device';

function DeviceActionsMenu({ agentId, deviceName }: { agentId: string; deviceName: string }) {
  const { rebootDevice, isRebooting } = useRebootDevice();

  const handleReboot = async () => {
    const success = await rebootDevice(agentId, deviceName);
    if (success) {
      console.log('Reboot command sent successfully');
    }
  };

  return (
    <button onClick={handleReboot} disabled={isRebooting}>
      {isRebooting ? 'Rebooting...' : 'Reboot Device'}
    </button>
  );
}
```

## Notes

- The MeshCentral control client connection is always closed in a `finally` block, ensuring no socket leaks even if the power action fails.
- Requires a valid, online `meshcentralAgentId`; offline agents will cause the action to fail and trigger the destructive error toast.
- `deviceName` is optional and only used for user-facing toast messages (defaults to `"Device"`).
