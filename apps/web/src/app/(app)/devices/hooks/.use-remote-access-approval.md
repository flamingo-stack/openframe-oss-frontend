# use-remote-access-approval.ts

A React hook implementing the technician-side state machine for requesting remote screen-access approval to a device, combining a NATS push channel with a polling fallback to receive the approval decision.

## Key Components

- **`RemoteAccessApprovalState`** - Union type modeling the full lifecycle: `idle` → `requesting` → `awaiting` → one of `approved` | `denied` | `timed_out` | `error`, plus the create-call refusals `busy` and `unreachable`.
- **`UseRemoteAccessApprovalResult`** - Return shape of the hook: current `state`, the `request` object, `error`/`errorCode`, and the action functions `requestAccess`, `cancel`, `reset`.
- **`stateForSettled(request)`** - Maps a settled `RemoteAccessRequest` status to its corresponding UI state (e.g., `REVOKED`/`CANCELLED` resolve back to `idle`).
- **`stateForCreateError(code)`** - Maps a `RemoteAccessCreateErrorCode` from a failed create call to `busy`, `unreachable`, or generic `error`.
- **`useRemoteAccessApproval(deviceId)`** - The main hook. Manages:
  - Creating a request via `remoteAccessApprovalApiService.create`.
  - An `attemptRef` generation counter to discard stale async results (similar to a seek-generation pattern) on retry, cancel, or unmount.
  - A `POLL_MS` (2s) fallback poll against `remoteAccessApprovalApiService.get` while awaiting a decision.
  - A NATS subscription (`useNatsJsonSubscription`) on the technician's `user.<userId>.notification` subject to receive push-based `REMOTE_ACCESS_DECISION` events, parsed via `parseRemoteAccessDecisionEvent` and merged via `applyRemoteAccessDecisionEvent`.
  - `cancel()` to revoke an open request and return to `idle`.
  - `reset()` to return from any settled/error state back to `idle`.

## Usage Example

```typescript
import { useRemoteAccessApproval } from './use-remote-access-approval';

function RemoteAccessButton({ deviceId }: { deviceId: string }) {
  const { state, request, error, requestAccess, cancel, reset } = useRemoteAccessApproval(deviceId);

  if (state === 'idle') {
    return <button onClick={() => requestAccess('Troubleshooting ticket #123')}>Request Access</button>;
  }
  if (state === 'awaiting' || state === 'requesting') {
    return <button onClick={cancel}>Cancel Request</button>;
  }
  if (state === 'approved') {
    return <span>Access granted - launch session {request?.requestId}</span>;
  }
  if (state === 'denied' || state === 'timed_out' || state === 'busy' || state === 'unreachable' || state === 'error') {
    return (
      <div>
        <p>{error ?? 'Request not approved'}</p>
        <button onClick={reset}>Try Again</button>
      </div>
    );
  }
  return null;
}
```

Note: The hook requires an authenticated user (via `useAuthStore`) to establish the NATS decision subject; it degrades to polling-only if `userId` is unavailable.
