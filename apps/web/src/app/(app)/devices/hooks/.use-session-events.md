Custom React hooks for loading and tracking MeshCentral session recording playback events, built on TanStack Query's infinite query pattern for paginated timeline data.

## Key Components

- **`useSessionEvents(recordingId)`** — Loads the full timeline of session events for a given recording ID using `useInfiniteQuery`. It automatically fetches subsequent pages in the background (up to `MAX_PAGES` = 20, or 500 rows per page) until exhausted, returning a flattened, oldest-first array of `SessionTimelineEvent` objects. Returns an empty array while loading or if `recordingId` is `null` (uses `skipToken` to disable the query).

- **`useReportRecordingPlayed(sessionId, state)`** — Fires a one-time "recording played" notification to the backend when playback starts (`state === 'playing'`). Uses a ref (`reportedRef`) to ensure only one report is sent per session per mount, regardless of re-renders. The call is fire-and-forget; errors are silently swallowed since the server already dedupes by user/session/hour.

- **`MAX_PAGES`** — Internal constant capping pagination at 20 pages to guard against runaway timelines.

## Usage Example

```typescript
import { useSessionEvents, useReportRecordingPlayed } from './use-session-events';

function SessionPlayer({ recordingId, sessionId }: { recordingId: string; sessionId: string }) {
  const events = useSessionEvents(recordingId);
  const [playerState, setPlayerState] = useState<RecordingPlayerState>('idle');

  // Reports playback once when state transitions to 'playing'
  useReportRecordingPlayed(sessionId, playerState);

  return (
    <div>
      <RecordingPlayer onStateChange={setPlayerState} />
      <SessionEventsTimeline events={events} />
    </div>
  );
}
```

Both hooks are client-side only (`'use client'`) and designed for the remote sessions feature, relying on `deviceQueryKeys` for cache key consistency and the `remote-session-events-api-service` for data fetching.
