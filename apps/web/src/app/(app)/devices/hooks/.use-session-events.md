## use-session-events.ts

React hooks for loading a remote session's timeline events (via paginated infinite query) and reporting first-playback of a session recording.

## Key Components

- **`useSessionEvents(recordingId)`** — Wraps `useInfiniteQuery` to fetch session timeline events page by page (500 rows per page, capped at `MAX_PAGES` = 20). Automatically triggers subsequent page fetches in the background via an `useEffect` until all pages are loaded, erroring out, or the cap is hit. Returns a flattened array of `SessionTimelineEvent` objects (oldest first), or an empty array if no data is available yet or `recordingId` is `null` (uses `skipToken` to disable the query).

- **`useReportRecordingPlayed(sessionId, state)`** — Fire-and-forget hook that reports the first time a recording enters the `'playing'` state for a given `sessionId`. Uses a `ref` to ensure the report fires only once per session per component lifecycle. Failures are silently swallowed since the server-side dedupe logic (by user/session/hour) makes retries unnecessary.

## Usage Example

```typescript
import { useSessionEvents, useReportRecordingPlayed } from './use-session-events';

function SessionTimelinePanel({ recordingId, sessionId, playerState }: {
  recordingId: string | null;
  sessionId: string | null;
  playerState: RecordingPlayerState;
}) {
  const events = useSessionEvents(recordingId);

  // Reports playback once the player transitions to 'playing'
  useReportRecordingPlayed(sessionId, playerState);

  return (
    <ul>
      {events.map(event => (
        <li key={event.id}>{event.label}</li>
      ))}
    </ul>
  );
}
```

Both hooks are client-only (`'use client'`) and rely on `@tanstack/react-query` for caching and pagination, with query keys scoped via `deviceQueryKeys.sessionEvents`.
