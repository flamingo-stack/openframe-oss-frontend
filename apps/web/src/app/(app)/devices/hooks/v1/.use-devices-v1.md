# use-devices-v1.ts

React hook that powers the scrolled, filterable device list (Devices page, customer devices tab, and archive page) using Relay for pagination and store management. This is the legacy implementation rendered while the `tenant-management-v2` feature flag is off; it is deleted once the flag is fully rolled out.

## Key Components

- **`UseDevicesResultV1`** — Interface describing the hook's return shape: the normalized `devices` list, `filteredCount`, pagination state (`hasNextPage`, `isFetchingNextPage`), and a `fetchNextPage` callback.
- **`useDevicesV1(filters?, search?)`** — Main hook that:
  - Issues a `useLazyLoadQuery` for the first page of devices via `devicesListRelayV1Query`, converting app-level filters with `toRelayDeviceFilter`.
  - Uses `usePaginationFragment` with `devicesListRelayV1Fragment` to manage cursor-based pagination.
  - Subscribes to `useDeviceEpoch()` so the query refetches whenever a device mutation elsewhere in the app bumps a shared epoch value (the standard way to refresh an already-mounted Relay query).
  - Normalizes raw edges into `Device` records via `readListedMachineEdges`.

## Usage Example

```typescript
import { useDevicesV1 } from './use-devices-v1';
import { Suspense } from 'react';

function DevicesList({ filters, search }: { filters?: DeviceFilterInput; search?: string }) {
  const { devices, filteredCount, hasNextPage, isFetchingNextPage, fetchNextPage } =
    useDevicesV1(filters, search);

  return (
    <div>
      <p>{filteredCount} devices found</p>
      {devices.map((device) => (
        <div key={device.id}>{device.hostname}</div>
      ))}
      {hasNextPage && (
        <button onClick={fetchNextPage} disabled={isFetchingNextPage}>
          Load more
        </button>
      )}
    </div>
  );
}

function DevicesPage() {
  return (
    <Suspense fallback={<div>Loading devices...</div>}>
      <DevicesList filters={undefined} search="" />
    </Suspense>
  );
}
```

**Important notes:**
- The hook **suspends** on first load and on any filter/search change — callers must wrap it in `<Suspense>`. To avoid flashing the fallback on filter changes, defer the `filters`/`search` values with `useDeferredValue` before passing them in (see `DevicesPanel`).
- **Known limitation:** refetching after a device mutation resets pagination to the first page (`DEVICES_PAGE_SIZE` rows) because the refetch restarts from `after: null`, and `ConnectionHandler` replaces rather than merges on a head fetch. A proper fix requires migrating the delete mutation from REST (`apiClient.post`) to a Relay mutation with a `ConnectionHandler` updater.
