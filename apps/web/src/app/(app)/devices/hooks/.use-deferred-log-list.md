# use-deferred-log-list.ts

A React hook that decouples a device-log surface's filter controls from the underlying data query, letting controls update instantly while the actual log-fetching request is debounced and deferred.

## Key Components

- **`DEVICE_LOG_LIST_DEBOUNCE_MS`** — Exported constant (300ms) defining how long a filter change waits for subsequent changes before triggering a new query.
- **`KeyedList`** — Interface requiring a `key: string` property that uniquely identifies a query's identity; the list "remounts" (resets pending state) whenever this key changes.
- **`useDeferredLogList<L extends KeyedList>(next: L)`** — The main hook. Takes the latest filter list (`next`) and returns:
  - `deferredList: L` — the filter list that should actually be used to fetch data (lags behind rapid control changes).
  - `isPending: boolean` — `true` while waiting for the debounce to settle or while the deferred query itself is still resolving.

## Usage Example

```typescript
import { useDeferredLogList } from '@/app/hooks/use-deferred-log-list';

interface LogFilters {
  key: string;
  level: string;
  deviceId: string;
}

function DeviceLogsPanel({ filters }: { filters: LogFilters }) {
  const { deferredList, isPending } = useDeferredLogList(filters);

  return (
    <div>
      {/* Controls reflect `filters` immediately, no waiting */}
      <FilterControls value={filters} />

      {/* The list/query uses the debounced, stable value */}
      <DeviceLogsList filters={deferredList} loading={isPending} />
    </div>
  );
}
```

This ensures rapid UI interactions (e.g., clicking multiple log-level chips) collapse into a single debounced request, while the identity (`key`) guarantees that re-parsing the same URL values doesn't needlessly restart the pending state or trigger redundant queries.
