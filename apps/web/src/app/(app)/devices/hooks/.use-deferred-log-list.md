# use-deferred-log-list.ts

A React hook that decouples device-log filter controls from the debounced, deferred query used to fetch log lines, so UI controls stay responsive while the underlying Loki query is throttled and deferred.

## Key Components

- **`DEVICE_LOG_LIST_DEBOUNCE_MS`** — Exported constant (300ms) defining how long a filter change waits before triggering a new log query.
- **`KeyedList`** — Interface requiring a `key` property that uniquely identifies a filter list; used to detect identity changes versus value-only changes (e.g., re-parsed URL params).
- **`useDeferredLogList<L extends KeyedList>(next: L)`** — Main hook. Takes the latest filter list and returns:
  - `deferredList: L` — the debounced/deferred list to pass to the actual log-fetching query.
  - `isPending: boolean` — `true` while waiting for the debounce to settle or while the deferred query is still resolving.

## Usage Example

```typescript
'use client';

import { useDeferredLogList } from '@/app/hooks/use-deferred-log-list';

interface LogFilters {
  key: string;
  level: string;
  deviceId: string;
}

function DeviceLogsSurface({ filters }: { filters: LogFilters }) {
  const { deferredList, isPending } = useDeferredLogList(filters);

  return (
    <div>
      <DeviceLogControls filters={filters} isPending={isPending} />
      <DeviceLogsList filters={deferredList} />
    </div>
  );
}
```

## Behavior Notes

- Rapid, repeated control interactions (e.g., multiple level-chip clicks) collapse into a single debounced query instead of firing one request per click.
- Because Relay cannot cancel an in-flight `deviceLogs` request, debouncing at the hook level avoids wasted Loki scans.
- Identity comparison via `key` prevents re-renders from restarting the debounce timer when only object references change but logical content stays the same.
