# use-busy-device-live-session.ts

A React hook that detects when a "busy" device (one already engaged in a Remote Control session with another technician) has an active live session to watch, and automatically redirects the current user to that live session page when "Watch live" is enabled.

## Key Components

- **`useBusyDeviceLiveSession(deviceId, busy)`** — Main hook that:
  - Checks the `useRemoteSessionWatchGate()` status to determine if watch-live is `'on'`, `'off'`, or `'loading'`.
  - When `busy` is `true` and watching is enabled, queries tenant live sessions for the given `deviceId` via `readLiveSessions`.
  - Finds a live session belonging to a technician other than the current user.
  - Redirects (via `router.replace`) to `routes.devices.liveSession(target)` when such a session is found.
  - Returns `{ looking: boolean }` indicating whether the lookup/redirect decision is still pending, so callers can keep showing a "busy" loading state until resolved.

## Usage Example

```typescript
import { useBusyDeviceLiveSession } from './use-busy-device-live-session';

function DeviceBusyScreen({ deviceId, busy }: { deviceId: string; busy: boolean }) {
  const { looking } = useBusyDeviceLiveSession(deviceId, busy);

  if (looking) {
    return <Spinner label="Checking for an active live session..." />;
  }

  return <BusyDeviceMessage deviceId={deviceId} />;
}
```

**Behavior summary:**
- If `busy` is `false`, the hook does nothing and `looking` is `false`.
- If watch-live is still resolving, `looking` is `true` so the UI can wait.
- If a matching live session from another technician is found, the user is redirected automatically.
- If no session is found or the lookup fails, `looking` resolves to `false` and the busy screen remains visible.
