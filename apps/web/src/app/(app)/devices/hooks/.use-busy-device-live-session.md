# use-busy-device-live-session.ts

React hook that handles the "device busy" scenario during remote control attempts: when a technician tries to remote into a device that's already occupied by another technician, and the "Watch live" feature is enabled, this hook looks up the device's active live session and automatically redirects to that session's viewing page.

## Key Components

- **`useBusyDeviceLiveSession(deviceId, busy)`** — Main hook accepting the target device ID and a `busy` flag (true when a remote control request was refused due to the device being occupied).
  - Returns `{ looking: boolean }`, indicating whether a session lookup/redirect is in progress, so the caller can keep showing a "busy" loading state instead of a final busy screen.
  - Internally uses `useRemoteSessionWatchGate` to check if "Watch live" is enabled (`'on'`, `'off'`, or `'loading'`).
  - Queries live sessions for the device via `readLiveSessions`, only when `busy` is true and the watch gate is `'on'` (using `skipToken` otherwise to avoid unnecessary fetches).
  - Identifies a live session belonging to a *different* technician than the current user and redirects to it using `router.replace(routes.devices.liveSession(target))`.

## Usage Example

```typescript
'use client';

import { useBusyDeviceLiveSession } from './use-busy-device-live-session';

function RemoteControlModal({ deviceId }: { deviceId: string }) {
  const requestBusy = true; // set when the remote control request returns "busy"
  const { looking } = useBusyDeviceLiveSession(deviceId, requestBusy);

  if (looking) {
    return <p>Checking for an active session to watch...</p>;
  }

  return <p>This device is currently busy with another session.</p>;
}
```

The hook performs navigation as a side effect (via `router.replace`), so components using it don't need to manually handle the redirect — they only need to render appropriate UI based on the `looking` state while the lookup resolves.
