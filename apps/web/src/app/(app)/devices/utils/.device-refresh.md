# device-refresh.ts

A lightweight, module-level pub/sub mechanism that drives cache-busting for mounted Relay device queries. It solves the problem of refetching an already-rendered Relay query from outside the component tree, where `store.invalidateStore()` fails to trigger a refetch for queries already on screen.

## Key Components

- **`bumpDeviceEpoch()`** — Increments the module-level `deviceEpoch` counter and notifies all subscribed listeners. Called from mutation callbacks (e.g., after archiving/deleting a device) to force dependent queries to refetch.
- **`useDeviceEpoch()`** — React hook that returns the current epoch value, deferred via `useDeferredValue`. Intended to be used as part of a Relay query's `fetchKey` so that mutations trigger a fresh fetch without dropping already-rendered rows to a loading skeleton.
- **`subscribe` / `getSnapshot`** (internal) — Implementation details wired into `useSyncExternalStore` to keep the hook's output in sync with the module-level counter across all consumers.

## Usage Example

```typescript
import { useDeviceEpoch, bumpDeviceEpoch } from './device-refresh';

// In a component rendering a Relay query for devices:
function DevicesPanel() {
  const epoch = useDeviceEpoch();

  const data = useLazyLoadQuery(
    DevicesQuery,
    { /* ...variables */ },
    { fetchKey: epoch }, // bumps Relay's cacheBreaker when epoch changes
  );

  // ...render devices
}

// In a mutation's onCompleted callback (e.g., archiving a device):
function archiveDevice(deviceId: string) {
  commitMutation(environment, {
    mutation: ArchiveDeviceMutation,
    variables: { deviceId },
    onCompleted: () => {
      bumpDeviceEpoch(); // forces all mounted device queries to refetch
    },
  });
}
```

Because `useDeviceEpoch` wraps the counter in `useDeferredValue`, the UI keeps showing previously committed rows during the refetch transition instead of suspending the whole page — preserving the "background refresh" behavior previously provided by react-query invalidation.
