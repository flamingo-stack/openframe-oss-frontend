## query-keys.ts

Defines the centralized React Query key factory for device-related data and a single invalidation entry point that synchronizes both the React Query cache and the parallel Relay cache after device mutations.

All device reads (bounded pages, full-fleet walks, detail views, session recordings, counts, and stats) key off a shared `['devices']` root. This ensures a single invalidation call can refresh every react-query device surface, preventing the stale-data drift that occurs when queries are keyed with ad-hoc literals instead of this shared factory.

## Key Components

- **`deviceQueryKeys`** — Query key factory object with methods for:
  - `all`, `lists()`, `page()`, `full()` — device list/page queries
  - `detail()` — single device detail
  - `sessionRecordings()`, `sessionRecording()`, `liveSession()`, `tenantLiveSessions()`, `sessionEvents()`, `recordingTickets()`, `recordingStorage()` — remote session/recording data
  - `counts()`, `countsBy()`, `stats()` — device counters and dashboard breakdowns
- **`invalidateDeviceQueries(queryClient)`** — Invalidates both caches after a device mutation: bumps the Relay device epoch (forces active Relay queries to refetch via `fetchKey`) and invalidates React Query's `devices` and dashboard org-stats keys.

## Usage Example

```typescript
import { deviceQueryKeys, invalidateDeviceQueries } from './query-keys';
import { useQuery, useQueryClient } from '@tanstack/react-query';

// Reading device detail data
function useDeviceDetail(machineId: string) {
  return useQuery({
    queryKey: deviceQueryKeys.detail(machineId),
    queryFn: () => fetchDeviceDetail(machineId),
  });
}

// After archiving/deleting a device, refresh every dependent surface
function useArchiveDevice() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: archiveDeviceApi,
    onSuccess: () => {
      invalidateDeviceQueries(queryClient);
    },
  });
}
```

**Important:** Never invent a new query key literal at the call site — always add the key to `deviceQueryKeys` so `invalidateDeviceQueries` can reliably refresh it.
