# query-keys.ts

Defines the canonical React Query key factory for device-related data and a single invalidation helper that refreshes every device surface (React Query and Relay) after a device mutation.

All device reads keyed under React Query are rooted at `['devices']`, making it possible to invalidate every dependent query with one call. Device *list* views, picker components, and filter facets are instead powered by Relay and refreshed separately via a device "epoch" bump (see `device-refresh.ts`), since Relay's `QueryResource` does not re-check staleness on invalidation alone.

## Key Components

- **`deviceQueryKeys`** — Hierarchical query key factory object:
  - `all` — root key `['devices']`
  - `lists()`, `page(filter, search, first)`, `full(filter)` — list-related keys
  - `detail(machineId)` — single device detail key
  - `sessionRecordings(deviceId)`, `sessionRecording(recordingId)`, `liveSession(sessionId)`, `tenantLiveSessions(filter)`, `sessionEvents(recordingId)`, `recordingTickets(recordingId)`, `recordingStorage()` — remote session/recording-related keys
  - `counts()`, `countsBy(filter)`, `stats()` — aggregate/counter keys
- **`invalidateDeviceQueries(queryClient)`** — Invalidates all device-related React Query caches, triggers a Relay device epoch bump, and invalidates the dashboard org-stats query, ensuring consistency across both data layers after a mutation (e.g., archive, delete).

## Usage Example

```typescript
import { deviceQueryKeys, invalidateDeviceQueries } from '@/app/(app)/devices/utils/query-keys';
import { useQuery, useQueryClient } from '@tanstack/react-query';

// Querying device details
const { data } = useQuery({
  queryKey: deviceQueryKeys.detail(machineId),
  queryFn: () => fetchDeviceDetail(machineId),
});

// After a mutation (e.g., deleting a device)
function useDeleteDevice() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: deleteDevice,
    onSuccess: () => {
      invalidateDeviceQueries(queryClient);
    },
  });
}
```

**Important:** Never construct device query key literals at call sites — always add new keys to `deviceQueryKeys` so `invalidateDeviceQueries` continues to refresh every dependent screen.
