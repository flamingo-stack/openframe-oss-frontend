## device-tags.ts

Maps GraphQL `MachineTag` assignment nodes (from the device row fragment) into the `DeviceTag` shape used by UI components. This mapper is intentionally kept separate from `device-transform.ts` because it has no GraphQL tag dependencies, making it testable with vitest without the Relay babel plugin.

## Key Components

- **`MachineTagFields`** — Type alias extracting the element type of `tagAssignments` from the `deviceRowFields_machine` fragment's generated data.
- **`MachineTagFieldsLike`** — A relaxed version of `MachineTagFields` where everything except `id` (on the assignment) and `id`/`key` (on the nested `tag`) is optional. This looser shape lets the device detail page reuse the mapper even when it sources data from raw POST responses instead of a Relay node.
- **`toDeviceTags(assignments)`** — Converts an array (or nullish value) of `MachineTagFieldsLike` into a `DeviceTag[]`. Null/undefined entries are filtered out via `flatMap`. Field mapping:
  - `tagId`, `key`, `description`, `color` — sourced from the tag definition
  - `values` — sourced from the assignment, copied into a new mutable array (Relay returns readonly arrays)
  - `createdAt` — sourced from `assignment.taggedAt`, representing when the device was tagged

## Usage Example

```typescript
import { toDeviceTags } from './device-tags';

const deviceTags = toDeviceTags(machine.tagAssignments);

deviceTags.forEach(tag => {
  console.log(tag.key, tag.values, tag.createdAt);
});
```

```typescript
// Works with looser, non-Relay shaped data too
const tags = toDeviceTags([
  {
    id: 'assignment-1',
    values: ['production'],
    taggedAt: '2024-01-01T00:00:00Z',
    tag: { id: 'tag-1', key: 'environment', color: '#00ff00' },
  },
  null,
]);
```
