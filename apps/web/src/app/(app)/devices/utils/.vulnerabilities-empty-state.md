## Purpose

Determines why a device's vulnerabilities list is empty (or stale) by evaluating Fleet MDM pipeline state in a fixed priority order. This encodes a decision table agreed with the backend team for consistent empty-state messaging across the UI.

## Key Components

- **`VulnerabilitiesEmptyReason`** — Union type representing possible empty-state reasons: `'error'`, `'disconnected'`, `'collecting'`, `'scan-pending'`, `'clean'`.
- **`getVulnerabilitiesEmptyReason(device)`** — Evaluates a device's Fleet source status and software inventory timestamps to determine the top-down applicable empty reason.
- **`isVulnerabilityScanPending(device)`** — Returns `true` when the last completed vulnerability-matching run does not yet cover the device's current software inventory (used both for empty-state and for "data sync in progress" banners even when results exist).

## Usage Example

```typescript
import { getVulnerabilitiesEmptyReason, isVulnerabilityScanPending } from './vulnerabilities-empty-state';
import type { Device } from '../types/device.types';

function renderVulnerabilitiesPanel(device: Device) {
  if (isVulnerabilityScanPending(device)) {
    showSyncBanner();
  }

  const reason = getVulnerabilitiesEmptyReason(device);
  switch (reason) {
    case 'error':
      return showMessage('Unable to fetch vulnerability data.');
    case 'disconnected':
      return showMessage('Device is disconnected from Fleet.');
    case 'collecting':
      return showMessage('Collecting device inventory…');
    case 'scan-pending':
      return showMessage('Vulnerability scan pending for latest software.');
    case 'clean':
      return showMessage('No known vulnerabilities found.');
  }
}
```

## Notes

- Priority order matters: `error` > `disconnected` > `collecting` > `scan-pending` > `clean`.
- `isVulnerabilityScanPending` never returns `true` for devices in earlier pipeline stages (error/disconnected/collecting)—it strictly represents a sync-timing gap, not a missing-data state.
- Depends on `fleetTimestampMs` from `./fleet-timestamp` for safe timestamp comparisons.
