Parses free-text device log search input into structured include/exclude term lists, enforcing the `DeviceLogService` constraints on term count and length before the query is sent to the backend.

## Key Components

- **`MAX_SEARCH_TERMS`** / **`MAX_SEARCH_LENGTH`** — Constants mirroring `DeviceLogFilterInput.contains` / `excludes` backend limits (5 terms max, 256 characters each).
- **`TERM_PATTERN`** — Regex matching a single search token: a quoted phrase (`"..."`) or a bare word, optionally prefixed with `-` to mark it as excluded.
- **`DeviceLogSearch`** — Interface describing the parsed result: `contains` (terms to match), `excludes` (terms to filter out), and `error` (validation message, or `null` if valid).
- **`parseDeviceLogSearch(text: string): DeviceLogSearch`** — Main entry point. Tokenizes the raw search text, splits terms into `contains`/`excludes` based on a leading `-`, strips surrounding quotes, and validates against the length/count limits.
- **`stripQuotes`** — Internal helper removing leading/trailing double quotes from a token.
- **`searchLimitError`** — Internal helper returning a human-readable error string if any term exceeds `MAX_SEARCH_LENGTH` or if either list exceeds `MAX_SEARCH_TERMS`, otherwise `null`.

## Usage Example

```typescript
import { parseDeviceLogSearch } from './device-log-search';

const result = parseDeviceLogSearch('"control channel" failed -heartbeat');

// result.contains => ['control channel', 'failed']
// result.excludes => ['heartbeat']
// result.error     => null

if (result.error) {
  // Show validation message to the user; do not send contains/excludes to the API
  console.warn(result.error);
} else {
  // Safe to pass result.contains / result.excludes into DeviceLogFilterInput
  fetchDeviceLogs({ contains: result.contains, excludes: result.excludes });
}
```

Empty tokens (e.g. stray quotes `""`) are silently dropped, and exceeding either the term count or per-term length populates `error`, signaling callers to skip applying the filter.
