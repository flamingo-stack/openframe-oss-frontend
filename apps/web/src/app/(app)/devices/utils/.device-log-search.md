Parses free-text search input from a device log search box into structured `contains`/`excludes` term lists, enforcing the `DeviceLogService` limits on term count and length.

## Key Components

- **`MAX_SEARCH_TERMS`** / **`MAX_SEARCH_LENGTH`** — constants mirroring the `DeviceLogFilterInput.contains`/`excludes` backend limits (5 terms max, 256 characters max per term).
- **`TERM_PATTERN`** — regex that tokenizes input into quoted phrases or bare words, each optionally prefixed with `-` for exclusion.
- **`DeviceLogSearch`** — interface describing the parsed result: `contains` terms, `excludes` terms, and an `error` string (or `null`) indicating whether the parsed terms violate the limits.
- **`parseDeviceLogSearch(text)`** — main entry point; tokenizes the input text, splits terms into `contains`/`excludes` based on a leading `-`, strips surrounding quotes, and validates against the term/length limits.
- **`stripQuotes(token)`** — internal helper that removes leading/trailing double quotes from a token.
- **`searchLimitError(contains, excludes)`** — internal helper that returns a user-facing error message if any term is too long or too many terms were supplied, otherwise `null`.

## Usage Example

```typescript
import { parseDeviceLogSearch } from './device-log-search';

const result = parseDeviceLogSearch('"control channel" failed -heartbeat');
// result.contains === ['control channel', 'failed']
// result.excludes === ['heartbeat']
// result.error === null

if (result.error) {
  // Show validation message to the user; skip applying contains/excludes.
  console.warn(result.error);
} else {
  // Safe to forward `contains` and `excludes` to DeviceLogFilterInput.
  applyDeviceLogFilter({ contains: result.contains, excludes: result.excludes });
}
```

Empty tokens (e.g., stray quotes or extra whitespace) are silently dropped during parsing, so only meaningful terms reach `contains`/`excludes`.
