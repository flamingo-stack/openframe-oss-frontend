# device-transform.ts

Transforms Relay-generated `Machine` GraphQL fragments into the flattened `Device` type consumed by device tables, cards, and selectors. Implements a three-step "field ladder" where each transform function reads a progressively richer fragment and builds on the output of the previous step, ensuring callers can only access fields their GraphQL query actually selected.

## Key Components

- **`DeviceRowFields`** — Plain data type (fragment marker stripped) for the row step, used by non-Relay data sources like the assignments list that construct devices from raw queries instead of Relay fragment references.
- **`rowFieldsToDevice(machine)`** — Step 1 core logic: maps raw row fields (identifiers, network placeholder, status, OS, organization, tags) to a `Device`. Separated from the Relay-reading wrapper so non-Relay callers can reuse it.
- **`machineRowToDevice(ref)`** — Step 1 entry point: reads `deviceRowFields_machine` fragment via `readInlineData` and delegates to `rowFieldsToDevice`.
- **`machineSelectorToDevice(ref)`** — Step 2: extends Step 1 with hardware identifiers (serial, vendor, model) and a single resolved customer contact email, for use in `DeviceSelector`.
- **`machineToDevice(ref)`** — Step 3: extends Step 2 with network details (IP, MAC), OS version/build, agent version, tool connections, and timestamps — the full shape for the Devices page.
- **`toToolConnections(connections)`** — Internal helper that normalizes nullable `toolConnections` arrays into `ToolConnection[]`.

## Usage Example

```typescript
import { machineToDevice, machineRowToDevice } from './device-transform';
import type { deviceFields_machine$key } from '@/__generated__/deviceFields_machine.graphql';

function DeviceTableRow({ machineRef }: { machineRef: deviceRowFields_machine$key }) {
  const device = machineRowToDevice(machineRef);
  return <span>{device.displayName}</span>;
}

function DeviceDetailPanel({ machineRef }: { machineRef: deviceFields_machine$key }) {
  const device = machineToDevice(machineRef);
  return (
    <div>
      <p>{device.hostname} — {device.ip}</p>
      <p>OS: {device.osVersion} ({device.osBuild})</p>
    </div>
  );
}
```

Each function requires the caller to have spread the corresponding fragment (`deviceRowFieldsFragment`, `deviceSelectorFieldsFragment`, or `deviceFieldsFragment`) into their GraphQL query — the compiler enforces this via the `$key` types.
