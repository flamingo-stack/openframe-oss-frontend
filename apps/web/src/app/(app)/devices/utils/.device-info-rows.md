# device-info-rows.ts

Utility module for building the labelled rows displayed in device detail cards (Hardware, OS, and Network tabs). It normalizes raw values into display-ready rows, falling back to an empty-value placeholder when data is missing, while keeping the field consistently present across loaded and loading states.

## Key Components

- **`DeviceInfoRow`** — Type describing a single detail row: `label`, an optional `value` (`string | number | null`), and an optional `copyable` flag.
- **`deviceInfoItems(rows)`** — Maps an array of `DeviceInfoRow` into display rows. Rows with a real value are stringified (preserving `copyable`); rows with no value get `EMPTY_VALUE` instead. This guarantees loading skeletons and loaded cards render the same set of rows via `labelsOf(rows)`.
- **`hasDeviceInfo(rows)`** — Returns `true` if at least one row has a non-empty value, used to decide whether a whole section (e.g., Network tab) should render at all.

Internally, `hasValue(row)` checks that `row.value` is not empty per `isEmptyValue` and not just whitespace.

## Usage Example

```typescript
import { deviceInfoItems, hasDeviceInfo, type DeviceInfoRow } from '@/lib/device-info-rows';

const hardwareRows: DeviceInfoRow[] = [
  { label: 'CPU', value: 'Intel i7-12700K', copyable: true },
  { label: 'RAM', value: null },
  { label: 'Serial Number', value: 'SN-12345', copyable: true },
];

// Decide whether to render the "Hardware" section at all
if (hasDeviceInfo(hardwareRows)) {
  const items = deviceInfoItems(hardwareRows);
  // items[1].value === EMPTY_VALUE (RAM missing)
  // items[0] and items[2] retain their stringified values and copyable flag
  items.forEach(item => {
    console.log(`${item.label}: ${item.value}`);
  });
}
```

This pattern keeps device detail cards and their loading placeholders structurally identical, only swapping real values for the empty-value marker when a device doesn't report a field.
