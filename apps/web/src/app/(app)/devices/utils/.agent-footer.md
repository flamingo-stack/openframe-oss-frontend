Builds and returns footer metadata for agent info cards, displaying a "Signed by Flamingo" badge with a repository link for recognized tool types.

## Key Components

- **`AGENT_REPO_LINKS`** — Static map of `ToolType` values to their corresponding GitHub repository URLs. Only tool types with an entry here will receive a footer.
- **`isLinkedToolType(toolType)`** — Type guard that narrows a `string` to `ToolType` by checking presence in `AGENT_REPO_LINKS`.
- **`getAgentFooter(toolType)`** — Main export. Accepts a loosely-typed `string` (to accommodate synthetic values like `OSQUERYD` from the agents tab) and returns an `InfoCardFooterData` object or `undefined` if the tool type has no registered link.

## Usage Example

```typescript
import { getAgentFooter } from './agent-footer';

const footer = getAgentFooter('FLEET_MDM');
// Returns:
// {
//   icon: <ShieldCheckIcon size={24} className="text-ods-success" />,
//   text: 'Signed by Flamingo',
//   logo: <FlamingoLogo width={24} height={24} />,
//   link: { href: 'https://github.com/flamingo-stack/fleetmdm' },
// }

const noFooter = getAgentFooter('OSQUERYD');
// Returns: undefined
```

## Notes

- The `toolType` parameter intentionally accepts `string` rather than `ToolType` because the agents tab may synthesize values (e.g. `OSQUERYD`) that fall outside the `ToolType` union. The `isLinkedToolType` guard handles safe narrowing internally.
- To add footer support for a new tool, add an entry to `AGENT_REPO_LINKS` with the appropriate `ToolType` key and its GitHub URL.
