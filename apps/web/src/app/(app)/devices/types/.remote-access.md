## remote-access.ts

Defines the read-model types, enums, and helper functions for the remote-access approval and session lifecycle feature, mirroring the backend's approval contract (OpenAPI 1.0.0-draft). It models request/session state machines, policy modes, and the real-time notification events used to drive the technician-facing remote access UI.

## Key Components

- **`RemoteSessionKind`** – Literal type for the MeshCentral surface being accessed (currently only `'desktop'`).
- **`RemoteAccessRequestStatus`** / **`RemoteAccessDecisionSource`** – Enumerate the request state machine (`PENDING` → `DELIVERED` → terminal states) and who resolved it.
- **`RemoteAccessRequest`** / **`CreateRemoteAccessRequestInput`** – Shape of an approval request and the payload used to create one.
- **`RemoteAccessCreateError`** / **`RemoteAccessCreateErrorCode`** – Typed error class/codes for create-request failures (409/503/404 cases).
- **`RemoteAccessDecisionEvent`** – Shape of the NATS notification event signaling a request's delivery/settlement.
- **`buildRemoteAccessRelayIdPrefix()`** – Builds the MeshCentral relay id prefix (`<requestId>.<protocol>`) used to gate sessions.
- **`REMOTE_ACCESS_MODES`**, **`RemoteAccessMode`**, **`REMOTE_ACCESS_MODE_META`** – Policy modes (`APPROVAL_REQUIRED`, `NOTIFY_ONLY`, `SILENT_ACCESS`, `DENY_ACCESS`) with UI display copy.
- **`CUSTOMER_DEFAULT`**, **`RemoteAccessChoice`**, **`REMOTE_ACCESS_CHOICES`** – Device-level select options including "inherit from customer".
- **`remoteAccessChoiceLabel()`** / **`remoteAccessChoiceDescription()`** – Format human-readable labels/descriptions for a policy choice.
- **`TenantRemoteAccessPolicy`**, **`OrganizationRemoteAccessPolicy`**, **`DeviceRemoteAccessPolicy`** – Policy records at each scope, including resolved effective mode.
- **`RemoteSessionStatus`**, **`RemoteSessionEndReason`**, **`RemoteSession`**, **`RemoteSessionViewerEntry`**, **`RemoteSessionEnd`**, **`RemoteSessionEvent`** – Full session lifecycle model, including active viewers and end-of-session notification payloads.

## Usage Example

```typescript
import {
  RemoteAccessRequest,
  RemoteAccessMode,
  remoteAccessChoiceLabel,
  CUSTOMER_DEFAULT,
  buildRemoteAccessRelayIdPrefix,
} from './remote-access';

function describeRequest(request: RemoteAccessRequest) {
  return `Request ${request.requestId} for device ${request.deviceId} is ${request.status}`;
}

// Resolve UI label for a device override select
const label = remoteAccessChoiceLabel(CUSTOMER_DEFAULT, 'APPROVAL_REQUIRED' as RemoteAccessMode);
// => "Customer Default (Approval Required)"

// Build the MeshCentral relay id prefix for an approved desktop session
const relayPrefix = buildRemoteAccessRelayIdPrefix('01HXYZ...', 2);
// => "01HXYZ....2"
```

These types are consumed by `remote-access-approval-api-service.ts`, which produces instances matching these shapes from backend responses and NATS notification events.
