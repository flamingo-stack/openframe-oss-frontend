Renders the **Archived Devices** page, a filtered view of the `DevicesPanel` component locked exclusively to archived device records.

## Key Components

- **`ArchivedDevices`** *(default export)* — Page component that mounts `DevicesPanel` with status filters hard-locked to `DEVICE_STATUS.ARCHIVED`, hiding the status filter UI and the "Add Device" control.
- **`ARCHIVED_ONLY_FILTERS`** — Module-level constant passed as `lockedFilters` to prevent users from changing the status filter away from `ARCHIVED`.
- **`NO_DEFAULT_STATUSES`** — Stable empty array reference used as `defaultStatuses` to avoid unnecessary re-renders from inline array literals.
- **`useSafeBack`** — Hook providing a back-navigation handler that falls back to `routes.devices.list` if no browser history entry exists.

## Usage Example

This page is route-mounted automatically (Next.js App Router). It is typically reached via an "Archive" button on the main `/devices` list page.

```typescript
// Navigating to this page programmatically
import { routes } from '@/lib/routes';
import { useRouter } from 'next/navigation';

const router = useRouter();
router.push(routes.devices.archived); // renders ArchivedDevices
```

```typescript
// How DevicesPanel receives the locked filter internally
<DevicesPanel
  lockedFilters={{ statuses: ['ARCHIVED'] }}
  defaultStatuses={[]}
  hideFilters={['status']}
  showAddDevice={false}
  emptyMessage="No archived devices."
/>
```

## Notes

- `ARCHIVED_ONLY_FILTERS` and `NO_DEFAULT_STATUSES` are declared at module scope to maintain **stable prop identity**, preventing `DevicesPanel` from re-rendering on every parent render cycle.
- The `status` filter is hidden from the UI (`hideFilters={['status']}`) because only archived devices are shown; toggling status here would be meaningless.
