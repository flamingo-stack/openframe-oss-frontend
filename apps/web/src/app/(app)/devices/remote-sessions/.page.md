Next.js page component rendering the "Remote Sessions" tab of the Devices section, displaying a tenant's remote session history across all devices with feature-gated access control.

## Key Components

- **`RemoteSessionsPage`** (default export) — Client component that renders the Remote Sessions tab, guards access via a feature gate, and composes the tab navigation, storage banner, and sessions table.
- **`useSessionRecordingsGate`** — Hook determining whether the feature is `'on'`, `'off'`, or still resolving (undefined/loading state).
- **Gate redirect logic** — `useEffect` that redirects to `routes.devices.list` when the gate resolves to `'off'`, preventing access to a disabled feature.
- **`DevicesTabNavigation`** — Shared tab navigation bar shown with `activeTab="remote-sessions"`.
- **`RecordingStorageBanner`** — Conditionally rendered banner warning when tenant recording storage is full (only shown once loading completes).
- **`TenantSessionsShell`** — The main table/content component listing remote sessions, wrapped in `LoadingWhen` and `ContentErrorBoundary`.

## Usage Example

This file is a Next.js App Router page and is rendered automatically by the framework based on its route location (not imported directly). The pattern it demonstrates:

```typescript
// Conceptual usage - Next.js resolves this automatically via file-based routing
// Accessing the route navigates here, e.g.:
router.push(routes.devices.remoteSessions); // illustrative; actual route depends on routes.ts

// Internally, the page:
// 1. Checks the feature gate
// 2. Redirects away if disabled
// 3. Shows a loading state until the gate resolves
// 4. Renders the sessions table once enabled
```

The page relies on `routes.devices.list` for redirect behavior when the feature gate is `'off'`, and on `useSessionRecordingsGate` to avoid rendering gated content prematurely, ensuring a flicker-free experience while the gate check resolves.
