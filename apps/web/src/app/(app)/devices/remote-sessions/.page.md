This client-side Next.js page component renders the **Remote Sessions** tab of the Devices section, displaying a tenant's remote session history across all devices while gating access via a feature flag.

## Key Components

- **`RemoteSessionsPage`** (default export) — the page component rendered at the remote sessions route.
- **`useSessionRecordingsGate`** — hook determining feature flag state (`'on'`, `'off'`, or loading/undetermined); drives both the redirect logic and the loading state.
- **Redirect behavior** — if the gate resolves to `'off'`, the user is redirected to `routes.devices.list` via `router.replace`.
- **`DevicesTabNavigation`** — renders the shared tab navigation for the Devices section, with `remote-sessions` marked active.
- **`RecordingStorageBanner`** — conditionally shown banner warning when tenant recording storage is full; only rendered once loading completes.
- **`ContentErrorBoundary`** — wraps the sessions table to gracefully handle load failures.
- **`LoadingWhen`** — displays a loading state until the gate finishes resolving.
- **`TenantSessionsShell`** — the core table component listing all tenant remote sessions.

## Usage Example

```typescript
// Rendered automatically by the Next.js App Router for the
// remote-sessions route under the Devices section.
// No manual instantiation needed — navigation is handled via routes.devices list.

import { routes } from '@/lib/routes';

// Example: linking to this page from elsewhere in the app
router.push(routes.devices.remoteSessions);
```

The page itself requires no props. Access is controlled entirely by `useSessionRecordingsGate()`: while the gate is undetermined, the page shows a loading state; once resolved to `'off'`, it auto-redirects to the devices list; once `'on'`, it renders the full tenant sessions table with an optional storage-full banner and error boundary protection.
