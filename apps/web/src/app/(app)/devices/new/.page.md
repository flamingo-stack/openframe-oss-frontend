The top-level client-side page component for the "New Device" route, wrapping the device creation form in a `LoadingSuspense` boundary whose fallback is the same form drawn in a loading scope while the customers are read.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `NewDevicePage` | Default export | Page-level component that renders `NewDeviceContent`, with `NewDeviceForm` (no customers yet) as its `LoadingSuspense` fallback, drawn in a loading scope |

**Dependencies:**

- [`NewDeviceContent`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/app/(routes)/devices/new/new-device-content.tsx) — the primary form/content for adding a device

## Usage Example

This is a Next.js App Router page component — it is rendered automatically when a user navigates to the `/devices/new` route. No manual instantiation is required.

```typescript
// Rendered automatically by Next.js at /devices/new
// Internal structure:
<LoadingSuspense
  label="Loading device setup"
  fallback={<NewDeviceForm orgs={NO_ORGANIZATIONS} preselectedOrgId={null} />}
>
  <NewDeviceContent />
</LoadingSuspense>
```

> **Note:** The `'use client'` directive marks this as a Client Component. While `NewDeviceContent` suspends, the page shows the same form in a loading scope, each part drawing its own loading state, so nothing moves when the data arrives.
