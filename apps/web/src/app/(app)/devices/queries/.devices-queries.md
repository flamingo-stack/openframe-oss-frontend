## devices-queries.ts

Defines plain GraphQL query strings for device-related reads that have not yet been migrated to Relay. These are intentionally narrow, single-purpose documents consumed directly (not through Relay's compiler), covering the device detail page, counter facets, and an organization existence probe.

This file is explicitly scoped: the device list and filter facets used by the filter UI live as Relay documents under `src/graphql/devices/`. Any new `devices`/`deviceFilters` selection should extend an existing document here (or be added as a Relay document) rather than being inlined elsewhere.

## Key Components

- **`HAS_ORGANIZATIONS_QUERY`** — Checks if the tenant has at least one organization. Used to gate the "Add Device" action on the Devices page, since a device must belong to an organization.
- **`GET_DEVICE_STATUS_COUNTS_QUERY`** — Fetches only device status facet counts and the filtered total, for counter UI components. Backed by the same `deviceFilters` resolver as other facet queries, so it costs the backend the same regardless of selection width — widen this document instead of creating a new one for overlapping facets.
- **`GET_DEVICE_ORGANIZATION_COUNTS_QUERY`** — Fetches per-organization device counts, used by the customers table and dashboard overview.
- **`GET_DEVICE_QUERY`** — Fetches full detail-page data for a single device by `machineId`, including organization info, tag assignments, tool connections, and installed agents.

## Usage Example

```typescript
import { GET_DEVICE_QUERY, HAS_ORGANIZATIONS_QUERY } from './devices-queries';

// Example: fetching device details
const result = await graphqlClient.request(GET_DEVICE_QUERY, {
  machineId: 'abc-123',
});

// Example: gating "Add Device" button
const { organizations } = await graphqlClient.request(HAS_ORGANIZATIONS_QUERY);
const canAddDevice = organizations.edges.length > 0;
```

**Note:** Do not add a new facet-only query if an existing one (e.g. `GET_DEVICE_STATUS_COUNTS_QUERY`) already triggers the needed Pinot facet resolution — widen its selection set instead, since `deviceFilters` always resolves all facets server-side.
