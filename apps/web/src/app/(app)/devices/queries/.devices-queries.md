The raw-POST device documents — the device reads that are NOT yet on Relay.

The device list and the filter facets are Relay documents under `src/graphql/devices/`. What is left here is the detail-page node, the counter facets, and an organization probe.

## Key Components

| Export | Purpose | Caller |
|---|---|---|
| `HAS_ORGANIZATIONS_QUERY` | Minimal probe — fetches the first organization to gate the "Add Device" action | `hooks/use-has-organizations.ts` |
| `GET_DEVICE_COUNTS_QUERY` | Counters only — status + per-organization breakdowns and `filteredCount` | `devices-api.ts` → `fetchDeviceCounts` |
| `GET_DEVICE_QUERY` | Single device by `machineId`, including `installedAgents` | `devices-api.ts` → `fetchDeviceNode` |

## Notes

- The counter surfaces (dashboard stat cards, customer device counts, the customers overview) need nothing but the numbers, which is why `GET_DEVICE_COUNTS_QUERY` is narrower than the Relay `deviceFiltersRelayQuery` the filter UI runs.
- `GET_DEVICE_QUERY` must keep selecting `tags { id … }`: the transform renames `id` → `tagId`, and without it every tag React key collapses to `undefined-<value>`.
- Don't inline a `devices`/`deviceFilters` selection elsewhere. Extend a document here, or add a Relay one under `src/graphql/devices/`.
