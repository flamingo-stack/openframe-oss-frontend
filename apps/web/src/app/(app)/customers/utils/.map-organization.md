# map-organization.ts

Defines the raw GraphQL organization node types returned by the legacy `/api/graphql` route and maps them into the `CustomerDetails` view-model consumed by the customer details and edit pages.

## Key Components

- **`CustomerDetails`** — View-model interface used by customer details/edit UI, including flattened addresses, a contacts array, MRR, contract dates, and image metadata. Note: `contacts` round-trips wholesale on save — any contact missing from this list is deleted on the next `PUT /api/organizations/{id}`.
- **`OrganizationAddressNode`** — Shape of an address sub-object (street, city, state, postal code, country) as returned by the raw GraphQL query.
- **`OrganizationContactNode`** — Shape of a single contact entry from the API (name, title, email, phone).
- **`OrganizationNode`** — Full organization node shape returned by `/api/graphql`, including nested `contactInformation` and `image`.
- **`formatAddress(addr)`** — Joins non-empty address fields into a single comma-separated string.
- **`toContactDto(contact)`** — Converts an `OrganizationContactNode` into a `ContactPersonDto`, defaulting missing fields to empty strings.
- **`mapOrganization(org)`** — Pure function mapping an `OrganizationNode` into `CustomerDetails`, normalizing nullable fields, formatting addresses, and defaulting `status` to `'ACTIVE'`.

## Usage Example

```typescript
import { mapOrganization, type OrganizationNode } from './map-organization';

async function fetchCustomerDetails(orgNode: OrganizationNode) {
  const details = mapOrganization(orgNode);

  console.log(details.name, details.industry);
  console.log('Physical address:', details.physicalAddress);
  console.log('Contacts:', details.contacts);

  return details;
}
```

**Important:** When saving edits, always send back the full `contacts` array from `CustomerDetails`—omitting an existing contact will cause the API to delete it on save, since `contactInformation` is replaced wholesale.
