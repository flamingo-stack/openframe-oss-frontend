Utility function that invalidates all React Query caches affected by a customer create/update/delete operation, ensuring UI consistency across customer lists, dashboard counters, and detail views.

## Key Components

- **`invalidateCustomerQueries(queryClient, organizationId)`** — Async function that invalidates:
  - The full customers list cache (`customersQueryKeys.all`)
  - The dashboard counters cache (`dashboardQueryKeys.all`)
  - The specific customer's detail cache (`customerDetailsQueryKeys.detail(organizationId)`), only when `organizationId` is provided (relevant in edit mode)

  All invalidations run concurrently via `Promise.all` and the function should be `await`ed before navigation to guarantee fresh data on the next render.

## Usage Example

```typescript
import { useQueryClient } from '@tanstack/react-query';
import { invalidateCustomerQueries } from './invalidate-customer-queries';

async function handleSaveCustomer(organizationId: string | null) {
  const queryClient = useQueryClient();

  await saveCustomer(organizationId);
  await invalidateCustomerQueries(queryClient, organizationId);

  // Safe to navigate now — caches are fresh
  router.push('/customers');
}

// On create (no existing organizationId yet)
await invalidateCustomerQueries(queryClient, null);
```

## Notes

Place this call immediately after a successful mutation (create, update, or delete) and before any navigation away from the current view. Passing `null` for `organizationId` skips the detail-cache invalidation, which is appropriate for newly created customers that have no existing cached detail entry.
