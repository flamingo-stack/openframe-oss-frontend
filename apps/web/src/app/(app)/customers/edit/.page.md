This client-side Next.js page component renders the customer edit form for an existing organization, resolving the required `id` query parameter and delegating rendering to the shared `NewCustomerPage` component.

## Key Components

- **`EditOrganizationPage`** (default export) — Page component that extracts the organization `id` from the URL query string and renders the edit form for that organization.
- **`useRequiredIdParam`** — Hook that reads and validates a required `id` param from the current route, redirecting to a fallback route if missing.
- **`key={id}`** — Forces React to remount `NewCustomerPage` whenever `id` changes, ensuring the form's internal seed/state isn't stale from a previous organization.

## Usage Example

```typescript
// Navigating to this page with a query parameter:
// /customers/edit?id=org_12345

export default function EditOrganizationPage() {
  const id = useRequiredIdParam('/customers', routes.customers.new);
  if (!id) return null;

  return <NewCustomerPage key={id} organizationId={id} />;
}
```

**Notes:**
- If the `id` param is absent, `useRequiredIdParam` redirects the user back to `/customers` (via the fallback route `routes.customers.new`), and this component renders `null` while the redirect occurs.
- The `key={id}` prop is essential: since `NewCustomerPage` manages form state internally based on initial props, changing the `organizationId` without remounting could leave the form displaying stale data from a previously edited organization.
- This component reuses `NewCustomerPage` for both creation and editing flows, differentiated by whether `organizationId` is provided.
