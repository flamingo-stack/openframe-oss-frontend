This Next.js client page component renders the edit view for an existing customer/organization, reusing the new-customer creation form in "edit mode" by passing an `organizationId`.

## Key Components

- **`EditOrganizationPage`** (default export) — Page component that:
  - Extracts and validates the `id` query/route parameter via `useRequiredIdParam`, redirecting to `routes.customers.new` if missing/invalid.
  - Renders `NewCustomerPage` with the resolved `organizationId`, keyed by `id` to force a remount whenever the id changes (since the form seeds its initial state only once per mount).

## Usage Example

This page is typically resolved automatically by Next.js routing (e.g., a route like `/customers/edit?id=123` or a dynamic segment mapping to this file). Example of the underlying pattern:

```typescript
// app/(app)/customers/edit/page.tsx
'use client';

import { NewCustomerPage } from '@/app/(app)/customers/components/new-customer-page';
import { useRequiredIdParam } from '@/app/hooks/use-required-id-param';
import { routes } from '@/lib/routes';

export default function EditOrganizationPage() {
  const id = useRequiredIdParam('/customers', routes.customers.new);
  if (!id) return null;

  return <NewCustomerPage key={id} organizationId={id} />;
}
```

**Key behavior notes:**

- `useRequiredIdParam` handles redirect logic when the required identifier is absent, keeping this component focused purely on rendering.
- The `key={id}` prop is essential: without it, navigating between different organization IDs (e.g., `?id=1` → `?id=2`) would not reset the form's internal state, since React would reuse the existing component instance.
