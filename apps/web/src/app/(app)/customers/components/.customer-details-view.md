## Customer Details View

Renders the full customer (organization) detail page: header, tab navigation, and archive/restore/edit actions. Manages tab state via URL query params, gates feature tabs (AI assistant, guardrails, directory) based on tenant mode and feature flags, and integrates with Mingo context tracking.

## Key Components

- **`CustomerDetailsView`** — Main component accepting a customer `id` prop; orchestrates data fetching, tab visibility, and page actions.
- **`DETAIL_TO_EDIT_TAB`** — Maps detail-page tab IDs to their corresponding edit-page tabs for deep-linking into "Edit Customer".
- **`handleTabChange`** — Updates the `tab` query param via `router.replace` instead of relying on `TabNavigation`'s built-in URL sync, avoiding a tab-reset flicker.
- **`handleArchiveClick` / `handleArchiveConfirm`** — Checks archive eligibility, opens `ArchiveCustomerModal`, and performs the archive mutation with query cache invalidation and toast feedback.
- **`handleRestoreConfirm`** — Restores an archived customer via `RestoreCustomerModal`.
- **`actions`** — Memoized `PageActionButton[]` for Archive/Restore and Edit Customer, with the Edit action deep-linking to the tab matching the current details tab.
- Feature gates: `useRemoteAccessApprovalGate` (device guardrails tab) and `useTenantManagementV2Gate` (directory tab), both tri-state (`'loading' | 'on' | 'off'`) to avoid tab-list flicker.

## Usage Example

```typescript
import { CustomerDetailsView } from './customer-details-view';

export default function CustomerPage({ params }: { params: { id: string } }) {
  return <CustomerDetailsView id={params.id} />;
}
```

The component reads the active tab from the `tab` search param (defaulting to `'devices''`), falling back to `'devices'` if the requested tab isn't available for the current tenant/feature-flag configuration. It wraps rendering in `LoadingWhen`/`useLoadingScope` so the header, tab strip, and individual tab content each manage their own loading states independently.
