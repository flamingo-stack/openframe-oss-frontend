The main view component for displaying detailed information about a single customer (organization), managing tab navigation, and handling archive/restore actions.

## Key Components

- **`CustomerDetailsView`** — Primary exported component. Accepts a customer `id` prop and renders the full customer detail page including header, tabbed content, and action modals.
- **`DETAIL_TO_EDIT_TAB`** — Mapping from detail-page tab IDs to their corresponding edit-page tab IDs, enabling deep-linked navigation to the correct edit tab.

### Key Behaviors

- **Tab navigation** — URL-controlled (via `?tab=` param) to avoid flicker from `TabNavigation`'s internal sync effect. Defaults to `devices` for unknown tabs.
- **Feature-flagged tabs** — AI Assistant and Guardrails tabs are conditionally shown based on `featureFlags` and `runtimeEnv.appMode()` (`saas-tenant` only).
- **Archive/Restore** — Pre-checks archive eligibility before opening the confirmation modal; invalidates both `customers` and `customerDetails` query caches on success.
- **Mingo context tracking** — Registers the viewed organization as the active Mingo context via `useTrackOpenView`.

## Usage Example

```typescript
// Rendered by the customer detail page route
import { CustomerDetailsView } from './customer-details-view';

export default function CustomerDetailPage({ params }: { params: { id: string } }) {
  return <CustomerDetailsView id={params.id} />;
}
```

## Dependencies

| Hook / Utility | Purpose |
|---|---|
| `useCustomerDetails` | Fetches organization data |
| `useCustomerArchive` | Archive/restore mutations + eligibility check |
| `useClientView` | Loads AI assistant appearance override (legacy flag) |
| `useTrackOpenView` | Registers entity in Mingo context |
| `useSafeBack` | Handles back navigation with archived-list fallback |
