# customer-details-view.tsx

Client-side React component rendering the Customer Details page, including the tabbed detail view, header actions (archive/restore, edit), and modals for archiving or restoring a customer organization.

## Key Components

- **`CustomerDetailsView`** — Main exported component. Accepts an `id` prop (organization ID) and renders:
  - A `PageLayout` header with customer name, subtitle (website/industry), logo, and action buttons.
  - A `TabNavigation`/`TabContent` structure driven by the URL's `tab` query parameter, with tabs conditionally shown based on feature gates (`useTenantManagementV2Gate`, `useRemoteAccessApprovalGate`) and app mode (`saas-tenant` vs OSS).
  - `ArchiveCustomerModal` and `RestoreCustomerModal` for lifecycle actions.

- **`DETAIL_TO_EDIT_TAB`** — Maps detail-page tab IDs to their corresponding edit-page tab IDs, used to deep-link the "Edit Customer" action into the matching edit tab.

- **Internal handlers**:
  - `handleTabChange` — Updates the `tab` query param via `router.replace` (controlled tab navigation to avoid URL-sync flicker).
  - `handleArchiveClick` / `handleArchiveConfirm` — Checks archive eligibility and performs archive, invalidating related React Query caches.
  - `handleRestoreConfirm` — Restores an archived organization and invalidates caches.

## Usage Example

```typescript
import { CustomerDetailsView } from './customer-details-view';

export default function CustomerDetailsPage({ params }: { params: { id: string } }) {
  return <CustomerDetailsView id={params.id} />;
}
```

The component is intended to be used as the body of a Next.js route page (e.g., `/customers/[id]`), reading `id` from route params and the active tab from the `?tab=` search parameter. Tab visibility and edit deep-linking are automatically resolved based on tenant type and feature gates—no additional configuration is required by the consumer.
