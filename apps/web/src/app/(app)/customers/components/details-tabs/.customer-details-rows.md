# customer-details-rows.tsx

Builds the `PanelRow` definitions for the customer Details tab, defining row shapes shared between the live tab and its loading skeleton so both stay in sync. It centralizes row ids, field labels, and responsive breakpoint classes so the two consumers cannot drift apart.

## Key Components

- **`SINGLE_COLUMN_ROW` / `DESKTOP_ROW` / `DESKTOP_LAST_ROW` / `MOBILE_ROW`** - Shared CSS class constants controlling row height and responsive visibility (desktop vs. mobile stacked layout).
- **`CustomerInfoCells`** - Interface describing the website and address cell values for the info section.
- **`buildCustomerInfoRows(cells)`** - Produces rows for website (own row) and physical/mailing addresses (side-by-side on desktop, stacked on mobile).
- **`CustomerContactField`** / **`CustomerContactCells`** - Types derived from `CONTACT_FIELD_LABELS` describing per-contact fields (name, title, email, phone).
- **`buildCustomerContactRows(contacts)`** - Produces one desktop row (all four fields) plus two mobile rows (name/title, email/phone) per contact; the last contact's desktop row drops its bottom border.
- **`NO_CONTACTS_COPY`** - Empty-state copy constant for the contacts card.
- **`buildNoContactsRow()`** - Produces a single empty-state `PanelRow` matching the Notes card's styling.

## Usage Example

```typescript
import {
  buildCustomerInfoRows,
  buildCustomerContactRows,
  buildNoContactsRow,
} from './customer-details-rows';

const infoRows = buildCustomerInfoRows({
  website: 'example.com',
  websiteHref: 'https://example.com',
  physicalAddress: '123 Main St',
  mailingAddress: 'PO Box 456',
});

const contactRows = contacts.length
  ? buildCustomerContactRows(
      contacts.map((c) => ({
        contactName: c.name,
        title: c.title,
        email: c.email,
        phone: c.phone,
      }))
    )
  : [buildNoContactsRow()];

// Pass rows into a StackedRowsPanel component
<StackedRowsPanel rows={[...infoRows, ...contactRows]} />;
```

**Note:** The `StackedRowsPanel` component only drops the bottom border of its last DOM child, so mobile rows must be placed last to let the appropriate desktop row absorb the border removal.
