# customer-details-rows.tsx

Builds the `PanelRow` configurations for the customer Details tab, defining row layouts and responsive breakpoint behavior shared between the live tab and its loading skeleton. This ensures both stay in sync on row ids, labels, and breakpoint classes.

## Key Components

- **`SINGLE_COLUMN_ROW`, `DESKTOP_ROW`, `DESKTOP_LAST_ROW`, `MOBILE_ROW`** — Tailwind class constants controlling responsive visibility and border behavior between desktop (`content-md+`) and mobile layouts.
- **`CustomerInfoCells`** — Interface describing the website/address cell content passed into `buildCustomerInfoRows`.
- **`buildCustomerInfoRows(cells)`** — Produces rows for website (single column) and physical/mailing addresses (side-by-side on desktop, stacked on mobile).
- **`CustomerContactField` / `CustomerContactCells`** — Types derived from `CONTACT_FIELD_LABELS` describing a single contact's fields.
- **`buildCustomerContactRows(contacts)`** — Produces one row per contact (4 columns on desktop; split into two stacked rows on mobile), with the last contact's desktop row dropping its bottom border.
- **`NO_CONTACTS_COPY`** — Shared empty-state copy string for the contacts card.
- **`buildNoContactsRow()`** — Produces a single empty-state `PanelRow` matching the Notes card's copy style.

## Usage Example

```typescript
import {
  buildCustomerInfoRows,
  buildCustomerContactRows,
  buildNoContactsRow,
} from './customer-details-rows';

const infoRows = buildCustomerInfoRows({
  website: 'example.com',
  websiteHref: 'https://example.com',
  physicalAddress: '123 Main St',
  mailingAddress: 'PO Box 456',
});

const contactRows = contacts.length
  ? buildCustomerContactRows(
      contacts.map((c) => ({
        contactName: c.name,
        title: c.title,
        email: c.email,
        phone: c.phone,
      }))
    )
  : [buildNoContactsRow()];

// Pass rows into a StackedRowsPanel component
<StackedRowsPanel rows={[...infoRows, ...contactRows]} />;
```

## Notes

- Mobile rows are intentionally rendered as separate `PanelRow` entries (rather than CSS reflow) so that `StackedRowsPanel`'s "drop border on last DOM child" behavior works correctly — mobile rows are placed last in each group.
- Row structures here must mirror whatever skeleton/loading component consumes the same ids and labels to avoid visual drift.
