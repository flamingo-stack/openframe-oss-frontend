# customer-tickets-tab.tsx

Renders the "Tickets" tab within a customer detail view, displaying a searchable, paginated table of support tickets scoped to a specific organization, with a "New Ticket" action.

## Key Components

- **`CustomerTicketsTab`** — Main component accepting an `organizationId` prop. Fetches and displays tickets belonging to that organization, with search, infinite scroll, and loading states.
- **Data fetching** — Uses `useTicketsQuery` scoped by `organizationIds: [organizationId]`, filtered to non-archived tickets, with debounced search (300ms) and conditional fetching (`enabled: !!organizationId`) so the tab stays in a loading scope while the parent customer record is still resolving.
- **Table columns** — Combines shared ticket columns (`getTicketTableColumns`) with an "open in new tab" action column (`getTicketOpenColumn`), memoized against `isUserDeleted` status.
- **Loading behavior** — Uses `useLoadingScope` and `loadingPlaceholderRows` to render a full page of skeleton rows while either the parent customer or the first ticket page is loading, so each cell can show its own loading UI.
- **Sticky toolbar** — `useStickyToolbar` pins the search bar below the page header; `stickyHeaderOffset` is passed to `LiveTable` so the table header docks flush beneath it.
- **`LiveTable`** — Renders the actual table with pagination (`TICKETS_PAGE_SIZE`), empty state, row navigation (`ticketRowHref`), and a "load more" footer wired to `fetchNextPage`.

## Usage Example

```typescript
import { CustomerTicketsTab } from './customer-tickets-tab';

function CustomerDetailPage({ customerId }: { customerId: string }) {
  return (
    <div>
      {/* other tabs */}
      <CustomerTicketsTab organizationId={customerId} />
    </div>
  );
}
```

The component is self-contained: it manages its own query, search state, and table instance. Consumers only need to supply the `organizationId` of the customer whose tickets should be displayed. On query error, it renders `PageError` instead of the table.
