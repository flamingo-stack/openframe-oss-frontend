# customer-tickets-tab.tsx

Renders the "Tickets" tab within a customer's detail page, displaying a searchable, paginated table of support tickets scoped to the given `organizationId`. It provides a sticky search toolbar, a "New Ticket" action button, and handles loading, error, and empty states for the ticket list.

## Key Components

- **`CustomerTicketsTab`** — Default exported component accepting `organizationId` and rendering the tickets tab UI.
- **`CustomerTicketsTabProps`** — Props interface requiring `organizationId: string`.
- Uses `useTicketsQuery` to fetch paginated tickets filtered by `organizationIds: [organizationId]` and debounced search text.
- Uses `useUserStatusMap` to detect deleted assignees and reflect that in the ticket columns.
- Builds table columns via `getTicketTableColumns` plus a trailing `getTicketOpenColumn()` action via `useDataTable`.
- Uses `useStickyToolbar` for sticky search bar positioning and `LiveTable` for rendering rows, pagination ("load more"), and empty/loading states.

## Usage Example

```typescript
import { CustomerTicketsTab } from './customer-tickets-tab';

function CustomerDetailPage({ customerId }: { customerId: string }) {
  return (
    <div>
      {/* Other customer tab content */}
      <CustomerTicketsTab organizationId={customerId} />
    </div>
  );
}
```

### Behavior Notes

- Tickets are scoped server-side by the ticket's own `organizationId` field (via `TicketFilterInput.organizationIds`), not by the owning machine's current organization.
- When `organizationId` is falsy (e.g., while the parent customer is still loading), the query is disabled (`enabled: !!organizationId`) and the component renders placeholder loading rows instead.
- Search input is debounced by 300ms before triggering a refetch.
- Clicking "New Ticket" navigates to `routes.tickets.new()`.
- Row clicks navigate using `ticketRowHref` from the shared ticket table columns module.
