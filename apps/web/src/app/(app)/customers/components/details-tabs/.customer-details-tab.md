# customer-details-tab.tsx

Renders the "Details" tab of a customer record view, showing organization info (website, addresses), a contacts list, and a notes card. Supports a loading state that renders skeleton bars using the same row builders as the loaded view, ensuring layout consistency between loading and loaded states.

## Key Components

- **`CustomerNotesCard`** — Internal component rendering the notes section; shows placeholder text when no notes exist, and a loading skeleton (via `LoadingParagraph`) while data loads.
- **`CustomerDetailsTab`** — Main exported component. Accepts an `organization: CustomerDetails | null` prop (`null` triggers skeleton rendering). Composes three sections:
  - An info panel (`StackedRowsPanel`) built from `buildCustomerInfoRows` showing website (as a clickable external link) and both addresses.
  - A contacts panel built from `buildCustomerContactRows`, or `buildNoContactsRow` when there are no contacts.
  - The `CustomerNotesCard`.
- **`cell()`** — Helper that wraps a value in `ValueText`, handling truncation tooltips, empty states, and skeleton width during loading.
- Constants: `NOTES_CARD_CLASS`, `CONTACTS_SKELETON_ROWS`, `NOTES_SKELETON_LINES` control styling and skeleton shape.

## Usage Example

```typescript
import { CustomerDetailsTab } from '@/app/components/customer/customer-details-tab';
import type { CustomerDetails } from '../../hooks/use-customer-details';

function CustomerPage({ customer }: { customer: CustomerDetails | null }) {
  // Pass `null` while fetching to show skeleton bars with the same layout
  return <CustomerDetailsTab organization={customer} />;
}
```

The component relies on `useLoadingScope` to detect an ancestor loading context, in which case it forces its internal `customer` reference to `null` regardless of the passed `organization` prop, ensuring consistent skeleton rendering within nested loading scopes.
