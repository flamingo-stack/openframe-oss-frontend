## customer-details-tab.tsx

Renders the "Details" tab of a customer view: a company info card (website link, physical/mailing addresses), a contacts card, and a Notes card. Supports a loading state that draws skeleton placeholders using the same row builders as the loaded state, preserving layout consistency.

## Key Components

- **`CustomerDetailsTab`** — Main exported component. Accepts `organization: CustomerDetails | null`; when `null` (or inside a loading scope), renders skeleton bars instead of real data while keeping identical layout.
- **`CustomerNotesCard`** — Internal component rendering the Notes section, showing either the customer's notes or a placeholder message ("No notes yet — add them from Edit Customer.").
- **`cell`** — Helper that wraps a value in `ValueText`, handling truncation, tooltips, and skeleton width during loading.
- **`NOTES_CARD_CLASS`**, **`CONTACTS_SKELETON_ROWS`**, **`NOTES_SKELETON_LINES`** — Styling and skeleton-state constants controlling the notes card frame and the number of placeholder rows/lines shown while loading.

## Usage Example

```typescript
import { CustomerDetailsTab } from './customer-details-tab';
import type { CustomerDetails } from '../../hooks/use-customer-details';

function CustomerPage({ customer }: { customer: CustomerDetails | null }) {
  return (
    <div>
      {/* Pass null while fetching to show skeleton loading state */}
      <CustomerDetailsTab organization={customer} />
    </div>
  );
}
```

The component relies on `buildCustomerInfoRows`, `buildCustomerContactRows`, and `buildNoContactsRow` from `./customer-details-rows` to construct `StackedRowsPanel` row definitions, ensuring loading and loaded states share identical structure. Contacts default to a single placeholder entry while loading, since typical customers have one contact; additional contacts shift layout below it once loaded.
