# customer-guardrails-tab.tsx

Renders the read-only "Customer AI Guardrails" tab on the customer details page, displaying the effective guardrails policy (tenant default or organization-specific override) for a given organization.

## Key Components

- **`CustomerGuardrailsTab`** — Main exported component. Accepts `organizationId` and displays:
  - A loading state via `LoadingWhen` while guardrails and templates fetch
  - An error state via `LoadError` with retry support
  - An "Using Default Settings" banner (when the org inherits tenant defaults) with a button linking to AI Settings → Guardrails for editing
  - A `GuardrailsPresetCard` showing the resolved preset label (default template name, source template, or "Custom Policy")
  - `GuardrailsPolicyGroups` listing the organization's effective rules, or a `NoData` empty state if none are configured

- **`CustomerGuardrailsTabProps`** — Props interface requiring `organizationId: string`.

## Usage Example

```typescript
import { CustomerGuardrailsTab } from '@/app/(app)/settings/customers/components/customer-guardrails-tab';

function CustomerDetailsPage({ organizationId }: { organizationId: string }) {
  return (
    <div>
      {/* other customer tabs... */}
      <CustomerGuardrailsTab organizationId={organizationId} />
    </div>
  );
}
```

**Data flow notes:**
- Uses `useOrganizationGuardrails(organizationId)` to fetch effective guardrails (tenant default rules if `inheritDefault` is true, otherwise the org's materialized policy).
- Uses `useGuardrailsTemplates()` to resolve preset display names.
- `buildPolicyGroups` transforms raw `guardrails.rules` into grouped data consumed by `GuardrailsPolicyGroups`.
- This tab is **read-only**; actual edits happen in AI Settings → Guardrails (`routes.settings.aiSettings`), or via a future per-customer edit flow built on `updateOrganizationGuardrails` / `resetOrganizationGuardrails` mutations.
