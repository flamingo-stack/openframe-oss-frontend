# customer-guardrails-tab.tsx

Client-side React component that renders a read-only "Customer AI Guardrails" tab on the customer details page, displaying the effective guardrail policy (inherited tenant defaults or a customer-specific override) for a given organization.

## Key Components

- **`CustomerGuardrailsTab`** — Main exported component. Accepts `organizationId` and renders:
  - A loading state via `LoadingWhen` while guardrails and templates fetch.
  - An error state via `LoadError` with retry support.
  - An informational banner (when the org inherits tenant defaults) linking to AI Settings → Guardrails for editing.
  - A `GuardrailsPresetCard` showing the resolved preset label (default, source preset, or "Custom Policy").
  - `GuardrailsPolicyGroups` listing rule groups, or a `NoData` empty state when no rules exist.
- **`CustomerGuardrailsTabProps`** — Props interface requiring `organizationId: string`.

Relies on:
- `useOrganizationGuardrails(organizationId)` — fetches the effective guardrails for the org (GraphQL-backed).
- `useGuardrailsTemplates()` — fetches tenant preset templates (REST-backed) for display-name resolution.
- `buildPolicyGroups` — transforms raw guardrail rules into grouped data for rendering.

## Usage Example

```typescript
import { CustomerGuardrailsTab } from '@/app/(app)/settings/ai-settings/components/guardrails/customer-guardrails-tab';

export function CustomerDetailsPage({ organizationId }: { organizationId: string }) {
  return (
    <div>
      {/* Other tabs... */}
      <CustomerGuardrailsTab organizationId={organizationId} />
    </div>
  );
}
```

This component is read-only — editing tenant-wide defaults happens via the "Edit Default Guardrails" button, which navigates to `routes.settings.aiSettings({ tab: 'guardrails', edit: true })`. Per-customer override editing is not yet implemented but can be built on top of the existing `updateOrganizationGuardrails` / `resetOrganizationGuardrails` mutations.
