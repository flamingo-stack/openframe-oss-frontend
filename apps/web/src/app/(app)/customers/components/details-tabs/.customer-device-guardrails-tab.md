## CustomerDeviceGuardrailsTab

A read-only React client component that renders the "Customer Device Guardrails" tab on the customer details page, displaying the organization's effective remote access permission mode.

This component shows whether a customer organization inherits the tenant's default remote access policy or has its own custom mode configured. When inheriting defaults, it displays an informational banner with a link to edit tenant-wide default guardrails. The underlying permission value is always shown via a `PolicyValueCard`, muted when inherited from defaults.

## Key Components

- **`CustomerDeviceGuardrailsTab`** — Main exported component, accepts `organizationId` prop.
- **`CustomerDeviceGuardrailsTabProps`** — Props interface requiring `organizationId: string`.
- Uses `useOrganizationRemoteAccessPolicy` hook to fetch the org's policy data (`mode`, `effectiveMode`).
- Uses `useLoadingScope` combined with the query's `isPending` state to drive a unified loading experience via `LoadingWhen`.
- Renders `LoadError` with a retry action if the fetch fails.
- Renders a `PolicyValueCard` to display the effective mode label (derived from `REMOTE_ACCESS_MODE_META`).
- Conditionally renders an "Using Default Settings" banner with an `Edit Default Guardrails` button that navigates to `routes.settings.aiSettings({ tab: 'device-guardrails', edit: true })`.

## Usage Example

```typescript
import { CustomerDeviceGuardrailsTab } from '@/app/components/customer-device-guardrails-tab';

export function CustomerDetailsPage({ organizationId }: { organizationId: string }) {
  return (
    <div>
      {/* Other tabs... */}
      <CustomerDeviceGuardrailsTab organizationId={organizationId} />
    </div>
  );
}
```

**Behavior notes:**
- If `data.mode` is `null`, the organization inherits the tenant default — the banner is shown and the value card is muted.
- Otherwise, the organization's own configured mode is displayed (not muted), and the banner is hidden.
- A per-customer edit flow (as opposed to editing tenant defaults) is not yet implemented; it is expected to build on `setOrganizationMode` once backend support is available.
