## Customer AI Configuration

React component implementing the "Customer AI Configuration" tab on the customer edit page, allowing a customer organization's AI assistant settings (name, avatar, accent color, provider/model, answer style, quick actions) to either inherit from the tenant-wide default or use a per-organization override. It exposes an imperative handle so the parent page's "Save Customer" action can validate and persist both backend overrides (`ClientView` and `OrganizationClientAiConfig`) in a single, coordinated commit.

## Key Components

- **`CustomerAiConfiguration`** — Forward-ref component (wrapped with `forwardRef`) rendering the configuration tab UI, including a "use default" toggle, assistant appearance fields, provider/model and answer-style fields, quick actions editor, and live previews.
- **`CustomerAiConfigurationHandle`** — Imperative API interface exposing:
  - `validate()` — Validates custom fields; resolves `false` if correction is needed before saving.
  - `commit()` — Persists changes: updates both overrides when customized, or resets both when inheriting defaults.
- **`CustomerAiConfigurationProps`** — Props interface requiring `organizationId` to scope data fetching and mutations.

## Usage Example

```typescript
import { useRef } from 'react';
import {
  CustomerAiConfiguration,
  type CustomerAiConfigurationHandle,
} from './customer-ai-configuration';

function CustomerEditPage({ organizationId }: { organizationId: string }) {
  const aiConfigRef = useRef<CustomerAiConfigurationHandle>(null);

  const handleSaveCustomer = async () => {
    const isValid = await aiConfigRef.current?.validate();
    if (!isValid) return;

    await aiConfigRef.current?.commit();
    // continue saving other customer tabs...
  };

  return (
    <>
      <CustomerAiConfiguration ref={aiConfigRef} organizationId={organizationId} />
      <button onClick={handleSaveCustomer}>Save Customer</button>
    </>
  );
}
```

The component manages its own data fetching (`useClientView`, `useOrganizationClientAiConfig`) and mutation state internally; the parent only needs to call `validate()` and `commit()` through the ref during its own save flow.
