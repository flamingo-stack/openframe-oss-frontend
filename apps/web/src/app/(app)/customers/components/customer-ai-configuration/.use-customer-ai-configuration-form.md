Manages form state for the per-customer AI configuration panel, combining appearance settings (assistant name, theme, avatar) with AI logic settings (LLM provider, model, answer style, quick actions) into a single `react-hook-form` instance validated by Zod.

## Key Components

- **`useCustomerAiConfigurationForm(options)`** — Primary hook returning form controls and avatar handlers
- **`getCustomerAiConfigurationDefaults(view, config)`** — Derives initial form values from the effective `ClientView` appearance and `OrganizationClientAiConfig`, falling back to tenant/base defaults
- **`commitAvatar(clientViewId)`** — Async function that flushes a pending avatar upload or deletion to the `/api/client-agent-settings/:id/image` endpoint; throws on failure

## Usage Example

```typescript
const {
  form,
  avatarUrl,
  handleAvatarChange,
  handleAvatarRemove,
  commitAvatar,
} = useCustomerAiConfigurationForm({ view, config });
```

## Notes

- **Sync guard** — A `syncKey` derived from `view.id`, `view.updatedAt`, `config.inheritDefault`, and `config.updatedAt` prevents redundant resets when parent data re-renders without meaningful changes
- **Avatar lifecycle** — Object URLs created for local previews are always revoked via `clearPreview()` on re-sync, removal, or component unmount to prevent memory leaks
- **Quick actions defaults** — When `quickActionsIsDefault` is `true`, the `quickActions` array is intentionally left empty; the editor seeds rows only when the user opts out of defaults, mirroring `getAiLogicDefaults` behavior
