# use-customer-ai-configuration-form.ts

Custom React hook that manages form state for per-customer AI assistant configuration, including appearance settings, AI logic, quick actions, and avatar upload/removal handling. It reuses the global CLIENT AI assistant schema but defers avatar operations to a separate commit step since the avatar must target the specific customer's `ClientView` ID rather than the tenant default view used during editing.

## Key Components

- **`useCustomerAiConfigurationForm(options)`** — Main hook accepting `view` (effective appearance) and `config` (effective per-org AI config). Returns the form instance, avatar URL state, and avatar management handlers.
- **`getCustomerAiConfigurationDefaults(view, config)`** — Builds form default values by merging the client view's appearance with the organization's AI config, falling back to `CLIENT` defaults when inheriting.
- **`handleAvatarChange(file)`** — Stages a new avatar file locally, generating an object URL preview without uploading immediately.
- **`handleAvatarRemove()`** — Stages avatar removal locally; flags backend deletion only if a persisted avatar exists.
- **`commitAvatar(clientViewId)`** — Flushes the pending avatar upload or deletion to the backend for the given customer's `ClientView` ID. Throws on failure, so callers should handle errors during save.

## Usage Example

```typescript
import { useCustomerAiConfigurationForm } from './use-customer-ai-configuration-form';

function CustomerAiSettingsPanel({ clientViewId, view, config }: Props) {
  const { form, avatarUrl, handleAvatarChange, handleAvatarRemove, commitAvatar } =
    useCustomerAiConfigurationForm({ view, config });

  const onSubmit = form.handleSubmit(async (values) => {
    await saveCustomerAiConfig(clientViewId, values);
    await commitAvatar(clientViewId);
  });

  return (
    <form onSubmit={onSubmit}>
      <AvatarUploader
        src={avatarUrl}
        onChange={handleAvatarChange}
        onRemove={handleAvatarRemove}
      />
      {/* other form fields bound via form.register / form.control */}
    </form>
  );
}
```

The hook automatically re-syncs form values and avatar state whenever the underlying `view` or `config` records change (tracked via a composite `syncKey` of IDs and update timestamps), discarding any unsaved local edits.
