# use-customer-ai-configuration-form.ts

A React hook that manages form state for per-customer AI assistant configuration (appearance, AI logic, quick actions) within the client AI settings module, including deferred avatar upload/removal handling scoped to the customer's own `ClientView`.

## Key Components

- **`UseCustomerAiConfigurationFormOptions`** – Input interface requiring `view` (effective appearance, possibly inherited from org) and `config` (effective per-org AI config, possibly inherited from tenant defaults).
- **`getCustomerAiConfigurationDefaults(view, config)`** – Builds form default values, falling back to the global `CLIENT` agent defaults. Keeps `quickActions` rows empty while `quickActionsIsDefault` is true, mirroring the tenant-level AI logic defaults pattern.
- **`useCustomerAiConfigurationForm({ view, config })`** – Main hook. Returns:
  - `form` – `react-hook-form` instance validated via `customerAiAssistantSchema` (Zod).
  - `avatarUrl` – Current avatar URL (persisted, preview, or `undefined` if pending removal).
  - `handleAvatarChange(file)` – Stages a new avatar file and generates a local object-URL preview.
  - `handleAvatarRemove()` – Stages avatar removal (only triggers backend delete if a persisted avatar exists).
  - `commitAvatar(clientViewId)` – Async function to flush pending avatar upload/removal to the backend for a specific customer's `ClientView` id; throws on failure.

The hook also auto-resyncs form state and avatar when the underlying `view`/`config` records change (tracked via a composite `syncKey`), and cleans up object URLs on unmount to avoid memory leaks.

## Usage Example

```typescript
import { useCustomerAiConfigurationForm } from './use-customer-ai-configuration-form';

function CustomerAiSettingsPanel({ view, config, clientViewId }) {
  const { form, avatarUrl, handleAvatarChange, handleAvatarRemove, commitAvatar } =
    useCustomerAiConfigurationForm({ view, config });

  const onSubmit = form.handleSubmit(async (values) => {
    await saveCustomerAiConfig(clientViewId, values);
    await commitAvatar(clientViewId); // flush pending avatar changes
  });

  return (
    <form onSubmit={onSubmit}>
      <AvatarUploader
        src={avatarUrl}
        onChange={handleAvatarChange}
        onRemove={handleAvatarRemove}
      />
      {/* other form fields bound via form.register / Controller */}
    </form>
  );
}
```

**Note:** Avatar changes are staged locally and only persisted when `commitAvatar` is called (typically alongside form submission), ensuring uploads target the correct customer-specific `ClientView` id rather than a borrowed tenant default.
