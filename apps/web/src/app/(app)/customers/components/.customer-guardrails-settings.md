Renders the "Customer AI Guardrails" settings tab on the customer edit page, allowing users to either inherit tenant-default guardrail policies or configure per-organization approval-level overrides via an imperative `commit()` ref handle driven by the parent "Save Customer" form.

## Key Components

| Export | Type | Description |
|---|---|---|
| `CustomerGuardrailsSettings` | `forwardRef` component | Main settings panel with toggle, template picker, and policy group editor |
| `CustomerGuardrailsHandle` | Interface | Imperative handle exposing `commit(): Promise<void>` for parent-driven persistence |
| `CustomerGuardrailsSettingsProps` | Interface | Accepts `organizationId: string` |
| `OrgGuardrailsSelection` | Type | Discriminated union: `{ kind: 'template' }` or `{ kind: 'custom', baseTemplateId, edits }` |

**Internal behavior:**
- **Toggle ON** — org inherits tenant defaults; an existing org policy is reset only after user confirms via `ConfirmDialog`
- **Toggle OFF** — user picks a stock preset as-is (`kind: 'template'`) or customizes per-policy approval levels on top of one (`kind: 'custom'`)
- `isDirty` guards against unnecessary API calls in `commit()`
- Seeding from server state happens once via `seededRef` after both queries resolve

## Usage Example

```typescript
import { useRef } from 'react';
import { CustomerGuardrailsSettings, type CustomerGuardrailsHandle } from './customer-guardrails-settings';

function EditCustomerPage({ organizationId }: { organizationId: string }) {
  const guardrailsRef = useRef<CustomerGuardrailsHandle>(null);

  const handleSave = async () => {
    // Commits guardrail changes as part of the broader "Save Customer" flow
    await guardrailsRef.current?.commit();
  };

  return (
    <>
      <CustomerGuardrailsSettings ref={guardrailsRef} organizationId={organizationId} />
      <button onClick={handleSave}>Save Customer</button>
    </>
  );
}
```
