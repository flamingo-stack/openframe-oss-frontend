# new-customer-page.tsx

Page component for creating or editing a customer organization. Renders a single form (Details) or a tabbed interface (Details / AI Configuration / Guardrails / Device Guardrails) depending on app mode and feature gates, delegating form state to `useCustomerForm` and logo handling to `useCustomerLogo`.

## Key Components

- **`NewCustomerPage`** — main exported component, accepts `organizationId` (nullable; `null` means create mode, a string means edit mode).
- **Tab visibility logic** — `showAiConfig` and `showGuardrails` are SaaS-tenant and edit-mode only (require `runtimeEnv.appMode() === 'saas-tenant'` and an existing `organizationId`); `showDeviceGuardrails` depends on `useRemoteAccessApprovalGate()` returning `'on'` (available in both SaaS and OSS since it's backed by MeshCentral).
- **URL-controlled tabs** — active tab is derived from the `?tab=` search param (`activeTab`), with `handleTabChange` updating the URL via `router.replace` (no scroll jump). Unknown/hidden tab ids fall back to `DETAILS_TAB`.
- **Invalid-submit recovery** — `handleInvalid` switches back to the Details tab and, via `pendingScrollRef` + `useLayoutEffect`, scrolls to the first invalid field once that tab's panel is visible again.
- **Persistent panel mounting** — all tab panels stay mounted simultaneously (toggled with the `hidden` CSS class, not conditional rendering), so form state and imperative refs (`refs.aiConfigurationRef`, `refs.guardrailsRef`, `refs.deviceGuardrailsRef`) survive tab switches and are saved together by a single "Save Customer" action.
- **`recordPending`** — gates form editability until an existing customer's data has loaded (edit mode only; not applicable when creating).

## Usage Example

```typescript
import { NewCustomerPage } from './new-customer-page';

// Create mode
<NewCustomerPage organizationId={null} />

// Edit mode — remount per customer to reset internal seed state
<NewCustomerPage key={organizationId} organizationId={organizationId} />
```

**Important:** Always mount with `key={organizationId}`. The underlying form hook seeds its state once per mount, so changing the `?id=` query param in place (without remounting) would retain the previous customer's edits instead of loading the new one.
