A client-side React component that renders a confirmation modal for archiving a customer, conditionally displaying either a blocking "Archive Unavailable" notice (when active devices exist) or a confirmation dialog to proceed with archiving.

## Key Components

- **`ArchiveCustomerModal`** — Main exported component that renders one of two UI states based on `canArchive`:
  - **Blocked state**: Shows an `AlertDialog` informing the user that the customer cannot be archived because it still has active devices, with a single "Close" action.
  - **Confirm state**: Renders the shared `ConfirmDialog` component with a destructive-styled confirmation flow for archiving the customer.
- **`ArchiveCustomerModalProps`** — Props interface controlling dialog visibility, archive eligibility, confirmation callback, and pending/loading state.

## Usage Example

```typescript
import { useState } from 'react';
import { ArchiveCustomerModal } from '@/app/components/customers/archive-customer-modal';

function CustomerActions({ customer }: { customer: { hasActiveDevices: boolean } }) {
  const [open, setOpen] = useState(false);
  const [isPending, setIsPending] = useState(false);

  const handleArchive = async () => {
    setIsPending(true);
    await archiveCustomer(customer);
    setIsPending(false);
    setOpen(false);
  };

  return (
    <>
      <button onClick={() => setOpen(true)}>Archive Customer</button>
      <ArchiveCustomerModal
        open={open}
        onOpenChange={setOpen}
        canArchive={!customer.hasActiveDevices}
        onConfirm={handleArchive}
        isPending={isPending}
      />
    </>
  );
}
```

## Notes

- Depends on shared UI primitives from `@flamingo-stack/openframe-frontend-core` and the local `ConfirmDialog` component (`@/app/components/shared/confirm-dialog`).
- The `isPending` prop is only relevant to the confirm flow and is ignored in the "Archive Unavailable" state.
