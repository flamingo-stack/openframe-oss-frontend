# archive-customer-modal.tsx

A React client component that renders a confirmation modal for archiving a customer, displaying either a blocking "unavailable" dialog (when the customer has active devices) or a destructive confirmation dialog (when archiving is permitted).

## Key Components

- **`ArchiveCustomerModalProps`** — Interface defining the component's props: `open`, `onOpenChange`, `canArchive`, `onConfirm`, and optional `isPending`.
- **`ArchiveCustomerModal`** — The main component. Conditionally renders:
  - An `AlertDialog` with an "Archive Unavailable" message and a single "Close" action when `canArchive` is `false` (customer still has active devices).
  - A `ConfirmDialog` (shared component) with destructive styling, confirm/cancel/pending labels, and an `onConfirm` callback when `canArchive` is `true`.

## Usage Example

```typescript
import { useState } from 'react';
import { ArchiveCustomerModal } from '@/app/components/customers/archive-customer-modal';

function CustomerActions({ customer }: { customer: { id: string; hasActiveDevices: boolean } }) {
  const [open, setOpen] = useState(false);
  const [isPending, setIsPending] = useState(false);

  const handleArchive = async () => {
    setIsPending(true);
    await archiveCustomer(customer.id);
    setIsPending(false);
    setOpen(false);
  };

  return (
    <>
      <button onClick={() => setOpen(true)}>Archive</button>
      <ArchiveCustomerModal
        open={open}
        onOpenChange={setOpen}
        canArchive={!customer.hasActiveDevices}
        onConfirm={handleArchive}
        isPending={isPending}
      />
    </>
  );
}
```

## Notes

- Relies on `AlertDialog` primitives from `@flamingo-stack/openframe-frontend-core` and a shared `ConfirmDialog` component (`@/app/components/shared/confirm-dialog`) for the actionable confirmation flow.
- The `canArchive` flag drives a branching UI: blocking message vs. destructive confirmation, keeping archive-eligibility logic external to this component.
