# page.tsx

Client-side page component that renders the Organizations (Customers) view with tab-based navigation, managing active tab state and search query synchronization via URL-driven API params.

## Key Components

- **`Organizations`** (default export) — The main page component rendering tab navigation and the active tab's content.
- **`useApiParams`** — Hook (from `@flamingo-stack/openframe-frontend-core/hooks`) that syncs `tab` and `search` state with URL query parameters, providing `params` and `setParams`.
- **`getTabComponent`** — Utility that resolves the component to render based on the currently active tab key.
- **`CUSTOMERS_TABS`** / **`CustomersTabNavigation`** — Tab configuration and navigation UI imported from the local `customers-tabs` component module.

## Usage Example

```typescript
// Rendered automatically by the Next.js App Router for this route segment.
// Internally, tab switches reset the search query:

const { params, setParams } = useApiParams({
  tab: { type: 'string', default: 'active' },
  search: { type: 'string', default: '' },
});

// Switching tabs clears the search field so each tab starts fresh:
setParams({ tab: 'archived', search: '' });
```

## Notes

- `search` state is declared here (not in the child `CustomersTable` component) so it can be reset to an empty string whenever the user switches tabs, ensuring each tab starts with a clean search context.
- `tab` defaults to `'active'` if no value is present in the URL params.
- If `getTabComponent` returns `undefined` or `null` for an unknown tab key, nothing is rendered below the tab navigation.
