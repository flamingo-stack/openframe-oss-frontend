Client-side Next.js page component that renders the Organizations (Customers) view with tab-based navigation, synchronizing the active tab and search state with URL query parameters.

## Key Components

- **`Organizations`** — Default export; the page component rendering the Customers tab navigation and the active tab's content.
- **`useApiParams`** — Hook (from `@flamingo-stack/openframe-frontend-core/hooks`) that binds `tab` and `search` state to URL query parameters, providing `params` and `setParams`.
- **`getTabComponent`** — Utility that resolves the component to render based on the currently active tab key.
- **`CUSTOMERS_TABS`** / **`CustomersTabNavigation`** — Local tab configuration and navigation UI imported from `./components/customers-tabs`.

## Usage Example

```typescript
// This is a Next.js page file; it's automatically routed based on its
// location in the app directory and requires no manual instantiation.

// Tab configuration shape expected by getTabComponent, e.g.:
const CUSTOMERS_TABS = {
  active: { label: 'Active', component: ActiveCustomersTable },
  archived: { label: 'Archived', component: ArchivedCustomersTable },
};
```

Key behavior:
- `tab` defaults to `'active'` and is persisted in the URL.
- `search` defaults to `''` and is reset to an empty string whenever the tab changes, ensuring each tab starts with a fresh search context (search state itself is owned/consumed by the child `CustomersTable` component).
- If no component matches the active tab key, nothing is rendered below the tab navigation.

## Notes

- Marked `'use client'` since it relies on client-side hooks (`useApiParams`) for URL state management.
- Part of the Organizations/Customers feature area; actual tab content components live under `./components/customers-tabs`.
