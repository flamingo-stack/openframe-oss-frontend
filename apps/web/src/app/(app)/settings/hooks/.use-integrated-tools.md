React hook that fetches the list of integrated tools from the OpenFrame GraphQL API, exposing their metadata (URLs, credentials, layer info, health check config) with built-in loading/error state management and toast notifications on failure.

## Key Components

- **`GET_INTEGRATED_TOOLS_QUERY`** – GraphQL query string requesting `integratedTools` with filter/search variables, returning each tool's full metadata (URLs, credentials, layer, health check settings, etc.).
- **`ToolUrl`, `ApiKey`, `Credentials`, `IntegratedTool`** – TypeScript types describing the shape of a tool and its nested data returned by the API.
- **`GraphQlResponse<T>` / `IntegratedToolsResponse`** – Internal types modeling the generic GraphQL response envelope and the specific `integratedTools` payload.
- **`useIntegratedTools()`** – The main hook. Returns:
  - `tools: IntegratedTool[]` – current list of fetched tools.
  - `isLoading: boolean` – `true` initially and during fetch requests.
  - `error: string | null` – last error message, if any.
  - `fetchIntegratedTools(filter?, search?)` – async callback that queries the API, updates state, and shows a destructive toast on failure.

## Usage Example

```typescript
import { useEffect } from 'react';
import { useIntegratedTools } from '@/hooks/use-integrated-tools';

function ArchitectureView() {
  const { tools, isLoading, error, fetchIntegratedTools } = useIntegratedTools();

  useEffect(() => {
    fetchIntegratedTools({ enabled: true, category: null }, '').catch(() => {
      // Error already surfaced via toast and `error` state
    });
  }, [fetchIntegratedTools]);

  if (isLoading) return <p>Loading tools...</p>;
  if (error) return <p>Error: {error}</p>;

  return (
    <ul>
      {tools.map((tool) => (
        <li key={tool.id}>{tool.name}</li>
      ))}
    </ul>
  );
}
```

**Notes:**
- `isLoading` starts as `true` so the initial render (before the fetch completes) doesn't flash an empty "no tools" state.
- Calls go through the shared `apiClient` to `/api/graphql`; GraphQL-level errors in the response's `errors` array are surfaced the same way as HTTP failures.
