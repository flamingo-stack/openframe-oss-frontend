React hook providing CRUD operations for managing SSO (Single Sign-On) provider configurations via the OpenFrame API client.

## Key Components

- **`AvailableProvider`** - Type describing an SSO provider option (`provider` key, `displayName` label).
- **`ProviderConfig`** - Type describing a configured SSO provider's settings (client ID/secret, tenant ID, enabled state, provisioning options).
- **`UpdateSsoPayload`** - Type for the payload sent when creating/updating a provider configuration.
- **`useSsoConfig()`** - Hook returning the following memoized async functions:
  - `fetchAvailableProviders()` - Lists all SSO providers that can be configured.
  - `fetchProviderConfig(provider)` - Fetches a specific provider's config. Returns `undefined` only on a `404` (not configured); other failures (5xx, network errors) throw, preventing the UI from mistakenly treating an unknown state as "not configured" and overwriting a working configuration.
  - `updateProviderConfig(provider, payload)` - Creates or updates a provider's configuration.
  - `toggleProviderEnabled(provider, enabled)` - Enables/disables a provider.
  - `deleteProviderConfig(provider)` - Removes a provider's configuration.

## Usage Example

```typescript
import { useSsoConfig } from '@/hooks/use-sso-config';

function SsoSettingsPanel() {
  const {
    fetchAvailableProviders,
    fetchProviderConfig,
    updateProviderConfig,
    toggleProviderEnabled,
    deleteProviderConfig,
  } = useSsoConfig();

  async function loadConfig() {
    const providers = await fetchAvailableProviders();
    const config = await fetchProviderConfig('google');

    if (config === undefined) {
      console.log('Google SSO is not yet configured');
    }
  }

  async function saveConfig() {
    await updateProviderConfig('google', {
      clientId: 'client-id',
      clientSecret: 'client-secret',
      autoProvisionUsers: true,
      allowedDomains: ['example.com'],
    });
  }

  async function disableProvider() {
    await toggleProviderEnabled('google', false);
  }

  return null; // render UI using the above handlers
}
```

**Note:** All methods throw an `Error` with a descriptive message on failure (except the documented `404` case for `fetchProviderConfig`), so callers should wrap invocations in `try/catch` blocks.
