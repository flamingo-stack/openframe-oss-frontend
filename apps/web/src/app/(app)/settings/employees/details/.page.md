Renders the employee details page within the settings section, resolving the required `userId` route parameter before delegating rendering to the `EmployeeDetailsView` component.

## Key Components

- **`EmployeeDetailsPage`** — Default-exported Next.js client page component that extracts the `userId` param and conditionally renders `EmployeeDetailsView`.
- **`useRequiredIdParam`** — Hook used to retrieve and validate the required `id` route parameter, redirecting to `routes.settings.employees` if missing or invalid.
- **`EmployeeDetailsView`** — Child component responsible for displaying the actual employee details once a valid `userId` is resolved.

## Usage Example

```typescript
// Accessed via dynamic route, e.g. /settings/employees/[id]
// Next.js automatically renders this page when navigating to:
// /settings/employees/123

export default function EmployeeDetailsPage() {
  const userId = useRequiredIdParam(routes.settings.employees);
  if (!userId) return null; // Redirects or renders nothing if id is invalid
  return <EmployeeDetailsView userId={userId} />;
}
```

This page acts as a thin wrapper: it guards against missing/invalid `id` params using `useRequiredIdParam`, falling back to the employees list route (`routes.settings.employees`) when necessary, and otherwise passes the validated `userId` down to `EmployeeDetailsView` for rendering the employee's detailed information within the app's settings module.
