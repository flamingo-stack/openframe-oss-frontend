# ai-settings.ts

Defines the TypeScript view-model types for the AI settings feature, mirroring the two-collection backend schema (`ai-settings.graphqls`): `AgentAiConfig` for per-agent AI logic (CLIENT/ADMIN) and `ClientView` for the client assistant's appearance. Also provides default-value factories used when no backend record exists yet.

## Key Components

- **`AgentType`** — Distinguishes which assistant a config applies to: `'CLIENT'` (customer-facing Fae) or `'ADMIN'` (Mingo).
- **`AiImage`** — Shape for an uploaded image (avatar) with optional id/hash.
- **`AiQuickAction` / `AiQuickActionInput`** — Quick-action chat chips with optional icon metadata; the input variant is the editable subset sent to mutations.
- **`AgentAiConfig` / `AgentAiConfigInput`** — Tenant-wide AI logic (provider, model, answer style, custom prompt, quick actions) for an agent, and its mutation input.
- **`ClientView` / `ClientViewInput`** — Client assistant appearance (name, avatar, accent color), supporting a tenant-wide default (`organizationId === null`) or a per-organization override.
- **`ApplicationTheme`**, **`AnswerStyle`** — Supporting enum-like string unions.
- **`getDefaultAgentAiConfig(agentType)`** — Returns a fallback `AgentAiConfig` with an empty `id` (signals "not yet persisted").
- **`getDefaultClientView(organizationId?)`** — Returns a fallback `ClientView` with sensible defaults (name `'AI'`, accent color `#F357BB`).

## Usage Example

```typescript
import {
  getDefaultAgentAiConfig,
  getDefaultClientView,
  type AgentAiConfig,
  type ClientViewInput,
} from '@/types/ai-settings';

// Seed UI state before the backend query resolves
const adminConfig: AgentAiConfig = getDefaultAgentAiConfig('ADMIN');
const orgView = getDefaultClientView('org-123');

// Building a mutation input for saving appearance changes
const update: ClientViewInput = {
  assistantName: 'Fae',
  accentColor: '#4A90D9',
};
```
