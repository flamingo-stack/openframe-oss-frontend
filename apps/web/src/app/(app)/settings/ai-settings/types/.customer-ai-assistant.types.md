Defines the Zod validation schema, types, and transformation utilities for the Customer AI Assistant settings form, which manages both appearance (client view) and AI logic configuration.

## Key Components

| Export | Type | Description |
|--------|------|-------------|
| `CUSTOMER_AI_ASSISTANT_FORM_ID` | `string` | Stable HTML form ID for the customer AI assistant settings form |
| `customerAiAssistantSchema` | `ZodObject` | Zod schema validating assistant name, theme, accent color hex, and AI logic fields |
| `CustomerAiAssistantFormValues` | `type` | Inferred TypeScript type from `customerAiAssistantSchema` |
| `CustomerAiAssistantSubmit` | `interface` | Dual-payload shape (`ai` + `view`) produced on form submission |
| `getCustomerAiAssistantDefaults` | `function` | Populates form defaults from existing `AgentAiConfig` and `ClientView` backend data |
| `toCustomerAiAssistantSubmit` | `function` | Transforms validated form values into the two backend mutation payloads |

## Usage Example

```typescript
import {
  customerAiAssistantSchema,
  getCustomerAiAssistantDefaults,
  toCustomerAiAssistantSubmit,
} from './customer-ai-assistant.types';

// Populate form with existing data
const defaults = getCustomerAiAssistantDefaults(agentAiConfig, clientView);

// Validate on submit
const result = customerAiAssistantSchema.safeParse(formValues);

if (result.success) {
  // Split into two separate backend mutation payloads
  const { ai, view } = toCustomerAiAssistantSubmit(result.data);

  await updateAgentAiConfig(ai);
  await updateClientView(view);
}
```

> **Note:** The schema enforces a valid 3- or 6-digit hex accent color (e.g. `#F357BB`) and delegates AI logic validation — including the conditional `customPrompt` requirement — to the shared `aiLogicShape` and `requireCustomPrompt` utilities from [`ai-logic.types`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/src/types/ai-logic.types.ts).
