# customer-ai-assistant.types.ts

Defines the Zod schema, form types, and transform helpers for the CLIENT-facing "Customer AI Assistant" settings form, which manages both the client view's appearance (assistant name, accent color) and the CLIENT-scoped AI logic configuration (prompts, quick actions).

## Key Components

- **`CUSTOMER_AI_ASSISTANT_FORM_ID`** - Constant string identifier for the form, used for DOM/form targeting.
- **`customerAiAssistantSchema`** - Zod object schema combining `assistantName`, `accentColor` (hex color validation), and the shared `aiLogicShape` fields. Enforces `requireCustomPrompt` via `.refine()`.
- **`CustomerAiAssistantFormValues`** - Inferred TypeScript type from the schema, representing the form's validated shape.
- **`CustomerAiAssistantSubmit`** - Interface describing the two backend payloads produced on save: `ai` (`AgentAiConfigInput`) and `view` (`ClientViewInput`), since they are persisted via separate mutations.
- **`getCustomerAiAssistantDefaults(aiConfig, view)`** - Builds initial form values by merging `ClientView` appearance fields with AI logic defaults derived from `AgentAiConfig`.
- **`toCustomerAiAssistantSubmit(values)`** - Converts validated form values into the two separate submit payloads (`ai` and `view`) expected by the backend mutations.

## Usage Example

```typescript
import {
  customerAiAssistantSchema,
  getCustomerAiAssistantDefaults,
  toCustomerAiAssistantSubmit,
  type CustomerAiAssistantFormValues,
} from './customer-ai-assistant.types';

// Initialize form defaults from existing data
const defaultValues = getCustomerAiAssistantDefaults(agentAiConfig, clientView);

// Validate form input
const result = customerAiAssistantSchema.safeParse(formValues);

if (result.success) {
  // Split into separate backend payloads
  const { ai, view } = toCustomerAiAssistantSubmit(result.data);
  await updateAgentAiConfig(ai);
  await updateClientView(view);
}
```
