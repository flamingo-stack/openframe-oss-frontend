Manages form state for the Customer AI Assistant configuration screen, handling both the react-hook-form lifecycle and a two-phase avatar upload pattern where image changes are staged locally and flushed only after a successful save.

## Key Components

### `useCustomerAiAssistantForm(options)`
Primary hook accepting `aiConfig`, `view`, and `onSubmit`, returning form controls and avatar state.

### `CommitAvatar`
Exported type for the deferred avatar flush function `(clientViewId: string) => Promise<void>` — called by the parent after the GraphQL save resolves with a confirmed `clientViewId`, preventing uploads against an empty ID on first-time tenant saves.

### Internal Refs
- `pendingFileRef` — staged `File` awaiting upload
- `pendingRemovalRef` — flags a pending backend delete when an existing avatar is removed
- `previewUrlRef` — tracks the object URL blob for cleanup via `URL.revokeObjectURL`

### Sync Effect
Detects upstream record changes via a composite `syncKey` (`aiConfig.id + updatedAt + view.id + updatedAt`) and resets form defaults and avatar state, preventing stale data after post-save refetches.

## Usage Example

```typescript
const {
  form,
  avatarUrl,
  handleAvatarChange,
  handleAvatarRemove,
  handleSubmit,
} = useCustomerAiAssistantForm({
  aiConfig,
  view,
  onSubmit: async (payload, commitAvatar) => {
    const savedView = await saveAiConfig(payload);
    // Flush staged avatar upload after confirmed save
    await commitAvatar(savedView.id);
  },
});

// In JSX
<AvatarUpload
  src={avatarUrl}
  onChange={handleAvatarChange}
  onRemove={handleAvatarRemove}
/>
<form onSubmit={handleSubmit}>...</form>
```
