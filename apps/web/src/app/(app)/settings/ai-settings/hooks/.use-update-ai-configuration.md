# use-update-ai-configuration.ts

A React hook that synchronizes the chat backend's active AI provider/model configuration whenever the admin AI settings change, using a GraphQL mutation over the REST API client.

## Key Components

- **`useUpdateAiConfiguration()`** — Custom hook returning:
  - `updateAiConfiguration` — mutate function accepting `{ provider, modelName }` to trigger the sync.
  - `isPending` — boolean indicating mutation in-flight status.
- **`UpdateAiConfigurationInput`** — Input type with `provider: AIProvider` and `modelName: string`.
- **`SAVE_TENANT_AI_MODEL_CONFIG_MUTATION`** — GraphQL mutation string sent to `/chat/graphql` to persist the tenant's AI model configuration.

## Behavior Notes

- Uses `@tanstack/react-query`'s `useMutation` to POST to `apiClient` at `/chat/graphql`.
- Relies on `throwOnErrors` (from `chat-graphql`) to surface GraphQL `userErrors` as thrown errors.
- **No success toast is shown** — success feedback is owned by the caller (the settings save flow). This hook only surfaces failures via a destructive toast from `@flamingo-stack/openframe-frontend-core/hooks`.
- **No cache invalidation** is performed, since dependent UI (model badges) reads from `adminAiConfig` / `organizationClientAiConfig`, which are invalidated elsewhere by the settings mutations.

## Usage Example

```typescript
import { useUpdateAiConfiguration } from './use-update-ai-configuration';

function AiProviderSettings() {
  const { updateAiConfiguration, isPending } = useUpdateAiConfiguration();

  const handleSave = () => {
    updateAiConfiguration({
      provider: 'openai',
      modelName: 'gpt-4o',
    });
  };

  return (
    <button onClick={handleSave} disabled={isPending}>
      {isPending ? 'Syncing...' : 'Apply AI Configuration'}
    </button>
  );
}
```

Typically called **after** the main AI settings save succeeds, so the chat backend stays in sync with the selected provider/model without duplicating success notifications.
