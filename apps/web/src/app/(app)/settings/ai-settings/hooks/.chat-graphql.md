Shared response envelope and error-handling utilities for raw POST requests against the AI agent's `/chat/graphql` endpoint.

## Key Components

| Export | Type | Description |
|---|---|---|
| `GraphqlResponse<T>` | Interface | Generic response envelope wrapping `data` and optional `errors` array |
| `MutationPayloadGql` | Interface | Standard mutation payload shape containing a `userErrors` array |
| `throwOnErrors` | Function | Validates a GraphQL response and throws on any failure condition |

## `throwOnErrors` Error Cascade

The function checks three distinct failure layers in order:

1. **Transport failure** — `response.ok` is false or `response.data` is missing → throws `response.error` or `fallbackMessage`
2. **GraphQL errors** — `response.data.errors` is non-empty → throws joined error messages
3. **User errors** — First root field's `userErrors` array is non-empty → throws joined user error messages

## Usage Example

```typescript
import { throwOnErrors, GraphqlResponse, MutationPayloadGql } from './chat-graphql';

interface CreateTicketPayload extends MutationPayloadGql {
  ticket: { id: string };
}

const response = await fetch('/chat/graphql', { method: 'POST', body: JSON.stringify({ query }) });
const json: GraphqlResponse<{ createTicket: CreateTicketPayload }> = await response.json();

throwOnErrors(
  { ok: response.ok, data: json },
  'Failed to create ticket',
);
// Safe to access json.data.createTicket.ticket.id here
```

## Notes

- `throwOnErrors` inspects only the **first root field** of the mutation response via `Object.values(data)[0]` — ensure mutations return a single root field or the correct payload may be skipped.
