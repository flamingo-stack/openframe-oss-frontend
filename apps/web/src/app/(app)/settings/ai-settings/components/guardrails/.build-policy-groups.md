Transforms flat `PolicyRule` arrays into a nested `Map<policyGroup → PermissionCategory[]>` structure suitable for rendering in the core-lib `PolicyConfigurationPanel`.

## Key Components

- **`buildPolicyGroups(rules)`** — Main export. Iterates over flat policy rules, buckets them by `policyGroup` (defaulting to `"General"`) then by `category` (defaulting to `"Other"`), and maps each rule to a `PermissionCategory` policy entry. Categories within each group are sorted alphabetically by name.
- **`slugify(value)`** — Internal helper. Converts arbitrary strings to URL-safe slugs used as stable `PermissionCategory` IDs.

## Usage Example

```typescript
import { buildPolicyGroups } from './build-policy-groups';
import type { PolicyRule } from './guardrails.types';

const rules: PolicyRule[] = [
  {
    naturalKey: 'restart-service',
    policyGroup: 'Infrastructure',
    category: 'Services',
    operation: 'Restart Service',
    commandPattern: 'systemctl restart *',
    tool: 'bash',
    approvalLevel: 'require_approval',
  },
];

const groups = buildPolicyGroups(rules);
// Map {
//   'Infrastructure' => [{ id: 'infrastructure:services', name: 'Services', policies: [...] }]
// }
```

## Notes

- This is a **pure data transform** — no UI or presentation state is managed here. Expansion and bulk-selection state live in the consuming `PolicyConfigurationPanel`.
- Rules without a `policyGroup` fall into `"General"`; rules without a `category` fall into `"Other"`.
- Tool names are normalized via `normalizeToolTypeWithFallback` from `@flamingo-stack/openframe-frontend-core/utils` before being stored.
