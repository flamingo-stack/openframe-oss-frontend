Utilities for managing pending edits to guardrail policy approval levels, shared between the tenant guardrails editor and per-customer settings components.

## Key Components

| Export | Description |
|---|---|
| `buildBaseLevels` | Builds a `naturalKey → ApprovalLevel` map from the server-authoritative policy rules |
| `applyEditsToRules` | Overlays a pending-edits map onto a rules array, returning updated rules (no-op if edits are empty) |
| `withPolicyEdit` | Returns a new edits map with a single policy's level changed; drops the entry if it matches the base level |
| `withCategoryEdits` | Returns a new edits map with a level bulk-applied to all policies in a `PermissionCategory`; drops entries that match base |

**Core invariant:** An edit that restores a rule to its server-side base level is always removed from the map, ensuring the edits map represents only the overrides worth persisting.

## Usage Example

```typescript
import {
  buildBaseLevels,
  applyEditsToRules,
  withPolicyEdit,
  withCategoryEdits,
} from './rule-edits';

// Build baseline from server-fetched rules
const baseLevels = buildBaseLevels(rules);
let edits = new Map();

// User changes a single policy
edits = withPolicyEdit(edits, baseLevels, 'policy.create_user', 'MANAGER');

// User bulk-sets an entire category
edits = withCategoryEdits(edits, baseLevels, networkCategory, 'ADMIN');

// Overlay edits before rendering
const displayRules = applyEditsToRules(rules, edits);
```
