React hook that generates the set of `PageActionButton` definitions for the AI Settings page header, toggling between "edit" and "save" actions based on the current edit mode.

## Key Components

- **`useAiSettingsActionsArgs`** — Input props interface controlling edit mode state, callbacks, and save-related flags (`isSaving`, `isSaveDisabled`).
- **`useAiSettingsActions`** — Memoized hook returning a `PageActionButton[]` array:
  - When not in edit mode: returns a single "Edit Settings" outline button with a pen icon that triggers `onEdit`.
  - When in edit mode: returns a single "Save Settings" accent button that triggers `onSave`, displays a loading state and "Saving..." label when `isSaving` is true, and disables itself when `isSaving` or `isSaveDisabled` is true.

The result is memoized via `useMemo` and only recomputes when `isEditMode`, `onEdit`, `onSave`, `isSaving`, or `isSaveDisabled` change, avoiding unnecessary re-renders of consuming page header components.

## Usage Example

```typescript
import { useAiSettingsActions } from './ai-settings-actions';

function AiSettingsPage() {
  const [isEditMode, setIsEditMode] = useState(false);
  const [isSaving, setIsSaving] = useState(false);

  const actions = useAiSettingsActions({
    isEditMode,
    onEdit: () => setIsEditMode(true),
    onSave: async () => {
      setIsSaving(true);
      await saveSettings();
      setIsSaving(false);
      setIsEditMode(false);
    },
    isSaving,
    isSaveDisabled: !isFormValid,
  });

  return <PageHeader title="AI Settings" actions={actions} />;
}
```

This hook is typically consumed by a page header component that renders action buttons based on the returned configuration, keeping action logic decoupled from presentation.
