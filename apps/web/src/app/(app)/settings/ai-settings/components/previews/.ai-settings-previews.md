# ai-settings-previews.tsx

Renders responsive previews of Fae's assistant window (welcome screen and chat) within AI settings, with a modal for viewing either at full scale. Adapts layout between a single mobile button and desktop thumbnail cards based on viewport width via CSS breakpoints rather than a mobile-detection hook.

## Key Components

- **`AiSettingsPreviews`** — Main exported component. Shows loading skeletons while data resolves, then renders either a mobile "Preview Assistant" button (below `content-md`) or two thumbnail previews (welcome + chat) with a shared modal for full-size viewing. Manages open/pane state separately to avoid visual glitches during the modal's exit animation, and wires up native Android back-button dismissal.
- **`MobilePreviewButton`** — Internal button shown only on small viewports; renders disabled with fixed copy while loading, enabled once an `onClick` handler is available.
- **`ThumbnailTrigger`** — Internal wrapper that overlays a clickable "Expand" affordance on top of an inert preview (using the `inert` attribute to disable interaction inside), since the real preview contains nested interactive elements that can't be wrapped in a `<button>`.
- **`AiSettingsPreviewsProps`** — Props interface: `assistantName`, `avatarUrl`, `accentColor` (all optional, treated as "loading" when `assistantName`/`accentColor` are `undefined`).

## Usage Example

```typescript
import { AiSettingsPreviews } from './ai-settings-previews';

function AiAssistantSettingsForm() {
  const { data } = useAssistantSettings();

  return (
    <section>
      {/* Name/avatar/model/accent are rendered elsewhere above this */}
      <AiSettingsPreviews
        assistantName={data?.name}
        avatarUrl={data?.avatarUrl}
        accentColor={data?.accentColor}
      />
    </section>
  );
}
```

When `assistantName` or `accentColor` is `undefined` (or `useLoadingScope()` reports an active loading scope), the component automatically renders skeleton placeholders matching the final layout.
