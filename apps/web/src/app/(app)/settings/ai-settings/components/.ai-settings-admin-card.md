Read-only summary card component for the admin-facing "Mingo" AI configuration view, displaying LLM provider, model, and answer style in a responsive grid layout with built-in loading-state support.

## Key Components

- **`AiSettingsAdminCard`** — Functional component rendering a read-only grid of AI configuration cells (provider, model, answer style) for the ADMIN tab.
- **`AiSettingsAdminCardProps`** — Props interface:
  - `aiConfig?: AgentAiConfig` — the AI configuration data; `undefined` while loading.
  - `providerModelLabel?: string` — human-readable display name for the backend `providerModel` value.
- **`GRID_CLASS`** — Tailwind class string defining the responsive grid container styling.

The component delegates cell rendering to the shared `aiConfigCells` helper (from `./ai-config-cells`), passing a fixed `providerLabel` of `"Mingo LLM Provider"` to distinguish it from the CLIENT-facing counterpart (`AiSettingsCustomerCard`), which additionally renders appearance-related fields.

Loading state is derived via `useLoadingScope()` from `@flamingo-stack/openframe-frontend-core/components/ui`, combined with a check for `aiConfig == null`, ensuring skeleton/placeholder rendering while data is unavailable.

## Usage Example

```typescript
import { AiSettingsAdminCard } from './ai-settings-admin-card';
import type { AgentAiConfig } from '../types/ai-settings';

function MingoSettingsTab({ config }: { config?: AgentAiConfig }) {
  return (
    <AiSettingsAdminCard
      aiConfig={config}
      providerModelLabel={config ? 'GPT-4 Turbo' : undefined}
    />
  );
}
```

When `aiConfig` is `undefined` or the component is within an active loading scope (via `useLoadingScope`), each cell renders with a real label and a skeleton bar in place of the value, providing a consistent loading UX without conditional branching in the parent.
