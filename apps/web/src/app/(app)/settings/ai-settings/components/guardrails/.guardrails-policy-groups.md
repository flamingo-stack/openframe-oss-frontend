# guardrails-policy-groups.tsx

Renders a template's guardrail policy groups as a stacked list of labeled `PolicyConfigurationPanel` sections, with built-in skeleton loading states for both initial load and template-switching transitions.

## Key Components

- **`GuardrailsPolicyGroups`** — Main exported component. Takes a `Map<string, PermissionCategory[]>` of policy groups and renders one `PolicyGroup` per entry. Shows `GUARDRAILS_SKELETON_GROUPS` skeleton groups while `groups` is `undefined` or inside a loading scope. When `switching` is `true`, existing content stays visible but dimmed (`opacity-60`) and marked `aria-busy` instead of flashing a skeleton.
- **`PolicyGroup`** (internal) — Renders a single group: an `h5` label (via `policyGroupLabel`, truncated) above a `PolicyConfigurationPanel`. Delegates its own skeleton rendering to the panel via `loading`/`skeletonCount` props.
- **`GuardrailsPolicyGroupsProps`** — Props interface: `groups`, `editMode`, `onPolicyPermissionChange`, `onCategoryPermissionChange`, `switching`.
- **`GUARDRAILS_SKELETON_GROUPS`** / **`GUARDRAILS_SKELETON_CATEGORIES`** — Constants controlling skeleton row/category counts, matching a typical template's shape.

## Usage Example

```typescript
import { GuardrailsPolicyGroups } from './guardrails-policy-groups';

function GuardrailsPanel({ template, isEditing, isSwitchingTemplate }) {
  return (
    <GuardrailsPolicyGroups
      groups={template?.policyGroups}
      editMode={isEditing}
      switching={isSwitchingTemplate}
      onPolicyPermissionChange={(categoryId, policyId, level) => {
        updatePolicyLevel(categoryId, policyId, level);
      }}
      onCategoryPermissionChange={(categoryId, level) => {
        updateCategoryLevel(categoryId, level);
      }}
    />
  );
}
```

When `groups` is `undefined`, the component automatically renders skeleton placeholders; pass the resolved `Map` once data loads, and toggle `switching` while fetching a different template's policies to avoid a jarring skeleton flash.
