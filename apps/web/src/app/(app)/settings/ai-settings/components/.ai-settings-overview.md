# ai-settings-overview.tsx

Read-only composite view for the CLIENT (customer-facing) AI settings tab, rendering the customer card, visual previews, and quick actions section with full loading-skeleton support.

## Key Components

- **`AiSettingsOverview`** — Default export component that composes the customer AI settings read-only view.
- **`AiSettingsOverviewProps`** — Props interface:
  - `aiConfig?: AgentAiConfig` — AI logic configuration for the active agent
  - `view?: ClientView` — client-facing appearance settings (only present for the CLIENT tab)
  - `providerModelLabel?: string` — human-readable label for the resolved provider model
  - `quickActions?: AiQuickAction[]` — list of quick actions to render
  - `quickActionsBanner?: QuickActionsBannerCopy` — overrides the default banner copy (used by per-customer views to indicate inheritance from global config)

## Usage Example

```typescript
import { AiSettingsOverview } from './ai-settings-overview';

function ClientAiSettingsTab({ aiConfig, view, providerModelLabel, quickActions }) {
  return (
    <AiSettingsOverview
      aiConfig={aiConfig}
      view={view}
      providerModelLabel={providerModelLabel}
      quickActions={quickActions}
    />
  );
}

// Per-customer view with inherited quick actions banner
function CustomerAiSettingsTab({ aiConfig, view, quickActions }) {
  return (
    <AiSettingsOverview
      aiConfig={aiConfig}
      view={view}
      quickActions={quickActions}
      quickActionsBanner={{ source: 'inherited', label: 'Inherited from global config' }}
    />
  );
}
```

## Notes

- Uses `useLoadingScope()` to detect an active loading state, rendering internal child components in their own skeleton states rather than conditionally hiding the whole tree.
- The customer card and previews section render only once both `aiConfig` and `view` are resolved (or while loading).
- The quick actions section renders independently once `aiConfig` is available, even if `quickActions` itself is still `undefined` (it manages its own skeleton).
- Avatar URLs are resolved via `getFullImageUrl` from the client view's `assistantAvatar` data.
