# scaled-preview-frame.tsx

A React component that renders a fixed 1024×800 layout (matching the Fae desktop window's default size) scaled down to fit a responsive card container, using measured CSS transforms instead of breakpoint-based sizing.

## Key Components

- **`FAE_WINDOW_WIDTH`** / **`FAE_WINDOW_HEIGHT`** — Constants defining the Fae window's default dimensions (1024×800), used as the "source" layout size.
- **`PREVIEW_FRAME_CLASS`** — Shared Tailwind class string (`aspect-[1024/800]` box) for the preview frame, exported so loading/skeleton states can match the same aspect ratio before content loads.
- **`ScaledPreviewFrame`** — Component that measures its container's width via `ResizeObserver`, computes a scale factor (`containerWidth / FAE_WINDOW_WIDTH`), and applies a CSS `transform: scale(...)` to its children so a fixed 1024×800 layout fits responsively.

## Usage Example

```typescript
import { ScaledPreviewFrame, PREVIEW_FRAME_CLASS } from './scaled-preview-frame';

function FaePreviewCard() {
  return (
    <div className="w-full max-w-md">
      <ScaledPreviewFrame>
        <FaeAppLayout /> {/* rendered at fixed 1024x800, then scaled */}
      </ScaledPreviewFrame>
    </div>
  );
}

// Matching loading skeleton using the same aspect ratio:
function PreviewSkeleton() {
  return <div className={PREVIEW_FRAME_CLASS + ' animate-pulse bg-ods-bg'} />;
}
```

## Notes

- Uses `ResizeObserver` rather than a fixed breakpoint map because the container width can change for reasons unrelated to viewport size (e.g., a docked side panel narrowing the content area).
- Uses a CSS `transform: scale()` instead of the `zoom` property because `zoom` renders text incorrectly in Safari.
- Children are hidden (`scale === null`) until the first measurement completes, preventing a flash of unscaled (1:1) content on initial render.
