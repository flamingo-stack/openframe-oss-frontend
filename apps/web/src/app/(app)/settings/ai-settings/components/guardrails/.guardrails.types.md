Defines TypeScript DTOs and constants for the AI agent tenant policy REST API (`/chat/api/v1/policies`), covering policy templates, rules, and custom override structures.

## Key Components

| Export | Type | Description |
|---|---|---|
| `CUSTOM_POLICY_TYPE` | `const` | Discriminator string `'CUSTOM'` for custom policy type |
| `CUSTOM_CREATION_TEMPLATE_ID` | `const` | Sentinel radio value `'CUSTOM_CREATION'` for unsaved custom policies |
| `CUSTOM_POLICY_DESCRIPTION` | `const` | UI picker description for the Custom policy option |
| `PolicyTemplateSummary` | `interface` | Lightweight policy listing shape (id, name, type, active state, override count) |
| `PolicyRule` | `interface` | Single guardrail rule entry mapping a tool/function to an `ApprovalLevel` |
| `PolicyTemplateDetail` | `interface` | Full policy detail including rules, custom overrides, and optional source template |
| `CustomPolicyRequest` | `interface` | Request body for creating/updating a custom policy with a base template and overrides |

## Usage Example

```typescript
import type {
  PolicyTemplateSummary,
  PolicyTemplateDetail,
  CustomPolicyRequest,
  PolicyRule,
} from './guardrails.types';
import {
  CUSTOM_POLICY_TYPE,
  CUSTOM_CREATION_TEMPLATE_ID,
} from './guardrails.types';

// Detect an unsaved custom policy in the picker
const isNewCustomPolicy = (id: string) => id === CUSTOM_CREATION_TEMPLATE_ID;

// Build a request to save a custom policy
const request: CustomPolicyRequest = {
  templateId: 'tpl_strict_001',
  overrides: {
    'restart-service': 'MANAGER_APPROVAL',
    'delete-user':     'ADMIN_APPROVAL',
  },
};

// Narrow a summary to the custom type
const isCustom = (summary: PolicyTemplateSummary) =>
  summary.type === CUSTOM_POLICY_TYPE;
```

## Notes

- `PolicyRule.approvalLevel` and override values all use `ApprovalLevel` from `@flamingo-stack/openframe-frontend-core`.
- Per-organization guardrails use the GraphQL API instead — see `use-organization-guardrails.ts`, whose rules normalize to `PolicyRule`.
- `PolicyTemplateDetail.sourceTemplate` is only present on `CUSTOM` type policies and references the base template id.
