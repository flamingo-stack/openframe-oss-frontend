Next.js client page component that renders the "Download Apps" view, gating access so the page is unavailable when accessed from the mobile app shell.

## Key Components

- **`DownloadAppsPage`** — Default export; the route's page component. Checks `isMobileShell()` at render time and calls `notFound()` to immediately return a 404 if the app is running inside the mobile shell, otherwise renders `DownloadAppsView`.
- **`isMobileShell()`** — Build-time/platform predicate (imported from `@/lib/platform`) used directly rather than a reactive hook, since this component either throws (via `notFound()`) or renders the view — there's no intermediate state to preserve across hydration.

## Usage Example

This file is a Next.js App Router page and is not imported manually — it's resolved automatically based on its file path (e.g., `app/download-apps/page.tsx`):

```typescript
// Example: equivalent manual usage of the same pattern elsewhere
import { notFound } from 'next/navigation';
import { isMobileShell } from '@/lib/platform';

function SomeDesktopOnlyPage() {
  if (isMobileShell()) {
    notFound();
  }

  return <SomeDesktopOnlyView />;
}
```

**Design notes:**
- The mobile app shell is excluded because that build *is* the app being distributed — a desktop installer/QR code page is irrelevant to a user already inside the mobile app.
- The desktop shell retains access to this page, since it's the natural place to display download links/QR codes for the mobile app.
- `isMobileShell()` is called as a plain predicate (not a hook like `useIsMobileShell()`) because this component has no reactive subtree to preserve — it either throws via `notFound()` or renders `DownloadAppsView` outright.
