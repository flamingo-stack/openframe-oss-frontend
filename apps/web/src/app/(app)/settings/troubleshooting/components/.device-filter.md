## Device Filter Component

A client-side React component that renders a multi-select device filter with server-side search, used to pick devices for filtering (e.g., in troubleshooting workflows).

The component debounces user input and queries the devices API via React Query, displaying results in an `Autocomplete` control. It supports scoping the device list to a set of organizations and preserves previously selected chips' labels even after the search results move on, falling back to the raw `machineId` for devices restored from a shared link that haven't been fetched yet.

## Key Components

- **`DeviceFilter`** — Main exported component rendering the multi-select device autocomplete.
- **`DeviceFilterProps`** — Props interface:
  - `value: string[]` — selected `machineId`s (URL-driven)
  - `onChange: (value: string[]) => void` — selection change handler
  - `organizationIds?: readonly string[]` — optional scope to specific organizations' devices
  - `disabled?: boolean`, `className?: string`
- **`OPTIONS_LIMIT`** — Max devices fetched per query (50), matching the API page size.
- Internal state:
  - `search` / `debouncedSearch` — raw and debounced (300ms) search text
  - `picked` — a `Map` caching previously selected options so chips retain labels across searches

## Usage Example

```typescript
import { useState } from 'react';
import { DeviceFilter } from './device-filter';

function TroubleshootingFilters() {
  const [deviceIds, setDeviceIds] = useState<string[]>([]);

  return (
    <DeviceFilter
      value={deviceIds}
      onChange={setDeviceIds}
      organizationIds={['org-123', 'org-456']}
      className="w-full max-w-md"
    />
  );
}
```

**Notes:**
- Relies on `fetchDevicesPage` and `deviceQueryKeys` from the devices feature module, and shared utilities `sortDevicesLiveFirst` / `toDeviceOption` for normalizing API results into `AutocompleteOption`s.
- Enforces a maximum selection via `TROUBLESHOOTING_PICK_LIMIT`.
- Filtering happens server-side (`disableClientFilter`), so each keystroke (post-debounce) triggers a new API query scoped by `filter` (statuses + optional organization IDs) and search term.
