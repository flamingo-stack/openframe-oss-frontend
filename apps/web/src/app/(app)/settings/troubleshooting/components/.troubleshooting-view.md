# troubleshooting-view.tsx

Client-side React component implementing the tenant-wide Troubleshooting page under Settings. It aggregates device logs across all devices (optionally scoped by customer and device filters) by querying `deviceLogs` with `machineIds`/`organizationIds` parameters, reusing the same list, drawer, and filter UI as a single device's Device Logs tab.

## Key Components

- **`TroubleshootingView`** — Default export: the full page component composing toolbar, log list, error boundary, and drawer.
- **`DEFAULT_RANGE`** — Default time range constant (`'1h'`) for the log query, chosen for responsiveness over completeness.
- **`PARAM_SCHEMA`** — URL param schema combining shared device-log params with page-specific `customer` and `device` array params.
- **`CUSTOMER_EMPTY_DESCRIPTION`** — Copy explaining why customer-filtered results may be incomplete (agents not yet reporting customer).
- **`UNKNOWN_PICK_COPY`** — Lookup table mapping `customer`/`device` unknown-id errors to `EmptyState` icon/title/description.

## Behavior Notes

- Uses `useFeatureFlagGate('device-logs-customer-filter')` as a tri-state gate so the `customer` param is only sent to the API once the flag resolves, preventing a premature or stale filter from reaching the query.
- Builds a composite `list.key` (organization/machine ids + anchor + filter) via `useMemo` so `useDeferredLogList` only triggers a new fetch when the actual query inputs change—manual Refresh forces a new key via the `anchor`.
- `selected` (drawer state) is lifted above the list so re-filtering (which remounts the list) doesn't close an open log entry drawer.
- `unknownPickFallback` inspects GraphQL errors to detect a deleted/invalid `customer` or `device` id in the URL and offers a "Clear filter" action instead of a generic error.

## Usage Example

```typescript
// Rendered as a route page component, e.g. in a Next.js App Router page file:
import { TroubleshootingView } from '@/app/(app)/settings/troubleshooting/components/troubleshooting-view';

export default function TroubleshootingPage() {
  return <TroubleshootingView />;
}
```

This component expects to run within the app's `PageLayout`/routing context and relies on Relay/GraphQL hooks (`useApiParams`, `useDeferredLogList`) configured elsewhere in the app.
