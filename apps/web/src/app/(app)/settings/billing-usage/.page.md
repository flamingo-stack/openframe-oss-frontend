Client-rendered Next.js page component for the Billing Usage section, gating access by feature flag and user role before rendering billing data.

## Key Components

- **`BillingUsagePage`** (default export) — Page component that orchestrates three independent gate checks before rendering billing content:
  - `useFeatureFlagGate('billings')` — determines if the Billing feature is enabled for the tenant (`'on'` / `'off'` / `'loading'`)
  - `useBillingAccessGate()` — determines if the current user (owner/admin) is authorized to view billing (`'granted'` / `'denied'` / `'loading'`)
  - `useFeatureFlagGate('billing-live-mode')` — determines whether the "Test mode" banner should display, resolved alongside initial data load
- Renders `notFound()` only on a definitive `'off'` flag state (avoids false 404s while the flag is still resolving)
- Renders `BillingRestrictedScreen` when access is explicitly `'denied'`
- Renders `BillingUsageView`, passing a combined `loading` flag until all three gates resolve

## Usage Example

```typescript
// This is a Next.js App Router page file — rendered automatically at its route path.
// File location: app/.../billing-usage/page.tsx (or similar route segment)

// No manual invocation needed; Next.js renders it for matching requests.
// Example of the gating logic reused elsewhere:

import { useFeatureFlagGate } from '@/app/hooks/use-feature-flag';
import { useBillingAccessGate } from '@/app/hooks/use-billing-access-gate';

function ExampleGatedComponent() {
  const gate = useFeatureFlagGate('billings');
  const access = useBillingAccessGate();

  if (gate === 'off') {
    // Treat as not found
    return null;
  }

  if (gate !== 'loading' && access === 'denied') {
    return <p>You do not have permission to view this page.</p>;
  }

  return <p>Loading: {String(gate === 'loading' || access === 'loading')}</p>;
}
```

**Note:** State resolution order matters — flags default to `'loading'` until resolved, preventing premature 404s or restricted-screen flashes during hydration.
