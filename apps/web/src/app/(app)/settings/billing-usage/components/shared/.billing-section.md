## Billing Section Components

A collection of presentational React components used to build the billing page UI, handling test-mode warnings, read-only notices, section grouping, and summary rows with built-in loading-state support.

## Key Components

- **`TestModeBanner`** — Renders a warning banner when the `billing-live-mode` feature flag is off, signaling that displayed invoices/usage are sample data. Returns `null` once the flag resolves to any non-`'off'` state, and is marked `data-loading-optional` so it doesn't block loading states.
- **`BillingReadOnlyNotice`** — Static informational notice explaining that billing is managed externally (in-browser) via a "Manage Billing" action.
- **`SectionBlock`** — Layout wrapper that renders a titled, bordered card container for grouping related billing content.
- **`BillingRow`** — A labeled summary row (built on the shared `LeaderRow` component) supporting `muted`, `warning`, `loading`, and `optional` display states. Automatically participates in an ambient loading scope via `useLoadingScope()`.

## Usage Example

```typescript
import {
  TestModeBanner,
  BillingReadOnlyNotice,
  SectionBlock,
  BillingRow,
} from './billing-section';

function BillingPage() {
  return (
    <div className="flex flex-col gap-4">
      <TestModeBanner />

      <SectionBlock title="Current Plan">
        <BillingRow label="Plan" value="Pro" />
        <BillingRow label="Seats used" value="18 / 20" warning />
        <BillingRow label="Next invoice" value={undefined} loading />
        <BillingRow label="Trial ends" value="—" optional />
      </SectionBlock>

      <BillingReadOnlyNotice />
    </div>
  );
}
```

## Notes

- `BillingRow` relies on `useLoadingScope()` from `@flamingo-stack/openframe-frontend-core/components/ui` to automatically show a skeleton bar when rendered inside a loading context, regardless of the explicit `loading` prop.
- `TestModeBanner` and the `optional` prop on `BillingRow` use `data-loading-optional` to exclude non-critical elements from blocking the page's loading state.
- Styling relies on CSS custom properties (e.g., `--spacing-system-s`, `--ods-open-yellow-base`) and `ods-*` utility classes from the shared design system.
