# use-test-clock.ts

Client-side React hooks wrapping Stripe test-clock GraphQL mutations, used in dev/stage environments (gated by the `test-clock` feature flag) to manipulate time for testing subscription billing cycles.

## Key Components

- **`TestClockAdvance`** — Interface describing the clock-advance input (`days?`, `hours?`). Both are optional but the backend rejects a call with neither set or with negative values.
- **`useAdvanceTestClock()`** — Hook returning `{ mutate, isPending }`. Calls the `advanceTestClock` mutation, converting unset fields to `null` so the backend's validation logic stays accurate. On success it invalidates the entire Relay store (since billing jobs re-run server-side and affect many untracked fields) and forwards the resulting `frozenTime` to an optional `onSuccess` callback.
- **`useResetTestClock()`** — Hook returning `{ mutate, isPending }`. Calls the `resetTestClock` mutation, which deletes the Stripe test customer. On success it also invalidates the Relay store and calls an optional `onSuccess` callback.

Both hooks surface GraphQL-level errors (`errors` array on a nullable/partial payload) and network-level errors (`onError`) via toast notifications, since Relay doesn't always route mutation failures to `onError`.

## Usage Example

```typescript
import { useAdvanceTestClock, useResetTestClock } from '@/hooks/use-test-clock';

function TestClockPanel() {
  const { mutate: advance, isPending: isAdvancing } = useAdvanceTestClock();
  const { mutate: reset, isPending: isResetting } = useResetTestClock();

  const handleAdvanceOneDay = () => {
    advance({ days: 1 }, frozenTime => {
      console.log('Clock frozen at:', frozenTime);
    });
  };

  const handleReset = () => {
    reset(() => {
      console.log('Test clock reset');
    });
  };

  return (
    <div>
      <button onClick={handleAdvanceOneDay} disabled={isAdvancing}>
        Advance 1 Day
      </button>
      <button onClick={handleReset} disabled={isResetting}>
        Reset Clock
      </button>
    </div>
  );
}
```

Both hooks invalidate the Relay store on success, so any component reading subscription/billing data automatically refetches to reflect server-side changes.
