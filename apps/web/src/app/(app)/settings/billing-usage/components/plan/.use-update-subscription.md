# use-update-subscription.ts

A React hook that wraps a Relay mutation for applying subscription plan changes (upgrades/downgrades), handling success and error states via toast notifications.

## Key Components

- **`useUpdateSubscription()`** — Hook returning `{ mutate, isPending }` for triggering a subscription update.
- **`mutate(input, options?)`** — Fires the `updateSubscription` mutation; accepts an `UpdateSubscriptionInput` and optional `UpdateSubscriptionOptions` (with `onSuccess` callback).
- **`UpdateSubscriptionOptions`** — Interface defining the `onSuccess` callback invoked after a successful update. The hook does **not** navigate on completion—callers decide what "done" means.
- **`updateSubscriptionMutation`** — The GraphQL mutation definition, selecting only `subscription { id status }` and `errors { message }` (deliberately omits `pendingInvoices` and `products { packageOptions }`; see inline docs for why).
- **`NOT_SAVED`** — Fallback error message shown when a failure has no backend-provided message (e.g., gateway 5xx, WAF block, timeout).
- **Re-exported types**: `PackageUpdateInput`, `UpdateSubscriptionInput` (from generated GraphQL types).

## Usage Example

```typescript
import { useUpdateSubscription } from '@/hooks/use-update-subscription';

function PlanChangeButton() {
  const { mutate, isPending } = useUpdateSubscription();

  const handleUpgrade = () => {
    mutate(
      { subscriptionId: 'sub_123', packageId: 'pkg_premium' },
      {
        onSuccess: () => {
          // e.g., refetch billing data or close a modal
          refetchBillingInfo();
        },
      }
    );
  };

  return (
    <button onClick={handleUpgrade} disabled={isPending}>
      {isPending ? 'Updating...' : 'Upgrade Plan'}
    </button>
  );
}
```

**Note:** Since the mutation response doesn't include `products { packageOptions }` or `pendingInvoices`, callers must refetch related data themselves after a successful update to reflect plan and invoice changes in the UI.
