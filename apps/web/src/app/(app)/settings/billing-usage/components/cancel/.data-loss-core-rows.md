# data-loss-core-rows.tsx

Renders the list of "what you'll lose" summary rows shown in a subscription cancellation/data-loss warning dialog. It aggregates counts from a GraphQL fragment (devices, customers, articles, scripts, schedules, tracked hours) plus externally-sourced impact data (tickets, monitoring policies, saved queries), and conditionally displays only non-zero rows, each formatted with correct pluralization.

## Key Components

- **`dataLossCoreRowsFragment`** — GraphQL fragment (`dataLossCoreRows_query`) pulling subscription usage, organization count, knowledge base articles/folders, active scripts/schedules, and employee time stats.
- **`CORE_ROW_SKELETON_WIDTHS`** — Fixed array of Tailwind width classes used to render loading skeletons matching the expected number/shape of rows.
- **`DataLossCoreRows`** — Main component. Accepts a Relay fragment reference (`query`) and:
  - Shows skeleton loading state (via `LoadingWhen`/`LoadingItems`/`useLoadingScope`) while the fragment or external cancellation-impact data (`useCancellationImpact`) is unavailable.
  - Otherwise renders a `DataLossItem`/`DataLossStat` pair for each metric, omitting any row (or sub-clause) whose value is zero.

## Usage Example

```typescript
import { DataLossCoreRows } from './data-loss-core-rows';
import type { dataLossCoreRows_query$key } from '@/__generated__/dataLossCoreRows_query.graphql';

function CancellationDataLossDialog({ query }: { query: dataLossCoreRows_query$key | null }) {
  return (
    <div className="data-loss-summary">
      <h3>Cancelling will remove:</h3>
      <DataLossCoreRows query={query} />
    </div>
  );
}
```

**Notes:**
- `query` may be `null` while the parent dialog's Relay query is still loading; the component handles this by rendering skeleton placeholders.
- Depends on `useCancellationImpact` for ticket/policy/query counts sourced outside this fragment (e.g., ai-agent, Fleet).
- "Events across monitoring policies" is intentionally excluded since no backend counts them.
