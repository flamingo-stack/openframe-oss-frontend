# updated-plan-section.tsx

A React client component that renders the "Updated Plan" section of a billing summary, displaying details about a subscription's upcoming plan change — whether it's a scheduled package switch or a fallback to pay-as-you-go metered billing.

## Key Components

- **`UpdatedPlanSection`** — Main exported component. Accepts Relay fragment references for `subscription` and `billingPlan`, derives the pending plan's billing cycle, device rate, AI token grant, and start date, then renders them via `SectionBlock` and `BillingRow`.
- **`updatedPlanSectionSubscriptionFragment`** — GraphQL fragment on `SubscriptionDetail`, delegates to `planSchedule_subscription` to extract pending plan scheduling data.
- **`updatedPlanSectionBillingPlanFragment`** — GraphQL fragment on `BillingPlanDetails`, fetches `products` (with `catalogDeviceRate_product` fragment) used to resolve device rates when no explicit price is set.
- **`UpdatedPlanSectionProps`** — Prop types tying the component to its Relay fragment keys.

### Behavior notes
- Returns `null` if there's no pending plan (`schedule.hasPendingPlan` is falsy).
- Device rate resolution: uses the pending plan's explicit price if present, otherwise falls back to `catalogDeviceRate` looked up by billing period (or `null` for pay-as-you-go metered pricing).
- Free AI token grants are **derived** client-side via `freeTokensForPlan`, not fetched from the server, and favor the larger grant when a package is scheduled.
- Billing cycle label is "Annual" for `BillingPeriod.YEARLY`, otherwise "Monthly".

## Usage Example

```typescript
import { UpdatedPlanSection } from './updated-plan-section';

function BillingSummary({ subscriptionRef, billingPlanRef }: {
  subscriptionRef: updatedPlanSection_subscription$key;
  billingPlanRef: updatedPlanSection_billingPlan$key | null;
}) {
  return (
    <div className="billing-summary">
      <UpdatedPlanSection
        subscription={subscriptionRef}
        billingPlan={billingPlanRef}
      />
    </div>
  );
}
```

This component is typically rendered alongside a "Current Plan" section, reading from the same `subscription` query response, so both sides of the comparison stay consistent.
