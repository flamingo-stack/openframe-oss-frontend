# plan-schedule.ts

Derives a normalized `PlanSchedule` view from a subscription's device package data, resolving the active and pending (scheduled) device packages, computing transition dates, and detecting plan-change signals like downgrades to pay-as-you-go or upcoming cancellations.

## Key Components

- **`planScheduleFragment`** — GraphQL `@inline` fragment pulling subscription status, product packages (with billing period, price, status, and date range), and the pay-as-you-go option.
- **`DevicePackage`** — Interface describing a single device package's billing period, price, and start/end dates.
- **`PlanSchedule`** — Interface summarizing the full schedule: active/pending packages, trial/cancellation flags, PAYG pricing, transition dates (`currentPlanEndsOn`, `nextPlanStartsOn`), and derived booleans (`revertsToPayg`, `hasPendingPlan`, `carriesAi`).
- **`toPackage(option)`** — Converts a raw `SubscriptionOption` into a `DevicePackage`.
- **`planSchedule(ref)`** — Main function; reads the inline fragment and computes the full `PlanSchedule`, including:
  - Locating the `MANAGED_DEVICES` product and its active/pending package options.
  - Determining if the current plan is genuinely ending (not just renewing) via `endDate` presence and cancellation status.
  - Computing `nextPlanStartsOn` as either the pending package's start date or the day after the current plan ends.
  - Flagging whether the plan reverts to metered billing (`revertsToPayg`) when no replacement package is scheduled.

## Usage Example

```typescript
import { planSchedule } from '@/lib/plan-schedule';

function SubscriptionSummary({ subscriptionRef }: { subscriptionRef: planSchedule_subscription$key }) {
  const schedule = planSchedule(subscriptionRef);

  if (schedule.hasPendingPlan) {
    console.log(`Current plan ends on ${schedule.currentPlanEndsOn}`);
    if (schedule.revertsToPayg) {
      console.log('Billing will revert to pay-as-you-go.');
    } else if (schedule.pending) {
      console.log(`New plan starts on ${schedule.nextPlanStartsOn}`);
    }
  }

  return schedule.active ? (
    <PlanBlock title="Current Plan" pkg={schedule.active} />
  ) : null;
}
```

This is typically consumed by UI components rendering "Current Plan" / "Updated Plan" blocks side by side, using `currentPlanEndsOn` and `nextPlanStartsOn` to align the transition dates.
