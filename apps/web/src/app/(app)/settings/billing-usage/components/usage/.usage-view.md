# usage-view.tsx

A payment-free variant of the Billing & Usage page that displays device and AI usage consumption data without exposing any purchasing mechanisms (prices, plans, or payment CTAs). This component is rendered for builds where payment UI must be hidden to comply with App Store Guideline 3.1.1.

## Key Components

- **`usageViewQuery`** — GraphQL query that fetches consumption-only subscription data (usage counters, committed quantities) deliberately excluding priced fields like `nextPayment`, `pendingInvoices`, or option `price`. Shares the `deviceAllocation_subscription` fragment with the billing page to keep device figures consistent across both views.
- **`UsageView`** — Top-level exported component. Wraps the page in a `LoadingSuspense` boundary, accepting an optional `loading` gate prop.
- **`UsageReader`** — Internal component that checks `useLoadingScope()` to decide between rendering a skeleton (`UsageScreen` with `null` data) or triggering the actual query (`UsageQuery`).
- **`UsageQuery`** — Executes `useLazyLoadQuery` with `store-and-network` fetch policy and `skipSubscriptionGate` metadata (so `PAST_DUE` subscriptions can still view this page).
- **`UsageScreen`** — Renders the actual UI: device usage card, AI usage card (if the subscription includes `AI_ASSISTANCE`), an over-limit warning banner, and usage/limits section blocks.

## Usage Example

```typescript
import { UsageView } from './usage-view';

// Rendered in a page/route when payment UI is hidden for the build
export default function UsagePage() {
  return <UsageView />;
}

// With an external loading gate (e.g., awaiting entitlement checks)
export default function GatedUsagePage() {
  const stillResolvingEntitlements = useEntitlementsPending();
  return <UsageView loading={stillResolvingEntitlements} />;
}
```

Key behavioral notes:
- Device usage shows a progress ring and limit comparison only when the device product is **not** pay-as-you-go and has a positive allocation.
- AI usage shows a bare token count only (no progress ring), since AI consumption has no locally-known allowance to compare against.
- The "over your device limit" warning only appears when `deviceOverLimit` is true — there is no "approaching limit" warning tier, matching the billing page's philosophy of surfacing only states that have actually occurred.
