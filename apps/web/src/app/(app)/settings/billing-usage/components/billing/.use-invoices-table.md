# use-invoices-table.ts

A React hook that encapsulates the state and TanStack table instance powering the Invoices History table, including search filtering, status filtering, and a tri-state sort cycle. It's designed so both the main table header and a separate mobile filter modal can drive the same underlying state.

## Key Components

- **`useInvoicesTable(invoices, loading)`** — Primary hook that returns everything needed to render the invoices table:
  - `table` — the TanStack table instance (client-side sorting/filtering)
  - `search` / `setSearch` — free-text search state (matches invoice number and amount)
  - `sortState` — normalized `{ id, desc } | null` representation of the active sort column
  - `handleSortChange(columnId)` — cycles a column through ascending → descending → unsorted
  - `sorting` / `setSorting` — raw `SortingState` for direct control
  - `columnFilters` / `setColumnFilters` — raw `ColumnFiltersState`
  - `statusOptions` — computed status filter options derived from the invoice data

- **`matchesSearch(invoice, query)`** — Internal helper that builds a searchable haystack from the invoice number and both raw/formatted amount strings, enabling partial matches like `"11.9"`, `"11.92"`, or `"$11.92"`.

## Usage Example

```typescript
import { useInvoicesTable } from './use-invoices-table';

function InvoicesHistoryTable({ invoices, loading }: {
  invoices: InvoiceRow[];
  loading: boolean;
}) {
  const {
    table,
    search,
    setSearch,
    sortState,
    handleSortChange,
    statusOptions,
  } = useInvoicesTable(invoices, loading);

  return (
    <div>
      <input
        value={search}
        onChange={e => setSearch(e.target.value)}
        placeholder="Search invoices..."
      />
      {/* Render table using `table` instance, pass `sortState` and
          `handleSortChange` to header cells, `statusOptions` to the
          status filter control */}
    </div>
  );
}
```

**Notes:**
- When `loading` is `true`, the hook substitutes skeleton placeholder rows (via `loadingPlaceholderRows`) instead of filtering real data, so search is bypassed during loading.
- Rows, columns, and `getRowId` are memoized because `useDataTable` relies on referential stability to avoid recomputing its internal row model — not purely for render performance.
