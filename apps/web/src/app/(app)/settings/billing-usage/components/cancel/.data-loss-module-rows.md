# data-loss-module-rows.tsx

Renders the list of per-module data-loss summary rows shown in a confirmation dialog (e.g., before a destructive action like tenant/workspace deletion). Each row independently queries one feature module (incidents, remote sessions, recordings, integrations) and reports what data would be lost, gracefully hiding or showing a loading state based on feature flag gates and GraphQL query results.

## Key Components

- **`DataLossModuleRows`** — Main exported component. Resolves feature gates for incidents, remote sessions, and tenant management/integrations, then renders a `ModuleRow` per module, each wrapping an isolated `QueryIsland` GraphQL query.
- **`ModuleRow`** — Gate-aware wrapper: renders nothing if the module is `'off'`, a loading placeholder if `'loading'`, otherwise wraps children in a `ContentErrorBoundary` so one module's query failure doesn't break the others.
- **`ModuleRowCount` / `ModuleRowCountReader`** — Suspense/loading-scope wrappers ensuring a count row renders a skeleton (`DataLossItem`) while data streams in, without triggering reads during the loading phase.
- **`CountRow`** — Renders a `DataLossItem` with a `DataLossStat` only when `value > 0`; returns `null` otherwise (no row for zero counts).
- **GraphQL queries** — `incidentsQuery`, `remoteSessionsQuery`, `recordingsQuery`, `integrationsQuery`: four separate queries (not combined) so a disabled/undeployed module's failing field doesn't take down the others' counts.

## Usage Example

```typescript
import { DataLossModuleRows } from './data-loss-module-rows';

function DeleteWorkspaceDialog() {
  return (
    <div className="confirmation-dialog">
      <p>Deleting this workspace will permanently remove:</p>
      <DataLossModuleRows />
    </div>
  );
}
```

Each row (incidents, remote sessions, recordings, integrations) independently:
1. Checks its feature flag gate (`off` / `loading` / resolved).
2. Fetches its count via an isolated Relay query (`store-or-network`).
3. Hides itself if the count is zero or the module is disabled.
4. Shows a loading placeholder (`DataLossItem`) while flag/data resolve.
5. Isolates failures via `ContentErrorBoundary` so one broken module doesn't blank the whole dialog.
