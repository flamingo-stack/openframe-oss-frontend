# subscription-package.ts

Determines whether a subscription includes a recurring (non-UNLIMITED) billing package, which affects cancellation behavior: subscriptions with a recurring package run until the end of the paid term, while pay-as-you-go-only subscriptions end immediately upon cancellation with usage invoiced right away.

## Key Components

- **`subscriptionPackageFragment`** — Inline Relay GraphQL fragment that reads `products.packageOptions.billingPeriod` from a `SubscriptionDetail`.
- **`hasSubscriptionPackage(ref)`** — Reads the inline fragment data and returns `true` if any product has at least one package option whose `billingPeriod` is not `UNLIMITED`. Mirrors the backend's `hasSubscriptionPackage` logic from saas-lib's `SubscriptionAllowanceUtils`.

## Usage Example

```typescript
import { hasSubscriptionPackage } from '@/path/to/subscription-package';
import type { subscriptionPackage_subscription$key } from '@/__generated__/subscriptionPackage_subscription.graphql';

function CancellationNotice(props: { subscriptionRef: subscriptionPackage_subscription$key }) {
  const willRunToEndOfTerm = hasSubscriptionPackage(props.subscriptionRef);

  return willRunToEndOfTerm ? (
    <p>Your subscription will remain active until the end of the current billing period.</p>
  ) : (
    <p>Your subscription will end immediately and remaining usage will be invoiced now.</p>
  );
}
```

**Note:** `ref` must be a fragment reference (`$key`) obtained via `useFragment`/`readInlineData` chaining from a parent query that spreads `...subscriptionPackage_subscription` on a `SubscriptionDetail` type.
