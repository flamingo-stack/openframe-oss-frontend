# device-allocation.ts

Derives a single, authoritative view of device usage against the managed-devices package, shared by the Device Usage card, its overage block, and the payment-free Usage page. Centralizing this logic ensures all consumers display consistent numbers, since the backend's usage figures already account for in-period package upgrades (frozen overage is billed, not recalculated as "used minus allocation").

## Key Components

- **`deviceAllocationFragment`** — Relay inline GraphQL fragment pulling `usage` metrics and `products` (including the pay-as-you-go option and active package reference) from `SubscriptionDetail`.
- **`DeviceAllocation`** — Interface describing the computed device allocation state: `used`, `usedAgainstLimit`, `allocation`, `committedOverage`, `overage`, `overLimit`, `isPayg`, and `paygActive`.
- **`deviceAllocation(ref)`** — Reads the inline fragment data and computes a `DeviceAllocation` object. It finds the `MANAGED_DEVICES` product, checks for an active package via `activePackage`, and determines pay-as-you-go status and overage limit breach.

## Usage Example

```typescript
import { deviceAllocation } from './device-allocation';
import type { deviceAllocation_subscription$key } from '@/__generated__/deviceAllocation_subscription.graphql';

function DeviceUsageCard({ subscriptionRef }: { subscriptionRef: deviceAllocation_subscription$key }) {
  const {
    used,
    allocation,
    overage,
    overLimit,
    isPayg,
    paygActive,
  } = deviceAllocation(subscriptionRef);

  return (
    <div>
      <span>{used}/{allocation}</span>
      {overLimit && <span className="warning">{overage} Devices over limit</span>}
      {isPayg && !paygActive && <span>Pay-as-you-go expired — overage blocked</span>}
    </div>
  );
}
```

**Note:** `overLimit` only fires when billing is actually impacted (overage > 0 and not pure PAYG), deliberately omitting any "approaching limit" warning tier to avoid alert fatigue.
