## TestClockPanel

Developer-only React panel for manipulating a tenant's Stripe test clock (virtual billing time), enabling QA and engineers to exercise trial expirations, renewals, and invoice generation without waiting on real time. Gated by a server-driven feature flag so it renders (and queries) nothing in production.

## Key Components

- **`TestClockPanel`** — Public entry point. Checks the `test-clock` feature flag via `useFeatureFlag`; renders `null` when disabled, otherwise wraps the reader in a `LoadingSuspense` boundary.
- **`TestClockPanelReader`** — Internal gate that detects an active `useLoadingScope()` and skips the GraphQL query during loading, rendering a frozen/inert view instead.
- **`TestClockPanelContent`** — Fires `testClockPanelQuery` via `useLazyLoadQuery` (with `skipSubscriptionGate` metadata for PAST_DUE tenants) and hands the result to the view.
- **`TestClockPanelView`** — Presentational component containing the form (days/hours advance, reset button), provisioning status display, and the "Seed usage" controls.
- **`parseStep(input)`** — Helper parsing a text field into `undefined` (blank), a valid non-negative integer, or `null` (invalid).
- **`SeedUsageField`** — Field for seeding billing metrics (device peaks, AI tokens) used within the panel.

## Usage Example

```typescript
import { TestClockPanel } from './test-clock-panel';

function BillingPage() {
  const [fetchKey, setFetchKey] = useState(0);

  return (
    <div>
      {/* ...billing content... */}
      <TestClockPanel onClockChanged={() => setFetchKey(k => k + 1)} />
    </div>
  );
}
```

The `onClockChanged` callback must bump the host page's Relay `fetchKey` (or equivalent re-fetch trigger) since the underlying mutations invalidate the Relay store but mounted queries still need a fresh key to re-request data.

**Note:** This component only renders when the backend's `test-clock` feature flag (tied to `openframe.billing.test-clock.enabled`) is active — it is intended strictly for development and QA environments.
