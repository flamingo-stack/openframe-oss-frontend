A dev-only React panel for controlling a tenant's Stripe test clock, enabling time-based billing scenarios (trials, renewals, invoices) without waiting for real time to pass.

## Key Components

### `TestClockPanel` (exported)
Feature-flag-gated entry point. Returns `null` when the `test-clock` flag is disabled, preventing GraphQL requests that would fail schema validation in production. Wraps content in `Suspense` with a skeleton fallback.

### `TestClockPanelContent` (internal)
The rendered panel UI. Fetches current virtual time via `testClockPanelQuery` and exposes two actions:

- **Advance** — moves the clock forward by N days; the first call also creates the clock and flushes metered Stripe usage
- **Reset** — deletes the Stripe customer and test clock, returning to real time, then restarts provisioning polling

### `testClockPanelQuery`
Relay GraphQL query fetching `testClockTime.frozenTime` from the server.

### State Management
Uses a `frozenTimeOverride` pattern: mutation responses immediately overwrite the initial query result so the UI reflects the latest committed value without waiting for a re-fetch.

## Usage Example

```typescript
// In a billing settings page
import { TestClockPanel } from './test-clock-panel';

function BillingSettingsPage() {
  const [fetchKey, setFetchKey] = useState(0);

  return (
    <>
      <TestClockPanel onClockChanged={() => setFetchKey(k => k + 1)} />
      <BillingDetailsQuery fetchKey={fetchKey} />
    </>
  );
}
```

> **Note:** The `onClockChanged` callback should increment a Relay `fetchKey` on the host page — mutations invalidate the store, but mounted queries need a new `fetchKey` to re-request updated data.

> **Dev only:** This component is silently suppressed in production via the server-driven `test-clock` feature flag (`openframe.billing.test-clock.enabled`).
