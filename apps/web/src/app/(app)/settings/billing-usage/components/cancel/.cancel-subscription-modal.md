# cancel-subscription-modal.tsx

Renders the subscription cancellation confirmation dialog, combining a reason/comment capture form with independently-loaded server data about cancellation terms and data loss impact.

## Key Components

- **`CancelSubscriptionModal`** — Top-level component that conditionally mounts `CancelSubscriptionForm` based on `isOpen`. The form fully unmounts when closed, guaranteeing a fresh state on each open.
- **`CancelReason`** — Union type of allowed cancellation reasons (`TOO_EXPENSIVE`, `NOT_USING_ENOUGH`, `MISSING_FEATURE`, `TECHNICAL_ISSUES`, `OTHER`).
- **`REASON_OPTIONS`** — Static list of `{ value, label }` pairs powering the reason `Select`.
- **`CancelSubscriptionForm`** — Internal form managing `reason`/`comment` state, rendering the `SimpleModal` with confirm/keep-subscription actions. The "Continue" button is disabled until a reason is chosen.
- **`cancelSubscriptionModalQuery`** — GraphQL query (via `react-relay`) composing fragments `cancellationTerms_query` and `dataLossCoreRows_query`, fetched once and shared by both data islands using `store-or-network` fetch policy.
- **`CancellationTermsIsland` / `DataLossCoreRowsIsland`** — Independent `LoadingSuspense`-wrapped readers that each resolve the shared query and render their respective sub-components (`CancellationTerms`, `DataLossCoreRows`), each guarded by `ContentErrorBoundary` so a failed fetch doesn't block cancellation.

## Usage Example

```typescript
import { useState } from 'react';
import { CancelSubscriptionModal, type CancelReason } from './cancel-subscription-modal';

function BillingSettings() {
  const [isModalOpen, setModalOpen] = useState(false);
  const [isPending, setPending] = useState(false);

  const handleConfirm = async (reason: CancelReason, comment: string) => {
    setPending(true);
    await cancelSubscription({ reason, comment });
    setPending(false);
    setModalOpen(false);
  };

  return (
    <CancelSubscriptionModal
      isOpen={isModalOpen}
      isPending={isPending}
      onClose={() => setModalOpen(false)}
      onConfirm={handleConfirm}
    />
  );
}
```

Each data-dependent section (`CancellationTermsIsland`, `DataLossCoreRowsIsland`) renders its own loading state independently, so the modal paints progressively as data resolves rather than blocking on a single loading gate.
