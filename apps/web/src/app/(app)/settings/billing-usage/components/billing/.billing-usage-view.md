Renders the Billing & Usage settings page: the payment-free `UsageView` on builds that may not show payments, else `BillingUsageContent` (a `next/dynamic` import, so those builds never download it).

## Key Components

| Export / Symbol | Description |
|---|---|
| `BillingUsageView` | Public entry point; picks `UsageView` or `BillingUsageContent` by build and hands them `loading` (the page's gates still resolving: the `billings` flag, the billing role, the `billing-live-mode` flag) |
| `BillingUsageContent` | The billing page. Its query component sits behind a `GatedSuspense`: while a gate resolves or the query is in flight, the same page (`BillingUsageScreen` with no data) is drawn in a loading scope, where every part draws its own loading state |
| `BillingUsageScreen` | The page drawn from its query's answer (props only); header actions, plan sections, cards and notices |
| `BillingUsageContentSkeleton` | Used only on the dynamic import's `loading:` line, while `BillingUsageContent`'s code downloads: the page's own frame and sections in a loading scope |

## Usage Example

```typescript
import { BillingUsageView } from './billing-usage-view';

export default function BillingUsagePage() {
  // Draw the page in its loading scope while the page's gates answer.
  return <BillingUsageView loading={gate === 'loading' || access === 'loading' || liveMode === 'loading'} />;
}
```

## Notes

- `TestClockPanel` and `TestModeBanner` are dev/test-only. The banner waits on `billing-live-mode` and sits below the page's sections, marked `data-loading-optional`, so it never moves loaded content.
- The AI cards are drawn while loading (the typical subscription carries the AI product).
- Current Plan is drawn for a trial too (stated as a free trial, "Next Payment" $0.00), so the page has one shape loading and loaded.
