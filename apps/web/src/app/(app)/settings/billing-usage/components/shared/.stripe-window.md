# stripe-window.ts

Utility module for safely opening Stripe-hosted pages (checkout, customer portal, hosted invoices) in new browser tabs, working around popup-blocker restrictions that occur when Stripe URLs are fetched asynchronously after the triggering user gesture has ended.

## Key Components

- **`DeferredTab`** — Interface representing a tab opened in advance of knowing its destination URL, exposing `navigate(url)` to point it somewhere once the URL is ready, and `cancel()` to close it if the URL never arrives.
- **`openDeferredTab(caption: string): DeferredTab`** — Opens a blank tab immediately (synchronously, within the user gesture) so browsers don't treat it as a popup, paints a loading placeholder with the given `caption`, and returns a handle to navigate or cancel it once the real URL (e.g., from a Stripe mutation) resolves. Falls back to navigating the current tab if the popup was blocked.
- **`openExternalTab(url: string): void`** — Opens an already-known URL (like a hosted invoice link) in a new tab with `noopener,noreferrer`, falling back to same-tab navigation if blocked.

## Usage Example

```typescript
import { openDeferredTab, openExternalTab } from './stripe-window';

// Case 1: URL not known yet (e.g., async checkout session creation)
async function handleCheckoutClick() {
  const tab = openDeferredTab('Preparing your checkout…');

  try {
    const { url } = await createCheckoutSession(); // async mutation
    tab.navigate(url);
  } catch (err) {
    tab.cancel();
    showError('Could not start checkout.');
  }
}

// Case 2: URL already known (e.g., hosted invoice link)
function handleViewInvoiceClick(invoiceUrl: string) {
  openExternalTab(invoiceUrl);
}
```

**Why `openDeferredTab` exists:** Since Stripe URLs are typically generated by a server-side mutation that completes after the click event, calling `window.open(url)` at that point is often blocked as a popup. `openDeferredTab` opens the tab synchronously during the click, then navigates it once the URL resolves — preserving the tab handle and avoiding `noopener`, since severing `target.opener` manually achieves the same security guarantee while keeping the reference needed to navigate later.
