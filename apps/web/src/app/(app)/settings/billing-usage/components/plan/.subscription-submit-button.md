A client-side React component that renders the appropriate subscription action button based on the user's current subscription state — either initiating a Stripe Checkout session or updating an existing subscription.

## Key Components

### `SubscriptionSubmitButton`
The single exported component that conditionally renders one of two button variants:

| State | Button Label | Behavior |
|---|---|---|
| `needsCheckout: true` | **Proceed to Payment** | Calls `createCheckout.mutate()` with `checkoutProducts` |
| `needsCheckout: false` | **Update Subscription** | Calls `updateSubscription.mutate()` with `packageUpdates`, with validation |

**Props (`SubscriptionSubmitButtonProps`):**

| Prop | Type | Description |
|---|---|---|
| `needsCheckout` | `boolean` | `true` for TRIAL / TRIAL_EXPIRED / CANCELED states |
| `packageUpdates` | `PackageUpdateInput[]` | ADD/CANCEL diff for the update flow |
| `checkoutProducts` | `ProductCheckoutInput[]` | Desired end-state for checkout flow |
| `hasInvalidCustom` | `boolean` | Blocks update if a Custom Amount quantity is invalid |
| `className` | `string?` | Extra Tailwind classes (e.g. `w-full` for mobile) |

**Internal hooks used:**
- `useUpdateSubscription` — mutation for modifying an active subscription
- `useCreateCheckoutSession` — mutation for initiating Stripe Checkout
- `useToast` — surfaces validation errors to the user

## Usage Example

```typescript
// In a subscription management page
<SubscriptionSubmitButton
  needsCheckout={subscriptionStatus === 'TRIAL_EXPIRED'}
  checkoutProducts={[{ productId: 'prod_abc', quantity: 1 }]}
  packageUpdates={[{ packageId: 'pkg_xyz', action: 'ADD' }]}
  hasInvalidCustom={false}
  className="w-full"
/>
```

> **Disable logic:** The "Update Subscription" button is automatically disabled when `packageUpdates` is empty (no diff from current plan) or while a mutation is pending.
