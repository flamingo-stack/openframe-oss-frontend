# device-overage-block.tsx

Renders a warning block shown when a subscription's device count exceeds its plan's device package limit, displaying overage details, billing impact, and an upgrade action when applicable.

## Key Components

- **`DeviceOverageBlock`** — React component that renders the overage warning UI. Returns `null` when the device count is within plan limits (`device.overLimit` is `false`).
- **`DeviceOverageBlockProps`** — Props interface:
  - `subscription`: Relay fragment key (`deviceOverageBlock_subscription$key`) for subscription data.
  - `onUpgrade`: Callback to open the plan-change flow, or `null` if upgrading is unavailable.
- **`deviceOverageBlockFragment`** — GraphQL fragment pulling `currentPeriodEnd`, `cancellationEffectiveAt`, `currentInvoice.estimatedOverage`, and spreading `deviceAllocation_subscription`.

The component distinguishes two states:
- **Pay-as-you-go active (`billed`)**: extra devices are billed at metered rates; shows an "Upgrade Plan" button and estimated overage cost/next billing date (sourced from Stripe's invoice forecast, not computed locally).
- **Pay-as-you-go inactive**: extra devices are blocked rather than billed; shows a subscription end date if cancellation is scheduled.

It also surfaces a breakdown when `device.committedOverage > 0`, splitting overage into devices frozen at a mid-period upgrade versus devices currently over the limit.

## Usage Example

```typescript
import { DeviceOverageBlock } from './device-overage-block';

function BillingPanel({ subscriptionRef }: { subscriptionRef: deviceOverageBlock_subscription$key }) {
  const openUpgradeDialog = () => {
    // trigger plan-change modal/navigation
  };

  return (
    <DeviceOverageBlock
      subscription={subscriptionRef}
      onUpgrade={openUpgradeDialog}
    />
  );
}
```

Pass `onUpgrade={null}` when the current context (e.g., a cancelled subscription) offers no upgrade path—the "Upgrade Plan" button will simply be omitted.
