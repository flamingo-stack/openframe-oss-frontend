# use-cancel-pending-downgrade.ts

A React hook that cancels a previously scheduled subscription downgrade via a GraphQL mutation, restoring the current plan to renew as-is.

This hook reverts a staged downgrade (either a pending package change or a commitment lapsing to pay-as-you-go) by dropping the staged change and releasing the associated Stripe schedule on the backend. It surfaces success/failure feedback via toast notifications and always triggers an `onSettled` callback so the calling page can refetch fresh subscription state—whether the cancellation succeeded or failed (e.g., due to the downgrade already being undone or applied elsewhere).

## Key Components

- **`cancelPendingDowngradeMutation`** — GraphQL mutation definition requesting the updated `subscription` (`id`, `status`) and any `errors` from `cancelPendingDowngrade`.
- **`CancelPendingDowngradeOptions`** — Options interface with an optional `onSettled` callback, invoked after both success and failure paths.
- **`UNDO_FAILED`** — Shared toast payload used for both GraphQL user errors and network/mutation errors.
- **`useCancelPendingDowngrade()`** — The exported hook. Returns:
  - `mutate(options?)` — Triggers the mutation; no input variables required.
  - `isPending` — Boolean flag reflecting mutation in-flight status.

## Usage Example

```typescript
import { useCancelPendingDowngrade } from '@/hooks/use-cancel-pending-downgrade';

function UndoDowngradeButton({ refetchSubscription }: { refetchSubscription: () => void }) {
  const { mutate, isPending } = useCancelPendingDowngrade();

  return (
    <button
      disabled={isPending}
      onClick={() => mutate({ onSettled: refetchSubscription })}
    >
      {isPending ? 'Undoing...' : 'Undo Downgrade'}
    </button>
  );
}
```

The `onSettled` callback is called regardless of outcome, ensuring the UI always reflects the latest subscription state—even if the undo attempt fails because the downgrade was already canceled or had already taken effect.
