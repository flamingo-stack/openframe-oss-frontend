Provides a React hook for seeding synthetic billing usage data via a Relay GraphQL mutation, intended strictly for development/staging environments where the `seedTestUsage` mutation exists in the schema.

## Key Components

- **`seedTestUsageMutation`** — GraphQL mutation document that sends `metricType` and `value` to seed a billing usage data point, returning `metricType`, `billingDate`, and `dayValue`.
- **`SeedTestUsageResult`** — Interface describing the shape of a successful seed result (`billingDate`, `dayValue`).
- **`useSeedTestUsage()`** — Hook that exposes:
  - `mutate(metricType, value, onSuccess?)` — Triggers the mutation, handling both GraphQL partial errors and network errors via toast notifications, and invalidates the Relay store cache on success so dependent usage cards refetch.
  - `isPending` — Boolean flag (`isInFlight`) indicating whether the mutation is currently in progress.

## Usage Example

```typescript
import { useSeedTestUsage } from '@/hooks/use-seed-test-usage';
import type { BillingMetricType } from '@/generated/schema-enums';

function TestClockPanel() {
  const { mutate, isPending } = useSeedTestUsage();

  const handleSeed = () => {
    mutate('API_CALLS' as BillingMetricType, 1000, (result) => {
      console.log(`Seeded ${result.dayValue} on ${result.billingDate}`);
    });
  };

  return (
    <button onClick={handleSeed} disabled={isPending}>
      {isPending ? 'Seeding...' : 'Seed Test Usage'}
    </button>
  );
}
```

**Notes:**
- This hook should only be invoked behind the same `test-clock` feature flag that gates the UI panel using it, since the underlying mutation does not exist in production schemas.
- On success, the Relay store is invalidated (`store.invalidateStore()`), forcing any components reading tenant usage aggregates to re-fetch fresh data.
- GraphQL-level errors (partial error payloads returned alongside data) are treated as failures, not silently ignored, to avoid falsely reporting successful seeding.
