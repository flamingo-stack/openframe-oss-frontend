A React hook that reverses a scheduled subscription cancellation by calling the `resumeSubscription` GraphQL mutation, restoring a subscription from `PENDING_CANCELLATION` back to `ACTIVE`.

## Key Components

- **`resumeSubscriptionMutation`** — GraphQL mutation definition with no input variables, returning a `Boolean`. Only valid while the subscription is still within its paid period.
- **`useResumeSubscription()`** — Hook that wraps the mutation with toast notifications and Relay store invalidation.
  - **`mutate(options?: ResumeSubscriptionOptions)`** — Triggers the mutation. Accepts an optional `onSuccess` callback invoked after successful completion.
  - **`isPending`** — Boolean flag (aliased from Relay's `isInFlight`) indicating whether the mutation is currently executing.

## Usage Example

```typescript
import { useResumeSubscription } from '@/hooks/use-resume-subscription';

function BillingPanel() {
  const { mutate, isPending } = useResumeSubscription();

  const handleResume = () => {
    mutate({
      onSuccess: () => {
        console.log('Subscription resumed, navigating back to billing overview');
      },
    });
  };

  return (
    <button onClick={handleResume} disabled={isPending}>
      {isPending ? 'Resuming…' : 'Resume Subscription'}
    </button>
  );
}
```

## Notes

Since the mutation returns only a `Boolean` with no updated entity data, Relay cannot auto-update the normalized store. On success, the hook calls `commitLocalUpdate(environment, store => store.invalidateStore())` to force every subscription-derived query (billing page, feature lock guards, usage balance bars) to refetch fresh data instead of continuing to display the stale `PENDING_CANCELLATION` state. This mirrors the approach taken by the corresponding `useCancelSubscription` hook in the opposite direction.
