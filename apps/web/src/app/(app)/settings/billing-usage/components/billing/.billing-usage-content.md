# billing-usage-content.tsx

React/Relay client component implementing the Billing & Usage page: it fetches the tenant's subscription and billing plan via GraphQL, then composes the page from independently-loading sub-components (plan cards, AI balance, auto top-up, token packs, device overage) while handling loading, missing-subscription, and read-only states.

## Key Components

- **`BillingUsageContent`** — Public entry point. Wraps the page in a `LoadingSuspense` boundary gated by an external `loading` flag, rendering `BillingUsageReader` once ready.
- **`BillingUsageReader`** — Detects whether it's inside a loading scope (fallback/gate) and either renders a skeleton (`BillingUsageScreen` with `data={null}`) or triggers the actual query via `BillingUsageQuery`.
- **`BillingUsageQuery`** — Runs `billingUsageContentQuery` with `react-relay`'s `useLazyLoadQuery`, using a `fetchKey` counter (`refreshKey`) to force refetches after mutations the Relay store can't reflect automatically (e.g., resume/cancel/plan-change/test-clock actions).
- **`BillingUsageScreen`** — The presentational core. Given `data` (or `null` while loading) and an `onRefetch` callback, it:
  - Resolves subscription status and read-only mode (`isBillingReadOnly`)
  - Determines if AI assistance/auto-top-up features should be offered (not on trial, not read-only)
  - Manages modal state for plan change, activation, cancellation, and AI balance management (synced to the `?action=` URL param via `useApiParams`)
  - Renders a `LockedScreen` if no subscription exists
  - Composes `BillingPageFrame` with header actions, `BillingSections`, notices (AI balance alert, auto top-up notice, purchased token packs, device overage), and modals (`ManageAiBalanceModal`, `UpgradePlanModal`, `ActivateSubscriptionModal`, `CancelSubscriptionFlow`)
- **`billingUsageContentQuery`** (GraphQL) — Fetches `billingPlan` and `subscription` (status, products) plus Relay fragment spreads consumed by child components.

## Usage Example

```typescript
import { BillingUsageContent } from './billing-usage-content';

// In a route/page component, optionally gated by an external loading flag
// (e.g., while resolving auth or feature flags)
export default function BillingPage({ isInitializing }: { isInitializing: boolean }) {
  return <BillingUsageContent loading={isInitializing} />;
}
```

Child components (`PaidAiTokensCard`, `AutoTopUpSection`, etc.) each own their own loading/error boundaries via `AutoTopUpIsland`, so the page degrades gracefully per-section rather than failing as a whole.
