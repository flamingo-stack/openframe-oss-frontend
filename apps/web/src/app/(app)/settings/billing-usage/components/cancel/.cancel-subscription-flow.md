# cancel-subscription-flow.tsx

Orchestrates the multi-step subscription cancellation experience as a sequence of three modal dialogs: capturing the cancellation reason, presenting a retention offer, and confirming the final cancellation outcome. It owns the step state and the data collected in the first dialog, passing it forward to the mutation triggered in the second.

## Key Components

- **`CancelSubscriptionFlow`** — Client component that renders three mutually-exclusive modals (`CancelSubscriptionModal`, `CancelOfferModal`, `SubscriptionCancelledModal`) based on an internal `Step` state (`'reason' | 'offer' | 'cancelled'`).
- **`cancelSubscriptionFlowFragment`** — GraphQL fragment (`cancelSubscriptionFlow_subscription`) fetching `cancellationEffectiveAt` and composing the `subscriptionPackage_subscription` fragment, used to determine end-date and package terms shown in the final dialog.
- **`CancelSubscriptionFlowProps`** — Props contract: `subscription` (Relay fragment key), `onClose`, `onChangePlan`, `onCancelled` callbacks.
- Relies on `useCancelSubscription` hook for the mutation and `hasSubscriptionPackage` helper to decide messaging in the cancelled-state modal.

## Usage Example

```typescript
import { CancelSubscriptionFlow } from './cancel-subscription-flow';

function SubscriptionPage({ subscription }: { subscription: any }) {
  const [isCancelFlowOpen, setCancelFlowOpen] = useState(false);

  return (
    <>
      <button onClick={() => setCancelFlowOpen(true)}>Cancel Subscription</button>

      {isCancelFlowOpen && (
        <CancelSubscriptionFlow
          subscription={subscription}
          onClose={() => setCancelFlowOpen(false)}
          onChangePlan={() => router.push('/plans')}
          onCancelled={() => refetchSubscription()}
        />
      )}
    </>
  );
}
```

**Note:** The component should only be mounted while the flow is active, ensuring each invocation starts fresh at the `'reason'` step with no prior selections carried over.
