# invoices-table-layout.ts

Defines the responsive column layout configuration for the Invoices History table, consumed by the column builder (`invoices-table-columns.tsx`) and shared between the real table header/rows and the loading skeleton state.

## Key Components

- **`INVOICE_COLUMNS`** — A `Record<string, TableSkeletonColumn>` describing each column's id, header label, width, sortability, and responsive `hideAt` breakpoint:
  - `invoiceNumber` — always visible, not sortable (acts as the row's primary identity).
  - `dueDate` — sortable, hidden below `lg` (first column dropped on narrow screens).
  - `amountDue` — always visible, sortable (core value of the row).
  - `status` — filterable (not sortable), hidden below `md`.
  - `actions` — always visible, fixed-width, right-aligned action column.
- **`INVOICES_SKELETON_ROWS`** — Constant (`3`) defining how many placeholder rows are rendered while invoice history loads, since Stripe returns the full unpaged list.

## Usage Example

```typescript
import { INVOICE_COLUMNS, INVOICES_SKELETON_ROWS } from './invoices-table-layout';

// Building table columns from the layout definition
function buildInvoiceColumns() {
  return Object.values(INVOICE_COLUMNS).map((column) => ({
    ...column,
    // apply header rendering, sort handlers, etc.
  }));
}

// Rendering skeleton rows while data loads
function InvoicesTableBody({ isLoading, invoices }) {
  if (isLoading) {
    return Array.from({ length: INVOICES_SKELETON_ROWS }).map((_, i) => (
      <DataTable.Body.LoadingRow key={i} columns={INVOICE_COLUMNS} />
    ));
  }

  return invoices.map((invoice) => (
    <DataTable.Body.Row key={invoice.id} columns={INVOICE_COLUMNS} data={invoice} />
  ));
}
```

Note: this table follows the standard responsive pattern used across the app (tickets, schedules, device tabs) — below `lg`, the header collapses into the core's compact filter toolbar (only `STATUS` survives as a filter), and columns progressively hide via `hideAt` rather than relying on custom width overrides.
