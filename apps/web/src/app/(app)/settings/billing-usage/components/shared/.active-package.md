# active-package.ts

Resolves the currently active package option from a subscription product's list of package options, using a Relay `@inline` fragment shared across multiple independent readers.

## Key Components

- **`activePackageFragment`** — A GraphQL `@inline` fragment (`activePackage_subscriptionProduct`) that selects `packageOptions` (`id`, `packageOptionId`, `quantity`, `status`) from a `SubscriptionProductDetail`. Marked `@inline` because it's consumed by plain functions/hooks rather than React components.
- **`ActivePackage`** — Interface describing the resolved active package:
  - `packageOptionId: string` — the catalog option the commitment was made against.
  - `quantity: number | null` — the number of devices covered.
- **`activePackage(ref)`** — Reads the inline fragment data from a given Relay key and returns the single `packageOptions` entry whose `status` is `SubscriptionProductStatus.ACTIVE`, or `null` if none exists.

## Usage Example

```typescript
import { activePackage } from './active-package';
import type { activePackage_subscriptionProduct$key } from '@/__generated__/activePackage_subscriptionProduct.graphql';

function DeviceAllocationSummary({ subscriptionRef }: { subscriptionRef: activePackage_subscriptionProduct$key }) {
  const active = activePackage(subscriptionRef);

  if (!active) {
    return <span>No active package</span>;
  }

  return (
    <span>
      Package {active.packageOptionId} covers {active.quantity ?? 'unlimited'} devices
    </span>
  );
}
```

This function is designed to be called from multiple consumers—such as a device counter, a plan picker's initial state, and a plan-change diff—ensuring all three agree on what "active" means by centralizing the lookup logic in a single, reusable place.
