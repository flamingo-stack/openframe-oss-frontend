# invoice-row.ts

Defines a shared Relay inline fragment and helper functions for rendering invoice rows consistently across the billing history table and the suspended-workspace lock screen, ensuring a single normalized shape for `PendingInvoice` records in the Relay store.

## Key Components

- **`invoiceRowFragment`** — A `@inline` GraphQL fragment on `PendingInvoice` selecting the fields needed by any invoice list view (`id`, `invoiceNumber`, `status`, `amountDue`, `dueDate`, `createdAt`, `hostedInvoiceUrl`). Being `@inline`, it can be read synchronously without a parent query, and guarantees both consumers fetch/normalize the same fields.
- **`InvoiceRow`** — A type alias derived from the generated fragment data (minus the `$fragmentType` key), representing the plain-data shape used by tables and lists for keying/sorting.
- **`toInvoiceRow(ref)`** — Reads the inline fragment data from a fragment reference and returns a plain `InvoiceRow` object.
- **`isOutstandingInvoice(invoice)`** — Determines whether an invoice is still unpaid. Treats `null` status (legacy, unreconciled entries) and `OPEN` (Stripe's "finalized, awaiting payment") as outstanding; all other statuses (`DRAFT`, `PAID`, `VOID`, `UNCOLLECTIBLE`) are considered non-payable or already settled.

## Usage Example

```typescript
import { toInvoiceRow, isOutstandingInvoice, type InvoiceRow } from './invoice-row';
import type { invoiceRow_invoice$key } from '@/__generated__/invoiceRow_invoice.graphql';

function renderInvoiceList(refs: invoiceRow_invoice$key[]) {
  const rows: InvoiceRow[] = refs.map(toInvoiceRow);

  return rows.map((invoice) => ({
    ...invoice,
    canPay: isOutstandingInvoice(invoice),
  }));
}
```

Use `invoiceRowFragment` inside a parent GraphQL query or fragment wherever `PendingInvoice` data is selected, then pass the resulting fragment reference to `toInvoiceRow` to obtain a plain object suitable for table rendering, sorting, or passing to `isOutstandingInvoice` to decide whether to show a "Pay now" action.
