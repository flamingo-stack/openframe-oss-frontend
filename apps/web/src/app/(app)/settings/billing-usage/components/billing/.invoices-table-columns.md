# invoices-table-columns.tsx

Defines the column configuration for the invoices data table, including cell renderers for invoice number/date, due date, amount, lifecycle status, and a link-to-Stripe action column. Also provides helpers for deriving sortable/filterable values from raw invoice rows.

## Key Components

- **`statusTag(status)`** — Maps an `InvoiceStatus` (or `null`/legacy value) to a `StatusTag` (variant + label), exhaustively covering all enum values with `UNPAID` as the fallback for legacy rows.
- **`statusKey(invoice)`** — Returns the display label for a row's status, used as the accessor for filtering/grouping so visually identical tags (e.g., legacy `null` and `OPEN`) collapse into one filter option.
- **`dateSortValue(iso)`** — Converts an ISO date string to epoch milliseconds for sorting, returning `undefined` for missing/unparseable dates so they sort last regardless of direction.
- **`invoiceStatusOptions(invoices)`** — Builds the `DataTableFilterOption[]` for the status filter from statuses actually present in the data, not the full enum.
- **`InvoiceDate`, `InvoiceAmount`, `InvoiceStatusTag`** — Cell components that render loading skeletons via `useLoadingScope()` when the table is in a placeholder/loading state.
- **`invoiceColumns(statusOptions)`** — The main export; returns `ColumnDef<InvoiceRow>[]` for: invoice number + issue date, due date, amount, status (filterable), and an actions column linking to the hosted Stripe invoice (disabled button if no link exists yet).

## Usage Example

```typescript
import { invoiceColumns, invoiceStatusOptions } from './invoices-table-columns';
import { DataTable } from '@flamingo-stack/openframe-frontend-core/components/ui';

function InvoicesTable({ invoices }: { invoices: InvoiceRow[] }) {
  const statusOptions = invoiceStatusOptions(invoices);
  const columns = invoiceColumns(statusOptions);

  return <DataTable columns={columns} data={invoices} />;
}
```

Status options should be recomputed whenever the underlying `invoices` list changes, ensuring the filter always reflects statuses currently present in the table rather than retiring a user-selected option during a search.
