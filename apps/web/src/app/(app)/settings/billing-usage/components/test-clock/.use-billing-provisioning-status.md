Polls the tenant's billing provisioning state via GraphQL at a fixed interval, stopping automatically when the state reaches `READY`. Designed for the dev test-clock panel where Stripe customer teardown/rebuild makes billing data temporarily untrustworthy.

## Key Components

**`useBillingProvisioningStatus()`** — Primary exported hook returning:
- `status: ProvisioningStatus | null` — latest `{ state, message }` from the GraphQL endpoint
- `restart: () => void` — triggers a fresh polling cycle (call this after a tenant reset)

**Constants**
- `POLL_INTERVAL_MS` (`3000`) — delay between each poll
- `MAX_CONSECUTIVE_ERRORS` (`5`) — consecutive network failures tolerated before polling halts

**`billingProvisioningStatusQuery`** — Relay GraphQL query fetching `billingProvisioningStatus.state` and `billingProvisioningStatus.message`

## Behavior Notes

- Uses `fetchQuery` (not `useLazyLoadQuery`) so polls run **outside Suspense**, preventing the panel from blanking between requests
- Polling continues only while `state === BillingProvisioningState.PENDING`; any other state (including `READY`) stops the loop
- On cleanup or restart, the in-flight subscription is unsubscribed and any pending timer is cleared
- Errors are swallowed silently (preserving last known state on screen) up to `MAX_CONSECUTIVE_ERRORS`

## Usage Example

```typescript
import { useBillingProvisioningStatus } from './use-billing-provisioning-status';
import { BillingProvisioningState } from '@/generated/schema-enums';

function TestClockPanel() {
  const { status, restart } = useBillingProvisioningStatus();

  const handleReset = async () => {
    await triggerTenantReset();
    restart(); // re-start polling after teardown
  };

  if (status?.state === BillingProvisioningState.PENDING) {
    return <Spinner message={status.message} />;
  }

  return <BillingPanel onReset={handleReset} />;
}
```
