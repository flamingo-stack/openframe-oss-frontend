## cancellation-terms.tsx

Renders the cancellation terms section of a subscription-cancellation dialog, showing the effective end-of-access date and the applicable terms copy (package-based or pay-as-you-go), with loading placeholders while data resolves.

## Key Components

- **`cancellationTermsFragment`** — GraphQL fragment pulling `subscriptionCancellationPreview` and `subscription` (including `currentPeriodEnd` and the nested `subscriptionPackage_subscription` fragment) needed to determine the cancellation date and terms type.
- **`TERMS_LINES`** — Constant (`2`) controlling the number of skeleton lines rendered for the terms paragraph while loading.
- **`CancellationTerms`** — Default-exported component that:
  - Resolves the fragment via `useFragment` using the passed `query` key.
  - Determines loading state via `useLoadingScope()` or a null fragment result.
  - Checks `hasSubscriptionPackage` to decide between package-based terms (with a date) and pay-as-you-go terms (no date).
  - Displays `PAYG_CANCELLATION_TERMS` directly when not loading and no package is present.
  - Otherwise renders the "active until" date (preferring `subscriptionCancellationPreview`, falling back to `currentPeriodEnd`, formatted via `formatDate`) alongside `PACKAGE_CANCELLATION_TERMS`, using `LoadingLine` and `LoadingParagraph` as skeleton states.

## Usage Example

```typescript
import { CancellationTerms } from '@/app/components/cancellation/cancellation-terms';
import type { cancellationTerms_query$key } from '@/__generated__/cancellationTerms_query.graphql';

function CancellationDialog({ queryRef }: { queryRef: cancellationTerms_query$key | null }) {
  return (
    <div className="cancellation-dialog">
      <h2>Cancel Subscription</h2>
      <CancellationTerms query={queryRef} />
    </div>
  );
}
```

The component expects `query` to be `null` only transiently while the parent's Relay query is in flight; once resolved, it automatically switches between package and PAYG terms based on the underlying subscription data.
