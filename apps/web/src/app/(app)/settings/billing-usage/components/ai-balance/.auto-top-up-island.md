# auto-top-up-island.tsx

A self-contained UI "island" component that independently fetches and renders the auto top-up billing arrangement, isolating its loading and error states from the rest of the billing page.

## Key Components

- **`autoTopUpIslandQuery`** — GraphQL query fetching `autoTopUpSettings` (non-nullable, so one failed fetch can't null out the entire page payload). Relay deduplicates this query across multiple islands using the same variables.
- **`AutoTopUpIslandProps`** — Props interface:
  - `label: string` — identifies the island in error boundary console output
  - `fallback: ReactNode` — shown both during loading *and* on error (no distinct error UI)
  - `children: (status: AutoTopUpStatus) => ReactNode` — render-prop receiving the resolved status
- **`AutoTopUpIsland`** — The exported component. Wraps `QueryIsland` in a `Suspense` boundary and a `ContentErrorBoundary`, ensuring that a failed or pending fetch never bubbles up to break the surrounding page. Passes `skipSubscriptionGate: true` in network cache metadata so this data remains available even when the subscription gate would otherwise block requests (e.g., `PAST_DUE` state).

## Usage Example

```typescript
import { AutoTopUpIsland } from './auto-top-up-island';

function BillingCard() {
  return (
    <AutoTopUpIsland
      label="billing-card-auto-top-up"
      fallback={<AutoTopUpSkeleton />}
    >
      {status => (
        <AutoTopUpSummary enabled={status.enabled} threshold={status.threshold} />
      )}
    </AutoTopUpIsland>
  );
}
```

**Key behavior:** If the query fails or is still loading, `fallback` is rendered in both cases — there's no separate error state, since a decorative feature failing shouldn't alarm the user with an error card. The `children` render-prop only executes once data resolves successfully, receiving a normalized `AutoTopUpStatus` via `toAutoTopUpStatus`.
