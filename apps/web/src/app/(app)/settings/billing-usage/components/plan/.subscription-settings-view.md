Renders the paywall: the plan form a locked workspace gets instead of the app, for both the "update existing subscription" and "new checkout" flows.

## Key Components

| Export / Symbol | Description |
|---|---|
| `SubscriptionSettingsView` | Public entry point. Takes `loading` (a gate above it, the billing role check, still resolving). One body for every wait: a `GatedSuspense` draws `PaywallBody` with no catalog in a loading scope while the gate resolves (the query is not sent) and while the catalog query is in flight. A thrown query degrades to `WorkspaceInactiveScreen` |
| `SubscriptionSettingsContent` | Internal: reads the catalog (`useLazyLoadQuery`, skipping the subscription gate) and renders `PaywallBody` |
| `PaywallBody` | The single layout: header, plan cards, total summary and submit controls, the same whether or not the data has landed (each part draws its own loading state) |
| `subscriptionSettingsViewQuery` | Relay query spreading the body's fragment |

## Usage Example

```typescript
import { SubscriptionSettingsView } from './subscription-settings-view';

// Inside the subscription lock: draw the paywall in its loading state until the role check answers.
<SubscriptionSettingsView loading={access === 'loading'} />;
```

## Behaviour Notes

- **Checkout vs. update flow**: when subscription status is `TRIAL`, `TRIAL_EXPIRED`, or `CANCELED`, changes go through Stripe Checkout rather than a mutation diff.
- **Responsive submit bar**: desktop uses an inline flex row; mobile uses a `fixed` bottom bar, its room reserved by the page's own `pb-28`.
