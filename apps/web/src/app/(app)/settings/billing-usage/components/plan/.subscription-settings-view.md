# subscription-settings-view.tsx

Renders the paywall screen shown to workspaces with a locked/inactive subscription, letting users select a plan and submit a checkout or subscription update. It renders its own content during loading (no separate skeleton) so the layout stays in sync with the live data state.

## Key Components

- **`SubscriptionSettingsView`** — Top-level exported component. Wraps the paywall in a `PageLayout` and an `ErrorBoundary` (falling back to `WorkspaceInactiveScreen`), so a failed or refused catalog query degrades gracefully instead of crashing the lock screen.
- **`SubscriptionSettingsContent`** — Wraps the reader in `LoadingSuspense`, gating it on the `loading` prop (e.g., feature flag / role checks upstream).
- **`SubscriptionSettingsReader`** — Detects whether it's inside a loading scope (via `useLoadingScope`) and either renders `PaywallBody` with `query={null}` (pending state) or defers to `SubscriptionSettingsLive`.
- **`SubscriptionSettingsLive`** — Issues the `subscriptionSettingsViewQuery` GraphQL query via `useLazyLoadQuery`, explicitly skipping the subscription gate on this network request (since this *is* the lock screen's own data).
- **`PaywallBody`** — Core layout: renders plan subtitle, outstanding invoices notice, plan checkout cards, totals summary (desktop and mobile), and the submit button. Built on top of `usePlanCheckout` for form state, shared with the billing page's "Activate Subscription" modal.

## Usage Example

```typescript
import { SubscriptionSettingsView } from '@/app/(paywall)/subscription-settings-view';

export default function SubscriptionLockPage() {
  return <SubscriptionSettingsView loading={false} />;
}
```

The `loading` prop is typically driven by upstream gates (e.g., feature-flag resolution) before the component's own GraphQL query runs:

```typescript
const { data: featureFlag, loading: flagLoading } = useFeatureFlag('subscription-lock');

<SubscriptionSettingsView loading={flagLoading} />
```

Internally, the component reads subscription status via `useSubscriptionLock` to determine whether the user needs a new Stripe Checkout (trial, trial-expired, canceled) versus updating an existing paid subscription, and redirects to `routes.settings.billingUsage()` after a successful update.
