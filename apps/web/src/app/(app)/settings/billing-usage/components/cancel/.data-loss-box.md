# data-loss-box.tsx

A client-side React component that renders a warning box informing users that their data will become inaccessible once their subscription ends. It automatically hides itself when no data-loss rows are present, combining pre-rendered `children` rows with asynchronously-loaded module rows.

## Key Components

- **`DataLossBox`** — Default export, a functional component accepting `children: ReactNode`. Renders:
  - A warning header (icon + message) using `AlertCircleIcon` from `@flamingo-stack/openframe-frontend-core`.
  - A `role="list"` container that combines the passed-in `children` with `<DataLossModuleRows />` (loaded independently, likely via Suspense).
  - Self-hiding behavior via the CSS selector `[&:not(:has([role=listitem]))]:hidden` — the box disappears entirely if no list items are rendered.

## Implementation Notes

- The list container uses `div` instead of `ul` because loading rows render inside Suspense fallback regions (which are `div`s, incompatible with `ul`/`li` semantics). The `[&>div:not([role])]:contents` rule flattens these wrapper divs so the flex `gap` spacing applies uniformly to loading and loaded rows alike.
- The outer container uses `shrink-0` as a **functional requirement**, not a defensive default: because the box has `overflow-hidden` (for clipping the rounded header), it loses the automatic flex-item minimum size protection. Without `shrink-0`, the box could collapse to a sliver inside a scrolling flex column instead of forcing the column to scroll.

## Usage Example

```typescript
import { DataLossBox } from './data-loss-box';
import { DataLossRow } from './data-loss-row';

function SubscriptionWarning() {
  return (
    <DataLossBox>
      <DataLossRow role="listitem" label="Device inventory" />
      <DataLossRow role="listitem" label="Ticket history" />
    </DataLossBox>
  );
}
```

The box renders only if at least one `role="listitem"` child (static or from `DataLossModuleRows`) is present in the DOM, making it safe to always include in a component tree even when data-loss content may be empty.
