# plan-sections.tsx

Renders the billing plan overview for a subscription, showing the current plan alongside an upcoming scheduled plan (if one exists). Handles loading and trial states, and adapts its layout based on whether a pending plan transition is present.

## Key Components

- **`PlanSections`** — Main component that composes `CurrentPlanSection` and conditionally `UpdatedPlanSection` based on subscription schedule state.
- **`PlanSectionsProps`** — Props interface accepting Relay fragment keys for `subscription` and `billingPlan` (both nullable while loading).
- **`planSectionsSubscriptionFragment`** / **`planSectionsBillingPlanFragment`** — GraphQL fragments composing child component fragments for `CurrentPlanSection`, `UpdatedPlanSection`, and `planSchedule`.

## Behavior

- While loading (`useLoadingScope()` true or `subscription` is `null`), renders a single-column grid with `CurrentPlanSection` in its own loading state.
- Returns `null` entirely for trial subscriptions, since trials have no plan to display (billing starts on activation).
- Once data resolves, uses `planSchedule(data)` to determine `hasPendingPlan`:
  - If `false`, only `CurrentPlanSection` is shown, spanning the full width.
  - If `true`, the grid switches to two columns (at the `content-md` breakpoint) showing `CurrentPlanSection` beside `UpdatedPlanSection`.

## Usage Example

```typescript
import { PlanSections } from './plan-sections';

function BillingOverviewPage({ subscriptionRef, billingPlanRef }) {
  return (
    <PlanSections
      subscription={subscriptionRef}
      billingPlan={billingPlanRef}
    />
  );
}
```

Typically used within a billing/settings page where `subscriptionRef` and `billingPlanRef` are Relay fragment references passed down from a parent query, and may be `null` during the initial render pass.
