# employee-details-view.tsx

A page-level component that renders the employee details view, designed to isolate data-fetching boundaries so that only the parts of the UI dependent on the employee record suspend while loading.

Unlike a standard `PageLayout` (which takes a title prop and would suspend the entire page when the title depends on record data), this component draws its own container and places the `TitleBlock` inside the suspending content area. The `EmployeeWorkTime` section fetches independently by `userId` and renders alongside—not behind—the employee record content, allowing its query to run in parallel rather than being blocked by the record fetch.

## Key Components

- **`EmployeeDetailsView`** — Default export; client component accepting a `userId` prop that lays out the employee details page.
- **`ContentErrorBoundary`** — Wraps the record-dependent content, providing error/suspense handling scoped to just that section, keyed by `userId` for proper reset on navigation.
- **`EmployeeDetailsContent`** — Renders the employee record details (including title) within the error boundary.
- **`EmployeeWorkTime`** — Renders work time data for the employee, fetched independently and positioned outside the error boundary.

## Usage Example

```typescript
import { EmployeeDetailsView } from '@/app/components/employee-details/employee-details-view';

export default function EmployeePage({ params }: { params: { userId: string } }) {
  return <EmployeeDetailsView userId={params.userId} />;
}
```

**Layout behavior:** The component uses a vertical flex layout with system spacing tokens (`--spacing-system-l`) to separate the employee details section from the work time section below it, ensuring consistent spacing regardless of which section finishes loading first.
