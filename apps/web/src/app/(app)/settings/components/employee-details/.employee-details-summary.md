# employee-details-summary.tsx

Renders the summary card for an employee details page, displaying avatar, name, email, role, and status. Handles three distinct states: loading (null fragment reference), active user, and deleted user (with different layouts and field visibility for each).

## Key Components

- **`EmployeeDetailsSummary`** — Main component that accepts a `employeeDetailsSummary_user$key | null` fragment reference and renders the appropriate card layout.
- **`employeeDetailsSummaryFragment`** — GraphQL fragment pulling `roles`, `status`, and composing `userSummaryFields_user` for shared summary fields (name, email, avatarUrl, deleted).
- **`NO_SUMMARY`** — Fallback values used while the record is loading, allowing child components (`InfoCell`, avatars) to render their own loading/empty states.

## Usage Example

```typescript
import { EmployeeDetailsSummary } from '@/app/components/employees/employee-details-summary';

function EmployeePage({ userRef }: { userRef: employeeDetailsSummary_user$key | null }) {
  return (
    <section>
      <EmployeeDetailsSummary user={userRef} />
    </section>
  );
}
```

**Behavior notes:**
- When `user` is `null` (still loading), all fields render in an empty/loading state via `InfoCell` and avatar placeholders.
- When `data.deleted` is `true`, the card collapses to a single row (avatar, name, status) and drops the role row. Email is shown only if present (admin-deleted users retain it; self-deleted users have it anonymized server-side).
- Active (non-deleted) users render a two-row layout: avatar/name/email on top, role/status below a bordered divider.
- Avatar sizing is manually overridden with responsive Tailwind classes (`h-9 w-9` on mobile, `content-md:h-12 content-md:w-12` on larger screens) since the underlying `SquareAvatar`/`DeletedUserAvatar` components only expose fixed size buckets.
