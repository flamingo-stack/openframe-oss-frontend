# employee-details-content.tsx

Client component that fetches and renders a single employee's details page, splitting it into a header and summary card while coordinating loading state and Mingo's "open view" context tracking.

The component resolves a user by `id` via a GraphQL query, gracefully handles not-found cases, and reports the viewed entity to Mingo's context system so the AI assistant stays aware of what the user is currently viewing.

## Key Components

- **`employeeDetailsContentQueryNode`** — GraphQL query fetching a `User` node by global ID, spreading fragments for the summary, header, and card fragments.
- **`EmployeeDetailsContent`** — Top-level exported component; wraps the reader in a `LoadingSuspense` boundary with a "Loading employee" label.
- **`EmployeeDetailsReader`** — Detects whether the surrounding boundary is in its loading fallback (`useLoadingScope`) and, if so, renders skeleton versions of the header/summary and reports a `null` open view instead of mounting the query.
- **`EmployeeDetailsQuery`** — Executes `useLazyLoadQuery` with `store-and-network` fetch policy and a retry key, resolves the `User` node, converts it via `toUserSummary`, tracks it as the Mingo open view, and renders `EmployeeDetailsHeader`/`EmployeeDetailsSummary` or a `NotFoundError`.

## Usage Example

```typescript
import { EmployeeDetailsContent } from './employee-details-content';

export default function EmployeePage({ params }: { params: { userId: string } }) {
  return <EmployeeDetailsContent userId={params.userId} />;
}
```

The component expects `userId` as a raw (non-global) identifier; it converts it internally with `toGlobalId('User', userId)` before querying. Any resolved user status (including deleted users) renders normally, while an unresolvable id surfaces a `NotFoundError`.
