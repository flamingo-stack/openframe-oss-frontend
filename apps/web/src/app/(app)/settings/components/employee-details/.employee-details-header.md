# employee-details-header.tsx

Renders the header for an employee's detail page, using the page title bar itself as a dynamic "is this me or someone else?" view: it shows actions to edit/delete your own profile (mirroring the `/settings` flow, owner transfer included) or delete another user, with guardrails preventing deletion of the account owner or an already-deleted user.

## Key Components

- **`EmployeeDetailsHeader`** — Main exported component. Accepts a `user` Relay fragment key (or `null` for unknown/loading states) and renders a `TitleBlock` with a back button and contextual menu actions.
- **`employeeDetailsHeaderFragment`** — GraphQL fragment pulling `roles` and spreading `userSummaryFields_user` and `confirmDeleteUserModal_user` fragments.
- **`HeaderDialog`** — Internal type (`'edit' | 'delete' | 'delete-account'`) tracking which modal is currently open.

## Behavior Notes

- While loading or when `user` is `null`, the title falls back to an empty string (loading scope draws its own skeleton bar) or `EMPLOYEE_DETAILS_TITLE`.
- `isSelf` is derived by comparing the viewed user's `rawId` against the authenticated user from `useAuthStore`.
- Delete is disabled if the user is already `deleted`, or (for other users) if they hold the `OWNER` role.
- Depending on `isSelf`, renders either `EditProfileModal` + `DeleteAccountModal`, or `ConfirmDeleteUserModal`.

## Usage Example

```typescript
import { EmployeeDetailsHeader } from './employee-details-header';
import { useFragment } from 'react-relay';

function EmployeeDetailsPage({ queryRef }: { queryRef: EmployeeDetailsQuery$key }) {
  const data = useFragment(employeeDetailsPageFragment, queryRef);

  return (
    <div>
      <EmployeeDetailsHeader user={data?.user ?? null} />
      {/* rest of employee detail page content */}
    </div>
  );
}
```

The component is typically rendered at the top of an employee details route, consuming a Relay fragment reference resolved by the parent query (e.g., in `app/(authenticated)/settings/employees/[id]/page.tsx`).
