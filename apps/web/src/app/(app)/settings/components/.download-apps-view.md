# download-apps-view.tsx

Client component that mounts the shared `<DownloadAppsPage>` from the component library to render the "Get OpenFrame Apps" screen within Settings, reusing the same download page served publicly at `/download`.

## Key Components

- **`DownloadAppsView`** — Default/named export; a thin wrapper component that configures and renders `DownloadAppsPage` with app-specific behavior:
  - Wraps content in `PAGE_SHELL_OVERRIDE` styling since `shell={false}` is passed (the parent `AppLayout` already supplies the page `<main>`).
  - Fetches all data (installers, install commands, store listings, QR code) in one request via `EP.downloads`.
  - Provides a back button linking to `routes.settings.root()`.
  - Uses `useIsDesktopShell()` to hide the desktop install section when already running inside the desktop app (`showDesktop={!desktopShell}`), while still allowing the underlying data fetch to run (needed by the mobile section).
  - Uses `useSameWindowLinks()` combined with `desktopShell` to decide whether store links should force `target="_blank"` (`openStoresInNewTab`), ensuring app store links always escape the desktop shell into a system browser.

## Usage Example

```typescript
// Rendered as a settings sub-page, e.g. in a route file:
import { DownloadAppsView } from '@/app/(app)/settings/download-apps-view';

export default function Page() {
  return <DownloadAppsView />;
}
```

This component requires no props — all configuration (title, subtitle, endpoint, navigation behavior) is resolved internally via hooks and shared route/endpoint constants. It's intended to be rendered directly as a page body within an app layout that already provides the page shell.
