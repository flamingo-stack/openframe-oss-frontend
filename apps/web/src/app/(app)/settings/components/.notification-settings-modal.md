# Notification Settings Modal

A React/Relay modal component that lets users view and edit their per-account notification preferences, including a master enable/disable switch and per-group checkboxes. Built on `ModalV2` primitives with a Suspense-based loading flow that opens the modal instantly while data fetches in the background.

## Key Components

- **`NotificationSettingsModal`** — Public entry point. Renders the modal chrome (`ModalV2`, header, title) synchronously and delegates data-dependent content to `NotificationSettingsBody`, so the modal opens immediately on click rather than waiting for the network round-trip.
- **`NotificationSettingsBody`** — Wraps the data-reading tree in `LoadingSuspense` (live mode) so Cancel stays interactive during load.
- **`NotificationSettingsReader`** — Detects whether it's rendering inside the loading fallback scope and conditionally skips the GraphQL read.
- **`NotificationSettingsForm`** — Issues the `notificationSettingsModalQuery` via `useLazyLoadQuery` with `network-only` fetch policy (required since `NotificationSettings` has no `id` for Relay normalization).
- **`NotificationSettingsFormView`** — The actual form: master `Switch`, per-group `CheckboxBlock` list (server-driven labels/order), and save/cancel logic via `useMutation`.
- **`SettingsFooter`** — Shared Cancel/Save footer; Save is disabled until settings have loaded.
- **GraphQL operations**: `settingsQuery` (fetches `notificationSettings`), `updateSettingsMutation` (persists `enabled` + `typeSettings`).

## Usage Example

```typescript
import { useState } from 'react';
import { NotificationSettingsModal } from './notification-settings-modal';

function HeaderActions() {
  const [isOpen, setIsOpen] = useState(false);

  return (
    <>
      <button onClick={() => setIsOpen(true)}>Notification Settings</button>
      {isOpen && (
        <NotificationSettingsModal onClose={() => setIsOpen(false)} />
      )}
    </>
  );
}
```

**Important notes:**
- Group labels, order, and defaults come entirely from the server (`typeSettings`); do not re-derive them from the `NotificationSettingGroup` enum.
- Opted-out groups are filtered server-side before persistence/publishing (`NotificationBroadcaster.withoutOptedOut`), so toggling a group off suppresses future notifications immediately with no retroactive delivery when re-enabled.
- Each modal open triggers a fresh network fetch (no cache reuse), so a loading skeleton (`NOTIFICATION_GROUPS_SKELETON_ROWS`) is always shown briefly.
