# settings-hub.tsx

Renders the main Settings page hub, displaying a navigation grid of settings sections (AI/Guardrails, Architecture, Employees, API Keys, SSO, Download Apps, Troubleshooting, Billing & Usage), plus account/profile management, email verification, biometric login, and logout controls.

## Key Components

- **`SettingsHub`** — Default-exported page component composing the full settings experience.
- **`SETTINGS_NAV_ITEMS`** — Static array of navigation cards (`SettingsNavItem`), each with route, icon, title, description, and optional `badge`.
- **`USAGE_MENU_ITEM`** — Fallback card content that replaces "Billing & Usage" when billing UI is hidden (`isBillingHidden()`), pointing to the same route but with usage-only wording.
- **Visibility logic**:
  - `defaultItems` — filters nav items by build-time constants (OSS tenant mode for Architecture, mobile shell for Download Apps) so the loading skeleton matches final layout.
  - `visibleItems` — further filters by async feature-flag/access gates (`useFeatureFlagGate('billings')`, `useBillingAccessGate()`) for the Billing & Usage card.
  - `gatesResolved` — tri-state check ensuring gates have loaded before swapping from `defaultItems` to `visibleItems`.
- **Modals/cards rendered**: `AccountSettingsCard`, `EmailVerificationBanner`, `EmailVerificationModal`, `BiometricLoginCard`, `EditProfileModal`.
- **`handleResendVerification`** — Async handler calling `authApiClient.resendVerificationEmail`, surfacing success/error via `useToast`.

## Usage Example

```typescript
// Rendered as a page within the settings route segment
import { SettingsHub } from '@/app/(settings)/settings-hub';

export default function SettingsPage() {
  return <SettingsHub />;
}
```

The component self-manages all state (modals, gates, profile fetch via `useAuthStore`) — no props are required. It conditionally renders a "Log Out" button only in OSS tenant mode (`isOssTenantMode()`), since the Mingo-first shell exposes logout via its account menu instead.
