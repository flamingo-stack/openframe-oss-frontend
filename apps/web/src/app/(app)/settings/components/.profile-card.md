# profile-card.tsx

Renders the signed-in user's profile summary row with an actions menu for editing the profile, managing notification settings, resetting onboarding, and deleting the account. Handles loading/error states by distinguishing between the transient "store not yet populated" window and a genuinely terminal "no user data" condition.

## Key Components

- **`ProfileCard`** — Main component accepting an `onEditProfile` callback. Renders `UserIdentityRow` (avatar, name, email) with an `ActionsMenuDropdown` for profile actions.
- **Loading logic** — Combines `useLoadingScope()` and the absence of `user` in the auth store to compute a `loading` flag, avoiding a server/client hydration flash.
- **Error guard** — Uses `useAuthSession()` (not the store) to detect the one true error case: a resolved, authenticated session with no backing user object.
- **Conditional "Reset Onboarding"** — Only shown when `useCanResetOnboarding()` is true and the tenant is not in SaaS mode (SaaS onboarding is replayed via Mingo's chat menu instead).
- **Modals** — `NotificationSettingsModal`, `DeleteAccountModal`, and `ResetOnboardingDialog`, each mounted/controlled via local `useState` flags, wrapped in `ErrorBoundary` where needed.

## Usage Example

```typescript
import { ProfileCard } from './profile-card';

function AccountSettingsPage() {
  const handleEditProfile = () => {
    // open edit-profile flow, e.g. navigate or open a drawer
  };

  return (
    <div className="settings-section">
      <ProfileCard onEditProfile={handleEditProfile} />
    </div>
  );
}
```

The component relies on `useAuthStore` and `useAuthSession` being available in context (typically provided by the app's auth layout), so it should be rendered within an authenticated route tree.
