# settings-view.tsx

Client component that renders the Settings page with URL-synchronized tab navigation. The active tab is derived from the `tab` query parameter, with local state used only to avoid a visible flash when navigating back/forward.

> **Note:** This file is marked with a `TODO: delete if component is redundant` comment, suggesting it may be superseded by another implementation.

## Key Components

- **`SettingsView`** — Main exported component. Renders `SettingsTabNavigation` and `SettingsTabContent`, keeping the active tab in sync with the URL's `tab` search parameter.
- **`TabId`** — Type alias for `SettingsTab` from `@/lib/routes`.
- **`DEFAULT_TAB`** — Fallback tab (`'ai-settings'`) used when the URL parameter is missing or invalid.
- **`TAB_PARAM`** — Name of the query string parameter (`'tab'`) used to track the active tab.

## Usage Example

```typescript
import { SettingsView } from '@/components/settings/settings-view';

export default function SettingsPage() {
  return <SettingsView />;
}
```

Navigating to `/settings?tab=ai-settings` will activate the "AI Settings" tab. Clicking a different tab updates the URL via `router.replace`, keeping the URL as the single source of truth while avoiding a flash of the previous tab's content:

```typescript
// Tab switching updates both local state and the URL in one step
const handleTabChange = (tabId: string) => {
  setActiveTab(tabId as TabId);
  const params = new URLSearchParams(searchParams?.toString());
  params.set('tab', tabId);
  router.replace(`${pathname}?${params.toString()}`);
};
```

This pattern ensures tab state survives page refreshes and supports deep-linking to specific settings tabs.
