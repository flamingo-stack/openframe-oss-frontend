A client-side settings page view that manages URL-synchronized tab navigation for the settings section, reading and writing the active tab to the `tab` query parameter.

## Key Components

- **`SettingsView`** — Main exported component that renders the settings layout with tab navigation and content
- **`activeTab` state** — Tracks the currently selected settings tab, initialized from the URL `?tab=` param
- **`handleTabChange`** — Updates both local state and the URL (via `router.replace`) when the user switches tabs
- **`useEffect` sync** — Keeps active tab in sync with URL changes (e.g., browser back/forward navigation)
- **`DEFAULT_TAB`** — Falls back to `'ai-settings'` when no valid tab param is present in the URL

## Usage Example

```typescript
// Render the full settings view (typically in a settings page route)
import { SettingsView } from './settings-view';

export default function SettingsPage() {
  return <SettingsView />;
}

// Navigating to a specific tab programmatically:
// /settings?tab=ai-settings  → opens AI Settings tab
// /settings?tab=integrations → opens Integrations tab (if valid)
```

## Notes

- Marked `'use client'` — requires a client-side render boundary
- Tab IDs are validated against `getSettingsTabs()` before being applied; invalid values fall back to `DEFAULT_TAB`
