Renders the "ROLE" column cell in a users table, displaying a comma-separated list of a user's roles via a GraphQL Relay fragment, with built-in support for loading-state placeholders.

## Key Components

- **`employeeRolesCellFragment`**: A GraphQL fragment (`employeeRolesCell_user`) declared on the `User` type that selects the `roles` field, colocating data requirements with the component.
- **`EmployeeRolesCell`**: A client component that accepts a `user` prop (typed as the Relay fragment key `employeeRolesCell_user$key`), resolves the fragment data via `useFragment`, and renders a `ValueText` component with the joined role names (or `null` while loading).

## Usage Example

```typescript
import { EmployeeRolesCell } from '@/app/components/employees/employee-roles-cell';
import { graphql } from 'react-relay';

// Parent query/fragment must spread the cell's fragment on each user row
const usersTableFragment = graphql`
  fragment usersTable_query on Query {
    users {
      id
      ...employeeRolesCell_user
    }
  }
`;

function UsersTableRow({ user }: { user: any }) {
  return (
    <tr>
      <td>{user.id}</td>
      <td>
        <EmployeeRolesCell user={user} />
      </td>
    </tr>
  );
}
```

**Loading state:** When rendered within a loading scope (e.g., while a row's data is still being fetched via Relay's `@loading` directive or a suspense boundary), `useLoadingScope()` returns `true`, causing the component to skip reading the fragment and pass `null` to `ValueText`, which displays an appropriate placeholder instead of throwing or suspending unexpectedly.

**Note:** This component relies on Relay's compiler-generated types (`employeeRolesCell_user$key`) found in `@/__generated__/`, so the GraphQL schema and fragment must be compiled before type-checking succeeds.
