# invitations-listing.ts

Relay store helper utilities for managing the invitations list connection, used by mutations that need to update or invalidate the paginated invitations table from outside its component tree.

## Key Components

- **`INVITATIONS_CONNECTION_KEY`** - Constant matching the `@connection` key defined on the invitations list table's GraphQL query.
- **`invitationsListingId(search, filter?)`** - Computes the Relay store connection ID for a given search term and filter combination, allowing mutations to locate the correct connection record.
- **`affectedInvitationsListings(onScreenId)`** - Returns a deduplicated list of connection IDs affected by a mutation: the currently displayed listing plus the default unfiltered listing (so clearing search/filters never reveals stale data).
- **`decrementInvitationsCount(store, listingIds)`** - Decrements the `filteredCount` field on each given listing (floored at 0), used after an invitation edge is removed via `@deleteEdge`.
- **`invalidateInvitationsListings(store, listingIds)`** - Marks the given listing records as stale via `invalidateRecord()`, forcing Relay to refetch them rather than attempting to manually patch in new edges—since matching/sorting logic lives server-side.

## Usage Example

```typescript
import {
  invitationsListingId,
  affectedInvitationsListings,
  decrementInvitationsCount,
  invalidateInvitationsListings,
} from './invitations-listing';

// Inside a Relay mutation updater function:
function updater(store: RecordSourceProxy) {
  const onScreenId = invitationsListingId(currentSearch, currentFilter);
  const listingIds = affectedInvitationsListings(onScreenId);

  // After revoking an invitation (edge removed via @deleteEdge):
  decrementInvitationsCount(store, listingIds);

  // After creating new invitations:
  invalidateInvitationsListings(store, listingIds);
}
```

This pattern ensures that whether a user is viewing a filtered or unfiltered invitations table, mutations keep both the visible listing and the default listing consistent and in sync with the server.
