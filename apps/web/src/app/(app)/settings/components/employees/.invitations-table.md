# invitations-table.tsx

Renders the invitations table within the employees/invitations listing, mapping each `Invitation` GraphQL node to a row with email, roles, status, and actions cells, and hosting the row-action dialog (resend, revoke, etc.).

## Key Components

- **`invitationsTableFragment`** — Relay plural fragment declaring the fields each row needs (`id` plus spreads for email, roles, status, actions, and dialog sub-fragments).
- **`InvitationRow`** — Type alias for a single element of the fragment's data array.
- **`buildColumns(filterOptions, onAction)`** — Builds the `ColumnDef[]` for user/email, roles, status, and actions columns, wiring in filter options and the row-action callback.
- **`emptyState(search, isFiltered)`** — Produces contextual empty-state copy depending on whether a search term or filter is active.
- **`InvitationsTable`** — Main exported component. Resolves the fragment, manages column filters (synced to server-side funnel `selections`), shows placeholder rows while `useLoadingScope()` reports loading, renders `LiveTable`, and conditionally renders `InvitationDialog` for the active row action.

## Usage Example

```typescript
<InvitationsTable
  rows={invitationRowRefs}
  totalCount={queryData.invitations.totalCount}
  search={search}
  isFiltered={selections.roles.length > 0 || selections.status.length > 0}
  filterOptions={filterOptions}
  selections={selections}
  onSelectionsChange={setSelections}
  listingIds={[listingId]}
  isPending={isRefetching}
  stickyHeaderOffset="64px"
  infiniteScroll={infiniteScrollFooter}
/>
```

The parent component (e.g. an employees listing page) owns the query, pagination, and search/filter state, and passes the fetched `invitationsTable_invitation$key` fragment reference along with derived metadata. `InvitationsTable` itself owns row shape, cell rendering, and the row-action dialog lifecycle via `useRowDialog`.
