## invite-refusals.ts

Utility module for parsing and formatting the partial-failure responses returned by the `inviteUsers` mutation, mapping GraphQL field-path refusals back to the originating email addresses.

## Key Components

- **`InviteRefusal`** — Internal interface describing a single refusal as reported by `inviteUsers`, where `field` is a path like `["emails", "<index>"]` pointing to the rejected entry, and `message` is the human-readable reason.
- **`refusedEmailIndexes(refusals)`** — Extracts the numeric indexes (within the submitted emails list) of entries that were refused, returned as a `Set<number>`. Used to mark which inputs failed.
- **`describeInviteRefusals(emails, refusals)`** — Builds a single toast-friendly string summarizing all refusals as `"email: reason"` pairs joined by `; `, prefixed with `"Not sent: "`. Returns `null` when there are no refusals (i.e., all invites succeeded).

## Usage Example

```typescript
import { refusedEmailIndexes, describeInviteRefusals } from './invite-refusals';

const emails = ['alice@example.com', 'bob@example.com', 'carol@example.com'];

const refusals = [
  { field: ['emails', '1'], message: 'Already invited' },
  { field: ['emails', '2'], message: 'Invalid domain' },
];

// Determine which input rows to flag in the UI
const failedIndexes = refusedEmailIndexes(refusals);
// => Set { 1, 2 }

// Build a toast message for the user
const toastMessage = describeInviteRefusals(emails, refusals);
// => "Not sent: bob@example.com: Already invited; carol@example.com: Invalid domain"

if (toastMessage === null) {
  console.log('All invitations sent successfully.');
} else {
  showToast(toastMessage);
}
```
