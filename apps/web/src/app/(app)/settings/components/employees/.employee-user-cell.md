A React component that renders the "USER" table column cell, displaying an employee's avatar, name, and email, with built-in support for loading states and deleted-user handling.

## Key Components

- **`EmployeeUserCell`** — The main exported component. Accepts a `user` prop (a Relay fragment reference of type `employeeUserCell_user$key`) and renders a compact avatar + name/email layout.
- **`employeeUserCellFragment`** — The GraphQL fragment (via `graphql` tag) that spreads `userSummaryFields_user` to fetch the data needed to build the user summary.
- Relies on `useLoadingScope` to detect whether the row is still loading (skipping the fragment read and rendering a loading-friendly empty state).
- Uses `toUserSummary` to normalize fragment data into a `summary` object (`name`, `email`, `avatarUrl`, `deleted`).
- Renders `DeletedUserAvatar` for deleted users, or `SquareAvatar` otherwise, alongside `TruncateText` for name and (conditionally) email.

## Usage Example

```typescript
import { EmployeeUserCell } from '@/app/components/shared/employee-user-cell';
import { graphql, useFragment } from 'react-relay';

// Typically used as a cell renderer inside a table column definition,
// where `row` provides a fragment reference matching employeeUserCell_user$key
function UserColumnCell({ row }: { row: employeeUserCell_user$key }) {
  return <EmployeeUserCell user={row} />;
}
```

**Notes:**
- When the row is in a loading scope, `user` is effectively ignored and the component renders with `summary` as `null`, producing empty placeholders for avatar/name/email.
- Email is only rendered when `summary.email !== null`. This distinguishes self-deleted users (whose email is nulled as a placeholder) from admin-deleted users (whose real email is preserved and shown).
- Styling uses Tailwind utility classes with design-system CSS variables (e.g., `var(--spacing-system-xs)`) for consistent spacing.
