Renders a paginated, searchable, filterable table of a tenant's users using Relay for data fetching, with a loading-state placeholder and infinite scroll support.

## Key Components

- **`UsersListTable`** — Top-level exported component that wraps the data-fetching logic in a `LoadingSuspense` boundary, giving the table its own suspense scope.
- **`UsersListReader`** — Checks `useLoadingScope()` to decide whether to render a placeholder `UsersTable` (empty rows, no filters) while in a loading/fallback state, or delegate to `UsersListQuery` for real data.
- **`UsersListQuery`** — Executes the Relay query (`usersListTableQuery`) and consumes the paginated connection fragment (`usersListTable_query`) via `usePaginationFragment`, mapping edges to rows and wiring up infinite scroll (`loadNext`, `hasNext`, `isLoadingNext`).
- **`usersListTableQueryNode`** / **`usersListTableFragment`** — GraphQL query and refetchable fragment definitions backing the `users` connection, including server-side filtering and search.

## Usage Example

```typescript
import { UsersListTable } from './users-list-table';

function EmployeesPage() {
  const [selections, setSelections] = useState(NO_EMPLOYEE_FILTER_OPTIONS);
  const [search, setSearch] = useState('');

  return (
    <UsersListTable
      search={search}
      backendSelections={selections}
      selections={selections}
      onSelectionsChange={setSelections}
      isPending={false}
      stickyHeaderOffset="64px"
    />
  );
}
```

Pass `backendSelections` (deferred, drives the query) separately from `selections` (live, drives header checkmarks) to keep filter UI responsive while a refetch is in flight. The `isPending` flag indicates a deferred search/filter update is lagging behind the displayed rows.
