# invitation-actions-cell.tsx

Renders a per-row actions menu for invitation table entries, exposing status-dependent actions (revoke, resend, remove) via a dropdown menu. Designed to work within a Relay fragment-based table that supports deferred/loading-scope rendering.

## Key Components

- **`InvitationActionsCell`** — Component that reads invitation status via a Relay fragment and renders an `ActionsMenuDropdown` with context-appropriate actions:
  - `EXPIRED` status → `Resend` and `Remove` (danger) actions
  - Any other status (pending) → `Revoke` (danger) action only
- **`InvitationAction`** — Union type (`'revoke' | 'resend' | 'remove'`) representing the possible actions emitted by the cell.
- **`invitationActionsCellFragment`** — GraphQL fragment declaring the `status` field required from the `Invitation` type.

## Usage Example

```typescript
import { InvitationActionsCell, type InvitationAction } from './invitation-actions-cell';

function InvitationRow({ invitation }: { invitation: invitationActionsCell_invitation$key }) {
  const handleAction = (action: InvitationAction) => {
    if (action === 'revoke') {
      // open revoke confirmation dialog
    } else if (action === 'resend') {
      // trigger resend mutation
    } else if (action === 'remove') {
      // open remove confirmation dialog
    }
  };

  return (
    <InvitationActionsCell
      invitation={invitation}
      onAction={handleAction}
    />
  );
}
```

**Notes:**
- When rendered inside a loading scope (e.g., Suspense boundary for table rows), the component short-circuits fragment reading and renders an inert menu trigger instead of suspending.
- The `onAction` callback is intentionally owned by the parent table rather than the row itself — see `useRowDialog` for the rationale (dialogs must be controlled at the table level, not per-row).
- The wrapping `div` uses `data-no-row-click` to prevent the row's own click handler from firing when interacting with the menu.
