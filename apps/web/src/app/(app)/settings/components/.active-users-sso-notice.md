This file renders an inline, data-driven notice showing the number of active users who will be affected when switching to SSO authentication. It's designed to be embedded inside a confirmation dialog's description text.

## Key Components

- **`GENERIC_SSO_NOTICE`** — Exported fallback string used when the active user count is unavailable (loading or error state).
- **`ActiveUsersSsoNotice`** — Main exported component. Wraps the data-fetching logic in a `LoadingSuspense` boundary rendered as an inline `span`, ensuring no block-level layout disruption.
- **`ActiveUsersSsoNoticeReader`** — Internal component that checks `useLoadingScope()` to detect if it's rendering inside a suspense fallback; if so, it short-circuits to the generic notice text instead of triggering a new query.
- **`ActiveUsersSsoNoticeQuery`** — Internal component that executes the GraphQL query (`activeUsersSsoNoticeQuery`) via `useLazyLoadQuery`, fetching the count of `ACTIVE` users with a `network-only` fetch policy, and returns a pluralized sentence with the live count.

## Usage Example

```typescript
import { ActiveUsersSsoNotice, GENERIC_SSO_NOTICE } from './active-users-sso-notice';

function SsoConfirmationDialog() {
  return (
    <p>
      Enabling SSO will change how your team signs in. <ActiveUsersSsoNotice />
    </p>
  );
}
```

The component requires no props. It automatically:
1. Shows `GENERIC_SSO_NOTICE` while the count is loading or during suspense fallback.
2. Fetches and displays the exact active user count (e.g., "5 users will switch to signing in through SSO providers.") once resolved.
3. Correctly pluralizes "user"/"users" based on the count.

This pattern keeps the dialog's description text flowing naturally as a single sentence, regardless of the data-fetching state.
