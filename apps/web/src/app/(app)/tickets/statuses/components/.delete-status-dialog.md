A confirmation dialog component that handles ticket status deletion by requiring users to select a replacement status before proceeding, preventing orphaned tickets.

## Key Components

### `DeleteStatusDialog`

The primary exported component. Renders a modal dialog that:

- Displays the name of the status being deleted
- Presents a dropdown of available replacement statuses (with color swatches)
- Auto-selects the first available option when the dialog opens
- Disables the confirm button until a valid replacement is selected or while the operation is pending

### `DeleteStatusDialogProps`

| Prop | Type | Description |
|---|---|---|
| `isOpen` | `boolean` | Controls dialog visibility |
| `onClose` | `() => void` | Callback to dismiss the dialog |
| `statusName` | `string` | Name of the status being deleted |
| `options` | `ReplacementOption[]` | Available replacement statuses |
| `onConfirm` | `(replacementStatusId: string) => void` | Called with the selected replacement ID on confirm |
| `isPending` | `boolean` | Disables actions while a delete mutation is in-flight |

## Usage Example

```typescript
<DeleteStatusDialog
  isOpen={isDeleteOpen}
  onClose={() => setDeleteOpen(false)}
  statusName="In Progress"
  options={replacementOptions} // [{ id, name, color }]
  onConfirm={(replacementId) => deleteStatus({ id: targetId, replacementId })}
  isPending={isDeletingStatus}
/>
```

## Notes

- Replacement selection auto-resets to the first available option each time the dialog opens via a `useEffect` on `isOpen`
- The **Delete** button remains disabled if no replacement is selected (`replacementId.length === 0`) or while `isPending` is `true`
