# ticket-statuses-view.tsx

Client-side page component that renders the Ticket Statuses configuration screen, allowing admins to view fixed system statuses and manage (add, reorder, rename, recolor, delete) custom ticket statuses within a single editable form.

## Key Components

- **`TicketStatusesView`** — Main exported component rendering the full page: a `PageLayout` with a save action, system status sections (top/bottom groups split by `TOP_KINDS`), a draggable/reorderable list of custom statuses, an "Add Status" button, and a confirmation dialog for deleting persisted custom statuses.
- **`LOADING_SYSTEM_STATUSES`** — Skeleton placeholder data derived from `SYSTEM_KIND_META`, used so each system status row renders its own loading skeleton while real data is fetched.
- **`createCustomStatus()`** — Factory producing a new blank `CustomTicketStatus` with a generated UUID and default color, used when appending a new row via `fieldArray.append`.
- **`renderSystemRow()`** — Helper rendering a read-only `TicketStatusConfigRow` for a system status (not editable, shows tooltip/tag variant).
- **`DELETE_DISABLED_REASON`** — Constant message shown when deletion is blocked because at least one custom status must remain.

## Usage Example

```typescript
import { TicketStatusesView } from './ticket-statuses-view';

// Typically rendered directly as a route/page component
export default function TicketStatusesPage() {
  return <TicketStatusesView />;
}
```

The component relies on `useTicketStatusesForm` for form state, field array management, and save/delete mutations, and `useSafeBack` for back-navigation to `routes.tickets.list`. Deleting a persisted custom status opens `DeleteStatusDialog`, requiring the user to choose a replacement status (via `replacementOptionsFor`) before the `deleteMutation` runs and the row is removed from the field array.
