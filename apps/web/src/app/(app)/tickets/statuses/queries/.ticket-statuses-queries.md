GraphQL query and mutation definitions for managing ticket statuses, targeting the `openframe-saas-ai-agent` service via `/chat/graphql`.

## Key Components

**Shared Fragment**
- `STATUS_DEFINITION_FIELDS` — Internal template literal defining the common field selection (`id`, `name`, `color`, `position`, `kind`, `isSystem`, `systemKey`, `staleAfterMinutes`) reused across all operations.

**Exported Operations**

| Export | Type | Description |
|---|---|---|
| `GET_TICKET_STATUSES_QUERY` | Query | Fetches all ticket statuses |
| `CREATE_TICKET_STATUS_MUTATION` | Mutation | Creates a new ticket status |
| `UPDATE_TICKET_STATUS_MUTATION` | Mutation | Updates an existing ticket status |
| `DELETE_TICKET_STATUS_MUTATION` | Mutation | Deletes a ticket status by input |
| `REORDER_TICKET_STATUS_MUTATION` | Mutation | Reorders a ticket status position |

## Usage Example

```typescript
import {
  GET_TICKET_STATUSES_QUERY,
  CREATE_TICKET_STATUS_MUTATION,
  REORDER_TICKET_STATUS_MUTATION,
} from './ticket-statuses-queries';

// Fetch all statuses
const statuses = await graphqlClient.request(GET_TICKET_STATUSES_QUERY);

// Create a new status
await graphqlClient.request(CREATE_TICKET_STATUS_MUTATION, {
  input: { name: 'In Review', color: '#FFA500', position: 2 },
});

// Reorder an existing status
await graphqlClient.request(REORDER_TICKET_STATUS_MUTATION, {
  input: { id: 'status-id', position: 1 },
});
```

## Notes

- `DELETE_TICKET_STATUS_MUTATION` returns a scalar (no field selection), while all other mutations return the full `STATUS_DEFINITION_FIELDS` fragment.
- `isSystem` and `systemKey` fields indicate platform-managed statuses that may have restricted mutability.
- `staleAfterMinutes` is the per-status staleness threshold powering the board activity indicators (a ticket's `lastActivityAt`/`activityState` and the activity filter are computed against it); `null` disables staleness for that status.
