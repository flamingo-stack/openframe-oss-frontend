## ticket-table-layout.ts

Defines the shared, data-only column layout for ticket tables, providing a single source of truth consumed both by the live `/tickets` table builder and by skeleton/loading states across different ticket views (fleet-wide, device tab, customer tab).

## Key Components

- **`TICKET_COLUMNS`** — Record of column definitions (`title`, `source`, `assignee`, `status`, `open`) satisfying `TableSkeletonColumn`. Columns with an empty `width` fall back to flexible (`flex-1 min-w-0`) layout, letting SOURCE, ASSIGNEE, and STATUS share leftover row space.
- **`ticketTableColumns(options)`** — Builds an ordered array of columns for a ticket table. Accepts:
  - `withSource` (default `true`) — omits the SOURCE column when the list is already device-scoped.
  - `withOpen` (default `true`) — includes/excludes the trailing "open in new tab" column.
  - `widths` — per-column width overrides, applied after the base layout is assembled.
- **`DEVICE_TICKET_COLUMNS`** — Precomputed layout for the device Tickets tab: drops SOURCE and pins fixed widths for ASSIGNEE (`w-[280px]`) and STATUS (`w-[160px]`) to prevent flex-width drift once SOURCE is removed.

Note: `sortable` is intentionally **not** set here — only `/tickets` wires a server-side sort, so that flag is added per-consumer by the live column builder (`getTicketTableColumns`), not in this shared layout.

## Usage Example

```typescript
import { ticketTableColumns, DEVICE_TICKET_COLUMNS } from '@/app/components/.../ticket-table-layout';

// Fleet-wide /tickets table (all columns, default widths)
const fleetColumns = ticketTableColumns();

// Customer tab: no "open" column, keep SOURCE
const customerColumns = ticketTableColumns({ withOpen: false });

// Device tab: reuse the precomputed layout directly
function renderDeviceTicketsSkeleton() {
  return DEVICE_TICKET_COLUMNS.map(col => col.header);
}
```
