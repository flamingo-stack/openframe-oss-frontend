Route-level loading skeleton for the `/tickets` page, rendering a structural placeholder that mirrors the real `TicketsView` in both board and table modes before data is fetched.

## Key Components

| Export / Constant | Description |
|---|---|
| `TicketsPageSkeleton` | Main exported component; accepts an optional `viewMode` prop to render either board or table skeleton |
| `ACTIONS` | Disabled "New Ticket" button matching the real page's header actions |
| `MENU_ACTIONS` | Disabled "Edit Statuses" and "Tickets Archive" menu items mirroring `useTicketsActions` |
| `COLUMNS` | Table column definitions passed to `TableSkeleton`, mirroring `ticket-table-columns.tsx` |
| `buildPlaceholderBoardColumns` | Imported helper that generates placeholder Kanban columns; called once on mount via `useState` to prevent lane shifts during loading |

## Usage Example

```typescript
// In a Next.js route segment — app/tickets/loading.tsx
import { TicketsPageSkeleton } from './tickets-page-skeleton';

export default function Loading({ searchParams }: { searchParams: { viewMode?: string } }) {
  return <TicketsPageSkeleton viewMode={searchParams.viewMode} />;
}
```

## Behavior Notes

- **Mode resolution** mirrors `useApiParams`: absent or falsy `viewMode` → board; any non-`"board"` truthy value → table
- **Board mode** renders `<Board isLoading>` with frozen placeholder columns and two disabled `<Autocomplete>` filter dropdowns (desktop only)
- **Table mode** renders `<TableSkeleton>` with a sticky `<TagFilterBarSkeleton>` toolbar
- Board columns are read once on mount (`useState(buildPlaceholderBoardColumns)`) to prevent layout shifts while the skeleton is visible
