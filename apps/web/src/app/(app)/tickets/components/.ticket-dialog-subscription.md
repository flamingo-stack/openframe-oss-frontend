Manages the JetStream NATS subscription for a ticket dialog's client topic, deduplicating redelivered messages and telling the parent when to refetch persisted history after a gap.

## Key Components

### `TicketDialogSubscription`
A render-less React component (`returns null`) that wires up one `useJetStreamDialogSubscription` hook against the `CHAT_CHUNKS` JetStream stream: the client topic (`NATS_TOPICS.MESSAGE`), replaying from `clientInitialOptStartSeq` once `isInitialOptStartSeqReady` is true.

### Deduplication logic
The last applied `streamSeq` is tracked in `lastClientStreamSeqRef`. Chunks with a sequence ≤ the last seen value are silently dropped, protecting against JetStream redeliveries on reconnect. The ref resets when `dialogId` changes.

### Catch-up notification
`onCaughtUp` fires when the hook's `caughtUpCount` moves (see its docs): the tail came back after a gap (reconnect, consumer recreation, resync) and has replayed what the stream still held, or could not be resumed at all. Tracked against a `lastNotifiedCatchUpRef`.

> **Note:** The `CHAT_CHUNKS` stream retains ~10 minutes of history. Outages longer than that leave a gap JetStream replay cannot fill — the parent refetches persisted history when `onCaughtUp` fires, after the replay rather than beside it.

## Usage Example

```typescript
<TicketDialogSubscription
  dialogId={activeDialogId}
  dispatchChunk={chunk => {
    // route chunk to the client-side processor
    processClientChunk(chunk);
  }}
  clientInitialOptStartSeq={clientSeq}   // 0 = replay from stream start
  isInitialOptStartSeqReady={historyLoaded}
  onCaughtUp={() => {
    // refetch persisted history to cover any gap > 10 min
    refetchDialogHistory(activeDialogId);
  }}
/>
```
