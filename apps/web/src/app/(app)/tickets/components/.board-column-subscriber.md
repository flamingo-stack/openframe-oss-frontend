# board-column-subscriber.tsx

A headless (render-nothing) React component that manages an infinite, cursor-paginated query for a single board column's tickets, enabling a dynamic number of board columns without violating React's rules of hooks.

## Key Components

- **`BoardColumnUpdate`** — Interface describing the shape of updates pushed up to the parent: column `state`, `isLoading`, and `error`.
- **`BoardColumnSubscriberProps`** — Props including the column's `statusId`, filter `params` (search, organization/assignee/tag filters, unread-only, activity), an `onUpdate` callback, and a `registerLoadMore` callback used to expose pagination control to the parent.
- **`dedupeById`** — Utility that removes duplicate items by `id`, keeping the first occurrence. Necessary because cursor-based pagination can cause the same ticket to appear on multiple pages when items move between lanes or pages shift mid-fetch.
- **`BoardColumnSubscriber`** — The main component. It runs a `useInfiniteQuery` scoped to `dialogsQueryKeys.boardColumn(statusId, ...)`, flattens and deduplicates pages into a `BoardColumnState`, reports state changes via `onUpdate`, and registers a `loadMore` function via `registerLoadMore` so the parent board can trigger `fetchNextPage` externally.

## Usage Example

```typescript
import { BoardColumnSubscriber, type BoardColumnUpdate } from './board-column-subscriber';

function TicketsBoard({ columns, filters }: { columns: { id: string }[]; filters: object }) {
  const loadMoreFns = useRef<Record<string, () => void>>({});
  const [columnStates, setColumnStates] = useState<Record<string, BoardColumnUpdate>>({});

  return (
    <>
      {columns.map(column => (
        <BoardColumnSubscriber
          key={column.id}
          statusId={column.id}
          params={filters}
          onUpdate={(statusId, update) =>
            setColumnStates(prev => ({ ...prev, [statusId]: update }))
          }
          registerLoadMore={(statusId, loadMore) => {
            loadMoreFns.current[statusId] = loadMore;
          }}
        />
      ))}
    </>
  );
}
```

Each instance owns its own query lifecycle (polling, retry, pagination) independently, while the parent board component reads aggregated state through `onUpdate` and triggers further page loads through the registered `loadMore` functions—keeping the board's hook count stable regardless of how many columns exist.
