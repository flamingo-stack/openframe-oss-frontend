# tickets-view.tsx

Top-level client component that renders the Tickets page, switching between **board** and **table** view modes based on a `viewMode` URL parameter. It centralizes all filter/sort state as URL query parameters so filters are shareable, bookmarkable, and survive navigation.

## Key Components

- **`sanitizeActivityParam(raw)`** — Whitelists and dedupes raw `activity` URL values against the canonical `ACTIVITY_FILTER_VALUES` (`ACTIVE`, `STALE`, `AWAITING_EXTERNAL`), preventing invalid enum values from breaking GraphQL queries.
- **`TicketsView()`** — Main exported component. Responsibilities:
  - Reads/writes URL params via `useApiParams` (status, organizationIds, assigneeIds, tagIds, unread, activity, search, viewMode, sortDir).
  - Debounces search input locally via `useSearchParam` to avoid re-rendering on every keystroke.
  - Resolves the active view (`board` vs `table`) via `resolveTicketsViewMode`.
  - Batches related filter changes into a single `setParams` call (via `handleFiltersChange` / `handleTableFiltersChange`) to avoid clobbering state from sequential `setParam` calls.
  - Renders a shared `tabs` selector (`TabSelector`) passed down as the `selector` prop to both view components.
  - Conditionally renders `TicketsBoard` or `CurrentTickets` (table view) with the appropriate props.

## Usage Example

```typescript
// Rendered as the page content for the Tickets route
import { TicketsView } from './components/tickets-view';

export default function TicketsPage() {
  return <TicketsView />;
}
```

The component requires no props—all state is derived from and synchronized with the URL. Switching `viewMode` (e.g., `?viewMode=table`) swaps between `CurrentTickets` (table) and `TicketsBoard` (kanban-style board), while filters like `?status=...&activity=ACTIVE&unread=true` persist across both views via shared URL param handlers.
