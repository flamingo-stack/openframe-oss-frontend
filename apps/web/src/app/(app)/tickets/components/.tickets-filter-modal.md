# tickets-filter-modal.tsx

A modal component that buffers ticket filter selections (customer, assignee, activity, status, unread messages, and sort order) locally and flushes them in a single `onApply` call on confirmation, avoiding sequential URL writes that could clobber each other.

## Key Components

- **`TicketsFilterModal`** — Main component rendering a `SimpleModal` with filter sections. The Customer and Assignee filters always render; Activity, Status, and Sort sections are conditionally rendered based on whether their respective props (`activity`, `status`, `sort`) are passed, since the board and table views expose different filter sets.
- **`TicketsFilterModalProps`** — Props interface defining the current filter values, optional section data, and the `onApply` callback that commits all filters atomically.
- **`SORT_OPTIONS`** — Static list of sort direction options (`DESC`/`ASC`) mapped to human-readable labels.
- **Local state buffering** — Uses the "derived state during render" pattern (comparing `isOpen` vs `wasOpen`) to reseed local state only on the open transition, preventing background data refreshes from resetting in-progress user selections while the modal is open.

## Usage Example

```typescript
import { TicketsFilterModal } from './tickets-filter-modal';

function TicketsBoardFilters() {
  const [isOpen, setIsOpen] = useState(false);

  return (
    <TicketsFilterModal
      isOpen={isOpen}
      onClose={() => setIsOpen(false)}
      organizationIds={[]}
      assigneeIds={[]}
      unreadOnly={false}
      activity={['comment', 'status_change']}
      onApply={filters => {
        // Apply organizationIds, assigneeIds, unreadOnly, and activity
        // in a single URL/state update
        updateTicketFilters(filters);
      }}
    />
  );
}
```

For the table view, pass `status` and `sort` instead of `activity` to enable the Status and Sort-by-ticket-number sections.
