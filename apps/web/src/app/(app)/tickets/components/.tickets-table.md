Renders the main tickets list view (active or archived), combining search, tag/status/assignee filtering, sorting, infinite-scroll pagination, and row actions into a single page-level table component.

## Key Components

- **`TicketsTable`** — The primary exported component. Orchestrates:
  - `useTicketsQuery` for fetching paginated ticket data (search, filters, sort).
  - `useTicketStatusesQuery` / `useAssigneeOptions` for building column-header filter dropdowns (status, assignee).
  - `useTicketsActions` for page-level actions and bulk/menu actions (e.g., emphasizing "New Ticket" on empty state).
  - `useStickyToolbar` for sticky search/filter toolbar behavior.
  - `TicketTagFilter`, `TicketsFilterModal`, `TicketsEmptyState`, and `TicketTableBody` as composed child UI.
- **`getUnreadCount`** — Extracts the per-ticket unread client-chat message count (`Ticket.unreadMessageCount`) for row badges.
- **`TicketsTableProps`** — Prop contract covering archive mode, filters (`statusFilters`, `organizationIds`, `assigneeIds`, `tagIds`, `unreadOnly`), search state, sort state, and callback handlers (`onFiltersChange`, `onSearchChange`, `onTagIdsChange`, `onSortChange`).

## Usage Example

```typescript
import { TicketsTable } from './tickets-table';

function TicketsPage() {
  const [search, setSearch] = useState('');
  const [tagIds, setTagIds] = useState<string[]>([]);
  const [sort, setSort] = useState<TicketListSort>({ field: 'number', direction: 'DESC' });

  return (
    <TicketsTable
      isArchived={false}
      search={search}
      onSearchChange={setSearch}
      tagIds={tagIds}
      onTagIdsChange={setTagIds}
      sort={sort}
      onSortChange={setSort}
      statusFilters={['open', 'in-progress']}
      assigneeIds={[]}
      organizationIds={[]}
      onFiltersChange={(filters) => {
        // Apply status/assignee/customer/unreadOnly/sort atomically
        console.log(filters);
      }}
    />
  );
}
```

**Note:** Filter updates (status, assignee, organization, unread-only, sort) must be applied atomically via `onFiltersChange` since these values are typically synced to URL params, where sequential writes could overwrite each other.
