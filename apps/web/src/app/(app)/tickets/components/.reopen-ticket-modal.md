## ReopenTicketModal

Container component that wires up the ticket-reopen confirmation dialog shown when a user attempts to move a terminal-status ticket (Resolved/Archived) back into an active workflow. It composes data from the ticket detail cache, available status transitions, and assignee options, then delegates presentation to the shared `ReopenTicketModalView` from `@flamingo-stack/openframe-frontend-core`.

## Key Components

- **`ReopenTicketModal`** – The main component. Reads the target ticket from the detail cache, computes valid reopen-target statuses (excluding Resolved/Archived kinds), resolves a sensible initial status default (Tech Required, or an honored prefill), and submits the confirmed selection via `useReopenTicket`.
- **`ReopenTicketTarget`** – Interface describing what opens the modal: a `ticketId` and an optional `initialStatusId` prefill (e.g. from a drag-and-drop action on the board).
- **`ReopenTicketSelection`** (re-exported type) – Shape of the confirmed selection (`statusId`, `assigneeId`, `reason`) passed to `onSuccess`.
- **Hooks used:** `useTicketDetail`, `useAssigneeOptions`, `useTicketStatusesQuery`, `useReopenTicket` — supply ticket data, assignee search/options, status kind lookups, and the reopen mutation respectively.

## Usage Example

```typescript
import { useState } from 'react';
import { ReopenTicketModal, type ReopenTicketTarget } from './reopen-ticket-modal';

function TicketBoard() {
  const [reopenTarget, setReopenTarget] = useState<ReopenTicketTarget | null>(null);

  return (
    <>
      <button
        onClick={() =>
          setReopenTarget({ ticketId: 'ticket-123', initialStatusId: 'status-tech-required' })
        }
      >
        Reopen Ticket
      </button>

      <ReopenTicketModal
        target={reopenTarget}
        onClose={() => setReopenTarget(null)}
        onSuccess={selection => {
          console.log('Reopened with selection:', selection);
        }}
      />
    </>
  );
}
```

Pass `null` as `target` to keep the modal closed; set a valid `ReopenTicketTarget` to open it. The `onSuccess` callback fires before `onClose`, allowing hosts (e.g. the ticket board) to convert pending UI state instead of discarding it.
