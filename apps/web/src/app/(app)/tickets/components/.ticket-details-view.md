## ticket-details-view.tsx

Top-level page component that renders the ticket detail screen: a client-facing chat panel alongside a details/attachments/tags column, with full ticket lifecycle management (assignment, status transitions, take-over/reopen flows, notes, and AI model display).

## Key Components

- **`TicketDetailsView({ ticketId })`** — Main exported component. Orchestrates ticket data fetching, client chat state, device info, assignment, approval requests, and note management for a single ticket's detail page.
- **`withActivityTracking(item, subtype, navigate)`** — Internal helper that wraps a device-menu `ActionsMenuItem` so opening it fires an analytics event before navigating. Recurses into submenu leaf items to preserve reliable `onClick` firing (replaces `href`-based navigation with manual `navigate()` calls to avoid losing tracked events).
- **`TICKET_TITLE_SKELETON_LINES`** — Constant controlling how many skeleton lines render for the ticket title at each breakpoint (`phone`, `md`, `lg`) while data loads.

Internally composes many hooks: `useTicketDetail`, `useDeviceDetails`, `useDeviceActionsMenu`, `useDirectChat`, `useAssignTicket`, `useApprovalRequests`, `useTicketDetailsStore`, `useTrackOpenView`, and note/transition mutation hooks, plus modals (`ReopenTicketModal`, `TakeOverTicketModal`) and sub-sections (`TicketAttachmentsSection`, `TicketTagsSection`, `NotesSection`).

## Usage Example

```typescript
import { TicketDetailsView } from './ticket-details-view';

// Typically rendered from a dynamic route page, e.g. app/(app)/tickets/[ticketId]/page.tsx
export default function TicketPage({ params }: { params: { ticketId: string } }) {
  return <TicketDetailsView ticketId={params.ticketId} />;
}
```

The component relies on `'use client'` and must be rendered within the app's providers (React Query, Relay, auth store, toast context) since it consumes `useQueryClient`, `useMutation` (Relay), `useAuthStore`, and `useToast`. It does not accept children or additional props beyond `ticketId`.
