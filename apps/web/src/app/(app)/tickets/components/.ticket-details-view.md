Renders the full ticket details view for the OpenFrame MSP platform, combining the ticket's client chat, ticket metadata, notes, attachments, assignments, and device actions into a single paginated layout.

## Key Components

### Main Export
- **`TicketDetailsView`** — Primary view component accepting a `ticketId` prop; orchestrates all ticket detail sub-features

### Supporting Utilities
- **`withActivityTracking`** — HOF wrapping `ActionsMenuItem` entries to fire analytics events before navigation, ensuring reliable tracking regardless of link/button rendering

### Key Hooks Used
- `useTicketDetail` — Fetches ticket/dialog metadata
- `useTicketClientChat`: the client chat on the lib's chat engine (`useChatEngine`, the client side of `ticketChatStore`): its thread, approvals, paging, model badge and send. The view keeps only the ticket's own display: the end user's rows named by the device, the technician's own send drawn as theirs, and the receipt a form-made ticket opens with
- `useDirectChat`: starts a direct (non-AI) client chat and says whether the ticket is in one
- `useDeviceDetails` / `useDeviceActionsMenu` — Remote device context and action items
- `useTrackOpenView` — Registers the open ticket as active Mingo sidebar context

### Child Components Rendered
- `TicketNotificationsAutoReader` — Null-rendering; marks the ticket's notifications (per user) and the dialog's unread client messages (`markDialogMessagesRead`, shared by all technicians) read once its client chat is on screen. `TicketDetailsView` owns the `clientChatOnScreen` derivation and passes `lastClientMessageId(clientMessages)` (the newest end-user row) as the re-arm signal for the message mark, which is `mainTab === 'chat'` **or** the bare-chat desktop column (`useContentLgUp() && !showDetailsTabs`) that every AI-dialog ticket lands in. See `.ticket-notifications-auto-reader.md`
- `useAssignedItems` — Loads assignment data when sidebar layout is active
- `useSupportedModels`: the model labels of the client chat's badge

## Usage Example

```typescript
// Route-level page rendering the ticket details
import { TicketDetailsView } from './ticket-details-view';

export default function TicketPage({ params }: { params: { id: string } }) {
  return <TicketDetailsView ticketId={params.id} />;
}
```
