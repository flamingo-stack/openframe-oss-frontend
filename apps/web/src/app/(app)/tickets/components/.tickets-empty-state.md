# tickets-empty-state.tsx

A React client component that renders the empty-state placeholder shown when no ticket history exists. It reuses the shared `EmptyState` layout to display a tag icon, headline/description, feature highlight tiles, and an onboarding-guide footer link, mirroring the Figma design (`data-placeholder-onboarding`).

## Key Components

- **`TicketsEmptyState`** — Default-exported functional component with no props. Composes:
  - `EmptyState` (from `@/app/components/shared`) — the shared empty-state shell (icon, title, description, action tiles, footer button).
  - `onboardingGuideButton('tickets')` — generates the footer button props linking to the Tickets Help Center guide.
  - Icon set (`TagIcon`, `RadarIcon`, `Filter02Icon`, `UserPlusIcon`) from `@flamingo-stack/openframe-frontend-core/components/icons-v2` used for the header icon and the three feature tiles.

This component is shared verbatim between the main Tickets page and the Tickets tab on the device-details view, ensuring consistent empty-state messaging across both contexts.

## Usage Example

```typescript
import { TicketsEmptyState } from '@/app/components/tickets/tickets-empty-state';

function TicketsPage() {
  const tickets = useTickets();

  if (tickets.length === 0) {
    return <TicketsEmptyState />;
  }

  return <TicketsList tickets={tickets} />;
}
```

```typescript
// Reused identically in the device-details Tickets tab
function DeviceTicketsTab({ deviceId }: { deviceId: string }) {
  const deviceTickets = useDeviceTickets(deviceId);

  return deviceTickets.length === 0
    ? <TicketsEmptyState />
    : <DeviceTicketsList tickets={deviceTickets} />;
}
```

**Notes:**
- Must be used in a client-rendered context (`'use client'` directive).
- No props are accepted; all content is statically defined within the component.
- See the shared `EmptyState` component for layout/styling details and `onboardingGuideButton` for footer link behavior.
