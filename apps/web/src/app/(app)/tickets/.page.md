This is the Next.js page component for the Tickets feature, which gates access based on application mode and renders the ticketing UI only for SaaS tenant deployments.

## Key Components

- **`Tickets`** (default export) — Client-side page component that:
  - Checks `isSaasTenantMode()` to determine if the app is running in SaaS tenant mode.
  - Redirects to `routes.dashboard` via `router.replace()` if not in SaaS tenant mode.
  - Returns `null` during the non-SaaS mode render pass to avoid flashing unauthorized content.
  - Renders `TicketsView` when SaaS tenant mode is active.

## Usage Example

This file is a route-level page and is automatically rendered by Next.js when navigating to the tickets route; it's not typically imported directly. The pattern it demonstrates can be reused for other mode-gated pages:

```typescript
'use client';

import { useRouter } from 'next/navigation';
import { useEffect } from 'react';
import { isSaasTenantMode } from '@/lib/app-mode';
import { routes } from '@/lib/routes';
import { TicketsView } from './components/tickets-view';

export default function Tickets() {
  const router = useRouter();

  useEffect(() => {
    if (!isSaasTenantMode()) {
      router.replace(routes.dashboard);
    }
  }, [router]);

  if (!isSaasTenantMode()) {
    return null;
  }

  return <TicketsView />;
}
```

**Notes:**
- Relies on the `isSaasTenantMode()` utility from `@/lib/app-mode` to toggle feature availability across deployment modes.
- Uses `router.replace()` (not `push()`) to avoid adding the gated route to browser history.
- The double-check pattern (`useEffect` + conditional render) prevents a flash of the ticketing UI before the redirect completes.
