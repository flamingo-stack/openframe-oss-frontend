Determines whether a given ticket status ID corresponds to a RESOLVED-kind status, serving as the single source of truth for "is this ticket being resolved?" across all resolve entry points in the application.

## Key Components

### `isResolvedStatusId(statusId, snapshot)`

Looks up `statusId` in the provided `TicketStatusDefinition[]` snapshot and checks whether its `kind` matches `TICKET_STATUS_KIND.RESOLVED`.

| Parameter | Type | Description |
|-----------|------|-------------|
| `statusId` | `string \| null \| undefined` | The status ID to evaluate |
| `snapshot` | `TicketStatusDefinition[] \| undefined` | Full list of status definitions including `kind` metadata |

**Returns:** `boolean` — `true` only when the status is found and its `kind` is `RESOLVED`; `false` for any missing/null input.

> **Why `kind` instead of `id` or `name`?** Custom-named resolved statuses ("Done", "Closed", etc.) all share the `RESOLVED` kind, so keying on `kind` ensures correct detection regardless of display name or database ID. Note: `availableTransitions` responses omit `kind`, which is why callers must pass the full statuses snapshot.

## Usage Example

```typescript
import { isResolvedStatusId } from './is-resolved-status';
import { useTicketStatusSnapshot } from '@/stores/ticket-statuses';

const snapshot = useTicketStatusSnapshot();

// In the detail-view status changer
function onStatusChange(newStatusId: string) {
  if (isResolvedStatusId(newStatusId, snapshot)) {
    trackActivity('resolve_ticket_ticket_detail');
  }
  applyStatusChange(newStatusId);
}

// Gracefully handles missing data
isResolvedStatusId(null, snapshot);      // false
isResolvedStatusId('status-42', undefined); // false
```
