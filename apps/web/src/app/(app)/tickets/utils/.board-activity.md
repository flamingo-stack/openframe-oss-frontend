Determines which single live-activity indicator (if any) a board ticket card should display, implementing the priority rules for AI activity, client-waiting state, and staleness detection.

## Key Components

- **`DEFAULT_STALE_AFTER_MINUTES`** — Client-side fallback staleness threshold (120 minutes), used only when the server-resolved `staleAfterMinutes` is unavailable.
- **`resolveBoardActivity(dialog, status, now)`** — Main function that computes the board activity indicator for a ticket. Returns a `BoardTicketActivity` object (`ai-working`, `waiting-external`, or `stale` with a label) or `undefined` if no indicator should be shown.
- **`formatIdleDuration(idleMs)`** — Internal helper that converts an idle duration in milliseconds into a human-readable string (e.g., `"45 min"`, `"2 hours"`, `"3 days"`).

The resolution logic follows this priority order:
1. Closed-out lanes (`RESOLVED`, `ARCHIVED`) never show activity indicators.
2. `AI_WORKING` or `AWAITING_EXTERNAL` activity states take precedence when present.
3. Higher-priority signals (pending approval, escalation, unread messages) suppress staleness.
4. Staleness is shown only when the dialog has been idle past the status's threshold.

## Usage Example

```typescript
import { resolveBoardActivity } from './board-activity';

const activity = resolveBoardActivity(dialog, statusDefinition, Date.now());

if (activity?.kind === 'stale') {
  console.log(activity.label); // e.g., "No activity for 3 hours"
} else if (activity?.kind === 'ai-working') {
  console.log('AI is working on this ticket');
} else if (activity?.kind === 'waiting-external') {
  console.log('Waiting for client response');
}
```

This function is typically called when rendering board cards to decide which badge/indicator to render on each ticket, re-evaluating on a periodic tick (e.g., every minute) since staleness is time-dependent.
