# board-status-filter.ts

Resolves the board's `?status=` query filter into the set of lanes to display. On a kanban-style board, each lane corresponds to a status, so this filter determines which lanes are visible based on status ids passed in the URL.

Invalid or stale status ids (e.g., referencing a deleted status, or from a hand-edited URL) are silently dropped. If filtering results in zero matching lanes, the filter is treated as inactive and all lanes are shown — this avoids an empty board reading as "no tickets" when it actually means "the filter doesn't apply."

## Key Components

- **`resolveBoardStatusFilter<Lane>(lanes, statusIds)`** — Generic function that takes the board's full lane list and the requested status ids, returning:
  - `activeIds`: the status ids actually in effect, ordered to match the filtered lanes (empty array means "no filter applied")
  - `lanes`: the filtered (or unfiltered, if filter resolved to empty) lane list

## Usage Example

```typescript
import { resolveBoardStatusFilter } from './board-status-filter';

interface Lane {
  id: string;
  title: string;
}

const lanes: Lane[] = [
  { id: 'open', title: 'Open' },
  { id: 'in-progress', title: 'In Progress' },
  { id: 'closed', title: 'Closed' },
];

// Valid filter from URL: ?status=open&status=closed
const { activeIds, lanes: visibleLanes } = resolveBoardStatusFilter(
  lanes,
  ['open', 'closed'],
);
// activeIds: ['open', 'closed']
// visibleLanes: [{ id: 'open', ... }, { id: 'closed', ... }]

// Stale/invalid ids (e.g., deleted status) fall back to showing all lanes
const fallback = resolveBoardStatusFilter(lanes, ['deleted-status']);
// fallback.activeIds: []
// fallback.lanes: all lanes (unfiltered)

// No status param at all
const unfiltered = resolveBoardStatusFilter(lanes, undefined);
// unfiltered.activeIds: []
// unfiltered.lanes: all lanes
```

Use `activeIds` to drive the board's status filter control UI (e.g., highlighting active chips), and `lanes` to render the board columns.
