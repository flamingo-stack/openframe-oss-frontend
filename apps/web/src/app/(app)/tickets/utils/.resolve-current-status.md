Resolves a ticket's current status into a `TicketStatusRef`, bridging the modern lifecycle-based status system and legacy enum-based statuses.

## Key Components

**`LEGACY_STATUS_TO_KIND`** — Internal mapping from legacy `status` enum values (`ACTIVE`, `TECH_REQUIRED`, `RESOLVED`, `ARCHIVED`) to system status kind strings. `ON_HOLD` is intentionally excluded as it has no lifecycle equivalent.

**`resolveCurrentStatus(ticket, snapshot)`** — Primary export. Accepts an optional `Ticket` and an optional array of `TicketStatusDefinition` snapshots, returning a `TicketStatusRef` (with `id`, `name`, `color`) or `undefined` if resolution fails.

Resolution priority:
1. Returns the ticket's `statusDefinition` directly if present (modern lifecycle path)
2. Falls back to matching a system status in `snapshot` by `kind` derived from the legacy `status` enum
3. Returns `undefined` for unresolvable cases (e.g. `ON_HOLD`, missing snapshot, or undefined ticket)

## Usage Example

```typescript
import { resolveCurrentStatus } from './resolve-current-status';

// Modern ticket with statusDefinition
const statusRef = resolveCurrentStatus(ticket, statusSnapshot);
// → { id: 'status-123', name: 'Tech Required', color: '#FF6B00' }

// Legacy ticket (no statusId yet)
const legacyTicket = { status: 'ACTIVE', statusDefinition: null, ...rest };
const statusRef = resolveCurrentStatus(legacyTicket, statusSnapshot);
// → { id: 'sys-001', name: 'AI Assistance', color: '#00AAFF' }

// Unresolvable (ON_HOLD or missing snapshot)
resolveCurrentStatus(onHoldTicket, undefined);
// → undefined
```

## Notes

- Safe to call with `undefined` arguments; all access is guarded with optional chaining
- The `snapshot` array should contain system status definitions (where `isSystem === true`)
