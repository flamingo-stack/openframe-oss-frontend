## ai-dialog.ts

Determines whether a ticket is still actively being handled by the AI assistant, which gates whether actions like status changes, assignment, or starting a direct chat must go through the "Take Over" confirmation flow instead of executing immediately.

## Key Components

- **`hasActiveAiDialog(dialog)`** - Predicate function that returns `true` when a ticket's dialog is still AI-owned. A dialog is considered "AI-active" only when:
  1. It has a valid `dialogId`
  2. Its `statusKind` equals `TICKET_STATUS_KIND.AI_ASSISTANCE`
  3. Its `currentMode` is **not** `DIALOG_MODE.DIRECT`

This mirrors backend logic where AI is disabled the moment a ticket's status kind leaves `AI_ASSISTANCE`. The status kind — not the dialog mode — is the authoritative signal, since `currentMode` only flips to `DIRECT` via an explicit take-over or "Start Direct Chat" action, and never automatically on reopen, escalation, or closure.

## Usage Example

```typescript
import { hasActiveAiDialog } from './ai-dialog';
import { DIALOG_MODE } from '../constants';
import { TICKET_STATUS_KIND } from './ticket-statistics';

const dialog = {
  dialogId: 'dlg_123',
  currentMode: DIALOG_MODE.AI,
  statusKind: TICKET_STATUS_KIND.AI_ASSISTANCE,
};

if (hasActiveAiDialog(dialog)) {
  // Show "Take Over" confirmation before allowing status/assignment changes
  showTakeOverConfirmation();
} else {
  // Ticket is not AI-owned - proceed with the action directly
  applyStatusChange();
}
```

## Notes

- Returns `false` for `null`/`undefined` dialogs or dialogs missing a `dialogId`.
- Acts as the complement to the `isDirectMode` check used in `use-direct-chat`.
- Prevents incorrect "Take Over" prompts for tickets already owned by a technician (e.g., reopened Fae tickets, Tech Required escalations) and avoids bypassing the dedicated Reopen flow for closed tickets.
