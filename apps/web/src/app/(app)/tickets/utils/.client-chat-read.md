# client-chat-read.ts

Utility module for tracking and clearing unread-message state in the client-facing chat/ticket experience. It identifies the most recent message written by the end user and synchronizes the ticket unread-message badge across cached React Query data once that message has been read.

## Key Components

- **`CLIENT_AUTHOR_TYPE`** — Internal constant (`'user'`) identifying end-user authored messages, as opposed to technician (`'admin'`) or assistant (`'fae'`) rows.
- **`lastClientMessageId(messages)`** — Returns the `id` of the newest message authored by the end user (or `null` if none exists). Used as the signal to detect whether the read marker may be stale, since technicians' unread counters only track client-authored messages.
- **`clearCachedUnreadMessages(queryClient, ticketId)`** — Zeroes out a ticket's `unreadMessageCount` across all cached dialog/ticket pages in the React Query cache. Writes directly to cache (rather than invalidating) to avoid stale badge flashes when navigating back to a ticket board, and skips re-renders for unaffected cache entries by preserving object references.

## Usage Example

```typescript
import { lastClientMessageId, clearCachedUnreadMessages } from './client-chat-read';

// Determine if a new client message arrived since the last read mark
const latestClientMessageId = lastClientMessageId(messages);
if (latestClientMessageId !== lastKnownReadId) {
  // Mark as read on the server, then sync the cache
  await markTicketAsRead(ticketId, latestClientMessageId);
  clearCachedUnreadMessages(queryClient, ticketId);
}
```

This pattern is typically invoked after a technician or client views a ticket's chat, ensuring the unread badge disappears immediately in the UI without waiting for the next background poll cycle.
