## ticket-device-name.ts

Utility helpers for resolving ticket ownership type and deriving a human-readable device name from a ticket's owner data, used to display the reporting machine's name consistently across ticket-related UI.

## Key Components

- **`isClientDialogOwner(owner)`** — Type guard that narrows a `ClientDialogOwner | DialogOwner` union to `ClientDialogOwner` by checking the `type === 'CLIENT'` discriminant. A CLIENT-owned ticket carries the reporting machine; an ADMIN-owned ticket carries a user instead.
- **`getTicketDeviceName(ticket)`** — Resolves the display name of the device that reported a ticket, following the standard `nickname → displayName → hostname` precedence (via `getDeviceName`). Uses the ticket's own denormalized `deviceHostname` as the hostname fallback (ahead of the machine's hostname). Returns an empty string if the ticket has no associated device.

## Usage Example

```typescript
import { isClientDialogOwner, getTicketDeviceName } from './ticket-device-name';
import type { Dialog } from '../types/dialog.types';

function TicketDeviceLabel({ ticket }: { ticket: Dialog }) {
  if (!isClientDialogOwner(ticket.owner)) {
    // ADMIN-owned ticket: no device to display
    return null;
  }

  const deviceName = getTicketDeviceName(ticket);
  return deviceName ? <span>Reported from: {deviceName}</span> : null;
}
```

```typescript
// Resolving device name directly from a partial ticket object
const name = getTicketDeviceName({
  owner: { type: 'CLIENT', machine: { nickname: null, hostname: 'web-01' } },
  deviceHostname: 'web-01.local',
});
// => 'web-01' or 'web-01.local' depending on nickname/hostname precedence
```
