Resolves the active view mode (`table` or `board`) for the `/tickets` page based on the `viewMode` query parameter, with board as the default fallback.

## Key Components

- **`TicketsViewMode`** — Type alias representing the two valid view modes: `'table'` and `'board'`.
- **`resolveTicketsViewMode(rawViewMode)`** — Function that takes a raw, possibly-undefined query string value and returns a canonical `TicketsViewMode`. Only an exact match of `'table'` resolves to the table view; every other value (including `undefined` or legacy/invalid values) resolves to `'board'`.

## Usage Example

```typescript
import { resolveTicketsViewMode } from './resolve-view-mode';

// Explicit table selection
resolveTicketsViewMode('table'); // 'board'... wait, returns 'table'

// No query param set — defaults to board on all viewport widths
resolveTicketsViewMode(undefined); // 'board'

// Legacy or invalid values fall back to board
resolveTicketsViewMode('grid'); // 'board'
```

A typical consumer reads the query parameter from the route and passes it straight through:

```typescript
import { resolveTicketsViewMode } from './resolve-view-mode';

const viewMode = resolveTicketsViewMode(route.query.viewMode as string | undefined);

if (viewMode === 'table') {
  // render TicketsTable
} else {
  // render TicketsBoard (default, touch-friendly with swipeable lane pager)
}
```

**Note:** Since the board is now the default at every viewport width, components should no longer branch on screen size to choose the initial view — only the `viewMode` query parameter determines the result.
