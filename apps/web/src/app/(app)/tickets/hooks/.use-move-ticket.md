# use-move-ticket.ts

React Query hook for moving/reordering tickets on a Kanban-style board, implementing optimistic UI updates with automatic rollback on failure and consistency reconciliation on settlement.

## Key Components

- **`MoveTicketParams`** — Interface describing a move operation: ticket ID, source/target status columns, and optional anchor tickets (`afterTicketId`/`beforeTicketId`) defining the drop position.
- **`moveTicketRequest`** — Internal async function that dispatches either a pure status transition (cross-column drop with no anchor) or a reorder request (same-column, or cross-column with an anchor). Enforces sending exactly one anchor ID, since the backend resolves the other neighbor itself.
- **`useMoveTicket`** — Primary mutation hook built on `useMutation`. Applies an optimistic board update in `onMutate`, rolls back on `onError`, and always invalidates affected board columns, ticket detail, and statistics queries in `onSettled` to reconcile with server state.
- **`useMovingTicketIds`** — Selector hook using `useMutationState` to return a `Set<string>` of ticket IDs currently in-flight for a move, useful for disabling drag handles or showing loading indicators on cards being moved.

## Usage Example

```typescript
import { useMoveTicket, useMovingTicketIds } from './use-move-ticket';

function TicketBoard() {
  const moveTicket = useMoveTicket();
  const movingIds = useMovingTicketIds();

  const handleDrop = (ticketId: string, targetStatusId: string, sourceStatusId: string) => {
    moveTicket.mutate({
      ticketId,
      sourceStatusId,
      targetStatusId,
      afterTicketId: 'ticket-123',
      beforeTicketId: null,
    });
  };

  return (
    <div>
      {/* Render cards; disable drag if movingIds.has(ticket.id) */}
    </div>
  );
}
```

**Notes:**
- Never pass both `afterTicketId` and `beforeTicketId` as non-null — only one anchor should be provided.
- `statusId` is always included in reorder requests (even same-column) because it determines the ranking lifecycle; omitting it causes tickets to rank against a stale legacy field.
- Rollback on error is best-effort only; `onSettled` always refetches affected columns to guarantee correctness.
