A React hook for fetching and paginating ticket dialog messages using TanStack Query's infinite query pattern, with automatic cache invalidation on dialog/chat type changes.

## Key Components

- **`useTicketMessages(dialogId, chatType)`** — Main hook that manages paginated message fetching for a given ticket dialog and chat type.
- **`ticketDialogMessagesQueryKey(dialogId, chatType)`** — Internal factory producing a stable query key for cache lookups and invalidation.
- Returns an object exposing:
  - `rawPages` — raw array of fetched message pages
  - `dataUpdatedAt`, `isLoading`, `isFetched`, `isFetchedAfterMount` — query status flags (the latter distinguishes freshly fetched data from stale cached data, important for deriving JetStream consumer start sequences without duplicating messages)
  - `hasNextPage`, `isFetchingNextPage`, `fetchNextPage` — pagination controls
  - `refetch` — manually re-fetch loaded pages
  - `error` — stringified error message, or `null`

## Usage Example

```typescript
import { useTicketMessages } from './use-ticket-messages';

function TicketDialog({ dialogId, chatType }: { dialogId: string | null; chatType: ChatType }) {
  const {
    rawPages,
    isLoading,
    hasNextPage,
    fetchNextPage,
    isFetchingNextPage,
    error,
  } = useTicketMessages(dialogId, chatType);

  if (isLoading) return <Spinner />;
  if (error) return <ErrorBanner message={error} />;

  return (
    <div>
      {rawPages?.flatMap(page => page.messages).map(msg => (
        <MessageItem key={msg.id} message={msg} />
      ))}
      {hasNextPage && (
        <button onClick={() => fetchNextPage()} disabled={isFetchingNextPage}>
          Load more
        </button>
      )}
    </div>
  );
}
```

**Notes:**
- The query is disabled (`enabled: !!dialogId`) until a `dialogId` is provided.
- Messages are sorted by `createdAt` descending, fetched in pages of 50.
- `refetchOnReconnect` is intentionally restricted to only refetch when no data exists yet, since live updates are handled separately via `TicketDialogSubscription`.
- Switching `dialogId` or `chatType` triggers automatic invalidation of the previous query's cache.
