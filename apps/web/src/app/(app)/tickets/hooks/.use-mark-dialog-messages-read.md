# use-mark-dialog-messages-read.ts

A React hook that marks a client-chat dialog's messages as read, optimistically clearing the ticket's unread badge in cached queries before and after the server request completes.

## Key Components

- **`useMarkDialogMessagesRead()`** — Hook returning a memoized async callback `(dialogId: string, ticketId: string) => Promise<void>` that:
  - Clears the cached unread-messages badge for the ticket **before** calling the API (since the user is already viewing the chat, the stale badge should disappear immediately).
  - Calls `ticketService.markDialogMessagesRead(dialogId)` to reset the server-side unread counter.
  - Clears the cached badge **again** after the request succeeds, to overwrite any stale count repainted by a concurrent background poll.
  - Deduplicates concurrent calls per `dialogId` using an in-flight `Set`; if a call arrives while one is already running, it schedules exactly one rerun after the current request finishes (handles messages arriving between the server reset and the response).
  - On failure: logs a warning (no user-facing toast, matching the pattern used by `useMarkEntityNotificationsRead`) and invalidates the `dialogsQueryKeys.all` query to prevent an optimistic zero from persisting after a failed write.

## Usage Example

```typescript
import { useMarkDialogMessagesRead } from './use-mark-dialog-messages-read';

function ChatDialog({ dialogId, ticketId }: { dialogId: string; ticketId: string }) {
  const markDialogMessagesRead = useMarkDialogMessagesRead();

  useEffect(() => {
    // Mark messages read as soon as the dialog is opened/viewed
    void markDialogMessagesRead(dialogId, ticketId);
  }, [dialogId, ticketId, markDialogMessagesRead]);

  return <div>{/* chat UI */}</div>;
}
```

## Notes

- Safe to call repeatedly in quick succession (e.g., on every new incoming message while the dialog is focused) due to built-in in-flight deduplication and rerun scheduling.
- Relies on `clearCachedUnreadMessages` to synchronously patch the React Query cache, and `dialogsQueryKeys` for consistent invalidation targeting.
- Intended for client-facing chat dialogs tied to support tickets; requires `QueryClientProvider` context (`'use client'` directive confirms client-side usage in a Next.js app).
