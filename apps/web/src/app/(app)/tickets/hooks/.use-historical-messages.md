# use-historical-messages.ts

A React hook that synchronizes paginated, fetched ticket message history into the ticket-details store, merging it with in-flight realtime streaming state and reconciling approval request statuses.

## Key Components

- **`useHistoricalMessages`** — Hook that processes newly-fetched `MessagePage[]` data for a given chat side (client/admin), transforms raw history into display-ready messages, and writes the result into `useTicketDetailsStore`.
- **`UseHistoricalMessageSyncOptions`** — Input interface: chat side, dialog id, chat type, assistant config, fetched pages, freshness timestamp (`dataUpdatedAt`), fetch status, and approval callbacks (`onApprove`/`onReject`).

### Internal behavior
- Flattens paginated message pages chronologically and maps them into `HistoricalMessage` objects, preserving `lastChunkStreamSeq` for per-role seq coverage.
- Scans message data for `APPROVAL_RESULT` entries to pre-resolve approval statuses before processing.
- Calls `processHistoricalMessagesWithErrors` with the assistant config, chat type filter, and combined approval statuses (`CLIENT` + `ADMIN` display types).
- Folds pending-approval envelopes via `foldPendingApprovalsEnvelope` before building the final `ChatMessage[]` list.
- Detects pagination (new pages appended) vs. a fresh fetch:
  - **Non-pagination**: merges processed history with realtime/streaming messages using `mergeHistoryWithRealtime`, respecting `streamingMessageId` and seq boundaries.
  - **Pagination**: computes and applies only the prepended older messages via `computeHistoryPrepend` and `prependWithBoundaryMerge`.
- Uses refs (`approvalStatusesRef`, `onApproveRef`, `onRejectRef`) updated post-commit to avoid stale closures without violating render-phase ref rules.

## Usage Example

```typescript
function TicketChatPanel({ side, messageDialogId, chatType, assistantConfig }: Props) {
  const { data: pages, dataUpdatedAt, isFetched } = useTicketMessagesQuery(messageDialogId);

  useHistoricalMessages({
    side,
    messageDialogId,
    chatType,
    assistantConfig,
    pages: pages?.pages,
    dataUpdatedAt,
    isFetched,
    onApprove: async requestId => approveRequest(requestId),
    onReject: async requestId => rejectRequest(requestId),
  });

  // Messages are now available via the ticket-details-store
  const messages = useTicketDetailsStore(s => s.getMessages(side));
  return <MessageList messages={messages} />;
}
```

Note: this hook performs no rendering itself—it's a side-effect synchronizer meant to run alongside a message-fetching query hook, feeding results directly into the shared Zustand store (`ticket-details-store`).
