Synchronizes paginated historical ticket messages with the real-time chat store by processing each fetched page, extracting approval resolutions, and merging the result with any in-flight streaming messages.

## Key Components

### `useHistoricalMessages(options)`

A React hook that drives the full historical → store pipeline:

| Option | Type | Description |
|---|---|---|
| `side` | `ChatSide` | Which side of the ticket chat (`client` / `admin`) |
| `messageDialogId` | `string \| null` | Current dialog ID; resets page tracking on change |
| `chatType` | `ChatType` | Filters messages by type (matches server-side filter) |
| `assistantConfig` | `{ name, type }` | Assistant metadata passed to the message processor |
| `pages` | `MessagePage[] \| undefined` | Paginated raw messages from react-query |
| `dataUpdatedAt` | `number` | react-query freshness timestamp used as the merge boundary |
| `isFetched` | `boolean` | Guards against running before the first fetch completes |

**Internal behavior:**

1. **Flattens** paginated `MessagePage[]` into a chronological `HistoricalMessage[]`.
2. **Extracts** `APPROVAL_RESULT` entries from message data and calls `mergeApprovalStatuses` on the store.
3. **Processes** the flat list through `processHistoricalMessages`, applying `chatTypeFilter` and the known approval statuses.
4. **Merges or prepends** depending on whether this is an initial load or a pagination event:
   - Initial load → `mergeHistoryWithRealtime` (handles streaming synthetic exemption).
   - Pagination → `computeHistoryPrepend` + `prependWithBoundaryMerge`.

## Usage Example

```typescript
useHistoricalMessages({
  side: 'client',
  messageDialogId: ticket.dialogId,
  chatType: 'CLIENT',
  assistantConfig: { name: 'Mingo', type: 'AI' },
  pages: messagePages,
  dataUpdatedAt: queryResult.dataUpdatedAt,
  isFetched: queryResult.isFetched,
});
```

## Notes

- `streamingMessageId` is a reactive dependency (not a getter) so the merge re-runs the moment an active stream ends, preventing stale synthetic retention.
- An approval card holds no callback: its approve and reject are `ChatMessageActions` at render, and which tiers it draws is `DISPLAY_APPROVAL_TYPES` (`lib/chat-approval-tiers.ts`).
