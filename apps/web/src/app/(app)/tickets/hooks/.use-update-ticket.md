# use-update-ticket.ts

A React hook that handles updating a ticket via GraphQL, including special handling for unlinking/unassigning relationships (organization, device, assignee) before applying generic field updates. Integrates with TanStack Query for cache invalidation and toast notifications for user feedback.

## Key Components

- **`runTicketMutation<K>()`** — Generic helper that executes a GraphQL mutation against `API_ENDPOINTS.GRAPHQL`, extracts the typed payload by key, throws on `userErrors`, and returns the resulting `Ticket` or `null`.
- **`updateTicketApi()`** — Orchestrates the update flow:
  - If `organizationId === null`, unlinks the organization via `UNLINK_ORGANIZATION_FROM_TICKET_MUTATION`.
  - If `deviceId === null`, unlinks the device via `UNLINK_DEVICE_FROM_TICKET_MUTATION`.
  - If `assigneeId === null`, unassigns via `UNASSIGN_TICKET_MUTATION`; if a string, assigns via `ASSIGN_TICKET_MUTATION`.
  - Applies any remaining field changes (including new `deviceId`/`organizationId` string values) via `UPDATE_TICKET_MUTATION`, only when there are fields left to update.
  - Returns the most recent `Ticket` result from whichever mutation ran last.
- **`useUpdateTicket()`** — Exported hook wrapping `updateTicketApi` in a `useMutation`. On success, invalidates `ticketsQueryKeys.all` and `dialogsQueryKeys.all` and shows a success toast. On error, shows a destructive toast with the error message.

## Usage Example

```typescript
import { useUpdateTicket } from './use-update-ticket';

function TicketEditForm({ ticketId }: { ticketId: string }) {
  const { mutate: updateTicket, isPending } = useUpdateTicket();

  const handleSave = () => {
    updateTicket({
      id: ticketId,
      title: 'Updated title',
      assigneeId: null, // unassigns the ticket
      organizationId: 'org-123', // links a new organization
    });
  };

  return (
    <button onClick={handleSave} disabled={isPending}>
      Save Ticket
    </button>
  );
}
```

Note: this hook only performs the mutation and cache invalidation—navigation after update is handled separately by the consuming form (e.g., `useCreateTicketForm`).
