# use-create-ticket-form.ts

React hook that powers the create/edit ticket form, handling both creation of new tickets and in-place editing of existing ones (including prefill from an existing ticket, status transitions, assignments, and attachments) behind a single unified API.

## Key Components

- **`useCreateTicketForm(options)`** — Main hook accepting `{ ticketId?, prefill? }`. When `ticketId` is provided, the hook operates in edit mode; otherwise it's in create mode using optional `prefill` values (e.g., from an incident or query params).
- **Form state** — Built on `react-hook-form` with Zod validation (`createTicketSchema`) via `zodResolver`.
- **Edit-mode prefill** — Fetches the ticket via GraphQL, resolves its current status, and resets the form exactly once per ticket using a ref guard to avoid render loops.
- **`handleSave`** — Submit handler that orchestrates, in order: pending attachment deletes, status transition, ticket update/create, and assignment diff application, then navigates to the ticket detail route.
- **Returned API** — `{ form, ticket, isEditMode, isLoadingTicket, ticketLoaded, isSubmitting, handleSave, tempAttachments, isFaeForm }`.

## Usage Example

```typescript
import { useCreateTicketForm } from './use-create-ticket-form';

function TicketFormPage({ ticketId }: { ticketId?: string }) {
  const {
    form,
    ticket,
    isEditMode,
    ticketLoaded,
    isSubmitting,
    handleSave,
    tempAttachments,
  } = useCreateTicketForm({ ticketId });

  if (isEditMode && !ticketLoaded) {
    return <LoadingSpinner />;
  }

  return (
    <form onSubmit={handleSave}>
      <input {...form.register('title')} />
      <textarea {...form.register('description')} />
      {/* attachment uploader using tempAttachments */}
      <button type="submit" disabled={isSubmitting}>
        {isEditMode ? 'Save Changes' : 'Create Ticket'}
      </button>
    </form>
  );
}
```

## Notes

- `ticketLoaded` (not `isLoadingTicket`) must gate the Save button in edit mode, since the ticket query can report "not loading" while offline with no data, risking blank values overwriting the real ticket.
- Status transitions are applied before the main ticket update to avoid partial saves on transition failure.
- Optimistic tag IDs (still being created) are filtered out of `tagIds` before submission.
- Navigation only happens after all async steps succeed, ensuring failures keep the user on the form with input intact.
