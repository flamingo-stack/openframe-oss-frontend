Unified form hook for both creating and editing tickets, handling form state initialization, validation, prefill in edit mode, attachment management, status transitions, and assignment diffing.

## Key Components

**`useCreateTicketForm(options)`**
Main export. Accepts an optional `ticketId`; when provided, switches to edit mode and fetches the existing ticket for prefill.

**Returns:**

| Property | Type | Description |
|---|---|---|
| `form` | `UseFormReturn` | React Hook Form instance with Zod validation |
| `ticket` | `Ticket \| undefined` | Fetched ticket data (edit mode only) |
| `isEditMode` | `boolean` | `true` when `ticketId` is provided |
| `isLoadingTicket` | `boolean` | Loading state for ticket fetch |
| `isSubmitting` | `boolean` | Aggregate pending state across all mutations |
| `handleSave` | `() => Promise<void>` | Form submit handler |
| `tempAttachments` | object | Temp attachment state/helpers |
| `isFaeForm` | `boolean` | `true` when ticket was created via Fae client form |

## Usage Example

```typescript
// Create mode
const { form, handleSave, isSubmitting, tempAttachments } = useCreateTicketForm();

// Edit mode — prefills form from fetched ticket
const { form, handleSave, isEditMode, ticket } = useCreateTicketForm({ ticketId: 'abc-123' });

// Wire into your form component
<form onSubmit={handleSave}>
  <input {...form.register('title')} />
  <button type="submit" disabled={isSubmitting}>Save</button>
</form>
```

## Edit Mode Behaviour

1. Fetches ticket via GraphQL (`staleTime: 0` to always reflect remote transitions)
2. Resolves current status (including legacy-status fallback)
3. Prefills form once ticket data **and** assignment data are both ready
4. On save: transitions status first, then updates ticket fields, then diffs assignments
5. Tracks `RESOLVE_TICKET` analytics event when transitioning to a resolved-kind status
