React Query mutation hooks for managing ticket notes (add, update, delete) with optimistic UI updates and automatic cache rollback on error.

## Key Components

| Export | Description |
|---|---|
| `useAddTicketNote(ticketId)` | Mutation hook that appends a new note with an optimistic placeholder entry |
| `useUpdateTicketNote(ticketId)` | Mutation hook that edits an existing note's content optimistically |
| `useDeleteTicketNote(ticketId)` | Mutation hook that removes a note from the list optimistically |

**Internal helpers:**

- `setNotesInCache` — writes updated notes array into the `Dialog` query cache for a given ticket
- `getNotesFromCache` — reads the current notes array from cache to snapshot before optimistic updates

All three hooks share the same pattern:
1. **`onMutate`** — snapshot current notes, apply optimistic change immediately
2. **`mutationFn`** — fire the GraphQL mutation via `apiClient`
3. **`onSuccess`** — invalidate the ticket detail query to sync server state
4. **`onError`** — restore the snapshot and show a destructive toast notification

## Usage Example

```typescript
import { useAddTicketNote, useUpdateTicketNote, useDeleteTicketNote } from './use-ticket-notes';

function TicketNotes({ ticketId }: { ticketId: string }) {
  const addNote    = useAddTicketNote(ticketId);
  const updateNote = useUpdateTicketNote(ticketId);
  const deleteNote = useDeleteTicketNote(ticketId);

  // Add a new note
  addNote.mutate({ content: 'Following up with the client tomorrow.' });

  // Edit an existing note
  updateNote.mutate({ id: 'note-abc', content: 'Updated follow-up details.' });

  // Remove a note
  deleteNote.mutate('note-abc');
}
```

> **Optimistic updates:** The UI reflects changes instantly. If the server returns an error, the previous notes state is automatically restored and a toast is displayed.
