# use-ticket-detail.ts

A React hook that fetches and manages the state of a single support ticket's dialog using React Query, with conditional fetching based on ticket ID availability.

## Key Components

- **`useTicketDetail(ticketId)`** - Custom hook that retrieves ticket dialog data for a given `ticketId`. Returns an object containing:
  - `ticket` - The fetched `Dialog` object, or `null` if unavailable
  - Spread `state` properties from `queryState` (e.g., `isLoading`, `isOffline`, `isError`, etc.)
  - `refetch` - Function to manually re-trigger the query

## Usage Example

```typescript
import { useTicketDetail } from './use-ticket-detail';

function TicketDetailView({ ticketId }: { ticketId: string | null }) {
  const { ticket, isLoading, isOffline, isError, refetch } = useTicketDetail(ticketId);

  if (isOffline) {
    return <OfflineBanner onRetry={refetch} />;
  }

  if (isLoading) {
    return <TicketSkeleton />;
  }

  if (isError || !ticket) {
    return <ErrorState onRetry={refetch} />;
  }

  return <TicketDialog dialog={ticket} />;
}
```

## Notes

- The query is only `enabled` when `ticketId` is truthy, preventing unnecessary network calls.
- `staleTime` is set to 30 seconds, so repeated views within that window avoid refetching.
- The hook deliberately relies on `queryState`'s derived `isOffline` flag rather than a raw `isPending`/`isLoading` check, since a paused query (e.g., due to network loss) should surface an offline UI rather than leaving the view stuck on a skeleton loader indefinitely.
- Query keys are centralized via `ticketsQueryKeys.detail(...)` to ensure cache consistency across the tickets feature.
