# use-archive-resolved-mutation.ts

A React hook that provides a mutation for bulk-archiving resolved tickets via GraphQL, with optimistic UI updates and automatic cache rollback on failure.

## Key Components

- **`ArchiveResolvedFilter`** — interface describing the filter criteria (organization IDs, assignee IDs, tag IDs, unread-only flag, activity filters) used to scope which resolved tickets get archived. Must mirror the filters used when fetching the Resolved lane to keep the archived count accurate.
- **`ArchiveResolvedPayload`** — internal shape of the GraphQL mutation response, including the archived `count` and any `userErrors`.
- **`useArchiveResolvedMutation()`** — the main hook, built on `useMutation` from `@tanstack/react-query`. It:
  - Sends the `ARCHIVE_RESOLVED_TICKETS_MUTATION` GraphQL mutation via `apiClient`, normalizing empty filter arrays to `undefined`.
  - Throws an error if the GraphQL response includes `userErrors`.
  - **`onMutate`**: optimistically removes resolved dialogs from all cached dialog list queries (`dialogsQueryKeys.lists()`), snapshotting prior data for rollback.
  - **`onError`**: restores the previous query data and shows a destructive toast with the error message.
  - **`onSuccess`**: shows a success toast with the number of tickets archived.
  - **`onSettled`**: invalidates all dialog queries and ticket statistics to ensure fresh data from the server.

## Usage Example

```typescript
import { useArchiveResolvedMutation } from './hooks/use-archive-resolved-mutation';

function ArchiveResolvedButton({ organizationIds, assigneeIds }: { organizationIds: string[]; assigneeIds: string[] }) {
  const { mutate: archiveResolved, isPending } = useArchiveResolvedMutation();

  const handleArchive = () => {
    archiveResolved({
      organizationIds,
      assigneeIds,
      unreadOnly: false,
    });
  };

  return (
    <button onClick={handleArchive} disabled={isPending}>
      {isPending ? 'Archiving…' : 'Archive Resolved Tickets'}
    </button>
  );
}
```

Use this hook anywhere a confirmation dialog needs to trigger bulk archival of resolved tickets while keeping the ticket list UI responsive via optimistic updates.
