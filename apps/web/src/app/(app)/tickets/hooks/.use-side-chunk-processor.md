# use-side-chunk-processor.ts

Drives a single chat side (client or admin) of a ticket dialog by connecting NATS chunk events to the ticket details store. It wraps the shared `useChatChunkProcessor` from the lib layer with tickets-only glue: direct-mode synchronization, model-badge binding, and interception of client-authored direct messages.

This is **Phase 4** of the chat pipeline refactor — chunks now flow through the lib's master stream reducer (`decodeNatsChunk` → `ticketChatDialogStore.apply`), which owns accumulation rules and cross-side projections (approval resolution, tool-execution merge). This hook retains only the residual logic specific to tickets: direct-mode flag sync and the client-side `direct-message` intercept.

## Key Components

- **`UseSideChunkProcessorOptions`** — options interface: `ticketId`, `userDisplayName`, `isDirectMode`, `onMetadata` callback.
- **`useSideChunkProcessor(side, options)`** — main hook that:
  - Reads messages and approval statuses for the given `side` from `useTicketDetailsStore`.
  - Syncs `isDirectMode` into the store via `mutateTicketSide` so the reducer drops AI events once a technician takes over.
  - Late-binds the `onMetadata` handler for model-badge updates via `setChatHandlers`.
  - Intercepts `direct-message` participant events authored by non-admins, rendering them as user-authored rows (preserving end-user identity instead of defaulting to admin authorship).
  - Delegates core chunk processing to `useChatChunkProcessor`, passing a bound mirror (`bindTicketSide`), messages, approval statuses, and the custom `interceptEvent` callback.
- **Re-exported type**: `ChatModelMetadata` (from `@/lib/chat-stream-thread`).

## Usage Example

```typescript
import { useSideChunkProcessor } from './use-side-chunk-processor';

function TicketAdminPanel({ ticketId, isDirectMode }: { ticketId: string; isDirectMode: boolean }) {
  const { sendMessage, isStreaming } = useSideChunkProcessor('admin', {
    ticketId,
    isDirectMode,
    onMetadata: (metadata) => {
      console.log('Model used:', metadata.modelName);
    },
  });

  return (
    <button disabled={isStreaming} onClick={() => sendMessage('Hello!')}>
      Send
    </button>
  );
}
```

Use one instance per side (`client` and `admin`) within the same ticket view to drive both halves of the dialog independently.
