# dialogs-queries.ts

Defines GraphQL queries/mutations for fetching and managing dialog messages, plus a helper to normalize field aliasing introduced to resolve GraphQL `FieldsConflict` errors between message data types that share field names with differing nullability.

## Key Components

- **`OFFER_TEXT_ALIAS`**, **`ESCALATED_TEXT_ALIAS`**, **`TICKET_EVENT_REASON_ALIAS`** — exported alias constants used in the query to disambiguate `text`/`reason` fields across union members with conflicting nullability (`String` vs `String!`).
- **`normalizeMessageDataAliases<T>(messageData: T)`** — reverses the GraphQL aliasing on fetched message data arrays, remapping aliased fields (e.g. `offerText`) back to their canonical names (e.g. `text`) so downstream consumers (like the core history decoder) always see a consistent shape. Passes through unmodified items by reference; only allocates a new array when changes occur.
- **`GET_DIALOG_MESSAGES_QUERY`** — paginated query fetching dialog messages with full `messageData` union coverage (text, thinking, system, tool execution/approval, escalation, ticket events, context compaction, errors), including `POLICY_REVIEW_SELECTION` fragment inclusion for tool-related fields.
- **`CREATE_DIALOG_MUTATION`**, **`UPDATE_DIALOG_MODE_MUTATION`**, **`STOP_DIALOG_GENERATION_MUTATION`**, **`SEND_MESSAGE_MUTATION`**, **`RESOLVE_APPROVAL_REQUEST_MUTATION`** — mutations for dialog lifecycle and message/approval actions, each returning `userErrors { field message }` for consistent error handling.

## Usage Example

```typescript
import {
  GET_DIALOG_MESSAGES_QUERY,
  SEND_MESSAGE_MUTATION,
  normalizeMessageDataAliases,
} from './dialogs-queries';

// Fetch messages for a dialog
const { data } = await graphqlClient.query({
  query: GET_DIALOG_MESSAGES_QUERY,
  variables: { dialogId, chatType: 'SUPPORT', limit: 50 },
});

// Normalize aliased fields before handing off to shared parsing logic
const messages = data.messages.edges.map(edge => ({
  ...edge.node,
  messageData: normalizeMessageDataAliases(edge.node.messageData),
}));

// Send a new message
await graphqlClient.mutate({
  mutation: SEND_MESSAGE_MUTATION,
  variables: { input: { dialogId, text: 'Hello' } },
});
```

**Important:** If you add or rename a field alias in `GET_DIALOG_MESSAGES_QUERY`, you must update the corresponding entry in `MESSAGE_DATA_FIELD_ALIASES` so `normalizeMessageDataAliases` stays in sync.
