# Ticket Details Page

Next.js client page component that renders a single ticket's detail view, resolved from a `ticket` query parameter. It normalizes legacy or Relay-encoded global IDs into the raw ticket ID format expected by the application's internal queries.

## Key Components

- **`TicketDetailsPage`** (default export) — Page component that reads the `id` query parameter, normalizes it via `rawIdOfType('Ticket', id)`, and renders `TicketDetailsView`.
- **ID normalization logic** — Handles links/mentions that carry a Relay global `Ticket.id` (e.g., from older bundles or `@ticket:` chat mentions) by converting them to the raw ID the view expects.
- **Redirect behavior**:
  - Redirects to `routes.tickets.list` if no `id` is present.
  - Rewrites the URL in place (via `router.replace` with `scroll: false`) when the raw ID differs from the given ID, preserving other query params (e.g., `mingoDialog` set by the Mingo drawer).

## Usage Example

This page is automatically rendered by Next.js routing when a user navigates to the ticket details route with an `id` query parameter:

```text
/tickets/details?id=<relay-or-raw-ticket-id>
```

No manual instantiation is required — Next.js handles mounting based on the file's location in the `app` directory. The component internally depends on:

```typescript
import { rawIdOfType } from '@/lib/relay-id';
import { routes } from '@/lib/routes';
import { TicketDetailsView } from '../components/ticket-details-view';
```

If integrating a link to this page elsewhere in the app, construct the URL with the ticket's ID (raw or Relay-encoded — both are handled):

```typescript
router.push(`${routes.tickets.details}?id=${ticketId}`);
```

The component returns `null` while resolving the ID transition to avoid rendering with a stale or invalid ticket ID.
