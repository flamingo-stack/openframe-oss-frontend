# index.ts

Centralizes dialog-related constants and enums for the chat/dialog feature, re-exporting wire-protocol enums from the shared frontend-core library (SSOT) and defining app-specific constants for dialog modes, intents, assistants, and network configuration.

## Key Components

- **Re-exported wire-protocol enums** — `APPROVAL_STATUS`, `CHAT_TYPE`, `MESSAGE_TYPE`, `OWNER_TYPE` (and their types) sourced from `@flamingo-stack/openframe-frontend-core`, ensuring consistency with the shared SSOT.
- **`ApprovalStatus`** — alias for `ChatApprovalStatus` from the core lib.
- **`DIALOG_MODE`** — distinguishes `AI` vs `DIRECT` chat dialogs.
- **`DIALOG_INTENT`** — flags why an admin dialog was opened (e.g., `CREATE_SCRIPT`, `CREATE_TICKET`), steering the AI's conversation flow toward creating a specific entity.
- **`ASSISTANT_CONFIG`** — defines the two AI assistants, `FAE` (client-facing) and `MINGO` (technician-facing), each with a `type` and `name`.
- **`CREATION_SOURCE`** — tracks the origin of entity creation (`FAE_FORM`, `FAE_DIALOG`, `ADMIN_DASHBOARD`).
- **`API_ENDPOINTS`** — GraphQL endpoint path for chat.
- **`NATS_TOPICS`** — NATS subject names for standard and admin messages.
- **`NETWORK_CONFIG`** — timing/connection constants for NATS client behavior (timeouts, ping intervals, message limits).

## Usage Example

```typescript
import {
  DIALOG_MODE,
  DIALOG_INTENT,
  ASSISTANT_CONFIG,
  MESSAGE_TYPE,
  NETWORK_CONFIG,
} from './index';

function openAdminDialog(intent: typeof DIALOG_INTENT.CREATE_TICKET) {
  return {
    mode: DIALOG_MODE.DIRECT,
    intent,
    assistant: ASSISTANT_CONFIG.MINGO.type,
  };
}

// Using re-exported wire enums
if (message.type === MESSAGE_TYPE.THINKING) {
  // handle AI thinking state
}

// Configuring NATS client timeouts
const timeout = NETWORK_CONFIG.CONNECT_TIMEOUT_MS;
```

**Note:** `MESSAGE_TYPE` from the lib is a superset (18 keys) of the legacy local const; unknown types are safely tolerated by app switch statements. `APPROVAL_STATUS` includes `CANCELLED`, but this app's NATS wire protocol cannot produce that state — it only decodes `approved`/`rejected` outcomes.
