Type definitions for the ticket/dialog chat system, covering ticket board data (lifecycle status, activity state, approvals) and the message/chat payload shapes exchanged between clients, AI assistants, and admins.

## Key Components

- **`TicketActivityState` / `TicketActivityFilter`** — live activity state of a ticket (`AI_WORKING`, `AWAITING_EXTERNAL`, `IDLE`) versus server-side board filter values (`ACTIVE`, `STALE`, `AWAITING_EXTERNAL`).
- **`DialogOwner` / `ClientDialogOwner` / `DialogOwnerEnum`** — identifies whether a dialog belongs to a `CLIENT` (with associated `Machine`) or `ADMIN`.
- **`Machine`** — device metadata (`id`, `hostname`, `nickname`, `organizationId`) used to resolve display names.
- **`Dialog`** — the core ticket/dialog record, combining lifecycle board fields (status, transitions, resolution), v2 ticket fields (assignee, tags, attachments, notes, token usage), and activity tracking (`lastActivityAt`, `unreadMessageCount`, `pendingApproval`).
- **`DialogRating`, `ChatTypeTokenUsage`** — supporting sub-records for ratings and per-chat-type token accounting.
- **`DialogConnection` / `DialogEdge` / `CursorPageInfo`** — cursor-based pagination wrapper for dialog lists.
- **`Message` and owner/data variants** — chat message model: `MessageOwner` subtypes (`ClientOwner`, `AssistantOwner`, `AdminOwner`) and `MessageData` subtypes (`TextData`, `ErrorData`, `ExecutingToolData`, `ExecutedToolData`, `ApprovalRequestData`, `ApprovalResultData`, `SystemData`, `TicketEventData`).
- **`MessageConnection` / `MessageEdge`** — cursor-based pagination wrapper for message lists.

## Usage Example

```typescript
import type { Dialog, Message, TextData, ExecutingToolData } from './dialog.types';

function isAiWorking(dialog: Dialog): boolean {
  return dialog.activityState === 'AI_WORKING';
}

function renderMessage(message: Message): string {
  switch (message.messageData.type) {
    case 'TEXT':
      return (message.messageData as TextData).text;
    case 'EXECUTING_TOOL': {
      const data = message.messageData as ExecutingToolData;
      return `Running ${data.toolFunction}...`;
    }
    default:
      return '[unsupported message type]';
  }
}
```
