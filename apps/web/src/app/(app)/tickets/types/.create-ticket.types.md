Defines the Zod validation schema and inferred TypeScript type for the ticket creation form, enforcing field constraints and handling nullable autocomplete inputs.

## Key Components

- **`createTicketSchema`** — Zod object schema validating ticket creation fields:
  - `title`: required string, 1–255 characters
  - `description`: string, max 5000 characters
  - `statusId`, `organizationId`, `deviceId`, `assignedTo`: nullable/optional strings (support autocomplete fields that emit `null` on clear)
  - `tagIds`: array of strings, max 20 entries
  - `userId`: optional string (reporter field, pending backend/Authentik support)
  - `type`: string (pending backend support)
  - `assignKnowledgeBase`: boolean
  - `assignments`: nested schema imported from `assignmentsSchema`
- **`CreateTicketFormData`** — TypeScript type inferred from `createTicketSchema` via `z.infer`, used for form state typing.

## Usage Example

```typescript
import { createTicketSchema, type CreateTicketFormData } from './create-ticket.types';

const formData: CreateTicketFormData = {
  title: 'Printer not working',
  description: 'The office printer is jammed.',
  statusId: null,
  organizationId: 'org-123',
  deviceId: null,
  assignedTo: null,
  tagIds: ['tag-1', 'tag-2'],
  userId: undefined,
  type: 'incident',
  assignKnowledgeBase: false,
  assignments: { /* assignments schema fields */ },
};

// Validate before submission
const result = createTicketSchema.safeParse(formData);
if (!result.success) {
  console.error(result.error.flatten());
}
```

This schema is typically used with form libraries like `react-hook-form` via `zodResolver(createTicketSchema)` to drive validation and type-safe form state in the ticket creation UI.
