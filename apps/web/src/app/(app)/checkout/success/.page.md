## CheckoutSuccessPage

Next.js page component rendered after a successful Stripe Checkout redirect, confirming the payment and guiding the user back into the app.

This page only ever loads via a cold, full-page navigation (Stripe redirects the browser), so it carefully gates visibility using both a synchronous shell check (`isBillingHidden()`) and an asynchronous feature flag (`useFeatureFlagGate('billings')`). Since the flag is uncached and unresolved on first render, the component treats `'loading'` as a pending state rather than prematurely calling `notFound()` — avoiding a permanent 404 for paying customers that would otherwise occur on every cold load.

## Key Components

- **`CheckoutSuccessPage`** — Default export; the page component itself.
- **`useFeatureFlagGate('billings')`** — Resolves to `'on'`, `'off'`, or `'loading'`; only a resolved `'off'` triggers `notFound()`.
- **`isBillingHidden()` / `isBillingReadOnly()`** — Build-time/shell-level checks from `billing-visibility.ts` that can hide the page outright.
- **`CheckoutResultCard`** — Shared UI component used to render the success state, with a `pending` prop for the loading flag state.

## Usage Example

```typescript
// Rendered automatically by Next.js when Stripe redirects to this route,
// e.g. after a successful checkout session completes.

// Example of the gating pattern reused elsewhere (e.g. billing-usage/page.tsx):
const gate = useFeatureFlagGate('billings');
if (isBillingHidden() || isBillingReadOnly() || gate === 'off') {
  notFound();
}

// Only render the final UI once the gate is resolved or explicitly 'on',
// passing `pending` so the result card can show a loading state instead
// of flashing a 404.
```
