# page.tsx (Checkout Success)

Client-side Next.js page rendered after a successful Stripe Checkout redirect, confirming payment and guiding the user back into the app.

## Key Components

- **`CheckoutSuccessPage`** — Default export; a client component that gates access via billing feature flags and renders a success confirmation card.
- **Gating logic** — Combines `isBillingHidden()`, `isBillingReadOnly()`, and `useFeatureFlagGate('billings')` to decide whether to call `notFound()`. Critically, it only triggers a 404 when the gate resolves to `'off'` — never while `'loading'` — since this page is always reached via a cold load (full browser navigation from Stripe) where the flag store starts unanswered.
- **`CheckoutResultCard`** — Shared presentational component used to render the success message, icon, and CTAs, with a `pending` state while the flag resolves.

## Usage Example

This page is routed automatically by Next.js App Router (e.g. `app/checkout/success/page.tsx`) and is not invoked manually. Stripe redirects here after a successful checkout session:

```typescript
// Stripe Checkout session configuration (elsewhere in the app)
const session = await stripe.checkout.sessions.create({
  success_url: `${baseUrl}${routes.checkoutSuccess}`,
  // ...
});
```

The page itself requires no props — it derives all state from feature flags and billing visibility helpers:

```typescript
import CheckoutSuccessPage from './page';

// Rendered by Next.js when the route matches
<CheckoutSuccessPage />
```

**Important:** When replicating this gating pattern elsewhere, always check the resolved flag value (`'off'`) rather than treating "not yet loaded" as "disabled," to avoid permanently 404-ing users on cold loads.
