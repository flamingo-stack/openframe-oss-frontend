# page.tsx (Checkout Cancel)

Client-rendered Next.js page displayed when a user cancels a checkout/payment flow. It gates access behind the `billings` feature flag and billing visibility settings, then renders a standardized result card informing the user that no charges were made.

## Key Components

- **`CheckoutCancelPage`** — Default export; the page component rendered at the checkout cancel route.
- **Feature gating logic** — Uses `useFeatureFlagGate('billings')` combined with `isBillingHidden()` and `isBillingReadOnly()` to determine whether the page should 404 via `notFound()`. The page waits for the flag to resolve (`gate === 'loading'`) before definitively hiding content, avoiding a flash of a 404 before the flag answer arrives.
- **`CheckoutResultCard`** — Shared presentational component (imported from `../components/checkout-result-card`) used to render the cancellation message, icon, and call-to-action buttons.

## Usage Example

This file is a route-level page component and is not imported directly elsewhere. It is automatically rendered by Next.js when a user navigates to the checkout cancel route (e.g., after a payment provider redirects back following cancellation).

```typescript
// Example: redirecting to this page after a canceled checkout session
import { routes } from '@/lib/routes';

function redirectToCancelPage(router: { push: (href: string) => void }) {
  router.push(routes.checkout.cancel());
}
```

**Behavior notes:**
- If billing is hidden, read-only, or the `billings` feature flag is explicitly `off`, the page triggers Next.js's `notFound()`.
- While the flag is still resolving (`loading`), the card renders in a `pending` state rather than prematurely showing a 404.
- CTAs let the user return to the billing/usage settings page (`routes.settings.billingUsage()`) or navigate to the dashboard (`routes.dashboard`).
