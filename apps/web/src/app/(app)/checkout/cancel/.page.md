# Checkout Cancel Page

A Next.js client page component that renders a cancellation confirmation screen when a user aborts a billing checkout flow, gated behind feature flag and billing visibility checks.

## Key Components

- **`CheckoutCancelPage`** (default export) — React component that:
  - Checks the `billings` feature flag via `useFeatureFlagGate` and triggers `notFound()` if billing is hidden, read-only, or the flag is explicitly off.
  - Renders a `CheckoutResultCard` configured for a cancellation state (error-styled icon, "Payment Cancelled" messaging).
  - Supports a `pending` state while the feature flag is still loading, preventing premature rendering decisions.

## Usage Example

This page is automatically routed by Next.js App Router (e.g., at a path like `/checkout/cancel`) and requires no manual invocation. It integrates with:

```typescript
// Navigating to this page after a cancelled Stripe/payment checkout
import { routes } from '@/lib/routes';

router.push(routes.checkout.cancel()); // example route helper usage
```

The component relies on shared utilities for consistent gating logic:

```typescript
import { useFeatureFlagGate } from '@/app/hooks/use-feature-flag';
import { isBillingHidden, isBillingReadOnly } from '@/lib/billing-visibility';

const gate = useFeatureFlagGate('billings');
if (isBillingHidden() || isBillingReadOnly() || gate === 'off') {
  notFound();
}
```

**Note:** This page mirrors the gating logic in the sibling `success/page.tsx` route to ensure consistent behavior across checkout outcomes — see that file for detailed reasoning on why the flag check guards against a flash of a 404 before the flag value resolves.
