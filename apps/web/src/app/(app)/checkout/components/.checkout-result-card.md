A reusable client-side card component for displaying checkout outcome screens (e.g., success or cancellation pages after a Stripe redirect), featuring an icon, title, description, and one or two call-to-action buttons.

## Key Components

- **`CheckoutResultCard`** — Default-exported React component that renders a centered card with:
  - An icon wrapped in a styled circular badge (`iconWrapperClassName` controls background/color)
  - A title (`h1`) and description (`h4`, accepts `ReactNode` for rich content)
  - A primary CTA button (always rendered) and an optional secondary CTA button, both navigating via `next/navigation`'s `useRouter`
  - A `pending` flag that disables both buttons while the page awaits confirmation of its own access state (e.g., a billing gate check), without altering the already-true message being shown

- **`CheckoutResultCardProps`** — Prop interface defining `icon`, `iconWrapperClassName`, `title`, `description`, `primaryCta`, `secondaryCta`, and `pending`.

## Usage Example

```typescript
import { CheckInCircle } from 'lucide-react';
import { CheckoutResultCard } from './checkout-result-card';

export default function CheckoutSuccessPage() {
  return (
    <CheckoutResultCard
      icon={CheckInCircle}
      iconWrapperClassName="bg-ods-success/10 text-ods-success"
      title="Payment successful"
      description="Your subscription is now active. You can manage billing details anytime."
      primaryCta={{ label: 'Go to dashboard', href: '/dashboard' }}
      secondaryCta={{ label: 'View invoice', href: '/billing/invoices' }}
      pending={false}
    />
  );
}
```

Use `pending={true}` while an async check (such as verifying billing access) is in flight, so the buttons are disabled but the confirmed message remains visible instead of showing loading placeholders.
