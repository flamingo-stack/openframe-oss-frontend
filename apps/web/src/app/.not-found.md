A Next.js "not found" page that silently redirects legacy path-parameter URLs to their modern query-parameter equivalents, preventing dead-ends for users arriving via bookmarks or pre-migration links.

## Key Components

### `LEGACY_ID_ROUTES`
Array of old route patterns using `{id}` as a placeholder (e.g., `/devices/details/{id}`). When matched, the path-param `id` is extracted and rewritten as a `?id=` query parameter.

### `LEGACY_RENAMED_ROUTES`
A lookup map of routes that were renamed (e.g., `/scripts/create` → `/scripts/new`). Matched before the `{id}` pattern scan to avoid ambiguous redirects via the `?id=new` sentinel.

### `remapLegacyPath(pathname, search)`
Pure function that resolves a legacy pathname to a modern URL. Returns `null` if no legacy pattern matches — preventing interference with genuine 404s.

- Strips trailing slashes before matching
- Handles percent-encoded path segments by decoding before passing to `URLSearchParams`
- Preserves existing query parameters when rewriting

### `NotFound` (default export)
Client component that runs `remapLegacyPath` in a `useEffect` and calls `router.replace()` if a target is found, preserving the URL hash. Falls back to a "Page Not Found" UI via `ContentPageContainer` when no legacy route matches.

## Usage Example

```typescript
// A user visits a bookmarked legacy URL:
// /devices/details/abc-123/remote-shell

// remapLegacyPath produces:
// /devices/details/remote-shell/?id=abc-123

// A renamed route:
// /scripts/create  →  /scripts/new/

// No match (genuine 404):
// remapLegacyPath returns null → "Page Not Found" UI renders
```
