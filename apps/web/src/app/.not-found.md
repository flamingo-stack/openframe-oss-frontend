# not-found.tsx

Next.js catch-all `NotFound` page that transparently redirects legacy URLs to their new locations before falling back to a genuine 404 message. It exists to preserve old bookmarks, browser history entries, and shared links created before routes were migrated from path-params (for example `/devices/details/123`) to query-params (`/devices/details/?id=123`), and before module renames/relocations (such as the retired `scripts-v2` feature flag prefix or Cloud Tenant Management moving out of Settings).

This component is only reached after the router has already failed to match a real route, so the remap tables can never shadow legitimate pages.

## Key Components

- **`LEGACY_ID_ROUTES`** — list of old path-param route patterns (using `{id}` placeholders) that must be rewritten to the equivalent `?id=` query-param route.
- **`LEGACY_RENAMED_ROUTES`** — direct string-to-string map for routes that were renamed or relocated outright (e.g. `/scripts/create` → `/scripts/new`, `/settings/tenant-management` → `/cloud-tenant-management`).
- **`LEGACY_ID_OVERRIDES`** — corrections for ambiguous `{id}` patterns, specifying an alternate `target` path or a list of `reserved` segment values that must not be treated as an id (e.g. `run`, `edit`, `devices`).
- **`dropV2Prefix(path)`** — strips the obsolete `/scripts-v2` prefix, remapping it to `/scripts`.
- **`remapLegacyPath(pathname, search)`** — core resolver that normalizes the incoming path, checks the renamed-routes map, then attempts a segment-by-segment match against `LEGACY_ID_ROUTES`, decoding and injecting the id as a query param. Returns `null` if no legacy pattern matches.
- **`NotFound` (default export)** — the page component. On mount, it computes a redirect target via `remapLegacyPath` and calls `router.replace()` if one is found (preserving the URL hash); otherwise it renders a "Page Not Found" message using `ContentPageContainer`.

## Usage Example

This file is automatically used by Next.js as the app-wide 404 handler and requires no manual invocation:

```typescript
// app/not-found.tsx
// Automatically rendered by Next.js when no route matches.
// No explicit import or usage needed elsewhere in the app.
```

To extend legacy redirect support for a newly renamed route, add an entry to the appropriate table:

```typescript
const LEGACY_RENAMED_ROUTES: Record<string, string> = {
  // ...existing entries
  '/old/path': '/new/path',
};
```

For a path-param route migrated to `?id=`, add a pattern to `LEGACY_ID_ROUTES` using `{id}` as the placeholder segment, and add an entry to `LEGACY_ID_OVERRIDES` only if the pattern is ambiguous with real sub-routes.
