# agent-identity-root.tsx

A client component that wraps the application tree with `AgentIdentityProvider`, supplying the AI agents' (Fae, Mingo) identity data—including their avatar marks—fetched once from a shared content endpoint.

## Key Components

- **`AGENT_IDENTITIES_URL`** — Constant URL pointing to the AI agents content API, built from `CONTENT_ORIGIN`.
- **`AppAgentIdentityProvider`** — Root-level provider component that conditionally enables fetching of agent identities based on authentication/session readiness, and renders `AgentIdentityProvider` from `@flamingo-stack/openframe-frontend-core/components` around its children.

## Usage Example

```typescript
// app/layout.tsx (root layout, mounted above notifications provider)
import { AppAgentIdentityProvider } from './agent-identity-root';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <AppAgentIdentityProvider>
          {/* NotificationsProvider and app tree go here */}
          {children}
        </AppAgentIdentityProvider>
      </body>
    </html>
  );
}
```

**Important placement notes:**
- Must be mounted in the **root layout**, above the notifications provider—not inside the `(app)` route group—since notification popups (e.g., Mingo notification tiles) render outside `(app)`'s tree and require access to this provider.
- The `enabled` prop is gated on `isReady && isAuthenticated` from `useAuthSession`: fetching identities before the session is ready can trigger a refused request and an unwanted token refresh that may interrupt an in-progress sign-in.
- On signed-out auth pages, no identity data is fetched.
