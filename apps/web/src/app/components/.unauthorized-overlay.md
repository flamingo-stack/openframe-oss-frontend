Full-screen "Sign in required" screen a SaaS tenant shows when the session is gone (`AppLayoutInner` renders it once the auth check is ready and the user is not authenticated). Its Sign in button always ends somewhere visible: a navigation to the auth host, or an error.

## Key Components

**`UnauthorizedOverlay`** — the screen, with no props.

**`buildSignInUrl(sharedHost)`** — the auth host's Login tab (`<host>/auth/login/`), or `null` when `NEXT_PUBLIC_SHARED_HOST_URL` is empty or not an absolute http(s) URL.

**`SIGN_IN_PENDING_TIMEOUT_MS`** — 10 s: how long Sign in stays pending when the page never leaves.

**`handleLogin`** — the Sign in tap:

1. **Native shell** — `router.replace(routes.auth.root)`, the in-app sign-in, so the auth screens don't stack on the back history.
2. **Auth host configured** — records the tap (`captureSignInRequiredClick`), sets the button pending (spinner, disabled) and calls `window.location.assign` on the Login tab.
3. **Auth host missing or invalid** — records the tap with `fallback: true`, logs `console.error` and shows an inline error ("Sign-in is unavailable right now. Please contact support."). There is no relative fallback: a SaaS tenant redirects every `/auth` path back into the app.

## Pending state

- The first tap sets it; later taps return early (a ref guards a tap that lands before the render).
- It is cleared on a bfcache restore (`pageshow` with `persisted`, i.e. Back from the auth host), when the navigation throws, and after `SIGN_IN_PENDING_TIMEOUT_MS` if the page never left.

## Analytics

`captureSignInRequiredClick` (`@/lib/posthog/posthog-events`) sends `sign_in_required_click` with `app_mode`, `shell`, `target_url` and `fallback` to the GTM-loaded `window.posthog` with `transport: 'sendBeacon'`, so it survives the navigation. A no-op until the SDK has loaded and in the native shells.
