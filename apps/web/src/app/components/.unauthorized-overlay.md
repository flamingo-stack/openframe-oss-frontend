# unauthorized-overlay.tsx

A client-side React component that displays a "Sign in required" overlay, guiding unauthenticated users to the appropriate login flow depending on whether the app is running inside the native app shell or as a standalone web app.

## Key Components

- **`UnauthorizedOverlayProps`** — Interface defining the optional `onRetry` callback prop, invoked as a fallback when no login URL is available.
- **`UnauthorizedOverlay`** — Default-exported functional component rendering a centered "Sign in required" message with a "Sign in" button. Its `handleLogin` handler branches the navigation logic:
  - **App shell context** (`isAppShell()` is `true`): uses `router.replace(routes.auth.root)` to navigate to the native sign-in flow (email → tenant discovery → provider selection → system-browser OAuth), replacing history so back-navigation after login doesn't return to the login screen.
  - **Web context with configured login URL** (`runtimeEnv.authLoginUrl()`): performs a full-page navigation (`window.location.href`) to the auth host's `auth/login/` path, since the auth host is a different origin and its root defaults to a Sign Up page.
  - **Fallback**: invokes the optional `onRetry` callback if no login URL is configured.

## Usage Example

```typescript
import { UnauthorizedOverlay } from '@/components/unauthorized-overlay';

export function ProtectedPage() {
  const handleRetry = () => {
    window.location.reload();
  };

  return <UnauthorizedOverlay onRetry={handleRetry} />;
}
```

Typically rendered by route guards or data-fetching layers when a request returns a 401/403 status, prompting the user to re-authenticate before retrying access to the protected page.
