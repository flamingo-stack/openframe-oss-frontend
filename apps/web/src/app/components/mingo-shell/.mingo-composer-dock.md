## Overview

`MingoComposerDock` is the session-wide chat composer docked under every page of the Mingo-first shell. It hosts the single `EmbeddableChat` instance for the entire session, preserving draft input, staged context, and uploads across navigation, while routing the chat's header/thread into the dedicated chat page node when applicable.

## Key Components

- **`MingoComposerDock`** — Top-level export; renders the composer section, resolves the current `ComposerRoute` from the pathname, handles mobile sheet/list visibility, and shows a locked loading placeholder (`held` prop) while onboarding/session state resolves.
- **`DockSurface`** — Reads the Mingo chat surface (`useMingoChatSurface`); renders the locked `DockComposerLoading` placeholder until the chat session is enabled, otherwise wraps `DockChat` in a `ChatIdentityProvider`.
- **`DockChat`** — Wires the live `EmbeddableChat`/`ChatComposer` into the Manhattan dock/column system, routing (`useRouter`/`usePathname`), and the composer target/tour hooks.
- **`DockComposerLoading`** — Renders a locked, skeleton version of the composer (with route-specific placeholder, context memory, and page chip) to prevent layout shift while the real chat loads.
- **`ContextChipRow`** — Small layout helper rendering a horizontally scrollable row of context chips.
- **`samePath`** — Utility comparing a href against the current pathname, ignoring query/hash and trailing slashes.

## Usage Example

```typescript
import { MingoComposerDock } from './mingo-composer-dock';

// Mounted once per session in AppLayout's `composerDock` slot
function AppLayout({ children }: { children: React.ReactNode }) {
  const holdsDashboard = useOnboardingHold();

  return (
    <div className="app-shell">
      <main>{children}</main>
      <MingoComposerDock held={holdsDashboard} />
    </div>
  );
}
```

Behind a paywall, the shell should pass `null` instead of rendering `MingoComposerDock`, ensuring no chat traffic is initiated for unauthorized sessions.
