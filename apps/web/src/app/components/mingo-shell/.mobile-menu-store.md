# mobile-menu-store.ts

A lightweight Zustand store that tracks whether the mobile (phone-sized) burger drawer in the application shell's `AppLayout` is open. It serves as a single source of truth shared between the layout component and any UI element (nav links, keyboard shortcuts, drawer actions) that needs to open or close the mobile menu.

## Key Components

- **`MobileMenuStore`** — TypeScript interface describing the store shape: `open` (boolean state) and `setOpen` (setter function).
- **`useMobileMenuStore`** — Zustand hook/store created with `create<MobileMenuStore>()`. Exposes reactive `open` state and `setOpen` action for use in React components.
- **`closeMobileMenu()`** — Convenience function for closing the drawer outside of React render logic (e.g., in event handlers or callbacks). Safe to call even when the drawer is already closed — it's a no-op in that case, and also effectively a no-op on viewports `md` and above where the drawer never opens.

## Usage Example

```typescript
import { useMobileMenuStore, closeMobileMenu } from './mobile-menu-store';

// Inside a React component (e.g., AppLayout)
function AppLayout() {
  const { open, setOpen } = useMobileMenuStore();

  return (
    <MobileDrawer isOpen={open} onClose={() => setOpen(false)}>
      {/* drawer contents */}
    </MobileDrawer>
  );
}

// Toggling open from a burger button
function BurgerButton() {
  const setOpen = useMobileMenuStore(state => state.setOpen);
  return <button onClick={() => setOpen(true)}>☰</button>;
}

// Closing from an unrelated event handler (e.g., "New chat" action)
function NewChatButton() {
  function handleClick() {
    closeMobileMenu();
    // ...start new chat logic
  }
  return <button onClick={handleClick}>New chat</button>;
}
```

Typical triggers for closing include selecting a nav entry, pressing `⌘K` (which may also open it below the `md` breakpoint), or performing an in-drawer action that doesn't navigate (e.g., starting a new chat already on the home screen).
