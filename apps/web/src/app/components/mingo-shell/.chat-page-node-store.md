A Zustand store that coordinates handoff between the chat page (`/mingo/chat`) and the docked `EmbeddableChat` component, synchronizing the DOM portal target and readiness flags needed to avoid layout flicker or premature remounting.

## Key Components

- **`ChatPageNodeStore`** — Interface defining the shared state:
  - `node` / `setNode`: the DOM element the chat page exposes (via ref callback) for the dock to portal its header and thread into. Resets to `null` on unmount.
  - `chatMounted` / `setChatMounted`: tracks whether the dock's lazily-loaded chat module has mounted.
  - `threadReady` / `setThreadReady`: tracks whether the page's active conversation has finished loading, signaling the dock it's safe to portal into `node`.
- **`useChatPageNodeStore`** — The exported Zustand hook instance used by both the chat page and the composer dock to read/write this shared state.

## Usage Example

```typescript
// In the chat page: publish the portal target via ref callback
import { useChatPageNodeStore } from './chat-page-node-store';

function ChatPage() {
  const setNode = useChatPageNodeStore(state => state.setNode);
  const setThreadReady = useChatPageNodeStore(state => state.setThreadReady);

  // ref callback reverts node to null on unmount
  return <div ref={setNode}>{/* skeleton shown until threadReady */}</div>;
}

// In the composer dock: consume the state to decide rendering
function ComposerDock() {
  const { node, chatMounted, threadReady } = useChatPageNodeStore();

  if (node && chatMounted && threadReady) {
    // safe to portal header + thread into `node`
  }
}
```
