# use-chat-behind-page.ts

A React hook that persists the "chat behind page" selection in `sessionStorage` so it survives a tab reload, while keeping the restoration scoped to pages where a background chat sheet is applicable.

## Key Components

- **`useChatBehindPage({ route, state })`** — Hook that restores and persists the active dialog ID tied to the chat sheet shown behind certain pages. It:
  - Reads a previously stored chat ID from `sessionStorage` on mount (once per mount, guarded by `restoredRef`).
  - Only restores the chat if there is no currently active dialog, the current route `isSheetRoute(route)`, and the stored ID still exists in the loaded `dialogs` list (archived/deleted chats are ignored).
  - Writes the active dialog ID to storage on every subsequent change, but only after the initial restore pass has completed — preventing an empty initial state from clobbering the stored value before it's read.
- **`readChatId()` / `writeChatId(id)`** — Internal helpers wrapping `window.sessionStorage` access in `try/catch` to gracefully degrade when storage is blocked (e.g., private browsing).
- **`STORAGE_KEY`** — `'of.mingo-chat-behind-page'`, the session-scoped storage key (per-tab, not shared across tabs).

## Usage Example

```typescript
'use client';

import { useChatBehindPage } from './use-chat-behind-page';
import { useUnifiedChatState } from '@flamingo-stack/openframe-frontend-core/components/chat';
import { useComposerRoute } from './mingo-dock-route';

function MingoDock() {
  const route = useComposerRoute();
  const state = useUnifiedChatState();

  // Restores the previously open chat (if any) when this tab reloads
  // on a page that displays a chat sheet behind it.
  useChatBehindPage({ route, state });

  return null; // renders the dock/sheet elsewhere based on `state`
}
```

**Notes:**
- This hook does not run on the home page (always starts a new chat) or the dedicated chat page (which selects its own `?id=` query param instead).
- The restore effect waits for `isDialogsLoading` to resolve to `false` before attempting to match the stored ID against the loaded `dialogs` list.
