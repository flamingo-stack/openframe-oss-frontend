# use-approval-decider.ts

A React hook that centralizes the Approve/Reject decision logic for the "Needs approval" page, ensuring decisions propagate consistently across every surface that displays approval requests (notification drawer, tickets board, chat list, and Mingo chat threads).

## Key Components

- **`ApprovalDecider`** — Interface describing the hook's return shape:
  - `kept`: A map of cards already decided on this page, retained on screen (with their resolved decision) until navigation away.
  - `decide(card, approve)`: Executes the approve/reject mutation, updates related caches and stores, and throws on failure so the calling tile can roll back its optimistic UI state.
  - `complete(card)`: Marks related notifications as read and invalidates the notifications query, typically called after a successful decision.

- **`useApprovalDecider()`** — The main hook. Internally wires together:
  - `useApproveRequest` to perform the actual approve/reject mutation.
  - `settleApprovalCaches` to drop the resolved request from tickets/chat list caches.
  - `useMingoMessagesStore` to flip the approval card status inside any loaded Mingo chat thread.
  - `useOptionalNotifications` to mark corresponding notifications as read.
  - Local `kept` state to track decisions made during the current page visit.

## Usage Example

```typescript
import { useApprovalDecider } from './use-approval-decider';

function ApprovalTile({ card }: { card: ApprovalCard }) {
  const { kept, decide, complete } = useApprovalDecider();
  const resolvedCard = kept[card.approvalRequestId] ?? card;

  const handleApprove = async () => {
    try {
      await decide(card, true);
      complete(card);
    } catch (error) {
      // Roll back optimistic UI state on failure
      console.error('Approval failed', error);
    }
  };

  return (
    <button onClick={handleApprove} disabled={!!resolvedCard.decision}>
      {resolvedCard.decision ?? 'Approve'}
    </button>
  );
}
```

The hook must be used within a component tree that has access to `QueryClientProvider`, the auth store, and (optionally) the notifications provider.
