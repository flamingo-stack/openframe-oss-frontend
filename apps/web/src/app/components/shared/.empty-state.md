# empty-state.tsx

A client-side component providing a consistent, vertically-centered empty state for list and page views. It wraps `NoData` and dynamically calculates a fill height so the empty state visually occupies the remaining space in its scroll container, with a `60vh` minimum.

## Key Components

- **`EmptyStateProps`** — Type alias for `NoDataProps`, re-exported for consumer convenience.
- **`oneLineEmptyState(title)`** — Helper that builds `EmptyStateProps` for a single-line message, explicitly suppressing the default `description` text (e.g., "Try adjusting your search or filters") that a table body's deprecated `emptyMessage` prop would otherwise imply.
- **`EmptyState(props)`** — The main component. Renders a centered `NoData` element inside a container that:
  - Measures the nearest scrolling `<main>` ancestor and the page's outermost non-`display: contents` wrapper.
  - Computes the free space between the page content's bottom edge and the scroll container's bottom edge.
  - Sets `minHeight` to `max(60vh, computedFillHeight)` using `useLayoutEffect` to avoid a visible jump on mount.
  - Re-measures on resize via `ResizeObserver` and a `window.resize` listener.

## Usage Example

```typescript
import { EmptyState, oneLineEmptyState } from './empty-state';

// Simple one-line message, no extra description
function DeviceList({ devices }: { devices: Device[] }) {
  if (devices.length === 0) {
    return <EmptyState {...oneLineEmptyState('No devices found')} />;
  }
  return <DeviceTable devices={devices} />;
}

// Full control with title, description, and action
function TicketsPage({ tickets }: { tickets: Ticket[] }) {
  if (tickets.length === 0) {
    return (
      <EmptyState
        title="No tickets yet"
        description="Create your first ticket to get started."
        action={<Button onClick={createTicket}>New Ticket</Button>}
      />
    );
  }
  return <TicketsTable tickets={tickets} />;
}
```

**Note:** `EmptyState` must be rendered inside the app's `<main>` scroll container (as provided by `AppLayout`) for the fill-height measurement to behave correctly; outside that context it falls back to viewport height.
