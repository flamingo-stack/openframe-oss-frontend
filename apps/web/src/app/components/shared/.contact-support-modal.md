# contact-support-modal.tsx

A reusable support-ticket modal component that submits tickets through the shared HubSpot-backed ticket pipeline, with an optional "Call Me Back" tab and file-attachment support. Designed to work even on locked workspaces, since it bypasses the app's gated Relay endpoint in favor of the content gateway's `embedAuthedFetch`.

## Key Components

- **`ContactSupportModal`** — The main configurable modal component. Renders a subject field (free-text or pick-list via the `subjects` prop), a message textarea with character counter/cap, file attachments (reusing the chat composer's upload pipeline), and an optional second "Call Me Back" tab when a `callBack` renderer is supplied.
- **`OTHER_SUBJECT`** — Exported constant (`'Other'`) marking the pick-list entry that reveals a free-text subject field.
- **`BillingContactSupportModal`** — A pre-configured wrapper around `ContactSupportModal` for the lock-screen billing flow, with fixed `BILLING_SUBJECTS`, a call-back tab (`BillingCallBack`), and an email fallback footnote.
- **`ContactSupportModalProps`** — Prop interface controlling title, labels, subject list, footnote content, and the call-back renderer.

## Usage Example

```typescript
import { useState } from 'react';
import { ContactSupportModal, BillingContactSupportModal } from './contact-support-modal';

function SupportTrigger() {
  const [open, setOpen] = useState(false);

  return (
    <>
      <button onClick={() => setOpen(true)}>Contact Support</button>
      <ContactSupportModal
        open={open}
        onOpenChange={setOpen}
        title="Contact Support"
        submitLabel="Send"
      />
    </>
  );
}

// Lock-screen billing variant with preset subjects and call-back tab
function BillingLockScreen() {
  const [open, setOpen] = useState(false);

  return (
    <BillingContactSupportModal open={open} onOpenChange={setOpen} />
  );
}
```

Tickets are submitted via `useTicketActions().submitTicket`, which handles toast notifications on success/failure internally. The cache-management callbacks (`prependOptimistic`, `removeOptimistic`, `removeTicketFromCache`) are intentionally no-ops since this modal has no list view to update optimistically.
