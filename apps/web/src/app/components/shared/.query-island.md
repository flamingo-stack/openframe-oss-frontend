Client component that provides a shared, Suspense-friendly Relay query reader, enabling multiple independently-suspending UI fragments on a page to consume the same GraphQL query without duplicating network requests.

## Key Components

- **`QueryIsland<TQuery>`** — Generic React component that calls `useLazyLoadQuery` with the given query, variables, and cache options, then renders its `children` render-prop with the resolved data.
- **`QueryIslandProps<TQuery>`** — Props interface defining `query` (a `GraphQLTaggedNode`), `variables`, optional `fetchPolicy` and `networkCacheConfig`, and a `children` function that receives the query's response type.
- Integrates with `useRetryKey` (from `content-error-boundary`) to supply a `fetchKey`, allowing error boundaries to force a refetch by bumping the retry key.

## Usage Example

```typescript
import { Suspense } from 'react';
import { QueryIsland } from './query-island';
import { MyPartQuery } from './__generated__/MyPartQuery.graphql';

function MyPart({ userId }: { userId: string }) {
  return (
    <Suspense fallback={<PartSkeleton />}>
      <QueryIsland query={MyPartQuery} variables={{ userId }}>
        {(data) => <MyPartContent data={data} />}
      </QueryIsland>
    </Suspense>
  );
}
```

Because each part wraps `QueryIsland` in its own `<Suspense>` boundary while sharing the same query shape and variables as sibling parts, Relay deduplicates the underlying network request into one call, letting each part paint independently as its data resolves. Pass `networkCacheConfig` (e.g., `{ skipSubscriptionGate: true }`) to customize network-layer behavior per part.
