# onboarding-guide-button.tsx

Provides a factory function that generates "Learn more" footer-button props for `EmptyState` components, linking users to section-specific onboarding guides in the in-app Help Center.

## Key Components

- **`OnboardingGuideSource`** — Union type of section identifiers (`'queries'`, `'customers'`, `'policies'`, `'scripts'`, `'script-schedules'`, `'logs'`, `'devices'`, `'tickets'`) that may show an onboarding button.
- **`ONBOARDING_GUIDES`** — Internal lookup map associating each section with a `subject` (used in the button label) and a `slug` (Help Center route identifier). Sections omitted from this map render no button. Note that `queries`/`policies` and `scripts`/`script-schedules` intentionally share the same guide slug.
- **`onboardingGuideButton(source)`** — Main exported function. Given an `OnboardingGuideSource`, returns a partial `EmptyStateProps` object (`buttonLabel`, `buttonIcon`, `buttonProps`) ready to spread onto an `EmptyState` component. Returns an empty object `{}` when no guide is configured for the given source, effectively hiding the button.

## Usage Example

```typescript
import { EmptyState } from './empty-state';
import { onboardingGuideButton } from './onboarding-guide-button';

function DevicesEmptyState() {
  return (
    <EmptyState
      title="No devices yet"
      description="Connect your first device to get started."
      {...onboardingGuideButton('devices')}
    />
  );
}
```

```typescript
// Sections without a configured guide render no button
const props = onboardingGuideButton('customers');
// => { buttonLabel: "Learn more about Customers", buttonIcon: <BookOpenIcon ... />, buttonProps: { href: ... } }
```

This pattern keeps onboarding-link configuration centralized, so any `EmptyState` across the app can opt into a contextual Help Center link without duplicating label/icon/href logic.
