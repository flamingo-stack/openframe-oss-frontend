# deleted-user.tsx

Provides shared utilities for representing deleted user accounts consistently across the app, including a re-exported avatar component, a fallback display label, and status-check helpers that distinguish admin-deleted (revivable) from self-deleted (anonymized) accounts.

## Key Components

- **`DeletedUserAvatar`** — Re-exported from `@flamingo-stack/openframe-frontend-core/components/ui`. The visual placeholder (red round user-x icon) for deleted users, kept under one import path alongside the helpers in this file.
- **`DELETED_EMPLOYEE_LABEL`** — Constant string (`'Deleted Employee'`) used as a fallback label on surfaces lacking fresh user data (e.g., denormalized assignee snapshots on tickets).
- **`isDeletedUserStatus(status)`** — Returns `true` if the status is `UserStatus.DELETED` or `UserStatus.SELF_DELETED`, i.e., the account should render with "deleted" styling. `REMOVED` (purged) accounts are intentionally excluded since they never appear in lists.
- **`isSelfDeletedUserStatus(status)`** — Returns `true` only for `UserStatus.SELF_DELETED`, identifying accounts whose personal data (including email) has been anonymized server-side.

## Usage Example

```typescript
import {
  DeletedUserAvatar,
  DELETED_EMPLOYEE_LABEL,
  isDeletedUserStatus,
  isSelfDeletedUserStatus,
} from '@/components/deleted-user';

function AssigneeDisplay({ user }: { user: { status?: string; name?: string; email?: string } }) {
  if (isDeletedUserStatus(user.status)) {
    return (
      <div className="flex items-center gap-2">
        <DeletedUserAvatar />
        <span>{user.name ?? DELETED_EMPLOYEE_LABEL}</span>
        {!isSelfDeletedUserStatus(user.status) && user.email && (
          <span className="text-muted">{user.email}</span>
        )}
      </div>
    );
  }

  return <span>{user.name}</span>;
}
```

**Notes:**
- Surfaces with fresh user data should still prefer the real name/email for admin-`DELETED` users; only fall back to `DELETED_EMPLOYEE_LABEL` when no current user record is available.
- Never display email for `SELF_DELETED` users, since it's a synthetic, anonymized value (`deleted-{id}@deleted.invalid`).
