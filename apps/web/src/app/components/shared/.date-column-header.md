# date-column-header.tsx

A reusable table column header component that combines a sortable label with a date range filter popover (`DateFilterMenu`). It provides a consistent, accessible trigger for date-based sorting and filtering across multiple list views in the application.

## Key Components

- **`DateColumnHeader`** — The main component rendering a column header with a label and calendar icon. When `filter` is provided, the whole header becomes a clickable button opening `DateFilterMenu`; when omitted, it renders an inert skeleton version with identical markup/layout.
- **`DateColumnHeaderProps`** — Props interface: `label` (header text), optional `filter` (enables the interactive state), and optional `actionHint` (screen-reader-only description appended after the visible label).
- **`TableDateFilter`** — Interface describing the filter state passed to the header: `sortDirection` (`'asc' | 'desc'`), `range` (current `DateRange`), and `onApply` callback fired on Apply/Reset.

The component applies an "active" accent style to the calendar icon whenever the list is filtered or sorted away from the default (`desc`), since the header is the only visual indicator of an active date filter.

## Usage Example

```typescript
import { DateColumnHeader } from './date-column-header';
import type { DateFilterResult } from '@flamingo-stack/openframe-frontend-core/components/ui';

function LogsLastActivityHeader() {
  const [sortDirection, setSortDirection] = useState<'asc' | 'desc'>('desc');
  const [range, setRange] = useState<DateRange | undefined>(undefined);

  const handleApply = (result: DateFilterResult) => {
    setSortDirection(result.sort);
    setRange(result.range);
    // trigger refetch / update URL params here
  };

  return (
    <DateColumnHeader
      label="Last Activity"
      filter={{ sortDirection, range, onApply: handleApply }}
    />
  );
}

// Skeleton / loading state — omit `filter` to render an inert placeholder
function LoadingHeader() {
  return <DateColumnHeader label="Last Activity" />;
}
```

**Note:** Always render the skeleton version without the `filter` prop (not with a disabled button) to guarantee identical layout between loading and loaded states.
