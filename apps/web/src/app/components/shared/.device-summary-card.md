# device-summary-card.tsx

A React client component that renders a compact summary card for a device referenced elsewhere in the app (e.g., in a log entry or ticket), wrapping the shared `DeviceCard` UI primitive with status badge and a Details navigation button. It gracefully handles partial or pending device data by falling back to a bare `deviceId` and showing a loading state.

## Key Components

- **`DeviceSummaryCardProps`** — Props interface:
  - `device?: PartialNamedDevice | null` — partially loaded device data
  - `deviceId?: string` — fallback identifier when full device data isn't available yet
  - `loading?: boolean` — triggers the card's built-in loading/skeleton state
  - `onNavigate?: () => void` — callback fired when the Details button navigates (useful for closing overlays/modals)

- **`DeviceSummaryCard`** — Default-exported function component that:
  - Resolves `id` and `machineId` with fallback chains (`device` → `deviceId`)
  - Computes a status tag via `getDeviceStatusConfig` when `device.status` is known
  - Hides the tags row (`showTags={false}`) since tag listing isn't relevant in this summary context
  - Hides the "more" action button and renders a `DeviceDetailsButton` for navigation
  - Delegates all visual rendering to the shared `DeviceCard` component from `@flamingo-stack/openframe-frontend-core`

## Usage Example

```typescript
import { DeviceSummaryCard } from '@/app/(app)/devices/components/device-summary-card';

function TicketDeviceSection({ ticket }: { ticket: Ticket }) {
  return (
    <DeviceSummaryCard
      device={ticket.device}
      deviceId={ticket.deviceId}
      loading={!ticket.device}
      onNavigate={() => closeOverlay()}
    />
  );
}
```

When only a `deviceId` is known (device not yet fetched), the card still renders using the id as a placeholder name/organization:

```typescript
<DeviceSummaryCard deviceId="device-123" loading={true} />
```
