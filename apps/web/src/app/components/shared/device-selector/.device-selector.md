Renders a client-side, selection-oriented device list component that allows users to browse, filter, and select devices from a pre-fetched list — distinct from the server-driven `DevicesPanel`.

## Key Components

### `DeviceSelector` (default export)
The primary component accepting these key props:
- `devices: Device[]` — pre-fetched device array owned by the parent
- `selectedIds: Set<string>` — controlled selection state
- `onSelectionChange: (ids: Set<string>) => void` — selection change callback
- `singleSelect?: boolean` — single vs. multi-select mode
- `readOnly?: boolean` — disables all interaction and hides selection UI
- `infiniteScroll?` — optional infinite scroll configuration
- `addAllBehavior?: 'merge' | 'replace'` — controls add-all behavior
- `isDeviceDisabled?: (device: Device) => boolean` — per-device disable predicate

### Internal Hooks Used
- `useDeviceSelector` — manages search term, active tab, and filtered/displayed device arrays
- `useTagFilterModal` — drives the tag/filter modal across breakpoints

### Key Utilities
- `toggleDevice` — stable callback for toggling a single device selection (uses a ref to avoid stale closures in memoized rows)
- `addAllDevices` / `removeAllSelected` — bulk selection operations
- `clientDeviceFilters` — derives `DeviceFilters`-shaped data client-side from the `devices` prop (no extra network calls)

## Usage Example

```typescript
import { DeviceSelector } from '@/app/components/shared/device-selector';

function MyModal() {
  const [selectedIds, setSelectedIds] = useState<Set<string>>(new Set());

  return (
    <DeviceSelector
      devices={prefetchedDevices}
      loading={isLoading}
      selectedIds={selectedIds}
      onSelectionChange={setSelectedIds}
      singleSelect={false}
      addAllBehavior="merge"
      readOnly={false}
    />
  );
}
```

> **Note:** All filtering is client-side. If the parent passes a partial dataset, filter options and counts reflect only that subset — not the full server dataset. For server-driven pagination with URL state, use `DevicesPanel` instead.
