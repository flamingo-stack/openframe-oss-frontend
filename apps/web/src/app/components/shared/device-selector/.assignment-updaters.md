## assignment-updaters.ts

Relay store updater factory for managing device-to-assignment relationships (e.g., devices joining/leaving a script schedule or software bundle) with optimistic UI updates and minimal re-rendering.

This module encapsulates the store mutations needed when a single device is assigned or unassigned, writing directly to the known-good state rather than re-fetching connections — avoiding a full table re-render on every toggle.

## Key Components

- **`ConnectionNarrowing`** — Interface describing the `filter`/`search` pair that uniquely identifies a `@connection`'s storage key. Since Relay folds all non-pagination arguments into the connection key, updaters must target the exact narrowing the screen is currently reading.
- **`AssignmentOwner`** — Interface describing the record that owns an assignment (e.g., a schedule or bundle), including its global `id` and the `available`/`assigned` connection keys used by its picker UI.
- **`assignmentUpdaters(owner, deviceId, assigned, narrowing)`** — Factory function that returns `{ optimisticUpdater, updater }`, both pointing to the same patch function. It:
  - Flips the `assigned` flag on the matching edge in the **available** connection (without removing it from that list).
  - Inserts or removes the device edge in the **selected/assigned** connection.
  - Adjusts `filteredCount` on the selected connection and `deviceCount` on the owner record by `±1`, guarded by idempotency checks so repeated or out-of-order calls don't double-count.

## Usage Example

```typescript
import { commitMutation } from 'relay-runtime';
import { assignmentUpdaters } from './assignment-updaters';

const { optimisticUpdater, updater } = assignmentUpdaters(
  { id: scheduleGlobalId, keys: { available: 'ScheduleAvailableDevices', assigned: 'ScheduleAssignedDevices' } },
  deviceGlobalId,
  true, // assigning the device
  { filter: currentFilter, search: currentSearch },
);

commitMutation(environment, {
  mutation: AddDeviceToScheduleMutation,
  variables: { scheduleId: scheduleGlobalId, deviceId: deviceGlobalId },
  optimisticUpdater,
  updater,
});
```

Both updaters apply the same patch so the row and counts move instantly on click (optimistic layer), and settle to the same net delta once the real response commits.
