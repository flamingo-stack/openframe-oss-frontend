# device-list-picker.tsx

A self-contained `DeviceSelector` component that fetches its own device data through the shared Relay query layer, managing its own Suspense, loading, and error boundaries so consuming pickers don't need to re-implement fallback logic.

## Key Components

- **`DeviceListPickerProps`** — Props type extending `DeviceSelectorProps` (minus data-related props the component derives internally), adding `filter`, `search`, `first`, `retryKey`, `getDeviceKey`, `selected` (full `Device[]`, not ids), and `onSelectionChange`.
- **`DeviceListPicker`** — Public entry point. Detects whether it's rendering inside a loading scope (e.g., a parent's Suspense fallback) and short-circuits to a skeleton state if so; otherwise wraps the query in an `ErrorBoundary` with retry support.
- **`DeviceListPickerQuery`** — Wraps the actual data-reading component in a `LoadingSuspense` boundary.
- **`DeviceListPickerReader`** — Checks for loading scope again (for the Suspense fallback itself) before rendering the real content.
- **`DeviceListPickerContent`** — Calls `useDeviceList` (which suspends), computes `selectedIds` from the `selected` devices array, and renders the actual `DeviceSelector`.
- **`LoadingDeviceListPicker`** — Renders `DeviceSelector` with no devices and `loading` set, used as the skeleton state.

## Usage Example

```vue
<!-- Usage is from a parent component, e.g. a run-config dialog -->
<script setup lang="ts">
// Conceptual React usage shown below — this file is a .tsx component.
</script>
```

```typescript
function RunConfigDialog({ isOpen }: { isOpen: boolean }) {
  const [selected, setSelected] = useState<Device[]>([]);

  return (
    <>
      {isOpen && (
        <DeviceListPicker
          filter={{ status: 'ONLINE' }}
          search="laptop"
          selected={selected}
          onSelectionChange={setSelected}
          getDeviceKey={device => device.id}
        />
      )}
    </>
  );
}
```

Because selection is returned as full `Device` objects (not just ids), the parent component can remain outside the Suspense boundary and still have everything it needs to submit the selection—no lookup against the internally-fetched device list is required.
