A lightweight inline error strip component for sections whose content survives a fetch failure (e.g., a card list or table toolbar remaining visible). Unlike core-lib's `LoadError`, which replaces content with a bordered error card, this component sits above still-visible (but empty) content to explain the failure and optionally offer a retry action.

## Key Components

- **`SectionLoadErrorProps`** — Interface defining the component's props:
  - `message: string` — the error message to display
  - `onRetry?: () => void` — optional retry callback; omitted when retrying is pointless (e.g., query is paused due to a known-offline link)
- **`SectionLoadError`** — Functional component rendering a status row with the error message and an optional "Retry" button

## Usage Example

```typescript
import { SectionLoadError } from './section-load-error';

function CustomersTable({ error, refetch }: { error?: string; refetch: () => void }) {
  if (error) {
    return (
      <>
        <SectionLoadError message={error} onRetry={refetch} />
        <Table data={[]} />
      </>
    );
  }

  return <Table data={customers} />;
}

// When retry is not applicable (e.g., paused query on offline link):
<SectionLoadError message="Connection unavailable — waiting to reconnect" />
```

## Notes

- Use `SectionLoadError` when the surrounding content (cards, table toolbar, etc.) remains rendered despite the error.
- Use core-lib's `LoadError` instead when there is no surviving content to show (see `customers-overview.tsx` for an example of that case).
- The `onRetry` prop should be derived from helpers like `loadErrorProps` in `lib/query-state.ts`, which determines when retrying is meaningful.
