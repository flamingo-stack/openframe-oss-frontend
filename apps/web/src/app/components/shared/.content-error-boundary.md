## content-error-boundary.tsx

A React class component implementing a scoped error boundary for query-driven content regions, with automatic retry-on-reconnect handling and Relay cache-busting support via a propagated retry key.

## Key Components

- **`RetryKeyContext`** — React context that propagates a retry counter down the tree so descendant queries can compose it into their `fetchKey`, forcing a real refetch instead of re-reading a cached Relay rejection.
- **`useRetryKey()`** — Hook that reads the nearest boundary's retry counter; returns `0` outside any boundary, so it's always safe to call.
- **`ContentErrorBoundary`** — Class component that catches render-time throws (from both Relay's `useLazyLoadQuery` and other sources), distinguishes real failures from Next.js `notFound()`/`redirect()` control-flow throws, and renders a scoped fallback (default `LoadError`, or a custom `fallback` render-prop) instead of crashing the whole page.
  - Props: `children`, `resetKey`, `message`, `onRetry`, `onError`, `label`, `title`, `fallback`.
  - Automatically retries once when connectivity is restored after an offline-caused failure (via `subscribeConnectivity`), guarded by an `autoRetryPending` latch to prevent infinite update loops.
  - Bumps a module-level `latestRetryKey` on commit so sibling/remounted boundaries never reuse a key whose request already failed.
- **`isControlFlowError(error)`** — Internal helper that detects Next.js's internal `NEXT_HTTP_ERROR_FALLBACK*` / `NEXT_REDIRECT*` digest prefixes so those throws are re-thrown instead of swallowed.

## Usage Example

```typescript
import { ContentErrorBoundary, useRetryKey } from './content-error-boundary';

function DeviceList({ searchQuery }: { searchQuery: string }) {
  const retryKey = useRetryKey();
  const data = useLazyLoadQuery(deviceListQuery, { searchQuery, retryKey });
  // ... render data
}

function DevicesPage({ searchQuery }: { searchQuery: string }) {
  return (
    <ContentErrorBoundary
      resetKey={searchQuery}
      title="Devices"
      label="DevicesPage"
      onError={(error) => console.error('Devices failed', error)}
    >
      <DeviceList searchQuery={searchQuery} />
    </ContentErrorBoundary>
  );
}
```

Pass `fallback` when the subtree owns its own `PageLayout` chrome (header, back button, view switcher), so the boundary can redraw that chrome around the error instead of showing a bare `LoadError` card.
