A responsive button component that displays an icon with a text label on desktop viewports and collapses to an icon-only button on mobile, avoiding SSR/hydration mismatches by rendering both variants simultaneously and toggling visibility via CSS breakpoints.

## Key Components

- **`ResponsiveActionButton`** — Main exported component that renders two `Button` instances (desktop and mobile), toggled via the `content-md:` Tailwind breakpoint classes (`hidden content-md:inline-flex` for desktop, `content-md:hidden` for mobile).
- **`ResponsiveActionButtonProps`** — Props interface:
  - `label` (required) — visible text on desktop, used as `aria-label` on the mobile icon-only button.
  - `icon` (required) — leading icon rendered on both breakpoints.
  - `onClick`, `variant`, `disabled` — passed through to both underlying `Button` instances.
  - `className` — extra classes merged (via `cn`) into both buttons.

## Usage Example

```typescript
import { ResponsiveActionButton } from './responsive-action-button';
import { PlusIcon } from 'lucide-react';

export function Toolbar() {
  return (
    <ResponsiveActionButton
      label="Add Device"
      icon={<PlusIcon className="h-4 w-4" />}
      variant="default"
      onClick={() => console.log('Add device clicked')}
    />
  );
}
```

**Notes:**
- Since both buttons render on the server, there's no layout flash or hydration mismatch when switching breakpoints.
- Mirrors the icon-only pattern used by the library's `PageActions` component for consistency across the UI.
- The `content-md:` breakpoint is a custom Tailwind variant (likely scoped to a content container) rather than the default `md:` viewport breakpoint—ensure it's configured in your Tailwind theme.
