## Overview

Provides a React context-based coordination mechanism for revealing multiple page sections simultaneously rather than one at a time. Sections report their data-loading status, and the page transitions from a unified skeleton state to full content in one step once all sections have answered (or after a timeout cap).

## Key Components

- **`REVEAL_CAP_MS`** — Maximum wait time (4000ms) before forcing the page to reveal content even if some sections haven't answered yet.
- **`RevealTogether`** — Provider component that wraps a page's sections, tracking each section's readiness and exposing a shared `held` state via context.
- **`useRevealPart(id, answered)`** — Hook for a section to report whether its data read has completed (errors count as answered).
- **`useRevealWait(id, waiting)`** — Hook for a section whose readiness depends on a child component (e.g., a Relay reader) that mounts only once data is available.
- **`useRevealHeld()`** — Hook returning whether the page is still holding sections in their loading state.

## Usage Example

```typescript
import { RevealTogether, useRevealPart, useRevealHeld } from './reveal-together';

function Section({ id, data, loading }: { id: string; data: unknown; loading: boolean }) {
  useRevealPart(id, !loading);
  const held = useRevealHeld();

  if (held) return <SectionSkeleton />;
  return <SectionContent data={data} />;
}

function Page() {
  return (
    <RevealTogether>
      <Section id="profile" data={profileData} loading={profileLoading} />
      <Section id="stats" data={statsData} loading={statsLoading} />
    </RevealTogether>
  );
}
```

Once all sections have reported `answered: true` (or the `REVEAL_CAP_MS` timeout elapses), `held` flips to `false` for all sections at once, producing a single synchronized transition from skeleton to content instead of a staggered, section-by-section reveal. After the initial reveal, subsequent refetches are handled independently by each section.
