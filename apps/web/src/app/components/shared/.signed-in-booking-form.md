# signed-in-booking-form.tsx

A client-side wrapper around the shared `BookingForm` component that pre-fills the current user's name and email into the meeting scheduler's details form.

## Key Components

- **`SignedInBookingForm`** — A React component that wraps `BookingForm` from `@flamingo-stack/openframe-frontend-core/components/meeting-scheduler`, injecting the signed-in user's `firstName`, `lastName`, and `email` as `initialValues`.
- Reads the current user via `useAuthStore` (from `@/app/(auth)/auth/stores/auth-store`).

## Behavior Notes

- Pre-fill is applied through `initialValues`, **not** `answers`. The `answers` prop only populates the link's custom questions and never touches these built-in fields.
- Defaults are read once, at the details step of the booking flow, after the session has already loaded.
- If the scheduler provides its own values on a remount (e.g., navigating back), those values take precedence over the injected defaults, since `initialValues` passed via `props` is spread before the auth-derived defaults are merged in.

## Usage Example

```typescript
import { SignedInBookingForm } from '@/components/signed-in-booking-form';

export function MeetingScheduler() {
  return (
    <SignedInBookingForm
      onSubmit={handleBookingSubmit}
      // any additional BookingFormProps
    />
  );
}
```

```typescript
// Overriding a default value explicitly
<SignedInBookingForm
  initialValues={{ email: 'custom@example.com' }}
  onSubmit={handleBookingSubmit}
/>
```

This component is intended for use only within authenticated contexts where `useAuthStore` has a populated `user` object; unauthenticated users will simply see empty defaults for name and email.
