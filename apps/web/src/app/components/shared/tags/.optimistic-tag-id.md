Defines a shared convention for identifying optimistic (not-yet-persisted) tag IDs used while a tag creation mutation is in flight, allowing form submission logic to detect and exclude these placeholder IDs before the backend has acknowledged them.

This module is intentionally kept free of Relay `graphql` tags so it can be imported in unit tests without requiring the Relay babel transform.

## Key Components

- **`OPTIMISTIC_TAG_ID_PREFIX`** — String constant (`'_optimistic_'`) used to prefix placeholder tag IDs generated client-side by a tag picker while `createTag` is pending.
- **`isOptimisticTagId(id: string): boolean`** — Checks whether a given tag ID is an optimistic placeholder (i.e., has not yet been replaced by a real, persisted ID from the backend).

## Usage Example

```typescript
import { OPTIMISTIC_TAG_ID_PREFIX, isOptimisticTagId } from './optimistic-tag-id';

// Generating a placeholder id while a create mutation is in flight
const placeholderId = `${OPTIMISTIC_TAG_ID_PREFIX}${crypto.randomUUID()}`;

// Later, in form submission logic, filter out optimistic ids
const selectedTagIds = ['tag_123', placeholderId];
const confirmedTagIds = selectedTagIds.filter((id) => !isOptimisticTagId(id));

if (isOptimisticTagId(placeholderId)) {
  // Avoid sending this id to the backend; wait for createTag to resolve
  // and swap it for the persisted id instead.
}
```

Typical flow: a tag picker optimistically adds a new tag to the UI with an `OPTIMISTIC_TAG_ID_PREFIX`-prefixed id, then once the `createTag` mutation resolves, the picker replaces the placeholder with the real persisted id. Any form submit that races ahead of the mutation completing must use `isOptimisticTagId` to strip out unresolved placeholders before submitting.
