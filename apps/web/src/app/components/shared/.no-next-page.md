Provides reusable constants and types for representing "empty" or "inert" states in lists with infinite scroll behavior, avoiding repeated allocation of no-op objects across the codebase.

## Key Components

- **`noop`** — A shared no-op function used as a placeholder callback for controls that are rendered inert (e.g., loading forms, read-only views).
- **`InfiniteScroll`** — Interface describing the state of a paginated/infinite-scrolling list: whether a next page exists (`hasNextPage`), whether a fetch is in progress (`isFetchingNextPage`), and the handler to request more data (`onLoadMore`).
- **`NO_NEXT_PAGE`** — A singleton `InfiniteScroll` object representing a list with no further pages to load, useful as a default/fallback value before data has loaded.
- **`NO_ITEMS`** — A singleton empty array (`never[]`) representing an empty item list, used for loading or genuinely empty states.

## Usage Example

```typescript
import { NO_NEXT_PAGE, NO_ITEMS, InfiniteScroll } from './no-next-page';

function useDeviceList(isLoading: boolean): { items: Device[]; scroll: InfiniteScroll } {
  if (isLoading) {
    return { items: NO_ITEMS, scroll: NO_NEXT_PAGE };
  }

  return {
    items: fetchedDevices,
    scroll: {
      hasNextPage: true,
      isFetchingNextPage: false,
      onLoadMore: () => fetchNextPage(),
    },
  };
}
```

Using these shared constants avoids creating new objects/arrays on every render when no data is available, which helps prevent unnecessary re-renders in components that rely on referential equality (e.g., `React.memo` or dependency arrays).
