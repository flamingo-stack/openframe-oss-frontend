# queries-table.tsx

A reusable table component for rendering osquery schedule entries (`QueryTableRow[]`), shared between the fleet-wide monitoring queries page and the per-device Queries tab. Supports both paginated and fully-loaded (skeleton) rendering modes, with consistent loading, empty, and row-action states.

## Key Components

- **`formatQueryInterval(seconds: number): string`** — Converts a schedule interval in seconds into a human-readable label (`Manual`, `Every Ns`, `Every Nm`, `Every Nh`, `Every Nd`).
- **`QueriesTableProps`** — Discriminated union type requiring either `pageSize` (paginated mode, with optional `infiniteScroll`) or `skeletonRows` (whole-list mode), plus shared props like `rows`, `isLoading`, `emptyState`, `rowAsLink`, `stickyHeaderOffset`, and `showRowCount`.
- **`QueriesTable(props: QueriesTableProps)`** — Main exported component. Builds columns (Name/Description, Frequency, optional Actions, Open-in-new-tab), manages loading placeholders via `useLoadingScope`, and renders via `LiveTable`.
- **`QueryNameCell`, `QueryFrequencyCell`, `QueryActionsCell`, `QueryOpenCell`** — Internal cell renderers handling per-field loading skeletons and interactive controls (actions menu, open-in-tab button).

## Usage Example

```typescript
import { QueriesTable } from './queries-table';
import type { QueryTableRow } from './query-table-row';

const rows: QueryTableRow[] = [
  {
    id: 'q1',
    name: 'Installed Software',
    description: 'Lists all installed applications',
    frequencyLabel: formatQueryInterval(3600),
    href: '/queries/q1',
    actions: [{ label: 'Edit', onClick: () => {} }],
  },
];

// Paginated usage (fleet-wide monitoring page)
<QueriesTable
  rows={rows}
  pageSize={25}
  infiniteScroll={{ hasNextPage: true, fetchNextPage, isFetchingNextPage }}
  rowAsLink
  showRowCount
/>

// Whole-list usage (device Queries tab)
<QueriesTable
  rows={rows}
  skeletonRows={5}
  emptyState={{ title: 'No queries', description: 'No scheduled queries found.' }}
/>
```

Column count stays stable across loading/loaded states by always reserving the actions column when any row (or loading state) requires it, preventing layout shift ("jitter") as data arrives.
