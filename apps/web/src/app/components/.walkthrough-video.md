# walkthrough-video.tsx

App-shell wrapper around the shared `<FloatingWalkthroughVideo>` component from the core library, mounting the floating demo-video widget once at the application root while handling app-specific layout concerns (sidebar clearance, composer dock clearance, and modal suppression).

This component supplies the data (via `useWalkthroughVideoData`) and positioning logic, while all visual/UI behavior lives in the shared library component. It coordinates with inline video mounts elsewhere in the app (e.g., an onboarding promo) so the same clip is never shown twice simultaneously.

## Key Components

- **`WalkthroughVideo`** — Main exported component. Mounted once in the app shell; renders `null` when a page has claimed the video inline (via `useHasInlineWalkthrough`).
- **`useSidebarWidthVar(scope, enabled)`** — Internal hook that mirrors the live navigation sidebar width into a CSS variable (`--of-sidebar-live-width`) using a `ResizeObserver`, so the floating card's left margin animates in sync with sidebar collapse/expand.
- **`useComposerDockHeightVar(scope, pathname)`** — Internal hook that mirrors the Mingo composer dock's height into a CSS variable (`--of-composer-dock-live-height`) so the card lifts above the dock instead of being covered by it.
- **Constants** — `SIDEBAR_CLEARANCE`, `COMPOSER_DOCK_CLEARANCE`, `MODAL_SUPPRESSION_HOOK` — Tailwind class strings spelled out explicitly (not interpolated) so Tailwind's static source scanner can extract them.

## Usage Example

```typescript
// Mounted once in the root app shell layout
import { WalkthroughVideo } from '@/components/walkthrough-video';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        {children}
        <WalkthroughVideo />
      </body>
    </html>
  );
}
```

**Notes:**
- Do not mount this component per-page — it is designed as a single, app-wide instance.
- It automatically defers to inline video mounts via `useHasInlineWalkthrough`, so no manual coordination is needed on pages that render the walkthrough clip directly.
- Sidebar and composer dock clearances are measured live via `ResizeObserver`, requiring the corresponding DOM elements (`SIDEBAR_ELEMENT_SELECTOR`, `[data-composer-dock]`) to exist in the tree for accurate positioning.
