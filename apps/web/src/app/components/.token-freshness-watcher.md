# token-freshness-watcher.tsx

A client-side React component that proactively rotates a stale access token when a backgrounded browser tab or mobile app view becomes active again, preventing a burst of requests from firing with a dead credential.

## Key Components

- **`TokenFreshnessWatcher`** — A headless (renders `null`) React component that mounts global listeners for app/tab resume events:
  - Listens for the `visibilitychange` DOM event and triggers a refresh check when the document becomes visible.
  - Registers an `onAppResume` listener (from `@/lib/native-shell`) to catch mobile shell resume events, since WKWebView doesn't reliably fire `visibilitychange` when backgrounded.
  - Delegates the actual refresh logic to `refreshIfStale()` (from `@/lib/token-refresh-manager`), which is single-flight and safely no-ops when the token is fresh, absent, or managed by the native shell.
  - Cleans up both listeners on unmount.

## Usage Example

Mount once near the root of the app so it's active for the lifetime of the session:

```typescript
import { TokenFreshnessWatcher } from '@/components/token-freshness-watcher';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <TokenFreshnessWatcher />
        {children}
      </body>
    </html>
  );
}
```

Because it renders nothing, it can be placed anywhere in the component tree without affecting layout — typically alongside other app-wide providers or watchers in a top-level layout component.
