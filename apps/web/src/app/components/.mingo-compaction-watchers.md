# mingo-compaction-watchers.tsx

Manages the lifecycle of manual chat memory compaction requests for Mingo dialogs, tracking each in-flight compaction via a real-time JetStream subscription and surfacing its outcome (success, failure, or timeout) as toast notifications.

## Key Components

- **`requestCompaction(dialogId)`** — Sends the `COMPACT_MINGO_DIALOG_MUTATION` GraphQL request and classifies the server's response into `accepted`, `unconfirmed`, `nothing-to-compact`, or `refused`.
- **`latestStreamSeq(dialogId)`** — Resolves the stream sequence to resume the JetStream consumer from, combining the newest persisted message sequence with the in-memory store's highest known sequence, so no compaction chunks are missed or replayed.
- **`CompactionWatcher({ dialogId })`** — Internal component that drives a single compaction: fetches the resume sequence, subscribes to the dialog's chunk stream, sends the compaction request once subscribed, watches for `CONTEXT_COMPACTION_START`/`END`/`ERROR`/`MESSAGE_END` chunks, and settles with a toast plus store cleanup. Enforces two timeouts: `COMPACTION_STREAM_START_TIMEOUT_MS` (stream never came up) and `COMPACTION_WATCH_TIMEOUT_MS` (request sent but no terminal chunk arrived).
- **`MingoCompactionWatchers()`** — Exported component that mounts one `CompactionWatcher` per dialog id currently tracked in `useMingoCompactionStore`. Designed to be mounted outside the Mingo drawer so compactions keep reporting results even after the drawer closes. Resets the compaction store on unmount to avoid duplicate requests from a later host.
- **`COMPACTION_STREAM_START_TIMEOUT_MS`** / **`COMPACTION_WATCH_TIMEOUT_MS`** — Exported timing constants controlling how long the watcher waits before giving up.

## Usage Example

```typescript
// Mount once, near the Mingo drawer, at a layout level that outlives it:
import { MingoCompactionWatchers } from '@/components/mingo-compaction-watchers';

function MingoLayout() {
  return (
    <>
      <MingoDrawer />
      <MingoCompactionWatchers />
    </>
  );
}

// Triggering a compaction elsewhere just adds the dialog id to the store:
import { useMingoCompactionStore } from '../(app)/mingo/stores/mingo-compaction-store';

function CompactButton({ dialogId }: { dialogId: string }) {
  const startCompaction = useMingoCompactionStore(state => state.startCompaction);
  return <button onClick={() => startCompaction(dialogId)}>Compact chat</button>;
}
```

The watcher component itself is not used directly outside this module—consumers interact only through `useMingoCompactionStore` to queue a dialog for compaction and `MingoCompactionWatchers` to host the active watchers.
