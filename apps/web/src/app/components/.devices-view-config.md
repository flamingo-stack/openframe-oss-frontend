# devices-view-config.tsx

Application-level configuration provider that supplies app-specific context (routing, notifications, image resolution, and mobile shell detection) to the shared core library's device view components (device table, grid, and picker).

This component bridges the generic `openframe-frontend-core` package with app-specific concerns that the core library cannot know about on its own, such as route construction and notification entity linking.

## Key Components

- **`DevicesViewConfig`** — A context provider component that wraps children with `DevicesViewConfigProvider`, supplying a memoized configuration object consumed by core device view components.

The provided configuration includes:
- `getDeviceHref` — builds the device details route using `routes.devices.details`
- `getDeviceNotificationsHref` — builds a notifications route scoped to the device's agent (`machineId`); returns `undefined` if the device has no agent (and thus no notifications)
- `resolveImageUrl` — resolves customer image paths to full URLs via `getFullImageUrl`
- `isMobileShell` — boolean flag from `useIsMobileShell`, indicating whether the page is rendered inside the mobile shell

## Usage Example

Mount once near the root of the application layout, above any pages that render device views:

```typescript
import { DevicesViewConfig } from '@/app/devices-view-config';

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <DevicesViewConfig>
      {children}
    </DevicesViewConfig>
  );
}
```

Once mounted, any descendant component from `@flamingo-stack/openframe-frontend-core/components/features` (such as the devices table, grid, or picker) automatically receives this configuration via context, without needing props drilled through intermediate components.
