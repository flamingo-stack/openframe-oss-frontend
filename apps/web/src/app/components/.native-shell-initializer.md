## native-shell-initializer.tsx

A headless React client component that bootstraps platform-specific startup behavior for native app shells (mobile and desktop), coordinating token hydration, splash screen dismissal, native back navigation, notification click handling, and download-link attribution.

## Key Components

- **`NativeShellInitializer`** — The exported component. Renders nothing (`return null`); runs all setup logic inside a single `useEffect`.
- **Module-level guards** (`nativeClickHandlingInitialized`, `downloadLinkHandlingInitialized`, `bundleBootConfirmed`) — Ensure one-time registration of listeners/reports across React remounts, since the native shell's event transport outlives the component lifecycle.
- **Shared step** — `initKeyboardInset()` runs unconditionally (even on touch web), handling visual viewport adjustments.
- **Shell gate** — Everything else is skipped unless `isAppShell()` is true; sets `document.documentElement.dataset.shell` and calls `primeShellVersion()`.
- **Mobile-only steps** — `initNativeChrome()` (status bar/safe-area), `initNativeBack()` (hardware back), `confirmBundleBooted()` (OTA update boot report).
- **Shared step** — `initTokenStore()` hydrates auth tokens, then `hideSplashScreen()` fires once settled (covers biometric unlock delays).
- **Desktop-only steps** — Registers native notification click handling (`onNativeNotificationClick`, `takeNativeStartupNotificationClick`) that routes via `followNotificationTap`/`resolveNatsNotificationAction`, and download-link handling (`onDesktopDownloadLink`, `takeDesktopDownloadId`) that persists via `storeDownloadId`.

## Usage Example

```typescript
// app/layout.tsx
import { NativeShellInitializer } from '@/components/native-shell-initializer';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <NativeShellInitializer />
        {children}
      </body>
    </html>
  );
}
```

Mount it once near the root of the app tree. It requires no props and performs all work as side effects, making it safe to include unconditionally — it no-ops outside of a recognized native shell (except for the cross-platform keyboard inset logic).
