# route-error.tsx

A shared, page-weight error UI rendered by Next.js route-segment error boundaries (`app/error.tsx` and `(app)/error.tsx`). It centralizes error logging, accessibility focus management, and recovery actions for any route that crashes.

## Key Components

- **`RouteError`** — The default-exported (named) component rendered at the route-segment boundary level. Accepts:
  - `error: Error & { digest?: string }` — the thrown error, logged to console with a `[label]` prefix via a `useEffect`.
  - `reset: () => void` — Next.js's recovery callback; re-renders the segment against the same Relay environment ("Try Again").
  - `label: string` — identifies which boundary caught the error in console output.

  On mount, it auto-focuses the "Try Again" button (via `retryRef`) since `PageLayout`'s heading absorbs the natural focus target, ensuring keyboard/AT users land on a recovery control. It renders two actions: **Try Again** (`reset()`, retains the existing Relay environment) and **Reload** (`window.location.reload()`, builds a fresh environment and clears any temporarily-retained query resources).

This component intentionally avoids core-lib's `PageError`/`ErrorState`, which is a closed component fixed to Try Again / Go Home actions inside a bordered, in-page card — unsuitable for a full route replacement that needs page-weight presentation and a Reload action instead of Go Home.

## Usage Example

```typescript
// app/(app)/error.tsx
'use client';

import { RouteError } from '@/components/route-error';

export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  return <RouteError error={error} reset={reset} label="app-segment" />;
}
```

Each route boundary (`app/error.tsx`, `(app)/error.tsx`) supplies its own `label` to distinguish log output while sharing identical rendered output and behavior.
