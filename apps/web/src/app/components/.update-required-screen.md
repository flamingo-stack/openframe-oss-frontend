# update-required-screen.tsx

A blocking, full-screen React component shown when the native shell determines the app bundle is below the minimum required version or the gateway rejects requests with HTTP 426. It replaces the entire app tree (including the biometric unlock gate and login pages) and offers the user either a restart into an already-downloaded bundle or a trip to the app store, with no dismiss option.

## Key Components

- **`UpdateRequiredScreen`** — The main exported component. Renders a bottom-anchored (mobile) / centered (desktop) card with:
  - An accessible, auto-focused `<h1>` heading for screen reader announcement when the tree is replaced.
  - A polite live-region status message that adapts based on whether a restart-ready bundle is available.
  - Either `DownloadedUpdateRow` + "Restart to Update" button, or `StoreUpdateRow` + "Update Now" button.
- **`LOOK_AGAIN_MS`** — Constant (65s) controlling the polling interval for re-checking update availability, slightly past the native shell's 60s "recent check" cache window.
- **`lookForPendingBundle`** — Internal `useEffectEvent` handler that reads cached update state from the native shell and triggers a fresh `checkForUpdate()` if the cached bundle doesn't lift the block.
- **`restart`** — Async handler invoking `restartIntoPendingUpdate()`; clears `pendingVersion` if the native shell rejects the restart.

## Usage Example

```typescript
import { UpdateRequiredScreen } from '@/components/update-required-screen';
import { useAppUpdateStore } from '@/lib/version-check';

function AppGate({ children }: { children: React.ReactNode }) {
  const isBlocked = useAppUpdateStore(s => s.isBundleBlocked);

  if (isBlocked) {
    return <UpdateRequiredScreen />;
  }

  return <>{children}</>;
}
```

This component is intended to be mounted as a top-level replacement for the entire app when blocking update policies are triggered — it should not be nested inside navigation, auth gates, or other conditional UI, since it intentionally bypasses those layers.

**Behavior notes:**
- Listens for app resume events (`onAppResume`) to re-check for a pending update whenever the user returns from the store.
- Falls back to periodic polling (`LOOK_AGAIN_MS`) only when no restart-ready bundle exists, avoiding unnecessary checks once a valid bundle is found.
- Intercepts the Android back button via `pushBackDismissible`, exiting the app rather than navigating SPA history.
