## app-update-gate.tsx

A client-side React gate component that blocks app usage when a mandatory update is required, and checks version policy on mobile cold start and app resume.

## Key Components

- **`AppUpdateGate`** — Top-level wrapper component that:
  - Subscribes to `useAppUpdateStore` to detect if an update is `required`
  - On mobile shells only, triggers `refreshVersionPolicy()` on mount and on every `onAppResume` event
  - Renders `UpdateRequiredScreen` (blocking everything below, including NATS sockets, biometric unlock, and login) when an update is required
  - Otherwise renders children wrapped in `WorkspaceGoneGate`, alongside the non-blocking `UpdateAvailableModal`

- **`HiddenWhileUpdateRequired`** — Lightweight visibility gate for root-level chrome (toasts, offline banners) that live outside `AppUpdateGate`. Renders `null` while an update is required so stray UI (e.g., a 426 error toast) can't overlay the blocking screen.

## Usage Example

```typescript
import { AppUpdateGate, HiddenWhileUpdateRequired } from './app-update-gate';

function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <AppUpdateGate>
        {children}
      </AppUpdateGate>

      <HiddenWhileUpdateRequired>
        <ToastContainer />
        <OfflineBanner />
      </HiddenWhileUpdateRequired>
    </>
  );
}
```

## Notes

- Version policy checks (`refreshVersionPolicy`) only run via `onAppResume`/cold start on `isMobileShell()`; web and desktop shells never trigger these signals.
- `AppUpdateGate` also composes `WorkspaceGoneGate`, which handles a separate "workspace deleted" refusal state that applies across all shells (not just mobile).
- Use `HiddenWhileUpdateRequired` for any UI rendered outside the gate's subtree to keep it in sync with the blocking state.
