## Manhattan Composer Host

Implements a persistent, portal-based composer (chat input dock) that moves between layout positions without remounting, preserving draft text, staged context, and uploads across work-area mode changes (`chat`, `split`, `page`).

### Purpose

React normally destroys and recreates a component when it moves in the tree. Here, a single `EmbeddableChat` instance must survive moving between the bottom of the chat column and a page-level dock. This module solves that by rendering the composer once into a detached DOM node (the "host"), then physically reparenting that DOM node between slots via direct DOM manipulation — React's reconciliation never touches the composer's subtree.

## Key Components

- **`useComposerHostStore`** — Zustand store holding the shared `host` `HTMLDivElement` and an `attached` flag indicating the host has been placed into a slot at least once.
- **`ManhattanComposerPortal`** — Renders `children` (the composer UI) once via `createPortal` into the shared host node. Returns `null` until the host exists and has been attached to a slot.
- **`ManhattanComposerSlot`** — A candidate mounting location. When `active` is `true`, its `useLayoutEffect` appends the host node into itself and marks it attached. On deactivation/unmount, it detaches the host (only if still its child), handing it off cleanly to the next active slot in the same commit.

## Usage Example

```typescript
import { ManhattanComposerPortal, ManhattanComposerSlot } from './manhattan-composer-host';

function ChatLayout({ mode }: { mode: 'chat' | 'split' | 'page' }) {
  return (
    <div>
      {/* Mount the composer tree once per session, anywhere high in the app */}
      <ManhattanComposerPortal>
        <EmbeddableChat />
      </ManhattanComposerPortal>

      <div className="chat-column">
        <ManhattanComposerSlot active={mode === 'chat' || mode === 'split'} />
      </div>

      <div className="page-dock">
        <ManhattanComposerSlot active={mode === 'page'} />
      </div>
    </div>
  );
}
```

Only one slot should be `active` at a time, derived from the same `mode` value, ensuring exactly one owns the host node per render.
