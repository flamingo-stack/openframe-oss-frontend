# openframe-chat-runtime-provider.tsx

React context provider that wires the `@flamingo-stack/openframe-frontend-core` chat library (`<EmbeddableChat>`) into openframe-frontend's auth, navigation, and content-routing systems. It supports both Mingo (NATS-based) and Guide (SSE-based, proxied through `/content` to the MPH backend) chat modes, operating in `mode: 'host'` since openframe-frontend serves its own copy of the `openframe-docs` knowledge base.

## Key Components

- **`CHAT_SOURCE`** — Stable `'openframe'` namespace constant used for localStorage key scoping inside the chat lib; must remain stable across deployments.
- **`bearerGatewayOrigins()`** — Returns the tenant gateway origin when running in bearer-auth mode (native shell / dev-ticket web), used to scope cross-origin credential attachment.
- **`CHAT_AUTH_ADAPTER`** (`EmbedAuthAdapter`) — Module-level singleton registered with the chat lib's `embedAuthedFetch`. Handles:
  - `getHeaders` / `hasCredential` — attaches Bearer token only in bearer-auth mode; otherwise relies on cookie credentials.
  - `refresh` — delegates to `refreshAccessToken`, epoch-gated via `lastChatSendEpoch` to avoid redundant token rotations.
  - `beforeRequest` / `onResponse` — enforces force-update and session-gone checks (`UpdateRequiredError`, `SessionGoneError`).
  - `resolveAssetUrl` — resolves backend image paths through the gateway.
  - `subscribe` — notifies listeners only on genuine token epoch changes.
- **Module-load side effect** — Synchronously calls `clearEmbedProxyAuth()` and `setEmbedAuthAdapter(CHAT_AUTH_ADAPTER)` at import time (not in `useEffect`) to guarantee the adapter is ready before any child chat component's mount-time requests fire.
- **`OpenframeChatRuntimeProvider`** (implied default export, truncated in source) — Supplies `ChatRuntimeContext` and `AssistantRuntimeContext`, wiring `useDocNavigation`, `useRouter`, and `decideNewTab` logic so in-app content (help-center, knowledge base) soft-navigates while external content opens in a new tab.

## Usage Example

```typescript
import { OpenframeChatRuntimeProvider } from '@/app/components/chat/openframe-chat-runtime-provider';

function AppShell({ children }: { children: React.ReactNode }) {
  return (
    <OpenframeChatRuntimeProvider>
      {children}
    </OpenframeChatRuntimeProvider>
  );
}
```

This provider is typically mounted high in the component tree (e.g., in a layout) so any descendant using `<EmbeddableChat>` can access `ChatRuntime` and `AssistantRuntime` context for navigation decisions, authenticated asset resolution, and token refresh handling.
