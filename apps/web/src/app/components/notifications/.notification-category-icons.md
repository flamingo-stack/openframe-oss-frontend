# notification-category-icons.tsx

Resolves display icons for notification tiles, applying host-specific overrides on top of the shared library's category-based icon lookup. It prioritizes per-type icons, falls back to per-category icons, and finally defers to the library's default category icon resolver.

## Key Components

- **`ICON_BY_TYPE`** — Maps specific backend notification `type` values to icons, used for types whose category (e.g., `GENERIC`) doesn't carry its own icon. Currently maps `NEW_PERMISSIONS_REQUIRED_TYPE` to a cloud icon.
- **`ICON_BY_CATEGORY`** — Maps backend `category` values to icons for categories the shared library leaves unstyled (e.g., `INTEGRATIONS`).
- **`ownIcon(table, key)`** — Safe lookup helper using `Object.prototype.hasOwnProperty.call` to avoid false-positive matches against inherited `Object.prototype` members (e.g., a category string like `"constructor"`).
- **`getNotificationIcon(notification)`** — Returns a `ReactNode` icon for a notification: checks type-specific override first, then category override, then falls back to the shared library's `notificationCategoryIcon`.
- **`withNotificationIcon(notification)`** — Returns a copy of the notification with an `icon` attached for tile rendering, unless the notification already specifies an explicit `icon` or `imageUrl`.

## Usage Example

```typescript
import { withNotificationIcon, getNotificationIcon } from './notification-category-icons';

// Enrich a notification before rendering in a list
const enriched = withNotificationIcon(notification);
renderTile(enriched);

// Or compute the icon directly for custom rendering
const icon = getNotificationIcon(notification);
if (icon) {
  return <div className="tile-icon">{icon}</div>;
}
```

Both functions respect precedence: explicit `icon`/`imageUrl` fields win over computed icons, type-specific mappings win over category mappings, and the shared library's category icon table is the final fallback.
