Resolves navigation actions and routes for notifications, mapping notification context types to their corresponding UI destinations (ticket dialogs, Mingo chat drawers, or page routes).

## Key Components

### Constants
- **`CONTEXT_TYPENAME_BY_TYPE`** — Maps backend `NotificationContext.type` strings to GraphQL `__typename` values; used by the NATS live path to reconstruct typed context records.
- **`TICKET_CONTEXT_TYPES`** — Set of context types whose entity is a ticket (navigate via `ticketId`).
- **`TICKET_CHAT_CONTEXT_TYPES`** — Subset of ticket contexts that deep-link to the Chat tab.
- **`NOTIFICATION_ACTION_FIELDS`** — The fields an action is resolved from besides `type` and `category` (entity ids and an announcement's `link`). The desktop's `click_payload` keeps every one, held to it by the shared cases in `apps/desktop/src-tauri/src/notification-click.json`.

### Types
- **`NotificationAction`** — `NotificationRouteAction | NotificationLinkAction`. A route action (`{ label, route, mingoDialogId?, readOnOpen? }`) opens something inside the app; a link action (`{ label, externalUrl, readOnOpen: true }`) is an `ANNOUNCEMENT`'s link off the app's origin, opened with `openNotificationLink` and never pushed through the router. Tell them apart with `isNotificationLinkAction`. `readOnOpen` marks an announcement's link, in the app or out of it: opening it reads it, arriving at its page never does.

### Functions

| Function | Description |
|---|---|
| `resolveNotificationAction(notification)` | Returns the primary `NotificationAction` for a store-shaped notification, or `null` if no navigable entity exists. |
| `resolveNatsNotificationAction(payload)` | Resolves the action for a raw NATS wire payload (used on OS-toast click before the notification is shaped into a store record). |
| `resolvePushNotificationAction(data)` | Resolves the action for a push's flat FCM `data` map (the mobile tap path). |
| `tappedNotificationId(payload)` | The stored id a shell's tap names (the push data's or the desktop click's top-level `notificationId`), or `null` when it is missing or not shaped like an id. |
| `isNotificationLinkAction(action)` | `true` for a link action (an announcement's page outside the app). |
| `openNotificationLink(url)` | Opens a link action's page outside the app: a new tab on the web, the system browser on desktop, the in-app browser on mobile. |
| `followNotificationTap(action, { navigate, markRead })` | Opens a link outside the app, else navigates to the route, else to `/notifications`; calls `markRead` for a `readOnOpen` action. What both shells' taps and the in-app tiles do (the tiles first open a Mingo chat over the page when they can). |
| `resolveNotificationRoute(notification)` | Convenience wrapper — extracts the `route` string (`null` when the notification points at nothing openable, or at a page outside the app). |
| `notificationTargetsDialog(notification, activeDialogs)` | Returns `true` when the notification's `dialogId` is in the currently active drawer view set. |
| `notificationTargetsLocation(notification, pathname, searchParams)` | Returns `true` when the current URL matches the notification's target route (pathname + query params); drives auto-read behavior. |

## Usage Example

```typescript
import {
  followNotificationTap,
  notificationTargetsDialog,
  notificationTargetsLocation,
  resolveNotificationAction,
} from '@/app/components/notifications/notification-navigation';

// Open a notification's action: a link outside the app, a route inside it, or the
// notifications page; an announcement's link is read here, since no arrival reads it.
followNotificationTap(resolveNotificationAction(notification), {
  navigate: route => router.push(route),
  markRead: () => markRead(notification.id),
});

// Auto-mark read when the user is already on the target page
const isOnTarget = notificationTargetsLocation(
  notification,
  window.location.pathname,
  new URLSearchParams(window.location.search),
);

// Auto-mark read when the target dialog is open in the drawer
const isDialogOpen = notificationTargetsDialog(notification, activeDialogViews);
```
