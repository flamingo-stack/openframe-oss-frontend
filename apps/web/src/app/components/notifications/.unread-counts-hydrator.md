Renders nothing to the DOM; fetches per-category unread notification counts from the Relay store and propagates updates to a parent callback whenever the store refreshes.

## Key Components

- **`UnreadCountsByCategory`** — Type alias for a partial record mapping `NotificationCategory` enum values to their unread count.
- **`UnreadCountsHydratorProps`** — Props interface requiring an `onChange` callback that receives the latest counts map.
- **`UnreadCountsHydrator`** — Headless client component that queries `unreadCountsByCategory` via `useLazyLoadQuery` with `store-and-network` policy, memoizes the filtered counts map, and calls `onChange` on every change.

## Usage Example

```typescript
import { UnreadCountsHydrator, type UnreadCountsByCategory } from '@/components/unread-counts-hydrator';

function AppShell() {
  const handleCountsChange = (counts: UnreadCountsByCategory) => {
    // e.g. update global state or badge indicators
    console.log('Unread counts updated:', counts);
  };

  return (
    <>
      <UnreadCountsHydrator onChange={handleCountsChange} />
      {/* rest of shell */}
    </>
  );
}
```

## Notes

- Returns `null` — no DOM output; purely a data-sync side-effect component.
- Filters out entries with `count === 0` and the internal `'%future added value'` sentinel before lifting state.
- Automatically reflects updates triggered by `refreshUnreadCounts` calls (e.g. NATS push events or mark-read mutations) because it stays subscribed to the Relay store.
