# unread-counts-hydrator.tsx

A headless React client component that fetches per-category unread notification counts via Relay and propagates them to a parent component through a callback. It renders no UI (`null`) and acts purely as a data-loading/sync bridge between the Relay store and the app shell.

## Key Components

- **`UnreadCountsByCategory`** — Type alias: a partial record mapping `NotificationCategory` to unread counts.
- **`KNOWN_CATEGORIES`** — A `Set` of all `NotificationCategory` enum values known to this build, used to safely filter out unrecognized/future server-added categories (Relay's `'%future added value'` sentinel pattern).
- **`UnreadCountsHydrator`** — The main component. Accepts an `onChange` callback prop, runs `useLazyLoadQuery` against `unreadCountsRelayQuery`, derives a filtered/normalized `UnreadCountsByCategory` object via `useMemo`, and calls `onChange` whenever the counts change via `useEffect`. Because it's subscribed to the Relay store with `store-and-network` fetch policy, any store updates (e.g., NATS push notifications, mark-read mutations) automatically trigger re-renders and propagate fresh counts.

## Usage Example

```typescript
'use client';

import { useState } from 'react';
import { UnreadCountsHydrator, type UnreadCountsByCategory } from '@/components/unread-counts-hydrator';

export function AppShell() {
  const [unreadCounts, setUnreadCounts] = useState<UnreadCountsByCategory>({});

  return (
    <>
      <UnreadCountsHydrator onChange={setUnreadCounts} />
      <NotificationBadge counts={unreadCounts} />
    </>
  );
}
```

**Note:** This component must be rendered within a Relay environment provider (e.g., `RelayEnvironmentProvider`) and wrapped in a `Suspense` boundary, since `useLazyLoadQuery` suspends while fetching.
