# open-mingo-dialog.ts

Provides a single entry point for opening a Mingo conversation dialog from anywhere in the app, choosing between rendering it over the current page (via the composer dock) or navigating to its dedicated chat page as a fallback.

## Key Components

- **`normalizeMingoDialogId(id: string): string`** — Converts a Relay global id (base64-encoded `Dialog:<rawId>`) back into its raw dialog id. Used for ids arriving from URLs (e.g., older `?mingoDialog=` links); ids already raw pass through unchanged.
- **`canOpenMingoDialogOverPage(): boolean`** — Checks whether the composer dock is currently mounted (i.e., the app is in an unlocked SaaS workspace), which determines if a dialog can open inline instead of via navigation.
- **`openMingoDialog(dialogId: string, options?: { navigate?: (href: string) => void }): void`** — Opens the given Mingo dialog. If the dock is mounted, it opens inline via `useMingoLauncherStore`. Otherwise, it navigates to the dialog's chat route, using the optional `navigate` override or falling back to `navigateInApp`.

## Usage Example

```typescript
import { openMingoDialog, normalizeMingoDialogId } from './open-mingo-dialog';

// From a notification click handler with a raw id
function onNotificationClick(rawDialogId: string) {
  openMingoDialog(rawDialogId);
}

// From a URL query param that may be a Relay global id
function onDeepLink(dialogIdFromUrl: string) {
  const dialogId = normalizeMingoDialogId(dialogIdFromUrl);
  openMingoDialog(dialogId);
}

// From a component that already holds a router instance
function onChipClick(dialogId: string, router: { push: (href: string) => void }) {
  openMingoDialog(dialogId, { navigate: router.push });
}
```

This seam ensures consistent dialog-opening behavior across React event handlers, non-React code (e.g., desktop notifications), and callers with their own navigation context.
