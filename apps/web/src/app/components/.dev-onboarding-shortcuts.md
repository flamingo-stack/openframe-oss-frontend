Provides developer/QA-only onboarding shortcuts surfaced in the Mingo chat's "⋯" menu, allowing testers to skip the Get Started tour and reset a tenant's Initial Setup without going through the full flow manually.

## Key Components

- **`useDevOnboardingMenuItems(onResetInitialSetup)`** — Hook that returns an array of `ActionsMenuItem` entries for the dev/QA menu, gated behind the `onboarding-skip` feature flag:
  - `"Skip onboarding (dev)"` — shown when the current user's onboarding is neither completed nor skipped; triggers `skipOnboarding()` and also completes the tenant's Initial Setup.
  - `"Reset Initial Setup (dev)"` — shown when the tenant has any Initial Setup progress (completed or partial steps); invokes the provided `onResetInitialSetup` callback to open the confirm dialog.
  - Returns an empty array if the feature flag is disabled.
- **`ResetInitialSetupDialog`** — A `ConfirmDialog` wrapper that confirms and executes `resetTenant`, clearing the tenant's Initial Setup. Calls `onOpenChange(false)` and the optional `onReset` callback on success.
- **`ResetInitialSetupDialogProps`** — Props interface: `open`, `onOpenChange`, and optional `onReset` (used by the host to navigate to the setup wizard after reset).

## Usage Example

```typescript
import { useState } from 'react';
import { useDevOnboardingMenuItems, ResetInitialSetupDialog } from './dev-onboarding-shortcuts';

function MingoChatMenu() {
  const [resetDialogOpen, setResetDialogOpen] = useState(false);

  const devMenuItems = useDevOnboardingMenuItems(() => setResetDialogOpen(true));

  return (
    <>
      <ActionsMenu items={[...otherMenuItems, ...devMenuItems]} />
      <ResetInitialSetupDialog
        open={resetDialogOpen}
        onOpenChange={setResetDialogOpen}
        onReset={() => router.push('/setup-wizard')}
      />
    </>
  );
}
```

**Notes:**
- Only rendered when the `onboarding-skip` feature flag is enabled (dev/QA environments).
- Menu items disappear automatically once their underlying condition no longer applies (e.g., after onboarding is skipped or completed).
- Relies on `useOnboardingStore` for tenant/user state and `useOnboardingMutations` for the GraphQL mutations (`skipOnboarding`, `resetTenant`).
