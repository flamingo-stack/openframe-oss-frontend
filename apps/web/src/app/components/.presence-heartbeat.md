# presence-heartbeat.tsx

A headless React component that periodically reports the current session as "present" to the backend, enabling smarter push-notification timing. It bypasses the app's subscription gate (since mutations aren't caught by it) by only beating while a valid subscription is confirmed open.

## Key Components

- **`PresenceHeartbeat()`** — The exported component (renders nothing; `null`). Mount it once near the app root to activate heartbeat reporting.
- **Timing constants**:
  - `PRESENCE_TTL_MS` — mirrors `openframe.presence.ttl-seconds` server config (30s).
  - `JITTER_MS` — randomizes beat timing to avoid tenant-wide QPS spikes.
  - `MIN_BEAT_GAP_MS` — minimum spacing between beats to avoid flooding on rapid activity events (e.g. alt-tabbing).
  - `SAFETY_MARGIN_MS` — latency headroom subtracted from the interval calculation.
  - `HEARTBEAT_MS` — derived, clamped interval guaranteeing two consecutive beats always fit inside the TTL window.
- **`lastBeatAt`** — module-scoped (not effect-scoped) timestamp guard, so remounts (e.g. React StrictMode) don't trigger duplicate unthrottled beats.
- **`beat()`** — fires `recordPresenceMutation` via `commitMutation`, guarded by online/active-session checks and the minimum beat gap.
- **`schedule()`** — self-rescheduling `setTimeout` loop, re-armed only after a beat actually fires (preserving the TTL-safety invariant).

## Usage Example

```typescript
// app/layout.tsx (or any top-level client component)
import { PresenceHeartbeat } from '@/components/presence-heartbeat';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <PresenceHeartbeat />
      {children}
    </>
  );
}
```

The component requires no props. It automatically:
- Starts beating once `useSubscriptionOpen()` confirms an active subscription.
- Pauses beats when offline (`isOnline()`) or idle (`isSessionActive`).
- Beats immediately on regained connectivity or renewed session activity, then resumes its jittered interval.

**Note:** Server-side, `openframe.push.outbox.presence-enabled` must be enabled only after heartbeats are confirmed flowing — enabling it prematurely marks all users absent, breaking the push-cancellation grace window this component supports.
