# onboarding-v2-redirect.tsx

Client component that enforces the `onboarding-v2` redirect rules between the landing page and the `/setup` wizard, ensuring users land on the correct screen based on their onboarding progress.

## Key Components

- **`OnboardingV2Redirect`** — Renders nothing; a side-effect-only component that:
  - Reads onboarding state via `useSetupPending()` (`'unknown'`, `'setup'`, or `'none'`).
  - Redirects landing-page visitors to `routes.setup` when setup is still pending.
  - Redirects `/setup` wizard visitors away (to `routes.mingo.home` in SaaS tenant mode, or `routes.dashboard` otherwise) once pending status resolves to `'none'` — but only decides this once per wizard visit, tracked via a `decidedFor` ref keyed on `pathname`.
  - Leaves deep links to any other route untouched.
  - Resets its "decided" state whenever the user leaves the wizard route, so re-entering (e.g. via "Reset Onboarding") re-evaluates the redirect.

## Usage Example

Mount once near the app shell, below session/subscription gates and the progress hydrator, so `useSetupPending` always reads fully loaded state:

```typescript
import { OnboardingV2Redirect } from '@/app/(app)/_shell/onboarding-v2-redirect';

export function AppShell({ children }: { children: React.ReactNode }) {
  return (
    <>
      {/* session + subscription gates, progress hydrator */}
      <OnboardingV2Redirect />
      {children}
    </>
  );
}
```

This component relies on `isBareChromeRoute` and `isLandingRoute` from `./app-shell-chrome` to classify the current route, and `isSaasTenantMode()` from `@/lib/app-mode` to pick the correct post-setup destination.
