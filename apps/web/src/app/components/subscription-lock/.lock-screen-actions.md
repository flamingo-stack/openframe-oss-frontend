## lock-screen-actions.tsx

Provides the shared "exit" actions (log out, delete account, contact support) rendered on lock screens where a workspace cannot be accessed — presented either as a button row or a dropdown menu, depending on the hosting screen's layout.

## Key Components

- **`CheckAgainButton`** — Reloads the page to re-resolve subscription status; used on the inactive screen.
- **`InactiveScreenActions`** — Row combining `CheckAgainButton` and a plain "Log Out" button, for the inactive (not-paywall) lock screen.
- **`DeleteMyAccountLink`** — A link-style button opening `DeleteAccountModal`, used in the inactive screen's footer.
- **`ContactSupportButton`** — Standalone support button with its own modal, used as an error fallback.
- **`LockScreenActions`** — The full three-button row (Log Out, Delete Account, Contact Support) shared by role-blind lock screens (e.g. member/owner billing locks).
- **`LockScreenActionsMenu`** — The same three actions as a "…" dropdown menu, used on the paywall screen where a primary "Proceed to Payment" action takes precedence.
- **`useLockScreenActions`** (internal hook) — Centralizes handler wiring (`logOut`, `deleteAccount`, `contactSupport`) and the modals (`DeleteAccountModal`, `BillingContactSupportModal`) that must be mounted alongside either presentation.

## Usage Example

```typescript
import { LockScreenActions, LockScreenActionsMenu } from '@/app/components/lock-screen-actions';

// Row presentation for a screen with no competing primary action
function MemberBillingLockScreen() {
  return (
    <div>
      <p>Your workspace is locked due to a billing issue.</p>
      <LockScreenActions />
    </div>
  );
}

// Menu presentation for the paywall header, alongside "Proceed to Payment"
function PaywallHeader() {
  return (
    <div className="flex items-center justify-between">
      <h1>Choose a plan</h1>
      <LockScreenActionsMenu triggerClassName="ml-auto" />
    </div>
  );
}
```

**Note:** Neither component manages logout confirmation — that modal is mounted higher up in `AppLayoutInner`, outside the lock/shell branch where these components render. Both exported row/menu components internally render their own `DeleteAccountModal` and `BillingContactSupportModal` instances via the shared hook.
