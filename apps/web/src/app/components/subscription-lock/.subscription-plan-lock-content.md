# subscription-plan-lock-content.tsx

Lazily-loaded gate component that decides which of three billing-related screens to render: the paywall (plan selection), an unpaid-invoices screen for workspaces in debt, or an access-denied screen for roles without billing permissions.

## Key Components

- **`SubscriptionPlanLockContent`** (default export) — `next/dynamic` entry point that resolves subscription state and renders the appropriate lock screen.
- Uses **`useBillingAccessGate`** to determine role-based access (`'denied'`, `'loading'`, or granted).
- Uses **`useSubscriptionLock`** to read the current `SubscriptionStatus`.
- Delegates rendering to:
  - `WorkspaceInactiveScreen` — shown when access is denied.
  - `UnpaidInvoicesScreen` — shown when status is `PAST_DUE` or `SUSPENDED`.
  - `SubscriptionSettingsView` — shown otherwise (the plan/paywall view).

## Usage Example

```typescript
// Typically loaded via next/dynamic from subscription-lock-content.tsx,
// not imported directly by page components.
import dynamic from 'next/dynamic';

const SubscriptionPlanLockContent = dynamic(
  () => import('./subscription-plan-lock-content'),
  { ssr: false }
);

export function SubscriptionLockContent() {
  return <SubscriptionPlanLockContent />;
}
```

## Design Notes

- **Lazy boundary**: This module is split out so that plan/pricing/invoice/Stripe code doesn't bloat the shared chunk used by every page under `AppLayout`.
- **Role check placement**: The access-denied check happens *inside* this lazy module (not in the eager parent) because the loading state must visually match the paywall, and that markup only lives here.
- **Loading behavior**: Each screen manages its own loading state independently — the unpaid-invoices screen never borrows the paywall's spinner, and invoice amounts are never rendered before access is confirmed, since a denied viewer should never see the workspace's actual debt figures.
- **Debt resolution**: Debt status (`PAST_DUE`/`SUSPENDED`) is determined synchronously from already-resolved subscription status, so the correct screen is chosen on first paint.
