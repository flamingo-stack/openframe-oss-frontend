This client component renders the billing lock screen for the desktop (read-only) build, where billing management is unavailable in-app and users must be directed to the web app instead.

## Key Components

- **`ReadOnlyLockContent`** (default export) — A `next/dynamic` entry point component that gates rendering based on billing access state.
  - Uses `useBillingAccessGate()` to determine the current access state: `'denied'`, `'loading'`, or granted.
  - On `'denied'`, renders `WorkspaceInactiveScreen` with default copy (pointing to an administrator, since the button-based remedy wouldn't work for a non-owner).
  - On `'loading'`, renders `WorkspaceInactiveScreen` in a loading state, avoiding showing either the denial message or the action button prematurely.
  - Otherwise, renders `WorkspaceInactiveScreen` with a description and a "Manage Billing" action button that calls `openBillingInBrowser()` to hand off to the web app, since billing cannot be managed directly on desktop.

## Usage Example

```typescript
import dynamic from 'next/dynamic';

const ReadOnlyLockContent = dynamic(() => import('./read-only-lock-content'), {
  ssr: false,
});

export function DesktopBillingLock() {
  return <ReadOnlyLockContent />;
}
```

This component is designed to be lazy-loaded via `next/dynamic` since it depends on client-only billing access state and browser-opening behavior, both unavailable during server-side rendering.
