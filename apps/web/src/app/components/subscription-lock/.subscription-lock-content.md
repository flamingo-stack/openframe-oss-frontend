# subscription-lock-content.tsx

Renders the tenant-wide lockout screen shown when a workspace's subscription is inactive (trial expired, canceled, etc.), selecting the correct variant based on build-specific billing visibility rules.

This component enforces a platform-compliance boundary: on builds where payment UI must be hidden (per App Store Guideline 3.1.1), the subscription plan picker must never be reachable or even present in the loaded code. To achieve this, the plan-picker module is lazy-loaded so it's excluded from the shared chunk on builds that can't show it.

## Key Components

- **`SubscriptionLockContent`** — Main exported component. Decides which lockout screen to render based on billing visibility:
  - `isBillingHidden()` → renders `WorkspaceInactiveScreen` (no billing UI at all)
  - `isBillingReadOnly()` → renders `ReadOnlyLockContent` (desktop builds; directs users to the web app)
  - otherwise → renders `SubscriptionPlanLockContent` (full paywall with plans/Stripe Checkout)
- **`SubscriptionPlanLockContent`** — Dynamically imported, `ssr: false`, no loading spinner (kept out of shared chunks on non-paying builds).
- **`ReadOnlyLockContent`** — Dynamically imported, `ssr: false`, no loading spinner (avoids leaking subscription vocabulary into mobile build chunks).

## Usage Example

```typescript
// Rendered by AppLayout when SubscriptionGuard detects a locked-out tenant
import { SubscriptionLockContent } from './subscription-lock-content';

function AppLayout({ children }: { children: React.ReactNode }) {
  const isLocked = useSubscriptionGuard();

  if (isLocked) {
    return <SubscriptionLockContent />;
  }

  return <>{children}</>;
}
```

**Important notes:**
- The lock applies uniformly to all roles in the tenant — role-based remedy logic lives inside the lazily-loaded modules, not here.
- Do not inline the plan-picker logic into this file; doing so would reintroduce the paywall UI into shared chunks on builds where it must be absent.
