React client component that renders a full-screen unlock gate for the native-shell app when biometric login is enabled but the Keychain read was canceled or failed (token-store lock state `'locked'`). Since the tokens still exist on device, this is explicitly not a signed-out state — it offers the user a way to retry biometric unlock or abandon the locked session for a fresh sign-in.

## Key Components

- **`BiometricUnlockGateProps`** — interface defining the single `onUseAnotherLogin` callback prop, used to hand off to the normal sign-in flow (OpenFrame SSO / Google / Microsoft).
- **`BiometricUnlockGate`** — the exported component. Renders a centered card with:
  - A focus-managed heading (`Unlock OpenFrame`) that grabs keyboard focus on mount for accessibility, since this gate replaces the entire app tree.
  - Dynamic biometry label (e.g. "Face ID", "Touch ID") resolved via `isBiometricAvailable()` and `biometryLabel()`.
  - A **Retry/Unlock** button that calls `retryTokenHydration()` — on success the token store clears the lock and the parent unmounts this gate; on repeated cancellation the lock re-arms and the gate stays.
  - A **"Log in another way"** button that triggers `onUseAnotherLogin`, disabling both buttons until the caller completes the route hand-off (avoids flashing a stale screen).

## Usage Example

```typescript
import { BiometricUnlockGate } from '@/components/biometric-unlock-gate';
import { useRouter } from 'next/navigation';

function AppShellGuard() {
  const router = useRouter();

  const handleUseAnotherLogin = async () => {
    // Clear locked session state and navigate to sign-in
    await router.push('/sign-in');
  };

  return <BiometricUnlockGate onUseAnotherLogin={handleUseAnotherLogin} />;
}
```

This component is only rendered by native-shell callers when the token store reports a `'locked'` state — it should not be used in web-only builds, since that lock state is exclusive to the native shell's biometric flow.
