Client component that captures ad-tracking identifiers and UTM campaign parameters from the URL as soon as any page loads, persisting them for later use during user registration/signup.

## Key Components

- **`RegistrationAttributionCapture`** — A headless React component (renders `null`) that runs `captureAttributionFromUrl()` inside a `useEffect` on mount, storing attribution data (e.g., `fbclid`, `utm_source`, `utm_campaign`) before it's lost from the URL.

## Usage Example

Mount this component once in the **root layout** (not the auth layout), so it captures attribution data on the actual landing page — since marketing/ad traffic typically lands on `/` or another marketing route, not directly on `/auth`:

```typescript
// app/layout.tsx
import { RegistrationAttributionCapture } from '@/components/registration-attribution-capture';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <RegistrationAttributionCapture />
        {children}
      </body>
    </html>
  );
}
```

## Notes

- **Placement matters**: Query params like `?fbclid=...&utm_source=...` are typically stripped or absent by the time a visitor navigates to `/auth` after clicking through from a landing page. This component must run as early as possible — at the root layout level — to reliably capture these values before they disappear from the address bar.
- The actual parsing/storage logic lives in `captureAttributionFromUrl`, imported from `@/lib/registration-attribution`.
- Uses the `'use client'` directive since it relies on `useEffect` and browser URL state.
