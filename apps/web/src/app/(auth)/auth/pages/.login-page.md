# login-page.tsx

Client-side page component that renders the login screen, orchestrating email-based tenant discovery, SSO authentication, and the fallback organization signup flow when an SSO identity has no matching account.

## Key Components

- **`LoginPage`** (default export) — the main page component rendering the login flow.
- **`handleDiscover`** — runs debounced tenant discovery for an email address, converting the result via `toLoginDiscoveryResult` for consumption by `LoginSection`.
- **`handleSso`** — initiates SSO login for a given provider/tenant pair; on failure, delegates to `useSsoSignupTakeover` to capture the error and potentially transition to the signup form instead of surfacing a hard error.
- **`genericProviders`** — computed list of SSO providers (`google`, `microsoft`, `apple`), filtering out `apple` unless the client is running on an Apple platform (via `useIsApplePlatform`).
- **`ssoLoading`** — local loading flag scoped to the SSO redirect action only, avoiding UI flicker caused by `useAuth`'s broader `isLoading` state (which also toggles during background discovery calls).

## Usage Example

This is a Next.js route page and is rendered automatically by the framework for its route segment — it is not typically imported directly:

```typescript
// app/(auth)/auth/login/page.tsx
export default function LoginPage() {
  // ...component implementation
}
```

The component composes two main UI states:

```typescript
// Default state: email discovery + SSO provider buttons
<LoginSection
  onDiscover={handleDiscover}
  onSso={handleSso}
  genericProviders={genericProviders}
  isLoading={ssoLoading}
/>

// Takeover state: shown when an SSO identity lacks an account
<NativeSsoSignupSection
  pending={signup.pending}
  onRegistered={signup.onRegistered}
  onExit={signup.onExit}
/>
```

Related hooks: `useAuth` (login/discovery), `useSsoSignupTakeover` (signup fallback state), `useIsApplePlatform` (platform detection).
