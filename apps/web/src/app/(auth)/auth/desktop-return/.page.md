# page.tsx

Next.js client page that renders the browser-side landing screen for desktop app sign-in hand-off. It reads the OAuth/SSO result encoded in the URL, displays a human-readable outcome (success, signup required, canceled, or error), strips the sensitive query parameters from the address bar, and launches the desktop app via its custom URL scheme.

## Key Components

- **`DesktopReturnPage` (default export)** — The page component. Uses `useSyncExternalStore` to read the hand-off data once per page load (SSR-safe), derives an `Outcome` from it, fires the desktop app launch exactly once via a `useEffect`/`useRef` guard, and renders a card UI with status, error details, and action buttons.
- **`outcomeFor(handoff: DesktopAuthReturn): Outcome`** — Maps a `DesktopAuthReturn` (`signed-in`, `signup`, `error`, `incomplete`, `none`) to user-facing title/body/reason/failureCode.
- **`Outcome` interface** — Shape of the rendered outcome: `title`, `body`, `reason` (either a server-provided reference code or a client-side text message), and `failureCode`.
- **`subscribe` / `getSnapshot` / `getServerSnapshot`** — Support functions for `useSyncExternalStore`, implementing a "read-once" external store since the URL is parsed a single time and never changes.
- **`captured`** — Module-level cache ensuring the URL-derived `DesktopAuthReturn` survives the URL-stripping side effect.
- **`FAILURE_BODY`** / **`DESKTOP_APP_NAME`** — Shared copy constants for the generic failure message and app name ("OpenFrame Console").

## Usage Example

This is a Next.js App Router page and is not imported directly; it's served automatically at its route path (e.g. `/sso/desktop-return`) when the gateway redirects back from a desktop OAuth flow:

```typescript
// Invoked implicitly by Next.js routing when the OAuth gateway
// redirects to this page with query params encoding the result.
// No manual instantiation needed — the file's default export
// is the route's page component.

// Example of the URL shape this page expects to parse:
// https://app.example.com/sso/desktop-return?status=signed-in&app_url=openframe://auth?...
```

Key behaviors to note when working with this file:
- The desktop app launch (`launchDesktopApp`) fires automatically for every non-`none` outcome, including cancellations and errors, since the native app is blocked waiting for a response.
- The "Open {DESKTOP_APP_NAME}" button is a manual fallback for browsers that block automatic protocol launches.
- Error reasons prefer an app-side worded message (`appWordedMessage`) over a raw server reference code, falling back to `useAuthErrorMessage` to resolve the server code asynchronously.
