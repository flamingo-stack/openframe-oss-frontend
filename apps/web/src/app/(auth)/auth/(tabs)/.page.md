Client-side Next.js page component that serves as the `/auth` route entry point, conditionally rendering either the sign-up flow or the login flow based on the current build/platform context.

## Key Components

- **`AuthRootPage`** — Default export; a client component (`'use client'`) that renders the root `/auth` route.
- **`useLoginOnlyMobileShell`** — Hook that detects whether the app is running in a login-only mobile shell build (a variant with no sign-up capability).
- **`AuthPage`** — Full authentication page (typically includes sign-up) rendered for standard builds.
- **`LoginPage`** — Login-only page rendered when running inside a login-only mobile shell.

## Usage Example

```typescript
// This component is automatically mounted by Next.js routing
// when a user navigates to /auth

// Conceptually, the routing logic resolves to:
function AuthRootPage() {
  const isLoginOnlyMobile = useLoginOnlyMobileShell();

  return isLoginOnlyMobile ? <LoginPage /> : <AuthPage />;
}
```

This file is located at the route segment `app/(auth)/auth/page.tsx`, so it automatically handles requests to `/auth`. No manual invocation is required—Next.js resolves and renders it based on the file system routing convention. The conditional logic ensures mobile shell builds (which restrict account creation) only expose the login experience, while standard web/desktop builds show the full auth page with sign-up options.
