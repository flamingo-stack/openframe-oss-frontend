# layout.tsx

Next.js route-group layout for the authentication section (sign-in, registration, setup wizard), wrapping child pages with shared chrome and tracking components.

## Key Components

- **`metadata`** — Sets an absolute page title via `routeTitle('Authentication')` (avoiding the root layout's title-template suffix being appended twice) and a static description for sign-in pages.
- **`AuthLayout`** — Default export; a server component that renders:
  - `MaximizeDesktopWindow` — expands the desktop app shell to full size, triggered on auth pages and persisted through the subsequent setup wizard.
  - `RedditClickIdCapture` — captures Reddit click-tracking IDs for attribution.
  - `AuthAnnouncementBar` — displays an announcement banner above the auth content.
  - `children` — rendered inside a `div.of-auth-pages` wrapper, intentionally without a shared `Suspense` boundary so each page manages its own loading state independently.

## Usage Example

This layout is automatically applied by Next.js to all routes within the `auth` route group—no manual import is needed:

```typescript
// app/(auth)/sign-in/page.tsx
export default function SignInPage() {
  // Rendered as `children` inside AuthLayout
  return <SignInForm />;
}
```

File structure context:

```text
app/
  (auth)/
    layout.tsx        <- this file
    sign-in/page.tsx
    register/page.tsx
    setup/page.tsx
```

Each page under this layout should wrap any URL-dependent logic in its own `Suspense` boundary, since `AuthLayout` deliberately omits a top-level one to avoid blocking the whole auth section on a single page's data fetch.
