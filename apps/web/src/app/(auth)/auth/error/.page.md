The `/auth/error` page: where every auth failure lands. The URL carries one thing, `ref`, and the page shows only
what the auth server answers for it. No query parameter is ever rendered as text.

## Key Components

- **`AuthErrorPage`** — Default export. A `LoadingSuspense` whose fallback is `AuthErrorScreen` itself in a loading
  scope (`useSearchParams` bails out to the client during the static prerender), so the loading page and the loaded
  one are the same screen.
- **`AuthErrorFromUrl`** — Internal. Reads `ref` from the URL, resolves it with `useAuthErrorMessage` and hands the
  description to `AuthErrorScreen` (`undefined` while it is resolved, which the screen draws as its paragraph's
  loading lines).

## Usage Example

```typescript
// The auth flow redirects with the server's reference, never with free text:
router.push('/auth/error?ref=SSO_SESSION_EXPIRED');
```

| `ref` | Description shown |
|---|---|
| A catalog code | The catalog sentence the auth server answers |
| A stored attempt | The message the server stored for that attempt |
| Missing or unknown | The generic entry ("An unexpected error occurred. ...") |

## Notes

- The page used to print `?error=<text>` as the message, which let anyone put their own words under the logo; that
  parameter is now ignored (`page.test.tsx` pins it).
- The title and the two ways out (contact support, back to login) are `AuthErrorScreen`'s static copy.
