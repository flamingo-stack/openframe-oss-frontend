# page.tsx

Next.js page component implementing the SSO "join" confirmation step — a consent gate shown by the auth server before an SSO flow creates a new user (e.g., accepting an invitation or first login via a shared domain). It reads pending join data from a session cookie, lets the user accept terms and create their account, or back out to login.

## Key Components

- **`SsoJoinPage`** (default export) — Top-level route component. Wraps content in `SsoJoinCardLayout`, which renders immediately while the card content suspends on `useSearchParams`.
- **`SsoJoinContent`** — Wraps the reader in a `LoadingSuspense` boundary so only the card (not the layout) shows a loading state.
- **`SsoJoinContentReader`** — Renders a static, disabled placeholder card during the loading scope (e.g., static prerender) before switching to the live, interactive version.
- **`SsoJoinContentLive`** — Core logic:
  - Fetches pending SSO join data via `authApiClient.pendingSsoJoin()` on mount.
  - Calls `pushIdentify` with the user's email for analytics identification.
  - Handles session expiry (409) with a toast and redirect to login.
  - On mobile flows, hands control back to the app via `authApiClient.ssoJoinReturnUrl()` instead of showing UI.
  - `handleSubmit` — performs a **top-level navigation** (`window.location.href`) to complete the join (required so redirect-set auth cookies are committed, unlike a `fetch`).
  - `handleBack` — navigates back to login, or signals cancellation to a mobile app shell.

## Usage Example

This is a Next.js App Router page and is not meant to be imported directly; it's resolved automatically by file-based routing (e.g., at a route like `/auth/sso/join`). The server redirects here via `openframe.sso.join-confirm-url` with identity/session state carried in cookies, not the URL.

```typescript
// Example: how authApiClient.pendingSsoJoin() is consumed internally
const res = await authApiClient.pendingSsoJoin();
if (res.ok && res.data?.email) {
  // proceed with join flow
} else if (res.status === 409) {
  // session/flow cookie expired — show message, redirect to login
}
```

Key behavioral notes:
- Submission and cancellation (for mobile) use `window.location.href`/`.replace`, never `router.push` or `fetch`, to ensure redirect chains (e.g., `/oauth/continue`, `/oauth/join-return`) are properly followed by the browser.
- `isNavigating` disables the form during the outbound navigation to prevent double submission.
