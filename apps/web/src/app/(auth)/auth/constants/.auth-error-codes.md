Defines shared constants and types for backend auth/registration error codes, ensuring consistent error handling across domain-availability checks and organization registration flows without duplicating string literals.

## Key Components

- **`AUTH_ERROR_CODE`** — Constant object mapping backend error code names (`INVALID_ARGUMENT`, `TENANT_REGISTRATION_BLOCKED`) returned by SaaS-shared auth and registration endpoints.
- **`AuthErrorCode`** — Union type derived from `AUTH_ERROR_CODE` values, used for type-safe error handling.
- **`AUTH_ERROR_REF`** — Constant object listing error reference names the frontend sends to `/auth/error?ref=<name>` (currently `VERIFICATION_LINK_INVALID`), matching the auth server's `AuthErrorCode` catalog.
- **`AuthErrorRef`** — Union type derived from `AUTH_ERROR_REF` values.

Note: `AUTH_ERROR_REF` only contains names the frontend itself emits. Message text for these refs is resolved elsewhere via the `authErrorMessage` query — this file does not map names to display text.

## Usage Example

```typescript
import { AUTH_ERROR_CODE, type AuthErrorCode } from './auth-error-codes';
import { AUTH_ERROR_REF } from './auth-error-codes';

function handleRegistrationError(code: AuthErrorCode) {
  switch (code) {
    case AUTH_ERROR_CODE.TENANT_REGISTRATION_BLOCKED:
      return 'This organization cannot be registered.';
    case AUTH_ERROR_CODE.INVALID_ARGUMENT:
      return 'Invalid request data.';
    default:
      return 'An unknown error occurred.';
  }
}

// Redirecting to the error page with a known ref
router.push(`/auth/error?ref=${AUTH_ERROR_REF.VERIFICATION_LINK_INVALID}`);
```
