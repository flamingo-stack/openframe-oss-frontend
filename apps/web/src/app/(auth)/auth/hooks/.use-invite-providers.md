# use-invite-providers.ts

A React client hook that fetches the list of SSO providers (and the invited email, if available) associated with a given invitation ID, intended for use on invitation acceptance screens.

## Key Components

- **`SsoProvider`** — Interface describing an SSO provider entry (`provider` name and `enabled` flag).
- **`InviteProvidersResponse`** — Shape of the API response, containing `providers` (string array) and an optional `email`.
- **`useInviteProviders(invitationId: string | null)`** — Hook that:
  - Fetches available SSO providers for the given `invitationId` via `authApiClient.getInviteProviders`.
  - Automatically re-fetches whenever `invitationId` changes.
  - Returns `{ providers, email, loading, error }`.
  - Skips fetching (and resets state) when `invitationId` is `null`.

## Usage Example

```typescript
'use client';

import { useInviteProviders } from '@/hooks/use-invite-providers';

function AcceptInvitePage({ invitationId }: { invitationId: string }) {
  const { providers, email, loading, error } = useInviteProviders(invitationId);

  if (loading) return <p>Loading invitation details...</p>;
  if (error) return <p>Error: {error}</p>;

  return (
    <div>
      {email && <p>Invited email: {email}</p>}
      <ul>
        {providers.map(({ provider, enabled }) => (
          <li key={provider}>
            {provider} {enabled ? '(enabled)' : '(disabled)'}
          </li>
        ))}
      </ul>
    </div>
  );
}
```

## Notes

- The hook treats a missing or `null` `invitationId` as a no-op, immediately clearing `providers` and setting `loading` to `false`.
- Errors from the API are surfaced via the `error` state, falling back to a generic `'Failed to fetch providers'` message when no specific error is provided.
- A `console.log` call exists in the non-ok response branch for debugging; `console.error` logs unexpected exceptions.
