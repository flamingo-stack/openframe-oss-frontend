# use-sso-signup-takeover.ts

A React hook that manages the "no-account" takeover state for SSO authentication flows, capturing verified identities (Apple or ticket-based) that lack an associated organization and need to complete registration.

This hook unifies the signup-after-SSO experience across both the Login and Sign Up tabs, ensuring a consistent UI regardless of whether the user's identity arrived via native Apple Sign-In or a browser-based SSO ticket. In login-only mobile shells (where in-app registration is disallowed per App Store review guidelines), the hook instead redirects to a no-account notice screen without ever holding the identity in state.

## Key Components

- **`SsoSignupTakeover`** — Interface describing the hook's return shape:
  - `pending`: The verified identity awaiting org assignment, or `null` to render the normal auth form
  - `capture(error)`: Inspects an error from `loginWithSso` and either sets `pending`, redirects to the no-account notice (mobile shell), or ignores unrelated errors
  - `onRegistered()`: Navigates away from the auth screen after successful registration/token storage
  - `onExit()`: Clears `pending` to return to the sign-in form

- **`useSsoSignupTakeover()`** — The hook implementation. Holds `pending` state in-memory only (never persisted to storage, routes, or logs) since it may wrap a single-use Apple authorization code or a live server-side ticket.

## Usage Example

```typescript
import { useSsoSignupTakeover } from '@/hooks/use-sso-signup-takeover';
import { loginWithSso } from '@/lib/native-login';

function AuthScreen() {
  const { pending, capture, onRegistered, onExit } = useSsoSignupTakeover();

  const handleSsoLogin = async () => {
    try {
      await loginWithSso();
    } catch (error) {
      capture(error);
    }
  };

  if (pending) {
    return (
      <SignupCompletionForm
        identity={pending}
        onSuccess={onRegistered}
        onCancel={onExit}
      />
    );
  }

  return <SsoLoginForm onSubmit={handleSsoLogin} />;
}
```

## Notes

- Errors are only captured when they are `AppleRegistrationRequiredError` or `SsoRegistrationRequiredError`; all other errors are assumed already handled by `loginWithSso`.
- `isLoginOnlyMobileShell()` is checked directly (not via a hook) because the underlying shell detection is memoized once per document load, matching the context in which the original native login occurred.
