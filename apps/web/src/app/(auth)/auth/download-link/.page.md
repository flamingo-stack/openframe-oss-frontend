# page.tsx (Download Link Page)

A Next.js client page that renders the "send me a download link" flow, allowing visitors on devices where installation isn't possible (phones, restricted systems) to request a download link via email instead.

This page reuses the shared `AuthShell` layout (the same visual shell used for sign-up) but omits the sign-up tabs, since this is a distinct, standalone flow rather than part of account registration. Marketing site links to this page carry attribution parameters in the URL, consistent with how trial links are handled, and the app-wide attribution capture logic persists that data on arrival.

## Key Components

- **`DownloadLinkPage`** (default export) — Client component (`'use client'`) that composes the page by wrapping `DownloadLinkSection` inside `AuthShell`.
- **`AuthShell`** — Shared layout component imported from `@flamingo-stack/openframe-frontend-core/components/features`, providing consistent auth-page chrome.
- **`DownloadLinkSection`** — Local component (from `./components/download-link-section`) containing the actual form/UI logic for requesting a download link.

## Usage Example

This file is a Next.js route entry point and is rendered automatically by the framework when the corresponding path is visited:

```typescript
// Accessed via routing, e.g. /auth/download-link
// No manual import/invocation needed - Next.js handles rendering.

// Example of how AuthShell + section composition pattern is reused elsewhere:
import { AuthShell } from '@flamingo-stack/openframe-frontend-core/components/features';
import { SignUpSection } from '@/app/(auth)/auth/components/sign-up-section';

export default function SignUpPage() {
  return (
    <AuthShell>
      <SignUpSection />
    </AuthShell>
  );
}
```

Marketing links to this page should include attribution query parameters, e.g.:

```text
https://app.openframe.ai/auth/download-link?utm_source=marketing-site&utm_campaign=mobile-cta
```
