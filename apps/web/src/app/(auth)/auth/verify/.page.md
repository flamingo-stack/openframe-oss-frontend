# VerifyEmailPage

Next.js client page component that handles email verification redirects by forwarding the verification token to a backend auth endpoint, while displaying a loading animation during the transition.

## Key Components

- **`VerifyEmailPage`** (default export) — Top-level page component that renders a loading screen and wraps the redirect logic in a `Suspense` boundary, since `useSearchParams` requires client-side rendering.
- **`VerifyEmailScreen`** — Presentational component showing an animated three-dot "traveling" indicator inside `AuthStatusFrame` while the redirect is in flight.
- **`VerifyEmailRedirect`** — Logic component that reads the `token` query parameter and either:
  - Redirects to the auth error page (via `routes.auth.error`) if no token is present, using `AUTH_ERROR_REF.VERIFICATION_LINK_INVALID`.
  - Builds an absolute URL to the backend `/sas/email/verify` endpoint (not a Next.js route) and performs a full browser navigation via `window.location.href`.

## Usage Example

This page is automatically routed by Next.js App Router (e.g., `app/verify-email/page.tsx`) and is triggered when a user clicks a verification link containing a `token` query parameter:

```typescript
// Example verification link that routes here:
// https://app.example.com/verify-email?token=abc123

// The component automatically:
// 1. Extracts `token` from the URL
// 2. Redirects to `${sharedHostUrl}/sas/email/verify?token=abc123`
//    or falls back to the current origin if no shared host is configured
```

**Notes:**
- The redirect target is constructed with `new URL()` rather than string concatenation to guarantee an absolute URL, falling back to `window.location.origin` in OSS deployments without a configured shared host (see `runtimeEnv.sharedHostUrl()`).
- The `Suspense` fallback is intentionally `null` since `VerifyEmailScreen` (rendered outside the boundary) already provides the visible loading state.
