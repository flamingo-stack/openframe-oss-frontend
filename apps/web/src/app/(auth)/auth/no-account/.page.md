## NoAccountPage

Client component rendered when a mobile-only login flow authenticates an SSO identity (e.g., Apple Sign-In) that has no corresponding OpenFrame account, offering the user a path back to the login screen instead of proceeding to organization setup.

This route is the mobile counterpart to the web's `sso-continue` flow: since no OpenFrame account exists for the verified identity, there's nothing to continue into. Any captured credential or signup ticket is discarded upstream (via `useSsoSignupTakeover`) before reaching this page, and such artifacts are single-use and self-expiring, so this component never has access to sensitive identity data.

## Key Components

- **`NoAccountPage`** — Default-exported Next.js page component (client-side, `'use client'`).
- **`NoAccountNotice`** — Imported UI component from `@flamingo-stack/openframe-frontend-core` that renders the "no account" message and handles the back-to-login action via its `onBackToLogin` prop.
- **`routes.auth.login`** — Shared route constant used to navigate back to the login page.

## Usage Example

```typescript
// This is a Next.js page component, automatically routed based on file location.
// It requires no props — rendering is triggered by navigation to its route path
// (e.g., after a mobile SSO flow detects a missing OpenFrame account).

import NoAccountPage from './page';

// Rendered by the Next.js App Router when the matching path is visited.
// On "Back to Login" interaction, it replaces the current history entry
// with the login route, preventing the user from navigating back to this notice.
export default NoAccountPage;
```

Navigation uses `router.replace` rather than `router.push`, ensuring the no-account notice is removed from browser history once the user returns to login.
