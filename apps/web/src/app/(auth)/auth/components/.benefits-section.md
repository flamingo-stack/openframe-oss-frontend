# benefits-section.tsx

Client-side React component that renders the right-hand panel of the authentication pages, displaying either a waitlist signup form (for shared SaaS deployments) or a list of OpenFrame product benefits (for standard deployments), based on the current runtime app mode.

## Key Components

- **`AuthBenefitsSection`** — Default-exported function component with no props. Determines rendering behavior using `runtimeEnv.appMode()`:
  - **`saas-shared` mode**: Renders the OpenFrame logo/wordmark and a `WaitlistForm` that posts registrations to the hub public API.
  - **All other modes**: Renders the OpenFrame logo and a stack of `BenefitCard` components ("Cut Vendor Costs", "Automate Everything", "Reclaim Your Profits").
- **`handleRegister`** — Internal `useCallback` handler that submits the waitlist registration (email, optional phone, platform, and Reddit click ID if present) to `${HUB_PUBLIC_API}/waitlist`. Handles success, duplicate-email, and error states via `useToast`, and manages `isSubmitting`/`isSuccess` state.

## Usage Example

```typescript
import { AuthBenefitsSection } from '@/components/auth/benefits-section';

export default function AuthLayout() {
  return (
    <div className="grid grid-cols-2">
      <div>{/* Login/Signup form */}</div>
      <AuthBenefitsSection />
    </div>
  );
}
```

## Notes

- Relies on external configuration: `HUB_PUBLIC_API`, `PRIVACY_POLICY_URL`, `TERMS_URL`, and `runtimeEnv.appMode()`.
- Integrates Reddit click-ID tracking (`getStoredRedditClickId`/`clearStoredRedditClickId`) for attribution on successful waitlist signups.
- Treats a `DUPLICATE_EMAIL` API error code as a successful outcome (shows an "Already Registered" toast instead of an error).
- Styling uses Tailwind utility classes with `ods-*` design tokens for theme consistency.
