# sso-join-card.tsx

A client component that wraps `SsoJoinForm` to render the "One Last Step" SSO onboarding card, mapping a pending SSO join identity into the form's display props while handling the loading state before that identity is fetched.

## Key Components

- **`SsoJoinCardProps`** — Props interface extending `SsoJoinForm`'s props (minus `name`, `email`, `organizationName`, `roles`), adding a `pending: PendingSsoJoin | null` field representing the server-held identity for the SSO flow.
- **`SsoJoinCard`** — The main exported component. It:
  - Derives a display `name` by joining `firstName` and `lastName` from `pending` (falling back gracefully when either is missing, e.g. for providers like Apple that only assert an email).
  - Passes `identityLoading={!pending}` to `SsoJoinForm` so the form can render skeleton/loading bars for identity fields until `pending` resolves.
  - Maps `email`, `organizationName` (from `pending.tenantName`), and `roles` (defaulting to `NO_ITEMS`) onto the underlying form.

## Usage Example

```typescript
import { SsoJoinCard } from '@/app/components/sso-join-card';
import type { PendingSsoJoin } from '@/lib/auth-api-client';

function SsoOnboardingPage() {
  const pending: PendingSsoJoin | null = usePendingSsoJoin(); // fetched elsewhere

  return (
    <SsoJoinCard
      pending={pending}
      onSubmit={(values) => {
        // handle join submission
      }}
    />
  );
}
```

While `pending` is `null`, the card renders with `identityLoading` enabled so the form shows loading placeholders for the identity row. Once `pending` resolves, the real `name`, `email`, `organizationName`, and `roles` values populate the form automatically.
