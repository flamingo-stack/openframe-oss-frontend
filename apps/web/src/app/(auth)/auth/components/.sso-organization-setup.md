## sso-organization-setup.tsx

React component that renders an organization-creation form for SSO identities that authenticated successfully but have no associated account yet. It is shared between the web `sso-continue` flow (session-based identity) and the native Apple sign-in flow (in-memory credential), unifying the same organization/domain collection UX across both paths.

## Key Components

- **`SsoSetupIdentity`** — Interface describing the verified SSO identity passed into the form (optional `email`, required `provider`). The email is always read-only since the server derives it from the verified identity.
- **`SsoOrganizationSetup`** — Main exported component. Renders `CreateOrganizationForm` pre-populated with the SSO provider's identity, manages organization name/domain state, validates input, and calls `onSubmit` with the finalized `tenantName`/`tenantDomain`.
- **`ssoProviderLabel`** — Internal helper that maps a provider id (including the special `openframe-sso` built-in id) to its display name via `PROVIDER_META`.
- **`OPENFRAME_SSO_ID`** — Constant for the authorization server's built-in provider id.

## Usage Example

```typescript
import { SsoOrganizationSetup, type SsoSetupIdentity } from './sso-organization-setup';

function SsoContinuePage() {
  const identity: SsoSetupIdentity | null = useSsoIdentity(); // from session
  const router = useRouter();

  const handleSubmit = async ({ tenantName, tenantDomain }: { tenantName: string; tenantDomain: string }) => {
    await createOrganization({ tenantName, tenantDomain });
    router.push('/dashboard'); // navigates away; component never resolves further
  };

  return (
    <SsoOrganizationSetup
      identity={identity}
      onSubmit={handleSubmit}
      isSubmitting={false}
    />
  );
}
```

For the native Apple flow, pass an `onBack` callback so users can abandon the single-screen form:

```typescript
<SsoOrganizationSetup
  identity={appleCredentialIdentity}
  onSubmit={bridgeSubmitHandler}
  onBack={() => dismissSheet()}
/>
```

The form self-manages loading state via `useLoadingScope`, draws placeholder bars while `identity` is `null`, and revalidates domain availability at submit time to avoid stale debounce results.
