# create-organization-section.tsx

A two-step client-side React component that drives the organization sign-up flow, collecting an email/SSO choice first, then organization and account details on a second screen within the same view.

## Key Components

- **`CreateOrganizationSectionProps`** — Interface defining the component's inputs: `onRegister` callback (fires with the full signup payload), optional `ssoProviders` list and loading flag, `onSsoLogin` handler, and `isLoading`.
- **`CreateOrganizationSection`** — Main exported component. Manages local state for email, organization name, terms agreement, personal details, and password fields. Internally tracks a `step` state (`'email'` | `'details'`) to render either:
  - **Step 1 (`email`)**: Renders `LoginForm` with email input and SSO provider buttons, validating email format and availability before allowing progression.
  - **Step 2 (`details`)**: Renders `CreateOrganizationForm` with organization name, domain (via `useOrganizationDomain`), and personal/credential fields, plus an optional dev-only PR number input.
- Relies on `useEmailAvailability` and `useOrganizationDomain` hooks for live validation of email and subdomain availability, and various validation helpers/constants (`getPasswordError`, `isValidPersonName`, `ORG_NAME_REGEX`, etc.) from `registration-validation`.
- Fires a `pushSignupStarted` PostHog analytics event exactly once when the user advances to the details step.

## Usage Example

```typescript
import { CreateOrganizationSection } from '@/app/(auth)/auth/components/create-organization-section';

function SignupPage() {
  const handleRegister = (payload: {
    orgName: string;
    domain: string;
    email: string;
    firstName: string;
    lastName: string;
    password: string;
    prNumber?: number;
  }) => {
    // Submit the complete signup payload to the backend
    submitSignup(payload);
  };

  return (
    <CreateOrganizationSection
      onRegister={handleRegister}
      ssoProviders={availableSsoProviders}
      ssoProvidersLoading={false}
      onSsoLogin={(provider) => startSsoFlow(provider)}
      isLoading={isSubmitting}
    />
  );
}
```

Both validation (email/domain availability, password strength, name format) and submission are fully handled internally; the parent only needs to supply `onRegister` and optional SSO wiring.
