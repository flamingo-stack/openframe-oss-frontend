Client-side React component rendering the login step of the authentication flow, offering SSO provider sign-in options (including OpenFrame's built-in SSO) in a card-styled UI.

## Key Components

- **`AuthLoginSection`** - Default-style exported function component that renders the SSO login UI.
- **`AuthLoginSectionProps`** - Props interface defining `email`, `tenantInfo`, `hasDiscoveredTenants`, `availableProviders`, `onSso`, `onBack`, `isLoading`, and optional `onEmailPasswordLogin`.
- **`TenantInfo`** - Interface describing discovered tenant data (`tenantName`, `tenantDomain`).
- **`SsoProvider`** - Interface describing a normalized SSO provider entry (`provider`, `enabled`, `displayName`).
- **`OPENFRAME_IDS`** - Constant array distinguishing OpenFrame's built-in SSO (`openframe`, legacy `openframe-sso`) from standard third-party providers.
- **`handleSsoClick`** - Internal handler that sets the active login method and triggers the `onSso` callback for a given provider.

## Usage Example

```typescript
import { AuthLoginSection } from './login-section';

function LoginPage() {
  const handleSso = async (provider: string) => {
    // redirect to SSO provider or initiate OAuth flow
    console.log('Signing in with', provider);
  };

  return (
    <AuthLoginSection
      email=""
      tenantInfo={null}
      hasDiscoveredTenants={false}
      availableProviders={['openframe', 'google', 'microsoft']}
      onSso={handleSso}
      onBack={() => console.log('Back to previous step')}
      isLoading={false}
    />
  );
}
```

The component automatically separates OpenFrame's built-in SSO from third-party providers (Google, Microsoft, Slack, GitHub), rendering OpenFrame SSO as the primary call-to-action with a "Back" button, and other providers beneath an "or continue with" divider via `AuthProvidersList`.
