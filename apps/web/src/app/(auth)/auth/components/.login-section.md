Renders the login interface for authenticated users, presenting SSO provider options (including OpenFrame SSO as a primary option) and an email/password fallback for accessing an organization's tenant.

## Key Components

### `AuthLoginSection`

Main exported component that handles the login UI flow.

**Props (`AuthLoginSectionProps`):**

| Prop | Type | Description |
|------|------|-------------|
| `availableProviders` | `string[]` | List of SSO provider identifiers (e.g. `"google"`, `"openframe-sso"`) |
| `onSso` | `(provider: string) => Promise<void>` | Callback triggered when a provider button is clicked |
| `onBack` | `() => void` | Callback to navigate back to the previous step |
| `isLoading` | `boolean` | Disables buttons and shows loading state |
| `onEmailPasswordLogin` | `(email, password) => Promise<void>` | Optional email/password login handler |

**Internal logic:**
- Separates `openframe-sso` from standard OAuth providers
- Renders OpenFrame SSO as a primary `accent` button when present
- Delegates standard providers to `AuthProvidersList` in vertical orientation

## Usage Example

```typescript
import { AuthLoginSection } from '@/components/auth/login-section';

<AuthLoginSection
  email="user@acme.com"
  tenantInfo={{ tenantName: 'Acme Corp', tenantDomain: 'acme.com' }}
  hasDiscoveredTenants={true}
  availableProviders={['openframe-sso', 'google', 'microsoft']}
  onSso={async (provider) => {
    await initiateOAuthFlow(provider);
  }}
  onBack={() => router.push('/auth/email')}
  isLoading={false}
/>
```

## Notes

- `openframe-sso` always renders above other providers with an `"or continue with"` divider
- Provider display names are derived automatically from the provider identifier string
- The `loginMethod` state tracks SSO vs. email mode for scoped loading indicators
