# native-sso-signup-section.tsx

Renders the organization-setup screen shown after a verified SSO identity (Apple or ticket-based) is confirmed but has no linked account yet. It is shared by both native signup paths so they present identical UI and behavior, and is always rendered in place on the current auth tab rather than at a dedicated route, since neither identity type survives a navigation.

## Key Components

- **`NativeSsoSignupSectionProps`** — Props interface: `pending` (the verified identity, memory-only), `onRegistered` (callback after successful token storage), `onExit` (discards the identity and returns to sign-in).
- **`NativeSsoSignupSection`** — The main component. Responsibilities:
  - Resolves the display identity: immediate for Apple (`appleIdentityEmail`), fetched asynchronously for ticket-based flows via `authApiClient.pendingSsoIdentityByTicket`.
  - Handles ticket expiry (HTTP 409) by toasting and calling `onExit`.
  - Submits the organization form via `appleNativeRegister` or `completeNativeSsoSignup` depending on `pending.kind`.
  - Tracks `isSpent`/`spentMessage` state for a non-recoverable Apple authorization code failure, rendering a dedicated "couldn't create organization" screen with a back-to-sign-in action.
  - Calls `markPendingSignup()` and `onRegistered()` on success to align analytics with the password signup flow.
  - Wraps the shared `SsoOrganizationSetup` form in `LoadingWhen` until the identity is resolved.

## Usage Example

```typescript
import { NativeSsoSignupSection } from '@/app/(auth)/auth/components/native-sso-signup-section';
import type { PendingSsoSignup } from '@/lib/native-login';

function AuthLoginTab({ pending }: { pending: PendingSsoSignup }) {
  const handleRegistered = () => {
    // navigate away from the auth screen
  };

  const handleExit = () => {
    // clear pending identity, show sign-in form again
  };

  return (
    <NativeSsoSignupSection
      pending={pending}
      onRegistered={handleRegistered}
      onExit={handleExit}
    />
  );
}
```

Typically instantiated by the login/signup tab controller once a provider (Apple or ticket-backed SSO) returns a verified identity with no existing account.
