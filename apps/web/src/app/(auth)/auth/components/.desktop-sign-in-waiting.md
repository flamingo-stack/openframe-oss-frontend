# desktop-sign-in-waiting.tsx

A client-side React component that displays a waiting state while a desktop sign-in flow completes in the user's default browser, replacing what used to be a frozen spinner for up to five minutes.

## Key Components

- **`formatTimeLeft(seconds: number): string`** — Formats remaining seconds into a `M:SS` countdown string.
- **`DesktopSignInWaiting({ wait }: { wait: DesktopSignInWait })`** — Component that renders a card showing sign-in progress, a live countdown, and two actions:
  - **Reopen browser** — Re-opens the original sign-in URL (`wait.loginUrl`) in a new browser tab/window, useful if the user accidentally closed the tab, without canceling the wait.
  - **Cancel** — Calls the native shell's auth plugin to cancel the pending sign-in. If the cancellation succeeds (i.e., the shell hadn't already resolved the wait via a browser result or timeout), a toast notification confirms the cancellation.

The component uses `useNow(1000)` to tick a live clock every second, computing `secondsLeft` from `wait.deadline`. It is explicitly never prerendered since the wait state only exists at runtime in the shell app.

## Usage Example

```typescript
import { DesktopSignInWaiting } from '@/components/desktop-sign-in-waiting';
import type { DesktopSignInWait } from '@/lib/desktop-sign-in-wait';

function AuthForm({ pendingWait }: { pendingWait: DesktopSignInWait | null }) {
  if (pendingWait) {
    return <DesktopSignInWaiting wait={pendingWait} />;
  }

  return <LoginForm />;
}
```

The `wait` object typically includes `deadline` (epoch ms), `loginUrl` (string), and an optional `email` to display which account is signing in. This component should be swapped in for the standard login form whenever a `DesktopSignInWait` is active, and swapped back out once the native shell resolves (success, cancellation, or timeout).
