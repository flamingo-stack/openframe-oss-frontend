# standalone-auth-shell.tsx

Provides a shell wrapper for standalone auth pages (invite, password reset, and their loading states) that live outside the `(tabs)` route group, conditionally rendering a compact layout for login-only mobile builds to comply with App Store review requirements.

## Key Components

- **`StandaloneAuthShell`** — Internal component that switches between `AuthShell` (default, with optional footer) and `CompactAuthShell` (no marketing benefits panel, no footer slot) based on `useLoginOnlyMobileShell()`. Not exported; used internally by `BackToLoginShell`.
- **`BackToLoginShell`** — Exported wrapper that renders `StandaloneAuthShell` with a `BackToLoginLink` footer, used for pages that need a "back to login" action.
- **`StandaloneAuthShellProps`** — Props interface: `children` (ReactNode) and optional `footer` (ReactNode, desktop-only).

## Usage Example

```typescript
import { BackToLoginShell } from '@/app/components/standalone-auth-shell';

function PasswordResetPage() {
  const router = useRouter();

  const handleBack = () => {
    router.push('/login');
  };

  return (
    <BackToLoginShell onBack={handleBack}>
      <PasswordResetForm />
    </BackToLoginShell>
  );
}

function PasswordResetLoadingFallback() {
  // onBack is a no-op since the Suspense fallback is inert
  return (
    <BackToLoginShell onBack={() => {}}>
      <LoadingSpinner />
    </BackToLoginShell>
  );
}
```

**Note:** On login-only mobile builds, `useLoginOnlyMobileShell()` returns `true`, causing the component to render `CompactAuthShell` with `tagline={null}` instead of the default `AuthShell`, suppressing the marketing/sign-up panel that conflicts with App Store guidelines 3.1.1/3.1.3.
