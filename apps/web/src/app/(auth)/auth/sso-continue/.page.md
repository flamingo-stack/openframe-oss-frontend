## Overview

Next.js client page that continues a browser-flow SSO login for an identity with no existing OpenFrame tenant account. The auth server redirects to this route after a provider authenticates a user it cannot map to a tenant; the page lets the user create/select a tenant organization to complete signup, without ever letting them edit the already-established identity.

## Key Components

- **`SsoContinuePage`** (default export) — the page component, rendered within `AuthShell`.
- **`identity` state** — fetched via `authApiClient.pendingSsoIdentity()` on mount; a session-cookie XHR that returns the pending SSO identity tied to the current SAS session.
- **`handleSubmit`** — builds the organization setup values and performs a **top-level navigation** (`window.location.href`) to `authApiClient.completeSsoRegistrationUrl(values)`, since the response is a 302 redirect chain that sets auth cookies and must be committed by the browser, not followed via `fetch`.
- **`SsoOrganizationSetup`** — child form component rendered once the identity resolves, handling tenant name/domain input.
- **`LoadingWhen`** — wraps the form so it shows its own loading state while identity data is in flight.
- **Analytics hooks** — `pushIdentify` (identifies the user by email once known) and `markPendingSignup` (sets a marker consumed later to gate the `signup_completed` funnel event for SSO signups).

## Behavior Notes

- A `409` response from `pendingSsoIdentity()` signals an expired session/flow cookie — the user is shown a message and redirected to `routes.auth.login`. Any other failure shows a generic expiry message.
- `hasNavigated` (a `ref`) guards against duplicate submissions triggering multiple navigations.
- `isNavigating` keeps the form disabled while the browser is mid-redirect, since the component is about to unmount.

## Usage Example

This page is routed to automatically by the auth server redirect and is not meant to be invoked directly in app code. Conceptually, the flow looks like:

```typescript
// Auth server redirects here after SSO auth succeeds but no tenant match is found:
// GET /auth/sso-continue

// On mount:
const res = await authApiClient.pendingSsoIdentity();
if (res.ok && res.data?.email) {
  // show SsoOrganizationSetup with the resolved identity
}

// On user submit:
window.location.href = authApiClient.completeSsoRegistrationUrl({
  tenantName: 'Acme Inc',
  tenantDomain: 'acme',
});
// Browser follows the 302 chain to /oauth/continue, cookies are set, session begins.
```
