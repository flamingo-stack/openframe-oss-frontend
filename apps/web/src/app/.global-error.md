Next.js root-level error boundary that replaces the entire document when an unrecoverable error occurs in the root layout. Unlike nested error boundaries, this component renders its own `<html>`/`<body>` tags and operates without any app providers or shell chrome.

## Key Components

- **`GlobalError`** — Default export; a `'use client'` Next.js global error boundary accepting `error` and `reset` props
- **`hideSplashScreen`** — Called on mount to dismiss the native splash screen if a crash occurs before the normal initialization chain completes (no-op on web)
- **Focus management** — `headingRef` moves focus to the error heading on mount for assistive technology compatibility
- **Dual recovery actions** — "Reload" triggers a full `window.location.reload()`; "Try Again" calls the Next.js-provided `reset()` to attempt re-rendering

## Usage Example

This file is automatically used by Next.js — no manual import required. Place it at the app root alongside `layout.tsx`:

```text
app/
├── layout.tsx
├── global-error.tsx   ← picked up automatically by Next.js
└── globals.css
```

```typescript
// Next.js invokes this automatically on root layout crashes.
// The reset() callback is provided by the framework.
<GlobalError
  error={new Error('Root layout failed')}
  reset={() => {/* Next.js retry logic */}}
/>
```

## Behavior Notes

- Imports `globals.css` directly since the normal layout (which would supply it) is not mounted
- Logs all errors to the console via `console.error('[Global Error Boundary]', error)`
- Renders in `dark` mode with `data-app-type="openframe"` to preserve on-brand styling during a crash
- Safe to deploy standalone — has no dependency on app-level context providers or routing state
