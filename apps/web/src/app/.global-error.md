# global-error.tsx

Next.js root error boundary component that catches errors thrown by the root layout itself. Since it replaces the entire document when triggered, it renders its own full `<html>`/`<body>` structure independent of the app's normal providers and shell chrome, presenting a self-contained, on-brand crash screen.

## Key Components

- **`GlobalError`** — Default export; the root error boundary component required by Next.js App Router convention (`app/global-error.tsx`). Accepts:
  - `error: Error & { digest?: string }` — the thrown error, logged via `console.error`
  - `reset: () => void` — Next.js-provided callback to attempt recovery without a full reload

### Behavior
- Logs the error to the console for debugging
- Calls `hideSplashScreen()` to dismiss the native splash screen in case the crash occurred during shell boot, before the normal token-hydration flow could hide it (no-op on web)
- Moves keyboard focus to the error heading on mount for assistive technology support
- Renders a centered error UI with `OpenframeLockup`, an alert message, and two actions:
  - **Reload** — forces a full page reload via `window.location.reload()`
  - **Try Again** — invokes the `reset` callback to attempt in-place recovery
- Includes `PoweredByFlamingo` branding footer

## Usage Example

This file is automatically used by Next.js and is not imported manually. It must live at the app root (e.g., `app/global-error.tsx`) and is activated only when an error escapes the root layout:

```typescript
// app/global-error.tsx
// Next.js automatically renders this when the root layout throws.
// No manual invocation is required — simply ensure the file exists
// at the app directory root with the exported default component.
```

**Note:** Because this boundary replaces the root layout entirely, it must remain self-contained — avoid relying on context providers, global styles beyond the explicit `./globals.css` import, or any shell chrome mounted elsewhere in the app.
