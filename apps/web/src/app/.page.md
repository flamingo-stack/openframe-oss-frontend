This is the root (`/`) route component for the Next.js app. It performs a pure client-side redirect to either the dashboard or the auth page based on authentication state, while preserving query strings and URL hash fragments needed for marketing/analytics tracking (ad click IDs, UTM params, PostHog distinct IDs).

## Key Components

- **`Home`** — Default exported page component for the root route. Renders nothing but a blank background `div` while an effect redirects the user.
- **`isAuthenticated`** — Read from `useAuthStore`; `null` indicates the auth state hasn't resolved yet, which pauses the redirect.
- **`target()`** — Builds the redirect URL via `getDefaultRedirectPath`, appending `window.location.search` and `window.location.hash` so tracking params survive the hop.
- **Fallback timer** — A 1.5s `setTimeout` safety net that re-fires the redirect if a third-party GTM tag wipes the router state mid-transition and leaves the user stuck on `/`.

## Usage Example

This file is a Next.js App Router page and is not imported directly; it's automatically mounted for the root path:

```typescript
// app/page.tsx
// Visiting "/" with tracking params, e.g.:
// /?fbclid=abc123&utm_source=meta#distinct_id=xyz789
//
// Behavior:
// 1. Waits for auth state to resolve (isAuthenticated !== null)
// 2. Redirects to either the dashboard or /auth, preserving the
//    query string and hash:
//    /auth?fbclid=abc123&utm_source=meta#distinct_id=xyz789
// 3. If still on "/" after 1.5s (e.g. a GTM tag reset router state),
//    forces a hard redirect via window.location.replace
```

**Notes:**
- The component intentionally renders only a minimal background (`bg-ods-bg`) matching the native splash screen — it should never be visible long enough to need a full loading UI.
- The fallback `setTimeout` is defensive insurance against third-party tag managers mutating browser history during the redirect; see inline comments for the historical incident this guards against.
