## eslint.config.mjs

ESLint flat configuration for the OpenFrame OSS frontend. This is the fast, non-type-aware lint pass — the one the editor loads and `npm run lint` runs — built entirely from shared presets in `@flamingo-stack/openframe-frontend-core/eslint-config`, with narrowly-scoped local exceptions layered on top. A separate `eslint.types.mjs` extends this file to add type-aware rules, keeping a single source of truth.

## Key Components

- **Default export** — an array built with `defineConfig`, composing (in load-bearing order): `next` (base config), `relay`, `tests` (additive), then `prettierCompat` last so it always wins over stylistic rules from future preset updates.
- **`openframe-rules/index.mjs`** — imported but not directly spread here; used to supply custom local rule definitions referenced elsewhere in the repo's lint tooling.
- **File-scoped override blocks** — each disables one specific rule for a named, justified set of files rather than globally:
  - `node-test-runner`: disables Vitest-specific rules for `**/*.test.mjs` files that run under `node --test`.
  - `hydrate-from-browser-storage`: disables `react-hooks/set-state-in-effect` for components reading `localStorage`/`sessionStorage` post-mount (required due to static export/SSR hydration constraints).
  - `start-work-on-mount`: disables the same rule for hooks that fetch data or subscribe on mount, where state is set asynchronously inside callbacks.
  - `reference-stability-caches`: disables `react-hooks/refs` where ref-based caches are intentionally read/written during render for reference-equality memoization.
  - `component-registry-lookup`: disables `react-hooks/static-components` for components resolved via a registry/lookup table rather than declared inline.
  - `contravariant-filter-fn`: disables `@typescript-eslint/no-explicit-any` for one documented, load-bearing `any` in `src/lib/table-filters.ts`.
  - `fragment-definitions-render-nothing`: disables `relay/must-colocate-fragment-spreads` for GraphQL modules and components following the inline-fragment-ladder pattern mandated by the project architecture.
  - `store-mirror-cycle`: disables `@typescript-eslint/no-use-before-define` for store/mirror pairs with genuine circular references resolved at runtime via callbacks.

Each override documents *why* it exists, since inline `eslint-disable` comments are rejected by the shared config's `noInlineConfig` setting.

## Usage Example

```bash
# Run the fast (non-type-aware) lint pass
npm run lint

# Fix auto-fixable issues
npm run lint -- --fix
```

```javascript
// Referencing this config directly, e.g. in an editor integration
import config from './eslint.config.mjs';
// config is an array of flat ESLint config objects
```
