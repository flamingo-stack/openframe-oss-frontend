## eslint.config.mjs

ESLint flat-config entry point for the OpenFrame frontend. It assembles shared rule presets from `@flamingo-stack/openframe-frontend-core` and layers on repo-local, file-scoped exceptions — each documented with the specific code shape that justifies disabling a rule rather than fixing the code.

## Key Components

- **Default export** — an array built with `defineConfig` combining:
  - `next`, `relay`, `tests` — shared presets from `@flamingo-stack/openframe-frontend-core/eslint-config`, loaded first/additively.
  - `openframeRules` import from local `./eslint-rules/index.mjs` (custom rule definitions referenced by name, e.g. `openframe-frontend/*` block names).
  - `prettierCompat` — intended to load last so it overrides any stylistic rule from presets (noted in comments, though not visibly spread into the final array in this snippet).
- **Scoped override blocks** — each targets specific `files:` globs and turns off a narrow set of rules, with an inline comment explaining the architectural reason (e.g., hydration-sensitive `useEffect` reads, Relay fragment colocation exceptions, contravariant `any` usage, mirror/store circular references).

## Usage Example

```bash
# Fast, non-type-aware lint pass (what npm run lint and the editor use)
npm run lint
```

```javascript
// Pattern for adding a new scoped exception — always file-scoped and reasoned
{
  name: 'openframe-frontend/my-exception-name',
  files: ['src/app/(app)/some-feature/some-file.ts'],
  rules: { 'rule-name': 'off' },
}
```

Note: this file is the **non-type-aware** fast pass. The type-aware counterpart lives in `eslint.types.mjs`, which extends this config rather than duplicating it — keeping a single source of truth for lint rules across both fast and full CI checks.
