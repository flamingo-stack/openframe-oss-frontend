This script enforces the project's loading-state convention by running the shared "loading gate" check against all page components, ensuring every page implements proper skeleton/loading UI states.

## Key Components

- **`runLoadingGate(checkName)`** — Imported from `./lib/loading-gate.mjs`; the shared engine that performs the actual validation logic and rule enforcement for loading-state checks.
- **Execution call** — Invokes `runLoadingGate('check-page-skeletons')`, passing this script's identifier so the shared engine can report results and errors under the correct check name.

This file is intentionally a thin CLI entry point: all validation rules, file scanning, and reporting logic live in the shared library module (`scripts/lib/loading-gate.mjs`), keeping this script minimal and declarative.

## Usage Example

Run directly as a Node script (it has a shebang, so it can be executed or invoked via `node`):

```bash
# Direct execution (requires executable permission)
./scripts/check-page-skeletons.mjs

# Or via node
node scripts/check-page-skeletons.mjs
```

Typically wired into `package.json` as a lint/CI script:

```json
{
  "scripts": {
    "check:page-skeletons": "node scripts/check-page-skeletons.mjs"
  }
}
```

```bash
npm run check:page-skeletons
```

The script exits with a non-zero status code if any page component is missing a required loading skeleton, making it suitable for CI pipelines and pre-commit hooks.
