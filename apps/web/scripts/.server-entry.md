# server-entry.js

Runtime monkey-patch wrapper around Next.js's generated `server.js` that fixes a Next 16 bug where non-GET/HEAD requests to existing static assets (`/_next/static/` or `public/`) incorrectly return HTTP 500 instead of the correct HTTP 405 (Method Not Allowed).

Next's internal 405 handling tries to render a `/405` page through a Pages-Router-only lookup that App-Router builds can't satisfy, silently degrading to a 500 response. This file intercepts the response at the `http.createServer` level and rewrites botched 500 responses (detected by the presence of an `Allow` header) back into proper 405 responses with a clean plain-text body.

This is a temporary workaround intended to be deleted once upstream Next.js fixes the issue (unfixed as of Next 16.3.0).

## Key Components

- **`http.createServer` override** — Wraps the handler function passed to `createServer` so every request/response pair gets patched before reaching Next's handler.
- **`isBotched405(status)`** — Detects the bug signature: a `500` status combined with an `Allow` header (which only Next's base-server and router-server set on genuine 405s).
- **`applyRepair()`** — Strips asset-specific headers (`ETag`, `Transfer-Encoding`) and sets correct headers (`Content-Length`, `Content-Type: text/plain`, `Cache-Control: no-store`) for the repaired 405 body.
- **Patched `res.writeHead` / `res.write` / `res.end`** — Intercept response writes to suppress the original (incorrect) body and substitute the fixed 405 status and `BODY` constant (`"Method Not Allowed"`).
- **Install-check watchdog** — A 10-second `setTimeout` that logs an error to the console if the patch was never installed (e.g., if a future Next version stops using `http.createServer` directly), so regressions are caught instead of silently reappearing.

## Usage Example

This file is not imported programmatically — it's used as the container/process entrypoint in place of Next's own `server.js`.

```dockerfile
# Dockerfile
ENTRYPOINT ["node", "scripts/server-entry.js"]
```

```bash
# Direct invocation
node scripts/server-entry.js
```

Internally it requires and boots the real server:

```javascript
// at the bottom of server-entry.js
require('./server.js');
```

Once the upstream Next.js 405/500 rendering bug is fixed, this file should be removed and the entrypoint reverted to `node server.js` directly.
