# server-entry.js

Standalone-server entrypoint that wraps Next.js's generated `server.js` to patch a Next 16 bug where non-`GET`/`HEAD` requests to existing static files (`/_next/static/` or `public/`) incorrectly return `500 Internal Server Error` instead of `405 Method Not Allowed`.

Next sets the `Allow` header and attempts a 405 response via a Pages-Router-only status-page lookup that fails under App Router builds, silently downgrading the response to a 500. This file monkey-patches `http.createServer` to detect and repair that specific response signature (500 status + `Allow` header present) before requiring the real `server.js`.

## Key Components

- **`http.createServer` override** — Intercepts Next's server creation call and wraps its request handler to inspect/repair outgoing responses.
- **`isBotched405(status)`** — Detects the bug signature: a `500` status paired with an `Allow` header, which only Next's internal 405 code paths ever set.
- **`applyRepair()`** — Strips stale headers (`ETag`, `Transfer-Encoding`), sets `Content-Type`, `Content-Length`, and `Cache-Control` for the replacement plain-text body.
- **Patched `writeHead` / `write` / `end`** — Hooks on `res` that detect the botched response at whichever stage headers/body are first flushed, rewrite the status to `405`, and ensure only the fixed `BODY` ("Method Not Allowed") is sent, discarding the original payload.
- **Install-check watchdog** — A 10-second `setTimeout` that logs an error if `http.createServer` was never invoked with a handler, signaling the patch silently no-op'd (e.g., after a Next upgrade changes internals).

## Usage Example

This file is not imported programmatically — it's a Docker/runtime entrypoint replacement:

```dockerfile
# Instead of:
# ENTRYPOINT ["node", "server.js"]

ENTRYPOINT ["node", "scripts/server-entry.js"]
```

At runtime it requires and boots the real server:

```javascript
// Last line of server-entry.js
require('./server.js');
```

No other usage is needed — simply point your container/process manager at `server-entry.js` instead of Next's generated `server.js`. Remove this wrapper once the upstream Next.js bug is fixed (unresolved as of 16.3.0).
