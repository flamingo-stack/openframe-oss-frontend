Thin CLI entry point that invokes the shared loading-gate validation engine under a legacy script name, preserved for backward-compatible invocation (e.g., existing CI pipelines or npm scripts referencing this filename).

## Key Components

- **`runLoadingGate(scriptName)`** - Imported from `./lib/loading-gate.mjs`; performs the actual loading-state/skeleton validation logic. This file simply calls it with its own script name (`'check-skeleton-full-page'`) as an identifier, likely used for logging, error messages, or config lookup within the shared engine.

## Usage Example

Run directly via Node.js (requires the shebang and executable permissions, or invoke with `node` explicitly):

```bash
node check-skeleton-full-page.mjs
```

Or as an npm script:

```json
{
  "scripts": {
    "check:skeleton": "node scripts/check-skeleton-full-page.mjs"
  }
}
```

The actual validation rules, exit codes, and reporting behavior are defined in the shared library at [`scripts/lib/loading-gate.mjs`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/scripts/lib/loading-gate.mjs) - refer to that file's header documentation for details on what the gate checks and how failures are reported. This wrapper exists purely to preserve an older script name/path so existing automation that references `check-skeleton-full-page.mjs` continues to work without modification.
