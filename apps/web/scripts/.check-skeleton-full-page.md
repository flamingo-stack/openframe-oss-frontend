A thin CLI entry point that invokes the shared loading gate validation engine under a legacy script name, preserved for backward compatibility with existing tooling or CI references.

## Key Components

- **`runLoadingGate` (imported)** — Core validation function from `./lib/loading-gate.mjs` that performs the actual skeleton/loading-state checks; this file does not redefine logic, it only triggers the shared engine.
- **Invocation** — Calls `runLoadingGate('check-skeleton-full-page')`, passing the script's identifier so the shared engine can report context-specific results (e.g., in logs or error messages).

## Usage Example

Run directly via Node.js as an executable script (it has a shebang):

```bash
node scripts/check-skeleton-full-page.mjs
```

Or, if marked executable:

```bash
./scripts/check-skeleton-full-page.mjs
```

Typical integration in a `package.json` script:

```json
{
  "scripts": {
    "check:skeleton-full-page": "node scripts/check-skeleton-full-page.mjs"
  }
}
```

This script is typically run as part of CI or pre-commit checks to ensure full-page skeleton/loading states follow the conventions enforced by the shared `loading-gate` library. For details on what checks are performed, refer to the implementation in [`scripts/lib/loading-gate.mjs`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/scripts/lib/loading-gate.mjs).
