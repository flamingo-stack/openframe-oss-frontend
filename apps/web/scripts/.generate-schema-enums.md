Node.js build script that parses `schema.graphql` and generates a TypeScript module containing Prisma-style enum objects for every GraphQL `enum` definition, enabling type-safe access to both enum values and types from a single exported identifier.

## Key Components

- **`SCHEMA_PATH`** — resolved path to the root `schema.graphql` file (input).
- **`OUT_PATH`** — resolved path to `src/generated/schema-enums.ts` (generated output, gitignored).
- **Enum extraction** — parses the SDL with `graphql`'s `parse()`, filters `EnumTypeDefinition` nodes, and sorts them alphabetically by name.
- **Code generation** — for each enum, emits a `const` object mapping each value to its string literal, plus a derived TypeScript type of the same name using `(typeof X)[keyof typeof X]`.
- **File writer** — creates the `src/generated/` directory if missing and writes the final `.ts` file with a `@generated` header warning against manual edits.

## Usage Example

Run directly via the npm script (chained into the build process):

```bash
npm run generate-enums
```

This produces output like:

```typescript
// @generated by scripts/generate-schema-enums.mjs from schema.graphql — DO NOT EDIT

export const SubscriptionStatus = {
  ACTIVE: 'ACTIVE',
  CANCELED: 'CANCELED',
} as const;
export type SubscriptionStatus = (typeof SubscriptionStatus)[keyof typeof SubscriptionStatus];
```

Consumers can then import and use both the runtime value and the type:

```typescript
import { SubscriptionStatus } from '@/generated/schema-enums';

function isActive(status: SubscriptionStatus): boolean {
  return status === SubscriptionStatus.ACTIVE;
}
```

**Note:** This output directory is intentionally separate from `src/__generated__/`, which is managed exclusively by `relay-compiler` and prunes non-Relay files. See [`generate-schema-enums.mjs`](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/scripts/generate-schema-enums.mjs).
