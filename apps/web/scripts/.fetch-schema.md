# fetch-schema.mjs

A Node.js CLI script that fetches a GraphQL schema from a running DGS backend using introspection and writes it to `schema.graphql` in SDL format, enabling the Relay compiler to generate typed queries.

## Key Components

- **`getArg(name)`** - Parses `--<name> <value>` style CLI arguments from `process.argv`.
- **`loadDotEnv()`** - Reads `.env.local` and `.env` files (without overwriting existing env vars) to populate `process.env`, used to resolve `NEXT_PUBLIC_TENANT_HOST_URL`.
- **`INTROSPECTION_QUERY`** - Standard GraphQL introspection query (with `FullType`, `InputValue`, and `TypeRef` fragments) used to retrieve the full schema definition.
- **`fetchSchema()`** - Async function that:
  - Sends the introspection query via `POST` to the resolved `ENDPOINT`, optionally with a Bearer `TOKEN`.
  - Validates the HTTP response and checks for GraphQL errors.
  - Uses `buildClientSchema` and `printSchema` from the `graphql` package to convert introspection JSON into SDL.
  - Writes the generated schema (with a header comment) to `schema.graphql` at the project root.

Configuration resolution order:
- **Endpoint:** `--endpoint` CLI arg → `${NEXT_PUBLIC_TENANT_HOST_URL}/api/graphql` → `http://localhost:8080/api/graphql`.
- **Token:** `--token` CLI arg → `GRAPHQL_TOKEN` environment variable.

## Usage Example

```bash
# Use NEXT_PUBLIC_TENANT_HOST_URL from .env / .env.local
npm run fetch-schema

# Pass an auth token explicitly
npm run fetch-schema -- --token <JWT>

# Supply token via environment variable
GRAPHQL_TOKEN=<JWT> npm run fetch-schema

# Override the GraphQL endpoint
npm run fetch-schema -- --endpoint http://localhost:4000/api/graphql

# Override both endpoint and token
npm run fetch-schema -- --endpoint http://localhost:4000/api/graphql --token <JWT>
```

On success, the script writes `schema.graphql` to the project root and logs the output path. On failure (e.g., network error, non-2xx response, or GraphQL errors), it logs the error and exits with status code `1`.
