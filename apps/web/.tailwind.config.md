# tailwind.config.ts

Tailwind CSS configuration for the application, built on top of the shared `@flamingo-stack/openframe-frontend-core` design-system preset. It wires up content scanning and route-level style isolation rather than defining a standalone theme.

## Key Components

- **`config: Config`** — Tailwind configuration object combining:
  - `content`: computed via `appStyleSources({ root: __dirname, appDir: 'src/app' })`, which scans both the app's own routes and the design-system library's style sources so Tailwind only generates utility classes actually used.
  - `presets: [openframeCorePreset]`: inherits the full Open Design System (ODS) theme — colors, tokens, and plugins (including `tailwindcss-animate`) — from the core library. The app intentionally omits its own `safelist`, since that would override the preset's.
- **`withRouteStylesTailwind(config)`** — Wraps the final config to support `next-styles build`, a build mode where the root stylesheet contains no utilities and each page/route brings its own scoped styles.

## Usage Example

This file is consumed automatically by the Tailwind CLI/PostCSS pipeline — no manual invocation needed:

```typescript
// tailwind.config.ts is picked up automatically by Tailwind/Next.js build tooling
// No direct imports required in application code; utility classes are simply
// used in components as usual:

export function Button() {
  return (
    <button className="bg-primary text-white rounded-md px-4 py-2">
      Click me
    </button>
  );
}
```

To extend the theme locally, add a new preset entry or merge additional Tailwind options into the `config` object before passing it to `withRouteStylesTailwind`.
