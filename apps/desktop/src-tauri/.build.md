Build script for the Tauri desktop application that configures cargo rebuild triggers and declares the app's command manifest for Tauri's access control layer.

## Key Components

- **`main()`** — Entry point executed by Cargo before compiling the crate. Performs two tasks:
  - Emits `cargo:rerun-if-env-changed` directives for `OPENFRAME_SHARED_HOST_URL` and `OPENFRAME_GTM_CONTAINER_ID`, ensuring the build is invalidated and these `option_env!`-baked values are refreshed whenever the environment variables change.
  - Calls `tauri_build::try_build` with an `AppManifest` declaring every IPC command exposed by the app (auth lifecycle, notifications, logging, updates, autostart, and agent installation). This manifest is what allows commands to be referenced in `capabilities/main.json`; omitting a command here causes it to be refused at runtime regardless of capability configuration.

## Usage Example

This file is not invoked directly — Cargo runs it automatically as part of the build process for any crate with a `build.rs` at its root and `build = "build.rs"` (or default) in `Cargo.toml`.

```rust
// Cargo.toml
[package]
build = "build.rs"

[build-dependencies]
tauri-build = { version = "2", features = [] }
```

To add a new Tauri command, register the `#[tauri::command]` function in the app, then add its name to the `commands(&[...])` list in `build.rs`:

```rust
tauri_build::AppManifest::new().commands(&[
    "native_auth_start",
    // ...
    "my_new_command", // must be listed here first
])
```

After adding it here, also grant access in the relevant file under `capabilities/`, such as `main.json` — see [`src-tauri/capabilities/`](https://github.com/flamingo-stack/openframe-oss-frontend/tree/main/src-tauri/capabilities) in the repository.
