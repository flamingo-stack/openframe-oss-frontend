# build.rs

Cargo build script for the Tauri desktop application. It configures cache invalidation for environment-dependent build variables and declares the Tauri app's command manifest, which governs which commands are eligible for inclusion under the capability-based ACL system.

## Key Components

- **`main()`** — Entry point executed by Cargo before compiling the crate. Performs two tasks:
  - Emits `cargo:rerun-if-env-changed` directives for `OPENFRAME_SHARED_HOST_URL` and `OPENFRAME_GTM_CONTAINER_ID`, ensuring the build is invalidated and recompiled when these env vars change (since their values are embedded via `option_env!` at compile time).
  - Calls `tauri_build::try_build` with an `AppManifest` listing every custom Tauri command exposed by the app (e.g., `native_auth_start`, `update_check`, `agent_install_start`). This manifest is required for commands to be referenced in `capabilities/main.json`; omitting a command here means it is rejected at runtime even if listed in a capability file.

## Usage Example

This file requires no direct invocation — Cargo runs it automatically during `cargo build` for the Tauri binary crate.

```rust
// To add a new Tauri command, define it in your command module:
#[tauri::command]
fn my_new_command() -> Result<(), String> {
    Ok(())
}

// Then register it in build.rs's commands list:
// tauri_build::AppManifest::new().commands(&[
//     ...,
//     "my_new_command",
// ])

// Finally, grant access in capabilities/main.json for the relevant window/page.
```

**Note:** Forgetting to add a command to `build.rs` results in a silent runtime refusal — the frontend's `invoke("my_new_command")` call fails even if the capability file grants permission, since the manifest here is the authoritative source of allowed commands.
