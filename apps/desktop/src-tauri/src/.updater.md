## Updater Module

Manages application self-update checks, downloads, and installation via the `tauri-plugin-updater`, with Tauri event emission for progress and error reporting to the frontend, plus tenant-aware manifest resolution and installed-agent reporting over NATS.

## Key Components

- **`UpdateManager`** — Holds an `apply_lock` (`Mutex<()>`) to serialize update application, preventing concurrent downloads/installs.
- **`UpdateAvailability`** — Serialized payload describing whether an update exists, its version, release notes, release notes URL, and whether applying it is `blocked` (e.g., read-only mount).
- **`UpdateError`** — Structured error with a `kind` (`"busy"`, `"gone"`, `"unavailable"`, `"location"`, `"network"`, `"signature"`, `"disk"`, `"permission"`, `"security"`, `"unknown"`) and a human-readable `message`, used so the frontend can branch on `kind` without parsing error text.
- **`Progress`** — Serialized download progress (`downloaded` bytes, optional `total`), throttled via `PROGRESS_EMIT_INTERVAL` to avoid flooding IPC.
- **`check_for_update(app)`** — Resolves the manifest URL (tenant-specific or config override) and queries the updater plugin for an available update.
- **`apply(app, manager, update)`** — Acquires the apply lock, checks for in-place update blockers (read-only mounts), downloads with throttled progress events, and installs.
- **`classify` / `classify_io`** — Map plugin and IO errors into the coarse `UpdateError` kind buckets described above.
- **`in_place_blocker()`** — Detects whether the running executable sits on a read-only mount (e.g., macOS DMG or translocated `.app`), which would make an in-place swap fail.
- **`resolve_manifest_url(cfg)`** — Builds the updater manifest URL from either an explicit config override or the tenant host plus `GATEWAY_MANIFEST_PATH`.
- Event constants (`EVENT_AVAILABLE`, `EVENT_PROGRESS`, `EVENT_INSTALLING`, `EVENT_ERROR`) — Names emitted to the main window for frontend consumption.

## Usage Example

```rust
use crate::updater::{UpdateManager, check_for_update, apply};

// Check for an update and report availability to the UI
let update = check_for_update(&app_handle).await?;
if let Some(update) = update {
    let availability = UpdateAvailability::from_update(&update);
    app_handle.emit("update:available", availability)?;

    // Later, when the user confirms:
    let manager = app_handle.state::<UpdateManager>();
    apply(&app_handle, &manager, update).await?;
}
```

Errors surfaced via `UpdateError` carry a `kind` the frontend can match on (e.g., show a "move the app" message for `"location"`, or a disabled retry for `"busy"`), rather than parsing raw plugin error strings.
