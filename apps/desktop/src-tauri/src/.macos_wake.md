# macos_wake.rs

Registers a macOS system wake observer that proactively triggers a token refresh the instant the machine wakes from sleep, rather than waiting for whichever internal timer happens to fire first after resume.

## Key Components

- **`DID_WAKE`** — Constant string `"NSWorkspaceDidWakeNotification"`, referenced by name rather than through a generated binding to minimize the AppKit surface this file depends on.
- **`observe(app: AppHandle)`** — Registers a block-based observer on `NSWorkspace`'s notification center (not the default `NSNotificationCenter`, which never receives this event) that:
  1. Calls `crate::tokens::mark_resume(&app)` to flag that the machine just resumed.
  2. Calls `crate::tokens::refresh_soon(&app, "system woke")` to immediately kick off a token refresh.
  3. Leaks the observer token via `std::mem::forget` so the registration lives for the lifetime of the process.

## Usage Example

```rust
// During app setup (e.g., in a Tauri `setup` hook), register the wake observer
// so token refresh is triggered immediately on system wake:

fn setup(app: &tauri::App) -> Result<(), Box<dyn std::error::Error>> {
    let handle = app.handle().clone();

    #[cfg(target_os = "macos")]
    macos_wake::observe(handle);

    Ok(())
}
```

**Design notes:**
- This fires only on *full* wakes (`NSWorkspaceDidWakeNotification`), never on maintenance `DarkWake`, and is macOS-only — it has no effect on Windows.
- It complements, rather than duplicates, `tokens::spawn_wake_watch`: the watcher independently detects resume via clock comparison and gates rotations until the system has settled, while this observer provides an immediate nudge so the webview doesn't hit a stampede of overdue timers (and a resulting 401) before Wi-Fi reassociates.
- `mark_resume` is called *before* `refresh_soon` so the resume state is recorded ahead of the wake watcher's next tick, preventing a redundant rotation at resume+0.
