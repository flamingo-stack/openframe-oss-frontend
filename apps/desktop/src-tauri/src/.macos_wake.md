# macos_wake.rs

Registers a macOS system-wake observer that proactively triggers a token refresh the instant the machine wakes from sleep, rather than waiting for whichever internal timer happens to fire first after a long sleep.

## Key Components

- **`DID_WAKE`** — Constant string `"NSWorkspaceDidWakeNotification"`, referenced by name rather than via a generated AppKit binding to minimize dependencies.
- **`observe(app: AppHandle)`** — Registers a block-based observer on `NSWorkspace`'s notification center (not the default `NSNotificationCenter`) that fires on full system wake. On notification, it:
  1. Calls `crate::tokens::mark_resume(&app)` first, to prime the separate wake-watch gate before any rotation can happen.
  2. Calls `crate::tokens::refresh_soon(&app, "system woke")` to proactively nudge a token refresh.

The observer token returned by `addObserverForName_object_queue_usingBlock` is intentionally leaked via `std::mem::forget` so the registration persists for the lifetime of the process.

## Design Notes

This function is a **nudge**, not a correctness guard. It only fires on full wakes (never on macOS's maintenance `DarkWake`, and never on Windows at all). The actual safety mechanism — gating token rotation until the system has settled — lives in `tokens::spawn_wake_watch`, which detects resume independently using its own clock comparison. Driving the nudge from the wake-watch instead would cause it to fire on every `DarkWake` cycle and waste the refresh rate limit on rotations the gate would reject anyway.

## Usage Example

```rust
// Called once during app setup, typically from the Tauri setup hook
fn setup(app: &AppHandle) {
    macos_wake::observe(app.clone());
}
```

Once registered, no further interaction is required — the observer lives for the duration of the process and triggers `tokens::refresh_soon` automatically on each system wake event.
