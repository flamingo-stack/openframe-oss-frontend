## notifications.rs

Background notification plane for the Tauri shell that subscribes to `user.<userId>.notification` on the shell's own NATS connection and dispatches OS notifications plus badge updates while the app window is hidden in the tray. It coordinates platform-specific click delivery (macOS `UNUserNotificationCenter`, Windows toast activation via custom URI scheme) and routes click payloads to the webview through a stash-until-ready mechanism that protects against cold-start race conditions.

## Key Components

- **`NotificationsPlane`** — Managed Tauri state holding the active NATS subscription slot, unread counter, and a stash for click payloads delivered before the webview's listener mounts.
- **`Delivery` enum** — Distinguishes `New` notifications from `Update`s that supersede an earlier push, so updates don't double-count unread badges or re-interrupt the user.
- **`init(app)`** — Registers plane state and initializes the platform click/action backend (`macos_un` or `windows_activator`); must run before `crate::nats::spawn`.
- **`ensure_subscription(app, client)`** — Called on every NATS Connected event; subscribes to the signed-in user's notification subject, replacing the router only if the user changed, and drops it entirely when no session exists.
- **`notification_router`** — Async task consuming the NATS subscriber stream, parsing JSON envelopes, and dispatching them to `maybe_notify`.
- **`maybe_notify(app, envelope, user_id)`** — Core dispatch logic: records action resolutions, extracts title/body/click payload, applies the "window visible" suppression gate (with a silent-update exception on Windows), updates the unread badge, and posts the OS notification via the platform backend.
- **`CLICK_EVENT`** — Frontend-facing event name (`notification:click`) consumed by `onNativeNotificationClick` in `native-shell.ts`.
- **`BODY_CHARS`** — Truncation limit (140 chars) applied only to text the shell didn't author itself.
- **`CLICK_URI_PREFIX`** — Windows-only URI prefix (`openframe-console://notify`) used to distinguish notification activation from OAuth callbacks.

## Usage Example

```rust
// During app setup, before NATS connects:
notifications::init(&app_handle);

// On each NATS Connected event (handled internally by crate::nats):
notifications::ensure_subscription(&app_handle, nats_client).await;

// Frontend side (native-shell.ts) listens for delivered clicks:
// listen(CLICK_EVENT, payload => resolveRoute(payload.click_payload))
```

Consumers typically don't call `maybe_notify` or the router directly — they're wired internally once `ensure_subscription` establishes the NATS listener. Integrators only need to call `init` during app bootstrap and ensure `ensure_subscription` is invoked from the NATS connection lifecycle handler.
