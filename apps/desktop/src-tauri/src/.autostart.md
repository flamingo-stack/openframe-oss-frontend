## autostart.rs

Implements per-user "start at login" registration for the desktop app, hand-rolled rather than using `tauri-plugin-autostart` due to platform-specific correctness bugs in that crate (unquoted Windows exe paths with spaces, missing macOS bundle attribution). Handles Windows Registry Run keys, macOS launchd agents, and Linux XDG autostart entries, while respecting OS-level user overrides instead of fighting them.

## Key Components

- **`FLAG`** — The `--autostart` argv flag that lets the process distinguish an OS-initiated login launch from a user-initiated one, so it knows to stay headless in the tray.
- **`LEGACY_IDENTIFIER`** *(macOS/Linux)* — Pre-rename bundle identifier (`com.openframe.desktop`) used to detect and clean up stale autostart registrations.
- **`remove_legacy_registration`** — Deletes any autostart entry left behind by a pre-rename build, on all platforms.
- **`launched_at_login`** / **`has_flag`** — Detect whether the current (or a forwarded second-instance) launch carries `FLAG`.
- **`set_headless` / `is_headless`** — Thread-safe (`AtomicBool`) flag recording whether this process run will skip building a window entirely.
- **`Status`** — Serializable struct reporting whether autostart is `enabled` and whether it is `enforced` (managed/pinned by policy), consumed by the UI toggle.
- **`AutostartError`** — Serializable error type with `enforced`, `unavailable`, and `io` variants for reporting registration failures back to the frontend.
- **`windows_run_command`** / **`win32_path`** *(Windows)* — Build a correctly quoted Run-key command string, converting Tauri's verbatim (`\\?\`) paths into shell-parseable Win32 form.
- **`macos_plist`** / **`escape_xml`** *(macOS)* — Generate a launchd agent plist with `AssociatedBundleIdentifiers` for proper Login Items attribution, with strict XML-safe escaping (rejecting unrepresentable control characters).
- **`linux_desktop_entry`** *(Linux)* — Generate an XDG `.desktop` autostart entry without forcing an `enabled` key, to avoid colliding with user-set `Hidden`/disable state.

## Usage Example

```rust
// Check whether this process instance was started by the OS at login
if autostart::launched_at_login() {
    autostart::set_headless(true);
}

// Later, before building the main window:
if !autostart::is_headless() {
    show_primary_window(&app);
}

// Clean up any pre-rename autostart leftovers on startup
remove_legacy_registration(&app_handle);
```

Platform backends (`windows_run_command`, `macos_plist`, `linux_desktop_entry`) are pure string builders consumed by a separate `backend` module that performs the actual registry/file-system writes and reconciliation against user overrides (see `status` and `decide`, referenced but defined elsewhere in this module).
