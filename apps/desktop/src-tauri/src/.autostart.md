## Overview

This module implements **start-at-login** (autostart) functionality for the OpenFrame Console desktop app, hand-written per-platform rather than via `tauri-plugin-autostart` due to bugs in that crate's Windows (unquoted path) and macOS (missing bundle attribution) backends. It handles registration, flag-based detection of login-triggered launches, legacy cleanup, and reporting of OS-level user overrides.

## Key Components

- **`FLAG`** — the `--autostart` argument the registered launch command carries, distinguishing OS-triggered starts from user-initiated ones.
- **`launched_at_login()`** / **`has_flag()`** — detect whether the current (or a forwarded) process launch came from the login registration.
- **`HEADLESS`** / **`set_headless()`** / **`is_headless()`** — atomic flag recording whether this process will stay in the tray without building a window.
- **`Status`** — serializable struct reporting whether autostart is `enabled` and/or `enforced` (managed install).
- **`AutostartError`** — serializable error with `kind` (`enforced`, `unavailable`, `io`) and `message`, mirroring the updater's error shape.
- **`remove_legacy_registration()`** — cleans up login entries left by the pre-rename (`com.openframe.desktop`) build.
- **Platform payload builders** (compiled on all targets for test coverage):
  - `windows_run_command()` / `win32_path()` — builds a quoted Run-key command string, converting verbatim `\\?\` paths to shell-parseable form.
  - `macos_plist()` / `escape_xml()` — builds a launchd user agent plist with `AssociatedBundleIdentifiers` for proper attribution.
  - `linux_desktop_entry()` — builds an XDG autostart `.desktop` file.

## Usage Example

```rust
// Check if the process was launched by the OS at login
if autostart::launched_at_login() {
    autostart::set_headless(true);
    // ...stay in tray instead of opening a window
}

// Later, query status for the UI toggle
let status = autostart::status(&app_handle);
if status.enforced {
    // disable the toggle in the UI
}
```

Note: the user's own OS-level disable (e.g. Windows `StartupApproved\Run`, or a GNOME/XDG `Hidden` entry) is deliberately left untouched by reconciliation — only an explicit user request clears it, never automatic sync.
