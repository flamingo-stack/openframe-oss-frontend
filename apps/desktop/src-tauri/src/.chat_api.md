This Rust module implements authenticated, webview-free calls to the tenant chat-service GraphQL API, used by the desktop shell to act on notification actions (approving/rejecting AI tool requests, replying to Mingo messages) without opening a window. It mirrors the frontend's `ticketService` mutations but runs in bearer-token mode against the tenant host learned at login.

## Key Components

- **`Session`** — Represents a live signed-in session (access token + user ID).
- **`active_session(app)`** — Resolves the current usable session from stored tokens, returning `None` if nobody is signed in, the token is expired, or no refresh succeeded.
- **`ApprovalOutcome`** — Enum distinguishing `Resolved` from `AlreadyResolved` (the latter is not a failure).
- **`resolve_approval(app, session, request_id, approve)`** — Resolves a Mingo tool-approval request via GraphQL mutation; treats `ILLEGAL_STATE` as already-resolved rather than an error.
- **`send_message(app, session, dialog_id, content)`** — Sends a message to a Mingo admin AI chat dialog.
- **`CommandError`** — Internal error type carrying a user-facing `reason` and optional gateway `code`.
- **`mutate(...)`** — Core HTTP/GraphQL executor: builds the request, handles timeouts, 401/403 responses, and parses the GraphQL body.
- **`command_outcome`, `error_message`, `message_of`** — Helpers for parsing GraphQL/HTTP error bodies into user-facing messages, with truncation for notification display.

## Usage Example

```rust
use tauri::AppHandle;

async fn handle_approval_click(app: &AppHandle, request_id: &str, approve: bool) {
    let Some(session) = chat_api::active_session(app).await else {
        log::warn!("no active session; cannot resolve approval");
        return;
    };

    match chat_api::resolve_approval(app, &session, request_id, approve).await {
        Ok(chat_api::ApprovalOutcome::Resolved) => {
            log::info!("approval resolved");
        }
        Ok(chat_api::ApprovalOutcome::AlreadyResolved) => {
            log::info!("approval was already handled elsewhere");
        }
        Err(reason) => {
            // Surface `reason` in a follow-up notification to the user.
            log::warn!("approval failed: {reason}");
        }
    }
}
```

Unit tests validate error-message extraction and `userErrors` parsing against sample GraphQL response bodies.
