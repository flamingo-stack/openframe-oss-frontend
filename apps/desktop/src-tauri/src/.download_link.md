# download_link.rs

Handles the `openframe-console://download?id=<uuid>` deep link used by the desktop app's "Open the app" flow. This link carries a download attribution id (recorded by the gateway when a visitor downloads the installer) so the app can later associate a new signup with that download source — something no browser cookie can do across the website-to-app boundary.

## Key Components

- **`DownloadLinkState`** — Tauri-managed state holding the latest pending download id (`Mutex<Option<String>>`) until the frontend consumes it.
- **`is_download_link(url)`** — Checks whether a URL uses the app's custom scheme (`crate::URI_SCHEME`) with host `download` (case-insensitive).
- **`download_id_of(url)`** — Extracts the `id` query parameter and validates it as a UUID, normalizing it to lowercase hyphenated form (matching the gateway's stored format). Returns `None` if absent or invalid.
- **`handle_url(app, url)`** *(macOS/Windows only)* — Entry point called when the OS delivers a URL on the app's scheme. If it's a download link, stores the id in `DownloadLinkState` and emits `download-link:received` to the main window so the frontend can pick it up if already running. Returns `true` for any download link (valid id or not), signaling the caller to bring the app window to front.
- **`take_pending_download_id`** *(Tauri command)* — Frontend-invoked command that takes (removes) the pending id, called on page load or in response to the `download-link:received` event.

## Usage Example

```rust
// Registering state and command in the Tauri app builder
use tauri::Manager;

tauri::Builder::default()
    .manage(DownloadLinkState::default())
    .invoke_handler(tauri::generate_handler![take_pending_download_id])
    .setup(|app| {
        // On startup, if the OS launched the app via a deep link:
        let url = "openframe-console://download?id=0f8fad5b-d9cb-469f-a165-70867728950e";
        if handle_url(app.handle(), url) {
            // bring window to front
        }
        Ok(())
    });
```

The frontend's `native-shell.ts` listens for `download-link:received` and calls `take_pending_download_id` to retrieve the id, storing it in `localStorage` until signup completes.
