This module manages the NATS-over-WebSocket connection lifecycle that backs the shell's background notification plane, handling token-bearer authentication, reconnect backoff, and tenant-switch teardown/redial. It is a Rust port of `openframe-chat`'s `nats_bridge/connection.rs`, adapted for the OpenFrame shell's Tauri runtime.

## Key Components

- **`Connector`** — Shared state struct holding the live `Client`, dial/session guards (`dialing`, `session` mutex), a `generation` counter to detect superseded connections, and `auth_failures` tracking for backoff on repeated auth rejections.
- **`spawn(app: AppHandle)`** — Entry point that constructs the `Connector`, registers it with Tauri's state manager, and starts the background `run` loop.
- **`resubscribe(app: &AppHandle)`** — Re-applies the current user's notification subscription on the existing connection, used when the signed-in user changes without a network reconnect.
- **`reconnect(app: &AppHandle)`** — Tears down the current connection (bumping `generation`, dropping subscriptions) and triggers a fresh dial when the tenant changes.
- **`run(connector: Arc<Connector>)`** — The core dial loop: waits for credentials (server URL + bearer token), builds the connect URL, configures `async_nats::ConnectOptions` with retry/backoff/event callbacks, and connects. Delegates reconnects to async-nats via `auth_url_callback`, which calls back into the shell for fresh tokens.
- **`credentials(app)` / `read_server_url(app)` / `read_token(app)`** — Helpers resolving the tenant gateway URL and access token, triggering background token refresh without blocking the reconnect loop.
- **Constants** — Tuning knobs like `FAST_RETRIES`, `BASE_DELAY_MS`, `MAX_DELAY_MS`, `GONE_DELAY_MS` (tenant-deleted backoff), and `SUPERSEDED_DELAY` (parks a stale connector forever).

## Usage Example

```rust
// During app setup, after notifications::init:
nats::spawn(app_handle.clone());

// When the signed-in user changes on the same tenant:
nats::resubscribe(&app_handle);

// When the active tenant changes:
nats::reconnect(&app_handle);
```

Consumers should call `spawn` exactly once during startup; subsequent tenant or user changes are handled via `reconnect` and `resubscribe` respectively, both of which safely no-op if the connector hasn't been initialized yet.
