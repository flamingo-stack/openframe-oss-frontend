## nats.rs

Manages the lifecycle of a NATS-over-WebSocket connection used by the shell's background notification plane. The gateway's WS endpoint embeds the bearer token in the connect URL, so this module coordinates connection dialing, automatic token refresh on reconnect, and resubscription when the signed-in tenant/user changes. It is a port of `openframe-chat`'s `nats_bridge/connection.rs`.

## Key Components

- **`Connector`** — Core state holder: holds the live `Client`, tracks consecutive auth failures, a dialing guard, a session mutex to serialize `resubscribe` against `reconnect`, and a generation counter to detect superseded connections.
- **`spawn(app: AppHandle)`** — Entry point; creates and manages a `Connector`, then spawns the connect/reconnect loop. Call once after `notifications::init`.
- **`resubscribe(app: &AppHandle)`** — Re-subscribes the current user's notification subject on the existing connection, without redialing (e.g. sign-out/sign-in on same tenant).
- **`reconnect(app: &AppHandle)`** — Tears down the current connection and redials, used when the tenant changes (the old connection is pointed at the wrong gateway/bearer).
- **`run(connector: Arc<Connector>)`** — Internal loop: waits for credentials (server URL + bearer token), builds the connect URL, configures `async_nats::ConnectOptions` with retry/backoff/event/auth callbacks, and establishes the connection.
- **`read_server_url` / `read_token` / `credentials`** — Async helpers that resolve the tenant gateway URL and bearer token, kicking off background token refresh without blocking the reconnect path.
- **Constants** — Tuning knobs for retry/backoff behavior (`FAST_RETRIES`, `BASE_DELAY_MS`, `MAX_DELAY_MS`, `GONE_DELAY_MS`, `PING_INTERVAL`, etc.), plus compile-time assertions ensuring retry/backoff invariants hold.

## Usage Example

```rust
// During app setup, after notifications::init:
nats::spawn(app_handle.clone());

// When the tenant changes (e.g. user switches orgs):
nats::reconnect(&app_handle);

// When the signed-in user changes but the connection stays up:
nats::resubscribe(&app_handle);
```

This module is intended to be used internally by the Tauri shell's startup sequence and auth/tenant-change handlers; it is not a public API for external consumers.
