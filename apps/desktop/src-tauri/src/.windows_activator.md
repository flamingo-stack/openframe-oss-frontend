## windows_activator.rs

Implements the Windows COM activator that routes toast notification button presses back into the application. Since `activationType="background"` buttons bypass normal protocol activation (which only carries body clicks), Windows must resolve them to a registered CLSID, which this module implements via `INotificationActivationCallback`. Registration is HKCU-only and rewritten on every launch so the CLSID always points at the current executable, mirroring `crate::register_url_scheme`.

## Key Components

- **`ACTIVATOR_CLSID`** — Fixed GUID identifying this build's activator; must stay stable across releases or existing toasts in the Action Center lose their buttons.
- **`TOAST_ACTIVATED_ARG`** — CLI flag (`-ToastActivated`) appended to the registered launch command, distinguishing COM-triggered launches from user launches.
- **`is_activation_launch(argv)`** — Checks whether the process was started to serve a button press, so setup can skip opening a window.
- **`init(app)`** — Entry point called during Tauri setup; stores the `AppHandle` router, writes registry keys, and starts the COM server thread.
- **`register(app)`** — Writes `LocalServer32` and `AppUserModelId\CustomActivator` registry keys (plus `DisplayName`/`IconUri`) under HKCU.
- **`serve()`** — Spawns a dedicated MTA thread that registers the class factory with COM (`CoRegisterClassObject`) and parks forever to keep the apartment alive.
- **`Activator`** — Implements `INotificationActivationCallback::Activate`, decoding invoked args and user input data, then dispatching to `handle_activation`.
- **`ActivatorFactory`** — Implements `IClassFactory` to produce `Activator` instances for COM.
- **`handle_activation` / `open_window`** — Routes parsed toast actions to `notification_actions::spawn`, falling back to opening the main window on unknown actions.

## Usage Example

```rust
// Called once during Tauri app setup (only on the surviving single-instance):
use crate::windows_activator;

fn setup(app: &tauri::AppHandle) {
    windows_activator::init(app);
}

// In the single-instance / launch-args handler:
fn on_launch(argv: &[String]) {
    if windows_activator::is_activation_launch(argv) {
        // Launched by COM to serve a toast button press — don't open a window.
        return;
    }
    // Normal user launch: proceed as usual.
}
```

Toast buttons are declared with `activationType="background"` in `windows_toast`; when pressed, Windows resolves the registered CLSID and invokes `Activator::Activate`, which decodes the action and forwards it to `notification_actions::spawn` on Tauri's async runtime.
