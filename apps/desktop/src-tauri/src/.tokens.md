## tokens.rs

Owns the shell-side OAuth token lifecycle for the Tauri desktop app: persisting tokens to disk, scheduling proactive refresh based on token lifetime, performing the refresh against the gateway BFF, and detecting the "tenant gone" (HTTP 410) condition that permanently stops refresh activity.

This module exists to keep a single authoritative refresher in the native shell rather than the webview, because refresh tokens rotate on use — if both the webview and the shell tried to refresh independently, they would race and invalidate each other's tokens. Shells exposing a `refreshTokens` API let the frontend's token-refresh-manager delegate here instead of calling `/oauth/refresh` directly.

## Key Components

- **`TOKEN_UPDATE_EVENT`** — Tauri event name (`native-auth:token-update`) emitted to all bundle windows whenever tokens change (rotation or session death), carrying a `PageTokens` payload.
- **Refresh timing constants** (`REFRESH_MARGIN_SECS`, `MIN_REFRESH_INTERVAL_SECS`, `SHORT_TOKEN_LEAD_SECS`, `MAX_TOKEN_LIFETIME_SECS`, `CLOCK_SLACK_SECS`) — govern when a refresh is scheduled relative to a token's lifetime, balancing the risk of letting the access token die versus rotating the refresh token too often.
- **Polling and retry constants** (`POLL_INTERVAL`, `REFRESH_RETRY_DELAYS`, `MAX_POLL_BACKOFF`, `REFRESH_WALL_CLOCK_BUDGET`, `REVOKE_BUDGET`, `REFRESH_CONNECT_TIMEOUT`) — drive the background freshness-check loop and bound how long a single refresh/revoke attempt may run, using wall-clock deadlines (not just monotonic timeouts) since sleep stops monotonic clocks.
- **Sleep/wake handling constants** (`WAKE_SETTLE_SECS`, `LONGEST_DARKWAKE_SECS`, `SETTLE_WAIT_BUDGET_SECS`, `WAKE_TICK`, `SLEEP_DETECT_SECS`) — implement a "wake gate" that withholds token rotation until the machine has been continuously awake long enough to avoid losing a rotation response inside a short maintenance DarkWake cycle.
- **Lost-rotation recovery constants** (`LOST_ROTATION_RETRY_AFTER_SECS`, `LOST_ROTATION_RETRY_WITHIN_SECS`, `LOST_ROTATION_RETRY_TRIGGER`, `REFRESH_GRACE_SECS`, `GATEWAY_AUTH_WAIT_SECS`) — control re-presenting a refresh token after a POST whose outcome is unknown, timed to land after the original request has surely been served but before the grace period on the old token expires.
- **Tenant-gone handling** (`TENANT_GONE`, `GONE_PROBE_BACKOFF_INITIAL_SECS`, `GONE_PROBE_BACKOFF_MAX_SECS`, `GONE_WATCH_TICK`, `DIALS_BEFORE_PROBE`, `DIAL_PROBE_MIN_GAP_SECS`) — detect and back off probing when the gateway reports the tenant deleted (410), aligned with the device agent's own probe schedule.
- **Compile-time invariants** (`const _: () = { assert!(...) }` blocks) — enforce that timing constants remain correctly ordered relative to one another (e.g., settle window must exceed the longest observed DarkWake, retry windows must fall strictly between the gateway's auth wait and the refresh grace period).

## Usage Example

```rust
// Conceptual usage within the Tauri app setup — this module wires into
// the app's token refresh scheduler, typically invoked once at startup.
use tauri::AppHandle;

fn setup_token_lifecycle(app: &AppHandle) {
    // Loads persisted tokens, computes next refresh time from the
    // access token's lifetime, and spawns the background poll loop
    // (POLL_INTERVAL-driven) that performs refresh via the gateway BFF
    // when due, respecting the wake-settle gate and retry/backoff rules.
    crate::tokens::init_token_refresh(app.clone());
}
```

Consumers typically don't call the constants directly; instead, the module exposes initialization and refresh-trigger functions (invoked from Tauri commands like `refreshTokens`) that internally apply this scheduling, retry, and wake-detection logic before contacting the gateway.
