## tokens.rs

Owns the full lifecycle of OAuth tokens in the Tauri shell: persisted custody (`tokens.json`), scheduled freshness checks based on each token's own lifetime, refresh calls against the gateway BFF, and handling of the "tenant gone" terminal state. Refresh is centralized in the shell (rather than the webview) because refresh tokens rotate on use — a webview refresher racing a shell refresher would invalidate each other's tokens. When a shell exposes `refreshTokens`, the frontend's token-refresh-manager delegates to this module instead of calling `/oauth/refresh` directly.

The module is heavily tuned around real-world sleep/wake pathologies on macOS (App Nap, timer coalescing, maintenance DarkWake) that can cause a refresh POST to go out in a doomed window, or a background poll loop to starve for over an hour of wall-clock time. Constants encode these tradeoffs explicitly, with assertions validating the relationships between timing bounds (settle windows, grace periods, gateway timeouts) at compile time.

## Key Components

- **`TOKEN_UPDATE_EVENT`** — event name emitted to bundle windows when stored tokens change (rotation or session death); payload is `PageTokens`.
- **Timing constants** — `REFRESH_MARGIN_SECS`, `MIN_REFRESH_INTERVAL_SECS`, `MAX_TOKEN_LIFETIME_SECS`, `POLL_INTERVAL`, `REFRESH_RETRY_DELAYS`, `WAKE_SETTLE_SECS`, `REFRESH_GRACE_SECS`, `GATEWAY_AUTH_WAIT_SECS`, etc. — govern refresh scheduling, retry budgets, and sleep/wake detection.
- **Compile-time invariants** — `const _: () = { assert!(...) }` blocks enforcing that timing constants are mutually consistent (e.g., settle window must exceed the longest observed DarkWake; retry windows must fit inside the server's refresh grace period).
- **Failure reason strings** — `UNSETTLED`, `TENANT_GONE` — standardized diagnostic text used across settle/gone gates.
- **Gone-tenant probe backoff** — `GONE_PROBE_BACKOFF_INITIAL_SECS`, `GONE_PROBE_BACKOFF_MAX_SECS`, `DIALS_BEFORE_PROBE` — coordinate with the device agent's NATS reconnect schedule to detect deleted tenants without hammering the gateway.
- Depends on `crate::{load_config, tenant_host, AppConfig, MAIN_LABEL}` for configuration and host resolution, and uses `tauri::{AppHandle, Emitter, Manager}` to broadcast token updates to windows.

## Usage Example

```rust
use tauri::AppHandle;

// Elsewhere in the shell, after startup, spin up the background
// freshness/refresh loop and the wake/gone watchers:
fn setup_token_lifecycle(app: &AppHandle) {
    // spawn_poll_loop, spawn_wake_watch, and spawn_gone_watch
    // (defined later in this module) wire into the app's event loop,
    // reading persisted tokens and emitting TOKEN_UPDATE_EVENT on change.
    let _ = app; // see module internals for actual spawn calls
}
```

Frontend code (via the bridge) listens for rotation:

```typescript
import { listen } from "@tauri-apps/api/event";

await listen("native-auth:token-update", (event) => {
  const tokens = event.payload; // PageTokens
  // apply refreshed/cleared tokens to in-page auth state
});
```
