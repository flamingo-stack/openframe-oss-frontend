Entry point binary for the Tauri desktop application, responsible for bootstrapping the app by delegating to the shared library crate's run function.

## Key Components

- **`main`** — The binary entry point; invokes `app_lib::run()` to start the Tauri application.
- **`windows_subsystem` attribute** — Conditional compiler directive (`#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`) that suppresses the console window on Windows for release builds while keeping it visible in debug builds for logging/diagnostics.

## Usage Example

This file is the standard Tauri desktop app entry point and is not meant to be imported or called directly. All actual application logic (window setup, plugins, commands, state management) lives in the `app_lib` crate.

```rust
// main.rs
#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]

fn main() {
    app_lib::run();
}
```

To build and run the desktop app:

```bash
# Development build (console window visible for debugging)
cargo tauri dev

# Release build (no console window on Windows)
cargo tauri build
```

**Important:** Do not remove the `windows_subsystem` attribute — it prevents an unwanted console window from appearing alongside the application on Windows in release mode. The actual implementation logic should be added to `app_lib`, keeping `main.rs` minimal and stable.
