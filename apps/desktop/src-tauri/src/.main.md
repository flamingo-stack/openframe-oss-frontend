Entry point binary for the Tauri desktop application, responsible for bootstrapping the app by delegating execution to the shared library crate.

## Key Components

- **`main()`** — The binary's entry function. Calls `app_lib::run()` to initialize and launch the Tauri application.
- **`windows_subsystem` attribute** — A conditional compiler directive (`#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`) that suppresses the console window on Windows for release builds, while keeping it visible during debug builds for logging/diagnostics.

## Usage Example

This file is the standard Tauri binary entry point and is not meant to be imported or called directly. It is built and executed as the desktop application binary:

```bash
# Run in development mode
cargo tauri dev

# Build a release binary
cargo tauri build
```

The actual application logic (window setup, plugins, commands, event handlers) lives in the `app_lib` crate's `run()` function, keeping `main.rs` minimal:

```rust
fn main() {
    app_lib::run();
}
```

**Note:** Do not remove the `windows_subsystem` attribute — it prevents an unwanted console window from appearing alongside the application on Windows in release builds, which is required for a polished desktop UX.
