# capacitor.config.ts

Capacitor configuration for the OpenFrame mobile app shell, defining how the native iOS/Android wrapper loads and interacts with the web-based frontend bundle.

## Key Components

- **`config` (default export)** — `CapacitorConfig` object controlling the native shell's behavior:
  - **`appId` / `appName`** — App identity (`ai.openframe.mobile` / `OpenFrame`).
  - **`webDir`** — Points to `www`, the git-ignored static web bundle produced by `npm run build:web` (or `npm run web:placeholder` for dev).
  - **`backgroundColor`** — Matches the ODS background token to avoid color flash during load.
  - **`ios.handleApplicationNotifications`** — Disabled so the native shell (not Capacitor) owns `UNUserNotificationCenter`, enabling native actions like Approve/Reject and inline reply.
  - **`plugins.FirebaseMessaging`** — Suppresses iOS foreground push banners to match Android/FCM behavior.
  - **`plugins.Keyboard`** — `resize: 'none'` keeps WebView sizing identical across platforms; keyboard height is instead published to CSS via a custom `--of-keyboard-inset` variable.
  - **`plugins.SplashScreen`** — Manual-hide splash screen, held until frontend init (including biometric unlock) completes.
  - **`cordova.preferences.DisableDeploy`** — Blocks persistent server base path overrides (mitigates a potential XSS persistence vector).
  - **`experimental.ios.spm`** — Symlinks the `@capacitor-firebase/messaging` SPM package to avoid a package-identity collision.
  - **Commented `server` block** — Optional LAN live-reload config for local development against `openframe-frontend`.

## Usage Example

```typescript
// Enable live-reload against a local frontend dev server during development:
import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  // ...existing config
  server: {
    url: 'http://192.168.1.50:3000',
    cleartext: true,
  },
};

export default config;
```

After editing, sync native projects:

```bash
npx cap sync ios
npx cap sync android
```

**Note:** Remove the `server` block before building a shippable, bundled release — it is intended for local development only.
