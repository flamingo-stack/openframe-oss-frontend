# capacitor.config.ts

Capacitor configuration file for the OpenFrame mobile shell app, defining native platform behavior, bundled web asset location, and plugin settings for iOS notification handling, keyboard behavior, and splash screen presentation.

## Key Components

- **`config`** (`CapacitorConfig`) — the default-exported configuration object containing:
  - `appId` / `appName` — app identity (`ai.openframe.mobile` / `OpenFrame`)
  - `webDir` — points to the `www` build artifact (generated by `npm run web:placeholder` or `npm run build:web`)
  - `backgroundColor` — matches the ODS design system background to avoid flash during load
  - `ios.handleApplicationNotifications` — disabled so the native shell (not Capacitor) owns `UNUserNotificationCenter` delegate handling
  - `plugins.FirebaseMessaging` — suppresses default foreground push banners on iOS to match Android behavior
  - `plugins.Keyboard` — `resize: 'none'` ensures the WebView never resizes; keyboard height is instead exposed via the `--of-keyboard-inset` CSS variable
  - `plugins.SplashScreen` — manual-hide splash screen configuration, kept visible until the frontend explicitly hides it post-token-hydration
  - `experimental.ios.spm` — SwiftPM symlink workaround for a Firebase iOS SDK package-identity collision
  - (commented) `server.url` — optional dev live-reload pointer to a local frontend dev server

## Usage Example

This file is consumed automatically by the Capacitor CLI; it is not imported directly by app code.

```bash
# After editing capacitor.config.ts, sync native projects
npx cap sync ios
npx cap sync android
```

```typescript
// To enable live-reload during development, uncomment in capacitor.config.ts:
server: {
  url: 'http://192.168.1.50:3000',
  cleartext: true,
},
```

Remember to remove the `server` block before producing a shippable build, since it points the WebView at a local dev server instead of the bundled `www` assets.
