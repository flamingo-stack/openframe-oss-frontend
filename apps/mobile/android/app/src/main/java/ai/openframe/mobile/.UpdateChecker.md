## UpdateChecker.java

Checks a shared gateway for app bundle updates (OTA — over-the-air updates), verifies downloaded release manifests and bundles cryptographically, and stages verified bundles for installation on next launch. This is Android-side logic for Capacitor-based mobile builds, using a compiled-in gateway host and compiled-in public keys so that update behavior cannot be hijacked by content served inside the web view.

## Key Components

- **`UpdateChecker`** — Main class orchestrating the update check/download/install flow.
- **`DownloadPermit`** (interface) — Callback asked whether a bundle download is allowed, given whether Data Saver currently restricts background data.
- **`NoUpdate`** (private exception) — Represents a benign "no update available" outcome, distinct from transport/verification failures, with a log-safe message.
- **`manifestUrl(String)`** — Static helper that builds the manifest endpoint URL from a compiled shared host, validating it is a bare HTTPS origin (no path/query/fragment/credentials).
- **`compiledKeys()`** — Decodes and loads the compiled-in OTA public keys (`OtaKeys`); returns an empty key map if keys are malformed, causing all manifests to be refused.
- **`disabledReason()`** — Returns a human-readable reason the update mechanism is disabled, or `null` if updates are enabled.
- **`run(String trigger, DownloadPermit permit)`** — Entry point: fetches and verifies the manifest, decides an action (`DROP`, `NOTHING`, `DOWNLOAD`) via `OtaSession`, and executes it.
- **`download(Manifest.Payload, DownloadPermit)`** — Handles bundle download, verification, unpacking, env injection, and installation into staging.
- **`fetchManifest()` / `fetchBundle(...)`** — Network fetch helpers using separate OkHttp clients (short timeout for manifest, long timeout for bundle), enforcing strict redirect and cookie policies.

## Usage Example

```java
// Typically invoked from an app lifecycle hook or scheduled background task
UpdateChecker checker = new UpdateChecker(
    context,
    updateStore,
    otaSession,
    hasBuiltinVersion,
    () -> envScriptBytesSupplier()
);

String disabledReason = checker.disabledReason();
if (disabledReason == null) {
    checker.run("app-foreground", dataSaverRestricts ->
        !dataSaverRestricts // only download when Data Saver is not restricting background data
    );
} else {
    log.notice("updates disabled: " + disabledReason);
}
```

**Notes:**
- The gateway host and signing keys are always compiled into the binary (`BuildConfig`) and never influenced by web content.
- Manifests are capped at 64 KiB and must be signed; bundles are verified by size and SHA-256 before being unpacked.
- Bundles already verified on disk are reused without re-downloading (`session.isUsable`).
- Content-verification failures mark a version as "bad" (`session.markBad`) to avoid retrying a doomed download.
