# OpenFrameMessagingService.java

Android FCM (Firebase Cloud Messaging) service that owns push notification delivery, extending the Capacitor Firebase plugin's `MessagingService` to preserve JS-side token/notification handling while adding custom native banner logic and retraction support.

This service is the sole handler registered for `MESSAGING_EVENT` in the manifest — the plugin's own manifest registration is removed, since Firebase binds only the first matching service and caches it for the process lifetime. It processes three categories of incoming pushes: data-only notifications (rendered as native banners), retraction events (used to dismiss stale notifications), and baseline SDK-rendered pushes (only forwarded while the app is foregrounded, since the SDK handles them natively otherwise).

## Key Components

- **`OpenFrameMessagingService`** — extends `MessagingService` (from `io.capawesome.capacitorjs.plugins.firebase.messaging`); the app's single FCM entry point.
- **`onMessageReceived(RemoteMessage)`** — overridden handler that:
  - Calls `super.onMessageReceived()` to preserve JS-side plugin behavior (`onNewToken`, `notificationReceived`, cold-start replay).
  - Always processes retraction data via `PushNotifications.retract(...)`.
  - Skips further processing for retraction events (`PushNotifications.EVENT_RETRACTED`).
  - Skips baseline notification-block pushes lacking `KEY_TITLE` (already handled by the SDK/web view).
  - Suppresses the native banner when the app is in the foreground (checked via `TokenLifecycle.get(this).isForeground()`), logging via `ShellLog.notifications`.
  - Otherwise, displays the notification through `PushNotifications.show(...)`.
- **`@SuppressLint("MissingFirebaseInstanceTokenRefresh")`** — intentional, since `onNewToken` is inherited from the parent class, which forwards rotations to the JS plugin.

## Usage Example

This service is not invoked directly; it is wired via the Android manifest to receive FCM messages:

```java
// AndroidManifest.xml registration (conceptual, not Java code):
// <service android:name="ai.openframe.mobile.OpenFrameMessagingService"
//          android:exported="false">
//     <intent-filter>
//         <action android:name="com.google.firebase.MESSAGING_EVENT" />
//     </intent-filter>
// </service>

// Backend sends a data-only payload; the OS routes it here automatically:
Map<String, String> data = message.getData();
// data.get(PushNotifications.KEY_EVENT)      -> e.g. "retracted"
// data.get(PushNotifications.KEY_TITLE)      -> notification title, if present
// data.get(PushNotifications.KEY_NOTIFICATION_ID) -> unique id for tracking
```

See related classes: `PushNotifications`, `TokenLifecycle`, and `ShellLog` for downstream behavior.
