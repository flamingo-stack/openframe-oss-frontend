Defines the OTA (over-the-air) update decision logic that determines whether an incoming update payload should be downloaded, ignored, or dropped, based on version comparison and bridge-level compatibility rules described in `docs/ota.md`.

## Key Components

- **`Decision`** (enum) — Represents the possible outcomes of the OTA evaluation:
  - `DOWNLOAD` — the payload is newer and eligible to be downloaded.
  - `NOTHING` — the payload is already known (active, pending, or previously marked bad) or incompatible with the current bridge level.
  - `DROP` — the payload version is not newer than the builtin version and should be discarded.

- **`decide(String builtinVersion, int bridgeLevel, OtaState state, String payloadVersion, int payloadBridgeLevel)`** (static method) — Evaluates the update payload against the current device state and returns a `Decision`:
  1. If `payloadVersion` is not strictly greater than `builtinVersion`, returns `DROP`.
  2. If `payloadVersion` matches the state's `active`, `pending`, or is in the `bad` set, returns `NOTHING` (already handled).
  3. If `payloadBridgeLevel` exceeds the current `bridgeLevel`, returns `NOTHING` (incompatible bridge level).
  4. Otherwise, returns `DOWNLOAD`.

## Usage Example

```java
OtaState state = new OtaState();
state.active = "1.2.0";
state.pending = null;
state.bad = Set.of("1.3.0-beta");

Decision result = Decision.decide(
    "1.2.0",      // builtinVersion
    5,            // bridgeLevel
    state,
    "1.4.0",      // payloadVersion
    5             // payloadBridgeLevel
);

switch (result) {
    case DOWNLOAD -> startDownload("1.4.0");
    case NOTHING -> System.out.println("No action needed");
    case DROP -> System.out.println("Payload discarded");
}
```

This logic ensures that devices only download genuinely new, compatible updates, avoid re-downloading already-known versions, and reject payloads that are outdated or incompatible with the current bridge level.
