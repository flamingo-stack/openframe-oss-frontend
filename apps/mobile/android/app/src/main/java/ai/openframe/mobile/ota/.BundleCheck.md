# BundleCheck.java

Incrementally validates a downloaded OTA bundle against the expected size and SHA-256 checksum declared in its manifest, failing fast as soon as the byte count is exceeded rather than waiting until the download completes.

## Key Components

- **`BundleCheck(long size, String sha256)`** — Constructor that captures the expected bundle size and SHA-256 hex digest from the manifest.
- **`update(byte[] bytes, int offset, int length)`** — Feeds a chunk of downloaded bytes into the running digest and byte counter; throws `OtaError` with code `SIZE` immediately if the received byte count exceeds the manifest's declared size, stopping the download at the first byte too many.
- **`finish()`** — Called after the download completes to perform final verification: throws `OtaError` with code `SIZE` if the total received bytes don't exactly match the expected size, or code `SHA256` if the computed digest doesn't match the manifest's checksum.

## Usage Example

```java
BundleCheck check = new BundleCheck(manifest.size(), manifest.sha256());

try (InputStream in = downloadStream()) {
    byte[] buffer = new byte[8192];
    int n;
    while ((n = in.read(buffer)) != -1) {
        check.update(buffer, 0, n); // throws early if too many bytes arrive
    }
    check.finish(); // throws if size or SHA-256 don't match
} catch (OtaError e) {
    // handle size/checksum mismatch
}
```

This class is designed to be used alongside `BundleReader.readVerified`, which performs the same length and SHA-256 checks on the downloaded file before any decoding occurs, ensuring corrupted or tampered bundles are rejected as early as possible.
