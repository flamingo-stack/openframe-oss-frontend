Defines the exception type used throughout the mobile OTA (over-the-air update) pipeline to represent verification and extraction failures with a standardized error code, matching the shared test case codes expected by `apps/mobile/ota/fixtures`.

## Key Components

- **`OtaError`** — checked exception extending `Exception`, carrying a classification `Code` and a shell-specific log message.
- **`Code` (enum)** — the set of distinct failure categories an OTA bundle can produce, covering envelope parsing, signature verification, payload decoding (XZ/TAR), entry validation, and index/metadata checks (e.g. `ENVELOPE`, `UNKNOWN_KEY`, `SIGNATURE`, `PAYLOAD`, `SIZE`, `SHA256`, `XZ`, `TAR`, `ENTRY_TYPE`, `ENTRY_NAME`, `DUPLICATE`, `NO_INDEX`, `NO_ENV`, `HAS_ENV`, `NO_HEAD`).
- **`code`** — public final field exposing the classified error code for callers to branch on.
- **`isContentRefusal()`** — determines whether the failure stems from the bundle's content itself (meaning the specific version should be marked permanently bad) versus a transient download issue (size/SHA-256 mismatch), which should simply be retried.

## Usage Example

```java
try {
    verifyAndApplyOtaBundle(bundlePath);
} catch (OtaError e) {
    if (e.isContentRefusal()) {
        // Bundle content is invalid for this version; mark the version as bad
        markVersionBad(currentVersion, e.code);
    } else {
        // Likely a corrupted/incomplete download; retry
        scheduleRetryDownload();
    }
    log.warn("OTA failed: code=" + e.code, e);
}
```

This exception is typically thrown by lower-level OTA verification steps (signature checking, archive extraction, manifest parsing) and caught by the update orchestrator to decide whether to retry the download or reject the firmware version outright.
