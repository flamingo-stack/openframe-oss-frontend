# NotificationActionReceiver.java

`BroadcastReceiver` that handles taps on push notification action buttons (e.g., Approve/Deny/Reply) delivered by `PushNotifications`. Since a `BroadcastReceiver` has only a few seconds to run and the actual response (which may involve a token refresh and network request) can take longer, this class validates the incoming intent, hands off the real work to `NotificationActionWorker` via `WorkManager` as expedited work, and swaps the notification's buttons for a progress spinner while the worker runs.

## Key Components

- **`onReceive(Context, Intent)`** — Entry point invoked when a notification action button is pressed. Validates the action belongs to this app, extracts notification extras, handles typed replies (via `RemoteInput`), enqueues a unique `WorkManager` job scoped to `notificationId + "|" + actionId`, and shows an in-progress state.
- **`INPUT_ACTION` / `INPUT_REPLY`** — Keys used to pass the pressed action and optional reply text into the `NotificationActionWorker`'s input `Data`.
- **`DATA_BUDGET_BYTES`** — Byte budget (9,000 of WorkManager's 10,240 cap) reserved for building the worker's `Data` payload, leaving headroom for serialization overhead.
- **`restore(...)`** — Rolls back to the original notification (with buttons restored) if the reply/data can't fit or enqueueing fails, preserving any typed reply text so it isn't lost.
- **`trimmed(...)`** — Strips oversized/irrelevant extras (retracted IDs, tool calls) and clips the notification body before forwarding to the worker.
- **`fitReply(...)` / `modifiedUtf8Length(...)`** — Computes how much of a typed reply fits within the remaining `Data` byte budget, accounting for modified UTF-8 encoding used internally by `Data`.

## Usage Example

This receiver is not invoked directly by app code — it's registered in the Android manifest and triggered by the system when a user taps a notification action:

```xml
<receiver android:name="ai.openframe.mobile.NotificationActionReceiver"
    android:exported="false" />
```

`PushNotifications` builds `PendingIntent`s targeting this receiver for each action button:

```java
Intent intent = new Intent(context, NotificationActionReceiver.class)
    .setAction(PushNotifications.ACTION_REPLY)
    .putExtra(PushNotifications.EXTRA_NOTIFICATION_ID, notificationId);
PendingIntent pendingIntent = PendingIntent.getBroadcast(
    context, requestCode, intent, PendingIntent.FLAG_MUTABLE);
```

When the user taps the button, Android delivers the broadcast, and `onReceive` takes over: validating the payload, queuing `NotificationActionWorker`, and updating the notification's UI to reflect in-progress or restored state.
