Singleton controller that manages Android-side over-the-air (OTA) bundle updates for the OpenFrame mobile app, mirroring the behavior of `ios/App/App/NativeUpdate.swift`. It decides which bundle a launch boots into, downloads and validates new bundles off the main thread, tracks trial/rollback state, and exposes status to the Capacitor bridge.

## Key Components

- **`NativeUpdate.get(Context)`** — thread-safe singleton accessor, initialized from the application context.
- **`BRIDGE_LEVEL`** — version constant bumped whenever the native bridge surface changes; bundles requiring a higher level are rejected.
- **`bootDirectory(boolean recreated)`** — determines the bundle directory to boot from on launch vs. Activity recreation, cleaning stale/staging files as needed.
- **`state()`** — returns a `JSObject` snapshot (enabled, builtin/booted/active/pending versions, trial flag, bridge level) for the JS layer.
- **`notifyReady()`** — marks the currently booted bundle as confirmed-good, promoting it to active and cleaning up stale bundles.
- **`applyPending()`** — switches to a pending downloaded bundle, starting a new trial period.
- **`installObservers()`** — hooks into `ProcessLifecycleOwner` to trigger update checks on app foregrounding.
- **`check(String trigger, Runnable whenSettled)`** — requests an update check (from system trigger or JS page), deduplicating concurrent requests via `CheckSchedule`.
- **Internal collaborators** — `UpdateStore` (bundle file storage), `OtaSession` (boot/trial/version state), `UpdateChecker` (network check/download logic), all serialized on a single background `worker` executor.

## Usage Example

```java
// Typically invoked from a Capacitor plugin or Activity
NativeUpdate update = NativeUpdate.get(context);

update.installObservers(); // auto-check on foreground

// On Activity creation:
File bundleDir = update.bootDirectory(activityWasRecreated);
// load WebView content from bundleDir, or fall back to built-in assets if null

// From JS bridge calls:
JSObject status = update.state();
update.check("manual refresh", () -> {
    // callback once check settles
});
update.notifyReady(); // called once WebView content finishes loading
File applied = update.applyPending(); // apply a downloaded update
```

All file I/O, network checks, and cleanup run serially on a dedicated background thread; this class itself is the synchronization point for state transitions exposed to the UI thread.
