# CheckSchedule.java

Manages the timing and deduplication logic for OpenFrame's Android app update checks, deciding when a native update check is due and coordinating between background-triggered and page-triggered (foreground "Update required" screen) requests. This is the Android counterpart to iOS's `OtaCheckSchedule`, and the two must be kept behavioral in sync.

## Key Components

- **`CheckSchedule`** (package-private, final class) — stateful scheduler, not thread-safe; callers must synchronize externally (e.g., under `NativeUpdate`'s check lock).
- **`Asked`** (enum) — result of an `ask()` call:
  - `ANSWERED` — no check needed; a recent/valid result already exists.
  - `JOINED` — a check is already in progress; caller's request is merged into it.
  - `STARTED` — a new check has begun.
- **`CHECK_EVERY_MS`** — minimum interval (1 hour) between background-initiated checks.
- **`RECENT_CHECK_MS`** — minimum freshness window (60s) for page-initiated checks; intentionally shorter than the web client's 65s retry interval.
- **`ask(boolean fromPage, long now)`** — entry point; determines whether a check should start, join, or be skipped based on elapsed time and whether a prior check deferred its download.
- **`mayDownload(boolean dataSaverRestricts)`** — decides whether the in-progress check may proceed to download, deferring it if Data Saver is active and no page has asked.
- **`finish(long now)`** — completes the current check; if a deferred download is owed to a page request, immediately restarts a check instead of finishing.

## Usage Example

```java
CheckSchedule schedule = new CheckSchedule();
long now = SystemClock.elapsedRealtime();

CheckSchedule.Asked result = schedule.ask(/* fromPage= */ false, now);
if (result == CheckSchedule.Asked.STARTED) {
    boolean canDownload = schedule.mayDownload(dataSaverRestricts);
    // perform network check, download if canDownload allows it
    boolean mustRestart = schedule.finish(SystemClock.elapsedRealtime());
    if (mustRestart) {
        // a page request arrived while download was deferred; start again
    }
}
```

**Notes:**
- Time values use `SystemClock.elapsedRealtime()` semantics, not wall-clock time.
- Under metered connections with Data Saver on, a check still runs but may defer its download until a page explicitly requests an update, per `mayDownload`.
- Any timing rule changed here must be mirrored in iOS's `OtaCheckSchedule` and validated against `NativeUpdateCheckTimingTest` / `CheckScheduleTests`.
