## PushNotifications.java

Final utility class that renders and manages Android tray notifications for OpenFrame's data-only FCM push payloads. Since the backend sends notifications without a native notification block (title, body, group, and category arrive as data keys via `AndroidDataOnlyPushFormatter`), this class is responsible for constructing and posting the visible notification itself. It is the Android counterpart to iOS's `NotificationActions.swift`.

Notifications share a fixed identity (`tag = notificationId, id = 0`), matching the baseline FCM tray entry tag, so a single cancel call retracts either kind, and action outcomes **replace** the original push in place rather than dismissing it.

## Key Components

- **`createChannels(Context)`** — Idempotently creates the `of.push` (high-importance, heads-up) and `of.outcomes` (low-importance, silent) notification channels on Android O+.
- **`show(Context, String, Map)`** — Renders the initial push notification from data payload keys, attaching a content intent and category-based actions (approve/reject/reply).
- **`markInProgress(Context, String, Map, String)`** — Replaces a notification's action buttons with an indeterminate progress spinner while an action is processed.
- **`replace(Context, String, Map, String, String, boolean, String)`** — Posts the final outcome notification; optionally restores action buttons on failure (`retry`), echoing back failed reply text.
- **`replaceWithStoreLink(Context, String, Map, String, String, String)`** — Replaces a notification with one linking to an app store listing (used when the backend rejects an outdated app version).
- **`retract(Context, Map)`** — Cancels notifications named in a retraction event or a `retractedIds` JSON array.
- **`foregroundWork(Context)`** — Builds the foreground-service notification for expedited work on API < 31.
- **`isOwnAction(String)`** — Checks whether an action id belongs to this app's own actions (approve/reject/reply).
- **`stringExtras(Bundle)`** — Extracts all String extras from a `Bundle` into a `Map<String, String>`.
- Constants for category values (`CATEGORY_APPROVAL`, `CATEGORY_REPLY`), action ids, data payload keys (`KEY_NOTIFICATION_ID`, `KEY_TITLE`, `KEY_BODY`, etc.), and limits (`MAX_REPLY_LENGTH`, `BODY_LIMIT`).

## Usage Example

```java
// During application startup
PushNotifications.createChannels(context);

// When an FCM data-only message arrives
Map<String, String> data = remoteMessage.getData();
PushNotifications.show(context, remoteMessage.getMessageId(), data);

// While handling a user action (e.g., approve button tapped)
Map<String, String> extras = PushNotifications.stringExtras(intent.getExtras());
PushNotifications.markInProgress(context, notificationId, extras, PushNotifications.ACTION_APPROVE);

// After the action completes successfully
PushNotifications.replace(context, notificationId, extras,
    "Request Approved", "Approved successfully", false, null);

// Handling a retraction push
PushNotifications.retract(context, data);
```
