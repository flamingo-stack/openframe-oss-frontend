## NotificationActionWorker.java

A background `Worker` that resolves notification action button taps (approve/deny/reply) without launching a web view, by refreshing the session token, sending a single GraphQL mutation to the tenant's AI-agent endpoint, and writing exactly one outcome back onto the notification.

## Key Components

- **`NotificationActionWorker`** — `Worker` subclass driving the full tap-to-outcome flow; entry point is `doWork()`.
- **`getForegroundInfo()`** — Promotes the work to a foreground service for pre-API-31 expedited execution.
- **`act(...)`** — Core orchestration: obtains a fresh `TokenPair` via `TokenLifecycle.ensureFresh`, validates the token's owner against the notification's recipient, resolves the tenant host, builds the request, and dispatches it.
- **Reply ledger (`wasAttempted` / `markAttempted` / `clearAttempted` / `ledger`)** — `SharedPreferences`-backed idempotency guard ensuring WorkManager's at-least-once retries don't duplicate a sent reply; entries expire after `LEDGER_TTL_MS` (24h).
- **`request(...)`** — Builds the GraphQL `Request` (`SEND_MESSAGE_MUTATION` or `RESOLVE_APPROVAL_REQUEST_MUTATION`) using the learned tenant host and bearer token; returns `null` if no valid id is present.
- **`ID_PATTERN`** — Validates ids extracted from the push payload before use.
- **Constants** — `SESSION_WAIT_SECONDS`, `REQUEST_TIMEOUT_MS`, `GATEWAY_MESSAGE_LIMIT`, `FALLBACK_STORE_URL`, `GRAPHQL_PATH`, mutation strings.

## Usage Example

This worker is not invoked directly; it's enqueued by the notification action receiver via WorkManager with the action and reply data as input:

```java
Data inputData = new Data.Builder()
    .putString(NotificationActionReceiver.INPUT_ACTION, actionId)
    .putString(NotificationActionReceiver.INPUT_REPLY, replyText)
    .putString(PushNotifications.EXTRA_NOTIFICATION_ID, notificationId)
    .putString(PushNotifications.KEY_DIALOG_ID, dialogId)
    .build();

OneTimeWorkRequest workRequest = new OneTimeWorkRequest.Builder(NotificationActionWorker.class)
    .setInputData(inputData)
    .setExpedited(OutOfQuotaPolicy.RUN_AS_NON_EXPEDITED_WORK_REQUEST)
    .build();

WorkManager.getInstance(context).enqueue(workRequest);
```

The worker handles session refresh, account-mismatch checks, gateway resolution, and reply deduplication internally, always completing by updating the original notification with a success or failure message.
