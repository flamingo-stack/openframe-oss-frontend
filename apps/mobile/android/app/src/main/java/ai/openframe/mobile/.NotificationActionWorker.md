## NotificationActionWorker.java

Background `Worker` that executes a single notification tray action (approve/deny an approval request, or send a chat reply) without launching a web view or Activity. It refreshes the session credential via `TokenLifecycle`, POSTs to the learned tenant gateway host, and writes exactly one outcome back onto the notification.

## Key Components

- **`NotificationActionWorker`** — `Worker` subclass driving the action lifecycle; entry point is `doWork()`.
- **`doWork()`** — Extracts action/reply/notification-id from input data, delegates to `act(...)`, and guarantees a terminal notification update even on unexpected exceptions.
- **`act(...)`** — Core flow: ensures a fresh session via `TokenLifecycle.ensureFresh`, validates token liveness and recipient match, resolves the learned tenant host, builds the request, and dispatches it.
- **`request(...)`** — Builds the outgoing `okhttp3.Request` for either a chat reply (`/chat/api/v1/messages`) or an approval decision (`/chat/api/v1/approval-requests/{id}/approve`), validating IDs against `ID_PATTERN` to prevent path injection.
- **Reply ledger (`wasAttempted`, `markAttempted`, `clearAttempted`, `ledger`)** — `SharedPreferences`-backed idempotency guard ensuring at-least-once WorkManager retries don't double-send replies; entries expire after `LEDGER_TTL_MS` (24 hours).
- **`getForegroundInfo()`** — Supplies foreground service info for expedited work on pre-API-31 devices.
- **Constants** — `SESSION_WAIT_SECONDS`, `REQUEST_TIMEOUT_MS`, `ID_PATTERN`, `LEDGER_TTL_MS`, `REASON_UNREACHABLE` govern timing, validation, and error messaging.

## Usage Example

This worker is not invoked directly by application code; it is enqueued by `NotificationActionReceiver` when a user taps a notification action button:

```java
Data inputData = new Data.Builder()
    .putString(NotificationActionReceiver.INPUT_ACTION, "approve")
    .putString(PushNotifications.EXTRA_NOTIFICATION_ID, notificationId)
    .putString(PushNotifications.KEY_APPROVAL_REQUEST_ID, requestId)
    .build();

OneTimeWorkRequest work = new OneTimeWorkRequest.Builder(NotificationActionWorker.class)
    .setInputData(inputData)
    .setExpedited(OutOfQuotaPolicy.RUN_AS_NON_EXPEDITED_WORK_REQUEST)
    .build();

WorkManager.getInstance(context).enqueue(work);
```

Its logic intentionally mirrors the iOS counterpart's `act`/`report` handling in `NotificationActions.swift`, keeping HTTP-status-to-outcome mapping consistent across platforms. See the [source file](https://github.com/flamingo-stack/openframe-saas-mobile/blob/main/NotificationActionWorker.java) for full implementation details.
