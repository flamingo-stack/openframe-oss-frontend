## NotificationActionWorker.java

Android `Worker` implementation that resolves a single notification action (reply, approve, or deny) performed from a tray notification, without launching a WebView or UI. It refreshes the session token via `TokenLifecycle`, issues a single GraphQL mutation against the tenant's chat/approval endpoint, and writes a terminal outcome back onto the notification. Behavior mirrors the iOS counterpart (`NotificationActions.swift`'s `act`/`report` logic) to keep error handling and button semantics consistent across platforms.

## Key Components

- **`NotificationActionWorker`** — the `Worker` subclass; `doWork()` extracts action/reply/notification-id from input data and delegates to `act()`.
- **`act(...)`** — core orchestration: waits for a fresh session (`TokenLifecycle.ensureFresh`), validates the token belongs to the notification's intended recipient, resolves the tenant host, builds and sends the GraphQL request, and reports the result.
- **Reply ledger (`SharedPreferences`-backed)** — `wasAttempted`, `markAttempted`, `clearAttempted`, `ledger()` — guards against WorkManager's at-least-once retries causing duplicate replies; entries expire after `LEDGER_TTL_MS` (24h).
- **`request(...)`** — builds the `okhttp3.Request` for either `SEND_MESSAGE_MUTATION` or `RESOLVE_APPROVAL_REQUEST_MUTATION`, validating ids against `ID_PATTERN` and using only the learned tenant host (never payload-derived URLs).
- **`ID_PATTERN`** — strict allowlist regex ensuring ids extracted from push payloads are safe identifiers only.
- **Failure/feedback helpers** (`failure`, `signInFeedback`, `report`) — translate session/network/GraphQL error states into user-facing notification updates, matching codes handled by the iOS implementation.

## Usage Example

This class is not instantiated directly; it is scheduled by WorkManager from a notification action `BroadcastReceiver`:

```java
Data input = new Data.Builder()
    .putString(NotificationActionReceiver.INPUT_ACTION, "approve")
    .putString(PushNotifications.EXTRA_NOTIFICATION_ID, notificationId)
    .putAll(extras)
    .build();

OneTimeWorkRequest request = new OneTimeWorkRequest.Builder(NotificationActionWorker.class)
    .setInputData(input)
    .setExpedited(OutOfQuotaPolicy.RUN_AS_NON_EXPEDITED_WORK_REQUEST)
    .build();

WorkManager.getInstance(context).enqueue(request);
```

The worker reports its outcome asynchronously by replacing the notification's content (e.g., success message, re-auth prompt, or error), never by returning a UI result.
