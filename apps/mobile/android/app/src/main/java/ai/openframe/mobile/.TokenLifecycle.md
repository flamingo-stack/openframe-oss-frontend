## TokenLifecycle.java

Shell-owned token lifecycle manager for the Android Capacitor app: holds the in-memory access/refresh token pair, serializes refresh requests against the gateway BFF (single-flight), and propagates every token change to the web view. This is the Android port of the iOS `TokenLifecycle.swift`, sharing the same state taxonomy and tunables but adapted for Android's process model, where the Capacitor bridge is ephemeral but token lifecycle must also be reachable from background components (FCM service, broadcast receivers, workers) with no web view present.

## Key Components

- **`TokenLifecycle`** (singleton) — process-wide instance accessed via `get(Context)`, owning a single-thread "store queue" executor that serializes all state reads/writes.
- **`RefreshResult`** — outcome of a refresh call exposed to callers: `TOKENS` (rotated pair), `SESSION_OVER` (refresh token refused), or `FAILED` (transient error, pair intact).
- **`Outcome`** — result of a single POST to `/oauth/refresh`: `ROTATED`, `REJECTED`, `UNREACHED` (no request sent/received), `ANSWERED_ERROR` (non-token server error), `UNKNOWN` (ambiguous — may or may not have rotated).
- **`Code`** — string constants surfaced to the web view for reject reasons (`REFRESH_UNREACHED`, `DEVICE_LOCKED`, `SESSION_REPLACED`, etc.).
- **`GateResult`** — result of gating pending operations behind biometric enablement.
- **`Waiter`** — internal record of a caller queued behind an in-flight refresh, tagged with the session epoch it joined under.
- **Tunables** — `REFRESH_MARGIN_MS`, `POLL_INTERVAL_MS`, `RETRY_DELAYS_MS`, `LOST_ROTATION_RETRY_AFTER_MS`, `LOST_ROTATION_RETRY_WITHIN_MS` govern refresh timing and the "lost rotation" retry window, matching values used on iOS and desktop.

## Usage Example

```java
// Obtain the process singleton (application context only)
TokenLifecycle lifecycle = TokenLifecycle.get(context);

// Request a refresh, handling the result asynchronously
lifecycle.refresh(force, rejectedAccessToken, "trigger-reason", result -> {
    switch (result.kind) {
        case TOKENS:
            // result.pair holds the rotated/fresh TokenPair
            break;
        case SESSION_OVER:
            // refresh token was refused — sign the user out
            break;
        case FAILED:
            // transient error — result.code / result.message describe it
            break;
    }
});
```

Background components (e.g. a `FirebaseMessagingService`) reach the same singleton without any Capacitor plugin or web view attached, relying solely on the store queue for thread-safe state access.
