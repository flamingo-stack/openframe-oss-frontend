Utility class responsible for safely removing an OTA (over-the-air) bundle directory on disk, ensuring deletion order guarantees that a crash mid-deletion never leaves behind a directory that still looks like a valid, complete bundle.

## Key Components

- **`BundleRemoval`** — final utility class (non-instantiable) with static methods for bundle removal.
- **`remove(File directory)`** — deletes all files and subdirectories under the given bundle directory, deleting `index.html` first so that an interrupted deletion can never pass for a whole bundle.
- **`order(File directory)`** — package-private helper that computes the deletion order as a `List<File>`, placing `index.html` at the front if present.
- **`collect(File file, File first, List<File> order)`** — recursive helper that performs a post-order traversal (children before parents), skipping the already-ordered `index.html`, so directories are only added once empty.

## Usage Example

```java
import ai.openframe.mobile.ota.BundleRemoval;
import java.io.File;

public class OtaCleanup {
    public void cleanupOldBundle(File bundleDir) {
        // Removes index.html first, then all other files/dirs bottom-up,
        // then the directory itself — safe even if interrupted mid-way.
        BundleRemoval.remove(bundleDir);
    }
}
```

**Design rationale:** Since the updater writes bundles as plain files and directories (no symlinks), deleting `index.html` first ensures that if the JVM process dies partway through removing the remaining ~4,200 files, the leftover directory is immediately recognizable as invalid/incomplete rather than mistakenly treated as a valid bundle. The recursive `collect` method performs a depth-first, children-first traversal so directories are emptied before being deleted.
