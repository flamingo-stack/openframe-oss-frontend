# DirectorySink.java

A `BundleReader.Sink` implementation that extracts bundle entries directly onto the filesystem under a given root directory, writing files with the process's own permissions without applying any tar header metadata.

## Key Components

- **`DirectorySink`** — Final class implementing `BundleReader.Sink` and `Closeable`, responsible for writing extracted bundle entries to disk.
- **`DirectorySink(File root)`** — Constructor that sets the base directory under which all extracted files will be written.
- **`begin(String path, long size)`** — Resolves the target file path relative to `root`, creates any missing parent directories, and opens a `FileOutputStream` for writing.
- **`write(byte[] buffer, int offset, int length)`** — Writes a chunk of bytes to the currently open output stream.
- **`end()`** — Closes the current output stream after a bundle entry has been fully written.
- **`close()`** — Safety net that closes any dangling open file if the reader aborts mid-extraction (e.g., due to a rejected bundle).

## Usage Example

```java
File extractRoot = new File("/data/local/tmp/ota-bundle");

try (DirectorySink sink = new DirectorySink(extractRoot)) {
    BundleReader reader = new BundleReader(bundleInputStream);
    reader.extractTo(sink);
} catch (IOException e) {
    // Handle extraction failure; close() ensures partial files are cleaned up
    throw new RuntimeException("Bundle extraction failed", e);
}
```

**Note:** The caller (`BundleReader`) is responsible for ensuring that the `path` passed to `begin()` stays within `root` and does not collide with other entries — `DirectorySink` performs no path sanitization itself. Always use try-with-resources to guarantee `close()` is invoked if extraction is interrupted.
