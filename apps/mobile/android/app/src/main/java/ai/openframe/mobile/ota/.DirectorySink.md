# DirectorySink.java

A `BundleReader.Sink` implementation that extracts bundle entries to disk as regular files under a given root directory, preserving the process's own file permissions without applying any permission bits from tar-style headers.

## Key Components

- **`DirectorySink`** - Final class implementing `BundleReader.Sink` and `Closeable`, used to write extracted bundle entries directly to the filesystem.
- **`DirectorySink(File root)`** - Constructor that sets the base directory under which all extracted files will be written. Callers (e.g., `BundleReader`) are responsible for ensuring paths stay within `root` and don't collide.
- **`begin(String path, long size)`** - Opens a new `FileOutputStream` for the given relative path, creating parent directories as needed. Throws `IOException` if the parent directory cannot be created.
- **`write(byte[] buffer, int offset, int length)`** - Writes a chunk of entry data to the currently open output stream.
- **`end()`** - Closes the current output stream and clears the reference, signaling the entry is complete.
- **`close()`** - Safety net that closes any still-open stream if the bundle reader aborts mid-entry, preventing file descriptor leaks.

## Usage Example

```java
File extractDir = new File(context.getFilesDir(), "ota-update");

try (DirectorySink sink = new DirectorySink(extractDir)) {
    bundleReader.extractTo(sink); // calls begin/write/end for each entry
} catch (IOException e) {
    // handle extraction failure; close() ensures partial file is closed
}
```

Typically used as the destination for `BundleReader` when unpacking an OTA update bundle onto local storage. The `try-with-resources` pattern ensures `close()` runs even if extraction fails partway, closing any dangling file handle left open by an aborted entry.
