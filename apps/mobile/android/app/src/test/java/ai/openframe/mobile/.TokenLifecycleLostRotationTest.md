## TokenLifecycleLostRotationTest.java

JUnit test suite validating the timing rules for "lost rotation" scenarios in `TokenLifecycle` — cases where a refresh token rotation response is lost in transit but the auth server has already rotated the token server-side. It verifies hold windows, retry deadlines, retry delays, and outcome classification used by the mobile shell to decide whether to retransmit a refresh POST or sign the user out.

## Key Components

- **`SERVER_GRACE_MS` / `GATEWAY_AUTH_WAIT_MS` / `WALL_CLOCK_BUDGET_MS`** — Test constants mirroring production timing configuration (`openframe.authz.refresh-token-grace-seconds`, `WebClientConfig` response timeout, and the shell's wall-clock budget for a refresh call).
- **`holdEndsOnlyOnceTheGatewayHasStoppedServingTheLostPost`** — Confirms `TokenLifecycle.lostRotationHoldEnd` waits past the gateway's auth-wait timeout.
- **`aCallersLostPostIsRePresentedInsideTheServerGrace`** / **`theRetryWindowClosesBeforeTheServerGraceDoes`** — Verify retry timing stays within the server's token grace period.
- **`aLossOnTheShellsOwnRetryKeepsItsWindowSoTheShellStops`** / **`aLaterCallersLostPostAfterACappedDoubtGetsItsOwnWindow`** — Validate deadline preservation vs. fresh-window creation logic via `lostRotationRetryDeadline`.
- **`aRetryMayStartUpToTheDeadlineButNotAtIt`** — Boundary test for `mayRetryLostRotation`.
- **`theTimerNeverFiresBeforeItsMomentAndAMissedMomentFiresAtOnce`** — Tests `lostRotationRetryDelay` scheduling semantics.
- **`onlyARePresentationThatNeverLeftTheDeviceIsTriedAgain`** — Tests `rearmsLostRotationRetry` across different `RefreshResult` outcomes (`UNREACHED`, `UNKNOWN`, `ANSWERED_ERROR`, `HELD`, `NO_HOST`, success, session-over).
- **`anAnsweredErrorIsNotALostAnswer`** / **`aSuccessWithoutTokensRotatedAndHoldsCallersLikeALostAnswer`** — Validate `outcomeOfAnswerWithoutTokens` classification for HTTP status codes (502/503/500/429/403/404/401/204).

## Usage Example

```java
// Run via standard JUnit tooling (e.g., Gradle/Maven test task)
// Example of the pattern under test:
long holdEnd = TokenLifecycle.lostRotationHoldEnd(sentAtMillis);
long deadline = TokenLifecycle.lostRotationRetryDeadline(sentAtMillis, false, null);

if (TokenLifecycle.mayRetryLostRotation(holdEnd, deadline)) {
    long delay = TokenLifecycle.lostRotationRetryDelay(holdEnd, System.currentTimeMillis());
    // schedule retry after `delay` ms
}
```

This test class documents and enforces the business rules referenced in tickets CU-17tkuw64r3v and CU-17tkuw65dnm, ensuring lost refresh responses are retried correctly without prematurely signing users out or looping indefinitely on genuine auth failures.
