JUnit test suite that specifies the timing rules governing how the mobile shell recovers from a "lost-rotation" scenario — a refresh request whose token-rotation response never reached the client, even though the auth server rotated the token server-side. It documents and verifies the hold windows, retry deadlines, and retry-delay computations defined in `TokenLifecycle`, referenced against tickets CU-17tkuw64r3v and CU-17tkuw65dnm.

## Key Components

- **`TokenLifecycleLostRotationTest`** — test class covering the lost-rotation recovery contract.
- **Timing constants** — `SERVER_GRACE_MS` (auth server's rotated-token grace period), `GATEWAY_AUTH_WAIT_MS` (gateway's wait on the auth server), `WALL_CLOCK_BUDGET_MS` (shell's give-up budget for a refresh POST).
- **Hold/retry window tests** — verify `TokenLifecycle.lostRotationHoldEnd`, `lostRotationRetryDeadline`, `lostRotationRetryDelay`, and `mayRetryLostRotation` correctly sequence retries within the server's grace period without re-opening expired windows or refusing legitimate retries.
- **Retry eligibility tests** — verify `TokenLifecycle.rearmsLostRotationRetry` only re-arms a retry when a refresh never left the device (`Code.UNREACHED`) and the doubt still stands, excluding other failure codes and successful outcomes.
- **Outcome classification tests** — verify `TokenLifecycle.outcomeOfAnswerWithoutTokens` and `TokenLifecycle.holdsCallers` distinguish answered errors (502/503/500/429/403/404, which do not hold callers back) from rejected (401) and unknown/lost outcomes (204, which do hold callers back).

## Usage Example

```java
// Run via the standard JUnit runner, e.g. with Gradle or Maven:
// ./gradlew test --tests "ai.openframe.mobile.TokenLifecycleLostRotationTest"

// Example of the pattern under test:
long holdEnd = TokenLifecycle.lostRotationHoldEnd(sentAt);
long deadline = TokenLifecycle.lostRotationRetryDeadline(sentAt, isOwnRetry, previousDeadline);

if (TokenLifecycle.mayRetryLostRotation(holdEnd, deadline)) {
    long delay = TokenLifecycle.lostRotationRetryDelay(holdEnd, System.currentTimeMillis());
    // schedule retry after `delay` ms
}
```

These tests act as executable documentation for `TokenLifecycle`'s lost-rotation handling—see [TokenLifecycle.java](https://github.com/flamingo-stack/openframe-oss-frontend/blob/main/TokenLifecycle.java) for the implementation under test (path may vary by module).
