## OtaSessionTest.java

JUnit test suite validating `OtaSession`, the component that manages over-the-air (OTA) bundle lifecycle for the mobile app's embedded web view — including boot sequencing, activity recreation handling, trial/revert logic, environment-compatibility checks, and persisted state transitions.

## Key Components

- **`OtaSessionTest`** — Test class covering `OtaSession` boot, recreation, download, and revert behaviors.
- **`MemoryStore`** — In-memory fake implementing `OtaSession.Store`, simulating on-disk bundle pages (`index`), persisted `OtaState` (`read`/`write`), and failure injection (`unreadable`, `unwritable`) for error-path testing.
- **`session(MemoryStore)`** — Factory helper constructing an `OtaSession` wired to a fixed built-in version, a fake environment supplier, and a given store.
- **`pageWith(String envElement)` / `ascii(String)`** — Helpers building fake HTML page bytes embedding a `window.__ENV` script tag, used to simulate bundle index pages with matching/mismatching build environments.
- **`state(...)`** — Shorthand for constructing `OtaState` instances (active version, pending version, attempt count, bad-version list).

## Usage Example

```java
@Test
public void exampleBootFlow() {
    MemoryStore store = new MemoryStore(
        OtaSession.OtaState.of("1.2.3", "1.2.4", 0, Collections.emptyList()),
        "1.2.3", "1.2.4"
    );
    OtaSession process = session(store);

    OtaSession.Booted booted = process.boot();

    assertEquals("1.2.4", booted.version);
    assertTrue(booted.trial);
}
```

The suite exercises scenarios such as:
- Activity recreation not consuming an extra trial attempt.
- Reverting to the previous bundle after repeated failed trials (marking it "bad").
- Dropping bundles whose embedded environment doesn't match the running build.
- Falling back to the built-in bundle when a pending bundle's page becomes unreadable.

Run via standard JUnit tooling (e.g., Gradle/Maven test task) alongside the rest of the `ai.openframe.mobile.ota` package tests.
