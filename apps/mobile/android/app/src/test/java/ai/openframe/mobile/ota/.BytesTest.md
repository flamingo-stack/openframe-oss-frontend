Unit test suite for the `Bytes` utility class, verifying the behavior of `Bytes.readAtMost(InputStream, int)` under various stream conditions, including exact-limit reads, over-limit reads, empty streams, and streams that return fewer bytes than requested per call.

## Key Components

- **`BytesTest`** — JUnit 4 test class covering `Bytes.readAtMost` edge cases.
- **`bytes(int length)`** — Helper that generates a byte array of a given length with sequential values for predictable test data.
- **`ShortReads`** — A custom `InputStream` implementation that simulates partial ("short") reads by returning at most `step` bytes per call, used to validate that `Bytes.readAtMost` correctly accumulates data across multiple reads.
- **Test methods**:
  - `aStreamAtTheLimitIsReadWhole` — Confirms a stream exactly at the limit is read in full.
  - `oneBytePastTheLimitIsNull` — Confirms a stream exceeding the limit returns `null`.
  - `anEmptyStreamIsAnEmptyArray` — Confirms an empty stream with a zero limit yields an empty array.
  - `shortReadsAddUp` — Confirms partial reads are aggregated correctly up to and beyond the limit.
  - `nothingIsReadPastTheReadThatCrossesTheLimit` — Confirms reading stops once the limit is exceeded, leaving the remaining stream untouched.
  - `noLimitOfItsOwnReadsEverything` — Confirms `Integer.MAX_VALUE` as a limit effectively reads an entire stream.

## Usage Example

Run via standard JUnit tooling (e.g., Gradle/Maven test task):

```java
// Example of what Bytes.readAtMost is expected to do, as exercised by this test:
InputStream in = new ByteArrayInputStream(data);
byte[] result = Bytes.readAtMost(in, 4096);
// result is the full byte array if data.length <= 4096, otherwise null
```

This test file resides alongside the `Bytes` class it validates; see [`ai.openframe.mobile.ota`](https://github.com/flamingo-stack/openframe-oss-frontend/tree/main/) package for the implementation under test.
