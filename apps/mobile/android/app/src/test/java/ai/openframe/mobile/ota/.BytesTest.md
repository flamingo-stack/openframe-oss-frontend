Unit test suite for the `Bytes` utility class, validating the behavior of `Bytes.readAtMost(InputStream, int)` under various stream conditions, including exact-limit reads, over-limit reads, empty streams, and streams that produce short (partial) reads.

## Key Components

- **`bytes(int length)`** - Static helper that generates a deterministic byte array of the given length, filled with sequential byte values (wrapping via truncation to `byte`).
- **`ShortReads`** - A private `InputStream` implementation that simulates partial/short reads by returning at most `step` bytes per call, used to test that `Bytes.readAtMost` correctly accumulates data across multiple short reads. Exposes `left()` to check remaining unread bytes.
- **Test methods** - Cover key scenarios for `Bytes.readAtMost`:
  - Reading a stream exactly at the limit returns the full array.
  - Reading a stream exceeding the limit (even by one byte) returns `null`.
  - An empty stream with a zero limit returns an empty array.
  - Short reads that collectively sum to the correct data are handled correctly.
  - Reads are not continued past the point where the limit is crossed, leaving the stream partially unread.
  - Using `Integer.MAX_VALUE` as the limit effectively reads the entire stream regardless of short reads.

## Usage Example

```java
// Example of what this test suite verifies for Bytes.readAtMost
byte[] data = new byte[4096];
InputStream stream = new ByteArrayInputStream(data);

// Reads succeed when stream size <= limit
byte[] result = Bytes.readAtMost(stream, 4096);
assertArrayEquals(data, result);

// Reads fail (return null) when stream exceeds the limit
InputStream oversized = new ByteArrayInputStream(new byte[4097]);
assertNull(Bytes.readAtMost(oversized, 4096));
```

This test file ensures `Bytes.readAtMost` reliably enforces size limits while correctly handling streams that deliver data in multiple partial chunks.
