# OtaStateTest.java

JUnit test suite validating `OtaState`, the core state machine for the OTA (over-the-air) bundle update mechanism. It verifies boot resolution logic, trial-based rollout of pending bundles, rollback behavior, bad-version tracking, stale directory cleanup, and JSON serialization/parsing of the persisted state file.

## Key Components

- **`state(...)` helper** – Builds an `OtaState` from active/pending versions, trial attempt count, and bad version list for concise test setup.
- **Boot resolution tests** – Verify `OtaState.resolveBoot()` correctly selects between built-in, active, and pending bundles, handles trial attempt counting (`MAX_TRIAL_ATTEMPTS`), and reverts bundles after failed trials.
- **Usability/disk checks** – Confirm bundles unusable on disk (via `OtaState.Usable` predicate) are dropped silently rather than marked bad, and that versions at/below the built-in version are never probed on disk.
- **`applyReady` / `applyNothing` / `applyDrop` / `applyDownloaded`** – Tests state transitions for bundle confirmation, no-op cases, rollback, and completed downloads.
- **`markBad`** – Validates the bad-version list caps at 20 entries, evicting oldest first, and re-marking moves an entry to most recent.
- **`staleDirectories`** – Confirms only active, pending, and currently-booted directories are retained; all others are flagged stale for cleanup.
- **JSON round-trip tests** – Validate `toJson()`/`parse()` symmetry and that malformed/invalid state files safely fall back to `OtaState.EMPTY`.

## Usage Example

```java
// Example pattern used throughout the test class
OtaState before = OtaState.of("1.2.3", "1.2.4", 0, Arrays.asList("1.2.1"));

OtaState.Boot boot = OtaState.resolveBoot(before, "1.2.0", version -> true);

assertEquals("1.2.4", boot.version);
assertTrue(boot.trial);
```

This suite runs via standard JUnit 4 tooling (`mvn test` or your IDE's test runner) and requires no external fixtures—all state is constructed programmatically in-memory.
