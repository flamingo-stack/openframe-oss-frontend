# BundleCheckTest.java

Unit test suite validating the `BundleCheck` class, which verifies OTA (over-the-air) update bundles against an expected size and SHA-256 hash before accepting them as valid downloads.

## Key Components

- **`BundleCheckTest`** - JUnit test class covering `BundleCheck` validation logic
- **`bytesOfTheSignedSizeAndHashPass`** - Confirms that data matching both the expected size and hash passes validation across multiple `update()` calls
- **`theFirstByteTooManyIsRefusedAsItArrives`** - Verifies that exceeding the expected byte count is rejected immediately (streaming size check) with `OtaError.Code.SIZE`
- **`aShortDownloadIsRefusedBySizeBeforeItsHash`** - Ensures an incomplete download (fewer bytes than expected) fails on `finish()` with `OtaError.Code.SIZE`, checked before hash validation
- **`otherBytesOfTheSameSizeAreRefusedByHash`** - Confirms that data of the correct size but incorrect content fails hash verification with `OtaError.Code.SHA256`

## Usage Example

These tests exercise the expected contract for `BundleCheck`:

```java
// Create a check expecting 3 bytes with a known SHA-256 hash
BundleCheck check = new BundleCheck(3, SHA256_OF_ABC);

// Feed data incrementally as it arrives (e.g., from a network stream)
check.update(new byte[] {'a', 'b'}, 0, 2);
check.update(new byte[] {'c'}, 0, 1);

// Validate total size and hash match expectations
check.finish();
```

If the data stream exceeds the expected size or the final hash doesn't match, `BundleCheck` throws an `OtaError` with the corresponding `Code` (`SIZE` or `SHA256`), allowing callers to distinguish between truncated downloads and corrupted/tampered content.
