Unit tests for `BundleCheck`, a component in the OpenFrame mobile OTA (over-the-air update) system that validates downloaded firmware/bundle data against an expected size and SHA-256 hash before accepting it as valid.

## Key Components

- **`BundleCheckTest`** - JUnit test class covering `BundleCheck` validation logic.
- **`SHA256_OF_ABC`** - Precomputed SHA-256 hash constant used as the expected hash fixture across test cases.
- **`bytesOfTheSignedSizeAndHashPass()`** - Verifies that data matching both the declared size and hash is accepted without error.
- **`theFirstByteTooManyIsRefusedAsItArrives()`** - Verifies that exceeding the declared byte count is rejected immediately during `update()`, not deferred to `finish()`.
- **`aShortDownloadIsRefusedBySizeBeforeItsHash()`** - Verifies that incomplete downloads (fewer bytes than expected) fail with a `SIZE` error at `finish()`, before hash validation occurs.
- **`otherBytesOfTheSameSizeAreRefusedByHash()`** - Verifies that data of the correct size but incorrect content fails with a `SHA256` error at `finish()`.

## Usage Example

```java
// Create a check expecting 3 bytes matching a known SHA-256 hash
BundleCheck check = new BundleCheck(3, expectedSha256Hex);

// Feed bundle bytes incrementally as they are downloaded
check.update(downloadedChunk, 0, chunk.length);

try {
    // Validates total size and final hash match expectations
    check.finish();
} catch (OtaError e) {
    switch (e.code) {
        case SIZE:
            // Byte count mismatch (too many during update, or too few at finish)
            break;
        case SHA256:
            // Content hash mismatch despite correct size
            break;
    }
}
```

This test suite ensures `BundleCheck` fails fast on oversized input (during streaming) and correctly distinguishes between size-related and integrity-related (hash) failures when validation completes, which is critical for safely applying OTA firmware updates on mobile devices.
