Android instrumented test suite that runs shared OTA (over-the-air update) test cases on-device, leveraging the device's native security provider (Conscrypt) for signature verification instead of the JVM's default provider.

## Key Components

- **`SharedCasesInstrumentedTest`** - Instrumented test class annotated with `@RunWith(AndroidJUnit4.class)`, executed on an actual Android device/emulator rather than a local JVM.
- **`assets`** - `AssetManager` obtained from the instrumentation context, used to read bundled test fixtures (manifests, bundles) from the app's assets folder.
- **`cases`** - A `SharedCases` instance constructed with an asset-opening function reference (`assets::open`) and the target app's cache directory, encapsulating the actual OTA test logic shared across test runners.
- **Test methods**:
  - `manifestCases()` - Validates OTA manifest parsing and handling.
  - `bundleCases()` - Validates OTA bundle processing logic.
  - `envCases()` - Validates environment-specific decision logic.
  - `decisionCases()` - Validates update decision outcomes.
  - `keyIds()` - Validates cryptographic key ID resolution.

This class is a thin instrumented wrapper that delegates all actual test logic to the shared `SharedCases` class, ensuring the same test cases can run both on-device (here, using Conscrypt and ART) and potentially in JVM-based tests, guaranteeing signature verification behaves consistently with real device security providers.

## Usage Example

```java
// Run via Gradle on a connected device/emulator:
// ./gradlew connectedAndroidTest

// Example of how SharedCases is wired for instrumented execution:
AssetManager assets = InstrumentationRegistry.getInstrumentation().getContext().getAssets();
SharedCases cases = new SharedCases(
    assets::open,
    InstrumentationRegistry.getInstrumentation().getTargetContext().getCacheDir()
);

cases.manifestCases();
cases.bundleCases();
cases.keyIds();
```

Note: this test requires a connected Android device or emulator—it cannot run as a plain unit test, since it depends on ART and the device's Conscrypt security provider for DER signature verification (unlike SunEC used in standard JVM tests).
