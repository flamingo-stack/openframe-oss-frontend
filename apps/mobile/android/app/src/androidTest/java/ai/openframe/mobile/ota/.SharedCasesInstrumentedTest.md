# SharedCasesInstrumentedTest.java

Android instrumented test that executes the shared OTA (over-the-air update) test suite on a real device or emulator, running under Android's native runtime (ART) and security provider (Conscrypt) rather than the host JVM. This matters because signature verification behaves differently between environments: the JVM's SunEC provider rejects DER-encoded signatures that Conscrypt accepts, and XZ decompression must be validated against ART specifically.

This class is a thin Android-specific wrapper around `SharedCases`, which contains the actual OTA update logic test cases (manifest parsing, bundle validation, environment checks, update decisions, and key ID verification). By delegating to `SharedCases`, the same test logic can potentially be reused across different test runners while this class handles Android-specific setup (asset access and cache directory).

## Key Components

- **`SharedCasesInstrumentedTest`** — JUnit4 test class annotated with `@RunWith(AndroidJUnit4.class)`, executed as an Android instrumented test (requires a connected device/emulator).
- **`assets`** — `AssetManager` obtained from the instrumentation test context, used to read bundled test fixtures (manifests, bundles, keys).
- **`cases`** — Instance of `SharedCases`, constructed with an asset-opening function reference and the target app's cache directory.
- **Test methods** — `manifestCases()`, `bundleCases()`, `envCases()`, `decisionCases()`, `keyIds()`: each delegates to the corresponding method on `SharedCases` to validate OTA update manifest parsing, bundle integrity, environment preconditions, update decision logic, and cryptographic key ID handling.

## Usage Example

This test runs via the Android Gradle instrumented test task, not as a plain JUnit test:

```bash
./gradlew connectedAndroidTest
```

Or target a single test method:

```bash
./gradlew connectedAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=ai.openframe.mobile.ota.SharedCasesInstrumentedTest#keyIds
```

The test itself requires no direct invocation in code—it's picked up automatically by the Android test runner. The underlying `SharedCases` logic can be inspected for details on what each test validates:

```java
// Example of what a test method does internally
@Test
public void keyIds() throws Exception {
    // Delegates to SharedCases, which reads key fixtures via `assets`
    // and verifies key ID derivation/matching using ART's Conscrypt provider
    cases.keyIds();
}
```
