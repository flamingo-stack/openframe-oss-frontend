Defines the shared error vocabulary for over-the-air (OTA) bundle validation, used by both release-building scripts and shell-side verification code to ensure consistent, code-based rejection reasons regardless of how each side phrases its error messages.

## Key Components

- **`CODES`** — An array of string constants identifying every distinct reason an OTA bundle or update envelope can be refused, grouped by validation stage:
  - Envelope/signature checks: `ENVELOPE`, `UNKNOWN_KEY`, `SIGNATURE`, `PAYLOAD`
  - Bundle integrity checks: `SIZE`, `SHA256`, `XZ`, `TAR`, `ENTRY_TYPE`, `ENTRY_NAME`, `DUPLICATE`, `NO_INDEX`
  - Environment injection checks: `NO_ENV`, `HAS_ENV`, `NO_HEAD`
  - Key management: `KEYS`
- **`OtaError`** — A custom `Error` subclass that attaches a validated `code` (must be one of `CODES`) alongside a human-readable `message`. Throws if given an unrecognized code, preventing silent drift between fixtures and implementation.
- **`runCli(main)`** — A CLI wrapper that invokes a script's `main` function, catches any thrown error, prints it (prefixing with the `OtaError` code when applicable), and exits with status `1` on failure.

## Usage Example

```javascript
import { OtaError, runCli } from './ota-error.mjs';

function main() {
  const payload = JSON.parse(rawEnvelope);
  if (!payload.signature) {
    throw new OtaError('ENVELOPE', 'missing signature field in envelope');
  }
  // ... further validation
}

runCli(main);
```

Shared test fixtures can then assert on `error.code === 'ENVELOPE'` instead of parsing free-form messages, keeping release scripts and shell implementations decoupled in wording but aligned in behavior.
