## ota-error.mjs

Defines the shared error vocabulary for the over-the-air (OTA) update verification pipeline. It establishes a fixed set of refusal codes used when validating OTA envelopes, bundles, and keys, so that release scripts and shell implementations can agree on outcomes (codes) while varying their human-readable messages.

## Key Components

- **`CODES`** - An array of string constants representing every valid refusal reason, grouped by validation stage:
  - Envelope/signature checks: `ENVELOPE`, `UNKNOWN_KEY`, `SIGNATURE`, `PAYLOAD`
  - Bundle checks: `SIZE`, `SHA256`, `XZ`, `TAR`, `ENTRY_TYPE`, `ENTRY_NAME`, `DUPLICATE`, `NO_INDEX`
  - `window.__ENV` injection checks: `NO_ENV`, `HAS_ENV`, `NO_HEAD`
  - Key file checks: `KEYS`
- **`OtaError`** - An `Error` subclass that requires a valid code from `CODES` (throws if given an unknown code) and attaches it as `this.code`, alongside a free-form `message`.
- **`runCli(main)`** - A CLI entry-point wrapper that runs a script's `main` function, catches any thrown error, prints it to stderr (prefixing the OTA error code when applicable), and exits the process with status `1` on failure.

## Usage Example

```javascript
import { OtaError, runCli } from './ota-error.mjs';

function validateBundleSize(actual, expected) {
  if (actual !== expected) {
    throw new OtaError('SIZE', `bundle size ${actual} does not match payload size ${expected}`);
  }
}

function main() {
  validateBundleSize(1024, 2048);
}

// Runs main(), printing "✗ SIZE: bundle size 1024 does not match payload size 2048"
// and exiting with code 1 if validation fails.
runCli(main);
```

This pattern lets downstream tooling (e.g., tests in `apps/mobile/ota/fixtures`) assert on `error.code` rather than parsing message strings, keeping error semantics stable even as wording evolves.
