## ota-fixtures.mjs

A Node.js script that generates the shared test fixtures used to validate the over-the-air (OTA) update format across all mobile shells. It produces `manifest-cases.json` (signed envelopes and their expected outcomes) and `bundle-cases.json` (test bundles), writing them into `apps/mobile/ota/fixtures`. Each run creates fresh EC key pairs and signatures, so results differ between runs but the semantics of each test case remain stable.

The fixtures encode expected *outcomes* (accepted payload fields or specific error codes) independently of the verification implementation (`ota-verify.mjs`), ensuring that bugs in verification logic cause test failures rather than silently passing.

## Key Components

- **`FIXTURES_DIR`** — exported path to the fixtures output directory.
- **`knownFields(payload)`** — exported helper returning only the fields a manifest payload is expected to expose.
- **`KEYS` / `HELD`** — generated EC key pairs (`a`, `b`, `c`) where shells hold only `a` and `b`.
- **`manifest(payloadText, options)`** — builds a signed manifest envelope (base64 payload + DER signature) with optional field overrides for crafting malformed cases.
- **`manifestCases()`** — builds the full list of manifest test cases, covering accepted manifests, envelope malformations (non-JSON, bad base64, non-canonical JSON), unknown/invalid keys, and signature tampering (high-S normalization, wrong payload, wrong keyId, DER edge cases).
- **`payloadWhere(accept)`** / **`signatureWhere(bytes, accept)`** — search helpers that pad a payload or re-sign until a target base64/DER property (e.g., padding bits, URL-safe chars) is satisfied.
- **DER helpers** (`derParts`, `derSequence`, `derInt`, `intContent`, `toBig`) — low-level ECDSA-Sig-Value manipulation for constructing edge-case signatures (e.g., high-S forms, long-form lengths).
- **`dirtyPaddingBits(b64)`** — mutates base64 padding bits to test lenient-decoder rejection.
- Uses `writeTar`/`XZ_ENCODE` from `ota-tar.mjs` and `keyIdOf` from `ota-verify.mjs`.

## Usage Example

Run from the `apps/mobile` directory to (re)generate fixtures:

```bash
npm run ota:fixtures
```

Programmatic use of exported helpers in tests:

```javascript
import { FIXTURES_DIR, knownFields } from './ota-fixtures.mjs';

// Compare a verified payload against only its known/expected fields
const expected = knownFields(myPayload);
assert.deepEqual(actualResult.payload, expected);
```

**Note:** Since each run generates new signing keys and signatures, only rerun this script when a test case needs to change, and always commit the regenerated fixture files alongside the change.
