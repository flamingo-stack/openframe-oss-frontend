## ota-fixtures.mjs

Script that generates deterministic test fixtures for the OTA (over-the-air update) format used by the mobile app's release/verification shells. It writes `manifest-cases.json` (and the ephemeral signing keys used to produce them) and `bundle-cases.json` into `apps/mobile/ota/fixtures`, covering every acceptance and rejection path a shell's manifest/bundle verifier must handle (malformed envelopes, bad base64, unknown/wrong signing keys, invalid signatures, version edge cases, etc.). These fixtures are consumed by both the release scripts' tests and the native shells' unit tests, which must reproduce the exact expected outcome (error code, payload, or file list) for each case.

## Key Components

- **`FIXTURES_DIR`** - resolved path to `apps/mobile/ota/fixtures`, exported for consumers that need to locate the generated files.
- **`knownFields(payload)`** - extracts only the OTA payload's documented fields, representing what an accepting case should expose.
- **`KEYS` / `keyId(name)`** - generates three EC (P-256) keypairs (`a`, `b` held by shells, `c` unknown) and derives key IDs via `keyIdOf` from `ota-verify.mjs`.
- **`manifest(payloadText, options)`** - builds a signed manifest envelope (keyId, base64 payload, base64 DER signature) with optional field overrides for crafting malformed cases.
- **`payloadWhere(accept)` / `signatureWhere(bytes, accept)`** - search for payload padding or re-signed signatures satisfying a predicate (e.g., producing specific base64 edge cases like unpadded or URL-safe output).
- **`manifestCases()`** - produces the full array of manifest test cases: accepted manifests (valid signatures, unknown fields ignored, high-S signatures, version edge cases) and refused manifests (malformed envelope/JSON, unknown keys, bad signatures), each tagged with an expected outcome (`payload` or `error` code).
- **DER helpers** (`derSign`, `derParts`, `derSequence`, `derInt`, `intContent`) - low-level ECDSA DER signature construction/manipulation used to craft canonical and non-canonical signatures (e.g., high-S vs low-S, long-form lengths).
- **`dirtyPaddingBits(b64)`** - mutates base64 padding bits to test lenient-decoder rejection cases.

## Usage Example

```bash
# Run from apps/mobile to regenerate fixtures
npm run ota:fixtures
```

```javascript
// Fixtures are consumed in tests like:
import { readFileSync } from 'node:fs';
import { join } from 'node:path';
import { FIXTURES_DIR } from './ota-fixtures.mjs';

const cases = JSON.parse(readFileSync(join(FIXTURES_DIR, 'manifest-cases.json'), 'utf8'));
for (const { name, manifest, expect, keys } of cases) {
  // verify manifest against held `keys`, assert result matches `expect`
}
```

Note: each run generates fresh keys and signatures (private keys are discarded), so rerun only when a case needs to change, and commit all generated output.
