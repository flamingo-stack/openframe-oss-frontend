WHAT THE APP IS:
OpenFrame is a remote monitoring and management platform for Managed Service Providers (MSPs). The app is the technician's console: devices, tickets, chat, alerts, scripts and the AI assistant. Audience: MSP employees, not consumers.

No account or organization registration in the app. OpenFrame is sold directly to MSPs by contract; the app signs in their employees, with accounts created by their administrator (Guideline 3.1.3(c)). It is a free companion to that web service: no purchasing in the app, no calls to action for purchase outside it (3.1.3(f)).

CHANGES SINCE THE APPROVED VERSION:
- New home: sign-in opens the AI assistant (a greeting and "What to ask Mingo?"). The menu button (top right) opens the navigation; Settings is last.
- Web links open in an in-app Safari view.
- "Update Available" and, for an unsupported version, "Update Required" lead to the app's App Store page; "Update Required" offers "Restart to Update" instead once newer web content is downloaded.
- Web content updates, below. Sign-in, account deletion, Face ID and permissions work as before.

WEB CONTENT UPDATES:
The console is web content (HTML, CSS, JavaScript) in WKWebView; a copy ships in the app. On launch the app asks our gateway (openframe.ai), sending no user data, which release our service runs. If it is newer than that copy, the app downloads its bundle, a public release file of our GitHub repository, and shows it from the next launch. It first verifies our signature on the release manifest (public keys built into the app) and the bundle's size and SHA-256.
No native code is downloaded. The bundle can call only native functions already in this binary, so it cannot add a permission or native capability. Registration and payment surfaces stay disabled in every release; updates change neither its purpose nor the features described here.

HOW TO SIGN IN:
- On the Login screen enter the demo email, tap "Continue with OpenFrame" under the field, then enter the same email and password in the sheet; it closes and the workspace opens.
- Apple, Google and Microsoft buttons sign in users whose administrator created an account with that email. Your own Apple ID shows "No account found" - by design.

ACCOUNT DELETION:
Menu -> Settings -> actions button on the row with your name -> Delete Account. Deletion is immediate and signs the user out everywhere. An OWNER first picks a new owner in the same dialog; a sole owner is told to invite a member or email hello@openframe.ai. The second demo account, a regular member, can verify deletion.

FACE ID:
Optional, off by default, offered after the first sign-in. The unlock screen has "Log in another way".

NO PURCHASES IN THE APP:
No in-app purchases or purchase surfaces: no plans, prices, trials, upgrade buttons or invoices, and no link to a registration or purchase page.

EXTERNAL SERVICES:
- Auth: Sign in with Apple (native sheet); Google, Microsoft and our IdP in ASWebAuthenticationSession against our gateway.
- Push: Firebase Cloud Messaging, the only third-party service SDK. No Analytics or Crashlytics.
- Attachments: Google Cloud Storage. AI assistant: the LLM provider each customer configures.
- Web content updates: GitHub Releases, download only.
- Payment processors: none. Analytics: first-party only.

PERMISSIONS:
- Notifications: asked after the first sign-in; neither answer affects access.
- Camera and microphone: only for "Take Photo or Video" when attaching a file (e.g. Tickets -> a ticket -> Add Files).
- Face ID: opt-in only (above).

USER CONTENT:
Private to one MSP's workspace; membership by administrator invitation. Support: hello@openframe.ai.

DEVICE SUPPORT:
iPhone only.
